## 背景

在 OpenClaw-CN 的日常使用中，很多人都遇到过同一个痛点：每次开新对话，Agent 就“失忆”了。你的项目结构、惯用工具链、代码风格偏好、甚至是本地路径的缩写习惯，都需要重新交代一遍。即便使用 MCP 扩展了文件系统访问能力，Agent 仍然缺乏一个“我应该去读取什么”的明确约定。

于是，一个很自然的工程化想法诞生了：**给 Agent 准备一份 USER.md，就像给人准备 README 一样。** 它不是系统提示的简单扩展，而是一份结构化的、可被 Agent 通过工具按需读取的“用户说明书”。当 Agent 需要了解你的上下文时，它应该主动去查阅这份文件，而不是依赖你反复输入。

## 问题拆解

为什么直接往系统提示里塞一大堆个人信息不理想？

1. **Token 浪费**：每次请求都携带大量静态文本，即使与当前任务无关。
2. **维护困难**：修改偏好需要调整多个会话或配置文件，容易遗漏。
3. **隐私边界模糊**：系统提示通常会被完整记录在日志中，包含过多个人信息有泄露风险。
4. **缺乏触发机制**：Agent 不知道“什么时候该重新认识你”，只能被动接受一次性注入。

我们真正需要的是一个 **Agent 可主动检索的元信息文件**，配合合指令，让它在合适的时机自动加载并遵循其中的约束。

## 核心实践：构建你的 USER.md 体系

以下方案已经在 OpenClaw 0.9+ 环境（搭配文件系统 MCP 或内置文件工具）下验证通过。

### 1. 文件位置与层次

推荐使用层级化的 USER.md，避免单一大文件：

- `~/.openclaw/user.md`：全局用户画像，适用所有项目。
- `{项目根目录}/.claw/user.md`：项目级覆盖，例如特定仓库的语言规范、测试命令等。

Agent 应该被引导优先读取项目级，再回退到全局级。文件名统一为小写，避免跨平台路径问题。

### 2. USER.md 内容结构

为了兼顾可读性与 Agent 解析效率，采用带有 Front Matter 的 Markdown 格式，并用固定小节划分信息：

```markdown
---
name: "你的代号"
role: "后端开发者"
os: "macOS"
shell: "zsh"
editor: "neovim"
default_language: "zh-CN"
---

## 工具与命令
- 包管理: pnpm
- 测试: vitest --reporter=verbose
- 部署脚本: ./scripts/deploy.sh --env=staging

## 项目结构约定
- 源码: src/*
- 环境变量: 统一使用 .env，不硬编码
- 禁止向 AI 粘贴 API 密钥或数据库连接串

## 编码偏好
- 优先使用 TypeScript 严格模式
- 错误处理: 不吞异常，必须记录上下文
- 注释: 中文，但变量名使用英文

## 约束与禁忌
- 不要生成超过 200 行的脚本，除非明确允许
- 不要修改 .gitignore 外的点文件
- 不在 USER.md 中存储任何凭据
```

### 3. 让 Agent 知道如何读取

在 Agent 的全局指令（instruction）或项目 rule 中加入类似描述：

```text
你拥有读取本地文件的能力。当需要了解用户的环境、偏好、项目结构时，
请主动读取以下文件（按优先级）：
1. {workspace}/.claw/user.md
2. ~/.openclaw/user.md

读取后，你应当严格遵循其中的约束，除非用户本次明确覆盖。
```

如果你使用 MCP 提供的文件系统工具，需确认工具名称（如 `read_file`）与路径参数的传递方式，并在指令中明确调用方式，防止 Agent 臆想出幻觉路径。

### 4. 验证与触发

测试时，可先在新会话中提问：“根据我的偏好，我应该用哪个包管理器初始化项目？” Agent 若正确回答 `pnpm`，并且引用 USER.md 内容，则集成成功。

进一步，可在 `user.md` 中预定义“触发词”段：

```markdown
## 触发规则
- 提到“环境初始化”时，必须重新读取项目级 user.md
- 涉及修改配置前，再次确认 user.md 中的约束
```

Agent 需在指令中理解这些规则，但不要过度复杂化——简单场景下，只在对话开头或切换项目时读取一次即可。

## 踩坑记录

1. **Agent 不主动读取**  
  指令中如果只写“你可以读取 USER.md”，Agent 大概率不会主动读取。必须写明“当涉及环境/偏好/约束时，**必须**先读取……”，用强约束词汇。

2. **路径解析错误**  
  在远程 MCP 场景中，Agent 可能会把 `~` 理解为字面量。建议 instruction 中使用绝对路径模板 `{home}/.openclaw/user.md`，并在运行时由宿主进程替换，或者直接提供完整路径。

3. **编码与换行**  
  在 Windows 环境下，USER.md 若使用 UTF-16 LE 编码，Agent 读取后可能出现乱码。统一用 UTF-8，换行符使用 LF。

4. **隐私遗漏**  
  曾有人把临时测试用的 API Key 随手写在 USER.md 里，然后被 Agent 在别的会话中无意暴露。解决方法是：禁止在 USER.md 存放任何凭据，敏感信息一律通过环境变量注入，并在约束中写明。

5. **过度读取**  
  如果每轮对话都让 Agent 重新读取文件，会增加 I/O 延迟和工具调用消耗。合理的做法是：仅在会话初始化时读取一次，或在用户明确要求“重新加载偏好”时再更新。

## 可复用建议

- **模板化**：维护一份 `user.template.md`，包含所有小节标题与注释，团队成员可快速复制修改。
- **分层可覆盖**：项目级文件只写差异部分，全局文件保持稳定，减少维护成本。
- **元数据机读化**：Front Matter 中的字段（如 `os`、`shell`）能让 Agent 做决策（例如自动选择 shell 脚本的格式），这远比自然语言描述可靠。
- **配合 MCP 资源提示**：如果你的 MCP 服务端实现了 `resources/list`，可以将 USER.md 注册为资源，Agent 可像引用知识库一样使用它，避免路径硬编码。
- **版本化**：将 USER.md 纳入 dotfiles 仓库，和你的 `.zshrc`、`gitconfig` 一起管理，任何环境切换后即可同步偏好。

## 总结

USER.md 是一种低成本但效果显著的 Agent 上下文增强手段。它把“我是谁、我怎么工作”从系统提示中剥离出来，作为可检索、可分层、可维护的静态资产。结合 OpenClaw 现有的文件访问能力和 MCP 生态，你可以让 Agent 真正“记住”你，而无需在每次对话开始时重复自我介绍。

在工程实践中，记住三个原则：**指令明确触发时机、结构清晰便于解析、敏感信息物理隔离**。做到这三点，你的 Agent 就能从一个通用工具，进化为真正了解你工作习惯的个人助手。
