最近微博上有个话题挺热闹：AICoding 新时代钓鱼佬。配图里，一个人蹲在岸边，鱼竿上挂的已经不是鱼，而是一串「帮我写个完整项目」的 prompt。评论区纷纷对号入座：有人每天追新模型，有人攒了十几个 AI 编程工具，却一个功能都没合进主干。

调侃归调侃，这个现象背后其实是 AI 时代最扎心的问题之一：工具效率肉眼可见地提升，为什么我们的交付反而更碎片了？



## 什么是"代码钓鱼佬"

「钓鱼佬」的原意是自嘲——装备上万，打龟上岸。这个词传入技术圈后，精准命中了一类开发者：他们不是不写代码，而是把绝大部分时间花在了"生成代码"上。

典型画像有三个特征：

- 装备越买越全：Cursor、Copilot、Claude Code、Gemini CLI、DeepSeek，每个 release 都要体验一遍，仿佛工具矩阵就是技术实力
- 姿势越来越专业：精通各类 prompt 流派，会写 system prompt，懂 temperature 调参，唯独 push 到仓库的 commit 寥寥无几
- 成果越来越虚：生成过大量"看起来能用"的代码，但要么没有跑通，要么跑通之后没人敢接手

这类人并不懒惰，恰恰相反，他们是最关心工具动态的一批人。问题在于：探索工具的时间被记进了「开发工时」，而产出却没跟上，于是出现了一种体感很忙、实际很空的「假生产力」。

## 为什么"钓代码"容易上瘾



上瘾不是意志力问题，是机制问题。行为学里有个概念叫「可变比率强化」（variable ratio reinforcement）：当奖励出现的次数和时机都不可预测时，行为最容易固化。老虎机就是典型——你不知道下一次会不会中，所以一直摇。

AI 编程恰好复刻了这套机制：

1. 模型生成的代码质量参差不齐，且好坏分布不稳定
2. 你永远不知道下一次 prompt 会不会「出货」
3. 偶尔一次高质量的生成，足以让之前的挫败感烟消云散

GitHub 官方数据显示，Copilot 生成的代码采纳率大约在 30% 上下。换句话说，平均要「钓」两三次，才能得到一段可用的结果。而每一段「惊喜代码」带来的正反馈，会把「多试几次」这个行为反复强化下去。

技术产品设计也在主动推波助澜。主流 AI 编程工具的交互都偏向「连续对话」——聊得越多，token 消耗越多，模型对你的意图理解反而越「飘」。旧需求会污染新上下文，最后你不得不在一个新会话里重新描述一遍需求，然后继续钓。

## 三笔被忽略的时间账

如果只是多投入点时间，「钓鱼式开发」或许还能用「熟悉新工具」来正当化。但长期看，它有三笔账相当不划算：

- **上下文账**：一个会话里反复换方案，token 成本翻倍，且有效上下文被历史信息挤占，模型反而更容易跑偏
- **切换账**：从聊天窗口复制代码到编辑器，跑测试，再回到聊天窗口修 bug——这种「人肉往返」比连续编码消耗明显更多的注意力，任务切换的认知成本在研究中早有证实
- **认知账**：长期依赖随机反馈拿结果，拆解问题、辨析代码正确性的能力会钝化。工具越强，你对「这段代码到底对不对」的判断力越值钱，也越不能丢

三笔账合起来，就能解释为什么有些团队 AI 工具用得最勤，交付反而最慢。

## 从"钓鱼"到"养鱼"：四个务实姿势



先别急着怪模型。换个角度想：钓鱼佬钓不到鱼，通常不是因为鱼竿不行，而是不知道哪片水域有鱼、该下多深的钩。把 AI 从「随机渔获」变成「可控养殖」，需要四个姿势：

- **先写设计，再写 prompt**：把需求拆成接口级别的任务描述，而不是丢一句「帮我写个用户系统」
- **一次只钓一条鱼**：单个 prompt 只解决一个函数、一个 bug、一个页面。范围越大，翻车率越高，返工的隐性成本越难察觉
- **给 AI 输出上三道验收关卡**：代码规范扫描、单元测试、人工 code review。凭感觉「看起来还行」是最危险的验收方式
- **在团队里保留「AI 提交记录」**：把每次 prompt、生成结果和人工改动留痕，让钓上来的代码可审计、可回滚、可复用

## 冷思考：工具越强，越要清楚自己要什么

AI Coding 的进步是实打实的。GitHub 的对照研究显示，使用 Copilot 的开发者完成指定任务的速度大约提升 55%。但这里有个容易被忽略的细节：那 55% 来自「明确任务 + 熟练开发者」，而不是「模糊想法 + 反复试错」。

工具的杠杆效应在放大，目标的权重也同步放大。未来几年，三类人吃到最大的红利：

1. **能把需求说清楚的人**——prompt 的底层能力就是需求规格化能力
2. **能判断代码对不对的人**——AI 生成，人来把关，判断力就是话语权
3. **能把 AI 结果快速缝合进系统的人**——集成能力比生成能力值钱，因为生成的成本正在趋近于零

反过来，如果沉迷于「钓」的过程本身，新版本发布永远在等你，旧功能永远没上线。

## 三条实用建议

收个尾。如果你想摆脱「AI 钓鱼佬」的循环，试试这三条：

1. **每天限定 30 分钟的「钓鱼时间」**：新工具、新 prompt 思路只在这个窗口里探索，其余时间锁死在自己的真实任务上
2. **给 AI 上 KPI**：衡量 AI 的指标，只看「合入主干的有效代码行」和「被保留超过一个月的函数」，而不是「生成的 token 数」或「聊了多少轮」
3. **每两周沉淀一次 prompt 库**：把反复用过的有效 prompt 提炼成团队模板。随机强化变成稳定输出，你才算真正从「钓鱼佬」毕业

AI 时代不缺会写代码的人，缺的是能把代码变成交付的人。别再当那个装备最全的钓鱼佬了——把鱼带回家，才是硬道理。
