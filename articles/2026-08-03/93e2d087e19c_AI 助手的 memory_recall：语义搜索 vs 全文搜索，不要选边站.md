在 OpenClaw 这类 Agent 框架里，memory_recall 负责把历史对话、用户偏好、项目上下文捞回来喂给模型。这个环节做不好，模型上下文再长也白搭——垃圾进，垃圾出。最近我们在给内部自动化助手做 memory_recall 评估时，把语义搜索和全文搜索两种方案都跑了一遍，结论可能是你最不想听的：不要二选一。

## 背景与问题

语义搜索（向量相似度）在“意思相近但字面不同”的时候很强。用户说“帮我查上次报销规则”，规则里写的是“费用报销流程”，向量能召回。但一旦用户说出“请加载 config_v1.2.3.yaml，端口 8080”，向量常常会把 v1.2.3 和 v1.3.2 搞混，把 8080 和 8008 看成“语义相近”。

全文搜索（BM25/关键词）恰好相反：精确 token 很稳，端口号、文件名、版本号一个不差；但用户说“退款标准”，文档里写“退货赔偿”，全文就哑火了。

所以核心问题不是谁更强，而是**什么时候走哪条路，以及两条路怎么合流**。

## 做法与步骤

我们用的是轻量方案：SQLite FTS5 做全文，sqlite-vec 做向量，外面包一层路由和融合。

**第一步：构造评测集。** 从生产日志捞 300 条真实 query，分三类：

- 精确类：含 ID、版本号、文件名、端口号（100 条）
- 改写类：同义表达、缩写、口语化说法（100 条）
- 混合类：既有精确 token 又有自然语言（100 条）

每条都标注“期望从哪条 memory chunk 中召回”，这条 ground truth 决定了后续所有评估能不能落地。

**第二步：双通道召回。** 全文通道用 FTS5 的 BM25，语义通道用 embedding 余弦相似度，各自取 top-20。

**第三步：融合排序。** 不搞复杂模型，直接用 RRF（Reciprocal Rank Fusion）：

```python
score = sum(1 / (k + rank_i))  # k 固定 60
```

按融合分数排序后取 top-5。如果两条通道的 RRF 分数都趋近于零，就返回空，不要硬给结果。

**第四步：离线评估。** 计 Recall@5 和命中率。三类各 100 条跑下来，混合通道比单语义高 21%，比单全文高 15%。差距主要来自混合类 query——单通道基本只能覆盖一半。

## 踩坑点

几个我们踩过的坑，值得你绕开：

1. **语义搜索对数字和代码极其不稳定。** 向量模型不知道 `v1.2.3` 和 `v1.3.2` 是两回事。我们的解法是加一层浅路由：正则命中 `端口|版本|0x[0-9a-f]+|\.yaml$` 这类强信号时，直接走全文通道，不经过向量。
2. **中文分词决定全文检索下限。** 用 jieba 但没加领域词典，最终结果就是搜“记忆”匹配不到“回忆”。领域词典必须包含工具名、项目代号这些词，否则等于没做全文搜索。
3. **混合检索不是简单拼接。** 直接 concat 两条通道的结果，同一个 chunk 会以不同形式出现两次，在线上去重必须按 chunk_id 合并，保留最高分。
4. **chunk 大小两头难。** 语义检索喜欢 200–300 token 的完整段落，全文检索更喜欢短小精确的片段。我们最终定在 256 token、重叠 32 token，两种通道都能接受。
5. **不要拿 30 条 demo query 下结论。** 我们一开始用 30 条测试觉得语义搜索不错，扩到 300 条之后立刻现原形。

## 可复用建议

- **先跑评测，再调优。** 造一个 300 条以上的测试集，按类型拆分统计。没有 Recall@K，你无法回答“哪个好”。
- **路由比参数重要。** 在向量全家桶前面加一层浅层分类，成本极低，收益极大。纯向量在精确查询上的失败率不是 5%，是 30% 以上。
- **融合用 RRF，不要手动加权。** RRF 没有需要调的超参（k 取 60 是经验值），对分数分布不敏感，结果稳定。
- **保持轻量。** SQLite FTS5 + sqlite-vec 足够支撑中小型 agent 的 memory 系统，不需要为了混合检索上重型的向量数据库。
- **持续监控失败样本。** 每周抽一次召回失败的 query，按错误类型归因，把新的领域词加进分词词典，把新的数字模式加进路由正则。

## 总结

memory_recall 的好坏不完全取决于模型，而取决于**检索设计 + 评估方式**。语义搜索和全文搜索不是互斥选项，而是互补选项。目前我们跑下来最稳的组合是：轻量路由分流精确查询 + 双通道召回 + RRF 融合 + 离线 Recall@K 评估。工具链不复杂，但每一步踩坑都需要真实数据来驱动。没有测试集，就没有发言权。
