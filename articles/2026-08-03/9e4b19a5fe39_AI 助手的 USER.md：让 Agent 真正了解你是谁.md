### 背景

用 OpenClaw 做自动化跑了一段时间的人，基本都会撞上同一个问题：每开一个新会话，Agent 就像失忆了一样，重新把你当成陌生人。它问你"你的代码风格是什么""部署到哪个环境""要不要加测试"——这些明明是三个月前就定好的事。

OpenClaw 支持 agent 配置、插件、MCP，但真正决定个性化质量的，往往是那个常被忽略的 USER.md。它是 Agent 开工前读到的"人设页"：我是谁、我在哪、我喜欢怎么干活。

### 问题：Agent 为什么总是不懂你

常见原因有三个：

1. **记忆机制是任务态的**。会话记忆只存活在对话窗口里，切了 session 就归零。
2. **系统提示是全局通用的**。它面向所有用户，不会默认包含你的个人偏好。
3. **用户画像缺失或散落**。偏好描述东一句西一句，Agent 不会主动汇总。

结果是：每次对话都在重复交代背景，成本全部转嫁到你身上。

### 做法：怎么把 USER.md 写对

我的做法是把它当成一份"配置文件"，而不是自我介绍。

目录结构（OpenClaw 场景）：

```
~/.openclaw/
  agents/
    default/
      USER.md
      AGENTS.md   # agent 行为约束
```

USER.md 核心分五块：

```markdown
## 身份
- 角色：后端开发，运维兼带

## 环境
- 本机：macOS + zsh + docker compose
- 常用工具：mise, hugo, sqlite

## 沟通偏好
- 回复要短，直接给结论和命令
- 不要问"是否继续"，除非有破坏性操作

## 工作流规则
- 提交信息用 conventional commits
- 代码改动附带测试，跳过要说明理由
- 部署前必须先跑 lint + pytest

## 硬性约束
- 绝不自动执行 rm -rf 或修改 ~/.ssh
- 需要 sudo 的操作先列出命令等我确认
```

要点：**用 always/never 写规则，不要用形容词**。"做事认真"没有可执行性，"每次改动附测试"才有。

写完启动一个新会话，问一句"你对我有哪些了解"，让 Agent 复述 USER.md 里的关键规则，验证它真的读进去了。

### 踩坑点

1. **写成生平传记**。长文的工作经历和风格描述，Agent 读完全是噪音。要压缩到 80 行以内，每条信息必须能影响行为。
2. **环境事实和偏好混在一起**。本机工具版本三个月换一轮，写进 USER.md 就等着过期。环境信息放环境文件，偏好才放 USER.md。
3. **没做版本管理**。USER.md 是一次性配置，不是活文档。放进 dotfiles 仓库，每次删掉一条规则都留个 commit。
4. **和 AGENTS.md 冲突**。USER.md 管"你是什么样的人"，AGENTS.md 管"Agent 怎么干活"，两者对同一件事要求相反时必须以 USER.md 为准，否则 Agent 会持续摇摆。
5. **改完不测试**。新增规则后，必须用真实任务跑一遍，确认 Agent 确实跟随。否则自我感觉良好，实际无效。

### 可复用建议

- **分两层放**：全局 USER.md 放稳定身份；每个项目再放一份局部 USER.md，覆盖项目专属约定（如"后端项目必须走 pnpm test"）。
- **放样例输出**。给 Agent 一个"每次重构应长成什么样"的 diff 示例，比十句文字描述有效。
- **季度大扫除**。每季度回头删掉过时规则，保留率控制在 60% 以下。
- **先小后大**。别一口气写 50 条，先写 10 条最重要的，跑两周再补。

### 总结

USER.md 的本质，是你和 Agent 之间的接口契约。花三十分钟写一份高质量的 USER.md，换来的是每个新会话都不必自我重复。记住：Agent 的个性化上限，取决于你把自己的规则表达得有多精确。
