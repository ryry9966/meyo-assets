"DeepSeek 一天消耗 8 万亿。" 这个数字在微博上刷屏的时候，很多人的第一反应是——这是不是把整个国家电网都干崩了？第二反应是——这么贵，那这家公司是不是马上要倒闭了？

先说结论：这个数字大概率是**把「训练期间所有实验的总成本」和「全天全量服务运营成本」混在一起算出来的估算值**，不是某一天真实扣款的账单。但即便它是个混沌估算，这条热搜也撕开了一个值得聊的窗口：**大模型的账本，普通人到底该怎么看？** 今天我们就把它拆成三笔账来讲清楚。



## 一、先看单位：8 万亿到底怎么算出来的

这个数字的源头，来自一份被反复转引的分析框架。它把 DeepSeek 的算力开销拆成几条线：

- **训练成本**：V3 的训练据公开论文约 557.6 万美元（按当时 GPU 价格折算），R1 在此基础上做了强化学习，总成本可粗略估到千万美元级别
- **服务成本**：按日活用户数 × 平均请求数 × 单次推理耗卡时 × GPU 市场价，折算出每天的推理开销
- **预期收入**：用 API 定价推算出每百万 token 的定价能覆盖多少推理成本，再反推缺口

问题出现在最后一步——**很多人把「缺口」当成「耗损」**。比如：
- 假设日活 3000 万
- 平均每天每人产生 2 万 token
- 按 H800 折算每 token 推理成本约 $0.014 / 千 token（含电费、折旧、运维）
- 每天总成本 ≈ 3000万 × 20000 / 1000 × 0.014 = 840 万美元/天 ≈ 人民币 6000 万/天
- 再乘上一个「服务冗余系数」（比如 2~3 倍峰值预留），一年下来就接近 8 万亿人民币的传闻口径

你看，每一步单看都有合理性，但**乘在一起就变成了一种「悲观放大」**。真实账单里，很多成本是被摊销的、很多卡是自有的、很多时段是空闲的，不可能按峰值需求天天满负荷烧钱。

## 二、训练和推理：两种完全不同的「烧钱逻辑」

### 训练是一次性基建
- 像修一条高铁：修的时候花大钱，但修完不代表每天都花这个钱
- DeepSeek 的 MoE（混合专家）架构只激活部分参数，训练时 token 利用率高，成本已经被压到极低
- 公开论文里 V3 的训练成本约 557.6 万美元，这个数字在业界是「性价比天花板」，不是「烧钱典型」

### 推理是持续性运营
- 像地铁开通后每天的电费、维护费、人工费
- 每次用户提问，模型都要做一次前向传播，消耗 GPU 显存和算力
- 如果日活持续暴涨、免费用户占比高、长上下文占比高，推理成本会非线性上升

所以「一天 8 万亿」如果真的发生，它更可能来自**推理环节的极端假设**——比如假设所有用户都在不停提问、所有请求都走最贵的长上下文模式、且所有 GPU 都按市场租赁价计费。**但现实是：自有硬件、批量调度、缓存命中、低位宽量化推理，都会让真实成本大幅下探。**



## 三、为什么各家都在谈「推理成本屠夫」？

这里有个关键概念：**推理成本不只是钱的问题，更是架构问题。** DeepSeek 被热议的推理成本优势，主要来自几个技术点：

1. **MLA（多头潜在注意力）**：把 Key/Value 缓存压缩成低秩潜在向量，显存占用下降一个量级，长上下文时优势尤其明显
2. **MoE 稀疏激活**：每次只激活 8 个专家（总参数 671B，激活约 37B），单 token 计算量远小于同尺寸稠密模型
3. **FP8 混合精度训练与推理**：低精度计算在保证效果的前提下大幅提升吞吐
4. **Prefill / Decode 分离**：把长提示词处理和生成阶段拆开，避免互相拖累，提升 GPU 利用率

简单对比一下（单位：每百万 token 的估计成本量级）：

| 模型类型 | 输入（缓存命中） | 输出 | 相对量级 |
| --- | --- | --- | --- |
| 稠密模型（类似 GPT-4 同类） | $2~15 | $15~60 | 基准 |
| DeepSeek V3/R1 类稀疏模型 | $0.2~1 | $2~8 | 低 5~10 倍 |

这就解释了为什么 DeepSeek 敢把 API 价格压到白菜价——它不是在亏本赚吆喝，而是在**用架构优势获取成本结构上的不对称竞争空间**。

## 四、这笔账，行业内到底怎么算？

其实真正的算力账本，从来不是「一天多少亿」这种简单公式，它至少包含四个维度：

- **TCO（总拥有成本）**：GPU 采购价（自建）vs 云租赁价 × 折旧周期
- **利用率**：一台 A100/H800 是 30% 时间干活还是 90% 时间干活，差距是 3 倍
- **Token 经济**：同样 1 亿用户，人均日 token 数是 5000 还是 5 万，决定了一切
- **收入对冲**：API 收入、商业化应用、企业私有化部署授权费，都会反过来降低「净消耗」

所以，当你看到「XX 一天烧 X 亿」的新闻，先别急着转发，可以问三个问题：

- 是训练还是推理？
- 是毛成本还是净成本？
- 是峰值假设还是实际运营数据？

这三个问题一过滤，大部分「天文数字」都会瞬间缩水 5~10 倍。

## 五、三条冷思考

1. **别用「电费思维」理解 AI 算力**——算力不是能耗，而是资产。GPU 集群在折旧期内持续产出模型服务能力，就像网购平台建仓，前期重投入、后期靠复用和调度摊薄成本。真要判断健康度，看毛利率和用户付费转化，而不是看单日绝对支出。

2. **「成本下降」本身就是最大的商业变量**——DeepSeek 这类架构创新的意义在于把推理边际成本拉低了一个量级，这会触发新的应用场景（比如全量代码审查、批量文档处理、实时语音助手）。当算力变便宜，需求曲线就会右移，市场总量反而扩大。

3. **警惕「数字通胀式传播」**——热搜里的天文数字通常不是事实，而是「最坏假设的线性外推」。对一个工程师来说，重要的不是惊叹数字有多大，而是搞懂它背后的**计量口径、假设边界、变量敏感度**。真正的高手，看到 8 万亿，第一反应是去查：这个数字是「EB 级 FLOPs」还是「人民币成本」？是「单日峰值」还是「年度合计」？



最后再说句实在话：AI 行业现在最稀缺的能力，不是发论文，也不是跑分，而是**把「资源消耗」翻译成「商业模型」的能力**。DeepSeek 的账本到底好不好看，等它的 API 收入规模和 GPU 利用率数据公开时，自然会见分晓。在此之前，所有「一天 X 亿」都是故事，不是账单。
