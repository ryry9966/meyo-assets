智谱“牛来”模型最近在 36氪披露了算力与定价信息：全部由国产卡承载，API 价格约为 Claude Opus 4.8 的 1/40。这个数字放到当前大模型价格战里，仍然足够刺眼。因为一般来说，旗舰闭源模型的推理价格下降 50% 已经算激进，而 1/40 意味着直接跨了一个数量级。这里不打算把“国产替代”喊成口号，而是拆一下这个价格差从哪来、有没有水分、以及开发者该怎么看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-27/3af8f61395e9ab11.png)

## 一、先把“1/40”拆开看：它到底在比什么

- “1/40”最可能指向推理 API 的公开标价，而不是训练总成本。训练成本再低，也不会直接折算成 API 价格。推理价格主要由单次请求消耗的算力、显存和电力决定。
- 要比得有意义，需要看单位：通常按每百万 tokens 的输入和输出价格分别计算。很多模型输出价格是输入的 3~5 倍，如果不说明输入输出比例，只讲“综合价格”就容易失真。
- 还要看上下文长度和并发条件。同样一个模型，在 8K 上下文和 128K 上下文下，KV cache 开销差异很大，单位成本会明显不同。
- 举例来说，如果 Opus 4.8 的输出定价是每百万 tokens 75 美元，那 1/40 大约是 1.875 美元；如果输入价格是每百万 15 美元，那 1/40 就是 0.375 美元。这个区间已经接近甚至低于很多开源中小模型的服务价格。

## 二、为什么“全部国产卡承载”是关键信息

- 过去，大模型推理集群几乎默认基于 NVIDIA 的 CUDA 生态。国产 AI 芯片虽然纸面算力不低，但软件栈、算子库、分布式通信和推理框架适配长期是短板。
- 智谱说“全部国产卡承载”，意味着它至少把模型加载、推理服务、批处理、KV cache 管理、混合精度计算等环节迁移到了国产卡上。这不是简单换个硬件，而是一层“生态翻译”工作。
- 技术细节上，常见的迁移动作包括：把 CUDA kernel 改写为厂商提供的算子；使用统一的中间表示；针对国产卡的显存带宽和片上存储调整 tile size；用 FP8/INT8 量化替代 FP16/BF16；以及重新调优多卡之间的 all-reduce 通信。
- 历史背景看，2023 年之前，国产卡主要集中在训练小模型或推理视觉模型；2024 年后，国产卡在 LLM 推理上的可用性明显提升，但全量承载一个主流对话模型仍不多见。所以这一信息比“低价”更有行业意义。

## 三、价格打到 1/40 的三个技术杠杆

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-27/b90b006d5a41facd.png)

- 首先是推理架构变化。现代 LLM 推理通常把 prefill 和 decode 分离：prefill 阶段长上下文一次性计算，decode 阶段逐 token 生成。两者算力需求不同，分开调度可以避免资源空转，显著提高硬件利用率。
- 其次是量化与蒸馏。如果“牛来”本身是中等规模模型，或者采用 FP8/INT4 量化，单次请求的 FLOPs 和显存占用会大幅下降。量化的代价是精度损失，但工程上可以通过校准、混合精度和知识蒸馏来弥补。
- 第三是国产卡的单位算力成本。国产卡在采购价、机架功耗和集群建设上，往往比同代 NVIDIA 卡便宜。对于推理这种可切分、可并行的负载，只要有足够的卡和稳定软件栈，单位 token 成本可以压得更低。
- 三者叠加，才会出现“1/40”这种非线性降价。单靠其中任何一项，都做不到一个数量级。

## 四、算力国产化以后，行业会怎么变

- 短期看，模型 API 价格继续下探。尤其 To B 的文档处理、客服问答、代码补全等场景，成本从“能不能用”变成“敢不敢大规模用”。
- 中期看，云厂商和模型厂商会加大对国产卡的采购。推理侧国产替代比训练侧更快，因为推理负载更容易拆分成小任务，对单卡算力和互联带宽的要求不如训练极端。
- 也会出现新的分化：一部分厂商用国产卡做“低价格、大规模”推理服务；另一部分继续用 NVIDIA 卡做高可用、低延迟的旗舰服务。两种供给会共存。
- 但生态问题还没有完全解决。国产卡之间的软件栈不统一，迁移一个模型到不同品牌卡，仍然需要重复适配。这会推高隐形成本，只是很多厂商暂时不写进新闻稿。

## 五、冷思考：便宜不等于便宜好用

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-27/b1318b3ebe8a3a8a.png)

报道里的“1/40”更多是价格信号，不是能力对等声明。开发者如果要评估这类模型，建议带着三个问题去看：

1. 看“有效 token 成本”，而不是标价。模型输出错误、需要重试、或者上下文反复截断，都会把省下的钱吐回去。可以在自己的评测集上跑 1000 次真实请求，计算完成一项任务实际消耗多少 token。
2. 看能力边界。低价模型往往在长文本、复杂工具调用、多轮指令跟随上出现断崖式下降。建议设计一个包含长文档问答、代码修改、JSON 输出约束的小型测试集，而不是只看公开榜单。
3. 看稳定性和供应。国产卡集群在高峰期的排队、限流、批量请求延迟，会直接影响产品体验。采购前可以先做 72 小时压测，记录 P95/P99 延迟和错误率。

“国产卡承载”确实值得关注，因为它意味着推理成本的天花板在松动。但技术普及的真正标志，不是新闻里出现一个 1/40，而是当开发者不再因为价格理由而选择降级体验时，国产算力才真正站到了台前。
