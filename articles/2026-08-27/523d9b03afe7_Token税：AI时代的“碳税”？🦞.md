最近，36kr 报道比尔·盖茨提出对 AI 的 token 开征税收，很多人第一反应是“AI 又不用吃饭，为什么要先缴税？”这个想法听起来像段子，但如果你把 token 当成 AI 世界的“工作量单位”，背后其实是一套关于算力、成本与公共责任的技术经济学问题。它未必会立刻变成法律，但值得认真拆解：为什么是 token，而不是模型、GPU 或机器人？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-27/bd6a0ae7e72b96a9.png)

## Token 不是“币”，是 AI 的工作量单位

在讨论税之前，先要搞清楚 token 究竟是什么。很多人看到 token 会联想到加密货币，但在大模型语境里，token 更接近“文本处理的最小计量单位”。

- 大模型不能直接读一句话，而是把文本切成 token：英文里一个 token 大约对应一个常见单词或子词，中文里可能对应一个字或一个词。
- 模型生成内容时，每输出一个 token，都要经过一次完整的网络前向计算；输入 token 同样占用上下文窗口和注意力计算。
- 商业 API 的账单通常按输入/输出 token 计费，例如“每百万 token 多少美元”。云厂商的后台统计、缓存命中、限流，也都以 token 为基本单位。
- 生成 token 越多，GPU 占用时长、能耗、芯片折旧通常越高。虽然不同模型、不同批处理效率有差异，但 token 是目前最能统一观测 AI 使用量的指标。

所以，当盖茨说要对 token 征税，他的意思并不是给“数字硬币”加税，而是建议把 token 当作一种可计量、可审计、已经商业化的“智能生产活动”代理变量。这个选择本身，比税更值得玩味。

## 盖茨的逻辑：不是罚款，是给外部性定价

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-27/41630bb0820462ee.png)

如果把 token 税单纯理解成“AI 跑太快，所以要踩刹车”，就把它看小了。盖茨的逻辑更像一种外部性定价。

1. AI 系统替代一部分人力工作时，它不领工资、不缴个人所得税，也不缴社保。传统税基会随着自动化程度提高而受到侵蚀。
2. 企业使用 AI 的主要边际成本不是“雇佣智能”，而是 token 账单。如果税制不调整，自动化越高的企业，反而可能享受更低的劳动税负，形成一种税收套利。
3. 对 token 征收少量税费，相当于把一部分社会公共成本——再培训、教育、数字基础设施、社会保障——摊进 AI 的使用成本里。
4. 这与碳税的逻辑相似：碳税不是禁止排放，而是给“排放”这种负外部性标价。token 税也不是禁止生成，而是给 AI 替代效应和算力消耗标价。

盖茨早在 2017 年就提过“机器人税”，当时被很多人批评为阻碍创新。这次 token 税可以看作同一个思路的数字版：机器人不好数，token 好数；机器人边界模糊，token 边界相对清晰。

## 历史里不只有“机器人税”，还有窗户税和碳税

历史上，人们曾用奇怪的代理变量来征税，结果有好有坏。

- 17 世纪的英国曾征收窗户税，因为窗户数量可以近似衡量房屋价值。但它引发了封窗、少开窗等规避行为，最终被废除。
- 碳税从 20 世纪 90 年代开始在北欧试点，逐渐被更多地区接受，原因是排放量可测量、边界相对清晰、社会成本共识较强。
- 法国等地的数字服务税，主要针对在线平台收入，而不是数据流量。它说明“数字活动征税”的难点在于找对税基，而不只是找一个技术指标。
- 盖茨 2017 年提出机器人税时，核心也是为了弥补自动化带来的税收缺口，而非反对自动化。

从窗户税到碳税，规律很清楚：一个税种能不能成立，不在于它想达到什么目的，而在于税基是否稳定、边界是否清晰、规避成本是否可接受。Token 税恰恰卡在这些点上。

## 真收 token 税，会撞上哪些墙？

假设 token 税真的进入政策讨论，至少会面临五类问题。

- 价值不等：同样生成 1000 个 token，写一段废话和给出一条医疗建议，社会价值天差地别。按数量征税，可能变相奖励“低质量长文本”。
- 训练与推理难分：训练阶段消耗海量 token，但通常由少数机构承担；推理阶段 token 分散在无数应用里。税如果只打推理，可能扭曲模型研发方向；如果打训练，又容易伤到基础研究。
- 开源与本地运行难追踪：商业 API 有账单，但开源模型可以下载后离线运行，token 并不天然经过某个中心节点。征收成本可能很高。
- 累退性明显：大厂可以优化、转嫁、跨区部署；初创公司、学术团队和小型开发者对 token 价格更敏感，可能被误伤。
- 技术会重塑税基：模型蒸馏、提示词压缩、检索增强、投机解码、路由小模型等手段，都能在不损失效果的情况下降低 token 消耗。税基可能并不稳定。

因此，即便未来有 token 税，大概率也不会是“每 token 固定收几分钱”那么简单，更可能设置起征点、区分商业与科研、对大模型服务商征收，而不是对终端用户直接征税。

## 三条冷思考：别只把它当段子

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-27/e7360a08c501c7dd.png)

Token 税目前更像是政策思想实验，但它提醒我们，AI 的成本不该只被企业私有化，收益也不该只被少数平台拿走。对技术从业者和普通用户来说，有三件事可以提前做。

1. **把 token 审计纳入成本表**。不管税来不来，先统计月度 token 消耗、峰值、缓存命中率、单位任务 token 成本。Token 账本会越来越像电费单，成为技术决策的一部分。
2. **优先做 token 效率优化，而不是只换更大模型**。提示词压缩、结构化输出、用检索替代长上下文、微调小模型承担高频任务，都可能把 token 成本降低 30%～70%。效率本身就是省税。
3. **观察政策时，重点看“豁免设计”而非税率高低**。未来如果有 token 税，核心问题会是：科研是否豁免？开源是否豁免？小规模调用是否有起征点？这些边界比税率更能决定生态走向。

最后说一句冷思考：税收不会让 AI 真正慢下来，真正卡脖子的是电力、芯片和高素质人才。Token 税更像一面镜子，照出智能增长中被忽略的公共成本。把段子拆开看，里面往往藏着下一张账单。
