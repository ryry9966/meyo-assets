“千问、智谱连夜开源，价格比 DeepSeek 还便宜。”这条热搜其实包含两层信息：一是基础模型权重继续开源，二是 API 调用价格继续下探。对开发者来说，热闹不是重点，重点是要不要换、怎么换、以及这个价格能不能持续。

先给结论：国产大模型已经进入“价格绞肉机”阶段，但便宜不等于免费午餐，算账要算全生命周期。过去两年，大模型 API 价格从“按美元心疼”到“按分钱纠结”，变化速度超过很多人预期。2023 年调用顶级模型，百万输出 tokens 折合人民币可能数百元；2024 年 DeepSeek 把价格拉到个位数；现在千问、智谱又继续往下压。价格战背后是技术、商业和生态的三重变化。

## 一、先把“便宜”翻译成工程师能听懂的账

很多同学只看“每百万 tokens 多少钱”，但真正影响账单的是三个变量。

1. **输入和输出价格不同。** 输出通常更贵，因为模型需要自回归逐 token 生成，计算量更大。如果一个任务输出很长，便宜输入价格可能被输出成本吃掉。
2. **缓存命中率。** API 通常对重复前缀做 KV cache 命中打折。把系统提示词、历史对话、知识库片段放在前缀，能显著降低输入成本。
3. **上下文长度与并发。** 长上下文会占用更多显存和带宽，并发高峰可能触发限流，实际吞吐量比单价更影响业务。

以公开定价页为参考，DeepSeek 此前已经把百万输入 tokens 价格压到 2 元级、输出价格拉到 10 元级，缓存命中另有折扣；这次千问和智谱的新模型或活动价，把非缓存输入价格继续打到 1 元以下，部分小模型或限时活动接近免费。注意，这里不是差几毛钱，而是倍数级下降。更重要的是，这些模型已经把“低价”从营销话术变成了默认配置。

## 二、为什么国产大模型突然集体“掀桌子”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-27/3536dbec69a8867c.png)

表面是价格战，实质是技术成熟和商业策略的叠加。

- **技术侧：** MoE（混合专家）架构让模型在推理时只激活部分参数，减少计算量；FP8/INT4 量化降低显存和带宽需求；推理引擎对连续批处理、KV cache 管理、Prefill/Decode 分离的优化，进一步压低单位 token 成本。
- **权重开源：** 千问、智谱、DeepSeek 都选择开源权重。开源本身不直接赚钱，但能吸引开发者、降低接入门槛、形成事实标准。模型权重一旦开源，边际分发成本接近零，低价 API 成为生态入口。
- **商业侧：** 大模型 API 对部分厂商来说不是利润中心，而是云资源、企业服务、数据平台的“引流品”。模型价格可以低，但后面的算力、存储、安全、合规、私有化部署、行业方案都要付费。
- **历史节奏：** 2023 年 API 价格很高，因为模型稀缺、算力紧张；2024 年 DeepSeek 用低价开源把压力传递给全行业；2025 年千问和智谱跟进，说明价格竞争从“参数规模”转向“单位智能成本”。

一句话：大家都在用价格换规模，用规模换生态，再用生态锁定未来应用层。

## 三、低价不等于白嫖：开发者要先算三笔账

“便宜”和“便宜好用”之间，隔着三个关键问题。

1. **成本账：不能只看标价。** 输出/输入价格比例、缓存命中率、限流策略、长上下文溢价，都会影响真实账单。建议拿自己的典型请求做一个月度模拟，而不是看到 0.5 元/百万 tokens 就换。
2. **质量账：返工也是成本。** 低价模型在通用对话、摘要、分类上可能够用，但在代码生成、结构化输出、多语言、复杂推理、function calling 上可能掉链子。如果因为幻觉或格式错误导致人工返工，省下的 token 钱远远不够填。
3. **稳定性与合规账：SLA 和数据边界。** API 服务是否稳定、是否有区域限流、数据是否被用于训练、是否支持私有化部署，都需要确认。开源权重可以自部署，但要自己承担推理集群、监控、安全补丁和模型更新成本。

比如，一个内部知识库问答机器人，用低价模型可能很合适；一个合同金额判断或金融合规助手，就不能只看价格，需要评测精度、数据隔离和审计能力。

## 四、价格战会走向哪里：从“参数竞赛”到“单位智能成本竞赛”

如果把大模型 API 看成一个商品，价格战的终局大概率不是“免费”，而是分化。

- **短期：** 基础模型继续卷价格，免费额度、限时折扣、小模型地板价会成为常态。厂商会用低门槛抢开发者和应用场景。
- **中期：** 通用底座模型会越来越像基础设施，毛利率被压到很低；但推理模型、Agent 框架、长上下文、多模态、垂直行业模型会维持一定溢价，因为能力有差异。
- **长期：** 价值会向应用层、数据层和工具链转移。模型层可能变成类似“云厂商入口”的生意，真正赚钱的是离业务近的工作流、私有数据、评测体系和自动化交付。

从经济学看，这很像互联网早期的补贴战：边际成本递减 + 规模效应，先让使用量上规模，再在生态里找利润。区别是，大模型的规模效应不只是算力，还有用户反馈、场景数据、工具链兼容。

## 五、三条冷思考，帮你别被价格表带偏

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-27/16e8023f46e46ead.png)

1. **固定评测集，先过关再谈价格。** 换任何模型前，用自己业务的 100-200 条典型案例做评测，评估准确率、格式稳定、工具调用和时延。价格可以在评测通过后再比较。
2. **做多模型 fallback，不要单押一家。** 把低价模型作为默认路由，把更强或私有化模型作为兜底。遇到复杂任务、长上下文或高价值请求时自动切换，兼顾成本和稳定性。
3. **算总拥有成本，而不是单价。** 包括工程改造、数据清洗、提示词重写、监控告警、安全审计、故障切换以及后续迁移成本。很多时候，模型单价只占系统总成本的一小部分。

价格战不会马上结束，但“谁便宜用谁”也不是长期策略。逢低换模型之前，先把账算清楚、把评测跑起来、把兜底方案留好——这才是开发者面对“价格绞肉机”该有的姿态。
