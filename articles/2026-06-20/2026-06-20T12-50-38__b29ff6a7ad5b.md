  "content": "最近 36kr 的一篇报道在技术圈刷了屏——\"硅谷最抢手的新岗位出现了\"。各路媒体跟风解读，有人说这是\"AI 时代的 Prompt Engineer 2.0\"，有人说是\"会写代码的产品经理\"。但扒开标题看细节，真正被大厂疯抢的，其实是一批介于传统研发和产品之间的\"混血角色\"。今天就来拆解一下，这些岗位到底是什么、为什么火、普通人能不能上车。\n\n\n\n## 抢手岗位的\"真面目\"：不只是 Prompt Engineer\n\n先说结论：2024-2025 年硅谷真正稀缺的，不是单一技能岗，而是几类\"交叉型 AI 岗位\"。根据各大招聘平台和科技公司公开数据，最热门的集中在以下几类：\n\n1. **Forward Deployed Engineer (FDE)**：前线部署工程师，源自 Palantir，被 OpenAI、Anthropic 等公司发扬光大。核心任务是带着模型直接去客户现场，快速搭建原型、解决问题。\n2. **AI Engineer / LLM Application Engineer**：专注于用 LLM API 构建应用层的工程师，需要懂 prompt engineering、RAG、agent 架构，同时有扎实的工程能力。\n3. **AI Product Manager (AI PM)**：既懂模型能力边界，又懂用户场景的产品经理。不是传统 PM 换个 title，而是需要真正理解模型能做什么、不能做什么。\n4. **AI Reliability / Evaluation Engineer**：负责 LLM 系统的评估、监控和稳定性保障。传统 SRE 的 AI 升级版。\n\n这几类岗位有一个共同特征：**它们都要求\"跨域能力\"——既不是纯算法研究，也不是纯前端后端，而是在模型能力和真实业务场景之间做翻译。**\n\n\n\n## Forward Deployed Engineer：从 Palantir 到 OpenAI 的\"前线工程师\"\n\n如果说上面几个岗位里哪个最\"新\"、最\"抢手\"，FDE 大概是讨论度最高的。\n\n**历史背景**：FDE 这个概念最早由 Palantir 在 2000 年代末提出。Palantir 做的是 toB/toG 的数据分析平台，每个客户的需求差异极大，不可能靠标准产品覆盖。于是他们派出一批既懂技术又懂业务的工程师，直接驻场客户，用自家平台快速搭建定制化解决方案。这批人就叫 Forward Deployed Engineer。\n\n**为什么现在火了**：大模型时代，情况惊人地相似。OpenAI、Anthropic、Cohere 等公司发现，企业客户买了 API 之后，根本不知道怎么用。模型能力很强，但落地场景千差万别——医疗、法律、金融、制造，每个领域的 know-how 都不同。于是 FDE 模式被重新激活：派一批技术过硬的人去客户现场，快速理解业务、搭建 prototype、迭代方案。\n\n**FDE 的典型工作流**：\n\n- **第 1 周**：和客户业务团队深度沟通，理解痛点和现有工作流\n- **第 2-3 周**：用 LLM API + RAG + 外部工具，快速搭一个可用的 prototype\n- **第 4-6 周**：迭代优化，处理 edge case，做评估和 benchmark\n- **持续**：把通用化的经验反哺给产品团队，沉淀成平台能力\n\n本质上，FDE 是\"特种兵模式\"——小团队、高权限、快迭代，直接在战壕里解决问题。\n\n\n\n## 为什么传统研发岗填不了这个坑？\n\n很多人会问：为什么不直接派后端工程师去？或者让产品经理兼着做？\n\n原因有三层：\n\n**1. 模型能力的\"非确定性\"打破了传统工程范式**\n\n传统软件工程的核心假设是：输入确定 → 输出确定。但 LLM 是概率模型，同样的输入可能给出不同输出。这意味着你需要一套全新的工程实践——prompt 版本管理、输出评估体系、fallback 策略、人工审核闭环。传统后端工程师如果没有系统学过这些，很容易踩坑。\n\n举个具体例子：你给客户做一个合同审查系统，传统规则引擎的做法是写正则匹配关键条款。但用 LLM 做，你需要考虑：同一类合同条款的表述差异有多大？模型漏检率怎么测？输出格式不稳定怎么兜底？这些问题在传统 SWE 体系里几乎没有现成答案。\n\n**2. 客户场景的\"碎片化\"要求快速学习能力**\n\nFDE 今天在律所，下周可能在医院。你不可能预先掌握所有领域知识，但你必须能在 1-2 周内理解客户的核心业务流程，并找到 AI 能切入的点。这种\"快速领域渗透\"能力，更接近咨询顾问而非传统工程师。\n\n**3. \"原型即产品\"的交付节奏**\n\n传统研发是：需求分析 → 设计 → 开发 → 测试 → 上线，周期数月。FDE 的节奏是：周一理解需求，周三出 prototype，周五给客户
