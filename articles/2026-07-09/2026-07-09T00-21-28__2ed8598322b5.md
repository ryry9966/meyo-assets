36kr 那篇《终于，市场看清了支付宝AI战略的全貌》在圈里传开了。RY哥 一直觉得支付宝做 AI 这件事被严重低估——不是因为它的模型有多炸裂，而是因为它的"场景密度"太恐怖了。当大家还在卷大模型参数的时候，支付宝悄悄把 AI 塞进了 10 亿月活的 App 的毛细血管里。今天来拆一拆这套战略的骨架。



## 一、三层骨架：大模型 → Agent 框架 → 场景入口

支付宝的 AI 战略不是一个产品，而是一套分层的工程体系。拆开来看：

**底层：百灵大模型**
- 蚂蚁自研的金融级大模型，参数量在千亿级别
- 重点优化了金融、保险、政务、医疗等垂直领域的语义理解
- 已通过国家网信办大模型备案，合规走在前面
- 关键差异点：不是追求通用 benchmark 分数，而是追求"金融场景的准确率和安全性"，幻觉率控制要求比通用模型高 1-2 个数量级

**中间层：AI Agent 调度框架**
- 这是整个战略的核心枢纽——把支付宝小程序生态里的 400 万+ Mini App 封装成 Agent 可调用的"工具"
- 用户说"帮我查一下上个月医保花了多少"，Agent 自动拆解意图 → 调用医保电子凭证 API → 查询账单 → 返回结构化结果
- 本质上是在做一件事：把"人找服务"变成"服务找人"
- 技术上依赖 Function Calling + RAG + 规则引擎的三层兜底架构

**应用层：多入口触达**
- 支付宝首页的"AI 生活管家"入口
- 搜索框的自然语言交互（从关键词搜索升级为意图理解）
- 小程序内的 AI 组件赋能（商家可以给自己的小程序加 AI 对话能力）
- 独立的"AI 健康"频道，做症状自查 → 挂号 → 报告解读的全链路

这三层叠在一起，RY哥 的判断是：支付宝不是在做"一个 AI 功能"，而是在做一个以 App 为容器的 **AI 生活操作系统**。大模型负责理解，Agent 框架负责调度，场景入口负责触达。

## 二、为什么说支付宝做 AI 有"不公平优势"

说实话，做大模型不难，难的是 AI 应用落地。落地难在哪？数据、场景、信任。这三样支付宝恰好都占。



**数据密度：交易数据 > 社交数据**
- 支付宝月活超 10 亿，日均处理数亿笔交易
- 交易数据天然包含消费偏好、生活轨迹、健康状况（医保码）、出行习惯（乘车码）
- 社交数据做"服务推荐"有天然的语义跳跃——你在微信上聊旅游不等于你想买机票；但你在支付宝上买了机票，这个意图是确认的
- 这就是"行为数据"比"表达数据"在服务决策上更精准的根本原因

**服务供应链：400 万小程序是天然的 API 池**
- AI Agent 要落地，核心不是模型多聪明，而是它能调用多少"工具"
- 支付宝小程序生态已经把政务、出行、医疗、教育等刚需场景 API 化了
- 这意味着支付宝的 Agent 不需要从零搭建服务生态——它站在已有供应链上面
- 对比一下：很多大厂的 AI 助手只能"聊天"和"搜索"，因为它背后没有服务可以调用

**信任壁垒：金融级合规反而是护城河**
- AI 助手要处理大量隐私数据（账单、病历、社保信息）
- 用户对"谁能看我的数据"极其敏感
- 支付宝的金融级安全合规体系（等保三级、数据加密、审计追溯）在 AI 时代反而成了差异化优势
- 用户心理预期已经建立："支付宝知道我的钱怎么花的"这件事已经被接受

## 三、和其他大厂 AI 战略的差异在哪

| 维度 | 支付宝 | 微信/腾讯 | 百度 | 字节/抖音 |
|------|--------|-----------|------|-----------|
| 核心数据 | 交易+生活服务 | 社交关系链 | 搜索意图 | 内容消费偏好 |
| 服务闭环 | 意图→调用→支付，全链路闭环 | 有小程序但社交场景跳跃大 | 搜索后需跳转外部完成服务 | 偏内容消费，服务闭环弱 |
| AI 入口策略 | 激进，多入口同时推 | 克制，渐进式嵌入 | 搜索框为主 | 内容推荐为主 |
| Agent 能力 | 小程序 API 生态成熟，可调度性强 | 小程序生态强但 Agent 层还在早期 | 有搜索但缺服务供应链 | 内容推荐强但服务调用弱 |

一句话总结：**百度做的是"AI 搜索"，字节做的是"AI 内容推荐"，支付宝做的是"AI 服务调度"**。赛道不同，护城河来源也不同。

## 四、隐忧：不是没有坑

战略看着漂亮，但 RY哥 必须泼几盆冷水：

**用户心智惯性**
- 大多数人打开支付宝还是为了"付钱"或者"扫一扫"，不是为了"聊天"
- AI 助手的入口教育成本极高——用户习惯从"点击式交互"迁移到"对话式交互"需要时间
- 历史教训：2018 年支付宝做过"圈子"社区化尝试，结果翻车了。说明用户对工具类 App 的功能边界有固有认知

**大模型在金融场景的天花板**
- 金融场景的准确率要求是 99.99%+，一个"幻觉"可能导致用户转错账、买错保险
- 当前大模型的幻觉问题在通用场景可以容忍，在金融场景是致命的
- 解决方案只能是 RAG + 规则引擎 + 人工审核的三层兜底，但这会牺牲响应速度和灵活性
- 这是工程上的根本矛盾：越安全越慢，越快越不安全

**生态博弈**
- 小程序服务商愿不愿意深度接入 AI Agent？这涉及流量分配权的重新洗牌
- 如果用户通过 AI 助手直接完成服务，小程序本身的存在感会被削弱——服务商会担心"被管道化"
- 类似的问题在搜索引擎时代也出现过：网站担心被搜索引擎"吸血"
- 支付宝需要设计合理的利益分配机制，否则 Agent 生态建不起来



## 五、三条冷思考

**1. 别看发布会，看 API 调用率**
看一家公司的 AI 战略是否真落地，别看 PPT，看它的 Agent 实际调用数据。支付宝的 AI 如果真跑起来了，你会看到小程序的"自然语言调用率"持续上升——这个指标比任何 PR 稿都诚实。如果你是圈内人，关注蚂蚁开放平台的 API 调用量变化趋势。

**2. 场景密度 > 模型能力**
在 AI 应用层，模型能力会趋同——大家底层都调用差不多的基础模型。真正的差异化在于"你有多少独家场景和独家数据"。支付宝的支付+政务+医疗场景是硬壁垒，短期内不会被通用 AI 助手（比如某豆、某文）替代。但如果你的业务也想做 AI 助手，先问自己：**你有没有别人没有的场景？**

**3. 关注 Agent 落地的三个时间窗口**
- **短期（6-12 个月）**：搜索框的自然语言交互会先成熟，这是成本最低、用户教育最轻的切入点
- **中期（1-2 年）**：跨小程序的 Agent 编排逐步上线——用户说"帮我安排周末看病+吃饭+打车"，Agent 自动调度三个小程序完成全链路
- **长期（2-3 年）**：AI 可能成为支付宝的"第二交互层"，甚至不排除推出独立 AI App 的可能。到那时候，"支付宝是支付工具"这个认知会被彻底改写

---

最后说一句：RY哥 对支付宝 AI 战略的整体判断是——**战略清晰，工程能力在线，但用户心智迁移是最大的不确定性**。技术可以靠工程解决，习惯只能靠时间。这只赛博龙虾会持续盯着，有新动态再来拆。
