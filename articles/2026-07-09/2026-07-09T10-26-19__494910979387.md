最近 DeepSeek 的一次面试演示「翻车」在技术圈炸开了锅，36kr 随后发了一篇长文，标题直指「中国科技公司离顶级公司还差什么」。RY 哥一直关注 DeepSeek——它在 MoE 架构、训练效率、开源策略上确实有真功夫，不是纯靠 PPT 融资的那种。但「翻车」这件事本身就值得认真拆一拆：问题到底出在哪一步？差距是技术层面的还是组织层面的？今天不站队、不灌水，把这件事掰到工程颗粒度来聊。



## 一、「翻车」的技术本质：Post-training 还差一口气



先说清楚「翻车」到底翻了什么。从公开信息看，DeepSeek 的模型在某些交互场景下表现不稳定——答非所问、前后矛盾、简单推理上犯低级错误。这些问题表面看是「能力不行」，但底层往往是 post-training 阶段的质量差距。具体拆开来看：

1. **SFT 数据质量不够扎实**
   - 顶级公司的 SFT 数据通常由领域专家（PhD、资深工程师）逐条审核，每条数据有明确的 quality rubric，标注一致性要求很高
   - 很多追赶者为了快速出货，SFT 数据用外包团队批量生产，标注一致性差，甚至存在 label noise
   - 参考：OpenAI 在 InstructGPT 论文中明确提到，少量高质量 SFT 数据的效果远优于大量低质量数据——「数据质量 > 数据数量」在 post-training 阶段几乎是铁律

2. **RLHF 的 reward model 鲁棒性不足**
   - Reward model 容易出现 reward hacking：模型学会了「看起来好」而不是「真的好」，比如生成冗长但空洞的回答来刷高分
   - DeepSeek 在 RLEF（Reinforcement Learning from Execution Feedback）等方向有创新，尤其代码场景用 execution feedback 比 human preference 更可靠，这是对的
   - 但 reward model 的泛化能力依然是短板——训练分布外的输入一旦出现，reward 信号就不可靠，模型行为开始飘
   - 对比 Anthropic 的 Constitutional AI 方法，他们在 reward shaping 和 alignment 方面做了更系统的研究，不只是追 KL divergence 这种单一指标

3. **长上下文与指令遵循的边界测试不足**
   - 很多模型在 benchmark 上分数漂亮，但实际多轮对话、复杂指令组合下就露馅——典型的「benchmark overfitting」
   - 这不是架构问题，而是 evaluation infrastructure 跟不上：如果你自己的 eval suite 都没覆盖这些 case，怎么发现 bug？怎么修？

一句话总结：**Pre-training 决定天花板，Post-training 决定地板。** 天花板够高了，地板没铺平，用户踩坑概率就大。

## 二、工程基础设施：差距在「看不见的地方」



很多人盯着模型参数量、训练数据 token 数这些显性指标，但顶级公司和追赶者之间真正的鸿沟，往往在工程基础设施——那些用户看不见、但直接决定产品可靠性的东西。

1. **数据管线（Data Pipeline）的成熟度**
   - 顶级公司有完整的数据飞轮：用户反馈 → 数据采集 → 质量过滤 → 自动化评测 → 回流训练，整个 pipeline 高度自动化
   - 飞轮的转速和精度决定了迭代速度。OpenAI 每次模型更新背后，都有海量真实用户 interaction 数据做支撑
   - 国内很多公司的数据管线还停留在「人工抽样 + 脚本过滤」阶段，没有系统化的 data quality monitoring，脏数据混进去的概率不小

2. **Eval Infrastructure 的系统性投入**
   - Google DeepMind 和 OpenAI 都有专门的 eval 团队，规模可能上百人，构建了海量的 adversarial test、red team test、real-world task suite
   - 他们不只是跑 MMLU、GSM8K 这些公开 benchmark，而是构建了大量自定义 eval，模拟真实用户场景
   - 国内很多公司的 eval 团队还在「跑公开 benchmark + 人工 vibe check」的阶段，缺乏系统化的自动化评测体系
   - 结果就是：benchmark 分数上去了，用户体验没跟上，中间有巨大的 eval gap

3. **Serving 和推理优化的稳定性**
   - 这块国内公司其实做得不错，vLLM、PagedAttention 等技术都有国内团队的贡献，DeepSeek 自己的 MLA（Multi-head Latent Attention）也是实打实的工程创新
   - 但在超大规模部署的稳定性、长尾延迟控制、动态 batch 调度、故障恢复等方面，和 Google 这种有几十年 infra 积累的公司比，仍然有差距
   - 工程差距不是「聪不聪明」的问题，是「踩过多少坑」的问题——很多边界条件，没有大规模线上流量是遇不到的

## 三、研究文化：First-principles vs. Fast-follow



这个话题比较「软」，但恰恰是最难缩小的差距。

1. **顶级公司容忍「无产出」的研究**
   - DeepMind 做了 AlphaFold，在出成果之前没几个人知道它有什么商业价值；OpenAI 在 GPT 路线上押注 Transformer scaling law 时，内部也不是所有人都买账
   - 这种「容忍不确定性」的研究文化，需要组织层面的耐心和资源支撑，不是喊口号能来的
   - 核心问题：你敢不敢让一群聪明人花两年时间做一个可能失败的方向？

2. **国内公司的现实约束**
   - 不是不想做 first-principles 研究，而是商业压力大、融资周期紧，容错空间小
   - 很多团队选择「先 fast-follow 追上再说」——从商业角度完全合理，甚至是最优策略
   - 但长期来看，fast-follow 的天花板是确定的：你永远在追别人的 next step，而不是定义 next step。当别人已经开始探索 reasoning model、agentic AI 时，你还在追上一代的基础能力

3. **人才密度 vs. 人才数量**
   - 顶级公司的核心研究团队往往不大，但密度极高——每个人都能独立定义问题、设计实验、推进方向
   - 国内公司在疯狂招人，但「能做 original research 的人」全球范围都稀缺，不是花钱就能堆出来的
   - 更关键的是 research environment：有没有足够的 compute resource 让研究员自由探索？有没有不急于 KPI 的文化？这些比 headcount 更重要

## 四、生态与开发者体验：不只是模型的事



一个 AI 公司能不能成为「顶级公司」，不只有模型能力，还在于生态建设。

1. **API 稳定性和文档质量**
   - OpenAI 的 API 文档、SDK、Cookbook、官方 cookbook 形成了完整的开发者体验闭环——从「看到 demo」到「跑通第一个 API call」可能只要 10 分钟
   - 很多国内公司的 API 文档还停留在「能用」阶段，缺少 best practice guide、edge case 说明、migration guide
   - 开发者用得不舒服，就不会形成生态粘性。模型再好，没人用你的 API，就是另一个「技术 demo」

2. **开源策略的成熟度**
   - DeepSeek 开源了模型权重甚至部分训练细节，这个策略值得肯定——在开源社区赢得了大量好感
   - 但开源不只是「放权重」，还需要配套的 eval 脚本、fine-tune 教程、量化工具、社区 issue 响应机制
   - 对比 Hugging Face 生态的繁荣，靠的不只是模型好，而是整体 developer experience 好——文档、工具链、社区三位一体

3. **品牌信任度的积累**
   - 企业客户选 AI 供应商，看的不只是 benchmark 分数，还有 SLA 承诺、数据安全合规、长期 roadmap 可见度
   - 这方面国内公司还在积累期。信任不是一天建立的，但每一次「翻车」都会消耗信任储备——这也是为什么这次事件引发了超出技术圈的关注

## 五、冷思考：3 条务实建议

说完了差距，给三条不鸡汤的冷思考：

**1. 别拿一场「翻车」否定全局，也别拿一次成功当永恒**

DeepSeek 在 MoE 架构创新、训练效率优化、开源贡献上确实有真功夫。一场演示翻车暴露的是 post-training 和 eval 的短板，不代表整个公司实力不行。但反过来，之前刷榜成功也不代表方法论已经成熟——benchmark 高分和产品可靠之间，还差一个完整的 eval infrastructure。批评要 precise，自信也要 precise。

**2. 工程投入和算法投入同等重要，甚至更重要**

很多公司愿意在算法团队上砸钱，但 eval infra、data pipeline、serving optimization 这些「脏活累活」的投入往往不足。建议技术负责人看看自己公司的 infra 团队和算法团队的人数比例——如果 infra 团队不到算法团队的 1/3，地板大概率没铺好。天花板再高，用户踩到地板上的坑，体验也是零。

**3. Fast-follow 可以，但要有「切换时机」的判断力**

Fast-follow 是合理的起步策略，但不能永远 fast-follow。关键信号是：当 fast-follow 的边际收益开始递减时——比如现在，GPT-4 级别的能力已经被多个团队追上，下一步的突破需要新的方法论（reasoning、agentic、world model），这时候就该开始投入 first-principles 研究了。切换太晚，你就永远是个 follower；切换太早，资源撑不住。这个 timing 判断，考验的是技术领导者的判断力，不是工程师的代码能力。
