你大概已经看过这些消息：OpenAI 被曝接触博通、台积电，想搞自己的推理芯片；特斯拉的 Dojo 超算已经迭代了两代；Google 的 TPU 进化到 v5p；微软连续推出 Maia 100；就连 Meta 也没闲着，MTIA 系列正往下一代走。另一边，英伟达的 GPU 依然供不应求，一张 H100 能卖出一辆小轿车的钱。

这就引出一个问题：明明有现成的“铲子”，为什么这些顶尖 AI 公司宁愿花几十亿美金、养上千人的团队，也要自己跳进造芯片的火坑？

核心原因既不是“去英伟达化”的意气之争，也不是单纯的成本计算。当 AI 模型大到一定程度，通用芯片的效率天花板就成了公司生死线。这背后的逻辑，远比“省钱”复杂得多。

## 1. 通用 GPU 的“能效墙”与“内存墙”

做一个不太准确的比喻：用通用 GPU 跑 AI，有点像用跑车去送货。马力很大，面子很足，但每公里的燃油和轮胎磨损，会让你怀疑人生。模型训练和推理，就是那个越来越沉重的货箱。

- **算力利用率低**：一个大模型实际运行时有大量非矩阵计算、动态 shape 和控制流。通用 GPU 的架构为了兼容各种图形和计算任务，有大量对 AI 没用的固定功能单元。结果就是，芯片面积和功耗花出去了，但真正用在矩阵乘加上的能量效率并不高。Google 的 TPU 第一次证明，砍掉所有图形功能，只留 systolic array，能用更小的功耗堆出更高的 AI 算力。
- **内存带宽是隐形杀手**：大模型参数动辄上百 GB，推理时每一步都要“吞吐”海量数据。HBM（高带宽内存）虽然快，但带宽增长远追不上模型规模膨胀。更致命的是，通用 GPU 的缓存层次并非为 Transformer 的特定访问模式优化。自研芯片可以设计更激进的 memory hierarchy，比如将 KV cache 直接怼在近存计算单元旁边，从而绕开“搬数据”的瓶颈。
- **芯粒（Chiplet）的诱惑**：传统单片 GPU 受光罩极限和良率制约，算力没法无限堆。AI 公司自己设计芯片时，能把逻辑晶片和 HBM 晶片通过先进封装拼成一个“乐高”，突破带宽和面积的物理限制。AMD 的 MI300X 已经这么干了，但自研者的想象空间在于：我可以定义晶片之间的数据流协议，而不是遵循某个通用互联标准。

## 2. 不只是省钱：自研芯片的真正算盘

把 GPU 价格打到骨折？想多了。摊薄研发成本需要海量出货，单一公司的采购量往往不够。那真实驱动力是什么？

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-13/cfc3051f15e1a94b.png)

- **第一性原理的性能功耗比**：如果 1000 亿参数模型要做实时服务，每次推理必须在 50ms 内完成，同时功耗不能超过 300W。用通用 GPU 很可能过不了线。自研芯片可以从指令集、数据通路、缓存层级到物理实现全面定制。例如，可以为 Transformer 的 Attention 算子设计专门的专用电路，用几十个晶体管完成原本需要几百个指令的运算，延迟和能耗都降一个数量级。
- **平台锁定与生态护城河**：拥有了自己的芯片，云厂商（如亚马逊 Trainium）、自动驾驶公司（如特斯拉 FSD 芯片）能将硬件、编译器、框架、模型服务深度耦合。客户一旦习惯了这套开箱即用的垂直体系，迁移成本就会高得惊人。苹果的 M 系列芯片与 Core ML 的配合就是教科书案例——不是最强的算力，但软硬协同带来的能效和延迟优势，让开发者根本不想跳船。
- **供应链的议价权**：哪怕自研芯片最终只覆盖了自己 30% 的算力负载，剩下的仍然买英伟达，谈判桌对面的态度也会完全不一样。有“第二货源”选项，企业就不会在 GPU 断供或涨价时被捏住喉咙。这个安全边际的价值，很难用财务报表衡量。
- **数据飞轮的特殊需求**：特斯拉的 Dojo 不仅要训视觉模型，还要处理海量视频片段，训练数据里带时间戳、带多模态对齐。通用芯片对此类负载的支持并不友好。自研芯片可以把数据预处理、格式转换这些脏活累活集成到硬件管线里，直接把“原始数据”变成“训练就绪”的 token。

## 3. 造芯片的“至暗时刻”为什么没劝退他们？

造芯有多难？一次 5nm 流片成本动辄数亿美元，架构设计、验证、后端物理实现、驱动和编译器开发，每一步都是地狱级难度。但 AI 公司有属于自己的“捷径”。

- **Chiplet + 成熟 IP**：并不需要从零发明轮子。大部分自研芯片内部仍使用 Arm 的 CPU 核来做控制，购买成熟的 DDR PHY、PCIe 控制器等 IP，再用自家的 AI 加速器逻辑把它们串起来。这种搭积木的方式，让研发风险大大降低。
- **制程红利还在**：从 7nm 到 3nm，每代工艺能带来大约 30% 的能效提升。即便架构不怎么优化，仅仅把已有设计往新制程上搬，也能获得显著收益。这让自研芯片的起步门槛变低——第一代只要调通，先解决有无问题。
- **编译器的军备竞赛**：很多 AI 公司通过收购编译器团队或直接使用开源 MLIR 生态，绕过了最难啃的软件栈。Google 的 XLA、Meta 的 Glow 等，为自家硬件生成高效代码的能力已经接近 CUDA 水平，但只适用于特定算子集。这种“有选择性”的优化，反而让迭代更快。
- **反直觉：AI 设计 AI 芯片**：用强化学习做布局规划、用生成式模型自动生成验证用例、用大语言模型写设计文档……这些不是科幻。Google 已经用 AI 优化了自己的 TPU 布局，把某些模块的面积缩减了 6%。造芯周期从数年缩短到 18 个月，并非神话。

## 4. 这场竞赛的终局会是“人人有芯”吗？

不太可能。但确实会形成多极格局。

- **超大规模玩家**（Google、Amazon、Microsoft）会把自研芯片作为云服务的基础设施，与英伟达共存。在特定任务上，自研芯片的性价比会吊打通用方案；但在通用 HPC 任务或小模型微调上，英伟达的 CUDA 生态依旧是事实标准。
- **垂直领域玩家**（特斯拉、字节、OpenAI）会聚焦于自己的核心负载，做出极度偏科的专用架构。比如只擅长 Transformer 推理、只擅长视频 tokens 压缩。这种芯片无法卖给第三方，因为换一个模型结构就废了——但他们对自家模型的路标足够清晰，能保证未来三代都适用。
- **英伟达的反制**：黄仁勋的应对是“加速一切”和“定制开放”。DGX Cloud 让你在云端用 GPU，买不到芯片的公司也能用上；同时英伟达也偷偷为头部客户定制专属 SKU，比如给某些云厂商的特供版 H100。这是用“软定制”延缓客户自研的冲动。

## 冷思考：自研芯片是必修课，但不是万能解

别被带节奏，自研芯片不是每个团队都该做的梦。最后给几条务实判断：

1. **先算经济账的精髓**：不要只看料号成本。要算“全生命周期服务成本”，包括硬件折旧、电费、软件移植、运维人力。如果自研芯片比购买等效 GPU 方案的总成本低不到 40%，这事不值得启动。多数芯片项目死在了“看起来省 2 亿，实际亏了 5 亿”的账上。
2. **软件生态先于硬件定义**：在画第一个晶体管之前，先把 PyTorch 算子在模拟器上跑通，把编译器后端的测试集铺满。硬件可以流片失败一次，软件栈如果一年内跟不上上游框架迭代，芯片出生即落后。建议采取“软件先遣、硬件跟进”的节奏，用 FPGA 或现有 GPU 做原型验证加速器逻辑。
3. **留好退路：兼容性设计**：如果没有意愿把全家的云原生基础设施都改成自己的护城河，那么至少要支持标准的开放运行时，比如 OpenXLA 或 Unified Acceleration Foundation 的接口。万一自研道路不顺，能够快速把业务切回通用算力，而不需要重写整个 Serving 管线。做“可热插拔”的专用加速卡，比绑定整个 data center 架构的做法更务实。

自研芯片本质上是一场“用确定性投资换取不确定性优势”的博弈。算力自由，终究是 AI 公司长大成人后不得不自己啃下的硬骨头。
