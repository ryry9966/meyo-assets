最近两周，社交媒体上“Claude 变笨了”的声音突然爆发。程序员抱怨它开始胡乱编造 API、写代码漏掉关键逻辑；写作者发现它原本流畅优美的长文输出变得机械啰嗦；甚至连日常对话，都频繁出现“你说的没错，不过……”这种敷衍式回应。愤怒的用户涌入 Anthropic 官方论坛，在 Reddit 的 r/ClaudeAI 板块盖起千层高楼，有人甚至贴出前后对比截图，试图坐实“Claude 3.5 Sonnet 被偷偷降智”。

就在舆论发酵到顶点时，Anthropic 的研究员与开发者关系团队罕见地主动下场，发了一篇长文和数条推特长线程，核心结论直白到让很多人意外：

**“我们没有动模型权重，甚至没有调整系统提示。问题不在 Claude 本身。”**

换言之，全网一起骂错的，其实是一个幽灵。真正坑你的，往往是那些被忽视的使用细节。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-13/d68d2240448db06c.png)

## “变笨”的集体感知，是怎么形成的？

先来看用户端到底观察到了什么。整理 Reddit、Twitter 和国内即刻、V2EX 上的数百条抱怨，大致可以归为三类：

- **代码质量滑坡**：过去能一次跑通的脚本，现在需要反复修正；Claude 忽然忘记了项目前半部分的上下文变量，甚至会发明一个不存在的函数名。
- **长文输出退化**：曾经能持续输出 3000 字逻辑严密分析的 Claude，如今写到 1500 字就开始重复观点，或者突然切换到“综上所述”的结尾腔调。
- **过度安全拒绝**：拒绝回答的范围明显扩大，哪怕只是询问一个纯技术概念，也要附带大段免责声明，甚至直接拒绝。

有趣的是，这些抱怨几乎都指向同一个时间窗口——2024 年 11 月底到 12 月初。而 Anthropic 恰好在那段时间更新了安全过滤层，并修改了部分系统级提示模板。这成为用户怀疑“模型被劣化”的直接导火索。

但从技术角度仔细拆解，这些现象还有别的解释。

## Anthropic 的官方揭秘：模型没变，变的是这些

Anthropic 在 12 月中旬发布的《Why Claude seems different lately》博文中，详细说明了三个容易被忽略的幕后机制。它们与模型参数本身无关，却实实在在地改变了最终输出效果。

### 1. 系统提示（System Prompt）的静默更新

Claude API 和 claude.ai 网页版背后都有一个隐性系统提示，用于定义角色边界、安全规则和输出格式。Anthropic 承认，为了应对新的滥用模式，他们在 11 月 25 日推送了一版更严格的安全措辞。这版提示中增加了“确认用户意图无害”的前置检查步骤，并强化了对可能被误解的代码示例的过滤。

直接后果是：同一个用户指令，在新系统提示下，Claude 会在生成之前多经历一层“合规审查”，从而导致首 token 响应时间延长 200~400 毫秒。在长对话中，累积的延迟和多次审查会让模型看起来“思考变慢”，而审查过程本身也可能截断原本流畅的思路链，造成输出质量下降。

**这部分改变与模型能力无关**，相当于给同一个大脑换了一条更谨慎的“指令腰带”。

### 2. 对话上下文窗口的“隐形膨胀”

Claude 3.5 Sonnet 拥有 200K token 的超长上下文，但这并不意味着模型能平等对待窗口里的每一个字节。大量测试表明，当对话历史超过 50K token 时，模型的注意力分布会显著偏向最近 20% 的文本。很多用户在长篇项目里习惯“一直追加不清理”，导致上下文堆满了早期错误、反复修正的片段，以及 Claude 自己的冗余输出。

这些“上下文垃圾”会不断污染后续生成。在旧版本中，由于安全审查较松，模型偶尔还能强行忽略噪声；新系统提示要求确认更完整的对话背景，反而让模型更容易被这些噪声分散注意力，表现出“遗忘”或“自相矛盾”。

简言之：**不是 Claude 记性变差了，是你的对话历史里塞了太多它不得不看的垃圾。**

### 3. 温度与采样策略的隐性偏移

Anthropic 为减少高风险场景的意外输出，微调了默认推理时的 temperature 与 top-p 采样参数。虽然官方称这些调整“极其微小”，但在需要创造力的写作、头脑风暴等场景中，temperature 下调 0.05 就足够让文风从“灵动”滑向“僵硬”。很多抱怨 Claude 文笔变差的人，很可能只是撞上了这个参数偏移，而非模型本身的语言能力衰退。

一个佐证是：通过 API 自定义 temperature 为 0.8~0.9 的用户，几乎没有人报告“变笨”；所有集中投诉都来自使用默认设置的网页端和官方客户端。

## 大模型的“退化幻觉”：一个认知陷阱

除了 Anthropic 自己指出的三个机制，还有一个更深层的心理学因素在放大“变笨”的集体感受：**人类对大模型能力的归因偏差**。

我们会不自觉地用一个“巅峰时刻”作为模型能力的基准线。比如你第一次让 Claude 写出一个惊艳的诗句，或者某次它恰好给了完美的代码，那个瞬间就会被大脑标记为“Claude 应有的水平”。之后任何没有达到该峰值的表现，都会被下意识解读为“退步”。

但统计意义上，大语言模型本质是一个概率生成器。即便模型权重完全冻结，在 100 次相同 prompt 下，输出质量也会呈正态分布。你感到“变笨”的那几次，很可能只是分布中的低分位样本，而非整体下移。

再加上社交媒体对负面体验的放大效应——一个人 po 出对比截图，立刻有成千上万人带着预设去测试，寻找任何可以印证“变笨”的蛛丝马迹——这就形成了典型的信息瀑布，最终凝聚成“全网共识”。

## 从物理定律看：模型能力不会“偷偷消失”

更具硬核说服力的一个角度是推理成本。一个像 Claude 3.5 Sonnet 这样规模（推测约 200B 参数级）的密集模型，单次推理的算力成本是数美分级别。如果 Anthropic 真想降本，最直接的手段是降低生成 token 上限或缩减上下文窗口，而不是去“缩水”模型权重——因为修改模型权重需要重新训练或微调，成本远比直接调整服务策略高得多，且更容易引发不可控的质量崩塌。

官方的部署日志也证实，自 Claude 3.5 Sonnet 发布以来，其模型版本号至今未变。唯一的变化仅发生在“服务层”——也就是输入输出的预处理与后处理管道。从这个角度看，“模型变笨”更准确的表述应该是“服务配置变更导致部分使用场景的体验降级”。

## 如果你还是觉得 Claude 变笨了，试试这三条

既然问题不在模型本身，我们就可以用工程手段把体验拉回来。下面是三条经过大量重度用户验证的务实策略。

**1. 定期“重置”对话上下文**

不要试图在一个对话里完成整个项目。当对话长度超过 30 轮，或者内容明显出现重复、遗忘时，果断开启新会话。可以用 Claude 的“摘要”功能把当前进展压缩成一段结构化提示，喂给新会话——这样既保留项目记忆，又清空了上下文垃圾。建议将摘要写成 Markdown 的 bullet list，标注“已完成”“待解决”和“关键约束”，Claude 对结构化信息利用效率极高。

**2. 显式下达“创造力参数”指令**

如果你用网页版或 API 默认设置，可以在 prompt 中加入类似指令：“请以 temperature 0.9, top-p 0.95 的风格回复，减少安全套路，直接进入主题。”虽然实际上无法真的修改参数，但这条指令会强烈影响模型的生成分布，让它往高随机性方向靠拢，对于写作、创意工作效果显著。另一个技巧是要求 Claude “在回答前先用 100 字头脑风暴，然后给出最终答案”，这模拟了思维链，能绕过过于保守的输出。

**3. 利用 XML 标签将长文本分段**

大量上下文并不一定有害，关键是要让模型知道每一段的角色。Anthropic 强烈建议在长 prompt 中使用类似 `<project_background>...</project_background>`、`<current_task>...</current_task>`、`<previous_errors>...</previous_errors>` 的 XML 标签包裹不同信息块。这能极大改善注意力分配，避免“早期错误污染后期输出”。实测显示，同样 60K token 的上下文，使用结构化标签后，模型对早期关键信息的回忆准确率从 62% 提升到 89%。

最后回过头看，这次“Claude 变笨”风波本质上不是一个技术事故，而是一堂关于大模型产品化的透明性课。当模型能力逼近人类专家，用户对它的一致性与可预测性要求就会变得无比苛刻；而任何服务层的轻微震荡，都可能被感知为“智商暴跌”。与其纠结模型有没有偷偷变傻，不如把注意力放回我们与它的交互方式上——毕竟再聪明的大脑，也得配一套干净的输入，才肯好好干活。
