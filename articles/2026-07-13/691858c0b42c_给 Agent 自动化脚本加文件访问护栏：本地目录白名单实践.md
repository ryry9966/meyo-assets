# 给 Agent 自动化脚本加文件访问护栏：本地目录白名单实践

## 背景：当脚本自由触碰文件系统时

在 OpenClaw、Agent 工作流或 MCP 工具链中，我们经常需要通过自动化脚本完成文件处理任务：读配置、写日志、生成报告、临时存储数据。这些脚本通常以脱离人工审查的方式运行，这意味着一个拼写错误、一个未处理的变量，或者模型幻觉生成的一条 `rm -rf /home/user/*` 就可能引发灾难。

多数情况下，我们会为 Agent 分配一个专属工作目录，但还是会面临以下问题：

- 脚本可能通过绝对路径或符号链接意外访问到敏感目录（如 `~/.ssh`、`/etc`）。
- 库代码或第三方依赖中可能存在不安全的文件操作。
- 模型生成的命令可能包含路径穿越（`../`）绕过预期边界。

为了把风险限制在可控范围内，工程上常见的做法是给自动化脚本加一层**文件访问护栏**：以本地目录白名单的形式，强制所有读写操作只能发生在指定的目录集合内。

本文以 Python 脚本为例，展示一种轻量、可落地的实现方案，可以直接嵌入 OpenClaw 的工具函数或 MCP server 中。

## 问题建模

目标很明确：对任意的文件 I/O 操作，在执行前检查其最终操作路径是否位于一个预定义的白名单目录内。如果是，放行；否则拒绝，并记录告警。

但是，路径检查并不是简单的前缀匹配。需要考虑：

- **路径规范化**：`./data/../config` 应该解析为绝对路径，消除其中的 `.` 和 `..`。
- **符号链接解析**：`/workspace/link` 可能指向 `/etc/passwd`，需要解析真实路径。
- **多级权限**：也许允许写入 `/tmp/agent-work`，但禁止读取 `/tmp/other`。
- **不同操作类型**：读写、创建、删除需要区分，某些目录可能只允许读。

一个健壮的白名单检查函数是护栏的核心。

## 实现步骤

### 1. 定义白名单模型

用一个简单的数据类存放目录路径和允许的操作模式。我们将模式表示为字符串标志的组合，例如 `"rw"` 表示可读可写，`"r"` 表示只读。

```python
from dataclasses import dataclass

@dataclass
class WhitelistEntry:
    path: str        # 已规范化的绝对路径
    mode: str       # 'r', 'rw'
```

配置可以从环境变量或 JSON 文件注入：

```json
{
  "whitelist": [
    {"path": "/home/agent/workspace", "mode": "rw"},
    {"path": "/tmp/agent-cache", "mode": "rw"},
    {"path": "/usr/share/agent-readonly", "mode": "r"}
  ]
}
```

### 2. 实现路径安全校验

核心校验函数需要做三件事：路径标准化、符号链接解析、白名单判断。

```python
import os

def is_path_allowed(requested_path: str, mode: str, entries: list[WhitelistEntry]) -> bool:
    # 1. 转为绝对路径并规范化
    abs_path = os.path.abspath(requested_path)

    # 2. 解析可能存在的符号链接，获得真实路径
    #    注意：路径可能尚未存在，此时 realpath 无法解析，需要逐级处理
    try:
        real_path = os.path.realpath(abs_path)
    except OSError:
        real_path = abs_path  # 文件不存在时简单退化

    # 3. 检查是否落在任一白名单条目内
    for entry in entries:
        # 确保白名单路径本身也是规范化的绝对路径
        if real_path.startswith(os.path.join(entry.path, '')) or real_path == entry.path:
            if mode in entry.mode:
                return True
    return False
```

**要点**：使用 `startswith` 时要在目录后追加分隔符，防止 `/var/app` 匹配到 `/var/app-other`。即 `real_path.startswith(entry.path + os.sep)` 或 `real_path == entry.path`。

### 3. 包装文件操作

在工具函数或脚本入口处，对文件操作进行代理。例如，自定义 `open` 包装器：

```python
import builtins

class FileGuard:
    def __init__(self, entries):
        self.entries = entries

    def safe_open(self, file, mode='r', *args, **kwargs):
        # 提取操作类型
        if '+' in mode or any(c in mode for c in 'wa+'):
            required_mode = 'rw'
        else:
            required_mode = 'r'
        if not is_path_allowed(file, required_mode, self.entries):
            raise PermissionError(f"Access denied: {file}")
        return builtins.open(file, mode, *args, **kwargs)
```

更彻底的方式是替换 `os.open`、`builtins.open` 或使用 `sys.addaudithook` 拦截所有文件事件（Python 3.8+），但简单的包装已满足多数 Agent 脚本场景。

### 4. 集成到 MCP 工具或 OpenClaw 插件

如果是 MCP server 中的一个工具，只需要在执行前初始化一个全局的 `FileGuard`，并在工具函数中显式调用 `safe_open`。对于遗留代码，可以用 monkey patch 临时替换内建 `open`，但务必在 Agent 任务结束后恢复，避免影响到框架本身。

**示例配置加载与初始化：**

```python
import json

def load_guard(config_path="file_whitelist.json"):
    with open(config_path) as f:
        config = json.load(f)
    entries = [WhitelistEntry(e['path'], e['mode']) for e in config['whitelist']]
    return FileGuard(entries)
```

## 踩坑记录

### 路径存在性导致符号链接解析失败

`os.path.realpath` 要求路径已经存在才能解析整个路径的符号链接。如果脚本要创建 `/workspace/newdir/file.txt`，而 `newdir` 还不存在，`realpath` 会失败。我的做法是：先逐级检查存在的父目录，对存在的部分调用 `realpath`，不存在的部分使用 `abspath`。这是一个经典缺陷，很多工具未处理好。

### Windows 兼容性

在 Windows 上，路径分隔符和驱动器号会带来额外麻烦。如果环境包含 Windows 节点，建议使用 `pathlib.Path`，用 `Path.resolve()` 替代 `os.path.realpath`，并在比较时统一大小写。本文场景以 Linux 为主，但可移植性需提前设计。

### 白名单遗漏隐藏目录

模型可能生成路径如 `/workspace/.hidden/output`。白名单通常只包含了 `/workspace`，所以子目录会被自动允许。但如果是 `/workspace/.ssh` 这样的敏感点，就需要更细粒度的规则。可引入黑名单机制，或禁止已存在的隐藏目录写操作，但复杂度会上升。折中方案是：为 Agent 分配专用空目录，内部结构完全不受限，风险可控。

### 性能开销

每次文件操作都进行路径校验会带来额外开销，尤其在大量小文件读写时。可以将白名单路径预编译为 Path 对象并缓存校验结果，但鉴于 Agent 脚本通常不是性能热点，简单实现即可。

## 可复用建议

- **最小权限原则**：Agent 工作目录严格限制为一个空目录，白名单中只包含该目录和临时缓存目录。即使脚本失控，破坏也被局限。
- **与现有权限框架结合**：如果使用容器，直接挂载只读卷或使用 `Landlock` 等内核安全模块会比应用层护栏更彻底。本文方法适合没有容器环境的轻量场景。
- **统一工具化**：将 `FileGuard` 封装成一个独立 pip 包，提供 `@guard` 装饰器，装饰在工具函数上，自动根据配置校验函数内所有文件访问。这样可以快速接入多个项目。
- **日志与告警**：每次拒绝访问时输出结构化日志，包含时间、请求路径、操作类型、来源脚本名，便于安全审计。

## 总结

给自动化脚本加本地目录白名单是一种性价比很高的安全护栏。通过规范化路径、解析符号链接、简单的 `startswith` 白名单检查，就能有效防止 Agent 脚本逃逸到不可预知的区域。虽然应用层检查无法替代系统级隔离，但对于日常的 OpenClaw 工具开发和 MCP 工具实现来说，这一层薄薄的保护足以让运维者睡得更安稳。

核心代码不到 50 行，配置清晰，集成方便——或许是每个 Agent 工程都应该内置的基础能力。
