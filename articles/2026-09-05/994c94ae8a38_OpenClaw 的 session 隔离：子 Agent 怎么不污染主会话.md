## 背景

跑自动化任务时，主会话很容易被塞满：读文件、跑脚本、翻日志，几个回合下来上下文里全是中间产物，真正要紧的决策上下文反而被挤掉。OpenClaw 的思路是把「干活」和「决策」拆开：主会话负责编排，子 Agent 在独立 session 里执行，结束后只把结果摘要交回来。

## 问题

不理解隔离边界时，常见三类翻车：

1. **以为子 Agent 能看到主会话历史**——结果它「失忆」，任务跑偏；
2. **把大段主会话原文塞进子 Agent 的 prompt**——隔离形同虚设，主会话照样被撑爆；
3. **隐性污染**：子 Agent 直接写共享状态（文件、配置、全局工具状态），主会话后续读到被改过的数据，排查成本极高。

## 做法

以 spawn 子 Agent 的机制为例（具体工具名以你所用版本为准）：

1. **明确契约**。子 Agent 的 prompt 只包含：任务目标、必需输入、期望的输出格式。不贴整段历史。
2. **显式传参**。需要的上下文从主会话里摘出来、压缩后再传，比如只传相关文件路径和关键约束。
3. **限定工具与权限**。只挂完成该任务必需的工具，避免它顺手做出范围外的事。
4. **收敛输出**。要求子 Agent 以结构化结果结束（摘要 + 关键数据 + 异常），主会话只注入这条结果，不回读子会话全文。
5. **记录 session id**。把子会话 ID 写进日志，出问题时单独回放子会话，而不是在主会话里考古。

实际效果：子 Agent 的全部中间对话、工具调用、报错重试都留在它自己的 session 里，主会话上下文只多一条结果消息——上下文增长从 O(子任务全过程) 降到 O(结果摘要)。

## 踩坑点

- 子 Agent 默认看不到主会话历史，这不是 bug，是设计。需要的信息必须显式传。
- 结果摘要太短丢关键信息，太长稀释主会话。建议约定「结论 + 数据 + 异常」三段式，控制在几百字内。
- 并发 spawn 多个子 Agent 时，别让它们写同一个文件或同一个状态键——隔离了上下文，不等于隔离了副作用。
- 超时和重试要在 spawn 时想清楚，挂死的子任务占资源，主会话还等不到结果。
- 部分插件工具带全局状态（登录态、工作目录），子 Agent 用完状态可能已变，主会话后续步骤要做校验。

## 可复用建议

- **把子 Agent 当纯函数设计**：显式输入 → 隔离处理 → 结构化输出。输入输出越规整，编排越稳。
- **主会话保持指挥官角色**：只做拆解、分派、汇总，不亲自干重活。
- **沉淀子任务模板**：标准 prompt 结构、标准结果格式、标准日志字段，减少团队重复踩坑。
- **多级子 Agent** 要注意每级摘要的信息损耗，关键决策数据宁可在主会话留底。

## 总结

session 隔离的价值不是「子 Agent 有自己的对话」，而是让主会话的上下文始终为决策服务。管住三件事——传什么进去、允许它动什么、拿什么回来——子 Agent 就是干净的工具，而不是主会话的污染源。
