## 背景

大多数 AI 助手默认是被动应答：你发消息、它回复、会话结束。问答场景够用，但作为个人助理很别扭——真正有价值的是在你没开口时就注意到事情：日报该发了、证书快过期了、某个服务半夜连续报错。

OpenClaw 的架构天然适合做这件事：Agent 常驻运行、能调工具、有心跳（heartbeat）机制周期性唤醒。这篇帖记录我把它从"应答机"调成"克制的主动助手"的过程。

## 问题

"主动"容易做，难在做好。朴素做法（定时醒来、想说什么说什么）几乎必翻车，归结为三个问题：

1. **何时说**，"值不值得打扰用户"全靠模型临场发挥，不是沉默就是刷屏；
2. **说什么**，没有结构化的主动行为定义，每次醒来重新发明一遍检查逻辑；
3. **说几次**，没有状态去重，磁盘告警能每小时提醒一遍。

## 做法

我的落地分四步：

**1. 心跳只做检查，不做输出。** 心跳 prompt 里明确：醒来只执行检查类工具（读状态文件、调监控 MCP、看日历），结论写入本地 `observations.md`，默认不给用户发消息。

**2. 用规则定义"什么值得说"。** 在 AGENTS.md 写清推送白名单：任务失败、deadline 剩 24h 内、外部服务不可用，三类可立即推送；其余只落日志，等晚间汇总。判断标准写成规则，不指望模型每次自己掂量。

**3. 确定性事件走 cron，模糊判断走心跳。** 每天 9 点日报、每周清理临时文件，用定时任务直接触发，可靠且便宜；心跳只负责"我没想到但值得注意"的长尾发现。两者混用是常见错误。

**4. 状态文件去重。** 主动消息发出前先查 `notified.json`，key 用"事件类型 + 资源标识"，同 key 24 小时内不重复推送。这是解决刷屏性价比最高的手段。

## 踩坑点

- **心跳间隔贪短。** 最初设 5 分钟，一天 token 开销比正常对话还高。降到 30 分钟加 cron 兜底，成本降一个量级。
- **心跳醒来"顺嘴"回复。** Agent 有时把检查结果当对话直接发到聊天渠道，用户半夜收到"一切正常"。必须写死：心跳上下文中禁止主动发消息，除非命中白名单。
- **上下文膨胀。** `observations.md` 只追加不清理，一周后心跳携带的上下文明显拖慢响应。改成只带最近 N 条加摘要。
- **时区问题。** cron 用了 UTC，"晚间汇总"变成早上八点推送。

## 可复用建议

1. 三级输出通道：日志（默认）→ 每日汇总 → 立即推送，主动消息必须显式声明级别。
2. 触发规则进配置和 prompt；模型负责发现，规则负责放行。
3. 所有主动行为幂等化：状态文件 + 去重 key，重启、重试都不应造成重复打扰。
4. 设静默时段（如 23:00–8:00 只放行 P0 级推送）。
5. 新规则先跑一周"纯日志模式"，人工 review 触发记录，误报率可接受再放开推送。

## 总结

主动能力的关键不是"让 agent 更聪明"，而是装上节流阀：**发现靠模型，决策靠规则，输出靠通道分级**。OpenClaw 的心跳 + 定时任务 + MCP 工具链足够搭出这套结构，剩下的主要是忍住"让它多说一点"的冲动，好的主动助手，标准是用户几乎注意不到它醒着。
