## 背景

给 Agent 接上 shell 和文件工具后，最大的心理负担不是它写不出代码，而是它可能执行一条你没预料的删除命令。自动化任务往往无人值守，一旦路径判断出错，损失是真实文件。OpenClaw 的设计假设很直接：**LLM 一定会犯错，安全模型必须在它犯错时兜底**，而不是指望提示词里写一句"请小心"。

## 问题：误删实际怎么发生

复盘社区里的真实案例，误删路径高度相似：

1. **路径幻觉**：模型把工作目录记成上一轮会话的路径，`rm -rf ./build` 落在了别的项目上；
2. **通配符扩大**：变量为空时 `rm -rf $DIR/*` 展开成 `rm -rf /*`；
3. **符号链接逃逸**：workspace 里一个指向家目录的软链，让"删 workspace 内文件"变成删外部文件；
4. **工具混用**：文件工具做了校验，但同会话还挂着一个不受限的 bash 工具，模型绕道执行。

这四类问题靠 prompt 约束都不可靠，必须在执行层解决。

## 做法：五层防御，逐层收窄

OpenClaw 的 sandbox 是分层模型，任何一层被绕过，下一层还能接住：

1. **根目录隔离**：Agent 进程跑在以 workspace 为根的隔离环境（容器或等价文件系统视图），它看到的 `/` 就是项目目录，物理上不存在"外面的文件"。
2. **路径校验**：文件工具在每次操作前做 `realpath` 解析，结果必须落在 allowlist 前缀内。先解析再校验，软链逃逸在这层被拦下。
3. **危险命令拦截**：shell 工具内置模式识别，对递归删除、`git clean`、`find -delete` 做两类处理：目标不在 workspace 内直接拒绝；在 workspace 内则改写为移入 trash，而非真删。
4. **回收站与日志**：删除先进 workspace 外的 `.trash/`，附带操作日志（原始命令、目标路径、时间），保留 N 天，恢复成本是一次 `mv`。
5. **MCP 作用域最小化**：工具注册时声明读写 scope，只做分析的 server 拿到只读权限，会话中途也无法自我提权。

配置上建议这样起步：workspace 指向具体项目目录而非家目录；allowlist 用最窄前缀；先开 dry-run 跑一轮，看日志里哪些命令被拦截或改写，再放开真实写入。

## 踩坑点

- **先判前缀再 resolve**：顺序反了，软链逃逸照旧发生，这是社区报得最多的一类；
- **allowlist 太宽**：填 `/home/user` 等于没填，请写到项目级目录；
- **回收站放 workspace 里面**：一条 `rm -rf ./*` 连兜底一起删掉，trash 必须在隔离视图之外；
- **同名工具两套实现**：自带文件工具和第三方 MCP 都能写文件时，必须走同一条校验通道，否则等于留了侧门；
- **Unicode 规范化**：macOS 的 NFD/NFC 差异会让路径比对失败，统一 normalize 后再比。

## 可复用建议

抽象一下，任何 Agent 项目都能套：

1. 默认拒绝，allowlist 只加必需项；
2. 校验放在执行层、解析之后，不放在提示词里；
3. 破坏性操作降级为可逆操作：删除改移动，覆盖先备份；
4. 每一层都留日志，出事时日志比直觉有用；
5. 定期用一个"故意犯错"的测试 Agent 去撞墙，确认拦截规则还活着。

## 总结

OpenClaw 敢让 Agent 无人值守，不是因为模型更聪明，而是因为执行环境默认它不聪明。分层防御的价值在于：任何单点失效都不会直接变成数据损失。如果你的自动化还在裸奔，先把 workspace 收窄、把 dry-run 跑起来——这两步成本最低，收益最直接。
