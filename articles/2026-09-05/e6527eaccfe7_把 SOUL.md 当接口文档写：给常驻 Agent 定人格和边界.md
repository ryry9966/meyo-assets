## 背景

OpenClaw 的 Agent 是常驻的：它收消息、跑定时任务、调 MCP 工具，还会在多个渠道主动开口。它的系统提示词不是硬编码的，而是由工作区几个 Markdown 文件拼装出来的——AGENTS.md 管流程，TOOLS.md 管工具用法，而 SOUL.md 管的是“它是谁”：语气、价值观、行为边界。

很多人的部署把 SOUL.md 留成模板原文，或只写一句“你是乐于助人的助手”。跑两天就会出问题。

## 问题

没认真写过 SOUL.md 的 Agent，常见三种症状：

1. **人格漂移**：今天简洁克制，明天 emoji 轰炸，重开会话又换一副面孔。
2. **边界失守**：半夜主动推消息、把 workspace 文件内容原样转述到群聊、用户一句“你看着办”就执行高风险操作。
3. **提示词打架**：SOUL.md 要求简短，AGENTS.md 的回复模板却要五段式，模型随机选边。

根因是把人格和边界当成了“氛围描写”，而不是可观测的行为约束。

## 做法

我的原则：把 SOUL.md 当接口文档写，而不是当人设小作文。四个段落：

1. **身份（3 行以内）**：它是谁、服务谁、默认语气。例如“某人的私人助理，语气平实、直接、不寒暄”。
2. **边界（写成可判定规则）**：不写“要有分寸”，写“23:00–8:00 不主动发消息，除非任务显式标注紧急”“不把 workspace 文件内容粘贴进群聊，只给结论和路径”。
3. **风格样例**：给一对好/坏回复对照。模型对示例的服从度远高于形容词。
4. **冲突裁决**：明确与 AGENTS.md 冲突时以谁为准，避免随机选边。

配套两条纪律：SOUL.md 进 git，Agent 说了不该说的话就回头补一条规则并提交，像修 bug 一样攒回归；总长控制在几百 token，超了就删形容词、保规则。

## 踩坑点

- **形容词无用**：“友善、专业、有分寸”几乎不改变行为，"if X then Y"式规则才有效。
- **只有“不要”**：全否定规则容易顾此失彼，每条禁令最好配一个正例。
- **把 SOUL.md 当安全边界**：文字约束是软的。真正拦住危险操作的是 MCP 权限收敛（只放行必要工具、只读挂载）和执行前确认，SOUL.md 只是第一道。
- **一套人格走天下**：私聊口语化没问题，但用它起草正式文档会很怪。频道级覆盖比写“看场合办事”可靠得多。
- **升级即回归**：换模型或升 OpenClaw 版本后行为基线会变，准备一组固定测试题（含边界试探）跑一遍再上线。

## 可复用建议

- 模板骨架：身份 / 边界规则 / 好坏样例 / 冲突裁决，四段起步，别贪多。
- 维护 10 条左右的“人格回归集”，改 SOUL.md 或升级后必跑。
- 规则一行一条，方便 diff 和 review。
- 软硬结合：SOUL.md 定行为，工具权限兜底，两层缺一不可。

## 总结

SOUL.md 的价值不在“让 Agent 更像人”，而在把主观预期翻译成模型可执行、你可回归测试的行为契约。写得短、写得可判定、版本化维护，再配上收敛过的工具权限，常驻 Agent 才能既有人味、又不出格。
