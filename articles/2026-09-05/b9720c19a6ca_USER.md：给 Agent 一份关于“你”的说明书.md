## 背景

主流 Agent 工具几乎都有“项目记忆”：AGENTS.md、CLAUDE.md、.cursorrules，解决的是“Agent 如何理解这个仓库”。但很少有人给 Agent 一份关于**使用者本人**的说明。结果是每个新会话都要重新自我介绍一遍：我什么水平、机器是什么环境、哪些事不许做。

## 问题

这些痛点大概率你遇到过：

- **默认假设错误**：Agent 默认 npm/pip，而我用 pnpm/uv；默认 Ubuntu，而我本机是 macOS、远端是 Debian。
- **风格反复调教**：“回答先结论后细节”每个会话都要说一遍。
- **红线靠运气**：不说“别动我的 zshrc”，它真敢动。

这些其实是稳定事实，却每次都以临时上下文的形式传入，既浪费 token，也不可靠。

## 做法

**第一步**：建一个固定路径的文件，比如 `~/.config/agent/USER.md`，纳入 dotfiles 仓库。内容分四段：

```markdown
# 关于我
## 环境事实
- 本机 macOS 15，服务器 Debian 12，shell 是 zsh
- Python 用 uv，Node 用 pnpm，不要默认 npm/pip
## 协作偏好
- 回答先给结论再给依据；不确定就问，不要猜
- 代码注释用中文
## 红线
- 不要修改 ~/.zshrc 和 crontab
- 不要用 sudo 全局安装
```

**第二步**：按工具能力选接入方式：

1. 支持全局记忆文件的工具：在全局记忆里写一行“会话开始先读 ~/.config/agent/USER.md”，或直接软链过去；
2. 支持 MCP 的：把 USER.md 暴露为一个 resource，Agent 启动时拉取；
3. 自托管、可定制系统提示词的：构建时直接注入。

## 踩坑点

1. **写成自传**。控制在一页内（约 150 行），过长的个人描述会稀释真正的规则，Agent 的注意力分配和人不完全一样，但趋势相同。
2. **混入易变状态**。本周任务、进行中项目放别的文件。USER.md 只放半年内不会变的事实。
3. **放敏感信息**。密钥、真实地址不要进上下文，一旦进入就可能被写进日志或带到子 Agent 的提示词里。
4. **与项目文件打架**。明确优先级：项目级覆盖全局级。“全局写 pnpm、仓库里用 npm”这种冲突必须在全局文件里声明清楚。
5. **写完即忘**。过期偏好比没有更糟，建议设个季度提醒做 review。

## 可复用建议

- **否定式规则比肯定式描述可执行**：“不要用 sudo 全局装包”远好于“我喜欢干净的环境”。
- **让 Agent 参与维护**：“根据最近十次对话，给我的 USER.md 提修改建议”，人工 review 后合并，比从零手写省力。
- **拆两个文件**：USER.md（稳定身份）+ NOW.md（当前焦点），只注入前者，后者按需读取。
- **多工具共享**：用 symlink 让几个 Agent 工具指向同一份文件，避免三处维护、三处漂移。

## 总结

USER.md 做的事很简单：把“我是谁”从每次会话的临时输入，变成一份版本化的个人基础设施。半小时的一次性成本，换来每个新会话少解释一遍自己、少踩一次错误的默认值。它没有任何魔法，就是配置管理思想用在了 prompt 上，所以它可靠。
