## 背景

OpenClaw 的工作区里有一组约定文件：`SOUL.md` 管人格，`USER.md` 管用户画像，`MEMORY.md` 管长期记忆，而 `AGENTS.md` 是每次会话启动时直接注入上下文的"操作手册"。它不是人格设定，也不是工具文档，而是告诉 agent 在这个工作区里"事情该怎么做"。不少新用户把它当成又一处随手笔记，写完就不管，结果 agent 的行为长期处于随机波动状态。

## 问题

典型症状：同一类任务，今天执行得干净利落，明天就绕路；你反复在对话里纠正"改配置前先备份""回复别超过三屏"，下个会话它又忘了。原因很直接——对话里说的规则随会话结束消失，只有写进 `AGENTS.md` 这类常驻文件的约束才每次生效。麻烦在于：写什么、写多细、和其它文件怎么分工，文档没有太多现成答案，只能自己踩。

## 做法

我的迭代流程，供参考：

1. **先跑空文件观察。** 把 `AGENTS.md` 清空用几天，记录哪些行为需要你反复纠正——这些就是规则条目的真实来源，比照搬模板有效得多。
2. **按"动作"归类。** 每条写成祈使句 + 明确触发条件，例如"修改任何配置文件前，先复制到 `backup/` 并加日期后缀"，而不是"要小心，别弄坏配置"。
3. **分四节写。** 行为约束（回复长度、语气）、操作流程（部署与测试顺序）、文件约定（哪些目录可写、`MEMORY.md` 何时追加）、安全边界（哪些命令永不执行），每节三五条即可。
4. **一次只改一处。** 改完观察两三个会话再动下一条，否则无法归因是哪条规则起了作用。

## 踩坑点

- **写太长。** 全文进系统提示，超过几百行后早期条目实际权重明显下降，agent 开始"选择性失忆"。我控制在 60 行以内。
- **职责越界。** 人格放 `SOUL.md`，工具特殊用法放 `TOOLS.md`。把"你是一个严谨的工程师"写进 `AGENTS.md`，只会和 `SOUL.md` 打架。
- **写愿景不写动作。** "保持代码整洁"没有可执行信息；"提交前运行 lint，失败则不提交"才有。
- **与 MCP 工具描述重复。** 工具的 description 已说明用法，`AGENTS.md` 里只写"什么时候用、什么时候别用"，别复述参数。

## 可复用建议

- 每条规则用 HTML 注释标注日期和来源（哪次翻车催生的），三个月后裁剪时能判断哪些还有效。
- 定期做减法：不再出现的行为问题，对应规则就删。手册越薄，每条权重越高。
- 多工作区/多 agent 场景下，把通用规则抽成公共段落，各工作区只保留差异项，避免多处维护漂移。

## 总结

`AGENTS.md` 的本质，是把"你对 agent 的口头纠正"沉淀为常驻上下文。它不提升模型能力，只是消除重复沟通。我的经验是：与其一开始追求完美手册，不如让规则从真实翻车里长出来——每次你忍不住在对话里说"跟你说过多少次了"，那就是 `AGENTS.md` 该多一行的时候。
