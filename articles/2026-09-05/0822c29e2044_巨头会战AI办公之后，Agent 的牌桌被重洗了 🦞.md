过去一年，AI 行业的关键词悄悄从"百模大战"换成了"Agent 落地"。36kr 说腾讯、字节、阿里在 AI 办公领域"会战"，并不夸张：钉钉、飞书、企业微信这三张办公入口，如今每一张背后都站着自家的模型、Agent 平台和一排 AI 功能。这一轮打完，Agent 赛道的规则变了——比的不再是谁的模型参数大，而是谁离工作流更近。这篇文章把它拆开讲清楚：Agent 到底是什么、三家各自怎么打、格局变了什么、还剩哪些坎。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-05/e4cc44a90c0369e4.png)

## 先补课：Agent 比 Chatbot 多了什么

把 Agent 理解成"更聪明的聊天机器人"，差了一整个物种。真正的 Agent 多了四个部件：

- **规划（Planning）**：把"帮我组织下周的评审会"拆成查日历、拉参会人、订会议室、发材料四步
- **工具调用（Function Calling）**：模型输出结构化指令去真正调用 API——查日程、写文档、发消息，不是嘴上说说
- **记忆（Memory）**：跨会话记住项目上下文和你的偏好，而不是每次失忆
- **反思循环（ReAct 模式）**：执行 → 观察 → 修正 → 再执行，直到任务闭环

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-05/672d72934952b7e8.png)

举个对比：你说"把这周的会议纪要整理成待办，提醒相关同学"。Chatbot 的上限是吐一段整理好的文字；Agent 会读文档 → 抽取任务 → 写入任务系统 → 按职责分派 → 发提醒，一条龙跑完。

办公场景为什么是 Agent 的天选之地？三个条件凑齐了：任务结构化程度高、工具天然有 API（IM、日历、文档、表格）、结果可验证。这三点决定了 Agent 在办公域的可靠性上限，远高于开放域闲聊。

## 三家的牌：生态、平台、开源云

这一轮会战，打法明显分化：

- **腾讯打生态牌**：入口是企业微信、腾讯文档、腾讯会议这套组合，模型用混元，C 端有元宝，知识库产品 ima 直接接微信生态的内容资产，另有元器这样的 Agent 搭建平台。逻辑很简单：办公数据本来就在我这里，Agent 只是把"存着"变成"用起来"。
- **字节打平台牌**：飞书是 B 端入口，豆包铺 C 端，中间的 Coze（扣子）走低代码路线，业务同学不写代码也能搭出 Agent 并发布到飞书、微信等渠道；火山引擎再把 token 价格打到厘级（2024 年豆包主力模型一度低至 0.0008 元/千 tokens），用价格换开发者。
- **阿里打开源+云牌**：通义千问 Qwen 系列坚持开源，衍生模型数量和下载量在全球开源社区名列前茅；钉钉把 AI 助理做成开箱即用的企业功能，让每家组织低成本造专属助理；底下接阿里云百炼的 MaaS 平台，形成"开源引流 → 云上变现"的飞轮。

一句话总结：三家都从"卷模型"转向"卷场景、卷平台、卷生态"。模型是发动机，但决定胜负的是装在什么车上、跑在哪条路上。

## 格局怎么变：三个关键转变

1. **从能力竞争到分发竞争**。模型能力趋同后，入口价值被放大。办公 IM 和文档套件是高频刚需，用户每天打开几十次——Agent 借着入口自然长在工作流里，而不是让用户专门跑去另一个 App"使用 AI"。
2. **从卖功能到卖"数字员工"**。上一代 SaaS 按席位收软件费；Agent 时代的想象空间是按任务、按产出计费——一个能独立完成纪要汇总、会议跟进的"数字员工"，对标的是一份真实人力成本。这也是 Agent 被称为"AI 应用终点形态"的原因。
3. **从封闭自研到平台生态**。三家都在做 Agent 开发平台，剧本类似当年小程序与应用商店：巨头出流量、模型、工具链，长尾需求交给 ISV 和个人开发者去补。2024 年底 Anthropic 提出 MCP（Model Context Protocol）工具接入协议并迅速普及，进一步拉低了 Agent 连接外部系统的门槛。

还有一个隐性变化：模型商品化。开源追平闭源的速度越来越快，API 价格一降再降，"裸模型"的溢价正在消失，差异化被挤到三个地方——私有数据、业务工作流、集成深度。

## 现实骨感：落地还有三道坎

牌桌重洗不等于胜负已分，落地侧的坎依然硬：

- **错误累积**：Agent 是多步串联执行，可靠性按复利衰减。单步成功率 90%，串十步整体只剩约 35%（0.9 的 10 次方 ≈ 0.35）。所以生产级 Agent 必须加校验、重试、回滚机制。
- **数据与权限**："它能不能看我无权看的文档""数据会不会出域"——私有化部署、权限继承、审计日志，这些不性感的东西决定生死。
- **评测缺失**：办公任务缺少公认的 benchmark，企业采购前算不清 ROI；而在"替你发一条消息"这类场景里，一次幻觉就是一次事故。

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-05/e40fa4696c328a93.png)

- **先落地高频、规则清晰、容错高的场景**：会议纪要转待办、周报汇总、客服 FAQ、合同要素抽取。别一上来就幻想"全自动数字员工"，先把一个环节跑稳，再谈接管流程。
- **护城河不在模型，在数据和流程**：把领域知识沉淀成结构化知识库，把 SOP 写成 Agent 的执行脚本。模型会贬值，你的数据和流程沉淀不会。
- **把 Agent 当新员工，别当魔法**：设计人机协同的确认节点，尽早建一套自己的评测集（evals），用错误率数据驱动迭代。评测做得越早，后面踩的坑越少。

AI 办公这一仗打到现在，赢家未定，但规则已经清楚：离工作流越近、数据越厚、生态越开放的玩家，手里的牌越多。对小团队来说这反而是好消息——巨头把铁轨铺好了，你只需要想清楚自己的车拉什么货。
