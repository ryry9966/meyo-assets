## 背景

OpenClaw-CN 社区每天沉淀大量有价值的内容：精华帖、新插件发布、高频问题。人工整理耗时且容易遗漏。我们的目标是做一个发帖机器人：定时抓取社区内容，由 Agent 生成摘要帖，经人工审核后自动发布。

需求看似简单，但从"能跑通"到"能长期稳定运行"，中间踩了不少坑。

## 初始方案的问题

第一版很直接：cron 定时触发 → 调 LLM 生成帖子 → 调社区 API 发布。三天内出了两次事故：同一内容重复发帖，以及一条没润色完的半成品直接发了出去。

## 重构后的架构

第二版拆成四层：

1. **调度层**：cron 只负责触发，执行状态全部落库。每次任务有唯一 task_id，发布前检查"当天是否已有同类帖"，天然幂等。
2. **Agent 层**：基于 OpenClaw 的 Agent 能力，通过 MCP 挂载三个工具——抓帖、读历史帖（去重用）、发布。模型本身不直接碰发布 API，只能走工具。
3. **审核层**：生成结果先写入待发队列，推送群里人工确认，确认后才调用发布工具。这一层是后加的，也是事故率归零的关键。
4. **观测层**：每次任务的 prompt、模型输出、工具调用日志全量落库，出问题可回放。

## 踩坑点

- **幂等比想象中难**：cron 重复触发、网络超时后重试，都可能造成重复发帖。最终用"内容指纹 + 发布前查重"双保险，指纹取标题归一化后的 hash。
- **MCP 工具超时**：抓取社区帖子偶发超时，Agent 会自作主张换个说法再试，内容就走样了。解决：工具层设明确超时并返回结构化错误，Agent 收到错误直接终止本轮，而不是硬编。
- **模型输出漂移**：同一 prompt 跑一周，文风开始变化。把 few-shot 示例和历史优秀帖一起注入上下文，并在 prompt 里固化格式约束，漂移明显缓解。
- **时区问题**：服务器是 UTC，cron 设的"每天早上 9 点"实际下午 5 点才发。调度层统一用本地时区计算，日志里同时打印两种时间。

## 可复用建议

- 生成和发布必须分离，中间加人工或规则审核，不要让 Agent 一条链路直达发布。
- 所有外部调用都假设会失败：超时、限流、返回异常格式。工具层做防御，Agent 层做决策。
- 状态存数据库而不是内存，任何一步都要可重入。
- 日志按任务聚合，一次发帖失败能回放完整链路。

## 总结

机器人上线一个月，稳定产出 30+ 篇摘要帖，触发过两次异常（都在审核层被拦下）。核心体会：AI 发帖机器人的难点不在生成，而在工程——幂等、审核、可观测。Agent 负责内容，架构负责兜底。欢迎在评论区交流你们的自动化实践。
