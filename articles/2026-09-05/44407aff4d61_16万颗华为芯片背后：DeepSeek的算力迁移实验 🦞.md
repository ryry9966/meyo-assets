2025年9月，彭博等外媒报道，DeepSeek（深度求索）经由第三方渠道向华为订购了约16万颗昇腾芯片，主要用于推理算力。消息尚未得到两家公司官方确认，但已经在圈内刷屏——因为它回答的不只是一家公司的采购问题，而是一个行业问题：当先进 GPU 供给受限、模型调用量持续暴涨，大模型公司的算力账本应该怎么记？这篇文章不站队、不喊口号，把事情拆成四层：量级、动机、难点、启示。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-05/59cd54fa07116234.png)

## 先算一笔账：16万颗是什么量级



- **换算成集群**：参照公开资料，DeepSeek-V3 的训练用了 2048 张 NVIDIA H800，累计约 279 万 GPU 小时。而 16 万颗昇腾 910C，即便按较保守的单卡等效算力折算，也大致相当于若干个“万卡集群”——这是只有头部云厂商才玩得起的体量。
- **用途定位**：多方报道指向“推理优先”。训练是一锤子买卖的大工程，推理是每天持续燃烧的日常开销。R1 爆火后 API 调用量激增，推理成本才是账本上增长最快的一行。
- **路线延续**：这并非临时起意。DeepSeek 一直以“极致成本工程”著称——V3 论文公开了 MLA（多头潜在注意力）、MoE（混合专家）、FP8 混合精度训练，把每一 FLOP 都抠出了价值。补充国产芯片承接推理，是同一条路线的自然延伸。

## 为什么是昇腾：算力供给侧的现实约束

- **客观背景**：受美国出口管制影响，H100/A100 长期不可得，H800、H20 等特供版的供应政策也几经反复。对企业而言，算力供给的“确定性”本身就是稀缺资源。
- **昇腾的底子**：910C 采用双 die 封装，综合公开资料，其半精度算力与显存带宽大致落在 A100 到 H100 之间的区间；910B 则是当前国产训练集群的主力卡。
- **行业通行打法**：这不是 DeepSeek 一家的动作。国内多家头部厂商都在推进“混合算力”布局——存量 NVIDIA 卡保训练，国产芯片承接推理增量。
- **一句话总结**：训练看峰值，推理看摊销。把长期烧钱的大头放在供给更稳的货源上，这笔账 CFO 一眼就能看懂。

## 真正的硬骨头在软件栈

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-05/5423ed0698e35967.png)

- **CUDA 护城河**：NVIDIA 从 2006 年开始沉淀 CUDA——算子库、编译器、NCCL 通信库、上百万开发者形成的社区。换硬件从来不只是换卡，而是换一整套“方言”：从 CUDA 普通话切到 CANN 方言，连报错信息都自带口音。
- **对应关系**：华为这侧的对应物是 CANN 计算架构、MindIE 推理引擎和 HCCL 通信库。vLLM、SGLang 等主流推理框架已提供昇腾支持分支，进步肉眼可见，但算子覆盖度、调试工具链的成熟度仍有差距——这是工程师群体的真实体感。
- **DeepSeek 恰好对口**：2025 年开源周，他们放出了 FlashMLA、DeepGEMM、DeepEP、3FS 等底层组件，还在论文里披露过手写 PTX 优化的细节。换句话说，这家团队本来就习惯在硬件和框架之间“修路”，迁移能力是现成的。
- **为什么先迁推理**：推理对生态的依赖远比训练浅——不需要复杂的分布式训练通信，主要吃算子覆盖和调度效率。选推理当切入口，是把迁移风险压到最低的工程决策。

## 这笔订单释放的三个行业信号

1. **推理算力需求正在反超训练。** 模型进入应用期后，每一次提问都是成本；推理时计算（test-time compute）让模型“想得更久”来换更强表现，进一步放大推理侧需求。
2. **算法效率与硬件自主两条路线开始会师。** DeepSeek 用算法把需求压低，国产芯片把供给补上，两者最终在同一个指标上碰头：单位 token 成本。
3. **超大规模真实负载是最好的验证场。** 评测集跑分替代不了生产环境——每天亿级请求下的吞吐、稳定性、故障率，才是国产算力栈真正的成人礼。

## 冷思考：三个值得记住的判断

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-05/be6e1c18f80f5cb1.png)

1. **订单 ≠ 验证。** 16 万颗是采购意向与产能锁定，不等于集群效率。单卡参数像简历，集群效率像入职后的实际表现。后续值得盯三个数：实际部署量、算力利用率（MFU/吞吐）、API 服务质量的稳定性。
2. **盯“每 token 成本”，别盯“卡数”。** 商业模式真正敏感的是单位推理成本与毛利率。用性价比更高的硬件把服务成本打下来，比单纯堆卡数有意义得多。
3. **给开发者的实操建议**：业务代码尽量站在高层框架一侧（PyTorch、vLLM/SGLang），把硬件相关的东西隔离在配置层；写关键算子时留意可移植性。未来算力供给无论怎么变，你的迁移成本都可控。

算力行业没有奇迹，只有账本。16 万颗芯片的故事，本质是一个把效率刻进方法论的高性能团队，在供给不确定的世界里解的一道工程题——答案对不对，接下来的服务稳定性和成本曲线会给出来。
