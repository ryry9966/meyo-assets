## 背景

用 OpenClaw 搭日常助手的人大概都遇到过同一件事：每开一个新会话，都要重新交代一遍"构建用 pnpm、回复用中文、别自动 commit"。这些不是任务，是偏好——但模型本身无状态，会话一断就归零。记忆系统要解决的就是这一件事：把稳定的偏好从一次性对话里沉淀下来，并在合适的时机用回去。

## 问题

三种常见做法都不太行：

1. **全塞 system prompt**：简单，但记忆一多就上下文膨胀、指令稀释，成本和注意力双输；
2. **靠聊天记录检索**：字面相似 ≠ 语义相关，召回一堆噪声；
3. **靠模型"自觉"记忆**：写入时机和内容不可控，经常把临时信息当永久偏好存下来。

## 做法

我的方案分三层，落在一个很小的 MCP memory 服务上（SQLite 起步就够）：

- **profile 层**：稳定偏好，键值结构，每条带 `source`、`confidence`、`updated_at`。静默注入 system prompt，硬性控制在 20 条以内。
- **episodic 层**：会话级事实（如"这周在赶项目 A"），带 TTL，默认 14 天过期。由 agent 按需调用 `memory_search` 工具查询，而不是每轮注入。
- **correction 层**：用户的显式纠错，最高优先级，永远覆盖 profile。

写入流程：会话结束后跑一次提取，模型只输出"候选记忆 + 置信度"。置信度低于阈值、或与现有条目冲突的，进队列等用户确认。读取按场景取切片：编码任务只带编码偏好，不整包灌入。

## 踩坑点

- **记忆污染**：第一版把"今天想吃清淡的"写成了永久偏好。后来加了规则：带时间状语（今天/这次/最近）的候选一律不进 profile。
- **冲突处理**：用户半年前说"不吃辣"，现在说"偶尔吃一点"。必须保留旧值做历史，`updated_at` 最新的生效，否则两条矛盾记忆会同时注入。
- **提取幻觉**：让模型自己总结偏好时它会编。自动提取的条目初始置信度打低，被用户确认过才升级。
- **不可见的记忆最危险**：用户不知道助手记了什么就不敢用。我加了 `/memory` 命令列出全部条目，支持查看、编辑、删除，信任问题解决一大半。
- **隐私红线**：凭据、证件号在写入前做模式拦截，宁可漏存不可错存。

## 可复用建议

- 先做可查看、可编辑、可删除，再做自动提取。顺序反了会直接失去信任。
- 写入要有门（置信度 + 确认队列），读取要有闸（按任务场景取切片）。
- 注入策略用混合式：profile 静默注入，episodic 交给 agent 按需调工具。
- 记录命中率：跑两周，统计 agent 实际引用的记忆条数占比，低于 30% 就该清理 schema。
- 记忆 schema 记得版本化，后续迁移不痛苦。

## 总结

记忆系统本质是工程问题而非模型问题：少而准，比多而全有用得多；可控、可查、可删，比"聪明"重要得多。一张 SQLite 表加一个 MCP 工具就能起步，先用起来，再按命中率迭代。
