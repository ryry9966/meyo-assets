## 背景：Agent 需要“往外看”，但门外有雷

任何具备工具调用能力的 Agent（无论是基于 OpenClaw 编排，还是通过 MCP 挂载浏览器工具），一旦需要从公开网页提取实时信息，就踏入了一片充满隐形雷区的战场。反爬策略、动态渲染、验证码、敏感内容过滤，每一个环节都可能让一次简单的信息抓取演变成不可控的风险事件。

直接由 Agent 裸调 HTTP 请求或无头浏览器，会遇到几个典型问题：

- **IP/指纹被封**：目标站识别无头浏览器特征或云厂商 IP 段，直接返回 403 或欺骗性内容。
- **脏数据污染**：被重定向到广告页、反爬页面，Agent 拿到错误内容后产生幻觉。
- **合规与安全风险**：无意中爬取到受版权保护、含有 PII 或违法内容，未经稽核直接进入上下文。
- **资源失控**：Agent 频繁抓取或渲染重型页面，造成本地资源耗尽或对目标站点造成压力。

因此，我们需要一个“稽客”（Scraping Auditor）——不是简单的爬虫，而是位于 Agent 与 Web 之间的安全中间层，负责对每一次外部采集动作进行安检、清洗、限流和回放。

## 问题拆解：稽客要解决什么

1. **请求前的合规性判断**：URL 白/黑名单、域名备案检查、robots.txt 尊重、频率限制。
2. **执行层的反检测**：浏览器指纹随机化、无头模式隐匿、请求头秩序维护、代理池轮换。
3. **响应校验与净化**：状态码合理性、内容指纹校验（是否被反爬劫持）、敏感词/标签剔除、HTML 转纯文本/AI 友好格式。
4. **异常兜底**：验证码识别（打码服务集成）、降级到缓存、熔断告警。

## 做法与步骤：构建稽客中间层

我们以 OpenClaw + MCP 的 `playwright-mcp` 为采集执行器，在其上游增加一个 Python 中间件（稽客服务），Agent 不直接调用浏览器工具，而是调用稽客暴露的工具函数。

### 1. 稽客服务设计

稽客服务提供如下两个核心函数，供 Agent 通过 Function Calling 调用：

- `audited_fetch(url: str, options: dict) -> dict`
- `audited_search(query: str, engine: str) -> dict`

内部流程：

```
Agent 调用 → 稽客 service → 规则引擎（URL/域/频率校验） → 
playwright-mcp 执行器 → 原始响应 → 内容净化 → 返回标准化结果
```

### 2. 请求前稽核

在 Python 中间件中，维护一张按域名粒度的规则表，可热更新：

```python
rules = {
    "allowlist": ["wikipedia.org", "docs.python.org"],
    "denylist": ["*.douyin.com", "*.tiktok.com"],
    "rate_limit": {"default": 5, "wikipedia.org": 10},  # req/min
    "robots_respect": True
}
```

每次请求前检查域名是否命中 denylist，否则检查 robots.txt（缓存 1h）。同时基于滑动窗口进行限流，超过阈值返回标准错误：“Rate limit exceeded, try again later.”

### 3. 利用 Playwright-MCP 执行安全采集

实验中最稳定的方案是挂载 `@anthropic/mcp-server-playwright` 并通过其 headless 模式执行，但需要做指纹伪装：

- 使用 `playwright-stealth` 或注入 stealth.js 隐藏自动化特征。
- 随机化 `viewport`、`userAgent`、`locale`，甚至模拟真实鼠标移动轨迹。
- 强制使用住宅代理或优质 ISP 代理，避免云服务器 IP 直接暴露。

通过 MCP 客户端调用浏览器工具时，稽客中间件会自动拼装这些选项，Agent 无需感知细节。

**踩坑点 1**：`playwright-stealth` 对最新版 Chromium 支持有延迟，曾出现 `navigator.webdriver` 仍为 `true` 的情况。解决方案：自维护 stealth 脚本补丁，每次 Playwright 升级后进行冒烟测试；或者降级使用 Playwright 1.38 稳定版配合对应 stealth 版本。

**踩坑点 2**：某些站点会检测 `window.outerWidth` 与 `window.innerWidth` 差值（是否模拟无头），需要正确设置 viewport 与窗口尺寸一致。

### 4. 响应后内容净化

原始 HTML 不仅体积大，还可能包含跟踪 pixel、恶意脚本、反爬暗语。稽客净化流程：

- 将 HTML 通过 `trafilatura` 或 `readability-lxml` 提取正文，自动剔除导航、广告、侧边栏。
- 对提取文本进行敏感信息正则扫描（邮箱、手机号、身份证、银行卡号等），一旦命中则清洗或中断，并记录日志供人工审查。
- 实施“反爬指纹检测”：检查页面标题、前 200 字符是否包含常见反爬关键词（“验证”、“403”、“blocked”、“captcha”等），若命中则抛出异常，触发代理重试或降级。

### 5. 验证码与熔断

不得不提验证码。简单的文本验证码可尝试 Tesseract，但现代图像验证码基本无解。稽客的策略是：

- 首次遇到验证码 → 切换到另一个代理和指纹重试 1 次。
- 仍失败 → 返回友好错误给 Agent，并将该域名标记为“高风险”，短期内不再尝试。
- 熔断器：某个域名连续失败 3 次，自动熔断 10 分钟，保护资源和 IP 信誉。

### 6. 集成到 OpenClaw 工具链

将上述稽客封装为一个本地 FastAPI 服务，再通过 OpenClaw 的 Tool 定义或者 MCP 插件形式暴露。Agent 在 system prompt 中被告知“所有外网内容获取必须经过 audited_fetch，严禁自行调用浏览器工具”。实测中，这样可以有效拦截 90% 以上的不规范抓取。

**可复用建议**：

- **配置驱动**：规则、限流值、净化策略全部配置化，不要硬编码。
- **监控与告警**：将每次稽客拦截、异常、验证码触发等事件打入日志，接入 Grafana 告警。
- **分层降级**：稽客服务不可用时，Agent 应能降级到本地缓存或直接告知用户“暂无法获取最新数据”，而不能绕过稽客直连。
- **代理池按需投入**：普通抓取使用数据中心代理（低成本），高风险域名使用住宅代理，动态调整。

## 踩坑点总结

1. **无头浏览器指纹对抗是一线战场**，没有银弹，需要持续跟进浏览器版本与检测技术。
2. **代理 IP 质量决定上限**，免费代理经常被封，反而增加处理复杂度。建议至少使用合规的付费代理服务。
3. **内容净化不能偷懒**，直接从 innerHTML 取文本容易带隐性垃圾，影响下游 LLM 推理。
4. **MCP 工具的超时设置**需要仔细调优，复杂页面渲染可能超过默认 30s，导致 Agent 超时死等。

## 结语

Agent 安全采数不是一次性的功能，而是一个持续的工程实践。通过构建稽客中间层，我们把散落在各处的风险收拢到统一的服务中管理，降低 Agent 触达外部世界的不可控性。这样做虽然增加了一层调用开销，但对于需要在生产环境中稳定运行的 Agent 应用，这一步不可或缺。

在 OpenClaw 社区中，也可将这套稽客方案包装为 MCP 插件共享，让更多依赖浏览器自动化的 Agent 享受安全与合规的红利。
