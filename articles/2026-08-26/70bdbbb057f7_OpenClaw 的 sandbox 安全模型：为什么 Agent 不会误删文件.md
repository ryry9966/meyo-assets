## 背景

Agent 自动化里最常见的恐惧之一，就是“它会不会一条命令把我家目录删了”。这种担心不是没有依据：模型根据上下文生成命令，可能因为目标漂移、路径拼接错误、工具返回不完整，或者只是把“清理临时文件”理解成了“删除所有临时目录”。如果没有执行层约束，误删只是时间问题。

OpenClaw 的 sandbox 安全模型要解决的不是“让模型变聪明”，而是**默认不让它拿到能造成大范围破坏的能力**。核心思路是：小环境、白名单、默认只读、高危审批。

## 问题

在插件、MCP 工具或自动化任务里，Agent 通常需要访问文件系统。如果直接把宿主机目录暴露给 Agent，就会出现两个典型风险：

- 权限过大：一个只应该处理 `/workspace` 的任务，却可以读写 `/home`、`/etc`。
- 缺少审批：删除、覆盖、修改权限等操作没有人工闸门，模型一旦产生错误意图就直接执行。

所以安全模型的关键不是“所有命令都拦截”，而是让 Agent 在一个**受限但够用的环境**里运行。

## 做法 / 步骤

### 1. 定义工作区边界

OpenClaw 的 sandbox 通常以挂载白名单为基础。只把任务需要的目录挂进去，系统目录默认只读或不挂载。

```yaml
sandbox:
  workspace: /workspace
  mounts:
    - host: ./project
      mount: /workspace
      mode: rw
    - host: ~/.cache/openclaw
      mount: /cache
      mode: rw
    - host: /etc
      mount: /etc
      mode: ro
```

这里 `/workspace` 和 `/cache` 可写，`/etc` 只读。其他宿主机路径对 Agent 不可见。

### 2. 对写操作分类

读取类操作不拦截；工作区内的写操作允许；工作区外的写、删除、覆盖、权限修改需要审批。

```yaml
policy:
  allow:
    - read
    - write:/workspace/**
    - write:/cache/**
  ask:
    - delete
    - overwrite
    - chmod
    - chown
    - write:/tmp/**
  deny:
    - "rm -rf /"
    - "mkfs*"
    - "dd if=/dev/zero*"
```

这种分类让常规任务可以自动运行，但破坏性动作会进入人工确认。

### 3. 命令级拦截

对高危命令直接拒绝，即使模型误生成也不会执行。`deny` 列表不是万能，但可以挡住最常见的事故。

### 4. 审计与回滚

开启文件系统快照或操作日志。即使绕过审批造成误删，也可以从快照恢复，或通过审计日志定位是哪一步出了问题。

## 踩坑点

- **只读挂载不能完全避免逃逸**：部分命令可以通过符号链接、`/proc/self/root`、`/dev` 等路径访问宿主机。挂载时需要解析真实路径，避免软链指向工作区外。
- **不要挂载整个家目录**：即使只给只读，也会暴露大量隐私文件；如果给可写，等于把风险拉满。
- **审批策略不要自动通过**：在 CI 里对白名单任务自动通过可以接受，但交互式任务应保留人工确认。全局自动通过等于没有 sandbox。
- **不要只靠 prompt 限制**：告诉模型“不要删除文件”只是意图约束，模型不总是遵守。必须由执行层兜底。
- **`.git` 目录容易被忽略**：如果工作区里包含 `.git`，建议单独只读或隔离，避免 Agent 误改版本历史。

## 可复用建议

1. **最小挂载原则**：只挂载任务需要的目录，不挂载家目录，不挂载系统目录。
2. **读写分离**：工作目录可写，参考数据只读，输出目录单独设置。
3. **高危命令默认拒绝**：`rm -rf /`、`mkfs`、`dd` 等直接进 deny 列表。
4. **做一次破坏性测试**：在临时容器里让 Agent 执行“清理临时文件”，观察它是否会尝试删除工作区外的内容，再根据结果调整策略。
5. **把 sandbox 策略纳入版本控制**：和插件配置、MCP 配置一起评审，避免某次部署时把边界放宽。

## 总结

OpenClaw 的 sandbox 安全模型不是“AI 不会犯错”，而是通过**小环境挂载、白名单权限、高危审批、审计回滚**，把误删的概率和影响降到可接受范围。真正有效的安全不是事后补救，而是默认拒绝和最小权限。把边界放在执行层，而不是放在 prompt 里，这才是让 Agent 自动化落地的工程化做法。
