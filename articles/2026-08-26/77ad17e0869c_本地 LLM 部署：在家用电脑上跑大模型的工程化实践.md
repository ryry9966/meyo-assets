## 背景

对于 OpenClaw/Agent/MCP/插件/自动化方向的用户来说，远程大模型 API 方便，但存在限流、隐私、成本不可控、调试不透明等问题。家用电脑上部署本地 LLM，可以作为稳定 fallback，也能承接一些数据敏感或低复杂度结构化任务。

目前 7B-14B 量化模型在普通电脑上已经可以完成信息抽取、简单规划、格式转换和部分工具调用。工程化的关键不是“跑起来”，而是让它在 Agent 工作流里稳定可用。

## 问题

家用电脑的主要瓶颈是显存、内存带宽和上下文长度。很多用户一开始就追求“最大模型”，结果加载慢、推理卡、工具调用格式不稳。对 OpenClaw/MCP 场景来说，**指令遵循和工具调用格式稳定，比模型参数更重要**。

另一个问题是资源竞争：本地模型和浏览器、开发环境、MCP 工具跑在同一台机器上，如果上下文开太大或并发过高，很容易把系统拖垮。

## 做法/步骤

### 1. 评估硬件基线

粗略参考：

- 8GB 显存：7B-8B 模型 Q4_K_M 量化，上下文控制在 4k-8k
- 12-16GB 显存：14B Q4，或 8B Q8
- 32GB 内存纯 CPU：7B Q4 约 3-8 token/s，只适合后台任务
- CPU 推理时，双通道内存和散热影响明显

不要把预算全压在模型大小上，先保证推理速度能接受。

### 2. 用 Ollama 提供 OpenAI 兼容层

Ollama 安装成本低，默认端口 11434，并提供 `/v1/chat/completions`，适合直接接入 OpenClaw。

```bash
ollama pull qwen2.5:7b-instruct-q4_K_M
ollama serve
```

测试本地接口：

```bash
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen2.5:7b-instruct-q4_K_M","messages":[{"role":"user","content":"return json"}]}'
```

### 3. 选择适合工具调用的模型

优先选指令微调版本，而不是基座模型。可用选择包括：

- Qwen2.5-Instruct 系列：中文和工具调用相对稳定
- Mistral-7B-Instruct：轻量，延迟低
- Llama-3.1-8B-Instruct：中规中矩

不要只看 benchmark，要实际跑一遍你的 MCP 工具 schema 和输出格式。

### 4. 接入 OpenClaw

在模型提供商里选择 **OpenAI-compatible**，填入：

- base URL：`http://127.0.0.1:11434/v1`
- api key：可随便填，例如 `ollama`
- model：必须与 `ollama list` 完全一致

建议把 temperature 调到 0.1-0.3，降低随机性；必要时关闭流式输出，减少解析变量。

### 5. 工具调用联调

先手动测一个 system prompt + 一个工具定义，看模型是否稳定返回 `tool_calls` JSON。如果不稳，可以在 system prompt 中加一句：

> 只输出 JSON，不要解释。

Ollama 也支持 `format: "json"`，但注意它并不能保证嵌套结构完全正确，仍需代码侧做 schema 校验。

## 踩坑点

- **KV cache 吃显存**：上下文设成 8192，7B 模型可能额外占 1-2GB 显存。不要盲目 `num_ctx=32768`。
- **并发排队**：多个 Agent 同时调用本地模型时，Ollama 默认可能串行处理。设置 `OLLAMA_NUM_PARALLEL=2`，`OLLAMA_MAX_LOADED_MODELS=2`，并调大 OpenClaw 的超时时间。
- **工具描述过长**：MCP 工具 schema 太复杂会占满上下文。本地模型窗口短，建议只暴露当前流程需要的工具。
- **量化损失**：Q4 模型在 JSON 结构输出上比 Q8 更容易出错。关键任务可以换 Q8 或 14B Q4。
- **markdown 包裹**：本地模型输出 JSON 时经常带 ```json 代码块，导致解析失败。需要在 prompt 里显式禁止，并在代码中做清理。

## 可复用建议

- **分层路由**：简单结构化任务走本地模型，复杂推理回退到远程大模型。
- **固化版本**：记录 `ollama list` 输出和量化级别，避免升级后行为漂移。
- **做回归测试**：固定一组 prompt 和工具调用用例，每次换模型后对比输出格式。
- **监控资源**：用 `ollama ps` 和 `nvidia-smi` 观察显存占用；第一次推理慢是模型加载，不是故障。
- **精简 system prompt**：本地模型对长 system prompt 更敏感，保留必要约束即可。

## 总结

在家用电脑上部署本地 LLM，不是为了完全替代云端大模型，而是获得一个离线、可控、可调试的自动化后端。对 OpenClaw/MCP 用户来说，从 Ollama + 7B/14B 量化模型开始，控制上下文长度，验证工具调用稳定性，再逐步接入工作流，是更务实的路径。

边界清晰、格式稳定，比一味追求大模型更重要。
