OpenAI 自研推理芯片的传闻又被推到热搜，中文圈给它起了个非常下饭的代号——“辣椒”。有说法称这颗芯片“压倒英伟达”，甚至会让 GPT-6 直接“干崩 CUDA”。热度是真的，但技术账不能按热搜算法来算。下面把传闻、算力、软件栈三层拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-26/2a7421885e0cfa50.png)

## 传闻拆解：“辣椒”目前还不是一颗能买的芯片

目前没有官方发布会，也没有一张公开 datasheet。能查到的主流信息基本来自外媒报道：OpenAI 正与 Broadcom 合作设计推理芯片，预计 2026 年由台积电流片，可能采用 3nm 或 5nm 工艺。所谓“辣椒”并未出现在任何正式文件中，更像是中文社区对“OpenAI 第一颗自研芯片”的戏称。

先把预期拉回地面：这颗芯片大概率是一颗推理优先的 ASIC，不是全能训练 GPU。它要解决的核心问题很直接——ChatGPT 级应用的推理成本太高。据公开报道估算，OpenAI 一年的训练与推理算力开销可能达到数十亿美元级别，其中推理占比还在持续上升。如果自研芯片能把单位 token 成本降 30%~50%，那省下的钱比多数上市公司利润还夸张。

技术上，推理 ASIC 会重点堆 HBM 带宽和矩阵单元。如果采用 HBM3e 或 HBM4，并配合台积电 CoWoS 封装，单卡 token 吞吐可能很漂亮。但“漂亮”的前提是：编译器、算子库、分布式推理调度都得跟上。

## “压倒英伟达”的三个层次

标题里的“压倒”，在不同语境下含义完全不同：

1. **单卡峰值算力超过 H100/B200**：ASIC 可以针对 Transformer 的矩阵乘、注意力计算做专用硬件，砍掉 GPU 上为图形、通用计算保留的调度单元，理论上可以在更小面积、更低功耗下堆出更高有效 FLOPS。但这只代表特定 benchmark 的胜利，不代表通用性。就像 Apple 的 Neural Engine 在特定 AI 任务上能效很高，但没人拿它训练大模型。

2. **单位 token 推理成本更低**：这是 OpenAI 最关心的指标。假设同样跑一个 70B 模型，自研芯片每百万 token 成本从 1 美元降到 0.5 美元，那么 ChatGPT 的毛利会明显改善。这种“压倒”比跑分重要得多。

3. **绕过 CUDA 软件栈**：这是最容易被忽略、但长期影响最大的一层。如果 OpenAI 不再依赖 CUDA 写 kernel，而是通过 Triton/MLIR 直接把高层模型编译到自研硬件，那么英伟达的生态锁定就被撕开一个口子。

把三层混在一起，正是很多标题让人误判的原因。

## CUDA 为什么难被“干崩”？

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-26/532b88c5c0f642db.png)

先说一个基本事实：CUDA 不是某个工具，而是一整套软件生态。英伟达从 2006 年推出 CUDA，用十几年时间积累了数百万开发者，以及 cuBLAS、cuDNN、TensorRT、NCCL、Cutlass 这些被广泛使用的库。大模型训练不是单卡跑分，而是几千张卡之间的通信、同步、故障恢复。NVLink、InfiniBand 加上 NCCL，这套组合经历过无数次超大规模集群验证。

但 AI 软件栈确实在发生“去 CUDA 化”的转变。PyTorch 2.x 默认使用 `torch.compile`，其中 Inductor 后端可以生成 Triton kernel；JAX 走 XLA；MLIR 作为中间表示，让硬件厂商只要维护一个后端，就能接入 PyTorch 等主流框架。OpenAI 很早就开源过 Triton，说明它对“如何绕开 CUDA”非常熟悉。

所以更准确的说法不是“干崩 CUDA”，而是**让 CUDA 不再成为唯一入口**。如果高层框架不感知底层硬件，开发者写的是 PyTorch 而不是 CUDA C，那么英伟达的软件护城河就会慢慢变浅。

## 如果 GPT-6 真跑在自研芯片上，会是什么样？

GPT-6 如果真是万亿参数级 MoE 架构，训练阶段对互连带宽和显存容量的要求极高。自研芯片如果没有类似 NVLink/NVSwitch 的高带宽互连，很难在训练侧直接替代英伟达集群。

更现实的路径是：

- **训练与推理分离**：训练继续用英伟达 GB200/NVL72 这类集群，推理逐步换到“辣椒”芯片。
- **渐进迁移**：先在 ChatGPT 高频、中小规模模型上压测，再扩散到 GPT-6 的部分推理任务。
- **成本结构变化**：推理 ASIC 如果良率、产能、编译器都成熟，可能把 token 成本拉低一个量级。这不叫“压倒”，但足够改变 OpenAI 与英伟达的采购谈判。

不过自研芯片的坑也很多。AWS Trainium 早期软件不成熟被开发者吐槽，Google TPU 也经历了多年迭代才稳定。硬件峰值永远不是全部，编译器、算子覆盖、分布式调度、运维成本同样重要。

## 行业现状：自研芯片不是新闻

Google TPU 从 2015 年就开始做了；AWS 有 Inferentia/Trainium；微软有 Maia；Meta 有 MTIA。OpenAI 加入自研阵营，只是把 ChatGPT 这个超大规模单一客户变成了自家芯片的练兵场。

英伟达也不会原地等着。Blackwell/Rubin 路线图继续推进，CUDA 也在增加面向 LLM 的新特性，NVLink-C2C、Grace-Hopper 等互连方案也在迭代。未来的格局大概率是**异构计算**：不同负载跑在不同硬件上，而不是某一家芯片“压倒”另一家。

## 冷思考：三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-26/a84d1f29ef36fa83.png)

1. **对开发者**：CUDA 仍然值得学，但别把技能锁死在单一厂商。补上 PyTorch 2、Triton、MLIR，理解编译器后端，能让你的技能更抗周期。
2. **对创业团队**：算力选型看 TCO（Total Cost of Ownership），不要被峰值 FLOPS 忽悠。采购成本、功耗、利用率、软件迁移、维护人力，都要算进总账。
3. **对普通读者**：下次看到“压倒英伟达/干崩 CUDA”，先问三个问题——跑的是哪个 benchmark？对标哪款英伟达芯片？软件栈和生态谁维护？三个问题问完，大多数标题会自动降温。
