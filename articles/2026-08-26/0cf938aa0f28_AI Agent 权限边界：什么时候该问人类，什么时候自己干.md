# AI Agent 权限边界：什么时候该问人类，什么时候自己干

## 背景

Agent 正在从“回答问题”变成“执行动作”。尤其接入 MCP、插件和本地自动化后，一个 Agent 可以读写文件、执行 shell、查数据库、发 HTTP 请求，甚至操作外部服务。

但权限边界一直模糊。问多了，Agent 变成立体化确认弹窗；问少了，它可能删错文件、覆盖配置、批量发出错误通知。真正的问题不是“要不要人工确认”，而是**在什么条件下、以什么粒度、用多快成本确认**。

## 问题

工程实践中，动作风险不是二元的。读一个文件、写一个临时文件、覆盖生产配置、删除数据库记录、触发对外支付，这些动作的风险和回滚成本完全不同。如果只用一个开关控制所有工具，要么所有操作都自动跑，要么所有操作都停下来问，系统会极其难用。

我们需要的是：**让低风险、可逆、低影响的操作自动执行；让高风险、不可逆、影响面大的操作强制停下等待人类决策。**

## 做法/步骤

### 1. 给动作打分，而不是给 Agent 打分

从四个维度评估一个工具调用：

- **可逆性**：查询、列出、读取通常可逆；删除、覆盖、支付通常不可逆。
- **影响范围**：单个文件/单条记录风险低；批量操作、全局配置风险高。
- **环境**：dev/staging 可以放宽；production 必须收紧。
- **成本/合规**：调用付费 API、发送大量对外通知、涉及隐私数据，自动执行要谨慎。

### 2. 把工具权限分成四个桶

- **L0 只读**：自动执行，不询问。例如 `read_file`、`search_docs`、`get_logs`。
- **L1 可逆写**：默认自动，但必须有审计。例如创建临时文件、新建 Git 分支、写草稿。
- **L2 不可逆但有回滚方案**：先 dry-run 或展示 diff，等用户确认。例如修改配置文件、执行 `UPDATE`、发布版本。
- **L3 高风险/无回滚**：必须人类确认，必要时要双人复核。例如删除生产数据、外部发信、支付操作。

### 3. 在工具层做权限检查，而不是提示层

不要只在 system prompt 里写“不要随便删除文件”。Agent 常常会忽略这类软性约束。

正确的做法是在工具执行前加一层权限适配器/中间件：

```text
用户请求 -> Agent 规划 -> 调用工具 -> 权限检查 -> 执行 or 暂停询问
```

对 L2/L3 动作，Agent 先输出“计划”：要调哪个工具、参数、预计影响，然后停下等待用户输入。对 L0/L1，直接执行并写入审计日志。

### 4. 设置自动执行预算和熔断

单次任务里，如果一个 Agent 连续自动执行了 10 个 L1 动作，后面即使还是 L1，也建议升级到 L2 询问一次。这样避免“自动操作雪崩”。

同时给审批流加超时：用户 30 分钟不确认，任务自动降级为“跳过该动作并记录”，而不是一直挂起。

### 5. 用 MCP tool definition 描述工具副作用

在 MCP 工具的元数据里写清楚：

- 是否幂等；
- 会不会修改外部状态；
- 建议的运行环境；
- 失败后的推荐回滚方式。

Agent 在规划阶段就能读取这些信息，自己先做一轮风险预判，而不是执行到一半才问。

## 踩坑点

### 1. 权限信息放在提示层，工具层裸奔

系统提示写得再严格，只要工具本身无权限检查，Agent 仍然可能绕过。权限必须落到工具执行入口。

### 2. 工具粒度过粗

一个 `run_command` 工具可以执行任意命令，等于把所有风险都塞进一个入口。应拆分成 `read_file`、`write_file`、`exec_shell`、`delete_file` 等细粒度工具，方便分桶。

### 3. 过度询问

把查看日志、读取配置也做成人工确认，会让 Agent 在长任务里频繁被打断。只读操作应该默认自动，否则自动化体验归零。

### 4. 长任务中途询问导致状态丢失

多步任务如果每一步都问，用户很容易漏看，Agent 也可能因为上下文丢失而重复执行或漏步骤。更好的方式是：**一开始让 Agent 给出完整计划，人类批准后执行到底，中间只在风险级别跳变时暂停。**

### 5. 审批流没有超时和降级

用户不在线时，任务可能一直挂着。建议加默认超时，并让 Agent 记录“未确认”状态，避免假死。

## 可复用建议

- **默认最小权限**：只给只读工具，写操作按需释放。
- **白名单优先**：已知安全操作（`list_files`、`get_status`）自动放行，不在白名单的进入审批。
- **dry-run 优先**：对可能改变状态的操作先模拟，展示 diff 或 plan。
- **审计与回滚**：每个自动动作记录工具名、参数、时间、结果；对重要操作准备回滚脚本或快照。
- **环境隔离**：dev 可以自动执行 L1/L2，production 收紧到 L2 确认。
- **定期复盘**：看审批通过率和误操作记录，动态调整动作分桶阈值。

## 总结

权限边界不是一次性配置，而是动态策略。核心原则是：**低风险可逆动作尽量自己干，高风险不可逆动作必须停下来问人。**

先在工具层定义动作风险等级，再通过权限检查、自动执行预算、审计日志和回滚方案把策略固化下来。这样 Agent 才能在保留自动化效率的同时，把爆炸半径控制在可接受范围内。
