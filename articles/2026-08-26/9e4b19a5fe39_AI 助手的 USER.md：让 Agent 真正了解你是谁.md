## 背景

在 OpenClaw 或自建 Agent 上接入 MCP、插件、定时任务后，最容易出现的问题不是“能力不够”，而是“它不够懂你”。同样一个任务，这次用 pnpm，下次用 npm；这次先问再改，下次直接操作；开发环境没问题，切到生产目录还是同一套激进策略。很多返工不是因为模型不会，而是它没有一个稳定的、关于你的上下文来源。

USER.md 就是把这个上下文固化下来：一个可版本管理、可审计、可注入的用户说明文件。

## 问题

缺少 USER.md 或等价用户上下文时，常见现象：

- 每次会话都问基础环境：Python 版本、包管理器、部署目录。
- 代码风格、提交规范、输出语言经常漂移。
- 自动化任务在“该先确认”的场景直接执行。
- 长会话或切换项目后，前面交代过的约束被淹没。
- 多项目偏好互相污染，例如个人项目习惯被带进生产项目。

## 做法/步骤

### 1. 确定文件位置与加载方式

建议分两级：

- 用户级：`~/.openclaw/USER.md`
- 项目级：`.openclaw/USER.md` 或 `.agent/USER.md`

加载方式可以是 OpenClaw 的 context files、system prompt 注入，或通过 MCP resource 暴露给 Agent。项目级优先，用户级兜底。

### 2. 用 frontmatter 标注作用域

```yaml
---
scope: personal
updated: 2026-03-18
priority: high
expires: never
---
```

这样做的好处是，脚本可以自动检查过期时间，避免 Agent 使用半年前的偏好。

### 3. 结构化写几个固定块

建议控制在 150–250 行，块结构如下：

- **我是谁**：身份、维护方向、技术栈，不要写成长简历。
- **当前目标**：让 Agent 知道“现阶段优先什么”，避免把长期愿望当成今天要执行的任务。
- **环境**：OS、shell、包管理器、常用路径、常见端口。
- **偏好**：语言、代码风格、提交信息格式、默认是否自动执行。
- **边界**：不能碰的目录、命令、数据；测试/生产环境区分。
- **沟通方式**：回答详细度、先方案后执行还是先执行后说明、失败如何上报。
- **示例**：1–2 条正确行为与错误行为对照，越具体越好。

例如：

> - 正确：修改依赖后，先运行 `pnpm lint && pnpm test`，再把结果汇总给我。
> - 错误：不要直接运行部署命令；不要修改 `deploy/` 下任何文件。

### 4. 设定优先级

明确规则：项目级 USER.md > 用户级 USER.md > 系统默认。

当项目规则与个人偏好冲突时，让 Agent 优先遵守项目规则，并在产生冲突时主动报告，而不是自行选择。

### 5. 维护

把 USER.md 当成代码。每次环境变化、踩坑、发现 Agent 越界后，就追加一条。控制总长度，详细内容用外链指向 docs。

## 踩坑点

- **太长**：超过 300 行后，模型注意力会稀释，关键约束反而失效。
- **写空话**：像“希望更高效”没有可执行性，要写“默认用 uv 管理 Python 依赖，不引入 poetry”。
- **敏感信息入文**：密钥、内网地址、账号信息不要放进全局 USER.md，应走环境变量或权限边界。
- **与系统提示冲突**：如果 OpenClaw 自带行为与 USER.md 不一致，要显式写“覆盖系统默认 X”，否则模型可能优先听系统提示。
- **未更新**：过期的 USER.md 比没有更危险，尤其是环境迁移后。
- **写成说明文档**：USER.md 不是项目文档，应该是“对 Agent 的约束和上下文”，不要塞满架构图。

## 可复用建议

- 三层结构：`global` 用户偏好、`project` 项目约束、`session` 临时覆盖。
- 给 Agent 增加一个“读取 USER.md”的工具，允许它不确定时主动查看，而不是只在启动时读一次。
- 对自动化任务增加字段：`dry_run: true`、`confirm_whitelist`、`allow_auto_deploy: false`。
- 用脚本做校验：检查 frontmatter、作用域、更新时间、行数。
- 每次 Agent 越界后，把失败案例追加到 `negative examples`，这比泛泛而谈更有效。

## 总结

USER.md 的核心不是“写得更像提示词”，而是给 Agent 一个稳定的用户模型。一个好的 USER.md 应当短、具体、分层、有边界、可执行。对 OpenClaw、Agent、MCP、插件和自动化实践来说，它往往比再加一个工具更能减少返工。
