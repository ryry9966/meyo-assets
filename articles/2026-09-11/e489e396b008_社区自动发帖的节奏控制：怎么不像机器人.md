## 背景

在 OpenClaw 社区，把 Agent 接进发帖链路已经很常见：版本说明、周度摘要、issue 分诊结果、插件更新通告。典型实现是 cron 定时加 MCP 工具调用，十几行配置就能跑起来。但跑起来之后，问题才真正开始。

## 问题

定点发帖的机械痕迹非常重：

- 每天 09:00:00 整触发，误差为零；有时连发三条，间隔两秒
- 模板一成不变，连标点都不带变的
- 频道正吵得热闹，它插进来一条无人问津的通告
- 服务恢复后重试没有间隔，一口气补发十几条

结果往往不是被封，而是更糟：**被静音**。发帖机器人的价值在于把信息送达人类，被静音等于功能失效。这里要把目标说清楚：节奏控制不是"伪装成人类"，bot 身份必须透明；要做的是消除机械行为模式，别让"太规律、太吵、太轴"消耗社区的信任。

## 做法

按影响排序，五步：

1. **时间抖动**：别用均匀随机——凌晨三点发帖比整点更失礼。用"活跃窗口 + 高斯抖动"：窗口 09:00–11:30，σ 取 25 分钟，中心偏向窗口前半段。
2. **合批**：事件驱动只保留最高优先级直发，其余进队列按摘要合批。八条小更新合成一条摘要，打扰成本直接降一个量级。
3. **活跃度感知**：发帖前检查频道状态——是否有进行中的热讨论、是否处于静默时段、距 bot 上次发帖是否超过最小间隔。不满足就推迟到下一个窗口。
4. **人工闸门**：按风险分级。低风险（摘要、统计）全自动；高风险（公告、对外口径）进队列等人确认，宁慢勿错。
5. **重试退避**：指数退避加上限，恢复后先去重合批再补发，禁止原样重放。

这些参数尽量收敛到一个 pacing 配置里：

```yaml
pacing:
  window: "09:00-11:30"
  jitter: { type: gaussian, sigma: 25m }
  quiet_hours: ["00:00-08:00"]
  min_gap: 40m
  batch: { max_items: 8, flush: "14:00-16:00" }
  retry: { backoff: exponential, cap: 3 }
```

## 踩坑点

- **抖动跨进深夜**：随机不等于任意时段，抖动范围必须卡在人类活跃区间内，否则观感比整点更差。
- **模板多样化做过头**：老成员认不出"这是那个摘要 bot"，辨识度也是资产。正确做法是变内容结构、固定身份标识。
- **有人建议去掉 bot 标识"更像人"**：不要。被识破的伪装，信任损失不可逆。
- **重试风暴**：网络抖一下，队列积压全部原样重发。补发前必须去重 + 合批。
- **时区**：跨时区社区里"上午九点"是谁的九点？按社区主体活跃时区配置，或统一按 UTC 定窗口。

## 可复用建议

- 节奏参数全部配置化，调参不该改代码。
- 先跑 dry-run：只记录"本应何时发什么"，观察一周再放行上线。
- 留反馈回路：统计每条的回复/引用数，连续 N 条零交互自动降频，别等用户来提 issue 才知道吵。
- 把 pacing 做成独立模块，任何发帖型 Agent 都能挂载复用。

## 总结

自动发帖"不像机器人"，核心不是模仿人类的随机性，而是尊重社区节奏：少打扰、可预期、出问题会退让。抖动解决太规律，合批解决太吵，闸门解决太自信，退避解决太轴。四件事做齐，机器人才能在社区里长期待下去。
