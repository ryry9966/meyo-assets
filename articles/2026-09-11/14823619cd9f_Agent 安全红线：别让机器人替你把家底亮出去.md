## 背景

最近社区里跑 OpenClaw 的同学越来越多：接 MCP 文件服务、挂内部知识库、配一堆自动化插件。遇到问题时，大家习惯性把"现场"贴上来求助——系统提示词、工具配置、会话日志、报错截图。这本身是社区互助的好事，但也是泄露的高发路径：你的 Agent 天天接触内部文档、路径、接口和流程，一次随手粘贴，可能就把整套工作方式交了出去。

## 问题在哪

实际出问题的场景基本是三类：

1. **贴日志带出上下文。** 会话日志和调试输出里，工具调用的参数经常包含文件内容、环境变量、内网地址，比想象中"脏"得多。
2. **配置即流程。** 完整的 system prompt + 工具清单 + MCP 拓扑贴出去，等于把你的自动化流水线画给别人看，里面往往还嵌着内部端点和命名习惯。
3. **Agent 主动外发。** 工具权限开得宽（比如文件系统给到根目录），再叠一个会联网/发消息的插件，一旦被诱导或产生幻觉，Agent 自己就能把内部信息整理成一段话输出——而你恰好在求助时把它导了出来。

一个关键认知：**写在 system prompt 里的"请勿泄露"不是安全边界，只是建议。** 真正的边界在权限和出口上。

## 做法

下面这套收敛方式可以直接复用：

1. **双配置分离。** 至少维护两套 Agent 配置：一套"内部工作"，工具全开；一套"社区调试"，只挂最小工具集（甚至只留对话），工作目录指向一个空的沙盒文件夹。去社区求助时，永远用第二套复现问题。
2. **权限按需白名单。** MCP 文件服务的可见目录用白名单圈定，不给根目录；每个插件单独审一遍读写范围；能不联网的就不联网。
3. **出口过滤。** 在输出侧加一层 hook/插件，对内网 IP 段、内部域名、密钥格式（如 `sk-` 前缀、token 串）、本机用户名做匹配，命中即拦截或脱敏。这层不追求完美，只求兜底。
4. **分享前人工过一遍。** 日志只贴报错段，不贴全文；截图裁掉终端路径和标签栏；配置里的路径、端点、用户名统一替换成占位符。我自己的习惯是贴之前搜三个词：真实域名、内网 IP、绝对路径。

## 踩坑点

- **以为删了 system prompt 就安全。** 会话历史里的工具调用参数往往比提示词本身更敏感。
- **`.env` 和凭据文件在 Agent 可读范围内。** 为了"省事"把工作目录开大，结果调试时 Agent 把 `.env` 内容读进了上下文，之后每一次导出都带着它。
- **截屏漏点。** IDE 标签页标题、终端 prompt 里的主机名，都是常见泄露源。
- **导出的"记忆/长期上下文"文件忘了脱敏。** 它是最容易被整份贴出来的东西。

## 可复用建议

- 固化一份**分享前检查清单**：工具清单只列名字不列参数；日志只贴报错段；路径/域名/密钥做占位符替换；导出文件先在本地过一遍脱敏脚本。
- 密钥按"已泄露"对待：只要怀疑进过上下文，直接作废轮换，不要赌。
- 把出口过滤沉淀成团队共用的插件和规则文件，比各自为战强得多。

## 总结

Agent 的能力半径越大，"贴出来求助"这个动作的风险就越高。守住红线靠的不是提示词里的一句叮嘱，而是三件事：最小权限、隔离的调试配置、出口上的机械过滤。让 Agent 帮你干活，但别让它替你交代家底。
