## 背景

用 Agent 做日常助手，最烦的不是模型不够聪明，而是它每次都"失忆"：代码风格要重新交代、时区和称呼要再说明一遍、上周刚纠正过的习惯这周又犯。会话无状态是 LLM 的默认行为，记忆系统本质上是在无状态模型外补一层有状态的存储和检索。

## 问题

常见做法有三种，各有坑：

1. **全量塞上下文**：把历史对话原文带进 prompt，token 成本线性上涨，噪声还会稀释真正重要的偏好。
2. **靠模型自觉记录**：让模型"觉得该记就记"，写入时机不稳定、格式随机，一周后文件里全是无法检索的自然语言碎片。
3. **只写不删**：记忆只增不减，过时条目和新条目冲突，模型每次随机采信一边，行为不可预测。

核心矛盾：写入要少而准，读取要相关而不冗余，生命周期要有人管。

## 做法

我的方案是**分层记忆 + 结构化写入**，落地在 OpenClaw 的 workspace 里，通过 MCP 工具读写。

**1. 分三层**

- 偏好层：稳定事实，如代码风格、回复语言、常用工具，量最小，价值最高；
- 情节层：会话摘要，按周聚合，用于回溯"当时怎么决定的"；
- 程序层：验证过的工作流（如部署步骤），可被 skill 直接引用。

重点在偏好层，每条记录用固定 schema 存 JSONL：

```json
{"key":"code.style","value":"单引号,2空格缩进","scope":"global","confidence":0.9,"source":"user-explicit","updated":"2025-06-01","hits":12}
```

**2. 写入走显式工具调用**，不靠模型自由发挥。两条触发路径：用户说"记住…"时立即写入；会话结束由定时任务跑一次摘要，抽取候选偏好，低置信度的先进 staging，下次使用前确认。

**3. 读取按 scope + 相似度取 top 3~5**。会话启动时注入偏好层命中条目；情节层只在用户提到"上次"时检索；项目级偏好挂独立命名空间，避免串台。

**4. 更新规则写死在流程里**：新旧条目相似度超阈值时走覆盖而非追加，保留 updated 历史；hits 长期为 0 的条目降权；用户可随时查看、编辑整个记忆文件——文件就是唯一真相源。

## 踩坑点

- **记忆污染**：一条错误偏好（比如误记"用户喜欢 tab 缩进"）会被反复注入。必须支持一句话覆盖写回，别让用户去翻文件。
- **作用域泄漏**：公司项目的编码规范混进个人项目。scope 要在写入时强制指定，读取时过滤。
- **隐私**：API key、密码绝不进记忆文件，写入工具里加一层黑名单校验。
- **写入时机**：只在会话结束做摘要，会漏掉中途的即时纠正，"记住"触发词必须当场响应。
- **同步冲突**：多设备用 git 而不是网盘，后者会产生无法合并的重复条目。

## 可复用建议

- 先做读路径：哪怕只有一份手写偏好文件，注入 prompt 的收益已经很明显，写路径可以后补。
- schema 宁小勿大：key/value/scope/confidence 够用，字段越多模型越容易写歪。
- 记忆必须用户可见可改，黑盒记忆库等你发现污染时已经晚了。
- 用 git 管理记忆文件，diff 天然就是审计日志。

## 总结

记忆系统的本质不是"存得多"，而是写入克制、检索相关、生命周期可控。三层分离加结构化 schema，配合显式工具调用写入和人工可编辑的存储层，几百行代码就能让 Agent 的长期表现稳定一个档次。先让记忆可见，再谈自动化。
