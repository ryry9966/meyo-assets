## 背景

OpenClaw 的 Agent 每次会话都会把 workspace 里的上下文文件装进提示词：`CLAUDE.md`/`AGENTS.md` 描述项目，`SOUL.md` 描述助手人格，但长期缺一块——"你是谁"。纯编码场景里项目上下文够用，可一旦把它当日常助理，它面对的默认是一个匿名、无时区、无偏好的通用用户。

## 问题

后果很具体：

- 每次都要重新解释：我用中文、我在 UTC+8、别贴大段无关代码；
- 靠会话记忆"慢慢认识你"，但记忆是黑盒，会积累噪声，记错之后难以批量修正；
- 个性化依赖模型现场猜，风格不稳定。

记忆机制解决"发生过什么"，解决不了"我一直是谁"。后者更适合声明式文件：可读、可改、可进 git。

## 做法

在 workspace 根目录建 `USER.md`，Agent 启动时作为用户上下文注入。我的结构分五段：

1. **基本事实**：称呼、时区、语言偏好、作息窗口；
2. **角色与工作**：职责、长期项目、技术栈、团队常用工具；
3. **偏好**：回答详略、代码风格、结论是否先行；
4. **边界**：明确不做的事（比如未经确认不要给真人发消息）；
5. **稳定背景**：愿意让 Agent 纳入考量的长期约束。

每条写成稳定陈述句，例如"默认中文回复，技术名词保留英文"。控制在 60 行以内——它每轮都占上下文。

## 踩坑点

- **写成简历**：初版我写了 150 行，每轮白烧 token，Agent 还会过度引用无关信息。删到 40 行后行为反而更准。
- **放时效性内容**："本周在赶 X 上线"两周后就变成毒数据。这类内容放日报和记忆里，USER.md 只放半衰期长的事实。
- **塞敏感信息**：密钥、证件号绝对不要。这个文件会整段进提示词，等于发给了模型服务商。
- **与记忆冲突**：记忆里存着"用户喜欢简短回复"，USER.md 又写"复杂问题要展开"，行为就会摇摆。稳定事实以 USER.md 为单一事实源，记忆只存事件。

## 可复用建议

- 把 USER.md 当配置管理：进 git，改动走 commit，每季度 review 一次；
- 让 Agent 协助起草："根据我们的对话，建议 USER.md 增加或删掉哪些条目"，但 diff 必须人工过目；
- 关注点分离：USER.md 写用户，SOUL.md 写助手人格，别混在一个文件里；
- 一条准入标准：**如果这条信息三个月后仍然成立、且会影响回答，才值得进 USER.md。**

## 总结

USER.md 不是记忆系统的替代品，而是把"用户画像"从模型猜测变成显式契约。成本是几十行 Markdown，收益是 Agent 不必每次重新认识你。建议先只写时区和语言偏好两条，跑一周，再决定往里加什么——这本身也是个迭代过程。
