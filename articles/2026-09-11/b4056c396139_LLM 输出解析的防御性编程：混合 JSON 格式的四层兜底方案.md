## 背景

在 OpenClaw 插件和 MCP 工具链里，让模型输出 JSON 再交给代码消费是高频路径：工具参数抽取、定时任务的结构化结果、Agent 间消息传递，都压在这一步。理想情况是模型严格按 schema 输出，但只要接多个模型、迭代过几版提示词、或用户侧走不同网关，你很快会发现：**解析失败不是偶发 bug，而是常态噪声**。

## 问题

实际拿到的输出形态远比文档里写的杂：

- 有 ` ```json ` 围栏的、裸 ` ``` ` 围栏的、完全没有围栏的；
- JSON 前后带一句"以下是结果："之类的说明文字；
- 推理类模型前缀 `<think>...</think>`；
- 中文语境下的全角引号、全角冒号；
- 尾逗号、行内注释、Python 风格的 `True/None`；
- 最麻烦的一种：字符串值本身包含反引号代码块，朴素正则一删就切碎 JSON。

`JSON.parse` 一抛异常，整条自动化流水线就断在中间。

## 做法：四层解析，逐层降级

把解析收敛到一个模块，内部按破坏性从低到高分四层：

1. **L1 归一化**：去 BOM、trim、剥 `<think>` 块；
2. **L2 直接解析**：先试裸 `JSON.parse`，多数干净输出到此结束；
3. **L3 候选提取**：先取"首个围栏 + 其后最近的结束围栏"（不要贪心匹配到文末）；失败再做字符串感知的括号配平扫描，从第一个 `{` 或 `[` 取到配对位置；
4. **L4 修复重试**：对候选串依次尝试尾逗号清理、全角标点替换、`True/None` 归一，每修一次 parse 一次，成功即返回。

彻底失败时不要抛裸异常，抛带原始输出的类型化错误，上层可选择带错误信息回问模型（有界重试，上限 1–2 次），或降级为结构化错误对象让流水线继续走。

```typescript
export function parseModelJson(raw: string): unknown {
  // L1 归一化
  const text = raw.replace(/^\uFEFF/, "")
    .replace(/<think>[\s\S]*?<\/think>/g, "")
    .trim();
  // L2 直接解析
  try { return JSON.parse(text); } catch { /* fallthrough */ }
  // L3a 首个围栏 + 其后最近的结束围栏（惰性匹配，不贪心）
  const fence = text.match(/```(?:json)?\s*([\s\S]*?)```/);
  if (fence) {
    try { return JSON.parse(fence[1].trim()); } catch { /* fallthrough */ }
  }
  // L3b 括号配平扫描（字符串与转义感知）
  const start = text.search(/[{[]/);
  if (start >= 0) {
    const cand = extractBalanced(text, start);
    if (cand) {
      for (const fixed of repairs(cand)) {   // L4 修复：由低破坏到高破坏
        try { return JSON.parse(fixed); } catch { /* next */ }
      }
    }
  }
  throw new ModelJsonParseError("unparseable model output", raw);
}

function* repairs(s: string): Generator<string> {
  yield s;
  yield s.replace(/,\s*(?=[}\]])/g, "");                 // 尾逗号
  yield s.replace(/,\s*(?=[}\]])/g, "")
    .replace(/[“”]/g, '"').replace(/[‘’]/g, "'")
    .replace(/\b(True|False)\b/g, m => m.toLowerCase())
    .replace(/\bNone\b/g, "null");                       // 动标点放最后
}

function extractBalanced(s: string, start: number): string | null {
  const open = s[start], close = open === "{" ? "}" : "]";
  let depth = 0, inStr = false, esc = false;
  for (let i = start; i < s.length; i++) {
    const c = s[i];
    if (esc) { esc = false; continue; }
    if (c === "\\") { esc = true; continue; }
    if (c === '"') inStr = !inStr;
    if (inStr) continue;
    if (c === open) depth++;
    else if (c === close && --depth === 0) return s.slice(start, i + 1);
  }
  return null;
}
```

## 踩坑点

1. **贪心删围栏**。`/```[\s\S]*```/` 会把两个代码块之间的内容全吞掉，代码生成类任务里必踩。用惰性匹配或直接上括号配平。
2. **全局替换中文标点**。全角引号可能就是字符串值的合法内容，所以替换只能放在 parse 失败后的修复层，且顺序放最后。
3. **无界重试**。解析失败就无限回问模型，token 和延迟都会失控，务必设上限并记录次数。
4. **迷信 JSON mode**。结构化输出确实该开，但本地模型和第三方网关不保证支持，解析器不能省。
5. **裸存原始输出**。排障需要留存 raw，但里面可能带用户数据，注意脱敏和保留期。

## 可复用建议

- 解析逻辑只写一份，全插件共享，别在每个 handler 里各写一套正则；
- 每层加计数埋点，按模型和提示词版本统计命中率——坏输出率是回归提示词的硬指标；
- 线上修过的坏样本脱敏后进测试集，解析器任何改动都跑回归；
- 提示词端配合 few-shot 和"只输出 JSON"约束，把失败率从 20% 压到 2%；剩下那 2% 靠解析器兜底。

## 总结

防御性解析的本质是承认概率：提示词负责降低格式漂移的概率，解析器负责把剩下的小概率事件变成确定性行为。这套四层结构一下午就能落地，但它决定你的自动化是"基本能用"，还是"敢挂到生产上无人值守"。
