## 背景

OpenClaw 工作区里有一组 Markdown 文件承担"启动上下文"的角色：`AGENTS.md` 管行为规范，`SOUL.md` 管人格基调，`USER.md` 管用户本身。实践中我发现，大多数人对前两个文件抠得很细，`USER.md` 却常常是空的，或者只有一行名字。

## 问题

后果很具体：

1. **每次冷启动**。"我用 pnpm 不用 npm""服务跑在家里的 Debian NUC 上"这类话，一个月要重复十几次；
2. **回答不对味**。Agent 默认给泛化方案，环境、技术栈、习惯全靠猜；
3. **记忆错位**。不少人把关于自己的长期事实塞进 `MEMORY.md`，和会话沉淀的动态记忆混在一起，越滚越大，检索质量跟着下降。

`USER.md` 和 `MEMORY.md` 的分工应该很清晰：前者是**稳定的、关于你的事实**，后者是**会话中动态产生的记忆**。

## 做法

我的 `USER.md` 大概长这样：

```markdown
# USER
## 基本情况
- 后端开发，主力 Go，辅助 Python
- 机器：MacBook Pro + 家庭服务器（Debian / Docker Compose）
## 技术偏好
- 包管理 pnpm；编辑器 Neovim；终端优先
## 沟通偏好
- 中文回复；先结论后过程；不确定就直接说不确定
## 红线
- 不要碰 ~/.ssh 和 crontab
- 任何删除操作先确认再执行
```

步骤建议：

1. 翻最近两周的聊天记录，把重复解释过的内容列出来——这是命中率最高的素材；
2. 按**事实而非指令**来写。`永远用 TypeScript` 是行为规范，放 `AGENTS.md`；`主力语言是 TS` 是事实，放 `USER.md`，让 Agent 自己推断默认值；
3. 篇幅控制在 40 行以内，它是每次会话都要加载的常驻成本；
4. 进 git，改动可追溯；
5. 用一两周后回看，删掉 Agent 从未实际用到的条目。

## 踩坑点

- **写成简历**。两百行的自我介绍，每次会话都占 token，实际命中率很低；
- **写秘密**。API key、完整内网 IP 段千万别放——`USER.md` 会进每次上下文，等于向所有会话广播；
- **指令和事实混写**。混写之后行为无法归因：改了一行"事实"，Agent 行为大变，排查起来很痛苦；
- **信息过期**。换了机器、换了语言栈不更新，Agent 会持续按旧环境给方案，而且看起来"很有道理"；
- **过度画像**。我写过"偏好简洁寒暄"，结果 Agent 连必要的技术上下文确认都省了。

## 可复用建议

- 把 `USER.md` 当**配置文件**而不是日记。配置文件的精神是：短、准、可版本化；
- 分层：关于你的稳定事实放 `USER.md`，项目相关约定放各项目的 `AGENTS.md`，动态记忆交给 `MEMORY.md`；
- 像对待依赖一样定期 review，我固定每月第一天过一遍；
- **红线一节收益最高**，优先写。它把破坏性操作的确认从"碰运气"变成"有据可查"。

## 总结

`USER.md` 的价值不在"Agent 更懂你"这种感性描述，而在工程上消灭重复输入、降低答非所问的概率，并把安全边界显式化。四条原则：40 行以内、只写事实、带上红线、进版本控制。做到这些，维护成本接近于零，收益却贯穿每一次会话。
