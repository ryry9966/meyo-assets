## 背景

OpenClaw 里每个 agent 都有独立的工作空间，默认在 `~/.openclaw/workspace/`。会话启动时，agent 会读取工作空间根目录下的 `AGENTS.md`——这份文件不参与任何代码执行，它唯一的作用是告诉 AI：这个空间里有哪些约定、哪些规矩、哪些雷区。可以把它理解为新同事入职第一天拿到的那份 README。

## 问题：没有它，agent 每次都在重新摸黑

实际用下来，缺 AGENTS.md 的 workspace 常见三种症状：

1. **文件乱放**。让 agent 整理笔记，这次建在根目录，下次塞进 `downloads/`，第三次干脆新建一个 `output_final_v2/`。
2. **重复踩坑**。上次明确纠正过的错误（比如不要改动 MEMORY.md 的结构），隔几个会话又犯——因为那条指令只存在于聊天记录里，会话结束就丢了。
3. **边界不清**。哪些操作可以先斩后奏、哪些必须先问，全靠模型自由发挥。接入 MCP 工具和插件之后，这个问题会被进一步放大。

## 做法：五段式骨架，控制在百行以内

我的 AGENTS.md 大致按这个结构写：

```markdown
# Identity
（一两句话：这个 agent 是谁、服务谁）

# Environment
（固定路径、操作系统、常用目录的用途）

# Workflow
（文件命名规则、产出放哪、每日/每周例行动作）

# Security
（绝不外发的信息类型、敏感操作前必须确认）

# Escalation
（哪些事必须先问，哪些可以直接做）
```

关键原则：**每条都写成可执行的祈使句**。“小心处理文件”是废话；“不要移动或重命名 MEMORY.md，只允许追加”才是规则。

## 踩坑点

- **写太长**。AGENTS.md 每个会话都会被读进上下文，两百行的“根本大法”意味着每次对话都在为它付费。我实测压缩到 60 行左右，行为没有劣化。
- **和其他文件抢职责**。AGENTS.md 管静态规则，MEMORY.md 管长期记忆，USER.md 管用户画像。把记忆塞进规则文件，等于让手册越写越厚，还互相稀释。
- **规则含糊或互相冲突**。出现两条冲突规则时，模型执行哪条接近随机，而且事后你很难定位是规则的问题。
- **改了忘提交**。AGENTS.md 本质是配置，不进 git 的话，换机器或回滚时全靠回忆。

## 可复用建议

1. **把每次纠错沉淀成规则**。agent 做错事，除了当场纠正，多花十秒判断：这是不是该写进 AGENTS.md 的通用规则？这个习惯的复利非常高。
2. **规则按优先级排布**，安全类放最前面。
3. **接入 MCP / 插件后单独开一节**，写清楚“优先用哪个工具、什么情况不要调用”，比在每次 prompt 里反复强调省事得多。
4. **每月删一次**。过时规则和过时代码一样，是负债不是资产。
5. **多 agent 场景按需拆分 workspace**，公共约定放共享层，个性规则留在各自的 AGENTS.md，避免一份文件服务所有人的互相妥协。

## 总结

AGENTS.md 是 OpenClaw 里成本最低、杠杆最高的配置文件：不用写一行代码，只是把你脑子里“这个 agent 该怎么干活”的预期落成文字。写得越像给新同事的操作手册——具体、简短、可执行——agent 的表现就越稳定。如果目前你的 workspace 根目录还没有这个文件，今天就值得花二十分钟补上。
