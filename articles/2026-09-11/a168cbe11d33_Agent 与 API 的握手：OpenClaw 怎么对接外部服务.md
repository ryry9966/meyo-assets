## 背景

OpenClaw 的价值不止在对话，而在"能动手"：读日历、查工单、调内部接口、触发自动化。这些动作本质上都是 Agent 与外部 API 的握手——模型决定"调什么、传什么"，运行时负责"怎么调、调完怎么回"。接得顺，Agent 是生产力；接得糙，它就是一个不可控的脚本触发器。

## 问题

过去几个月接了五六个外部服务（一个工单系统、一个日历服务、两个内部 HTTP API、一个对象存储），踩出来的共性问题有三个：

1. **凭证怎么放**。写进 prompt 或全局配置都容易泄漏，日志一打就出去了。
2. **调用不可靠**。网络抖动触发重试，一个 POST 重发两次，工单系统里多了两条重复记录。
3. **权限没有边界**。图省事把管理员 token 直接挂上，Agent 一次参数幻觉差点把测试环境数据清了。

## 做法

我的主路径是 MCP，轻量场景用自定义 tool，步骤如下：

**1. 选接入方式。** 优先找现成的 MCP server；没有就自己写一个薄封装（MCP server 或 HTTP 工具），把鉴权、超时、限流收在自己这一层，不把原始 API 直接暴露给模型。

**2. 凭证走环境变量。** API key 只放环境变量或本地加密配置，server 启动时注入，任何情况下不进 prompt、不进日志。

**3. 工具 schema 收窄。** 参数能用 enum 就用 enum，必填字段标清楚，description 里写明"这个工具做什么、副作用是什么"。参数空间越小，模型幻觉越少。

**4. 先 dry-run 再上真。** 每个写操作先实现 `dry_run=true` 模式，返回"将要执行的操作"，链路确认无误再放开。

**5. 超时与幂等。** 所有调用设显式超时；只读接口才允许自动重试，写接口必须带幂等键，重试时复用同一个键。

**6. 每次调用落日志。** 记录工具名、参数摘要、耗时、状态码，出问题时能回放。

## 踩坑点

- **重试导致重复写入**：最贵的一课。现在写操作一律带幂等键，服务端不支持的就在封装层自己去重。
- **schema 太松**：早期一个时间参数只写了 string，模型传过"明天下午"这种值。改成 ISO 格式描述加 enum 限制时区后才稳定。
- **MCP 工具全量自动放行**：某次新增工具没审查就开了自动批准，Agent 直接调了一个级联删除接口。之后新工具一律先只读验证。
- **凭证进了调试日志**：日志打印过完整请求头，改成只记 key 的后四位。

## 可复用建议

- **薄代理层思维**：永远不让模型直连第三方 API，中间那层是你的安全带。
- **最小权限双 token**：读和写分开，Agent 默认只拿只读凭证，写操作走确认流程。
- **少而精的工具集**：十个马虎的工具不如三个测试充分的工具，工具越多，模型选错的概率越高。
- **破坏性操作加人工确认**：删除、批量写、对外发送，一律 confirm 后再执行。

## 总结

对接外部服务，难点从来不是"连上"，而是连得**可控、可观测、可回滚**。把鉴权、幂等、超时这三件事在封装层做扎实，Agent 的握手才是可靠的握手。OpenClaw 提供了很好的扩展面，但边界要自己画——这部分的责任，没有现成配置替你兜底。
