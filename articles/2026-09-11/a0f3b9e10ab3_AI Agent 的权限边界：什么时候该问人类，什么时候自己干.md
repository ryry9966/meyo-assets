## 背景

当 Agent 从"聊天"变成"执行"，问题的性质就变了。接上 MCP、插件、Shell 之后，Agent 的每一步都可能是真实世界的副作用：写数据库、发消息、动支付。OpenClaw 这类框架把工具调用做得足够顺手，顺手到很容易忘记一件事——不是所有动作都该由模型自己决定。

## 问题：两个极端都不对

- **全部自动**：一次工具输出注入、一条幻觉路径，就可能删错表、发错公告。不可逆动作没有刹车。
- **全部问人**：每次调用都弹审批，人很快开始无脑点确认，审批流形同虚设，自动化价值归零。

真正的工程问题不是"要不要问人"，而是**哪些动作必须问、哪些可以放行、用什么粒度问**。

## 做法：按风险给动作分级

**第一步，盘点所有工具调用**，按两个维度分类：

1. **可逆性**：改完能不能撤？读操作天然可逆；写文件可以回滚；发消息、删数据、对外付款基本不可逆。
2. **爆炸半径**：只影响一份草稿，还是影响生产数据、外部用户？

由此得到四档：

- **A 档·自动放行**：只读、纯本地计算、可逆且影响小的写操作（如写临时文件）。配置成白名单，不弹审批。
- **B 档·带护栏自动**：可逆但面广的写操作。强制先 dry-run 输出 diff，限定每日调用配额，执行后写审计日志。
- **C 档·必须审批**：不可逆、对外、涉及钱和权限的动作。Agent 只能生成结构化的"审批请求"（含真实参数和影响范围），人类确认后才执行。
- **D 档·直接禁止**：无论模型多自信都不给的工具，比如改自身权限配置。

**第二步，把分级写成配置文件**而不是散落在 prompt 里，进代码评审——权限变更要有 diff、有记录。

**第三步，用数据迭代**。跑两周审计日志，把 B 档里零事故、高频的动作逐步升到 A 档，把频繁误触发的降下来。权限是活的，不是一次定死。

## 踩坑点

- **审批疲劳**：C 档一天弹 30 次，人一定会开始无脑通过。控制 C 档数量，宁缺毋滥。
- **粒度错误**：按"每次工具调用"审批太碎，按"整个计划"审批又看不到细节。折中方案是计划开始前审一次摘要，执行到 C 档动作时再逐个确认。
- **重试吞掉审批**：审批通过后调用失败，Agent 自动重试时可能绕过闸门。审批凭证要与单次执行绑定，重试需重新确认。
- **审批内容造假**：让人看的必须是工具的真实参数和 diff，而不是 Agent 自己写的摘要——模型可能"描述得很安全"。
- **异步审批超时**：审批等 10 分钟没人理，任务静默挂死。要预先定义超时策略：取消、降级还是默认拒绝。

## 可复用建议

- 新工具**默认 C 档**，观察后再降级；升级靠审计日志说话，不靠感觉。
- 所有自动放行都带**预算**：次数、范围、时间窗。
- 审计日志记三样：**谁批准的、原始参数、执行结果**。
- 每月回顾一次分级表，像复盘 on-call 事故一样对待。

## 总结

权限边界不是安全功能的附属品，而是 Agent 设计的核心输入。判断标准可以压缩成一句话：**可逆且影响小的，让 Agent 自己干；不可逆、对外、动钱的，结构化地问人；问不清楚的，先禁止。**先用最保守的配置跑起来，再用数据逐步放权——这比一开始就追求"全自动"靠谱得多。
