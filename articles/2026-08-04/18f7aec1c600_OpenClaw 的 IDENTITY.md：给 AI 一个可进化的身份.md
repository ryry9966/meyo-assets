## 背景

OpenClaw 用户大多经历过同一个困惑：Agent 用着用着就"不像自己了"。上下文一长，风格漂移、越界行为、忘记用户偏好，这些往往都源于身份信息是死的。IDENTITY.md 不该是一个写死的一次性角色设定，而应该是 Agent 自我认知的条目库。问题在于，大多数人把它当成了静态 prompt。

## 问题

静态 IDENTITY.md 有三种典型失效模式：

1. 过期：工作流早就换了，文件里还写着三个月前的偏好；
2. 膨胀：什么都往里面塞，最后变成一本没人读的说明书；
3. 漂移：Agent 自行改了自己的行为描述，但没有任何记录和约束。

身份应该是"基线清晰、外围可演化"的，而不是一成不变或彻底失控。

## 做法

### 1. 拆分三段式结构

把 IDENTITY.md 显式分成三块：

- `[CORE]`：不可变约束，铁律，Agent 无权修改；
- `[PREFERENCES]`：可演化偏好，经审批后可改；
- `[CHANGELOG]`：每次变更的日期、原因、触发上下文。

### 2. 给 Agent 一个受控的修改通道

不要直接授权 Agent 改文件，而是暴露一个 `update_identity` 的 MCP 工具。工具内部做三件事：

- 校验修改范围：只能动 `[PREFERENCES]`，碰到 `[CORE]` 直接拒绝；
- 强制追加 changelog 条目，带上触发会话的摘要；
- 把变更标记为"待确认"，由人审批后才生效。

身份更新用工具做：工具管得住权限，人管得住审批，模型管不了越权。

### 3. 用 git 托底

IDENTITY.md 纳入版本管理。每次漂移都能 revert，也能看到 Agent 是什么时候、基于哪段上下文改了自己。建议工具内部输出 `git diff --stat`，让每次修改自带可审计的脚印。

### 4. 定期做身份整理

每 N 次会话或每周做一次 consolidation：从 changelog 里提炼稳定偏好，把一次性的临时判断挪到 memory 或 notes，保证 `[PREFERENCES]` 里只保留"至少连续三次都成立的结论"。

## 踩坑点

- 最大的坑：让 Agent 直接在文件系统上改文件。绕过工具即绕过校验和审批，一次误改污染后续所有会话。
- 第二个坑：把事实当身份。用户说"今天用中文回我"是上下文，不是身份。IDENTITY 只放跨会话稳定的东西。
- 第三个坑：没有 changelog 的修改。改完不知道改了啥，出问题无法归因。

## 可复用建议

- 身份文件控制在 150 行以内，超出就做 consolidation；
- 每次变更必须回答"为什么改、哪个会话触发的"；
- 用 IDENTITY.md + memory/ + CONFIG 分离关注点：身份管稳定性，memory 管临时上下文，CONFIG 管系统行为；
- 对 CORE 部分做哈希校验，防止工具逻辑被绕过。

## 总结

可进化的身份不是让 Agent 自由生长，而是在约束下持续收敛。把 IDENTITY.md 当作一套带权限控制、版本审计、定期整理的"活代码"，它才不会变成漂移的源头。工程化思路只有一句话：身份是资产，必须可审、可回滚、可解释。
