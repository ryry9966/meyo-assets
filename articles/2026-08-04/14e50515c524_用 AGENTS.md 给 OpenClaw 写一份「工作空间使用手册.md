## 背景

用了几天 OpenClaw 之后，我遇到一个典型问题：agent 在仓库里「迷路」。

它不是找不到文件——VSCode 的 workspace 让它能看到所有目录。它是不知道我要它按什么方式工作。同一个仓库里，哪些文件是生成物、哪些目录不该动、release 流程是手工还是自动、代码风格是什么，它一概不知。于是它发挥「合理猜测」，把不该改的改了，该走的流程跳了，产出一堆需要人工返工的东西。

问题不在模型能力，在于我从未告诉它这个工作空间的「使用规则」。AGENTS.md 就是为了解决这件事。

## 什么是 AGENTS.md

一句话：**写给 AI 阅读的 README**。README 是给人看的项目介绍，AGENTS.md 是给 agent 的工作空间使用手册，描述在进入这个仓库后应该遵循的操作约束和上下文约定。

它类似 Claude Code 的 CLAUDE.md，但 AGENTS.md 是跨工具约定，OpenClaw、Cline 等主流 agent 方案都原生支持。OpenClaw 在初始化工作区或加载会话时，会检索根目录和当前目录下的 AGENTS.md 注入到系统上下文中，让 agent 在动手前先读到你的「使用说明」。

## 我的做法

写 AGENTS.md 不需要额外插件，一个 Markdown 文件即可。放在仓库根目录，agent 进入 workspace 时会自动加载。

我的模板分四块，每块都极短：

```markdown
# AGENTS.md

## 工作区说明
- 本项目是 [一句话描述]
- 主分支为 dev，release 由 CI 负责，不要直接在 main 提交

## 运行与验证
- 启动命令：`npm run dev`
- 测试命令：`npm test`，改动前必须跑
- 构建命令：`npm run build`

## 关键约束
- `generated/` 目录下所有文件是构建产物，禁止手动修改
- 配置文件的真实来源是 `config/base.yaml`，其他环境配置由脚本生成
- 新增第三方依赖需先说明理由，不可直接安装

## 工作流
- 需要改前端组件时，先查 `src/components/` 下的同名索引
- 遇到 API 变更，同步更新 `docs/api.md`，否则 CI 会挂
- 一次只做一个任务，完成后停下等确认
```

实际使用中，前面加一段「你是 OpenClaw 环境中的工程助手，工作目标是……」，帮助 agent 锚定角色。

在 OpenClaw 里检查它是否被正确加载，可以跑 `claw --debug` 或者在交互中问一句「你读到的 AGENTS.md 里，关于 generated 目录的约束是什么？」。

## 踩坑记录

几个真实踩过的坑：

1. **index 文件污染上下文。** 如果工作区里存在大量 AGENTS.md（比如 node_modules 里有第三方自带的），OpenClaw 会全部注入。解法：在项目根目录写一个明确的 AGENTS.md，并注明「覆盖以下子目录中的同名文件」，同时在 `.gitignore` 排除 node_modules 里的 AGENTS.md。

2. **过度具体导致 agent 变傻。** 我第一版把某个模块的内部实现细节全写了进去，agent 反而不敢动手，每一步都回来问。克制一点，只写「规则、边界、验证方式」，不要写「怎么做」。

3. **Todo 文件与 AGENTS.md 冲突。** agent 读到的约束如果和你给的独立 Todo 指令矛盾，行为不可预测。现在我把 Todo 里涉及全局规则的内容抽出来放进 AGENTS.md，只保留任务级指令在 Todo。

4. **中文编码兼容性。** AGENTS.md 用 UTF-8 无 BOM 没问题，但如果用户用的是 Windows 记事本默认保存，可能带 BOM，个别 agent 解析会出现首个标题识别异常。统一用编辑器保存为 UTF-8 without BOM。

5. **约束要写「为什么」而不是只写「不能」。** 「禁止手动修改 generated 目录」不如「generated 目录是构建产物，手动修改会在下次 build 时被覆盖」。agent 理解了原因之后，在类似场景下可以做出更合理的判断。

## 可复用的建议

- AGENTS.md 是给 AI 看的，不是给人看的。文件越短越有效，超过 100 行需要拆分。
- 命令类信息要写全：`npm test` 而不是「跑测试」。
- 把「最常见的三类错误」直接写进去作为反面样例，比规则描述更管用。
- 多个项目共用的规则（比如「不要自动 commit」）放进全局配置，不要在几个 AGENTS.md 里各写一份。
- 改了 AGENTS.md 的时候，开一个新会话验证，因为旧会话的 system prompt 已经固定，不会实时更新。

## 总结

AGENTS.md 的本质是：把工作空间的隐性约定显性化。它无法解决所有 agent 行为偏差，但能把「碰运气式合作」变成「有据可依的执行」。对用了 OpenClaw 但还没建这个文件的团队，建议今天就在主仓库加一个，总成本十分钟，省下的是每次返工的时间。
