## 背景

在 OpenClaw 里编排多 Agent 流程时，常见做法是让主 Agent 派发子 Agent 去做检索、跑 MCP 工具、清洗数据这类子任务，子任务跑完把结果汇总回来。听起来干净，但如果你不主动做 session 隔离，子 Agent 的对话、工具调用、中间输出会全部写进主会话的历史里。多跑几个任务，主会话就废了。

## 问题

不隔离的后果是三类：

1. **上下文膨胀**。主会话很快被子任务的中间过程塞满，有效上下文被挤占，主 Agent 的决策质量肉眼可见地下降。
2. **状态串扰**。子 Agent 里某个工具改了状态（变量、资源路径、临时文件），主会话拿到的是一份被污染的环境。
3. **排障困难**。主会话和子会话混在一起，出了错你分不清是哪一层、哪一步、哪个 Agent 干的。

## 做法

核心思路：给每个子 Agent 一个独立的 session，主会话只接收最终结果。

**第一步，显式划分 session。** 启动子 Agent 时指定一个新的 session，而不是复用主会话的 context。相当于给每个子任务一个独立工作台，主会话的工作台保持干净。

**第二步，限制写入范围。** 子 Agent 完成后只返回显式声明的结构化结果，主 Agent 只解析这个返回值，绝不读取子 Agent 的中间对话。隔离要体现在契约上，而不是靠自觉。

**第三步，隔离工具会话。** 如果子 Agent 要调用 MCP 工具，单独给它分配独立的 MCP session 或工具实例，避免复用主会话里已建立的连接和状态。

**第四步，打标识。** 每个子会话带上 task_id，写到日志里。事后回溯时，能从日志里直接串起"主任务 → 子任务 → 工具调用"的完整链路。

## 踩坑点

- **只隔 session 没隔凭据。** 子会话独立了，但底层工具调用的 key 是共享的，子任务间接触碰主会话的配置。要确认凭据的作用域和 session 是绑定的。
- **返回值夹带私货。** 有些子 Agent 把整个对话历史塞进返回值，等于隔离了又没隔离。必须在代码层校验返回结构，超出的字段直接丢弃。
- **异步回收过早。** 异步编排下，子 session 的生命周期管理不当，结果还没回来 session 就被回收了，报错还很隐蔽，只在超时日志里露出一行。

## 可复用建议

- 命名规范：主会话 `main-xxx`，子会话 `task-{task_id}`，一眼可辨。
- 建立一个轻量 session 注册表，记录每个子 session 的状态、归属任务、存活时间。
- 在 system prompt 里写死"子 Agent 必须返回结构化结果"，同时代码层做校验，双保险。
- 子任务完成后及时清理 session，避免磁盘和内存堆积。

## 总结

Session 隔离不是可选项，是多 Agent 场景的卫生底线。把子任务关进独立 session，主会话只留结果，上下文干净了，状态不串了，排障也快了。改造本身不复杂，收益却是整个系统稳定性的。趁还没被污染，早点做。
