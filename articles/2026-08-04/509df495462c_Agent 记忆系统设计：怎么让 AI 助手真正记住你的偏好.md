## 背景

从 ChatGPT 普及到 OpenClaw/Agent 落地，最常被吐槽的不是"能力不行"，而是"刚说完就忘"。对话历史并不等于记忆：会话窗口一清，Agent 立刻回到陌生人状态。做自动化任务、跑批处理的人对这点最有体会——偏好设置要是每次重新交代，Agent 的自动化就名存实亡。

## 问题

我见过三种常见的"伪记忆"方案，全部翻车：

1. **全量塞上下文**：几千条历史全进 prompt，token 烧钱，且有效信号被噪声淹没。
2. **无脑向量化**：所有对话丢进向量库，检索到的 top-k 十个里八个是噪音。
3. **轻信式写入**：用户随口说一句"今天别用 markdown"，就被记成永久偏好；第二天正常需求全被改坏了。

核心矛盾是：**记忆不等于存储，记忆是"在合适的时机、以合适的粒度、取回合适的信息"**。

## 做法

我在 OpenClaw 里做的是三层记忆 + 受约束的工具调用：

**第一层：会话缓冲**。一个 JSONL 滚动窗口，只留最近 N 轮，用于连贯性和短期任务状态，不落盘为长期数据。

**第二层：偏好档案**。一个结构化的 `profile.json`，格式固定：

```json
{
  "preference": {
    "key": "response.style.markdown",
    "value": "false",
    "scope": "issue_tracker",
    "confidence": 0.8,
    "updated_at": "2025-06-01",
    "source_msg_ids": ["m-1234", "m-1288"]
  }
}
```

关键是写入策略：**只接受两种来源**——用户明确说"以后都这样"，或者同一偏好 7 天内出现 ≥2 次（用 `source_msg_ids` 溯源）。单次出现的一律不进档案，只放第三层。

**第三层：长期知识库**。向量检索（FAISS/LanceDB），用于事实回忆、偏好佐证。但检索不裸用 top-k，加时间衰减：
`score = similarity × (0.5 + 0.5 × decay(updated_at))`，近 30 天的记忆有加成，一年前的即使相似度再高也降权。

工具侧只暴露三个操作：`search_memory(query, top_k=3)`、`update_profile(key, value, scope)`、`deduct_and_collapse()`（定时把零散记录压实成概括性条目）。Agent 不能直接写文件，只能调工具，所有写入都走统一 schema。

## 踩坑点

- **全量向量化是灾难**。偏好记忆必须"先摘要、再入库"，原始对话扔进去只会让检索退化成关键词匹配。
- **偏好覆盖冲突**。用户某场景说不用 markdown，配置成全局后其他场景全乱。解决：`scope` 字段必填，全局值只允许在用户明确说"我平时都怎样"时写入。
- **隐私漂移**。原始消息可能含密钥/人名，落盘前做泛化脱敏，比如把邮箱替换为 `<user_email>`。
- **冷启动乱猜**。无档案时 Agent 容易脑补偏好，我加了一个"偏好未知度"阈值，低于阈值就明确向用户提问，而不是猜。

## 可复用建议

1. 给记忆条目加 TTL 和定期 review pass，三个月没召回过的条目自动降级。
2. 保留 `memory inspect` 命令，让用户能直接看到"我记住了你什么"。信任是记忆系统的地基。
3. top_k 宁小勿大，3 条精确命中远好于 10 条似懂非懂。
4. 整个记忆目录纳入版本控制，回滚偏好错误时成本极低。

## 总结

好的记忆系统应该像"不打扰的管家"：**少写、精写、按需取**。在 OpenClaw 里，这本质上就是一组受约束的工具调用加一个被检查和审计的存储目录。先限制写入来源，再做分层检索，最后留好审计入口——这三步做完，AI 助手才算真正"记得你"。
