# MCP 协议入门：Model Context Protocol 到底解决了什么问题

## 背景

如果你在 OpenClaw 里配过插件，或者在别的 Agent 框架里接过多模型，大概率遇到过这样一类问题：调天气 API 写一套鉴权逻辑，查数据库写一套连接逻辑，接内部工具又是一套自定义 schema。每个工具都是一次点对点集成，维护成本随工具数量线性甚至超线性增长。

MCP（Model Context Protocol）最初是 Anthropic 开源的一个协议，本意是标准化模型与应用、工具、数据源之间的交互。现在它已经不只是某个公司的项目，而是一个社区事实标准。今天不吹概念，就讲一个实际问题：它到底替我们省了哪些事。

## 问题

在引入 MCP 之前，Agent 框架接一个外部工具大致要经历这几步：

1. 定义工具入参和出参格式
2. 写工具调用的鉴权
3. 实现工具发现（让 Agent 知道有哪些工具可用）
4. 处理错误和上下文拼接

这些逻辑每个工具做一遍，且不同框架的实现互不兼容。OpenClaw 这边如果你维护过多个 plugin，应该有过这种感受：插件框架自己的接口形态决定了大半的集成工作量，有些是内置的，有些是外部 adapter，但每个新工具进来都要重新走一遍集成流程。

MCP 的核心思路其实很简单：**把工具本身做成一个小服务，模型和 Agent 框架只通过一个标准协议去调它。**

## 做法/步骤

以 OpenClaw 里挂一个 MCP server 为例，完整链路大概是：

1. 起一个 MCP server（可以是 stdio 模式，也可以是 SSE / streamable HTTP）。最简单的方式是直接用官方 SDK，写一个 30 行的 server，暴露一两个工具。
2. 在 OpenClaw 的配置里声明 MCP 连接：指定 transport 类型、endpoint、超时等参数。
3. OpenClaw 启动时走 MCP 的 initialize 握手，拿到工具列表并注册到运行时。
4. 对话中 Agent 需要调用工具时，通过 MCP 协议把调用请求发到 server，返回结构化结果。

这一步做完的最大变化是：一个新工具接入，不需要改 OpenClaw 核心代码，也不需要重写插件。MCP server 自己把协议、鉴权、输入输出格式都管好，框架侧只是多了一个“已经知道的工具”。

## 踩坑点

说几个实际会碰到的问题：

**第一，transport 模式的选择不能只看文档。** stdio 适合本地进程，SSE/HTTP 适合远程部署。但如果你在容器里跑 OpenClaw，连外部 MCP server 时注意 HTTP 模式的超时设置——很多 SDK 默认超时很短，流式响应容易超时断连。

**第二，工具描述的质量直接影响召回率。** MCP 的 tool description 就是 Agent 识别“什么时候该用这个工具”的唯一依据。写得太泛，模型会在不该调用的时候乱调；写得太窄，该调的时候不调。这是一层隐性成本，不只是多写几个字的问题。

**第三，MCP server 自身要稳。** MCP 复用的是一个长连接通道，如果 server 端出现未捕获异常导致连接断了，Agent 可能不会自动重连。建议在 server 侧做简单的 panic recovery 和 graceful shutdown。

**第四，OpenClaw 的配置项名和别家的不完全一致。** 如果你从 n8n 或 Cursor 迁移配置过来，注意参数名差异，不要想当然直接复制。

## 可复用建议

给几条实际经验：

- 新工具接入时，第一个动作不是写代码，而是定义一个最小的 MCP server 原型，把 schema 跑通，再往里面填逻辑。这能帮你尽早发现协议层的坑，而不是业务逻辑和协议问题混在一起。
- 工具粒度控制在“一个 function 干一件事”的水平。把太大、太杂的操作拆成多个 MCP tools，这样 Agent 的意图分类会更准。
- 状态管理放 server 侧，尽量保持无状态。每个 MCP 调用都当成一次独立请求来处理，避免 Agent 上下文和 server 状态错配。
- 如果团队里多个项目要复用一个工具，直接起一个公用的 MCP server 按 namespace 区分工具，比每个项目重写一遍高效很多。

## 总结

MCP 没有解决 Agent 的智能问题，也不承诺提升推理效果。它做的是把“工具接入”这件事从零散的硬编码变成了标准协议对接。对于 OpenClaw 用户来说，这意味着维护成本下降、工具复用性变强、迁移框架时少一层重写成本。

这几年 Agent 框架层出不穷，今天用这个明天用那个，MCP 至少让“工具”这一层不再需要跟着重来。如果你还没接入过，找个小工具起一个 server 试试，十分钟就能体会到差别。
