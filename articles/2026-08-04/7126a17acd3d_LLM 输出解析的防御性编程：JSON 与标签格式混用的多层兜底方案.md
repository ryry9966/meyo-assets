## 背景

在 OpenClaw / Agent 插件开发里，`JSON.parse(llm_output)` 是重复率最高的失败点。Agent 循环中，模型返回给工具的参数、MCP 服务器回传的结构化数据、插件从长文本里抽取的结果，全都要过这道解析关口。但大模型不是 JSON-RPC 服务端——它会在 JSON 外加 Markdown 代码块、随手包一层 `<output>` 标签、开头先写一句"好的，结果是"，结尾补个尾逗号。拿严格解析器去对付概率分布的输出，属于自杀式编程。

## 问题

实测常见五种污染形态：

```json
```json
{"a": 1}
```
```

```
<output>{"a": 1}</output>
```

```
好的，结果如下：{"a": 1}
```

```
{"a": 1,}  // 尾逗号
```

```
{ a: "1" }  // 键没加引号
```

任何一层不处理，插件就直接报错，Agent 循环中断。

## 做法

核心思路：解析管线分层兜底，每一层失败才降级到下一层，优先级按可靠性递减排列。

1. **预清洗**：去 BOM、去首尾空白
2. **直接解析**：`JSON.parse` 原生走一遍（绝大多数正常输出在这一步过掉）
3. **代码块提取**：匹配 \`\`\`json ... \`\`\` 取内部内容
4. **标签提取**：匹配 `<output>` / `<result>` 等包裹，取标签间内容
5. **启发式截取**：用括号配对算法取第一个 `{` 到与其匹配的 `}`（不能用首尾截取）
6. **兜底抛错**：返回原始文本前 500 字符作为错误上下文

伪代码：

```ts
function parseLoose(raw: string): unknown {
  const candidates = [
    raw.trim(),
    extractFence(raw),
    extractTag(raw, ['output', 'result', 'json']),
    extractBalancedBraces(raw),
  ];

  for (const candidate of candidates) {
    try {
      return JSON.parse(repair(candidate));
    } catch { /* 进入下一层 */ }
  }

  throw new Error(`LLM output unparseable: ${raw.slice(0, 500)}`);
}
```

`repair()` 只做保守修复：去尾逗号、将单引号外套的双引号转义规范化。过度修复（比如正则替换注释）宁可跳过，交给下一轮重试。

## 踩坑点

- **首尾截取 `{` 和 `}` 是错的**：字符串里出现 `"text {x}"` 会截断 JSON。必须用栈配对括号
- **清洗顺序别反**：先删标签会把代码块内的 `<output>` 文本误删；先取代码块会把纯标签包裹的输出丢掉。按"直接 → 代码块 → 标签 → 截取"的顺序递减可靠性
- **别动原始输出**：日志永远记录原始串，清洗只在解析函数内部发生。否则排障时你根本不知道模型实际吐了什么
- **正则不是解析器**：正则只能兜底，不可能正确处理嵌套和转义。写再复杂的 pattern 都别指望它替代括号配对
- **MCP 场景要降级而非崩溃**：解析失败时，把错误信息拼进下一轮 prompt 让模型重试，而不是让工具直接抛异常中断整个会话

## 可复用建议

- 把 `parseLoose()` 放进插件公共库，OpenClaw 各工具脚本统一引用，避免每个插件各写一份坏掉的解析器
- 解析成功后再做 schema 校验（zod / Valibot），确认 `id` 是字符串还是数字，类型错了照样重试
- 工具返回契约写成"要求模型输出 `<output>JSON</output>` 格式"，但解析端必须兼容无标签情况——**契约要严格，实现要宽容**
- 在解析器里埋一层 fallback 计数：线上统计显示长期超过 2 层兜底，说明 prompt 格式约束失效，该修 prompt 而不是修解析器

## 总结

防御性解析不是偷懒，是对随机性的尊重。大模型的输出本质是概率分布，解析层就该按概率分布做全覆盖兜底。分层管线 + 原始日志 + schema 校验 + 失败重试，这一套组合能让插件从"偶发崩溃"变成"自动纠正"。这不性感，但这就是 Agent 工程化的分水岭。
