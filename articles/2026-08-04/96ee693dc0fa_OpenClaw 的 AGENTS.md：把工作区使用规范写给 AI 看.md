# 背景

OpenClaw 的 agent 会话是无状态的。每次新会话，模型对项目的认知从零开始：不知道你的 MCP server 配置、不记得代码风格、不清楚哪些命令被允许。很多用户把期望寄托在 system prompt 里，但实际效果是——每次都花大量对话轮次重新"教育" agent，或者接受它产出的、风格不一致的结果。

AGENTS.md 就是来解决这个问题的：把它放在工作区根目录，作为 agent 行为约束的持久化文件。它不是给人读的文档，是给 AI 执行的"操作手册"。

# 问题

没有 AGENTS.md 时，典型症状：

- 每轮对话都要重申"用 `claw` 执行而不是直接跑 docker"
- agent 在多个可选的 MCP 工具之间随机选择，输出不稳定
- 文件命名、目录规范被反复违反
- 同一个错误，换个会话又犯一遍

根因不是模型笨，是上下文缺失。你在人脑里的隐性知识——约定、偏好、禁令——agent 完全感知不到。

# 做法

## 1. 提炼"稳定知识"

只放可复用的信息：常用命令、工具选择偏好、目录约定、任务流程。不要把临时任务、一次性请求写进去。

## 2. 结构化组织

推荐分层：

```
# 项目概述（3行以内）
# 命令清单（高频命令 + 禁止命令）
# MCP / 工具选择（什么任务用哪个 server）
# 规范（命名、路径、提交信息格式）
# 工作流（典型任务的执行顺序）
```

## 3. 语气用祈使句

写"执行测试时使用 `pytest -x`"，不要写"你可以考虑使用 pytest"。AGENTS.md 的读者是模型不是人类，指令性语句的遵循率显著更高。

## 4. 验证生效

写完后做一个测试会话，故意触发那些你希望被阻止的行为，观察 agent 是否引用文件中的规则。不看效果就上线，等于没写。

# 踩坑点

- **过长**：超过 200 行就开始挤占上下文预算。写不下的内容拆到独立文件，在 AGENTS.md 里只留指引。
- **规则矛盾**：比如既说"优先用 MCP 的 memory server"，又在另一节说"所有数据存本地文件"。矛盾会让模型行为随机化。
- **放过期信息**：MCP server 地址变了、命令弃用了，AGENTS.md 还在写旧接口——它比没有更糟。
- **不进版本管理**：AGENTS.md 是代码，请进 Git。能 diff、能回滚，否则你永远不知道 agent 为什么变"笨"了。

# 可复用建议

1. 初始版本控制在 80-120 行，覆盖命令、规范、工作流三块即可。
2. 建立错误复盘习惯：每个 agent 反复犯的错，都转化成一个 AGENTS.md 条目。
3. 为不同类型的任务指定默认工具链，消除随机行为。
4. 每 2-4 周审视一次文件，删掉无效条目，更新变动信息。
5. 在会话 prompt 中显式引用它："先阅读 AGENTS.md 再开始"。

# 总结

AGENTS.md 的本质是你与 agent 之间的一份契约：把散落在你脑中的工作习惯，变成可审查、可 diff、可演进的文件。它不会让 agent 更聪明，但会让 agent 更稳定——而这恰恰是自动化实践中最缺的东西。
