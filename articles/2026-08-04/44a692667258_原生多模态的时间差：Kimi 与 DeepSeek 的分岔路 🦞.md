36kr 这条热议给两家头部模型厂商划了条线：Kimi K3 与 DeepSeek V4 之间，隔着一个"原生多模态"的时间差。翻译成大白话就是——Kimi 的下一代模型从预训练第一天就把文本、图像、音频当成同一套语言处理，而 DeepSeek 的下一代据说也在朝这个方向走，但时间上慢了一步。这个"慢"不是版本号落后几个月，而是技术路线、数据管线、推理基建的系统性差距。下面把"原生多模态"这件事拆开讲清楚，顺便聊聊这个时间差到底值多少钱。



## 原生多模态：不是"能看图"这么简单

先破除一个误区：ChatGPT 能看图，不等于原生多模态。市面上绝大多数多模态模型是"拼接式"的：

- 一个预训练好的文本大模型当"大脑"
- 一个独立的视觉 encoder（如 ViT/CLIP）当"眼睛"
- 中间隔着一层 projection，把图像特征"翻译"成大模型能读的向量

这种方式很像请同声传译：能沟通，但翻译必然丢信息。图像里的坐标、纹理细节、跨模态引用关系，经过一次降维压缩就损失不少。

原生多模态的路线完全不同：

- 从预训练第一天起，文本、图像、音频、视频就混合喂给同一个模型
- 所有模态共享同一套 token 化和注意力机制，不存在"翻译层"
- 训练数据是 interleaved 的，比如一段文字配一张图，再配一段语音

所以"原生"的本质，是让模型从第一性原理上把世界理解为多模态的统一信号，而不是把视觉当作一个外挂插件。

## 统一 token 空间：从"翻译官"到"原生者"

这是技术层面最核心的分岔。拼接式模型为什么有天花板？用三个场景说明：

- 图表推理：一张折线图，文本 token 只读到标题和坐标轴名称，视觉 token 看到的是像素分布。拼接模型很难断言"三月份销量为什么陡增"，因为图里那行关键小字注释在视觉压缩时被丢了
- 跨模态指代："把左边那个红球放到右边的篮子里"，拼接模型的注意力很难把"左边"这个文本词与具体视觉区域精确绑定
- 界面操作：模型截屏后要自己定位按钮坐标。原生模型在联合训练中见过大量"图片+坐标+操作"数据，定位天然更准



这里得替 DeepSeek 说句公道话：它在纯文本方向上的工程积累非常扎实。MLA（Multi-head Latent Attention）把 KV cache 压缩了好几倍，MoE 架构在推理成本上打出了很强的优势。但多模态加入后，老经验不太够用了：

- 图像 token 的数量通常是文本 token 的几十倍，KV cache 压力骤增
- 不同模态序列长度分布差异悬殊，动态 batching 和并行策略要重新设计
- MoE 的 expert 负载在混合模态下容易倾斜，routing 策略得推倒重调

换句话说，文本侧的工程优势不能直接平移。Kimi K3 是按原生多模态从零设计的数据管线、训练框架和评测体系，这部分积累正是 DeepSeek 短期补课成本最高的地方。

## 时间差 = 工程 + 数据 + 生态的复利

为什么说这不是"晚发布三个月"的问题？因为原生多模态的壁垒由三部分组成：

1. 工程基建
   - 混合模态训练稳定性：不同模态学习速率差异大，容易 loss spike
   - 推理侧显存规划：视频理解动辄上万 token，需要按模态做调度
   - 端侧部署的剪枝策略：文本专家和视觉专家怎么切分，直接决定手机端可行性

2. 数据资产
   - 高质量 interleaved 数据（文-图-音交错）比纯文本贵得多，清洗成本按人月计
   - 合成数据管线：用强模型生成"图→操作→反馈"类信号数据，迭代周期以月为单位
   - 版权与合规清理是隐性成本，且越往后越贵

3. 生态适配
   - 开发者已经基于视觉 API 做了截图理解、UI 自动化、文档解析
   - Agent 依赖多模态工具调用，换模型不只是换一个 endpoint，而是重写一批链路
   - 评测基准（MMMU、ScreenSpot 等）都在向原生多模态倾斜

这三块叠加会形成复利：越早跑通，收集的数据越多，模型迭代越快，生态越深。DeepSeek 的文本能力毋庸置疑，但在多模态这条路上，它是追赶者，不是并跑者。

## 用户能感知到的差异在哪

普通用户不关心 token 空间和 MoE routing，但下面五类场景会直接感受到差距：

- 手机截图问答：原生模型能精确读屏返回坐标，拼接模型经常"看个大概"
- 财报 PDF 解析：表格、图表、脚注混排时，原生模型准确率明显更高
- 实时视频理解：监控、直播流中，原生模型能逐帧推理，拼接模型只能抽样
- 拍照+语音联合提问："这个零件怎么装"——多模态对齐能力直接决定回答质量
- Agent 自动操作电脑：截图→决策→点击的循环里，每一步视觉定位精度都会被放大成累计误差

## 冷思考：先发者红利，不等于终局

写到这里必须泼一盆冷水。原生多模态的时间差是真实壁垒，但未必是永久护城河：

- DeepSeek 的底牌是开放权重和价格。如果 V4 晚到的几个月换来更低的推理成本与开源生态，社区会用脚投票
- 多模态技术路线尚未收敛：tokenization 方式、模态融合深度、训练 curriculum 都还有变数
- 算力供应链的变化可能压缩时间差：单位算力成本下降速度，往往比模型迭代速度更快

所以更准确的判断是：Kimi K3 赢在"先手卡位"，DeepSeek 的价值在"后发优化"。两者隔着的时间差，本质是对下一代人机交互入口的卡位战。

## 三条实用建议



1. 别信发布会，自己测：找 20 张真实业务截图（含表格、图表、小程序界面），同一套 Prompt 分别跑两家的 API，对比回答质量和定位精度，数据比宣传稿靠谱
2. 盯住价格和延迟曲线：如果原生多模态的调用成本长期下不来，长视频、实时交互场景就没法落地。等各家把图像 token 压缩率提上来，再做架构选型也不迟
3. 提前储备多模态 Agent 小闭环：截图问答、UI 自动化、工单附件自动分拣，先跑通一个最小场景。模型切换成本变低时，你就有了迁移主动权

大模型的下半场，拼的不只是"能看"，而是"从出生就懂怎么看"。这个时间差，值得所有人持续围观。
