## 背景

OpenClaw 社区里，越来越多人在跑多 Agent 自动化。工具链越来越顺，但一个反复出现的问题是：Agent 进入工作空间后，经常"不知道该干什么"。它读代码、猜命令、试错，然后浪费一堆 token 做错事。

你缺的不是更好的模型，而是一份 `AGENTS.md`。

## 问题

Agent 的上下文窗口有限，且无法像人一样"浏览"项目。它进入工作目录时，面对的是完全陌生的环境：不知道用什么语言、不知道构建命令、不知道哪些文件是生成的、不知道 MCP 工具该不该调用。

结果就是：

- Agent 用 `node` 跑 Python 项目
- 把 `dist/` 目录当成源码改
- 不调用 MCP 工具，反而去 parse 文件
- 每次会话都在重复"发现"项目的常识

这些问题，靠 prompt 调教解决不彻底。你需要在工作空间里放一份给 AI 看的"使用手册"——这就是 `AGENTS.md`。

## 做法：怎么写一份真正有用的 AGENTS.md

### 第一步：创建入口文件

在仓库根目录创建 `AGENTS.md`。同时保留 `README.md` 给人看，`CLAUDE.md` 给 Claude Code 用。**不要合并，不要互相引用**。三者的读者不同，维护成本远低于误导成本。

### 第二步：按模块组织，不要按流程组织

一份好的 `AGENTS.md` 包含这几块：

```markdown
# 项目一句话定位
## 常用命令（精确到可复制粘贴）
## MCP 工具能力说明（哪些可用、哪些不可用）
## 目录地图（标注：源码 / 生成物 / 勿动）
## 常见任务拆解（3-5 个高频任务）
## 禁止事项（避免 Agent 自作主张）
```

### 第三步：写精确值，不要写描述

❌ 错误写法：

```markdown
构建项目：使用项目的构建工具，参见 package.json
```

✅ 正确写法：

```markdown
构建项目：npm run build -> 产物输出到 dist/
格式化代码：npx prettier --write src/
验证一切 OK：npm run lint && npm test
```

Agent 对精确命令的遵循率，远高于对自然语言描述的遵循率。你写"用包管理器安装依赖"，它可能用 yarn；你写 `npm install`，它就一定用 npm。

### 第四步：显式声明 MCP 工具边界

如果你挂了 `filesystem`、`github` 等 MCP 服务器，在 `AGENTS.md` 里写明：

```markdown
## MCP 工具

- filesystem: 允许读取 src/ 与 docs/，禁止递归列表 node_modules/
- github: 允许读 issue、PR，禁止创建分支
- 未列出的工具，默认不可用，需要先询问
```

默认拒绝，比默认放权安全得多。

## 踩坑点

**坑 1：写过长的任务流程**

`AGENTS.md` 超过 300 行，Agent 会选择性遗忘。它只保留最重要的指令。优先级：命令 > 目录 > 禁令。流程性的内容尽量写进任务脚本，而不是写进文档。

**坑 2：两份文档漂移**

`README.md` 和 `AGENTS.md` 同时存在，更新了一个忘了另一个，等你重建会话时，Agent 读到的和实际环境不一致，所有操作全偏。建议在 CI 里加一个校验：读取 `AGENTS.md` 中出现的命令，逐一执行 `--help` 检查是否存在。

**坑 3：把 AGENTS.md 当万能规则库**

不要写"始终使用最佳实践""保持代码整洁"这种抽象话术。Agent 无法量化判断。要写就写："所有新文件必须包含 MIT license header"，这种可以被验证的规则。

**坑 4：不给"临时文件"出口**

Agent 工作时免不了产生临时脚本或调试输出。如果没有声明，它会随手把文件写在项目根目录。建议在 `AGENTS.md` 里固定一个 `tmp/` 目录，并写入 `.gitignore`，让 Agent 有明确的"垃圾堆放处"。

## 可复用建议

1. 在 `AGENTS.md` 开头放一段 3 行以内的"身份卡"：项目是什么、主要语言、构建系统，一次性交代清楚
2. 所有命令必须从实际验证过能运行的命令中拷贝，不要在没跑通的情况下写进文档
3. 把 `AGENTS.md` 纳入代码 review 范围，改动需要和代码改动一起合入
4. 在 OpenClaw 的会话配置中，将 `AGENTS.md` 设置为 pre_session_prompt 的引用文件，确保每个新会话自动加载
5. 每月做一次"Agent 盲测"：删除所有上下文，只保留 `AGENTS.md`，让 Agent 从头执行一次部署流程，记录所有卡壳点，然后修复文档

## 总结

`AGENTS.md` 的本质，是把你头脑中关于工作空间的"隐性知识"外化为 Agent 可读取的"显性规则"。它不需要写得像技术手册那样全面，只需要聚焦高频操作、精确指令和硬性边界。

写好了，Agent 是可靠的执行者；写不好，Agent 就是昂贵的随机数生成器。花一个小时写完这份文档，能省下未来千百小时的对齐成本。
