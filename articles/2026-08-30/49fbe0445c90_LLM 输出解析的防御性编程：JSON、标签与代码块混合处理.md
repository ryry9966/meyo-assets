# LLM 输出解析的防御性编程：JSON、标签与代码块混合处理

## 背景

在 OpenClaw、Agent、MCP 工具调用和插件自动化链路里，经常要求 LLM 输出 JSON，用来驱动参数生成、配置更新或工具路由。但真实模型输出往往不是干净的标准 JSON：外面包着 ````json` 代码块，前面带一句“好的，以下是结果：”，或者用 `<json>` 标签包裹，甚至同一个回复里混着解释文本、多个候选 JSON 块和总结。

如果只按理想格式做 `json.loads`，线上会频繁出现解析失败。防御性编程的目标，不是要求模型“输出再标准一点”，而是让解析器能够兼容真实世界的混合格式，并在失败时给出可定位的信息。

## 问题

常见的混合形态包括：

- Markdown 代码块：````json`、````jsonc`、````json5` 或裸三反引号包裹；
- XML 风格标签：`<json>...</json>`、`<output>...</output>`，有时还带属性；
- 自然语言前后缀，例如“这是结果：”和“希望能帮到你”；
- 同一输出中出现多个 JSON 对象或数组；
- 尾逗号、单引号、注释、未引号 key 等非标准语法；
- BOM、零宽字符导致首字符解析失败。

正则提取容易引入新问题：`\{.*\}` 贪婪匹配会跨多个对象，非贪婪又可能截断嵌套。直接从第一个 `{` 开始取也可能误选解释文字中的 JSON 片段。因此需要一套分层、可评分的候选提取流程。

## 做法 / 步骤

1. **预处理**
   先去除 BOM、零宽字符（如 `\u200b`、`\ufeff`）、首尾空白，统一换行符。这一步可以解决大量“首字符异常”问题。

2. **候选区域提取**
   按优先级提取：
   - 先找 Markdown 代码块，支持 ````json`、````jsonc`、````json5` 以及裸 ```` ``` ````；
   - 再剥离 XML 风格标签，例如 `<json>...</json>`。不要硬编码属性，定位到第一个 `>` 之后取内容；
   - 如果以上都没有，从文本中第一个 `{` 或 `[` 开始，用平衡扫描器找到完整结构。

3. **平衡扫描器**
   不要用正则去数括号。维护一个栈，遍历字符时：
   - 遇到 `{` 或 `[` 入栈；
   - 遇到 `}` 或 `]` 时，如果栈顶是对应的开括号则弹栈；
   - 当栈第一次变空时，截取完整候选区间；
   - 字符串状态下必须忽略 `\"` 和 `\\`，否则字符串内的大括号会干扰扫描。

4. **候选评分**
   多个候选片段时，按以下规则选择最佳：
   - 解析器验证成功的优先；
   - 长度更长、嵌套更深的对象或数组优先；
   - 如果调用方有预期类型，例如 MCP 工具要求 object，则优先选 object；要求 list，则优先选 list。

5. **分级解析**
   - 第一层：标准 `json.loads`；
   - 失败后：使用 `json5`，它能兼容单引号、尾逗号、注释、未引号 key；
   - 再失败：做保守修复，例如将 `True/False/None` 转为 `true/false/null`，去除尾逗号。不要盲目替换所有单引号为双引号，因为会破坏字符串中的撇号。

6. **保留元信息**
   解析过程中应记录：最终选择的候选区间、使用哪种解析器、是否丢弃了前后缀。若全链路失败，返回结构化错误并保留原始文本片段，避免直接抛裸异常导致 Agent 中断。

## 踩坑点

- **代码块不闭合**：模型可能只写了开头的 ```` ```json ````，没有结尾。此时应回退到平衡扫描器。
- **带属性的标签**：`<json type="object">` 用简单正则匹配尖括号会把属性带进 JSON 内容。应先定位标签名，再找第一个 `>` 结束。
- **字符串状态遗漏**：平衡扫描如果在字符串里还继续匹配括号，遇到 `"a{b"` 这类内容就会提前判空。必须正确处理转义。
- **BOM 干扰**：很多从流式响应拼接出的 JSON 带 BOM，标准 `json.loads` 会报错，预处理必须去除。
- **多候选误选**：模型先说“好的，结果如下：”再给代码块，如果只找第一个 `{`，可能选中说明文字里的碎片。应优先提取 fence 内 JSON。
- **尾逗号高频出现**：标准库解析失败，但 `json5` 可以解决。注意 `json5` 对数字格式和 `NaN` 更宽容，如果后续有严格 schema 校验，需要额外限制。
- **单引号替换风险**：不要用全局 `replace("'", "\"")`，这会破坏 `"it's"` 这类字符串。

## 可复用建议

- 封装一个 `extract_json(text, expect_type=None)`，统一走预处理、候选提取、评分、分级解析，返回 `(data, meta)`。
- 将解析器选择写入 `meta`，例如 `meta["parser"] = "json5"`，便于线上定位问题。
- Agent 工具参数解析、MCP 返回结构解析都用同一个入口，避免各写一套正则。
- 建立回归样例集：嵌套对象、字符串含大括号/引号、代码块包 JSON、标签包 JSON、尾逗号、多候选、BOM、注释，全部纳入单元测试。
- Prompt 中可以明确要求“只输出 JSON，不要解释”，能降低混合格式比例，但不能替代防御性解析。

## 总结

模型输出解析位于 Agent 与工具调用的交界处，稳定性直接影响整条链路。与其用正则硬提，不如用平衡扫描器发现候选，用评分选择最优区间，再用分级解析器兼容常见非标准语法。保留解析路径和元信息，是比“能跑就行”更可靠的工程实践。
