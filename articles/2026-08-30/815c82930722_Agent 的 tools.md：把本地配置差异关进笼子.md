## 背景

Agent 需要调用本地命令、脚本或 MCP 工具，但开发机、CI、生产环境的路径、依赖版本、认证方式往往不同。直接把命令写进 prompt 或代码，会让 Agent 换个环境就失效。tools.md 作为工具清单与配置入口，能把差异显式化，而不是让 Agent 靠猜。

## 问题

常见三个坑：

1. 命令硬编码，例如直接写 `python`，但有人机器上是 `python3`，有人是 conda 环境。
2. 环境变量散落各处，数据目录、缓存目录、密钥路径各写各的。
3. 工具描述和实际实现不一致，Agent 按描述调用，结果命令不存在或行为不同。

这些问题在单机调试时不容易暴露，一旦切到同事电脑或 CI 容器，就会变成反复试错。

## 做法 / 步骤

### 1. 用 tools.md 定义工具契约

每个工具至少包含：名称、用途、命令模板、环境变量、前置检查命令。不要写绝对路径，只写占位符。

```markdown
| name       | purpose      | command                                      | env       | check          |
|------------|--------------|----------------------------------------------|-----------|----------------|
| pdf_to_text| 提取 PDF 文本 | `${PDF_BIN} --input ${INPUT} --output ${OUTPUT}` | PDF_BIN   | `${PDF_BIN} -v` |
| search_code| 本地代码搜索 | `${CODE_SEARCH_BIN} --query ${QUERY}`          | CODE_SEARCH_BIN | `${CODE_SEARCH_BIN} --health` |
```

### 2. 按环境拆分文件

维护 `tools.base.md` 放通用定义，`tools.local.md` 放机器差异，启动时合并。合并顺序为：base → env → local override，后加载的覆盖前面的键值。

### 3. 校验与 dry-run

Agent 启动或工具调用前，对 tools.md 做 schema 校验，并对每个工具执行：

- 命令存在性检查（`command -v`）
- 路径存在性检查
- 版本探测或 `--health` 检查

失败的工具标记为不可用并降级，不要把坏工具暴露给 Agent。

### 4. 通过 wrapper 统一入口

所有工具调用都经过 `run_tool.sh <tool_name> [args]`，wrapper 负责加载环境、切换目录、检查依赖、返回 JSON。tools.md 只记录逻辑名称，不关心底层命令。

```bash
#!/usr/bin/env bash
set -euo pipefail
TOOL_NAME="$1"; shift
case "$TOOL_NAME" in
  pdf_to_text)
    exec "${PDF_BIN:-pdftotext}" "$@"
    ;;
  *)
    echo '{"error":"unknown tool"}' >&2
    exit 2
    ;;
esac
```

## 踩坑点

- **不要相信 `which` 的结果**：可能找到 shim 或错误版本。建议用显式环境变量，并做 `--version` 校验。
- **Windows 与 POSIX 差异明显**：路径分隔、环境变量语法、扩展名都不同。最好为每个平台提供 wrapper，tools.md 只管理逻辑名称。
- **密钥别写进 tools.md**：用环境变量引用，如 `${GITHUB_TOKEN}`，并限制 Agent 只读必要的环境变量。
- **tools.md 改了不生效**：给文件加 hash 或 mtime，变更后触发 reload 或重启。
- **工具描述漂移**：尽量让 tools.md 从 manifest/wrapper 自动生成，或定期用脚本比对，避免文档和实现两张皮。

## 可复用建议

- 维护一份 `tools.schema.json` 校验 tools.md 结构，防止拼写错误或字段缺失。
- 如果工具通过 MCP 暴露，可以把 MCP server 启动配置集中在 `mcp.json`，tools.md 只做索引，例如 `search_code: mcp:local-code-index`。
- 为每个工具写一条 failure hint，Agent 失败时能给出环境修复建议，而不是无限重试。
- 模板里统一用 `${VAR}` 占位符，启动时一次性解析，避免运行时多次替换。

## 总结

tools.md 的核心不是记录命令，而是管理“环境差异”。把它当作契约层：声明式、可合并、可校验、可降级。这样 Agent 才能在不同机器上稳定工作，而不是把时间花在猜路径和排查环境上。
