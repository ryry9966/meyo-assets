# AI Agent 的权限边界：什么时候该问人类，什么时候自己干

## 背景

Agent 已经从“聊天”走到“调工具”。在 OpenClaw、MCP、插件这类工程化场景里，接入一个工具的成本越来越低，但权限边界的建设往往落后。于是容易出现一种情况：Agent 自动删除资源、重复下单、把测试配置推到生产、或者给外部发了一封不该发的邮件。

这些问题通常不是模型“不够聪明”，而是没有一个稳定的 action policy。权限边界不应该只靠 prompt 告诉模型“小心一点”，而应该在工具层、配置层和执行层被卡住。

## 问题

日常实践里，真正需要回答的是四件事：

1. 哪些动作可以自动执行？
2. 哪些动作必须暂停等人类确认？
3. 模型被 prompt injection 诱导调用工具时怎么办？
4. 重试、超时、重复调用导致非幂等副作用怎么办？

如果这些问题没有规则，Agent 的自动化能力越强，事故半径越大。

## 做法/步骤

### 1. 给工具分级，而不是给模型讲道理

建议把工具分成四级：

- **L0 只读**：查询日志、查看状态、列表、搜索。Agent 可自动执行，但要限制并发和返回长度。
- **L1 可逆或低影响**：创建草稿、写临时文件、本地构建、可回滚配置。可在 dry-run 后自动执行。
- **L2 有外部副作用但可审计**：发送消息、创建工单、合并 PR、修改 DNS、调用付费 API。默认需要人类确认，审批时展示 payload、diff 和影响范围。
- **L3 不可逆/高权限**：删除数据、删除资源、发布生产、修改权限、提取密钥、支付、批量外发。永远需要 human-in-the-loop，必要时双人审批。

### 2. 在 OpenClaw/MCP 层做允许清单

不要依赖自然语言约束，直接在配置里声明允许范围。例如：

```yaml
tools:
  kubectl:
    allow: ["get", "describe", "logs", "top"]
    deny: ["delete", "apply", "drain"]
    contexts: ["staging"]
  send_email:
    mode: ask_human
    require: ["to", "subject", "body"]
```

同时给 Agent 一个 `ask_human` 工具，把动作、参数、影响范围、可逆性、证据返回给用户，由用户选择 approve、deny 或 always ask。

### 3. 把决策因素量化

用几个维度判断：

- **影响半径**：当前会话、当前用户、生产环境、全公司。
- **可逆性**：可逆、可回滚、不可逆。
- **成本**：金额、时间、外部限流。
- **身份**：是否以用户身份执行、是否使用高权限凭据。

可以简单定义 `risk = impact * 3 + irreversibility * 2 + cost * 1 + credential * 1`，超过阈值就升级人类。不一定要很复杂，关键是稳定。

### 4. 增加执行保护

- 所有写操作先返回 dry-run/plan，再决定批准。
- 外部调用带 idempotency key，避免重试重复下单。
- 写操作默认不自动重试，或最多一次，冲突时停下来。
- 审计日志记录：哪个 Agent、哪个工具、哪些参数、是否被批准、结果摘要。不记录密钥。

### 5. 逐步放开

先 shadow mode，只记录不执行；然后只读自动；再开放可逆写；最后有限允许副作用操作。每周回顾误判，收紧或放宽边界。

## 踩坑点

- **模型会假装请求批准，但参数已经变了**。审批前校验 tool call payload 一致，不要只显示摘要。
- **confirmation fatigue**。频繁弹窗会让用户机械点允许。把工具合并成意图，一次批准“发这封邮件”，而不是每个 SMTP call 都问。
- **prompt injection**。来自网页、邮件的内容可能诱导 Agent 忽略规则。高权限工具不要直接暴露给被注入的上下文，关键动作用服务端策略卡住，不信任自然语言判断。
- **测试与生产共用 prompt 但不同凭据**。容易“测试环境没问题，生产把库删了”。工具必须绑定环境 tag。
- **自动重试造成重复执行**。HTTP 超时可能已经执行成功，写操作默认不要自动重试。

## 可复用建议

- 默认拒绝：新接入 MCP 工具先放 L0，写操作必须显式加入白名单。
- 审批信息必须包含 diff、payload、影响范围、可逆性、操作对象，而不是简单问一句“要执行 xxx 吗？”
- Agent 不要拿生产根凭据，只给最小权限临时凭据，用完轮换。
- 人类超时后的默认策略应该是 pending 不是 allow，超时自动 deny 并记录。
- 每季度用真实事故样本跑一遍，检查权限边界是否还能拦住。

## 总结

权限边界不是让模型更听话，而是让危险动作在工程层被拦住。自动执行的标准是：**只读、可逆、低影响、有幂等保护**。必须问人类的标准是：**花钱、不可逆、跨环境、影响他人、权限提升**。灰色地带，默认升级。真正安全的 Agent 不是“什么都能干”，而是“知道什么时候停下来问你”。
