## 背景

在 OpenClaw-CN 的日常实践中，很多人已经用 Agent 做代码生成、文档整理和命令编排，但 Git 操作往往还是手动完成。提交信息随意、分支命名混乱、PR 描述复制模板，这些问题并不影响代码能跑，却会让仓库历史越来越难读，回滚和协作成本变高。

Agent 擅长摘要、结构化输出，也适合辅助“读懂 diff 后写出准确说明”这类工作。把 Git 操作交给 AI，真正有价值的不是让它替你乱提交，而是把提交说明、分支创建和 PR 初稿这些重复性文字工作委托出去。

## 问题

直接让 AI 执行 `git commit` 或 `git push`，风险很高：

- 误提交 `.env`、本地配置或生成物；
- 一次 `git add .` 把无关文件一起 stage；
- 在错误分支提交，或对 merge/rebase 等危险操作自作主张；
- 生成的 commit message 与实际 diff 不符；
- 自动 push 到 main/master，破坏主干。

所以方案不是“AI 全自动 Git”，而是 **AI 建议 + 受限执行**：读操作放开，写操作必须确认。

## 做法/步骤

### 1. 把 Git MCP 工具按权限分离

在 OpenClaw 中接入 Git MCP server 后，默认只开放只读工具，写操作标记为需要审批。例如：

```yaml
git_status: allow
git_diff: allow
git_branch_list: allow
git_commit: requires_approval
git_push: requires_approval
git_branch_create: requires_approval
```

不要让 Agent 直接拿到 `reset --hard`、`clean -fd`、`push --force` 这类能力。

### 2. 让 Agent 先读，再给结构化建议

约定 Agent 的输出结构：先执行 `git status --short` 和 `git diff --stat`，必要时读取单个文件 diff。然后输出：

- `branch_name`
- `commit_message`
- `staged_files`
- `pr_summary`

这一阶段不写任何东西，只生成方案。

### 3. 分支自动化：从任务 ID 生成规范分支

由任务 ID 生成分支名，例如 `feat/task-456` 或 `fix/issue-123`。创建前先检查分支是否已存在，并确认当前 `main` 已更新。禁止 Agent 自动 merge 或 rebase。

### 4. 提交自动化：指定文件 + dry-run

Agent 只允许 `git add -- <file1> <file2>`，禁止 `git add .`。提交信息遵循 conventional commits 模板。真正提交前先跑一次 `git commit --dry-run` 或展示暂存区内容，用户确认后再执行。

### 5. PR 描述自动生成

Agent 汇总 commits 和 diff，生成测试说明、影响范围、回滚方案。PR 创建后仍需人工 review 和 merge。

### 6. 加上本地安全网

配置 pre-commit hook 跑 secret scan 和 lint；commit-msg hook 校验提交格式；分支保护禁止直接 push 到 main/master。

## 踩坑点

- **大 diff 截断导致摘要失真**：不要一次把整个 diff 喂给 Agent。只给 `diff --stat` 和每个文件前 N 行，或让 Agent 按文件分别摘要。
- **误提交生成物**：模型可能仍会把 `dist/`、`.env` 加进 stage。强制使用指定路径，并维护好 `.gitignore`。
- **hook 与 Agent 冲突**：commit-msg hook 拒绝 Agent 生成的 message 时，不要让它无限重试。把 hook 错误信息回传给 Agent，让它修正格式。
- **分支漂移**：Agent 在旧 main 上建分支会带出落后提交。步骤中先 `git fetch` 并检查本地 main 是否最新。
- **push 权限过大**：push 永远需要用户确认，且只允许 push 新分支，不允许 `--force`。
- **MCP server 暴露危险命令**：如果 Git MCP server 默认暴露了 `reset --hard`、`clean -fd`，必须禁用或加二次确认。

## 可复用建议

- 用模板固定 commit 格式：`type(scope): subject` + body + footer。
- 限制 Agent 每次只提交一个逻辑变更；diff 行数过大就先拆分。
- 每次自动提交后记录 commit SHA 和分支，必要时用 reflog 找回。
- 先上线“只读建议”模式，人工执行一周，确认质量后再放开 add/commit。
- 用正则限制分支名，例如 `^(feat|fix|docs|chore)/[a-z0-9-]+`。
- 提交后不自动开 PR，先在本地跑 `lint + test`，通过后再由用户 push。

## 总结

OpenClaw 场景下的 Git 自动化，核心不是让 AI“替你提交”，而是把提交说明、分支命名、PR 初稿这些结构化文字工作委托出去。写操作保持人工确认，让 Agent 跑在“只读 + 建议 + 受限执行”的安全边界内，才能真正提高效率，而不是引入新的工程债。
