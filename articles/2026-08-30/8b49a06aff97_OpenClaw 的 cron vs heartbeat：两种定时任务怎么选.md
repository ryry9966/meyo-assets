## 一、背景：定时任务在 Agent 系统里的两种面孔

在 OpenClaw 这类 Agent 框架里，定时触发几乎是每个自动化项目的刚需。但很多人没注意到，框架层面其实提供了两种语义完全不同的定时机制：

- **cron**：基于日历时间的调度，到点就触发，不管系统当前处于什么状态。
- **heartbeat**：基于生命周期的脉冲信号，间隔发出"我还活着"的心跳，状态感知是它存在的意义。

两者都能实现"每隔一段时间执行某段逻辑"，但选错机制，轻则逻辑别扭，重则出现竞态和重复执行。

## 二、问题：为什么不能互相替代

典型的翻车场景是这样的：

> 你写了一个 heartbeat 处理器，每 30 秒检查一次外部 API 是否有新消息。看起来没问题，但某次 API 响应慢到 45 秒，heartbeat 下一拍再次触发，两个请求同时读写同一个会话状态，直接导致消息重复入队。

反过来，也有人用 cron 每分钟执行一次 agent 空闲检测。cron 到点就触发，不关心 agent 是否正在处理任务。一旦检测逻辑里访问了正在变更的上下文，就会拿到半初始化状态。

核心区别在于：

| 维度 | cron | heartbeat |
|---|---|---|
| 触发语义 | 日历时间 | 生命周期脉冲 |
| 状态感知 | 无 | 可携带运行态 |
| 典型用途 | 轮询、清理、定时报告 | 保活、看门狗、条件触发 |
| 失败重试 | 通常不内置 | 可以结合状态判断 |

## 三、做法：各自正确的打开方式

### cron 适用场景

1. **外部数据轮询**：每 15 分钟抓取 RSS、API 变更列表。任务本身幂等，重复执行无害。
2. **缓存/会话清理**：每天凌晨清理过期 session、日志切片。
3. **定时摘要**：工作日上午 9 点生成昨日报告。

写法上，cron 任务应该保持**无状态、幂等**。OpenClaw 的 cron 调度部分在框架内部实现，但业务逻辑应当只依赖传入参数和外部存储，不依赖上一次执行的内存状态。

### heartbeat 适用场景

1. **连接保活**：WebSocket 空闲超时前发送心跳包，避免被服务端踢掉。
2. **空闲检测**：发现 agent 超过 N 分钟无任务，主动拉取待办队列。
3. **看门狗**：检测子进程/插件是否失联，失联则自动重启。

heartbeat 的处理器可以访问当前 agent 的运行时上下文，因此能做出"如果正在忙则跳过本次"这类条件判断。

## 四、踩坑点

### 1. cron 表达式与服务器时区不一致

OpenClaw 部署在容器里默认 UTC，而你的"每天早上 9 点"期望的是本地时间。务必在 cron 表达式或配置里显式声明时区，否则报告会在大半夜推送到群里。

### 2. 任务重叠执行

cron 间隔 5 分钟，但任务跑了 7 分钟，下一轮又启动了。解决方式：在任务开头设置一个运行标记（比如数据库锁或内存 flag），检测到已运行则直接退出。这是"单飞"（single-flight）模式。

### 3. heartbeat 触发的竞态

heartbeat 间隔短、频率高，如果处理器内部有阻塞 I/O，很容易和主流程的并发读写冲突。建议 heartbeat 处理器只做**轻量检查**，把耗时操作丢进队列或单独 worker。

### 4. 长期运行的内存残留

cron 任务回调如果持有闭包引用，容易导致老对象无法释放。建议每次执行完毕后显式置空非必要引用，或者将任务逻辑放在独立模块中。

## 五、可复用建议

1. **默认用 cron，除非你需要状态感知。** 大多数"每隔 X 时间做 Y"的任务都能用 cron 无状态实现，反而更可控。
2. **给每个周期任务加"上次执行时间"与"执行结果"记录。** 不管是 cron 还是 heartbeat，出问题时能快速定位是否漏跑、重跑。
3. **将调度与业务逻辑解耦。** 定时器只负责"触发"和"路由"，具体业务收敛到独立函数，方便单独测试。
4. **对 heartbeat 频率保持克制。** 如果只是保活，30 秒就够，不要用 1 秒间隔做轮询——那是在把 Agent 当轮询器用。
5. **测试时注意时钟漂移。** 本地模拟长时间运行时，用假时钟或缩短周期验证，不要硬等几小时。

## 六、总结

cron 和 heartbeat 不是"哪个更好"的问题，而是"哪把刀切哪块肉"的问题。cron 管"什么时候做"，heartbeat 管"我还在不在、我现在能不能做"。在一个成熟的 OpenClaw 自动化项目里，两者往往并存：cron 负责定期外部同步，heartbeat 负责内部健康与保活。厘清它们的边界，能少踩一半的并发和状态坑。
