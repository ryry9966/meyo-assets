## 背景：Agent 的“网上冲浪”不是想冲就冲

在 OpenClaw 这类工具链里，Agent 经常需要实时获取外部网页来完成回答、总结或动作。无论是查产品页、读取文档站，还是监控舆情，一个能“自己上网”的 Agent 自然比纯文本模型强得多。然而，让 Agent 直接发起 HTTP 请求或无头浏览器访问，很快会撞上现实世界的反爬、合规与稳定性壁垒。

很多实践者只是简单挂了 `fetch` 或 Puppeteer，接着便遇到：IP 被 Ban、请求被截断、被目标站投诉，甚至涉及法律争议。Agent 的自主性越高，这种“无治理上网”的风险越大。为此，我们设计了一套轻量级的 **Web scraping 稽客（Auditor）** 机制，作为 Agent 与目标网站之间的安全代理层，用工程手段把无序采集变成可控、可审计的流水线。

## 问题界定：不是“能不能采”，而是“怎么采才不翻车”

常见的“流氓式”采集会让 Agent 行为看起来像攻击，典型问题包括：

- **无视 robots.txt**：直接被识别为恶意爬虫，封禁速度极快  
- **请求频率失控**：Agent 短时间内发出大量请求，触发限流或 DDOS 防御  
- **非隐身模式暴露**：`navigator.webdriver` 等特征暴露无头浏览器身份  
- **动态内容失败**：未等待关键 JS 渲染，带回的空骨架毫无价值  
- **无审计能力**：出了问题无法回溯到底是哪次调用惹的祸  

这还不是全部——即使只是偶尔采集一次，也可能因为代理 IP 质量、Cookie 丢失或被站点重定向到登录页而失败。光靠 Agent 本身的推理能力，根本无法应对这些工程细节。

## 做法：用一个 MCP 工具把“稽客”逻辑封装起来

在以 MCP (Model Context Protocol) 为工具标准的 OpenClaw 环境里，最适合的方案是做一个专门的 **Scraper Auditor MCP 服务器**，暴露一个 `audit_scrape` 工具。Agent 需要外部网页时，只能通过该工具访问，而不是直接调用底层 HTTP 库。

下面的步骤描述了一个最小可行实现（以 Node.js 参考，可平移到 Python）：

### 1. 构建带合规检查的请求入口
在 MCP 工具内部，首先解析目标 URL 的 domain，然后：
- **缓存 robots.txt**（可以用 `robotstxt-parser` 库），根据路径检查是否允许抓取。不允许则直接返回被拒绝状态，写入审计日志，避免发起请求。
- **黑/白名单过滤**：维护一个简易 JSON 配置文件，列出禁止访问的域名或路径模式，避免误吃内网地址或付费墙内容。

### 2. 速率限制与代理调度
- 对每个域名维护一个请求时间窗口，强制最小间隔（例如 2~5 秒），超出批次直接返回 429 并提示 Agent 稍后重试。
- 集成代理池：可以是简单的 IP 轮换服务或者付费代理 API。启动时拉取一批可用代理，请求时轮转，并标记超时失败的代理自动下线。
- 统一设置用户代理（User-Agent）池，避免固定值，同时去除 `HeadlessChrome` 字样。

### 3. 动态渲染与内容净化
- 内容可能依赖 JavaScript，可以选择性启用无头浏览器（Playwright）。无头浏览器启动时注入反检测脚本，覆盖 `navigator.webdriver`、`chrome.runtime` 等特征，降低被识别概率。
- 等待 `networkidle` 或关键选择器出现，超时后仍返回已渲染内容，但标记为部分内容。
- 从返回的 HTML 中剥离 `<script>`、`<iframe>`、跟踪像素等无关元素，减少 Agent 上下文浪费，同时避免意外执行源码中的恶意代码。

### 4. 结构化返回与审计记录
工具返回的 JSON 结构建议包含：
```json
{
  "url": "https://example.com",
  "status": 200,
  "title": "...",
  "text": "...",
  "crawl_time": "2025-01-...",
  "is_cached": false,
  "audit_id": "a1b2c3d4"
}
```
同时，每个请求后向本地日志追加一条记录：`audit_id`、时间戳、HTTP 状态码、耗时、代理 IP、命中规则等。一旦被目标站投诉，能迅速定位哪次调用越界。

### 5. 与 OpenClaw Agent 集成
在 OpenClaw 的配置里注册该 MCP 服务器，让 Agent 的工具列表里出现 `audit_scrape`。处理提示词时，可明确告知：“采集任何外部 URL 前必须调用此工具，不要直接使用 HTTP 请求。” 部分 Agent 需要几个 sample 学习才能稳定遵守，必要时可以在 system prompt 里加入强制声明。

## 踩坑实录：真实环境中容易忽略的细节

- **robots.txt 路径规则远比想象复杂**：`Allow: /path` 和 `*` 匹配需要严格处理，一些站点甚至写错通配符，导致合法路径也被拦截。直接用成熟解析库，别手搓正则。
- **无头浏览器仍有指纹泄露**：即使隐藏 `webdriver`，字体、WebGL 指纹、字体列表等仍可被反爬。轻度采集可以接受 80% 成功率，若追求高可用，需要投入隐身浏览器方案（成本较高）。
- **代理池崩溃连锁反应**：当所有代理都因黑名单失效时，稽客服务直接瘫痪，Agent 无法回答任何涉及外网的问题。必须设计降级策略：要么回退到直接连接（风险自负），要么提示 Agent 使用缓存或放弃。
- **动态渲染的超时灾难**：某些页面入口加载了无限滚动或广告重定向，导致 `networkidle` 永远不到，工具卡死。要设置两层超时：整体超时（15 秒）和导航超时，超时后返回已解析内容并加上标志。
- **法律红线的隐蔽性**：技术合规不等于法律合规。某些数据如用户生成内容、价格数据库可能受 ToS 约束。稽客可外挂一个人工维护的“禁止采集”域名清单，由运营定期更新。

## 可复用建议：做一套能生长的基础设施

把这个稽客工具看成一个可以持续演化的内部服务，而不是一次性脚本：

- **模板化配置**：将各域名的抓取策略（是否渲染、代理区域、速率因子）写成 YAML 文件，新增站点时只需加配置，不必改代码。
- **语义缓存**：对相同 URL 且未过期的内容，使用 Embedding 做相似度匹配，减少重复请求，同时让 Agent 更快速反应。配合向量数据库可进一步提升缓存命中率。
- **健康检查端点**：暴露一个简单的 HTTP endpoint 用于监控代理存活率、各域名的错误率，以便及时更换 IP 池或调整策略。
- **人工审核回路**：当 Agent 遇到 robots.txt 禁止但业务又确实需要的数据，可以设计一个 Review 队列，由人类确认后临时白名单放行，避免全盘拒绝导致的业务阻塞。
- **作为 OpenClaw 插件发布**：如果团队内部有多人使用，可以把稽客 MCP 服务器打包成插件，附带默认配置和简单文档，降低每个人重复搭建的成本。

## 总结

Agent 的互联网触角越伸越长，如果不加管控，就会变成埋雷的“自动爬虫”。Web scraping 稽客的核心理念不是限制能力，而是用一层薄薄的审计与保护壳，让每一次网页采集都经过合规检查、速率控制、身份伪装和内容净化。这套机制与 MCP 工具理念天然匹配，适合直接集成到 OpenClaw 等 Agent 框架中，让“安全采集”成为默认行为。

工程上的投入很小，带来的却是大幅降低的封禁风险、可追溯的审计能力和稳定的运行体验。当你的 Agent 安全上线后突然被目标站投诉时，你会感谢那个安静的稽客日志。
