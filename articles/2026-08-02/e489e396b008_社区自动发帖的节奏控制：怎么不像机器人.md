## 背景

有自动化发帖需求的场景已经非常普遍：定时将技术摘要、日报、更新日志推送到 Discord、Slack、飞书或自有社区。早期方案是 crontab + webhook，后来的 Agent 框架（如 OpenClaw）把“抓取→整理→发布”串成一条线。问题是：消息能发出，但一眼就能看出是机器人。

不是内容的问题，而是**节奏感**差。几点发、隔多久发、内容密度如何、是否总在整点……这些特征更容易暴露自动化痕迹。尤其在一个真实成员活跃的社区里，固定的间隔和机械的时间点非常突兀。

市面上很多教程都在讲怎么做“自动发布”，却很少讨论怎么控制发布节奏，让整套行为看起来像真人在操作。这篇文章基于我们自己在 OpenClaw 生态中踩过的坑，给出一套可控的节奏方案。

## 问题拆解：为什么一眼就看出是机器人？

- **定时过于精确**：每天 10:00:00 触发，秒级一致。
- **间隔固定**：每 3 小时一条，误差为 0。
- **无上下文感知**：凌晨三点也在发，长假期间照样推。
- **行为单一**：总是同一种消息类型，缺乏互动停顿。

本质上，这是将一个异步自动化系统当成了精确时钟控制的生产线。真人发帖的节奏是不规则的，会受时区、工作日、社区活跃度甚至心情影响。

## 做法与步骤

我们以一个典型的 OpenClaw 插件为例，这个插件每天多次发布 AI 领域的技术简报到 Discord 社区。目标是让它“看起来像一个时区在东八区的开发者，有正常工作节奏”。

### 1. 引入时间随机抖动

放弃固定 cron 表达式，改用**时间窗口** + 随机偏移。

在插件配置中，不用 `0 9 * * *`，而是定义：

```yaml
schedule:
  - window: "9:00-10:30"
    action: morning_brief
  - window: "14:00-15:30"
    action: afternoon_update
  - window: "20:00-21:30"
    action: evening_roundup
```

每次任务触发时计算一个随机延迟，例如：

```ts
function randomDelay(windowStart: Date, windowEnd: Date): number {
  const range = windowEnd.getTime() - windowStart.getTime();
  return Math.floor(Math.random() * range);
}
```

然后 `setTimeout` 里执行实际发布。确保每天每一轮的发布时间都不相同，且误差在分钟级别。

**注意**：如果社区规模较小，抖动范围建议缩小（±15 分钟），否则可能出现“连续两天早上发布差了一个半小时”的情况，反而显得不稳定。

### 2. 添加休息日与假期的意识

真人不会 7×24 相同频率发帖。我们维护一个轻量的日历配置，标记：

- 周末不推晚间摘要（或改为中午一条）。
- 法定节假日降低频率，仅保留一条“本周回顾”。
- 深夜窗口（23:00-07:00）完全静默。

对于国际社区，需要基于目标受众的时区设定本地假日的静默规则。一个简单的实现是读取一个 `holidays.json`，里面按日期列出 “quiet” 或 “skip” 策略。

### 3. 发布间隔的动态变化

即使是同一天内，不同帖子之间也要打破固定间隔。可以在任务调度器中维护一个 `lastPostTime`，下一个任务的随机窗口基于上一个实际发布时间计算，而非配置的固定偏移。

伪逻辑：

```
minGap = 45min
maxGap = 3h
nextWindowStart = lastPostTime + minGap + random(0, maxGap-minGap)
```

这样发布节奏会自然波动，不会出现“每两小时一条”的机器感。

**坑点**：如果两个任务窗口因随机抖动发生碰撞（后一个早于前一个），必须做冲突检测，将后一个推迟到前一个完成后至少 minGap。

### 4. 内容类型的随机交织

机器人感还来自消息类型的单一。解决方法是给同一时间段定义多个可能的内容池，随机选择或轮换：

- 技术摘要 / 工具推荐 / 论文速递 / 一句话行业观察
- 偶尔插入非技术内容：社区贡献者感谢、维护公告（低频率）

在 OpenClaw 中，可以用一个简单的模板路由：

```yaml
actions:
  - pool: [tech_digest, tool_highlight, paper_note]
    weights: [0.6, 0.3, 0.1]
```

每天早上发布的就不是永远“昨日 AI 动态”，有时是“本周推荐工具”，看起来更像是真人在随性地分享，而不是定时汇报。

## 踩坑记录

- **时区陷阱**：所有时间窗口必须用社区目标时区计算。服务器 UTC 与用户本地时间混淆会导致凌晨推送。处理方式：所有调度时间显式指定时区，内部统一转为 UTC 比较。
- **随机种子导致可预测**：如果你用固定种子测试，发布节奏会重现，上线一定移除。
- **过大的抖动带来体感混乱**：社区用户如果每天差不多同一时间看到消息，会形成预期。抖动太大（比如可达 4 小时）反而会让人感觉“这个账号不正常”。我们最终收敛到 45–90 分钟抖动区间。
- **节假日的边界处理**：假期前一天晚上是否发晚间摘要？我们采用“假期前一天仍然正常，但删掉最晚的一轮”，避免跨天发送。

## 可复用建议

如果你正在基于 OpenClaw 或 MCP 插件构建自动发布 Agent，可以从下面几项开始：

1. **用时间窗口 + 随机偏移代替固定 cron**，给每个动作一个合理的“发生期”。
2. **维护一份社区日历**：时区、周末策略、节假日静默规则。
3. **发布间隔基于上次实际时间动态计算**，不要用固定常量。
4. **内容池化**：每个窗口至少准备 2–3 种不同类型的帖子，并设置权重。
5. **记录日志与回溯**：导出每次发布的确切时间与内容类型，定期回顾是否出现规律性，人工微调窗口或权重。

可以把这个逻辑封装成一个独立的 `SchedulerRhythm` 模块，在多个插件中复用。

## 总结

控制自动发帖节奏的核心不是“模拟人类 random”，而是在工程层面建立一套**带约束的不规则性**：时间有窗口、间隔有弹性、内容有变化、行为有节假日意识。OpenClaw 生态提供了灵活的调度与内容生成能力，我们只需要在上面加上一层节奏控制，就能显著降低“机器人感”，让自动化真正融入社区而不是突兀地存在。
