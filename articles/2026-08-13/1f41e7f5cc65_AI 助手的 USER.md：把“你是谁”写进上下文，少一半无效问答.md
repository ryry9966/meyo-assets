## 背景

不管是 OpenClaw 还是其他 Agent，默认情况下，每次会话都像一个新来的远程同事：模型本身并不记得你的机器环境、工作习惯和边界。我们往往把项目文档、系统提示、CLAUDE.md 写得很详细，却忽略了最基础的一层——用户是谁。

CLAUDE.md 告诉 Agent“这个项目是什么”，而 USER.md 告诉 Agent“你是谁、你在哪台机器上、你默认怎么工作”。

## 问题

没有 USER.md 时，Agent 经常出现这些行为：

- 反复问操作系统、Shell、包管理器；
- 默认使用 macOS 路径，实际运行在 Linux 上；
- 使用未安装的工具，或者忽略你更偏好的 MCP/插件；
- 自动任务时间不符合你的时区习惯；
- 不知道权限边界，直接执行高风险命令；
- 每次都要你重新解释“我常用 rsync，不是 scp”。

这些问题不只是浪费 token，更危险的是错误假设。比如它可能以为你有 `brew`，结果在 Ubuntu 上构造出无法执行的命令。

## 做法 / 步骤

### 1. 确定 USER.md 的位置与加载方式

建议全局放稳定信息，项目级放临时偏好。

例如：

- 全局：`~/.openclaw/USER.md`
- 项目级：`.openclaw/USER.md`
- 也可以在入口提示中通过 include 合并

全局文件负责跨项目不变的个人事实，项目级文件负责当前仓库的特殊约定。这样避免把所有东西塞进一个文件。

### 2. USER.md 写什么

建议固定成五个部分：

- **身份**：你的角色、目标、常用环境；
- **环境事实**：操作系统、发行版、Shell、架构、是否可用 sudo、时区、网络环境；
- **工具与偏好**：编辑器、终端、常用 CLI、包管理器，优先使用哪些 MCP 工具；
- **硬性约束**：不要执行的命令、不要访问的目录或主机、密钥处理方式、输出语言和风格；
- **验证与工作流**：偏好先 dry-run、执行前确认、失败后如何报告。

示例片段：

```markdown
# USER.md

## 身份
- 后端工程师，主要维护 Python/Go 服务
- 工作目录通常在 ~/code

## 环境
- OS: Linux (Ubuntu 22.04)
- Shell: bash
- 用户权限: sudo
- 时区: Asia/Shanghai

## 工具偏好
- 编辑器: nvim
- 包管理: apt / mise
- 优先 MCP: filesystem, github, playwright

## 硬性约束
- 不要在 ~/.ssh 外创建私钥
- 不要删除任何没有明确指定的文件
- 执行网络请求前先说明目标域名

## 输出偏好
- 中文答复，命令保持英文
- 默认先给方案再执行
- 失败时只给 5 行以内摘要
```

### 3. 与项目文件分工

CLAUDE.md 或 AGENTS.md 管项目，USER.md 管用户。如果项目指令与用户约束冲突，必须明确优先级。通常来说，安全约束 > 用户约束 > 项目默认规范。

## 踩坑点

### 1. 把秘密写进 USER.md

Token、SSH key、API key、内部主机地址等，都不应该进入会被模型读取的文件。即使本地使用，也可能因为 MCP 工具或插件的上下文上报而泄露。

### 2. USER.md 过长

超过 40–60 行后，Agent 的注意力会下降，关键约束容易被淹没。USER.md 不是个人 wiki，而是高频上下文的摘要。

### 3. 用模糊语言

写“尽量简洁”没有用。要写“输出少于 120 字”或“默认不显示详细堆栈”。模糊描述无法被稳定执行。

### 4. 优先级不明确

USER.md 和项目文件同时存在时，模型容易犹豫。建议在 USER.md 中直接写明：“当项目文件与 USER.md 冲突时，以 USER.md 的安全约束为准”。

### 5. 信息过期

换机器、改 Shell、调整工作目录后没有更新 USER.md，Agent 会照着旧环境执行。建议和 dotfiles 一起纳入版本管理，并定期 review。

### 6. 把动态状态写入 USER.md

当前分支、临时调试开关、本次任务特定要求，不应该进入 USER.md。动态信息适合放在会话开头或项目上下文里。

## 可复用建议

1. **使用模板**：固定“身份 / 环境 / 工具 / 约束 / 输出偏好”五段结构，便于快速维护。
2. **把“不要做什么”前置**：约束优先于偏好，安全优先于效率。
3. **加入自检指令**：在 USER.md 末尾写“会话开始用 2 行确认当前 OS / Shell / 工作目录”，可以快速发现加载失败。
4. **与 MCP/插件联动**：明确告诉 Agent 哪些 MCP 工具优先，哪些插件不要启用。例如“优先使用 filesystem MCP，不要直接执行 shell 命令去遍历目录”。
5. **保持静态与动态分离**：临时偏好写在会话里，稳定偏好才进入 USER.md。
6. **定期删减**：每次增加了新规则，就看看能不能删掉一条旧的。

## 总结

USER.md 是给 Agent 的“用户上下文”。它不是另一份系统提示堆料，而是把稳定、高频、跨项目的个人事实固定下来。

写好 USER.md，能减少反复确认、降低误操作，也能让你更敢把自动化任务交给 Agent。对 OpenClaw 用户来说，配合 MCP 和插件体系，USER.md 还可以进一步告诉 Agent：在你的工作流里，哪个工具更合适、哪个操作不该碰。

先写一份 60 行以内的版本，跑几次真实任务后再迭代。你会发现，Agent 从“总在猜”变成了“更像你的助手”。
