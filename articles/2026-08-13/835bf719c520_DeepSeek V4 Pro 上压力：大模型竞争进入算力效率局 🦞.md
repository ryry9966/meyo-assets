36kr 把梁文锋和马斯克放上同一条热搜，关键词是 DeepSeek V4 Pro。很多人第一反应是“又来一款模型打榜了”。但如果只看跑分，很容易漏掉真正重要的信号：大模型竞争正在从“谁参数更多”切换到“谁的单位算力产出更高”。DeepSeek V4 Pro 给全球最强上压力，本质上不是一次性能宣战，而是一条效率路线的公开验证。



## 一、热闻背后：两个被混用的词，需要拆开看

“全球最强”和“上压力”这两个词，在不同语境下含义差别很大。

1. **全球最强通常指能力上限**  
   在闭源阵营里，OpenAI、Google、xAI 的超大模型仍占据很多复杂推理、多模态任务的最高分。它们靠大算力、大参数、大规模强化学习堆出能力天花板。说“最强”，更多是指单点任务的上限，不代表所有场景都最优。

2. **上压力更多指性价比临界点**  
   当一款模型在主流 benchmark 上进入第一梯队，同时推理成本低一个数量级、权重可开源、还能私有化部署时，它就会在商业层面给头部闭源模型上压力。因为用户最终购买的是 token，不是参数数量。价格、时延、吞吐，才是生产环境里每天要面对的东西。

3. **判断标准正在分层**  
   学术榜、Agent 任务、长文本、代码生成、多模态，不同场景下“最强”的模型可能完全不同。只看一个总分，很容易被热搜带着走。很多企业的真实需求不是“最强模型”，而是“足够好且部署得起”。

所以这条热闻的准确读法不是“谁打败了谁”，而是：DeepSeek 这条效率路线，已经逼近闭源超大模型的商业护城河。

## 二、DeepSeek V4 Pro 为什么能“上压力”：三个技术杠杆



如果只看名称，V4 Pro 像是一次常规迭代。但它真正值得关注的地方，是把“训练和推理的单位成本”打了下来。背后至少有三个公开可追踪的技术杠杆。

1. **MoE 稀疏激活：用一部分参数干大部分活**  
   MoE（Mixture of Experts）把模型拆成多个专家子网络，每次前向只激活其中 top-k 个专家。这意味着总参数量可以很大，但实际计算量远小于同尺寸的 dense 模型。对用户来说，同样一块 GPU，能跑更大的模型、更长的上下文。过去 175B dense 模型需要多卡才能部署，而 MoE 模型可以在更低算力下提供相近能力。

2. **MLA 注意力：压缩 KV cache，长文本更便宜**  
   MLA（Multi-head Latent Attention）把注意力机制里的 Key 和 Value 先压缩成低维潜在向量，推理时再还原。KV cache 是长文本推理的主要显存消耗来源，压缩后能显著降低长上下文服务的硬件门槛。这是 API 价格能持续下探的关键之一。很多长文档、代码仓库场景，省下的不只是钱，还有首 token 时延。

3. **FP8 低精度 + 训练流水线优化：训练侧省大钱**  
   低精度训练不等于牺牲精度。FP8 通过缩放因子和误差补偿，在多数矩阵运算中保持可用精度，同时提升吞吐。再加上 DualPipe 这类管道并行算法，减少 GPU 空闲等待，训练成本可以大幅下降。业内对 DeepSeek 路线的普遍评价是：它不是在单点炫技，而是在做系统化效率工程。

这些技术都不是第一次出现，但把它们组合到一款可公开使用的模型里，并且以极低价格放出 API，才是竞争压力所在。举个粗略例子：假设 A 闭源模型与 B 效率模型在业务任务上成功率只差 1%，但 API 单价相差 8 倍，长期跑下来，绝大多数团队都会选择后者。

## 三、马斯克和 xAI 的底牌：算力规模与工程暴力

另一边，马斯克的 xAI 走的是完全不同的路线：用超大规模算力，快速拉高能力上限。

1. **Colossus 超算代表规模路线**  
   xAI 的 Colossus 超算以数万甚至十万张 GPU 级别著称，配合液冷、高速互联和快速部署能力。这种规模让 Grok 系列在多模态、实时数据接入和复杂推理上具备很强爆发力。大算力的好处是上限高、迭代快，很多复杂任务确实需要这种暴力。

2. **规模路线也有代价**  
   千亿甚至万亿参数模型训练一次，电费、芯片、网络、运维都是天量成本。推理侧同样重。如果 API 定价不能覆盖成本，就需要持续融资或强力商业化。相比之下，高效架构路线在商业可持续性上更灵活，也更适合向中小客户渗透。

3. **两种路线并非互斥**  
   更可能的结果是：闭源厂商继续用算力堆上限，同时吸收高效架构经验；效率路线团队也会在收入增长后扩大算力。竞争不是单点对决，而是成本、数据、生态、分发渠道的复合对抗。过去 GPT-3 时代，175B dense 参数模型让很多团队望而却步；现在 MoE 路线把同等能力所需算力压了一个数量级，参与的人更多，竞争自然更卷。

用工程师的话说：一个在优化“每美元能买多少智能”，另一个在证明“算力密度本身也是一种壁垒”。两条路线都有合理之处，但市场正在用 API 调用量投票。

## 四、三条冷思考：选模型，不如选单位智能成本



如果开发者或创业者只看到“谁更厉害”，很容易做出错误决策。更实用的判断框架是下面三条。

1. **把“单位智能成本”当 KPI**  
   同一批任务，在质量达标的前提下，比较每百万 token 的成本、时延和成功率。榜单排名只能说明上限，不能说明你的业务能否长期跑下去。一个可以在本地部署的中等模型，往往比一个需要高额按量付费的顶级模型更可持续。

2. **优先考虑可私有化、可微调、可审计的模型**  
   很多真实业务里，数据不能离开内网，或者需要针对行业语料微调。开源权重 + 可自部署，比单纯调用 API 更可控。模型能力再强，数据合规上不可用，对你就是零。部署前问清楚：数据出不出域？模型能不能自己托管？日志能不能审计？

3. **不要锁定单一厂商，建立模型路由与评测体系**  
   简单任务用便宜模型，复杂推理用强模型，多模态单独分流。定期用自有测试集评估模型漂移，保留切换能力。这样无论 DeepSeek、Grok、还是其他模型谁领跑，你的系统都能稳定降本。路由层比模型本身更值得投入。

大模型竞争会继续热闹，但真正决定商业价值的，不是热搜上的输赢，而是谁能把智能变成可规模、可盈利、可交付的日常能力。
