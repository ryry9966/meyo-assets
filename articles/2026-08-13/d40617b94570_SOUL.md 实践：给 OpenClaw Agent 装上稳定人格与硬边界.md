# SOUL.md 实践：给 OpenClaw Agent 装上稳定人格与硬边界

## 背景：为什么需要 SOUL.md

OpenClaw 的 Agent 常常同时接 MCP、插件和自动化脚本。模型本身不是问题，问题在于行为一致性：同一个任务，这次谨慎、下次激进；工具一多就乱试；长会话跑到后面把前面的约束忘掉。SOUL.md 可以作为持久化的人格与边界文件，在每次会话启动时注入，减少这种漂移。

它不是“让 Agent 更像人”的装饰，而是把运行边界从隐式提示词变成可版本化、可评审的工程文件。

## 问题：没有 SOUL.md 时的典型故障

- **越权写文件**：Agent 为了完成目标，直接修改配置，不提示用户。
- **工具滥用**：MCP 里有删除、执行命令能力时，模型容易选择“最省事路径”。
- **人格不稳定**：同一类任务，两次运行的表达风格和决策尺度差异很大。
- **上下文污染**：长会话中早期约束被新信息覆盖，边界逐渐失效。

这些大多不是提示词技巧问题，而是缺少稳定的、可复现的运行约束。

## 做法：从最小可用的 SOUL.md 开始

建议不要把 SOUL.md 写成“友好助手”的散文。把它当成运行时配置文件，分五块：

1. **身份**：一句话说明角色。例如“你是 OpenClaw 自动化运维 Agent，只做用户明确授权的变更。”
2. **目标排序**：明确优先级。例：安全 > 不破坏现有状态 > 完成请求 > 节省 token。
3. **硬边界**：用 MUST NOT 表达。例：MUST NOT 删除/覆盖文件；MUST NOT 调用未列入 allowlist 的 MCP 工具；MUST NOT 修改自身 SOUL.md。
4. **工具策略**：写明工具选择规则。例：读文件优先 find/grep；写操作前先 dry-run；执行 shell 前先说明命令。
5. **失败与确认**：规定何时停下。例：遇到权限错误立即停下；影响多个文件时必须先列清单等用户确认。

文件位置建议放在项目根目录 `SOUL.md`，并在 OpenClaw 启动配置里显式引用。即使 OpenClaw 支持默认扫描，也建议显式写路径，避免被忽略或加载错文件。

## 踩坑点

- **太长的 SOUL.md 会被“稀释”**：超过 80–120 行后，模型容易只记住开头和结尾。把硬边界放最前，并定期裁剪。
- **与 MCP 工具描述冲突**：如果 MCP 工具描述很“诱人”，SOUL.md 的禁止可能被模型忽略。边界里要点名工具名，例如“禁止使用 fs.write_file 直接覆盖已有文件”。
- **只写禁止，不写替代路径**：光说“别乱删文件”不够。要写“删除前必须用 trash 命令并输出预览”。替代路径能让模型有路可走。
- **人格太强导致幻觉**：不要写“你是一个完美的资深工程师”，而要写“当信息不足时，明确说不知道，不要补充假设”。
- **没有版本管理**：SOUL.md 变更会影响所有 Agent 行为，应该进 Git；改边界时像改代码一样 review。

## 可复用建议

一个可落地的 SOUL.md 模板如下，按需裁剪：

```markdown
# SOUL
你是 OpenClaw 项目自动化 Agent。

## 优先级
1. 安全：不造成不可逆变更。
2. 透明：所有关键操作先说明。
3. 最小改动：只做完成请求所必需的事。
4. 效率：在满足以上条件后减少冗余操作。

## 硬边界
- MUST NOT 删除或覆盖任何已有文件。
- MUST NOT 执行未经确认的 shell 命令。
- MUST NOT 调用 allowlist 之外的 MCP 工具。
- MUST NOT 修改本文件。

## 工具策略
- 只读任务优先使用只读工具。
- 写操作前先给出 diff/预览。
- 批量操作必须分批，每批间隔等待确认。

## 停止条件
- 遇到权限错误、数据丢失风险、不确定的业务规则，立即停止并询问。
```

每次新接 MCP 或插件时，先问一句：“这个工具会不会打开一个新边界？”如果会，就在 SOUL.md 里补一条明确的 MUST NOT 或 SHOULD。

另外建议做“边界测试”：故意给 Agent 发敏感指令，看它是否按 SOUL.md 拒绝。比如让它“把日志清空”，正确行为应是先列出后果并请求确认。测试结果可以记录在团队文档中，避免边界形同虚设。

## 总结

SOUL.md 的价值不在于让 Agent 更有“人味”，而在于把人格和边界从隐式提示词变成可版本化的工程文件。好的 SOUL.md 是约束，不是口号：它要具体到工具名、操作类型和停止条件。对 OpenClaw + MCP 这类组合，边界清晰比能力堆叠更关键。先写一份最小版，跑几次真实任务，再逐步收紧，远比一次性写成长文有效。
