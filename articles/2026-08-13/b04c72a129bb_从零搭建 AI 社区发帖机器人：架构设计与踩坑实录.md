## 背景

社区里不少朋友在做 OpenClaw + MCP 的自动化实践，常见需求之一是把本地笔记、修复记录、实验过程整理后发到社区。这个需求看起来简单：让 Agent 读文件、改格式、调发帖工具。但实际跑起来会发现，难点不在“能不能发”，而在“如何不发错、不发重、格式不崩”。

我搭了一个最小可用的发帖机器人，下面按架构、步骤、踩坑和建议展开。

## 问题拆解

一开始我尝试让 Agent 直接读写社区页面，结果出现了三类问题：

1. **输出不可控**：Agent 写出来的标题、标签、正文经常跑偏，甚至出现编造数据。
2. **副作用难管理**：发布动作不可逆，测试时容易误发。
3. **格式转换不稳定**：Markdown 代码块、表格、图片路径到社区编辑器里经常丢失或错位。

所以后来把目标收敛为：**Agent 只做整理和决策，发布动作通过 MCP 工具隔离，人工 review 默认开启**。

## 架构与做法

整体架构分为三层：

- **触发层**：定时任务或手动触发，调用 OpenClaw 任务。
- **决策层**：OpenClaw Agent 读取本地草稿，生成结构化帖子，写入 review 目录。
- **工具层**：通过 MCP 提供文件读取、社区分类查询、预览、发布、状态查询等工具。

流程如下：

```text
trigger
  -> OpenClaw agent
  -> read posts/inbox/*.md
  -> generate post draft
  -> write posts/review/{slug}.md
  -> human review
  -> publish via MCP community-post
  -> write published.json + log
```

关键的 MCP 工具不要做成一个万能 `post`，建议拆开：

```json
[
  "list_categories",
  "get_draft",
  "preview_post",
  "publish_post",
  "get_post_status"
]
```

其中 `publish_post` 工具描述必须写清楚副作用，例如：

> Publish a post to community. This action is irreversible in production. Requires both `dry_run=false` and `approved=true` to execute.

这样能明显降低 Agent 误调用的概率。

发布工具实现上，优先使用社区开放 API；如果没有 API，再用 Playwright MCP 操作网页。登录态不要放进 Agent 上下文，而是放在 MCP server 的环境变量或独立配置中。

## 踩坑点

**1. 登录态污染 Agent 上下文**

最初我把 cookie 直接塞进 prompt，结果 token 过期后 Agent 开始反复重试，甚至把错误堆栈写进正文。后来把认证完全下沉到 MCP server，Agent 只拿到 `post_id` 和发布结果，问题消失。

**2. 工具描述太宽泛**

只写 “publish a post” 时，Agent 会在草稿还没生成完时就调用发布。后来给每个工具都写明前置条件和副作用，尤其是 `publish_post` 需要两个参数同时满足才执行，误发率明显下降。

**3. Markdown 转社区格式不一致**

代码块、表格、相对路径图片最容易出问题。我的做法是发布前先做一次 normalize：代码块补语言标识、相对路径图片转外链或先上传、去掉内嵌 HTML。这样进入编辑器的内容是可预测的。

**4. 定时全自动发重复帖**

早期每 6 小时跑一次，有几次因为源文件未更新，重复发了内容。后来给每个源文件算 SHA256，写入 `published.json`，每次任务先查哈希，已发过就跳过。

**5. 频率限制和审核机制**

社区 API 有 429 限制，MCP server 里要做指数退避和简单队列。触发频率不要太高，建议先手动或低频率跑通，再逐步放开。

**6. 上下文过长导致跑偏**

一次把大量素材塞给 Agent，生成质量会下降。改成先抽取标题、摘要和标签，再按需读取正文细节，效果更稳定。

## 可复用建议

- **发布动作必须可回滚**：保存 `post_id`，提供 `delete_post` 工具，出问题能撤回。
- **dry-run 是默认值**：只有人工把 `status: approved` 写入 manifest 后才真正发布。
- **用 source hash 去重**：比依赖文件名或时间戳可靠。
- **Prompt 里放示例帖子**：一个格式正确的示例，比长篇规则更有效。
- **日志结构化**：记录 trigger、source_hash、post_id、status、错误信息，方便排查。

## 总结

这套系统的核心不是“让 AI 自动写爆款”，而是把整理、排版、发布、归档这些重复动作串起来，同时用 dry-run、工具约束和人工 review 控制风险。OpenClaw 适合做编排层，但真实发帖的可靠性，更多来自 MCP 工具设计和发布边界，而不是模型本身。
