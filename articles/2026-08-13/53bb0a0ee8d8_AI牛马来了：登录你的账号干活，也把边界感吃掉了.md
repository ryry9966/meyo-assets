最近，马斯克旗下 xAI 的 Grok 智能体（Agent）功能在中文互联网被戏称为“AI 牛马”——据说它能直接登录你的邮箱、社交账号、购物网站，像助理一样替你干活：订机票、回邮件、发帖子、甚至下单付款。但“牛马”这个称呼背后还有另一层意思：它干起活来太猛，猛到让人不安。不少用户在测试后发现，这个 Agent 对“边界”的理解和人类不太一样。它不会问你“要不要先确认”，而是直接把事办了。今天就从能力、风险和技术原理三个角度，把这只“AI 牛马”拆开看看。



## 一、它能干什么：不是聊天，是接管你的账号



这类 Agent 和传统聊天机器人的最大区别，是它不再只给建议，而是直接操作图形界面。

- 典型任务清单：读取未读邮件并归纳要点、自动回复评论、填写报销单、在电商平台比价下单、预订航班或酒店。
- 工作方式：你给它一句自然语言指令，例如“帮我订明天上午去杭州的票，靠窗，价格别超过1200”。它会打开航司或出行平台网页，登录你的账号，填写出发地、目的地、日期、乘客信息，走到支付页面前停下——或者在一些激进模式下，直接完成付款。
- 与 RPA 的区别：传统机器人流程自动化只能处理固定元素 ID、固定按钮，一旦网页改版就失灵。LLM 驱动的 Agent 能理解页面截图和 HTML 结构，像人一样“看见”按钮在哪里，然后决定下一步。
- 现实案例：部分早期用户用它管理 X（原 Twitter）账号，自动拉黑垃圾账号、定时发布草稿；还有人用它每天检查电商价格，降价后自动抢券。这些操作如果靠人工，需要频繁切换页面；Agent 一次跑完。

这里有一个容易混淆的点：我们说的不是“帮你查一下”，而是“帮你在浏览器里点下去”。完成一次典型的多步骤任务，Agent 可能需要点击几十次、滚动多个页面、处理至少一次意外弹窗。它每走一步都在消耗模型的推理 token，同时也把操作痕迹留在你的账号活动记录里。

## 二、为什么说它“没边界感”：不是能力问题，是授权设计



“没边界感”不是指它技术糟糕，而是说它在权限和数据访问上几乎没有保守策略。

- 授权粒度太粗：大多数 Agent 只提供“全有或全无”的权限。你给了它邮箱，它就能读你所有邮件；你给了它购物网站，它就能用你绑定的支付方式。很少有产品支持“只读邮件，不能发送”“能选品，不能下单”这样的细分控制。
- 操作不可逆：自动发送的私信、自动提交的退款申请、自动下的订单，都可能造成真实损失。更麻烦的是，很多 Agent 的“撤销”能力很弱，出错了只能靠人工补救。
- 数据训练争议：xAI 过去曾因为默认使用用户数据训练模型引发过讨论。虽然现在有开关，但用户很难判断自己的网页操作轨迹、邮件内容是否会被纳入训练集。一旦账号连接，你的消费记录、社交关系、工作邮件都可能变成模型“学习材料”。
- 缺少人类确认环节：人类助理会在花大钱、对外发言前问你一句；而部分 Agent 为了追求任务完成率，默认跳过确认。用网友的话说：它不像一个“有分寸感的实习生”，更像是拿着你工牌到处刷门的急性子外包。

一个更值得警惕的点是：如果你把主力邮箱、银行账号、社交媒体都交给同一个 Agent，那么一旦它的会话被劫持或者云端容器泄露，就相当于把所有钥匙一次性交了出去。更别说有些 Agent 的云浏览器会保留你的登录 Cookie 多个小时，期间任何能访问该会话的人都有可能接着操作。

## 三、技术原理：从聊天到接管账号，中间隔了几层



一个能登录你账号干活的 Agent，底层通常由三部分组成。

1. 多模态理解模块：负责“看懂”网页。它会同时接收页面截图和 DOM（文档对象模型）信息，识别文本框、按钮、下拉菜单的位置和功能。没有这一步，它就无法区分“登录”和“注册”两个长得像的按钮。
2. 动作生成模块：负责“动手”。它会输出鼠标点击坐标、键盘输入内容、滚动指令等。部分实现通过浏览器扩展注入操作，部分则调用系统级无障碍 API。这也是为什么它能覆盖那些没有开放 API 的长尾网站。
3. 规划与记忆模块：负责“拆任务”。比如“订机票”会被分解成：搜索航班 → 筛选时间 → 选择舱位 → 填写乘客信息 → 进入支付页。规划模块还要处理意外弹窗、登录验证码、页面加载失败等异常。

这不是突然蹦出来的能力。如果拉一条时间线，能看出清晰的演进：

- 1990 年代，微软 Office 的 Clippy 只会弹一个“看起来你在写信，需要帮助吗？”的对话框，没有操作权限。
- 2010 年代，RPA 工具可以自动填写表单、抓取数据，但规则写死，界面一变就崩。
- 2023 年以后，大模型让 GUI Agent 有了“理解并适应新界面”的可能，计算机使用（Computer Use）成为热门方向。
- 2025 年前后，多家公司相继推出通用计算机使用 Agent，马斯克的 Grok 只是其中风格最激进的一个。

与 OpenAI 的 Operator、Anthropic 的 Computer Use 相比，Grok 这一代 Agent 在浏览器自动化上并没有本质不同，差异更多体现在产品策略上：马斯克更倾向于“能自动就自动”，强调减少人工干预。这种思路在效率上占优，但也放大了风险。

另外，当前所有这类 Agent 都面临两个硬约束：

- 上下文窗口有限：长任务超过一定步数后，模型容易“忘记”最开始的目标，比如订票订到一半去刷微博。
- 错误恢复能力弱：如果页面改版或弹窗内容复杂，Agent 可能会在同一个按钮上反复点击，直到超时。

理解这些原理，不是为了替它开脱，而是为了在使用时知道哪些环节需要人工兜底。

**实用建议：如果你也想养一只 AI 牛马**

- 用专用小号：注册一个独立的邮箱、社交账号和购物账号，不要直接绑定主力账号。就算 Agent 出问题，损失也被隔离在小范围内。
- 开启支付确认和敏感操作提醒：没有这类功能的 Agent，建议只让它做查询和草稿类任务，不要碰付款和对外发布。
- 定期清理授权：用完就退出 Agent 的登录态，检查第三方应用授权列表，撤销不再使用的会话。不要把一次性密码或验证码告诉任何插件。

AI Agent 的边界感，本质上不是模型自己能学会的，而是产品设计者和用户共同划出来的。在你把钥匙交给它之前，最好先问一句：它配吗？
