上周，一家主打“物理隔离级安全”的初创公司高调发布了 Codex 键盘，号称通过独立安全芯片与端到端加密链路，能彻底杜绝键盘侧录与远程窃听。产品出海第一波上手视频还在网络上发酵，黑客社区就传出消息：有人拆了一台 Codex，只花了不到 48 小时便完整提取出主控固件，甚至重现了密钥派生路径。互联网上瞬间炸锅——说好的硬件安全天花板，纸糊的？

这件事远超一个单品翻车的范畴。它把消费电子安全中最隐秘的弱点——硬件信任根设计、供应链防护与侧信道抵御——再一次推到镁光灯下。与其跟着弹幕嘲讽，不如借 Codex 这次“社会性死亡”，把所有这些概念拆开来，看看我们身边的键盘、加密狗、硬件钱包，到底在依赖什么，又是怎么被攻破的。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-25/a3aecae54a2f63d8.png)

## 一把“安全键盘”到底在保卫什么？
普通键盘从按键矩阵读取 scancode，通过 USB HID 报告直接交给操作系统，中间没有认证，没有加密，甚至连完整性校验都没有——任何插在电脑和键盘之间的硬件 Keylogger，或者伪装成 USB 充电口的嗅探器，都可以无感知地记录每一次敲击。Codex 想解决的正是这一段“裸奔”的链路。

它的方案并不新鲜，但在消费级产品中很少被做到如此激进：
- **独立安全元件（Secure Element, SE）**：键盘内嵌一颗取得 CC EAL5+ 认证的 SE，用于密钥存储与加解密运算。
- **端到端加密**：按键数据离开 MCU 之前，便在 SE 内部用会话密钥进行 AES-256-GCM 加密，密文才通过 USB 送出，最终由运行在电脑端的代理程序解密。
- **安全启动链**：从 BootROM → bootloader → 固件，每一级都验证签名，理论上阻止了恶意固件注入。
- **物理防篡改**：键盘外壳采用一次性防拆卡扣，并宣称在 SE 内部配有主动 tamper 检测，一旦探测到开壳便擦除密钥。

卖点清晰，技术路线也符合“不信任主机、不信任传输链路、不信任物理环境”的安全设计三原则。那问题究竟出在哪儿？

## 48 小时攻破：攻击链长什么样？
根据社区披露的碎片信息与类似产品历史漏洞复盘，我们可以还原出一条高度可行的攻击路径。攻击者并没有去正面硬撼 AES-256 或 SE 认证机制，而是围绕信任根本身，做了一次经典的“供应链式降维打击”。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-25/7bdc657bdc917225.png)

### 突破口 1：JTAG/SWD 调试口未彻底熔断
Codex 主控大概率是一颗通用 Cortex-M4 MCU，通过 SWD 接口与 SE 通信。设计上，量产阶段应当通过熔丝（fuse）永久禁用调试口。但第一波破解表明，熔丝并未熔断，或者可通过电压扰动绕过——攻击者只需飞线连接 J-Link，就能 dump 出完整固件镜像。

### 突破口 2：固件中硬编码了 SE 的通信密钥
更致命的事情发生在这里。为了简化产线初始化流程，SE 与 MCU 之间的 I2C/SPI 通信使用了一条对称密钥进行认证与加密。这条密钥以明文形式硬编码在 MCU 固件的某个常数区。一旦固件被 dump，攻击者无需触碰 SE，便能够伪装成合法 MCU，向 SE 下发“导出私钥”或“解密按键流”的指令。

### 突破口 3：tamper 机制被绕过
SE 的防拆设计往往依赖外壳上的导电回路或光敏传感器。但在 Codex 的实现中，tamper 信号需要经由主控转发，主控恰好是那个已被攻破的“叛徒”。在 SE 尚未察觉开壳的几十毫秒内，攻击者已经完成了上述的指令注入。事后就算 SE 自毁，密钥早已被取出。

整条攻击链没有用到 0day，没有侧信道数学攻击，更像是在产线上留了一把钥匙——而这恰恰是硬件安全最常见的反模式：**在最脆弱的骨架上，堆叠最厚重的装甲**。

## 硬件安全为什么总在“修锁忘关门”？
Codex 的案例极具教学意义，因为它几乎集齐了硬件安全产品的经典设计缺陷。

**1. 信任根错位**  
安全产品的信任根应当是那颗 SE，但整个系统的安全启动却依赖一颗不具备任何安全存储能力的通用 MCU。当 MCU 被攻破，SE 反而变成了一个听话的加密黑盒。正确的做法是让 SE 作为主动方，启动时先验证 MCU 固件完整性，认证不通过便拒绝通信，可惜成本、芯片选型与开发复杂度让很多团队选择简化架构。

**2. “生产便利性”侵蚀安全边界**  
产线上刷写初始密钥、调试固件，几乎是每个 IoT 产品的刚需。为了不让烧录流程卡顿，开发团队经常保留一个“后门接口”，或用出厂默认密钥统一初始化。这些临时妥协一旦随量产固件流出，就变成永久漏洞。Codex 硬编码的通信密钥，大概率就是这样的“临时工”转了正。

**3. 物理攻击模型过于理想化**  
设计文档里往往写着“tamper 响应时间 < 2ns”，但工程师很少用人话告诉自己：开壳到注入指令，攻击者有没有 2 纳秒的窗口？在实际操作中，从揭开防拆膜到飞线完成，可能需要数分钟。但如果 tamper 信号需要等待一个运行在已沦陷 MCU 上的中断服务程序来处理，这数分钟就成了攻击者的悠闲时光。物理安全永远是一个系统问题，而不是一颗芯片的问题。

## 安全产品的信任来自哪里？不是口号，是设计范式
Codex 被破解，舆论很容易滑向“所有硬件安全都是智商税”的虚无主义。现实不是这样。安全硬件领域不缺认真做产品的人，缺的是一种从设计阶段就把攻击者成本量化的习惯。

在专业安全圈子里，判断一个安全键盘/加密设备是否值得信任，核心看这几项：
- **有没有不可读的信任根**：私钥是否生成并永驻于 SE 内部，且不可被任何外部接口读出。
- **安全边界是否闭合**：MCU 是否已永久关闭调试口；是否启用 RDP2/安全熔丝，并经过外部审计。
- **生产密钥能否被批量泄露**：每台设备的出产密钥是否为独立的、随机生成的，且工厂端无法批量导出。
- **有没有物理攻击应急预案**：tamper 是否由 SE 直接、异步处理，而不依赖外部主控转发；是否在开壳时主动短路关键走线。
- **固件升级是否有防回滚与签名验证**：攻击者即便拿到旧版本固件，也不能通过降级覆盖已修补的漏洞。

如果一个产品能在产品页面清晰回答这五个问题，并且愿意公开第三方安全审计报告，那它至少是值得被“认真攻破”的对手。而 Codex 在官方宣传中只强调了 SE 的证书和 AES-256，对上述关键细节一概模糊处理——这次闪电破解，并不太冤枉。

## 三条冷思考
硬件安全领域没有绝对无敌的堡垒，只有不断抬高的攻击成本。在 Codex 事件过去之后，作为普通用户或产品经理，有三件事可以沉淀下来：

1. **别把“认证芯片”当护身符**  
一颗 EAL5+ 的 SE 只能证明它对特定攻击向量的抵抗能力，但无法保证系统设计者没有在别处开门。任何时候，安全器件 + 不安全系统 = 不安全的整体。购买硬件安全产品之前，多问一句：你们的固件开源或有第三方审计吗？如果对方含糊带过，信任基础就已经折损一半。

2. **安全型创业公司，先补上“敌意模型”这一课**  
很多团队抱着“我们先做出功能，再慢慢加固”的想法进入安全赛道。但安全产品天然处于攻击者优势地位——你守 360 度，攻击者只需要找 1 度裂缝。在设计评审阶段，就应该邀请外部安全专家做 Threat Model 演练，把攻击路径画出来，逐一确认防御手段是不是实打实落地的，而不是只存在于文档里。

3. **作为社区，我们欢迎这样的“暴力测试”**  
Codex 的破解虽然让厂商难堪，但对整个消费电子安全行业是极佳的免费渗透测试。每一次透明披露，都会推高行业的安全基线。不要因为产品被打脸就否定它存在的意义，但也不要因为情怀就容忍低级设计错误。让工程师用攻击说话，让市场用钱包投票——这才是技术社区最健康的纠错机制。
