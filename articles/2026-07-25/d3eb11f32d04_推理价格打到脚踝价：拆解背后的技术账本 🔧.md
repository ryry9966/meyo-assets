## 价格跳水 90%：数字不会骗人

- **OpenAI 系列**：GPT-4（2023年3月）输入 $30/1M tokens，输出 $60；GPT-4o mini（2024年7月）输入 $0.15，输出 $0.6。输出端价格脚踝斩，只剩百分之一。
- **DeepSeek-V2**：标准价格输入 ¥1/1M tokens，输出 ¥2。注意这是人民币，还没算各种折扣，企业级客户还能再打五折。
- **豆包 Lite**：完全免费，每天数百万 token 调用量白送，相当于把推理当成流量入口。
- **通义千问 Qwen-Long**：直接把 1M tokens 输出价压到 ¥0.5，比很多云服务器的内存费还便宜。

翻译成人话：生成一篇 1000 字文章，推理成本从去年的几毛钱，跌到了今天不到一分钱。AI 应用的底层能源，正在像水电一样走向“按需计费、近乎无限供应”。但这背后不是慈善，而是一套精密的技术瘦身工程。

## 推理成本的三根大动脉

大模型推理的本质，是让几百亿参数跑一次不带反向传播的前向计算。听起来简单，可每一次 token 生成，都要经历三道关口：计算、内存和通信。它们就像三根大动脉，任何一条堵塞，成本都下不来。

**1. 计算：矩阵乘法的无底洞**  
大模型的一次推理，本质上是几千次矩阵乘法。以 Llama-70B 为例，生成一个 token 要消耗约 140 GFLOPS 算力。在 FP16 精度下，一块 A100 GPU 每秒只能生产几十个 token，按时间计费自然昂贵。于是“量化”成为第一把手术刀：把 FP16 权重压缩成 INT8，推理速度直接翻倍；再压成 INT4，模型大小减半，吞吐量还能再跃升，精度损失却控制在 1% 以内。这相当于把一本百科全书印在巴掌大的小册子上，还不怎么影响阅读。

**2. 内存：KV Cache 这只吞金兽**  
自回归生成时，每生成一个新 token，都要把前面所有 token 的 Key 和 Value 缓存起来，这就是 KV Cache。假设一次对话长度 4096 tokens，一个 70B 模型所占的 KV Cache 内存就高达数十 GB。如果不加约束，GPU 显存会被迅速吃光，推理只能排队——成本直线上升。于是 Multi-Query Attention、Grouped-Query Attention 被请了出来：多个注意力头共享同一套 Key/Value，内存占用立砍 70% 以上。这招好比图书馆改制，原来每本书配一个管理员，现在一排书架只配一个，照样能找到书，省下大量人力。

**3. 通信：多卡协作的隐形税**  
当模型大到一块 GPU 装不下，就得切片到多张卡上。每次计算，卡与卡之间都得互相传梯度、传激活值。PCIe 带宽成了瓶颈，甚至在 A100 的 NVLink 上也未必游刃有余。FlashAttention 这类算法就做了一件事：把通信隐藏到计算阴影里，让数据搬运和矩阵乘法同时进行，无缝衔接。看起来每张卡都忙得“火上浇油”，实际上隐藏了通信延迟，整体吞吐提升 30% 以上。

## 降价三板斧：模型瘦身、硬件加速、调度玄学

把三根动脉打通之后，厂商又祭出了三把板斧，一刀接一刀把价格砍到地板。

**模型瘦身三板斧：量化、剪枝、蒸馏**
- **量化**：除了 INT8/INT4，还有 GPTQ、AWQ 等后训练量化算法，能在不重新训练的前提下，把模型精度压缩到极限。有些极端方案甚至搞起了 2-bit 量化，虽然精度损失开始显现，但简单问答场景已经够用。
- **剪枝**：SparseGPT 之类的算法，能一次性剪掉一半以上的神经网络连接，模型变稀疏后，推理时直接跳过大量乘法，速度飙升。就像把国道的收费站撤掉一半，不堵了。
- **蒸馏**：用大模型当老师，训练一个更小、更专的学生模型。通义千问就有一系列蒸馏版，从 72B 蒸馏到 1.8B，某些任务精度保留 90%，成本却只有千分之一。

**硬件加速：不靠 NVIDIA 也能飞**  
推理场景不像训练，对显存带宽和延迟极其敏感。于是特化芯片登场了：Groq 的 LPU（语言处理单元）彻底抛弃了 GPU 那套架构，用 SRAM 和确定性调度，做到了单 token 延迟低于 10ms。国内也有不少专用推理卡，软件栈虽然还在追赶，但价格优势已经显现。另外，投机推理（Speculative Decoding）让一个小模型先草拟几个候选 token，再由大模型一次验证，若通过，一下省掉好几步大模型调用，吞吐量直接翻倍，相当于先让实习医生问诊，主任医师盖章就行。

**工程调度玄学：vLLM 与连续批处理**  
这可能是 2023 年下半年最不像黑科技的黑科技。vLLM 提出 PagedAttention，把 KV Cache 像操作系统的虚拟内存一样分页管理，彻底解决了 KV Cache 碎片化问题，内存利用率从 20% 拉到 70%。配合连续批处理（Continuous Batching），每次有新请求进来，不用等当前批次结束，直接动态插入，GPU 永远在跑，不空转。结果：同样的硬件，吞吐量提升 5~10 倍。翻译成人话：一台服务器，原来一天只能服务 100 个客户，现在能服务 1000 个，单价自然摊薄。

## 低价羊毛有三坑，薅之前问自己三句话

推理价格跌得这么狠，是不是可以闭着眼睛上船？先别急，低价背后往往藏着隐性成本。动手之前，用下面「三问」做个压力测试。

**1. 延迟：快吗？稳吗？**  
很多低价 API 的 P50 延迟看着还行，但 P99 延迟飙到几秒。如果你的应用是实时对话，用户等 5 秒才蹦出一个字，他早跑了。测试时一定要看长尾延迟，别被平均值忽悠。

**2. 并发上限：高峰时会不会限流？**  
免费和低价 API 常常标注“免费额度每秒限 5 个请求”，或者“爆满时排队”。一旦你的产品上了活动，并发涌上来，API 直接返回 429 错误，用户看到的就是“服务暂不可用”。别忘了仔细阅读 SLA 条款，确认并发上限和过载保护策略。

**3. 数据隐私：便宜没好货？**  
有些小厂推理 API 之所以便宜，是因为他们把用户数据拿来二次训练模型。你的企业机密、用户对话，可能转眼就成了别人模型的养料。务必看清数据使用条款，敏感场景优先考虑自部署。

## 🦞 RY哥的冷思考

推理价格战的下半场，赢家不会是杀价最狠的厂商，而是最先理解成本构成、并把推理能力转化为产品壁垒的团队。

**1. 别贪零元购，盯住单位质量成本。**  
一毛钱一顿的麻辣烫和五十块一份的和牛，本质不是同一个物种。关键业务场景上，先评估“每正确回答的成本”，而不是“每 token 的成本”。一个廉价但答非所问的模型，浪费的是用户的时间和你的口碑。

**2. 开源模型 + 自建推理，开始有性价比了。**  
随着 vLLM、TensorRT-LLM 等工具链成熟，自建推理服务的门槛大幅降低。一台 A100 服务器配上量化模型，推理成本可以压到 API 售价的一半甚至更低，数据还完全掌控在自己手里。对于日均调用量超过百万的团队，早就过了盈亏平衡点。

**3. 推理成本终将趋近于电力成本，但需求会指数爆炸。**  
就像当年的带宽，单价一直在降，总支出却一路攀升。因为每个人都开始用视频、直播、高清图片。大模型推理也一样，单价降 90%，可能刺激出 100 倍的新使用场景——无限生图、实时语音翻译、全天候 AI 助手。你在这个弯道之前，准备好弹药了吗？
