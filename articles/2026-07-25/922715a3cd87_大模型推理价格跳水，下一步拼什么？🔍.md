年初还在按“分/千tokens”计费的大模型推理服务，到年底已经出现了免费套餐、按次调用甚至近乎“白菜价”的定价。这场从训练侧蔓延到推理侧的价格战，正在把大模型从实验室奢侈品推向水电般的基础设施。降价不是终点，而是下半场的入场券。



## 一、推理成本“打骨折”的技术底牌

推理成本从暴利走向微利，根子在于一系列工程突破叠加。

- **模型架构的“懒人模式”**：以 MoE（混合专家）为代表的稀疏模型，每次推理只激活参数总量的一小部分。比如 8×7B 的 MoE 模型，实际推理时只“唤醒” 12B~14B 的活跃参数，算力消耗直接对折。再加上**注意力头剪枝、层数缩减**等结构优化，推理所需的 FLOPs 指数级下降。
- **量化让精度给效率让路**：INT8 早已是标配，GPTQ/AWQ 等 4-bit 量化方案在不明显损失效果的前提下，把显存和带宽需求压到 FP16 的 1/4。最近甚至出现了 2-bit 推理，尽管精度略有波动，但在大批量简单任务（如分类、抽取）中，性价比拉满。
- **推理框架的魔法**：vLLM 的 PagedAttention 把 KV 缓存管理得像操作系统分页，碎片化显存利用率从 20% 提升到 80% 以上。连续的动态批处理（Continuous Batching）让 GPU 不再空等，一张卡能同时服务上百个请求。TensorRT-LLM、SGLang 等进一步榨干硬件，延迟降低 5~10 倍。
- **推理专用硬件的崛起**：Groq 的 LPU 用 SRAM 取代 HBM，推理速度惊人；Cerebras 的晶圆级芯片用海量片内带宽避开了数据搬运瓶颈。虽然这类硬件事先部署成本高，但在大规模推理场景中，单位 token 成本能打掉一个数量级。
- **规模化摊薄边际成本**：当一家云厂商部署成千上万张 GPU 专门做推理，电力、散热、带宽的固定开销被海量请求均摊，token 单价自然一低再低。



## 二、计价方式的七十二变

价格战的下半场，不只是数字变小，计价方式也在疯狂内卷。

- **从按 token 到按次**：早期所有模型都按“每 1K 输入/输出 token”定价，开发者必须估算 token 消耗。现在主流 API 几乎都支持**按次调用**，甚至提供**包月、资源包**模式，像买云虚拟机一样简单。
- **输入输出分离，缓存变钱**：很多模型把输入价格压到几乎免费，靠输出收费。同时引入**前缀缓存（Prompt Caching）**：如果多次调用共享同一长前缀（如 system prompt），缓存命中后输入价格打一折甚至免费。这对客服、文档问答等场景极为友好。
- **分级“订阅制”**：OpenAI、Anthropic 等推出免费额度 + 付费套餐，免费用户使用稍慢但免费的 GPT-4o mini，付费用户享受更快、更高级的模型。本质上是用低价版引流，再用高性能版本盈利。
- **MCP 与内置工具，变相提价**：部分平台把推理与工具调用、结构化输出捆绑，虽然裸 token 价在降，但带工具的高级调用可能价格更高。用户不知不觉为生态支付溢价。

## 三、价格战背后的算盘

赔本赚吆喝？远没有这么简单。

- **生态锁定的“微信模式”**：低价甚至免费让开发者迅速入驻，一旦在平台上构建了大量工作流、数据接入和 fine-tuned 模型，迁移成本陡增。云厂商赌的是用户“来了就不走”。
- **数据飞轮的闭环**：海量推理请求带来真实的 prompt 和反馈。这些数据经过脱敏后，可以直接用于后续模型对齐与微调，形成“越用越聪明，越聪明越有人用”的飞轮。
- **云服务“捆绑销售”**：微软、谷歌、AWS 把大模型推理作为云套餐的引流品。你使用的模型几乎免费，但数据存储、负载均衡、日志分析等服务在悄悄记账。总的 ARPU 不降反升。
- **开源模型的鲶鱼效应**：Llama 3、Mistral Large、Qwen 2.5 等开源模型性能已逼近闭源的旗舰，私有化部署的成本固定，按 3 年 TCO 计算，大批量推理可能比 API 更划算。闭源厂商被迫降价保市场。



## 四、开发者该高兴还是该警惕？

推理价格下探，对开发者是实实在在的利好，但几盆冷水也必须浇醒。

- **创业门槛断崖式下降**：用百元预算就能为一个小型 SaaS 接入顶级模型，快速验证 PMF。不需要拿融资去训模型，应用层的创新被彻底点燃。
- **同质化内卷加速**：人人用得起的模型，意味着如果没有差异化数据和业务逻辑，产品很容易沦为“套壳”。下一阶段，拼的不再是谁能用大模型，而是谁能把模型用出花来。
- **成本结构剧变**：当推理价格降到训练价格的几百分之一，很多企业会把推理当作“计算常数”，但高并发场景下，累计成本仍可能失控。精细的**耗用监控、模型路由、缓存策略**成为必备工程能力。
- **绑定风险不可忽视**：过度依赖单一提供商的 API，一旦对方调价或调整服务协议，业务可能被动。建议至少设计 **双供应商 + 开源备选** 的架构，保持“随时可切换”的能力。
- **隐私与合规的暗礁**：超低价推理有时意味着数据会被更深度地用于训练。调用条款中的“数据使用”条款必须逐字阅读，尤其是涉及 PII（个人身份信息）时。

## 五、冷思考：白菜价的尽头是什么？

面对如火如荼的推理价格跳水，三条接地气的建议送给你：

1. **别只盯着价格**。评估一个推理服务，要把**延迟、吞吐量、并发上限、SLA 保障、隐私条款**打包看待。一个免费但每次调用排队 10 秒的 API，可能让用户体验崩盘。
2. **算好总拥有成本（TCO）**。如果月调用量超过 1 亿 token，一个精心调优的开源模型部署在自建推理集群上，可能比按量付费的 API 便宜 60% 以上——但得算上运维工程师的人力成本。做一张 Excel，把账算清。
3. **把降价当作信号，而非终点**。价格战打到地板价时，意味着整个行业即将进入“价值战”：谁的生态最丰富？谁的工具链最丝滑？谁能保证数据不“投喂”？这些才会是下一轮洗牌的关键。
