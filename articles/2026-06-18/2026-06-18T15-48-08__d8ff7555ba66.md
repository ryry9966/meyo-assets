最近 36kr 的一条新闻在制造业圈和 AI 圈同时刷屏：海尔智家公开了它的「企业 Agent OS」，说要把 AI 真正塞进研发、生产、供应链、营销、服务这条全链路里去。比起那些只会发 PPT 的「AI 转型」案例，这事算是动了真格。今天我们不谈营销话术，聊点更底层的——为啥制造业搞 AI 这么难，所谓「企业 Agent OS」到底是个什么东西，又凭什么海尔会先动手。

## 一、为什么制造业的 AI 落地，比互联网难一个量级

互联网行业搞 AI，数据是现成的，业务是数字原生的，模型推完结果直接进系统就完事了。但制造业不是这样，它的痛点几乎全在「物理世界」这一层：

- **数据散、脏、孤岛**：MES、ERP、PLM、SCM、CRM……一家中大型制造企业里跑十几套系统是常态，数据格式各异，时间戳还经常对不上。
- **流程链条极长**：从一个用户需求到一台空调下线，中间要过研发、采购、排产、装配、质检、物流、售后，任何一个环节出问题都会传导到下游。
- **试错成本高**：互联网产品 A/B 测试坏了顶多回滚；产线一停一小时可能就是几十万；模具改一版周期是按周算的。
- **业务知识高度隐性**：一个老师傅看一眼焊点就知道有没有问题，这种「Tacit Knowledge」很难用结构化数据描述，也很难直接喂给大模型。

所以你会发现，过去几年制造业的 AI 项目，大多停留在「单点 AI」：质检视觉、设备预测性维护、能耗优化、销量预测……都是局部最优，缺一个把它们串起来的「中枢」。Agent OS 想解决的，就是这个串联问题。

## 二、企业 Agent OS 到底是什么？

「Agent OS」这个词最近用得有点滥，但拆开看其实并不玄。它和操作系统 OS 的类比是成立的：

- **OS 之于硬件**：管理 CPU、内存、磁盘、外设，给应用提供统一接口。
- **Agent OS 之于企业**：管理模型、工具、数据、流程、权限，给业务 Agent 提供统一接口。

更具体一点，一个企业级 Agent OS 通常包含这几层：

1. **模型层（Model Layer）**：不是只有一个大模型，而是「大模型 + 行业小模型 + 经典 ML 模型」混搭。比如对话用 LLM，缺陷检测用 CV 小模型，需求预测用时间序列模型。
2. **工具层（Tool Layer）**：把企业现有系统的 API 都包装成 Agent 可调用的工具，比如「查 BOM」「下排产单」「调取工单」。这一层的工作量极大，本质上是个「全公司 API 化」工程。
3. **记忆层（Memory Layer）**：包括知识库（手册、SOP、历史工单）、向量库、业务实体图谱。决定 Agent 能不能「懂这家公司」。
4. **编排层（Orchestration）**：多 Agent 协作的调度，谁负责拆解任务、谁执行、谁审核、谁回写结果。
5. **治理层（Governance）**：权限、审计、风控、合规。这一层在 To C 应用里常被忽略，但在企业里是生死线。

简单说：**没有 Agent OS 之前，AI 是一个个能力点；有了 Agent OS，AI 才有可能变成业务流程本身**。

## 三、海尔为什么会先做？背后的三个客观条件

抛开品牌叙事，从工程视角看，海尔具备做这件事的几个前提条件，这些条件并不是每家制造企业都有：

- **数字化底子厚**：海尔从 2005 年就开始搞「人单合一」，2012 年起在内部推 COSMOPlat 工业互联网平台，相当于已经把企业内部 API 化、数据化做了十多年。Agent OS 是建在这层地基上的，不是空中楼阁。
- **业务复杂度足够高**：白电、厨电、热水、空调、海外品牌（GE Appliances、Candy、AQUA）……产品线和市场都极其复杂。复杂度本身就是 Agent 的「需求来源」——简单业务用 RPA 就够了，根本不需要 Agent。
- **小微组织结构适配**：海尔内部把团队拆成大量「小微」自主单元，这种结构天然适合「每个小微养一个或几个 Agent」的模式，比传统科层制企业更容易迭代。

值得注意的是，公开信息显示这套 Agent OS 已经渗透到研发、智造、营销、服务等多个场景：研发端用来辅助方案生成与器件选型，智造端做排产优化与质量分析，服务端则做工单分类、知识检索、用户交互。这种「全链路铺开」而不是「单点试点」的打法，在当前国内制造业里算激进的。

## 四、技术细节：几个容易被忽略的硬骨头

做过企业级 AI 的同学应该都懂，PPT 上画得漂亮，落地全是坑。以下几块是真正决定成败的：

- **企业知识的「灌入」问题**：把几十年的工艺手册、SOP、历史故障库喂给模型，不是简单 RAG 就完事。文档里有大量图表、公式、隐含上下文，需要专门的解析 pipeline，外加领域专家做标注。
- **Agent 的可靠性**：LLM 本身有幻觉，但企业场景容不得乱编。常见做法是「确定性流程 + LLM 兜底」混合架构，关键路径用规则和经典模型，LLM 只负责理解意图和生成自然语言。
- **成本控制**：一个 7B 模型推理一次几分钱看似便宜，但当一天有几百万次调用、还要走多 Agent 协作（一次请求可能触发十几次模型调用），账单会很可观。模型路由（Model Routing）几乎是必选项。
- **组织阻力**：技术问题往往不是最难的。Agent 上线意味着流程重构，意味着有些岗位的工作内容会变。如何让一线员工愿意用、敢用、用对，是比模型调优更花时间的事。

## 五、对其他制造企业的启示

不是每家公司都要立刻上 Agent OS，但有些信号值得关注：「单点 AI」的红利已经吃得差不多了，下一波价值在「流程级 AI」。可以从下面几个角度想想自己的位置：

- 你公司的业务系统 API 化程度有多高？如果连查个库存都要登 5 个系统，那 Agent 落地的地基还没打。
- 你有没有一个真正能负责「数据 + 模型 + 业务」三栖的小团队？纯算法团队和纯 IT 团队都做不出 Agent OS。
- 你能不能容忍一个 6~12 个月「看起来没产出」的建设期？这种事急不来。

## 三条冷思考

1. **别神化 Agent OS**：它不是银弹，本质是「企业数字化的下一个版本」。没有前序的数据治理、API 化、流程标准化，直接上 Agent 就是在沙滩上盖楼。
2. **从「最痛的一个场景」切入，而不是从最酷的场景切入**：研发辅助听起来高大上，但如果你公司最大的成本黑洞在售后工单，就先做服务 Agent。ROI 比 Demo 重要。
3. **警惕「为了 Agent 而 Agent」**：很多场景规则引擎 + 经典 ML 已经能做到 95 分，硬上大模型只是把成本翻 10 倍换 96 分。技术选型永远要回到「问题—成本—收益」三角。

制造业 AI 这件事，热闹是别人的，落地是自己的。海尔走出了第一步，但路还很长——对所有想沿着这条路走的公司来说，地基比楼顶更重要。
