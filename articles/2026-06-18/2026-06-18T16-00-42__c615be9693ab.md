最近一条消息在 AI 圈炸了锅：长文本评测榜单 Fable 5 的榜首选手疑似「作弊」，相关代码被扒出后，那个看起来神秘兮兮的「黑马模型」真实身份也被曝光。围观群众一边吃瓜，一边开始质疑：现在那些一夜屠榜的大模型，到底有几分真本事？今天就借这件事，把「大模型评测」这门玄学拆开来聊聊——为什么榜单会被玩坏、常见的作弊手法长什么样，以及作为用户，应该怎么看待这些花花绿绿的排行榜。

## 先搞清楚：Fable 5 是个什么榜

Fable 系列是近一两年在小圈子里热度颇高的长文本/长上下文叙事评测，主要考察模型在「长篇虚构内容」场景下的几项能力：

- **长程一致性**：故事写到十几万 token，人物设定、伏笔、时间线还能不能对得上。
- **隐藏信息追踪**：作者在前文埋了一个细节，几万字后再问模型，能不能正确回忆。
- **风格保持**：能不能从头到尾维持同一种叙述腔调，而不是写着写着变成新闻稿。
- **推理与情节闭合**：故事结尾的合理性、伏笔的回收率等。

相比 MMLU、GSM8K 这种「填空考试」式的传统 benchmark，Fable 这类评测更接近真实创作场景，分数不太容易靠刷题刷上去——所以它一旦出现「神秘黑马霸榜」，圈内人第一反应往往不是「真牛」，而是「先看看代码」。

## 「作弊」到底是怎么作弊的：几种常见手法

这次事件的细节不必深究，但围绕评测榜单的「常规操作」，业界其实早有一份不成文的「黑名单」。

1. **测试集污染（test set contamination）**
   - 最经典也最难证伪的一种。训练语料里悄悄混入了评测题目和答案，模型不是在「推理」，而是在「背答案」。
   - 学术界已经有不少论文专门研究怎么检测污染，比如看模型对题目原文和扰动版本的 perplexity 差异、用「金丝雀字符串」反查等。

2. **路由 / 套壳（model routing）**
   - 对外宣称是一个「独立小模型」，实际背后挂的是 GPT-4、Claude 之类的顶级 API，按问题类型自动转发。
   - 这次 Fable 5 事件中「代码泄露」之所以杀伤力大，就是因为路由逻辑往往写得很直白，一看就懂：「if 是评测请求 → 调用大模型」。

3. **Prompt 注入 + 后处理**
   - 在评测请求到来时，悄悄拼上一段超长的 system prompt，里面塞满了对该评测的 few-shot 样例，甚至直接给出评分标准的反向工程。
   - 再配合后处理脚本，把模型的输出按榜单偏好「精修」一遍，比如统一格式、删掉啰嗦语气。

4. **针对评分模型的 adversarial 优化**
   - 很多榜单用一个「裁判模型」（比如 GPT-4）打分。如果选手知道裁判是谁，就可以专门针对它的偏好做 RLHF，写出一种「裁判最爱听」的文风。
   - 结果是榜单分数高，但人类读者看了反而觉得做作。

5. **小动作的灰色地带**
   - 比如重复采样 N 次，只提交分数最高的一次；用更大算力跑评测、用线上服务跑而非论文里宣称的本地权重等。这些不一定算「作弊」，但显然不公平。

## 为什么评测榜单这么容易被玩坏

这不是 AI 圈第一次出现刷榜丑闻，更不会是最后一次。深层原因有几条：

- **评测本身是「公开的考卷」**：只要题目公开，就一定会被反向利用。这在传统机器学习时代就已经反复上演——ImageNet、SQuAD 都被刷过头。
- **激励结构错位**：榜单分数 → 媒体报道 → 融资估值 → 商业订单，这条链路太短、太诱人。一家小厂多花一周「优化」一下评测脚本，回报可能是几千万的融资差距。
- **裁判模型自身有偏好**：用 LLM 评 LLM，本来就存在「自我偏爱」「长度偏爱」「礼貌偏爱」等系统性 bias，被针对性优化是迟早的事。
- **复现成本高**：很多榜单只看选手提交的结果，不强制要求开源权重、不要求第三方在隔离环境复跑。等于考生交了卷，没人监考。
- **「长上下文」尤其难评**：一份测试样例动辄几十万 token，跑一遍要烧不少钱，所以题目总量有限、轮换慢，污染窗口长。

## 这件事对行业意味着什么

刷榜本身并不新鲜，但 Fable 5 这次事件之所以值得多看两眼，是因为它暴露了几个新趋势：

- **「神秘模型」营销正在祛魅**。过去一年，匿名上榜、隐藏身份、等舆论发酵再揭晓，已经成了一种标准化的 PR 套路。用户开始警觉：黑马是真的黑马，还是穿了件马甲的老朋友？
- **代码与权重的可审计性会被反复强调**。未来评测平台大概率会要求选手提供可复现的 inference pipeline，至少在沙箱里跑一遍，而不是只接受一个 API endpoint。
- **「私有题库 + 滚动更新」会成为新标配**。类似 SWE-bench Verified、LiveBench 这种动态题库的评测会越来越多，公开静态题库的权威性会持续下降。
- **裁判多元化**。单一 LLM 当裁判的方案正在被「多模型集成 + 人类抽检」取代，至少在头部榜单上。

## 三条冷思考

聊这么多，不是为了让大家对所有榜单产生 PTSD，而是希望多一点判断力。给三条小建议：

1. **看榜单先看方法论，再看分数**。
   - 题目是否公开、是否滚动更新、裁判是谁、是否允许 N 选 1 提交，这些远比榜首是谁更重要。一个透明度高的第二名，往往比一个神秘的第一名更值得信任。

2. **自建小型私有评测集，是开发者的护身符**。
   - 哪怕只有 30~50 道贴合你业务的真实任务，跑出来的分数也比任何公开榜单更能反映「这个模型对你有没有用」。成本不高，但能屏蔽掉 90% 的营销噪声。

3. **对「一夜屠榜」保持本能怀疑**。
   - 真正的能力跃迁通常伴随论文、技术报告、可复现 demo 一起出现，而不是只有一条匿名提交记录和一段语焉不详的推文。如果一个新模型只在某一个榜单上一骑绝尘，在其他场景却没人讨论，大概率是「专项训练」的产物。

说到底，benchmark 是工具，不是信仰。它能帮我们粗筛模型，但替代不了你亲自把它丢进真实业务里跑一遍的那种确定感。Fable 5 这次的瓜，与其说是某家厂商翻车，不如说是整个行业又一次被提醒：**当衡量标准变成目标，它就不再是一个好的衡量标准**——古德哈特定律，在 AI 时代依然管用。
