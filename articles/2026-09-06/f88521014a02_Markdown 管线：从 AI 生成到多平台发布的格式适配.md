## 背景

社区自动化里一个常见场景：Agent 生成长文，要同时发到博客、GitHub、公众号、知乎、论坛。每个渲染器对 Markdown 的支持都不一样，硬拷贝必然翻车。我们把这些适配做成了一条管线：维护一份 Canonical Markdown，派生出各平台的发布产物。

## 问题

AI 输出的 Markdown 看着像，坑却不少：标题层级跳跃（H1 直接 H3）、列表标记 `-` 和 `*` 混用、表格单元格里带竖线、脚注/公式/任务列表只有部分渲染器支持。目标平台差异更大：有的不支持内联 HTML，有的吞掉外链图片，有的要求行内样式。逐平台写正则替换脚本，模型输出风格一变就全崩——所以正确做法是统一走 AST。

## 做法

管线分四步：

1. **生成期约束**。在 Agent 的 prompt 里固定模板：单一 H1、固定小节、禁用 HTML、表格不超过四列。这不是指望模型输出完美，而是降低下游清洗成本。
2. **规范化**。用 mdformat/remark 之类统一格式：列表标记、缩进、强调风格、多余空行，再跑一遍 markdownlint。校验失败直接打回重试，不带病进下游。
3. **按目标做 AST 变换**。每个适配器只做一件事：脚注转行内括号注、公式转图片或降级为代码块、表格降级为列表、外链图片先搬到可控图床；需要行内样式 HTML 的平台，在 markdown-it 的 renderer 上覆写输出，而不是后处理 HTML 字符串。
4. **校验与发布**。步骤间做断言：标题层级合法、链接可达、图片存在。变换失败走降级路径（如表格→列表），记 warning，不中断发布。

## 踩坑点

- 不要信任模型输出的代码围栏语言，空语言围栏会导致按纯文本渲染，部分平台直接渲染错乱。
- YAML frontmatter 的 `---` 在不支持的渲染器里会被当成水平线，适配前先摘掉。
- 表格内嵌 `|` 和反引号嵌套是解析事故高发区，规范化阶段就该重写成列表或引用。
- `$` 公式定界符与金额符号冲突，我们两次把 `$100 $200` 渲染成公式，建议强制 `$$...$$` 或 `\(...\)`。
- 单换行在部分渲染器会折叠，而模型爱用单换行分段，规范化时统一转双换行。

## 可复用建议

- 变换器写成 AST 上的纯函数，配 golden 文件做快照测试，改动只看 diff。
- MCP/插件场景：只暴露一个 `publish(markdown, target)` 工具给 Agent，别让它自己拼平台特化输出——适配责任在管线，不在模型。
- Canonical Markdown 是唯一事实源，发布产物全是派生物，出问题重跑即可。
- 降级路径必须留日志，否则你会发现某平台悄悄变成一堆列表而你毫不知情。

## 总结

这条管线的价值不在于某个转换技巧，而在于把格式适配从一次性脚本变成可测试的工程组件。模型输出永远不可控，但你的 AST 层可控：先约束生成、再规范化、后按目标变换、全程断言，多平台发布就能稳定跑在自动化里。
