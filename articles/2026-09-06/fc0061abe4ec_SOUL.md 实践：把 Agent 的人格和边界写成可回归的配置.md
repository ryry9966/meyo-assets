## 背景

OpenClaw 的工作区里有一组用 Markdown 维护的“人格文件”：`SOUL.md` 定义 agent 是谁、怎么说话、哪些事不做；`USER.md` 记录用户画像；`MEMORY.md` 存长期记忆。其中 SOUL.md 会随系统上下文注入每轮对话，相当于 agent 的“宪法”——优先级高、占 token 预算、影响每一句回复。

很多人的用法是两种极端：要么保留默认文件直接跑，要么写一句“你是一个乐于助人的助手”。前者导致语气和行为随模型版本漂移，后者基本不产生约束力。

## 问题

我踩过的三个典型坑：

1. **语气漂移**：模型升级后，同一份 SOUL.md 下回复风格明显变化，群里的 bot 突然变话痨。
2. **人格与工具冲突**：SOUL.md 写“回复保持简洁”，但 MCP 工具返回结构化长结果，agent 在“执行任务”和“遵守人格”之间反复横跳。
3. **边界形同虚设**：写了“不要乱发消息”，但它替我在群里回了一条不该回的消息，全程没有拦截。

根因相同：SOUL.md 被当成了许愿池，而不是一份可测试的行为规范。

## 做法

我现在的结构约 40 行，控制在上下文预算内：

1. **一句话身份 + 行为化语气规范**。不写形容词：“简洁”没用；“先给结论，再给最多三条理由，默认不用 emoji”才有约束力。
2. **红线块（最短的硬规则）**。动钱、以我名义发消息、删除/覆盖文件、暴露凭据——这四类必须先向我确认再执行。单独成块，方便 review。
3. **2~3 个 few-shot 片段**。每个两行，示范“期望的回复”和“期望的拒绝”，效果远好于十条描述。
4. **冲突裁决顺序**。明确写：工具文档与本文冲突时红线优先；简洁性要求让位于任务完整性。

配套实践：

- SOUL.md 只放人格和边界，事实性内容进 USER.md / MEMORY.md，避免单文件膨胀导致注意力稀释；
- workspace 纳入 git，改 SOUL.md 走 commit + diff，至少能回答“它上周为什么不是这样的”；
- 维护一个 10 条左右的回归提问集（含 2 条边界试探），每次改文件或换模型后跑一遍。

## 踩坑点

- **全是否定句**。连续十几个“不要……”，遵循效果明显弱于正面示范，压缩成红线 + few-shot 后稳定很多。
- **改完不重开会话验证**。注入时机与会话生命周期相关，旧会话里测出的行为不反映新文件。
- **边界太抽象**。“注意安全”没有任何拦截作用，必须落到具体动作：哪些工具、什么参数特征、确认话术是什么。
- **人格过强导致拒活**。写过“只聊技术”，结果它拒绝帮我订会议室。人格描述的是风格，不是任务白名单。

## 可复用建议

- 长度预算：SOUL.md 控制在 50 行内，超了就拆子文件。
- 每条人格描述自问：能写出一个让模型“违反它”的提问吗？写不出来就是空话。
- 红线必须对应可观察的动作（调用某工具、携带某参数），否则没法验证。
- 把模型升级视为破坏性变更，回归集全量重跑。

## 总结

SOUL.md 的价值不在“给 bot 一个性格”，而在于把不可靠的默认行为收敛成一份可 review、可版本化、可回归的规范。人格部分写行为不写形容词，边界部分落到具体动作加确认机制，再配一个小回归集，agent 的行为稳定性会有肉眼可见的提升——本质上是给 agent 做一次最小限度的配置管理。
