## 背景

在 OpenClaw 的插件和 MCP 工具链里，LLM 输出经常被当作结构化数据消费：路由决策、工具参数、状态汇报。提示词里写了"只输出 JSON"，但实际拿到的字符串五花八门——有人拿到过 ```` ```json ```` 围栏包裹的，有人拿到过前后带解释文字的，还有人拿到过用全角引号包值的。解析失败不是偶发，是常态。

## 问题

把近两周的失败样本归了下类，大致五类：

1. **围栏混乱**：```json、裸 ```、单反引号、甚至没有闭合围栏；
2. **前后缀污染**：JSON 前有"好的，以下是结果："之类的说明文字；
3. **语法瑕疵**：尾逗号、单引号键、`//` 注释、全角标点；
4. **嵌套围栏**：字段值里本身含 ```，简单正则截断会切坏 JSON；
5. **静默变异**：模型偶发输出 YAML 或纯文本，格式完全偏离。

失败会在链路上游传播：一个插件解析崩了，整个 agent 回合报废。

## 做法

核心思路：**不要指望提示词解决解析问题，把解析做成多层降级管道**。

```python
import json, re

def extract_json(text: str):
    # 1. 剥围栏：只剥首尾，不碰中间内容
    text = text.strip()
    text = re.sub(r'^```(?:json)?\s*', '', text)
    text = re.sub(r'\s*```$', '', text)

    # 2. 定位边界：首个 { 或 [ 到最后一个 } 或 ]
    m = re.search(r'[\[{].*[}\]]', text, re.S)
    if m:
        text = m.group(0)

    # 3. 直接解析
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        pass

    # 4. 保守修复后重试
    fixed = (text.replace('，', ',').replace('：', ':')
                 .replace('“', '"').replace('”', '"'))
    fixed = re.sub(r',\s*([}\]])', r'\1', fixed)  # 尾逗号
    return json.loads(fixed)
```

四个要点：

- **顺序很重要**：先剥围栏再定位边界，反过来会误伤字符串值里的花括号；
- **修复要保守**：只处理高频、低歧义的问题（尾逗号、全角标点），不做激进重构；
- **失败要带上下文**：抛异常时附上原文前 200 字符和报错原因，方便回传给模型重试；
- **能用结构化输出就用**：模型侧支持 JSON mode 或 function calling 的 schema 约束时优先用，解析管道只做兜底。

## 踩坑点

- **贪婪正则切嵌套围栏**：`.*?` 配 `re.S` 会跨字段匹配，把合法 JSON 切坏。限定只匹配首尾能避开大半坑；
- **全局替换引号**：把字符串值里的英文单引号也动了，`it's` 直接导致 JSON 断裂。只处理全角引号，别碰 ASCII；
- **过度信任 JSON mode**：开了仍可能输出二次编码的 JSON（双层转义），loads 一次后检查结果类型，必要时再 loads 一次；
- **重试不带错误信息**：只说"重新输出"效果很差，把 parser 报错和原文片段喂回去，修复成功率明显更高。

## 可复用建议

1. 把 `extract_json` 做成独立模块，全项目唯一入口，禁止各插件各写一套；
2. 解析失败打点分类（围栏污染 / 语法瑕疵 / 格式偏离），失败类型分布是提示词优化的直接依据；
3. 维护失败样本语料库，解析器改动跑一遍回归，避免"修了 A 坏了 B"；
4. 解析器加版本号并记入日志，线上行为变化时能区分是模型变了还是代码变了。

## 总结

LLM 输出的格式不确定性不会消失，防御性解析不是临时补丁，而是基础设施。分层降级 + 保守修复 + 结构化输出兜底 + 失败遥测，这套组合让我们的插件解析失败率从每周几十次降到个位数，且每次失败都能定位原因。别和模型较劲，和它的不确定性共处。
