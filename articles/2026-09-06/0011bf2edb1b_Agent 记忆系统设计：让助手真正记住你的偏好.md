## 背景

用 OpenClaw 这类长期在线的 Agent 助手，最劝退的往往不是能力不够，而是"失忆"：今天说清楚"我用 pnpm、回复要短"，下周它又开始默认 npm 和长篇大论。上下文窗口再大，会话结束就清零；跨会话偏好靠人肉重复，体验上等于每次都在带新人。

## 问题

常见误区是"模型够强就行"或"上下文够长就行"。实际做下来，难点集中在三处：

1. **记什么**：偏好、事实、一次性指令混在一起，全记会膨胀，少记没用；
2. **怎么更新**：只追加不合并，记忆文件三个月后就自相矛盾；
3. **怎么用**：全量塞进 system prompt 会挤占注意力预算，Agent 反而变笨。

## 做法

我目前的方案是分层结构 + 一套写入管线，核心原则八个字：**结构化、可遗忘、按需检索**。

**第一步：定义记忆 schema。** 别存大段自由文本，把用户画像拆成字段，用一个 markdown 文件维护（人类可读，随时能手动改）：

```markdown
# profile
language: zh-CN
timezone: Asia/Shanghai
style: 回复简短，先结论后细节
tooling: pnpm, uv
# changelog
- 2025-06: 部署环境从自建 k8s 迁到 fly.io
```

**第二步：写入管线。** 在任务收尾后跑一次提取，而不是每轮都提：提取候选记忆 → 与现有字段比对 → 合并或新增 → 打时间戳。合并时保留旧值做版本记录，方便回滚。注意**负向偏好**（"别再给我表格"）也要记，这类信息最容易被漏。

**第三步：分层注入。** system prompt 只放核心画像，控制在几百 token 内；细节记忆封装成一个 MCP 工具（比如 `memory.search`），Agent 拿不准时按需查询。注入是"目录"，检索才是"正文"。

**第四步：遗忘机制。** 每条记忆带 TTL 和命中计数，长期不命中且过期的条目自动降权归档。过期记忆比没有记忆更危险。

## 踩坑点

- **只追加不合并**：早期我的 memory.md 一周长到几千字，"喜欢简洁"和"要详细解释"同时存在，Agent 随机选一个。合并逻辑必须一开始就做。
- **提取太频繁**：每轮都提取会产生大量噪音（"用户今天问了天气"）。绑定在任务完成后批量提取，噪音少一大半。
- **敏感信息入库**：有次把临时 token 记进了画像文件。现在写入前过一道敏感模式过滤（key/token/password），宁可漏记。
- **置信度缺失**：用户随口一句"以后都用 Go"被当成永久偏好。低置信度记忆先标记，复现两次再转正，比直接写入稳。

## 可复用建议

1. 记忆用人类可读格式，用户能直接看和改——可审查性是信任的基础；
2. 读写做成独立 MCP 工具，而不是写死在 prompt 里，方便单独测试和回归；
3. 建一个小的跨会话测试集（10 条"上周说过 X，这周应记得 X"），每次改记忆逻辑后跑一遍；
4. 从 5 个核心字段起步，跑两周看命中率再扩展，不要一上来设计 20 个字段。

## 总结

Agent 记忆系统的核心不是"多记"，而是记对、会更新、会遗忘、能检索。结构化画像 + 分层注入 + 遗忘机制，比一个单纯的大向量库实用得多。先让最核心的 5 个偏好稳定生效，再谈更复杂的情景记忆，这条路走通的概率最高。
