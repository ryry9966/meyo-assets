## 背景

用 OpenClaw 做多步任务编排时，最常见的结构是：主会话负责拆解目标、协调进度，把检索、批量处理、长文档分析这类"重活"交给子 Agent。早期我们图省事，直接让子 Agent 复用主会话上下文启动，跑了一阵才意识到代价。

## 问题

主会话明显"变笨"了：

- 子 Agent 的中间产物——工具调用日志、网页抓取片段、失败重试记录——全部堆进主会话历史，token 消耗翻倍，关键指令被稀释；
- 子 Agent 测试期的错误结论残留在会话里，后续轮次被当成既定事实反复引用；
- 共享的 memory 文件被子 Agent 覆盖，主会话积累的用户偏好直接丢了。

本质上这不是模型问题，是会话边界没划清。

## 做法

现在团队约定三条硬规则：

1. **子 Agent 一律开隔离 session**。spawn 时显式声明独立上下文，不继承主会话历史，只带最小化系统提示。
2. **用任务简报传参，不用上下文继承**。给子 Agent 的输入收敛为四项：目标、约束、输入文件路径、期望输出格式。它需要什么就传什么，宁少勿多。
3. **结果结构化回收，细节落盘**。子 Agent 返回固定结构：一行结论 + 关键数据 + 产物路径。完整中间过程写到自己的工作目录（如 `workspace/tasks/<task_id>/`），主会话只拿摘要，需要时按路径回查。

两个配套动作：按 Agent 过滤 MCP 工具，子 Agent 只挂载它声明要用的工具；spawn 深度限制一层，禁止子 Agent 再开子 Agent。

## 踩坑点

- **摘要过狠**：只回一句"已完成"，出错后无法定位。关键数字和失败原因必须进结构化结果——子 Agent 自己的上下文用完即焚，不留档就等于丢了。
- **工作区互踩**：两个子 Agent 并发写同一个临时文件。现在每个任务强制独立子目录 + 唯一 ID 前缀。
- **系统提示串味**：子 Agent 默认继承主会话口吻和工具偏好，分析类任务跑去调浏览器。最小化提示 + 工具白名单基本解决。
- **异常路径漏隔离**：失败重试最容易把调试信息写回主会话。重试逻辑必须也在隔离 session 内闭环。

## 可复用建议

- 判断标准一句话：这段上下文主会话还需要吗？不需要，就别让它进来。
- "文件是合同，会话是现场"——跨 Agent 传递的一切事实，以落盘为准，不靠记忆。
- 定期审计主会话 token 构成，中间产物占比超过两成，就该回头查隔离配置了。

## 总结

会话隔离的核心不是省 token，而是保证主会话里只有决策需要的信息。子 Agent 是外包工人：交付摘要和工件，不留生活垃圾。边界划清之后，长任务的稳定性提升非常直接——至少我们不用再每周手工清理被污染的会话了。
