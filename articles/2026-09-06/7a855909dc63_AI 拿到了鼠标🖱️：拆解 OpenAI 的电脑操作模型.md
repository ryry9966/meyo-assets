2025 年 1 月，OpenAI 发布了一款叫 **Operator** 的产品，底层是一个名为 **CUA（Computer-Using Agent，计算机使用智能体）** 的新模型。它和 ChatGPT 的区别一句话就能说清：以前的 AI 只能"说"，现在的 AI 能"动手"——自己看屏幕、自己移动虚拟鼠标、自己点按钮、敲键盘，把网页操作从头跑到尾。这条热搜能爆，是因为它戳中了大众想象多年的场景：AI 不再是问答机，而是数字世界的代驾。它到底怎么实现的？靠不靠谱？这篇把它拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/47a7951be3fcdf2c.png)

## 从截图到点击：CUA 是怎么"动手"的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/85f42f1633819bf4.png)

CUA 的核心思路朴素得有点反直觉：**把屏幕当眼睛，把鼠标键盘当手**，像人一样使用图形界面。

- **感知**：模型以纯视觉方式接收屏幕截图，靠像素理解界面——按钮在哪、输入框在哪、下拉菜单展开没有。
- **决策**：基于 GPT-4o 的多模态底座，把"当前截图 + 任务目标"放在一起推理，得出下一步动作。
- **执行**：输出结构化指令，例如"移动鼠标到某坐标并单击""在输入框键入文本""滚动页面""按快捷键"。
- **闭环**：每执行一步就截一张新图，观察变化、修正计划，循环往复，直到任务完成或需要人工介入。

训练方式值得一提：OpenAI 用强化学习让模型在浏览器沙盒里反复试错，同时混入人类演示操作电脑的数据。成绩单是实打实的——在测试真实软件操作的 **OSWorld** 基准上，CUA 拿到 **38.1%**，接近此前约 15% 最好水平的两倍；网页任务基准 **WebVoyager** 上达到 **87%**，**WebArena** 上为 **58.1%**。当然，对照人类约 72% 的 OSWorld 水平，它还没到"超人"阶段。另外，Anthropic 早在 2024 年 10 月就推出了类似的 computer use 能力，OpenAI 这一步是把话题真正推向了大众。

## 为什么放着 API 不用，偏要"看屏幕"

工程师的第一反应多半是：操作软件不走 API，反而模拟点击，这不是绕远路吗？恰恰相反，这正是这个方向的价值所在。

1. **界面是通用接口**。世界上绝大多数软件、老系统、内网工具没有开放 API，或文档残缺。图形界面才是全人类共有的"标准接口"——只要人会操作，AI 就能操作。
2. **RPA 的前车之鉴**。传统 RPA（机器人流程自动化）工具靠录制固定坐标和规则工作，页面一改版就全线崩掉，维护成本极高。CUA 理解界面语义，按钮挪个位置照样找得到，鲁棒性高一个量级。
3. **长尾任务的经济学**。为一个每周只用三次的内部系统写集成，性价比极低；让通用 agent 直接上手，边际成本趋近于零。

一句话总结：这是"用单点速度换通用覆盖"的取舍——慢一点，但几乎什么都能干。

## 实力与短板：一份不太客气的成绩单

别被热搜带节奏，目前的 CUA 是个偏科生。

**擅长的事：**
- 重复性网页任务：填表、订位、比价、批量整理信息；
- 串接多个互不相通的网站，比如"在这三家店各查一次库存再汇总给我"；
- 操作那些没有 API 的遗留系统。

**明显的短板：**
- **慢**：单步动作要几秒到十几秒，手速远不如你；
- **错误会累积**：假设单步成功率 90%，连续 10 步全对只剩约 35%，长任务容易半路翻车；
- **会认输**：遇到验证码会主动停下来交还人类——这是设计使然，不是 bug；
- **场景局限**：Operator 初期跑在 OpenAI 云端的虚拟浏览器里，并非接管你的本地电脑，桌面级软件仍是弱项。

## 把键盘交给 AI 之前，先过一遍风险清单

能力越通用的 agent，安全面越复杂，这不是危言耸听：

- **Prompt injection（提示注入）**：恶意网页可以在页面内容里埋"指令"，诱导 agent 误操作，比如把"点击这个链接下单"伪装成正常文案。这是目前学术界和 OpenAI 重点防御的方向。
- **不可逆操作**：转账、删除、群发邮件，出错没有撤销键。Operator 的对策是 **watch mode**——碰到密码输入、支付环节强制交还人类确认。
- **权限边界**：agent 要靠登录态干活，意味着它能访问账号上下文，权限隔离、操作日志、行为回放必须跟上。
- **责任归属**：agent 下错单算谁的？平台条款和法规都还在补课。

## 三条冷思考：怎么用才不踩坑

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/b2a281181cfc290e.png)

1. **把它当实习生，别当全托管**。交给它"高频、低风险、可撤销"的任务（填表、订餐、比价），把不可逆、涉及钱和隐私的操作留在自己手里。判断标准一句话：这件事做错了，我能不能五分钟内挽回？不能就别托管。
2. **自己测失败模式，别只看演示**。官方演示永远挑成功案例，真实价值要看长尾任务的成功率和翻车后的自救能力。设计几个"刁钻但真实"的任务跑一轮，比任何宣传片都准。
3. **从业者请抢跑"编排层"**。RPA、自动化测试、爬虫岗位会被重塑，但"把模糊需求翻译成可验证任务、并验收结果"的能力短期无法替代。工具会换，问题定义能力永远是稀缺品。

从 1966 年只会打字聊天的 ELIZA 到 ChatGPT，人类用了五十六年；从聊天到"会用鼠标"，只用了两年多。下一次热搜，也许就是几个 agent 互相协作替我们开会——但愿它们记会议纪要比人类靠谱。
