最近一条新闻在技术圈刷屏：据 36kr 等媒体报道，一位独立开发者靠一个人、一只鼠标，在 42 天里击退了 3103 个 OpenAI 智能体的连续"围攻"。评论区分成两派，一派喊"人类防线万岁"，一派说"这不就是爬虫大战的续集"。情绪先放一边——这个案例真正值钱的地方，是它把三件事同时摆上了台面：AI agent 的攻击长什么样、当代 Web 防御的工具箱里有什么、人机分工的真实边界在哪。下面逐个拆。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/6be68f6f429af30c.png)

## 3103 个智能体，到底是个什么阵仗

先纠正一个直觉：这 3103 个"智能体"，大概率不是 3103 台黑客机器，而是 3103 个 agent 会话实例。

- **传统爬虫**：按固定规则抓 HTML，带上 User-Agent（比如 Googlebot），请求—响应，节奏机械，特征明显。
- **浏览器 agent**（如 OpenAI 2025 年推出的 Operator、ChatGPT Agent）：在云端虚拟浏览器里真实渲染页面，"看"截图、移动光标、点按钮、填表单，行为层面像一个远程真人。
- **数量为什么能堆到 3103**：agent 是任务导向的，一个任务失败会自动重试、换路径、再开新会话；如果目标是"在某个网站上完成某件事"，编排系统很可能把它并行拆成大量子任务。42 天持续轰击，说明对面不是单点攻击者，而是一套带重试和调度机制的自动化作业流。

打个比方：传统爬虫像按图索骥的快递员，agent 像一万个自己会找路的实习生——执行力参差，但耐心像永动机。

## 为什么小网站成了主战场

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/97c85afa467ee5aa.png)

agent 时代的流量有个新特征：**目标导向导致流量极度集中**。

- 人类用户逛网站是发散的：首页 → 分类 → 乱点 → 走人；agent 是收敛的，它只对"完成任务必需的那个页面"感兴趣，会把请求精准砸在同一个入口上。
- 大站有 CDN、WAF 和安全团队兜底；小站往往就是一台服务器加一个兼职运维。同样的请求量，落在小站上就是生死问题。
- 这不是孤例。2025 年以来类似剧情密集上演：维基类站点和开源社区纷纷报告带宽被 AI 抓取流量打爆；工程师 Xe Iaso 的反爬工具 Anubis 一夜走红——它要求客户端先完成一段计算量的 proof-of-work 才放行；Cloudflare 则推出 AI Labyrinth，用 AI 生成的诱饵页面把爬虫引进"迷宫"里空耗。多家基础设施厂商的报告都指向同一结论：AI 相关抓取流量在一年内出现了数量级增长。

## "一只鼠标"能赢，靠的不是手速

很多人被"一只鼠标"的叙事带偏，以为他在和 3103 个 agent 比 APM。真实情况更接近：**人当规则引擎，机器当执行器**。

1. **热更新规则**。人扫一眼日志就能发现"这条路径的请求节奏不像人"，写一条拦截规则、点击生效，整个回路几分钟；而攻击侧要调整 agent 策略，得改 prompt、改编排、重跑任务。攻防的迭代节奏根本不对称。
2. **语义级判断**。行为指纹——请求间隔分布、header 组合、cookie 链路一致性——在规则引擎里要穷举，在人眼里是一眼假。人类擅长的恰恰是"没见过也能判断不对劲"。
3. **引导式消耗**。高段位防守不是硬拦，而是把 agent 引进 tarpit（无限迷宫）、蜜罐路由，让它拿着预算在"看起来有用、其实在绕圈"的页面森林里空转，直到任务超时。
4. **成本不对称**。agent 每开一个会话都在烧 token 和浏览器算力；防守方一条 iptables 规则，成本约等于一杯白开水。42 天打下来，账面消耗比是悬殊的。

所以"一只鼠标"是个精确的隐喻：鼠标不是武器，是控制台。点击一下，生效一条规则。

## 攻防背后，是两本对不上的账



这场拉锯战的根因，是双方的成本收益模型对不上。

- **AI 侧**：agentic browsing 是明确的战略方向，2025 年 Operator、ChatGPT Agent 先后上线。产品要跑起来，就需要海量真实网页交互来验证能力边界——这场围攻本身，某种程度上也是一次大规模压力测试。
- **内容方侧**：小站的收入（广告、订阅、捐赠）按"人类访问"计价，而 agent 带来的是纯消耗：带宽、CPU、数据库查询，一分钱收入不产生。投入产出为负，关门是最理性选择。
- **行业的中间路线**：Cloudflare 已试点 pay-per-crawl（爬虫付费抓取），多家内容方开始与 AI 公司签授权协议。方向很清晰——把"抓与不抓"的二元对抗，升级为"身份认证 + 计费"的市场机制。

负面外溢也很真实：如果小站默认对 agent 关门，agent 能看到的开放网会越来越窄，反过来损害 AI 产品自身。这是个典型的博弈困局。

## 写给站长和开发者的三张牌

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/fc89bf62a1af4974.png)

1. **先分层，别一刀切**。最低配防御三件套：速率限制（rate limit）、按 UA/ASN 识别大流量来源、对"高消耗低价值"路径（站内搜索、翻页、批量列表）加质询——轻量 proof-of-work 或验证码，成本极低，劝退效果显著。
2. **学会看 agent 的"身份证"**。合规的官方爬虫通常有公开 UA 标识并遵守 robots.txt，可以走授权通道给差异化待遇；无头浏览器伪装成真人的，直接送进质询队列。判断成本五分钟，收益按月计。
3. **冷思考：防御的终点是抬高对方成本，不是绝对安全**。长期解在协议层——身份、授权、计费。个人英雄主义注定是过渡态，但恰恰是这些"一个人守 42 天"的样本，在替整个行业实测 agent 的真实边界。向守门员致敬，但别指望人人都去当守门员。

## 写在最后



这则新闻最动人的地方，不是"人赢了 AI"，而是它演示了一种成熟的姿态：不恐慌、不投降，用工程方法把一个看似科幻的对局，拆成日志、规则和成本账。AI agent 会越来越强，这几乎没有悬念；但"判断下一步该拦谁"这件事，短期内仍然是人的一杯咖啡、一只鼠标的事。
