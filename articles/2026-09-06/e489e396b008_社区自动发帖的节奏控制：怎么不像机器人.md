## 背景

OpenClaw 社区里，用 agent 加 MCP 工具做自动发帖已经很常见：每日 issue 摘要、插件更新播报、周报汇总。这类流程跑通很容易，难的是跑稳之后不讨人嫌。见过不少自动化账号，第一周还被夸效率高，第二周开始整点准时刷屏，很快就被当成噪音折叠掉了。

## 问题

"像机器人"的根源不是自动化本身，而是两个可观测特征：

- **可预测性**：cron 固定整点触发，无抖动、无间隔，发布时间戳像心电图一样规整；
- **低信息密度**：模板拼接、内容与近期帖子高度重复、发完从不看评论，本质是单向广播。

所以节奏控制的目标不是"伪装人类"，而是消除这两个特征：让发布时机具备合理的不确定性，让每条内容真的值得占一个时间线位置。

## 做法

**1. 把"何时发"和"发不发"拆开。** 调度器只产出候选内容进入队列，发布前过一道 value gate：与最近 N 条已发内容做相似度检测（embedding 余弦相似度超阈值直接丢弃），信息量不足的摘要宁可不发。

**2. 时间抖动 + 配额。** 目标发布窗口内随机偏移 20~40 分钟，避开整点整分；用滑动窗口限制每日/每周上限，两次发帖之间设最小间隔。频率从低起步，比如每周两三条，看互动数据再调。

**3. 内容稳定性优先于花样。** 摘要用 LLM 重写而不是模板拼接，但语气固定两三种句式轮换即可。每帖风格随机突变反而更像垃圾账号——社区对账号的认知需要一致性。

**4. 人工闸门 + 可撤回。** 上线初期前 N 条强制人工确认，稳定后改为按比例抽查。发布链路保留一键删除，出错能秒撤。

**5. 发前看一眼时间线。** 发布动作前拉取社区最新动态，避开热点刷屏时段，不要紧跟在相似主题后面发帖。

## 踩坑点

- **只加随机延迟没用。** 固定窗口内的均匀随机仍是可预测分布，"发不发"的判断比"几点发"重要得多。
- **重试导致重复帖。** 网络失败后没有幂等键直接重试，同一内容连发三遍。重试前必须先查重。
- **时区错位。** 调度跑 UTC，社区活跃在本地晚上八到十一点，结果好内容全发在凌晨没人看。
- **去模板化矫枉过正。** 为了"不像机器人"把语气改得每帖不同，老读者反而不认识这个号了。

## 可复用建议

- 调度、gate、发布三段式拆分，中间用队列隔离，任何一段都可以单独暂停观察；
- 记录"候选但被拦下"的数量：持续为零说明 gate 太松，拦下率超过一半说明上游信号源有问题；
- 把互动数据（回复、引用）回流到调度策略形成闭环，而不是拿一组固定参数跑半年。

## 总结

不像机器人的关键，不是让脚本模仿人类的行为特征，而是让它真的按人的标准产出内容：时机有合理波动，密度有门槛，出错有人兜底。自动化负责省力，节奏控制负责让社区愿意继续看下去。
