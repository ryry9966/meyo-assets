# 社区自动发帖的节奏控制：怎么不像机器人

## 背景

OpenClaw 接上 MCP 工具或社区插件后，让 Agent 定时往论坛、频道发内容的成本已经低到写个调度脚本就能跑。但跑过一段时间的人大多遇到过同一个问题：账号活跃曲线是标准锯齿波，发言间隔精确到秒，很快会被管理员或眼尖的社区成员盯上。自动化本身不是问题，问题在于**节奏暴露了它**。

## 问题：固定节奏就是指纹

人的发帖行为有三个特征：有活跃时段（本地时间白天密集、深夜沉寂）、有会话性（一段时间内连发几条然后消失几小时）、有不规则性（间隔方差大，但不是均匀随机）。多数自动化脚本恰好三项全反：24 小时均匀触发、单发单停、间隔要么固定要么均匀随机。这些特征叠加，不需要任何检测工具，肉眼翻两页历史就能看出来。

## 做法：四层节奏控制

我在自己的发帖 Agent 里拆了四层：

**1. 排程层：加权抖动。** 不要 `0 */2 * * *` 式的整点触发。按账号本地时间生成权重曲线（工作日上午、午后高，深夜趋近 0），触发时加非均匀抖动，比如以目标时刻为中心的高斯抖动，标准差 15–40 分钟。

**2. 会话层：聚簇与静默。** 维护一个"在线窗口"状态：以 60%–85% 概率延续当前会话（10–40 分钟内再发 1–2 条），会话结束后进入 2–5 小时静默。一天通常只产生 2–4 个会话，而不是十几个孤立时间点。

**3. 内容层：去模板化。** 相同的段落结构、固定的开头句式和署名后缀，比时间规律更容易被认出来。把生成 prompt 里的格式约束松开，允许长度、语气、是否带列表有变化；同一主题 48 小时内不二次发言。

**4. 触发层：回复延迟。** 被 @ 后秒回是最大的红旗。给触发型回复加 3–15 分钟延迟，同一小时内触发回复设上限（比如 3 条）。

另外必须有熔断：连续 N 次发帖零互动、或出现负反馈，自动降频甚至暂停 24 小时。参数建议显式化成配置：

```yaml
cadence:
  daily_cap: 5
  jitter: { type: gaussian, sigma_minutes: [15, 40] }
  session: { continue_prob: 0.7, gap_minutes: [120, 300] }
  reply_delay_minutes: [3, 15]
  breaker: { zero_engagement_threshold: 5, cooldown_hours: 24 }
```

## 踩坑点

- **均匀随机 ≠ 像人。** 在固定窗口里取随机数，长期看间隔分布还是平的，必须按时段加权。
- **重试导致重复发帖。** 网络失败后的重试逻辑如果不去重，一次事故连发三四条相同内容，比规律发帖更扎眼。发帖前先查自己最近历史。
- **时区错位。** 服务器在 UTC、账号画像在东八区，结果"深夜三点"高频活跃，一眼假。所有时间决策用账号所在时区。
- **只控节奏不控量。** 节奏再像人，日均 30 条也不像人。先定总量上限（我设每天 ≤5 条），节奏控制才有意义。

## 可复用建议

1. 节奏参数全部进配置，不散落在代码里，方便审计与灰度调整。
2. 每次发帖记录：计划时间、实际时间、触发来源、会话 ID。跑一周后把自己的发帖时间序列画出来，和真人账号对比，比任何理论都直观。
3. 上线前自问：遮住头像和昵称，管理员翻历史时，会把它当成一个"有点话痨的真人"吗？

## 总结

节奏控制的目的不是骗过谁，而是让自动化成为社区里一个低打扰、可预期的参与者。频率克制、时段合理、内容不重样、触发不秒回——做到这四点，大部分"机器人感"就消失了，剩下的靠熔断和持续观察补齐。自动化越便宜，克制越值钱。
