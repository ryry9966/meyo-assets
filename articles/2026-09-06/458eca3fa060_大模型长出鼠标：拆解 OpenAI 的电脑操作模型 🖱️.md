2025 年 1 月，OpenAI 上线了一款叫 Operator 的产品，藏在背后的是代号 CUA（Computer-Using Agent，计算机操作智能体）的新模型。它不接 API、不做专门适配，而是像人类用户一样：看屏幕、移光标、点按钮、填表单，一步步把活干完。这是 AI 从「能聊天」走向「能动手」的标志性一步。这篇就把它的原理、成绩单、短板和落地方向一次讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/4ce44f0562674884.png)

## 先搞清楚：它到底是什么

- **发布节奏**：Operator 于 2025 年 1 月率先向美国 ChatGPT Pro（200 美元/月）订阅用户开放，核心引擎就是 CUA 模型
- **技术底座**：以 GPT-4o 的视觉能力为基础，再用大规模强化学习训练出「看屏 → 操作」的策略
- **同一赛道**：Anthropic 在 2024 年 10 月率先放出 computer use 能力，Google 的 Project Mariner 也在路上。GUI agent 是各家共同押注的方向
- **一句话定义**：CUA 是一个「把屏幕像素当输入、把鼠标键盘动作当输出」的多模态 agent

它和普通对话模型的区别可以这么理解：ChatGPT 输出的是 token，CUA 输出的是坐标和键盘事件。

## 工作原理：截屏 → 思考 → 点击的闭环

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/209b9f5eaf00ab3c.png)

CUA 的执行流程是一条标准的感知-决策-行动循环：

1. **感知**：在 OpenAI 托管的虚拟浏览器里加载页面，模型对当前屏幕做视觉理解，识别按钮、输入框、菜单的位置和语义
2. **决策**：结合任务目标（比如「把这批订单录入系统」），推理出下一步最合理的动作
3. **行动**：生成具体操作——`click(x, y)`、`type("...")`、`scroll`，交给执行层去真实点击
4. **反馈**：截取新屏幕，回到第 1 步，直到任务完成或触发人工确认

关键在感知这一环：它看到的是**像素**，不是 DOM 也不是 API。这带来一个质变——只要人能用图形界面操作的软件，它理论上就能操作，包括那些没有接口、界面十年没改过的企业遗留系统（legacy software）。

工程层面也有兜底设计：

- 不可逆操作（付款、发邮件）必须人工确认
- 登录和密码输入由用户接管，模型不碰密码
- 银行等敏感站点直接拒绝服务
- 提供 watch mode，让用户全程盯着它干活

## 为什么「会点鼠标」是大新闻：自动化的最后一公里

过去十年，办公自动化基本两条路，各有各的脆：

- **RPA**（机器人流程自动化，UiPath、影刀这类）：靠录制脚本、按坐标点击。网页改一个按钮位置，整套流程报废，维护成本高到怀疑人生
- **API 集成**：稳定，但前提是对方开放接口。现实中大量软件根本没有像样的 API

LLM 视觉模型恰好补上空档：它靠**语义**理解界面，按钮挪了照样认得，用模糊匹配替代了精确坐标。于是自动化第一次能覆盖长尾场景——订机票、填报销单、跨系统比价、招聘网站筛简历，这些以前「不值得写脚本」的活，现在一句话就能委派。

打个比方：API 是高铁专线，快，但只到修了站的地方；GUI agent 是会看路面的司机，路修到哪儿就能开到哪儿。GUI 是人类数字化世界事实上的通用接口，谁掌握了它，谁就拿到了自动化的万能钥匙。

## 成绩单与短板：数字不会说谎



热度归热度，先看公开基准：

- **OSWorld**（真实操作系统任务）：CUA 拿到 38.1%，人类约 72%
- **WebArena**（模拟真实网站）：58.1%（多次尝试取最好成绩）
- **WebVoyager**（网页任务）：约 87%，但任务相对简单直接

短板也要一个不落地列出来：

- **慢**：每一步都要截图-推理，十几步的任务动辄几分钟，人早干完了
- **会错**：点错按钮、填错字段、陷入死循环都发生过，关键流程里一次误点代价可能很高
- **贵**：每次截屏都是一次多模态推理，长任务的 token 消耗非常可观
- **被挡**：验证码等反自动化机制天然针对这类 agent，该拦就拦

所以现阶段的准确定位是：低风险 + 高重复 + 有人兜底的任务交给它，高风险任务它当助手、你来把关。

## 安全这根弦：网页本身就是不可信输入

CUA 类产品有一个绕不开的软肋：模型「看」的网页内容，本身就是它的输入。恶意页面可以在图片或隐藏元素里塞入指令，诱导 agent 执行非授权操作——这就是提示注入（prompt injection），对一个以截图为食的模型尤其致命。

OpenAI 的缓解手段包括虚拟浏览器沙箱隔离、敏感站点黑名单、不可逆操作强制确认、监视模式。但研究社区的攻防一直在拉锯，没有一劳永逸的方案。企业落地还要多问一句：截图里的商业数据流向了哪里、是否符合数据合规要求——这是采购决策里比准确率更先要过的一关。

## 三条冷思考：怎么用、怎么判断、怎么看

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-06/ae45ea8eb707333e.png)

1. **给任务分级再委派**：用「可逆性 × 出错代价 × 执行频率」三个维度打分。高频、可逆、规则清晰的活（填表、汇总、比价）先交出去；涉及支付、发送、删除的，无论宣传多智能，都保留人工确认
2. **把它当实习生，别当员工**：38% 对 72% 的差距说明它今天是 copilot 不是 autopilot。开着监视模式让它干活，错了随时接管，等成熟度上来再逐步放手
3. **看懂范式比追产品更重要**：方向是从「人类学软件操作」转向「AI 学人类操作」。长期看这会反过来影响软件设计——未来产品可能同时为人和 agent 留门，MCP、agent 协议这些基础设施正在补位。对开发者来说，现在研究 agent 与 GUI 的交互协议，是提前占位

## 写在最后



AI 拿到鼠标和键盘之后，自动化的边界从「有 API 的世界」扩展到了「有人机界面的世界」。这条边界还能推多远，取决于模型可靠性、安全攻防和成本曲线三条线的斜率。最务实的姿势是：小场景先试水，大权限后放手，让数字实习生在你的监督下慢慢转正。
