## 背景

需求很朴素：社区有几个固定栏目（每周精选、问题汇总），人工发帖重复度高。目标是用 OpenClaw Agent + MCP 工具链做一个发帖机器人，实现"定时产出草稿、审核后自动发布"，而不是完全无人值守——这点后面会反复出现，它救了我好几次。

## 整体架构

四层结构：

1. **触发层**：cron 定时任务 + 事件触发（RSS / 仓库更新）。触发只负责投递消息，不做业务逻辑。
2. **生成层**：Agent 拉取素材源（网页抓取工具、本地笔记库），按版本化的 prompt 模板生成帖子正文。
3. **护栏层**：语义去重（embedding 相似度阈值）、链接可访问性校验、dry-run 模式（只写本地 Markdown，不调用发帖 API）。
4. **动作层**：发帖 API 封装成 MCP 工具，带幂等键；发布后把状态回执写入本地状态库。

关键决策是**生成与发布解耦**：Agent 只产出"待发布对象"，发布由独立脚本消费队列完成。Agent 挂了不影响已入队内容，反之亦然。

## 实施步骤

1. 先手写 5 篇目标栏目的帖子，提炼结构模板（标题句式、段落结构、标签规范）。
2. 把发帖 API 包成 MCP 工具，参数收敛为 title / body / tags 三个字段，多余能力一律不暴露。
3. Agent 侧跑 dry-run，产出落盘 Markdown，人工比对一周。
4. 加护栏：语义去重、链接校验、单日发布上限。
5. 上线"人工审批队列"：草稿推送到 IM，回复确认才发布。
6. 稳定运行一个月后再考虑放宽到全自动，目前仍保留每日上限。

## 踩坑实录

- **时区坑**：cron 按 UTC 跑，首发时间差了 8 小时。此后定时任务一律显式声明时区。
- **语义重复**：关键词去重挡不住"换个说法的旧帖"，换成 embedding 余弦相似度，阈值 0.85，误杀率可接受。
- **幻觉链接**：模型早期会编造参考链接。现在所有外链必须来自抓取工具的原始输出，prompt 里明确"不得新增 URL"。
- **上下文膨胀**：一开始把历史帖全塞进上下文做"风格学习"，成本翻倍收益为零。改为 3 篇精选样例 + 结构模板。
- **凭证过期**：社区 API 的 access token 半天过期一次，裸奔的重试逻辑导致静默失败。补了刷新机制和告警。
- **静默失败最危险**：队列消费失败如果没有回执，表面上一切正常。现在的原则是"失败必通知"，宁多勿漏。

## 可复用建议

1. **永远从 dry-run 开始**，先看产出质量，再谈自动化程度。
2. **发布动作做幂等**，同一任务重跑不会发双帖。
3. **prompt 当代码管理**，改动走版本记录，出问题能回滚。
4. **保留人工闸门**，全自动是结果，不是起点。
5. **监控发布回执**，没有回执的自动化等于盲飞。

## 总结

这个项目工程量不大，真正的难点在护栏和可观测性。Agent 生成内容的质量波动是常态，架构设计的目标不是消除波动，而是保证波动不会演变成事故。先半自动、后全自动，是我给所有想复刻的同学的建议。欢迎在评论区交流你们的护栏方案。
