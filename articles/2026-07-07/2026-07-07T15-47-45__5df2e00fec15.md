最近，36kr发布了19省份2023年平均工资的报道，评论区立刻两极分化——有人说“又拖后腿了”，有人质疑“这数据怎么算的”。RY哥翻了各省统计局的原始公报，发现这组数据背后藏着一堆统计学的小心思和劳动经济学的大逻辑。今天不灌鸡汤，不贩卖焦虑，纯从数据和原理角度，把“平均工资”这件事掰开揉碎讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-07/f6f596e2d484f16c.png)

## 一、“平均”二字里的统计学陷阱

先补一节统计课。各省公布的“平均工资”全称是“城镇非私营单位就业人员年平均工资”，这里头至少有三个容易被忽略的细节：

1. **统计口径**：只覆盖“非私营单位”，即国企、事业单位、外企和规模以上民企。大量个体户、灵活就业者、小微企业员工不在统计范围内。这个筛子相当于在 SQL 里加了个 WHERE 条件，直接把底部海量数据过滤掉了，所以这个“平均”天然偏高。
2. **均值 vs 中位数**：公报里用的是算术平均数（mean），而非中位数（median）。在收入分布右偏的情况下，均值一定大于中位数。举个简化例子：一个房间里有9个人月薪5000元，第10个人月薪50000元，均值是9500元，中位数是5000元——均值是中位数的1.9倍。这就像你用 `Array.average()` 算全班成绩，被那个考满分的大佬直接拉高了一个标准差。mean 天生对极端值敏感。
3. **税前工资**：公布的是税前应发工资，包含社保公积金个人缴纳部分。到手大概打个七到八折。

所以当你看到某省平均月薪8000元时，实际对应的“到手中位数”可能只有5500-6000元。这不是数据造假，而是口径差异造成的认知偏差。

## 二、撑起天花板的行业密码

各省数据里都附一张分行业平均工资表，这里才是真正的“信息金矿”。拉通19个省份的数据，撑起薪酬天花板的行业高度集中：

1. **信息传输、软件和信息技术服务业（IT业）**：连续多年稳居各行业第一，多数省份年均工资在20-28万元区间。原因不复杂——这个行业的人力资本密度极高，且产出的边际成本递减（软件写一份卖无数次），企业愿意用高薪抢人。
2. **金融业**：传统高薪大户，年均普遍在15-25万元。但要注意，金融业内部分化极大——总部投行/资管岗位和基层网点柜员，收入可能差5-10倍。平均数在这里就像用一个 color picker 取整张渐变图的中间色，掩盖了内部的剧烈撕裂。
3. **科学研究和技术服务业**：随着研发投入持续增长，薪资水涨船高，年均在15-22万元。尤其在大科学装置和国家级实验室密集的省份，这个数字更高。

反过来，垫底的通常是住宿餐饮业、居民服务业和农林牧渔业，年均多在4-7万元。最高与最低行业之间的差距，普遍在3-4倍。这个倍数在经济学上叫“行业工资溢价”，反映的不是“谁更努力”，而是行业的技术壁垒、资本密集度和劳动力议价能力的综合差异。就像选编程语言一样，赛道本身的红利，往往大于个人努力的增量。

## 三、城市能级与薪酬的耦合关系

把19个省份的数据按地理分布铺开，会发现一个清晰的梯度：

- **第一梯队（京沪）**：北京和上海作为直辖市，平均工资显著领先，年均多在20万元以上。这两个城市集中了大量总部经济、金融机构和科技巨头，高薪岗位密度极高。
- **第二梯队（东部沿海）**：浙江、江苏、广东紧随其后，年均在12-16万元。制造业基础雄厚，民营经济活跃，规模以上民企的薪资拉高了整体水平。
- **第三梯队（中西部）**：河南、四川、湖北等省份年均在9-13万元。这些省份虽有强省会（如成都、武汉），但全省非私营单位岗位密度有限，平均数被拉低。
- **第四梯队（东北和部分西部）**：受产业结构和历史路径影响，部分省份年均在8-11万元。

这个梯度的底层逻辑是“产业集聚效应”——高附加值产业向中心城市集中，带动薪酬上行；低附加值产业向外围转移，形成区域间的薪酬断层。这不是某个人“选择”的结果，而是资本和要素流动的系统性规律。就像 Git 的 commit graph，每个分支的走向都有其历史路径依赖，不是一句“努力”就能解释的。

## 四、被“平均”的沉默大多数

每次平均工资公布，评论区都会出现“对不起，我拖后腿了”。从统计学角度看，大约60-70%的劳动者实际收入低于公布的平均数。这不是你的问题，而是右偏分布的数学必然——少数高收入者对均值的拉拽效应，远大于多数中低收入者。

更深层的问题在于，“非私营单位”这个口径本身就过滤掉了超过2亿灵活就业者和个体经营者。如果把这批人纳入统计，均值大概率会下降20-30%。所以你现在看到的“平均工资”，更准确的表述应该是“体制内加大企业的平均工资”，而非“全民平均工资”。

理解这一点，就不会因为“没达到平均线”而产生不必要的自我否定。数据是用来分析趋势的，不是用来丈量个人价值的。这跟性能 benchmark 一样，跑分高不代表你的具体 use case 就快——场景比数字更重要。

## 五、三条冷思考

1. **读数据时先看口径**：下次看到任何“平均工资”新闻，第一步去查原始公报，看统计范围是“非私营”还是“全口径”，是“税前”还是“税后”，是“mean”还是“median”。口径不同，结论天差地别。就像 debug 一样，先确认你看到的数据到底是什么，再谈分析。
2. **选行业比选城市更重要**：数据反复证明，行业间的工资差距（3-4倍）远大于城市间的差距（1.5-2倍）。同样是程序员，在三线城市的 IT 岗位收入可能高于一线城市的传统服务业。赛道选择的杠杆效应，大于地理位置。这跟技术选型一个道理——选对技术栈比选对公司更影响长期发展。
3. **建立个人工资坐标系**：别拿“全省平均”来对标自己，去你所在行业、所在城市、所在岗位层级的招聘平台上搜同岗位薪资区间。用“行业-城市-职级”三维定位法，比一个笼统的省平均数有用得多。统计学告诉我们：样本越聚焦，参考价值越大。就像做用户画像一样，维度越细，洞察越准。
