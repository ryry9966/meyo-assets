“自进化”这个词最近被反复提起，但它并不是新概念。从 AlphaGo 的自我对弈，到 AlphaZero 完全靠规则奖励变强，人类一直想让模型少一点人工标注，多一点自主迭代。今天这轮大模型竞争里，智谱和 DeepSeek 恰好站在两条分叉路径上：一个更偏向让模型在推理时自己修正，另一个更偏向让模型在真实任务与工具反馈中持续迭代。二者目标相近，但训练栈、数据闭环和商业结构几乎对称。把这棵自进化树拆开，能看清的不只是两家公司，而是大模型下一阶段的两个方向。


## 一、自进化的两层含义：推理内修与智能体外求


- 第一层是“推理内修”。模型在训练后继续接触数学题、代码题、逻辑题，这些任务有明确答案或编译器反馈。模型生成多个候选，自动筛掉错误答案，再更新策略。DeepSeek-R1 用的 GRPO 就是典型：不用额外训练一个 critic 网络，而是根据规则奖励对一组采样结果加权，让模型自己出现反思、验证、回溯等行为。
- 为什么这层现在特别有效？因为数学和代码任务可以大规模自动验证。模型一次生成 8 条候选，把编译失败或答案错误的轨迹丢掉，用正确轨迹继续训练。这个循环不需要人工写偏好，适合持续扩展。
- 第二层是“智能体外求”。模型不只输出文本，还要去操作手机、浏览器、API，根据任务成功或失败获得反馈。智谱的 AutoGLM 和 GLM-PC 偏向这条路：把“看屏幕、点按钮、填表单、处理报错”串成闭环。
- 一个直观类比：DeepSeek 像在题库里反复刷卷子的考生，靠参考答案和判卷规则变强；智谱像上岗后靠任务反馈积累经验的员工，靠真实环境里的试错变强。两者没有高下，只是对“自进化”的边界定义不同。

## 二、训练栈分叉：RL优先与多模态对齐


- DeepSeek 的训练栈更偏向语言与推理。以 DeepSeek-V3 为例，采用 MoE、MLA 和 MTP 组合。MoE 每次只激活少量专家，压缩计算量；公开技术报告显示 V3 一次训练成本约 557.6 万美元，显著低于同规模稠密模型。在此基础上，R1 进一步用强化学习放大推理能力。
- MoE 的原理可以简单理解成：模型内部有多个专家子网，每个 token 只激活其中一部分。这样总参数量可以很大，但单次推理计算量不高。MLA 压缩键值缓存，降低长上下文的显存占用；MTP 一次预测多个 token，提升训练效率。
- 智谱的 GLM 系列在多模态和智能体方向投入更多。GLM-4V、GLM-4.5V 以及 AutoGLM 强调视觉理解与操作动作的对齐。模型不仅要看懂界面，还要知道点击、滑动、输入如何改变状态，这对监督信号和奖励设计都不一样。
- 自进化数据的来源因此分叉。DeepSeek 大量依赖可自动判定的任务：数学证明、代码通过率、逻辑题答案，这些可以大规模合成，闭环速度快。智谱更依赖真实交互轨迹：操作步骤、工具调用链、失败恢复路径，这些数据更稀缺，但对 Agent 落地更直接。
- 开源策略也加深了分叉。DeepSeek 开放权重，社区蒸馏、微调、部署都活跃，反向提供大量真实使用反馈和合成数据。智谱也开源部分模型，但更多场景通过开放平台与私有化交付，数据飞轮更贴近企业业务系统。

## 三、工程与商业分叉：低成本创新与平台化落地


- DeepSeek 更像一座研究型实验室。产品层保持极简，核心技术动作是降低推理成本、提高数学与代码能力、把权重放出来。好处是技术外溢极快，小团队可以拿它做垂直应用；代价是场景适配要自己补。例如不少团队会蒸馏 R1 得到小模型，跑在消费级显卡上做代码助手或数学工具。
- 智谱更像 AI 平台公司。从 MaaS 到智能体开发框架，再到企业私有化部署，交付链路更重，但与企业系统绑定更深。客户结构决定了它必须兼容不同硬件栈，尤其是国产芯片生态。这不是单纯的芯片话题，而是一个平台型公司要面对的真实工程约束。
- 推理成本路线不同。DeepSeek 的 MoE 稀疏激活适合云端低成本服务，配合 FP8 训练、量化、蒸馏，边际成本容易被压下去。智谱的多模态和智能体任务常需要更长的上下文、更复杂的工具调用，推理负载结构不一样，优化重点也不同。
- 数据飞轮方向不同。DeepSeek 的飞轮来自社区使用：大量代码调试、自然对话、逻辑问题，配合合成数据回流。智谱的飞轮来自业务流：订单处理、客服操作、报表生成、网页任务，这些数据不性感，但离实际收入更近。
- 如果画成两棵树，一棵向上长在云端和开源生态里，靠推理能力延展；一棵向下扎进业务流程和硬件适配里，靠智能体闭环延展。树冠不同，根系也不同。

三条冷思考：

1. 别神化“自进化”。目前模型仍严重依赖可验证奖励或明确任务指标；在开放域、长链条、目标模糊的任务中，自进化还很脆弱。
2. 选路线先看数据闭环。做代码工具、数学辅导、知识问答，可能更需要 DeepSeek 式推理模型；做电商运营、企业流程自动化、跨 App 操作，可能更需要智谱式 Agent 闭环。
3. 关注推理成本而非只看 benchmark。一个模型再强，如果每次请求都要激活 671B 参数，产品化会很痛苦。MoE、量化、蒸馏、缓存，这些工程细节才是自进化能落地的底座。
