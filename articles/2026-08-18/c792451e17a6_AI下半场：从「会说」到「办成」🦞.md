过去两年，大模型最让人印象深刻的，是“会说话”。写邮件、做摘要、润色文案、模仿语气，几乎到了以假乱真的地步。但一到真正要“做点事”——订一张机票、报销一笔费用、把会议改期、把客服工单真正关闭——AI常常停在“我建议你这样操作”，而不是“我已经办好了”。

这轮讨论把问题点得很准：AI下半场，竞争重点正从“生成文本”转向“完成任务”。用工程圈更直接的话说，就是怎么把 Agent 从 demo 跑成产线。



## 一、先分清：“会说”和“办成”是两条赛道



很多人把“智能”当成一个整体。其实，让模型说一句正确的话，和让系统办成一件事，底层逻辑差别很大。

1. **语言生成是预测，任务是状态变更**  
   大模型生成“建议你改到周四下午”，只需要输出一串概率较高的 token。而“办成”意味着日历里原来的会议时间真的变了，相关人的邀请邮件真的发出去了，冲突真的被检查过。后者改变的是外部世界，不是文字空间。

2. **错误的代价不同**  
   一句话说错，用户可以重问；一件事办错，可能付错款、订错航班、删错文件。所以“会办”的系统必须把可靠性当成一等公民，而不是把“成功率90%”挂在嘴边。

3. **反馈也不同**  
   说话好不好，人类一眼能判断；办事成不成，往往要看数据库、日志、API返回码、最终结果。评估链路完全不一样。

## 二、让AI办事，技术栈其实有三层



把“话”变成“动作”，不是模型更大会自动发生。它至少需要三层能力。

1. **模型层：会调用工具**  
   这层解决“AI能不能听懂工具”。典型能力包括 function calling、tool use、reasoning。模型要根据用户输入，决定调用日历 API 还是支付 API，参数怎么填。现在很多模型都能做，但“能做”不等于“做对”。

2. **编排层：规划、记忆与重试**  
   真实任务往往不止一步。比如“帮我把这周所有和产品组的会改到周四”，需要先查询、再筛选、再逐条修改、最后汇总。编排层要负责拆步骤、记住中间结果、失败后重试、冲突时回退。这是目前最薄弱的一环。

3. **执行层：API、RPA与权限**  
   最后要真正碰系统。有些任务有标准 API，很顺；有些只有老旧的网页后台，就得上 RPA 或 UI 自动化；还有些涉及支付、删除、发送，必须有人工确认和权限边界。

三层缺一层，结果就是“模型很聪明，事情没办成”。

## 三、Agent翻车的五个常见原因



为什么很多 Agent 演示很惊艳，一进真实环境就拉胯？常见原因有五个。

1. **错误累积**  
   假设一个任务需要 10 步，每步准确率 90%，整个流程成功率只有约 35%。长链路下，错误会指数级放大。

2. **上下文稀释**  
   任务越长，中间结果越多，模型越容易忽略关键信息。检索增强、摘要、压缩上下文只能缓解，不能根治。

3. **工具描述脆弱**  
   API 改个字段、文档写得不清楚、返回格式变了，都可能让调用失败。很多“不听话”的 Agent，其实是工具描述本身太烂。

4. **不可逆动作风险高**  
   发邮件、转账、删除数据，一旦执行，回滚成本很高。没有权限分级和人工确认，Agent 就是一个危险的操作员。

5. **成功难以定义**  
   写文章可以看流畅度，办事要看“有没有真正关闭工单”。如果指标还是回答满意度，团队永远不会去优化“办成率”。

## 四、从Demo到产线：把“办成”变成工程问题



好消息是，这些问题不是模型问题，更多是工程问题。做产线化的团队，通常会在四件事上下功夫。

1. **从自由聊天，到约束工作流**  
   不让 Agent 什么都自由发挥。把高频任务拆成固定流程：查询→校验→执行→复核，模型只负责其中“判断”部分，确定性步骤交给脚本。

2. **给系统加“刹车”和“倒挡”**  
   每个关键动作前设 checkpoint，失败可回滚；发外部邮件、转账、删除，必须经过人工 approval。权限采用最小授权，能查就不给写，能草稿就不直接发。

3. **每一步都留痕**  
   保留模型输入、工具调用、返回码、中间状态。出了问题能复盘，也能给模型继续重试提供上下文。没有日志的 Agent，等于没有黑匣子的飞机。

4. **用任务完成率替代答案满意度**  
   核心指标换成：任务完成率、人工接管率、平均完成时长、错误回滚次数。只有这样，团队才会真正围绕“办成”做优化。

## 五、AI下半场，谁更可能把事办成？

答案可能不是“模型最强的那家”。因为光有模型，没有场景、数据和业务闭环，很难把可靠性做起来。

1. **手里有真实流程的企业软件公司**  
   他们最清楚哪些步骤容易出错，哪些动作需要审批，哪些失败可以接受。比如客服、差旅、财务、人力资源这些高频场景。

2. **垂直SaaS和行业服务商**  
   越窄的场景，任务越容易被定义清楚。一个只做电商售后退款的 Agent，比一个“什么都帮你做”的通用 Agent，更容易落地。

3. **把Agent当“实习生”而不是“神话”的团队**  
   先让 AI 处理低风险、可回滚任务，人工做例外。一步步扩大授权，比一上来就追求全自动更靠谱。

## 收尾：三条冷思考

如果你也在考虑从“会说”转“办成”，建议先记住这三条。

1. **先选失败成本低的任务**  
   订会议室、整理资料、生成草稿，比转账、发公告、删除数据更适合作为起点。坏一次，代价可控。

2. **把Agent当实习生，不当神**  
   给它明确指令、限定工具、保留检查点。你愿意让它独立做什么，就只开放什么权限。

3. **重新定义成功**  
   不是“AI回答了”，而是“事情闭环了”。如果看完演示还是只看输出像不像人话，那可能是选错了指标。

AI 下半场不会淘汰所有“会说话”的模型，但真正稀缺的，是能“把事办了”还能“办得稳”的系统。这条路不性感，但值钱。
