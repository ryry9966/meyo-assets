ChatGPT 之后，大家都习惯了大模型“会说”：写周报、回邮件、生成代码注释，甚至假装面试官。但企业真正掏钱时，问的是另一句：“你说得挺漂亮，事办了吗？”订机票、改合同、跑数据、回工单，这些才是 ROI 所在。2023 年 AutoGPT 一度刷屏，用户以为 prompt 一写，AI 就能自己上网订 Pizza，结果常常陷入死循环或乱花钱。这暴露出一个关键 gap：从生成自然语言到完成真实任务，中间隔着一整套工程体系。



## 一、会说 ≠ 办成：两道不同的题

- 会说属于 token prediction。模型根据上下文预测下一个 token，追求语言流畅、语义合理。
- 办成属于 state transition。Agent 要改变外部系统的状态：查库存、写数据库、调支付、发回执。任何一步没闭环，任务就是失败。
- 举例：你让模型“帮我订明天去上海的机票”，它可能给出比价网站链接和操作建议。但真订票需要：查询余票 → 比较价格 → 填入乘机人 → 调用支付 → 接收出票号 → 异常处理。链路里只要一次失败，比如支付超时，就要重试或回滚。
- 所以语言能力是入口，执行能力才是闭环。会说让你愿意试，办成让你愿意付费。

## 二、工程化三件套：规划、工具、记忆



把“说”变成“办”，目前主流做法不是让模型更聪明，而是给它一套外部骨架。三个组件缺一不可：

1. 规划 / 推理  
   - ReAct（Reasoning + Acting）让模型一边想一边做：先输出 thought，再输出 action。  
   - Plan-and-Execute 更稳妥：先拆解目标为子任务，再逐步执行，避免边想边跑偏。  
   - Reflexion 这类框架让模型根据执行反馈自我修正，类似“先复盘再重试”。

2. 工具调用 / Tool Use  
   - 模型不再只输出自然语言，而是输出结构化 JSON，触发外部 API。  
   - 2023 年 OpenAI 提出 Function Calling；2024 年 Anthropic 等推 MCP（Model Context Protocol），试图标准化工具接入。  
   - 工具把“建议”变成“操作”：查询接口、创建工单、写入表格。

3. 记忆 / 状态  
   - 短期上下文保存当前任务进度；长期记忆存用户偏好和历史决策；工作记忆避免重复执行。  
   - 没有记忆，Agent 就像每次醒来都失忆的实习生：反复问同一个问题，或者忘了自己刚才调过哪个 API。

示例：一个智能客服 Agent 的真实链路可能是：解析用户意图 → 调用订单查询 API → 校验退换货规则 → 创建工单 → 回传单号 → 记录状态。每一步都有返回码和失败分支，不是一句“建议您联系人工”就算完。

## 三、三类玩家在抢同一张牌

- 模型厂商：OpenAI 的 Operator/Deep Research、Anthropic 的 Claude computer use、Google 的 Gemini extensions。优势是离模型能力最近，短板是离行业流程远。  
- 中间层 / 框架：LangChain、LlamaIndex、AutoGen、CrewAI、Dify、Coze。把工具编排、记忆、多 Agent 协作封装成低代码模块。优势是灵活，短板是工程深度、安全合规需要自己补。  
- 企业软件 / RPA：Salesforce Agentforce、Microsoft Copilot Studio、UiPath、ServiceNow。把 Agent 嵌入 CRM、ERP、财务、工单系统。优势是懂业务、有权限边界，短板是模型迭代容易被新能力甩开。

格局不是谁取代谁，而是分工：模型厂提供大脑，中间层提供神经，企业软件提供手脚。

## 四、为什么“办成”还是很难

- 可靠性：长链路错误率会累积。每个步骤成功率 90%，10 步后只有约 35%，20 步后约 12%。必须设计校验、重试、回滚和人工兜底。  
- 权限与安全：给模型支付、数据库、邮件发送权限，一旦幻觉或 prompt injection，可能造成真实损失。最小权限原则要成为默认配置。  
- 成本与延迟：复杂任务可能调用 20 次 API，多轮推理 token 消耗大。一次自动报销从秒级变成分钟级，费用也不低。  
- 评测难：对话可以看人类偏好，执行要看任务完成率、副作用、恢复能力。真实环境评测成本高，仿真环境又难覆盖边界 case。

## 五、实用建议：先给 Agent 焊上护栏



1. 选场景先看“失败成本”，而不是“酷炫度”。从失败只影响内部效率、可回滚的流程开始，比如报表生成、工单分类、数据提取；别一上来就碰支付、合同、对外发信。  
2. 权限最小化 + 关键操作人工确认。只读 API 优先；写操作分级审批；删除、支付、群发等敏感动作必须有人点击确认。把 Agent 当实习生，别一入职就给财务章。  
3. 用可验证指标验收。跑通 10 次不算数，至少 100 次；记录任务完成率、单步失败率、平均回滚次数、人工介入率。上线后同样监控，而不是只看演示视频。
