## 背景：Agent 不缺工具，缺的是关于你的上下文

在 OpenClaw、MCP、插件和自动化实践里，很多人会把大量时间花在接工具、调权限、写 workflow 上，但 Agent 仍然经常“不懂你”。

典型表现是：每次新会话都要重新解释“我的时区是 Asia/Shanghai”“我常用 pnpm 而不是 npm”“我的项目在 ~/dev 下”。更麻烦的是个人自动化场景：Agent 帮你处理消息、文件或定时任务时，如果不知道你的身份、环境和边界，就容易给出正确但不适配的建议，甚至误执行危险操作。

USER.md 解决的就是这个问题。它不是高级记忆系统，而是一份每次会话都能加载的“用户说明书”，让 Agent 在开始工作前先知道你的事实、偏好和边界。

## 问题：上下文缺失的代价

没有 USER.md 时，常见问题包括：

- 时区错误：定时任务默认按 UTC，导致通知或任务偏移。
- 环境误判：默认 python 而不是 python3，或者默认 npm 而不是 pnpm。
- 路径混乱：不知道你的工作目录，生成脚本时路径写错。
- 偏好冲突：你希望命令先 dry-run，但 Agent 直接执行。
- 边界模糊：不知道哪些目录、操作或信息不该碰。

这些问题共同点是：不是工具能力不足，而是用户上下文没有在会话开始前被稳定注入。

## 做法：从 30 行开始维护 USER.md

### 1. 确认加载位置

先确认你的 OpenClaw 版本从哪里读取 USER.md。常见位置是 OpenClaw 配置目录下的 `USER.md`，例如用户级配置目录，也可能支持项目级覆盖。不同安装方式路径会有差异，建议先看文档或直接在配置目录创建后验证。

### 2. 写最小可用的 USER.md

我建议用三段式结构：**事实 / 偏好 / 边界**。只放稳定、高复用、每次会话都需要知道的内容。

下面是一个最小示例：

```markdown
# USER.md

## 事实
- 时区：Asia/Shanghai
- 工作语言：zh-CN，可读英文文档
- OS：macOS 14 / Debian 12
- Shell：zsh
- 包管理：pnpm，不用 npm
- 常用目录：~/dev、~/notes

## 偏好
- 代码注释用中文
- 命令默认先 --dry-run 或先说明影响
- 定时任务统一用本地时间，不写 UTC
- 生成脚本时优先用 bash，避免复杂依赖

## 边界
- 不要修改或删除 ~/dev 下任何文件，除非明确要求
- 涉及付款、密钥、内部地址的操作必须先确认
- 不要假装知道我的内部系统，不确定就询问
- 不生成超过 100 行的临时脚本
```

### 3. 验证是否真正加载

创建后启动一次新会话，问几个简单问题：

- “我现在是什么时区？”
- “我默认用什么包管理器？”
- “哪些目录你不能动？”

如果答对，说明加载正常；如果答错，检查文件名大小写、文件位置，以及 OpenClaw 是否在 system prompt 中包含了 USER.md。

### 4. 把纠正写进 USER.md

每次你对 Agent 说“下次别用 npm”“不要默认 UTC”“这个路径不对”时，就顺手把这条追加进 USER.md。这样同类纠正不会反复出现。可以手动编辑，也可以让 Agent 帮你追加，但最终要人工确认。

## 踩坑点

### 1. 写成百科全书

USER.md 超过 150-200 行后，token 消耗上升，关键信息也会被稀释。不要放低价值内容，比如“我喜欢吃什么”“最近在看什么剧”。这些不是 Agent 工作必需上下文。

### 2. 混入可变状态

“今天正在做 X 项目”“本周重点”这类内容不要放 USER.md。它们变化快，应该放项目级 CONTEXT.md 或会话笔记。USER.md 只放相对稳定的事实。

### 3. 明文写入敏感信息

API key、密码、内部 IP、私人地址不要写进 USER.md。它可能被日志、备份或共享会话带走。敏感信息应通过 MCP secret 管理或环境变量注入。

### 4. 多层级配置冲突

如果同时有用户级和项目级 USER.md，指令可能冲突。建议用户级只放通用事实和边界，项目级只补充差异，不要重复定义同样内容。

### 5. 认为一次写好就完事

环境会变，目录会迁移，包管理器会切换。建议定期让 Agent 根据近期纠正生成更新建议，再由你确认合并。

## 可复用建议

- **用只读命令生成环境快照**：`uname -a`、`echo $SHELL`、`which python3`、`date +%Z`，避免手误。
- **控制长度在 40-80 行**：超出就考虑拆分到项目文件或按主题分文件。
- **加版本与更新时间**：在文件头部写 `last_updated`，或直接放进 git 管理，方便回溯。
- **边界用否定句**：模糊表达如“尽量不要动文件”不如“不要修改 ~/dev 下任何文件，除非明确要求”。否定句对 Agent 的执行约束更清晰。
- **避免与插件/MCP 冲突**：如果插件已经定义了工具行为，USER.md 不要再重复“你必须如何调用工具”，只写用户层面的偏好。

## 总结

USER.md 不会让 Agent 变得更聪明，但它能显著减少无效沟通和误判。它适合放每次会话都需要知道的稳定上下文，是 OpenClaw 个人化配置中投入产出比很高的一步。

从一个 30 行的最小版本开始，把每次纠正沉淀进去，比一开始设计复杂记忆体系更实用。
