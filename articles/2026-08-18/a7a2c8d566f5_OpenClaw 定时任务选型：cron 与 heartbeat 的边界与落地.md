# OpenClaw 定时任务选型：cron 与 heartbeat 的边界与落地

在 OpenClaw 里做 Agent 自动化，定时触发是最常见的能力之一。无论是定时拉取数据、巡检插件状态、发送日报，还是做补偿循环，都会碰到两种内置触发器：`cron` 和 `heartbeat`。它们都能让任务“自动跑起来”，但语义完全不同。混用不是不能跑，而是容易在时区、失败重试、任务重叠上埋坑。

这篇文章不讨论哪个更高级，只从工程实践角度讲清楚：什么时候该用 cron，什么时候该用 heartbeat，以及配置时最容易忽略的问题。

## 先理清两种触发语义

`cron` 是日历触发，回答的是“在什么时间点执行”。它有自然日、时区、周几、月几号等概念。典型场景是：

- 每天 09:00 生成前一日的 Agent 使用报告
- 每周一 10:00 汇总 MCP 插件调用量
- 每月 1 日清理过期会话

`heartbeat` 是等间隔脉冲触发，回答的是“每隔多久执行一次”。它不关心现在是几点，也不关心今天几号。典型场景是：

- 每 30 秒检查一次任务队列是否有积压
- 每 5 分钟做一次插件健康巡检
- 每 10 分钟检查一次外部 token 是否即将过期

一句话区分：如果需求里出现“每天/每周/每月/工作日”，优先选 cron；如果需求是“每隔 X 秒/分钟执行一次”，优先选 heartbeat。

## 实践做法

### 1. 先给任务分类

新建自动化任务前，建议先写下两个字段：

- 是否与墙钟时间相关？
- 最小执行间隔是多少？

例如，“每天早上 9 点发日报”明显与墙钟时间相关，用 cron；“每 2 分钟检查一次服务心跳”与具体时间无关，用 heartbeat。

### 2. cron 配置示例

当前 OpenClaw 的 cron 触发器支持时区配置，建议显式声明，不要依赖系统默认时区：

```yaml
tasks:
  daily_report:
    trigger:
      cron: "0 9 * * *"
      timezone: Asia/Shanghai
    action: report_daily
    timeout: 5m
```

如果任务是分钟级周期，cron 也可以写 `*/5 * * * *`，但这并不是 heartbeat 的替代品。因为 cron 的语义仍然是“在每分钟的第 0、5、10...分钟执行”，而 heartbeat 的语义是“上一次完成后隔 5 分钟再执行”。两者在任务耗时较长时会产生明显差异。

### 3. heartbeat 配置示例

heartbeat 通常配置固定间隔，并建议加上执行锁和抖动，避免多个实例同时触发：

```yaml
tasks:
  queue_watchdog:
    trigger:
      heartbeat:
        interval: 30s
        jitter: 5s
    action: check_queue_depth
    timeout: 10s
```

如果 heartbeat 任务可能执行超过一个间隔，需要显式设置 `max_overlap` 或 `allow_concurrent: false`，否则同一任务可能被重复触发，造成并发写冲突。

## 我遇到过的坑

### 1. 容器里 cron 跑错时间

这是最常见的问题。OpenClaw 跑在容器里时，系统默认时区往往是 UTC。如果配置文件里没有显式设置 `timezone`，你会看到“日报在下午 5 点才发出来”。cron 一定要带时区，不要赌宿主机配置。

### 2. 用 heartbeat 做“每天一次”的任务

有人会配置 `interval: 24h` 来做每日任务。这在短时间跑没问题，但一旦 OpenClaw 重启，heartbeat 会从启动时刻重新计算间隔，任务执行时间会漂移。更合适的是用 cron 固定每日时间点。

### 3. 用 cron 做秒级巡检

cron 通常最小粒度是分钟，秒级需求硬套 cron 会很痛苦。如果确实需要秒级，应该用 heartbeat，或者在外部循环里调用 OpenClaw action。

### 4. 心跳不是存活探针

heartbeat 是“触发任务执行”的机制，不代表 OpenClaw 进程本身健康。不要把“能触发 heartbeat”当成“Agent 还活着”的证据。真正的存活需要独立探针 + 上一次成功执行时间监控。

### 5. 错过补跑策略不清晰

如果 OpenClaw 在凌晨重启，恰好错过了 02:00 的 cron，是否补跑？不同版本/部署方式可能有差异。对于关键任务，建议在任务内部记录 `run_id` 和小段逻辑，确保即使补跑或重复触发也是幂等的。

## 可复用建议

1. **选择规则**：日历语义用 cron，固定间隔语义用 heartbeat。
2. **显式时区**：所有 cron 都写 `timezone`。
3. **设置 timeout**：避免长任务占用调度队列。
4. **默认禁止并发**：heartbeat 任务尤其要配置 `allow_concurrent: false` 或等价参数。
5. **加 jitter**：多任务同间隔时加入 2-5 秒抖动，避免惊群。
6. **记录上次成功时间**：监控“距离上次成功”比监控“任务是否触发”更有用。
7. **保持幂等**：无论 cron 补跑还是 heartbeat 重叠，任务本身都应可以重复执行。

## 总结

cron 和 heartbeat 不是竞争关系，而是两种不同语义的调度原语。cron 解决“到点执行”，heartbeat 解决“周期巡检”。选型时先问自己：这个任务和具体时间点有关吗？如果有关，用 cron；如果只是固定频率，用 heartbeat。把语义选对，叠加时区、并发控制、幂等和监控，定时任务才能真正稳定地在 OpenClaw 里跑下去。
