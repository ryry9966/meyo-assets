互联网上有个反直觉的讨论：AI 非但没有让 C 端 SaaS 变得更“轻”，反而把很多产品推回了“人越多越亏钱”的健身房模式。

传统软件生意最迷人的地方，是边际成本趋近于零。但到了 AI-native 的 C 端 SaaS，每多一个活跃用户，尤其是高频重度用户，都可能意味着真金白银的 GPU 推理账单。订阅费收进来了，成本却可能比收入涨得更快。



## 一、消失的“零边际成本”，又从 GPU 里回来了

过去十年，SaaS 的核心叙事是：软件写完以后，多卖一份几乎不增加成本。服务器、带宽和存储的价格越来越低，多一个账号主要分摊固定成本，所以规模越大，毛利越高。这个逻辑支撑了从 Salesforce 到 Notion 的估值。

但 AI-native 产品打破了这条曲线。原因很直接：每次用户请求都要过模型，而模型推理消耗的是昂贵的 GPU/TPU 时间。

- 一个典型的 GPT-4 级问答，输入 3000 token + 输出 800 token，成本大约在 $0.02–$0.08。
- 如果用户上传 PDF 让 AI 总结，输入可能膨胀到 2 万 token，成本翻几倍。
- 如果用 Agent 模式，一次任务内部调用 5–10 次模型，成本再乘 5–10。
- 长上下文、RAG 检索、工具调用，都会让单次成本继续抬高。

可以算一笔账：假设一个免费用户每天调用 20 次，每次成本 $0.03，一个月就是 $18。而很多 C 端 AI 产品的订阅价不过 $9.9 或 $12。也就是说，最活跃的那批用户，可能让产品在每个用户身上每个月倒亏几美元。用户越多，亏损越大。

这就是问题的起点：AI 把 C 端 SaaS 从“复制即零成本”拽回了“每次服务都有成本”。

## 二、健身房生意的三个“反规模”特征

健身房的商业模式有一个出名矛盾：卖的是会员卡，赌的是你不来。场地、器械、淋浴、热水都有物理上限，人一多体验就下降，器械折旧也加快。

AI C 端 SaaS 正在被逼进同一条胡同。



### 1. 成本由用户行为决定，不由座位数决定

传统 SaaS 多一个登录账号，边际成本几乎为零。AI 产品里，用户多聊 10 轮、多发 10 张图，成本就直线上升。成本不再跟“账号数”挂钩，而是跟“调用次数 × token 量 × 模型单价”挂钩。

### 2. 高峰并发会放大成本

健身房最怕晚高峰：所有人都来跑步机和洗澡。AI 产品也一样，晚上 8 点大家一起让 AI 修图、写文案、做总结，GPU 排队，延迟变差。为了保持体验，只能加机器扩容，但订阅费并不会因为今晚用户用得猛而多收一分钱。

### 3. 使用率与利润存在天然矛盾

健身房希望会员少来一点，这样器械和热水成本低。AI 产品却希望用户用得更多，因为高频使用通常意味着留存和黏性。但在订阅制下，用得越多反而越蚕食毛利。产品越好用，用户越重度，毛利率越差。

这三条合在一起，就是典型的规模不经济：增长没有摊薄成本，反而放大了成本。

## 三、为什么 C 端比 B 端更先撞墙？

C 端 AI SaaS 面临的不是“算力贵”这一件事，而是增长、留存、毛利三者的互相拉扯。

- 要增长，就得靠免费或低价获客，但免费用户同样消耗模型算力。
- 要留存，就得让用户高频使用，但高频使用直接推高成本。
- 要毛利，就得限制使用或涨价，但 C 端用户价格敏感，很容易流失。

举个例子：一个 AI 陪伴类产品，用户把它当情绪出口，每天聊几十轮，单用户月成本可能超过 $20，但订阅费只有 $12。产品团队会面临一个尴尬选择：限制对话轮数会伤害体验，不限制则亏损。

B 端情况会好一些。企业客户可以按席位 + 用量签约，可以设置配额、洽谈 SLA、私有化部署，也可以按效果付费。客户为 ROI 买单，AI 算力成本更容易被覆盖。所以很多 AI 工具从 C 端起家，最后主动转向 B 端或 API 平台，例如 Jasper 从个人营销文案转向企业工作流。

还有一个更不能忽视的点：模型推理成本确实在下降，但需求增长往往更快。用户拿到更聪明的模型，会提出更长、更复杂的任务，单用户消耗不降反升。这类似 Jevons 悖论：效率提高反而刺激更多消耗。AI 推理成本的下降，未必能自动换来 C 端订阅业务的毛利改善。

## 四、如何不做“亏本健身房”？

破局的关键，不是祈祷模型降价，而是把成本结构、定价方式和产品设计对齐。



### 1. 分层模型路由

简单任务用 7B/13B 小模型，复杂任务再上大模型。大部分日常请求其实不需要最强模型，把模型选择做成内部路由，可以显著降低单次成本。

### 2. 缓存与前缀共享

长 system prompt、RAG 知识库、固定的上下文前缀，都可以缓存复用，避免每次请求重复计算。工程上做好前缀缓存和会话级 reuse，能省下可观的 token 开销。

### 3. 端侧推理

手机、PC 的 NPU 越来越强，把一部分可离线、低敏感度的推理放到用户设备上，直接减少云端 GPU 压力。对隐私也有好处。

### 4. 免费层必须设硬限额

免费额度不能无限。需要设计严格的每日/每月调用上限，超出后进入按量付费或订阅套餐。免费用户不是不能有，但不能成为纯成本黑洞。

### 5. 从“卖 token”转向“卖结果”

AI 简历优化可以按份收费，AI 生成 PPT 模板可以按次收费，AI 修图可以按张收费。价格锚定用户感知到的结果价值，而不是后台 token 消耗。

### 6. 尽早想清楚 C 端与 B 端的边界

如果 C 端毛利始终无法打正，可以保留 C 端做品牌和反馈入口，同时把核心能力打包成 B 端 API、企业工作流或行业解决方案。

---

最后，三条冷思考：

- 先算清“每活跃用户边际毛利”，不要被 DAU 增长骗了。月活再高，如果每用户毛利为负，增长就是加速亏损。
- 如果模型推理成本占收入超过 30%，优先做成本工程和定价重构，而不是继续烧钱买量。
- 警惕“高使用率等于好留存”的直觉。高使用率只有在可变现设计跟上时，才会转化为商业价值，否则就是健身房晚高峰：热闹，但不赚钱。

AI 没有杀死 SaaS，只是把 SaaS 从“卖无限复制”的上一个时代，拽进了“卖有限算力服务”的新阶段。能跨过这道坎的团队，不是最会烧钱的，而是最会算账的。
