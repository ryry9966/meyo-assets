## 背景

OpenClaw 作为 Agent 运行时，很多任务是在工作空间里直接执行的。模型能力很强，但对你的项目一无所知：它不知道你用的是 pnpm 还是 yarn，不知道 `src/generated/` 不能手改，也不知道本地 5432 端口已经被 Docker 占用。

没有约束时，Agent 会频繁用 `ls`、`cat` 探索目录，消耗大量 token；会跑错命令；会误触 MCP 工具；甚至在你没意识到时执行危险操作。AGENTS.md 就是解决这个问题的：它是一份放在工作区根目录的说明文件，OpenClaw 在会话启动或切换目录时读取，成为 Agent 的常驻上下文。

它不是替代 prompt，而是把项目规则固化成“机器可读的入职文档”。

## 问题

典型症状：

- Agent 每次都要先探索项目结构，浪费上下文。
- 分不清 dev/test/prod 环境约定，跑错脚本。
- 对 MCP 工具能力不清楚，反复试错。
- 产物写错目录，比如把构建输出塞进 `src/`。
- 权限边界只靠模型自觉，缺少硬约束。

## 做法/步骤

### 1. 位置放对

优先放在工作区根目录：

```text
/your-workspace/AGENTS.md
```

子目录可以放补充说明，但根目录总纲最稳。不要放在 `.openclaw/` 或 `docs/` 里等它被自动发现。

### 2. 控制规模

全文件尽量控制在 200–400 行以内。AGENTS.md 是常驻上下文，太长会被截断或稀释注意力。信息密度比完整性重要。

### 3. 结构模板

```markdown
# AGENTS.md

## 项目一句话
这是一个订单服务，主要处理下单、库存扣减和支付回调。

## 硬性规则
- 只使用 pnpm，禁止 npm/yarn。
- 不要修改 src/generated/ 下的文件。
- 执行删除、推送、发布命令前，先列出计划并等待确认。

## 常用命令
- 安装依赖: pnpm install
- 开发: pnpm dev
- 测试: pnpm test -- --run
- 构建: pnpm build

## 目录结构
- src/ 业务代码
- scripts/ 一次性脚本
- .openclaw/ 工作区配置，不要手动改

## 工作流
1. 改代码前先读 docs/architecture.md。
2. 新增 MCP 工具调用前检查 .openclaw/mcp.json。
3. 完成后运行 pnpm lint 和 pnpm test。

## 已知坑
- 本地 5432 端口被 Docker postgres 占用，不要重复启动。
- .env 不要提交，缺失变量找 .env.example。

## MCP/插件约定
- 优先使用 git MCP，不要直接 shell git。
- 浏览器插件只在需要渲染验证时使用。
```

### 4. 验证

新建一个临时会话，让 Agent 只根据 AGENTS.md 回答“如何启动项目 / 哪些目录不能碰 / 测试怎么跑”。如果它还要反复 `ls` 探查，说明文档不够明确。

## 踩坑点

- **位置不对**：放在 `.openclaw/` 或 `docs/` 里可能不会被自动读取，根目录最可靠。
- **层级冲突**：子目录也放 AGENTS.md，可能出现指令覆盖或拼接混乱。建议根目录放总纲，子目录用 `README.md` 补充。
- **太长**：超过 1000 行后，模型可能只记住开头和结尾。删掉散文，保留命令和边界。
- **只写否定句**：只写“不要”，不给替代方案，模型反而容易踩雷。例如写“禁止 npm”，不如写“只使用 pnpm”。
- **命令不完整**：只写 `pnpm test`，但实际需要 `pnpm test -- --run`，会导致 Agent 反复失败。
- **写入敏感信息**：AGENTS.md 可能被外部 MCP 工具读取，不要放 API key、内网拓扑等机密。
- **不维护**：项目改了技术栈，AGENTS.md 还停留在旧版本，比没有更糟。

## 可复用建议

- 把 AGENTS.md 当“新成员入职文档的机器可读版”。
- 多用列表和命令块，少用段落叙述。
- 每个硬规则带一个反例或示例，减少歧义。
- 在 CI 或 pre-commit 里检查 AGENTS.md 是否存在，并提醒更新。
- 可以从 `package.json`、目录扫描、git remote 自动生成初版，再人工补齐规则。
- 对频繁误用的命令，直接写“禁止 / 替代方案”。

## 总结

AGENTS.md 是给 AI 的工作空间使用手册，不是魔法。它解决的是“模型每次从零探索”和“项目规则无法固化”的问题。写得好，能明显减少 token 消耗和试错次数；写得差，只是多了一个没人看的文件。

对 OpenClaw 这种强工具调用的 Agent 环境，明确的命令白名单、目录边界和 MCP 约定，比泛泛的“请谨慎操作”有用得多。
