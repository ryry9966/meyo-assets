## 背景

很多团队每天需要从多个系统拉日志、看错误、盯指标，最后汇总成日报。人工操作重复、易漏，时间久了容易形式化。用 OpenClaw 这类 Agent 编排工具可以把“采集—清洗—结构化—成文—推送”串起来，但直接把原始日志丢给大模型，往往会出现上下文爆炸、输出不稳定、关键信息丢失。本文基于实际跑通的一条流水线，分享可复用的做法与踩坑点。

## 问题定义

日报生成不是“让模型读日志写总结”这么简单，需要解决四个问题：

- 数据源分散且格式不一。
- 日志量大且噪声多，直接送模型成本高、效果差。
- 输出必须结构稳定、可验证。
- 定时触发要幂等、可追溯，不能重复统计或漏报。

## 做法 / 步骤

### 1. 数据源接入

用 MCP Server 或自定义插件统一暴露日志数据源，例如 file tail、HTTP API、SQL 查询。每个数据源返回统一的 Record 结构：

```json
{
  "source": "order-service",
  "timestamp": "2025-01-01T00:00:00Z",
  "level": "ERROR",
  "message": "...",
  "raw_offset": 123456
}
```

不要直接把整个日志文件读入 Agent 上下文。

### 2. 预处理与归一化

在确定性代码里完成时间解析、时区统一、日志级别归一化、敏感字段脱敏、去重。这一步不用 LLM，保证可复现。

例如统一将时间转为北京时间，对手机号、token、身份证号做正则脱敏。

### 3. 分段与采样

按时间窗口（如过去 24 小时）取数据，控制每条 message 长度，超过 N 字符做智能截断。对 `ERROR` / `FATAL` 级别全量保留，`INFO` / `DEBUG` 按比例采样。

生成一个中间统计 JSON：

```json
{
  "data_start": "2025-01-01T00:00:00+08:00",
  "data_end": "2025-01-02T00:00:00+08:00",
  "error_count": 17,
  "top_errors": [...],
  "timeline": [...],
  "by_service": {...}
}
```

### 4. 结构化生成

把中间 JSON + 固定模板交给 LLM / OpenClaw Agent，只让它生成日报的自然语言部分。用 JSON Schema 约束输出，例如：

```json
{
  "summary": "string",
  "highlights": ["string"],
  "risks": ["string"],
  "next_actions": ["string"]
}
```

通过校验器检查输出，失败自动重试一次；再失败就回退到模板填充，避免任务挂起。

### 5. 发布与归档

通过插件推到钉钉、飞书或邮件。同时把原始中间 JSON 和最终报告落盘，带时间戳和批次号，方便回溯。

## 踩坑点

- **时间窗口边界**：定时任务可能漂移，导致同一条日志跨两个窗口被重复统计。建议固定使用左闭右开 `[start, end)`，并在中间 JSON 里记录 `data_start` 和 `data_end`，下次从上次的 `data_end` 继续。
- **大日志截断**：直接截断可能把异常堆栈的后半段截掉，导致摘要误判。可以先取前 500 字 + 后 200 字，或对堆栈只保留首行和末行。更稳的做法是先聚合，让模型看聚合结果而不是原始日志。
- **输出不稳定**：LLM 偶尔不按 Schema 输出，或字段缺失。校验后重试能覆盖大部分情况，但不要无限重试，设置最大 2 次，否则成本和延迟不可控。
- **时区混乱**：日志系统可能用 UTC，业务用北京时间。统一在预处理阶段转换，并在报告里注明时区。
- **敏感信息泄露**：日志里可能夹带手机号、token、身份证号。必须在预处理阶段脱敏，不要让原始日志进入 LLM 上下文。

## 可复用建议

- **严格分离统计与写作**：统计用代码，写作用模型。这样可测试、可复现，也能大幅降低 token 消耗。
- **中间产物落盘**：每一步的 JSON 都保存，排查“日报为什么写错”时不用重新跑全流程。
- **用 MCP 做数据源抽象**：一个 MCP Server 提供 `query_logs` 和 `fetch_metrics` 工具，Agent 不直接读文件。以后换数据源只改 MCP 层。
- **配置化模板**：日报标题、段落、收件人、数据源都放配置里，便于按团队复制。
- **失败兜底**：如果 LLM 或数据源挂掉，至少推送一条“今日日报生成失败，请检查流水线”的告警，而不是静默失败。

## 总结

这条流水线跑通后，日报从“人肉翻日志”变成了一条可观测、可复用、可回滚的自动化链路。核心不是让模型更聪明，而是把非确定性集中在写作环节，用工程手段守住数据和输出结构的稳定。对于 OpenClaw / Agent / MCP 实践，这比堆 prompt 更有长期价值。
