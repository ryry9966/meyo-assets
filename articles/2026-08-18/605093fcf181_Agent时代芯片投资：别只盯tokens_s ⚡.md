最近一年，大模型发布会的参数表里，tokens/s 几乎成了速度的代名词。厂商喜欢用“每秒生成多少个 token”证明推理性能，二级市场也容易把这个数字直接映射为芯片竞争力。但进入 Agent 时代，模型承载的任务从“一问一答”变成了规划、工具调用、记忆读写、检查点回滚等多步骤执行。此时，单纯盯着 tokens/s，就像用发动机最高转速衡量一辆车在拥堵城市里的通勤效率。本文从计算芯片和存储芯片两个角度，拆解这种变化。



## 一、tokens/s 为什么容易失真


tokens/s 本身没有错，它衡量的是解码阶段（decode）单位时间内生成的 token 数量。问题在于，Agent 的端到端延迟远不止解码阶段。

- prefill 与 decode 严重不对称。输入上下文越长，prefill 阶段耗时越高。Agent 每次调用工具后，往往要把工具描述、返回结果、历史记录重新输入，这会反复触发 prefill。
- 首 token 延迟（TTFT）更影响决策链。一个模型即使 tokens/s 很高，但如果 TTFT 是 1 秒，Agent 连续调用 10 次工具，仅仅等待首 token 就可能累积 10 秒以上。
- 实验室跑分常使用大 batch 提升吞吐，但真实 Agent 请求是小 batch、低并发、低延迟场景。芯片在大 batch 下的成绩，未必能平移到 Agent 任务里。

举一个简化例子：某 Agent 需要连续调用 5 个工具，每次工具返回后都要重新 prefill。假设每次 prefill 为 200ms，工具本身执行 300ms。即使 decode 速度达到每秒 300 token，整个任务耗时仍然被 prefill 和工具执行占掉大头。这时 tokens/s 看起来不错，但用户感受到的是“快不快”已经被其他环节决定。

## 二、Agent 负载：四个真正改变芯片需求的特征


Agent 的负载不像聊天机器人那样线性，更像一个服务器程序。它有四个明显特征：

1. **多步工具调用**。模型生成指令 → 调用外部 API → 解析返回结果 → 继续生成。整个过程会在 prefill 和 decode 之间频繁切换，缓存命中率会显著下降。
2. **长上下文记忆**。为了完成复杂任务，Agent 需要保存用户偏好、工具说明、执行轨迹和中间结果。上下文从 4K、32K 扩展到 128K 甚至 1M token，存储需求呈超线性增长。
3. **并发与调度**。一个任务可能被拆解为多个子 Agent 并行处理，芯片需要处理上下文切换、任务优先级和资源隔离，对调度器的要求比单纯推理更高。
4. **检查点与回滚**。任务失败后必须能回到稳定状态，这会产生状态快照、日志写入、元数据更新等额外操作，让系统从“读多写少”变成“读写混合”。

这些特征共同说明：Agent 时代的瓶颈不再只是“生成 token 快不快”，而是系统能否高效管理上下文、状态和多个执行路径。

## 三、计算芯片：从“峰值算力”到“可预测延迟”


在推理芯片上，过去大家关注 FLOPS、TOP/s 等峰值指标。Agent 工作负载出现后，更值得关注的是可预测延迟和单位能耗产出。

- **缓存层次比峰值更重要**。权重、KV cache、工具描述频繁访问，片上 SRAM 和 HBM 的大小、带宽会直接决定有效吞吐。如果数据频繁跑到片外，算力再高也只能等待。
- **小 batch 下的利用率**。Agent 请求数量不少，但每个请求 batch 很小。芯片如果只优化大 batch 吞吐，单请求延迟可能很差。这就像快递分拣中心，每天件量很大，但如果每件都要求即时送达，分拣中心必须重新设计流水线。
- **尾延迟决定任务链**。Agent 任务通常有多步依赖，只要一步慢，整个任务就慢。芯片架构需要减少多租户干扰、调度抖动和缓存争用。
- **能效被重新定价**。长上下文推理的能耗增长很快，如果单任务能耗过高，数据中心的总拥有成本会快速上升。

历史上有类似路径：CPU 行业曾从“GHz 大战”转向更看重 IPC、缓存和能效。AI 芯片也在经历这样的指标迁移。

## 四、存储芯片：被低估的上下文与状态瓶颈


如果计算芯片的叙事是“快”，存储芯片的叙事就是“稳而深”。Agent 对存储的影响可能比计算更深远。

- **KV cache 膨胀**。长上下文会让解码缓存急速增长。对于某些推理框架，百万 token 上下文的 KV cache 可能达到几十 GB 甚至上百 GB，单靠 HBM 已经放不下，必须扩展到 DRAM、CXL 内存甚至 NVMe SSD。
- **读写混合加剧**。传统推理主要是读权重、输出 token；Agent 还要保存中间状态、日志、工具返回值、检查点等，写的比例明显上升，对存储介质的寿命和写入延迟提出新要求。
- **层次化存储成为标配**。热数据放 SRAM/HBM，温数据放 DRAM，冷数据放 NAND，层与层之间的迁移策略直接影响上下文切换速度。
- **持久化与恢复**。多用户会话、失败回滚、任务续跑，都要求存储系统具备低延迟写入和高一致性，而不只是大带宽读取。

一个直观类比：算力像发动机，存储像道路和停车场。城市里车很多，如果停车场入口太窄、匝道太堵，发动机再强也跑不起来。长上下文 Agent 恰恰是把“停车场”和“匝道”的规模同时放大了。

在投资和技术选型上，不能再把存储芯片简单看作“配套”。当上下文成为智能体的短期记忆和长期记忆载体，存储带宽、容量、分层效率和持久化能力会直接影响产品体验和运营成本。

最后给出三条冷思考：

1. **评测时把“任务完成时间”放在 tokens/s 之前**。先看一个完整 Agent 任务多快完成，再看细分指标。
2. **关注上下文成本占比**。同样支持 128K 或 1M 上下文，不同方案在存储、互连和能耗上的成本差异可能远大于算力芯片本身的价差。
3. **警惕单一指标定价**。市场如果只按 tokens/s 给芯片估值，很可能忽略存储与互连的系统性瓶颈，导致高估“快”而低估“稳”。
