tokens/s 像性能车的马力，Agent 时代更像同城配送：车再快，仓库分拣、红绿灯、装卸货慢，时效照样崩。最近热议的「别只看tokens/s：Agent时代的计算与存储芯片投资思辨」，戳中的正是这个认知差。

过去我们讨论大模型推理，习惯把“每秒生成多少 token”当成核心指标。但 Agent 把推理从“一次生成”变成了“长链条执行”，工作负载特征彻底变了。芯片投资的逻辑，也需要从“单点算力崇拜”转向“系统效率与存储约束”。



## 一、Agent 推理：不再是“一句生成”，而是长链条执行

传统 LLM 推理模型很简单：输入 prompt，一次性输出 completion。用户看的是输出质量和速度。

但 Agent 完全不同，它在一个循环里工作：

1. **PLAN**：把任务拆成可执行步骤。
2. **TOOL CALL**：调用代码执行、网页检索、API、文件读写等外部工具。
3. **OBSERVE**：读取工具返回结果，更新上下文。
4. **REASON**：基于新信息继续推理。
5. **ACT**：执行下一步动作，直到任务完成。

这个循环可能走几十次。每一步都要携带完整或压缩过的上下文，大量 token 被反复搬运。举一个修 bug 的 Agent 例子：它先读 issue、相关代码、测试用例，生成 patch，跑测试，失败后再改。一次任务上下文很容易超过 10 万 token，最终输出可能只有几百行，但系统需要反复读取、缓存、更新海量中间状态。

所以 Agent 时代的真实瓶颈，往往不在“生成得多快”，而在“上下文搬得多顺”。

## 二、tokens/s 只是“最高时速”，不是“配送效率”



tokens/s 这个指标本身没有错，但它描述的是 decode 阶段的峰值吞吐。而且这个峰值通常在 batch 大、输出长、忽略首 token 延迟时最好看。

Agent 任务显然不是这种形态：

- 多为短输出、多次往返、强依赖，很难打满 batch。
- 首 token 延迟（TTFT）和 token 间隔（ITL）对用户体验影响极大。
- 串行步骤会让单步延迟成倍放大，5 步各 2 秒，总时延就是 10 秒以上。
- 多用户并发时，每个请求都要占用 KV cache，显存容量直接限制并发数。

一个更接近真实的公式是：

**有效吞吐 ≈ min(计算上限, 带宽上限, 容量上限)**

三者谁最小，谁决定体验。很多评测里漂亮的 tokens/s，到了真实 Agent 场景会被内存带宽和 KV cache 容量卡住。就像高速最高时速 300km/h，不影响城市配送平均时速只有 25km/h。

## 三、存储墙：Agent 时代的隐形税

存储墙不是新概念。传统计算机体系结构里，CPU 速度长期跑在内存前面，存储墙已经存在几十年。AI 推理只是把这个矛盾搬到了 HBM 和显存上。

关键机制有三个：

1. **每生成一个 token，都要读一遍权重**。模型越大，单 token 搬运的字节数越大。粗略估算：假设模型权重约 100GB，主流 HBM3 带宽约 3TB/s，单流 token 上限大约 30 tokens/s。这还只是权重读取，不含注意力计算和 batch 开销。
2. **长上下文下 KV cache 容量爆炸**。一条 128K context 的请求，KV cache 可能占用数十 GB 显存。Agent 多步循环如果频繁 evict 再 recompute，性能会雪崩。
3. **互连和内存扩展决定系统上限**。HBM 堆叠、CXL 内存扩展、NVMe pooling、KV cache offload，都是把“墙”往后推的手段。

这带来一个投资含义：存储芯片在 Agent 时代不只是周期品，而是推理系统里最硬性的约束之一。HBM、DRAM、CXL 控制器、高速互连，可能会拿到与算力芯片不同的风险收益比。

## 四、计算芯片：从“堆算力”到“堆系统效率”

计算芯片的价值评估也在变。

过去看单卡 FLOPS，现在更接近：

**推理芯片价值 ≈ FLOPS × 利用率 × 软件生态 / 功耗 / 成本**

单独一个 FLOPS 指标没有意义。有的加速卡纸面算力很强，但软件栈不成熟，实际 serving 利用率不到 30%；有的芯片算力一般，但 SRAM 带宽大，对短上下文 Agent 任务反而更快。

系统维度同样重要：NVLINK、PCIe、InfiniBand、CXL、SmartNIC，决定多卡、多节点能否高效协同。一批 Agent 任务里，每请求平均 20 步，输出 token 只占 20%，80% 消耗在上下文读取和工具调用上。这时内存带宽和互连延迟，可能比 FP8 算力重要得多。

指标也应该从“每 GPU 多少 TFLOPS”，转向“每 1M tokens 综合成本、尾延迟 SLA、每瓦特有效吞吐”。

## 五、冷思考：给关注芯片投资的人三条清单



1. **把 paper spec 当上限，别当承诺。** 查 p99 latency、KV cache 容量、多用户并发下的有效 tokens/s。只看峰值很容易高估真实能力。
2. **买“系统”而不是买“单卡”。** GPU、HBM、互连、软件栈、散热、电源，任何一环短板都会拉低整体 TCO。存储/互连相关公司在 Agent 推理中可能比单纯算力芯片更具弹性。
3. **区分训练与推理、单步与多步。** 训练仍然是算力密集，但 Agent 推理是内存/带宽密集。不能用训练时代的估值模型去套所有 AI 芯片。

Agent 时代不是不需要算力，而是算力的定价单位变了。从“每秒生成多少 token”，变成“每单位成本能稳定完成多少步有用工作”。这可能是芯片投资里最值得重估的一句话。
