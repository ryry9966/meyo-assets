最近，科技媒体又开始刷屏：GPT-6 的代号再度泄露，甚至给出了“或将周四见”的时间窗口。每隔几个月，大模型圈就会上演类似剧情——有人从网页源码里扒出一个字符串，有人在 API 返回头里发现一个陌生模型名，还有人声称在灰度测试中截到了系统提示词。这些传闻真假难辨，但背后确实存在一套可拆解的技术传播逻辑。今天不赌发布日，只聊泄露、版本号与识别方法。



## 一、代号不是产品名：泄露为什么总是“周四见”

在大模型公司内部，工程代号与产品名往往不是一回事。项目启动时，团队通常会用代号追踪实验版本，例如早期传闻中的 Orion、Strawberry，以及后来演化为 o 系列的一些中间形态。代号的意义是内部索引，而不是对外承诺。

常见的泄露源头主要有几类：

- 前端资源引用：网页 JS 或 API 路径里出现 `/models/gpt-6`、`gpt-6-preview` 之类的字符串；
- 接口返回数据：某些灰度用户调用 `/v1/models` 时，返回了尚未公开的 model id；
- 人员公开信息：工程师在简历、论文致谢或技术分享中，误写了内部项目名；
- 开源仓库与模型卡：一些实验分支没有清理干净，留下了配置文件名或超参数标签。

至于“周四见”，硅谷公司的确偏好周四发布：发布后有一整天观察反馈，周五消化热度，避免周一上线带来的周末加班压力。但这并非铁律。回看 OpenAI 历史：GPT-4 发布于周二，GPT-4o 发布于周一，o1 发布于周四。因此，周四只是一个概率略高的窗口，而不是所谓内部日历。



## 二、从 GPT-1 到 GPT-6：版本号正在被注入太多预期

如果只看网络情绪，可能会产生一种错觉：GPT-5 还没捂热，GPT-6 就要来了。要理解这种错位，得先回到技术代际本身。

大模型版本迭代的公开脉络大致是：

1. GPT-1（2018）：1.17 亿参数，验证了 Transformer 解码器做自回归预训练的可行性；
2. GPT-2（2019）：15 亿参数，展现出零样本多任务潜力，发布方因担心滥用选择分阶段公开；
3. GPT-3（2020）：1750 亿参数，小样本学习能力明显提升，成为 Prompt 工程的重要起点；
4. GPT-4（2023）：官方未披露确切参数量，但多模态输入、对齐质量与工具调用能力显著增强。

可以发现，从 GPT-3 到 GPT-4 的体验跃迁，并不是简单靠参数翻倍。数据质量、RLHF（基于人类反馈的强化学习）、推理链、安全对齐、工程稳定性同等重要。到了 GPT-5/GPT-6 传闻阶段，版本号更多成为一种市场预期管理工具，而不是严谨的技术指标。

另一个关键变量是 MoE（Mixture of Experts）。MoE 架构下，模型总参数量可能很大，但每次推理只激活一部分专家。这导致“总参数”与“激活参数”差距巨大，单纯比较模型尺寸已经没有太大意义。真正影响体验的是激活参数规模、推理成本与上下文窗口。



## 三、一次泄露里，哪些信息值得认真对待？

如果把所有传闻都当作噪声，可能会错过重要信号；但如果全部采信，又容易被市场情绪裹挟。判断一条泄露信息的价值，可以从“可验证性”出发。

高质量信号通常具备这些特征：

- 可复现的接口响应：例如 `/v1/models` 返回了新的 model id，并且多个独立用户能复现；
- 前端资源带时间戳：资源路径与已知版本格式一致，且有清晰的构建时间、hash 值；
- 模型卡或评估表：公开了具体指标，如 MMLU、AgentBench、多语言问答准确率，并注明 few-shot 设置和样本量；
- 产品化参数：上下文窗口、工具调用参数、API 价格、速率限制等，能够被直接验证。

低质量信号则相反：

- 只有“内部员工说”的转述，没有可查证据；
- 截图缺少日期、URL、请求头或响应体；
- 使用“人类水平”“智商测试”“颠覆认知”等模糊描述；
- 只给单一基准跑分，且不披露测试配置。

一条典型的泄露传播链是：代码/截图 → 技术社区讨论 → 科技媒体跟进 → 公众情绪 → 市场波动。信息每经过一层，确定性往往会下降一层，但传播音量会上升一层。



## 四、发布日不是终点：如何用工程师视角看“周四见”

即便 GPT-6 真的在周四发布，发布本身也不是最重要的节点。对于开发者和团队来说，发布日只是开始，真正需要评估的是能力是否可接入、成本是否可控。

如果真发布，建议盯住四个维度：

1. API 价格与速率限制：单 token 成本、并发上限、延迟 P50/P99，这直接决定能否上生产；
2. 上下文窗口与长文档召回率：不要只看 1M token 的宣传数字，要测试长文档中间位置的信息保留能力；
3. 工具调用与结构化输出：JSON schema 稳定性、函数调用一次性成功率，是 Agent 场景的关键；
4. 安全与数据隔离：私有数据是否被用于训练、企业版能力与权限边界是否清晰。

如果不发布，传闻也并非全无价值。它反映了行业对下一次能力跃迁的焦虑，也说明市场正在用真金白银为技术预期定价。从长期看，模型迭代的竞争焦点正在从“参数竞赛”转向“推理成本竞赛”。未来半年，比 GPT-6 参数量更重要的，或许是同等能力下推理成本能否下降一个数量级。



**三条冷思考**

1. 把泄露当信号，不当结论。只信可验证的一手信息，比如官方 API 文档、开源权重、模型卡；看到截图先问三个问题：时间、来源、能否复现。
2. 建立自己的评测集，而不是搬运跑分。从日常工作里抽 20~50 条典型任务，每次新模型发布后跑一遍，记录延迟、成本、准确率和失败模式。
3. 对交付节奏保持钝感。真正影响业务的是模型是否进入稳定 API、SLA 是否可靠、迁移成本是否可控。蹲一个周四的发布会，不如提前做好灰度切换方案。
