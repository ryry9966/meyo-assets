在 OpenClaw 里让 Agent 生成内容后，下一步往往是发布到微信公众号、知乎、Notion、飞书、WordPress 等平台。AI 输出的 Markdown 通常“看似标准”，但直接复制到各平台经常出现代码块丢失语言、表格混乱、公式变成源码、图片外链被禁等问题。根本原因是各平台对 Markdown 的支持是不同方言，需要一条格式适配管线，而不是手动逐篇修格式。

## 问题定位

我遇到的具体差异：

- **行内代码与代码块**：微信公众号不识别围栏代码块，需要转成带样式的 `<pre>`/`<code>`；知乎对代码块语言标注支持有限。
- **表格**：Notion 支持好，公众号需转 HTML 表格，飞书可能需要重新识别。
- **链接与图片**：公众号会过滤外链 `href`，需要处理为文末引用；图片必须上传到平台图床（如微信素材库）才能显示。
- **标题层级**：AI 生成的标题经常从 `##` 起跳，但某些平台要求 `#` 唯一且层级连续。
- **公式**：公众号不支持 LaTeX，需转成图片或使用 MathML；知乎支持 KaTeX 但有转义坑。

## 做法：三段式管线

我采用“规范化—适配—发布”三段式。

### 1. 规范化

将 AI 原始输出统一到 CommonMark + 受控扩展子集。用 `remark` 解析，剥离平台不兼容的语法，如脚注、HTML 注释、未知标记。此阶段输出“中间表示”（IR），保留 AST 或标准 JSON。

### 2. 平台适配器

针对每个平台写独立转换器。例如：

- **微信公众号适配器**：将 Markdown AST 转成内联样式的 HTML（可选择样式主题），把图片 URL 替换为已上传图床的 URL，外链转为引用列表。
- **知乎适配器**：保留标准 Markdown，但处理公式转义、标题层级、代码块语言映射。
- **Notion/飞书适配器**：通过 API 直接创建块，而非粘贴 Markdown，绕过格式解析差异。

### 3. 发布/导出

适配器输出平台所需格式（HTML、Markdown、API payload），再由发布模块执行上传/创建。

## 在 OpenClaw/MCP 中的集成

我将适配器封装成 MCP server，暴露 `convert_markdown` 工具。Agent 在生成内容后调用该工具，传入目标平台和原始 Markdown，得到适配结果。这样 Agent 不必关心平台细节，只要产出语义正确的 Markdown。

一个简化的 MCP 工具定义：

```json
{
  "name": "convert_markdown",
  "parameters": {
    "source": "string",
    "target_platform": "enum[wechat, zhihu, notion, feishu, wordpress]"
  }
}
```

内部根据 `target_platform` 选择 profile 调用对应转换器。

## 踩坑点

- **不要过早转换 HTML**：很多平台允许 Markdown，直接塞 HTML 可能被过滤或样式错乱。先输出标准 Markdown 试平台，再决定是否降级为 HTML。
- **图片处理是最大坑**：AI 生成的外链图片（如占位图）往往无法在平台显示。需要在管线中增加图片上传步骤：下载原图 -> 上传平台图床 -> 替换 URL。缓存上传结果避免重复上传。
- **表格不一定能保真**：公众号表格需要合并单元格或样式，建议在适配器中检测表格复杂度，复杂表格转成图片或列表。
- **公式处理**：国内平台对 LaTeX 支持参差。可以维护一个平台能力矩阵：哪些支持 KaTeX、哪些需要图片渲染。如果技术栈允许，使用 `pandoc` 或 `mathjax-node` 渲染公式为 SVG。
- **标题层级**：许多平台要求首个标题为 H1 且不能跳级。适配器应检查并自动调整：若首个标题不是 H1，则提升后续标题层级。

## 可复用建议

1. **定义平台 profiles**，而不是为每篇文章写特例。profile 包含：支持语法白名单、图片处理策略、标题规则、特殊字符转义表。
2. **建立 golden tests**：准备几篇包含各种 Markdown 特性的测试文章，记录每个平台的预期输出，每次改动适配器都跑回归。
3. **保留原始 Markdown 作为唯一事实来源**，所有转换都从它生成，不修改原始内容，方便切换平台重新适配。
4. **记录转换日志**：将转换前后的 diff 存入日志，便于排查某段内容为何在某平台丢失。
5. **在 MCP 层面做重试与降级**：如果平台 API 报格式错误，自动尝试简化版（如去掉表格、公式转图片）再提交。

## 总结

Markdown 从 AI 生成到多平台发布不是简单复制粘贴。通过规范化、平台适配器、发布三段式管线，配合 MCP 工具化，可以把格式适配固化成可维护工程，而不是手工救火。真正花时间的是平台能力调研和边界测试，代码本身并不复杂。
