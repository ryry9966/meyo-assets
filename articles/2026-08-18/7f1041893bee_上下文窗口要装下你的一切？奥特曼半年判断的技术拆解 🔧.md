最近 OpenAI CEO 奥特曼（Sam Altman，不是打怪兽那位）又放了个判断：半年内，GPT 的上下文窗口将大到足以覆盖一个人几乎所有的数字信息。这话听起来像科幻，但如果你看过过去两年各种大模型上下文长度的膨胀曲线，会发现它更像一道工程数学题，而不是魔法。



## 1. 上下文到底在“记”什么？

在大模型里，上下文（context window）指的是模型单次推理时能“看到”的最大 token 数量。你可以把它理解成模型的工作记忆：它不是在训练时记住你，而是你把材料递到它面前，它才能在这一次对话里使用这些材料。

- **Token 不是字**：英文里一个 token 约等于 0.75 个单词；中文里一个字通常占 1~2 个 token，取决于分词器。所以“128k tokens”听起来很大，换算成中文大概只有 8 万到 10 万字，约等于一本薄一点的小说。
- **上下文 ≠ 长期记忆**：模型参数在推理时是冻结的。你不提供信息，它不会主动记得你昨天说过什么。上下文只是每次调用时临时打开的工作台。
- **为什么越长越重要**：如果上下文能覆盖你几年的聊天记录、邮件、笔记、日历，模型就不需要靠外部检索（RAG）拼凑信息，而是可以直接“一眼看完”你的数字生活。比如你上传一个 PDF，它只能看到这个 PDF；但如果你授权它读取最近三年的全部笔记和邮件，它就能直接帮你找出矛盾、总结趋势。

## 2. 从 4K 到 1M：一场安静的军备竞赛

上下文长度的扩张速度，可能比大多数人感知到的更快。

- **2020 年 GPT-3**：上下文只有 2k/4k tokens，放一篇长一点的博客都费劲。
- **2023 年**：Anthropic Claude 把上下文拉到 100k，OpenAI 随后推出 GPT-4 Turbo 的 128k，能塞下一整本《三体》第一部。
- **2024 年**：Google 宣称 Gemini 1.5 Pro 支持 1M tokens（后续实验性支持到 2M），相当于一次读掉几百万字。
- **现在**：一些开源模型和架构（如状态空间模型、混合架构）开始把“长上下文”当成默认能力，而不再是一个卖点。

若按一个人每天产出 5000 字文本估算，一年约 180 万字，按中文 token 换算大约 300 万 tokens。十年就是 3000 万 tokens。也就是说，要“覆盖你的一切”，上下文窗口需要从现在的 128k 再提升两到三个数量级。半年内能不能做到？从工程迭代节奏看，并不是天方夜谭。把时间范围缩到“最近几年的关键数据”，百万到千万 token 已经覆盖大部分场景。

## 3. “覆盖一切”背后要翻过的三座山

“上下文变长”不是把窗口参数改大那么简单。标准 Transformer 架构在长上下文面前会遇到三个硬约束。



- **注意力计算成本**：标准 self-attention 对 n 个 token 的时间复杂度和显存占用都是 O(n²)。100 万 token 的注意力矩阵有 10¹² 个元素，即使每个用 fp16 存储，也要 2TB 显存。单卡 H100 只有 80GB，中间差了两个数量级。虽然 FlashAttention 等优化能大幅降低显存占用，但复杂度本质没变。
- **位置编码与长程依赖**：常用的 RoPE 位置编码在训练时一般只见过几万 token 的序列，直接外推到百万级会导致性能断崖。需要特殊的外推策略、长上下文微调，或者改用 ALiBi、NoPE 等更适合长序列的方案。
- **中间信息丢失（lost in the middle）**：多项研究发现，模型对上下文开头和结尾的内容利用效率最高，对中间部分容易“视而不见”。上下文越长，中间段越可能成为信息黑洞。

工程上可能的解题路线包括：稀疏注意力（只算部分 token 对）、线性注意力、Mamba 这类状态空间模型、KV cache 压缩、滑动窗口与检索的结合。这些路线不是互相替代，而是可能组合在一起，让百万级上下文从“能跑”变成“能用”。

## 4. 长上下文 ≠ 长记忆：三个容易高估的点

即使半年后模型真的能塞下你的一生，也不意味着它会像人一样“记得”你。

- **上下文是工作记忆，不是长期记忆**：每次新会话，你仍然需要重新把材料喂进去。模型不会因为昨天读过你的全部聊天记录，今天就自动调用，除非产品层做了记忆持久化。
- **塞得进去 ≠ 用得出来**：长上下文模型经常出现“读到但用不上”的问题。你给它一百万 token 的文档，问它中间某个细节，它可能回答得还不如一个简单的 grep 命令。
- **隐私账算不过来**：把全部个人数字痕迹交给一个第三方 API，意味着你的数据边界从“主动授权某一段”变成“默认全量进入”。一旦模型被提示注入攻击，泄露面会成倍放大。

所以“上下文覆盖一切”带来的更多是产品形态的变化，而不是模型突然拥有了人类的记忆能力。

## 5. 半年后你可能会得到什么：三条冷思考



如果半年后 OpenAI 真的推出超大上下文模型，普通人大概率会先通过企业版或 API 体验到，而不是免费聊天框。它能带来的可能是：一个能读完你三年邮件、两年日历和全部笔记的 AI 助理，直接帮你总结、比对、找矛盾。但有三件事现在就可以先想清楚。

- **别把长上下文当许愿池**：关键信息仍然需要结构化、分段、明确给出。模型对“一大坨”材料的处理能力并不均匀，重要的内容最好放在开头或结尾。
- **敏感数据别急着全量上云**：优先等待端侧/本地模型支持长上下文，或者使用企业级方案中的访问控制和数据隔离。对个人用户来说，数据最小化原则比“全塞进去”更安全。
- **把上下文窗口当成工作台，而不是仓库**：即使上下文再大，配合 RAG、索引、标签仍然有实际价值。长上下文降低了对检索的依赖，但不会取代信息架构。真正好用的 AI 助理，是“该塞的塞，该查的查”，而不是无脑全量喂给模型。

技术永远在膨胀，但判断力不会自动变长。这可能才是奥特曼那句话里，最值得被听见的部分。
