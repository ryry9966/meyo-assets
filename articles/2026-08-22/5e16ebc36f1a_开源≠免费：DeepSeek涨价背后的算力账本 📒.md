最近关于 DeepSeek 的讨论出现了一个很有意思的对照：开源社区在欢呼新权重发布，另一边 API 用户却在群里对比账单，发现部分调用成本变高了。于是“一边涨价一边开源，又香又臭”成了热搜话题。这个说法很形象，但容易把两件事混在一起。如果拆开看，涨价和开源非但不矛盾，反而是一个大模型公司同时经营两种产品的正常动作。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-22/68e2852a24f5e1e9.png)

## 一、先把两个“DeepSeek”分开：开放权重与托管 API

很多人看到“开源”两个字，就默认所有东西都该免费。这个直觉在软件时代或许成立，但到了大模型时代，需要重新划清边界。

1. **开源权重（open weights）** 是指把训练好的模型参数公开，开发者可以下载后自己部署、微调、做研究。它更像公开“菜谱 + 半成品配方”。
2. **托管 API** 是官方服务器帮你跑模型，按 token 计费。你不需要买 GPU、不需要维护推理集群，调用接口就行。
3. 两者成本结构完全不同：开源权重的主要成本发生在训练阶段，发布之后边际成本接近零；而 API 每次调用都在消耗算力、电力、网络带宽和运维人力。
4. 一个常见误区是“开源就应该免费”。实际上，Open Source 的定义从未包含“免费替你运行”。菜谱公开不代表餐厅免单，源代码公开也不代表云端服务白嫖。
5. 所以，当 DeepSeek 一边开源权重，一边调整 API 定价，它并不是精神分裂，而是在经营两条不同的产品线。开源负责生态和影响力，API 负责现金流和可持续性。

## 二、涨价涨的是什么？算力账单比想象中复杂

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-22/e71c02652e0f4e9c.png)

很多人看到“涨价”两个字，第一反应是“厂商想多赚钱”。但从技术视角看，API 定价背后是一整套算力经济学。

- **推理成本不等于训练成本。** 一个模型训练完只付一次钱，但每来一个用户请求，GPU 都要算一遍。大模型尤其长上下文、推理链（Chain-of-Thought）场景，token 消耗可能是普通对话的几倍。
- **API 定价通常包含几个隐藏变量：** 输入/输出 token 价格不同、缓存命中与否、批量任务与实时任务、错峰时段折扣。很多用户感觉“涨价”，可能是某项优惠取消或计费规则调整，而不是基础单价直接翻倍。
- **早期大模型 API 常走“补贴换规模”路线：** 用低价吸引开发者，验证产品、积累反馈。等调用量上来，算力供给紧张，价格自然会向成本线回归。这跟网约车早期补贴、后来涨价是同一套逻辑。
- **电力与服务器成本也在涨。** GPU 集群不是买一次就结束，要持续消耗大量电力，还需要散热、网络、运维。模型越大，单次推理的硬件时间越长，单位 token 的能耗和硬件折旧就越难被摊薄。
- **从行业规律看，API 价格不可能无限下降。** 它会随着硬件效率提升、稀疏化、量化、蒸馏等技术进步而阶段性下降，但短期供需波动会带来价格上浮。就像机票价格，长期看航空技术让飞行变便宜，但节假日该涨还是涨。

## 三、开源为什么还继续？生态本身就是护城河

既然 API 能赚钱，开源权重看起来是在“免费送核心资产”，为什么还要继续做？这背后是更长期的商业逻辑。

- **开源权重能吸引研究者、个人开发者和中小企业，形成庞大的使用基数。** 这些人不一定付得起高额 API 账单，但他们能贡献用例、反馈和口碑。
- **开发者可以在本地做微调、做垂直场景适配。** 这些创新会反哺社区，也帮助官方发现新需求。一个开源模型被集成到各种工具链里，本身就是在扩大影响力。
- **可审计、可复现是开源的重要价值。** 尤其对安全合规要求高的行业，能自己检查权重、复现结果，比闭源黑盒更有说服力。
- **从商业角度，开源是一种“标准争夺”策略。** 当你的开放权重被大量云厂商、工具链、应用集成时，你的生态位就稳固了。后续的商业化可以围绕企业支持、私有化部署、高级 API 能力展开。
- **举例：Meta 的 Llama 系列也是开源权重 + 官方托管并存的路线。** 开源并没有让 Meta 放弃商业授权或合作伙伴计划。开源与商业从来不是二元对立。
- **开源还能降低客户对“绑定”的恐惧。** 企业如果担心 API 停服或涨价，可以选择自部署开源权重。这种选择权本身就是卖点，甚至能让更多企业愿意先试用官方 API。

## 四、为什么有人觉得“臭”？预期错位比涨价更麻烦

“又香又臭”的观感，往往不是来自单一事实，而是来自不同人群的预期碰撞。

- **感觉“臭”的往往不是开源社区，而是依赖官方 API 的中小团队。** 他们可能没有算力自部署，涨价直接增加运营成本。
- **开源新闻自带传播性，涨价公告则藏在计费文档或邮件里。** 两者传播面不对称，导致很多人只看到“开源”这半边，突然收到账单时感觉被背刺。
- **一部分用户把大模型 API 当成“数字公共品”，忽略了商业公司需要现金流。** 这种预期一旦被打破，就容易产生情绪反弹。
- **也要看定价是否透明。** 如果厂商提前公告、规则清晰、按量计费，那属于市场化调整；如果暗改、突击涨价，才值得批评。后者的“臭”不是贵，而是不透明。
- 所以“又香又臭”更多是两种角色、两种预期的叠加，而不是产品本身出了问题。把开源权重和托管 API 看成两个独立商品，很多情绪就会消解。

## 五、实用建议：开源红利怎么薅，涨价怎么避

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-22/a22c84384bc11623.png)

面对“一边涨价一边开源”，不用急着站队，更不用急着骂。可以先做三件事。

1. **先算账，不要只看单价。** 把单次请求的真实成本算出来：输入 + 输出 token、缓存命中率、日调用量。如果成本占比不高，涨价可能没想象中痛。
2. **调用量大的团队，认真评估自部署开源权重。** 如果已有 GPU 资源或能接受运维复杂度，自托管可能更划算；但要把人力、电力、稳定性算进去。自部署不是零成本。
3. **优化 prompt 与架构。** 减少无效上下文、使用结构化输出、设置合理的 max\_tokens，能省下不少 token。缓存和批处理也要用起来。很多时候“涨价”带来的成本增量，远不如 prompt 浪费掉的 token 多。
4. **关注官方错峰折扣或企业协议。** 很多云服务都有预留容量折扣，公开单价只是标价，实际成交价可以谈。别只盯着页面上的数字。
5. **冷思考：开源和涨价都是手段，关键看单位智能成本是否持续下降。** 只要能用更少的钱获得更好的模型能力，短期价格波动不必过度解读。真正该担心的不是一次调价，而是模型能力停滞、成本结构恶化。

开源负责让技术扩散得更远，涨价负责让服务活得更久。两者同时出现，恰恰说明这个行业正在从“补贴换增长”走向“理性可持续”。对开发者来说，最好的姿态不是选边站，而是看懂规则，按需选择。
