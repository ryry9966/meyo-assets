## 背景

团队日报、项目日报的价值在于同步进展和暴露风险，但原始数据通常分散在 Git 提交、CI 构建记录、监控告警、需求工单和日历会议里。手动汇总不仅耗时，还容易漏掉关键信息。我们在 OpenClaw 上尝试用 Agent + MCP 工具链做了一条日报流水线，目标不是“让 AI 写漂亮空话”，而是把原始日志变成可追溯、结构化、人能快速确认的报告。

## 问题

实际跑起来后，主要卡在四类问题：

- **数据源多且异构**：git log 是文本，CI 是 JSON，监控是指标，人工记录是自然语言。
- **噪音大**：构建重试、机器人消息、自动回复、测试失败重跑等会淹没关键进展。
- **安全与隐私**：日志里可能混着 token、邮箱、内部域名、客户名称。
- **结构化困难**：直接让模型生成 Markdown，今天格式对，明天就漂移。

## 做法与步骤

### 1. 用 MCP 暴露数据源，而不让 Agent 直连系统

每个数据源封装成一个 MCP tool：`git-log`、`ci-status`、`incident-list`、`calendar-events`。Agent 只通过工具获取当天时间窗口内的数据，权限最小化，避免拿到全量工单或代码搜索能力。

### 2. 采集与预处理

定时触发 OpenClaw 任务，按本地工作日切时间窗口拉取原始日志。先做一轮机械过滤：

- 去掉 CI 重试、自动回复、机器人消息；
- 用正则脱敏邮箱、token、内部域名；
- 每条工具返回最多保留 N 条，附 `total_count` 让模型知道是否有截断。

### 3. 让 Agent 只做提取，不做创作

提示词里给出 JSON schema，要求每个字段都能回溯到原始工具返回内容：

```json
{
  "progress": [{"item": "...", "evidence": "commit abc / CI #123"}],
  "risks": [{"item": "...", "owner": "...", "evidence": "..."}],
  "plan": [{"item": "...", "source": "..."}],
  "unverified": [{"item": "..."}]
}
```

关键是 `evidence` 字段必须引用工具返回的 commit hash、CI 编号、告警 ID 等。引用不到的，一律放进 `unverified`，不允许混在正式结论里。

### 4. 模板渲染

把 JSON 交给一个简单模板插件，生成固定结构的 Markdown：进展、风险、计划三段，尾部附“原始数据来源”链接，指向 Git、CI 或告警平台。这样任何一条结论都能跳回原始记录。

### 5. 草稿-确认-发布

生成后先发到日报机器人草稿群，负责人确认或编辑，再通过插件发正式群或写入知识库。保留 `unverified` 段，放模型不确定但值得人看的内容。

## 踩坑点

- **时区与时间窗口**：MCP 工具返回的时间可能是 UTC，但日报按本地工作日切。必须在工具层明确传入 `start/end`，不要让模型自己算。
- **上下文不够**：原始日志很容易超过上下文。先去重、截断，并保留 `total_count` 告知模型是否有遗漏。
- **幻觉**：模型容易把不同日期的人或事混在一起。强制 `evidence` 引用工具返回的 id/hash/编号；引用不到就放 `unverified`。
- **结构化输出不稳定**：用 JSON schema 或 function calling 约束输出，并在解析后做校验。不符合 schema 就重试一次，再失败就退回纯文本摘要，避免整条流水线中断。
- **工具权限越界**：不要让日报 Agent 直接拿全量数据。只读、时间限定、字段白名单，能在工具层挡住的就不要靠提示词。

## 可复用建议

- **先跑通一个数据源**：比如只汇总 Git 提交，跑稳后再加 CI 和告警。
- **把“原始链接”作为硬性字段**：没有来源的内容不值得写进日报。
- **保留人工确认环节**：哪怕只是点一下“确认”。自动化日报的价值是降低汇总成本，不是替代判断。
- **封装成 OpenClaw 插件**：配置调度、工具白名单、敏感词过滤规则，团队复用时只改数据源，不碰核心逻辑。
- **加日志和回放**：每次生成记录输入摘要、输出 JSON、人工改动，便于事后定位模型行为。

## 总结

从原始日志到结构化日报，核心不是模型生成得有多流畅，而是数据源可控、输出可追溯、人工确认成本低。OpenClaw / Agent / MCP 适合做“连接-提取-渲染”的编排层，但真正决定好不好用的是预处理、schema 约束和发布权限。建议把它当成一条需要持续维护的小型数据流水线，而不是一个“AI 替身”。
