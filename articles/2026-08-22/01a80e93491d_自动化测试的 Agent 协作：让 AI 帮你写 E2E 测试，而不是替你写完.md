## 背景

E2E 测试的维护成本通常比编写成本更高。录制-回放工具生成的脚本选择器脆弱，手写用例又非常耗时。现在借助 OpenClaw + MCP，可以让 Agent 直接调用 Playwright 这类浏览器自动化工具，完成页面探索、元素定位、执行操作和读取失败堆栈。

但实际用下来，直接让 Agent“帮我写完整个 E2E 测试”通常不可靠。更工程化的做法是：把它当成一个能操作浏览器的协作者，而不是外包工人。

## 问题

一次性生成完整测试代码，容易暴露几个问题：

- 选择器幻觉：Agent 会写出 `div.css-xxx` 或绝对 XPath，看起来合理，实际跑不起来。
- 长页面快照过大，Agent 注意力漂移，遗漏关键异步状态。
- 生成代码与现有测试框架、目录结构、命名规范割裂。
- 缺乏中间产物，人工无法审核意图，只能审核一堆不稳定代码。

因此，我目前的实践不追求“全自动生成”，而是让 Agent 做重复劳动，人做契约确认。

## 做法 / 步骤

### 1. 准备工具链

在 OpenClaw 中接入 Playwright MCP server，把以下能力暴露给 Agent：

- `navigate`
- `click`
- `snapshot` 或可访问性树读取
- `screenshot`
- `evaluate`
- `wait_for`

建议本地调试时用 headed 模式，CI 中切换为 headless。

### 2. 先探索，后生成

不要直接要求 Agent 写测试。先让它以“只读”方式探索页面，基于可访问性树而不是渲染 HTML，记录元素角色、名称、label、testid。

要求输出一个中间产物，而不是最终代码。例如：

```yaml
- name: 登录按钮
  selector:
    role: button
    name: /登录|Sign in/
  action: click
  expect: 跳转到 /dashboard
```

这个 YAML 就是人审的“测试契约”。

### 3. 分步交互，保持上下文可控

让 Agent 按流程分步执行，每步返回截图和局部 DOM diff。遇到找不到元素时，要求它给出备选选择器并说明理由，而不是硬编码一个路径。

一个关键约束：限制每轮工具调用次数，并把长流程拆成多个短场景。比如把“登录-下单-支付”拆成三个独立用例，而不是一个超长脚本。

### 4. 生成代码 + 人工 review

基于中间产物生成 Playwright/Cypress 代码。这时人工只需要检查：

- 选择器是否使用 `data-testid` 或稳定的 role/name
- 测试数据是否可重复
- 是否包含合理的等待策略
- 断言是否真正验证业务状态

### 5. 回放与迭代修复

让 Agent 运行测试，读取失败堆栈，定位是选择器失效、环境问题还是断言错误。只允许它自动修复“选择器失效”这一类问题，最多迭代 3 次。否则容易陷入无限修改。

### 6. CI 集成

将最终生成的测试和中间产物一起提交到仓库。CI 中使用 CLI 方式执行，不依赖 Agent 在线生成，确保可重复、可审计。

## 踩坑点

- **截图不能作为唯一断言**。截图无法版本化，Agent 也容易误判视觉差异。优先使用 DOM 状态、URL、文本或角色断言。
- **异步加载导致快照不完整**。页面还在加载时，Agent 可能拿到旧快照。强制等待 networkidle 或等待特定 role 出现，不要只依赖固定 sleep。
- **探索阶段要有只读边界**。禁止 Agent 在探索时提交表单、点击删除、触发支付等破坏性操作。可以通过 MCP 权限或系统指令限制。
- **登录态不要每次都走 UI**。验证码、MFA 会直接卡住 Agent。更可靠的方式是注入 session storage 或 cookie，让 Agent 从已登录状态开始。
- **禁止绝对路径选择器**。这是最容易过拟合的选择器类型，维护成本极高。

## 可复用建议

- 中间产物 YAML/JSON 必须提交到仓库。人审的是契约，不是生成代码。
- 准备 2-3 个“黄金用例”，让 Agent 模仿现有测试风格和命名规范。
- 对 Agent 输出的步骤文件做 schema 校验，防止格式漂移。
- 使用随机化测试数据或专用测试账号，保证用例可重复运行。
- 建立失败分类：选择器失效、环境问题、断言错误、产品变更。Agent 只自动处理选择器失效，其他升级给人。
- 把长页面按流程切分，避免一次性给 Agent 过大的 DOM 上下文。

## 总结

Agent 在 E2E 测试里真正有价值的地方，不是替你写完所有测试，而是降低“探索页面—选选择器—写步骤—回放调试”的重复劳动。

用 MCP 给 Agent 接入真实浏览器反馈，用中间产物和权限边界控制风险，用人工 review 守住可维护性。这样 AI 生成的 E2E 测试，才有可能从 demo 变成日常工程实践。
