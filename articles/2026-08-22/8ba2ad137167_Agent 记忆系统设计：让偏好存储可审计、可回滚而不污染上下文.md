## 背景

很多 OpenClaw 用户的体感是：Agent 能力很强，但每次换会话就像失忆。告诉过它“回复不要加 emoji”“Python 脚本默认用 venv”“MCP 工具优先用本地接口”，下次还是忘。于是有人把这些内容全部塞进 system prompt，结果上下文越来越长，注意力被稀释，真正重要的指令反而被忽略。

记忆系统不是简单“存下来”，它要解决三个工程问题：存什么、何时提取、怎么回注。否则很快就会变成一份无法维护的偏好垃圾堆。

## 问题

散落在聊天记录、环境变量、插件配置里的“记忆”有几个典型坏处：

- 不可审计：用户不知道 Agent 记住了什么。
- 不可回滚：某次误写偏好会持续污染后续会话。
- 过度泛化：一句临时需求被当成永久偏好。
- 多用户串味：同一个 Agent 实例服务多人时，偏好互相覆盖。

## 做法：先跑通一条最小偏好闭环

### 1. 定义最小 schema

别一开始就做“用户画像”。先选 3–5 个高频且稳定的字段，例如：

- `tone`：回复风格
- `default_tool`：默认工具选择
- `constraints`：硬性约束（如“不要执行删除命令”）
- `avoid_topics`：避免讨论的话题

用 JSON Schema 约束，存储用 SQLite 的 `user_memory` 表，字段包括 `user_id, key, value, source, confidence, created_at, updated_at`。不要上向量库，等检索需求明确后再加。

### 2. 短期与长期记忆分离

短期记忆留在当前会话上下文；长期偏好落盘。不要把所有长期记忆都塞进 system prompt，而是按需检索。例如只有当用户提到“写脚本”“跑自动化”时，才查询 `default_tool` 和 `constraints` 并注入当前上下文。

### 3. 提取机制：规则优先，LLM 兜底

最稳定的做法是用规则拦截工具调用或用户明确指令。比如用户说“以后默认用 uv 管理 Python 依赖”，可以触发一个 `memory_upsert` 工具。对于模糊表达，再用 LLM 提取候选，但必须保留原文和会话 ID，不能只存总结。

在 OpenClaw 环境里，我建议把 `memory_search` 和 `memory_upsert` 做成一个 MCP server 暴露给 Agent、插件和自动化脚本，统一读写同一份存储，避免出现“插件记一份、Agent 记一份”的割裂。

### 4. 注入策略：分层注入

- 全局偏好：极少量硬约束放入 system prompt。
- 任务相关偏好：在工具调用前，通过 `memory_search` 检索并放入当前上下文。
- 用户显式查询：提供 `/memory list` 或 `memory_debug` 工具，让用户随时查看。

记忆内容要标注来源和更新时间，Agent 注入时优先使用高置信度、新近写入、显式确认过的条目。

### 5. 显式管理命令

至少提供三个能力：查看、删除、回滚。用户能说“忘掉我的默认工具偏好”或“回滚到上周三的版本”。这要求每次写入都有审计日志，最好支持版本号或简单 diff。

## 踩坑点

### 坑 1：把临时要求当永久偏好

“这次输出别用表格”如果被自动记为永久偏好，下次生成报告时会被错误抑制。解决方式：写入时必须带 `confidence` 和 `source`，只对明确说“以后”“默认”“总是”的表达提高置信度；临时指令不落库。

### 坑 2：全量注入污染上下文

把几条偏好全部放进 system prompt，短期看没问题，但上下文窗口是稀缺资源。偏好检索注入比常驻注入更可靠，尤其是 Agent 同时挂多个 MCP 工具时。

### 坑 3：多用户隔离缺失

如果你在服务器上部署 OpenClaw 给团队用，所有记忆必须带 `user_id` 或 `namespace`。否则 A 的“避免讨论股票”会变成 B 的硬约束。多用户场景下，提取和检索都要强制带用户维度。

### 坑 4：敏感信息自动落库

偏好中可能夹带身份、健康、财务等信息。自动提取时不要写入敏感字段，或者需要用户确认。存储层面至少做访问控制和加密，审计日志也不要记录完整原文。

## 可复用建议

- 从 3–5 个字段开始，跑通闭环再扩展。
- 写入加审计日志：谁、何时、因为哪句话、写入了什么。
- 提供 dry-run 模式：Agent 先建议写什么，用户确认才落库。
- 冲突策略：显式确认 > 最近写入 > 高置信度。
- 定期清理：过期、低置信度、长期未命中的偏好进入待删除队列。
- 用 MCP 统一记忆入口，避免插件和 Agent 各自维护一套状态。

## 总结

Agent 记忆系统的核心不是“让 AI 更像人”，而是工程上的可审计、可回滚、最小权限、按需注入。先做一个用户能查看、能删除、能追溯来源的最小记忆闭环，比一步到位做复杂图谱更实用。对 OpenClaw 实践者来说，MCP server + SQLite + 分层注入已经足够解决大多数“助手失忆”问题。
