最近社区里有个讨论很有意思：DeepSeek 一边被曝出 API 价格上调，一边继续把模型权重开源。有人觉得“涨价伤感情”，有人觉得“开源真香”，于是“又香又臭”的说法就传开了。先别急着下结论。涨价和开源很可能不是对立面，而是同一套商业与技术逻辑的左右手。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-22/9f2c5f1f70543279.png)

## 一、“涨价”涨的是服务费，不是模型本身

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-22/6aab0eaaf839806f.png)

很多人一听到“DeepSeek 涨价”，就理解成“模型卖贵了”。但严格说，这次价格调整主要发生在官方 API 这一层，而不是开源权重。

- API 是托管服务：你按 token 付费，官方来承担推理集群、显存调度、网络与可用性保障。
- 模型权重是“生产资料”：开源后你可以下载、量化、微调、本地部署，边际成本由自己承担。
- 调价通常不是一刀切：输入缓存命中、缓存未命中、输出 token、长上下文、并发场景，成本差异很大，官方往往会分开定价。

所以更准确的说法是：这是一次云服务价格调整，而不是软件许可证涨价。对使用官方 API 的用户影响明显；对自部署用户，几乎不改变。

## 二、开源不等于免费，更不能和免费服务划等号

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-22/b125b138fadbabb4.png)

开源模型很容易被误解成“所有东西都必须免费”。但在技术社区里，有两个概念需要区分：

- Open weights：开放权重，你可以下载、量化、微调、本地部署，甚至商用。
- Free API：免费或低价接口，本质是厂商在替你承担算力成本。

这两个东西的成本结构完全不同。权重一旦公开，后续分发的边际成本接近零；而 API 每多一次调用，都是实打实的 GPU 电费、显存占用与带宽消耗。

可以打个比方：菜谱公开，不等于餐厅免费管饭。拿到菜谱的人可以自己买菜做饭，成本自担；而餐厅提供座位、厨师、洗碗和稳定的出餐速度，当然要收费。开源权重与收费 API 的关系，大致就是这样。

## 三、为什么还要坚持开源：生态比单次收费更值钱

![img3](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-22/140f6c1d29ce98ec.png)

如果按短期商业直觉，既然要涨价，为什么不把模型闭源？因为开源收益不在账单的第一页。

1. 生态锁定：开发者基于开放权重做量化、微调、工具链和评测，逐渐形成事实标准。模型本身成为底座，周边生态会自动靠拢。
2. 社区反哺：开源社区会贡献推理优化、低比特量化、兼容层和部署方案，这些反过来降低官方技术成本。
3. 人才与注意力：工程师更愿意研究能下载、可复现的模型；开源是获取技术口碑和人才关注的高效方式。
4. 信任与安全：权重透明可审计，企业客户更容易做合规与风险评估，而不是面对一个黑箱 API。

从这个角度看，开源不是“亏本赚吆喝”，而是长期技术护城河。API 涨价与开源模型更新并行，并不矛盾。

## 四、涨价背后：推理成本是一道算力算术题

![img4](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-22/2f9802d231c8de6e.png)

为什么 API 会涨价？核心往往是推理成本上升，或者早期定价过低。大模型 API 的 token 经济学，比看起来复杂。

- 长上下文非常吃显存：KV cache 会随序列长度增长，同样一次调用，1k token 和 64k token 的显存占用差距巨大。
- 并发峰值要求冗余：为了稳定性和低延迟，服务商必须预留 GPU，闲时是空转成本，峰时需要弹性扩容。
- 缓存能省钱，但缓存不总是命中：输入缓存命中时几乎不用重算，未命中则要完整 prefill；如果大量用户都是低命中率长文本，成本会被明显拉高。
- MoE 架构虽然训练效率高，但推理时专家权重仍要占用显存，显存成本不能忽视。
- 一次推理分为 prefill 和 decode 两阶段：prefill 处理输入，算力密集；decode 逐 token 生成，显存带宽压力大。如果调价偏向输出 token 或缓存未命中，本质是在为最贵的资源消耗定价。

所以涨价常常不是“贪心”，而是把价格从获客期的不可持续水平，拉回能覆盖推理成本、保持服务稳定的区间。2024 年国内大模型价格战已经把 API 价格打到很低，部分价格甚至低于实际成本。现在回调，更像行业回归理性。

## 五、“又香又臭”的本质：分层服务正在形成

社区里“香”和“臭”同时存在，其实是因为用户需求已经明显分层。

- 对成本敏感、有工程能力的团队：开源权重很香。自己部署可以压成本、控数据、做私有化。
- 对稳定性和接入速度要求高的产品：官方 API 更省事，即使涨价也会继续用。
- 处于中间的用户最难受：既想省事，又对价格敏感。可以考虑缓存优化、缩短上下文、用更小的开源模型做前端路由。

所以不必把这次变化理解成“DeepSeek 变坏了”。更准确的说法是：服务分层正在形成。开源负责开放与生态，API 负责稳定与商业可持续，两条线并不互斥。

## 冷思考与实用建议

如果不想被单次涨跌牵着走，可以从三件事入手：

1. 算清自己的调用画像。先看缓存命中率、平均上下文长度、并发峰值。不同画像在调价中的感受差异可能超过 50%。
2. 把“开源权重”当作议价权。即便现在用 API，也可以定期测试开源模型在自己业务上的效果，别让架构被单一托管接口锁死。
3. 关注成本结构变化，而不只是价格数字。MoE、稀疏注意力、KV cache 压缩、量化部署这些变量，对长期成本的影响远比一次涨跌更大。

开源让模型不会被某家公司完全关进保险箱；涨价让 API 服务可以继续稳定运行。两者同时出现，不一定是“又香又臭”，更像是大模型商业化的必经路径。
