# Agent 本地文件操作安全加固：目录白名单设计与踩坑实录

## 背景：当脚本拥有了文件系统的“钥匙”

在 OpenClaw 等 Agent 框架中，通过 Function Calling 或 MCP 插件让 Agent 调用本地脚本、读写文件已经是家常便饭。比如一个自动化工作流中，Agent 需要将处理结果保存到指定文件夹，或者读取配置文件来生成下一步决策。

但问题也随之而来。如果 Agent 获得了完整的文件系统访问权限——哪怕是出于信任——一旦遇到错误的指令、幻觉生成的危险命令（例如拼接了 `rm -rf /home/user/*`），或者简单的一句“帮我把临时文件清理一下”，都可能带来灾难性的后果。即使是在纯内部、只有自己使用的项目里，写入了错误的位置也会花费大量时间排查。

**最小权限原则**同样适用于 Agent 工具：只开放必需的路径，其它一律拒绝。MCP 官方提供的 `filesystem` 工具已经内置了 `allowed_directories` 配置项，但很多场景下我们需要自己实现文件操作的 Tool——比如要读取专有格式、执行复杂的混合操作等。此时就需要自己加上目录白名单这道护栏。

## 问题：如何让一个 Python 函数只允许操作白名单目录？

目标很明确：定义一组允许访问的根目录，任何尝试在这些目录之外读写文件的操作都应当被拦截并抛出异常。

初看似乎很简单：判断目标路径的前缀是否在允许目录列表中即可。但真实工程中会踩到不少坑，我们需要处理符号链接、相对路径、路径规范化、跨平台差异等一系列细节。

## 实现：一个可复用的路径校验器

以下是一个经过实战检验的安全文件操作工具类的核心逻辑，使用 `pathlib` 和 `os.path.realpath` 来彻底解析真实路径。将该类作为所有文件 Tool 的基础设施。

```python
import os
from pathlib import Path
from typing import List, Union

class PathGuard:
    """文件访问白名单守卫"""
    def __init__(self, allowed_dirs: List[Union[str, Path]]):
        # 将所有允许目录转换为解析后的绝对路径集合
        self._allowed = set()
        for d in allowed_dirs:
            rp = Path(d).resolve(strict=False)
            self._allowed.add(rp)
    
    def validate(self, target: Union[str, Path]) -> Path:
        """校验路径，返回规范化的绝对路径；校验失败抛出 PermissionError"""
        try:
            # 1. 转为 Path 对象，并展开用户目录（如 ~）
            p = Path(target).expanduser()
            # 2. 解析为绝对路径（基于当前工作目录）
            p = p.resolve(strict=False) if not p.is_absolute() else p
            # 3. 关键：解析所有符号链接，获得真实路径
            real_p = Path(os.path.realpath(p))
        except Exception as e:
            raise ValueError(f"路径解析失败: {target}") from e
        
        # 4. 判断真实路径是否位于任一白名单目录下（包括子目录）
        for allowed in self._allowed:
            try:
                real_p.relative_to(allowed)
                return real_p  # 合法
            except ValueError:
                continue
        
        raise PermissionError(f"禁止访问路径: {target} (解析后: {real_p})")
    
    def safe_read(self, path: Union[str, Path], mode='r', encoding='utf-8') -> str:
        """安全读取文本文件"""
        safe_path = self.validate(path)
        with open(safe_path, mode, encoding=encoding) as f:
            return f.read()
    
    def safe_write(self, path: Union[str, Path], content: str, mode='w', encoding='utf-8'):
        """安全写入文件"""
        safe_path = self.validate(path)
        safe_path.parent.mkdir(parents=True, exist_ok=True)
        with open(safe_path, mode, encoding=encoding) as f:
            f.write(content)
```

在 OpenClaw 的 Tool 定义中，只需初始化一个全局的 `PathGuard` 实例，然后在 Tool 函数内部调用 `safe_read` / `safe_write` 即可。例如：

```python
from openclaw import tool

guard = PathGuard(allowed_dirs=['/home/user/project/data', '/tmp/agent_workspace'])

@tool
def append_to_log(content: str, filename: str = "output.log"):
    file_path = Path("/tmp/agent_workspace") / filename
    guard.safe_write(file_path, content, mode='a')
    return "写入成功"
```

## 踩坑点与应对

在实际使用中，以下几个问题最容易导致“白名单形同虚设”：

1. **符号链接绕过**  
   用户可能通过软链接将白名单目录下的文件指向 `/etc/passwd`。如果不调用 `os.path.realpath()`，仅做字符串前缀匹配或 `resolve()`（只处理相对路径和 `..`）无法解开软链。必须用 `realpath` 解析最终物理路径。

2. **相对路径与工作目录漂移**  
   多个 Tool 并发执行时，如果依赖当前工作目录，可能 A 工具把工作目录切走了，B 工具的相对路径就指向了意外位置。**始终将传入路径转为绝对路径**，并基于 `PathGuard` 实例化时记录的白名单绝对路径进行判断，不要依赖于 `os.getcwd()`。

3. **路径编码与大小写**  
   - Windows 不区分大小写，而 Linux 区分。若项目需要在两种系统上运行，可在比较前将 `real_p` 和 `allowed` 都转为小写（仅 Windows 下），避免 `DATA` 和 `data` 被判断为不同路径。
   - Windows 路径分隔符为反斜杠，使用 `pathlib` 可自动处理。

4. **目录末尾斜杠的迷惑行为**  
   用户可能传入 `/allowed_dir` 或 `/allowed_dir/`，后者在 `relative_to` 时可能引发微妙差异。统一用 `Path` 对象处理后，`relative_to` 不受末尾斜杠影响，但建议始终规范化。

5. **性能与异常审计**  
   每次文件操作都做 `realpath` 系统调用，对高频率小文件读写会有轻微开销。对于批量操作，可以在应用层缓存已校验的路径映射。另外，所有被拒绝的访问尝试都应该记录日志，方便后续排查是 Agent 幻觉还是人为误用。

## 可复用建议

- **封装为独立库**：将 `PathGuard` 抽离成团队内部 Python 包，所有文件类 Tool 统一依赖它。
- **配置化白名单**：通过环境变量 `ALLOWED_DIRS` 或 YAML 配置文件注入允许目录列表，不同环境（开发 / 生产）灵活切换。
- **集成到 MCP Server**：如果使用 MCP 的 `filesystem` server，可以直接通过 `allowed_directories` 参数实现同样的约束，避免自己重复造轮子。只有在需要自定义复杂操作且 MCP 不满足时才自己实现。
- **单元测试先行**：针对符号链接跨目录、`../` 逃逸、绝对路径与相对路径混合等场景写测试用例，确保校验器不被绕过。
- **日志与告警**：拒绝访问的记录最好推送至监控系统，当出现大量违规尝试时能及时发现异常行为。

## 总结

给 Agent 文件操作加上目录白名单并不复杂，但细节决定成败。看似简单的路径前缀匹配，在面临符号链接、并发工作目录、跨平台差异时很容易失效。实际工程中，推荐优先使用 MCP 官方提供的安全配置，若必须自建 Tool，请务必用 `realpath` 解析、封装可复用的校验器，并配合日志审计。

安全护栏不是束缚，而是让自动化脚本既能高效工作，又不用时刻担心误删文件的底气。
