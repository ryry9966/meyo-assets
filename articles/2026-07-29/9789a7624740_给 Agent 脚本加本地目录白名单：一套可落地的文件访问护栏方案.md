## 背景：Agent 的文件操作正在变得危险

如果你正在用 OpenClaw、MCP 或各种自动化 Agent 编排本地工作流，迟早会遇到一个两难问题：你想让脚本读写文件以完成实际任务，但又害怕它越界。典型的场景包括：

- 使用 MCP 的 `filesystem` server，允许大模型读写本地文件来生成报告、处理文档
- 将 Agent 接入 Shell 或 Python 执行器，让它“自动整理文件夹”
- 通过插件让 Agent 操作 Git 仓库、修改配置或清理缓存

只要给 Agent 文件系统权限，理论上它就能遍历你的 `~/.ssh`、读取环境变量文件、甚至删除整个项目目录。即便你信任模型意图，提示注入、幻觉路径、脚本 Bug 都可能把操作引向敏感区域。靠 prompt 里说“请只操作 /workspace 目录”是软约束，不是工程护栏。

在安全要求较高的内部工具中，我们需要把“目录白名单”做成硬限制：Agent 进程无论执行什么代码，都**只能看到并操作部分目录**，对其它位置无读无写。

## 问题：为什么 prompt 限制不够

很多早期的 Agent 实现依赖 prompt 约束文件访问边界，比如：“你只能读取 /data 下的文件”。但这对程序化操作完全不可靠。实际情况包括：

- 模型可能生成 `cat ~/.aws/credentials` 这类命令，只是因为训练数据里有
- 用 Python `os.listdir('/')` 或 `../` 路径穿越轻松绕过相对路径约束
- 多步骤任务中，Agent 可以读取配置决定下一步路径，而配置本身可能引入 `$HOME` 等变量
- 第三方工具（如 `pandoc`、`unzip`）在内部可能按照命令行参数写入任意位置

所以真正需要的是一种**操作系统级或运行时级**的强制隔离：即使 Agent 故意或无意执行越权操作，调用也会直接失败。

## 方案：三种工程化的白名单实现思路

下面给出三种不同侵入程度的做法，覆盖从轻量脚本到长期运行 Agent 的场景，你可以按需组合。

### 方案一：Python 运行时路径沙箱（适合 Python 执行器）

如果你的 Agent 通过 `exec()` 或 `subprocess` 执行 Python 代码，最简单的是在执行前打猴子补丁，替换内建的文件操作函数。

核心步骤：

1. 定义白名单路径集合，例如 `{"/workspace", "/tmp/agent_sandbox"}`，并全部解析为绝对路径。
2. 编写包装函数，对 `open`、`os.open`、`os.listdir`、`shutil.*` 等关键入口做路径校验。
3. 限制 `os.chdir` 只能切换到白名单内目录，避免后续相对路径绕过。
4. 对 `subprocess.Popen` 也要做一次参数扫描，提取出命令中的路径字符串，简单校验（更推荐配合方案三）。

关键代码片段：

```python
import os, builtins

SAFE_ROOTS = [os.path.abspath(p) for p in ["/workspace", "/tmp/agent_sandbox"]]

def is_safe(path):
    full = os.path.abspath(path)
    return any(full.startswith(root + os.sep) or full == root for root in SAFE_ROOTS)

real_open = builtins.open

def guarded_open(file, mode='r', *args, **kwargs):
    if not is_safe(file):
        raise PermissionError(f"Access denied: {file}")
    return real_open(file, mode, *args, **kwargs)

builtins.open = guarded_open
```

踩坑点：
- `os.scandir`、`pathlib.Path` 也需要处理，最好直接限制 `pathlib.Path` 的构造或操作方法。
- 某些第三方库可能直接调用 C 扩展（如 `numpy.load`），猴子补丁抓不到。这时需要配合方案三。
- 字符串 `mode` 里有 `'w'` 或 `'a'` 时，会触发文件创建，需确保父目录也在白名单（可由 Agent 自己建目录时校验）。

### 方案二：chroot / 容器 / macOS 沙盒（适合长期运行 Agent）

更可靠的办法是把整个 Agent 进程关进受限的文件系统视图里。

Linux 下最轻的做法是 **chroot** + `unshare`：

```bash
mkdir -p sandbox/{workspace,tmp}
unshare --mount --root=sandbox -- /bin/bash
```

如果 Agent 还需要访问 `/bin`、`/usr` 等系统文件才能运行，可以把最小需要的文件复制进去，或使用 overlayfs 构建精简根文件系统。但这对技能要求不低。

更实用的生产方案是用 **Docker 容器**挂载指定目录为读写，其余为只读或无挂载：

```yaml
services:
  agent:
    image: your-agent-image
    volumes:
      - ./workspace:/workspace:rw
      - /tmp/agent_tmp:/tmp:rw
    read_only: true
    tmpfs:
      - /run
      - /var/tmp
```

**macOS 开发环境**可以用 `sandbox-exec` 配置文件，以声明式方式限制文件访问。比如只放行项目目录和临时目录：

```scheme
(version 1)
(allow default)
(deny file-read* file-write* (subpath "/"))
(allow file-read* file-write* (subpath "/Users/me/projects/agent_workspace"))
(allow file-read* file-write* (subpath "/tmp"))
```

然后把 `sandbox-exec -f profile.sb your-agent-binary` 作为启动命令。

踩坑点：
- chroot/sandbox-exec 下如果 Agent 调用外部命令（git, python），必须确保这些命令在受限环境中可达且可执行；缺失共享库会导致奇怪的段错误，需用 `ldd` 或 `otool -L` 排查。
- 容器内还要注意 `/proc`、`/sys` 信息泄露问题，安全要求高时用 `--security-opt=no-new-privileges` 并隐藏 `/proc` 的敏感部分。

### 方案三：MCP filesystem server 加固（针对使用 MCP 的场景）

如果你已经在用 Anthropic 官方的 `@modelcontextprotocol/server-filesystem`，它的 README 里提供了一个命令行参数直接指定允许的目录：

```bash
npx -y @modelcontextprotocol/server-filesystem /workspace /tmp/agent_io
```

这会告诉 server 只暴露这些目录给工具调用。原理是 server 内部对每一个工具函数（`read_file`、`write_file`、`list_directory` 等）强制做绝对路径校验，拒绝超出范围的路径。

值得注意的实践：
- 给出的路径必须是绝对路径，且不要以 `/` 结尾，否则有些版本边界判断失效。
- 如果你的 Agent 中同时存在 shell 执行器，必须**独立限制 shell 的工作目录**，否则 shell 里仍可越过 MCP 直接访问文件。具体做法：设定 `cwd` 为白名单内部目录，并用前述 Python 或沙盒手段限制 shell。
- 路径穿越测试要覆盖 `../`、符号链接、硬链接等。可以用 `ln -s /etc/passwd /workspace/link` 测试，确保 MCP 工具拒绝追踪外部符号链接（大部分实现默认不跟随，但明确测试为好）。

## 可复用建议

1. **分层防御**：不要在单一层赌命。软件层目录校验 + 进程沙箱/容器 + 最小权限用户（如 nobody）组合使用。
2. **让失败可见**：遍历测试目录边界，故意在 Agent 指令里插入 `cat /etc/shadow`，观察是否抛出明确拒绝错误且不泄露敏感内容。
3. **白名单尽量收窄**：只给任务真正需要的目录，不要为了方便把整个 `$HOME` 放进去。
4. **自动化测试脚本**：写一个专门的越权测试集，CI 里跑，确认依赖升级后白名单机制未被破坏。
5. **日志中脱敏**：拒绝访问时，日志里只记录被拒绝的路径，不要 dump 文件内容或环境变量。

## 总结

Agent 文件访问控制不是可选项，而是从实验性 prototype 走向可信任工具的关键一步。通过组合 Python 运行时拦截、容器隔离、MCP 内置目录限制这三种手段，我们可以把“只能操作特定目录”变成工程硬约束，而不是 prompt 里的客气话。实现成本不高，但能防止大量潜在的数据泄漏和系统损坏事故。下次当你准备让 Agent 直接组织你的下载文件夹时，不妨先花半小时加一道白名单——你的 `~/.ssh` 会感谢你。
