## 背景：当 Agent 能执行本地脚本

OpenClaw 这类 Agent 框架通过 MCP 等协议接入了文件系统、命令行等工具，让自动化脚本可以读写本地文件。但一旦 Agent 有了执行 `rm -rf` 的权限，一次错误的推理就可能吞噬整个项目目录或更危险。即便不是恶意行为，AI 生成的路径拼接也极易出现“不小心多删了文件”的情况。

工程上我们需要一条明确的“文件访问护栏”：只允许 Agent 操作指定目录，其它路径一律拒绝。这就是本地目录白名单的核心诉求。

## 问题：自由度过高的文件工具

默认情况下，MCP 的 `filesystem` 服务器如果没有配置安全参数，可能暴露整个用户目录甚至系统目录。例如一个清理临时文件的任务，Agent 可能会写出：

```bash
rm -rf /tmp/logs/2024*
```

如果 `path` 参数被 AI 幻觉或错误的上下文注入篡改为 `/`，后果不堪设想。即使我们自己编写的自定义插件直接调用了 `open()` 或 `shutil.rmtree()`，若未做路径校验，也会给系统带来风险。

## 做法：在工具层实现目录白名单

### 1. 基于 MCP Filesystem Server 的快捷方案

若你使用官方的 MCP filesystem 服务器，可以在 `claw.conf` 的 `mcp_servers` 配置中直接限制其可访问目录：

```json
{
  "filesystem": {
    "command": "npx",
    "args": [
      "-y",
      "@anthropic/mcp-server-filesystem",
      "--allowed-directories", "/home/user/project",
      "--allowed-directories", "/home/user/project-data"
    ]
  }
}
```

重启 OpenClaw 后，该 MCP 服务器提供的所有文件工具（`read_file`、`write_file`、`list_directory` 等）都会在服务端校验路径，只允许白名单内的目录访问。这是对内置工具最“零侵入”的安全加固。

### 2. 自定义工具的白名单检查器

如果要自己编写文件操作工具（如一个 Python 插件），可以封装白名单验证逻辑：

```python
import os
from typing import List

class FileAccessGuard:
    def __init__(self, allowed_dirs: List[str]):
        # 预解析白名单的真实路径，避免符号链接干扰
        self.allowed_real = [
            os.path.realpath(d) + os.sep for d in allowed_dirs
        ]

    def is_allowed(self, target_path: str) -> bool:
        # 1. 转换为绝对真实路径（消解符号链接、.. 等）
        real_target = os.path.realpath(target_path)
        # 2. 检查是否以某个白名单目录开头
        for allowed in self.allowed_real:
            if real_target.startswith(allowed):
                return True
        return False

# 使用示例
guard = FileAccessGuard(["/home/user/project"])
if guard.is_allowed("/home/user/project/sub/file.txt"):
    with open("/home/user/project/sub/file.txt", "r") as f:
        ...
else:
    raise PermissionError("Access denied")
```

将该 `FileAccessGuard` 注册到 OpenClaw 的插件生命周期中，每个文件操作调用前都做一次检查即可。

## 踩坑实录

### 符号链接穿越

最容易被忽略的绕过方式：在白名单目录内创建一个符号链接指向 `/etc`，然后 Agent 通过该链接读取外部文件。`os.path.abspath` 不会解析符号链接，所以必须使用 `os.path.realpath`。务必先 `realpath` 再比较。

### 相对路径与当前工作目录

Agent 工具可能接受相对路径，比如 `"../../.bashrc"`。如果代码里直接用 `os.path.abspath`，结果会依赖当前工作目录。正确做法同样是 `os.path.realpath`，它可以同时解析相对路径和符号链接。另外，建议工具本身只接受绝对路径，或者将相对路径视为白名单目录内的相对路径（通过与白名单拼接后再校验），避免工作目录被意外篡改。

### 路径分隔符与大小写

Windows 上盘符和反斜杠会带来问题。跨平台时可用 `os.path.normcase(os.path.realpath(p))` 统一规范化后比较。Mac/Linux 文件系统默认区分大小写，但也要留意部分分区可能以大小写不敏感方式挂载。

### 多白名单目录的 `startswith` 陷阱

```python
# 白名单：/home/joe 和 /home/joe-ext
target = "/home/joe-ext/file"
# 错误：target.startswith("/home/joe") 会返回 True，但实际允许了不该访问的目录
```

解决方案是在白名单目录后统一添加 `os.sep`，保证只匹配完整目录路径。

## 可复用的工程建议

- **抽象成装饰器或中间件**：不要在每个文件操作函数里重复写校验逻辑。用 Python 装饰器或 Go 的中间件模式，将白名单检查分离出来，方便审计和修改。
- **可配置的白名单**：通过环境变量或配置文件声明白名单，避免硬编码。这样开发、测试、生产环境可以使用不同的白名单范围。
- **拒绝日志**：对每次拒绝访问记录日志，包含请求路径、真实路径、时间戳、触发的 Agent 任务 ID，方便事后排查误报或攻击尝试。
- **最小权限启动**：运行 OpenClaw 实例的进程本身也应限定系统权限，例如使用容器技术或专用的用户账号，让文件系统权限与白名单形成双重保险。

## 总结

给自动化脚本加上目录白名单，并不是不信任 AI，而是对工程风险的负责。通过 MCP 服务器的内置参数可以快速起步，自定义工具时则用 `realpath` + 前缀匹配来抵挡符号链接与路径遍历。加上日志和可配置化，这些护栏就能在不降低开发效率的前提下，把文件操作约束在一个可控的安全边界内。
