## 费马大定理：一个让数学家追了358年的目标

在讨论大模型到底跑出了什么之前，有必要先看明白这个命题的分量。

- **一句话版本**：当整数 n>2 时，方程 xⁿ + yⁿ = zⁿ 没有正整数解。
- **安德鲁·怀尔斯的证明**：1994年，怀尔斯用模形式、椭圆曲线、伽罗瓦表示等高等工具，给出了第一个严谨的证明。整篇论文长达上百页，建立在数十位数学家近百年的工作之上。
- **为何难**：费马大定理并非一道能靠“穷举”或“模式匹配”解决的题。它需要构造全新的数学对象，连接表面上毫不相干的领域，并在每一步都做到逻辑绝对自洽。任何一个细小的漏洞，都可能导致整个证明崩塌。

换句话说，这不是一道奥林匹克竞赛题，而是一次从地基直到穹顶的理论构建。哪怕对人类数学家而言，理解怀尔斯的证明都需要数年的专业训练。把这样一座山丢给一个没有任何先天数学直觉的语言模型，本身就意味着：失败的概率远大于成功。

## GPT-5.6 Sol：为“慢思考”而生的推理引擎

GPT-5.6 Sol 的代号暗示它属于当前最前沿的“推理模型”家族。和普通的聊天模型不同，这类系统被设计成可以长时间、多步骤地内部推演，类似 o1、o3 等已公开的推理架构。

- **隐藏思维链**：模型在给出最终回答之前，可能已经在后台生成了数万、甚至数百万 token 的“内心独白”。这些链式推理内容不会被完整展示，但每一段都会消耗算力、产生费用。
- **自我纠错与回溯**：推理模型会尝试多条路径，一旦发现矛盾，就自动回退、修正假设。这种机制极具探索价值，但也容易被自相缠绕的逻辑死结拖入循环。
- **不设限的代价**：开发者没有给 API 调用设置 max_tokens 或 timeout，相当于把一匹烈马解开了缰绳。33 小时的奔跑中，模型可能在反复生成相似的路径，也可能在某个错误的等价变换里越陷越深。

这就引出一个根本问题：我们需要的是“不停思考的 AI”，还是“可持续思考的 AI”？

## 33 小时的真相：token 在燃烧，逻辑在兜圈

从有限的技术细节和同类推理模型的运行特征推测，这 33 小时里至少发生了以下情况：

- **Token 爆炸**：如果模型平均每秒输出 50 个推理 token（保守估算），33 小时就是近 600 万 token。作为参照，怀尔斯证明全文如果用 token 计算，大概在 15~25 万 token 之间。模型输出的长度可能已经远超证明本身。
- **成本飞升**：前沿推理模型的 API 定价通常在每百万输入 token 10~20 美元，输出 token 可能达到 60~100 美元。假设输入部分占比较小，光是输出成本就可能高达数千美元。一次实验烧掉一个月的云预算绝非夸张。
- **逻辑回路**：模型很可能在类似“假设存在一个解，则构造椭圆曲线 E……”和“由模性定理，E 有对应的模形式……”的循环里不断打转，反复生成同一个中间结论却无法完成归纳。
- **没有形式化验证**：LLM 输出的只是一段文本，不是可以在 Lean、Coq 等证明助手中检查的形式化证明。即便模型在文本层面“看起来”漂亮地收尾了，它也并未真正完成数学意义上的证明。

## 强制终止：是保护，也是现实约束

系统之所以被强制终止，并不只是“服务器抽风”，而是因为在生产级 AI 基础设施里，这类保护策略是预设的。

- **API 超时限制**：大多数云端模型调用都有硬性 time limit，即便开发者没设置，平台也会在某个阈值（比如 10 分钟、60 分钟）直接切断连接。33 小时已经远超合理范围，触发了底层的资源保护。
- **配额与风控**：账户的每分钟 token 数、每小时调用次数、当月总费用都有限额。连续数万秒的满负载生成会被风控系统判定为异常行为，自动挂起进程，以避免冲击同一集群上的其他租户。
- **避免死循环**：从工程角度，推理模型一旦陷入“没有收敛迹象的链式输出”，自动终止是一种止损手段。否则它会像一个失控的打印程序，不断吐出重复的推理碎片，直到存储和算力耗尽。
- **商业逻辑**：“无限思考”的模型在技术上可行，但经济上不可持续。如果不加限制，一两个用户就可能拖垮整个服务，这显然不符合任何云厂商的长远利益。

这次实验的结局，与其说暴露了模型的“缺陷”，不如说是一次现实的成本课：通用大语言模型的无约束探索，并不适合那些需要极深结构洞见的数学问题。

## 大模型真能成为数学研究者吗？

冷静下来看，大语言模型在数学上的能力定位已经比较清晰。

1. **辅助猜想与直觉启发**：LLM 可以基于已有知识，给出可能的等价命题、推广方向，甚至发现人类容易忽略的模式。这更像是“超强文献检索 + 策略提示器”，而非独立研究者。
2. **形式化中间步骤**：目前最有希望的路径是“神经符号系统”——由 LLM 生成非正式证明思路，再通过 Codex、GPT 的代码能力翻译成交互式定理证明器的语言，由证明助手逐行核验。DeepMind 的 AlphaProof 等已经在这条线上做出了实质进展。
3. **无法替代深层结构创造**：费马大定理的证明需要“创造一条通向无人之地的桥梁”，而非在已知定理的森林里找一条最短路径。目前没有任何证据表明纯语言模型具备这种结构层面的创造力。符号系统强于验证，大模型强于联想，两者尚未融为一体。

这次 33 小时的狂奔，就像把一个拥有超强记忆力和联想力的助理丢进图书馆，告诉他“解决最难的数学问题”，但没给他任何形式化验证工具、也没有时间预算。结果可想而知。

## 三则冷思考

如果不想让自己的推理实验也变成一次昂贵的烟花，下面几条务实的思路值得参考。

- **给推理设定“沙箱边界”**：在任何长程探索任务之前，明确 max_tokens、timeout 以及成本上限。可以把长时间思考拆分成多个阶段，每个阶段结束后由人工或辅助模型评估中间结果，再决定是否继续。
- **用形式化验证兜底**：对于数学、逻辑类的硬核问题，输出一段流畅的论证是不够的。必须把推理结果对齐到 Lean、Coq 或 Isabelle 等系统里，让机器做最终裁决。大模型负责“想”，证明助手负责“判”，这才是当前最稳健的组合。
- **尊重问题的复杂度**：不是所有问题都适合用“烧 token”来解决。如果一个问题的已知证明需要组合多个世纪的深层次理论进展，就做好预期管理——大模型可以被视作启发式引擎，但离“自动化数学家”还有漫长的路。
