## 背景：为什么需要关心 Agent 的文件访问边界？

越来越多的自动化工具、MCP 服务器和自定义 Agent 脚本需要直接读写本地文件系统——导出数据、处理日志、管理本地知识库，这些场景已经常见。如果不加限制，一个工具往往能够访问整个文件系统。这意味着：误写系统配置、意外泄露敏感文件、或因为一个 prompt 就让脚本读到你不想暴露的目录，这些风险真实存在。

工程上有一条原则：最小权限。Agent 调用的脚本只应访问它必须碰的目录，其他区域即使“可能用不到”，也不应该被允许。给自动化脚本加一个本地位录白名单，能以极低的成本拦住大部分非预期行为。

这篇文章不堆砌概念，直接给出一个可落地的 Python 实现，面向 OpenClaw、MCP 工具开发者及需要与文件系统打交道的自动化实践者。

## 问题描述

假设你写了一个 MCP 工具，允许智能体读取日志文件来诊断问题。你理想中它只访问 `/var/log/myapp`，但实际调用时 prompt 可能传入了 `../../etc/passwd` 或符号链接绕到了 `/home/user/.ssh`。没有约束，工具会忠实地返回文件内容——后果可大可小。

一个简单有效的防线：在工具入口处强制校验访问路径，只允许落在预先配置的目录集合内。否则直接拒绝，并记录审计日志。

## 做法：从配置到执行的三步护栏

### 1. 定义白名单配置
通过环境变量 `ALLOWED_DIRS` 指定逗号分隔的允许目录，例如：
```
ALLOWED_DIRS=/var/log/myapp,/data/agent-workspace
```
这样做的好处是与代码解耦，容器化部署时方便切换。

### 2. 路径安全校验函数
下面这段 Python 代码实现了路径规范化、符号链接解析和白名单检查。

```python
import os
import sys
from pathlib import Path

def load_allowed_dirs() -> list[Path]:
    raw = os.getenv("ALLOWED_DIRS", "")
    if not raw:
        # 白名单为空时默认禁止所有文件访问，避免疏漏
        return []
    dirs = []
    for part in raw.split(","):
        part = part.strip()
        if part:
            # 解析为绝对路径并展开符号链接
            resolved = Path(part).resolve()
            if not resolved.is_dir():
                raise ValueError(f"配置的目录不存在或不是目录: {resolved}")
            dirs.append(resolved)
    return dirs

def check_path_in_whitelist(target: str | Path) -> Path:
    """
    校验目标路径是否在白名单内。
    成功时返回规范化后的绝对路径，失败抛出 PermissionError。
    """
    allowed = load_allowed_dirs()
    # 绝对化并解析所有符号链接
    target_resolved = Path(target).resolve()

    # 检查是否在任一允许目录下
    for parent in allowed:
        try:
            target_resolved.relative_to(parent)
            return target_resolved
        except ValueError:
            continue
    raise PermissionError(f"拒绝访问: {target} (不在白名单目录中)")
```

关键点：
- 使用 `Path.resolve()` 解决符号链接和相对路径问题，这是防绕过的核心。
- 用 `relative_to` 判断路径是否在允许目录树下，逻辑清晰，Python 3.9+ 可直接用。
- 如果白名单未配置，直接禁止所有访问，这是安全的默认行为。如果你的场景需要“仅当配置了才生效”，可改为无条件允许，但务必谨慎。

### 3. 在工具层集成
对于 MCP 工具或自动化脚本，只需在文件读写前调用 `check_path_in_whitelist`。例如：

```python
def read_file_safe(raw_path: str) -> str:
    safe_path = check_path_in_whitelist(raw_path)
    return safe_path.read_text(encoding="utf-8")
```

所有文件系统入口都经过这个统一函数，代码改动小，安全收益明确。建议额外增加日志记录被拒绝的访问，便于发现不当调用或潜在攻击尝试。

## 踩坑实录

在实际部署中，有几个坑需要提前避开：

- **符号链接原地绕路**：直接使用 `os.path.realpath` 或 `Path.resolve()` 是必须的。切忌使用未经解析的路径做前缀匹配，否则一个指向 `/etc` 的象征链接就能轻松跳出白名单。
- **相对路径和工作目录**：Agent 运行时的当前工作目录可能出乎意料。必须先在代码中转换成绝对路径，并且尽量统一设置 `cwd` 或不依赖它。
- **白名单配置缺失**：线上忘记设置环境变量，导致全部请求被拒。建议在服务启动时显式打印有效的白名单目录，并在日志中告警。如果业务允许，可设置一个最小默认目录而非直接拒绝所有。
- **性能考量**：每次文件操作都做磁盘 `resolve`（尤其是符号链接解析）可能带来额外 IO。白名单目录不多时，这个开销可忽略；若文件操作极为频繁，可以缓存已解析的盘符/挂载点作为辅助，但注意符号链接的变更。
- **跨平台分隔符**：使用 `pathlib` 基本能统一处理，但要小心 Windows 上盘符和长路径问题，避免硬编码正斜杠。

## 可复用的工程建议

1. **抽象成可复用的中间件**：将路径校验抽成装饰器或高阶函数，所有文件操作类工具统一调用，避免散落校验逻辑。
2. **记录拒绝事件**：无论是日志还是指标，记录什么路径、被谁请求、何时被拒，这能帮你在被攻击或误配置时快速定位。
3. **测试覆盖**：编写单元测试，覆盖符号链接绕过、相对路径、白名单为空、深层子目录等场景，确保升级时不退化。
4. **与配置中心配合**：不仅是环境变量，也可以从配置中心动态加载目录列表，方便运维调整。
5. **文件写入也需保护**：权限检查不仅适用于读操作，写操作同样凶险，务必同样套用白名单。

## 总结

给自动化脚本加一个本地目录白名单，不是银弹，但它是在没有专用沙箱的情况下最容易落地的一层防护。几十行代码就能让 Agent 无法越雷池半步，特别适合内部工具、MCP 服务器、OpenClaw 插件等非直连外部环境的场景。

最小权限不是一句口号，是每一个文件路径入口都先经过“这是你应该碰的吗”的一问。动手改几行，收益远大于成本。
