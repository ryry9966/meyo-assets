## 背景

在 OpenClaw 的日常使用中，我们越来越多地让 Agent 通过 MCP 工具或插件去执行本地文件操作——读取分析日志、生成报表、整理归档目录，甚至调用脚本处理批量文件。而一旦把文件系统的写入、删除能力交给大模型驱动的自动化流程，安全问题就不再只是“别把 rm -rf 拼错”这么简单。

一个典型的场景：Agent 根据自然语言指令操作文件，例如“把当前项目里的临时文件清理一下”。如果没有访问边界控制，Agent 很可能因为理解偏差或 prompt 注入，删掉上级目录的构建缓存、用户文档，甚至关键的系统配置。即便只开放了读取，也可能把 ~/.ssh 或/etc 下的内容泄露到日志里。

于是，一个工程上可行且成本最低的方案浮出水面：**给所有文件访问工具强制加上目录白名单**，只允许脚本在指定范围内读写。本文会结合在 OpenClaw 中接入 MCP 文件操作插件的实践，给出可复现的护栏实现方式。

## 问题拆解

简单来说，我们需要满足三个目标：

1. **路径规范化**：所有传入工具的路径，统一解析为绝对路径，消除符号链接、相对路径和 “..” 穿越带来的不确定性。
2. **白名单判定**：检查最终的绝对路径是否落在预设的一个或多个本地目录之内。
3. **彻底拒绝**：一旦路径越界，直接抛出错误并记录日志，而不是静默放行。

这看起来是经典的“路径前缀检查”，但实际落地时踩坑不少——符号链接、Windows 盘符、commonpath 的细微行为，都会让看似严密的逻辑瞬间失效。

## 做法与步骤

### 1. 设计白名单配置

在 MCP 插件（或 OpenClaw 工具层）的配置文件中声明允许访问的根目录列表，例如：

```json
{
  "allowed_roots": [
    "/home/user/projects/agent-sandbox",
    "/tmp/agent-workspace"
  ]
}
```

同时建议增加一个 `allow_writable` 布尔值，方便在某些场景下仅开放只读。

### 2. 实现路径校验器

用 Python 实现一个核心校验函数（其他语言思路一致）：

```python
import os
from pathlib import Path

ALLOWED_ROOTS = [
    "/home/user/projects/agent-sandbox",
    "/tmp/agent-workspace"
]

def validate_path(user_input: str) -> Path:
    # 将用户输入的相对路径基于统一的安全工作目录转为绝对路径
    safe_cwd = "/tmp/agent-default"  # 避免相对路径回退
    raw_path = Path(user_input)
    if not raw_path.is_absolute():
        raw_path = Path(safe_cwd) / raw_path

    # 关键：解析所有符号链接，得到真实路径
    try:
        resolved = raw_path.resolve(strict=False)
    except (OSError, RuntimeError) as e:
        raise ValueError(f"路径解析失败: {e}")

    # 检查是否在任一白名单目录内
    for root in ALLOWED_ROOTS:
        try:
            # 使用 os.path.commonpath 避免字符串前缀误判
            common = os.path.commonpath([str(root), str(resolved)])
            if common == os.path.normpath(root):
                return resolved
        except (ValueError, TypeError):
            continue

    raise PermissionError(f"访问拒绝: {resolved} 不在允许的目录内")
```

### 3. 集成到 MCP 工具

假设我们为 OpenClaw 提供了一个 `file_read` 和 `file_write` 的 MCP 工具，只需在工具处理函数入口调用 `validate_path`，并返回 `Path` 对象给后续操作。写文件前可额外检查 `allow_writable`。

### 4. 边界情况处理

* **相对路径**：统一补全到安全 CWD（通常是 tmp 下的一次性目录），避免“./../../etc”这样的回溯。
* **符号链接**：即使白名单目录里的软链接指向外部，通过 `resolve()` 得到的真实路径也会被正确拦截。这正是必须使用 `realpath` 而非简单字符串匹配的原因。
* **Windows**：使用 `os.path.realpath` 或 `pathlib.resolve`，同时注意盘符大小写和长路径前缀。
* **无意义路径**：空字符串或不存在文件也要进入校验，防止后续报错信息意外暴露路径信息。

## 踩坑点记录

1. **os.path.commonpath 的“坑”**  
   在 Python 3.5～3.8 中，`commonpath` 对跨盘符路径会抛出 ValueError，我们正好利用它来做兜底，但如果不想依赖异常流控，最好额外加上判断。另外，它只返回共同前缀，直接用 `root == common` 可能误判：`/home/user/projects` 与 `/home/user/projects-backup` 的 common 是 `/home/user/projects`，后者会被错误放行。解法是在比对前强制对 root 做 `os.path.normpath`，并确保 common 完全等于 root，而不是以 root 开头。

2. **resolve(strict=False) 的副作用**  
   如果路径包含不存在的中间目录，`resolve(strict=False)` 仍会返回一个想象中的绝对路径，可能绕过后面的白名单？实际上不会，因为只要解析后的路径以白名单根开头且文件操作时系统还会返回“不存在”，但至少不会访问到奇怪位置。更严谨的做法是：先解析父目录的 realpath，再拼接最后的文件名一并检查。

3. **硬链接**  
   硬链接指向的 inode 相同，路径可能位于不同目录。如果 Agent 先写了一个允许目录下的硬链接，再通过该硬链接写入文件，真实路径是在白名单内的，风险可控；但如果恶意构造硬链接绕过写入限制，这属于操作系统层面的权限问题，护栏不应作为唯一防线。

## 可复用建议

* **抽象为独立中间件**：将校验逻辑封装成 `FileAccessGuard` 类，供各 MCP Server 复用，避免每个工具都复制一遍代码。
* **增加操作审计**：在每次文件访问日志中记录原始请求路径、真实路径、发起时间，便于排障和溯源。
* **最小权限原则**：白名单目录尽量细化到具体项目目录，不要直接放行 `/home` 这样的宽泛目录。
* **定期检测**：在 Agent 启动时遍历白名单目录，验证它们存在且无异常软链接，必要时自动收紧策略。
* **结合沙箱**：目录白名单是软件层面的约束，对高风险任务仍建议结合 Docker 或 VM 级别的沙箱，形成纵深防御。

## 总结

给 Agent 的自动化脚本添加文件访问护栏，并不是要造一个无懈可击的沙箱，而是用最低的实施成本，为常见的“跑偏”指令和越权访问树起一道有效的屏障。通过目录白名单 + 路径规范化，我们可以让 Agent 在划定的圈子里放心工作，同时显著降低误操作和指令注入带来的数据安全风险。

在 OpenClaw 的插件生态中，遵循这一模式的 MCP 文件工具会变得越来越常见。下次当你准备让 Agent 接管本地文件处理之前，不妨先问自己一句：它的工作区，真的被圈好了吗？
