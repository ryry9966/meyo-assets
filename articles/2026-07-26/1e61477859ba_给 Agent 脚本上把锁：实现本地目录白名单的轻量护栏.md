## 背景：当 Agent 的手可以伸向任何文件

给 AI Agent 一个 `read_file`、`write_file` 或者 `run_shell` 工具，它就能替你整理下载文件夹、批量处理 CSV、生成项目模板。然而，它也能轻易读取 `~/.ssh/id_rsa` 或者 `~/.aws/credentials`，甚至一个 `rm -rf ~/` 直接清空家目录——无论是有意还是“理解偏差”，风险都真实存在。

很多人直接把 Agent 运行在 Docker 或虚拟机里，用 OS 级沙箱兜底。这当然安全，但开发调试、临时任务需要频繁与本地文件交互时，启动容器的成本就显得笨重。更贴近日常的是：在本地跑 Agent 脚本，但只让它触碰指定目录，就像一个加了白名单的施工现场。

这篇文章记录一种轻量、可复用的方案：**用 Python 路径规整加白名单检查，给 Agent 的文件操作带上“护栏”**，无需依赖容器。

## 问题拆解：为何不能只靠开发者自觉

假设你给 Agent 开放了这样一个工具函数：

```python
def read_file(path: str) -> str:
    with open(path, 'r') as f:
        return f.read()
```

Agent 调用时传入 `path="~/.ssh/config"` 或 `"/etc/passwd"`，系统照单全收。直接在函数里硬编码“不允许访问隐藏目录”吗？太脆弱。可行的思路是：**所有文件路径先规范化为绝对路径，然后判断它是否落在允许的目录树内**，并对符号链接、`..` 等诡计做防御。

## 实现步骤：一个可嵌入 Agent 工具的 Guard

### 1. 核心组件：路径白名单校验器

用 Python 的 `pathlib` 可以很干净地实现。

```python
from pathlib import Path
from typing import List, Optional

class PathGuard:
    def __init__(self, allowed_dirs: List[str]):
        # 将配置目录全部解析为绝对路径，并消除符号链接
        self.allowed = [Path(d).resolve() for d in allowed_dirs]

    def validate(self, target: str) -> Path:
        # 解析为绝对路径，并展开用户波浪号、消除符号链接和../
        resolved = Path(target).expanduser().resolve()
        # 检查是否在任一白名单目录之内
        for base in self.allowed:
            try:
                resolved.relative_to(base)
                return resolved
            except ValueError:
                continue
        raise PermissionError(
            f"Access denied: {resolved} is outside allowed directories."
        )
```

这里的关键点是 `.resolve()`：它会将符号链接转换为真实路径，并折叠 `..`，避免通过软链接跳出沙箱。`.relative_to()` 在判断 “是否在某个目录下” 时非常可靠。

### 2. 封装安全的文件操作

不要直接把 `open`、`os.listdir` 等暴露给 Agent，而是在 Guard 基础上封装一层最小权限函数。

```python
class SafeFileOps:
    def __init__(self, guard: PathGuard):
        self.guard = guard

    def read_text(self, path: str) -> str:
        safe_path = self.guard.validate(path)
        return safe_path.read_text(encoding='utf-8')

    def write_text(self, path: str, content: str) -> None:
        safe_path = self.guard.validate(path)
        safe_path.write_text(content, encoding='utf-8')

    def list_dir(self, path: str) -> List[str]:
        safe_path = self.guard.validate(path)
        if not safe_path.is_dir():
            raise NotADirectoryError(f"{safe_path} is not a directory.")
        return [p.name for p in safe_path.iterdir()]
```

这些函数可以进一步捕获异常、记录日志，以便 Agent 理解权限拒绝的原因并给出反馈。

### 3. 集成到 Agent 工具链

以常见的 LangChain 工具为例：

```python
from langchain.tools import tool

guard = PathGuard(allowed_dirs=["/home/user/projects/sandbox", "/tmp/agent_work"])
ops = SafeFileOps(guard)

@tool
def read_file(path: str) -> str:
    """读取指定文本文件内容，仅限沙箱目录。"""
    return ops.read_text(path)

@tool
def write_file(path: str, content: str) -> str:
    """写入文件，仅限沙箱目录。"""
    ops.write_text(path, content)
    return "写入成功"
```

如果你在使用 OpenClaw 或类似的 Agent 框架，同样可以将这些函数注册为可调用工具，并把白名单目录通过配置文件注入，实现“零信任、最小权限”原则。

## 踩坑点

1. **符号链接穿透**  
   只用 `os.path.abspath` 而不 resolve，无法防御软链接指向白名单外的目标。务必 `.resolve()`。但注意，如果白名单目录本身是符号链接，需要提前 resolve 或允许 `relative_to` 在 resolve 前后都匹配。

2. **Windows 盘符和大小写**  
   在 Windows 上，`Path.resolve()` 会将路径转换为 `WindowsPath`，盘符大写，但大小写不敏感。如果你的白名单 `D:\sandbox` 与实际盘符大小写不同，需要统一转 `str(Path).upper()` 比较，或者在配置时同样 resolve 后适配。

3. **Windows 下的 `相对路径` 与 `resolve` 的当前工作目录**  
   `resolve()` 依赖当前工作目录（cwd）。若 Agent 工具可能改变 cwd（如通过 Shell 工具），传给 Guard 的路径可能和预期不一致。最好在 Agent 初始化时设定 cwd 到白名单根目录，并且所有路径校验都在同一个进程中，避免意外。

4. **并发读写与竞态**  
   Guard 只在调用时检查路径合法性，不提供文件锁。如果多个 Agent 工具并发操作同一文件，需要额外的文件锁或事物控制，但不属于护栏职责范围。

5. **白名单过于宽泛**  
   如果允许根目录 `/`，护栏形同虚设。最佳实践是：每个任务一个临时工作区，任务结束后清理或归档。工具目录之间应显式列出，不允许 `..` 跳出。

## 可复用建议

- **最小权限工具集**  
  不要给 Agent 暴露能够执行任意命令的 `subprocess`，至少也要带上 `shell=False` + 严格的命令参数过滤。文件操作同理，只开放 `read_text`、`write_text`、`list_dir` 等必要方法，禁止 `delete`、`chmod` 等破坏性操作，除非任务确实需要，并给予用户确认机制。

- **配置驱动**  
  将白名单目录、允许的操作类型（读/写/删除）写进 YAML 配置文件，Guard 初始化时加载。这样不同任务可以用不同配置，也便于审计。

- **与系统级沙箱互补**  
  目录白名单是应用层护栏，依然建议结合非 root 用户运行、`systemd` 或 `launchd` 资源限制、甚至 SELinux 标签，构成纵深防御。但在快速原型阶段，轻量护栏就足够挡住 80% 的误操作。

- **审计日志**  
  每次文件访问，记录请求路径、真实路径、操作类型、Agent 调用栈，便于事后排查。一旦出现意外行为，可以回溯 Agent 当时到底想干什么。

## 总结

给 Agent 脚本加上本地目录白名单，本质上是用几十行 Python 代码将“任意文件访问”收敛为“受控沙箱”。代价极低，却能大幅降低因幻觉或解析错误导致的数据泄露、误删风险。这套模式不依赖容器，可直接嵌入到 OpenClaw、MCP 工具或其他自动化脚本中，即插即用。

安全无止境，但对大多数本地自动化场景而言，一个靠谱的 `PathGuard` 就已经是工程上务实的第一步。
