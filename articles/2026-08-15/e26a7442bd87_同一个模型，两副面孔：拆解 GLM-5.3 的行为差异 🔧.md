最近 GLM-5.3 的实测讨论里，一个高频现象是：同一个模型，在网页端像逻辑严密的工程师，在 API 里像随性发散的文案；前一秒写代码还会先给结论，后一秒就变成长篇背景说明。有人调侃“是不是换模型了”，也有人怀疑“这模型不稳定”。实际上，这种“两个 AI”的体验，往往不是模型本身变了，而是模型运行时的采样参数、隐藏提示词、推理链路与部署配置不同。把下面这些变量拆开，你会发现模型并没有“人格分裂”，它只是被不同方式操作了。



## 一、模型“人格”不是固定性格，而是采样策略决定的

大型语言模型的每一次输出，本质上是对下一个 token 的概率分布做一次选择，而不是从固定答案里取一条。

- temperature（温度）控制概率分布的尖锐程度。温度越低，模型越倾向选最高概率 token，输出稳定、甚至显得保守；温度越高，低概率 token 被选中的机会越大，输出更有创造力，也更容易跑偏。
- top_p（核采样）限制候选 token 集合。例如 top_p=0.9 意味着只从累积概率前 90% 的 token 里采样，范围越小越可控。
- 同一个 GLM-5.3 在不同入口的默认参数可能不一样。网页端为了体验稳定，可能把 temperature 设得较低；API 默认值则可能更高，于是同一问题会得到“严谨版”和“脑洞版”两种回复。
- 系统提示词差异也很关键。官方网页通常预置了一套隐藏 system prompt，约束语气、身份、安全策略和输出格式；API 裸调用往往没有这些包装，所以一个像客服，一个像自由开发者。

## 二、看似同一个模型，实际可能不是同一条推理链路



如果把“模型名称相同”当成“推理路径相同”，很容易误判。

- 推理模式开关：GLM-5.3 这类模型可能同时提供快速回答与深度思考模式。启用深度思考后，模型会先产生大量 reasoning tokens，再输出最终答案，风格会变得更谨慎、更结构化。没开启时，它就像一个反应快但想得不深的助手。
- 量化精度差异：网页端为了低延迟，可能用 BF16/FP16 部署；第三方 API 或边缘节点为了成本，可能用 INT8/INT4。低精度对短问答影响不大，但在长文本、数值计算和代码生成里，会表现为“偶尔犯低级错误”。
- 产品层路由：同一个模型名称背后可能灰度到不同小版本或集群。模型厂商做 A/B 测试时，用户可能无感知地命中不同后端，输出自然不完全一致。
- 安全与对齐层：网页端通常多一层内容过滤、输出格式化与合规改写；API 更接近裸模型。于是同样问一个边界问题，网页版可能先给免责声明，API 直接给技术方案。

## 三、用实验眼光判断：是采样噪声，还是版本差异

遇到“两个 AI”的观感，先别急着下结论，可以做一个轻量实验。

- 固定同一个 prompt，重复 5 次。如果 5 次输出方差很大，说明主要是采样参数在起作用；如果每次都卡在同一类错误上，就要怀疑量化精度、推理链路或模型版本。
- 记录完整参数：temperature、top_p、top_k、presence_penalty、frequency_penalty、max_tokens，以及是否开启 thinking/reasoning。很多对比帖没有这些，结论其实不可比。
- 检查隐藏系统提示词。部分平台可以在调试日志或返回对象里看到 system prompt；API 用户则要显式声明角色、输出格式和边界，否则不同入口的默认约束会干扰对比。
- 看 reasoning tokens 的消耗。如果深度思考模式下 reasoning token 数量很少，说明思考链路可能没真正激活；这比单纯看回答长度更准确。
- 历史经验：从 GPT-3 时代开始，同模型不同入口表现不一致就是常见工程问题。2024 年推理模型流行之后，“思考长度”成为比温度更大的变量——同一个模型在 2 秒和 20 秒之间产生的解释深度可能完全不同。

## 四、把“两个AI”变成可配置能力



与其把差异当 bug，不如把它当成可调的能力开关。

- 把温度当作创造力旋钮。写文案、起名、头脑风暴可以调到 0.8~1.1；写代码、做数学、读合同则应降到 0~0.3。
- 用 system prompt 显式固化人格。例如：“你是技术审稿人，只给结论和依据，不写客套话，不重复问题。” 这比只改 user prompt 更稳定。
- 把不同入口的输出差异当成免费 A/B 测试。同一个问题分别丢给网页端和 API，如果两者给出一致结论，说明这个答案对采样不敏感，可采信；如果差异很大，说明该问题本身容易被参数影响，不适合作为关键决策依据。
- 模型评测必须固定配置。任何“实测截图”如果没有附 temperature、thinking、系统提示词和模型版本号，都只能当现象参考，不能当能力结论。

最后三条冷思考：

1. 复现模型效果前，先检查采样参数和思考模式。很多“模型变笨”的抱怨，其实是温度被调高或深度思考被关闭。
2. 跨入口对比时，把隐藏提示词显式化。手动补上角色、输出格式、禁忌项，能大幅减少“两副面孔”的观感。
3. 严肃评测要固定 prompt 模板、采样参数、上下文长度和版本号，重复多次取中位数。单次输出像抽卡，不能用来判断模型能力。
