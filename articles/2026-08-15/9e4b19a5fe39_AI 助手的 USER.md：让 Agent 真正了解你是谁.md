## 背景

在 OpenClaw、Agent、MCP 和自动化脚本的日常使用中，很多人会把项目规则写进 `CLAUDE.md` 或 `AGENTS.md`，却忽略了一个更基础的问题：Agent 并不了解“你是谁”。

它不知道你常用的工具链、默认时区、语言偏好、哪些操作需要先确认、哪些路径绝对不能碰。于是每次会话都要重新交代，既浪费 token，也容易在自动化场景中产生误操作。

`USER.md` 就是用来解决这个问题的：一份持久化的用户档案，让 Agent 在启动或执行任务时，稳定地读取你的环境、偏好和约束。

## 问题

直接写一个“关于我”的长文塞进 system prompt，是最常见的错误做法。

实际使用中会暴露出几个问题：

- **上下文膨胀**：全量注入后，Agent 的注意力被大量无关信息稀释，执行关键任务时反而抓不住重点。
- **信息过期**：换了默认 shell、改了工作目录、调整了自动化策略，但 `USER.md` 没更新，Agent 仍按旧环境执行。
- **隐私泄漏**：手机号、内网地址、API key 等敏感信息混在文本里，容易误提交到公开仓库。
- **多场景冲突**：全局 `USER.md` 和项目级 `CLAUDE.md` 的规则互相矛盾，Agent 反复确认或直接执行错误分支。

## 做法/步骤

### 1. 先梳理信息维度

不要写散文，只保留会影响 Agent 行为的字段。常见维度包括：

- **环境**：操作系统、终端、默认 shell、常用路径、时区、语言。
- **工具链**：偏好使用的包管理器、版本管理工具、MCP 服务、插件。
- **沟通偏好**：回答语言、详细程度、是否使用 emoji、是否优先给命令而不是解释。
- **自动化约束**：哪些操作可以自动执行，哪些必须人工确认。
- **禁忌**：绝对不要执行的操作，比如 `rm -rf`、`git push --force`、修改 cron 前不确认。

### 2. 用结构化格式保存

建议使用 YAML frontmatter 加上 Markdown 正文，方便脚本解析，也方便 Agent 按需读取。

```yaml
---
timezone: Asia/Shanghai
language: zh-CN
os: macOS
preferred_tools: [OpenClaw, MCP, git, uv]
constraints:
  - 不要自动执行 git push
  - 修改任何 cron 任务前先确认
  - 删除超过 10 个文件前先列出清单
---
# Workflow
- 默认分支：main
- 提交信息使用中文，格式：type(scope): description
- 优先给出可复现命令，而不是抽象建议
```

### 3. 拆分模块，按需加载

不要把一份 `USER.md` 塞进所有场景。推荐拆成：

```
~/.config/openclaw/
├── user.core.md        # 核心身份、时区、语言、禁忌
├── user.workflow.md    # 工作流、命令偏好、提交规范
└── user.project-xxx.md # 特定项目或自动化任务的临时规则
```

在 OpenClaw 中，只把 `user.core.md` 作为基础上下文注入，其他模块通过 MCP 的文件读取工具按需调用。这样既保持上下文精简，又能覆盖多个工作区。

### 4. 建立更新机制

`USER.md` 不是写完就一劳永逸。建议：

- 每次环境或策略变更时，手动或让 Agent 更新对应模块。
- 对临时性偏好加上过期标记，例如 `# valid until 2026-12-31`。
- 用 git 管理 `USER.md`，便于回滚和查看变更历史。

## 踩坑点

- **模糊规则**：写“必要时提醒我”几乎等于没写。Agent 无法判断什么是“必要时”。应该写成“当检测到批量删除操作时，先确认再继续”。
- **全量注入**：所有模块都拼进 system prompt，token 消耗快，执行时容易遗漏关键约束。
- **敏感信息明文**：内网地址、手机号、个人 token 不要直接写进 `USER.md`。使用占位符或单独的加密配置。
- **多 Agent 规则冲突**：全局 `USER.md` 说“提交前不跑测试”，但项目 `CLAUDE.md` 要求“必须跑测试”。Agent 会困惑或选择错误优先级。需要明确规则优先级：项目级 > 全局，用户显式指令 > 所有配置文件。
- **信息过时而不自知**：Agent 按旧路径执行，可能找不到文件或操作错误目录。可以在 `USER.md` 中加一行 `last_updated`，让 Agent 在长时间未更新时主动提示确认。

## 可复用建议

- **Schema 最小化**：只写影响行为的字段，不要写“我喜欢喝咖啡”这种与执行无关的信息。
- **让 Agent 参与维护**：在会话中让 Agent 记录新偏好，再人工确认。例如：“以后默认分支改为 main，帮我更新到 `user.workflow.md`。”
- **冲突检测**：当用户当前指令与 `USER.md` 不一致时，Agent 应该先指出冲突并询问，而不是默默执行。
- **定期审计**：每月检查一次 `USER.md`，删除已失效的临时规则，合并重复约束。

## 总结

`USER.md` 的目标不是让 AI 更像一个“懂你的朋友”，而是提供稳定的执行上下文，减少重复沟通、降低自动化偏差。

结构化的字段设计、模块化拆分、按需加载和持续维护，比写一篇长文有价值得多。它本质上是 Agent 的上下文基础设施，和代码库里的 README 一样需要认真对待。
