最近很多人实测 GLM-5.3 时发现一个诡异现象：同一个模型，在网页版问数学题，回答严谨得像位老师；换到 API 里同样的问题，却开始一本正经地胡说八道。有人怀疑模型被“降智”，有人觉得是官方偷偷换了个小模型。其实，模型权重文件可能根本没动，真正让一个模型看起来像两个 AI 的，是几组被忽略的工程变量。



## 一、采样策略：同一个大脑，不同的“冒险程度”


- 大语言模型不是从知识库中检索答案，而是逐 token 预测下一个词。每一步都会在词表上产生一个概率分布，然后按一定策略采样。
- 温度（temperature）是最常用的旋钮：温度越低，模型越倾向于选择概率最高的 token，输出稳定但可能重复、保守；温度越高，低概率 token 被选中的机会越大，输出更具创意但也更容易跑偏。
- top-p（核采样）和 top-k 会进一步裁剪候选集合，改变随机性。例如 top-p=0.9 表示只从累计概率前 90% 的 token 中采样。
- 举例：同样问“用一句话形容下雨”，温度 0.1 时可能十次有九次回答“雨水从天空落下”；温度 1.0 时可能出现“天空在给大地做针灸”。模型没换，只是采样骰子变了。
- 很多平台为了体验稳定，网页版默认温度可能设 0.3，而 API 为了灵活性默认 0.7。用户没改参数，却得到了两种“性格”。

## 二、系统提示词：看不见的“老板指令”


- 系统提示词（system prompt）是对话开始前注入给模型的最高优先级指令，通常对用户不可见。它像一条隐形的公司规定，决定了模型回答的基调、风格甚至内容边界。
- 同一个权重，加上“你是一个严谨的学术助手”和“你是一个随性的聊天伙伴”，面对同一个问题，输出可能一个像论文摘要，一个像朋友圈吐槽。
- 网页版、App、API 往往使用不同的系统提示模板，部分还会动态注入当前时间、用户所在地区、历史偏好等上下文元数据。这些信息用户无感知，却会显著影响模型行为。
- 上下文顺序同样重要：同一段事实，放在提示词开头和结尾，模型关注度不同。有实验表明，关键指令放在开头或结尾效果最好，放在中间容易被“遗忘”。
- 举例：让模型评价一个产品方案，若系统提示要求“先列风险”，输出像保守派；若要求“先列收益”，输出像激进派。其实模型还是那个模型，只是被不同的“老板”管着。

## 三、量化与后端部署：同一个名字，不同的“身体”


- 模型名相同不代表权重文件完全相同。为了节省显存和加速推理，部署时常采用量化（quantization），把原始的 FP16 或 BF16 权重压缩到 INT8、INT4 甚至更低精度。
- 量化会损失一部分数值精度，可能导致输出质量下降、计算错误或“幻觉”概率上升。尤其在复杂推理任务上，INT4 量化版和全精度版可能表现出明显差距。
- 不同平台还可能使用不同的微调版本：有的针对安全规范做了对齐，有的针对代码生成优化，有的经过蒸馏（distillation）用小模型模仿大模型行为。
- 推理后端也有影响：vLLM、TensorRT-LLM、llama.cpp 等框架在算子实现、内存布局、浮点运算顺序上存在差异，即使同样的权重和参数，也可能产生细微的输出漂移。
- 举例：同一个 GLM-5.3，在云端 A100 GPU 上跑 FP16，逻辑严密；在手机芯片上跑 INT4 量化版，可能偶尔“犯迷糊”。这不是官方偷偷换模型，而是精度和算力的物理限制。

## 四、推理模式与随机性：快系统与慢系统的开关


- 新一代模型往往支持显式推理或思维链模式（reasoning mode）。开启后，模型会先内部生成多步思考过程，再输出最终答案；不开启时，则直接预测答案。
- 这类似于心理学中的“快系统”与“慢系统”：快系统响应迅速但容易在复杂问题上犯错；慢系统耗时更长，但通过自我修正和拆解问题，回答质量显著提升。
- GLM-5.3 这类模型可能同时提供两种模式，用户或开发者没注意到开关状态，就会觉得同一个模型时而聪明时而犯傻。
- 此外，即使完全相同的配置，GPU 浮点运算的非确定性（non-determinism）和随机种子不同，也会让长文本生成逐渐分叉。尽管单次差异可能很小，但多轮对话后可能累积成明显的风格差异。

## 收尾：三条冷思考与实用建议

1. 对比模型前先固定变量：温度、top-p、系统提示词、上下文长度、推理开关等都要统一。否则你对比的不是模型能力，而是不同配置下的采样行为。
2. 关注部署版本与量化精度：同一个模型名，可能是云端 FP16，也可能是边缘端 INT4。看评测时先确认跑的是哪个版本，精度差异有时比模型升级还大。
3. 把“不一致”当作特性而非 bug：大模型本质是概率系统，单次输出只是采样空间中的一个样本。评价它应该多次采样看分布，而不是用一次结果定优劣。“像两个 AI”未必是缺陷，也可能说明模型具备更宽的生成能力。
