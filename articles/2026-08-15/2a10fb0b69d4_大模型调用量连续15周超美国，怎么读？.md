“连续15周，中国大模型调用量超过美国。”这条来自36氪的消息最近在开发者群和产品圈里反复出现。它本身不构成一个技术突破，也不等于某个模型一夜封神，但它是一个值得拆解的市场信号：调用量比榜单分数更接近“真实使用”。



## 一、先厘清口径：调用量到底在数什么

调用量听起来直观，实际统计口径差异很大。如果不先拆开，很容易被一个总量数字带偏。

- 调用量通常包括 API calls、token 生成量、App 内请求等几种口径，不能混为一谈。  
- 一次“调用”不等于一次对话。一个智能客服会话可能触发多轮检索、多轮生成、函数调用，消耗几万 token。  
- 36氪引用的监测数据，大概率偏向可公开观测的云服务 API、开发者平台和部分 C 端流量；不同榜单对美国闭源模型的统计可能不完整。  
- 业界有时用 RPM（requests per minute）和 TPM（tokens per minute）来衡量，TPM 更能反映算力消耗。  
- 一个典型的 API 请求会包含 system prompt、user prompt、历史消息，如果使用 tool calling，还会多次返回中间结果。一次用户操作可能产生 5—20 次模型调用，所以调用量不能简单等同于日活用户数。

## 二、连续15周反超，背后至少有四个结构性推力



这轮反超不是突然发生的，而是几个结构性因素叠加的结果。

1. **移动互联网场景密度更高**  
   国内 C 端应用更习惯把 AI 嵌进支付、导航、电商、社交、办公等高频场景。一个超级 App 里的“AI 助手”天然带有千万级 DAU，调用量会快速累积。  
   示例：某地图类产品的语音交互，一天产生的 ASR + 大模型调用可能上亿次。

2. **开源模型与推理成本下降**  
   以 Qwen、DeepSeek 等为代表的开源模型性能逼近闭源前沿，企业可以私有化部署，不必依赖海外 API。  
   同时，token 单价大幅下降，某些 API 价格从每百万 tokens 几十元降到几元甚至更低。成本一旦压下来，中小团队也敢放开调用，总量容易被快速推高。

3. **企业端“智能体”落地更快**  
   不少公司直接接入客服、质检、合同、BI 报表等业务流程，而不是停留在聊天框。这类场景调用频次高、链路长，一次业务流可能触发几十次模型调用。  
   RAG、workflow、multi-agent 架构进一步放大了调用次数：模型被当成“流水线工人”，而不是“问答玩具”。

4. **开发者生态与平台补贴**  
   云厂商和模型平台提供免费额度、低折扣、hackathon，刺激了早期调用。高校、独立开发者、外包团队大量使用国内 API 做原型验证。  
   美国同样有生态，但国内在 C 端分发、私有化交付上更激进，短期内更容易推高调用总量。

## 三、调用量第一，不等于模型能力第一

这是最需要冷静的地方。调用量是商业化和规模指标，不是科研能力指标。

- 论文、benchmark、前沿突破仍然更依赖基础研究和算力生态，而美国在 frontier model、底层框架、芯片设计、学术影响力方面仍有明显优势。  
- 大量国内调用可能来自免费额度、简单任务、重复请求，不能直接折算成商业价值或技术代际领先。  
- 在 LMSYS Chatbot Arena 或 MMLU 等公开评测上，最前沿模型仍以美国公司为主；调用量领先更多反映工程优化和场景覆盖速度，不是模型智慧的最终排名。  
- 但也不能反过来说调用量没有意义：高频使用会带来反馈闭环、工程优化和场景 know-how，这是实验室刷分得不到的。  
- 需要注意的另一个风险是，如果大量调用沉淀在低质量数据上，比如营销文案、重复问答，反而可能影响后续模型训练的数据质量。

## 四、把调用量当成一种“电力消耗”，更该看三点

如果把调用量类比为电力消耗，那么“总用电量”只能说明规模，不能说明产业结构。真正值得跟踪的是下面三个指标。

1. **推理成本与单位经济**  
   每千次调用里有多少是付费调用，毛利率如何。如果靠低价甚至免费补贴冲量，不可持续。  
   一个简单公式：单位毛利 ≈ 客单价 -（推理成本 + 获客成本 + 工程成本）。当推理成本趋近于零，毛利就取决于工程效率。

2. **留存与场景粘性**  
   用户是因为好用回来，还是只在营销期白嫖；企业是否把模型嵌进核心流程，而不是做一个可有可无的 demo。  
   C 端看次日留存、7日留存；B 端看净收入留存（NDR）和流程渗透率。

3. **高质量调用占比**  
   代码生成、长文档分析、复杂 Agent 调用的价值，高于简单闲聊、翻译、格式转换。同样 1M token，高质量 token 的商业价值可能差一个数量级。  
   粗分一下：低价值是闲聊、简单翻译；中价值是摘要、客服；高价值是代码生成、复杂推理、多步 Agent。

## 五、冷思考与行动清单



面对“连续15周超美国”这个数据，无论是开发者、企业采购方还是行业观察者，都可以把视角从“谁超谁”转向“什么调用更值钱”。

1. **对开发者**：把调用量拆成“付费调用、复杂调用、留存调用”三个子指标，别只看总 token 数。  
   付费调用占比 = 付费 token / 总 token；复杂调用占比 = 使用 tool calling 或长上下文任务的调用 / 总调用；留存调用 = 7日内回访用户的调用。

2. **对企业**：采购模型时，重点测 token 成本与任务成功率，而不是拿厂商给的总调用排名当决策依据。  
   做 POC 时使用同一组测试任务，记录成功率、首字延迟、每千次成本、错误率。

3. **对观察者**：未来 2—3 个季度，更值得跟踪的是“高质量调用占比”和“单位算力收入”，而不是单一总量谁超谁。  
   总量反弹容易，质量上移很难。

连续 15 周反超是一个值得记录的市场节点，但它更像一面镜子：照出的是产业落地速度、场景密度和成本结构，而不是模型智慧的最终排名。
