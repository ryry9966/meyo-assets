## 背景

在 OpenClaw 里接入 MCP、插件和自动化流程后，很多团队会遇到同一个问题：AI 不是“一个人”，而是每次会话都失忆的执行器。今天你告诉它“只用只读工具、不要改生产数据”，明天换一个会话它就忘了。角色设定写在系统提示里，但系统提示越长，越容易稀释关键约束；写在项目文档里，又不会被自动加载。

IDENTITY.md 的思路很简单：用一个结构化文件，给 OpenClaw 一个持久、可版本化、可演进的“身份”。它不是简单地把 persona 塞进提示词，而是把“我是谁、我能做什么、我不能做什么、我最近改过什么规则”固化成工程文件。

## 问题

没有统一身份文件时，OpenClaw 的典型症状包括：

- 每次会话都要重新交代工具边界，MCP server 一多就容易误调用。
- 不同项目、不同插件各自的规则散落，相互冲突时没有优先级。
- AI 偶尔会“自我发挥”，给出超出授权范围的操作。
- 想调整行为只能改代码或重写系统提示，缺少可追溯、可回滚的入口。

IDENTITY.md 解决的不是“让 AI 更像人”，而是让行为约束可维护、可审计。

## 做法/步骤

### 1. 建立最小 IDENTITY.md

建议放在 OpenClaw 工作区或知识库根目录，例如 `.openclaw/identity.md`。初始模板不要超过 60–80 行，包含五块：

```markdown
# Identity

- role: OpenClaw automation operator
- owner: <你的团队或项目名>
- last_reviewed: 2025-04-01

## Capabilities
- 可以调用已授权的 MCP 工具
- 可以读写当前工作区文件

## Boundaries
- 禁止修改 /etc、~/.ssh、生产环境配置
- 禁止执行破坏性命令，除非用户明确确认

## Workflow Preferences
- 先给方案，再执行
- 涉及删除/覆盖操作前必须列出影响范围

## Change Log
- 2025-04-01: 初版创建
```

### 2. 在入口加载，而不是堆进系统提示

OpenClaw 启动或新会话开始时，把 IDENTITY.md 作为固定上下文加载。加载方式可以是入口 prompt 里引用文件路径，也可以由记忆模块读取后注入。关键点是：不要直接把整个文件复制进系统提示，让它作为“身份层”单独存在。这样身份变更不需要改主配置。

### 3. 分层：静态身份 + 动态状态

把身份拆开：

- **静态层**：角色、权限边界、工具约定，很少变。
- **项目层**：当前项目的约束、目录结构、关键路径。
- **会话层**：临时目标、本次任务的特殊说明，不进 IDENTITY.md。

这样 IDENTITY.md 不会因为每次会话的临时内容膨胀。

### 4. 定义更新协议

给 AI 一个可操作的“身份更新协议”：

- 当身份规则与现实冲突时，先询问用户，不自动改。
- 用户确认后，在 Change Log 追加记录，并注明原因。
- 保留旧版本，支持回滚。

## 踩坑点

**1. 文件膨胀导致上下文污染**

把 IDENTITY.md 当成“什么都写”的记事本，最后 AI 会迷失在大量无用信息里。建议限制在 200 行以内，超出就拆分到项目层或外部知识库。

**2. 让 AI 自动修改身份文件**

如果开放自动更新权限，AI 可能为了“省事”不断给自己放宽限制，或者把一次偶然的成功当成长期偏好。更新必须由用户确认，或者至少通过版本控制审查。

**3. 身份与系统提示冲突**

有时主系统提示里写“允许执行命令”，IDENTITY.md 里又写“只读操作”。AI 会困惑，甚至选择更宽松的那条。解决方法是明确优先级：IDENTITY.md 中的 `Boundaries` 覆盖系统提示中的泛化能力声明。

**4. 多个项目共用一份身份**

一份全局身份很难适配所有项目。建议保留全局 `core.identity.md`，在每个项目里用 `.openclaw/project.identity.md` 覆盖局部规则。

**5. 没有版本控制**

身份文件改坏了、误删了，或者某次更新导致 AI 行为异常，如果没有 git 记录，回滚很痛苦。IDENTITY.md 必须和项目一起纳入版本控制。

## 可复用建议

- **最小身份原则**：只写会影响决策的内容，不写“你好，我是一个乐于助人的 AI”这类无效描述。
- **把工具边界写清楚**：对每个关键 MCP server 或插件，写“只读/读写/禁止”三级权限，而不是笼统说“谨慎操作”。
- **加入“不确定就询问”规则**：尤其在自动化场景，明确告诉 AI：当身份文件没有覆盖当前情况时，不要猜。
- **定期 review**：每两周或每次大版本变更前，检查 Change Log 和现有规则是否仍有效。
- **保留一条回滚路径**：至少保留最近 3 个版本的 IDENTITY.md，或者在 Change Log 里写明如何恢复到上一版。

## 总结

IDENTITY.md 的本质，不是给 OpenClaw 一个花哨的人设，而是建立一套可进化的运行契约。它让 AI 的行为边界不再依赖每次手写提示词，也让团队对“AI 为什么这样做”有了可追踪的答案。对 MCP、插件、自动化重度用户来说，这比多接几个工具更重要：先把身份和边界管好，再谈能力扩展。
