过去五年，RISC-V 身上最常见的标签是“单片机里的开源备胎”：成本低、能做 IoT、但别指望跑大型负载。最近 36kr 将服务器、AI 和机器人列为中国 RISC-V 的下一站，更像是行业在表达一个判断：RISC-V 正在从“能点亮”过渡到“能不能上生产”。这个变化不是营销词汇，而是由三个工程变量推动——ISA profile 标准化、Linux/工具链主线化、以及 AI/机器人带来的端侧算力碎片化需求。



## 从嵌入式到服务器：RISC-V 为什么开始“上桌”



- **历史包袱更轻**：RISC-V 2010 年从伯克利出发，设计原则是“精简、可扩展、不替历史兼容债买单”。x86 必须兼容几十年指令，ARM 也有历史包袱，RISC-V 基础指令集很小，扩展可以按需增加。
- **模块化是最重要的工程分水岭**：RV64GC 等组合很常见，G 通常代表 IMAFD 基础能力。服务器平台更关注 A（原子操作）、V（向量）、H（虚拟化）、IOMMU；机器人更关注 C（压缩指令）与中断确定性。这种“乐高式”拼装让一颗 SoC 不必为不需要的功能付面积和功耗。
- **授权成本只是加分项**：ARM 的 IP 授权可以谈架构许可，但对多数中小公司仍然门槛不低。RISC-V 免除 ISA 授权费，允许自研核、可定制扩展。这在几十万颗边缘芯片市场里不是决定性优势，但在需要差异化的 AI/机器人 SoC 中很关键。
- **生态跨过了主线门槛**：Linux 内核、GCC/LLVM、QEMU、OpenSBI、U-Boot 等基础软件已经支持 RISC-V。中国厂商平头哥、算能、赛昉、全志等从 32 位 MCU 到 64 核服务器芯片都有布局。行业机构估计 RISC-V 累计核心出货已超百亿颗，虽然大头仍是 MCU，但服务器与 AI 端点的出货正在抬升。

一句话：RISC-V 上桌不是因为它“免费”，而是它开始具备做正经平台的能力。

## 服务器：从“能点亮”到“能扛业务”之间差什么



- **代表性产品与平台**：算能 SG2042 是 64 核 RISC-V 服务器芯片，已经能启动 Linux、跑 Web 服务与数据库；平头哥无剑 600 平台面向高性能 SoC；中科院香山项目则提供开源高性能 RISC-V 核作为研究基线。
- **关键工程指标**：服务器 CPU 不只要核多，还要看单核 IPC、内存带宽、PCIe 通道、IOMMU、虚拟化、RAS、安全启动。RISC-V 在这些方面正从“支持”走向“可用”。例如 Hypervisor extension 让 KVM 虚拟化落地，Vector 1.0 给服务器 SIMD 能力。
- **现实差距**：单核性能与主流 Arm/x86 服务器核心仍有差距，大致相当于中低端 Arm 服务器核的水平；内存与 I/O 生态也未必适合高并发、低延时数据库。适合切入的是存储网关、冷数据服务、边缘云节点、开发验证等场景。
- **标准化是拐点**：RVA20/RVA22 profile 定义了操作系统级 CPU 的最低能力集合，软件可以按 profile 优化，而不必为每种芯片重新适配。这比单颗芯片参数重要得多。

工程判断：RISC-V 服务器短期不是替代主力计算，而是先占领“第二算力平面”。

## AI 加速：RISC-V 不是在抢 GPU，而是在“捡漏”边缘推理



- **两条技术路线并存**：一条是强化 CPU 向量能力，RVV 1.0 支持可变向量长度，代码可以在不同 VLEN 间迁移；另一条是 RISC-V 作为控制面，搭配 NPU、Tensor 加速器或外部 AI 引擎。前者重要，后者更常见。
- **矩阵扩展还在爬坡**：AI 训练与推理大量依赖矩阵乘。RISC-V Matrix extension 仍在推进，通用 CPU 的矩阵算力短期内不可能挑战 GPU/NPU。因此 RISC-V AI 的关键机会是推理端点，不是训练卡。
- **场景更务实**：智能摄像头、工业视觉、语音唤醒、边缘盒子、可穿戴设备。这些场景对能效、体积、成本敏感，对峰值算力不敏感，正符合 RISC-V 的定制优势。
- **软件栈有进展**：ONNX Runtime、TFLite、MLIR 等都有 RISC-V 后端；社区已经能在 RISC-V 开发板上跑小型语言模型推理。要注意的是，很多优化仍依赖厂商私有扩展，主线化还不够。
- **结论**：RISC-V 在 AI 中的近期角色不是另一张训练卡，而是把推理成本打到更低的无数端侧节点。

## 机器人：开源 ISA 离物理世界更近



- **机器人是天然异构计算池**：底盘运动控制、电机伺服、视觉 SLAM、激光雷达、通信与安全监控，需要 MCU、DSP、NPU、SoC 多种计算组合。RISC-V 的可定制特性允许将编码器接口、运动控制协处理器、安全监控逻辑做进同一颗芯片。
- **实时性不可妥协**：伺服电流环通常要求微秒到几十微秒级中断。RISC-V 精简指令集和可裁剪流水线，有利于做确定性与低延迟设计。这个优势在纸面上存在，但要靠具体实现和编译器配合。
- **实际落地先行**：RISC-V 已经出现在机器人控制器、LiDAR、视觉模组、伺服驱动等环节；ROS 2 对 RISC-V 的适配也在推进。全志 D1 等中低端 RISC-V 芯片被用于教学与原型机器人。
- **生态短板**：机器人操作系统中传感器驱动、中间件、调试工具链仍不如 ARM 成熟。团队在选择 RISC-V 方案时，需要评估 ROS 包与硬件抽象层是否可用。

机器人可能是 RISC-V 最先跑通商业闭环的高价值场景，因为这里对峰值单核性能的宽容度比服务器高，对差异化 SoC 的需求又比 MCU 强。

## 冷思考：别把“开源”当成包治百病

1. **先看 profile 与工具链，而不是只盯 ISA**。一颗 RISC-V 芯片能不能用，取决于它实现了哪些扩展、编译器与调试器是否完善。私有扩展太多会破坏可移植性，长期看反而不划算。
2. **短期从边缘推理和机器人控制器切入更实际**。服务器替代是长周期工程，需要内存、互连、固件、操作系统全链路成熟，不适合多数团队用“替代主力服务器”作为第一目标。
3. **警惕“碎片化”陷阱**。RISC-V 最大的风险不是性能不足，而是生态分裂。尽量选择主流 profile、上游主线支持良好的产品，避免把产品绑定在某一家的私有修改上。

RISC-V 的下一站，不是口号式“弯道超车”，而是在服务器、AI 和机器人的边缘地带，先把工程闭环跑通。能稳定跑起一个真实负载，比一百页路线图更有说服力。
