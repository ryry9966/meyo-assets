## 背景

OpenClaw 的 Agent 默认是被动模型：你发消息，它处理，然后沉寂。cron 定时任务能补一部分缺口，但 cron 只会无条件执行，不会判断“这件事现在值不值得做”。OpenClaw 提供了一个更轻的机制：**HEARTBEAT.md**——工作区里的一个 Markdown 文件，Agent 每次心跳（默认约 30 分钟一次，可在配置中调整）都会读它，然后自行判断：动手，还是保持沉默。

## 问题

纯被动 Agent 有三个缺口：

1. **状态漂移没人管。** notes 仓库忘了 commit、磁盘悄悄涨到 90%，你不问它就不看。
2. **值班式查询成本高。** 很多事只需要“看一眼，没问题就闭嘴”，却每次都得你主动发起对话。
3. **cron 无法携带判断。** “每天 9 点推日历”可以，但“有冲突才提醒我”做不到。

本质上是缺一条低频、带判断的巡检回路。

## 做法

**1. 建文件。** 在 Agent 工作区（通常是 `~/.openclaw/workspace/`）创建 HEARTBEAT.md，推荐三段式结构：

```markdown
# 心跳任务

规则：默认沉默。无事不发言，有事一条消息说清。

## 每次心跳
- ~/notes 有未提交改动 → commit + push，静默完成
- 磁盘占用 > 85% → 告警到 #ops

## 每天首次心跳
- 汇总今日日历，有变更才推送私聊
```

**2. 控制节奏。** 调试期把心跳间隔调短到 5 分钟验证行为，稳定后拉回 30 分钟以上。

**3. 隔离输出。** 心跳的主动消息定向到一个专用频道或私聊，别混进日常群聊，否则噪音会毁掉整个机制。

## 踩坑点

- **Token 成本被低估。** HEARTBEAT.md 每个 tick 都注入上下文，哪怕无事可做。我见过 200 行的“愿望清单”一天烧掉可观的 token。控制在 30 行内，只放真正值得巡检的事。
- **忘了写“默认沉默”。** 不写这条，Agent 会每次心跳都汇报“一切正常”。第一行永远是沉默原则。
- **任务不幂等。** 在心跳里放“重新构建整个项目”这类长任务，会跨 tick 执行、状态混乱。心跳任务必须小、可重入、失败可重试。
- **和会话撞车。** 心跳触发的 git 操作可能和你正在对话里下的指令冲突，共享资源（分支、文件锁）要互斥。
- **文件会腐烂。** 完成的任务要删，别把它当 GTD 收件箱。我固定每周五清一次。
- **别写密钥。** 这个文件会进 prompt，任何 secret 都不该出现。

## 可复用建议

- 把 HEARTBEAT.md 当**常备指令（standing orders）**，不是待办清单：判断逻辑交给 Agent，状态放外部（git、文件、监控端点），心跳只做 diff。
- 三个通用模式：**check-then-act**（有条件才动手）、**silent-by-default**（无事不说话）、**report-on-change**（只在状态变化时上报）。
- 用 git 管理这个文件，每次调整都有迹可循。
- 和 MCP 工具组合价值最大：日历、监控、issue 面板的读取类工具天然适合放进心跳。

## 总结

HEARTBEAT.md 机制本身极简：一个文件加一个定时器。工程量全在任务筛选和噪音控制上——什么值得巡检、什么必须沉默，比机制本身更值得花时间。跑稳之后，Agent 才真正从“问答机”变成“值班员”。
