## 背景

让 Agent 直接操作文件系统，第一反应就是怕它删错东西。OpenClaw 的设计前提很明确：LLM 的输出本质上不可信，prompt 里写“请不要删除文件”不构成任何安全边界。所以 sandbox 模型不靠“提醒”，而是把 Agent 关进一个伤害有上限、操作可回滚的环境。

## 问题：Agent 的三种典型失败模式

实际跑下来，误删风险主要来自三处：

1. **路径幻觉**。模型会把训练数据里的路径当成真实路径，或把相对路径解析错，然后在错误的目录里执行“清理”。
2. **通配符误伤**。`rm *.log.tmp` 和 `rm * .log.tmp` 只差一个空格，而模型偶尔就会输出这种“看起来对”的命令。
3. **指令歧义**。用户说“把旧文件清一下”，Agent 对“旧”的判断和人不一致，且一旦执行不可逆。

传统 Unix 权限解决不了这些——它假设操作者理性且清楚自己要什么，Agent 不满足这个假设。

## 做法：四层防线

OpenClaw 的 sandbox 大致四层，彼此独立生效：

1. **jail root（路径围栏）**。Agent 进程启动时绑定专用工作根目录，所有文件工具调用先做 realpath 解析，再校验是否落在围栏内。校验发生在 exec 之前，不依赖模型自觉。
2. **三级路径策略**。围栏内再分 read-only / workspace（可写）/ forbidden。源码和配置默认只读，只有 workspace 开放写入。
3. **破坏性操作 confirm gate**。删除、覆盖、批量重命名不直接执行，先生成 diff 预览，等确认信号。Agent 能“想”做什么和能“做”什么是两套通道。
4. **审计 + 快照**。每次写操作记录 before/after，workspace 定期打快照——这是兜底：前面全失效也能回滚。

## 踩坑点

- **symlink 逃逸**。围栏目录里的软链接指向外部路径，只校验字面路径就直接放行了。必须在 realpath resolve 之后比对，这是最容易被忽略的洞。
- **通配符在 shell 层展开**。拦截工具参数时看到的是 `rm *`，展开结果 exec 时才产生。正确做法是执行前自己做一次 dry-run 展开，对展开后的文件列表再过一遍策略。
- **围栏太紧会逼出绕路行为**。tmp 目录没开写权限时，Agent 会反复重试、甚至尝试 base64 编码写文件，token 消耗翻倍且更不可控。围栏要完整覆盖工作流所需的全部目录，而不是一味收紧。
- **prompt 约束不进威胁模型**。system prompt 里写“删除前必须确认”有用，但只能算体验优化，防线必须落在代码和系统调用边界上。

## 可复用建议

- 默认拒绝、按需放行；策略配在工具/路径粒度，不要配在“这一次任务”粒度。
- 任何不可逆操作前强制产出 diff，给人一个 30 秒内能看懂的确认点。
- 校验逻辑收敛到统一的工具网关，别让各插件各写一份、口径不一。
- 快照 + 回滚是底线能力，没它，前面做得再好也是在赌。

## 总结

Agent 不误删文件，不是因为模型足够聪明，而是即使它犯错，伤害也被限制在围栏内、有预览、可回滚。OpenClaw sandbox 模型的核心就一句话：**把安全边界从 prompt 层挪到执行层**。这套思路不依赖特定框架，自己搭 Agent 工作流时同样适用。
