## 背景

LLM 本身无状态，每次新会话都是初次见面。对天天用 OpenClaw 搭 Agent 的人来说，最烦的不是模型不够聪明，而是同一个偏好——代码风格、回复语言、常用工具链、项目部署习惯——每开一个会话就得重申一遍。MCP 和插件解决了能力扩展问题，但"记住用户"这件事，目前还得自己设计。

## 问题：三种常见错误做法

1. **全塞 system prompt**：偏好少时能用，积累三个月后 token 爆炸，且没法维护和审计。
2. **聊天记录全量进向量库**：检索回来一堆无关上下文，噪声大于信号，反而干扰决策。
3. **指望模型"自己记"**：隐式记忆不可控、不可见，换个模型或清个缓存就全丢。

## 做法：四层记忆 + 一条写入流水线

**分层存储，各管各的：**

- **工作记忆**：当前会话上下文，不持久化
- **情景记忆**：会话结束后的结构化摘要（做了什么、关键决策、结果）
- **语义记忆**：用户偏好与事实画像，以结构化 KV 为主
- **程序记忆**：固化下来的工作流（哪个项目用哪套命令、发布步骤）

**写入流水线，核心原则是低频、结构化、可审计：**

1. 会话结束或每 N 轮触发一次轻量抽取，输出 schema 化候选记忆：`{type, content, confidence, source_turn, created_at, scope}`
2. 去重合并：与已有记忆做相似度比对，命中则合并或升版本，而不是无限追加
3. 高影响记忆（比如"操作数据库前先备份"）写入前让用户确认一次

**读取策略：**

- 会话启动：注入压缩后的用户画像，控制在几百 token 内
- 会话中：按需检索情景记忆，排序权重 = 相关度 × 时新性 × 使用频率
- 设注入预算上限，超了砍尾部

## 踩坑点

- **一次性指令被固化成永久偏好**："这次用中文注释"变成了永久规则。给记忆加 `scope` 字段（once / session / project / global），默认收窄。
- **抽取幻觉**：模型会脑补用户没说过的偏好。每条记忆必须带 source（哪一轮、原话是什么），审计时能回溯。
- **记忆腐化**：用户半年前偏好 Vim，现在换 VS Code，旧记忆还在抢注入名额。用 `last_used` + `created_at` 双时间戳，长期未命中的自动降权。
- **注入过多反而降智**：实测超过预算后模型开始忽略记忆内容，宁缺毋滥。
- **隐私**：记忆本质是敏感数据，必须支持列出、导出、删除，默认本地存储，别默认上云。

## 可复用建议

- **先做规则式偏好文件**（用户手写 YAML/JSON），跑通注入链路，再上 LLM 自动抽取。自动抽取是锦上添花，不是地基。
- **记忆对用户可见可编辑**。信任来自透明，黑盒记忆没人敢用。
- **盯两个指标**：记忆命中率（注入的记忆被实际使用）、纠偏率（用户推翻 Agent 决策的频率）。纠偏率持续上升，说明记忆在腐化，该清理了。
- **把记忆当配置管理**：版本化、可 diff、可回滚，出问题能一键回退到上周的画像。

## 总结

记忆系统本质是数据工程问题，不是 prompting 技巧。分层存储解决"记什么"，结构化 schema 解决"怎么记"，预算化注入解决"怎么用"，scope 和时间戳解决"记错了怎么办"。建议的路径是：先让用户手动写偏好跑通闭环，再逐步引入自动抽取——在 OpenClaw 的插件体系里，这套东西一个晚上就能搭出可用原型。先跑起来，再迭代。
