## 背景

大多数 Agent 的使用方式是被动式的：你打开会话、提问、得到回答、关闭。Agent 的生命周期被输入框绑架。OpenClaw 加了心跳机制之后，情况不一样了：agent 常驻后台，按固定间隔被唤醒一次，每次唤醒都会读取 workspace 根目录下的 `HEARTBEAT.md`——这个文件就是"主动性"的全部载体。

## 问题

我想让 agent 做的事里，有一类天然不适合一问一答：定时巡检下载目录有没有新发票、盯 CI 是否变红、每天早上汇总一次邮件。用 cron 加 shell 脚本能做，但逻辑游离在 agent 之外，改需求要重写脚本；直接在对话里交代，会话一关就忘。缺的是一个持久化、可迭代、agent 每次醒来都会看一眼的地方。

## 做法

1. **建文件，写清单。** 在 workspace 根目录创建 `HEARTBEAT.md`，每条一个动词开头的短句，写清"检查什么 + 触发条件 + 做什么"。例如：`若 ~/downloads 近 7 天新增 PDF，读完并总结要点提醒我`。
2. **配置唤醒间隔。** 默认约 30 分钟，通过 `HEARTBEAT_INTERVAL_MS` 调整。经验值 15–60 分钟：更短只是多烧 token，巡检类任务不需要分钟级响应。
3. **理解空转机制。** 没到触发条件的唤醒，agent 回复 `HEARTBEAT_OK`，框架会吞掉这条回复，你完全无感。只有真正有产出的心跳才送达聊天渠道，可用 `heartbeat.target` 把输出定向到指定会话或群。
4. **分层组织条目。** 按"每跳检查 / 每天一次 / 仅工作时间"分组，把跳过条件直接写在条目里，让 agent 自己判断这跳执不执行。

## 踩坑点

- **心跳不是 cron。** 间隔只是"最多多久醒来一次"，干不干活由 agent 判断。"X 点整提醒我"这种精确定时不可靠，请走系统提醒。
- **条目太模糊会爆炸。** "看看有没有什么重要的事"会让 agent 每跳做全量扫描，token 消耗翻几倍，输出全是噪声。条件必须可判定。
- **文件膨胀。** HEARTBEAT.md 每次唤醒都全文进入上下文，控制在十来行内，完成的条目及时删。
- **输出刷屏。** 心跳默认进主会话，人多的群里体验很差，务必用 target 定向到专门频道。
- **副作用要限流。** "没回的邮件提醒我"如果不加静默条件，会每 30 分钟轰炸你一次。条目里写明"同一件事只提醒一次"。

## 可复用建议

我在用的模板：

```
## 每跳
- 若 <目录> 有新增 <文件类型>，则 <动作>，否则跳过
## 每日（本地 9 点后第一跳）
- <汇总任务>，输出不超过 5 行
## 静默
- 同一件事只提醒一次，除非内容有变化
```

另一个值得养成的习惯：让 agent 自己维护这个文件。对话里说"以后每天早上帮我看一次 XX"，让它把条目写进 HEARTBEAT.md，需求收集和实现就闭环了。另外，心跳条目要有工具支撑才有意义——配合 skills 或 MCP 接入文件系统、CI、邮箱之后，"巡检"才不是空话。

## 总结

HEARTBEAT.md 的价值不在某个具体功能，而在于它把"什么时候、看什么、做什么"从一次性对话搬进了一个可版本化、可迭代的文件。Agent 的主动性不是模型自带的气质，是机制给的边界：唤醒节奏、可判定条件、有去重的输出。把这三件事写清楚，它就能在你不看屏幕的时候把活干了。
