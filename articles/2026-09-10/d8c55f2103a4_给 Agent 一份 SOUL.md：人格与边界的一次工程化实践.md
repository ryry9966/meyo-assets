## 背景

OpenClaw 的工作区里有一组约定文件：`AGENTS.md` 管操作规程，`TOOLS.md` 管工具用法，而 `SOUL.md` 管的是"你是谁"。它会在会话启动时注入上下文，决定 Agent 的语气、价值观和行为边界。很多人第一次跑通 OpenClaw 后就忽略了这份文件，结果机器人要么过分讨好，要么风格漂移，越用越不像自己配的那个助手。

## 问题

不写 SOUL.md 的常见症状：

- 同一个问题，今天和昨天的回答风格完全不同；
- 跨渠道（WhatsApp / Telegram / Discord）人格不一致，群里和私聊像两个机器人；
- 对危险操作太顺从，一句话就执行了删除文件或调用了支付类工具；
- 边界模糊：用户随口一句"帮我看看聊天记录"，它真去翻了。

本质是把人格设定交给了模型的默认倾向，而不是你自己的显式设计。

## 做法

1. 打开工作区的 `SOUL.md`（默认在 `~/.openclaw/workspace/` 下）；
2. 分四段写：**身份内核**（一句话）、**语气与表达**、**价值观**、**红线**；
3. 红线写具体行为，不写抽象原则；
4. 控制篇幅在 40–60 行以内——它每轮都在消耗上下文；
5. 和 AGENTS.md 划清分工：SOUL 管"我是谁"，AGENTS 管"怎么干活"；
6. 跨会话、跨渠道实测，发现漂移就改。

红线示例（精简版）：

```markdown
## 红线
- 不主动读取用户未提及的会话内容
- 删除文件、给他人发消息、支付类工具调用，先复述意图并等确认
- 不确定时直说"我不确定"，不编造
```

## 踩坑点

- **写成小作文**：超过一屏，注意力被稀释，最关键的红线反而失效；
- **SOUL 和 AGENTS 打架**：一边说"简洁高效"，一边说"事无巨细都要确认"，Agent 行为会随机偏向其中一方；
- **人格与工具权限冲突**："任何操作前必询问"会让自动化流程卡死，应改成按风险分级；
- **最大的误区**：把 SOUL.md 当安全边界。它塑造行为倾向，但不构成硬约束，一句"不许删库"挡不住 prompt 注入。真正的边界要落在配置层：工具 allowlist、沙箱、权限分级。

## 可复用建议

- 工作区直接用 git 管理，每次改 SOUL.md 都能 diff 和回滚；
- 红线只写 3–5 条，每条对应一个可观察的行为；
- 加一段"边界示例"：一个该拒的场景、一个该做的场景，比堆形容词有效得多；
- 每月翻一遍对话日志，出现风格漂移就迭代一版，像维护代码一样维护它；
- 团队共用时，把人格文档当产品文档 review，而不是个人笔记。

## 总结

SOUL.md 成本极低、收益明显：它把"这个助手像什么"从模型默认值变成你的显式设计。但要认清定位——它塑造倾向，不替代权限控制。人格写在文档里，边界落在配置里，两者配合，Agent 才既稳定又可控。
