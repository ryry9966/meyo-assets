### 背景

大多数 Agent 的交互模型是"你问它答"：会话结束，进程挂起，什么都不会发生。但个人助手类场景真正需要的是主动性——早上汇总昨天的 CI 失败、磁盘快满时告警、晚上推一条待办摘要。OpenClaw 给了一个很轻的解法：**HEARTBEAT.md**。它本质上是 Agent 工作区里的一个普通 Markdown 文件，配合心跳调度器，让 Agent 周期性醒来、读文件、自己决定"做事还是继续睡"。

### 问题

让 Agent 主动做事，最容易掉进三个坑：

1. **成本失控**：每分钟唤醒一次就是每分钟一次模型调用，token 开销和心跳频率成正比。
2. **噪音污染**：指令模糊时，Agent 每次醒来都汇报一句"一切正常"，一天推你二十条废消息。
3. **行为漂移**：没有稳定契约，同一个任务每次醒来的执行方式都不一样，甚至自作主张改配置。

HEARTBEAT.md 的设计目标就是同时压住这三个问题。

### 做法

核心机制一句话：**心跳触发 → Agent 读 HEARTBEAT.md → 没有到期任务就返回 `HEARTBEAT_OK`（网关吞掉，不转发给你）→ 有任务就执行并汇报**。

落地步骤：

**1. 在工作区根目录新建 HEARTBEAT.md，先写"规则"再写"任务"：**

```markdown
# HEARTBEAT.md

## 规则
- 没有到期任务时返回 HEARTBEAT_OK，不要发消息打扰我
- 任务失败最多重试 2 次，仍失败就记录原因等下次心跳
- 一次心跳只处理到期任务，不要展开额外工作

## 任务
- [ ] 每天 09:00：检查 CI，有失败才通知
- [ ] 每 2 小时：磁盘使用率超过 85% 才告警
- [ ] 每天 21:00：汇总未读与待办，发一条摘要
```

**2. 在配置里设置心跳间隔**（默认约 30 分钟，按需调整）。注意：间隔决定的是"最小检查粒度"，任务本身的触发条件由 Agent 按文件里的时间描述自行判断。

**3. 观察前几轮心跳日志**，确认"静默路径"和"执行路径"都符合预期，再逐步加任务。不要一上来堆十条。

### 踩坑点

- **必须写"何时沉默"，而不只是"何时行动"**。只写行动，Agent 会把每次心跳都当成汇报机会。
- **条件要可判定**。"关注一下服务器"没法执行；"磁盘 >85% 才告警"可以。
- **别在心跳里塞长任务**。心跳是轻量巡检，重活交给 cron 或独立会话，否则一次心跳阻塞几十分钟。
- **不要让任务隐式改写 HEARTBEAT.md 的结构**。格式漂移后，下次心跳可能解析失败。要改文件，就明确写一条"维护任务"。
- **多实例共享工作区要小心并发写**，建议一个实例对应一份 HEARTBEAT.md。

### 可复用建议

- 把 HEARTBEAT.md 当**配置即代码**：进 Git，改动走 commit，出问题可回滚、可审计。
- 任务一行一事，宁可拆成多行，也不要写复合长句。
- 用"**默认静默，例外才发声**"的心智模型设计每一条任务。
- 心跳管轻量巡检，定时任务管重计算，二者分工，不是替代关系。
- 每周 review 一次任务列表，砍掉连续两周没产出价值的条目——主动性和噪音只有一线之隔。

### 总结

HEARTBEAT.md 好用的原因，在于它把"主动性"从提示词技巧变成了**文件契约**：Agent 醒来读什么、做什么、什么时候闭嘴，全部白纸黑字。成本可预算，行为可审计，任务可版本化。如果你已经在跑 OpenClaw，建议从一条真实的巡检需求开始，比如每天检查一次 CI——先让心跳转起来，再慢慢长出你自己的主动式工作流。
