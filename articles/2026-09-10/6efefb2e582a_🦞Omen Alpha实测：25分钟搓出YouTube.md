最近 AI 圈又上演了保留节目：一个没有任何官方说明的神秘模型，顶着代号 **Omen Alpha** 悄悄出现在模型竞技场上。36kr 的实测文章里，作者只花了 25 分钟，就让这个模型从零搓出一个“牛来版 YouTube”——首页信息流、播放页、搜索、点赞评论一应俱全。25 分钟，够我泡杯咖啡外加回两封邮件，人家已经“复刻”了一个视频平台。热闹归热闹，这背后到底是什么技术在撑，又有哪些水分要拧？今天拆开看看。

## 神秘模型：竞技场上的“蒙面选手”

匿名模型不是新鲜事，它是模型评测圈一套成熟的玩法：

- **LMArena（前身 LMSYS Chatbot Arena）** 的机制：厂商把未发布模型挂上匿名代号，用户盲测对战、投票选胜负，系统汇总成 Elo 排名。模型是谁，全靠社区猜。
- 这套流程有著名先例：2024 年的 `gpt2-chatbot` 一夜爆红，后来被证实与 OpenAI 的 GPT-4o 相关；Google 的图像模型也顶着 `nano-banana` 的代号被社区“垂钓”了半个月才官宣。
- 对厂商来说好处很实际：盲测环境没有品牌光环，得分更接近真实口碑，顺便给正式发布预热——相当于上映前的点映场。
- Omen Alpha 出自谁家目前没有实锤，社区流传的猜测不少，但都停留在“猜”。我们能确认的只有一件事：它的代码生成能力，被一场 25 分钟的极限实测推到了聚光灯下。

## 25 分钟速搓：实测到底测了什么

把实测过程拆开，大致三步：

1. **一个总 prompt 起框架**：让模型生成视频平台的整体结构——顶部导航、侧边栏、首页视频卡片流、播放页布局，一气呵成。
2. **追加需求做迭代**：加搜索、加点赞评论、切暗色主题、调卡片间距。每次用自然语言描述，模型做局部修改、不推翻重来。
3. **少量 debug 收尾**：把报错贴回去，模型自己修。

“牛来”的点不在功能多，而在三个细节：

- 一次生成的 UI 直接可用，不是“半截子”页面；
- 局部改动能精准定位代码位置，不误伤其他模块——这要求模型对整个项目结构有全局把握；
- 全程节奏是“人说需求、模型写码”，人类只负责描述和验收。

但要划重点：这是一个**前端壳**。数据是 mock 的或来自公开接口，没有登录系统、没有上传转码、没有推荐算法。搓的是 YouTube 的“样子”，不是 YouTube。

## 为什么模型突然会“搓产品”了

这波能力跃迁不是魔法，是三个技术变量叠出来的：

1. **RLVR（可验证奖励的强化学习）**：代码天然适合当训练场——单元测试跑没跑过，通过或失败是硬信号，没有模糊空间。模型在“写码 → 跑测试 → 修复”的循环里被大规模训练。标志性证据是 SWE-bench Verified（用真实 GitHub issue 测修复能力）：2023 年主流模型还是个位数百分比，2025 年旗舰模型普遍冲到 70% 以上。
2. **长上下文 + Agent 工作流**：上下文窗口拉到 10 万 token 以上，模型能“读完整个项目”；配合工具调用，它可以自己执行代码、看报错、自我修复，不再是“一锤子买卖”。
3. **前端是语料富矿**：GitHub、技术博客、教程里 React/Tailwind 风格的代码海量存在，模式高度重复，恰好落在模型最擅长的“背诵 + 组合”区间。

Andrej Karpathy 给这类玩法起了个名字：**vibe coding**——人不细看代码，靠描述和感觉推进，模型负责实现。25 分钟搓 YouTube，就是 vibe coding 的极限走位。

## 冷水：demo 到产品隔着多少个 25 分钟

冷静下来算笔账，搓出界面只是露出海面的一角：

- **基础设施**：YouTube 官方数据是每分钟有 500+ 小时视频被上传。存储、转码、全球 CDN 分发，每一项都是重资产长周期工程，和生成一段 React 组件不在一个次元。
- **系统与生态**：信息流背后是推荐算法、创作者分成、内容审核、广告系统——这些才是视频平台真正的护城河，而且没有一个是“一句话生成”能搞定的。
- **安全债**：vibe coding 产物最常见的坑是鉴权漏洞和 API key 泄漏。界面 5 分钟生成，安全审计可能要 5 周，比例倒挂，但缺一不可。

所以更准确的说法是：**25 分钟复刻的是一个界面原型，不是一家公司**。demo 展示的是模型能力上限，不等于工程交付物，两者中间隔着的那段距离，恰恰是软件工程存在的原因。



## 三条实用建议

1. **把神秘模型当免费探针**。竞技场上的匿名模型不用白不用，拿你自己 tasks 里的真实任务去测——一个 bug、一版页面、一段数据处理脚本。别人 demo 里的“牛来”不算数，你自己任务上的表现才算数，这也是对抗营销滤镜最有效的办法。
2. **把“速搓”收编进工作流**。原型验证阶段放心让模型写，一天搓三个方案比一周磨一个强；但进入生产前，核心逻辑补测试、做 code review、查鉴权，一步都不能省。AI 提速的是“从 0 到 0.9”，“从 0.9 到 1”依然是工程的活。
3. **看到“X 分钟复刻 Y”先问三个问题**：测的是前端还是全栈？数据是真接的还是 mock 的？过程有没有剪辑和跳帧？三问下来，传播滤镜基本就卸干净了。

神秘模型还会一波接一波地冒出来，25 分钟的纪录也一定会被刷新。对普通人来说，值得攒的不是对某个模型的信仰，而是把这类工具变成肌肉记忆的能力——毕竟模型换得比手机壳还勤，会搓产品的那双手，才是你自己的固定资产。
