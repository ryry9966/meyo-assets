## 背景

OpenClaw 的主会话是一个长期存在的上下文：系统提示、历史消息、每一次工具调用的输出，都堆在同一个 session 里。日常问答没问题，但一旦主 agent 开始干重活——批量读文件、抓网页、跑长链路工具调用——上下文就会迅速膨胀。

OpenClaw 提供了子 agent 机制（`sessions_spawn`）：主 agent 把任务派发给一个独立的子会话，子 agent 在自己的 session 里完成工作，只把结果摘要回传主会话。这篇帖子记录我们在自动化实践里如何使用这套隔离机制，以及踩过的坑。

## 问题：上下文污染

不开隔离时的典型症状：

1. 一次抓取任务返回 20k token 的网页正文，永久留在主会话里，后续每一轮对话都在为它付费，同时稀释模型注意力；
2. 多个任务在同一 session 串行执行，工具输出互相交错，模型容易把 A 任务的中间结果误认为 B 任务的上下文；
3. 主会话被迫频繁 compact/reset，真正想留的记忆跟着一起被裁掉。

## 做法

1. **派发即隔离**。凡是"重 IO、多轮工具、一次性"的任务，都走 `sessions_spawn`，而不是在主会话直接执行。子 agent 有独立的 session 文件，工具调用和原始输出都留在里面。
2. **任务提示自包含**。子 agent 看不到主会话历史，spawn 时必须把目标、约束、输入数据、期望输出格式一次性写清楚。
3. **规定回传格式**。要求子 agent 只返回结构化摘要（结论 + 关键数据 + 失败项），主会话拿到的通常只有几百 token。
4. **收窄权限与工作目录**。spawn 时限定子 agent 可用的工具和目录范围，避免它顺手改动主会话正在维护的资源。
5. **独立任务并行派发**。互不依赖的任务同时 spawn、各自隔离，主 agent 只负责汇总。
6. **会话文件治理**。子会话是易耗品，定期清理 agents 目录下过期的 session 文件，防止磁盘无声堆积。

## 踩坑点

- **忘了自包含**：任务描述里写"接着刚才的分析"，子 agent 一脸懵，返回垃圾结果。上下文必须显式带过去。
- **回传太啰嗦**：子 agent 把整页网页原样粘回来，隔离形同虚设。务必在任务里写死输出格式和长度上限。
- **递归 spawn 失控**：子 agent 又去 spawn 子 agent，成本指数级上涨。要么在任务里明令禁止，要么限制层级和总数。
- **并发超限**：一次 spawn 十几个任务撞上模型速率限制，整批失败后重试更贵。并发控制在个位数，失败的单独重跑。
- **状态误假设**：两次 spawn 之间子会话互不相通，别指望"上一个子 agent 还记得"。

## 可复用建议

- 固化"主 agent 做规划与聚合、子 agent 干重活"的分工模式；
- 沉淀一个任务模板：目标 / 输入 / 约束 / 工具范围 / 输出格式 / 长度上限，spawn 时填空即可；
- 用主会话的 token 增速做判据：如果一次任务的上下文增量明显超过主会话日常水平，就值得下沉为子任务。

## 总结

session 隔离的本质是把"过程"和"结论"分开：过程留在子会话里自生自灭，只有结论进入主会话。派发时上下文自包含、回传时强制摘要、权限收窄、并发可控——做到这四点，主会话就能长期保持干净，不会被任何子任务拖垮。
