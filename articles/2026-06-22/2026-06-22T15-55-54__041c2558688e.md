最近技术圈有一条消息让人直呼“反直觉”：那位打造了 Claude Code 的工程师（被社区称为“Claude Code 之父”）公开表示，自己日常工作流已经淘汰了传统 IDE，甚至不写提示词（prompt），核心逻辑就靠一个循环（loop）。这背后是 AI 编程工具进化到新阶段的标志，还是某种极客式的个人偏好？今天从技术演进的角度，拆解这套“极简编程”背后的逻辑、可行性以及坑。

## 背景：IDE 和提示词，到底在解决什么问题？

要理解为什么有人想“删掉”它们，得先看传统 IDE 和提示词工程各自承担了什么角色。

- **IDE 的本质**：通过图形界面把编译、调试、代码补全、项目管理等功能打包。对开发者来说是“工作台”，但同时也意味着沉重重心——启动慢、插件冲突、配置复杂。
- **提示词的本质**：在 LLM 时代，提示词是人与模型沟通的“界面”。写一个好的 prompt 往往要反复调参、加示例、控制语气，本质上也是一种“编程”。
- **痛点叠加**：当你既要学会 VSCode 的快捷键、Git 的分支策略，又要精通 prompt 模板，认知负荷会快速飙升。

Claude Code 作为一款专为 AI 协作设计的终端工具，天然希望减少这些“中间层”。创始人删 IDE 的做法，更像是在问：如果 AI 能理解语义、直接执行多步操作，为什么还需要人眼盯着光标和文件树？

## 核心做法：删掉 IDE，去掉提示词，只写循环——实际在做什么？

从公开的技术演示和访谈看，这位工程师的工作流大致如下：

- **放弃图形 IDE**：仅使用终端 + 一个轻量编辑器（类似 vim 或 nano），但几乎不打开文件树。所有代码改动用自然语言描述给 Claude Code。
- **不再写 prompt**：没有“system prompt”、“few-shot示例”，只有一句目标描述，比如“把这个排序算法改成稳定排序”。
- **核心是循环**：让 AI 自动执行“思考→写代码→测试→反馈→修正”的循环。开发者只负责给出方向或修正信号的“停止条件”。

一个典型循环伪代码：
```python
while not enough:
    ai.write()
    ai.execute()
    human.check(result)
    if okay: break
```

关键区别：传统 prompt 是“一次性指令”，人必须提前想好所有细节；循环模式是“迭代对话”，人可以逐步完善目标，AI 承担中间探索。

## 技术原理：为什么循环能替代提示词？AI 的自我校正与推理链

这套工作流之所以能跑通，依赖 Claude Code 底层模型的几个关键能力：

- **长上下文与记忆**：Claude Code 在终端中保持持久会话，模型能记住前几轮的工具调用结果，无需每次都重复 context。
- **工具使用 (Tool Use)**：模型可以自主调用 shell 命令、读取文件、执行测试、查看输出。这让它像“实习生”一样自己做实验。
- **反思机制**：当测试失败或输出不符合预期时，模型能自动分析报错并调整方案。人只需要在循环临界点介入。

对比传统 prompt 工程：
| 维度 | 传统 prompt | 循环模式 |
|------|-------------|----------|
| 控制粒度 | 写一次，期望一次完美 | 分步反馈，逐步逼近 |
| 调试成本 | 修改 prompt 或重写 | 修改循环条件或方向描述 |
| 工具依赖 | 需要 IDE + 插件 + prompt 模板 | 终端 + AI + 基础编辑器 |

注意：这里“循环”不是简单重复，而是借助模型内置的 reasoning（推理）能力。比如给 AI 一个任务，它自己会分解、写代码、测试、重试。人只需要在循环里加一个“如果连续失败3次就问我”的终止条件。

## 影响与冷思考：这对普通开发者意味着什么？

### 好处很明显
- 降低多工具切换的认知损耗
- 减少 prompt 调优的苦力活，把精力放在“定义目标”上
- 适合原型快速验证和探索性编程

### 可能的坑
- **不可控性**：循环可能陷入死循环或偏离轨道，尤其是在复杂业务逻辑中。
- **缺乏可视化**：没有 IDE 的符号跳转、断点调试，出问题时定位困难。
- **模型局限**：如果 AI 理解错了业务语义，循环只会加速错误。
- **团队协作**：脱离标准化的 IDE 和代码风格，传统 code review 流程会受阻。

### 生存建议（写给想尝试的开发者）
1. **先适配小模块**：不要立刻用这个方式写核心系统。挑一个独立的、边界清晰的功能（如一个 API 端点、一个数据清洗脚本）来测试循环流程。
2. **定义“退出条件”**：在循环开始时明确：什么情况下必须人工接管？建议设置“连续失败2次 || 耗时超过5分钟”就暂停。
3. **保留“元记录”**：用一个简洁的日志文件记录每次循环的输入输出，既方便回溯，也方便给模型提供历史参考。

这套极简实验更像是人机协作从“命令行”走向“对话流”的一个缩影。IDE 和 prompt 未必会彻底消失，但“用循环管理 AI 循环”的思维方式，可能是明年最值得关注的编程范式之一。
