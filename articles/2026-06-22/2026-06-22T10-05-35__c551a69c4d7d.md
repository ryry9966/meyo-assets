最近一条来自 36kr 的话题在技术圈炸了锅：连微软这种把 OpenAI 当亲儿子养的公司，都开始把 DeepSeek 等开源模型悄悄塞进自家产品的推理后端。理由也很朴素——**Token 太贵，烧不起了**。听上去有点反直觉：全球最有钱的几家公司之一，居然会为了几分钱一千 Token 抠抠搜搜？但只要你掰开算一遍 LLM 的成本账本，就会发现这事一点都不夸张，反而是大模型产业进入「成本竞争」深水区的标志性信号。

## 一、Token 到底贵在哪：把账本摊开看

很多人对「Token 成本」只有一个模糊印象——「调 API 要花钱」。但要理解微软为什么也开始心疼，得先看清楚这笔钱到底烧在哪。

- **算力本质上是显存 + 算子**：一次推理需要把模型权重加载进 GPU 显存，然后逐 Token 生成。一个 70B 参数的稠密模型，FP16 权重就是 140GB，要塞进 H100（80GB）必须多卡并行，单次推理就要占用至少 2 张卡。
- **生成是串行的**：和训练可以高度并行不同，自回归解码每生成一个 Token 都要走一遍前向，KV Cache 还要随上下文线性增长。Context 越长，单 Token 成本越高，而不是越低。
- **典型成本量级**：GPT-4 级别模型的输出价格大约在 \$30 / 百万 Token，输入 \$10 / 百万 Token。看着便宜对吧？但 Copilot 这种产品，一次对话动辄几千 Token，乘以**月活上亿**，乘以**人均每天数十次调用**，分子分母一摆，单月推理账单轻松破亿美元。
- **微软的尴尬**：Office Copilot 早期定价 30 美元/月/人，但内部测算单用户推理成本一度逼近、甚至超过这个数字。卖一份亏一份的生意，谁都做不久。

所以「微软烧不起 Token」不是段子，而是字面意义的财务现实。

## 二、DeepSeek 凭什么成了「平替」候选

DeepSeek 这两年在开源圈子里口碑爆棚，不是因为它营销做得多花，而是它在**架构 + 训练效率**上做了几件硬功夫的事。

1. **MoE（Mixture of Experts）路线走得彻底**
   - DeepSeek-V2 / V3 采用稀疏激活的 MoE 结构，总参数量可以上探到几百 B，但每个 Token 实际只激活 20~40B 左右。
   - 这意味着「**模型容量大、推理便宜**」的好事可以同时拿到——对 Token 成本极度敏感的场景就是天选用例。
2. **MLA（Multi-head Latent Attention）压缩 KV Cache**
   - 传统 Attention 的 KV Cache 是显存大户，尤其在长上下文时。MLA 用低秩投影把 KV 压缩到一个小得多的潜空间，显存占用骤降。
   - 直接结果：同一张卡能服务更多并发用户，单 Token 摊销成本下来了。
3. **FP8 训练 + 自研训练框架**
   - V3 的训练成本被压到约 558 万美元，对比同量级模型动辄上亿美元的训练账单，差了一个数量级。
   - 训练便宜不直接等于推理便宜，但说明团队对底层算子和数值精度的掌控非常细。
4. **开源 + 宽松许可**
   - 权重可下载、可商用、可微调。对于希望「**把推理拉回自家机房**」的大厂来说，这是闭源 API 永远给不了的自由度。

一句话：DeepSeek 给出的不是「便宜一点」，而是「便宜一个数量级 + 可控」的组合拳。

## 三、为什么大厂会主动「降级」到开源模型

外行可能会奇怪：用更弱的模型不就是产品体验变差吗？其实没那么简单。

- **模型路由（Model Routing）已经是行业标配**
  - 一个成熟的 AI 产品后端，往往是「**分诊台**」结构：简单问题（改个错别字、总结一段文字）走小模型；复杂推理（代码、数学、多步规划）才路由到 GPT-4 / Claude 级别。
  - 据公开测算，**80% 的用户请求都属于「简单档」**，这部分完全可以用 DeepSeek、Llama、Qwen 这种开源模型承接，体验几乎无感。
- **闭源 API 的隐性税**
  - 一是**价格不透明**：随时可以涨/降，业务方完全被动。
  - 二是**数据合规**：金融、医疗、政企客户很难接受核心 prompt 被送到第三方服务器。
  - 三是**配额风险**：高峰期被限流，对产品 SLA 是灾难。
- **自部署的边际成本**
  - 当 QPS 足够高时，自建推理集群的单 Token 成本能压到 API 价格的 1/5 到 1/10。
  - 微软自己有 Azure，硬件、机房、网络都是自家的，「肉烂在锅里」比给 OpenAI 交过路费划算得多。

这也解释了为什么不只是微软，亚马逊、Meta、字节、阿里都在做类似的事——**只是有的公司更敢公开承认**。

## 四、对开源生态意味着什么

这件事放在更长的时间线看，是一次小型的「**范式转移**」。

- **「能力差距」正在变成「成本差距」**
  - 2023 年的叙事是：闭源模型遥遥领先，开源追不上。
  - 2024~2025 年的叙事变成：开源在多数 benchmark 上已经追到 90% 水位，剩下 10% 的差距，是不是值得多付 10 倍的钱？大量企业的答案是「不值」。
- **推理引擎成为新战场**
  - vLLM、SGLang、TensorRT-LLM、llama.cpp 这些推理框架的迭代速度肉眼可见。同一个模型在不同框架上，吞吐能差 2~5 倍。
  - 「**会调推理**」正在成为 AI 工程师比「会调 prompt」更稀缺的技能。
- **小模型 + 长推理 vs 大模型 + 短推理**
  - o1 / R1 路线证明：让小模型「多想一会儿」（test-time compute），效果可以追上大模型直答。
  - 这进一步利好开源——因为你能完全控制推理预算，而 API 模式下「思考时间」是黑盒计费。

## 五、冷思考：3 条可以拿走的实用建议

如果你是产品 / 工程 / 创业方向的同学，可以记一下：

1. **别一上来就 All in 最强模型**。先把你的请求按难度分桶，统计真实分布，再决定哪一桶必须上旗舰 API，哪一桶用开源就够。多数团队会发现自己「过度配置」了至少 50%。
2. **把推理成本当成一等公民指标**。除了准确率，请同时跟踪「单次会话成本」「P95 延迟」「Token / 美元」。一个产品能不能规模化，往往不取决于模型多聪明，而取决于这三个数字。
3. **不要把「开源」和「免费」划等号**。自部署意味着你要承担 GPU、运维、监控、安全、版本升级的全部成本。算清楚 TCO（总拥有成本）再决定是租 API 还是自建——很多时候，**月活百万以下，老老实实买 API 反而最便宜**。

大模型这场牌局，前两年比的是谁能把模型做大，今年开始比的是谁能把成本做小。微软选择 DeepSeek 不是「认输」，而是承认了一个朴素事实：**在工程世界里，能跑、好用、便宜，比什么都重要**。
