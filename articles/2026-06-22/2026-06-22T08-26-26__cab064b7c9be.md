最近 OpenAI 干了一件挺反常识的事——把 Codex（也就是它新一代的编程智能体产品）从「只支持自家 GPT 模型」改成了「可以挂载第三方模型」。在大模型公司普遍越锁越紧的当下，这一步被业界解读为 OpenAI「最开放的一次」。听上去像是奥特曼突然变佛系，但只要把账算清楚，你会发现这更像是一次精明的产品策略调整，而不是单纯的「释放善意」。下面把这件事掰开揉碎讲一讲：Codex 到底是个啥、为什么要放开模型、对开发者意味着什么、又会如何改变编程工具的竞争格局。

## 先把 Codex 这个词的「三重身份」说清楚

很多人一听 Codex 就懵，因为这名字 OpenAI 用了三次，每次指代的东西都不一样。

- **2021 年的 Codex 模型**：那是 GitHub Copilot 第一代背后的代码模型，本质是 GPT-3 在公开代码语料上微调的产物。这个版本后来在 2023 年被官方宣布弃用。
- **2024 年底的 codex-cli**：一个开源的终端命令行工具，让你在 shell 里直接喊大模型干活，比如 `codex "帮我把这个目录的 png 全部压缩"`。
- **2025 年的 Codex Agent 产品线**：这一代才是真正意义上的「编程智能体」，能读懂整个仓库、自己跑测试、提 PR、改 bug，跑在云端沙箱里，像一个 24 小时在线的初级工程师。

这次「不再独宠 GPT」，说的就是第三代 Codex Agent。原本它默认调用 OpenAI 自家的 codex-1（基于 o3 蒸馏的推理模型）和后续的 GPT-5 系列，现在则允许接入 Claude、Gemini 甚至开源模型作为执行引擎。注意：**不是底层 API 开放，而是 Agent 这个壳子允许换芯**。区别很关键，后面会讲为什么。

## 为什么 OpenAI 突然「松口」？三层逻辑

表面看是开放，里面其实有一整套商业算计。

1. **编程是 Agent 落地最快的场景，OpenAI 不想错过 workflow 入口**
   - 编程类任务有明确的成功信号（代码能不能跑、测试过不过），这让 Agent 的强化学习反馈循环特别顺。换句话说，AI Coding 是当下唯一一个「闭环跑得通」的 Agent 赛道。
   - 谁掌握了开发者的日常工作流，谁就握住了下一代生产力工具的分发渠道。Cursor、Windsurf、Claude Code、GitHub Copilot 已经卷成红海，OpenAI 必须把 Codex 的产品形态做厚，而不只是卖模型 token。

2. **模型同质化越来越严重，单点优势撑不住生态**
   - 在 SWE-bench Verified 这类编程基准上，GPT-5、Claude Sonnet 4.5、Gemini 2.5 Pro 的得分已经互相咬住，差距通常在个位数百分点。
   - 当模型本身的差异变小，「产品体验 + 工具链 + 沙箱环境」这一层的护城河反而更重要。OpenAI 想把 Codex 做成一个「模型无关」的 Agent 平台，类似 VSCode 之于编辑器市场。

3. **防御性开放：与其用户用 Cursor 调 Claude，不如让他们在 Codex 里调 Claude**
   - 这是最现实的一层。开发者用脚投票，很多人在 Cursor 里同时挂着 GPT 和 Claude，谁好用用谁。OpenAI 如果继续锁死，自己 Agent 产品的用户就被 Cursor 截胡。
   - 把模型选择权交出来，换的是 Codex 这个「产品容器」的用户停留时长。容器留住了，未来再通过沙箱、记忆、上下文管理这些「中间件」收钱。

## 技术上「换模型」到底换的是啥

这里要破除一个常见误解：以为 Agent 换模型就是改个 API endpoint。实际工程上要复杂得多。

- **Tool use 协议要兼容**：OpenAI 用的是 function calling 的 JSON schema，Anthropic 用的是 tool_use block，Google 又是另一套。Codex 中间得有一层 adapter 把 Agent 内部的工具调用翻译成对应模型能理解的格式。
- **上下文窗口和缓存策略要重新调**：Claude 3.5+ 的 prompt caching 计费方式和 GPT 不同，长上下文场景下成本曲线差异很大。Codex 需要根据当前模型动态决定「整个仓库塞进 context」还是「分块检索」。
- **推理链路差异**：o 系列模型是 thinking-first，Claude 走的是 extended thinking + tool use 交错，Gemini 有自己的 multi-turn 规划。Agent 的 planner 模块得针对不同模型调不同的 prompt。
- **安全沙箱不变**：这是 Codex 的核心壁垒。无论你换什么模型，跑代码的容器、文件系统隔离、网络访问控制都是 OpenAI 自己控制的。你换的是大脑，身体还是它的。

所以「开放」是有边界的——**模型层开放，执行层封闭**。这也是为什么说 OpenAI 这次没有那么「佛」。

## 对开发者意味着什么：四个实际变化

抛开战略博弈，回到日常使用层面，普通开发者会感受到这些变化：

- **同一个 Agent 任务可以试不同模型「投票」**。比如让 GPT-5 和 Claude 各跑一遍同一个 bug fix，对比谁的 diff 更干净。这对复杂重构特别有用，因为不同模型的「代码审美」差异明显。
- **成本结构会更灵活**。简单的脚手架生成用便宜的开源模型（比如 Qwen3-Coder），关键的架构设计用最强的闭源模型。Codex 如果做出自动 routing，token 账单可能降 30% 以上。
- **企业私有部署的可能性变大**。原本 Codex 只能跟 OpenAI 走，金融、政府等敏感行业用不上。现在如果允许挂载本地部署的开源模型，准入门槛立刻不一样。
- **「Agent 的可观测性」会成为新刚需**。模型一换，行为就变；同一个 prompt 在不同模型下产生不同的工具调用序列。trace、replay、diff 这些工程工具会火起来，类似当年 APM 之于微服务。

## 历史会重演吗：从浏览器战争到 AI Agent 战争

往回看 20 年，这种「先封闭做大、再开放做平台」的剧本并不新鲜。

- **浏览器**：IE 靠捆绑 Windows 封闭做大，最后输给了拥抱 Web 标准的 Chrome。
- **移动 OS**：iOS 一直封闭，但 App Store 抽成开放给所有开发者；Android 走全开源路线吃下另一半市场。
- **云**：AWS 早期只卖自家服务，后来主动开放 Kubernetes、容器、第三方数据库，反而做厚了平台。

AI Agent 这个赛道，目前的格局还在「IE 阶段」——每家都想用自家模型独占用户。OpenAI 这次的动作，相当于提前进入「Chrome 阶段」：把产品和模型解耦，赌的是**产品体验和生态网络效应比模型代差更持久**。这个判断对不对，未来 18 个月会有答案。

## 三条冷思考，给你带走

1. **「开放」不是道德选择，是商业策略**。当一家公司从封闭走向开放，往往意味着它判断「单点优势已经守不住，必须扩大战线」。看待这类新闻，先问「它为什么现在开放」，比问「它开不开放」更有信息量。

2. **模型会越来越像水电，产品才是真正的差异化**。如果你是工具开发者，把所有筹码押在某一个模型上是危险的；把 prompt、工具链、上下文管理这些「中间层」做扎实，才是长期资产。

3. **Agent 的瓶颈早就不是模型智商，而是工程脚手架**。沙箱、权限、记忆、回滚、可观测性——这些听起来「不性感」的能力，决定了 Agent 能不能从 demo 走到生产。下次评估一个 AI 编程工具，别只看 benchmark 分数，看它怎么处理「失败重试」和「长任务中断恢复」，那才是真功夫。

OpenAI 这次开了一扇门，但门后面是更大的棋盘。坐在键盘前的我们，至少多了一个选择——这本身就是好事。
