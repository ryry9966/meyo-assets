## 背景

在 OpenClaw 社区，分享自动化工作流、MCP 插件和 Agent 配置是常见做法。但风险往往被低估：Agent 在处理导出、总结、生成发布内容时，会把上下文中的内部信息带进公开帖子。泄露的不只是 API Key，还有内部路径、MCP 服务名、表名、业务规则。本文讨论如何给 Agent 设置安全边界，避免在社区交流中越线。

## 问题不只是密钥

很多人只盯着硬凭证：API Key、Token、Cookie、数据库密码。但实际泄露范围更宽：

1. **硬凭证**：`sk-`、`Bearer`、AWS AKIA、数据库密码。
2. **元信息**：内部域名、IP、绝对路径、用户名、项目代号。
3. **工作流语义**：MCP server 名称、工具名、SQL 表名、prompt 片段、业务规则。

第三类最容易被忽略。比如 `/home/deploy/order-sync` 暴露部署用户和业务模块；`prod-jump-01` 暴露主机角色；`mcp-server-crm` 暴露内部系统依赖。哪怕没有直接泄露密码，这些信息也能帮助外部人员推断内部架构。

## 做法：把“可能公开”当作默认假设

### 1. 隔离可分享上下文

给 Agent 配置“公开分享”专用 profile。系统提示明确禁止输出以下内容：文件绝对路径、环境变量名、密钥、内部域名/IP、真实主机名、表名、客户数据。同时创建工作目录，只放入脱敏后的示例文件，不要让 Agent 读整个 home 目录或项目根目录。

例如在 OpenClaw 中，不要直接让 Agent 基于生产对话历史写帖子。可以新建一个沙箱对话，只提供需要展示的虚构数据。

### 2. 使用脱敏脚本

在发布前对导出内容做自动扫描。除通用密钥规则外，增加 OpenClaw 常见模式：`OPENCLAW_API_KEY`、`MCP_SERVER_URL`、`/home/`、`/Users/`、`10.`、`192.168.`、`*.internal`。

示例脚本片段：

```python
import re

patterns = [
    r"(?i)(sk-[A-Za-z0-9]{16,})",
    r"(?i)(Bearer [A-Za-z0-9\-._~+/]+=*)",
    r"(/home/|/Users/)[^\s\"']+",
    r"\b(10\.\d{1,3}\.\d{1,3}\.\d{1,3}|192\.168\.\d{1,3}\.\d{1,3})\b",
    r"\b[a-zA-Z0-9.-]+\.internal\b",
]
# 替换为 [REDACTED]
```

脚本应输出命中列表供人工复核，而不是直接覆盖原文件。这一步可以避免误杀后无法恢复。

### 3. 工具与配置层默认脱敏

MCP 工具定义不要在描述中写生产系统地址，改用环境变量注入。公开示例中的 URL 使用 `https://sandbox.example.com`，Token 用 `{{YOUR_TOKEN}}`。配置文件的公开版本应删除 `env` 块或改为占位符。

### 4. 文件系统最小权限

限制 Agent 可访问目录，白名单只放示例项目。MCP server 运行在独立用户或容器中，避免读取宿主机的 `.ssh`、`.aws`、`.env`。即使 Agent 被诱导输出文件内容，也拿不到敏感文件。

### 5. 发布前检查清单

- 无真实凭证或 Token 片段
- 无内部域名/IP/绝对路径
- 无真实组织名、用户名、项目代号
- 截图中终端提示符已裁剪
- 工作流步骤使用虚构数据
- 未直接贴完整 OpenClaw/MCP 配置

## 踩坑点

- **只脱敏密钥，保留路径**：路径里包含用户名和业务模块，仍可推断内部结构。
- **社区求助时直接贴完整配置**：包含 MCP token 或内网地址，即使打了个马赛克，也常有字段名泄露。
- **让 Agent 根据生产对话历史生成帖子**：AI 会把真实案例、客户名称或内部代号写进去。
- **截图中的终端提示符**：`user@prod-jump-01`、浏览器地址栏内部系统名都可能暴露环境。
- **插件发布时未清理 `.env`、测试数据、历史记录**：打包时混入本地文件。
- **在线日志粘贴服务**：自动公开 headers 中的 Cookie，调试时尤其危险。

## 可复用建议

- 维护一个 `sanitize_export.py`，集成到发布流程：导出 -> 脱敏 -> 模型审查 -> 人工确认 -> 发布。
- 使用双模式提示词：日常内部讨论可以自由使用术语；公开分享工作区强制使用 `sandbox` 和虚构数据。
- 用 git hook 扫描 secret，可选 `detect-secrets` 或 `gitleaks`，但需加上自定义规则，否则抓不到内部路径和域名。
- 社区分享模板：只贴输入输出样例，不贴系统 prompt 和完整配置；配置只给关键片段且所有值用占位符。
- 把敏感信息放进环境变量或 secret manager，而不是 prompt、工具描述或配置文件。
- 让一个不含上下文的本地小模型对分享内容做一次泄露风险检查，重点问：“有没有看起来像内部系统、路径或身份的线索？”

## 总结

Agent 安全红线不只是防止 API Key 泄露，更是防止工作流语义和内部元信息在社区公开。通过隔离上下文、自动化脱敏、最小权限和发布前审查，可以在不过度增加成本的前提下把风险降下来。默认配置应当假设“Agent 生成的内容可能被公开”，而不是等泄露后再补救。
