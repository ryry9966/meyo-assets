36kr 这条“Google开卖TPU，大厂想靠AI芯片生产低价token”的热议，表面看是芯片新闻，实际是在说一件更接地气的事：以后调用大模型，价格能不能继续降。token 可以理解为模型读写文本的“计价颗粒”，谁能把每个 token 的计算成本压低，谁就更有机会在 AI 服务里打长期仗。

## “开卖TPU”到底卖的是什么

先把概念校准一下：这里的“开卖”，多数情况下不是像买显卡一样把 TPU 芯片寄到你公司前台，而是通过云服务开放 TPU 算力。

- **TPU 是什么**  
  TPU，全称 Tensor Processing Unit，是 Google 为机器学习设计的 ASIC。它不像 GPU 那样追求“什么都能算”，而是重点优化矩阵乘法、张量计算和高吞吐推理。

- **时间线并不短**  
  - 2015 年左右，TPU 已在 Google 内部用于搜索、翻译等业务。  
  - 2018 年，Cloud TPU 开始面向外部开发者。  
  - 后续 v4、v5e、v5p、Trillium 等版本，分别在训练、推理、能效和集群互联上迭代。

- **它和 GPU 的差别**  
  GPU 像“多功能工程车”，生态成熟，CUDA、PyTorch、各种 kernel 优化都很强；TPU 更像“专线高铁”，路线规划好时吞吐很猛，但对框架、编译器、模型结构和批处理方式更挑剔。

所以，新闻里的重点不是“多了一种芯片货架”，而是：AI 计算的供给侧多了一个重量级选项。对客户来说，多一个选项，议价空间就不是 0，采购同学终于不用只盯着一个报价表流汗。

## 低价token的账本：芯片只是第一行

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-06-25/52284b2e12b76a0c.png)

一个 token 的成本，不是“芯片单价 ÷ token 数”这么简单。真正的账本大致长这样：

1. **硬件成本**  
   包括芯片、HBM 高带宽内存、服务器、网络设备、机房折旧。大模型推理尤其吃内存带宽，HBM 有时比算力更像“收费站”。

2. **电力与散热**  
   推理服务 24 小时在线，电费不是小数。芯片能效提升，意味着同样 token 数少烧电，也少让机房变成烤箱。

3. **利用率**  
   设备买来闲着，成本照样走。云厂商最怕的不是机器不够强，而是高峰排队、低谷吃灰。  
   - 批处理 batching 做得好，吞吐上去；  
   - 请求调度差，昂贵芯片就会在等待中思考人生。

4. **模型效率**  
   同样任务，7B 模型能解决，就别每次都拉 70B 出场。常见优化包括：  
   - FP8、INT8、INT4 量化；  
   - speculative decoding 推测解码；  
   - KV cache 复用；  
   - MoE 只激活部分专家；  
   - 长上下文缓存与前缀复用。

5. **服务质量要求**  
   便宜 token 往往和延迟、稳定性、上下文长度相关。你要“秒回”和“超长上下文”，成本就会上去。工程世界没有免费午餐，最多有打折套餐。

大模型推理还可以拆成两段看：

- **Prefill**：模型先读完输入，上下文越长越贵。  
- **Decode**：模型一个 token 一个 token 往外吐，更依赖低延迟和内存访问效率。

因此，“低价 token”本质是硬件、软件、调度、模型压缩一起压成本。芯片是发动机，但车能跑多省油，还要看变速箱、路况和司机是不是在原地轰油门。

## 大厂为什么都想做自己的AI芯片

Google 做 TPU，不是孤例。云厂商和模型公司自研芯片，背后有几条很现实的逻辑。

- **减少供应约束**  
  AI 计算需求增长太快，只靠通用加速卡，很容易遇到排队、涨价、交付周期长。自研芯片至少能让关键业务有“自家粮仓”。

- **压低长期成本**  
  大厂每天跑海量推理，哪怕单次请求省一点点，乘以亿级调用量也很可观。token 成本每下降 10%，财务表上都会有声音。

- **软硬件协同**  
  自研芯片可以围绕自家模型和业务优化：  
  - 搜索推荐需要高吞吐；  
  - 办公助手需要低延迟；  
  - 视频理解需要多模态数据流；  
  - 云服务需要多租户隔离。  
  通用硬件要兼顾所有人，自研硬件可以先讨好自己。

- **形成云服务差异化**  
  如果某家云能提供更便宜、更稳定的推理实例，它卖的就不只是算力，而是“单位成本优势”。这会影响开发者选哪家 API，也会影响企业把模型部署在哪里。

不过，自研芯片不是写个 OKR 就能长出来。难点包括先进制程、封装、HBM 供应、互联网络、编译器、算子库、框架适配。芯片 tape-out 只是第一关，真正难的是让开发者少踩坑。毕竟，能跑 demo 和能撑住生产流量，中间隔着一片虾塘。

## TPU会把GPU价格打下来吗

短期看，不要期待一夜之间“全场五折”。长期看，替代供给增加，确实会改变市场结构。

- **会带来压力的部分**  
  对于稳定、规模化、可预测的推理任务，TPU 或其他 AI ASIC 很有机会拿到更好的性价比。云厂商如果能把这部分成本降下来，API 价格就有继续下探空间。

- **GPU 仍然很强的部分**  
  GPU 的优势在生态和灵活性。新模型、新算子、新训练方法层出不穷，研究和迭代阶段更依赖成熟工具链。很多团队宁愿多花点钱，也不想把时间花在兼容性问题上。

- **未来更可能是分工**  
  - 前沿模型训练：GPU 仍会很重要；  
  - 大规模推理：TPU、Inferentia、Trainium、各类 ASIC 会分走更多任务；  
  - 企业私有化部署：还要看供应、软件栈和运维能力。

也就是说，低价 token 不会只由某一颗芯片决定，而是由“谁能把整条流水线做得更顺”决定。芯片大战的终点，不是参数表赢了，而是账单变薄了。

## 给开发者和普通用户的3条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-06-25/fbb3851fd56ce3ae.png)

1. **别只看模型名，要看单位经济性**  
   选 API 或云实例时，至少比较三项：每百万 token 价格、平均延迟、失败重试成本。便宜但经常超时，最后可能更贵。

2. **把任务分层，不要大模型包打天下**  
   简单分类、摘要、结构化抽取，可以用小模型或缓存；复杂推理、代码生成、长文分析，再调用更强模型。省钱不是抠门，是架构设计。

3. **关注可迁移性，别被单一栈绑死**  
   TPU、GPU、各种专用芯片都会共存。模型格式、推理框架、监控指标、数据治理尽量标准化。未来价格战来了，能平滑迁移的人，才真正吃得到低价 token 的红利。
