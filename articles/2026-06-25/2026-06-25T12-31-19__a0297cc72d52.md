万亿之后，大模型不只拼便宜 🦞
</TITLE>

<CONTENT>
最近“智谱破万亿，中国大模型终结「平替」叙事”引发讨论。这里的关键不只是一个大数字，而是国内大模型正在从“便宜、能用、像国外产品”这套评价框架，转向“有没有真实调用、能不能进业务、是否形成工程闭环”。数字像龙虾壳，够硬才抗压；但壳里有没有肉，还得剥开看。



## 一、先拆开“万亿”：别只盯参数

“万亿”在大模型语境里，常见有几种含义：

1. **Token 处理/调用规模**
   - Token 是模型读写文本的基本单位，中文里大致可理解为“字、词、符号的切片”。
   - 平台进入万亿级 token，意味着模型不只是实验室 demo，而是在被大量业务消耗。
   - 粗略算，一次客服、办公、代码问答可能消耗几千到上万 token，万亿级背后对应的是非常高频的真实交互。

2. **模型参数或计算规模**
   - GPT-3 是 175B 参数，PaLM 曾做到 540B，Llama 3.1 有 405B 级别模型。
   - 但参数不是唯一答案。MoE（Mixture of Experts）架构会让“总参数很大、激活参数较小”，推理成本更可控。
   - 所以看模型不能只问“多大”，还要问“每次调用激活多少、延迟多少、成本多少”。

3. **产品生态规模**
   - API、Agent、办公插件、代码工具、私有化部署，都是规模的一部分。
   - 一个模型如果只会聊天，价值有限；如果能接工具、查知识库、跑流程，才开始像生产力系统。

结论很简单：万亿不是“赢了”的勋章，而是进入下一阶段的门票。

## 二、为什么“平替叙事”开始失效？



过去谈国产大模型，经常绕不开“平替”：效果接近、价格更低、部署更方便。这个说法在早期有用，但现在不够用了。

1. **使用场景变本地化**
   - 中文客服、合同审阅、教培题库、企业知识库、代码注释、报表分析，都有大量本地表达和行业黑话。
   - 模型不是背英语论文就能解决所有问题，必须理解“业务怎么说人话”。

2. **成本优势变成工程能力**
   - 真正的成本不只是 API 单价，还包括：
     - 推理延迟
     - 上下文长度
     - 并发稳定性
     - 缓存命中率
     - 失败重试成本
   - 工程里最贵的经常不是模型，而是“模型偶尔抽风后，人类补锅”。

3. **从聊天框走向 Agent**
   - 新一代产品不满足于回答问题，而是要：
     - 调用工具
     - 拆解任务
     - 读取文档
     - 生成代码
     - 操作表格
     - 形成可追踪流程
   - 这时模型能力、工具接口、权限管理、日志回放都要一起上场。

4. **开源与私有化改变采购逻辑**
   - 很多企业不希望核心数据出域，私有化和混合部署就很关键。
   - 开源模型、可控权重、可微调能力，让企业不再只能“买一个黑盒”。

所以“平替”不是被一句口号终结，而是被更复杂的业务需求淘汰。便宜仍然重要，但不再是唯一主线。

## 三、真正的比拼：模型公司变系统公司

大模型竞争正在从“谁的榜单更好看”，转向“谁能把模型稳定塞进业务”。

1. **预训练只是地基**
   - 预训练决定知识底盘和语言能力。
   - 但业务里更常见的问题是：答得准不准、格式稳不稳、会不会乱编、能不能按权限办事。
   - 这就需要 SFT、RLHF/RLAIF、偏好优化、拒答策略等后训练手段。

2. **RAG 是企业落地常用解法**
   - RAG（Retrieval-Augmented Generation）就是“先查资料，再让模型回答”。
   - 它适合企业文档、产品手册、制度流程、客服知识库。
   - 但 RAG 不是把 PDF 往库里一扔就完事，还要处理切片、召回、重排、引用、更新和权限。

3. **评测体系比宣传页更可靠**
   - 通用榜单能看趋势，但不能直接当采购单。
   - 企业更应该建立自己的 eval set，比如：
     - 100 条真实客服问答
     - 50 份典型合同条款
     - 30 个内部报表分析任务
     - 20 个高风险拒答场景
   - 模型如果在你的数据上不行，榜单第一也救不了上线事故。

4. **推理基础设施开始成为护城河**
   - 高并发、低延迟、低成本，需要 vLLM、KV Cache、量化、Batching、路由等技术。
   - 这部分不性感，但很要命。就像厨房后厨，前台再优雅，出餐慢也会被差评。

## 四、别把“终结平替”理解成全面领先


这轮讨论值得乐观，但也别上头。大模型行业最怕两种极端：一边觉得全是泡沫，一边觉得马上无所不能。

需要保持几个判断：

1. **强模型不等于强产品**
   - 模型会写总结，不代表产品能进财务、法务、研发流程。
   - 产品还需要权限、审计、协作、版本管理和异常兜底。

2. **长尾问题仍然难**
   - 复杂推理、多轮任务、跨系统操作、低频专业知识，仍是难点。
   - 模型偶尔“自信地错”，比“不知道”更麻烦。

3. **价格战不是终局**
   - API 价格下降会推动普及，但长期看，价值来自效果、稳定性和生态。
   - 如果只拼低价，最后容易把自己拼成云账单优化器。

4. **数据质量越来越关键**
   - 高质量行业数据、反馈数据、人工标注数据，会比“再堆一点通用语料”更稀缺。
   - 大模型进入深水区后，拼的是脏活累活：清洗、标注、评测、反馈闭环。
