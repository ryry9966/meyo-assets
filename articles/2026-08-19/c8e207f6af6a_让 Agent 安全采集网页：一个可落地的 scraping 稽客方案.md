## 背景

在 OpenClaw 或类似 Agent 框架里，读取网页是高频需求：让 Agent 查资料、看文档、抓取页面摘要、监控变更。但“让 Agent 直接上网抓取”这个动作远比听起来危险。

Agent 很容易把抓取变成不可控行为：跟随任意跳转、执行页面脚本、下载大文件、触发反爬、把整页 HTML 甚至内嵌广告塞进上下文。真正需要的是一个受约束的“稽客”层——它负责对采集目标做前置稽核、请求控制、内容清洗和审计，只把结构化、干净、合规的文本交给 Agent。

## 问题

直接给 Agent 一个 `requests.get` 或裸浏览器工具，通常会遇到四类问题：

1. **动态内容抓不到**：纯 HTTP 客户端拿不到 JS 渲染后的正文，尤其文档站、SPA、前端渲染的博客。
2. **行为不可控**：无头浏览器会执行页面脚本，可能自动跳转、弹窗、下载文件、请求第三方域。
3. **触发风控**：同一 UA 高频访问、不做限速、不检查 robots，轻则 403，重则封 IP。
4. **上下文污染**：抓回来的 HTML 混杂导航、广告、脚本、样式、跟踪参数，直接把 token 打爆。

这四类问题不能靠给 Agent 写更长的提示词解决。提示词只能约束意图，无法约束工具行为。正确做法是把抓取封装成一个受限工具，让 Agent 只能通过这个工具访问网络。

## 做法/步骤

下面以 MCP server 中的 `scrape_url` 工具为例，给出一个可落地的实现路径。

### 1. 前置校验

在发起任何请求前，先校验：

- URL 协议只允许 `http` 和 `https`，拒绝 `file`、`ftp`、`javascript` 等。
- 域名命中白名单才放行；若无白名单，至少做 DNS 解析并检查私网地址，防止 SSRF。
- 检查 robots.txt（可缓存），若目标路径被禁止，返回结构化拒绝信息，并说明原因。

### 2. 选择抓取引擎

默认走轻量 HTTP 客户端 + readability 提取正文，适合静态页面和文档站。只有需要 JS 渲染时才启用无头浏览器，例如 Playwright。不要让浏览器成为默认选项——它慢、重、风险高。

### 3. 请求控制

无论哪种引擎，都要设置：

- 固定或轮换 User-Agent，避免默认 Python/Node UA。
- 单请求超时 10–15 秒，整体超时 30 秒。
- 最大响应体限制，例如 2 MB，超出直接中止。
- 重定向次数上限（3 次以内），且重定向目标必须再次经过域名校验。

### 4. 浏览器沙箱

如果启用无头浏览器，至少做以下限制：

- 禁用弹窗、新窗口、自动下载。
- 拦截第三方域请求：只允许目标域及其必要的 CDN、静态资源域。
- 关闭地理位置、通知、摄像头等权限。
- 用独立 browser context，不继承用户主 profile 的 Cookie 和登录态。

### 5. 内容清洗

拿到 HTML 后，先移除 `script`、`style`、`nav`、`footer`、`iframe`、`svg`、注释，再提取标题、正文、代码块、表格，转成 Markdown。注意保留代码块的语言标注和表格结构，否则技术文档会被破坏。

### 6. 结构化输出

工具返回一个 JSON 对象，而不是大段文本：

```json
{
  "url": "https://example.com/docs",
  "title": "Example Docs",
  "text": "清洗后的 Markdown 正文",
  "links": ["https://example.com/next"],
  "metadata": {
    "status_code": 200,
    "engine": "http",
    "fetched_at": "2025-01-01T00:00:00Z",
    "content_hash": "abc123"
  }
}
```

同时按 token 或字符数截断，例如正文最多 8000 字符，超出部分提示用户使用 `selector` 参数精确提取。

### 7. 审计日志

每次抓取记录：时间、URL、状态码、引擎、耗时、内容哈希、是否命中缓存、是否触发限速。日志不要包含完整正文，避免敏感信息泄漏。

## 踩坑点

实际落地时，这几个坑最容易踩：

- **robots.txt 不是万能的**：有些站点 robots 禁止但提供公开 API，应允许用户在策略中覆盖，而不是一刀切拒绝。
- **不要固定 sleep 等待渲染**：用 `waitForSelector` 或 `waitForLoadState` 加超时，比盲目 sleep 更稳、更快。
- **反爬不止 UA**：同一 IP 高频访问、缺少 Accept-Language、请求头顺序异常都可能触发风控。对同一域名做 token bucket 限速，例如每秒最多 1 个请求。
- **登录态不要复用主 profile**：Agent 抓取登录后内容时，必须用独立 context，且凭据不能出现在日志或返回内容中。更安全的方式是让用户手动提供短期 Cookie。
- **重定向必须再次校验**：即使初始 URL 在白名单内，重定向到外域也要阻止或返回提示，不能自动跟随。
- **大文件陷阱**：PDF、视频、压缩包会迅速耗尽内存。先看 `Content-Type` 和 `Content-Length`，非 HTML 内容直接拒绝或只返回元信息。

## 可复用建议

如果不想从零开始，可以这样做：

- 把上述逻辑封装成一个 MCP server，只暴露 `scrape_url` 一个工具，减少 Agent 的选择空间。
- 用 SQLite 或内存缓存做 TTL 缓存，相同 URL 在 5–10 分钟内不重复抓取，降低目标站压力。
- 提供 `format` 参数（`markdown` / `text` / `html`）和 `selector` 参数（CSS 选择器），让用户在需要精确提取时能自己控制。
- 失败时返回结构化错误，例如 `{ "error": "blocked_by_robots", "message": "..." }`，而不是让 Agent 从异常堆栈里猜原因。
- 在 Agent 的 system prompt 里加一句：优先使用公开 API；不要对同一 URL 反复重试；遇到验证码或登录墙时停止，不要尝试绕过。

## 总结

安全采集的本质，是把“浏览网页”这个开放行为收敛为受限、可审计的工具调用。Agent 负责判断要抓什么、如何总结，抓取层负责校验、限速、清洗和记录。只要这个边界清晰，Agent 就不容易变成不可控爬虫，反而能稳定地从网页中提取有效信息。

在 OpenClaw 这类框架里，一个设计良好的 `scrape_url` 工具，比给 Agent 装十个浏览器插件更有价值。它不酷炫，但能让你少踩很多坑。
