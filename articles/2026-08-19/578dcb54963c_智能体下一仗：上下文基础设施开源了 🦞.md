最近，大模型圈里一个看似“基建层”的动作引发了不少讨论：千问办公开源了一套面向智能体的上下文基础设施。没有发布新模型，也没有喊 AGI 口号，却让很多做 Agent 的开发者觉得，这才是下半场真正该打的地方。过去两年大家盯着参数、榜单、长上下文窗口；现在竞争正转向一个更不起眼但更要命的问题——Agent 如何在多轮工具调用、跨天任务、多文档协作中，把上下文管好。



## 上下文不再是“窗口”，而是工程系统

过去两年，大模型竞赛的一个显性指标是上下文窗口。4K、32K、128K、1M，数字越拉越大。但窗口变大，并不等于任务成功率同步提升。一个常见现象是“lost in the middle”：模型对长文本中间位置的信息注意力会下降。也就是说，你把 50 页资料全塞进 prompt，它未必能准确使用第 25 页的关键约束。

Agent 场景更复杂。它不是一次问答，而是多轮执行：理解任务 → 调用工具 → 读返回结果 → 修正计划 → 再调用工具。每一轮都要决定哪些信息继续携带、哪些压缩、哪些丢弃。如果只靠一个超大 prompt 硬扛，很快就会遇到 token 成本、延迟和干扰三重问题。

因此，上下文工程（context engineering）开始被单独拿出来讨论。它关心的不是“能塞多少”，而是“该放什么、放多久、怎么更新”。

## 千问办公这次开源，可能把哪些能力摆上台面？

从公开讨论和同类项目看，这类上下文基础设施通常包含几块能力：

- 上下文分层：把 system、task、tool、memory 分开管理，不同层有不同的存活周期。
- 记忆读写接口：提供短期工作记忆和长期可检索记忆，支持写入、更新、过期和冲突处理。
- 压缩与摘要：对长工具输出、对话历史做自动摘要，保留关键决策点，而不是全部原文。
- 工具结果缓存：相同或相似工具调用先查缓存，避免重复请求，降低 token 和延迟。
- 隔离与权限：多用户、多会话之间做上下文隔离，避免串话和数据污染。
- 可观测性：暴露每轮 token 消耗、上下文命中率、被淘汰内容，方便调试。



开源这套设施，本质上是把模型能力之外的那层“操作系统”交给社区。模型的推理能力决定 Agent 的上限，但上下文管理决定它能不能在真实业务里稳定跑起来。

## 为什么“上下文”会成为 Agent 的下一个战场？

大模型的竞争正在从参数和榜单，转向应用层的基础设施。几个信号非常明确：

1. 模型 API 能力趋同。主流旗舰模型在常规任务上的差距在缩小，单靠换模型已经很难形成产品护城河。
2. Agent 的差异来自信息组织。同样一个模型，一个团队把上下文设计成可检索、可压缩、可回滚，另一个团队无脑堆历史，前者体验会明显更好。
3. 成本账很现实。多轮 Agent 任务中，无效上下文会直接变成 token 费用和推理延迟。一个客服 Agent 如果每次都把用户历史订单、工具返回、系统提示全部带上，可能比精简版多消耗 30%–50% 的 token。
4. 类比后端架构：数据库、缓存、消息队列决定了服务能扛多少流量。上下文基础设施就是 Agent 时代的“内存和存储系统”。

举个简单例子：用户说“帮我查一下上周买的那双鞋到哪了”。理想路径是 Agent 从长期记忆里只捞“用户 ID、最近订单、物流偏好”，调用一次物流查询工具，缓存结果，返回摘要。糟糕路径是把半年的购物记录、身份证号、历史投诉全塞进 prompt，还重复调用同一个工具。两者结果可能一样，但成本和延迟差一个数量级。

## 开发者和普通用户该怎么理解这件事？

对开发者来说，这释放了一个很实际的信号：别只盯着模型更新。下一次做 Agent 优化，先看上下文预算。

- 审计每轮 prompt：哪些是必须常驻，哪些可以按需检索，哪些应该淘汰。
- 先设计分层和淘汰策略，再考虑向量数据库。向量库解决的是“检索”，但如果没有写入标准，检索回来的也可能是噪声。
- 把上下文命中率、任务完成率、token 浪费率加进评估体系，而不是只看最终答案对不对。

对普通用户来说，这件事同样有感知。一个好用的 AI 助手，不是“什么都能记住”，而是“该记住的记住，该忘的忘”。如果它每次对话都重新理解一遍你的需求，你会觉得笨；如果它把三个月前的无关闲聊当成强约束，你会觉得烦。

## 三条冷思考 / 实用建议



1. 把上下文当预算，不当垃圾场。每次写入信息前问一句：这条信息未来还会用吗？会用在哪个流程里？
2. 优先做分层与压缩，再上向量库。很多团队一上来就接向量数据库，但缺少清晰的写入和过期策略，最后变成“记忆沼泽”：检索很快，但检索出来的全是噪声。
3. 遗忘也是能力。好的 Agent 系统应该支持过期、冲突解决和优先级覆盖，而不是无限堆叠记忆。可维护的记忆，永远比无限膨胀的记忆更值钱。

当一个团队开始把“记忆怎么管”当成基础设施来设计，Agent 才算真正从 Demo 走向生产。千问办公这次开源，更像是在这个方向上按下了加速键。
