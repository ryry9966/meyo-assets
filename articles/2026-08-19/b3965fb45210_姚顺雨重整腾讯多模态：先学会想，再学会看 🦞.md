36氪这篇《姚顺雨重整腾讯多模态路线：靠拢梁文锋，远离李飞飞》，很容易被读成“腾讯选边站”。但把它放到多模态大模型的技术演进里看，其实更像一次商业落地压力下的路线再平衡：把“推理”放到“看见”前面。

这不是人事八卦，而是一个关键问题：当算力、数据和团队都有限时，多模态模型应该先学会把事做对，还是先把世界看懂？



## 一、“看见”与“推理”，从来不是同一条曲线

多模态大模型内部一直有两条路线，它们解决的核心问题并不相同。

- **李飞飞路线：感知与空间智能**  
  这条路线从 ImageNet 开始，强调让模型理解视觉世界。2024 年李飞飞创立 World Labs，主打“空间智能”，目标是让 AI 理解 3D 结构、物体关系、物理常识，最终能在真实或虚拟世界里导航、操作。它面向的是机器人、AR/MR、自动驾驶等长期场景。

- **梁文锋路线：推理与工程效率**  
  DeepSeek 从 V3 到 R1 展示了一条以强化学习为核心的推理提升路径。它的关键词不是“看得更细”，而是长链条思考、可验证奖励、MoE 架构、FP8 训练、开源权重。目标很直接：让模型在数学、代码、复杂指令里把问题想清楚。

- **多模态模型正好夹在中间**  
  它既需要视觉编码器理解图像，又需要语言模型做决策。过去两年主流做法是“更强的视觉编码器 + 更大的多模态指令数据”，评测集中在 Caption、VQA。但姚顺雨带来的调整，显然想把重心从“看得更细”转向“做得更对”。

## 二、姚顺雨的调整，为什么是“DeepSeek味”



姚顺雨长期研究 LLM reasoning 和 agent，代表作 ReAct 提出“推理 + 行动”的框架：模型不能只输出答案，而要把思考、调用工具、观察环境串起来。这个背景天然偏好推理优先路线。

从公开信息和 36氪报道看，腾讯多模态可能正在发生三个变化：

1. **任务重心转移**  
   从图像描述、视觉问答 benchmark，转向 GUI Agent、图表问答、截图理解、UI 自动化。  
   举例：给模型一张会议软件截图，要求“把周会从下午三点改到四点”。模型需要理解界面元素、输出操作序列，系统最终可以通过界面状态判断任务成功或失败。这类任务比“描述图片氛围”更有产品价值，也更容易自动化验证。

2. **训练方法向 RLVR 靠拢**  
   传统 RLHF 依赖人类偏好打分，成本高、扩展慢。RLVR 用规则或程序自动判断结果：数学答案是否相等、代码测试是否通过、GUI 操作是否完成。信号更干净，模型可以大规模试错。  
   DeepSeek 已经在文本推理上验证了这条路径，多模态只是把“可验证奖励”从数学、代码扩展到界面与图表。

3. **工程架构强调部署效率**  
   MoE 降低训练和推理成本，FP8 压缩计算精度，再配合视觉 token 压缩。这样多模态模型才有可能跑进腾讯会议、微信输入法、文档助手这类高频场景，而不是只停留在研究 demo。

## 三、远离“空间智能”，不等于否定李飞飞

李飞飞方向的空间智能，是一个更长期、更难的科学问题。它需要大量 3D 数据、物理引擎、环境交互和真实世界反馈，对机器人、AR/MR、具身智能非常重要。

但腾讯当前的主战场是社交、内容、广告、办公、游戏。这些场景需要的多模态能力是：看懂 UI、表格、流程图、视频帧、文档截图，然后完成任务。它们更像“办公助理”和“操作员”，而不是“空间导航者”。

所以所谓“远离李飞飞”，更多是资源分配问题：把算力和团队先押在更易验证、更易产品化、回报周期更短的推理侧。空间智能可以作为长期课题保留，但不应该在当下抢占过多工程带宽。

## 四、多模态落地：为什么“推理优先”更务实

图像理解已经内卷。Caption、VQA 榜单接近饱和，提升一两个点，用户几乎没有体感。但真正有商业价值的多模态任务，大多带有“可验证结果”：

- UI 自动化：操作成功或失败可以判断；
- 文档、发票、合同信息提取：字段对错可以校验；
- 广告素材审核：规则命中可以判断；
- 视频帧时序理解：事件顺序可以验证。

这些任务天然适合 RLVR 形成飞轮：模型尝试 → 程序或环境给反馈 → 策略更新 → 成功率提升。DeepSeek 已经证明，用更少的人工标注，配合强化学习和工程优化，可以在推理侧快速逼近甚至超越更大模型。多模态也能复用这套逻辑。

但也要注意，多模态 RL 的难点在于感知噪声。图像里按钮边界不清晰、OCR 错误、元素遮挡，都会让奖励信号不稳定。所以工程上通常要先做好视觉 grounding，再叠加推理策略。不要误以为“推理优先”等于“感知不重要”。

## 冷思考：三条实用建议



1. **产品经理**：先定义“可验证结果”，再决定做多模态。如果你的场景只能让模型给描述，无法自动判断对错，商业化会很难规模化。  
2. **工程师**：把 RLVR、工具调用、轨迹回放纳入训练链路；部署阶段重点看 MoE 推理成本和延迟，而不是总参数。多模态模型的瓶颈往往在视觉 token 数量，先优化 token 压缩。  
3. **研究者和创业者**：不必在“空间智能 vs 推理智能”之间做信仰站队。短期看推理，长期看感知与推理融合。判断框架看三个变量：数据可得性、奖励可验证性、商业回报周期。

腾讯这次多模态变阵，说到底是一句话：先让模型把事做对，再让它把世界看懂。梁文锋路线提供了效率与推理方法，李飞飞路线保留了长期空间智能的想象空间。两者并不对立，只是同一家公司不同阶段的优先级排序。
