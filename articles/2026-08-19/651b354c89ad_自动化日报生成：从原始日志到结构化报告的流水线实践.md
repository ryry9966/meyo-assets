## 背景

团队日常需要汇总多个系统的信息：Git 提交、CI 构建状态、线上告警、任务系统变更、IM 里的关键讨论。人工整理日报的问题很一致：耗时、格式不统一、容易漏掉跨系统关联，比如某个告警其实是昨天一次部署引起的。

我们尝试直接把原始日志丢给 Agent 生成日报，结果并不稳定。要么上下文过长导致漏项，要么模型把“已合并”写成“已上线”，要么输出格式每次都不同。后来改成一条结构化流水线后，稳定性和可维护性明显提升。

## 问题拆解

日报生成的核心不是“写”，而是从多个非结构化源中提取可信事件。难点包括：

- 原始日志噪音大，大量构建日志和机器人提交没有信息量。
- 各系统时间字段不一致，容易把跨天事件记错日期。
- 直接生成 Markdown 文本时，格式漂移严重，难以发布和回溯。
- LLM 可能产生幻觉，把未完成的事情写成完成。

## 做法/步骤

### 1. 先定 JSON Schema

在写任何 prompt 之前，先定义日报结构：

```json
{
  "date": "2025-05-20",
  "sections": [
    {
      "module": "payment",
      "progress": ["..."],
      "risks": ["..."],
      "metrics": {"deploy_count": 2, "error_rate": 0.03},
      "evidence": ["commit:abc123", "deploy:#1234"]
    }
  ]
}
```

Schema 先行，后续所有 Agent 输出都按这个结构校验。

### 2. 采集层：每个源封装成 MCP 工具

在 OpenClaw/Agent 体系里，把每个数据源封装成独立工具，输出统一中间格式：

```json
{
  "source": "git",
  "timestamp": "2025-05-20T09:30:00Z",
  "actor": "alice",
  "action": "merge",
  "detail": "refactor payment retry logic",
  "url": "https://git.example.com/pr/123"
}
```

工具可以是 MCP server，也可以是插件里的本地函数。关键是要让 Agent 看到的是已经归一化的事件，而不是不同格式的原始日志。

### 3. 预处理与过滤

采集后先做确定性处理，不要依赖模型判断：

- 统一 UTC 时间存储，展示时再转本地时区。
- 按团队节奏划定窗口，例如每日 10:00 到次日 10:00，重叠 30 分钟避免漏报。
- 过滤机器人提交、自动构建成功且无变更的事件。
- 对敏感字段做脱敏，保留 `url` 作为证据链。

### 4. 分片结构化提取

不要把所有事件一次塞给模型。按模块或项目分片，每片只处理 30-50 条事件。每个分片要求输出带 `evidence` 的条目，没有证据的进展单独标记为 `unclear`，而不是直接丢弃。

这个阶段用 JSON mode 或 function calling 约束输出，后处理做 schema 校验。校验失败时只重试该分片，不重跑整条流水线。

### 5. 渲染与发布

结构化 JSON 生成后，用模板渲染 Markdown。模板与 prompt 分离，改格式时不需要动 Agent 逻辑。发布前可以停在“待确认”状态，人工补两句再发到 IM 或邮件。

## 踩坑点

**跨时区时间边界**：CI 机器是 UTC，任务系统是本地时区。早期经常把凌晨的部署记到前一天。解决方法是存储层统一 UTC，窗口计算在采集层完成，展示层才做转换。

**JSON 输出不稳定**：部分模型会在 JSON 外包反引号或添加注释。不要用正则硬提，优先使用支持 JSON schema 的接口；如果不行，加一层解析重试，失败就降级为纯文本并告警。

**重复运行产生重复日报**：定时任务重跑或手动触发时，容易发布两次。以日期为唯一键，写入前查重；中间结果落盘，便于重试时复用。

**上下文过长导致漏项**：一次塞入 200+ 事件，模型会忽略中段信息。分片提取后，最后只做汇总，不让模型同时处理所有原始日志。

## 可复用建议

- 先做半自动：Agent 生成草稿，人工确认后发布，稳定后再逐步减少人工。
- 把每个数据源封装成独立 MCP 工具，统一输出 schema，新增数据源只影响采集层。
- 保留原始日志和中间 JSON，方便事后回溯和构建评测集。
- 建立 20-50 条固定评测集，每次换模型或改 prompt 后回归，避免输出漂移。
- 成本控制方面，优先用轻量模型做分片提取，汇总阶段再考虑强模型。

## 总结

自动化日报的难点不在生成，而在采集和结构化。稳定输入、明确 schema、可校验输出，这三点比复杂 prompt 更重要。把确定性处理放在采集和预处理层，把模糊理解留给 Agent，整条流水线才可维护、可复用、可回滚。
