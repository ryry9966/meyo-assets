## 背景

OpenClaw 这类 Agent 框架接入 MCP、插件和自动化脚本后，能力提升很快，但一个尴尬的问题越来越明显：**工具很多，但 Agent 不知道你是谁。**

每次新开会话，它还是会问“你常用的工作目录是什么”“你希望用 Python 还是 Node”“要不要自动提交代码”。更糟的是，当你有多个可用 MCP 工具时，Agent 可能随机选择，生成不符合你习惯的脚本，或者反复触碰你已经明确不想用的工具。

这些信息不是项目规则，不适合写进 AGENTS.md；也不是临时任务上下文，放在每轮对话里太浪费。它们应该有一个稳定、跨会话、跨项目的注入位置。这就是 **USER.md** 的价值。

USER.md 不是备忘录，也不是知识库。它的定位是：**用户级偏好与约束层**，让 Agent 在进入任何任务前先建立“你”的基本模型。

## 问题

没有 USER.md 时，常见问题包括：

- 偏好靠每次会话临时描述，效率低且不一致。
- Agent 在多个可用工具之间乱选，例如用 `curl` 代替你已经配置好的 `gh` CLI。
- 部分敏感操作没有明确边界，Agent 可能主动执行高风险命令。
- 个人工作流信息散落在不同项目，无法跨项目复用。

如果你有多个 Agent 入口，例如 OpenClaw 加本地 CLI 自动化，这种不一致会更明显。

## 做法 / 步骤

### 1. 确定加载位置

OpenClaw 通常支持用户级上下文文件。可以放在 `~/.openclaw/user.md`，也可以在工作区根目录通过 preflight hook 注入到 system/developer 消息中。关键原则是：**USER.md 必须稳定注入，且优先级高于默认系统行为，但低于任务明确指令。**

如果你暂时不确定框架是否自动加载，可以先在启动命令里显式读取：

```bash
openclaw --user-md ~/.openclaw/user.md
```

### 2. 使用分层模板

建议用 YAML frontmatter 加 Markdown 正文，方便机器解析，也方便人工阅读。

```markdown
---
version: 1
priority: user
updated: 2026-01-15
---

# 基本信息
- 常用工作目录: ~/work
- 系统: macOS / Linux
- 时区: Asia/Shanghai

## 工具偏好
- 优先使用 gh CLI，不直接手写 GitHub REST 调用
- 自动化脚本用 Python 3.11，不引入重依赖
- 需要查询时才调用数据库 MCP，避免无意义连接

## 代码风格
- 提交信息遵循 Conventional Commits
- 单文件不超过 200 行
- 不生成无说明的一次性脚本

## 禁止事项
- 不回显 .env 或任何 secret
- 不主动执行 git push --force
- 不安装全局 npm 包
```

### 3. 控制长度

USER.md 不建议超过 300 行。超过这个长度后，模型注意力会被稀释，关键约束容易被忽略。如果你发现内容变长，优先删掉“偶尔有用”的信息，只保留“每次都需要”的信息。

### 4. 维护与版本化

USER.md 应该纳入 dotfiles 管理。每次修改记录版本号和更新日期。可以定期让 Agent 根据最近会话总结你的偏好，生成 draft，你人工确认后合并。这样比纯手写更接近真实需求。

## 踩坑点

1. **写成知识库**：USER.md 不是用来记录项目背景的，那些应该进 AGENTS.md 或文档。把大量项目上下文塞进去，会让 Agent 分不清什么是稳定偏好。

2. **泄露敏感信息**：不要写入 token、密码、内网地址。即使放在私有仓库，也可能在日志、会话摘要或错误输出中泄露。

3. **与项目规则冲突**：USER.md 说“优先使用 Python”，项目 AGENTS.md 说“用 Go”，这种冲突会让 Agent 决策混乱。需要提前约定优先级：任务指令 > 项目规则 > 用户偏好。

4. **写得太死**：例如“永远不调用 X 工具”在多数情况下合理，但遇到无法绕开的场景时，Agent 可能硬憋而不求助。建议写成“默认不调用 X；如需调用，先说明理由”。

5. **过时信息比没有更糟**：如果你换了工作目录，但 USER.md 没更新，Agent 会在错误路径下操作。定期检查是必须的。

## 可复用建议

- 使用 `frontmatter` 记录版本、优先级、更新时间。
- 分成“稳定信息”和“临时偏好”两块，临时内容定期清理。
- 环境相关路径用 `${HOME}` 变量表达，不要写死。
- 和 AGENTS.md 保持边界：项目内的事交给 AGENTS.md，个人的事交给 USER.md。
- 每两周让 Agent 做一次“USER.md 瘦身”，自动检查哪些条目最近未被触发。
- 如果你的团队有多个成员，可以在仓库中维护模板，每个人生成自己的 USER.md，但不要提交到公共仓库。

## 总结

USER.md 不是让 Agent 变得聪明，而是让它减少对你的猜测。它的核心目标只有一个：**把反复确认的上下文成本，从每次会话转移到一份稳定文件里。**

在 OpenClaw、MCP、插件越来越多的环境里，约束和上下文同样重要。一个简洁、准确、版本化的 USER.md，比十页泛泛的个人简介更实用。先写最小可用版本，跑几天，再根据实际触发情况调整，比一次性设计完美模板更靠谱。
