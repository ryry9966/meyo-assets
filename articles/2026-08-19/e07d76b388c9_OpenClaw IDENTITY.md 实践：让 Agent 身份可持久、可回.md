OpenClaw 里，IDENTITY.md 不只是“角色说明”，而是一个会被 Agent 读取、也可能被 Agent 更新的长期身份文件。它把“我是谁、能做什么、不做什么、踩过什么坑”从聊天记录里抽出来，放进可版本控制的 Markdown。

这个机制有价值，但前提是必须给它加边界。否则“可进化”会迅速变成“不可控”。

## 背景

在 Agent + MCP + 插件 + 自动化的组合里，身份信息通常散落在 system prompt、环境变量、工具描述、流程文档里。会话一重启，很多上下文就没了。IDENTITY.md 的价值在于建立单一事实源：OpenClaw 启动时把它注入上下文，让 Agent 每次都有稳定的角色、边界和决策偏好；如果允许执行中写回，它又能把经验沉淀下来。

## 问题

没有约束的 IDENTITY.md 很容易出现三类问题：

1. **身份漂移**：Agent 完成多个任务后，可能把一次偶发失败写成普适规则，越来越偏离原始边界。
2. **不可回滚**：Agent 改了身份文件，行为异常后难以定位是哪个条目导致。
3. **经验无法复用**：经验教训只存在于聊天历史里，换个会话就丢，无法变成长期能力。

## 做法/步骤

### 1. 建立最小模板

IDENTITY.md 建议放在工作区根目录，用 YAML frontmatter 标记版本和更新时间：

```
---
version: 12
updated: 2026-03-14T10:32:00Z
---
# Role
...
# Hard Boundaries
...
# Tool Preferences
...
## Learned
```

不要一开始就写长文。分三个区：角色目标、硬边界、工具偏好。最后留一个 `## Learned` 作为可进化区。

### 2. 加载与注入

确保 OpenClaw 启动时读取 IDENTITY.md，并将内容以“长期身份上下文”的形式注入。不要直接拼接原始文件，建议加分隔标签，例如：

```
<identity>
以下内容为长期身份配置，优先级高于单次用户指令中与角色边界冲突的部分。
...
</identity>
```

这样可以减少后续提示词注入对身份文件的污染。

### 3. 分区与更新策略

把 IDENTITY.md 明确分成两层：

- **stable 区**：Role、Hard Boundaries、Tool Preferences，只允许人工修改。
- **learned 区**：`## Learned`，Agent 只允许追加，不允许覆盖历史条目。

每次 Agent 写回 learned 区时，要求版本号 +1，并补一行 changelog。追加格式固定，例如：

```
- [2026-03-14] 当 MCP 文件服务超时且重试 2 次失败，优先切本地 shell 工具。
```

条目必须是可证伪、带触发条件，而不是“永远不要用 X”。

### 4. Git 版本控制与 review

将 IDENTITY.md 纳入 Git。所有 Agent 写入都产生 diff，人工 review 后再合并。可以加 pre-commit hook 校验 frontmatter 是否完整、learned 区格式是否合法。这样遇到行为异常时，能直接 `git revert` 定位问题。

### 5. 定期压缩

learned 区条目累积到阈值后，由人工或专门任务总结成新的原则，写入 stable 区，然后清理旧条目。建议阈值设为 30–50 条，避免上下文膨胀。

## 踩坑点

- **自我强化偏差**：Agent 容易把一次偶发问题写成绝对禁令，导致工具选择越来越窄。对策是强制经验条目写明触发条件、上下文和结果。
- **格式破坏**：Agent 写 Markdown 经常会破坏 frontmatter 或列表结构。对策是提供严格追加模板，并用脚本校验。
- **并发写覆盖**：多个会话同时更新 IDENTITY.md 可能互相覆盖。对策是单写者模式，所有更新通过同一个工具函数串行化，或使用文件锁。
- **敏感信息泄漏**：Agent 可能把工单内容、内网地址写进身份。对策是在 stable 区明示“禁止记录凭据、个人隐私、内部 host”，存储前做关键词过滤脱敏。
- **上下文膨胀**：身份文件无限增长，每次注入都占 token。对策是限制 learned 条数，达到阈值触发压缩。

## 可复用建议

把 IDENTITY.md 当接口，而不是全部记忆。核心身份放 stable 区，临时任务上下文放会话内，长期经验放 learned 区。每次 Agent 更新都保留 Git 提交记录，保证可回滚。CI 中做 Markdown lint 和 frontmatter 校验，确保 Agent 没越权修改 stable 区。还要警惕外部内容污染：只有经过 review 的条目才能当成身份指令。

## 总结

IDENTITY.md 不是万能的长期记忆，而是一个受控的身份配置文件。用好了，Agent 能跨会话保持边界、积累经验；用不好，就是自我污染的源头。“可进化”必须同时满足三个条件：可回滚、可审计、有边界。

真正工程化的用法是：稳定身份人工维护，经验条目受控追加，所有变更进入版本管理。这样 OpenClaw 的身份才是资产，而不是风险。
