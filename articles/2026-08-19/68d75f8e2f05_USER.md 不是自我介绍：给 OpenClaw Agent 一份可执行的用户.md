## 背景：Agent 为什么总是“不够懂你”

OpenClaw 的 agent 默认没有稳定记忆。每次新会话，它能推理、能调 MCP 工具，但对“你是谁”只有零散片段。于是常见问题：明明昨天说过用 zsh + tmux，今天又让你切 bash；知道你有 NAS，却每次都建议传到对象存储；部署脚本路径变了，agent 还在用旧路径反复失败。

很多人会去调 system prompt 或塞一堆 rules，但效果不稳定。更工程化的做法是维护一个 USER.md：写清楚身份、环境、偏好和边界，作为 agent 的持久用户上下文。

## 问题定位

不是 agent 不够聪明，而是缺少一个低噪声、可维护的用户事实源。Session 内的 context 会丢失，system prompt 里塞满一次性规则会污染推理。USER.md 的目标是：把“每次都要重新交代”的稳定信息沉淀下来。

## 做法：一个可用的最小 USER.md

以下是我在 OpenClaw agent 工作目录使用的结构。你的路径可能不同，关键是让 agent 在启动时读取它，或通过系统提示引用。

```markdown
---
updated: 2026-01-15
scope: personal-agent
---

# 我的环境
- OS: macOS 14 / Debian 12 (remote)
- Shell: zsh，默认使用 `~/bin` 下的脚本
- 常用目录: `~/dev`, `~/notes`, `~/deploy`
- 编辑偏好: 优先 CLI，少用 GUI

# 工作偏好
- 回答语言：中文，技术名词保留英文
- 代码风格：默认 shellcheck 通过，脚本要有错误处理
- 不要做：不要自动执行 `rm -rf`、不要修改 `~/.ssh`

# 自动化上下文
- MCP 工具：filesystem, git, docker
- 插件：定时任务、消息转发
- 部署目标：一台 Debian VPS，通过 Tailscale 访问

# 边界
- 不确定路径/主机时先问我，不要猜
- 敏感信息不要写入聊天记录
```

这个模板的重点不是“全面”，而是“可执行”：每一条都能减少一次追问或一次错误操作。

写完后，在 agent 会话中先问一句：“我的默认 shell 是什么？” 如果答得出，说明 USER.md 已进入上下文；答不出就检查路径和加载顺序。

## 踩坑点

1. **把 USER.md 写成日记本**。超过 200 行后，agent 的注意力会被稀释，关键规则被淹没。稳定事实放 USER.md，临时状态放 session 或外部存储。
2. **信息过期**。换机器、改路径、换部署目标后没有更新，agent 会一本正经地按旧环境执行。建议文件头写 `updated`，每月检查一次。
3. **硬编码敏感信息**。不要把 token、密码、私钥路径写进去。用环境变量或专门的 secret 管理，USER.md 只写“在 `~/.env` 读取”。
4. **与 system prompt 冲突**。比如 system prompt 说“默认英文回答”，USER.md 说“中文回答”，agent 可能摇摆。需要明确优先级，比如“USER.md 覆盖默认语言偏好”。
5. **没验证加载**。改完文件就以为生效，实际 agent 可能只加载一次。重启 agent 或新开会话验证，最简单的是问一个只有 USER.md 里有的信息。

## 可复用建议

- **分两层维护**：`USER.md` 存长期稳定信息；动态信息如“今天在调试的项目”用会话上下文或 notes 工具。
- **写成规则而不是故事**：与其写“我喜欢用命令行”，不如写“默认使用 CLI，避免 GUI 操作”，后者可直接约束行为。
- **给 MCP/插件留接口说明**：写清楚哪些工具可用、哪些需要确认，能避免 agent 乱调工具。
- **定期修剪**：每月删掉不再使用的环境条目，保证文件在 100 行以内。可以用 git 管理 USER.md 历史。
- **加检查点**：在文件末尾写一条“每次开始自动化任务前，先确认 target host 和 path”，比散落在各处更有效。

## 总结

USER.md 不是一份个人简介，而是一份给 agent 的“用户操作手册”。它解决的不是“让 AI 更懂你”的模糊需求，而是减少重复交代、降低误操作风险、提高自动化稳定性。对 OpenClaw/MCP/插件用户来说，维护好这份文件，比增加更多 prompt 技巧更划算。
