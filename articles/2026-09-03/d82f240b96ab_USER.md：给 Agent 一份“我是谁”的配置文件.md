## 背景

Agent 每次会话都是失忆的。项目侧我们有 AGENTS.md / CLAUDE.md 约定工程规范，但"我这个人"的上下文——操作系统、包管理器、时区、语言习惯、沟通偏好——只能靠每次手动重申。说了十遍"用 pnpm 不用 npm"，第十一遍它还是给你 `npm install`。

## 问题

没有用户画像时，三个典型损耗：

1. **重复注入**：每个新会话都要粘贴一遍个人上下文，token 和耐心双输。
2. **风格错位**：你想要简短结论，它给你百科式长文；你要中文交流，它默认英文。
3. **自动化跑偏**：定时任务、插件、MCP 工具在后台执行时，没人现场纠正它的假设——时区错了、通知渠道错了、环境假设错了，等错误浮出水面已经晚了。

AGENTS.md 管"这个项目怎么干活"，缺一份管"我是谁、我怎么干活"的文件。这就是 USER.md。

## 做法

核心三步：

**1. 写一份 30–60 行的 USER.md，放在固定路径**（如 `~/.openclaw/USER.md`），只写事实和硬约束：

```markdown
# 用户画像
- 环境: macOS + ARM, zsh, pnpm, Python 3.12 (uv)
- 时区: Asia/Shanghai, 工作时间 10:00-19:00
- 语言: 中文交流，代码注释英文
- 偏好: 先给结论再给过程；改代码前先说改动范围
- 禁止: 不自动 git push；不动生产环境配置
```

**2. 接入上下文**。最简单是会话启动时注入系统提示；也可以封装成 MCP resource 让 Agent 按需读取；OpenClaw 插件场景则在 hook 里加载。原则只有一条：单一路径、每次会话可见。

**3. 分层与版本化**。USER.md（我是谁）、AGENTS.md（项目怎么干）、MEMORY.md（发生过什么）各管一层，冲突时项目文件优先——这条优先级本身也写进 USER.md。文件进 dotfiles 仓库，多机同步，改动走 diff。

## 踩坑点

- **写成小传**。三条"我喜欢什么"比三段"我的经历"有用。画像超出一屏，Agent 会开始关注无关细节。
- **塞敏感信息**。USER.md 会进每次请求的上下文：密钥、住址、手机号一律不写。
- **约束写死**。"永远不用 Docker"会让需要容器的任务直接卡死。约束写"默认"，留例外口子。
- **过期不清理**。换了机器、换了包管理器，旧条目就是毒数据。条目加日期，季度复查，或直接让 Agent 对照文件挑出可疑条目。
- **和记忆系统打架**。Agent 自带的记忆也会沉淀偏好，出现两个"事实来源"。定死规则：记忆可以提议，USER.md 才算数。

## 可复用建议

- **冷启动偷懒法**：开一个会话让 Agent 面试你 15 分钟生成初稿，你只做删改——比从零写快得多。
- **拆 shared / local 两份**：可同步的通用偏好与机器相关的本机配置分开维护。
- 把"对照 USER.md 找过时项"做成一个定期自动化任务，让维护这件事本身也交给 Agent。

## 总结

USER.md 本质是把"个人上下文"配置化：三十行事实，换掉上千次重复解释。它不神秘，就是一份跟着你走的 README——写得越像配置文件（短、准、可 diff），Agent 就越像认识你的老同事，而不是每次见面都要重新自我介绍的实习生。
