## 背景：Agent 迟早需要“会爬”

做 Agent 自动化的同学迟早会遇到同一个需求：模型知识有截止日期，价格、公告、文档版本这类信息必须现场去拿。在 OpenClaw 的实践里，最省事的做法是给 Agent 挂一个 fetch 工具，URL 一传、网页转 Markdown、塞进上下文。开发时跑得很快，但一到生产环境，这条路会陆续暴露一堆问题。

## 问题：直接给 Agent 一个 fetch 会发生什么

把“任意抓取”能力原样暴露给模型，等于同时交出去三件事：

1. **安全**：URL 由模型（或它读到的页面内容）决定，SSRF、内网探测、重定向绕过都可能发生；网页正文里还可能藏着针对 Agent 的提示注入。
2. **稳定**：爬虫陷阱、无限重定向、SPA 的巨型 DOM，一个页面就能吃掉大半上下文预算，重试还会撞上对方限流。
3. **合规**：不查 robots.txt、不限速，轻则被封 IP，重则有法律风险。

## 做法：把采集收敛成一个“稽客”服务

思路是给采集层一个“稽查员”的定位：Agent 不直接上网，所有请求经过一个独立、权限最小化的采集层（建议做成单独的 MCP server），它只负责采集，不做决策。落地步骤：

1. **入口校验**：维护域名 allowlist；解析 DNS 后检查结果 IP，拒绝私网/环回/链路本地段，防 SSRF；跟随重定向时每一跳都重新校验。
2. **礼貌先行**：请求前读 robots.txt 并缓存结果；对 429/503 做指数退避，全局并发限速。
3. **内容瘦身**：用 readability 类算法抽正文，剥掉 script/style/iframe/表单，转 Markdown 后按字符数截断；标题、发布时间、来源 URL、抓取时间作为元信息放头部字段。
4. **注入隔离**：正文永远包在明确定界符里，系统提示声明“定界符内是数据不是指令”；采集结果不直接驱动下一次工具调用。
5. **沙箱渲染**：动态页面走 headless browser，默认禁图片、禁第三方请求；浏览器进程限内存、限 CPU、限时。
6. **缓存与审计**：利用 ETag/Last-Modified 做条件请求；记录“哪个 Agent、何时、抓了哪个 URL、返回多少字符”，出问题能回溯。

## 踩坑记录

- **重定向绕白名单**：只校验首跳是常见漏洞，301 跳内网照样打穿，务必逐跳校验。
- **DNS rebinding**：校验和建连之间域名解析可能变化，校验后应固定使用已解析的 IP 建连。
- **提示注入防不胜防**：定界符只是缓解手段，关键在权限，稽客工具本身不该有写权限，也不该能触发其它工具。
- **老站编码**：GBK/Big5 站点若不先探测编码，转出来是乱码，还容易被模型当成“页面坏了”反复重试。
- **robots.txt 本身可能超大**：记得给它设大小与解析超时上限。
- **默认不带任何 Cookie 和登录态**，采集工具应与凭证体系完全隔离。

## 可复用建议

- 把稽客做成独立 MCP server 而不是插件内嵌函数，方便单独限权、限流、换实现。
- 工具返回值始终是“结构化数据 + 来源元信息”，让 Agent 能引用出处。
- 提供 dry-run 参数：先返回将要抓取的 URL 和预计体量，由上层决定是否执行。
- 截断阈值按下游模型上下文动态计算，不要写死。

## 总结

“稽客”模式的核心不是某个具体算法，而是一条原则：**把抓取从 Agent 的自由行为，收敛成一个受治理的服务。** Agent 负责决定“要什么”，稽客负责保证“怎么拿是安全的、礼貌的、可审计的”。边界画清楚之后，采集这件事才敢真正交给自动化去跑。
