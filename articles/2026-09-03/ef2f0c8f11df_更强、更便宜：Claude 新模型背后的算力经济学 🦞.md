隔三差五就有"新模型发布"，大多数人的第一反应是：又更强了，大概也更贵了。但这一轮 Claude 的更新把剧本倒了过来，能力上去了，价格下来了。新发布的小模型 Haiku 4.5，能力追平并略超半年前的 Sonnet 4，价格却只有 Sonnet 4.5 的三分之一。这不是厂商大发慈悲，背后是一套挺值得聊的算力经济学：为什么"更强"和"更便宜"能同时发生，以及为什么单价降了，你的账单未必降。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-03/80348143d6091759.png)

## 先看事实：能力曲线和价格曲线在反向狂奔

- **定价**：Sonnet 4.5 维持 $3 / $15（每百万 tokens，输入/输出，下同），Haiku 4.5 只要 $1 / $5，直接便宜三分之二。
- **能力**：在 SWE-bench Verified（让模型修真实 GitHub issue 的基准）上，Haiku 4.5 拿到约 73%，超过半年前的 Sonnet 4；同代旗舰 Sonnet 4.5 约 77%。
- **拉长时间轴更明显**：2023 年 3 月 GPT-4 发布时定价 $30 / $60，今天同级甚至更强的能力，价格只剩它的零头。
- **结论**：这不是某一家的一次性促销，而是整条"能力 ÷ 单价"曲线在集体右移，同样的钱，一年后能买到明显更多的智能。

## 更强和更便宜，为什么能同时发生

很多人直觉里"强 = 贵"，但在 LLM 这门生意里，两者由不同的成本项决定，中间隔着好几个能"压成本"的技术抓手。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-03/de58bbfcf1eb623e.png)

1. **蒸馏（distillation）**：让旗舰模型当老师，先生成大量高质量解题过程，再用这些数据教小模型。小模型参数少、推理便宜，却能继承老师相当一部分能力。Haiku 4.5 本质上就是"老师变强了，学生跟着变强"的直接受益者。
2. **后训练重心转移**：算力不再全砸在预训练参数上，而是用强化学习把模型往 coding、agentic 这类高价值场景里反复练。小模型也能在垂直能力上逼近上一代的大个头。
3. **推理工程**：batching、KV cache、投机解码（speculative decoding）、更激进的量化，都在压低单 token 的实际成本；对外还有 prompt caching（缓存命中约一折）和 batch API（约五折）。
4. **规模摊薄**：训练是一次性成本，推理是持续成本。调用量指数级上涨后，固定投入被摊得极薄——和芯片业的规模经济是同一个逻辑。
5. **竞争压力**：DeepSeek、Gemini、OpenAI 贴身肉搏，谁也不敢把价格留在舒适区，降价从"选择"变成了"生存"。

## "智能的摩尔定律"：能力不变，价格一年掉一个数量级

- a16z 给这个现象起了个名字叫 **LLMflation**：在能力恒定的前提下，每百万 token 的价格大约每年下降 10 倍。
- 数据点：GPT-3 同等能力的输出，2021 年底约 $60 / 百万 tokens，到 2024 年中约 $0.06，三年跌了近一千倍。
- 一个直观类比：这相当于汽油车每年油耗降低一半、价格还打对折——于是"用什么车"不再是核心问题，"运什么货"才是。
- 对开发者的含义：把"智能"当成一种快速贬值的大宗商品来设计产品，别按今天的单价去推算三年后的成本结构，也别按今天的能力上限去否定一个产品想法——它明年可能就成立了。

## 冷知识：单价降了，你的账单未必降

这是很多人已经踩过的坑。便宜的单位价格 × 爆炸的调用量 = 更贵的总账单：

- **Agent 化**：一个任务被拆成几十次模型调用、几十万 token。单价降 3 倍、调用量涨 10 倍，账单照样起飞。
- **长上下文**：输入 token 才是大头。把系统提示词和历史对话反复塞进 context 又不做缓存，等于持续烧钱。
- **失败重试**：跑砸的任务也是要付钱的，低质量输出还会触发更多轮重试，成本双重放大。
- 所以真正该盯的指标是**每个成功任务的成本（cost per successful task）**，而不是"每个 token 的价格"。前者才是业务视角，后者只是报价单视角。

## 一个实用的模型路由框架

面对"更强更便宜"的新模型，与其每次都折腾一遍，不如搭一套固定的路由框架，让每次降价都自动变成你的红利。

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-03/597ec0022697ed57.png)

1. **分层**：旗舰模型留给架构设计、复杂推理这类"贵但值得"的活；中档模型干日常 coding 和长文写作；小模型跑分类、抽取、格式化。经验上，80% 的流量应该走中低档。
2. **自建评测**：拿 20~50 条真实业务任务，量三个数——通过率、单任务成本、延迟。公开榜单只能帮你筛掉明显不及格的选手，不能替你做最终决策。
3. **路由与降级**：默认走便宜模型，置信度不足或命中付费关键路径时再升级到旗舰；失败的任务自动用更强模型重试一次，把"省"和"稳"分开管。
4. **用足折扣**：系统提示词、长文档这类重复内容全部走 prompt caching；离线批处理走 batch API。这两项不花额外工程量，就能砍掉一大块成本。
5. **留一层抽象**：在模型 API 之上包一层自己的接口，保持可迁移性。价格战时代供应商会更迭，别把命脉焊死在单一厂商上。

## 三条冷思考

1. **稀缺的东西在变**：当"智能"本身越来越便宜，稀缺的不再是模型，而是场景、数据和工作流。护城河正在往上游搬。
2. **基准分数会过期，你自己的评测集不会**。每月花半天维护它，比追任何一条模型新闻都划算。
3. **价格战是买方市场，但能力上限仍由旗舰模型决定**：小模型负责省钱，旗舰模型负责"能不能做到"。别为了省小钱，亲手把产品的天花板锯矮了。

降价还会一轮一轮地发生，框架先搭好的人，每一次都能白捡一波红利。省 token 的最好姿势，从来不是等下次降价，而是现在就把路由和评测跑起来。
