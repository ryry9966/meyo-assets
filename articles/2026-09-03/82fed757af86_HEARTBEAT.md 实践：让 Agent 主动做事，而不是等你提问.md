## 背景

我们用 Agent 的习惯仍然是“人问它答”：不开口，它就不动。但很多活其实不需要你发起——CI 挂了该有人提醒你、错误日志该被定期看一眼、每周该有个摘要。OpenClaw 提供了一个很朴素的机制：**心跳（heartbeat）**。Agent 每隔固定时间醒来，读工作区根目录的 `HEARTBEAT.md`，有活就干，没活就沉默。它把“主动性”从一个模型能力问题，变成了一个纯文本配置问题。

## 问题

被动模式有三个实际痛点：你不问它不说；重复检查每次都要人肉触发；“它该定期做什么”这件事在上下文里没有落点。但很多人开了心跳之后发现它每隔半小时发一句废话，或者 token 账单莫名上涨，于是直接关掉。问题通常不在机制，在 `HEARTBEAT.md` 的写法。

## 做法

**1. 在 agent 工作区根目录建 `HEARTBEAT.md`**，每条任务写清楚：触发条件、动作、输出位置、沉默条件：

```markdown
# 每次心跳按顺序检查，无事则回复 NO_REPLY 保持沉默

## 常驻检查
- 若 ~/logs/app.err 过去 24h 有新增且未标记 handled，
  汇总写入 ~/notes/heartbeat-log.md，不要发消息
- 若 git -C ~/infra status --short 非空，
  用一句话说明哪个仓库有未提交变更，说完保持沉默

## 条件任务
- 若今天是周一上午，把上周 heartbeat-log.md 摘要发到 #ops
```

**2. 调整间隔**：`~/.openclaw/openclaw.json` 里 `agents.defaults.heartbeat.intervalMs`，默认 30 分钟。检查型任务 30–60 分钟足够，别一上来就改小。

**3. 配置推送渠道（target）**，让心跳结果只进工作渠道，不刷私聊。

关键一条：明确要求“无事发生时回复 NO_REPLY”，OpenClaw 会静默处理，不往渠道推送。大多数“心跳很吵”的问题都是少了这一句。

## 踩坑点

- **心跳 = 定时模型调用**。十条任务 × 5 分钟间隔，一天就是几百次调用。先用默认间隔跑一周，看日志再调。
- **心跳跑在主会话里，占上下文**。重活写成脚本，心跳只负责“跑脚本、看退出码、决定说不说话”。
- **条件写模糊会自作主张**。“帮我盯一下服务器”这种写法，它每次心跳都能找出话讲。要写成可判定的布尔条件。
- **注意时区**。容器里没设 TZ，“每天早上”会在错误的时间触发。
- **心跳执行权限和交互一样大**，能跑 shell。别把破坏性命令写成常驻任务。

## 可复用建议

- 把 `HEARTBEAT.md` 当**值班清单**，不是愿望清单。每条都要能回答：什么情况你该说话，说什么，到哪为止。
- 纯周期、无判断的任务（定时备份、清理）交给系统 cron，更便宜更稳；心跳只放**需要模型判断**的事。
- `HEARTBEAT.md` 进 git 管理，任务变更可追溯，出问题能 diff 出“它为什么开始做这件事”。
- 任务多了按频率拆：分钟级的走 cron 工具，小时级的留心跳，别全塞一个文件。

## 总结

`HEARTBEAT.md` 的价值不在于“AI 变聪明了”，而在于把 Agent 的主动性收敛成一份可版本管理、可审计的文本配置。写好它的核心就一句话：**每一行任务，都要同时定义“什么时候说话”和“什么时候闭嘴”**。先让它安静地跑一周，再逐步加任务，你会发现 Agent 第一次真正开始替你值班。
