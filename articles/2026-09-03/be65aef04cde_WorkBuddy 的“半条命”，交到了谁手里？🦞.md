最近，36 氪一篇关于 AI Agent 产品 WorkBuddy 的报道，把“交出半条命”这句话送上了热搜。先说明：这不是出到第二章就没下文的那个游戏《Half-Life》，而是创投圈的老黑话——把企业一半的命脉，交到别人手里。有意思的是，在 AI Agent 赛道，“半条命”是双向流动的：用户把一半日常工作交给它，它再把一半命脉交给上游。这条依赖链到底怎么运作，值得拆开看清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-03/5c37248dc3b2771a.png)

## 一、一句老话，一个新剧本

“把半条命交给别人”在中文互联网里有出处。2016 年前后，马化腾谈腾讯开放战略时说过类似的话：腾讯把半条命交给合作伙伴，自己专注连接与内容。当时这是一种生态分工哲学——我不通吃，大家分着活。

十年后，这句话在 AI Agent 赛道被反向引用了：

- **方向反了**：当年是平台把半条命交给生态伙伴；现在是 WorkBuddy 这类应用厂商，把半条命交给大模型厂商。
- **产品形态**：从公开信息看，WorkBuddy 属于典型的“AI 数字员工”——底座是大模型，上面加工具调用（function calling）、工作流编排、记忆系统，替企业写文档、跑审批、整理邮件和会议纪要。
- **依赖链条**：芯片/算力 → 云厂商 → 底座大模型 → Agent 应用 → 企业客户。这条链上，每一层都握着下一层的“半条命”。

问题在于：链条越长，离算力和模型越远的位置，话语权越弱。

## 二、为什么 Agent 应用最容易被“掐命门”？

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-03/8179c704e1de6a45.png)

Agent 的技术架构决定了它的脆弱点，主要有四处：

1. **能力空心化**。推理、规划、多模态理解全部来自底座模型，应用层真正自有的，往往只是提示词、编排逻辑和一层 UI。而模型每次大版本升级，都会“顺手”把应用层辛苦打磨的功能变成官方原生能力。前车之鉴不少：2023 年 OpenAI 开发者日发布 GPTs 当晚，一大批“套壳”产品的核心功能一夜之间变成官方默认项；写作助手 Jasper 在 2022 年底融资时估值高达 15 亿美元，ChatGPT 普及后迅速裁员转型。
2. **成本命门**。token 费用是这类产品最大的变动成本，公开案例里，推理成本占营收的比例从两成到五成都有，而 API 定价权 100% 在上游。上游一次调价，就能直接改写你的毛利率表。
3. **入口被截胡**。操作系统级、办公套件级的 AI 助手天然握着权限和数据：你的 Agent 要调用的日历、文档、通讯录，人家开一个默认开关就都有了。
4. **数据不在自己手里**。如果用户的对话记录、业务数据没有沉淀在自己的产品里，或者格式被锁死，那么客户迁移成本确实不为零——但你唯一能挽留客户的筹码，恰恰不该只有这一个。

## 三、“半条命”不全是坏事：依赖的另一面叫分工

把命交给上游，听起来惨，但价值链分工本来就是软件业四十年的常态——没有人因为 Salesforce 跑在 AWS 上，就说它没有护城河。应用层真正的资产，其实是这四样：

- **私域数据与反馈回路**：用户每修改一次 AI 的产出、每纠正一次结果，都是别人拿不到的训练信号；
- **行业 Know-how 的 SOP 化**：把一句“帮我把这个流程跑了”翻译成 Agent 可执行的几十步工作流，是脏活，也是壁垒；
- **集成深度**：接 ERP、CRM、审批流、财务系统的“最后一公里”，模型厂商大概率不愿下场；
- **信任与合规**：企业采购看的从来不是 demo 多惊艳，而是出了错谁负责、日志能不能审计。

一句话判断标准：你的核心功能是“模型能力的一层皮”，还是“流程资产的一份沉淀”？前者是伪护城河，模型一次升级就冲没了；后者才是真分工，上游越强你越受益。

## 四、一份自查清单：你的“半条命”押给了谁？

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-03/f33435dbb6532321.png)

**给创业者四个自查动作：**

1. **压力测试**：假设明天 API 涨价 50%，或某项核心能力被底座原生替代，业务还能活几个季度？
2. **数据飞轮自检**：用户用得越多，产品是否变得越聪明，而且这份“聪明”只存在于你这里？
3. **多模型架构**：关键链路能否在不同底座之间切换（model-agnostic），避免单点依赖？
4. **纵深下探**：把预算从“再调一版提示词”挪向集成、审计日志、交付 SLA——没人愿意干的活，才是议价筹码。

**给企业采购方三条提醒：**

- 关键业务流程保留 human-in-the-loop，不要 100% 托管给单一 Agent；
- 数据主权写进合同：可导出、可删除、明确产出数据是否用于对方模型训练；
- 准备好降级预案：AI 服务中断的那一天，老流程和电子表格必须还能转起来。

## 收尾：三条冷思考

1. **交出半条命之前，先算清换回来什么**。是生态位、渠道和数据，还是只是一个演示日很漂亮的 demo？前者是投资，后者是抵押。
2. **AI 应用的估值逻辑正在切换**：从“功能多新”转向“资产多厚”。数据、工作流和信任，才是模型升级的洪水冲不走的部分。
3. **依赖本身不可怕，没有议价能力的依赖才致命**。健康的依赖是双向锁定：你握着模型离不开的场景和数据，上游才不会随便动你的价格。

龙虾的壳看着硬，其实是靠不断蜕壳长大的。做 AI 应用，大概也是同一个道理。
