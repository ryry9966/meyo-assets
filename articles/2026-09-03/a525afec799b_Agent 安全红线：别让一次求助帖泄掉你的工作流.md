## 背景

社区里 Agent / MCP 相关的讨论越来越多。发帖求助时，最自然的动作是把日志、报错、配置、会话记录贴上来——但 Agent 的上下文和普通程序不一样：它常驻着系统提示词、工具清单、MCP 配置、长期记忆，甚至整个工作区的文件索引。你贴出去的"一段报错"，背后往往连着一大片内部信息。

## 问题：泄漏通常走四条缝

1. **日志与报错原文**：堆栈里常带内网域名、AK/SK 片段、带鉴权参数的内部 URL。
2. **截图**：终端里 `export XXX_TOKEN=...` 这种行，截图比粘贴更容易被忽略——粘贴时人会扫一眼，截图经常直接发。
3. **会话记录整段转发**：里面有系统提示词、工具 schema、内部 SOP 对应的推理过程。
4. **Agent 本身对外**：把 Agent 接到社区机器人或群助手后，它可能用内部文档回答外部提问。这是最容易被低估的一条。

## 做法：四道闸门

**1. 最小权限先行。** MCP server 按需开：只读就别给写权限，能限定目录就别挂根路径，token 按工具拆分。权限小了，泄漏面自然小。

**2. 建"对外安全 profile"。** 准备一套脱敏配置：placeholder 的 key、假 hostname、裁剪过的工具清单。求助时只贴这套配置能复现的最小例子，而不是拿生产配置改两行。

**3. 贴出前过一遍脚本。** 与其靠肉眼，不如固定跑一个 grep：

```bash
grep -nEi '(sk-[A-Za-z0-9]{16,}|Bearer\s+[A-Za-z0-9._-]{10,}|(10\.|192\.168\.|172\.(1[6-9]|2[0-9]|3[01])\.)[0-9.]+|\.internal\.|\.corp\.)' draft.md
```

命中就替换；截图里的关键行一律重新手打，不要依赖马赛克。

**4. 对外 Agent 加输出边界。** 接到社区的 bot 只挂必要工具，系统提示词里明确"不引用内部文档与内部路径"，出口再做一层关键词过滤加抽样人工审，日志留存方便回溯。

## 踩坑记录

- **脱敏了 key，漏了内网 IP。** 拓扑信息比凭证更难换，危害不比 key 小。
- **以为系统提示词是保密的。** 工具返回值、长对话都可能把它带出来，"提示词没公开过"不构成防线。
- **只删帖不轮换。** 一旦确认贴出去过，第一动作是吊销重发凭证，删除历史帖救不回来。
- **长期记忆被整包带走。** 有人导出"当前会话"分享，结果 agent 的 memory 文件把前几周的内部讨论一起带上了。导出前先检查 memory 目录。

## 可复用建议

发帖前 30 秒自查五条：

1. 有没有 key / token / 密码类字符串？
2. 有没有内网 IP、内部域名、真实客户名？
3. 工具清单是否裁剪到最小可复现？
4. 会话导出是否含 memory 或历史注入内容？
5. 如果已经泄了：轮换预案在哪？

再存一份脱敏配置模板（placeholder 加注释说明哪些字段必须替换），团队内共享，比每次口头提醒可靠。

## 总结

Agent 的便利来自它看得多，风险也来自它看得多。对社区分享这件事，红线就三条：**最小权限、最小披露、泄漏即轮换**。把脱敏做成固定流程而不是临场发挥，才谈得上放心折腾。
