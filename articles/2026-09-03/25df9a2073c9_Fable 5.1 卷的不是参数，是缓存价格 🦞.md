这两天 AI 圈的热搜属于 Anthropic：据 36kr 等媒体报道，Fable 5.1 发布，宣传口径照例是“多项基准全球最强”。但如果你是常年盯着 API 账单的开发者，真正值得注意的可能是另半句——它把**缓存价格**也卷进来了。参数和跑分决定模型强不强，缓存定价决定你用不用得起、Agent 跑不跑得动。这篇文章把 Prompt Caching 的原理、账本和实战打法一次讲透。

## 先泼点冷水：“全球最强”该怎么读

每一代旗舰发布都会伴随一轮屠榜截图，读者需要一点“翻译能力”：

- **基准污染（benchmark contamination）**：榜单题目可能混进训练数据，分数虚高未必是有意作弊，但属于行业常态风险
- **挑选偏差**：厂商放出的对比图，通常是自家最擅长的几个 benchmark；换成社区维护的真实任务评测集，名次常常缩水
- **跑分 ≠ 你的场景**：代码补全、长文档抽取、多轮工具调用，同一个模型在不同任务上的表现能差出一个档次

历史规律也摆在那里：过去两年几乎每代新旗舰都宣称刷新纪录，几个月后第三方复测总会挤掉一截水分。合理的姿势是：**把官方跑分当必要条件，把自家真实流量回放当充分条件**。发布会 PPT 再漂亮，也不如你手里 50 条真实用例有说服力。

## Prompt Caching：KV Cache 从内部优化变成计费商品

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-03/28b5693fcda031d2.png)

先补一点原理。Transformer 的推理分两段：

1. **Prefill**：把输入 token 并行计算一遍，生成 KV Cache（键值缓存），这一步的计算量随上下文长度快速增长
2. **Decode**：基于 KV Cache 逐 token 生成输出

问题在于：多轮对话和 Agent 场景里，系统提示词、工具定义、挂载的长文档这些**前缀**每一轮都一模一样，却每次都要重新 prefill——对 GPU 来说是纯浪费。

Prompt Caching 的思路很直接：把相同前缀的 KV Cache 存在服务端，下次请求命中就直接跳过 prefill。计费上通常拆成三件套：

- **缓存写入**：比普通输入贵，行业常见约为原价的 1.25 倍
- **缓存读取**：比普通输入便宜得多，常见为原价的 10%–50%
- **TTL（存活时间）**：常见 5 分钟，命中会刷新计时；也有厂商按存储时长单独收费

一个高频翻车点：前缀匹配通常要求**逐字节一致**。前面多塞一个时间戳、随机 ID，甚至空格变了，缓存直接 miss，写缓存的溢价就白付了。

## 把账算细：缓存到底能省多少



举个例子：一个 Agent 应用的系统提示 + 工具 schema + 知识库共 2 万 token，每轮对话原样重复发送，一天跑 500 轮。

- **不用缓存**：20,000 × 500 = 1000 万 token，全部按全价计费
- **用缓存**：首轮写入 2 万 token（按 1.25 倍价），之后 499 轮按 10% 读价。折算下来有效输入单价约为原来的 12%，**账单直接砍掉近九成**

钱之外还省时间：跳过 prefill 意味着首 token 延迟显著下降，长上下文场景里提速一半以上并不罕见。对交互式 Agent 来说，延迟收益有时比成本收益更值钱。

反例也要看清楚：如果你的前缀每轮都在变——比如把时间戳、用户 ID 放在最前面——那写缓存的 25% 溢价就是纯亏。**缓存是发给“前缀稳定”架构的奖励，不是无差别打折。**

## 为什么巨头开始卷缓存价格

把这件事放到行业时间线上看更清楚：

- **第一轮价格战**卷 output 单价：2023 年 GPT-4 时代每百万 token 几十美元的档位，如今同档任务的价格已降了两个数量级
- **第二轮**卷 input 单价：各家 mini 级模型把入门门槛打到地板
- **这一轮**卷的是“有效单价”：缓存读取折扣、Batch API 折扣、闲时定价——比的是账单工程

厂商愿意卷的逻辑并不复杂：

1. Agent 工作负载前缀长且稳定、调用频次高，缓存读取逐渐成为输入侧账单的大头，折扣等于精准补贴最黏性的那批客户
2. KV Cache 复用本来就省掉了 prefill 算力，折扣本质是**把节省让利给用户**，顺手换来更高频的调用
3. 竞品路径不一：OpenAI 走自动缓存、五折起，部分模型更低；DeepSeek 缓存命中价约为原价一折；Gemini 显式缓存按存储时长收费——打法不同，方向一致

还有一层飞轮效应：折扣让用户敢往上下文里塞更多资料，效果变好，用量继续涨。这可能是大模型时代第一次，“省钱”和“变强”指向同一个动作——把提示词写整齐。

## 开发者怎么接住这波红利

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-03/b83f6acef1fc6f50.png)

1. **前缀排版纪律**：稳定内容在前（系统提示、工具 schema、参考文档），动态内容最后（用户输入、日期）。这一条值大部分折扣，实施成本为零
2. **控制 TTL 窗口**：把同一轮任务的连续请求尽量打包在 TTL 内发出，让缓存“活着”；非实时任务再叠加 Batch API，省上加省
3. **埋点监控**：日志里把 cache_creation 和 cache_read 两列 token 数分开记录，算有效单价和命中率。命中率低于六成，先查前缀是不是被谁塞了个时间戳
4. **别拿默认配置交差**：缓存断点（breakpoint）位置、TTL 档位、显式缓存还是自动缓存，都值得做一轮 A/B

## 收尾：三条冷思考



1. **跑分听听就好**：宣称“全球最强”是发布会标准动作，选型结论请来自你自己的评测集和真实流量回放
2. **单价下降 ≠ 账单下降**：价格降一半，用量往往涨得更快——杰文斯悖论在 GPU 上照样成立，预算请按“用量增长后的账单”来规划
3. **缓存折扣是温柔的绑定**：当你的提示词结构越来越贴合某家的缓存机制（TTL、断点、匹配规则），迁移成本在架构设计那天就写好了。省钱的同时，给提示词层留一点与供应商无关的抽象
