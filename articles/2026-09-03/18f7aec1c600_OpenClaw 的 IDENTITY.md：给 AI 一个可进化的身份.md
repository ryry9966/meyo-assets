## 背景

OpenClaw 的 agent workspace 里有一组约定文件：SOUL.md 管性格与价值观，AGENTS.md 管操作流程，USER.md 记用户偏好。IDENTITY.md 是其中最不起眼的一个——大部分人的第一版就是三行：名字、物种、emoji，写完就再也没打开过。

我一开始也这么用。直到跑了几个定时任务、接了多个渠道之后，发现 agent 在不同会话里对“我是谁”的回答并不稳定，才回头认真对待这个文件。

## 问题

缺少一份明确、稳定的 IDENTITY.md 时，常见三类麻烦：

1. **自我介绍漂移**。底层模型对“你是谁”有默认答案，上下文一换，agent 可能把自己描述成另一个东西，重置会话后尤其明显。
2. **身份散落各处**。名字写在一处，口吻写在 SOUL.md，还有一部分塞在 agent 指令里。改一次身份要翻三个文件，漏掉一处就出现自相矛盾的输出。
3. **演进无据可查**。想让 agent 从“通用助手”长成“某个具体角色”，改完行为变了，但说不清是哪一行改的，回滚困难。

## 做法 / 步骤

现在我的 IDENTITY.md 保持在 10 行以内，结构大致是：

- `name` / `creature` / `emoji`：三个短字段，明确写死，不留空。
- 一句 self-model：“我是什么、我不是什么”。这句最有用，能拦掉一大类越界回答。
- `temperament`：只写两三个形容词，具体表达交给 SOUL.md。

配套三个习惯：

1. **职责分离**。身份归 IDENTITY.md，行为归 SOUL.md，流程归 AGENTS.md，同一信息只出现在一个文件里。
2. **当成配置代码管**。workspace 放进 git，一次只改一个字段，commit message 写清动机，随时可回滚。
3. **小步演进 + 固定探针**。改完用三个固定问题做冒烟测试：“你是谁”“你擅长什么”“你不会做什么”，和上一版输出对比，不符合预期就回退。

三四轮之后，这个文件就从“起名卡片”变成了身份锚点：跨会话稳定，改动可追溯。

## 踩坑点

- **写成小作文**。超过半页的人设，模型只会选择性吸收，段落之间还容易自相矛盾。短字段比长叙述可靠得多。
- **把任务规则塞进来**。“永远用列表回复”属于行为约定，放进身份文件，它迟早变成配置垃圾场。
- **和 SOUL.md 打架**。身份写“话少”，灵魂文件要求“详细解释”，输出就会忽长忽短。改完记得扫一眼另一个文件。
- **频繁改名**。历史记忆、定时消息、按名字关键词路由的自动化都可能依赖旧名字。改名是大事件，留一段别名过渡期。

## 可复用建议

- 起步模板：`name` / `creature` / `emoji` / 一句 self-model / 两三个气质词，够了。
- 文件末尾加 CHANGELOG 小节，一行一条：“某日：口吻改为偏工程，原因是 xx”。有 git 也要写，人读起来快。
- 多实例场景：共享一份基础身份，各 agent 只用覆盖字段表达差异，避免复制粘贴后各自漂移。
- 把三个探针问题存成固定 prompt，每次身份变更后跑一遍，成本一分钟，能省掉后面很久的排查。

## 总结

IDENTITY.md 是 workspace 里性价比最高的文件之一：十几行，决定 agent 在每个会话里以谁的身份出场。写短、写死、进 git、小步改——把它当成一段会被长期执行的配置，而不是一次性的自我介绍。身份会进化，但每一次进化都应该留下痕迹。
