最近有个反直觉的现象被推到台前：几家大模型服务商都标着“每百万 token 5 美元”，但开发者把账单拉出来一看，成本能差出三成。OpenAI 高管干脆回了一句：token 从来没法直接比价。这句话听起来像甩锅，但如果你拆开 token、计费结构和模型架构，会发现它其实点中了大模型 API 定价里最容易被忽略的常识：token 是一个刻度，不是一把统一的尺子。



## 一、Token 不是“标准砝码”，而是模型私有刻度


很多比价的第一步就错了：以为 token 是像克、毫升一样的物理单位。实际上 token 是分词器切出来的结果，每家模型的分词器可以完全不同。

- BPE 分词策略不同：同一个英文句子 The quick brown fox jumps over the lazy dog，A 模型可能切成 9 个 token，B 模型切成 11 个；unbelievable 可能被切为 un + believe + able，也可能被留作一个整词。
- 中文更明显：模型词表对中文的处理差异很大。“人工智能”在有的词表里是 1 个 token，在另一家可能是 2-4 个；遇到生僻字、标点、数字混合时，差距会进一步拉大。
- 多模态折算也不统一：一张 1024×1024 的图片，A 模型按 765 个 token 折算，B 模型可能按 1105 个；音频按帧或码率切分，更没有统一标准。

所以同样标注 5 美元/百万 token，如果两家 token 数量天然差 20%，账单就先差出一截。这不是谁偷工减料，而是计量刻度本身不统一。

## 二、5美元只是“牌价”，账单由计费结构决定


表面上都叫 5 美元/百万 token，但输入、输出、缓存、批处理的价格系数完全不同。

- 输入和输出通常分开计价：输出 token 往往比输入贵 3-5 倍。因为输出是串行生成，占用更多显存和推理时间。
- 缓存命中可能便宜一个数量级：相同前缀命中缓存后，输入 token 可能便宜 10-20 倍，甚至免费。不同服务商的缓存窗口、生效策略不同，对长对话型应用影响极大。
- 工具调用、函数调用、结构化输出、推理 token 可能单独加价或按不同倍率折算。有些模型会把隐藏思考过程计入输出，用户未必能直接看到。
- 批处理/非高峰折扣也会改变实际单价。

算一笔简化账：假设一个任务输入 100 token、输出 500 token。A 模型输出价为输入的 3 倍，B 模型为 5 倍，两者输入单价都是 5 美元/百万 token。A 的实际成本约为 0.008 美元，B 约为 0.013 美元，差距不是三成，而是超过六成。任务越偏重输出，差距越大。

## 三、架构差异：同一个答案，消耗路径可能完全不同


即便 token 数量完全一样，不同模型内部的推理路径也可能差异巨大。

- 稠密模型 vs MoE：稠密模型每次前向都激活全部参数，MoE 只激活一部分专家。从 token 看可能相同，但服务商的单位成本不同，这会影响他们能承受的折扣空间和限流策略。
- 推理模型的隐藏 token：一些 reasoning 模型在给出答案前会生成大量中间推理 token，即使前端不展示，计费时可能按隐藏 token 折算。两个模型都“回答了 200 token”，但一个可能在后台烧掉 2000 token。
- 输出长度倾向：同一问题，一个模型回答 400 token，另一个啰嗦地输出 1000 token。这不是单价差异，但账单一差就是 2.5 倍。
- 长上下文成本：随着上下文变长，prefill 阶段的注意力计算不是线性增长，模型对长上下文的实际资源消耗不同。按 token 计价时，这部分差异被掩盖了。

所以 token 只是一个“可观察代理指标”，它无法反映模型架构、推理深度和输出行为带来的真实成本。

## 四、实用建议：比价之前，先归一化三件事


如果不想被“5 美元”迷惑，建议把比价方式从静态单价换成任务级成本。

1. **比端到端单位任务成本，不要比单价**：用自己的真实 prompt 跑一个小样本集，计算总费用 ÷ 成功完成任务数。重试、超时、截断导致的额外调用也必须算进去。
2. **把输入/输出比例和缓存命中率纳入测算**：输出通常更贵，优化 prompt 要求简洁、结构化，能明显降低输出 token；长对话应用优先考虑缓存策略。对比时应固定相同上下文长度、相同任务难度。
3. **建立归一化指标**：比如“每 1K 次有效调用的美元成本”或“每单位业务价值的推理成本”。不要只看每百万 token 价格，因为 token 数量本身会撒谎。

最后一句冷思考：用 token 比价，就像用“粒”来比大米——都是米，但大小、形状、吸水率就差很多。5 美元/百万 token 只是入口，不是结论。
