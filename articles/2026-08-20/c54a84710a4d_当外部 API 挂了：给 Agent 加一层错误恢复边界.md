## 背景

在 OpenClaw 这类 Agent 运行时里，外部 API 经常作为 MCP server、插件或工具接入。Agent 的典型链路是：LLM 决策 → 调用外部工具 → 拿到结果继续推理。

但外部 API 不是一个可靠边界。搜索接口超时、天气服务返回 500、限流、HTTP 错误页、网络不可达，这些都会随时发生。很多 Agent 默认把工具异常直接抛回给模型，于是模型开始“临场发挥”：反复重试同一个接口、把错误页当业务结果继续分析，或者在降级时编造数据。

问题不在于让 API 永远不挂，而在于故障发生时，任务能不能可控失败、可恢复、可解释。

## 问题

缺少错误恢复策略时，常见表现是：

- 单次失败直接终止整个任务。
- 无限重试烧 token，甚至触发限流雪崩。
- 非幂等接口被重复调用，比如重复下单、重复发信。
- 大段堆栈或 HTML 错误页塞回上下文，模型忽略之前指令。
- 降级结果未标记，最终答案把旧数据当成实时数据。

这些问题的共同点：错误处理被寄托在模型判断上，而不是工程边界上。

## 做法/步骤

### 1. 工具层统一错误分类

不要让工具直接抛原始异常。外部 API 调用应封装一层，把错误映射为结构化结果：

```json
{
  "ok": false,
  "code": "UPSTREAM_TIMEOUT",
  "retryable": true,
  "fallback": false,
  "message": "search api timeout after 3s"
}
```

错误类型至少区分：超时、限流、4xx 参数错误、5xx 服务端错误、网络不可达、协议错误。这样 Agent 不需要分析堆栈，只处理 code 和 retryable。

### 2. 重试要有边界

只对查询类、只读类接口做自动重试。使用指数退避加抖动，最大重试次数建议 3 次。写操作必须确认幂等性，或者显式传入 idempotency key；没有幂等保证的写接口，禁止自动重试。

重试预算也很重要：一次任务最多 N 次工具级重试，超过就进入降级或暂停。

### 3. 降级路径

对可降级 API，提供一个明确的 fallback：

- 最近一次成功结果缓存，带 TTL，stale-if-error。
- 备用数据源。
- 结构化缺省值，例如“天气数据暂不可用”。

关键是 fallback 结果必须带标记，例如 `"fallback": true`，让模型和用户知道这不是实时数据。不能把降级结果静默当成真实结果。

### 4. 熔断与隔离

连续失败达到阈值后，打开熔断，后续请求快速失败，避免继续占用资源和 token。在 OpenClaw 场景下，可以把外部依赖封装在独立 MCP server 或插件进程里，由 server 内部做熔断和重试。Agent 只看到最终结果或结构化错误。

### 5. 上下文恢复与断点

长任务在执行前写 checkpoint：意图、已完成步骤、待办、关键参数。遇到可恢复错误时，让 Agent 读取 checkpoint 继续，而不是从头开始。错误信息进入上下文时只放摘要和下一步选项，不要放原始报错。

## 踩坑点

- **把整段堆栈和 HTML 错误页给模型**：会污染上下文，模型开始“分析错误页”而不是恢复任务。
- **盲目重试非幂等接口**：支付、订单、短信等场景尤其危险。没有幂等保证就不要自动重试。
- **超时设置不合理**：太长任务卡死，太短把慢查询误判为故障。按 P95/P99 设置，读写接口分开。
- **fallback 未标记**：用户会误以为降级数据是实时结果。
- **错误循环**：模型看到 tool error 后反复换参数重试，消耗大量 token。应检测重复调用并限制总步数。
- **把故障当 prompt 问题**：单纯在 system prompt 里写“失败请重试”不可靠，恢复逻辑应放在工具层或 MCP server 内。

## 可复用建议

- 封装统一的 `safe_call` 或 `with_retry` 工具装饰器，处理超时、重试、熔断、错误映射。
- 每个外部 API 的工具 schema 都定义 `error` 返回结构，而不是依赖异常字符串。
- 让 MCP server 承担外部依赖的容错，Agent 只拿最终或结构化失败结果。
- 给长任务加 checkpoint，失败后避免全部重来。
- 记录每次外部调用的 request id、延迟、状态码、重试次数、是否命中 fallback，方便回放和定位。

## 总结

外部 API 挂掉是常态，不是意外。Agent 的错误恢复应该做在工具层、MCP server 或插件运行时里，而不是靠模型临场发挥。

核心只有三件事：重试有边界，降级有标记，失败可恢复。做到这三点，当外部 API 挂掉时，Agent 要么用降级结果继续推进，要么干净地暂停并说明原因，而不是硬扛、幻觉或重复烧 token。
