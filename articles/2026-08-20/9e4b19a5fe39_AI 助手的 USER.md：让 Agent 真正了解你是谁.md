## 背景：为什么 Agent 总是“不懂你”

用 OpenClaw、Agent、MCP 或插件做自动化的人，大概率遇到过同一类问题：每次开新会话，你都要重新交代“我在哪个目录工作、默认用 pnpm 还是 npm、输出中文还是英文、哪些路径不能碰”。Agent 默认只看到项目文件和临时指令，对用户习惯、环境约束、跨项目偏好一无所知。

结果就是一致性很差：有时候按你的习惯来，有时候又回到默认行为；遇到模糊指令，要么多问，要么直接按错误的方式执行。更麻烦的是，这些上下文不沉淀，每次重复沟通都浪费 token，也容易遗漏关键约束。

## 问题定位：缺一份“用户级长期上下文”

项目级配置文件（如 AGENTS.md、CLAUDE.md）解决的是项目内上下文。但它管不到用户的全局环境、工具链偏好和跨项目约定。例如你希望 Agent 在所有项目里都不要自动提交 git、不要修改系统 Python、默认用中文回答，这些信息放在每个项目里既重复又难维护。

USER.md 的作用就是给 Agent 一份“用户说明书”：告诉它你是谁、你的环境长什么样、默认应该怎么干活、哪些事绝对不能做。它不是系统提示的替代品，而是用户侧持久化上下文。

## 做法：把 USER.md 变成基础设施

### 1. 确定加载位置

以 OpenClaw 为例，用户级 USER.md 通常放在用户配置目录下，例如 `~/.openclaw/USER.md`。如果你的版本支持 config 里的 `user_context_file` 或 `system_prompt` 注入，可以自定义路径。关键是让它在每次会话启动时以 system/context 方式自动进入，而不是每次手动粘贴。

### 2. 写最小可维护结构

不建议写成长篇自传。推荐分成五个固定段落：

- **身份与目标**：一两句说明你的角色或常用场景。例如“后端工程师，主要维护 Python/Go 服务，偏好可读性优先”。
- **环境与工具链**：默认 shell、包管理器、常用路径、版本管理策略。例如“用 zsh；Python 用 uv；Go 用 go mod；实验目录在 `~/lab`”。
- **输出偏好**：语言、语气、详细程度、是否要给 diff、是否要命令确认。
- **硬约束**：绝对不要做的事。例如“不要删除 `~/.ssh`；不要修改系统 Python；不要自动提交代码；不要联网搜索除非明确要求”。
- **触发规则**：什么情况下直接做、什么情况下先问、什么情况下停止。例如“改动超过 50 行先给方案；涉及付费 API 先确认”。

### 3. 接入与验证

接入后先验证是否生效。可以用两个简单问题测试：

- “我的默认 shell 和包管理器是什么？”
- “我的输出语言偏好是什么？”

如果 Agent 答不上来，检查文件路径、读取权限、是否被缓存，或者当前 OpenClaw 版本是否支持该注入方式。

### 4. 持续迭代

把 Agent 反复犯的错误提炼成一条规则写进去。例如它总是用 `npm` 而你想用 `pnpm`，就在环境段明确写“默认包管理器：pnpm，不要使用 npm 安装依赖”。USER.md 应该像代码一样被 review 和更新。

## 踩坑点

- **文件太长**：把 USER.md 写成个人技术史，会占用大量上下文窗口，冲淡关键约束。控制在 200–400 行以内，单段不超过 6–8 行。
- **放敏感信息**：不要把 token、密码、私钥路径明文写进去。用环境变量引用或安全存储。
- **上下文冲突**：项目级 AGENTS.md 写“用 npm”，USER.md 写“用 pnpm”，Agent 会混乱。需要在 USER.md 开头写明优先级：项目配置 > 用户配置 > 默认规则。
- **只写一次不更新**：环境变了，USER.md 还停留在旧机器、旧工具链，会导致 Agent 执行错误命令。建议加“更新时间”和“适用机器”字段。
- **格式不兼容**：有些工具要求 YAML frontmatter，有些要纯 Markdown。先确认你使用的 OpenClaw 版本支持哪种格式。

## 可复用建议

- **分层管理**：全局 USER.md 只放跨项目稳定偏好；项目特定信息放项目文件；会话临时要求放 prompt。
- **用模板不用散文**：固定标题，短句列表，减少阅读负担。
- **声明优先级**：文件开头写“如与项目配置冲突，以项目配置为准；如与本次指令冲突，以本次指令为准”。
- **定期清理**：每两周检查一次，删掉已经不需要的条目。
- **团队共享脱敏版**：如果团队用同一套 Agent，维护一个去掉个人路径和凭据的 USER.md 模板，能快速复用。

## 总结

USER.md 不是让 Agent“更懂你”的魔法，而是一份可维护的用户侧上下文契约。它能减少重复沟通，降低环境漂移带来的执行错误。对 OpenClaw 用户来说，写得短、准、可执行，比堆砌背景更有价值。尽早建立，把它当作自动化基础设施的一部分。
