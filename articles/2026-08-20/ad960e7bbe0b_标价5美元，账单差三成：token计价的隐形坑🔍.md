同样在 API 页面写着“$5 / 1M tokens”，月底对账时 A 供应商 372 美元，B 供应商 498 美元，差了三成。有人怀疑被多收，有人归咎于“模型贵”。OpenAI 高管在行业沟通中回了一句：token 从来没法直接比价。这句话不是甩锅，而是点破了 LLM 计费里的最大认知误区——token 并不是 kWh、GB 那样的统一物理单位，它更像每家自己揉出来的小面团，切法、算钱方式、运行策略都不一样。



## 一、Token 不是“一个字”，而是模型自己的切分单位

- 大模型不能直接读自然语言，文本要先经过 tokenizer 切成词汇表内的小块。主流用的是 BPE（Byte Pair Encoding）或类似算法，但每个模型的词汇表大小和合并规则不同。
- 同样一段 1,000 个汉字，A 模型可能切出 1,200 token，B 模型切出 1,800 token；英文、JSON、代码的差距可能更大。多模态模型还会把图片按 patch、音频按时间片折算成 token。
- 这导致一个关键问题：标价里的“1M token”不是统一单位。OpenAI、Anthropic、Google、Meta 各家的 tokenizer 有差异，直接把目录价并排比较，相当于拿“一小袋 A 牌豆子”和“一小袋 B 牌豆子”按袋计价。

## 二、同样标价，账单差三成的四层变量



即便 token 数拉平了，还有四层变量会把最终账单拉开：

1. **输入价 vs 输出价**：目录页常把便宜的输入价放前面，输出价通常是输入的 3~5 倍。比如 $5 input / $15 output。写作、摘要、Agent 这类输出占比高的任务，成本会显著高于“看起来”的 input 价。
2. **推理 token 的隐藏消耗**：o 系列和 reasoning 模型会先产生大量思考 token，再输出最终答案。这些思考 token 也按输出价计费，而且部分供应商不把详细用量默认展示。用户看到 answer 只有 300 token，实际 output 可能已经 1,500 token。
3. **缓存命中与折扣**：输入 cache hit 的价格可能低 50%~90%。系统提示、历史对话越稳定，缓存命中越高。批量、spot、承诺用量、预付费折扣各家策略不同，目录价到实际账单之间可以隔很远。
4. **计费粒度与附加项**：最小调用费、向上取整、工具 schema 计入 prompt、上下文填充、多模态特殊折算，这些都会改变真实费用。比如工具调用时，函数定义每次都被塞进 prompt，让 input token 被动膨胀。

一个简化模拟：三家都标 $5/$15，同一个长文档总结任务：

- A：1,200 input + 500 output，无思考，缓存命中，费用最低；
- B：1,400 input + 600 output，含 200 思考 token 计入 output，费用中档；
- C：1,600 input + 800 output，隐藏 reasoning 400 token，无缓存，费用最高。

三家里最高和最低相差 25%~40%，但目录价完全一样。

## 三、“5美元”只是目录价，不是实际单位成本

- 目录价是公开页面的报价，不等于你最终会支付的价格。大客户有合约折扣、预留吞吐、批量 API 优惠，可能打 6 折或更多；反之，小流量可能因为最低费用被拉高。
- 同名模型的默认版本可能在更新后变“啰嗦”，输出 token 上涨，但定价不变。模型的温度、max token、系统提示长度也会改变消耗。
- 端到端成本不能只看单次调用。重试、超时、限流、fallback 产生的额外 token 都要算进去。错误请求虽然没产出，也可能已经消耗了部分 input token。
- 更重要的是“有效输出成本”：模型 A 便宜 20%，但如果首轮成功率只有 80%，需要重试一次，实际成本和延迟可能反超一个成功率 95% 的稍贵模型。

## 四、正确比价：别比 token，比“单位任务成本”



比价时建议把 token 计价当“毛重”，把单位任务成本当“净价”：

- **统一口径**：固定 1,000 字中文、1,000 字英文、一段 JSON，分别测各家 token 数，得到 token 膨胀系数。
- **看 blended rate**：把输入、输出、思考 token 的实际用量乘以各自价格，算出加权后的有效每 1M token 成本。
- **压测真实任务**：不要用一句“你好”做 demo。选 100~1,000 条真实业务请求，记录端到端 token 消耗、延迟、成功率、重试次数。
- **折算单位任务成本**：用总成本除以成功完成的任务数，而不是看单 token 报价。这个方法能把隐藏的思考 token、缓存、重试统统折进去。
- **持续监控**：模型版本、业务 prompt 调整、工具 schema 变化都会影响 token 消耗，建议在日志里保存 token usage，按周追踪成本曲线。

## 五、三条冷思考，帮你避坑

1. **比价前先“称重”**：任何 token 价格对比之前，先用同一段文本测出各家实际 token 数，把“每 1 万字符的成本”作为第一层统一单位。
2. **别只盯着 input 价**：输出价、推理 token、工具 schema 才是长任务和 Agent 场景的成本大头；输出占比高的业务，要用输出/输入比例修正判断。
3. **信目录价，不如信影子流量**：拉一个 7 天影子流量，算每 1,000 次成功任务的总成本。这个数比任何 API 页面上的“$5 / 1M tokens”更接近你的真实账单。
