最近 36kr 那条「Claude Code神话破灭？大量用户正在取消订阅」在开发者群里刷屏。很多人疑惑：这工具不是前阵子还被吹成“一个人成一支团队”吗？怎么突然就开始退订了？其实仔细看退订帖，核心关键词不是“变笨”，而是“token 烧太快”“额度用光”“订阅被限速”。这波退订潮背后，不是模型能力崩了，而是 Agentic coding 第一次真正撞上成本、限额和预期差。



## 1. 发生了什么：从“真香”到退订

如果只看早期视频，Claude Code 确实很唬人：一句“帮我修这个测试”，它自己能读文件、跑命令、改代码、再跑测试。很多开发者立刻把订阅拉满，准备让 AI 当自己的数字同事。

但最近 Reddit、Hacker News、X 上开始出现大量取消订阅的帖子，情绪很一致：

- 不是不会写，而是太能写，写到 token 账单失控；
- 一些 Pro/Max 用户在重度使用几天后，就撞上 weekly rate limit 或高峰期限额；
- 有开发者吐槽：用 Claude Code 做一个中型重构，任务跑了几小时，折算 API 成本比自己写还贵。

所以“神话破灭”这个说法并不准确。更合适的描述是：一个被 demo 抬得太高的工具，开始被真实使用场景校准。

## 2. Agent 编程为什么这么“烧 token”



普通聊天式编程助手是“一问一答”，Claude Code 是 agent，它会自己规划、执行、观察、再修正。这种自主性，背后是极高的 token 消耗。

- 多轮循环：一个“修一个测试失败”的任务，可能产生 20~60 次 LLM 调用。每次都要带 system prompt、工具定义、历史消息，以及当前文件内容。
- 上下文膨胀：agent 经常需要反复读取大文件。它不像人类工程师会记住“这个函数在哪个文件”，而是每次决策都重新把相关代码喂给模型。一个小任务跑下来，上下文轻松从几十 k 涨到几百 k token。
- extended thinking：Claude 的思考 token 能提升复杂推理质量，但也是按 token 计费的。简单任务里，思考链可能占了大量消耗，产出却不像预期那么高。
- 算力特性：Transformer 对长上下文的注意力计算接近 O(n²)，上下文越长，成本增长越陡。输入 token 虽然比输出便宜，但量大、重复读，总账很快上来。
- 缓存不是万能：Anthropic 的 prompt caching 最高能把输入成本降低约 90%，但 agent 任务里文件频繁变化，cache 命中不稳定，不能完全兜底。

举一个结构示意：假设一个任务跑 30 轮，平均每轮 30k 输入、2k 输出，输入 3 美元/M tokens、输出 15 美元/M tokens，那单任务成本大约是 3.6 美元。如果上下文更大、轮数更多，费用会快速翻倍。这不是官方报价，但能解释为什么用户会肉疼。

## 3. 订阅制撞上按量计费：最拧巴的地方

Claude Pro/Max 原本是聊天订阅，用户默认“一个月随便问”。聊天场景没问题，单次 token 少，订阅费覆盖得了。但 agent 是另一个物种：

- 一次长任务可能消耗几十万甚至几百万 token；
- 订阅费根本包不住重度 agent 使用；
- Anthropic 只能通过 rate limit、高峰额度、并发限制来保护算力；
- 用户体感就变成：我花了订阅钱，Claude Code 却告诉我“额度已用尽”。

按 API 用量计费虽然更透明，但普通用户看到每几分钟扣一次费也焦虑。团队如果没有成本护栏，月底财务会想找你聊聊。

这不是某一家的问题，而是所有 AI agent 产品都在面对的结构性矛盾：聊天订阅的定价模型，装不下长时程自主任务。未来大概率会走向混合模式——基础订阅 + usage credit + 企业算力包。

## 4. 预期管理：演示视频 vs 真实仓库

类似的剧情不是第一次。2021 年 GitHub Copilot 刚上线时，也有人觉得开发者要失业；Devin 演示时更被称作“AI 程序员”。但真正落地后，用户发现它们更像提速工具，而不是零成本替代。

很多退订的人不是不需要 AI，而是被演示视频拉高了预期。

- Demo 仓库通常干净、依赖完整、测试齐全、任务边界清晰；
- 真实工作里是 monorepo、旧版依赖、内部框架、权限限制、弱测试覆盖；
- agent 在信息不完全时会“自信地猜”，猜错后修修补补，反而产生更多循环和 token 消耗。

所以更要看任务匹配度。Claude Code 适合明确、可验证、局部的工作，比如给模块写单测、根据报错修 bug、重构一个小函数。它不适合“把整个项目升级到 Next.js 15，顺便优化性能”这种开放式任务。

一个更健康的心态：把 agent 当很能干的 junior dev，而不是 senior。你需要写清楚 spec、验收标准和范围，review 成本必须计入。

## 5. 冷思考：该退订还是该换用法？



退订不一定错，但先别被单次账单吓到。实用建议三条：

1. 算单位产出，而不是只看单次成本。一个任务花 3 美元，省你 30 分钟，可能比咖啡便宜；花 30 美元才省 20 分钟，就该换工具或拆任务。
2. 给 agent 上护栏。设置 max turns、budget limit、git diff 检查、测试门槛，限制它全仓搜索的权限。先给最小上下文，再逐步放开，避免自动循环烧 token。
3. 按任务类型选工具。样板代码、测试生成、局部重构用 agent 很划算；架构设计、跨模块调试、需要产品判断的任务，仍然自己主导。

最后一句：Claude Code 的“神话破灭”不是技术倒退，而是 agent 编程第一次以真实账单的形式接受市场检验。少看一点神话，多看一点 token，才是 2025 年最实用的 AI 素养。
