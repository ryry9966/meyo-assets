最近，36kr 的一篇报道把 Claude Code 的退订潮推到了台前。曾经被开发者称为“能自己改代码的 CLI 同事”，现在却被不少用户吐槽为“高薪聘来的实习生”——活儿干得热闹，账单和返工成本却让人头疼。但把这件事简单概括为“神话破灭”并不准确。更接近事实的是：AI 编程 Agent 正在从极客玩具阶段，进入一场关于成本、可靠性与产品形态的硬着陆。



## 一、Claude Code 为什么曾被认为是“下一代编程”



Claude Code 与传统代码补全工具最大的不同，是它试图扮演一个真正的 agent，而不是只会接下一行的 Copilot。

- 它能直接操作代码库：读取文件、搜索符号、修改代码、执行 shell 命令，甚至运行测试并查看报错。
- 它依赖 Claude 模型的长上下文能力，可以一次性把中小型 repo 的关键结构塞进上下文，做跨文件修改。
- 它采用 plan-act-observe 的循环：先规划修改步骤，再动手改，然后读取结果，出错再调整。
- 对终端党来说，这种“命令行里长出一个同事”的体验非常新鲜，也适合写脚本、跑 CI、做批量重构。

举个例子：让它给一个 Python 项目加缓存层，它会先 grep 出所有数据库调用点，再插入缓存逻辑，最后跑一遍 pytest。整个过程不需要切出终端，确实有一种“远程实习生”的错觉。

但也正是这种“自主性”，为后来的口碑反转埋下伏笔。

## 二、退订用户到底在抱怨什么



翻看退订用户的反馈，核心问题不是“不好用”，而是“不可控”。

1. **长任务非常容易失控**  
   短任务表现惊艳，但任务超过一定步数后，模型容易跑偏：忘记最初目标、重复修改同一段代码、把已经正确的逻辑又改坏。有人让它把旧版 SDK 替换成新 SDK，前 30 分钟很顺利，后面开始“顺手”重构无关模块，最终 diff 大得吓人。

2. **Token 消耗速度远超预期**  
   Claude Code 的每一次请求都会携带大量代码上下文，输入 token 数量惊人。有用户反馈，跑一轮复杂重构，套餐额度几十分钟就撞墙，接下来只能等冷却或打开 API 开关继续烧钱。

3. **幻觉 API 和依赖版本**  
   在复杂依赖环境中，模型可能调用不存在的库方法，或者混用不同大版本的 API。等测试失败时，用户往往要花更多时间排查 AI 埋下的雷。

4. **CLI 交互对普通开发者不够友好**  
   没有 IDE 里那种逐行 diff 和可视化确认，出错后只能翻终端记录，定位成本高。极客能接受，但大量“想省事”的用户会被劝退。

换句话说，第一小时它像 10x 工程师，第三小时可能就退化成需要你时刻盯着的实习生。

## 三、订阅成本：看似月费，实则“按 burn rate 收费”



Claude Code 的退订潮里，钱是绕不开的因素。

- Anthropic 的订阅套餐并不等于“无限使用”。Pro、Max 档位虽然包含一定用量，但 Claude Code 的 token 消耗速度远高于普通对话。
- 重度用户一旦把 Claude Code 当成“全自动后台工人”，月底账单很容易超过心理账户。每月额外 API 费用破百美元并不罕见。
- 对比 Cursor Pro、GitHub Copilot 这类固定月费产品，用户对“刷爆额度”的感知会非常强烈。
- 更关键的是成本结构：Claude Code 每次行动都会重新读取大量上下文，即使输出只有几行代码，输入侧的费用也不低。

于是，很多用户开始意识到：Claude Code 更像一辆大排量跑车，短途冲刺很爽，但拿来通勤，油费会让你重新思考人生。

## 四、竞争对手没有睡觉，差异化正在收窄



如果把时间拨回一年前，Claude Code 的 agent 能力确实领先。但 AI coding 这条赛道变化太快。

- **Cursor**：把 agent 能力做进了 IDE，逐行 diff、一键 apply，交互门槛更低，更符合普通开发者的工作流。
- **GitHub Copilot**：背靠 VS Code 生态和企业账号体系，从个人到团队采购的路径更短。
- **Gemini CLI**：凭借激进免费额度和多模态能力抢用户，价格战打得很直接。
- **开源方案 Aider、Continue、OpenHands**：支持本地模型和私有部署，对数据敏感团队有吸引力。

Claude Code 的长上下文和复杂代码库理解能力仍有优势，但这种优势正在被成本和体验问题稀释。加上用户切换成本低，退订很多时候并不是“宣判死刑”，而是“用脚投票”。

### 实用建议：三条冷思考

1. **按任务粒度使用，不要一把梭**  
   写一次性脚本、生成单元测试、解释遗留代码，可以放心交给 Claude Code。但全仓库无监督重构、核心模块改造，暂时还是把它当辅助，而不是主驾驶。

2. **设置硬约束，保护钱包和代码库**  
   打开 API 前先设预算上限；所有变更走 feature branch；禁止 AI 自动 push；合并前必须人工 review diff。把“它能跑”和“它能上线”分开看。

3. **用试点数据决定续费，而不是靠新鲜感**  
   试用期做个小实验：记录它实际节省了多少时间，又花了多少时间修它引入的问题。如果节省时间小于返工时间，退订就是理性选择；如果某些场景收益稳定，按需订阅也未尝不可。

技术热点的生命周期从来不是直线。退订潮不是 Claude Code 的终点，而是 AI coding 工具从“演示惊艳”走向“生产可用”必须跨过的一道坎。
