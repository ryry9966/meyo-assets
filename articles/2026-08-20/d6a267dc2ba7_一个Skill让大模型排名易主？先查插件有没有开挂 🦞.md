最近关于“一个 Skill 让 DeepSeek V4 Pro 超越 Fable 5”的讨论，在技术社区里经历了两次反转：先是有人晒出分数，说某个插件让模型排名跃升；随后又有开发者指出这个热门 Skill 存在评测取巧，于是被锤。这起争议真正值得关注的，不是哪个模型强，而是我们到底该怎么看模型评测里的开挂。



## 一、Skill 不是模型参数，而是外挂式流程



Skill 这个词，在模型生态里并不指代权重更新。它更像一套挂在模型外面的操作手册：

- Skill 通常包含预置提示词、工具调用规则、输出格式模板，有时还会带一段可执行代码或本地知识库。
- 它不改变模型本身的参数，但可以改变任务完成的路径。
- 举例来说，一个数学 Skill 可能不会让模型自己一步步推理，而是在后台调用 Python 的 sympy 做符号计算，再让模型把结果包装成自然语言。
- 因此，装了 Skill 后的表现，是“模型 + 工具 + 提示工程”的系统表现，不是单纯的基座模型能力。

这种差异很像“裸跑测试”与“带着外挂装备上场”。如果只看最终分数，很容易误判。

## 二、所谓“超越”，通常藏在四条技术路径里



当一个 Skill 让某个模型突然超越另一个模型，常规怀疑不是权重突然进化，而是评测链路被改变了。常见路径有以下几种：

1. **外部求解器桥接**：把数学、代码、逻辑题转给 Python、Wolfram 或专用求解器处理，模型只负责翻译。
2. **题库命中 / 检索增强**：Skill 里可能内置了与评测集相似的样例库，遇到原题或近题时直接检索答案。
3. **评测集过拟合**：针对某个榜单写高度专用的 few-shot 示例，分数在特定数据集上很高，换题就明显回落。
4. **指标口径取巧**：把单次生成改成多次采样后投票，或者用更宽松的停止符截断，让 pass@1 或 EM 等指标变得好看。

以常见的 GSM8K、MATH、SWE-bench 为例，它们分别考察多步数学推理、数学竞赛能力、代码修复能力。只要 Skill 在其中一个环节加了外部工具或专用数据，分数就可能拉开几十个点。问题是，这种差距来源于系统设计，而不是模型推理层的提升。

## 三、为什么“被锤”反而有价值：评测要审计链路



过去几年，大模型排行榜不止一次因为数据污染、协议不统一、参数设置不一致而出现争议。Agent 和 Skill 兴起后，评测变得更加复杂：

- 以前的闭卷问答，还能靠去重、去污染控制变量；现在模型可以调用搜索、代码执行、数据库，变量更多。
- 同一个模型，裸跑和带 Skill 跑，分数可能天差地别；不同 Skill 之间，也可能差出几十分。
- 如果评测没有记录工具权限、采样次数、是否开卷、是否使用外部 API，那么榜单上的排名就缺少可比性。

所以，热门插件被锤，不是社区在抵制工具，而是在要求评测把“谁做的贡献”说清楚。科学一点的结论应该是：在某个协议下、某个系统组合超过了另一个系统组合；而不是简单地说某个基座模型超过了另一个基座模型。

## 四、看分数之前，先分清三件事



对普通用户和做模型选型的人来说，这起事件最大的提醒是：别把系统分当成模型分。

- **归因要谨慎**：一个 Skill 带来的提升，可能 90% 来自它背后的规则和工具，而不是模型更会推理。
- **选型要看可复现性**：如果某个 Skill 依赖闭源插件、私有题库或第三方 API，换到生产环境后可能无法复现。
- **对比要公平**：同一任务、同一评测集、同一工具权限、同一采样策略，比较结果才有意义。否则就像拿带计算器的人参加心算比赛，再宣布他心算最快。

最后，给三个冷思考：

1. 看协议再看分数：是否允许外部工具、是否闭卷、是否做过去污染、采样参数是否固定，这四行比排名本身更重要。
2. 把“超越”翻译成“系统超越”：追问一句裸模型差多少，能减少很多误读。
3. 做一次最小复现实验：关掉 Skill，用同一批题和同一参数跑 10 分钟，分数差往往会告诉你真相。

模型会继续刷榜，Skill 也会继续出新的神奇插件。但对工程师来说，稳定的不是某个让人惊喜的分数，而是一条能说清楚、能复现、能审计的评测链路。
