## 背景

OpenClaw 这类 Agent 框架解决了"调用工具"的问题，但没解决"认识你"的问题。每次新会话都是一张白纸。对话记忆存在却不可信：向量库检索出来的是碎片，长短时记忆经常过期。你上次明确说过"不要自动装依赖"，这次它又来了。

根因在于：我们把用户上下文当作"聊出来的副产品"，而不是"需要维护的资产"。Agent 不需要更多记忆机制，它需要一份可靠的、可随时引用的用户说明文件——USER.md。它应当像 README 一样被显式维护和版本化。

## 问题

没有 USER.md 的代价不是"Agent 偶尔犯错"，而是每次会话你都要重复一遍上下文：你用什么语言回复、哪些工具要二次确认、项目里哪块是雷区。一次性成本积累成持续开销，而 Agent 反而因为缺少约束，在每次会话里随机猜一个"你可能是谁"。

## 做法

1. **创建文件**。位置放在 OpenClaw 配置目录（如 `~/.openclaw/USER.md`），并在主配置里显式声明"会话开始时加载此文件，作为最高优先级个人偏好"。不要指望 Agent 自己去发现它。
2. **结构固定，五段即可**：身份 / 沟通偏好 / 工具使用 / 工作流 / 禁忌。
3. **写法只有两种：祈使句规则 + 正反例**。例如"回复用中文，代码注释用英文。术语保留原文，首次出现加中文译名"比"我比较习惯双语工作"有效得多。
4. **声明优先级**。在 AGENTS.md 或系统提示开头写一句："USER.md 定义用户偏好，与系统级指令冲突时以 USER.md 为准（涉及安全除外）"。
5. **按季度修订**，用 git 管理，每个改动带一句话说明。

## 踩坑

- **写成小传**。"我是一名八年全栈工程师"没有任何操作性。写成"涉及后端方案时，默认考虑 Go，不要提 Node"。Agent 只认可执行的规则。
- **条目太多**。超过 50 条，每条权重都被稀释。留下最重要的 20~30 条，其余删掉。
- **自相矛盾**。既写"回复要简短"，又在例子给出 800 字长文，Agent 会随机选一个执行。
- **没验证加载链路**。有些版本只在会话启动时读一次 USER.md，改完不重启不生效；有的需要在配置里打开开关。先确认你的版本真的读了这个文件。
- **往里面放密钥**。USER.md 会被塞进每次请求的上下文，等于把明文 token 发给模型服务商。

## 可复用建议

- 先记录一周你的抱怨："又让我确认""又用错了术语""又把方案搞复杂"。这些抱怨就是 USER.md 的素材。
- 用"当 X 时，做 Y"句式，每条尽量配一个反例。Agent 对反例的学习效率远高于抽象描述。
- 文件末尾加 Changelog，只记变更。之后想回溯"哪条规则让行为变好/变坏"时，这是唯一线索。
- 验证方法：开新会话，问"根据我的 USER.md，你会在什么情况下主动提醒我？"答不上来就是加载或写法有问题。

## 总结

USER.md 是性价比最高的上下文投资。它不试图让 Agent 更聪明，而是降低它的不确定性。花一小时写清楚，换来的是之后每次会话都少重复一遍自己。
