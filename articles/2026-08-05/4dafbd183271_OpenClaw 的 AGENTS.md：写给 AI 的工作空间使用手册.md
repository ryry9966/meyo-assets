## 背景

OpenClaw 跑起来之后，你很快会发现一个尴尬的问题：Agent 确实能干活，但它对你的工作空间一无所知。

它不知道哪些目录是构建产物、哪些文件是生成代码、哪个脚本会推生产环境。于是它开始猜测。猜测的结果通常是：读了不该读的大文件，改了不该动的配置，或者在错误的目录下执行了破坏性命令。

人需要 onboarding，AI 也需要。AGENTS.md 就是给 Agent 看的 README——不是给人看的文档，而是写给 AI 的工作空间使用手册。

## 问题

没有 AGENTS.md 的时候，OpenClaw 的行为不是"随机"的，而是"缺乏约束的合理"。它会：

- 从当前目录向上寻找 `.env`，即便那不是项目用的那个；
- 把临时文件写到工作区根目录，而不是你习惯的 `/tmp` 或者 `build/`；
- 在解读 `package.json` 时把 `devDependencies` 当成运行时依赖；
- 执行 `git clean -fd` 之前不确认是否包含 `.env.local`。

这些问题不在 Agent 的能力维度上，而在上下文维度。AGENTS.md 解决的正是上下文缺失的问题：把"你应该知道的事"写进工作区本身，让 Agent 在每次启动时都能读到。

## 做法

以一个常见的 OpenClaw 工作区为例，假设你管理三个项目：`agent-core`（核心逻辑）、`mcp-servers`（MCP 服务集合）、`scripts`（运维脚本），外加一个 `.claw/` 目录存放 OpenClaw 的会话记录和插件配置。

在根目录创建 `AGENTS.md`，内容建议包含以下段落：

```markdown
# AGENTS.md

## 工作区结构
- `agent-core/` — 核心代码，生产部署，任何修改需要运行 `npm test`
- `mcp-servers/` — 本地 MCP 服务，可独立重启，不涉及生产
- `scripts/` — 运维脚本，部分面向生产，执行前需确认目标环境
- `.claw/` — OpenClaw 运行时数据，不要修改，不要提交

## 执行规则
1. 所有命令在 `agent-core/` 下执行前，先确认当前工作目录（`pwd`）；
2. 生产环境部署脚本（`scripts/deploy*`）禁止直接运行，需列出 `--dry-run` 输出并等待用户确认；
3. 临时文件一律写到 `/tmp/claw-<会话ID>/`，不要在仓库内创建；
4. 修改 `agent-core/` 内文件之后，必须运行 `npm test` 和 `npm run lint`。

## 禁则
- 不要修改 `.claw/` 下的任何文件；
- 不要删除 `mcp-servers/` 下源码中的注释，部分注释与协议文档联动；
- 不要执行 `git push --force`；
- 不要安装新的 npm 包，除非用户明确要求。

## 常用变量
- `OPENCLAW_PROJECT_DIR`：当前工作区根目录
- `MCP_SERVER_PORT`：MCP 服务默认端口（8080）
- `LOG_DIR`：日志目录（`/var/log/claw/`）
```

写完保存后，在 OpenClaw 中开始新会话，发送"请简述你对我工作区的理解"，确认它能复述出关键约束。这一步是验证 AGENTS.md 是否真正生效的最小测试。

## 踩坑点

**1. 写得太抽象没用。**

"请谨慎操作生产环境"这种句子 Agent 没法执行。它需要的是可判定的规则："如果路径包含 `scripts/` 且名称以 `deploy` 开头，则必须 dry-run 并等待用户确认"。规则要写成 if-then 结构，不是价值观宣言。

**2. AGENTS.md 和 CLAUDE.md 的兼容问题。**

如果你同时保留 `CLAUDE.md`，很多 Agent 框架会优先读取它，导致 AGENTS.md 被忽略。处理方式：统一用 AGENTS.md，删掉或重定向 CLAUDE.md。不要两边维护，最后一定不一致。

**3. 版本管理要做好。**

AGENTS.md 属于仓库代码，应当纳入版本控制。更新规则后，在 commit message 里注明"rules changed"，方便回溯为什么 Agent 行为发生变化。我见过最糟糕的情况是：AGENTS.md 里的目录结构已经删掉半年了，Agent 还在按旧规则做事。

**4. 不要塞入密钥或内部路径。**

AGENTS.md 会随着仓库分发（如果你是开源项目），也会被 Agent 频繁读取。任何敏感信息放在这里等于明文泄露。内部路径写相对路径，不要写 `/Users/yourname/...` 这种绝对路径。

**5. 会话中途的规则更新不会生效。**

OpenClaw 在会话开始时加载 AGENTS.md。如果你在会话中途修改了文件，Agent 不会自动重新读取。改完规则，要重新开一个会话再测试。

## 可复用建议

- **位置固定**：放在工作区根目录，不要放子目录。Agent 通常从 cwd 向上查找，根目录是唯一稳定锚点。
- **篇幅控制**：AGENTS.md 最好在 50-100 行之间。太短说明信息不够，太长 Agent 注意力会被稀释。用 checklist 而不是散文。
- **区分"必须"和"允许"**：用"必须/禁止"标识硬性规则，用"可以"标识授权行为。Agent 对情态动词的分辨能力比想象中敏感。
- **定期审计**：每个月花十分钟检查 AGENTS.md 是否与当前工作区实际结构一致。删除失效规则，陈旧规则比没有规则更有害。
- **结合 MCP 使用**：如果你的 OpenClaw 同时加载了文件系统 MCP server，在 AGENTS.md 中注明哪些路径 MCP 可以访问、哪些被拒绝，避免 Agent 绕过 shell 限制通过 MCP 读文件。

## 总结

AGENTS.md 不是一份文档，而是一份运行时配置文件。它改变的不是 Agent 的能力，而是 Agent 的默认行为——把"猜"变成"读"，把"可能出错"变成"按规则执行"。

在 OpenClaw 的实践中，我把 AGENTS.md 视为工作区的"启动参数"。写一次，每次会话都在受益。如果你还没有给你的工作区写过 AGENTS.md，今天花三十分钟补上；如果你已经写了，试着用上面五条踩坑点过一遍，大概率能找到一两条需要修正的地方。

这比换一个更强的模型，对 Agent 实际输出的改善更明显。
