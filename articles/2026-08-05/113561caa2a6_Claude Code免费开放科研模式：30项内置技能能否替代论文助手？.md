过去一年，AI圈最热闹的叙事之一，是 **Claude 系列模型从"聊天机器人"向"自主科研智能体"（AI Scientist）进化**。但大多数科研工具要么闭源、要么依赖复杂环境配置、要么贵得离谱。2月中旬，一个好消息砸下来：**开源版 Claude Science 来了——零依赖、MIT 协议、内置 30+ 项科研 Skills**。

一句话翻译：你不需要懂云计算、不需要折腾 Python 环境、不需要申请付费 API key，把一个仓库拉下来，就能在自己的电脑上跑一个"会规划实验、写代码、读论文、出图表"的科研助手。这事到底有多大分量？我们拆开看。



## 科学计算模式：从"快问快答"到"慢思考推理"

Claude 的科研能力不是"模型变聪明了"这么简单。背后是 Anthropic 从 2025 年开始引入的 **科学计算模式（scientific computing mode）**——说白了，就是给模型两颗"大脑"：

- **快速模式（fast mode）**：适合日常对话、写摘要、头脑风暴；响应快但深度浅。
- **推理模式（reasoning mode）**：适合处理数学推导、统计分析、实验设计；本质是让模型用 **延展思考（extended thinking）** 把问题拆解、再验证、再执行。

关键的机制在于：**科学计算模式允许模型"计划行为"（planned behavior）**。具体来说，当 Claude 收到一个任务，比如"对这两个数据集做 t 检验并生成火山图"：

1. 它会先拆解子任务，列出步骤清单；
2. 选择该调用的 **工具（tools）**，比如 Python 执行环境、文件读写、网页检索；
3. 执行过程中实时检查输出是否合理，若有异常则自动回滚重写代码；
4. 最后把所有结果汇总成一份结构化报告。

这正是科研工作中"做实验"的标准流程。传统 AI 编程工具（比如代码补全）只能帮你把一段函数写对，而科学计算模式帮你把**一套工作流**跑通。前者是一个手脚麻利的实习生，后者是一个能独立设计实验并复盘结果的研究助理。

## 内置 30+ 科研 Skills：硬货还是花架子？

开源版本的核心资产，是这 **30 余项预置 Skills**。它们不是摆设，每个都对应真实科研场景。粗略归类：

- **文献处理类**：PDF 解析、引文提取、语义检索、会议论文格式转换（如 NeurIPS/ICML 模板）；
- **数据科学类**：缺失值处理、异常值检测、交叉验证、统计学检验（t 检验、ANOVA、回归诊断）；
- **可视化类**：matplotlib/seaborn 模板生成、自动图表注释、双 y 轴绘图；
- **论文写作类**：数学公式 OCR、LaTeX 生成、段落润色、审稿人意见生成（用来写 rebuttal 时模拟攻击性提问）；
- **领域专属**：蛋白质序列分析、基因表达矩阵处理、分子式解析、气候数据 NetCDF 提取。

举个例子，过去你想从一篇 PDF 里挖出所有表格和数据，常规流程是：下载 → OCR → 人工核对 → 整理成 CSV → 再写 Python 脚本做清洗。现在你只需要把 PDF 路径丢给 Claude，说一句"提取所有表格并按列重命名"，技能链会自动执行。

但注意，Skills 不是"魔法 API"。它们更像**一套经过设计的系统提示词 + 工具调用模板**，让模型知道"在这个场景下先做什么、再做什么"。也就是说，真正值钱的是 workflow 设计，而不是代码本身。



## 零依赖与 MIT 协议：开源背后的商业账

这个开源版本最"叛逆"的地方在于：**零依赖**。拿过科研项目的人都知道，环境配置是最大的时间黑洞——Conda 冲突、CUDA 版本、pip 依赖地狱。而这个项目把运行时做成单一可执行文件，拉下来就能跑，对没受过系统编程训练的科研人员极度友好。

MIT 协议意味着什么？你可以：

- 修改并商用，不罚钱；
- 集成进自己的私有工具链；
- 把 Skills 套用在自己收集的内部数据上，不用回馈开源；
- 甚至拆解其中某个 Skills 用到自己的产品里。

从商业逻辑看，Anthropic 做的是**"Agentic commerce"**——不靠卖软件收费，而是靠模型调用量和生态粘性。当你的科研工作流全部跑在 Claude 的协议上，你被锁定的不是代码，而是**工作习惯**。等到问题足够复杂时，你就会自然升级到付费的 API 或者企业版。这跟当年微软把 VS Code 免费让你用，再靠 Azure 和 GitHub Copilot 收费，是一套打法。

## 3 个值得关注的冷思考

风向已经变了：**AI 辅助科研的门槛，正在从"技术能力"变成"提问能力"**。工具越完善，个人的判断力、构思能力就越值钱。所以，当大家都在狂欢时，我想泼三瓢冷水：

1. **别神化"30+ Skills"。** 技能包的覆盖面广，但深度有限。针对你课题组里那种极端冷门的分析需求（比如某种非标准测序的质控算法），大概率还是要自己写代码。把它当工具箱，别当万金油。

2. **警惕"自动出结果"带来的验证风险。** 模型生成的统计检验、图表、甚至文献引用，都可能存在幻觉。用工具加速没问题，但**关键结论必须人为复核**。尤其生物医学领域，一个错误的 p 值可能毁掉整篇论文。

3. **核心竞争力仍是数据与选题。** 当每个人都能调用同样的模型和技能包时，差异在哪？在于你手里的 **私有数据、领域直觉、以及对真问题的洞察力**。工具开源了，但你的选题判断力没有开源。



科研的本质没有被改变——**提出好问题，设计好验证，给出好解释**。过去，拦在路上的有 80% 是重复劳动；现在这些劳动正在被压缩到趋近于零。接下来拼的，是剩下那 20% 的人类独有部分：好奇心、怀疑精神、以及对未知的审美判断。工具免费了，思考更贵了。
