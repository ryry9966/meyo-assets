## 背景

Agent 的信息检索能力一直存在两个断层：一是模型训练语料滞后，二是搜索 API 返回的往往是摘要而非原文。当我们需要 Agent 基于最新网页内容做判断时，光靠检索接口是不够的，必须让 Agent 直接"读"网页。

但直接把 URL 丢给 Agent 去爬，会遇到几个问题：目标站点反爬策略各异、页面动态渲染导致内容缺失、返回结果没有结构化清洗、合规边界不清晰。OpenClaw-CN 社区的很多实践者已经意识到：采集网页应该是一个独立的基础服务，而不是 Agent 的临时行为。

## 问题

我们从实际使用中归纳出三个核心痛点：

1. **合规风险**：无差别抓取会触达敏感内容，作为基础设施必须做屏蔽和去重。
2. **解析不可控**：不同站点 DOM 结构差异大，Agent 偶尔能处理，但缺乏稳定统一的结果格式。
3. **开销与稳定性**：每次请求都消耗 Token，且断连重试逻辑缺失，导致任务经常中途失败。

## 做法：让「稽客」成为一个 MCP Server

我们的思路是：**把网页采集封装成标准 MCP 工具，Agent 只负责表达意图，采集器负责执行与清理**。整个过程分三步：

### 第一步：搭建采集服务

使用 Python + Playwright + BeautifulSoup，实现一个轻量 HTTP 服务。核心接口包含：

- `fetch_url(url)`：抓取正文内容，去除导航、评论、脚本标签。
- `fetch_screenshot(url)`：返回页面截图路径，供 Agent 处理视觉类任务。
- `search_in_page(url, query)`：在指定页面检索关键词并返回上下文片段。

所有接口通过 MCP SDK 暴露，Agent 端只需在配置文件中注册该 server：

```
mcp_servers:
  scraper:
    command: python
    args: ["server.py"]
    env:
      BLOCKLIST: "ads,analytics,spam"
```

### 第二步：设计安全策略

- **域名白名单与黑名单**：在 server 启动时加载，黑名单域直接返回空结果。
- **内容合规过滤**：对正文做敏感词扫描，命中则丢弃内容但保留元数据（提示 Agent 该页面被过滤）。
- **请求频控**：每个域名每分钟最多 20 次请求，用简单的 token bucket 实现，避免触发对方反爬。

### 第三步：接入 Agent 工作流

在指令模板中约定了类似这样的用法：

> 任务：总结最近一周某官网公告
> 步骤：调用 `fetch_url` 获取公告页全文，再调用 `search_in_page` 筛选日期关键词。

实测效果：相比直接让 Agent 自行尝试抓取，结构化输出**减少了约 40% 的无效调用**，且失败重试由采集器统一管理，Agent 侧逻辑显著简化。

## 踩坑点

1. **动态渲染陷阱**：很多站点首屏是 JS 渲染的，直接 requests.get 拿到的是空壳。必须用 Playwright 等待网络空闲；但注意等待时间不宜过长，建议 3000ms 超时即可，同时抓取前先判断 `document.readyState`。
2. **续传与重试**：单个大页面（如长列表页）容易在传输中断开。实现时要记录已获取的 DOM 位置，断点续抓比整体重试节省大量时间。
3. **User-Agent 指纹**：不要用默认 UA，伪装成真实浏览器能减少一半的 403 问题。我们内部维护了一个小型 UA 池，轮换使用。
4. **MCP Server 并发**：多 Agent 实例同时调用时，默认 Python http.server 是单线程的。务必换成 `ThreadingHTTPServer`，否则会出现请求排队超时。

## 可复用建议

- **让采集器"哑"一点**：不要在服务端做内容理解，AI 的活留给 Agent，采集器只做提取、清洗和过滤。
- **设计缓存层**：对同一 URL 的重复请求，默认返回 5 分钟内的缓存，既快又省钱。
- **日志留痕**：每次抓取记录时间、目标域、返回状态码、内容大小。便于事后审计合规性。
- **给 Agent 传 Meta 信息**：不要只返回正文，同时返回标题、发布时间、作者，这些对 Agent 判断信息可信度非常重要。

## 总结

Web scraping 在 Agent 体系中不是"锦上添花"的插件，而是一层必须的工程基座。它把网络请求的复杂性、风险性隔离在 Agent 之外的独立服务中，让 Agent 专注于理解和决策。社区里已经有多种实现路径，但核心原则一致：**安全采集、结构化输出、失败可控**。如果你的 Agent 还在用裸 HTTP 请求读网页，值得试试把采集能力抽出来做一个标准服务。
