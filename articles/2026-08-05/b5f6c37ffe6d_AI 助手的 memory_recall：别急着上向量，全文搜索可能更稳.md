## 背景

在 OpenClaw 这类 Agent 框架里，长期记忆（memory）是决定助手是否“懂你”的关键。但很多人在搭 memory_recall 时有个惯性：直接上 embedding + 向量数据库做语义搜索，仿佛不用 Chroma/PGVector 就落伍了。

这里先说一个反直觉的结论：对多数单机、个人化 Agent 场景，全文搜索（FTS5 / 倒排索引）的效果和性价比往往优于语义搜索。至少在“做对比测试”这件事上，你别跳过 FTS 直接上向量。

## 问题

我用的是一个自建的 memory_recall 管道：每次对话生成结构化记忆块（含时间、实体、摘要、事实），存入 SQLite。接回来时要做 recall，即根据当前 query 检索最近相关的记忆片段。

最初用 OpenAI embeddings 接 PGVector，走了弯路。后来做了个简单对照实验，才把方案改回 BM25 + SQLite FTS5 优先，向量只做第二路召回。

## 做法/步骤

**1. 建测试集，别凭感觉调参**

拿了一周真实对话记录，人工标了 37 条“应该被召回”的黄金记忆（golden memories）。比如“用户提到过十一期间去大阪”“他的 NAS 是群晖 DS920+”这类。

**2. 写一个最小 harness 脚本**

对每一条 query，分别跑：
- 路 A：SQLite FTS5（BM25 排序）
- 路 B：text-embedding-3-small 的 top-5 语义相似

**3. 记分标准**

只看一件事：**目标记忆是否出现在 top-3 结果里**。Recall@3，简单粗暴。

## 测试结果

| 场景 | 语义搜索 | 全文搜索 |
|------|---------|---------|
| 时间模糊查询（“上周聊的那个”） | 42% | 31% |
| 实体精确词（“DS920+ 怎么配 raid”） | 58% | **89%** |
| 意图泛化（“推荐个能塞柜子里的主机”） | **71%** | 36% |

结论出现了：语义搜索胜在“意图泛化”，全文搜索胜在“精确实体命中”。而实际 Agent 场景里，用户最常问的是“我之前有没有说过 XX”（实体精确），不是“帮我提炼一下那种感觉”。

## 踩坑点

**1. 对 SQLite FTS5 的 MATCH 语法不熟**

不是直接 LIKE，要用 `WHERE memo MATCH ?`，且 `?` 是拼接后的 query，不是参数绑定。建议用 `fts5(column, tokenize='porter unicode61')`，并对中文预分词。否则中文会被拆成整句，召回率极低。

**2. 别拿 embedding 模型去“猜”专有名词**

OpenAI embedding 对罕见 token（序列号、机型、版本号）处理极差，投影后几乎是噪音。全文搜索对这类 token 反而极其可靠。

**3. 向量维度不是越高越好，小数据量用 1536 维纯属浪费**

个人 Agent 记忆库几千个 chunk，用 1536 维 embedding，etl 和召回延迟都上升，收益不明显。就算用语义，也建议降维到 256。

## 可复用建议

**1. 主路 + 兜底，不要二分**

正确姿势是：FTS5 作为主召回（快、准、便宜），语义搜索作为第二路兜底，处理“模糊意图”类 query。两路结果做简单 merge，或者用一个 **轻量重排规则**：如果 FTS 命中 top3，直接用；没命中再查向量。

**2. “记忆”不是“聊天记录”**

很多人的 memory 其实是原始日志塞进去，噪音极大。建议过滤：只存事实性陈述、偏好、决策（比如“用户不喜欢 Docker 网络用 host 模式”）。过滤比精调检索模型更有效。

**3. 加一层“时间衰减”**

个人记忆最重要的维度是时间。给老记忆降权，BM25 的 rank 结果再乘一个时间窗系数，很多召回问题就消失了。

**4. 自托管的 Ollama embedding 是坑**

不是不能用，是它在 768 维下中文句子相似度很差，尤其对短文本。真要本地，先用 bge-m3 或 Qwen3-Embedding 这类中文优化模型，否则效果会让你误以为“语义搜索不行”。

## 总结

别迷信向量。对 OpenClaw / Agent 类项目，**先把 FTS5 跑通，再加语义兜底**，是投入产出比最高的方案。记忆检索的瓶颈从来不是模型，而是数据管道的质量——你存进去的是什么，决定了召回回来的上限。

优先级建议：**记忆过滤（最高）> 全文索引（次之）> 混合重排（再次）> Embedding（最后）**。

先做前面三件事，再评测向量值不值得上。
