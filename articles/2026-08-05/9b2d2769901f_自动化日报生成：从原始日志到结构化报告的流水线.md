## 背景

日报是技术团队协作里绕不开的动作，但它又是最令人厌烦的重复劳动。我在维护一个多服务集群时，每天要面对来自 API 网关、应用 Pod、定时任务和审计系统的四路日志，手动整理日报耗时 20-30 分钟，还容易漏项。于是我用 OpenClaw Agent 接了几个 MCP 工具，搭了一条从原始日志到结构化日报的流水线，跑了一个多月，稳定输出，这里把做法和踩过的坑写出来。

## 问题拆解

原始日志有三个典型问题：

1. **噪声高**：INFO 级别的健康检查、重复的握手日志占了大半体积。
2. **口径不一致**：不同服务的错误码格式、时间戳时区不统一。
3. **需要判断力**：哪些异常是偶发、哪些是趋势性恶化，纯规则脚本做不好。

所以设计目标是：**用确定性代码处理统计和过滤，用 LLM 处理语义归纳**，两者分工明确。

## 流水线结构

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 日志源    │ → │ 预处理    │ → │ Agent归纳 │ → │ 渲染分发  │
│ MCP读取   │   │ 过滤器    │   │ 结构化    │   │ Webhook  │
└──────────┘   └──────────┘   └──────────┘   └──────────┘
```

**第一步：日志采集与预处理**。我用一个本地 Python 脚本通过 MCP 文件系统工具读取各日志源，按时间窗口切分，先做规则过滤：剔除心跳包、静态健康检查，按服务名和错误码聚合出初步统计。这一步完全是确定性的，不经过 LLM，保证计数准确。

**第二步：Agent 归纳**。OpenClaw Agent 拿到预处理后的统计摘要（而不是原始日志），按预定义的 JSON Schema 产出结构化结果：

```json
{
  "date": "2025-01-14",
  "summary": "整体稳定，支付服务延迟异常上升",
  "incidents": [
    {"service": "payment", "level": "warning", "count": 47, "summary": "gateway timeout 占比升高"}
  ],
  "trends": ["支付超时较昨日+12%"],
  "action_items": ["排查支付网关连接池配置"]
}
```

关键技巧：**给 Agent 的输入不是日志原文，而是预处理后的统计表**，这样既控制 Token 成本，也避免 LLM 在噪声中迷失。

**第三步：渲染与分发**。按固定模板渲染成 Markdown，附上原始日志的索引链接，通过 Webhook MCP 推送到团队的聊天工具。

## 踩坑记录

**时区不一致导致统计错位**。最开始有个服务的日志是 CST，其他是 UTC，时间窗口切分后数据对不上，一度以为系统有故障。排查半天发现是时区问题。现在统一在预处理阶段转换为 UTC，报告里再转回本地时区。

**LLM 对数字的幻觉问题**。Agent 在总结时会把"47 次超时"写成"几十次"，甚至在某次把 3 个错误码合并描述成"大规模故障"。**解决办法：统计数字全部由预处理脚本硬编码进模板，LLM 只负责归纳原因和影响，不能改写数值**。Schema 里把这些字段标记为 `readonly`。

**上下文窗口溢出**。有一次日志量暴增，预处理后的统计摘要也大了，Agent 的上下文不够用，产出的 JSON 截断了。后来加了分片归纳策略：按服务维度先分别归纳，再做汇总。

**瞬时故障导致流水线中断**。某日志源偶发不可读，Agent 直接报错退出。需要加降级策略：读不到就跳过该源并生成警示，不能中断全流程。

## 可复用建议

1. **Schema 先行**。先定义好日报的 JSON Schema，再写预处理和提示词，三者的字段保持一致性，后期迭代成本最低。
2. **保持引用可追溯**。报告里每条结论都附上原始日志的 grep 命令或索引链接，方便去查证。
3. **用确定性逻辑托管关键指标**。数量、百分比、同比环比都交给脚本算，LLM 只负责"怎么解读"。
4. **留一份中间产物**。预处理后的统计摘要存一份副本，流水线出问题时可以离线重放，不用重新读日志。
5. **API 成本可控**：由于喂给 Agent 的是聚合数据而非原始日志，日均 Token 消耗很稳定，大约只是原始日志方案的 1/10。

## 总结

这套流水线的核心原则是"确定性部分用代码、语义部分用 Agent"，它不追求全自动花哨效果，而是在出问题时知道去哪里排查。从自己的重复劳动里省出来的时间，才是自动化的真正收益。
