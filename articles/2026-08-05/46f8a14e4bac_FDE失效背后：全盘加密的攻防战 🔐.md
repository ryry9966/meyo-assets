看到“FDE又不够了”这个热搜，第一反应可能是：全盘加密（Full Disk Encryption，FDE）不是早就变成手机和电脑的默认配置了吗？怎么突然又不行了？

其实密码学算法没有崩，崩的是围绕它的信任模型。打个比方，FDE是一扇厚重的保险门——算法是门板，密钥是门锁，而攻击者从来不会傻到去撞门。他们会绕到窗户、通风管道，甚至直接翻进安保室把钥匙摸走。这篇文章顺着这条线，拆一下FDE失效的典型场景、真实攻击路径，以及未来防线。



## 一、FDE到底在防什么：别把加密神化



- **FDE的定义**：把整个存储介质按块加密，比如 Android 的 dm-crypt、Windows 的 BitLocker、macOS 的 FileVault，通常使用 AES-XTS 模式。系统启动后输入口令解锁，之后读写由一层透明的解密引擎自动处理。
- **它保护的是“静态数据”（data at rest）**：对应场景是“有人把硬盘拆走直接读扇区”“维修态下旁路读取存储芯片”这类物理接触式攻击。
- **它防不住什么**：已开机状态下的内存数据、被植入的系统后门、带有专业取证工具的物理接触者。2019 年之后，这两类问题越来越突出，于是“FDE又不够了”成了安全圈的一句调侃：你的硬盘确实上了锁，但钥匙就搁在保险柜旁边的抽屉里。
- **历史背景**：Android 5.0 起把全盘加密设为默认，iOS 从 3.0 就引入基于文件的加密，Windows BitLocker 依赖 TPM 芯片。但这些方案的目标高度一致——保护静态数据，而不是对抗一个已经拿到系统级权限的攻击者。

所以，FDE 从来就不是“绝对安全”的标志，它只是安全链条上的第一道闸门。“不够用”不是算法被破解，而是威胁模型早就变了。

## 二、攻击者是怎么“绕过去”的：四类真实路径



以下四类攻击路径，都不需要对 AES 做暴力破解，它们的共同点是：绕过密钥生命周期中的某个薄弱环节。

**1. 冷启动攻击（Cold Boot Attack）**

- 原理：DRAM 在断电后数据不会立刻消失，尤其在低温环境下，残留窗口可以从几秒延长到几分钟。
- 2008 年普林斯顿团队用一罐液氮冷冻内存，重启后把内存中的 AES 密钥寄存器直接读取出来。
- 现代设备通过内存加密和快速密钥清除缓解了这个问题，但在老旧硬件和部分 IoT 设备上依旧有效。

**2. DMA 攻击**

- Thunderbolt / PCIe 等高速外设接口支持 DMA（直接内存访问），外设可以绕过 CPU 和操作系统，直接读写物理内存。
- 攻击方式：插上一个雷电接口设备，几秒钟就能从内存中抓出解密密钥，或者干脆 Dump 整个明文页面。
- 防护手段是 IOMMU（Intel VT-d / AMD-Vi），它能把外设访问隔离到既定地址范围，但历史上默认关闭的案例并不少见。

**3. 调试口与制造链攻击（JTAG / SWD）**

- 芯片出厂时通常会保留 JTAG 或 SWD 调试接口，方便产线和维修。
- 如果厂商没有通过 eFuse 熔断或软件禁用调试口，拿到设备的人可以直接接管 CPU 调试权限，内存、闪存、密钥统统可读。
- 到了这一步，“全盘加密”形同虚设，因为对方不是在读你的硬盘，而是在读你的芯片。

**4. 取证工具与降级攻击**

- Cellebrite、GrayKey 这类取证工具，会利用还原模式漏洞、Bootrom 漏洞（比如 checkm8）或系统降级，绕过锁屏和加密层直接读取文件系统。
- 降级攻击的核心思路：把设备恢复到存在漏洞的旧固件，再复用旧漏洞提取密钥包。
- 对应防御是防回滚（Anti-Rollback）机制和系统完整性校验，但这些需要厂商真正实现到位，而不是只写进白皮书。

这四类路径指向同一个真相：钥匙在哪儿，危险就在哪儿。只要明文密钥没有待在硬件安全模块里，就总有工具能把它夹出来。

## 三、接下来这场仗怎么打：从FDE到硬件信任根，附三条冷思考



- **FDE 的短板倒逼架构升级**：Android 7.0 引入文件级加密（File-Based Encryption，FBE），把“整盘一把锁”细化成“每个文件一把锁”；iOS 的 Data Protection 则更早把密钥层级搬进硬件 SEP（Secure Enclave Processor），解密过程在 SEP 内部完成，主系统根本接触不到明文密钥。

**现代方案正在转向四件套：**

1. **硬件信任根（Root of Trust）**：密钥只存在于 TEE/SEP 内部，主系统只负责搬运密文，即使系统被攻破也拿不到核心密钥。
2. **AEAD 加密模式**：AES-GCM、ChaCha20-Poly1305 等模式，能在密文被篡改时立刻报警，堵住“改密文骗信任”的路径。
3. **防回滚机制**：用 eFuse 或单调计数器锁死旧版本固件，断掉降级攻击这条路。
4. **混合加密分层**：FBE 处理高频小文件，FDE 做全局兜底，性能与安全同时兼顾。

至于常被提及的“后量子密码”，短期内 AES 这类对称算法还没到失守边缘，真正需要提前迁移的是密钥交换和签名算法。现在开始关注，不算早。

### 三条冷思考

- **别把“开了FDE”当成“已安全”**：它守护的是数据静止状态，不是设备落入他人之手后的全部战场。越是高敏数据，越要依赖物理隔离和离线存放。
- **重点看“钥匙住哪”**：挑选设备时，优先选带 SEP/TEE/独立安全芯片的型号；电脑上开启 BitLocker + TPM + Secure Boot 三件套，比单纯把口令设得超级复杂更关键。
- **用降级和恢复模式做自查**：经常更新系统、关闭 USB 调试、设置“关机/重启必须输密码”、避免使用来历不明的线缆和扩展设备。外送维修前，关闭调试口并备份数据——这比任何加密算法都直接。
