## 背景

用 OpenClaw 跑自动化项目，最省力的模式是主 Agent 派生子 Agent 处理子任务：一个负责拆解目标，几个子 Agent 并行做代码审查、跑测试、查文档。刚开始图省事，所有子任务都沿用主 session 执行。跑了两三天，主会话慢慢变得不对劲——模型开始重复回答早期的错误结论，工具调用记录里交叉出现多个子任务的中间结果，有时候 A 任务查到的信息被 B 任务引用。

问题出在 session 隔离没做好。

## 问题本质

OpenClaw 的 session 是一块共享白板，谁都可以往上写。子 Agent 和主 Agent 的对话、工具调用、观察结果，如果不显式隔离，全混在同一块板上。直接后果：

- 主 session 的上下文被撑爆，token 消耗成倍增长，模型注意力被噪音分散
- 记忆系统把子任务的临场信息当成重要信号写入长期记忆，越跑越脏
- 并行子任务共享 session 时，消息串台，输出张冠李戴

这不是 bug，是默认行为。OpenClaw 不会主动帮子 Agent 创建独立 session，你必须自己管理。

## 做法

我现在的策略可以概括为"一人一板，散场擦板"。

**1. 子会话显式创建**

每次 spawn 子任务，强制生成独立 session id，不允许复用主 session，也不允许复用其他子任务的。

```text
spawn(
  task = "review the diff in ./src",
  session = "sub-" + task_type + "-" + sha1(task)[:8] + "-" + now()
)
```

用任务哈希加时间戳，保证每个子会话全局唯一。

**2. 上下文单向传入**

子 Agent 需要主会话的背景信息时，不要直接读主 session。把主会话的关键要点压缩成一段只读摘要，作为子任务上下文传入。子 Agent 的 session 可以写满、可以丢，不影响主会话。

**3. 工具调用绑定 session**

这是最容易漏的一步。子 Agent 内部调用的 MCP 工具，有些默认绑定主 session，导致部分调用依然写回主会话。需要把所有 tool call 显式绑定到当前子 session，而不是依赖默认值。我是在 spawn 的参数里做了全局强制覆盖，避免子 Agent 自己控制。

**4. 任务结束清理**

子任务完成后，只把结论写回主会话，细节和过程留在子 session 日志里。不需要审计的子 session 直接删除，需要留痕的落盘归档。主会话始终只保留任务派发和最终汇总两段内容。

## 踩坑点

**坑一：session 绑定了，MCP 没绑定。** 只在 spawn 时指定 session，子 Agent 内部的工具调用还是走主 session。排查了半个下午才发现是 MCP 工具层默认会话没覆盖。解决方式：在 spawn 统一入口对工具层做 session 注入，不要寄希望于子 Agent 自己守规矩。

**坑二：过度隔离导致信息断层。** 全部独立 session 后，子 Agent 读不到主会话提供的上下文，经常重复问同样的问题。修复思路不是放开隔离，而是把主会话上下文压成"只读摘要"传进去。既保住隔离，又不丢失信息。摘要这一步可以用主 Agent 自己完成，成本很低。

**坑三：并行清理时 session 误删。** 两个子 Agent 使用可读名字（比如 "sub-test"、"sub-doc"）时，后完成的把先完成的 session 覆盖了。排查时看到的是"子任务 B 的日志蒸发了"，实际是共享了同一个 session id。强制唯一命名之后解决。

**坑四：子 Agent 再派生子 Agent 时 session 传播断裂。** 父子 Agent 内部又 spawn 孙子任务时，如果不显式传递当前子 session 的标识，孙任务会退回主 session。需要在每一次嵌套 spawn 时都补上 session 继承逻辑。

## 可复用建议

1. **统一 spawn 入口。** 不要在整个项目里到处 spawn 然后再补 session，所有子任务产生必须走同一个函数，把 session 生成、工具绑定、摘要注入、事后清理全部封装进去。
2. **命名规范固定。** `sub-{taskType}-{hash}-{timestamp}`，既方便排查日志，又保证全局唯一。
3. **监控活跃会话。** 定期统计活跃 session 数量和 context 占用，超过阈值报警。没有监控的隔离，迟早会被某次异常任务打回原形。
4. **归档比删除更安全。** 默认保留子 session 日志，按业务需要定期清理。磁盘很便宜，排查问题时的现场很贵。

## 总结

Session 隔离不是安全特性，是工程纪律。关键在于三个词：**显式创建、单向传播、按时清理**。做到这三点，主会话就像一张干净的办公桌——每项任务有自己的资料夹，做完归档，桌上永远只有当前正在做的事。不要相信框架的默认行为，默认行为通常是最省事的路，而省事的路一般都是通往技术债的。
