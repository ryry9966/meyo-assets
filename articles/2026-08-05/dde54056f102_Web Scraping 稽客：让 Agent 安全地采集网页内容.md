OpenClaw 社区里，越来越多 Agent 不再只是回消息，而是被派出去"看"网页——盯竞品价、抓公告、存文档。但把 Agent 指向任意 URL 那一刻，问题就来了：反爬盾、登录墙、无头浏览器崩溃、甚至被防火拷问。你需要的不是一两个爬虫库，而是一套能约束 Agent 的采集工程方案。

## 问题：Agent 采集和传统爬虫不一样

普通爬虫是"一台机器跑固定脚本"，撞墙就换 IP、加延迟、写规则绕过。但 Agent 是带意图的：它会自主决定抓哪些链接，会跟着 JS 跳转，会为了完成"调研"任务反复访问同源页面。后果是——

- **动作模式像爬虫**：访问频次无规律、行为序列固定，容易被画像识别
- **内容解析脆弱**：站点改个 class 就崩，选择器全废
- **越权或误入陷阱**：Agent 顺着页面链接摸到后台、内网地址或蜜罐
- **成本失控**：一次任务可能产生几千个请求，账单和 IP 拉黑同时来

核心命题：如何让 Agent **在安全边界内**自由采集，而不是裸奔。

## 做法：四层管线，约束不靠自觉

我建议把采集能力拆成四层，每一层都内置护栏，而不是指望 Agent"自觉"：

### 1. 策略层（谁允许抓）

进来一个 URL，先过三层闸门：

- **robots 检查**：用 `urllib.robotparser` 按 Agent 身份查询，禁止则直接丢弃
- **域名白名单**：只允许业务必需域名，Agent 自主发现的未经审批域名一律绕过
- **频率预算**：滑动窗口限流，每个域名每分钟最多 N 次，N 写在外置配置里

### 2. 采集层（怎么抓）

- **轻量优先**：能用 `requests` 拿到的绝不开浏览器；只有确认内容依赖 JS 渲染时才走 Playwright
- **静态 header 与指纹**：不要像爬虫一样轮换 UA。真实业务场景固定 1-2 个 UA 加标准浏览器 header 就够了，轮换反而触发异常检测
- **重试退避**：遇到 429/5xx，指数退避（1s→2s→4s→8s），最多 3 次；403 不重试，直接回报"不可访问"
- **超时与体积上限**：连接 5s、读取 10s，响应体超过 2MB 截断

### 3. 解析层（拿什么）

- 用 **CSS 选择器 + 元数据** 而非全文抓取：先试听 `meta[name="og:title"]`、JSON-LD 结构化数据，再回到选择器
- 剥离脚本、样式、导航；只保留正文容器内文本
- 解析失败不静默，返回结构化错误：`status: "parse_failed", reason: "selector_expired"`

### 4. 落地层（存什么）

- 原始 HTML 只保留哈希，不入库
- 入库的是：页面标题、发布时间、正文、源 URL、抓取时间戳、当时选择器版本
- 数据与策略元信息分离，方便后续排查和复采

## 踩坑记录

- **Agent 会自己突破边界**：有一次 Agent 为了"完成信息缺口"，访问了 robots 里 disallow 的路径，把采集器带崩了。教训：限制要放在管线层，不要放在 prompt 里。
- **IP 池不是银弹**：上了代理池反而更容易被识别，机房的脏 IP 段被多数风控直接封。真实业务里固定 IP 配合理频次更稳定。
- **只请求不浏览，也是特征**：用 requests 拿 HTML 但页面有 JS 埋点，服务端会识别"只拿源码不执行脚本"的行为。应对：能走官方 API 走 API，不行的接受概率。
- **永远不要原地抓全站**：Agent 拿到一个列表页就"想"把全站都抓下来。预算和并发开关默认关，按任务显式启用。
- **选择器会过期**：上线时候写一个自检任务，每天抽几个页面验证选择器还活着，失败自动告警。

## 可复用建议

1. **策略外置**：白名单、频率、超时都放 YAML/环境变量，不要写在代码里。Agent 不可能每改一次策略就发版。
2. **把采集做成 MCP 工具**：在 OpenClaw 里把上面管线封装成一个 `fetch_page` 工具，Agent 只能调工具，拿不到裸 URL 出口。工具内部返回的内容自动做摘要，控制输出 token。
3. **治理日志**：每次采集记录"谁（task id）在什么时间抓了哪个域名的哪个页面，结果如何"。没有日志的采集就是裸奔。
4. **先用 API，再考虑爬**：大多数目标网站有开发文档，哪怕限流严格也优先用。爬取是最后一档，不是第一选择。
5. **给 Agent 喂数据方式要"分阶段"**：先抓索引页确认有价值，再展开详情页。一次任务不要超过 50 个 URL，保持可审计。

## 总结

Agent 时代，网页采集不是为了"对抗封锁"，而是为了**在秩序内自取所需**。把策略、预算、边界从 prompt 里挪到管线层，Agent 的自由度才真正可控。

采集不是你死我活的黑客游戏，是知识工程的管道问题。把管道修好，剩下的交给 Agent 自己跑——这就是"稽客"应有的样子。
