# 为什么需要文件访问护栏

让 Agent 通过插件或自定义脚本操作本地文件，已经成为 OpenClaw 社区的常见实践。无论是整理下载目录、处理日志还是操作项目文件，这些自动化工具极大提升了效率。但几乎没有开发者会否认：**直接给 Agent 开放整个文件系统的读写权限是一件很危险的事**。

真实场景中，一个看似无害的提示词“清理所有临时文件”，在脚本实现不够严谨时，可能因为路径拼接错误而删除重要数据。更糟的是，如果 Agent 被注入恶意指令，或者模型自身产生幻觉，它完全有能力执行 `rm -rf $HOME` 这类灾难性操作。工程上，我们需要一种最小权限机制——让 Agent 只能触碰我们明确定义的目录，除此以外皆是禁区。这就是“文件访问护栏”的核心价值。

# 问题拆解：从需求到实现约束

我们要做到：**当 Agent 调用任何涉及文件系统的工具函数时，其操作路径必须落在预先配置的白名单目录内**。表面看只需要一个路径前缀比对，但实际工程中有几个容易忽略的细节：

1. **相对路径与绝对路径的混用**：Agent 可能传入 `../../etc/passwd` 这样的相对路径，直接字符串前缀匹配会失效。
2. **符号链接绕过**：即使 `/tmp/safe` 在白名单中，`/tmp/safe/link -> /etc` 仍然能跳出沙箱。
3. **路径规范化差异**：`/app/data/./`、`/app//data`、`/app/data` 是等价的，需要标准化后再比较。
4. **跨平台兼容**：路径分隔符、大小写敏感、盘符等问题在 Windows 与 Unix 上表现不同，如果要写通用工具链，必须分别处理。

下面给出一个可实际落地的方案，以 Python 为例，因为 OpenClaw 的多数工具链都是用 Python 编写的。

# 做法：一个可复用的路径白名单检查器

核心思路是：在工具函数执行前，**解析所有传入的文件路径为“规范化真实路径”，然后检查其是否以任一白名单目录作为前缀**。

```python
import os
from pathlib import Path
from functools import wraps

class FileAccessError(Exception):
    pass

def resolve_real_path(path: str) -> Path:
    """解析路径为绝对路径并消除符号链接"""
    return Path(os.path.realpath(os.path.abspath(path)))

def check_path_in_whitelist(path: Path, whitelist: list[Path]) -> bool:
    """检查规范化后的路径是否在任一白名单目录内"""
    for allowed in whitelist:
        try:
            path.relative_to(allowed)
            return True
        except ValueError:
            continue
    return False

def file_guard(allowed_dirs: list[str]):
    """装饰器：限制被装饰函数的文件操作只能在 allowed_dirs 内进行"""
    allowed_resolved = [resolve_real_path(d) for d in allowed_dirs]

    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            # 简单实现：检查所有字符串参数是否为文件路径
            # 实际可按参数名显式声明哪些是文件路径
            for arg in list(args) + list(kwargs.values()):
                if isinstance(arg, str) and (arg.startswith('/') or arg.startswith('./') or arg.startswith('~')):
                    resolved = resolve_real_path(arg)
                    if not check_path_in_whitelist(resolved, allowed_resolved):
                        raise FileAccessError(f"路径 {arg} 不在允许访问的目录列表中")
            return func(*args, **kwargs)
        return wrapper
    return decorator
```

使用示例：假设我们只允许 Agent 操作 `/home/user/sandbox` 和 `/tmp/agent_work` 两个目录。

```python
SAFE_DIRS = ["/home/user/sandbox", "/tmp/agent_work"]

@file_guard(SAFE_DIRS)
def write_file(path: str, content: str):
    with open(path, 'w') as f:
        f.write(content)
```

Agent 调用 `write_file('/etc/hosts', 'evil')` 会直接抛出 `FileAccessError` 并被上层捕获，而不会执行任何磁盘操作。

# 踩坑点：真实世界要比示例复杂

**坑1：动态创建的路径还未存在**  
`os.path.realpath()` 在路径不存在时会返回最后存在的父目录的真实路径加上不存在的尾部。例如 `/home/user/sandbox/new_dir/../out` 如果 `new_dir` 不存在，`realpath` 可能无法完全解析。解决方法是**先分别解析已存在的部分**，或者禁止操作未创建路径的上级目录中的 `..`。更保守的做法是：只允许操作已存在文件的原地修改，创建新文件时要求其所在的父目录必须在白名单内且真实存在，这样可以用 `parent.realpath()` 做检查。

**坑2：与 subprocess 的交互**  
许多自动化脚本会通过 `subprocess` 调用外部命令（如 `tar`、`unzip`），这些命令内部也会访问文件。装饰器模式无法拦截子进程的文件操作。对此，需要配合操作系统级沙箱：Linux 下可使用 `bubblewrap` 或 `firejail` 将整个 Agent 执行环境限制在只读/只写的特定目录；在容器化部署中，直接挂载白名单目录到容器内部，其余部分只读。这是护栏的第二层防御。

**坑3：Windows 的盘符与长路径**  
`C:` vs `C:\`、短路径名 `PROGRA~1` 与真实路径的转换，需要调用 `win32api.GetLongPathName` 或使用 Python 3.8+ 的 `os.path.realpath`（它会正确解析）。白名单配置时需要统一盘符大小写。

# 可复用建议

1. **将检查逻辑抽成独立模块**，并让所有文件操作相关的 OpenClaw 工具函数统一从该模块导入装饰器或校验函数，避免散落各处。
2. **白名单目录放在配置文件中**，支持环境变量替换，例如 `$AGENT_WORKSPACE`，这样在不同部署环境只需修改环境变量。
3. **对路径操作的原子性保持警惕**：即使通过了检查，在检查点和实际操作之间仍存在 TOCTOU（time-of-check time-of-use）竞态条件。如果安全要求极高，应在打开文件前再次校验文件描述符的 `/proc/self/fd` 路径（Linux），但这已超出普通自动化脚本的范畴。
4. **写日志记录拒绝事件**：当护栏拦截非法访问时，记录完整的调用栈、原始路径和解析后路径。这不仅用于排障，也能帮助发现 Agent 的异常行为。

# 总结

给 Agent 的自动化脚本加上目录白名单限制，本质上是在系统调用层面前置了一层“权限防火墙”。用 Python 实现的路径解析加目录前缀比较可以解决大部分误操作和简单的提示注入，但对于复杂的子进程调用，仍需结合操作系统级沙箱。工程实践中，最小权限原则应该像呼吸一样自然——如果你正在维护一个会读写文件的 Agent 工具集，不妨现在就开始加上那几行检查代码，未来的你会感谢这个决定。
