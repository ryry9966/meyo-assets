## 背景

Agent 通过工具执行真实操作，但模型对环境的认知来自训练数据里的“通用世界”，而你手里是“这一台”：macOS 还是 Linux、brew 还是 apt、ffmpeg 装在哪、出网要不要走代理。OpenClaw 的 Agent 工作区里有一个 `TOOLS.md`，定位就是记录这些“环境事实与工具备注”——它随会话上下文加载，Agent 开工前会读到，相当于给它的一份本机说明书。

## 问题

没有这份记录时，常见三种损耗：

1. **重复探测**：每次会话都重新 `which`、`--version` 一遍，浪费 token 和时间；
2. **想当然出错**：把 Linux 的 `sed -i` 用法搬到 macOS，猜错路径，权限误判；
3. **经验不沉淀**：这次排障踩的坑，下次新会话原样再踩；多台机器之间配置漂移，说不清“为什么那台能跑通”。

## 做法

1. **生成初稿**：首次部署时让 Agent 自检环境——系统版本、包管理器、关键 CLI 及路径、shell 类型、网络出口，逐条写入 `TOOLS.md`。每条包含三要素：事实、依据、日期。
2. **只记差异**：只写“和默认认知不一样”的部分。ffmpeg 在标准路径且行为正常，不必记；装在 `/opt/xxx` 或缺了编解码器，才值得一行。
3. **踩坑即回写**：约定排障成功后，Agent 把根因中属于环境事实的部分追加一行。“追加”而非重写，避免误删他人条目。
4. **定期清理**：系统升级、工具迁移后让 Agent 自检一轮，过期条目直接删。事实过期比缺失更糟——旧路径会让 Agent 坚定地走错。
5. **多机分工**：环境相关的只留在各机器自己的 `TOOLS.md` 里，跟机器走不跟代码走；跨环境不变的部分（调用约定、参数模板）下沉到共享的技能/脚本层，别复制粘贴文件。

## 踩坑点

- **写成大杂烩**：需求、待办、日志都往里塞，token 涨了信噪比降了。它是环境事实库，不是项目文档。
- **敏感信息入库**：API key、内网拓扑写进去再同步到 git，等于泄密。写“去哪找”，不写值本身。
- **放任 Agent 整段重写**：它会顺手删掉别人维护的条目。约束为追加式修改，关键条目人工确认。
- **照抄命令帮助**：把 `--help` 输出整段贴进来没有价值，那是模型本来就知道的东西。

## 可复用建议

最小模板五个区块：**系统与包管理器 / 关键工具与路径 / 网络与代理 / 权限与禁区 / 已知坑**。两条固定指令即可跑起来：

- 初始化：“自检环境，生成 TOOLS.md 初稿，每条含事实、依据、日期。”
- 回写：“本次根因是 X，若属环境事实，追加一行。”

## 总结

`TOOLS.md` 的价值不在文件本身，而在把“环境会变、Agent 的认知需要喂养”变成流程：**初始化生成、踩坑回写、定期清理**。三步形成闭环，Agent 在你这台机器上的表现会从“大概率对”变成“稳定对”。
