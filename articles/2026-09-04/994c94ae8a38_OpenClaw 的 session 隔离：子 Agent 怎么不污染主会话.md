## 背景

OpenClaw 里每个通道对应一个主会话，上下文以 JSONL 追加式落盘，对话、工具调用、中间输出都会进入主会话的上下文窗口。日常使用没问题，但一旦让主 Agent 干“脏活”——批量抓网页、跑长脚本、逐条清洗几十个文件——大量原始输出会迅速吃掉 token 预算：自动压缩（compaction）频繁触发，早期指令被稀释，响应质量肉眼可见地下滑。

## 问题：主会话是怎么被污染的

典型症状：跑完一批任务后主会话开始“忘事”，不再遵守系统提示里的约定；compaction 后的 summaries 越滚越长；上下文里塞满了只值一次的抓取日志。根因只有一个——所有中间过程都发生在主会话里。

## 做法：让子 Agent 承接过程

1. **派生而非自己干。** 用 `sessions_spawn` 生成子 Agent，任务描述必须自包含：目标、输入路径、约束、输出格式、完成判据。子 Agent 拿到的是全新上下文，只有这段描述，不带主会话历史。
2. **过程留在子会话。** 子 Agent 在自己的 session 里自由调工具、产生中间输出，这些内容只写进子 session 的 JSONL，不回流主会话。
3. **只回收结论。** 子 Agent 结束时返回最终 summary。主会话上下文新增的是几十到几百 token 的结果，而不是几千 token 的过程。
4. **并行拆分。** 相互独立的子任务拆成多个 spawn 并发跑，主会话同时还能正常响应别的消息。
5. **收尾清理。** 子 session 用完即弃；定期用 `openclaw sessions` 查看占用，长期跑的实例顺手清理陈旧 session。

一句话原则：**主会话只做调度与决策，子会话负责执行与探索。**

## 踩坑点

- **任务描述不完整。** 子 Agent 看不到主会话历史，“继续刚才那个”对它毫无意义。spawn 时把路径、约束、样例写全，宁多勿少。
- **返回值不收敛。** 子 Agent 把全过程粘回主会话，隔离就白做了。任务里要明确“只返回结论，不超过一段/N 行”。
- **子会话也会爆。** 隔离不等于无限上下文。单子任务过大时再往下拆一层，或让它把产物落盘、只汇报文件路径。
- **并发资源冲突。** 多个子 Agent 同时写同一文件或调同一外部接口会互相踩，派发前先划清资源边界。
- **别把 spawn 当 reset。** `/reset` 是丢掉主会话历史重来，`sessions_spawn` 是保留主会话、把脏活外包，两者语义完全不同，用错代价不小。

## 可复用建议

- 建立条件反射：预计工具调用超过三五轮、会产出大量原始数据、任务可独立交付——就 spawn。
- 固化五段式任务模板（目标/输入/约束/输出格式/完成判据），存成 snippet 反复复用。
- 定期给主会话做体检：compaction 变频繁、summaries 变长，多半是脏活漏回了主会话。
- 长任务让子 Agent 把产物写进文件，主会话只拿路径和结论，顺带获得可复现性。

## 总结

session 隔离的本质是把“过程”和“结论”分开：过程留在子会话，可丢弃；结论回到主会话，可决策。主会话轻了，上下文预算才真正花在与用户对话和关键判断上。
