# 背景

用 OpenClaw 搭定时任务做社区内容发布，是很常见的玩法：每周整理 issue 摘要、同步 changelog、把新文档推到论坛。跑通不难——cron 触发 agent，agent 通过 MCP 工具取数据、组稿、调论坛 API 发出去。难的是发出去之后像什么。

我们一个摘要机器人上线两周就被群友"看穿"了：每天 9:00:00 整准时发帖，格式一字不差，服务重启后还一次性补发了七条。内容本身没问题，但观感像刷屏机器，互动率一路走低，最后有人开始手动折叠它。

# 问题

机械感来自几个具体行为，而不是"它是 AI"这件事本身：

- 固定时间点触发，秒级精确，大家能拿它对表；
- 模板完全一致，只有变量在换；
- 队列积压后集中补发，短时间刷屏；
- 多渠道同步发一模一样的内容；
- 回复延迟恒定，永远比人快。

先说清楚：目标不是把机器人伪装成人。发帖带自动化标识、出问题找得到人，反而降低社区摩擦。要解决的是行为模式上的"机器味"——本质是节奏和克制。

# 做法

我们最后收敛成一个发帖节流器（Posting Governor），agent 每次想发帖都要过它：

1. **队列化 + 限流**。所有发帖请求先进 SQLite 队列，令牌桶限流：全局每天最多 5 帖，单渠道每天 2 帖，两次发帖最小间隔 40 分钟。
2. **时间抖动**。计划时间 ±30 分钟随机偏移，避开整点；设安静时段（22:30–8:30 不发），按目标读者的时区算，不按服务器算。
3. **去重与聚合**。精确 hash 之外再做 embedding 相似度检查，阈值 0.85；相似内容合并进下一次摘要——聚合一条，永远好过碎片五条。
4. **质量门槛**。发布前跑一遍自查：信息量够不够、是否与近期帖子重复、标题是否套话。不过关的降级为草稿，不硬发。
5. **人在环**。公告、带观点的总结这类敏感内容推到我的 IM 等确认，👍 之后再发；日常摘要走全自动。
6. **反馈回路**。记录每帖互动数据，连续几期零互动的栏目自动停更并通知我，而不是继续产出没人看的东西。

# 踩坑点

- cron 写 `0 9 * * *` 这种，是所有问题的起点。
- 服务重启后队列直接回放，两分钟补发十条。补发必须重新走限流，过期内容宁可丢弃。
- API 返回 429 时无脑重试变成重试风暴，务必指数退避 + 死信队列。
- 每次运行重新采样语气，导致"人格分裂"。措辞可以变，人设和格式骨架要稳定。
- 开头一句"早上好"，但受众时区是凌晨两点——时区永远按读者算。
- 去重只做精确 hash，别人改写过的重复内容照样漏过去。

# 可复用建议

把节流器做成独立模块，别散在 prompt 里：队列、限流、安静时段、去重、审批全部配置化，日志记录每次"发/不发"的决策原因。换渠道、换内容源时只改配置。OpenClaw 侧的分工建议是：cron 只负责触发，agent 负责组稿，节流和发布收口在一个插件里——边界清楚，出问题好排查。

# 总结

自动发帖的"不像机器人"，拆开看是四件事：发得慢、发得少、像有编辑在把关、内容值得看。伪装身份是歧路，克制和透明才是自动化能长期留在社区里的方式。机器人最好的状态，是像个话不多但每句有用的同事。
