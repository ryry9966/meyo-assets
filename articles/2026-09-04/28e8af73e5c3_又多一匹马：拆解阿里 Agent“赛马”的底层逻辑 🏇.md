最近 36kr 报道，阿里在 Agent 方向上又多了一支内部团队入局，媒体戏称“又多了一个赛马”。加上此前的夸克、通义、钉钉 AI、淘宝的 AI 导购助手，阿里内部同时奔跑在 Agent 赛道上的“马”，已经能凑一场小型比赛。问题来了：为什么大厂面对新技术浪潮，第一反应往往不是集中兵力打歼灭战，而是先多养几匹马？这篇文章把“赛马机制”这门老手艺，放进 Agent 这个新赛道里拆一拆。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/627fa03074f4ba69.png)

## 赛马机制：大厂用了十几年的老手艺

所谓赛马机制，就是同一个方向上允许两三个团队独立立项：目标相似、资源相近、互不通气，在一个周期内比拼数据，赢家拿走追加资源，输家合并或关停。

几个经典案例：

- 2010 年前后，腾讯内部有三个团队同时做移动端 IM，最终广州邮箱团队跑出了微信，另外两条赛道自然终止；
- 阿里的钉钉，正是“来往”失利后那支团队换赛道跑出来的产品；
- 夸克由 UC 团队孵化，如今被推到 AI 助手的一线。

本质上，赛马是用组织冗余对冲方向的不确定性。技术路线没有收敛之前，“押注单点”失败的代价，远高于“重复投入”。这是被微信、钉钉反复验证过的方法论，不是拍脑袋的浪费。

## Agent 到底是什么：从“回答问题”到“完成任务”

不少人对 Agent 的印象还停留在聊天机器人，这里补一层技术视角。一个完整的 Agent 通常有三层结构：

- **大脑**：大模型负责规划与推理，把“帮我订下周三的机票”拆成查航班、比价格、填乘机人、支付确认等多步操作；
- **工具**：通过 function calling、MCP 这类标准协议，调用搜索、浏览器、代码执行器等外部能力；
- **记忆**：跨会话保存用户偏好与任务状态，否则每次对话都从零开始。

方法论上，2022 年论文提出的 ReAct 范式（Reason + Act）至今仍是主流骨架：模型想一步、执行一步、观察结果再调整。它和聊天机器人的本质区别在于交付物——ChatBot 交付“一段话”，Agent 交付“一个结果”：修好的 bug、生成的报表、订到的会议室。

Agent 在 2024~2025 年集中爆发，是三个条件叠加的结果：模型推理能力跨过可用阈值、工具接入协议标准化、上下文窗口变长。三者凑齐，多步任务的成功率才从“玩具”进入“可用”区间。这也是大厂现在突然集体加码的底层原因——窗口期到了。

## 为什么 Agent 值得多养几匹马

1. **产品形态没收敛**。“一个超级助手搞定一切”和“每个场景一个专属 Agent”，两种假设都有强团队押注，现在下结论为时过早；
2. **数据与场景强耦合**。电商、办公、搜索的数据闭环互不相同，隔着一堵部门墙，各场景团队自建反而是效率更高的解；
3. **模型能力每月都在变**。今天跑不通的场景，半年后可能就通了。多匹马等于保留多个“期权”，行权与否看模型能力的进度条；
4. **组织激励**。给核心团队一个独立战场和 owner 身份，比在成熟业务里“打杂”更能留住人。

再算一笔期望值账：对头部大厂，多养一支五六十人的团队，一年成本在数千万美元量级；而 Agent 若真成为下一代流量入口，错过的代价以百亿美元计。这笔账在期望值上是划算的——前提是公司有资源冗余，且赛马规则事先写清楚。对阿里来说还有一层：Qwen 开源生态提供了模型底盘，Agent 是模型能力兑现的出口，赛马赛的是“谁把底盘用好”。

## 赛马不是免费的：三笔隐性成本

1. **重复造轮子**。算力、评测基准、基础组件各建一套，内部冗余不小；
2. **品牌与用户认知分裂**。Google 十年间养了 Hangouts、Allo、Duo、Chat 一堆通信产品，最后多数关停，用户认知被反复消耗；放到 Agent 时代，“到底该打开哪个 App”会是同类问题；
3. **组织震荡**。赛马结束往往伴随合并、调岗甚至裁撤，这部分成本在立项时最容易被低估。

所以赛马是“高赔率 + 高成本”的组合：适合资源冗余、输得起的巨头；多数中小公司直接模仿，大概率先被成本拖死。



## 判断一场 Agent 赛马的五个胜负手

看热闹之外，给一套可复用的判断框架：

1. **底座模型**：有没有自研或深度定制的模型能力，这是马力上限；
2. **数据闭环**：任务执行数据能否回流训练，形成“越用越强”的飞轮；
3. **分发入口**：装机量与高频场景。Agent 是多步长任务，天然依赖高频入口摊薄唤醒成本；
4. **工程质量**：端到端成功率、时延、单次成本。Agent 是多步串联，每步 95% 的成功率连乘十步只剩约 60%——工程细节直接决定生死；
5. **组织耐心**：Agent 的迭代周期以年计，用季度 OKR 考核它会死得很快。

五要素凑齐几件，基本就能预判哪匹马能跑完全程。

## 收尾：三条冷思考

1. **给从业者**：判断一家公司 AI 业务的成色，别看发布会 Demo，看它是否同时握有模型、数据、入口三要素——缺一件，多半只是借势讲故事；
2. **给开发者与创业者**：别和大厂在同一条赛道赛马，去找大厂“懒得赛”的生态位——垂直行业的流程知识、私有系统集成、评测与安全工具层。大厂赛马越激烈，生态缝隙反而越多；
3. **给普通用户**：把 Agent 当“能干的实习生”，而不是“全自动员工”。付款、发送、删除这类关键操作保留人工确认，权限按最小化原则授予。

说到底，赛马赛的不是马，是组织敢不敢为不确定性付费。这一点上，Agent 时代和二十年前没什么不同——只是这匹马跑得更快，烧的油更贵。
