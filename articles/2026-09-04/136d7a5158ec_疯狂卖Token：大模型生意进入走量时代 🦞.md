最近 36 氪的一篇报道把两家大模型公司的同一个动作顶上了热议：智谱和 MiniMax 在“疯狂卖 Token”——API 价格一降再降，编程订阅月费低到一杯奶茶钱，开发者激励层层加码，token 出货量成倍往上翻。表面看是促销，实际上是一次商业模式的集体换挡：大模型公司正在从“秀模型”转向“拼走量”。这篇文章把这门生意的账本摊开，讲清楚三件事：Token 是什么生意、为什么要疯狂卖、这仗到底怎么打赢。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/a1411e7ee4a57028.png)

## 一、先看懂账本：Token 是一门什么生意

- Token 是大模型处理文本的最小单位。1 个英文单词约等于 0.75 个 token，1 个汉字大致对应 0.6~1.5 个 token，具体取决于分词器。
- 计费方式是“按量付费”：以百万 token 为单位报价，输入和输出分开计价，输出通常比输入贵 2~4 倍——因为生成是逐 token 解码，算力开销更大。
- 举个栗子 🌰：让模型通读一份 2 万字的合同并输出摘要，输入约 3 万 token、输出约 500 token。按“输入 2 元/百万 token、输出 8 元/百万 token”的主流价位，这一单成本不到一毛钱。
- 结论：单价极低、弹性极强，收入 = 调用量 × 单价。这不是传统软件生意，而是“智能时代的云生意”——客户像用水用电一样按度数付费，用多少算多少。

## 二、为什么要“疯狂”卖：三个发动机

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/9f84934d06cc523d.png)

**1. Agent 时代，token 消耗是乘法不是加法**

- 传统聊天机器人：一问一答，几千 token 就收工。
- Agent 干活：一个任务要循环几十上百次调用，每一步都要把完整上下文、工具返回结果、思考链重新喂给模型。一个复杂编程任务烧掉几十万 token 很正常。
- 推理模型（thinking 类模型）还会把“思考过程”本身也输出成 token，等于往火里再添一把柴。
- 这解释了 API 需求为何突然爆发：不是更多人开始聊天了，而是程序开始 7×24 小时不睡觉地烧 token。

**2. 上市故事需要“规模化收入”**

- 智谱、MiniMax 先后启动上市进程，招股书里最硬的叙事就是收入曲线。API 收入可审计、可预测，是典型的经常性收入，比 to C 订阅更有说服力。
- 两家披露的 token 处理量都在以数十倍的年增速扩张——这正是“走量”战略的直接证据。而且训练大模型要提前砸重金买算力，token 收入是少数能边花边回的血。

**3. 开发者生态的卡位战**

- 同代模型能力差距已经不大，开发者选谁，看的是价格、延迟、上下文长度、稳定性和工具链。
- 低价 + 开源是拉新钩子。一旦模型跑进业务流程，微调、prompt、评测体系这些迁移成本会形成真实粘性——先上车，后锁座。

## 三、低价倾销的账：毛利是赛跑出来的

- **成本端**：推理成本 = GPU 折旧 + 电力 + 机房。KV cache、前缀缓存、量化、批处理这些优化让单位 token 成本持续下降，不少厂商已把“缓存命中”的价格打到原价一折以下。
- **价格端**：2024 年以来，同能力水平的调用价格降了 1~2 个数量级，输入价格被打到个位数人民币每百万 token。
- **打法**：削峰填谷是云计算时代的老手艺——夜间半价、批量任务折扣，本质是提高 GPU 利用率，反正是闲时算力，卖一块是一块。订阅制打包则是另一路：把 token 做成月费流量包（比如每月二十元档的编程套餐），预付费锁频次，现金流也更好看。
- 所以真正的问题是：**成本下降速度能不能跑赢降价速度**。跑赢了，毛利随规模改善；跑不赢，就是拿融资补贴市场。

## 四、终局判断：API 会商品化，护城河在别处

- 纯文本 API 大概率走云计算的老路：同质化、价格战、利润向头部集中。
- 真正拉开差距的是“token 消耗密度”高的场景：视频生成、agent 平台、行业私有化部署。谁的应用生态能持续烧 token，谁的收入质量就高——MiniMax 自家的视频与社交类应用，本身就是吞 token 的大户，等于自产自销。
- 换句话说，卖 token 只是起点，终点是围绕 token 消耗建起一整条价值链。

## 五、给开发者和企业的三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/c4e20d175d067549.png)

1. **别只看单价，算“任务总成本”**：上下文长度、重试率、成功率都影响真实成本。便宜但错三次，不如贵一点但一次对，尤其在生产环境里。
2. **永远留一条开源备胎**：主模型用商业 API，同时跑通一个开源模型的兜底方案。模型下线、限流、涨价都是真实发生过的风险，架构上别做单点依赖。
3. **盯住“单位智能成本”，而不是绝对价格**：长期趋势是每一块钱能买到的智能在指数上涨。更聪明的做法是让产品架构随成本下降而升级能力，而不是按今天的价格锁死明年的预算。

“疯狂卖 Token”既不是赔本赚吆喝，也不是稳赚不赔的买卖，它是行业从“秀肌肉”进入“拼运营”的信号。接下来比的不是谁的模型跑分高，而是谁的算力利用率高、谁的 token 烧得值。
