36 氪一篇报道把“阿里内部又多了一支 Agent 团队”送上热议：在夸克、千问 App、钉钉、淘宝 AI 之后，据称又有一支独立小队入场做通用 Agent。同一方向反复下注、多队并行、赢家通吃——这套被互联网大厂用了十几年的“赛马机制”，为什么在 Agent 时代又被拿出来？它是组织智慧，还是资源浪费？这篇拆给你看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/ac696f779962dc36.png)

## 赛马机制：大厂内部的老配方

所谓赛马，就是同一个方向组建两支以上独立团队并行开发，数据说话，资源向赢家倾斜，输家解散或转岗。几个经典案例：

1. **微信**：当年腾讯内部三支团队同时做移动 IM，最终广州邮箱团队胜出，其余项目关停，这是赛马最出圈的教科书案例；
2. **钉钉**：前身是做“来往”的团队。来往对线微信失利后，整个团队带着“切工作场景”的新判断二次起跑，才有了后来的钉钉——赛马的另一面，是允许失败后的再出发；
3. **AI 时代的延续**：阿里 to C 侧，夸克（智能信息事业群）与通义系列长期双轨运行；据 36 氪等媒体报道，如今 Agent 方向上又有新团队进场，形成多马并行。

它为什么有效？核心是**不确定性下的期权思维**：当技术路线看不清时，单点下注的失败概率太高，并行下注相当于买一组看涨期权，总有一个能兑现。同时，赛马把“大公司没有创业感”的顽疾，改造成了“内部创业”——团队拿到的是接近创业公司的激励和节奏。

## 为什么 Agent 值得再赛一场

先把概念说清楚。Agent = 以大模型为大脑，加上任务规划（Planning）、工具调用（Tool Use）、外部记忆（Memory）和执行环境（浏览器、电脑、代码沙箱），把“陪聊”升级为“替你把活干完”。评判标准不是话术多流畅，而是任务完成率。

行业时间线也解释了大厂为什么焦虑：

1. 2023 年：AutoGPT 火过一轮，受限于模型能力和成本，昙花一现；
2. 2024 年 10 月：Anthropic 推出 computer use，让模型直接操作电脑；
3. 2025 年 1 月：OpenAI 发布 Operator；3 月，Manus 现象级出圈，通用 Agent 第一次被大众看见；
4. 2025 年：Claude Code、Codex 等编码 Agent 成为各家增速最快的营收线之一；Gartner 曾预测，到 2028 年约 33% 的企业软件将内置 Agentic AI，而 2024 年这个比例不足 1%。

更关键的是**入口逻辑**：如果未来大量需求（检索、比价、订票、下单）都经由 Agent 完成，今天的搜索框和货架入口就会被重构。吴泳铭在云栖大会上把“自主行动”（Agentic）描述为通向 AGI 的关键阶段——对阿里来说，Agent 不是做一个产品的问题，而是入口与生态的问题。

而形态至今没有收敛：超级框、对话式助手、嵌入式助手、垂直 Agent，没人知道哪种形态能长成平台。收敛之前多养几匹马，是理性选择，不是冲动。

## 阿里这匹“新马”跑在哪条道

盘点一下现有阵容，你会发现各家站位清晰：

1. **夸克**：2025 年升级为“AI 超级框”，主打一站式入口，官方口径月活过亿，强项在学习、健康、资料处理等高频场景；
2. **千问 App**：2025 年 11 月公测，基于 Qwen3-Max，定位个人 AI 助手，上线首日即冲上 App Store 免费榜头部，与千问开源生态、阿里云百炼形成“模型—云—应用”闭环；
3. **钉钉**：工作场景的 Agent，AI 助理、数字员工，把表格、审批、会议做场景化封装，走“组织协作”这条护城河；
4. **淘天**：电商侧的导购与交易 Agent，护城河是商品和交易数据。

据 36 氪报道，新团队方向更接近通用执行型 Agent。加上它之后，集团等于在“超级入口（夸克）—个人助手（千问）—工作场景（钉钉）—交易场景（淘宝）—通用执行（新马）”五个点位同时布兵。

组织结构上这是典型的**双层设计**：底层统一（阿里云提供模型与算力），应用层赛马（各事业群和独立小队各打各的仗）。在能力尚未收敛的大模型行业，这种“底座统一、应用分散”的结构，本质上是用组织冗余去对冲技术不确定性。

## 赛马的经济学：什么时候灵，什么时候翻车

赛马不是万能药，成立有条件，翻车有姿势。

**灵的条件：**

1. 技术曲线陡峭、产品形态未收敛——今天的 Agent 完全符合；
2. 各队真独立：独立代码、独立数据闭环、独立考核，避免“伪赛马”变相成为同一条流水线；
3. 有清晰的裁判信号：留存、任务完成率、成本曲线，用数据收敛，而不是用高层口味收敛；
4. 敢关停：收敛期一到就集中资源，把“赛马奖金”一次性兑现给赢家。

**翻车的姿势：**

1. 赛马变内耗：抢接口、抢数据、互相砌墙，中台资产被绕开，重复造轮子；
2. 只赛不收：永远在实验、没有判决节点，资源摊薄成撒胡椒面；
3. 误杀潜力股：裁判指标如果只看短期 DAU，会系统性错杀慢热型产品——很多好产品是“低开高走”的。

他山之石：谷歌在 Bard 时代同样多支对话团队并行，最终把 Google Brain 与 DeepMind 合并、收敛到 Gemini 单一路线。可见**收敛动作比开赛动作更难，也更关键**。

## 写在最后：三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/6e3d73380b0d74c2.png)

1. **给开发者/创业者**：不要把产品绑死在某一家大厂的某一款 Agent 入口上——API 政策、团队归属都可能在赛马结束后调整。优先押注协议层（如 MCP 这类标准协议）和垂直行业工作流，慎入大厂必争的“通用超级入口”赛道。
2. **给求职者/选团队的人**：Agent 团队正处高投入窗口，机会多但波动大，赛马输掉的组可能整体调整。判断一个团队值不值得去，看三件事：有没有拿到旗舰模型的深度权限、有没有真实用户的数据闭环、集团有没有明确的收敛时间表。
3. **给普通用户**：评估一个 Agent 产品好不好用，别看演示视频，看三个指标——真实任务完成率、可调用的工具与生态广度、跨场景记忆是否延续。演示惊艳和日用可靠之间，隔着一整个“长尾场景”的距离。

最后一句冷思考：赛马是手段，不是战略。大厂真正稀缺的能力，从来不是“多开几条赛道”，而是敢在正确的时点关掉输家、全力收敛。开赛容易，收马难。
