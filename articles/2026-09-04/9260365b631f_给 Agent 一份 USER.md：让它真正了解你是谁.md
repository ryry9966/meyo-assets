## 背景

用 OpenClaw 这类常驻 Agent 一段时间后，会发现一个尴尬的事实：它记得你说过的话，却不记得"你是谁"。每次新会话，都要重新交代一遍时区、系统环境、技术栈、回复语言……项目侧我们有 AGENTS.md 解决"这个仓库怎么干活"，但用户侧一直缺一份对应物。USER.md 就是补上这块：一份随会话注入、专门描述"我"的上下文文件。

## 问题

没有 USER.md 时，Agent 的默认行为全靠猜：

- 在 NixOS 上直接建议 `apt install`；
- 半夜主动推送消息，因为它不知道你的作息；
- 所有回复和注释用英文，而你团队规范是中文注释；
- 每次都重新问一遍"你的部署方式是什么？"

这些不是模型能力问题，是上下文缺失。靠对话逐条纠正，成本高且不可持续。

## 做法

1. 在工作区根目录建 `USER.md`（OpenClaw 会在会话启动时加载 workspace 下的 markdown 文件，先确认你版本的加载路径）。
2. 按固定骨架写，控制在 60 行以内：

```markdown
# 关于我
## 环境
- 时区 UTC+8，工作日 9:00–19:00 在线，深夜勿主动推送
- 日常机 macOS + NixOS 服务器，包管理用 nix，禁用 apt/yum
## 技术栈
- 主语言 Python/Go；数据库 Postgres；部署用 Docker Compose，别给 K8s 方案
## 沟通
- 默认中文回复，代码与注释用英文
- 先结论后推理；不确定就明说不确定
## 红线
- 未经确认不执行 sudo / rm -rf / git push --force
- 不代发任何对外消息
## 当前状态（2025-06 更新）
- 在做 X 项目迁移，Y 已暂停
```

3. 分层：全局偏好放 USER.md，仓库规则放各项目的 AGENTS.md，冲突时以项目文件为准。
4. 纳入 dotfiles 仓库做版本管理，多机同步。

## 踩坑点

- **写成长篇自传**。它每个会话都占 token，超过一屏就该砍，宁缺毋滥。
- **信息过期比没有更糟**。"当前在做 X"过时后，Agent 会拿着旧结论帮你做决策。易变内容放末尾、标日期、每月清理。
- **形容词无效**。"专业一点""简洁一些"模型理解不了，要写可执行规则并给示例。
- **放敏感信息**。USER.md 会随 prompt 发给模型服务端，API key、真实住址别写。
- **职责混淆**。Agent 该怎么干活是 AGENTS.md 的事，USER.md 只回答"我是谁"。

## 可复用建议

- 让 Agent 参与维护：隔段时间说一句"根据最近对话，总结你还不知道但应该知道的用户偏好，输出 USER.md 追加草稿"，人工审后再合并。
- 写完做一次验证：直接问"基于你的上下文，描述一下我的工作环境和偏好"，看哪些条目真正生效。
- 新项目初始化时，把 USER.md 里与该仓库相关的条目"下沉"到 AGENTS.md，避免重复注入。

## 总结

USER.md 本质是一份持久化的 prompt 资产：成本低（一次 60 行），杠杆高（每次会话省掉重复交代）。把它当代码维护——有版本、有 review、定期重构——Agent 对你的理解才能从"每次重新认识"变成"持续积累"。
