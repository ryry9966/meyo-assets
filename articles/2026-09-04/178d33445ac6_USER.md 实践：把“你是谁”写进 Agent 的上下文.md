## 背景

用 Agent 一段时间后会有个共同体感：模型能力不是瓶颈，上下文断层才是。项目层面有 CLAUDE.md / AGENTS.md 这类文件描述仓库规范，但“操作者是谁”这件事通常没人写——于是每个新会话，Agent 都要重新问一遍：用 pnpm 还是 npm？回复用中文还是英文？能不能直接 push？

在 OpenClaw 的持久化记忆里，USER.md 就是补这一块的位置：它不描述项目，只描述你。相当于给 Agent 一份用户级 README。

## 问题

没有 USER.md 时的典型症状：

- 同样的偏好反复声明，隔一个会话就忘；
- 定时任务、MCP 工具调用因为不知道你的时区和工作习惯而出错，比如深夜给你推一堆通知；
- 换机器、开新项目后 Agent 的“人设”归零，自动化链路全部要重调。

本质上这是“用户级配置缺省”，和服务器上没有 `.bashrc` 是同一类问题。

## 做法

**1. 定位置。** 全局放一份（你配置的全局记忆路径即可），跨项目生效；项目差异放在项目级文件里。优先级要明确：项目级覆盖全局级。

**2. 控篇幅。** 它每次会话都会进上下文，建议 30 行以内、几百 token 封顶。写事实，不写口号：

```markdown
# USER.md
## 环境
- macOS + zsh；包管理 pnpm，禁用 npm
## 偏好
- 中文回复；结论先行，细节后置
- 代码要有边界检查，测试用 vitest
## 红线
- 不自动 commit/push；.env 与 migrations 目录禁止改动
## 当前
- 主项目：网关重构（至 5 月底）
```

**3. 迭代维护。** 规则很简单：Agent 把同一个问题问了两次，就把答案写进去。可以让 Agent 自己执行“把这条偏好追加到 USER.md”，但 diff 必须人工过目。

## 踩坑点

- **写成简历。** “追求极致、热爱技术”这类形容词 Agent 无法执行，要写成可操作的事实。
- **越写越长。** 上下文被稀释，重要条目反而失焦。超预算就把低频内容拆到按需读取的二级文件。
- **放敏感信息。** 密钥、私有邮箱别写。这个文件可能被同步、被插件读取、被 MCP 工具带出去。
- **信息过期。** 三个月前的“当前主项目”会让自动化悄悄跑错方向。给条目加期限，定期清理。
- **放临时状态。** “正在修 bug”属于会话或任务清单，不属于身份文件。

## 可复用建议

- 把 USER.md 当代码管：放进 dotfiles 仓库，diff 就是你的偏好变更记录。
- 排障顺序固定下来：Agent 行为不符预期时，先查“这条偏好在不在 USER.md”，再怀疑模型。
- 团队场景可套同样结构做一份 ROLE.md，和仓库的 AGENTS.md 形成“人 / 角色 / 项目”三层。

## 总结

USER.md 不是什么高级技巧，只是把“你希望 Agent 默认知道的事”从每次会话的口头输入，固化成一个受版本管理、有篇幅预算的配置文件。30 行以内、只写事实、定期修剪——做到这三点，Agent 长期行为的稳定性会有很可观的改善。
