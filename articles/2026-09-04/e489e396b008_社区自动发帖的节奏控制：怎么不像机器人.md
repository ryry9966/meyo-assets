## 背景

用 OpenClaw 挂上 MCP 发帖工具后，很多人的第一件事是把「每周整理一次精华帖」做成定时任务。跑起来很容易，难的是跑两周之后——帖子格式雷同、发布时间整点整分、响应快得不像人，一眼就能被认出是机器发的。被识别成机器人不算最糟，最糟的是被当成低质量刷屏，直接进了版规黑名单。

## 问题：固定节奏本身就是特征

机器人感主要来自三个可统计的特征：

1. **时间特征**：固定 cron，误差在秒级，发布时间的直方图上是一根根针。
2. **频率特征**：失败重试或队列堆积之后爆发式连发。
3. **内容特征**：模板完全一致，连标点习惯都一样。

## 做法：把节奏当成一个调度问题

核心思路是别用 cron 触发，而是用一个带约束的调度器。

**第一步，抖动。** 不要固定间隔，用基准值加随机偏移：

```yaml
schedule:
  base_interval: 6h
  jitter_ratio: 0.4   # 实际间隔落在 3.6h ~ 8.4h
  min_gap: 2h         # 两次发帖的硬下限
```

**第二步，静默时段。** 按目标社区读者的时区设 quiet hours，比如 01:00–08:00 不发。注意服务器多半是 UTC，时区搞错是这里最常见的 bug。

**第三步，配额。** 每天设 `max_per_day`，每个频道单独计数，用令牌桶而不是简单计数器，避免「零点配额清零后连发」。

**第四步，失败退避。** 重试必须带指数退避加随机化，且重试同样要过抖动和静默时段检查，否则一次网络抖动会变成凌晨三点的三连发。

**第五步，内容变化。** 准备 3–5 套模板轮换，开头句、列表风格做差异；更本质的做法是让 agent 每次生成正文时换结构，而不是换壳。

## 踩坑点

- **独立随机 ≠ 不扎堆。** 每条消息独立均匀随机，长期看仍会泊松式扎堆。更稳的做法是先按天生成发布时刻表，再校验 `min_gap`，不满足就重排。
- **重启重复发。** 队列要落盘，发帖带幂等 key（内容 hash + 目标频道），OpenClaw 重启后先对账再发。
- **模板切换造成「断代」。** 排队中的帖子用旧模板、新帖用新模板，两批连着发反而更可疑。改模板时清空或重排队列。
- **抖过头。** 凌晨 3:47 发帖比整点更假。抖动范围应落在「人可能在线」的区间内。

## 可复用建议

- **调度与内容分离**：调度器只管时间和频率，agent 只管写，中间用持久化队列解耦，两边可以独立改。
- **保留发帖台账**：记录时间、频道、模板版本、触发原因，每周人工抽查 10%，比自己感觉靠谱。
- **参数全部进配置**：不同社区的活跃时段不同，节奏参数应按社区分别调，不要写死在代码里。
- **先 dry-run 一周**：只记录「将要发什么、什么时候发」而不发真帖，画出时间直方图，看着像人再上线。

## 总结

不像机器人的关键不是把随机数加得更大，而是让发布行为服从真实用户的分布：有人类活跃时段、有最小间隔、有失败退避、有内容差异。把节奏控制当成调度问题来做，配上台账和定期抽查，自动发帖才能长期留在社区里，而不是活三天被封。
