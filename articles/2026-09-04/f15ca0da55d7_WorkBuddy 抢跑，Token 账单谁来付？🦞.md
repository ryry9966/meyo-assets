最近 36kr 的一条热议把一个藏在水下的问题顶出了水面：以 WorkBuddy 为代表的 AI 工作助手开始真正进办公室干活了，而干活的代价，是一张越来越厚的 Token 账单。软件按席位收费大家很熟，但 AI 按"思考量"收费，这笔钱该记在谁的预算上？这篇不站队，把这件事的技术底座和商业逻辑拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/0eebdfde2c04e545.png)

## 先补课：Token 是什么，为什么按它收钱

- **Token 是大模型处理文本的最小单位**，一个汉字通常对应 1~2 个 token。模型读输入、生成输出，全部按 token 计量，这是 API 按量计费的基础。
- **定价差异巨大**：公开市场上每百万 token 从几毛钱到几十美元不等，轻量级模型便宜，带长推理链的旗舰模型贵得多。
- **成本来源是推理算力**：输入越长、输出越长、思考越深，GPU 时间越多。Agent 恰好三样全占。

关键是，Agent 把消耗放大了一个数量级：

1. 一次普通对话，来回也就几千 token；
2. 一个 Agent 任务要走"接目标 → 拆计划 → 调工具 → 读结果 → 自检 → 重试"的循环，每一步都把上下文重新喂给模型，单任务几十万 token 很常见；
3. 多 Agent 协作时，几个 Agent 互相"开会"，消耗还会再翻几倍。开发者社区的主流反馈是，Agent 类应用的单任务消耗达到普通对话的几十倍并不罕见。

所以这张账单不是厂商造出来的焦虑，它是真实的边际成本——过去被包月订阅摊平了，用户看不见而已。

## WorkBuddy 们"先行一步"，先的是什么

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/a7f42cc20733d252.png)

从这类产品的普遍打法看，"先行"先在三件事：

1. **产品形态先跑**：从"聊天框"升级为"能执行任务的工作流"，写纪要、跑数据、跟进事项。功能先行，意味着算力消耗先行。
2. **商业模式后置**：早期普遍是"订阅包月 + 算力补贴"，Token 成本由产品方垫付，先把用户规模圈进来，经典的以规模换议价权。
3. **定价权摸索**：等行业跑出"一个 AI 员工值多少钱"的共识，再切换到更精细的计费方式。

有一个工程事实在支撑这个打法：同档能力的模型，推理价格隔一两代常会下降一个数量级。厂商敢垫钱，赌的就是"今天的成本，明年是白菜价"。

## 三种付费模式：公司付、个人付，还是混合

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-04/31701d01f69b90e5.png)

账单总得有人付，目前能看到三条路径：

1. **企业统一采购（B 端）**
   - 类似今天的办公套件订阅：公司按席位付费，算力打包或按量后结；
   - 好处是管控统一、数据边界清晰、有议价空间；
   - 难点是预算科目不好放，算 IT 预算还是按部门分摊？用量波动大，财务难预估。

2. **员工自备（BYO AI）**
   - 用个人订阅干公司的活，相当于自带工具上班；
   - 好处是企业零成本试错，好用的工具自然沉淀下来；
   - 难点是数据出了公司边界，合规风险大，属于典型"影子 IT"；而且让员工自费给公司产出，本身就不太对劲。

3. **混合与转售**
   - 产品方向模型厂商批发算力，打包成"任务额度"卖给企业，溢价来自工作流编排、权限管理、审计留痕这些围绕模型的工程，而不是 token 本身。

从成本结构看，B 端统一采购大概率是终局——正如没有公司要求员工自费买企业邮箱。过渡期里，"个人订阅 + 找财务报销"会是灰色但真实存在的状态。

## 历史的镜子：工具账单不是新问题



- **移动电话**：早年商务人士自掏腰包付话费，后来话务量变成公司资产，转为企业统一采购；
- **软件授权**：从个人买软件带去公司用，到企业级授权统一管理，催生了整套企业软件采购体系；
- **云计算**：从自建服务器到按用量付费，还长出了 FINOps 这个专门管云账单的工种。

规律相当一致：当工具的成本大到无法忽略、产出又归公司所有时，账单最终会回到公司预算，并长出一套治理体系。Token 大概率走同一条路，甚至可能催生一个新岗位——专门盯 AI 用量的"算力财务"。

## 真正该计量的不是 Token，是价值

Token 是成本侧的语言，衡量不了产出。烧 50 万 token 完成一个任务，可能是浪费，也可能是省了一个人三天——取决于结果。换个视角说：对财务它是成本项，对用户它是产出率。

- **短期**：per-token / per-seat 计费为主，简单透明；
- **中期**：出现"席位 + 用量"的混合计费，形态类似手机套餐；
- **长期**：向 per-outcome（按结果付费）演进，按完成的任务量计费。前提是产品方要有能力自己吸收 token 成本的波动。

## 收尾：三条冷思考



1. **对个人**：如果干活已经离不开某个 AI 助手，别用私人订阅硬扛。推动公司走正式采购流程——既是争取报销，更是把数据合规责任放回该在的位置。
2. **对企业**：评估工具别只看订阅价，先小范围试点，测出"一个任务平均烧多少 token、换回多少工时"，再谈规模化。
3. **对观察者**：盯成本曲线，不如盯价值锚点。谁先把"AI 干完一件事"定义成可计价、可验收的标准单位，谁就拿到下一代企业软件的定价权。

Token 账单总会有人付。付钱的方式，会决定这场变革由谁主导。
