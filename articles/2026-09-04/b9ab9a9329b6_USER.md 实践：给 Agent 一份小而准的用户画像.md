## 背景

OpenClaw 的 Agent 每次会话都是“失忆”的——上下文里只有系统提示词、工具定义和你当次的输入。它不知道你主力语言是 Go 还是 Python，不知道你讨厌冗长解释，不知道你的服务器在哪个时区。这些信息要么每次重复，要么靠运气。

OpenClaw 的工作区（默认 `~/.openclaw/workspace`）里预留了几份常驻记忆文件：`AGENTS.md` 管工作规范，`SOUL.md` 管人格，而 `USER.md` 就是用户画像——每轮对话都会被注入上下文。用好它，是让 Agent 从“通用助手”变成“懂你的助手”成本最低的一步。

## 问题

不写 USER.md 的典型症状：

- 每次都要重新交代技术栈和个人偏好；
- Agent 默认输出长篇大论，你要反复说“简洁点”；
- 它给的方案不符合你的实际环境（比如你根本没用 Docker）；
- 多人共用一个网关时，它分不清是谁在说话。

## 做法

USER.md 放工作区根目录，纯 Markdown，建议控制在 60~100 行内。我目前用的结构：

```markdown
# 关于我
- 坐标上海，UTC+8，工作时间 09:00–19:00

# 技术环境
- 主力语言：Go / TypeScript，不用 Python 做服务端
- 部署：自建 K8s，无 Serverless

# 沟通偏好
- 先给结论，再给依据；不要开场白和客套
- 代码注释用中文，commit message 用英文

# 红线
- 删库、改生产配置等高危操作，必须先二次确认
```

三个要点：

1. **只写事实和稳定偏好**。“输出要克制”不如“默认 5 行以内总结，细节按需展开”，越可执行越好。
2. **让 Agent 自己维护**。对话中它识别到新偏好时，直接说“记到 USER.md”，它会用编辑工具更新并顺带修正冲突条目。
3. **纳入 git**。变更历史就是你偏好的演进记录，改坏了也能回滚。

## 踩坑点

- **写太长**。USER.md 占的是每轮固定上下文，300 行的画像会稀释指令权重，Agent 反而开始忽略细节。经验值：超过 120 行就该删了。
- **塞敏感信息**。USER.md 会进入子 Agent 和部分 MCP 工具调用的上下文，密钥、精确住址、证件号一律不写。
- **和 AGENTS.md 混淆**。“我是谁、我要什么”放 USER.md，“这个项目怎么干”放 AGENTS.md，放反了会导致换项目时画像跟着错。
- **绝对化措辞**。“绝不使用 X”会让 Agent 在确实需要 X 时死板绕路，改成“默认不用 X，除非我明确要求”。
- **内容过时**。项目迁移、偏好变化后不更新，Agent 会按旧世界行事。建议每月让 Agent 读一遍 USER.md，问你一句“哪些还成立”。

## 可复用建议

- 模板四段式：**身份与环境 / 技术栈 / 沟通偏好 / 红线**，顺序别乱，靠前内容权重更高；
- 每条一行，关键词加粗，方便模型扫描定位；
- 定期让 Agent 提议 diff：“基于最近对话，USER.md 有什么该更新的？”你只做审核；
- 多人网关场景，主用户的 USER.md 保持唯一，其他人的习惯放各自会话里，避免画像串味。

## 总结

USER.md 本质是你给 Agent 的“单一事实来源”：一份小而准的用户画像，换来的是会话免重复交代、输出风格稳定、危险操作有护栏。它不值得写长，值得写准——维护成本不超过每月十分钟，收益却贯穿每一次交互。
