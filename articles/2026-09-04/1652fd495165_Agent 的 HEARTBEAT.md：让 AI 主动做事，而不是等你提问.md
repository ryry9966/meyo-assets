## 背景

大多数人用 Agent 依然是"你问我答"：不提问，它就静默。但监控巡检、日报汇总、inbox 检查这类任务，本质是"到点该做"，不是"想起来才做"。OpenClaw 里有个很轻量的机制解决这个问题：heartbeat（心跳）。Agent 按固定间隔自动醒来，读取工作区根目录的 `HEARTBEAT.md`，按清单决定做什么；判断无事可做时回复 `HEARTBEAT_OK` 直接跳过。没有新协议、没有复杂调度，就是"一个文件 + 一个定时器"。

## 问题

没有心跳机制时的常见尴尬：

- 你让 Agent"盯一下 CI"，它只在当前对话里盯，你关掉窗口它就下班了；
- 用 cron 裸跑脚本能定时，但没有判断力——失败重试、优先级判断、写成给人看的汇报，都得自己再包一层；
- 你想让 Agent 主动提醒，又怕它每隔半小时发一条"一切正常"刷屏。

## 做法

1. 在工作区根目录（默认 `~/.openclaw/workspace/`）新建 `HEARTBEAT.md`。文件不存在或为空时，心跳直接跳过，不消耗 token。
2. 用自然语言写清单，每条尽量可判定：

```markdown
# 心跳清单
- CI 失败才报告，工作时间(9:00–19:00)内投递
- 磁盘占用超过 85% 才提醒
- 无事可做时，直接回复 HEARTBEAT_OK
```

3. 配置间隔（`~/.openclaw/openclaw.json`）：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": { "every": "30m" }
    }
  }
}
```

最小粒度 30 分钟，设 0 关闭，也可按 agent 单独覆盖。

4. 关键约定：Agent 判断无事时回复 `HEARTBEAT_OK`，框架就不向渠道推送，只消耗少量 token。清单里显式鼓励这个行为，长期省下大量成本。
5. 想让主动汇报进群，给对应 agent 配置心跳的目标渠道，或在清单里写明"异常时投递到 #ops"。

## 踩坑点

- **间隔太短**：15 分钟一轮全量巡检，一天几十次调用，账单先于效果爆炸。高频任务优先在清单里写"仅条件满足才动作"。
- **清单含糊**："帮我看看有什么新东西"等于让 agent 自由发挥。每条任务写清触发条件、动作、静默条件。
- **忘了静默时段**：凌晨三点收到"一切正常"是经典事故，务必写明 quiet hours。
- **心跳是独立会话**：长任务会占住心跳轮次，重活别塞进去，交给定时任务或手动触发。
- **权限过大**：心跳是无人值守执行，清单里避免直接写删除、部署类高危操作。先只读、后报告、人确认再执行。

## 可复用建议

- 按三级结构写条目：**触发条件 / 动作 / 静默规则**，缺一项就是未来的误报源。
- "无事不汇报"永远放第一条。
- 数据源尽量接 MCP 工具（代码仓库、文件系统、监控 API），让心跳读数据而不是翻聊天记录。
- 每周翻一次心跳日志，删掉重复触发但没价值的条目——清单是活的，不是写完就完。

## 总结

HEARTBEAT.md 的价值不在功能多强，而在它把"主动行为"的配置成本压到了一个 markdown 文件。不需要学新框架，只需要想清楚"我每天希望它替我看什么"。从一条"CI 失败才喊我"开始，跑一周，再决定要不要加第二条——这是最务实的落地节奏。
