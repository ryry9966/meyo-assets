36kr 最近一条热搜把腾讯和 AI 行业的格局变化摆上了台面——"腾讯放'手'，AI 没有大哥"。核心信息不复杂：腾讯在 AI 业务上正在做组织架构和投资策略上的"减法"，从集中管控转向更加分权的模式。与此同时，整个 AI 赛道也进入了一个没有绝对主导者的新阶段。这篇就来拆一拆：到底什么是"放手"，为什么"没有大哥"，以及这对普通开发者和用户意味着什么。



## 一、"放手"到底在放什么

"放手"不是摆烂，是战略性地松开方向盘。具体拆三层：

**1. 组织层面：从"一个大脑"到"多个小脑"**

腾讯过去在 AI 上的打法偏保守——习惯把核心能力收拢在 CSIG（云与智慧产业事业群）里统一指挥。但 2024 年以来的调整趋势很明显：

- 内部多个团队被赋予更大的模型研发和调用自主权
- 微信、QQ 浏览器、企业微信等产品线各自接入和调优模型的权限扩大
- 不再强求"一个模型打天下"，允许各业务线根据场景选型——哪怕是调用竞品的 API，只要 ROI 合理也开绿灯

**2. 投资层面：从"控股式"到"财务式"**

这是更关键的变化。过去腾讯投 AI 公司，习惯要董事席位、要战略协同、要并表话语权。现在的趋势是：

- 对被投 AI 企业（智谱AI、MiniMax、月之暗面等）减少直接干预
- 更倾向于"给钱不给人"，让创始团队自主决策技术路线
- 接受被投企业同时接受其他巨头投资，不再强求独家排他

用工程师的话说：从"紧耦合"变成了"松耦合接口"，容忍双工甚至多工并行。

**3. 产品层面：从"统一入口"到"百花齐放"**

- 不再把所有 AI 能力收口在单一产品里
- 允许各业务线自建 AI 功能模块，甚至内部赛马
- 混元大模型不再被定位为"唯一旗舰"，而是变成"基础底座 + 多个场景微调版"

这种"放手"的本质是：承认 AI 不是一个靠集中力量就能赢的赛道，过度控制反而会拖慢决策链条。

## 二、AI 赛道为什么"没有大哥"

"没有大哥"不是情绪化判断，是结构性结论。原因至少有四层：

**1. 技术层：没有单一架构形成垄断**

- Transformer 不是终点。MoE（混合专家模型）、SSM（状态空间模型如 Mamba）、Diffusion 等架构各有优势场景
- 没有任何一家公司能把所有技术路线同时走通——资源再厚也扛不住"全树展开"
- 模型能力的天花板远未触及，技术迭代速度远超集中化决策的反应速度

**2. 开源层：社区力量持续分流**

- Meta 的 Llama 系列、阿里 Qwen 系列、法国 Mistral 的模型，以惊人速度逼近闭源 SOTA
- 开源模型的进步速度让闭源"护城河"不断缩窄——每出一代闭源模型，社区大概 3-6 个月就能追到"可用"水平
- 一个开发者用 Llama 微调出来的垂直模型，在特定任务上完全可能超过 GPT-4——这在通用软件领域几乎不可能发生

**3. 商业层：场景碎片化决定没有"通用王"**

- To C 对话助手、To B 企业知识库、代码生成、多模态创作——每个场景的最优解不同
- 客户关心的是"在我的场景上好不好用"，不是"你的模型参数有多大"
- 这就好比数据库领域：Oracle 再强也没法杀死 Redis 和 ClickHouse，因为场景不同

**4. 地缘层：全球多极化已成事实**

- 中美两国的 AI 生态在芯片、数据、应用层面持续分化
- 东南亚、中东等新兴市场正在培育本土 AI 公司
- 全球 AI 不再是"OpenAI 一家独大"的单极格局，而是"多极+多模型"的网状结构



## 三、去中心化的技术逻辑

"放手"和"没有大哥"背后，有清晰的技术逻辑支撑，不是单纯的管理风格变化：

**模型多样性的必然性**

- 不同任务对模型的需求差异巨大：代码生成需要精确的符号推理，对话需要流畅的自然语言生成，图像理解需要强大的视觉编码器
- 单一模型（即使参数量极大）在所有维度上都做到 SOTA 的概率极低
- 这决定了一个"多模型协同"的架构比"一个模型统治一切"更合理——就像操作系统的微内核设计思路：核心精简，按需组合

**推理成本驱动分布式部署**

- 大模型推理的算力成本仍然高昂：一个 70B 参数模型做单次前向传播的 FLOPs 约在 10^11 量级
- 端侧小模型（1B-7B 参数量级）在手机 NPU、PC GPU 上的推理能力已经可用
- "云端大模型 + 端侧小模型"的协同推理模式正在成为主流范式
- 这从物理层面就决定了 AI 能力的分布是去中心化的——你不可能把所有推理都送到云端

**开源生态的飞轮效应**

- 开源模型的微调成本（几千到几万美元）远低于从头训练（几百万到上亿美元）
- 全球开发者社区的贡献形成了正向循环：用的人越多 → 发现的问题越多 → 改进越快 → 用的人更多
- 任何试图通过闭源垄断的玩家，都会面临"社区版"的持续追赶——Linux 对 Windows 的剧本可能重演

## 四、历史镜鉴：每一轮技术周期都有相似剧本

**移动互联网时代（2010-2020）**

- 早期大家以为"一个超级 App"能统治一切，结果走了分发、内容、服务的分层路线
- 微信没有杀死所有垂直应用，反而长出了小程序生态——开放比封闭赚得更多
- 启示：AI 也会走分层路线——基础模型层、平台层、应用层各有各的玩家

**云计算时代（2006-至今）**

- AWS 最早入场且份额最大，但 Azure 和 GCP 仍然各有领地
- 没有任何一家云厂商能通吃所有企业客户——合规、成本、技术栈偏好决定了多云常态
- 启示：AI 基础设施也会走向多模型、多平台的格局

规律很简单：**凡是技术迭代速度快的领域，集中化就难以持续。** AI 的迭代速度可能是互联网史上最快的——从 GPT-3 到 GPT-4 到 o1 到多模态，基本每 12-18 个月就有一次范式跳变。这种速度下，"大哥"还没坐稳位置，格局就已经变了。

## 五、三条冷思考



**1. 给开发者：别赌单押，做多模型适配**

- 不要把所有技术栈绑死在一家模型 API 上——今天的最优模型不一定是明天的
- 用 LangChain、LiteLLM 这类抽象层做好多模型切换的架构准备
- 关注开源模型的微调能力——这是你区别于"只会调 API 的prompt工程师"的核心竞争力
- 在 prompt engineering 层面建立模型无关的通用方法论，而非针对单一模型的"咒语集"

**2. 给企业：选模型像选数据库，不是选信仰**

- 不要被任何厂商的 "one model to rule them all" 话术带偏——没有银弹
- 建立内部模型评测基准（eval suite），按业务场景做 A/B 测试，用数据说话
- 合同谈判时保留模型切换权，设置明确的 exit clause，避免 vendor lock-in
- 考虑"自建小模型 + 调用大模型"的混合架构，高频低难度任务用本地小模型，低频高难度任务调云端大模型

**3. 给普通用户：享受竞争红利，但保持信息卫生**

- 多平台体验是好事——竞争意味着更好的产品和更低的价格，这是经济学常识
- 但要注意：不同模型的幻觉模式不同，交叉验证比信任单一来源更安全
- 关注模型的隐私政策，尤其是对话数据是否被用于训练——你的 prompt 可能变成别人的训练样本
- 在关键决策（医疗、法律、投资）上，把 AI 当顾问而不是裁判。它给的是参考意见，不是判决书
