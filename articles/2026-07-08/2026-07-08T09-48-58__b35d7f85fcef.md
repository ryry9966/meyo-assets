最近技术圈炸了个不大不小的瓜：Anthropic 的命令行编程工具 Claude Code，其诞生路径并非「我们想做个 coding agent」这么简单，而是脱胎于安全对齐（safety alignment）研究。Anthropic 联合创始人 Boris Power 在近期的访谈中还补了一刀——「才完成了 1%」。这条消息表面上看是个产品八卦，但剥开外壳，里面的虾肉其实是一整套关于大模型能力涌现、对齐技术反哺工程实践的硬核叙事。今天 RY 哥就带大家把这事儿掰开揉碎聊清楚。



## 一、Claude Code 是什么？先对齐一下认知

很多人看到热搜标题会一头雾水：Claude Code 是 Claude 里的某个功能模块？还是一个独立产品？这里先把基本面对齐清楚，避免后面聊的时候频道不对。

- **产品定位**：Claude Code 是 Anthropic 推出的 **agentic command-line coding tool**，也就是一个跑在终端里、能自主完成编码任务的 agent 工具。它不是 IDE 插件，不是 ChatGPT 式的对话框，而是直接在你的项目目录里以 CLI 形式运行。
- **核心能力**：能读写文件、执行 shell 命令、搜索代码库、调用 git、跑测试，甚至能做多步规划然后逐步执行。你可以理解为「一个坐在终端里的初级工程师，你给它一个 ticket 描述，它自己拆解、查代码、改代码、跑测试、提 PR」。
- **底层模型**：跑在 Claude 3.5 Sonnet（以及后续版本）之上，通过 **tool use** 机制把文件系统操作、bash 执行等能力挂载给模型，让它在推理过程中自主决定调用哪些工具。
- **使用方式**：通过 `npm install -g @anthropic-ai/claude-code` 安装，然后在项目根目录运行 `claude` 进入交互式 agent 循环。

所以 Claude Code 的本质是：**一个以 LLM 为大脑、以文件系统和 shell 为手脚的 autonomous coding agent**。理解了这一点，后面「脱胎于安全对齐」的说法才不会觉得突兀。



## 二、「脱胎于安全对齐」到底是什么意思

这是整件事最反直觉的部分。大多数人的因果链是：Anthropic 想做编程工具 → 训练一个擅长写代码的模型 → 包装成 CLI 产品。但实际情况更像是：Anthropic 在做安全对齐研究的过程中，发现某些对齐技术显著提升了模型的 **instruction following** 和 **agentic task execution** 能力，这些能力恰好是 coding agent 的核心需求，于是顺势孵化出了 Claude Code。

要把这个逻辑讲透，得从 Anthropic 的对齐方法论说起。

### 2.1 Constitutional AI 与能力涌现

Anthropic 的核心对齐方法叫 **Constitutional AI（CAI）**，核心思路是用一组「宪法原则」引导模型自我修正，减少对人工标注的依赖。具体流程大致是：

1. **Supervised phase**：让模型根据宪法原则对自己生成的回答进行 critique 和 revision，形成改进后的训练数据。
2. **RL phase**：用改进后的数据训练一个 preference model，再做 RL 微调。

这条路径的初衷是让模型更安全、更诚实、更无害。但研究团队发现了一个「副作用」——经过 CAI 训练的模型在 **复杂多步推理** 和 **工具调用场景** 下的表现也有显著提升。原因不难理解：

- 自我 critique 的过程本质上是一种 **chain-of-thought 式的反思训练**，模型学会了在给出最终答案前先审视自己的中间步骤。
- 这种反思能力在 coding 场景中极其关键——agent 需要在改完代码后自己检查是否引入了 bug、是否遗漏了边界条件，然后决定是否回退或继续。

### 2.2 RLHF 的副产物

除了 CAI，Anthropic 在 **RLHF（Reinforcement Learning from Human Feedback）** 上也有大量投入。在训练过程中，标注员会对模型在 agentic 场景下的表现做偏好标注。这里面有一个关键细节：

- 安全对齐要求模型在「不该做的事」上克制（比如不生成有害代码、不执行危险命令）。
- 但这种克制不是简单的拒绝，而是 **contextual judgment**——在什么情况下可以执行 `rm -rf`，什么情况下应该先确认。
- 这种判断力恰恰是一个可靠 coding agent 必须具备的素质。

换句话说，安全对齐训练出来的「知道什么时候该停下来问人」的能力，天然就是 agentic coding 的安全护栏。Claude Code 的可靠性，很大程度上继承了这条血脉。

### 2.3 从研究 artifact 到产品

据 Boris 在访谈中透露的线索，Claude Code 最初更像是安全对齐研究中的一个 **副产品 / artifact**——研究人员在测试模型 agentic 能力时搭的一个 CLI 工具壳子，用来验证模型在真实代码库里能不能靠谱地完成任务。结果这个「测试工具」效果好到超出预期，于是产品化提上日程。

这个路径其实并不罕见。工程史上很多伟大产品都是研究副产物：Slack 最初是游戏公司的内部沟通工具，Discord 是给游戏玩家做的语音聊天，Claude Code 则是安全对齐研究的测试框架。区别在于，Anthropic 敏锐地意识到了这个 artifact 的产品价值。



## 三、「才完成 1%」该怎么解读

Boris 说「才完成了 1%」，这句话如果只看数字会被吓到——1% 听起来像是在说「我们还没开始」。但结合上下文和技术语境，这个数字的含义其实更微妙。

### 3.1 这 1% 指的是什么

从 Boris 的访谈上下文来看，这 1% 更可能指的是 **agentic coding 的完整愿景**，而非 Claude Code 当前产品完成度。完整愿景至少包括：

- **全栈自主**：从需求理解 → 架构设计 → 代码实现 → 测试验证 → 部署上线 → 监控回溯，全链条 autonomous。
- **跨仓库协作**：不只是在一个 repo 里改文件，而是能理解多个服务的依赖关系，做跨仓库的 breaking change 迁移。
- **长期记忆与上下文管理**：能记住一个项目几个月的演进历史，理解某段代码「为什么这么写」而不只是「写了什么」。
- **主动发现问题**：不是你给它 ticket 它才干活，而是它自己巡检代码库、发现性能瓶颈或安全漏洞并主动修复。

当前 Claude Code 大致处在「能在单仓库内完成中等复杂度编码任务」的阶段，距离上面这个愿景确实还差得远。1% 可能是个修辞，但量级上不算太离谱。

### 3.2 当前能力的边界

为了不把 Claude Code 捧上天，这里客观列一下它目前做得好和做不好的地方：

**做得不错：**

- 单文件或小范围多文件的修改、重构
- 根据自然语言描述在代码库中定位相关代码
- 编写单元测试、生成 boilerplate 代码
- 执行简单的多步任务（改代码 → 跑测试 → 根据报错修复）

**仍有明显短板：**

- 复杂架构级重构（涉及十几个文件的联动修改）容易丢失全局上下文
- 长周期任务（需要多轮交互、跨 session 记忆）的连贯性不足
- 对非主流语言/框架的代码库理解深度不够
- 偶尔会「自信地写错」——代码看起来合理但逻辑有微妙 bug，且不会主动验证

这些短板恰好就是那 99% 要解决的问题。



## 四、安全对齐 → 工程能力，这条路径为什么值得注意

Claude Code 的身世之所以引发热议，核心不只是八卦，而是它揭示了一个 **技术路线的范式转移**：对齐研究不再只是「安全护栏」，它正在成为 **能力引擎** 的一部分。

这个认知对整个行业有几个重要启示：

### 4.1 安全和能力不是零和博弈

过去业界有一种朴素观念：对齐 = 给模型加枷锁，枷锁越多能力越弱。但 Anthropic 的实践表明，至少在某些维度上，**好的对齐方法反而增强了模型的实用能力**。原因在于：

- 对齐训练本质上是在教模型「更好地理解人类意图」，而这恰恰是 agentic 场景的核心。
- 一个能精准判断「人类到底想让我做什么、不该做什么」的模型，自然也更适合做 coding agent——因为 coding 的本质就是把模糊的人类需求转化为精确的代码实现。

### 4.2 反思能力是 agent 的核心竞争力

CAI 训练中引入的 self-critique 机制，让模型养成了「先想再答、答完自查」的习惯。这种习惯在 chatbot 场景里可能只是锦上添花，但在 agent 场景里是生死攸关的——因为 agent 的每一步操作都会改变环境状态，一步走错，后面全盘皆错。

这也解释了为什么 Anthropic 的模型在 agentic benchmark（如 SWE-bench）上表现突出：不是因为他们专门训练了 coding 能力，而是因为对齐方法论天然培养了 agent 所需的审慎和反思。

### 4.3 对其他厂商的示范效应

如果「对齐反哺能力」这条路径被验证成立，那其他厂商也可以复用：

- 不需要单独搞一个「coding 专用模型」，而是把对齐做扎实，coding 能力自然涌现。
- 这意味着对齐团队的投入不再是纯成本中心，而是有直接产品回报的能力孵化器。
- 长期来看，对齐研究和产品能力的边界会越来越模糊。



## 五、给开发者的三条冷思考

聊了这么多原理和趋势，最后落地到实操层面，RY 哥给各位开发者三条建议：

**1. 把 Claude Code 当「高能实习生」而非「自动驾驶」**
