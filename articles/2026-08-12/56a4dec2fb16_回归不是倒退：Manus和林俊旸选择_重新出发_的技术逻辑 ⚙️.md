如果你在 2023 年 AI 融资最狂热的时候告诉我，两个站在各自细分赛道顶端的人，会在一年后主动选择"回归"——一个把公司从独立 AI 产品的浪尖上拉了回来，另一个从顶级大厂的研究院"出走"后又以全新身份重返体系——我一定觉得你是在讲某种互联网寓言故事。但这件事确实发生了：Manus 的团队在经历 AI 浏览器新物种的探索后，近期做出了重大战略调整；而阿里通义千问大模型的技术灵魂人物林俊旸，也在离开达摩院后以一种更富张力的新角色重新"下海"干活。

这不是什么"退场"或者"认输"的信号。如果拉长时间轴来看，这恰恰是 AI 行业从实验室论文走向工程落地时，必然会发生的结构性震荡。



## 在资本最高点调转方向盘，Manus 想清楚了什么？

Manus 这个名字第一次被大规模讨论，是因为它做了一个非常"反直觉"的产品定义：别人在做聊天式 AI 助手，它在做"能帮你操作浏览器的自动化智能体"。你可以把它理解成一个具有执行力的大模型——你告诉它"帮我在飞猪上找到下周三去成都最便宜的中转航班，然后预订"，它真的会帮你打开网页、填表、点按钮。

这套技术栈我们通常称为 **Autonomous Web Agent**，核心架构是：

- **分层任务规划器（Hierarchical Task Planner）**：把自然语言指令拆成多步可执行动作
- **DOM-level 操作引擎**：直接阅读网页的文档对象模型，而不是靠计算机视觉截图
- **记忆与状态机**：维护跨页面上下文，能在多标签页间传递变量
- **安全沙箱环境**：隔离执行环境，防止"AI 乱点"引发真实交易风险

一个典型的执行流程可能是这样的：

1. 用户输入："帮我查一下杭州到北京下周三的高铁，选 G34 那趟的二等座"
2. 规划器分解为：打开 12306 → 输入出发地和目的地 → 选择日期 → 筛选车次 → 定位到 G34 → 选择二等座 → 提交订单
3. 每个步骤由 DOM 引擎精确定位元素并模拟操作
4. 遇到验证码或异常弹窗，回退到用户确认节点

听起来很酷对吧？但工程现实是残酷的。**Web Agent 的鲁棒性问题**几乎贯穿了所有这类产品的命门。你今天能跑通的流程，明天可能因为目标网站改了一个 CSS class 就全线崩溃。而国内互联网生态中，验证码、反爬策略、复杂的登录体系，让这件事的维护成本指数级膨胀。

所以 Manus 团队近期的战略回调，本质上是把核心能力从"面向 C 端消费者的完整产品"重新拆解为"可被企业集成的智能体中间件"。换句话说，他们不再试图一次性解决所有网站的兼容问题，而是把 Execution Engine 以 API 的形式开放给有明确场景的 B 端客户——让后者自己去适配特定网站，Manus 提供推理与执行的基础设施。

这在工程上是更务实的打法。

## 林俊旸的"出走与回归"，藏着大模型落地的第二曲线

林俊旸这个名字在 AI 圈的分量不需要铺垫。他在阿里达摩院期间主导了**通义千问（Qwen）系列模型**的研发，从最初的 7B 到后来的 72B、甚至 MoE（混合专家）架构的 Qwen-Max，几乎每一代都在开源社区引发过震动。

他的技术路线有一个清晰的标签：**对 Transformer 架构的激进改良派**。当业界还在讨论 Llama 2 的微调策略时，Qwen 已经在做几件超前的事：

- **预训练阶段的多语言词表优化**：使用 BPE-dropout 和动态 vocab expansion，在中英文之外对日语、韩语、阿拉伯语做原生支持
- **长上下文的 NTK-aware 插值**：早在 RoPE 外推成为显学之前，Qwen 就实现了基于 Neural Tangent Kernel 的注意力缩放
- **SFT 数据的合成管线**：不是纯人工标注，而是用更强大的模型自动生成多样化指令，再经过严格的规则过滤和人工抽检

这些技术决策让 Qwen 在 Hugging Face Open LLM Leaderboard 上长期霸榜。但更值得关注的是他离开达摩院后的动作：**以创业者身份重返大模型战场，但这次聚焦在 Agent 原生框架**。

这里的逻辑链条值得拆开看：

1. **基础模型能力的边际收益在递减**。从 7B 到 72B 再到 MoE，参数量增长带来的能力跃升已经不再是线性关系。GPT-4 到 GPT-4 Turbo 的提升远小于 GPT-3.5 到 GPT-4 的跨越。
2. **真正的产品化瓶颈不在"智商"，在"执行链路"**。一个 IQ 180 的模型如果无法调用工具、维护状态、处理异常，在实际场景里打不过一个 IQ 120 但有完整工具链支持的 Agent。
3. **系统层面的创新空间远大于模型本身**。Prompt Engineering、RAG（检索增强生成）、Memory Management、Multi-Agent 协作——这些系统工程层面的优化，对最终用户体验的影响往往超过模型微调几个百分点的基准提升。

所以林俊旸的"回归"，本质上是从"造引擎"转向了"造整车"。这个转型在技术史上并非孤例。当年 Linux 内核的 Linus Torvalds 写出 Git，并不是因为内核开发遇到了瓶颈，而是因为协作流程本身需要被重新发明。



## AI 行业的"回归潮"，反映的是底层范式的迁移

如果我们把 Manus 的调整和林俊旸的选择放在一起看，会发现一条隐藏的线索：**2024 年下半场的 AI 竞争，正在从"模型军备竞赛"全面转向"系统工程能力竞赛"**。

这背后有三个推动力：

- **算力成本结构的变化**：2023 年 Q4 到 2024 年 Q1，H100 集群的租赁价格下降了将近 30%，但企业客户的付费意愿并未同比例增长。纯粹靠模型 API 调用的商业模式，毛利率正在被挤压。
- **开源模型的加速追赶**：Meta 的 Llama 3、Mistral 的 Mixtral、阿里 Qwen 的开源版本，在某些垂直任务上的表现已经接近闭源头部模型。差异化不再是"我的模型比你好 5 个点"，而是"我能解决的端到端问题你解决不了"。
- **用户对"聊天机器人"的疲劳**：新鲜感消退后，普通消费者对通用对话式 AI 的日活留存率并不理想。真正愿意持续付费的，是那些把 AI 嵌入到具体工作流里的企业用户。

这种范式迁移导致了一个现象：**顶级人才开始从"做更好的模型"向"做更好用的系统"流动**。而 Manus 和林俊旸的路径选择，恰恰是两个典型的转型样本：

- **Manus 方向**：从垂直产品到通用中间件，向下沉为核心基础设施
- **林俊旸方向**：从基础模型研发到 Agent 应用框架，向上构建产品化能力

## 为什么"回归"在工程圈从来不是贬义词

软件工程领域有一个著名概念：**Second-System Effect**（第二系统效应）。它描述的是，当工程师第一次做某个系统时，往往会过度设计，加入大量"看起来很酷但用户不需要"的功能。等到第二代系统时，人才会真正理解哪些东西是本质、哪些只是噪声。

AI 行业正在经历它的"第二系统时刻"。

第一系统是"让模型说话"——ChatGPT 横空出世，所有人都在追求更流畅的对话、更长的上下文、更低的 hallucination（幻觉）。

第二系统是"让模型干活"——你需要它不只回答问题，还要能操作界面、查询数据库、触发工作流、在多步骤任务中保持一致性。

Manus 回归到中间件层，是因为它意识到"让模型干活"这件事的标准化程度远低于预期。与其每个客户都从零搭建 Web Agent，不如提供一套经过验证的执行引擎，让客户在它的基础上做定制化适配。

林俊旸回归到 Agent 框架，是因为他看到了基础模型的同质化趋势。当一个市场上同时存在 10 个以上性能接近的 LLM 时，决胜点就转移到了"谁能让这些模型真正跑进生产环境"。



## 三条冷思考，帮你看清这轮"回归"的本质

**第一，不要用"升职/离职"的视角理解技术人才的流动。** 在传统行业，一个人从大厂出去又回来，可能意味着"创业失败回归体制"。但在 AI 领域，这种流动更像是"在核心层积累不同的能力模块"。Lin 在达摩院做预训练，出来做 Agent 工程，再以新身份对接产业资源——他的技术树是在完整的，不是断裂的。

**第二，关注"回归者"选择的具体赛道，而不是回归本身。** Manus 选择了 Execution Middleware（执行中间件），林俊旸选择了 Agent Framework（智能体框架）。这说明当前 AI 行业最稀缺的既不是算力，也不是模型，而是**能够被可靠编排的执行单元**。如果你在做 AI 方向的创业或投资，值得把目光从"下一个 GPT"上移开，转向这些让现有模型产生实际价值的工程层。

**第三，警惕"大而全"的诱惑，拥抱模块化。** 不管是 Manus 还是阿里，他们共同的教训是：想在 AI 领域做一个什么都能干的超级产品，会在交付阶段碰到无穷无尽的边角案例。更可持续的路径是把能力拆成独立可组合的模块，让生态伙伴去完成最后一公里的适配。这种思维方式的转变，可能是这轮"回归"给我们最重要的启发。
