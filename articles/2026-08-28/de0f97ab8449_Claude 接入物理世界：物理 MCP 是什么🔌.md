就在今天，Anthropic 官方发布了一项被称作“物理 MCP”的新能力。过去一年多，MCP 让 Claude 可以读文件、查数据库、调用代码，但这些动作都发生在数字世界。物理 MCP 则把范围进一步推向真实设备：传感器、机器人、摄像头、开关、执行器。换句话说，Claude 正在获得一套面向物理世界的“眼睛”和“手”的标准接口。这篇文章不吹概念，拆开看它到底是什么、怎么工作、为什么值得关注，以及最容易被忽略的几个问题。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/cb21e8f27b0aebe5.png)

## 一、物理 MCP 是什么：把“工具调用”延伸到实体世界

- MCP 全称 Model Context Protocol，Anthropic 在 2024 年底开源，目标是给 AI 模型提供一套标准化的外部工具接入格式，类似 USB-C 对硬件设备的意义。以前每家数据源都要单独写插件，现在只要按 MCP 暴露能力，Claude 就能调用。
- 数字 MCP 的工具大多集中在软件 API：GitHub、Slack、数据库、浏览器、文件系统。模型可以“读”和“写”数字对象，但无法直接触碰物理环境。
- 物理 MCP 的本质，是把协议里的“工具”和“资源”映射到真实设备：一个机械臂可以暴露类似“移动到指定坐标”的能力，一个温控器可以暴露“设置目标温度”的能力，一个摄像头可以暴露“抓取当前画面”的能力。
- 用更直白的话讲：数字 MCP 让 Claude 在电脑里点按钮；物理 MCP 让 Claude 在工厂、仓库、实验室、楼宇里拧旋钮、按开关、移货物。

## 二、技术链路：一次动作从感知到执行怎么走

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/303bd7848b05b0ca.png)

- 典型链路分四步：感知、推理、动作、反馈。
  1. 传感器数据通过 MCP server 以资源形式推送给 Claude；
  2. Claude 结合任务目标判断是否有异常、该采取什么动作；
  3. Claude 以工具调用形式向执行设备发出指令；
  4. 执行结果和新的传感器状态回传，Claude 判断是否继续。
- 举一个仓储场景：温湿度传感器发现某货架区域温度超过阈值 → MCP server 把状态发给 Claude → Claude 判断可能是冷链异常 → 调用移动机器人巡检该区域 → 机器人摄像头回传图像 → Claude 识别包装表面是否有凝水或破损 → 生成维修工单并通知仓库管理员。
- 与传统 PLC 或固定规则系统相比，物理 MCP 的差异不在“能不能控制”，而在“谁能做语义决策”。传统系统需要工程师预先写下所有 if-else，物理 MCP 允许模型根据开放目标动态规划。
- 但必须强调：这不是让 Claude 直接驱动电机。大多数安全要求高的场景，底层仍会有实时控制器、安全继电器或运动控制卡。物理 MCP 更像“上层规划器”，底层执行闭环不依赖 LLM。

## 三、为什么这件事信号意义很大

- 第一，能力边界从信息流外移到物质流。过去 AI Agent 改变的是“信息处理成本”，现在开始触碰“物理操作成本”。哪怕初期只做低风险任务，也是一个明确方向。
- 第二，统一协议解决碎片化。工业设备、机器人、IoT 长期存在私有协议，集成成本极高。物理 MCP 如果能成为事实标准，硬件厂商只需实现一次 MCP server，就能被各种 AI 应用调用。
- 第三，生态卡位。Anthropic 已经在 MCP 数字生态有先发优势，物理 MCP 把这种优势延伸到硬件层。对开发者来说，熟悉的工具抽象可以降低上手门槛。
- 第四，竞争格局。OpenAI、Google 都在推进具身智能和机器人模型，但开放设备协议层仍不成熟。Anthropic 这一步更像在做“连接器”，而不是自己造机器人。连接器一旦被广泛采用，价值巨大。

## 四、真正难的不是“接上”，而是“安全地接上”

- 真实世界没有 Ctrl+Z。模型在文本里出现幻觉，顶多输出错误段落；物理世界一次错误动作可能撞坏设备、泄漏物料甚至伤到人。
- 延迟约束完全不同。文本生成慢一点可以接受，但机器人避障、阀门控制需要毫秒级甚至微秒级响应。当前 LLM 推理延迟根本不可能直接参与高速闭环，因此物理 MCP 必须与实时控制层解耦。
- 权限和审计比数字场景更严格。谁允许 Claude 操作某个设备？动作范围多大？是否每次都需要人工确认？如果出问题，日志能否还原完整决策链？
- 标准化的最后一段路仍难走。设备种类多、物理特性差异大，单靠协议抽象无法解决安全认证、硬件可靠性、环境适应性等问题。物理 MCP 更多是解决软件接口层，不可能替代硬件工程。

## 五、冷思考：不是“接管世界”，而是“翻译层”

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/b9460a75e9674ee0.png)

- 把物理 MCP 想象成“设备界的翻译官”，而不是“控制者”。它让模型用自然语言级别的意图去理解物理世界，并把决策翻译成设备能听懂的调用。最终执行权仍应该留在经过验证的工控系统或人类手里。
- 对企业和开发者，有三条实用建议：
  1. 先从只读和低风险场景切入：设备巡检、状态监测、异常分析、生成操作建议，先别让模型直接执行不可逆动作。
  2. 物理 MCP 只作为“决策建议层”，高危操作必须保留人工确认和传统安全控制器的双层兜底。
  3. 接入前先看三件事：审计日志是否完整、权限边界是否可控、故障时是否能快速降级到传统规则模式。不要为了追新而把安全架构推倒重来。

物理 MCP 的意义不在“Claude 有了手脚”，而在它给出了一个可扩展的接口，让物理世界对模型变得可读、可规划、可验证。真正落地的节奏取决于安全工程，而不是模型能力。
