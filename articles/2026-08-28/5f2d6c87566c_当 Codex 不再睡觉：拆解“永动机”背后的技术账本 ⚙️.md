最近，科技圈流传着一个很“科幻”的说法：OpenAI 把 Codex 做成了「永动机」，内部代码曝光显示它“不强制休眠不停机”。如果只看这几个字，很容易脑补出一个永远在写代码、永远不需要休息的机器人。但工程世界里，任何“不停机”都伴随着一串更实际的问题：上下文会不会溢出？错误会不会滚雪球？账单有没有上限？本文从技术角度拆解这个被热议的说法，看看一个 AI 代理真正“不睡觉”意味着什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/a84cd8f26a637bda.png)

## 先拆词：“永动机”不是物理概念，而是进程策略

- Codex 最初是 OpenAI 在 2021 年推出的代码生成模型，后来逐渐演变为能调用工具、执行命令、修改文件的云端代理（agent）。它和普通代码补全的本质区别是：它有一个持续运行的“计划—执行—观察”循环。
- 所谓“不强制休眠不停机”，在工程上很可能对应配置项：关闭 `idle_timeout`、移除 `max_run_duration`，或者把 `allow_sleep` 设为 false。也就是说，只要任务队列不为空，进程就不会主动退出。
- 媒体用“永动机”这个词，更多是比喻一种“没有外部干预就持续运行”的状态。真正的物理永动机不存在，但软件进程确实可以在资源允许的前提下不断循环。
- 值得关注的不是它“能不能一直跑”，而是取消强制停止之后，系统如何在有限的上下文、预算和安全边界内，保持“可用”。

## 为什么“不让他睡”比想象中更难

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/6570d0b695acb585.png)

- 上下文窗口像一条会溢出的河。模型本身没有记忆，每一步产生的输入输出都会累积在上下文里。长时间运行的任务，可能几步之后就塞满几万 token；一旦触发截断，前面的文件修改记录、测试结果可能被直接丢弃。
- 状态漂移不是线性的。一个运行 4 小时的 agent 和运行 40 分钟的 agent，行为偏差不是简单放大 6 倍。工具调用产生的中间文件、临时目录、环境变量，都会成为新的噪音源。
- 错误会自我复制。举个例子：重构任务中，第一步误删了一个函数，第二步读取时找不到该函数，于是生成一个错误补丁，第三步可能把错误补丁提交到主分支。每一步都在前一步的错误上继续走，直到系统失控。
- 长时间运行还面临类似传统进程的“资源泄漏”：无用的工具输出被反复引用，文件句柄不释放，甚至日志膨胀到拖慢响应速度。

## 一个粗算：取消休眠后，账单和时间线怎么变

- 假设一个 agent 平均每次工具调用消耗 5,000 token，一轮循环约 30 秒，那么一小时约 120 轮，消耗约 60 万 token。按当前大模型 API 的常见价格区间估算，这可能是几美元到几十美元不等。
- 如果任务目标模糊，agent 可能在“修改—测试—失败—再修改”的循环里跑上大半天，成本会轻松突破单次人工开发的预算。
- 时间线也会失真：没有强制检查点，中间任何一步失败，前面所有未写入持久层的进度都可能丢失。与其说是不停机，不如说是“低效燃烧”。
- 真正成熟的长时间运行进程，往往需要精确的步数上限、预算上限和时间上限，三者至少取其二。

## 合理场景 vs 危险场景：不是所有任务都适合 7×24

- 适合的场景：跨文件重构、批量迁移、长链路测试修复、大规模代码审查。这些任务天然需要多轮工具调用和长时间运行，强制休眠反而会打断工作流。
- 危险的场景：目标描述含糊、退出条件缺失、对文件系统或生产环境有写权限的任务。一旦 agent 在无边界环境里自由发挥，错误半径会迅速扩大。
- 一个更实用的判断标准是：能否在一秒内让它停下来，并且不丢任何重要状态。如果不能，那么“不停机”就不是优势，而是风险放大器。
- 历史上，很多自动化事故都不是因为程序太弱，而是因为缺少可靠的中断机制。AI agent 只是把这个问题放大了一个数量级。

## 冷思考：给 AI 代理上闹钟，还是装刹车？

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/d41f09427e36b0ac.png)

- 如果正在尝试让 Codex 或类似 agent 长时间独立干活，有三条建议值得参考：

1. 设置硬上限：预算、步数、运行时长三选二，任何一项触顶就终止。不要指望模型自己“觉得差不多了”。
2. 用检查点代替连续运行：把大任务切成多个小任务，每个小任务完成后做一次快照。断点续跑比一口气跑完更可靠。
3. 保留人工确认点：对关键操作（删除文件、执行命令、提交代码）加一层人工审批。这不是不信任模型，而是降低爆炸半径。

“不强制休眠不停机”听起来像解放生产力，但真正的工程成熟度，体现在你能否在合适的地方装上一道可靠的刹车。
