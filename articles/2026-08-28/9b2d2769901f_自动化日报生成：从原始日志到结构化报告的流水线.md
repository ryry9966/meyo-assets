# 自动化日报生成：从原始日志到结构化报告的流水线

## 背景

团队每天要汇总的日志来源很多：应用部署日志、脚本执行记录、Git 提交、监控告警、抓取任务状态，还有 IM 里零散的人工补充。它们散落在文件系统、数据库、API 和聊天记录里，格式不统一，上下文靠人工记忆。人工整理日报不是难在写，而是难在每天重复、容易漏，而且每个人对“重要”的判断不同。

在 OpenClaw 这类 Agent 环境里，常见的错误做法是直接让模型读一堆日志然后写一段摘要。短期看起来能用，长期会出现幻觉、结构漂移、关键证据丢失。我们的目标不是“生成一篇日报”，而是做一条可追溯、低维护成本的结构化流水线。

## 问题拆解

原始日志到日报之间有四个坑：

1. **多源异构**：日志级别、字段、时间格式都不一样。
2. **噪声大**：堆栈、重试、DEBUG、颜色码、重复信息混在一起。
3. **上下文脆弱**：一条错误可能和几分钟前的配置变更有关，单看一行会误判。
4. **量级波动**：日常 2 万行，发布日可能 20 万行，不能全量塞进上下文。

## 做法

### 1. 数据接入：MCP 拉取，先不碰语义

用 MCP server 把日志拉回。文件日志走 filesystem MCP，Git 提交走 git MCP，监控指标走 HTTP/API MCP。OpenClaw 里配置定时触发和输入参数，比如 `report_date=2025-01-15`、`source=deploy,scripts,alerts`。这一步只做收集，不做理解。

### 2. 预处理：统一成 JSONL 事件行

用插件或脚本把原始日志清洗成统一结构，每条保留：

- `ts`：标准化时间戳
- `source`：来源标识
- `level`：INFO/WARN/ERROR/DEBUG
- `event`：事件类型或脚本名
- `raw`：原始行内容
- `ref`：文件路径 + 行号

同时去掉 ANSI 颜色、重复堆栈和明显的 token 噪声。原始日志保留，不动。

### 3. 抽取：先用 schema 约束，不直接写日报

这一步最关键。不让模型写报告，而是让它做证据抽取。要求 agent 对每个来源输出结构化事件列表，字段固定为：

- `evidence`：必须引用 `raw` 片段
- `event_type`：错误、变更、性能劣化、任务失败、普通信息
- `impact`：对业务或任务的影响
- `action`：已采取动作或建议动作

输出用 JSON Schema 约束。解析失败的批次直接降级为“仅列原始日志片段”，不静默丢弃。

### 4. 生成：模板填槽，证据绑定

拿到事件列表后，再填日报模板。模板结构固定：概览、异常、变更、风险、明日计划。每个条目后面跟证据 id，比如 `#ev-12`。这样读者可以回到原始日志核实。OpenClaw 完成填槽并输出 Markdown。

### 5. 发布与留档

日报推送到 IM 或邮件，同时把标准 JSONL、抽取结果和最终 Markdown 归档。发布前跑一遍脱敏校验，避免 token、手机号、内网地址外泄。

## 踩坑点

- **上下文爆掉**：不要全量塞日志。先按来源和级别统计数量，只读 top N 错误及其前后窗口。其余用聚合行表示。
- **JSON 结构漂移**：今天模型返回 4 个字段，明天可能多出 `note` 或少 `action`。用 schema 校验 + 重试，解析失败降级，不能丢事件。
- **幻觉**：模型会把错误码解释成错误含义，或者把“warning”写成“已解决”。要求引用原文，关键数字不允许重写。
- **时区问题**：crontab 通常在 UTC 触发，而“今天”对团队是本地时间。生成前校验 `report_date`，必要时在收集层转换。
- **报喜不报忧**：模型倾向把负面描述软化。可以在 prompt 中要求 `severity` 不降级，且异常事件必须出现在摘要第一屏。
- **敏感信息**：日志里常有 token、手机号、内网 IP。预处理阶段做正则脱敏，发布前再校验一次。

## 可复用建议

- 保留三层产物：原始日志、标准化事件、最终报告。任何一层可回溯。
- Prompt 和模板纳入 git 管理，日志和报告分仓库。
- 先做 7 天 shadow run，只生成不发，每天人工对比，稳定后再推给团队。
- 提供“异常版”和“完整版”两个输出，异常版控制在 300 字内，适合 IM 阅读。
- 设置回滚：当 agent 输出异常或校验失败时，自动退回脚本拼接的基础日报，保证每天有产物。

## 总结

自动化日报的难点不在“生成”，而在“可信”。先做结构化抽取，再生成报告，用证据链、模板和版本控制把流程固定下来。这样才算一条能用于日常交接的流水线，而不是一个每天需要人重新检查的黑盒。
