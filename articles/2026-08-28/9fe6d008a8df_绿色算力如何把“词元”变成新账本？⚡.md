最近，科技圈和能源圈同时盯上两个词：绿色算力、词元经济。前者关心数据中心怎么少用电、用绿电；后者关心大模型输出的一小块文本怎么计价。它们看似一个偏基础设施，一个偏商业结算，实际已经缠绕成同一条链路：算力越省，词元越便宜；词元越普及，绿色算力的价值越被放大。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/bc3ff2453e899e80.png)

## 绿色算力：先把数据中心的电费账本翻开

绿色算力不是“少用算力”，而是让单位算力消耗更少的电与碳。它首先是一个工程问题。

- 数据中心是耗电大户。全球数据中心用电量约占全社会用电量的 2%—3%，AI 训练集群还在把这个比例继续推高。一个万卡级训练集群，峰值功率可能达到数十兆瓦，相当于几万户家庭同时用电。
- 衡量绿色程度常用 PUE（电能利用效率）。PUE 等于总耗电除以 IT 设备耗电，越接近 1 越理想。传统机房 PUE 常在 1.5 以上，意味着制冷、配电、照明额外吃掉一半电；先进液冷集群可以压到 1.1—1.2。
- 绿色化通常走三条路线：第一，提高制冷效率，从风冷转向冷板液冷、浸没液冷；第二，提高可再生能源占比，用风电、光伏、水电匹配算力负载；第三，做负载调度优化，把训练、推理任务迁移到绿电充足或气候凉爽的区域。

这些技术动作的目标不是让机器变慢，而是让每瓦电都花在真正的计算上。

## 词元：大模型时代的“最小计费单位”

大模型不按“字”计费，而按 token（词元）计费。理解这一点，是看懂词元经济的前提。

- 一个 token 是一段文本被切分后的最小单元。中文里，一个汉字通常会被拆成 1—2 个 token；英文中，一个常见单词大约也是 1—2 个 token。模型不是一次读一个字，而是把输入切分成 token 序列后处理。
- 商业上，token 同时出现在输入端和输出端。输入 token 负责理解，输出 token 负责生成。生成往往更贵，因为要逐个预测、多次往返计算。
- 很多大模型 API 报价会拆成“每百万输入 token”和“每百万输出 token”。输出 token 单价通常是输入的 3—5 倍。原因很直接：输出时模型需要一步步自回归生成，算力占用更高、显存带宽压力更大。

换句话说，token 把抽象智能变成了可计量、可比较、可交易的单位。这也是词元经济能成立的基础。

## 从瓦特到词元：商业逻辑是怎么迁移的

以前的算力生意，像租房；现在的词元生意，更像按用量加油。这个变化不是换了个名词，而是商业模式发生了迁移。

- 旧模式：按机柜、按月、按带宽峰值出租。客户即使不用满，也要为冗余买单。
- 过渡模式：按 GPU 小时出租。算力开始有时间维度，但仍然不是直接为“智能结果”付费。
- 新模式：按 token 计费。开发者只为实际生成内容买单，门槛降低，容易从小规模验证起步。

这个迁移把能源成本、硬件折旧、模型能力全部压缩进一个 token 单价里。对用户来说，token 是“智能零售价”；对厂商来说，token 是“算力批发价 + 模型毛利 + 服务溢价”的最终出口。

因此，词元经济的利润空间，很大程度取决于底层算力是否便宜。绿色算力不是道德口号，而是成本工程。

## 为什么词元经济必须靠绿色算力托底

词元经济放大了推理需求，而推理需求又放大了电力消耗。这是两者最深的耦合点。

- 训练耗电像短跑，推理耗电像长跑。一次模型训练可能消耗几百万千瓦时，但上线后每天亿万次调用会持续累加。词元经济一旦普及，推理总能耗可能超过训练。
- 生成一个 token 的能耗看似微小，但量级会被调用次数放大。若一个应用每天产生 10 亿 token，那么每 token 能耗降低一点点，全年电费与碳排放差异会非常可观。
- 云厂商的绿色算力优势会直接转化为词元定价权。液冷降低 PUE、绿电降低单位电价、自研芯片降低每 token 焦耳数，这些最终都体现在 API 价格和毛利里。

所以，绿色算力不是数据中心的外挂滤镜，而是词元经济能否长期成立的成本底座。

## 冷思考：别把词元经济变成新的耗能泡沫

词元经济也不是只有好处，有几个问题值得先冷静看看。

1. 能效提升可能带来更多消耗。经济学里有一个“杰文斯悖论”：效率越高，使用量反而越大。单位 token 成本下降，会刺激更多人调用大模型，总能耗未必减少。
2. token 口径并不统一。不同模型的 tokenizer 不同，同样一段中文，A 模型可能切成 800 token，B 模型切成 1200 token。只比单价，容易掉进出题陷阱。
3. 绿色标签需要细看。绿电证书、碳中和承诺、PUE 统计口径都可能存在水分。真正能证明绿色算力的，是可核验的实时绿电匹配、透明披露的 PUE 和供应链碳排放。

## 三条实用建议

- 看成本：采购大模型服务时，别只盯每百万 token 标价。把输出/输入比例、上下文长度、并发限流、错误重试一并算入综合成本。
- 优化用量：能缓存就缓存，能压缩提示词就压缩，能用小模型路由就不要什么都上大模型。降低 token 消耗，本身就是最直接的绿色算力。
- 建立预算：给团队设定“每功能每用户 token 预算”与“单位 token 碳预算”。把能耗和产出一起看，而不是只追求生成越多越好。

绿色算力决定词元经济能不能便宜，词元经济决定绿色算力能不能被规模买单。看懂这条链路，比追逐单个热搜更重要。
