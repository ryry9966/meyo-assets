最近一组数字在开发者圈里刷了屏：DeepSeek 披露，其 7 个月营收达到 4.75 亿元，API 业务毛利率高达 82.9%。很多人第一反应是“AI 终于赚钱了”，但如果只停留在“暴涨十倍”这个结论上，很容易把财务口径、技术成因和商业可持续性混在一起。这组数据真正值得拆的，不是“涨了多少”，而是“凭什么毛利这么高”，以及“这种毛利能不能长期站住”。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/a9aa5690b531b089.png)

## 先把数字放回统计口径里

讨论任何财务数据之前，先要避免把不同口径混为一谈。

- **7 个月 4.75 亿元，不等于公司全部收入**：目前公开信息更多指向模型推理、API 开放平台及相关商业化收入，而非集团所有业务的总营收。
- **API 毛利是“收入减去直接成本”**：直接成本通常包括 GPU/算力租赁、网络带宽、存储、推理集群电力和基础运维，不包括研发人员工资、模型训练费用、市场推广和管理成本。
- **“营收暴涨十倍”需要看基数**：如果上一年同期基数很低，十倍增长并不稀奇；真正值得关注的是增长是否来自可持续的客户复购，而不是一次性项目或补贴窗口。
- **统计周期和确认口径会显著影响结果**：预充值、代金券、免费额度、渠道结算、关联交易等都可能改变营收和毛利的账面表现。

换句话说，82.9% 的 API 毛利确实是重要信号，但它更像“推理业务的直接算力效率”指标，而不是公司整体盈利能力的完整答案。

## 82.9% 毛利怎么来的：三个技术账

API 毛利率能接近 83%，说明推理服务的直接算力成本被压得很低。这不是单一技巧，而是几层技术叠加的结果。

### 1. 稀疏激活与缓存复用

DeepSeek 模型采用 MoE 架构。推理时，每个 token 并不会激活全部参数，而只激活其中一部分专家模块。这意味着：

- 单次推理所需算力远低于同规模稠密模型；
- 高频输入可以命中缓存，减少重复计算；
- 前缀缓存、KV 缓存复用能大幅降低长会话、文档分析的边际成本。

举例来说，如果用户连续追问同一篇长文档，模型不必每次都重新计算全部上下文。缓存命中率越高，单位收入的算力消耗越低，毛利自然上升。

### 2. 批处理与动态调度

API 厂商不是来一个请求就单独占一张卡，而是进行动态批处理。

- 多个请求被合并成一个批次，提升 GPU 利用率；
- 不同优先级的请求进入不同队列，低延迟任务和高吞吐任务分开调度；
- 闲时段承接离线批处理任务，把空闲算力变成收入；
- 通过请求压缩、输出长度控制、停止词优化，减少无用 token 生成。

这些做法在云服务里并不新鲜，但在大模型 API 场景中，对毛利率的影响非常直接。同样的卡，利用率从 30% 提升到 70%，收入可能翻一倍，而电费和折旧并不会同比例上升。

### 3. 自建推理集群与低精度部署

毛利高还有一个容易被忽略的原因：模型部署方式。

- 自建集群可以绕开云厂商较高的资源溢价；
- FP8、INT8 等低精度量化在可接受精度损失内，大幅提高吞吐；
- 推理集群采用更贴近模型结构的网络拓扑，减少通信瓶颈；
- 长期运行的稳定负载更容易做容量规划，避免突发扩容带来的高成本。

这些技术动作叠加起来，才把直接算力成本压到较低水平，让 82.9% 的 API 毛利成为可能。

## 营收十倍增长背后的商业逻辑

技术只是成本端，收入端还有另一套逻辑。

- **开源模型带来巨大流量**：开放权重让开发者可以自行验证能力，降低接入门槛，也间接把开源社区转化为潜在 API 客户。
- **价格锚点明确**：当模型能力接近第一梯队、价格却明显更低时，价格敏感型客户会优先迁移。
- **API 的标准化程度高**：对开发者而言，切换模型服务比替换基础设施容易，只要兼容接口和稳定性足够，迁移成本低。
- **开发者生态形成复购**：从测试、小规模接入到生产环境扩容，API 客户的用量增长通常比传统企业软件更快。
- **云厂商和行业客户同时存在**：一部分客户需要完全托管的 API，另一部分客户基于开源权重做私有化部署。两者并不完全冲突，反而扩大了整体影响力。

需要注意的是，增长快并不意味着利润高。很多 API 客户对价格高度敏感，一旦出现更具性价比的模型，迁移也可能很快。

## 别被高毛利误导：三个冷思考

82.9% 的 API 毛利很漂亮，但它不是公司净利率，更不能直接等同于“AI 商业模式已经跑通”。

### 1. 毛利之上还有大量费用

- 模型训练成本尚未完全摊入 API 业务；
- 研发人员、数据治理、安全合规、市场推广等费用极高；
- 硬件折旧周期短，下一代模型可能要求新的集群投资；
- 免费额度、开发者补贴、促销活动会拉低实际净收入。

### 2. 高毛利不等于高壁垒

- 开源权重让客户随时可以选择自部署；
- 云厂商可以绑定算力、存储和安全产品，形成整体价格优势；
- 模型能力差距缩小后，API 服务容易陷入价格竞争；
- 高毛利业务可能被云厂商视为引流品，以更低的毛利甚至亏损销售。

### 3. 收入增速需要看长期留存

- 十倍增长很容易出现在早期阶段；
- 关键指标是客户留存率、净收入留存率、推理请求复购率和客户集中度；
- 如果大量收入来自少数大客户，议价压力会随规模上升；
- 市场从“尝鲜”转向“生产环境”，稳定性、安全与合规成本会显著增加。

## 给开发者和创业者的实用建议

如果你正在考虑接入大模型 API，或者评估 AI 业务的财务健康度，可以关注以下三点。

### 1. 别只看单价，算总拥有成本

- 把推理延迟、首字响应、上下文长度、并发限制和错误率都纳入评估；
- 对不同任务分别测算：短问答、长文档、代码生成、批处理，成本结构完全不同；
- 优先测试缓存机制是否适合自己的产品形态。聊天类、文档类产品的缓存收益通常更高。

### 2. 把毛利拆到“直接算力成本”以下

- 了解厂商的毛利口径，是否包含推理集群折旧、网络费用、技术支持；
- 关注模型是否采用 MoE、量化、批处理等技术，这些会影响价格的可持续空间；
- 对自部署方案做成本测算，对比 API 在不同请求量下的盈亏平衡点。

### 3. 用三个指标判断 AI 商业模式的健康度

- **第一，毛利率与净利率之间的距离**：如果毛利很高、净利率长期为负，说明研发和销售费用仍占主导；
- **第二，单位推理成本下降曲线**：这是模型厂商的核心竞争力，比单次价格更重要；
- **第三，客户留存与用量增长**：收入增长只有建立在稳定复购上，才不是一次性红利。

大模型 API 的竞争已经进入“细看账本”的阶段。对开发者来说，高毛利往往意味着供应商有降价空间，也意味着服务稳定性和持续迭代可能更强；但对投资判断来说，毛利只是起点，不是终点。
