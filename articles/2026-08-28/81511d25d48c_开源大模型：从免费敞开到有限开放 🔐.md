最近，不少开发者发现，自己平时挂在嘴边的“开源模型”，现在开始查户口了：有的要看你月活有没有超限，有的只许研究不许商用，有的干脆把 API 的免费额度一砍再砍。36氪那篇《开源模型们不想让所有人都免费使用了》点破了一个趋势：过去那种“权重一放、全宇宙随便用”的日子，正在收窄。与其抱怨，不如先把这件事拆开看看：开源到底开的是什么？许可证怎么变？背后是什么逻辑？我们又该怎么选型？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/10ccc1375abe7eea.png)

## 先分清：“开源”和“免费使用”从来是两件事

很多人把开源当成免费午餐，其实开源运动从 1998 年 OSI 提出定义开始，强调的就是“自由使用、修改、分发源代码”，并没有承诺“任意商业用途且不受任何限制”。

- **传统开源许可证**：Apache 2.0、MIT、BSD 这类宽松许可证，允许商用、修改、再分发；GPL 也允许商用，但要求派生作品同样开源。它们解决的是代码层面的自由。
- **大模型领域的“开源”多数是“开放权重”**：只把训练好的权重文件放出来，训练数据、代码、完整训练方法不一定公开。所以严格说，很多模型不是 OSI 意义上的开源。
- **既然不是传统开源，厂商就有权在权重使用许可里加商业门槛**。比如 Meta 的 Llama 系列一直叫“open source”，但它的社区许可并不是 OSI 批准的标准开源许可证。
- 所以“开源模型不想让所有人免费使用”这个说法，更准确地说，是“开放权重模型开始调整许可证边界”。

## 许可证正在发生什么变化？

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/821013e289875c33.png)

近两年，几个代表性模型许可证都在从“宽松”向“有条件”挪动：

- **Meta Llama 3 / 3.1**：社区许可允许免费商用，但设了一条：如果相关产品或服务的全球月活用户（MAU）超过 7 亿，就需要单独与 Meta 谈商业授权。这个数字对绝大多数团队没影响，但直接卡住的是超大规模云平台、社交和硬件厂商。
- **Mistral 的 Codestral**：早期 Mistral 7B 是 Apache 2.0，但 2024 年发布的代码模型 Codestral 使用 MNPL（非生产许可证），只允许研究和测试，明确禁止商用。后续 Mistral Large 2 也采用了研究许可，商业使用需单独签约。
- **部分国产开源模型**：开始区分“研究用途”和“商业用途”，或者对超过一定规模的企业要求申请授权。虽然很多小模型仍用 Apache/MIT，但旗舰大模型更倾向加上 MAU、并发或行业限制。
- **API 与权重解耦**：DeepSeek、通义等依然开放权重，但 API 免费额度不再无限，调用价格和限流成为新的调控手段。这本身不是许可证变化，但让“免费使用”体感大打折扣。

这个趋势的核心不是“关闭开源”，而是把“免费开放”变成“分级开放”：小开发者和研究者几乎不受影响，平台型、超大规模商业化需要额外成本。

## 为什么厂商开始“收口”？四个底层原因

- **成本回归**：训一个百亿参数模型，单次训练成本可能数百万到上千万美元。开放权重可以换生态，但如果所有云厂商都免费承载并转售，原厂很难靠 API 或云合作回收成本。许可证设限，等于给超大流量场景留一个“商业谈判入口”。
- **竞争防御**：大型云厂商可以把开源权重直接包装成托管 API，甚至贴自己的品牌售卖。原厂如果不限制，就会变成给竞争对手免费供货的上游。
- **安全与合规**：生成式模型容易被滥用，深度伪造、诈骗、自动生成违规内容等风险高。负责任 AI 许可（RAIL）会把“不能用于武器、监控、违法活动”等条款写进许可证，限制使用领域，也是法律风险对冲。
- **生态策略**：先开放权重吸引开发者，形成工具链和社区心智，再通过“有条件免费”筛选出可付费的企业客户。这有点像开源软件的“Open Core”模式：核心能力开放，高级商业场景收费。

## 对开发者和企业意味着什么？

- 对个人开发者、科研团队、小公司：基本无感，MAU 上限和商业限制很难触及，继续用即可。
- 对做 SaaS、云服务、开放平台、大型流量 App 的团队：必须把许可证审查纳入架构评审。一次“顺手用开源模型”可能埋下后期被迫换模型或补授权费的坑。
- 特别要看三个字段：可否商用、MAU/收入阈值、是否有领域限制。不要只看到 GitHub 标着 “open source” 就默认万事大吉。
- 云厂商、芯片厂商、手机厂商等生态位，通常需要提前接触模型原厂，评估是否需要单独商业授权，避免产品上线后才被动。
- 如果业务需要 100% 确定性，可以优先选 Apache 2.0、MIT 或权重完全开放的模型；如果用了“研究许可”模型做商业产品，等于法律风险自担。

## 冷思考与三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/ee30d506f53ea422.png)

开源运动的精神没有消失，但商业现实已经变化。开放权重只是技术分发方式，它的定价权仍然在模型方手里。过去两年，模型厂商把“开源”当成营销和生态武器，暂时牺牲短期收入；当竞争和成本压力上升，许可证自然会重新成为调节阀。

三条建议：

1. **读许可证别只看标题**：花 30 分钟看“Commercial use”“MAU threshold”“Usage restrictions”三个段落，比看十篇评测都实在。
2. **企业选型留 Plan B**：不要把核心产品绑在单一“有条件开源”模型上。至少准备一个完全宽松许可证的替代方案，防止授权变更导致业务中断。
3. **把开源模型当“会变化的公共品”，而不是永久免费的公共设施**：它可以免费进入，但商业规模越大，越需要把授权成本、合规成本算进 TCO。

模型可以继续开放，但不等于所有人都能零成本永远薅羊毛。看懂许可证，才能既不踩坑，也用得踏实。
