最近科技圈有个耐人寻味的消息：Meta 似乎也想做一个类似 Manus 的通用智能体，但产品被曝底层调用的是 Anthropic 的 Claude，而不是自家开源的 Llama。很多人第一反应是“小扎不死心，自研了个寂寞”。如果只看标题，确实有点黑色幽默；但稍微拆开看，这件事其实正常到不能再正常——智能体框架与底层模型，本来就可以是两回事。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/87dc61800d029a0f.png)

## 一、Manus 到底“自研”了什么

Manus 本身不是一个大模型，而是一个通用智能体产品。它的工作方式更接近“项目经理”：接到任务后拆解步骤，调用浏览器、代码解释器、文件处理工具，最终交付结果。

- 底层模型可以替换，早期公开信息里就提到会调用 Claude、GPT 等模型。
- 换句话说，Manus 的核心壁垒在任务规划、工具编排和执行闭环，而不是从头训练一个模型。
- 类比：自研智能手机，不代表必须自研屏幕、芯片、操作系统里的每一行代码。
- 很多人被“自研”两个字带偏，以为所有环节都该是原创。实际上，软件行业的常态是：核心体验自己做，通用能力用现成。

## 二、“自研”这个词，很容易被误读

在 AI 行业，“自研”至少有三层含义：自研底层大模型、自研智能体框架、自研产品与工程链路。Meta 的确有自研 Llama 系列模型，但做智能体时仍可能选择第三方模型，因为产品目标不是“炫技”，而是把任务完成率做上去。

- 类似的例子：苹果自研芯片，但 iPhone 里仍有三星、索尼、高通等供应商的元器件。
- 特斯拉自研自动驾驶算法，但早期也用英伟达芯片。
- 所以，“自研了一个 Manus，但模型用 Claude”这句话，翻译过来更准确的是：自研了智能体框架和产品，但模型底座选用了 Claude。
- 这并不丢人，反而说明团队清楚优先级：先把产品跑通，再逐步替换底座。

## 三、为什么偏偏是 Claude，而不是自家 Llama？

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/15b368650e3a47ac.png)

这个选择背后，不是简单的“外来的和尚好念经”，而是 Agent 对模型能力有非常具体、非常苛刻的要求。

- 第一，Agent 对模型的“工具调用”能力要求极高。模型需要稳定输出结构化参数、按顺序调用函数、在出错时重试。Claude 系列在这类任务上的口碑和基准表现都相对靠前。
- 第二，长上下文与指令遵循。通用 Agent 经常需要带着大量中间步骤、网页内容、代码片段继续工作。Claude 的长上下文处理能力和低“跑偏率”让它更适合做执行层。
- 第三，Llama 开源且可自部署，但工具调用需要更多工程适配。开源模型的优势是可控和便宜，劣势是开箱即用的稳定性、API 生态、安全对齐可能不如闭源成熟。
- 第四，商业上快速验证。Meta 想追通用 Agent，与其等内部模型团队把工具调用调到理想状态，不如先用成熟模型跑通产品闭环，再逐步替换底座。

可以这样理解：模型能力决定 Agent 的下限，框架能力决定 Agent 的上限。当前阶段，Claude 是那个更稳的下限。

## 四、Agent 竞赛：模型是底座，框架是放大器

![img3](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/b95f12c2b40b84c3.png)

通用智能体的竞争不止拼模型参数，更拼任务规划、记忆管理、沙箱安全、错误恢复和工具生态。如果把模型比作发动机，Agent 框架就是变速箱、底盘和驾驶辅助系统。发动机可以换，整车体验才是用户感知到的。

- Meta 真正的优势可能不在单点模型，而在分发：Instagram、WhatsApp、Quest 等产品里嵌入 Agent，能触达数十亿用户。
- 但前提是执行可靠。Claude 只是当下合适的底座之一，未来 Llama 追平后可以替换，这正是框架与模型解耦的好处。
- 这次“用 Claude”更像一个过渡策略：先让用户用起来，积累反馈，再决定是否把底座换成自研模型。
- 对行业来说，这也会加剧开源与闭源模型的错位竞争：闭源模型抢 Agent 执行层，开源模型抢自部署、隐私敏感场景。

## 五、冷思考：别被“自研”标签带偏

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/1b41c4d5943f5c6e.png)

这件事给开发者、用户和行业都提了个醒：不要用“是否自研”作为唯一判断标准。

- 对开发者：先跑通闭环，再谈全栈自研。选模型时重点看“工具调用准确率”和“长任务完成率”，而不是只看跑分。
- 对用户：判断一个 Agent 产品，别只看它是不是“自研”，要看实际完成任务的成功率、隐私处理方式、以及出错时是否可解释。
- 对行业：开源模型与闭源模型在 Agent 生态里会长期共存。自研框架 + 外部模型是常见过渡策略，没有必要用“不够纯粹”去否定一个产品。

![img4](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-28/6d5bf220f204cabc.png)

Meta 想复刻 Manus 并不奇怪，通用 Agent 是下一个入口竞争点。用 Claude 不代表 Llama 失败，只是说明当前 Agent 对模型能力的要求非常具体、非常现实。真正值得关注的，不是谁用了谁的模型，而是智能体框架能否把模型能力稳定放大为生产力。等到 Llama 在工具调用和长任务执行上追平那天，再换回来也不迟。
