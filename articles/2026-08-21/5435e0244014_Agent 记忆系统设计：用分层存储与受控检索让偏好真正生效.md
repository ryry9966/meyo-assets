# Agent 记忆系统设计：怎么让 AI 助手真正记住你的偏好

在 OpenClaw 这类 agent runtime 里跑自动化任务时，经常会遇到一个尴尬：你在项目里反复说“输出用中文、日志不要贴 token、部署前先 dry-run”，但下次新会话它还是会按默认习惯来。于是很多人开始往 system prompt 或 memory.md 里堆偏好，结果上下文越来越长，检索出来的内容也与当前任务无关，模型遵循度反而下降。

这里的关键不是“记住更多”，而是让记忆在正确的时刻以正确形式进入上下文。下面是我在 OpenClaw + MCP 工具链里实践的一套轻量记忆设计，不依赖复杂平台。

## 一、先分层，别把偏好写成一团

我习惯把记忆分成三部分：

- **profile.yaml**：稳定身份与全局默认，如用户名、常用语言、默认工作目录、代码风格。
- **memory.jsonl**：条目化记忆，每条有 id、content、type、scope、confidence、tags、created_at、updated_at、last_accessed_at、source、status。
- **review.jsonl**：隐式提炼出的候选记忆，未确认前不直接生效。

这样设计的原因是：不同偏好的生效范围不同。比如“我喜欢用 ruff 而不是 black”只在 Python 项目里重要；“所有对外消息用英文回复”是任务级偏好。混在一起会让 Agent 误判。

## 二、检索与注入：只给当前任务需要的记忆

全量注入不可靠。实际做法是：

1. 在 session 启动或工具调用前，基于当前任务生成 query。
2. 先做关键词过滤（例如任务里有 `python`、`deploy`），减少候选量。
3. 再做向量检索或相似度匹配，过滤 scope，取 top 3-5 条。
4. 命中的记忆以紧凑 block 注入 system prompt 后段，而不是全文粘贴。

示例注入块：

```text
memory block:
scope=python confidence=0.9
- 格式化使用 ruff，不使用 black。
- 任何 subprocess 调用必须带 timeout。
```

这个 block 比散落在长文里更容易被模型遵循。关键词过滤 + 阈值控制比直接上向量库更有效，尤其当记忆条数不超过几百条时。

## 三、更新机制：显式优先，隐式只做候选

记忆写入分两条路径：

- **显式更新**：用户明确说“记住我以后部署前先跑一遍 preflight”，直接 upsert 到 memory.jsonl，confidence 设 0.9 以上。
- **隐式提炼**：后台 agent 或定时任务从 session 摘要中提取候选，比如用户常说“我不喜欢这么长的日志”，先写 review.jsonl，confidence 0.3-0.5，下次重要任务前询问确认。

这个区分很重要。很多记忆系统一做隐式更新就把用户随口一句话变成永久偏好，导致后面冲突越来越多。候选队列加一个确认步骤，能避免记忆污染。

## 四、用 MCP 工具包起来

在 OpenClaw 里，我更推荐把记忆做成 MCP server 或插件工具，而不是只塞 system prompt。提供这几个方法：

- `memory_search(query, scope?)`
- `memory_upsert(item)`
- `memory_archive(id)` 或 `memory_decay()`
- `profile_get(section)`

Agent 在需要时自己调用，比启动时固定注入更灵活。多插件/多 Agent 也能共用同一个 provider，避免各存各的。

## 五、踩坑点

1. **偏好变成硬规则**：用户说“我不喜欢 Perl”，但某次任务必须用 Perl。如果记忆没有 scope 和 override 标记，Agent 可能拒绝执行。给偏好加 `allow_override: true` 会安全很多。
2. **检索噪声**：向量检索不设阈值或返回 10 条，结果与任务无关，模型反而被带偏。建议先关键词过滤，阈值约 0.55-0.65，top 3-5 条。
3. **频繁写入**：隐式提炼不加确认，用户说“下次可以试试”也写成记忆。用 review 队列和低 confidence 控制。
4. **多源冲突**：不同插件各自存偏好，A 说 python 3.11，B 说 3.12。统一 memory provider，条目带 source 和 version，冲突时保留旧值、记录来源。
5. **隐私泄漏**：个人偏好被注入到无关任务或共享 prompt 中。给敏感记忆加 scope=private，检索时校验。

## 六、可复用建议

- 最小实现从 `profile.yaml + memory.jsonl + 关键词 grep` 开始，不要一上来就接向量库。
- 字段设计尽量完整，尤其是 scope、confidence、last_accessed_at、source。
- 加 TTL 或访问衰减：长期不用的偏好自动归档或降权，避免记忆库膨胀。
- 准备 10-20 组用户指令来测试检索命中率和注入后的遵循度。

## 总结

Agent 记忆系统的目标不是把用户所有话都存下来，而是让正确的记忆在正确任务前进入上下文。分层存储、受控检索、显式更新优先、冲突处理，这四件事比“更大的上下文窗口”更实在。先在 OpenClaw 里跑通一个最小 store + MCP 工具，再考虑升级成 RAG 或细粒度权限，通常就能解决大部分“它还是没记住我偏好”的问题。
