## 背景

在 OpenClaw、MCP 工具链和自动化插件里，外部 API 是大多数 Agent 的“手和脚”：查天气、搜文档、调内部接口、发消息。API 抖动、限流、超时、宕机是常态，不是事故。问题在于：Agent 不像脚本一样失败就退出，它会拿着工具返回的内容继续推理。如果错误没有被结构化处理，模型很容易把异常堆栈或半截 JSON 当成真实答案，继续往下执行，导致错误动作扩散。

## 问题

常见故障路径：工具调用超时，整个 Agent 卡住几分钟；HTTP 500 的 HTML 错误页被丢给模型，模型开始“编造”原因；遇到 429 无限重试，反而把上游打挂；降级用了缓存数据，但下游链路完全不知道这不是实时结果。这些都是缺少统一的错误恢复策略造成的。

## 做法 / 步骤

### 1. 在工具边界做错误分类

不要所有异常都一视同仁。至少要区分：

- 可重试错误：429、502、503、504、连接超时、网络抖动
- 不可重试错误：400、401、403、404、业务校验失败
- 超时：连接超时和读取超时要分开，前者通常可以快速重试，后者可能说明上游慢，需要更长退避
- 限流：如果响应带 `Retry-After`，优先尊重它，不要盲目重试

### 2. 统一工具返回结构

给所有外部调用封装一个标准返回：

```json
{
  "ok": true,
  "data": {},
  "error": null,
  "meta": {
    "source": "live|cache|fallback",
    "retries": 0,
    "latency_ms": 123
  }
}
```

这样 Agent 可以明确知道数据来自实时、缓存还是降级，而不是靠猜。即使失败，`error` 里也放精简后的 `code` 和 `message`，不要把整个堆栈丢进去。

### 3. 实现超时、重试和退避

给每个外部 API 调用设置硬超时，比如 8~15 秒，避免 Agent 被一个慢接口卡死。重试最多 3 次，指数退避加随机抖动，比如 `0.5s -> 1s -> 2s`，抖动范围 ±30%。这样可以避免多个并发任务同时重试造成新的洪峰。

### 4. 降级与兜底

读接口可以降级到本地缓存、上次成功结果或备用数据源，但必须标记 `source: cache/fallback`，并设置 TTL。写接口不能随便降级：如果超时返回但实际已执行成功，重试可能造成重复扣款或重复下单。写操作要引入幂等键，失败就快速失败，并标记为 pending，等待后续确认。

### 5. 熔断保护

连续失败达到阈值（比如 5 次）后，直接短路一段时间（如 30 秒），不再访问上游。半开状态下放一个探测请求，成功就恢复，失败继续熔断。单机用内存计数即可，多实例用 Redis 等共享状态。

### 6. 让 Agent 能感知并决策

工具描述里写明可能的失败模式和 fallback 行为。系统提示中明确错误处理规则：遇到限流等可重试错误时等待重试，遇到不可重试错误时停止或转人工。错误信息要给出可行动的线索，而不是让模型自由发挥。

### 7. 可观测性

记录每次外部调用的状态码、耗时、重试次数、是否降级、熔断状态。最好为每个关键依赖建独立健康探针，失败时主动告警，而不是等 Agent 任务失败后才被动发现。

## 踩坑点

- **无限重试**：没有上限的重试会放大上游压力，甚至把上游彻底打挂。
- **没有抖动**：同步重试风暴会瞬时打爆服务，退避必须加 random jitter。
- **把限流当瞬时故障**：429 反复重试只会更糟，要尊重 `Retry-After` 或直接熔断。
- **超时设太长/太短**：太长 Agent 卡死；太短误判频繁，产生大量无效重试。
- **缓存半成功结果**：写操作超时后实际已成功，重试导致重复副作用，必须靠幂等键解决。
- **降级不标记来源**：后续链路把缓存当实时数据，做出错误判断。
- **把异常堆栈直接喂给 LLM**：模型会开始编造原因和解决方案，后期排障更痛苦。

## 可复用建议

做一个通用的 `safe_api_call` 包装器，内置 timeout、retry、fallback、circuit breaker 和结构化日志。所有外部工具统一走这个入口。错误码和重试策略放配置文件，不要硬编码。读接口和写接口分开策略：读可降级，写要幂等。MCP 工具返回统一 `ok/data/error/meta` 契约，让 Agent 有稳定的预期。定期做故障演练：手动关闭外部 API 或 mock 故障，观察 Agent 是否按预期降级而不是乱来。

## 总结

外部 API 挂掉不是偶发事故，而是系统常态。错误恢复不是加个 `try/except`，而是从超时、重试、熔断、降级、结构化错误到可观测性的一整套策略。对 Agent 来说，错误信息的结构比堆栈更重要。给模型可行动的线索，比让它自己猜更可靠。
