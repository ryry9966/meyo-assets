多模态版 DeepSeek “长眼”了。最值得说的不是它能识别猫和狗、能读截图，而是公开报道里的一个数字：处理 1000 张图大约只要 1 块钱。也就是说，单张成本进入“厘”级。这个定价像极了当年文本模型价格战的开场，但它发生在视觉理解上，意义不太一样。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-21/3f8bceafd3b152b7.png)

## 一、先别急着喊便宜：多模态“长眼”到底在看什么
多模态模型不是真的“看”图，而是把图变成 token，再让语言模型去理解。这个过程通常分三步：
- 切块：把一张图按网格切成若干 patch，例如 1024×1024 的图按 16×16 patch 走，理论上会得到 4096 个小块。
- 编码：用视觉编码器把每个 patch 映射成一串向量，相当于给每个小块生成“视觉词”。
- 拼接：这些视觉 token 与文字 token 一起进入 Transformer，模型再输出答案、摘要、提取结果。

所以，API 计费的核心不是“张数”，而是 token 数。一张小图可能只有几百 token，一张高分辨率扫描件可能上万 token。所谓“1000 张图 1 块钱”，大概率对应的是常见分辨率、以 OCR/轻理解为主的场景，而不是任意复杂图像都可以无限报销。

## 二、拆账：1000 张图为什么能压到 1 元
这个价格不是魔法，而是三层节省叠加出来的。

1. **token 单价本身已经被打下来**
   2024 年以来，DeepSeek 在文本模型上走通了低成本推理路线。尤其是 MoE（Mixture of Experts）架构，每次推理只激活部分专家参数，算力消耗远低于同规模稠密模型。MLA 等注意力优化又进一步压缩了缓存。这些能力复用到多模态端，视觉 token 的单价天然就低。

2. **视觉编码器做了“省 token”设计**
   图像 token 通常比文字贵，因为它的数量多、编码器也吃算力。可行的优化包括：
   - 动态分辨率：小图少切，大图多切，空白区域合并；
   - patch 合并：把相邻 patch 聚合，减少进入 LLM 的 token 数；
   - 低分辨率优先：对票据、截图、合同等任务，1024px 以下往往够用。
   如果一张图平均压到 600 token，1000 张就是 60 万 token。按照百万 token 1～2 元量级计算，千张成本确实可以落在 1 元左右。

3. **商业上主动把利润打薄**
   视觉理解是 Agent、文档处理、RPA 的入口能力。入口越便宜，越容易让开发者先接入、先跑量，后续再延伸到更复杂的高价值任务。这也是典型的基础设施式补贴逻辑。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-21/98afd4fc7b5700d1.png)

这里要提醒一句：低价不等于所有图都是这个成本。高分辨率、长图、多页 PDF 拆出来的 token 会指数级增加，实际账单可能远高于“千张 1 元”的直觉锚点。

## 三、便宜不是万能：一张能力边界清单
多模态便宜之后，最容易被误用的地方，是把“能看图”当成“能精确完成任务”。目前更适合的场景：
- 票据、卡证、合同、发票的信息抽取；
- 截图、PPT、图表、手写表单的 OCR 与摘要；
- 电商商品图分类、内容审核初筛；
- RAG 知识库的图片预处理。

需要谨慎的场景：
- 需要像素级定位的版面还原，比如精确框选表格线、印章位置；
- 医学影像、工业缺陷等高准确率要求任务；
- 长文档、复杂嵌套表格，可能出现漏读、顺序错乱；
- 对图片中的坐标信息有强依赖的任务，模型可能只给近似结果。

判断框架很简单：把它当成“读图实习生”，速度快、成本低，但涉及关键字段时，仍建议加规则校验或人工复核。

## 四、行业信号：价格战从文本烧到视觉
多模态降价并不是孤立事件。过去两年，文本模型 API 价格已经经历了一轮陡峭下降。2024 年 5 月，DeepSeek-V2 把百万 token 级别的价格压到 1 元上下，随后国内外多家厂商跟进。现在同样的路径正在视觉理解上重演。

这背后的原因也清晰：
- 推理优化从文本溢出到视觉：MoE、量化、蒸馏、缓存等技术越来越成熟；
- Agent 需要“看屏”：电脑操作、手机 GUI 自动化、浏览器填表、智能客服都要求模型具备屏幕理解能力；
- 文档数字化规模太大：发票、合同、报表、物流单、病历等非结构化图片是巨大的存量市场，低价是撬动它的前提。

## 五、收尾：3 条冷思考与实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-21/be6306452fe4753f.png)

1. **先做 100 张真实业务图的 A/B 测试。**
   别被“千张 1 元”锚定。用自己的发票、截图、合同去测 token 消耗、准确率、漏读率，再算真实成本。不同分辨率、不同背景的图，成本可能差 3～5 倍。

2. **把多模态识别当“预处理”，不做最终裁判。**
   对金额、日期、身份证号、合同条款等关键字段，最好在后面加一层规则校验或人工抽检。模型负责把非结构化图片变成结构化字段，人负责守住不可逆的决策。

3. **控制 token 膨胀，优先裁剪和压缩。**
   长图先切块，彩色扫描件可先转灰度或降噪，无关背景尽量裁掉。高分辨率不一定带来准确率提升，但一定会带来 token 和成本上升。

多模态版 DeepSeek “长眼”的真正意义，不在于突然看见了什么，而在于它把“看见”这件事的成本，拉到了很多业务可以规模化的临界点。对开发者来说，这既是机会，也是一道需要冷静计算的工程题。
