# Agent 记忆系统设计：让 AI 助手真正记住你的偏好

## 背景

多数 Agent 至今仍是“金鱼记忆”：每次对话结束，关于你习惯、工具偏好、项目约定的知识就消失殆尽。即使把历史消息硬塞进上下文，成本高不说，信息密度也低，很容易在长链条任务里被截断或遗忘。

在 OpenClaw + MCP 的自动化实践里，我们希望 Agent 真的像一个私人助手——跨会话记住你偏好简洁回答、默认使用中文、本周活跃在某个代码仓库、每次写完方案都要导出 Markdown。这不是一个“可以做”的锦上添花功能，而是让 Agent 从玩具进入生产的关键设计。

## 问题拆解

记忆不是简单存下对话记录。工程上需要拆成三层：

1. **用户档案**：长期稳定的偏好，如语言、回答风格、时间格式。
2. **任务上下文**：短期但重要的信息，如当前项目路径、正在调试的接口、约定的临时规则。
3. **习得经验**：从交互中总结的模式，比如“每次提交前你都要我跑一遍测试”。

这三层同时带来了四个核心难题：**何时提取**、**如何存储**、**怎么在合适时机注入**、**怎么处理记忆冲突与衰减**。下面用一套基于 MCP 的轻量化方案逐一解决。

## 做法 / 步骤

### 1. 定义记忆模型
用一个统一的 JSON 结构存储每一条记忆，字段包括：
- `type`：profile / context / experience
- `key`：唯一标识，如 `response_style`
- `value`：具体内容
- `confidence`：0-1，代表确定性
- `timestamp`：更新时间
- `source`：产生该记忆的对话摘要（脱敏后）

这种结构让检索和更新都能实现原子操作，也方便后面加遗忘机制。

### 2. 提取记忆
不强求模型默默总结。在 OpenClaw 里，让 Agent 拥有一个 `update_memory` 工具（通过 MCP 或本地函数）。工具描述里明确要求：
- 只有当用户**明确给出偏好信号**，或**行为改变已有偏好**时才调用。
- 输出必须符合上述 JSON schema，并附带简短解释。
- 禁止记录密钥、令牌、具体敏感内容。

典型 prompt 片段：
```
如果用户说“以后显示时区用 UTC+8”，则生成一条记忆，type=preference, key=timezone, value="UTC+8", confidence=0.95。
```
模型能很好地把这类强信号转成结构化记忆，而模糊主张可以设定较低的置信度，后续再确认。

### 3. 存储层：MCP 记忆服务
写一个 MCP 记忆服务，暴露两个工具：
- `memory_search(query, type, top_k=5)`：返回相关性最高的记忆。
- `memory_upsert(entries)`：按 key 做 upsert，自动更新 timestamp。

后端可以使用本地 SQLite 或直接一个 JSON 文件（初期足够）。如果团队有多 Agent 共享需求，换成 Redis 也不费力。MCP 封装让 Agent 和存储完全解耦，后续换存储甚至换成向量库检索，都不影响上游逻辑。

### 4. 注入时机
每次新建会话时，Agent 主动调用 `memory_search` 拉取当前用户的高置信度档案和近期任务上下文，作为系统提示词的前缀注入，例如：
```
[User Memory]
- prefers concise responses (confidence: 0.9)
- currently working on project "openclaw-hub" in /workspace
- uses markdown for reports
```
同时限制注入条目数量（通常 5–8 条，总 token 数<500），避免挤占工作窗口。

### 5. 冲突与遗忘
同一 key 的新记忆默认覆盖旧值，但如果新记忆置信度更低，则保留旧值并标记为“需确认”。遗忘可以通过定时任务实现：超过 30 天未访问且 type 为 context 的记忆自动降低置信度，低于 0.3 后软删除。用户也可通过 `/forget` 命令手动清理。

## 踩坑点

- **记忆膨胀与注入污染**：如果不加管控，几百条记忆会被强行塞进上下文，导致模型忽略真正重要的指令。必须做检索限制和浓度控制，而非全量注入。
- **提取噪音**：模型偶尔会把闲聊或假设性对话当成偏好，比如“我有时喜欢喝茶”，会生成 `drink_preference=tea`。解法是要求 `confidence` 低于 0.7 不自动写入，同时让用户能在 UI 里确认或丢弃。
- **隐私与持久化风险**：明文存储对话摘要可能泄露信息。Memory Store 只保存脱敏后的键值和来源摘要，不存储原始对话，并在 MCP 服务侧加一层过滤，屏蔽疑似密钥的正则。
- **跨会话一致性幻觉**：一旦记忆里记了错误的工具配置，Agent 会在后续任务里反复挣扎。提供清楚的手动修正路径（比如直接编辑记忆文件或 `/remember` 重写）比全自动修复更可靠。

## 可复用建议

1. **前期只抓强信号**。先让 Agent 记住显式的偏好声明，例如“记住我用中文回答”。自动推断可以后续再迭代。
2. **用 MCP 统一记忆接口**，避免每个插件自行实现一套存储。OpenClaw 生态已有的 MCP 工具可以直接挂载。
3. **给用户控制权**。提供 `/remember`、`/forget`、`/list_memories` 三个命令，让用户即时审查和修正。
4. **记忆要可审计**。每条记忆保留来源和更新时间，出问题时能快速回溯是哪个对话产生的。
5. **不要试图记忆一切**。Agent 记不住是常态，记忆系统的目标不是“全记得”，而是“关键时候不错”。

## 总结

Agent 记忆不是另一个要填满的知识库，而是一张不断修剪的偏好图谱。用 MCP 落地以后，跨任务的连贯性提升立竿见影，但工程上要保持克制：宁可少记，不可乱记；宁可给用户看到记忆做了什么，也不要暗箱操作。当你的 OpenClaw 助手在某天自动在报告末尾加上“（以 UTC+8 生成）”，你就知道这套设计真的起效了。
