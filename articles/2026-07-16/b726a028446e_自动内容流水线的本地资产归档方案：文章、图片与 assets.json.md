## 背景

在基于 OpenClaw 构建的自动内容发布流水线中，一次典型的任务会产出 Markdown 正文、若干配图以及一份记录生成元信息的 `assets.json`。多数实践者将“发布成功”视为终点，却忽略了将这些产物稳定落盘归档。这导致后期溯源、内容复用或审计时，只能在全量数据库中翻找，或者干脆丢失了关键上下文。

如果我们把流水线看作一条工厂产线，本地归档就是最后的装箱入库步骤——不复杂，但必须可靠。

## 问题

常见痛点包括：
- 文章与图片散落在临时目录或对象存储中，无结构化命名。
- 生成时使用的提示词、模型参数、时间戳等元信息在下次生成后就被覆盖。
- 离线阅读或二次编辑时，图片链接仍然是远程 URL，本地无法渲染。
- 缺乏版本记录，无法回看某一天产出的完整快照。

我们需要一套轻量、工程化的本地归档机制，不依赖外部服务，仅通过目录约定、脚本自动化和 Git 版本化管理实现可追溯的资产库。

## 做法与步骤

### 1. 确定归档目录结构

采用“日期 + 文章 slug”作为命名空间，示例：

```
archive/
└── 2025-03-18
    └── build-an-mcp-tool
        ├── index.md          # 最终文章（图片引用已改为相对路径）
        ├── images/
        │   ├── cover.png
        │   └── diagram.png
        └── assets.json       # 本次生成元信息
```

`assets.json` 中包含 `generatedAt`、`slug`、`title`、`model`、`prompt`、`totalTokens`、`images[]`（原始URL与本地路径映射）等字段，方便程序读取。

### 2. 在流水线“发布后”阶段插入归档任务

如果你的流水线使用 OpenClaw 的 Agent 编排，可以在最后一个 Agent 结束后触发一个 MCP 工具调用（例如 `local_archive`），传入最终内容与图片列表。如果流水线是纯命令行脚本，也可以直接调用一个 Node.js 归档模块。

关键步骤：
- 接收生成流水线产出的 Markdown 正文（已经是最终定稿）。
- 下载所有远程图片到 `images/` 目录，保留原始文件名或使用序号命名（如 `img-1.png`）。如果下载失败，重试最多 3 次，并记录失败日志。
- 替换 Markdown 中的图片引用：将 `https://...` 改为 `./images/xxx.png`，保证离线阅读正常。
- 根据生成上下文构造 `assets.json` 并写入。
- 可选：将整个 `archive/` 目录提交到 Git，并添加自动提交消息（例如 `archive: 2025-03-18 build-an-mcp-tool`）。

### 3. 封装为可复用脚本或 MCP 工具

将上述逻辑打包成一个通用工具，对外暴露最简单的接口。例如实现一个 `archive-assets` CLI：

```bash
npx archive-assets \
  --md ./output.md \
  --images-dir ./imgs \
  --meta assets.json \
  --dest ./archive \
  --slug build-an-mcp-tool \
  --timestamp 2025-03-18
```

如果集成到 OpenClaw MCP 服务中，Agent 可以直接调用 `archive_assets` 工具，参数包含 `markdownContent`、`imageUrls`、`meta`，工具内部完成下载、路径替换和写入操作，并向 Agent 返回归档路径供参考。

## 踩坑点

- **图片下载不稳定**：生成流水线中图床可能临时不可用，需实现指数退避重试，并将最终状态记录到 `assets.json` 以便追踪哪些图片未成功归档。
- **路径替换逻辑不严谨**：全局字符串替换容易误伤正文中非图片的 URL。建议使用正则匹配 Markdown 图片语法 `![alt](url)` 并精确替换。
- **并发写入冲突**：如果同一个 slug 在同一秒钟被多个流水线实例生成，可能发生文件覆盖。解决办法是使用 `slug-YYYYMMDDHHmmss` 作为目录名，或通过文件锁（如 `.lock` 文件）避免同时写同一路径。
- **大图占用磁盘 I/O**：某些生成模型会输出超高分辨率图片，建议在归档时增加压缩或尺寸限制，否则 `archive/` 目录几天就会膨胀到几 GB。

## 可复用建议

- 将归档目录结构固化成轻量规范，并在团队内部统一 `assets.json` Schema，可以极大降低协作成本。
- 提供 Docker 化的一键归档服务，可作为 sidecar 容器部署在流水线作业旁边，监听指定目录并自动执行归档。
- 归档后自动生成一份 `README.md` 或静态索引页，列出所有已归档文章的标题、日期和 slug，方便人工浏览。
- 结合 OpenClaw 的 Context 能力，通过 MCP 工具在对话结束后自动把整个对话产出归档，而不仅仅是文章。这对于构建知识库非常有价值。

## 总结

本地归档不应该是一个“可选的善后工作”，而是自动化内容流水线的出厂质检环节。通过简单的目录约定、稳定的图片下载与路径替换、以及一份结构化的 `assets.json`，我们能以极低的额外开销，建立起可靠的内容资产库。在 OpenClaw 生态中，利用 MCP 或自定义插件实现这一归档能力，会让你的整个自动化系统在可维护性上提升一个量级。
