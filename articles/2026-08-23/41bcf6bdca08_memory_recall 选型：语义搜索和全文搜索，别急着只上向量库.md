## 背景

给 OpenClaw/Agent 接长期记忆时，`memory_recall` 几乎是必做的一环。它负责根据当前问题从记忆库里拉回最相关条目，再注入上下文。这个模块的召回质量，直接决定助手是“记得你上次说过什么”，还是“明明存了却想不起来”。

常见的实现路线有两种：

- **语义搜索**：embedding + 向量库，按语义相似度召回；
- **全文搜索**：SQLite FTS5 / BM25，按关键词和词频召回。

很多人默认直接上向量库，觉得语义搜索更“智能”。但在实际插件和 MCP 工具里，这个结论不一定成立。

## 问题

我们在 OpenClaw 的记忆插件里同时实现了两种 `memory_recall` 后端，并用同一批真实记忆做了对比。核心问题是：**到底哪种方式在真实 Agent 记忆场景下更可靠？是否值得为语义搜索引入额外依赖？**

结论先行：语义搜索擅长处理“换一种说法”，全文搜索擅长处理“精确标识、编号、日期、命令、报错码”。工程上最稳的是混合召回，而不是二选一。

## 做法与步骤

### 1. 准备评测集

从 Agent 实际运行日志里抽了 300 条真实记忆，覆盖偏好、事实、命令、报错、清单等类型。为每个 query 标注了应该命中的 memory。评测集尽量别用自己手写的理想样例，否则容易虚高。

### 2. 实现两路召回

**全文检索**用 SQLite FTS5。中文不能直接依赖默认 `unicode61` 分词，否则整句可能被当成一个 token。我们的做法是写入时用 jieba 预分词，保留原始 `content` 和分词后的 `fts_content`。SQLite 5.0 内置的 `bm25()` 排序足够用。

**语义检索**用本地 `bge-small-zh-v1.5` 生成向量，向量库存 `sqlite-vec`，不引入额外重型服务。对 OpenClaw 来说，`memory_recall` 通过 MCP server 暴露成一个工具，支持 `mode=fts|vector|hybrid`，便于切换验证。

### 3. 对比结果

在 300 条评测集上跑 `recall@5` 和 `MRR`：

- 语义搜索整体 `recall@5` 约 0.72，改写类 query 表现好，比如“端口怎么改”能召回“把 8080 端口改成 9090”；
- 全文搜索整体约 0.58，但在 `ERR_CONN_REFUSED`、`v1.2.3`、`2024-11-02 的备份任务` 这类精确串上，召回率超过 0.9，语义搜索只有约 0.45；
- 两路召回后用 RRF 合并，整体 `recall@5` 提到 0.83，精确类和改写类都能兼顾。

## 踩坑点

**中文全文分词坑最多。** 如果直接建 FTS5 表而不做分词，中文查询基本等于白做。一定要在写入侧处理，别在查询侧临时分词。

**语义搜索的阈值不能写死。** 不同 embedding 模型下，cosine 0.7 可能完全不是同一个意义。阈值太松会把噪声注入上下文，太紧又召回不到。建议按自己的评测集标定。

**chunk 策略比模型更重要。** 我们一开始把长对话整段存成一条 memory，结果召回精度很差。后来改成“一条 memory 一个 chunk，最长按段落切分”，效果明显提升。

**数字、版本、日期是语义弱项。** embedding 对符号和数字不敏感，容易把 `v1.2.3` 和 `v1.2.4` 拉到很近。这类信息必须依赖全文或 keyword 字段，不要指望向量。

**索引更新不一致。** 新增记忆时，全文索引和向量索引要在同一事务或同一服务里完成。否则会出现 memory 明明存在，但 `memory_recall` 永远召不回的情况。

**评测集不能复用训练样本。** 拿自己写好的样例测，只能证明实现没错，不能证明召回好。

## 可复用建议

1. **默认 hybrid，不要只上向量库。** 全文先召回 top_n，语义再召回 top_n，用 RRF 或加权合并。OpenClaw 的 `memory_recall` 工具最好保留 `mode` 参数，方便线上切换和验证。
2. **保留原始文本和 metadata。** `type`、`tag`、`created_at`、`source` 这些字段用于召回后过滤，比盲目扩大 `top_k` 更有效。
3. **固定 embedding 模型和 chunk 策略。** 这两者一变，所有阈值和评测结果都会失效。
4. **建立 50-100 条最小评测集。** 覆盖精确串、同义改写、长尾问题。每次改召回逻辑都跑一遍，守住下限。
5. **对纯精确字段用 keyword/BM25。** 命令名、报错码、日期、版本号，不要只依赖 embedding。

## 总结

`memory_recall` 的选型并不是“语义搜索 vs 全文搜索”谁更好，而是如何让两者互补。语义解决表达差异，全文解决精确匹配。向量库不是银弹，全文搜索也没有过时。

在 OpenClaw 这类 Agent 场景里，更务实的路线是：先跑通全文检索，按需加入向量召回，最后用混合策略和评测集守住召回质量。如果现在还没有评测集，先建评测集，比急着换向量库更重要。
