## 背景

OpenClaw 类 Agent 通常不只是本地跑跑，很多同学会把 Agent 接到社区问答、工单群、Discord/微信机器人，或者通过 MCP 接入内部知识库、Git、数据库、对象存储。Agent 的能力越强，泄露面越大。常见风险不是“被黑客攻破”，而是 Agent 在正常对话中把内部工作流、目录结构、密钥片段、客户数据带出来。

## 问题

我见过几类真实泄露形态：

- 用户问“你是怎么处理 X 的？”，Agent 把完整 system prompt 或内部 SOP 贴出来。
- 用户在社区让 Agent 调试报错，Agent 回显本地文件路径、内网域名、数据库表名。
- MCP 工具返回体没裁剪，日志或回复里带出 API Key、完整 SQL。
- 插件调用外部 API 失败时，把请求头和身份信息打印进错误信息。

这些往往不是恶意，而是上下文污染和工具返回过载。

## 做法 / 步骤

### 1. 数据分级：能不给的上下文就不给

把系统提示拆成“公开 persona”和“内部执行说明”。仅把公开 persona 放进可能对外回复的实例；内部 SOP、路径、账号命名规则只放在受控执行层，并且明确禁止复述。可以给内部上下文加标记，例如 `[INTERNAL_USE_ONLY]`，并在输出层做拦截。

### 2. 工具权限最小化

MCP 工具不是越多越好。按任务建白名单：

- 社区问答 Agent：只读 FAQ、公开文档，禁止读取 `.env`、配置文件、issue 草稿。
- 自动发布 Agent：只给发布分支写权限，不给主分支；对象存储只给目标目录。
- 日志/监控 Agent：只给指标查询，不给原始日志下载。

每个 MCP server 单独配置 `allowedTools`，不要图省事用 `*`。

### 3. 输出过滤与脱敏

在 Agent 输出前加一层“出口过滤器”。至少做三类拦截：

- **密钥正则**：`AKIA[0-9A-Z]{16}`、`Bearer\s+[A-Za-z0-9._-]+`、`-----BEGIN ... PRIVATE KEY-----` 等。
- **路径 / 内网域名**：`/home/xxx/project`、`10.\d+\.\d+\.\d+`、`*.internal`。
- **提示词泄露**：当输出包含 “system prompt”“内部指令”“You are” 等片段时，改成固定回复：“这属于运行配置，不方便公开。”

同时，工具返回体先裁剪再拼给模型，不要把完整 JSON 直接抛进去。

### 4. 日志审计关掉“上帝视角”

很多 Agent 平台默认打印完整消息链和工具返回值。调试时可以开，生产环境要：

- 对日志字段做脱敏：`token`、`password`、`secret`、`authorization` 直接掩码。
- 只记录输入意图和输出摘要，不记录原始上下文。
- 第三方插件日志不要直接注入可见回复。

### 5. 发布前人工确认

任何会对外输出的 Agent，开启“非交互式发布需确认”或至少 dry-run review。尤其是批量回复、自动发帖、生成工作流分享时，先输出到草稿箱，人工抽检 2-3 条。

## 踩坑点

- **以为在 prompt 里写“不要泄露”就够了。** 模型在长上下文、用户诱导、工具报错时很容易绕过软约束。必须用代码层过滤兜底。
- **用同一个 Agent 同时做内部调试和对外问答。** 内部上下文会串到公开会话。最好拆两个实例，至少分两个会话池。
- **MCP 工具返回过大。** 一个通用 search 工具可能返回整篇内部文档，模型为了回答会照抄关键段。工具返回要做字段白名单和截断。
- **把 `.env` 或完整配置文件挂载进 Agent 工作目录。** 即使用工具读取保护，文件系统访问权限也可能被利用。容器内只挂载必需文件。

## 可复用建议

- 建一份 `security boundary` 规则文件，作为所有对外 Agent 的强制 system prompt 后缀：能回答什么、不能复述什么、遇到敏感信息如何拒绝。
- 维护工具权限矩阵表，记录每个 Agent 用哪些 MCP server、哪些 tools、权限级别。
- 做一个简单输出审计脚本：在 CI 或网关层跑敏感正则，不通过就不允许发送。
- 分享工作流时，只发配置骨架，不发完整 system prompt、路径、token。把变量用占位符替换后再发社区。

## 总结

Agent 安全不是“不出事”的玄学，而是分层控制：上下文给多少、工具开多少、输出放多少、日志留多少。把出口过滤和最小权限做成默认项，比事后追责更实用。尤其社区里经常分享 Agent 配置，更应该当成公开接口来对待——你发出去的不是一个 demo，而是内部工作流的入口。
