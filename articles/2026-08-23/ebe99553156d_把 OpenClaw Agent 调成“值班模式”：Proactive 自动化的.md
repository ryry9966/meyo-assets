## 背景

大多数 Agent 目前还是“问答机”形态：用户不开口，它就闲着。真正有用的场景往往是主动式——比如监控告警自动排查、过期 PR 自动提醒、证书到期前自动续期。这类能力在 OpenClaw 体系里并不缺组件，缺的是一套工程化边界：什么时候能动手、动什么、怎么回滚。

我们在内部用 OpenClaw 做了一段时间 proactive 自动化，场景包括每日依赖更新检查、证书到期扫描、异常日志摘要。踩了一些坑，也沉淀了几条可复用的做法。

## 问题

Proactive 能力最容易翻车的地方不是模型不够聪明，而是“太主动”。常见问题：

- 误报：模型判断“值得处理”不稳定，导致刷屏或无效操作。
- 重复执行：同一事件被多次消费，重复提 PR、重复发通知。
- 循环触发：Agent 创建了 PR，监控系统又检测到 PR，触发新的检查。
- 权限过大：直接给 repo admin token，出了事很难收场。
- 上下文膨胀：把所有事件塞进 prompt，token 消耗失控。

这些问题的根源是：proactive Agent 不能只靠 prompt 约束，必须有外部策略层和可回滚的动作设计。

## 做法 / 步骤

### 1. 事件源统一走 MCP，不直接调 Agent

我们的 cron 或 webhook 不直接触发 OpenClaw Agent，而是先落到一个事件队列。OpenClaw 通过 MCP server 暴露统一的 `read_events` / `ack_event` 工具。这样事件天然可以限流、去重、标记来源。

例如，证书到期扫描器每天把即将到期的域名写入队列，Agent 定时通过 MCP 读取，而不是每次扫描都拉起 Agent。

### 2. 决策层加动作白名单和 dry-run

把 Agent 的动作分成三类：

- **只读**：查询、读日志、读状态。自动执行。
- **可逆写**：创建 PR、打标签、创建 issue。允许自动执行，但必须先输出 dry-run 预览。
- **不可逆写**：删除、发布、变更生产配置。必须人工确认。

模型输出 JSON 动作，工程代码校验动作是否在白名单内。白名单之外的动作直接拒绝，并记录日志。这一步比在 prompt 里写“不要做危险操作”可靠得多。

### 3. 执行层加幂等键和冷却时间

每个写动作必须带幂等键。例如依赖更新，用 `repo + package + target_version` 作为幂等键，24 小时内不重复执行。动作完成后写入审计表，包含触发原因、动作内容、执行结果、回滚方式。

冷却时间可以避免同一类问题在短时间内反复打扰用户。我们设置了全局静默时间（晚 10 点到早 9 点），除非是紧急告警，否则 proactive 动作只排队不执行。

### 4. 通知带“撤销”入口

主动通知如果只是发消息，用户会逐渐忽略。我们在 IM 通知里带上“确认 / 撤销”按钮。撤销不是删消息，而是调用反向动作：关闭 PR、撤回标签、恢复配置。这样用户能在 30 秒内收回 Agent 的“先斩后奏”。

## 踩坑点

- **误报**：LLM 直接判断“是否需要处理”不稳定。我们改为规则阈值 + LLM 摘要。例如连续两次检查失败才触发，LLM 只负责把失败原因转成人话，不做决策。
- **重复执行**：最早没有幂等键，同一事件被消费两次。后来给事件加 lease 和 ack 状态，动作侧再做幂等校验。
- **循环触发**：Agent 自己创建的 PR 被监控系统再次检测到，形成死循环。解决办法是动作产物加 `source: agent` 标记，事件源过滤掉自己产生的对象。
- **权限过大**：早期用 repo admin token，一次误操作差点删掉分支。后来换成 fine-grained token，默认只读，写操作单独授权。
- **上下文膨胀**：把所有事件字段塞进 prompt，token 爆炸。现在先做结构化过滤，只给最近 N 条和关键字段。

## 可复用建议

1. **先跑 shadow mode**：Agent 只生成动作计划，不执行。人工观察一周，确认误报率和动作合理性再放量。
2. **动作白名单和回滚路径先于自动化存在**。没有回滚方案的动作，不允许自动执行。
3. **所有 proactive 动作必须可观测**：日志、指标、通知链路缺一不可。否则出了问题不知道 Agent 为什么动手。
4. **设置全局静默时间和用户离开模式**。主动不等于随时打扰。
5. **用 MCP 作为事件源和动作的统一接口**，避免直接耦合平台 API，后续换平台或加工具更平滑。

## 总结

Proactive 能力的关键不是让模型“更主动”，而是把触发、决策、执行、回滚做成闭环。工程边界比模型能力更重要。先把白名单、幂等、审计、静默这些基础打牢，再谈主动智能。否则 Agent 越主动，你越被动。
