# 背景

社区运营和插件测试经常需要定期发布技术记录、版本说明、复现实验。手工发帖效率低，容易在格式、标签、图片外链上出错。我们想做一个半自动机器人：用 OpenClaw 做任务编排，MCP 浏览器工具负责与社区 Web 交互，插件层统一处理“草稿→审核→发布”流程。

# 问题

目标社区没有开放 API，只能走 Web 自动化。主要难点：

- 登录态和验证码
- 富文本编辑器结构不稳定
- Markdown 到社区格式的转换
- 限流与风控
- 发帖失败后的回滚

如果直接让 Agent 自由操作网页，失败率很高，出错后也难定位。因此我们的原则是：把“操作浏览器”封装成受控工具，Agent 只做决策和内容整理，不直接乱点。

# 做法

## 1. 最小闭环

先不做自动发布，只做“草稿箱闭环”：

1. 本地准备 Markdown 帖子；
2. OpenClaw Agent 调用 MCP 工具打开社区发帖页；
3. 填入标题、正文、标签，保存草稿；
4. 人工在草稿箱确认后再发布。

这个闭环跑通后，再加入队列和定时任务。

## 2. 架构

- **内容层**：Markdown 文件 + frontmatter，包含标题、标签、摘要、是否允许发布。
- **Agent 层**：OpenClaw 接收任务，按预设流程调用工具。工具描述必须非常明确，避免 Agent 自己发挥。
- **MCP/浏览器层**：Playwright MCP 负责真实浏览器操作；社区适配器负责登录、草稿、上传、发布、状态检查。
- **审核层**：所有新帖默认进入草稿箱，生成预览链接，人工确认后发布。
- **队列层**：Redis + BullMQ 做定时任务和失败重试。

## 3. 关键实现

- **登录态管理**：使用持久化浏览器 profile，启动时做健康检查；cookie 过期则重新登录并通知。
- **编辑器适配**：先识别编辑器类型。Discuz 类编辑器常用 iframe/contenteditable，需要切换到正确 frame；代码块需要转成论坛支持的 BBCode 或 HTML。
- **图片处理**：外链图片容易被社区屏蔽或触发防盗链，统一先下载到本地，再通过上传接口传到社区，拿到附件 ID 后插入正文。
- **错误处理**：选择器点击失败、超时、验证码出现时，不无限重试；暂停任务并输出 trace 日志。

# 踩坑点

1. **登录态比想象中短**：社区 cookie 可能几小时就失效，频繁登录会触发短信验证。建议持久化 profile + 低频健康检查，不要每次任务都重新登录。
2. **前端选择器三天两头变**：class 名和 DOM 层级不可靠。优先用 role/text/label 定位，并把 selector 放到配置文件，改版只改配置不改代码。
3. **富文本 iframe 导致填不进去**：直接 fill 正文无效，因为焦点在 iframe 内。需要先 frame locator 切进去，再用 click + insertText 或 evaluate 设置内容。
4. **Markdown 直接提交会显示源码**：社区不会自动渲染 Markdown。链接、代码块、行内代码、图片都要按目标格式转换，最好写一个转换器并做样例测试。
5. **发布频率触发风控**：连续发布会被限流或要求验证码。加入随机间隔、单账号每日上限，遇到验证码立即暂停并通知，而不是让 Agent 尝试过验证码。
6. **“发布时间”时区坑**：定时任务用 UTC，但社区后台显示本地时间，容易造成“立即发布”。统一用社区服务器时区，并在任务里显式传时区。

# 可复用建议

- 把发布器抽象成 `Publisher` 接口：`login()`、`create_draft()`、`upload_image()`、`publish()`、`check_status()`。不同社区只实现适配器。
- 所有流程先草稿后发布，保留人工确认开关。别一上来就全自动。
- 给每次任务生成 trace id，日志里记录页面 URL、选择器、重试次数、截图路径，方便排障。
- 对不稳定的页面操作加重试和指数退避，但限制最大重试次数，避免把社区风控打出来。
- 内容做 schema 校验：标题长度、标签存在性、图片数量、正文是否为空。
- 本地 dry-run 模式：不打开真实浏览器，只打印将执行的动作和内容，适合调试。

# 总结

搭一个能稳定发帖的机器人，核心不是“让 AI 自动操作网页”，而是把不可靠的 Web 自动化封装成可观察、可重试、可回滚的工具。OpenClaw 的 Agent 负责流程和内容，MCP 负责浏览器交互，插件/适配器负责社区差异。先跑通“草稿箱 + 人工确认”的最小闭环，比一开始追求全自动要可靠得多。
