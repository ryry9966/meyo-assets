# AI 助手的 USER.md：让 Agent 真正了解你是谁

## 背景
OpenClaw 这类 Agent 默认像一张白纸。它能调用 MCP、执行插件、跑自动化脚本，却不了解你的系统环境、常用路径、身份和偏好。每次会话都要重复“我是做后端开发的”“项目都在 ~/work”“不要动我的 NAS”。这些上下文如果只靠聊天窗口，是临时的、易失的。

USER.md 的作用，是把“关于你”的稳定信息变成 Agent 每次启动都可读取的配置文件。它不是简历，而是一份面向执行环境的“用户手册”。

## 问题
很多人开始写 USER.md 时，会踩几个典型坑：

- 信息太泛：写“我喜欢高效工作”，Agent 无法据此决策。
- 路径和工具描述不明确：Agent 不知道你的测试环境跑在 Docker 里还是本机，只能猜测。
- 内容过期：项目已迁移，文件还写着旧路径，Agent 照着执行就出错。
- 泄露敏感信息：把 token、密码、内网地址直接丢进去，权限边界模糊。

这些问题会让 USER.md 从“有用”变成“误导”。

## 做法/步骤
1. **确定文件位置与加载规则**  
   在 OpenClaw 中，通常可在用户级配置目录放置 USER.md，例如 `~/.openclaw/USER.md`。如果支持项目级，则项目目录下放一份，全局与项目分层。确认你的 Agent 会自动读取该文件；如果不自动，可在启动指令或 MCP 插件逻辑里显式引用。

2. **只写可执行信息**  
   优先写能影响 Agent 决策的内容，比如：

   - 身份与角色：你是谁、主要领域。
   - 环境：操作系统、Shell、常用终端、硬件限制。
   - 目录约定：项目根目录、缓存目录、数据目录、备份目录。
   - 约束：哪些目录/命令绝对不能碰。
   - 偏好：输出语言、代码风格、日志级别、是否自动执行高危操作。

3. **采用结构化格式**  
   用 Markdown 标题和列表，便于 Agent 解析。示例：

   ```markdown
   # USER.md
   ## 身份
   - 后端工程师，主要使用 Go/Python
   - 维护个人 NAS 和家庭网络

   ## 环境
   - OS: macOS 14
   - Shell: zsh
   - 默认终端: iTerm2
   - 包管理: Homebrew

   ## 目录
   - 代码: ~/code
   - 实验项目: ~/lab
   - 下载: ~/Downloads
   - 禁止触碰: ~/Documents/私人

   ## 约束
   - 不要修改 /etc 下的系统配置
   - 不要删除任何未在清单中的文件
   - 执行 curl 或网络请求前先确认目标

   ## 偏好
   - 中文输出，代码注释用英文
   - 优先使用已安装的 CLI，不额外装无关工具
   ```

4. **让 Agent 每次任务前“读自己”**  
   可以在 task prompt 或 MCP 插件逻辑里加入：`Read USER.md first`，或者让 supervisor 在规划阶段把 USER.md 作为固定 context 注入。不是所有 OpenClaw 版本都会自动读取，验证一次即可。

5. **建立更新机制**  
   把 USER.md 纳入版本控制或定期备份。每次换机器、换项目结构、调整策略时，同步修改。

## 踩坑点
- **路径写死又不更新**：至少每季度 review 一次，或在 Agent 执行失败时先检查 USER.md 是否已过时。
- **信息过载**：十几条“我喜欢”“我讨厌”远不如一条具体约束有用。每写一条，问自己：Agent 看到这条后，行为会改变吗？
- **把一次性任务写进去**：比如“今天要部署 X”，这属于会话记忆，不是用户手册。
- **权限与密钥**：不要放 token、私钥、密码。可以用环境变量引用，或让 Agent 通过 MCP 安全存储读取。
- **编码问题**：中英文混排时注意换行和标点，避免某些解析器把整段读成一行。

## 可复用建议
- **三层分离**：全局 USER.md 放机器/身份信息，项目级 USER.md 放项目约定，临时上下文放会话里。
- **给 Agent 一个“自我校验”步骤**：执行关键命令前，让它复述“根据 USER.md，我不能碰 XX，当前操作不涉及 XX”。
- **用字段而非段落**：如 `OS: macOS` 比“我用的是 Mac 系统”更易解析。
- **最小化原则**：先写 20 行，用一段时间，把无效内容删掉，再补充真正影响决策的条目。

## 总结
USER.md 不是让 Agent 变得“更懂你”的情感配置，而是减少重复沟通、降低误操作风险的手册。它的价值取决于信息能否在每次执行时被稳定读取、被准确理解。把 USER.md 当作基础设施来维护，而不是一次性写完就忘，Agent 才能真正少问“你是谁、在哪跑、能不能删”。
