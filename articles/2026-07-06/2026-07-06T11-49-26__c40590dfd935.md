## 越狱攻防战：为什么你的请求会"死"？

在 LLM（大语言模型）的应用生态里，"越狱"是个绕不开的幽灵。简单来说，模型在出厂前会经过 RLHF（基于人类反馈的强化学习）和 Safety Training（安全训练），被教导不要输出有害内容。但用户总能通过角色扮演、编码混淆、长上下文稀释等手段，绕过这些安全护栏，让模型输出本不该输出的内容。

Anthropic 这次梳理的防御体系，本质上是一个 Multi-layer Defense（多层防御）架构。恶意请求从输入到输出，要经历四层严密的审查。这四层防线各有侧重，分别在意图识别、内部逻辑、对抗鲁棒性和输出生成阶段，给越狱请求执行了不同花样的「死刑」。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-06/d2b732e4c50f8432.png)

## 死法一：前置意图分类器的"安检门截杀"

第一道防线叫作 Expandable Classifiers（可扩展分类器）。你的 Prompt 刚敲完回车，还没真正进入大模型的核心推理引擎，就被保安拦下来了。

- **技术原理**：这是一个独立于主模型的小型分类器网络。它不追求理解你的文学意图，只关心你的 Prompt 里是否包含已知的越狱模式。它通过高速、低延迟的推理，提取输入的特征向量进行匹配。
- **典型死法**：如果你用 Base64 编码、Hex 编码或者一堆乱码后缀（比如经典的 GCG 攻击生成的对抗性后缀）来伪装恶意请求，分类器会瞬间识别出这种"非自然语言"的统计学特征，直接返回一个标准的拒绝话术。
- **工程师视角**：这招就像是 WAF（Web 应用防火墙）里的正则匹配，但比正则更智能。它的好处是成本极低，不需要动用大模型的算力就能挡住 80% 的脚本小子攻击。缺点是稍微变换一下句式结构可能就绕过去了，所以叫"可扩展"——需要不断往特征库里加新样本。

## 死法二：Constitutional AI 的"底层逻辑反制"

如果你的 Prompt 伪装得很自然，骗过了前置分类器，进入模型内部后，就会遇到第二道防线：Constitutional AI（宪法 AI）。这是 Anthropic 的看家本领，也是让越狱请求"死得最不服气"的一关。

- **技术原理**：模型在被训练时，内部植入了一套"宪法"原则（比如：不能协助制造武器、不能生成歧视性内容等）。在生成回答时，模型会进行 Self-critique（自我批评），先生成一个初稿，然后对照原则审查自己的初稿，如果发现违规就重写。
- **典型死法**：你用"DAN（Do Anything Now）"或者"奶奶漏洞"（让模型扮演过世的奶奶讲睡前故事，实际上是在套取敏感信息）来诱导模型。模型表面上进入了角色扮演，但在深层逻辑中，"宪法"原则的权重高于角色扮演的指令。模型会在内部推断："虽然我现在的角色是奶奶，但输出这些内容违反了核心宪法"，最终主动切断回答，给你一句"我不能提供此类信息"。
- **工程师视角**：这是一种基于价值观的对齐方式。相比于单纯的黑名单词库，它更看重意图理解。相当于程序员不仅知道" SQL 注入"的代码长什么样，还深刻理解了"数据与指令分离"的底层逻辑，所以不管你怎么变形，只要是那个味儿，就会被拦截。

## 死法三：鲁棒微调的"免疫疗法"

有些高级越狱会利用长上下文窗口，在几万字的无关文本中夹带私货（比如 Many-shot Jailbreaking）。针对这种利用上下文疲劳或梯度下降盲区的攻击，Anthropic 给出了第三种死法：Robust Fine-tuning（鲁棒微调）。

- **技术原理**：在模型的安全微调阶段，红队会使用各种最前沿的越狱技术对模型进行攻击，将成功越狱的 Prompt 收集起来，打上"必须拒绝"的标签，重新喂给模型进行训练。这相当于给模型打了一针"特种疫苗"。
- **典型死法**：你在 Prompt 里塞了一本十万字的小说，前九万字都在讲一个无关痛痒的冒险故事，在最后一千字突然话锋一转，要求模型总结如何提炼某种危险化学品。模型在读完前九万字时，上下文注意力机制已经被拉扯得很分散，但由于它在微调阶段见过成千上万种类似的长文本夹带攻击，它的 Attention 机制会像条件反射一样，精准捕捉到那个"转折点"，并在最后关头踩下刹车。
- **工程师视角**：这本质上是在补数据集的漏洞。大模型是"喂什么是什么"，如果训练集里没有某种攻击范式，模型大概率会中招。红队对抗生成的高质量负样本，就是在填补泛化能力的短板。

## 死法四：输出端扫描的"回马枪"

假设你的越狱手段极其高明，前三个关卡全被你破了，模型真的开始生成有害内容了。别急，还有第四道防线：Output Scanning（输出端扫描）。这叫做"不见棺材不掉泪，下了棺材还能给你拽回来"。

- **技术原理**：在模型逐 token 生成回答的过程中，系统会并行运行一个轻量级的监控模型。这个监控模型实时扫描生成的文本流。一旦检测到有害内容的前兆，系统会立即中断推理，并替换输出为标准的拒绝信息。
- **典型死法**：你通过极其复杂的逻辑链，让模型开始输出一段看似正常的代码，但代码的第五行开始出现危险的系统操作指令。监控模型在第三行就嗅到了危险，直接掐断输出流。用户端看到的现象就是：模型输出了两行字，然后突然卡住，接着弹出一个"由于安全策略，本次回答已被中断"的提示。
- **工程师视角**：这是典型的 Defense in Depth（纵深防御）思想。在系统架构设计中，永远不能假设前面的防御层是 100% 可靠的。输出端扫描作为最后一道兜底，虽然会带来轻微的延迟和算力开销，但它是防止有害信息触达终端用户的最后保障。
