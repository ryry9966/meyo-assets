最近Codex负责人关于「AI时代唯一值钱的能力」的访谈在技术圈刷了屏。核心观点不复杂：当AI能写代码、写文档、做PPT的时候，人类最稀缺的不是「产出能力」，而是「判断力」——你得知道什么是好的，什么是对的，什么是值得做的。这个观点乍看像鸡汤，但细想其实很硬核。今天不灌汤，掰开揉碎聊聊为什么判断力是AI时代的硬通货，以及怎么磨这个能力。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-06/b4656b42ec48160e.png)

## 一、代码生成能力正在「贬值」——贬的不是「代码」本身

先看几个数据点：

- GitHub Copilot在2023年底已有超过100万付费订阅用户，到2024年用户数持续增长。大量开发者的日常工作流中，AI辅助编码已经从「尝鲜」变成「默认」。
- OpenAI的HumanEval基准测试中，GPT-4的pass@1通过率已经超过80%，而2021年的初代Codex大概在30%左右。三年时间，代码生成的正确率翻了一倍多。
- 在一些标准化的编程任务上（比如写CRUD接口、写正则、写单元测试模板），AI生成的代码质量已经达到中级工程师的水平。

但这里有个容易误读的点：**「代码生成能力贬值」不等于「程序员要失业」**。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-06/2ea1832cfa458d38.png)

真正在贬值的是什么？是**「从零到一的机械编码」**——那些你能用Google搜到、能从Stack Overflow复制、能按模板套出来的代码。这类工作的价值确实在快速归零。

没有贬值的是什么？

- **系统设计能力**：知道一个功能应该做成同步还是异步、要不要上消息队列、数据一致性怎么保证
- **排障能力**：线上出了问题，能从一堆日志和metrics里找到根因
- **技术选型的判断力**：知道什么场景该用PostgreSQL，什么场景该用Redis，什么时候别上Kubernetes
- **需求理解力**：产品经理说「我要一个简单的搜索功能」，你得判断出他其实要的是一个带分词、权重、高亮的全文检索系统

这些能力的共同特征是：**需要上下文、需要经验、需要在多个选项之间做权衡**。而这恰恰是当前AI最不擅长的。


## 二、「唯一值钱的能力」到底是什么？

Codex负责人说的「唯一值钱的能力」，可以拆成三个层次：

### 1. 品味（Taste）：知道什么是「好」

AI能给你十个方案，但哪个方案是「好的」？这需要品味。品味不是天生的，是大量实践+反思+对标优秀案例积累出来的。

举例：

- 你看到一段代码，能一眼看出它的抽象层次是否合理
- 你看到一套API设计，能判断它的命名是否一致、边界是否清晰
- 你看到一个架构图，能预判它在流量翻10倍后哪里会先崩

### 2. 判断力（Judgment）：知道什么是「对的」

「好」和「对」不一样。一个好的方案可能因为团队技术栈、交付周期、运维能力等约束而不被选择。判断力是在**约束条件下做trade-off**的能力。

举例：

- 技术上最优雅的方案，但团队没人维护得了，你选不选？
- 重写整个系统最干净，但deadline只有两周，你怎么办？
- 用最新的框架最酷，但社区生态不成熟，线上出了bug没人帮，你敢不敢？

AI可以列出所有选项的pros and cons，但在具体语境下做「这个项目应该选B而不是A」的决策，需要人。

### 3. 提出好问题的能力（Problem Framing）

AI时代有个说法：**「答案变便宜了，好问题变贵了。」**

- 以前你花3小时写代码，现在你花3分钟让AI写
- 但你花在「想清楚到底要AI写什么」上的时间，可能变长了
- 如果你连问题都定义不清楚，AI给你的答案再快也是垃圾

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-06/f65dfa3ff734744f.png)

这就是为什么资深工程师用AI的效率远高于初级工程师——不是因为他们打字快，而是因为他们**知道该问什么、怎么追问、怎么验证**。


## 三、历史视角：每次工具革命都在问同一个问题

判断力成为核心能力，这不是AI时代才有的新鲜事。

**计算器时代（1970s）**

电子计算器普及后，「算得快算得准」不再是数学家的核心竞争力。但数学家没有失业——因为数学的核心从来不是计算，而是**提出猜想、构造证明、发现结构**。计算器替代了「执行」，放大了「思考」。

**Excel时代（1990s）**

Excel让任何人都能做财务模型。会计没有消失，但会计的角色从「记账」变成了「解读数据、做财务决策」。能用Excel的人多了，但知道**该建什么模型、模型假设是否合理、结果怎么解读**的人，还是少数。

**编译器时代（1950s-1970s）**

高级语言和编译器出现时，很多人担心「写汇编的人怎么办」。结果是：汇编写作能力确实贬值了，但「理解计算机怎么工作」的能力依然值钱。今天能用AI写代码的人，和当年能用编译器写高级语言的人一样——工具降低了执行门槛，但没有降低理解门槛。

![img3](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-06/ca789817378dde70.png)

**每一次工具革命的模式都是一样的：**

| 阶段 | 执行能力 | 判断能力 |
|------|---------|---------|
| 工具出现前 | 值钱，因为稀缺 | 也值钱 |
| 工具普及中 | 开始贬值 | 相对升值 |
| 工具普及后 | 基本归零 | 成为核心壁垒 |

AI时代只是这个模式的最新一集。但有一个重要的区别：**以前的工具替代的是「体力」，AI替代的是「脑力执行」**。这让它对白领工作的冲击比以往任何工具都要大。


## 四、怎么磨判断力？三个可操作路径

判断力不是靠读文章读出来的，是靠**做决策+看结果+复盘**磨出来的。三条路径：

### 路径一：主动做「有后果的决策」

判断力和肌肉一样，不练不长。但练判断力最好的方式不是做模拟题，而是做**有真实后果的决策**。

具体做法：

- 技术选型时，别只看benchmark，自己搭两个原型跑一下，感受真实的开发体验和运维成本
- Code Review时别只看「有没有bug」，多问一句「这个设计在需求变了之后好不好扩展」
- 做架构决策时，写下你的理由，三个月后回头看，当时的判断对不对

### 路径二：刻意接触你不熟悉的领域

判断力的底层是**模式识别**。你见过的模式越多，判断越快越准。

具体做法：

- 前端工程师去了解一些DevOps的实践，看看基础设施层面的约束怎么影响架构决策
- 后端工程师去学一点UX设计，理解用户行为怎么影响API设计
- 看开源项目的RFC/设计文档，特别看那些被rejected的提案——**被否决的方案往往比被采纳的方案更有学习价值**，因为你能看到「为什么不这么干」的推理过程

### 路径三：写决策日志

这是最被低估的习惯。每次做重要技术决策时，花5分钟写下来：

```
日期：2024-XX-XX
决策：选择PostgreSQL而不是MongoDB做主数据库
理由：1) 强一致性需求 2) 团队熟悉度高 3) JSON字段类型够用
风险：如果后面需要水平扩展，可能要迁移
复查时间：3个月后
```

三个月后回来复盘：你的判断对了吗？当时的理由站得住吗？有没有你没想到的因素？

**这个习惯的价值不在于记录本身，而在于强迫你把「直觉」变成「可验证的推理」。**

## 五、三条冷思考

最后，给三条冷思考，不灌汤：

### 1. 「判断力」不是万能挡箭牌

别拿「我有判断力」当不学新工具的借口。判断力的前提是**你有足够的信息和经验做判断**。如果你连AI能做什么、不能做什么都不清楚，你的「判断」只是偏见。

### 2. 判断力也有「半衰期」

十年前对「该不该上微服务」的判断，和今天的判断不一样，因为基础设施变了。判断力需要持续更新，否则你拿的是十年前的地图找今天的路。

### 3. 别忘了「执行力」仍是基本盘

判断力是上限，执行力是下限。AI能帮你写代码，但你得能看懂、能改、能调试、能部署。**判断力告诉你做什么，执行力让你真的做出来**。两者缺一不可，别为了追「判断力」把「执行力」丢了。
