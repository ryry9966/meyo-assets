过去十几年，软件的钱特别好算：按买断收一次，按席位收月费，按 token 收流水。现在这笔账要重算了。据 36kr 等媒体报道，OpenAI 正在探索一种新定价——AI agent 只有把任务真正干完，才开始收费；干砸了，就不收钱。CFO Sarah Friar 在公开场合确认过这个方向，Sam Altman 也放风过“按 AI 创造的价值抽成”的设想。这不是一次普通的价格调整，而是计费逻辑的换代：从“卖工具”进化到“卖结果”。这篇聊聊它背后的账本、工程和历史。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/0604d7fcb1a0ab98.png)

## 一、计费模型编年史：按结果收费其实是个老东西

软件收钱的方式，一路都在往“结果”靠近：

1. **License 时代**：光盘 + 序列号，一次买断。用得好不好，厂商概不负责。
2. **SaaS 订阅**：按席位、按月付，厂商开始为“续费率”负责，但依然不为单次使用的效果负责。
3. **Usage-based**：按调用量、按 token 计费，API 时代的默认值。用多少付多少，但“用了没效果”照样付钱。
4. **Outcome-based**：按结果付费。这一步软件业一直迈不出去，因为产出没法被程序化验收。

其实老行业早就玩过这一手：广告业从包天（CPD）走到按点击（CPC），再走到按转化（CPA）；律师有“风险代理”，官司赢了才抽成；猎头长期就是“人入职了才收钱”。**谁敢对结果负责，谁就能收更贵的价格**——这条规律从未变过。AI agent 第一次让机器的产出可以被自动验收，这套老逻辑才终于搬进软件。

## 二、订阅制和 Token 计费，为什么装不下 Agent

两种现行主流模式，在 agent 面前都有结构性缺陷：

- **订阅制的尴尬**：它赌的是“重度用户补贴轻度用户”。但 agent 时代这个杠杆会失灵——一个跑批量任务的 agent 一晚上烧掉的 token，可能顶普通用户一个月。Altman 曾公开承认，$200/月 的 ChatGPT Pro 一度被重度用户用得 cover 不住成本。用得越多亏得越多，订阅制扛不住。
- **按量计费的尴尬**：用户买的从来不是 token，是结果。agent 走错三步、重试五次，账单照付，活还是没干成——钱花了，事黄了，体验直接劝退。
- **成本方差太大**：agent 的成本结构天生波动，多步推理、调工具、self-correction，同一类任务的 token 开销可能差出一个数量级，任何“固定费率”都很难精确覆盖。

于是只剩一条路：让厂商自己扛试错成本，把“干完”设成计费触发器。对厂商来说，这相当于从“出租车计价器”改行做“工程总包”——听起来 customer-friendly，实际考验的是自家良品率。

## 三、最难的工程题：到底怎么定义“干完了”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/052c54053bd7be7b.png)

按结果付费听起来美好，落地要翻三座大山：

1. **验证（verification）**：什么算完成？客服场景简单——工单关闭、用户不再追问，机器可判。代码场景也不错——测试通过才算交付，SWE-bench 这类 benchmark 就是靠自动化判分跑起来的。这条线和大模型训练的前沿是同一件事：**RLVR（Reinforcement Learning with Verifiable Rewards）**——能自动打分的任务，模型进步最快，计费也最容易。反过来，不能自动判分的任务，训练难、计费更难。
2. **归因（attribution）**：结果是 AI 干的，还是人类同事救场的？人机混合协作之下，功劳怎么分？这既是审计问题，也是计费接口怎么设计的问题。
3. **防作弊（Goodhart's Law）**：当指标变成目标，它就不再是好指标。机器人可能诱导用户提前关闭工单来“结算”，也可能把硬骨头判定为“无解”来止损。所以按结果付费必须配套抽样复核、争议仲裁和防刷机制。

再加一层：厂商承担风险，意味着毛利要靠精算来兜底。这不是商业模式里的善良，是定价工程的升级。

## 四、先被“按结果”卖掉的，是可验收的活

按“可验证性”给任务排个序，就知道哪些活会先换计费方式：

- **高可验证**：代码（测试通过）、数据清洗（规则校验）、发票与表单处理（字段对错）——机器一跑就知道成没成。
- **中等可验证**：客服解决率、销售线索合格数。这一档已有先行者：Intercom Fin 按“每解决一单 $0.99”收费，Salesforce Agentforce 上线时按 $2/次对话计费，都算 outcome-based 的前身。
- **低可验证**：创意写作、战略咨询、陪伴聊天——“完成”没有客观标准，大概率继续订阅或按量。

对厂商，这意味着现金流波动变大，必须垂直深耕才有定价权，通用助手大概率走“订阅 + 按结果”的混合制；对买方，单价看着贵（含风险溢价），但算总账往往更划算。

## 五、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/1a4055c3bdadc30d.png)

1. **用期望值算账，别盯着单价标签。** 按结果付费的单价天然更高，正确的比较公式是：期望成本 = 单价 × 成功率，再叠加上你自己复核的时间。$2/单 × 85% 解决率，很可能比“看起来便宜”的订阅 + 人工兜底更省。
2. **拿“可验证性”当选型尺子。** 接入 agent 前先问一句：这个任务有没有机器能判的验收标准？有，大胆按结果付费；没有，订阅或按量 + 明确的人工验收反而更稳。
3. **把审计和数据归属写进合同。** 按结果付费意味着厂商深度嵌入你的业务流程：计量日志在谁手里、争议怎么仲裁、任务数据归谁所有——这三条不写清，今天省下的钱，明天会变成新的账单。

计费方式的变迁，本质是责任分配的变迁。当 AI 开始为结果签字画押，“软件只是工具”这句话，就真的过时了。
