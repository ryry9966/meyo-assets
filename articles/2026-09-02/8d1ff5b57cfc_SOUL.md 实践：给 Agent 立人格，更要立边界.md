## 背景

OpenClaw 的工作区里有一组以 Markdown 组织的“宪法文件”，`SOUL.md` 是其中最容易被低估的一个。它会在每次会话启动时注入系统提示词，决定 Agent 是谁、用什么语气说话、哪些事不做。很多人装完插件就开跑，SOUL.md 只留默认几行，结果就是同一个助手在不同会话里判若两人。

## 问题

我遇到的实际症状有三个：

- **语气漂移**：周一简洁克制，周三开始满屏客套话和表情堆砌；
- **越界**：让它整理笔记，它顺手“优化”了我不该动的文件，装了 shell / 文件类插件后尤其明显；
- **没有底线**：对任何请求都先答应，事后再道歉。

这些都不是模型能力问题，而是人格和边界没有被写成可复现的约束。

## 做法

我把 SOUL.md 控制在 40 行以内，分四段：

1. **身份与语气**：三五行写清“你是谁、面对谁、什么口吻”。用具体行为代替形容词，比如“回复默认三句以内，先结论后理由”，而不是“友善、专业”。
2. **能力边界**：列一份“不做清单”——不主动改工作区以外的文件、不执行删除类命令、不代替我做对外承诺。每条对应一个真实发生过的事故。
3. **与工具的关系**：接入 MCP 或插件后，在这里补一句“使用某工具前先向用户确认”，避免插件把行事风格带偏。
4. **修订记录**：底部两三行，写日期和改动原因。

关键习惯：每次纠正 Agent 之后，把这次纠正浓缩成一条规则写回 SOUL.md。这个文件应该像代码一样进 git，能 diff、能回滚。

## 踩坑点

- **写太长**。SOUL.md 每次会话都会加载，几百行的“人格说明书”只会稀释注意力，还持续烧 token。40 行讲不清的边界，靠权限和沙箱兜底，别靠嘴。
- **和 AGENTS.md 抢戏**。SOUL.md 管“是谁、不做什么”，AGENTS.md 管“怎么干活”。同一件事写两处，迟早冲突。
- **把它当安全边界**。提示词里写“不许删文件”不等于真的删不了，删除权限要在工具配置和系统层面收掉。人格约束是行为层，不是安全层。
- **边界立得太死**。我一度写了十几条“不许”，结果它连常规操作都开始反复请示。规则里要有否定，也要有明确授权。

## 可复用建议

- 每次升级模型或新增插件后，用固定的三五个问题做冒烟测试：一个模糊请求、一个越界请求、一个应该拒绝的请求，对比回复是否符合预期。
- 让 Agent 参与维护：定期让它读自己的 SOUL.md，指出与近期对话冲突的条目并给修改建议，你只做审校。
- 边界优先写“不做的事”，人格优先写“具体行为”，形容词能删就删。

## 总结

SOUL.md 的价值不在于把 Agent 写得“有灵魂”，而在于把你的偏好和底线变成每次会话都生效的、可版本管理的约束。小、具体、持续修订，比一次性写一份完美人格有用得多。
