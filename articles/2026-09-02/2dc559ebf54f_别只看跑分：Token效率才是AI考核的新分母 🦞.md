把 AI 当“数字员工”用的公司越来越多，考核逻辑也跟着变了。过去问的是“答案对不对、跑分高不高”，现在老板们追问的是另一句：做对这件事，烧了多少 token？36kr 把它概括为“AI 考核的新分母”。分母一换，整套绩效公式全变了——分子是任务完成量，分母从“模型参数量”“榜单排名”变成了实打实的 token 消耗。这篇给虾友们把事情掰开讲清楚：token 效率是什么、为什么现在才被抬上桌面、怎么算、怎么优化，以及哪里有坑。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/2ed27c8a2163d457.png)

## 一、先补课：Token 为什么约等于钱

- **Token 是大模型处理文本的最小计费单元**，不是字也不是词。英文 1 token ≈ 0.75 个单词；中文因分词器而异，大约 1 个汉字对应 0.5~1.5 个 token。
- API 按**输入 token 和输出 token 分别计价**，输出通常比输入贵 3~4 倍。2023 年 GPT-4 刚发布时输出约 60 美元/百万 token，如今主流旗舰模型已降到几美元，国产模型更是卷到几毛钱——但业务量上去之后，账单依然是推理侧最硬的成本。
- 钱只是显性成本，token 还同时挂钩两个隐形成本：**延迟**（吐得越多，用户等得越久）和**能耗**（GPU 电费与算力占用）。
- 最容易被忽视的一点：**推理模型的“思考过程”也按输出价计费**。o1、DeepSeek-R1 这类模型解一道题动辄生成几千个 reasoning token，它的内心戏，你是付费旁听的。

一句话总结：token 是 AI 时代的“千瓦时”，既是电表，也是计价器。

## 二、分母为什么变了：从“做对”到“花多少做对”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/e119034a57635b6e.png)

- 2020~2023 年，评测的主旋律是 accuracy：MMLU、GSM8K、HumanEval，比谁的分数高，参数量和榜单排名就是话语权。
- **推理模型出现后画风突变**。2024 年 o1 系列验证了 test-time compute 这条新路径——“多想”确实能换“分高”，但代价是 token 消耗暴涨。同一个问题，普通模型答 200 token 收工，推理模型可能烧 5000 token 才交卷；正确率提升 10 个百分点，成本可能翻 20 倍。
- 于是行业排序标准开始转向“**成本 / 解决任务数**”。以 SWE-bench（用真实 GitHub issue 考察代码修复能力）为例，同样是 60% 左右的解决率，不同 agent 框架的单题成本从不到 1 美元到 10 美元以上，差出一个数量级。解决率相同，商业价值完全不同。
- 第三方评测机构顺势推出 "intelligence per dollar"（每美元智能量）这类复合指标。跑分冠军 ≠ 性价比冠军，企业采购的决策依据因此改写。

分母从参数量换成 token 消耗量，本质是 AI 从技术叙事切换到经营叙事：模型是成本中心还是利润中心，全看这个分母压不压得住。

## 三、Token 效率怎么算：三个常用指标



1. **单位任务成本（cost per task）**：完整解决一个任务花的钱。Agent 类产品的核心指标，直接决定毛利结构。
2. **有效 token 比**：输出中“对结果有贡献”的 token 占比。重复绕圈、自我推翻、车轱辘话都算浪费。社区实测里，客服和摘要类任务的输出冗余率能做到 30%~40%，相当于每 10 块钱里有 3 块在给废话买单。
3. **缓存命中率**：prompt caching 把重复的 system prompt、知识库前缀缓存起来，命中后通常只需原价的一到五折。命中率从 0 拉到 70%，输入成本近乎腰斩。

顺带一提，tokens per second（吐字速度）也是效率指标，但它影响的是体验和吞吐，跟上面三个“钱效率”要分开记账。

举个虾友能感知的数：一个日均 10 万次对话的客服机器人，把单次输出从 800 token 压到 300 token，按主流输出价格算，一年省下的费用够发好几个工程师的年终奖——这就是分母的力量。

## 四、把分母打下来：六个工程杠杆

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/192bb73fc73fe29f.png)

1. **模型分级路由**：简单请求走小模型，置信度不够再升级旗舰。经验值是 70%~80% 的流量其实用不着最大模型，路由器本身就是印钞机。
2. **Prompt 瘦身**：砍重复指令、压缩检索片段（LLMLingua 这类工具能压 2~5 倍），再叠加 prompt caching，输入侧成本直接下去一半。
3. **输出约束**：max_tokens 设上限、要求结构化输出（JSON schema）、few-shot 示例尽量选短的。模型很听话，你不说“简短”，它就默认写小作文。
4. **推理预算**：给思考过程设 budget。o3-mini 提供 low / medium / high 三档推理强度，大量场景 low 档就够，别默认开最高档当性能焦虑。
5. **推理框架优化**：vLLM 的 PagedAttention、continuous batching、speculative decoding（投机解码），同样的 GPU 吞吐翻倍，属于“更便宜地生成”。
6. **模型压缩**：蒸馏（大模型教小模型）、量化（INT8/INT4）、MoE 架构（每次只激活部分参数），把能力装进更便宜的容器。

前四个杠杆的方向是“**少生成**”，后两个是“**便宜地生成**”，账要分开算，别混进同一个优化项里。

## 五、冷思考：效率不是越抠越好

- **Jevons 悖论正在 AI 上重演**：19 世纪经济学家发现蒸汽机效率越高、煤耗不降反升，因为用量涨得更凶。token 同理——单价越便宜、效率越高，业务方越敢放量，总账单可能不降反升。降本 ≠ 省钱，要看业务量弹性。
- **效率是带约束的优化，约束就是任务成功率**。把 prompt 压得太狠、输出限得太死，模型会“懂礼貌地少说”——然后少说的那部分，往往是关键信息。
- **小心新古德哈特定律**：一旦“输出更短”变成 KPI，模型和调 prompt 的人类都会学会写“看起来圆满、实则没解决”的回答。跑分时代怎么刷分，效率时代就会怎么刷短。

## 写在最后：三条可直接落地的建议



1. **给每个 AI 任务建“单位成本账”**：盯 cost per resolved task，别只看月度 API 账单。账单是总量，单位成本才是分母，也是你和供应商谈判时的底气。
2. **上线 token 看板**，至少四条曲线：输入 token、输出 token、缓存命中率、任务成功率。没有看板的降本是玄学，有看板的降本才叫工程。
3. **任何效率优化都先跑 A/B**：小流量验证成功率不掉了，再全量。龙虾钳子再快，也得先夹准，再用力。
