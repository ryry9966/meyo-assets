## 背景

OpenClaw 这类常驻本机的个人 Agent，和网页版一问一答有本质区别：它跨会话、跨天陪你工作。但模型本身没有持久记忆，每次启动近乎白纸。OpenClaw 的 workspace 里预留了一组记忆文件（`AGENTS.md`、`SOUL.md`、`USER.md`、`MEMORY.md` 等），其中 `USER.md` 的定位很明确：**描述"你是谁"的静态档案**，随会话注入上下文，让 Agent 不必每次重新认识你。

## 问题

没有它或写得很差时，常见损耗是：

- 每个新会话重复自我介绍：技术栈、项目背景、时区；
- Agent 拿默认风格回复——你想要克制简洁，它热情洋溢；
- 排程跨时区出错、中文语境夹英文回执；
- 每次口头纠正，纠正成本反复支付。

## 做法

我现在的 USER.md 约 40 行，骨架如下：

```markdown
# 基本信息
- 称呼 / 时区 / 默认语言
# 技术上下文
- 语言、框架、在维护的项目（各一行）
# 沟通偏好
- 默认中文回复；先结论后推导；不用表情
# 边界
- 不主动改配置文件；删库级操作先确认
# 当前阶段（每月更新）
- 近期重心两三行
```

三条写法原则：**只写稳定事实**（会话级状态进 MEMORY/日记，别混进来）；**每条可执行**（写成 Agent 能直接照做的规则，而非性格形容）；**控制长度**（压在 300–500 token，它常驻每轮上下文）。

非 OpenClaw 栈的等价做法：维护一个用户档案文件，通过 MCP resource 或启动脚本读入 system prompt，思路一致。

## 踩坑点

- **写成小作文**。早期我写了 200 行，结果 Agent "什么都懂一点"却抓不住重点，删到 40 行后遵循度明显上升；
- **动态信息混入**。"本周要交付 X"写进去两周没删，Agent 一直围绕过时目标规划——稳定档案和滚动状态必须分离；
- **规则打架**。"要简洁"和"关键操作给完整解释"并存时行为不可预测，冲突规则要显式写优先级；
- **敏感信息裸奔**。档案会随上下文发给模型服务商，token、内网地址、住址都别放；
- **只加不减**。半年后全是矛盾陈述，我固定每月清一次，git 留历史。

## 可复用建议

- 用 git 管理它，改动可回溯；
- 加一条写回规则："从对话中确认到长期有效的事实，先提议写入 USER.md，我确认后再写"——人在环路，避免它自作主张污染档案；
- 同时用多个 Agent 的话，共用（或软链）同一份档案，行为更一致；
- 拿不准一条该不该写，用这个判断：**三个月后它还成立吗？Agent 能照做吗？** 两个都成立才写。

## 总结

USER.md 是成本最低、杠杆最高的 Agent 配置之一：十几分钟写一次，换回每个会话少几十句无效确认。把它当生产配置对待——版本化、定期评审、有边界——Agent 对你的了解就从"每次重新猜"，变成一份可持续维护的状态。
