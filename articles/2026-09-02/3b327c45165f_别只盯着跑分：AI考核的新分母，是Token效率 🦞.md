过去两年选 AI 模型，标准动作是看榜单：MMLU、HumanEval、竞技场排名，谁分高用谁。2025 年风向变了：36kr 报道指出，AI 考核正在引入一个新分母，Token 效率。分子还是“任务完成得怎么样”，分母却从参数量、跑分名次，悄悄换成了“这个任务你烧了多少 token”。这不是学术趣味，而是真金白银：当一次 agent 任务动辄消耗几十万 token，分母每差一倍，账单就差一倍。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/0432678f0f71ce66.png)

## 分母的三次换代：从参数量到 Token

给模型“打分”这件事，分母一直在换：

1. **v1.0 参数量时代（~2022）**：大家比谁参数多、训练 FLOPs 大。后来 Chinchilla 论文证明同等算力下存在最优“参数-数据”配比，巨无霸神话开始松动。
2. **v2.0 跑分时代（2023–2024）**：API 虽然按百万 token 报价，但采购决策仍以基准测试排名为主，成本只是“顺带看一眼”。
3. **v3.0 Token 效率时代（2024 下半年至今）**：推理模型与 agent 兴起，token 消耗量级式上涨，“能力 ÷ Token”成了新公式，成本从脚注升格到第一页。

分母换代的本质：AI 的交付形态从“一次问答”变成了“长任务执行”，考核自然从“答对没有”变成“每任务成本”。

## 先搞清楚：Token 为什么是天然的计费单位

- Token 是 LLM 处理文本的最小单位，约 4 个英文字符对应 1 个 token；中文取决于 tokenizer，GPT-4o 一代之后大约 1 个汉字 ≈ 1 个 token，老一代模型常要 1.5~2 个。
- 成本结构不对称：输入（prefill）可以并行计算，输出（decode）是逐 token 自回归生成，受显存带宽限制，所以输出价通常是输入价的 3~5 倍。
- 算笔账：一个“读 1 万 token 上下文 + 生成 5 万 token 思考与答案”的任务，按一线闭源推理模型公开牌价（输入约 $15/百万、输出约 $60/百万）示意，约 $3 一单；换成输出约 $2/百万的高性价比开源模型，同样任务不到 $0.15。能力接近，账单差 20 倍——这就是分母被单独拎出来的原因。
- 国内价格战把逻辑推到极致：2024 年以来主流厂商把百万 token 输入价卷到几毛钱级别。“单价”不再稀缺，“每个任务总共花多少”才稀缺。

## 推理模型时代：分母被撑大了

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/8dc440eee38f40b4.png)

- 2024 年 9 月 OpenAI 发布 o1，“推理时扩展”（test-time scaling）成为新范式：模型先生成成千上万 token 的思考过程再作答。斯坦福 s1 论文验证，把思考预算从 1k 拉长到 64k token，一个 32B 开源模型在 AIME 数学竞赛上的准确率一路爬升，追平了当时的 o1-preview。
- 代价是“过度思考”（overthinking）。有研究统计过：面对“2+3 等于几”级别的简单题，o1 类模型平均要烧掉上千思考 token，普通模型几十个收工；在简单基准上，几十倍的 token 开销常常只换来零点几个百分点的准确率提升。思考链对难题是解药，对简单任务是慢性毒药——而按 token 计费时，毒药是甜的。
- DeepMind 2024 年的研究（Snell et al.）给出另一面：小模型多想几步，可以胜过大模型直接回答。换句话说，token 成了能直接购买智能的货币，只是不同模型的“汇率”相差巨大。
- Agent 场景火上浇油：一次长任务几十次工具调用，每轮都要重传历史上下文，总消耗轻松冲上几十万 token，缓存命中率直接决定分母的大小。

## 新考核公式：能力 ÷ Token = 效率

具体怎么算？业界正在出现三层指标：

1. **每任务成本（$ per task）**：ARC-AGI 榜单在准确率旁边标注每个任务的美元开销；SWE-bench 社区也在报告“修复一个真实 issue 平均花多少钱”。
2. **每 token 智能**：Epoch AI 统计，同等能力的模型推理价格正以每年数倍乃至上百倍的速度下跌，只看能力排名等于只盯分子，会高估真实性价比。
3. **口径差异**：同一个任务，不同模型输出的 token 量能差 2~5 倍（啰嗦程度、思维链长度、格式冗余不同），叠加单价差异后，总成本能差出一个数量级。

于是企业采购的问法正在改变：从“哪个模型分高”，变成“解掉一个工单花多少钱、多少秒、多少 token、缓存命中了多少”。

## 给分母减肥：六个省 Token 的工程抓手

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/4d6a27268e6bcdef.png)

1. **模型路由**：用打分器或规则把简单请求分流到小模型，难题才升级到推理模型，分母的大头立刻减半。
2. **Prompt caching**：系统提示词、长文档等重复前缀做缓存，命中部分通常只要原价一到五折。
3. **上下文裁剪**：别把整个知识库塞进 prompt，检索命中再注入；多轮对话做摘要压缩。
4. **结构化输出**：约束解码 + 固定 schema，减少模型输出“礼貌废话”的 token。
5. **批处理**：离线任务走 batch 接口，主流厂商基本半价。
6. **蒸馏**：把大模型的长推理链蒸馏进小模型，让“思考”更短更密，单位 token 含金量更高。

## 三条冷思考

1. **效率是分母，不是分子**：把思考 token 压到极限，复杂任务的准确率会塌方。正确姿势是按任务复杂度分层设预算，而不是一刀切地“省”。
2. **警惕指标被玩坏**：考核什么就优化什么。模型可能学会“少说废话”但暗中降低答案质量，评测必须同步做质量回归，防止单一指标博弈。
3. **分母还会继续变**：今天比 token，明天可能比“每焦耳的智能”或“每任务端到端时延”。把成本拆成“单价 × token 量 × 调用次数”的可解释公式，比记住任何单一榜单都耐用。

一句话收尾：榜单告诉你模型有多聪明，分母告诉你它有多划算——2025 年以后，聪明的买家两个都看。
