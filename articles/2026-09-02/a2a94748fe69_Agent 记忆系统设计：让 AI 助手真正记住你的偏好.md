## 背景

现在的 Agent 框架（OpenClaw、各类 MCP 插件）本质上是“无状态”的：每次会话都是白纸。你上周刚告诉它“commit message 用中文、缩进用 4 空格”，这周它照样给你 `feat: update` 加 tab。上下文窗口越来越大，但“塞得下”和“记得住”是两回事——历史记录全堆进去，关键偏好被几百条无关对话淹没，检索精度反而下降。

## 问题

三种常见失败模式：

1. **全塞 system prompt**：偏好越攒越多，token 成本上涨，新旧规则互相矛盾，模型随机挑一条执行。
2. **靠聊天历史**：关键信息埋在噪声里，“上上次他说过”这类依赖时序的偏好基本检索不到。
3. **伪记忆**：Agent 回一句“好的我记住了”，实际只是当轮上下文里的一个 token，下个会话直接蒸发。

核心矛盾在于：记忆需要**写入纪律、读取精度、更新机制**三者齐备，缺一个就退化成摆设。

## 做法

我的方案是三层结构 + 显式工具，全部可以收进一个 MCP server：

**存储分层**
- **L1 工作记忆**：当前会话上下文，不用管。
- **L2 核心偏好库**：结构化记录，按主题拆小文件（`memory/style.md`、`memory/tools.md`），每条带 `type / content / source / timestamp / hits` 字段。
- **L3 事件日志**：会话结束后的摘要（原始对话不存），供后续反思合并。

**写入路径**
- 暴露显式 `save_memory` 工具，只允许两种触发：用户明说“记住”，或同一偏好被用户纠正 2 次以上，且 Agent 写入时必须注明理由。
- 禁止静默写入——每条记忆都能溯源到某次对话。

**读取路径**
- 会话启动时注入两块：10 条以内的 always-on 核心偏好，加上按当前任务检索的 top-k 相关记忆。
- 检索用关键词 + 向量混合。偏好都是短文本，纯向量召回非常不可靠。

**更新路径**
- 新旧冲突走覆盖而非追加，旧条目标记 `superseded` 保留，方便回溯。
- 同级提供 `forget_memory`，"忘记"和"记住"必须是一等能力。

## 踩坑点

- **什么都记等于什么都没记**。早期我把用户提过的所有事都入库，两周后检索结果一半是废话。没有重复、纠正或明确指令的信号，就不写。
- **没有来源字段会死得很惨**。有次 Agent 行为怪异，排查半天发现是三个月前一条失效偏好在作祟。`source + timestamp` 是调试生命线。
- **注入不设上限**。always-on 偏好一度膨胀到 40 条，模型开始选择性失忆。要硬性 cap，超了就强制合并。
- **隐私红线**：密钥、token、路径里的用户名一律不入库，写入前先 redact。

## 可复用建议

1. 别一上来就上向量数据库。一个 markdown 文件 + 显式工具，撑到 200 条记录毫无压力。
2. 记忆工具做成 MCP 一等公民：read / write / search / forget 四个接口齐平，缺一个都会被滥用。
3. 每次注入记忆打一行日志，排障时你会感谢自己。
4. 每月人工 review 一次偏好库，删过时条目——现阶段自动清理的准确率撑不起全自动。

## 总结

Agent 记忆的本质不是“存得多”，而是“该出现时出现、该消失时消失”。显式写入、分层存储、带来源、可遗忘——这套东西没有任何黑科技，但比“把一切交给模型自己理解”可靠得多。先用最土的方案跑起来，等记录真的多到文件装不下，再升级检索。这个顺序，别反了。
