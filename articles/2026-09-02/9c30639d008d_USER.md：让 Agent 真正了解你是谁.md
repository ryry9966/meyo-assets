# 背景

用 OpenClaw 这类常驻 Agent 一段时间后，你会遇到一个尴尬的模式：每次新会话都要重新自我介绍——"我在 UTC+8"、"回复用中文"、"我是后端，别推前端方案"。这些话说过很多次，但 Agent 每次醒来都是白纸。

OpenClaw 的工作区约定里，有一组会注入上下文的文件：MEMORY.md 记动态事实，SOUL.md 定行为风格，而 USER.md 的定位很明确——告诉 Agent "我是谁"。项目知识有 AGENTS.md/CLAUDE.md 管着，用户自己的画像反而常常没人管，散落在各次对话里。

# 问题

不维护 USER.md 的代价是隐性的：

- 偏好靠对话临时传递，上下文压缩或换会话后就丢；
- Agent 用默认假设行事：猜错操作系统、猜错时区、猜错技术栈，输出前总要多纠正一轮；
- 多设备、多会话之间行为不一致，越用越像"陌生人"。

本质上，这是把本该结构化的静态上下文，错放进了易失的对话流。

# 做法

我的 workspace/USER.md 大约 40 行，分四段：

1. **身份与环境**：怎么称呼我、时区、主力设备与 OS、shell、常用目录。例：`Linux 服务器为主，本地 macOS 只做编辑`。
2. **沟通偏好**：中文回复、结论先行、不确定就问而不是编、少用 emoji。
3. **技术栈与习惯**：主力语言、包管理器、代码风格底线。
4. **红线与隐私**：哪些目录不碰、哪些信息不入记忆、密钥一律走环境变量。

写法上守两条纪律：

- **只写稳定事实，不写临时状态**。"最近在搞 K8s 迁移"这类会过期的事放 MEMORY.md，USER.md 里只留"运维方向，K8s 熟练度中等"这种半衰期长的描述。
- **控制体积**。USER.md 每个会话都注入，写 200 行等于给每次对话上税。经验值：一屏以内，超了就该删。

更新机制很简单：养成"纠正账本"习惯——Agent 在同一类个人上下文上犯第二次错，就花 30 秒补一行。文件进 git，多机同步。

# 踩坑点

- **写成愿望清单**。"我想学 Rust"写进去，Agent 会持续推 Rust 教程。写当前状态而非期望状态，或明确标注"仅作背景，不要主动建议"。
- **多轮编辑后出现矛盾条目**。时区改过一次旧条目没删，Agent 时而用旧时区。定期通读，每个事实只出现一次。
- **敏感信息入库**。USER.md 会被各类 skill 和 MCP 工具读到，路径偏好可以写，地址、密钥、客户名不要写。
- **假设所有 Agent 都会读**。主会话会注入，但某些子任务或第三方 MCP 工具不一定继承。"别动生产环境"这类关键约束，要么写进工具配置，要么验证过加载行为再放心。

# 可复用建议

- 把 USER.md 当成"给自己的 README"：稳定、简短、可执行。
- 每月清一次：一个月没被用到的条目，删掉或降级到 MEMORY.md。
- 验证方法：开全新会话，问 Agent "根据你的上下文，说说你了解我哪些信息"，输出和文件对不上，说明加载链路有问题。
- 团队场景可以做一份脱敏模板，新人 fork 后填自己的版本。

# 总结

USER.md 是极轻量的基础设施：一个 markdown 文件，换来 Agent 不再每轮重新猜你是谁。它考验的不是写，而是纪律——写得短、只写事实、错了就记。建议每个跑了超过两周的 Agent 工作区都补上这一份，成本一次，收益长期。
