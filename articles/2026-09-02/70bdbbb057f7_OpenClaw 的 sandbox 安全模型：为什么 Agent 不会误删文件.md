## 背景

让 Agent 直接操作文件系统，是自动化收益最高、也最让人手心冒汗的场景。模型再稳，也会有把 `dist/` 看成 `src/`、把通配符展开得过大的时刻。OpenClaw 的思路很明确：**不指望模型永远不犯错，而是保证犯错之后系统依然安全**。它的 sandbox 不是可选插件，而是默认开启的底层约束。

## 问题：误删到底是怎么发生的

实际排查过的误删事故，来源基本就两类：

1. **权限过大**：Agent 的文件工具直接以用户完整权限运行，任何路径都可写可删；
2. **破坏性操作无缓冲**：`rm` 是真 unlink，没有撤销、没有快照、没有确认。

所以这不是 prompt 工程问题，是权限工程问题。OpenClaw 的安全模型就是围绕这两点分层设计的。

## 做法：五层防线

**第一层：工作区围栏。** 所有文件工具收到的路径，先做 `realpath` 归一化（解析 symlink、`..`），再判断是否落在 sandbox root 内。越界直接拒绝，哪怕是插件发起的请求也一样。

**第二层：操作分级。** 读、写、删除是三个权限级别。删除默认关闭；即使开启，也不是真删，而是移动到工作区内的 `.trash` 目录，默认保留 7 天。

**第三层：破坏性操作前置检查。** 删除/批量写之前，先展开 glob，如果命中数量超过阈值、或者匹配到靠近工作区根的宽泛路径，直接拦截并要求人工确认。也可以配置成 dry-run 模式，只输出"将被影响的文件清单"。

**第四层：MCP / 插件能力令牌。** 每个插件和 MCP server 拿到的是 scoped capability：只能访问声明过的目录、只能执行声明过的操作类别。MCP 子进程本身也跑在沙箱内，不存在"插件绕过文件工具直接碰磁盘"的后门。

**第五层：快照与审计。** 任何 destructive 操作前自动做一次快照（git commit 或内容寻份），审计日志记录时间、调用方、原始请求和完整 diff。

## 踩坑点

- **symlink 逃逸被静默拒绝**：工作区里有个软链指向外部目录，realpath 之后越界，表现为"Agent 突然读不到文件"。先翻围栏拒绝日志，再决定是改结构还是加 allowlist。
- **图省事关掉沙箱**：外部挂载目录写不进去时，正确做法是把它显式加入 allowlist，而不是全局关闭沙箱。后者省十分钟，埋雷一整月。
- **shell 工具绕过文件工具**：Agent 用 shell 命令照样能删文件。OpenClaw 对 shell 工具同样包了一层沙箱（独立命名空间、非 root 运行），但建议在任务配置里再显式禁止破坏性 shell 命令，双保险。
- **`.trash` 污染上下文**：回收站目录会被 Agent 当成普通文件扫描，塞满无关内容。把它排除在索引和扫描范围之外。
- **阈值一刀切**：做批量重构的项目会频繁触发"命中数超限"拦截。阈值按项目粒度配置，不要用全局默认值硬扛。

## 可复用建议

1. **默认拒绝，按需放行**。权限跟着任务走，不要图方便全局放开。
2. **删除等于移动**。任何自动化里的"删"，实现上都应该是"移进回收站 + 定期清理"。
3. **快照先行**。destructive 操作前没有快照，等于没有后悔药。
4. **拒绝必须留痕**。所有拦截写日志，否则排障全靠猜。
5. **定期做对抗性测试**：故意给 Agent 一个"清理工作区外目录"的任务，验证围栏真的拦得住，而不是假设它拦得住。

## 总结

OpenClaw 的 sandbox 安全模型本质上是一套权限工程：围栏限制可达范围，操作分级限制危险程度，回收站和快照保证可恢复，审计日志保证可追查。模型会犯错，这是前提而非风险；工程要做的，是让每一次错误都停在可控范围内、且可以撤回。这比任何"请小心操作"的 prompt 都可靠。
