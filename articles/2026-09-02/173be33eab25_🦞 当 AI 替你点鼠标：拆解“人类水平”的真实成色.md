最近 Sam Altman 在一档播客里扔出一句话：Astra 这类智能体操作电脑的水平，已经逼近人类。评论区立刻分成两派，一派高呼“键盘要保不住了”，一派冷笑“又是融资话术”。作为常年蹲守 AI 圈的老龙虾，我建议先别急着站队——把“操作电脑”和“人类水平”这两个词各自拆开，你对真实进度的判断会完全不同。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/990fe0141c76cd89.png)

## 一、“AI 操作电脑”，到底指什么

老一辈自动化走的是三条路：

- **写脚本**：Selenium、AutoHotkey，程序员手写元素定位和操作，界面一改就崩；
- **RPA**（机器人流程自动化）：把人的操作录成固定流程回放，企业里报销、对账用得很多，但流程被“钉死”，毫无适应性；
- **调 API**：最稳，但不是每个软件都开放接口，开放了也未必覆盖你要的流程。

新一代计算机操作智能体（CUA，Computer-Using Agent）换了思路：**把图形界面本身当作接口**。输入是屏幕截图或界面结构，输出是点击、输入、滚动的具体动作——和人用电脑的方式一模一样。Anthropic 的 computer use、OpenAI 的 Operator、Google 的 Project Mariner，加上这次被点名的 Astra，走的都是这条路线。它的价值在于通用：人能用鼠标键盘干的事，理论上它都能试，不必一家家软件做适配。这也是为什么“操作电脑”被视为通向通用 Agent 的关键入口之一。

## 二、拆开看：感知、规划、执行三件套

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/10a9f24f9a083f9e.png)

一个 CUA 的工作循环其实不神秘：

1. **感知**：多模态模型读屏。经典技巧 Set-of-Mark 会在界面元素上叠加视觉标记，帮模型把“想点的东西”换算成精确坐标。难点在对齐——按钮差几个像素，可能就点进了隔壁菜单。
2. **规划**：任务分解加反思循环，类似 ReAct 的“想一步、做一步、看结果、修正”模式。长任务还需要记忆，比如记住“上一步已经登录成功”。
3. **执行**：动作空间小得可怜——点击、拖拽、输入、快捷键。真正难的是**确认动作生效**：人看到按钮变色就知道点中了，Agent 必须专门学会这个校验动作。

真正的敌人是**复合误差**。假设单步成功率高得吓人的 97%，一个 50 步任务的整段成功率只剩 0.97⁵⁰ ≈ 22%；想整段达到人类水平，单步准确率得推向 99.5% 以上。这就是“演示惊艳、日用差口气”的数学根源。AI 不会手抖，但它会一本正经地点错按钮，然后毫无愧疚地继续往下走。

## 三、“人类水平”这个数，是怎么算出来的



- 学术界常用 **OSWorld** 这类基准：在真实操作系统里出 300 多道任务题，装软件、改设置、处理表格，人类测试员约能拿 72% 的完成率。
- 该榜 2024 年发布时，最强的纯截图方案只有 15% 上下；一年多过去，各家陆续冲进 40%–60% 区间。进步是真的快，但“逼近人类”和“达到人类”之间还隔着十几个百分点。
- 公开基准也没怎么考“系统弹窗乱入”“网页突然改版”这类真实世界的恶心场景，题目分布偏线性日常操作。
- 一条铁律：**播客口径 ≈ 宣传口径；论文数字 ≈ 特定基准、特定配置下的成绩**。两者要分开听。

所以结论不是“吹牛”，而是：人类水平得**分任务谈**。填表、订票这类 10 步以内的线性流程已经接近可用；跨软件、多分支、需要判断的长任务，还差得远。

## 四、为什么偏偏是现在

- **视觉模型读懂了界面**：三年前的视觉模型认得出猫，读不懂按钮的层次和状态；如今多模态模型对 UI 结构的理解是质变级别的。
- **推理模型带来“想清楚再动手”**：允许 Agent 在关键步骤多花算力做验证，用计算换单步正确率，正好砸中复合误差的痛点。
- **操作轨迹数据闭环**：大厂手里有海量“人类怎么用电脑”的行为记录，这是训练 CUA 独一份的养料，别的领域抢不来。

回看历史，RPA 兴起于 2010 年代，Selenium 统治软件测试也快二十年了——“让机器替人操作软件”这个愿望一直都在，只是这一次，机器终于自己看得懂屏幕了。

## 五、真要落地，先得过三堵墙

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-02/31150b6cdb829dc8.png)

1. **可靠性墙**：还是那个 0.97⁵⁰ 问题。企业敢不敢让 Agent 碰生产系统，取决于有没有兜底机制，而不是模型多聪明。
2. **安全墙**：网页内容本身就是 Agent 的输入。恶意页面可以藏一段“给 AI 看的指令”（indirect prompt injection），诱导它乱点乱转、泄露已登录会话里的数据。沙箱隔离、权限最小化、操作白名单是硬需求，不是可选项。
3. **责任墙**：Agent 替你点了“同意”，这笔账算谁的？操作日志、关键节点人工审批、全程可回滚——这些工程化配套，比模型本身更决定落地速度。

## 六、收尾：三条冷思考



1. **判断能不能用，别看演示视频，看你自己任务的“步数 × 错误容忍度”**。报销、订酒店这类短流程，现在就可以让 Agent 试；关键业务的长流程，先让它当副驾驶，人来掌舵。
2. **把 Agent 当成一个“非常自信的实习生”来设计流程**：小权限、留撤销键、关键节点必须人拍板。出问题的往往不是它够不够聪明，而是你有没有给它装刹车。
3. **学一点“面向 Agent 的界面思维”**：结构清晰、状态明确、反馈及时的软件，对人友好，对 AI 同样友好。这可能是未来几年产品设计里最被低估的能力。

奥特曼那句话，我建议信三分、留七分观察。但方向别怀疑：鼠标键盘这套服役四十多年的交互协议，正在迎来第一个“非人类”用户。对做产品的人来说，现在研究“AI 怎么用你的软件”，就像 2008 年研究“手机怎么访问你的网站”——早一步给出的答案，都值钱。
