## 背景

OpenClaw 的 workspace 里有一组约定文件：`AGENTS.md` 管行为流程，`IDENTITY.md`、`USER.md` 管身份与用户信息，而 `SOUL.md` 承担"人格 + 边界"这一层。它会在会话启动时注入 system prompt，相当于 agent 的出厂性格说明书。很多人装完框架直接裸跑，这份文件要么空着，要么照抄模板，等于放弃了成本最低的一次行为调优机会。

## 问题

裸跑的 agent 常见三类毛病：

1. **语气漂移**：白天对话正经克制，深夜自动任务里突然话痨加卖萌，多渠道之间更是判若两 agent。
2. **越界**：替用户做决定（"我帮你拒绝了"）、在未授权的渠道主动发言、对不确定的事一本正经地编。
3. **不可回归**：今天调好的一句话术，明天换个会话就丢了，因为要求只存在于某次聊天记录里。

根因相同：模型默认行为 = 预训练分布 + 临时指令，缺一份稳定的、可版本化的行为基准。

## 做法

给一个最小可用的骨架：

```markdown
# SOUL

## 我是谁
两三句，性格关键词，别写小作文。

## 语气
- 默认简洁直接，中文为主
- 禁止 emoji 堆砌和过度道歉

## 边界（硬性）
- 花钱、删除、对外发送：先确认再执行
- 不确定就说不确定，禁止编造

## 升级规则
遇到拿不准的敏感操作 → 停下来问人
```

迭代流程比初版更重要：

1. 先写 20 行以内的最小版，正常跑一周；
2. 每出现一次不满意的行为，补一条**可执行**的规则，而不是情绪化描述；
3. 进 git，每次提交注明"为什么改"；
4. 与 AGENTS.md 分工：AGENTS.md 管怎么干活，SOUL.md 管是什么样、不做什么。

## 踩坑点

- **写太长**。塞几千字进去，关键规则被稀释，模型反而记不住。边界部分务必短、可判定。
- **拿 SOUL.md 当安全兜底**。它只是提示词层约束，长上下文一冲就淡。支付、删除、外发这类高危操作，必须在工具/插件权限层再兜一层，两层缺一不可。
- **规则冲突**。"永远简洁"和"重要事项详细解释"并列，模型会随机执行其中一个。冲突规则要写明优先级。
- **补丁式膨胀**。一次事故加一条，三个月后变成规则沼泽。定期合并同类项，删掉已由权限层覆盖的条款。

## 可复用建议

- 人格与边界分节写：人格可以宽松，边界每条都要能回答"违没违反"。
- 每条边界配一个触发场景，方便自测和回归。
- 多渠道 agent 在 SOUL.md 里加一小节渠道差异即可，别按渠道复制多份。
- 团队共用时，SOUL.md 进仓库走 PR 评审——改人格和改代码同级对待。

## 总结

SOUL.md 的价值不在"写得像个人"，而在把散落在聊天记录里的隐性要求，收敛成一份可版本化、可评审、可验证的行为基准。一句话：人格是软的，边界要硬；提示词层管性格，权限层管兜底。
