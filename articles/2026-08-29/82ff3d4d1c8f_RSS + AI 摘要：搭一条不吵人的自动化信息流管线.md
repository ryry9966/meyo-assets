# RSS + AI 摘要：搭一条不吵人的自动化信息流管线

## 背景
RSS 一直没死，反而在信息过载环境里重新变得实用。问题是订阅多了以后，阅读压力跟着回来。AI 摘要听起来能解决，但真正跑起来才知道：RSS 源质量参差、正文提取失败、摘要偶尔胡说、推送频率失控，任何一环不稳，管线都会变成另一个噪音源。

这篇文章记录我在 OpenClaw 环境里搭的一条 RSS + AI 摘要管线，重点不是“用 AI 读更多”，而是“少读但不错过”。

## 问题
直接让 Agent 去读 RSS 再总结，通常会有几个坑：

- 很多 RSS 只有标题或摘要，没有全文，AI 只能对着三行字编。
- HTML 正文混入 Cookie 声明、相关推荐、广告位，摘要被带偏。
- 同一篇文章在不同源或不同时间重复出现，造成重复推送。
- 摘要质量不稳定，有时补充原文没有的背景，有时只复述标题。
- 调度失败没有日志，任务挂了几天才发现。

所以这个管线不能只做一个“调 API 的脚本”，要把抓取、清洗、去重、摘要、推送拆开。

## 做法
整体结构很简单：

```text
RSS 源 -> 抓取/解析 -> 正文提取 -> 去重/过滤 -> AI 摘要 -> 推送/落库
```

在 OpenClaw 里，我把它挂成定时插件，或通过 MCP server 暴露 `rss_fetch`、`summarize` 两个工具。这样 Agent 需要时也能主动调用，而不是只能被动等定时任务。

### 1. 源整理与抓取
我会维护一个 `sources.yaml`，每个源包含名称、RSS 地址、分类、是否启用、最大抓取条数：

```yaml
sources:
  - name: infra
    url: https://example.com/feed
    enabled: true
    max_items: 20
```

抓取用 `feedparser` 就够。遇到需要登录或反爬的源，不硬刚，直接换 RSSHub 或其他公开桥接地址。源列表定期清理，长期不更新、内容质量低的直接禁用。源不在多，15 到 30 个高质量源足够。

### 2. 正文提取与去重
RSS 条目的 `summary` 字段经常不完整，所以正文提取不能省。试下来 `trafilatura` 比很多 readability 套壳稳定，对中文正文也更干净。提取后保留标题、原始链接、发布时间、正文纯文本。

去重用 SQLite 落库，主键用 `sha1(link)`。有些站点同一个链接会带不同 UTM 参数，先去掉 `?` 后的追踪参数再计算哈希。遇到同标题但不同链接，可以再用标题前 50 个字符的哈希做辅助判断。

### 3. AI 摘要
摘要质量一半靠 prompt。我给模型的是结构化 prompt，要求输出 JSON：

```text
你只能根据原文提取事实，不得补充背景或进行推断。
如果原文没有说明，输出"未提及"。
输出格式：{"title": "...", "summary": "...", "keywords": ["..."]}
summary 不超过 180 字，中文。
```

批量 5 到 10 条一起处理，温度设置在 0.2 左右。长文先截断到 4000 到 6000 字符，避免上下文超限。摘要结果连同原文链接一起落库，方便回看。

### 4. 推送与落库
推送方式看个人习惯，ntfy、Webhook、Telegram 或邮件都可以。我建议默认只推送每日聚合摘要，紧急或高优先级源才即时推送。OpenClaw 里可以再加一个邮件或 ntfy 插件，把摘要按分类聚合后发出去。

## 踩坑点
- **只有标题没有正文的源**：如果正文提取后长度不足 100 字，直接标记 `skip`，不要硬摘要。
- **HTML 清洗不彻底**：正文里混入“相关推荐”“热门文章”会污染摘要。可以在提取后按常见噪声段落做一次正则清理。
- **AI 幻觉**：模型喜欢补背景。必须在 prompt 里强制“只基于原文”，保留原文链接作为兜底，让用户可以跳回去看。
- **去重失败**：不要只看标题，链接去除追踪参数后再哈希最稳。
- **任务失败静默**：每次运行都写日志，失败时通过 Webhook 告警。管道里一定不要吞异常。
- **推送太频繁**：一天几十条摘要等于没摘要。聚合推送或按关键词过滤，低信息量内容直接不推。
- **时区问题**：RSS 时间格式混乱，统一转 UTC 存储，推送时再转本地时区。

## 可复用建议
- 摘要结果用 JSONL 或 SQLite 存，后续可检索、可回看。
- 源清单用配置文件管理，支持启用、禁用、分类。
- 摘要 prompt 模板化，技术源和新闻源可以有不同的字数限制和输出字段。
- 每次只处理未读条目，状态落库，已处理条目不重复请求。
- 在 OpenClaw 中把摘要工具注册为 MCP，Agent 可以按需查询某条摘要的原文，而不只是被动接收推送。

## 总结
这条管线的目标不是“读更多”，而是“少读但不错过”。稳定比效果重要，先跑通再优化。把抓取、清洗、去重、摘要、推送拆开，每个环节都能单独调试，比一个“一键总结”脚本可靠得多。RSS 本身不吵，吵的是没设计好的推送策略。
