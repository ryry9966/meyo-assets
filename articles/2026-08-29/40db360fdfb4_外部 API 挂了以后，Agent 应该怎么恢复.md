## 背景

在 OpenClaw 这类 Agent 工作流里，外部 API 不是辅助功能，而是执行路径的一部分。搜索、天气、支付、对象存储、模型推理、MCP 工具都可能依赖远程调用。API 一旦超时、限流或返回 5xx，Agent 会直接中断；更糟糕的是把错误当事实继续推理。

很多实践者把精力放在 prompt 和工具选择上，错误恢复却常被简化成“失败就重试”。真实环境里，重试不当会放大故障，降级缺失会让整条自动化链路不可用。

## 问题拆解

外部 API 失败通常有四类：

- 可重试错误：429、502、503、504、网络抖动。
- 不可重试错误：400、401、403、404、参数校验失败。
- 语义错误：HTTP 200 但返回空、字段缺失、格式变化。
- 依赖级故障：上游长时间不可用，需要熔断或降级。

如果只靠 LLM 阅读异常字符串决定下一步，容易产生两个问题：一是模型反复调用失败工具，消耗大量 token；二是错误信息可能泄露内部细节，或诱导模型误判“再试就能成功”。

## 做法：把恢复拆成两层

比较稳妥的工程结构是：工具层负责“怎么试”，Agent 层负责“试不动时怎么办”。

### 1. 工具层：重试、超时、熔断

给每个外部调用统一封装，不要裸调 HTTP。

- 超时：单次请求设置 3–10 秒，避免挂死。
- 重试：只对可重试错误进行指数退避，例如 base 200ms、max 5s，加随机抖动。尊重 429 的 Retry-After，不盲目重试。
- 熔断：连续失败或错误率达到阈值后，短时间内直接返回“服务不可用”，不再打 upstream。例如 30 秒内错误率超过 50%，open 30 秒，之后 half-open 放一个探测请求。

这些规则建议放在 MCP server 或工具 wrapper 里，而不是写在 prompt 里。

### 2. Agent 层：错误协议与降级策略

工具返回给 Agent 的信息应该是结构化错误，而不是原始异常。例如：

```json
{
  "ok": false,
  "error_type": "rate_limited",
  "retryable": true,
  "retry_after_ms": 2000,
  "fallback": "cache",
  "message": "search api 429"
}
```

这样 Agent 可以依据 `retryable` 和 `fallback` 做决策，而不是猜测异常文本。

降级策略要按业务区分：

- 搜索、天气、商品信息：可降级为缓存、上次成功结果或减少结果集。
- 支付、权限校验：不能自动降级，应暂停并转人工或标记待处理。
- 模型推理：可切换备用模型，或返回“暂时无法完成”的结构化结果。

### 3. 状态持久化与幂等

外部 API 调用成功但 Agent 进程崩溃时，重跑可能造成重复扣款或重复发送。关键调用需要幂等键或 request_id，并在任务状态里记录“已调用、未确认、已确认”。这比单纯重试重要得多。

## 踩坑点

- **无限重试循环**：在 prompt 里让 Agent“失败后继续尝试”，没有硬性轮次限制。建议设置 max_tool_calls 或 step 上限。
- **把 400/401 当可重试**：参数错误重试多少次都不会成功，只会放大无效请求。
- **熔断阈值太敏感**：一次抖动就 open，导致服务恢复后仍被挡。阈值应基于错误率和连续失败数，而不是单次失败。
- **返回原始堆栈给 LLM**：可能暴露内部 IP、密钥或依赖结构，也容易让模型产生错误判断。
- **缓存降级不标记 stale**：下游把过期数据当实时结果，造成业务误判。降级结果需要带 `stale: true` 或 `source: "cache"`。
- **忽略 Retry-After**：固定间隔重试在限流场景下会持续被 429 拒绝。

## 可复用建议

- 所有外部调用走统一工具封装，不要在每个插件里各写一套 retry。
- 定义统一的工具返回 schema：`ok / error_type / retryable / fallback / message`。
- 给 Agent 设置全局超时和 max_tool_calls，防止步数爆炸。
- 关键 API 做故障演练：用代理模拟超时、429、5xx，观察 Agent 是否按预期降级。
- 监控四个指标：工具成功率、重试次数、熔断打开次数、降级命中率。出现突增时先看上游，再看工具层配置。

## 总结

外部 API 挂了不是偶发，应该作为常态处理。比较可靠的恢复不是让 Agent 更聪明地读错误，而是把错误分类、重试、熔断和降级做成确定性规则，让 Agent 只负责流程决策。工具层吃掉大部分不确定性，Agent 层保留兜底路径，再加上幂等和监控，自动化任务才能在外部依赖不稳定时继续跑下去。
