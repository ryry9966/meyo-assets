36kr这条热搜，把智谱的新动作形容为“牛到家”，并且“第一刀就砍向DeepSeek”。如果只看字面，容易理解成两家公司又打了一轮嘴仗；但真正值得拆解的是：为什么这轮竞争会从参数规模转向推理成本、Agent落地和开源生态？这背后反映的是国产大模型正在从“能做出来”进入“用得起、用得稳”的阶段。下面从技术、商业和开发者视角，把这场“近身刀法”拆开看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-29/3ce1b302072fd892.png)

## 一、这刀不是营销，是价格与能力双重贴脸

之所以说这轮动作有针对性，是因为它同时踩中了开发者选型的三个关键决策点：成本、场景、迁移。

- **价格贴脸**：过去一年，国产模型 API 价格下降了一个数量级以上。DeepSeek 靠低成本推理建立了“默认选项”地位，智谱则用更低单价、上下文缓存折扣和免费额度，直接降低开发者切换成本。
- **能力贴脸**：DeepSeek 的强项在数学、代码和长推理链；智谱这轮更强调工具调用、浏览器操作、跨应用任务闭环，等于在对手的薄弱侧下刀。
- **生态贴脸**：开源协议、推理框架适配、API 兼容性，都成为比参数更重要的卖点。模型再强，如果工具链不顺手，开发者也不愿上车。

这说明“第一刀”不是砍品牌，而是砍在真实选型中最容易动摇的那几个环节。单点跑分已经很难说服人，能降低多少使用成本、能覆盖多少实际任务，才是硬通货。

## 二、推理成本为什么成为主战场

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-29/92c24698cf2d2f8a.png)

大模型推理不是一次计算，而是“读入上下文+逐步生成”的连续过程。这里有两个核心阶段：prefill 要把输入一次性编码，decode 要一个 token 一个 token 地生成。输入越长，KV cache 占用越大；输出越慢，机器占用时间越长。

DeepSeek 能快速出圈，很大程度靠的是 MLA（Multi-head Latent Attention）和 MoE 架构在长文本推理上的成本优势。智谱 GLM 系列则从量化、投机采样、国产芯片适配等工程方向做压缩。虽然路线不同，但目标一致：把“每单位智能的电费”打下来。

- 如果一个 Agent 完成一次“抓取 30 个页面并汇总成表”需要调用 50 次模型、平均每次 20k token，那么每百万 token 价格从 10 元降到 1 元，单任务成本就从 10 元降到 1 元，很多边缘业务突然变得可做。
- 商业逻辑很直接：API 单价每降一个数量级，能解锁的 Agent 场景就多一层——从偶尔问答，到自动处理邮件、批量报表、持续监控网页。
- 企业在意的不只是标价，而是长上下文满载时的真实计费。有些模型短文本便宜，但 128k 上下文时缓存计费、超时重试会让真实成本翻倍。

所以这轮竞争的本质，不是“谁更聪明”，而是“谁用更低的推理成本，把结果稳定交出来”。

## 三、Agent能力：从“会聊天”到“会干活”

会聊天模型只需要预测下一个 token；会干活的 Agent 需要多步规划、调用工具、理解界面、记住状态、失败重试。这不是同一件事。

- DeepSeek-R1 的推理链很强，但推理链不等于执行链。执行链要求模型在真实环境里完成动作，例如点击按钮、填写表单、滚动页面、跨窗口复制数据。
- 智谱近几代模型在 GUI grounding 和 function calling 上明显加码，目标是让模型从“给出建议”变成“直接交结果”。
- 以一次“自动订会议室”为例：模型要先理解“下周二下午三点、五人、带投影”的约束，再打开日历页面，识别可预订时段，填入人数和设备需求，最后确认。中间任何一步点错、弹窗遮挡、页面改版，都要能回到正确路径。
- 这些能力比拼的不是单一智商分数，而是训练数据里的操作轨迹、强化学习奖励设计和沙箱环境丰富度。

如果一个模型只会聊天，另一个能订会议室、整理票据、自动填表，企业很容易做出选择。Agent 落地不是“加分项”，而是决定模型能否进入生产流程的入场券。

## 四、开源与生态：迁移成本才是隐形护城河

对开发者来说，切换模型不是改一个字符串，而涉及推理框架支持、量化方案、LoRA/微调工具链、API 格式兼容。

- 开源协议越宽松，商业决策越快。DeepSeek 用 MIT 协议把商用门槛打到极低，后续玩家如果协议收紧，开发者会用脚投票。
- vLLM、SGLang、Ollama、llama.cpp 等社区框架的支持速度，决定一个开源模型能否在发布后一周内跑进生产环境。支持晚一周，就可能丢掉一批早期试用者。
- 云厂商适配、私有化部署、国产芯片推理也是 B 端客户考量的硬条件。同样开源权重，A 模型能在国产卡上高效运行，B 模型只能跑在特定 GPU 上，选型天平就会倾斜。
- API 兼容 OpenAI 格式、上下文缓存、batch 推理折扣，这些细节往往比模型跑分更能影响迁移成本。

智谱这轮如果能继续在开源协议、社区支持和芯片适配三条线上贴住 DeepSeek，就等于用生态把“第一刀”的切口扩大。不是一句“我们开源了”就结束，而是要让开发者在真实环境里少踩坑。

## 五、冷思考：价格战之后还剩什么

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-29/f56dd081dc3c8a12.png)

价格战会迅速拉低使用门槛，但也会掩盖一些真实成本。看清下面几点，比盯着一页 PPT 上的价格更有用。

- **不要只看首发价，要看长上下文满载价格**：短文本便宜不代表长任务便宜，缓存命中率、失败重试、并发排队都会影响最终账单。
- **首 token 延迟与并发吞吐同样重要**：实时 Agent 场景里，首 token 超过 1.5 秒可能让用户觉得卡顿，再便宜的模型也留不住 C 端用户。
- **企业选型应看“每成功任务成本”，而不是“每 token 价格”**：一次失败重试、一次人工兜底，可能吃掉几十次成功任务省下的成本。
- **开源不等于免费**：私有化部署要算 GPU/国产卡折旧、推理优化人力、安全合规改造。模型权重不花钱，不代表整套系统不花钱。

最后给三条实用建议：

1. **开发者别只看榜单**：用同一套任务集做 A/B，长文档问答、多步 Agent、工具调用成功率、错误恢复率各跑一遍，记录首 token 延迟和第 99 百分位延迟。
2. **企业采购把“每成功任务成本”写进评估表**：模型单价 × 调用次数 ÷ 成功率，再加失败后的人工兜底成本，算总账。
3. **观望者关注三个变量**：开源协议是否稳定、社区适配是否跟得上、Agent 工具生态是否在扩大。这个窗口期可能按月甚至按周变化，慢一步就可能多付一档推理成本。

国产大模型的竞争已经过了“发布会比参数”的阶段。智谱这刀砍向 DeepSeek，本质是把成本、Agent 和生态拉进同一张牌桌。对普通开发者和中小企业来说，这其实是好事：更低的试错成本、更快的落地速度、更丰富的选择。至于谁先“到家”，最终得看真实任务里谁能稳稳地把结果交出来。
