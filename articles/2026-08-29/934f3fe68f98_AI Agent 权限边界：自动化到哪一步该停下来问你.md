## 背景

在 OpenClaw 这类 Agent 实践中，模型不再只回复文本，而是通过 MCP 工具直接操作文件、浏览器、终端和外部 API。能力变大之后，真正需要解决的从“模型能不能做”变成“我们让不让它做”。权限边界不是一个信任问题，而是一个工程控制问题。

## 问题

如果每一步都问人类，Agent 基本不可用；如果全部自动放行，一个错误命令可能删掉目录、发错消息或污染线上数据。常见的做法有两种：一是把所有工具都设置成 auto approve，出问题后再补救；二是所有写操作都问，很快出现确认疲劳，用户会机械点“同意”。所以需要一套明确、可执行的分级策略。

## 做法

### 1. 给工具分级

先把 MCP 工具按风险拆成四类：

- 只读：查文件内容、读 API、看环境信息。
- 可逆写：改本地草稿、可回滚的配置变更。
- 不可逆写：删除数据、覆盖文件、推送代码。
- 外部副作用：发消息、发邮件、触发支付、调用生产接口。

分级不能只靠工具名，要看参数和上下文。`read_file` 看着只读，但路径参数如果来自不可信输入，可能读取敏感文件；`run_shell` 默认应该是高风险工具。

### 2. 在工具层强制策略

不要只在系统提示词里写“不要删除重要文件”。在 OpenClaw 的工具注册或 MCP 配置里，为每个工具声明 `risk_level` 和 `requires_approval`。例如：

```yaml
tools:
  - name: read_file
    risk_level: low
    auto_approve: true
  - name: write_file
    risk_level: medium
    auto_approve: false
  - name: delete_path
    risk_level: high
    auto_approve: false
    require_confirmation: true
```

工具层拦截的好处是模型无法用话术绕过，审批逻辑独立于提示词。

### 3. 设计三层决策

- **auto**：只读、低风险、已有明确指令的操作。
- **ask**：写操作、影响面不明确、跨环境或涉及敏感数据。
- **deny**：删除生产数据、权限提升、外部发消息，默认拒绝或需要更强的二次确认。

OpenClaw 的流程里，可以设置一个 `pre_flight` 校验：模型生成 action 后，先检查工具白名单和参数，再决定执行还是进入人工确认。

### 4. 关键步骤预演

对高风险操作先做 dry-run 或生成 diff。文件操作先列目录、计算差异；SQL 先 EXPLAIN；git 先展示 status 和 diff。把“将要做什么”变成可见的预览，这会显著减少误批。

### 5. 记录与回滚

每次自动执行和人工审批都记日志，包括工具名、参数摘要、时间、结果。对不可逆操作保留前后快照，或要求工具支持 `--dry-run`、`--backup` 参数。

## 踩坑点

- **把只读当绝对安全**：只读操作也可能把大量内部信息发送到外部模型或服务，信息泄露本身也是风险。
- **确认疲劳**：问得太多等于没问。只问真正不可逆或外部副作用的操作，低风险写操作可以交给策略自动放行。
- **白名单过宽**：一个工具名允许自动执行，但参数可以造成破坏。比如 `shell` 工具允许 `ls`，但参数可能变成 `rm -rf`。尽量用参数校验而非工具名做白名单。
- **测试和生产同权**：测试环境可以放宽，生产环境必须收紧，权限策略按环境区分。
- **只靠提示词约束**：模型可能误解或者被 prompt injection 诱导。最终拦截必须放在工具执行层。

## 可复用建议

1. 为每个 MCP 工具定义 `risk_level`、`requires_approval`、`side_effects` 三个字段。
2. 默认写操作 ask，只读操作 auto，外部副作用默认 deny。
3. 高风险操作要求用户输入特定短语确认，或等待一段时间。
4. 在 Agent 执行前输出 action plan，用户确认后进入批量执行，而不是每个工具都打断。
5. 保留审批日志，每周看一次哪些操作被手动拒绝了，调优策略。
6. 对开放环境或外部输入，降低 auto 比例，防止 prompt injection 借助工具造成影响。

## 总结

AI Agent 的权限边界不是“它可不可信”，而是“我们能不能在错误发生前拦住它”。把工具分级、策略强制执行、关键操作预演和事后审计结合起来，比单纯问“你确定吗”更可靠。自动化该快的时候快，该停的时候停，才是 OpenClaw 这类工具真正可用的工程底线。
