## 背景

在 OpenClaw 里接模型，容易出现两种极端：要么把所有任务都发给 GPT 类云端模型，哪怕只是解析日志、提取字段；要么把本地 7B/14B 当成全能主模型，结果复杂规划频繁失败。两者都会让 agent 看起来“能用但不好用”：前者成本高、延迟大、敏感数据外发；后者工具调用错误多，任务链经常断。

真正需要解决的不是“选哪个模型”，而是“哪类任务走哪条路”。

## 问题

OpenClaw 的典型链路里至少有三类模型调用：

- 主 agent 规划与决策；
- 工具参数生成与 MCP 工具结果清洗；
- 批量、定时或离线任务。

如果只有一个模型配置，就无法同时满足延迟、成本、隐私和能力。复杂推理需要 GPT 类模型，但高频小任务不需要。

## 做法/步骤

### 1. 注册两个以上模型端点

在 OpenClaw 的 provider 配置中，保留至少两类模型：

- `strong`：云端 GPT 系列或兼容 API；
- `local`：本地 vLLM/Ollama/Llama.cpp 暴露的 OpenAI 兼容接口。

不要用 default 覆盖全部任务，给不同 agent/task 绑定不同模型名。

### 2. 给任务分层

我通常这样分：

- GPT 负责：复杂规划、多步工具调用、长文档汇总、模糊需求拆解、异常兜底。
- 本地模型负责：分类、字段抽取、格式转换、日志摘要、脱敏、简单问答、离线批处理。

具体路由表：

| 任务类型 | 推荐模型 | 原因 |
| --- | --- | --- |
| 主 orchestrator 规划 | GPT | 需要多步推理与容错 |
| MCP 工具返回清洗 | 本地 | 高频、结构化、延迟敏感 |
| 敏感数据脱敏 | 本地 | 不离开内网 |
| 长文档总结 | GPT | 长上下文和推理能力 |
| 定时分类/抽取 | 本地 | 批量、低复杂度 |
| 工具调用异常重试 | GPT | 兜底能力 |

### 3. 实现路由

OpenClaw 里可以通过“模型档案”或外层网关做路由：

- 按 agent 类型绑定模型：主 agent 用 GPT，清洗类 agent 用本地。
- 按输入特征路由：统计 token 数，短文本走本地，长文本走 GPT；含敏感字段强制本地。
- 能力降级：本地模型先跑，输出 schema 校验失败或超时，再升级到 GPT。
- 互斥路径：写操作、危险工具、多步决策不交给本地模型。

### 4. 给本地模型加约束

本地模型稳定性不如 GPT，使用时要：

- 固定 `temperature=0`，限制 `max_tokens`；
- 输出 JSON schema 或正则，再加解析器；
- 对工具调用，优先用支持 function calling 的量化版本，但不默认其稳定；
- 先用于只读工具或低风险任务，逐步放开。

### 5. 监控与日志

每个调用记录 `model_name`、`route_reason`、延迟、token、失败类型。没有这些，误路由很难排查。OpenClaw 的日志里至少能看到 agent 名称和模型名，排查时能快速定位是“模型选错”还是“模型能力不足”。

## 踩坑点

- **本地模型工具调用容易缺参或多输出**：同一 schema 会返回额外解释文本。不要在支付、删除等危险工具上直接接本地模型。
- **并发与显存**：多个 agent 同时请求本地模型时，Ollama 会排队，延迟可能从 200ms 升到数秒。限制并发或准备一个小模型专做高 QPS。
- **量化退化**：4bit/5bit 量化对抽取影响小，对推理和总结影响大。不要用量化小模型做规划。
- **上下文静默截断**：本地模型 context 不足时可能不报错，只丢失前文。路由前要统计 token，而不是等失败。
- **成本误判**：本地模型并非零成本，显卡功耗、显存占用、维护时间都要算。小任务量不一定值得上本地 70B。
- **接口兼容**：OpenAI 兼容接口的 `tool_calls`、stop 行为有时和云端不一致。本地服务端要做适配或包装。

## 可复用建议

- 建立“模型档案”：`strong`、`local-fast`、`local-private`，每份档案写清能力、上下文、超时、重试策略。
- 从低风险任务开始切：日志清洗、标题生成、分类。稳定运行一周再扩。
- 为本地模型维护 20-50 条回归集，每次换量化版本或 prompt 后跑一遍。
- 复杂任务保留 GPT 兜底，设置超时与异常升级路径。
- 通过环境变量或配置区分模型，保证 CI、本地、生产可切换，不写死模型名。

## 总结

多模型路由不是把 GPT 换成本地模型，而是把任务按复杂度、风险、隐私和延迟分开。GPT 做大脑和兜底，本地模型做手脚和隐私边界。稳定路由、监控和降级机制，比换一个“更强模型”更重要。
