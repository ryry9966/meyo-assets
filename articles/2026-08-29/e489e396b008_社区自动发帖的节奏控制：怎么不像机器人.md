# 社区自动发帖的节奏控制：怎么不像机器人

## 背景

在 OpenClaw、Agent 或 MCP 插件的自动化发帖场景里，第一版实现通常很简单：cron 定时触发，整点或固定间隔运行，模型生成文本后直接调用发帖接口，结束。功能上没有问题，但发布痕迹非常明显。平台风控和社区用户都很容易通过时间分布、操作路径和内容结构判断出“这不是一个人”。

## 问题

自动发帖暴露的往往不是模型文笔，而是节奏。人类发帖间隔是抖动的，长文和短回复节奏不同，发帖前后通常有浏览、搜索、阅读等辅助行为，遇到失败也不会机械地每 60 秒重试一次。固定间隔、模板化内容、单一路径、无限重试，这四个点是最常见的机器人破绽。

自动化要解决的不是“更像 AI”，而是“更接近一个有点懒、偶尔犹豫、会看两眼再发的人”。

## 做法 / 步骤

### 1. 拆分发帖流水线

不要让 Agent 生成完内容直接发。把流程拆成：

- 内容生成
- 审核 / 过滤
- 入队
- 调度器决定 `execute_at`
- 执行发帖
- 记录结果

在 OpenClaw 里，可以让 Agent 只负责把内容提交到队列，真正发帖由独立的节奏控制器完成。这样调度逻辑和内容生成逻辑解耦，后续调参数不会影响 Agent 主体。

### 2. 时间抖动而不是固定间隔

把固定 interval 改成基础间隔加随机偏移。例如：

- 基础间隔：3600 秒
- 抖动范围：600～1500 秒
- 使用截断正态分布或 Beta 分布，不要用均匀分布

因为人类行为更多集中在中间时段，不会均匀散落在整个时间轴上。同时避免整点、半点、每 5 分钟这种容易被正则识别的规律。

### 3. 队列、冷却和日上限

单账号串行发帖，避免并发触发同一个账号。每次发帖后进入冷却时间，冷却可以根据成功率动态调整：

- 连续成功 5 次，冷却增加 15%～30%
- 命中验证码或限流，冷却指数上升
- 设置 `max_daily_posts`，宁可少发不要多发

同一个板块或同一类话题设置最小间隔，避免短时间内密集出现。

### 4. 内容指纹去重

对“标题 + 正文”做规范化后计算 SimHash 或 MinHash，与最近 N 条内容比较相似度。阈值可以设为 0.82，超过就延迟发布或切换到其他模板。

模板不要只改开头一句“大家好”，要改结构。可以加入日期、版本、场景、引用上下文等变量。如果连续三次发布内容高度相似，应暂停该模板，等待人工介入或重新生成。

### 5. 模拟行为路径

不要只调用一个 `post` 接口。可以通过 MCP 暴露 `read_timeline`、`search_post`、`open_post` 等工具，在执行发帖前按概率调用：

- 30% 概率先浏览两条帖子再发
- 20% 概率先搜索再发
- 10% 概率只打开发帖页停留一段时间

只要调用链不同，行为特征就不会是单一模板。注意这些操作必须是真实可执行的，不要用抓页面伪调用但没处理登录态，那样反而会产生一串 401/403 异常调用。

### 6. 失败重试和熔断

失败不要立即重试。使用指数退避加随机抖动：

- 第 1 次失败：等待 3～5 分钟
- 第 2 次失败：等待 15～25 分钟
- 连续失败或触发风控：进入熔断状态，冷却数小时并告警

不要无限重试把账号逼进黑名单。金属疲劳式的重试很容易被识别为脚本。

## 踩坑点

- 在 Agent 内部用 `time.sleep` 做长时间阻塞，任务不可控。应使用调度器或持久化队列。
- 只加随机间隔，但不改内容模板，仍然会被识别为机器人。
- 随机过头，导致凌晨 2 点发技术帖。必须设置本地时区窗口。
- 忽略平台的限频和社区反馈，继续按老节奏发。
- 用抓取模拟浏览但没有登录态，产生一串 401/403，更容易暴露。

## 可复用建议

把节奏控制器做成独立模块，接口可以很简单：输入 `content` 和 `target`，输出 `execute_at`、`fingerprint`、是否需要冷却。

参数全部配置化：

- `base_interval_range`
- `jitter_distribution`
- `cooldown_factor`
- `max_daily_posts`
- `similarity_threshold`

对 OpenClaw 来说，尽量用 MCP 工具暴露能力，发帖动作要可观测、可回滚。先小号观察 1～2 周，看间隔分布、成功率、被删帖数量和被折叠数量。

让节奏保持人类可解释：工作日略多，周末略少；短回复快，长文慢；遇到突发事件可以暂停，不必机械地保持日更。

## 总结

自动发帖像不像机器人，关键不在于模型能力，而在于发布节奏与行为指纹。固定间隔、模板化内容、单一路径、机械重试是最容易暴露的四个点。

把发帖拆成队列、抖动、冷却、指纹去重和熔断，至少能把“一眼机器人”变成“需要进一步观察”。任何自动化都有被识别的概率，工程上能做的就是延迟识别、控制损失，并保持整个过程可解释、可回滚。
