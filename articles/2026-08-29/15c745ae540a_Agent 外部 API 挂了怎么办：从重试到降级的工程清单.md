## 背景

在 OpenClaw 这类 Agent 框架里，外部 API 通常被封装成 tool 或 MCP server。Agent 的稳定性不只是模型本身的问题，更取决于这些外部依赖是否可靠。

天气、搜索、支付、内容审核、数据查询……任何一个接口超时或报错，都可能让 Agent 卡住、重复调用、给出错误结论。尤其是工具内部如果直接把异常吞掉，返回一段自然语言，模型很容易把“降级结果”当成“权威结果”。

外部 API 挂掉不是小概率事件。它不只是“完全不可用”，常见形态有：超时、429 限流、5xx、返回结构变化、业务错误码。每种故障需要不同的恢复策略。

## 问题

当外部 API 挂了，Agent 链路里通常会出现这些情况：

- 工具一直重试，导致任务长时间无响应；
- 429 时继续硬打，触发更严格的限流；
- 熔断后不再探测，外部恢复了也不知道；
- 降级数据没有标记，模型误判为实时可信数据；
- 异常直接抛给模型，模型开始“编造”结果。

所以错误恢复不能只靠一句“请重试”，需要在工具层做结构化处理。

## 做法 / 步骤

### 1. 先给错误分类

把外部 API 的失败分成三类：

- **可重试**：超时、429、500、502、503、504；
- **不可重试**：400、401、403、404、业务失败；
- **结构错误**：2xx 但字段缺失或类型变化。

结构错误最容易被忽略，但它比 500 更危险，因为请求本身“看起来成功”。

### 2. 基础重试与退避

给工具配置合理超时，比如 2–5 秒；重试 1–2 次；指数退避加抖动，避免同时重试造成踩踏。

```yaml
# 伪配置，不是某个框架现成字段
search:
  timeout: 3s
  retry:
    max: 2
    backoff: exponential
    jitter: 200ms
    on: [timeout, 429, 500, 502, 503, 504]
```

写操作、支付、发送类接口不要无脑重试，优先使用幂等键。

### 3. 熔断与半开探测

连续失败达到阈值后打开熔断，快速失败，避免继续占用 Agent 的等待时间。20–60 秒后放一个请求试探，成功就恢复，失败则继续熔断。

熔断的核心不是“不调用”，而是“快速失败”。让 Agent 尽快知道这个工具暂时不可用。

### 4. 降级与缓存

降级优先级建议：缓存 > 备源 > 静态默认 > 明确失败。

对可缓存结果设置 TTL。天气、汇率、搜索结果等可以接受短时过期。缓存击穿可以加短期负缓存或单飞锁。

### 5. 让 Agent 知道“降级了”

工具返回结构化对象，而不是自然语言错误：

```json
{
  "ok": false,
  "source": "fallback_cache",
  "stale": true,
  "data": { "temperature": 26 },
  "retryable": false
}
```

模型可以根据 `stale` 标记决定是否继续依赖这个结果。不要返回裸异常，也不要把“API is down”直接丢给模型。

### 6. 可观测性

记录每个外部调用的 `api_name`、`latency`、`status`、`retry_count`、`breaker_state`、`fallback_reason`。

没有这些日志，故障排查基本靠猜。

## 踩坑点

- **无脑重试**：429 时疯狂重试可能被封禁，写接口重复提交。
- **所有工具一套策略**：搜索接口可以重试，长任务生成接口 30 秒超时可能不够。
- **忽略返回结构变化**：2xx 但字段没了，比 500 更隐蔽。
- **熔断后永久关闭**：没有半开探测，外部恢复了还不知道。
- **用自然语言吞错误**：模型无法区分“权威结果”和“降级结果”。
- **只在稳定环境测试**：没做过故障注入，上线后第一次遇到故障就是事故。

## 可复用建议

把外部 API 封装成统一 client，内建超时、重试、熔断、降级、日志，避免每个工具单独实现。

在 MCP server 或插件层做错误映射，不让原始异常穿透到 Agent。策略配置化，不要硬编码在 prompt 里。

每次发布前做一次故障演练：手动关掉某个外部 API，观察 Agent 是否快速失败、降级是否生效、模型是否能识别降级结果。

给模型提供简短的能力状态，例如“当前搜索结果可能延迟或来自缓存”，比让它自己猜更可靠。

## 总结

外部 API 挂掉是常态，不是例外。Agent 的错误恢复不能靠更聪明的 prompt，而是靠工具层的超时、重试、熔断、降级和结构化错误处理。

把故障当成一种状态，而不是异常，才能让 Agent 在依赖不可用时仍然可控。
