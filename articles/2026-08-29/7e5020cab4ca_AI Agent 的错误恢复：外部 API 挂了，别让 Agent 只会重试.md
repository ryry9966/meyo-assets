## 背景

在 OpenClaw、Agent、MCP、插件这类自动化链路里，外部 API 不可用不是意外，而是常态。天气查询、支付预下单、OCR、地图逆地理编码、短信发送，任何一个依赖都可能超时、限流、返回 5xx，或者突然改了返回结构。

如果 Agent 没有恢复策略，常见结果有两种：一是直接失败，把整条任务带崩；二是盲目重试，造成重复副作用和上下文污染。更糟的是，模型看到原始错误后还可能产生幻觉，自己“发明”一个结果。

## 问题

很多实现只在工具函数里包一层 `try-except`，捕获后返回一句“调用失败”。这带来三个问题：

1. Agent 不知道错误类型，无法判断该重试、换参数，还是放弃。
2. 重试逻辑放在 prompt 里让模型决定，判断不稳定，且容易反复调同一个失败接口。
3. 没有熔断和降级，一个 API 抖动会拖慢所有任务，甚至把上游打挂。

## 做法/步骤

### 1. 统一外部调用层

所有走 HTTP、gRPC、MCP 的外部调用，都通过一个中间层。中间层只做错误分类：

- 超时、网络抖动：通常可重试
- 429/限流：可重试，但需要更长退避
- 5xx：可重试，但需要熔断
- 4xx 业务错误：不可自动重试，需要反馈给 Agent
- 200 但业务码失败：视为业务错误

错误分类用枚举或常量，不要依赖字符串匹配。外部 API 返回结构变了，只改映射层。

### 2. 设置重试策略

只对幂等请求和可重试错误开启自动重试。例如 200ms、400ms、800ms 指数退避，再加一点随机抖动，最多 2～3 次。

对于非幂等请求，比如支付、创建订单，不自动重试。必须返回结构化错误，让 Agent 或用户决定下一步。

### 3. 加熔断

给每个外部 API 维护一个熔断器。连续失败 N 次，或者错误率达到阈值后，直接快速失败，不再实际请求。熔断打开期间可以返回降级结果。

同时设置半开状态：允许少量探测请求，成功后再恢复。否则 API 恢复了，你的服务还一直不可用。

### 4. 准备降级路径

为关键依赖准备降级数据。比如天气 API 失败时，返回最近一次成功的缓存，并标注数据时间；支付 API 失败时，直接返回“支付通道暂不可用，请稍后”，而不是让 Agent 反复尝试。

缓存要有 TTL 和来源标记，不能让 Agent 把 10 分钟前的天气当成实时数据继续推理。

### 5. 给 Agent 结构化错误摘要

不要把原始堆栈、HTML 或大段 JSON 塞给模型。返回类似这样的结构：

```json
{
  "ok": false,
  "retryable": false,
  "reason": "rate_limited",
  "fallback_used": true,
  "message": "weather api rate limited, cached data from 10 min ago"
}
```

让 Agent 基于摘要决策，而不是基于猜测。尤其在使用 MCP server 时，错误映射要在 MCP 层做完，不要透传第三方噪音。

### 6. 做可观测性

记录每次外部调用的耗时、状态码、重试次数、是否命中熔断、是否使用了降级数据。这样线上 API 故障时，你能快速定位是哪个依赖出问题，而不是逐条翻 Agent 日志。

## 踩坑点

- 对非幂等接口自动重试，导致重复扣款或重复下单。
- 把重试策略放在 prompt 里，模型上下文丢失后反复调同一个失败接口。
- 降级数据没有时间戳，Agent 把过期信息当成实时结果。
- 熔断没有半开机制，API 恢复后服务一直快速失败。
- 对所有 5xx 都重试，但上游实际上已经部分成功，比如支付回调超时但扣款已完成。
- 在错误信息里暴露原始响应，模型看到大段噪声后产生幻觉。

## 可复用建议

- 把外部调用封装成统一工具或中间件，不要在每个 Agent 脚本里散落裸请求。
- 错误分类用常量或枚举，外部 API 结构变更只改映射层。
- 在测试环境加入故障注入：模拟超时、429、5xx、畸形 JSON，验证降级路径是否可用。
- 关键 API 准备静态降级表或本地缓存，并让 Agent 明确知道“这是降级数据，不是实时数据”。
- 重试、熔断、降级配置集中管理，不同 API 可以有不同的失败阈值和退避策略。

## 总结

外部 API 挂了以后，Agent 的错误恢复能力不是靠“多试几次”，也不是靠“让模型看着办”。真正有效的是在调用层做好错误分类、重试、熔断、降级、结构化反馈和可观测性。这样 Agent 才能从“调用失败就崩溃”，变成“失败后仍能给出可用的下一步”。

工程上，一次外部 API 故障就是一次链路体检。你不可能阻止所有外部依赖挂掉，但可以决定 Agent 在挂掉之后是继续提供降级服务，还是把整条任务一起带走。
