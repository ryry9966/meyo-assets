最近硅谷有个讨论正在升温：如果说上一轮平台机会属于 Harness 这样的开发者工具平台，那么下一个“Harness 级”机会，可能不是某个 App，而是整个桌面操作系统。理由很直接——大模型开始能看屏幕、点按钮、拖窗口、跨应用执行任务，操作系统从“被用户操作”变成“被智能体操作”。桌面 OS 的入口价值，正在被重新估值。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/e9fd95c5fb69ccbf.png)

## 先弄清“下一个 Harness”在指什么

Harness 并不是一家操作系统公司，它是一家从 CI/CD 起步的开发者平台。它的成长路径可以概括为三步：

- 先在交付流水线里找到高频痛点，用自动化替代人工；
- 再围绕工作流扩展出云成本管理、Feature Flags、安全测试等模块；
- 最后卡住企业软件交付的入口，形成平台定价权。

硅谷说“下一个 Harness”，指的不是再造一个 Harness，而是找下一个能把单点工具长成工作流平台的层。桌面 OS 刚好具备这种潜质：应用启动、文件管理、剪贴板、权限、通知、输入法、搜索，天然就是工作流底盘。过去这个层被认为“稳定但无聊”，Windows 和 macOS 各占生产力场景，移动端由 iOS 和 Android 分割，格局多年未变。当 AI 能在这一层稳定操作时，它就从静态的软件运行环境，变成了可编程的控制面。

## 技术拐点：从“调 API”到“操作屏幕”

过去自动化桌面主要有两条路：脚本/API，稳定但覆盖率低；RPA 模拟点击，覆盖广但脆弱。这一轮变化来自多模态 LLM 的屏幕理解能力，以及几个条件的同步成熟：

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/969ea3942118950d.png)

1. **多模态视觉 grounding**：模型不只是识别文字，还能理解按钮、窗口、表格、图标之间的空间关系；
2. **长上下文与多步规划**：一个任务可以被拆成几十个界面动作，并记住前面步骤的结果；
3. **隔离执行环境**：虚拟机、容器、沙箱让 agent 可以在受限环境里试错，减少对宿主系统的破坏；
4. **成本下降**：反复截图、推理、再截图，在算力足够便宜之后才具备工程可行性。

关键链路可以拆成四步：

- **Observe**：截取当前屏幕，理解窗口结构、按钮、输入框、表格内容；
- **Plan**：把“整理本周周报并发送”拆成若干界面动作；
- **Act**：输出鼠标坐标、键盘输入、滚动、拖拽等操作；
- **Verify**：再次截图，判断动作是否生效；失败则回溯重试。

一个典型例子是：让 agent 把收件箱前三封未读邮件摘出要点，写入 Notion。它需要先定位邮件客户端，理解未读列表，逐个打开、截图、总结，再切到 Notion 操作。这个过程中模型不是“执行代码”，而是在做界面推理。

## 桌面 OS 为什么重新变得值钱

桌面操作系统的平台价值，集中体现在三个层面：

- **入口**：用户大部分数字工作流从 OS 启动——打开浏览器、编辑器、终端、聊天软件。谁控制了 agent 与 OS 的接口，谁就控制了任务分发；
- **上下文**：桌面上有很多未上传到云的私有数据：本地文档、邮件、日历、代码库、财务表格。agent 在本地能看到的上下文，往往比云端 API 更完整；
- **分发与权限**：OS 能决定默认助手、后台运行策略、通知方式、文件访问范围。这种控制力类似移动互联网时代的应用商店与推送权限。

历史上，浏览器曾经成为 Web 应用的入口平台，移动 OS 通过应用商店和通知权限控制生态。现在桌面 OS 有可能重演这一幕：不是重新做一个操作系统，而是 OS 层变成 AI agent 的控制面与应用分发通道。这也是硅谷重新押注它的根本原因。

## 三条路线，和各自的代价

目前硅谷押注的做法并不完全一样，大体可以分成三类：

- **屏幕像素派**：直接让模型看截图、输出鼠标键盘动作。优势是不依赖第三方应用开放 API，长尾软件也能操作；缺点是慢、成本高、容易点错，界面一改就可能失效；
- **结构化 API 派**：操作系统或应用提供 Intent、Accessibility、UI Automation 等结构化接口，agent 调用 API 完成任务。优点是稳定、审计友好、执行快；缺点是覆盖率受限，需要生态配合；
- **混合派**：先用视觉模型定位界面元素，再通过可用的 API 或无头模式执行动作。这样既有长尾覆盖，又能在关键步骤保持稳定。

从工程角度看，混合路线更可能先在企业场景落地。纯像素操作做 demo 很惊艳，但生产环境对错误容忍度很低。一些公开项目已经展示出两种路径的差异：在受控测试集上很流畅，到了真实桌面、复杂弹窗、多屏切换时，成功率会明显下降。

## 真正的问题不是“AI会用电脑”，而是“你敢让它用吗”

技术能操作桌面，并不等于企业敢把权限交出去。几个现实约束：

- **安全风险**：提示注入、恶意界面诱导、误点支付/删除按钮，都可能在像素级操作中被放大；
- **可靠性**：长任务错误会累积。如果 10 步操作每步成功率是 95%，整体成功率可能不到 60%；
- **隐私合规**：屏幕内容要上传到模型，涉及代码、客户数据、内部文件，企业合规边界不清；
- **评估困难**：demo 视频不能替代指标体系。需要盯着任务完成率、单任务成本、误操作率、人工接管率。

权限模型也是绕不过去的坎。文件系统 ACL、钥匙串、浏览器 cookie、终端命令，都需要比“允许截图”更细粒度的授权。否则 agent 的每一次操作，都可能变成一次凭据泄露或误删事故。

## 三条冷思考，给想入场的团队

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/e0f62c0b29b9948b.png)

1. **先做窄场景，不做通用电脑管家**。报销发票录入、客服工单摘要、本地文件归类、测试环境巡检，这些边界清晰、结果可验收的任务更容易跑通；
2. **权限与审计先行**。给 agent 最小可用权限，保留详细操作日志，支持一键暂停和回滚。否则一次误操作就可能抵消所有效率收益；
3. **技术选型按稳定性排序**：有官方 API 的优先 API，长尾界面才考虑像素操作，混合架构做兜底。别把“能点”当成“能上线”。

如果桌面操作系统真的成为下一个 Harness，赢家大概率不是喊得最响的 demo，而是能把权限、审计、可靠性、成本一起解决掉的那一层。
