过去一年，几乎每一家 PC 厂商都在发 AI PC：高通、英特尔、AMD 轮流发布高 TOPS 的 NPU，OEM 抢着贴“Copilot+ PC”认证。但很多用户买回家后发现，能感知到的 AI 功能依旧停留在视频会议虚化、实时字幕和聊天机器人侧边栏。36kr 那条“Windows 是 AI PC 路上的绊脚石”之所以扎眼，是因为它戳破了一个被营销掩盖的问题：硬件已经换了几轮，操作系统这层地基却在沿用旧逻辑。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/4431e8e43789280d.png)

## 一、不是芯片不够快，是系统太重

Windows 最大的优势是兼容性，最大的代价也是兼容性。为了继续运行几十年前的 Win32 应用、旧驱动和行业软件，系统必须长期保留大量兼容层、后台服务与全局钩子。这对传统办公是好事，对端侧 AI 却是负担。

- 后台任务拥挤：Windows Update、搜索索引、Defender 实时扫描、OEM 预装服务等常驻进程，会在你唤醒 AI 助手的同一时刻抢占 CPU、磁盘与内存。
- 调度逻辑偏传统：Windows 调度器更擅长“长任务吞吐”，而端侧小模型推理是典型短突发、低延迟、高唤醒频率的任务。系统常把 NPU 当普通外设，而不是实时推理的第一优先级。
- 内存策略不友好：本地大模型对内存带宽和驻留很敏感，Windows 的内存压缩、分页和后台预加载策略，可能让一个 7B 模型在冷启动时多等几秒——这几秒足以让体验从“智能”变成“卡顿”。

换句话说，AI PC 的硬件素质已经不错，但 Windows 的“系统摩擦”会吃掉一部分体验红利。

## 二、NPU 有劲儿，但“车道”没修好

如果只看参数，2024 年以后的 AI PC NPU 算力普遍达到 40 TOPS 以上，部分平台甚至超过 50 TOPS。但 TOPS 更像一个理论峰值，不代表应用真的能稳定、高效地跑在 NPU 上。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/a170cc76f862a938.png)

- API 与 SDK 碎片化：开发者面对的是 Windows ML、ONNX Runtime、DirectML、各芯片厂商 SDK 并存的局面。Intel、AMD、Qualcomm 的 NPU 工具链不同，同一套模型要在三套平台上分别适配。
- 缺少统一的 NPU 资源视图：Windows 任务管理器直到较新版本才加入 NPU 占用显示，但仍不够细。开发者很难判断一个算子到底落到 NPU、GPU 还是 CPU，出了问题也不好定位。
- 可用场景仍太少：除了视频通话虚化、语音转文字、相机增强等少数几类，真正原生调用 NPU 的常用软件并不多。很多所谓 AI 功能其实是云端 API 套壳，端侧 NPU 长期空转。
- 对比更显落后：Apple 的 Core ML 与 ANE 从硬件到框架高度垂直整合，Android 也在 NNAPI/NN HAL 上不断收紧生态。Windows 生态则是横向开放但纵向不深，导致“有硬件、少应用”。

这就是为什么很多开发者说，AI PC 的瓶颈不在 TOPS 数字，而在调用链路的成熟度。

## 三、Windows on ARM 的阵痛：另一条腿还不稳

AI PC 想真正摆脱功耗和散热限制，ARM 架构是一条重要路线。高通骁龙 X 系列让 Windows on ARM 的续航和 NPU 效率明显提升，但生态兼容问题仍未完全解决。

- x86 模拟有损耗：大量传统 x86 应用通过仿真运行，复杂插件、驱动、专业软件容易出现性能下降或直接不兼容。
- AI 开发栈支持不足：PyTorch、TensorFlow 等框架的 ARM 原生 Windows 支持仍不完善，CUDA 生态更是暂时无解。开发者想在 ARM 设备上做本地模型微调或推理，常常要绕路。
- 外设与驱动跟不上：打印机、网银 U 盾、企业 VPN、行业采集卡等长尾设备，驱动适配进度慢，直接影响企业采购。
- Apple 的过渡之所以更快，是因为它从芯片、系统到 Rosetta 2 和开发工具都完全自控；而 Windows on ARM 需要微软、高通与数百家 ISV 一起动，协同成本高得多。

## 四、OEM 预装与“AI 功能通胀”

Windows 生态还有一个特殊问题：OEM 为了卖点，会预装大量第三方 AI 软件。这些软件往往不是深度集成，而是以常驻小工具、弹窗助手、云服务入口的形式存在。

- 资源占用叠加：一台新机可能同时有厂商 AI 助手、微软 Copilot、第三方语音助手和系统级 AI 组件，后台进程互相唤醒，反而拖慢整机。
- 功能重复与混淆：用户分不清哪些是本地 NPU 加速，哪些是联网调用；同一台电脑里有多个“AI 助手”，体验割裂。
- AI PC 与普通 PC 边界模糊：微软把不少 AI 功能通过 Windows Update 下放到旧设备，导致消费者很难感知新硬件的必要性，进一步削弱 AI PC 的购买理由。

这层“预装通胀”不是 Windows 内核的问题，但却是 Windows 商业生态与 AI PC 叙事难以对齐的体现。

## 五、不能只骂 Windows：它也在被推着改

把责任全推给 Windows 也不公平。Windows 仍然是企业 IT、游戏、工业软件和开发工具链最完整的平台，这是 macOS 和 ChromeOS 短期内无法替代的。

- 微软已经在推进 Windows Copilot Runtime、Phi Silica 等端侧推理方案，尝试把小型语言模型直接跑在 Windows 本地。
- DirectML 和 ONNX Runtime 的支持在改善，NPU 调度也不再完全黑盒。
- 对大多数企业来说，平滑迁移比极致 AI 体验更重要。Windows 的保守，某种程度也是它最大的商业壁垒。

所以更准确的说法是：Windows 不是 AI PC 的敌人，而是 AI PC 必须翻越的旧基础设施。

## 实用建议：普通人怎么避开“AI PC 陷阱”

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/110ad01b0479855c.png)

1. 别只盯 TOPS 数字。购买前先确认你常用的软件是否真的支持 NPU 加速，比如视频会议、转录、图片降噪是否有明确适配。没有真实应用落地的 TOPS，只是参数表上的装饰。
2. 优先选内存和调度更友好的机型。端侧 AI 对 32GB 以上内存、带宽和厂商驱动优化更敏感。部分机型虽然 NPU 标称高，但散热或调度保守，实际体验可能不如低一档但系统优化更成熟的型号。
3. 开发者先做跨硬件验证。如果要做端侧 AI 应用，优先基于 ONNX Runtime 或 DirectML 构建，避免绑定某一厂商 SDK；企业部署 AI PC 前，先用小批量设备验证“端侧任务是否真的落在 NPU 上”，而不是被营销 demo 误导。

AI PC 的长期方向没有问题，但 Windows 的重构速度会决定这条路的通车时间。对消费者来说，现在更重要的是买一台“真的能跑 AI 的 PC”，而不是为一张“AI PC”贴纸买单。
