# 外部 API 挂了，Agent 如何不把整条链路带崩：错误恢复实践

## 背景

在 OpenClaw 这类 Agent 编排环境里，真正容易出问题的往往不是模型本身，而是模型调用的外部世界：搜索 API、网页抓取、CRM、支付、通知、MCP 工具。外部 API 超时、限流、5xx、返回脏数据是常态。很多 Agent 的默认行为是：工具抛错 -> 把异常文本丢回模型 -> 模型再试一次 -> 再失败 -> 上下文越滚越大，最后任务中断或产生错误结论。

这暴露一个核心问题：Agent 的错误恢复不能只靠模型“聪明地理解错误”，而要提前在工具层和编排层把故障处理掉。

## 问题拆解

外部 API 故障通常分几类：

- 瞬时故障：网络抖动、服务重启、偶发 502/503
- 限流：429 或 Retry-After
- 超时：API 无响应或慢查询
- 业务错误：4xx，参数错误、权限不足
- 脏数据：返回 200 但结构缺失/半截 JSON

如果这些错误直接以异常或 HTML 堆栈形式返回给模型，会带来三个后果：

1. 模型把错误当成事实，继续编造或做出错误决策；
2. Agent 无限重试，造成 API 压力和 token 浪费；
3. 一个工具失败导致整条工作流失败，没有降级路径。

## 做法/步骤

### 1. 在工具客户端层先做错误分类

不要在每个 Agent 任务里判断错误。为外部 API 封装统一客户端，在边界处将异常转成结构化错误：

```json
{
  "ok": false,
  "error_type": "rate_limited|timeout|server_error|client_error|bad_response",
  "retryable": true,
  "message": "upstream returned 429",
  "retry_after_seconds": 3.2,
  "fallback_hint": "use_cache_or_secondary_api"
}
```

这样模型或编排器拿到的是机器可读信息，不是一段异常堆栈。

### 2. 设置超时与重试策略

对每次外部调用设置明确超时，建议：

- 默认连接超时：2-5 秒
- 读超时：10-20 秒，按 API P95 调整
- 重试：只对 `retryable=true` 的错误重试，最多 2-3 次
- 指数退避 + 抖动：例如 `min(backoff * 2^attempt, 30s) + random(0, 1s)`

避免所有 Agent 实例同时重试造成 thundering herd。若 API 返回 `Retry-After`，优先遵守。

### 3. 增加熔断与降级

当某个外部 API 连续失败达到阈值（如 30 秒内 5 次失败），打开熔断器，后续请求直接返回结构化降级结果，不再打真实 API。熔断打开一段时间后进入半开状态，允许少量探测请求。

降级路径按业务优先级设计：

- 搜索 API 挂了 -> 用本地索引或上一轮缓存结果
- 支付状态查询挂了 -> 返回 `unknown` 并触发人工确认，而不是当成“未支付”
- 通知 API 挂了 -> 写队列稍后重放，不阻塞主流程

### 4. 让 Agent 根据错误类型做决策

在 OpenClaw/MCP 工具描述中明确错误语义，让模型知道遇到 `rate_limited` 可以等待后重试，遇到 `client_error` 应停止或检查参数，遇到 `server_error` 可切换 fallback 工具。更稳的做法是在编排层写规则：某些错误类型不允许模型自由重试，直接走降级/终止。

### 5. 幂等与缓存兜底

凡是有副作用的外部调用（创建订单、发消息、写 CRM），必须做幂等键。重试时带上同一 `idempotency_key`，避免重复创建。读类 API 可加短 TTL 缓存（如 30-60 秒），在 API 抖动时直接返回最近一次成功响应。

## 踩坑点

- **把原始错误直接抛给模型**：模型可能被 500 页面的 HTML 干扰，甚至把错误页当数据解析。
- **无差别重试**：对 4xx 也重试，只会反复制造无效请求；对非幂等 POST 重试可能产生重复数据。
- **降级返回空结果但标记成功**：搜索降级返回空列表，Agent 可能得出“没有相关信息”，实际上只是 API 挂了。
- **超时设太长**：一个慢 API 拖住整个 Agent 并发，后续任务排队超时。
- **缺少熔断**：一个下游故障持续被打满，拖垮整个编排。
- **没有记录重试和降级事件**：事后无法区分“模型判断错误”还是“上游 API 挂了”。

## 可复用建议

1. 封装统一 `api_call` 工具客户端，内置超时、重试、熔断、降级、日志。
2. 错误返回固定 envelope，至少包含 `ok`、`error_type`、`retryable`、`fallback_hint`。
3. 重试只针对瞬时故障与限流，副作用调用必须幂等。
4. 所有降级结果要标记 `degraded: true`，避免模型误判。
5. 在编排层限制单任务最大重试次数，防止 Agent 自己无限循环。
6. 为关键外部 API 配置熔断阈值和告警。
7. 记录每次外部调用的状态、耗时、重试次数、是否降级，用于回放和优化。

## 总结

外部 API 挂掉不是异常，而是工程常态。Agent 的错误恢复不应该靠模型临场发挥，而应把重试、熔断、降级、幂等这些基础能力下沉到工具客户端和编排层。让模型只做它擅长的事——理解任务和选择路径，而不是处理混乱的异常文本。这样即使某个外部服务不可用，Agent 也能体面降级，给出可解释的结果，而不是把整条链路带崩。
