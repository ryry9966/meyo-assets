AI 圈又传来一则让硬件工程师们坐不住的消息：曾主导谷歌 TPU（Tensor Processing Unit）架构的核心人物，被 Anthropic 连夜挖走。这不是简单的跳槽新闻，而是一次算力竞争格局的微小地震。TPU 是谷歌 AI 能大规模落地的底层功臣，从搜索、翻译到 Gemini 都在依赖它；而 Anthropic 作为 Claude 背后的公司，正在大模型推理成本上寻找突破口。一位顶级芯片架构师的选择，往往会影响未来五年的产品路线。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/2d723ab0838cded0.png)

## 1. TPU：谷歌 AI 的“自研底牌”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/3818719d33f13bc5.png)

- 2013 年谷歌内部启动 TPU 项目，直接动因是：如果用当时市面上的 GPU 来支撑语音搜索，谷歌可能得新建大量数据中心。据 Jeff Dean 等人在论文中透露，当时数据中心规模如果扩张一倍，成本几乎是不可接受的。
- 第一代 TPU 于 2015 年部署，专门为神经网络的推理（inference）设计，而不是训练。它采用脉动阵列（systolic array）架构，让数据在芯片内像流水线一样流动，减少对内存的反复读写。
- 与 GPU 的通用计算路线不同，TPU 把大量晶体管用在 8-bit 整数乘加运算上，峰值吞吐很高，单位功耗性能大幅领先同代 GPU。第一代 TPU 在 ResNet 等模型上的推理能效比，比同期 GPU 高出 30~80 倍。
- 到了 TPU v4，单 pod 可扩展到 4096 颗芯片，总算力超过 1 exaflop（FP16 精度下），液冷设计让整个数据中心像一台超级计算机。TPU v5p 则进一步把训练和推理放到同一架构下，支持更大规模的 MoE 模型。
- 那位被称为“TPU 之父”的架构师，就是在这条从推理到训练再到超大规模集群的演进中，扮演了从 0 到 1 的角色。这类人才在全球范围内屈指可数，因为芯片架构的试错成本极高，一次流片失败可能就浪费数千万美元。

## 2. 大模型时代，推理正在吃掉算力预算

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/86cc1366289b3c60.png)

- 2023 年之前，AI 算力的叙事中心是“训练”：谁的集群大、谁的模型参数多。但 2024 年以后，越来越多的预算流向推理（inference）。部分云厂商的财报电话会中，推理收入已超过训练收入。
- 一个直观数据参考：如果某个大模型 API 每天处理 10 亿次 token 生成请求，单次推理成本哪怕只差 0.001 美元，一天就是百万美元级别的差距。Anthropic 的 Claude 同样面临这种规模效应。
- 推理负载的特点是高并发、低延迟、长上下文。这要求芯片不仅算得快，还要有极高的内存带宽来搬运 KV cache（键值缓存），否则 token 生成速度会明显下降。以 100k 上下文为例，KV cache 可能占满几十 GB 的显存，带宽瓶颈比算力瓶颈更突出。
- 通用 GPU 虽然也能跑推理，但在单位功耗和单位成本上并非最优。专用 ASIC（如 TPU、Groq 的 LPU）通过定制数据通路、片上 SRAM、精简调度，可以在特定模型上做到 2~5 倍的成本优势。
- 更微妙的是，模型结构正在变化：MoE（混合专家）要求更大的内存和通信带宽，稀疏注意力要求硬件支持动态路由。早期 TPU 的推理基因反而更契合这些需求。
- 这种趋势下，具备推理芯片设计经验的人，比只会做训练集群的人更抢手。而 TPU 恰好是从推理起家的。

## 3. Anthropic 为什么需要“TPU 之父”？

![img3](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-24/7c4bb1f9f474be08.png)

- Anthropic 目前主要依靠第三方云平台提供算力，训练和推理都要支付“芯片税”。随着 Claude 的 API 调用量增长，这部分成本会从技术问题变成生存问题。
- 自研或定制芯片的逻辑很直接：如果推理成本能降低 30%，同样的定价下毛利会显著改善；如果成本降低 50%，价格战的空间就大了。对于以 API 为主要商业模式的公司，推理成本就是生命线。
- 但芯片不是软件，从架构定义到流片（tape-out），再到编译器、算子库、集群互联，通常需要 2~4 年。没有顶级架构师，这个周期可能更长，甚至项目中途夭折。
- 挖来 TPU 之父级别的角色，等于把谷歌十多年在推理 ASIC 上的踩坑经验“浓缩”进 Anthropic。虽然不能直接复制代码或版图，但架构取舍、数据流设计、功耗规划这些隐性知识，才是真正的护城河。
- 从招聘动作看，Anthropic 最近在硅谷芯片圈频繁接触有 ASIC 背景的工程师，甚至开出了不设上限的薪资包。这说明它的目标不是小修小补，而是长期布局。
- 当然，Anthropic 并不会立刻抛弃现有云厂商。更可能的是“双轨策略”：短期继续采购 GPU/TPU，中期与云厂商联合定制芯片，长期孵化自己的推理 ASIC 团队。云厂商也会心生芥蒂，但算力生意的博弈本来就在于谁掌握底层主动权。

人才流动从来不是孤立事件。从 x86 时代的 AMD 挖角 Intel，到移动芯片时代的苹果挖角高通，再到 AI 芯片时代的这场抢人，底层逻辑都是：架构师的决定会影响未来五年的产品路线。但单一人才并不能直接改变格局。芯片研发是系统工程，软件生态、编译器、集群运维同样重要。

**三条冷思考：**

1. **对创业者和开发者**：不要只盯着模型参数和 benchmark，关注 API 的每百万 token 成本、推理延迟和长上下文表现。这些指标才是产品能不能规模化的关键。
2. **对工程师**：如果做 AI infra，除了 CUDA，最好补上编译器（MLIR/TVM）、量化、内存系统的知识。未来推理芯片的岗位会越来越多，但要求也更偏系统协同设计。
3. **对企业决策者**：自研芯片不是“招一个大神”就能解决的。先想清楚推理负载是否足够大、生命周期是否足够长，否则定制 ASIC 的流片费用会把账算穿。

算力竞赛没有终局，只有下一局。TPU 之父的去向，只是下一局刚刚开始。
