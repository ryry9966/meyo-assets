## 背景

在 OpenClaw/Agent 类实践里，很多人把“记忆”简单理解为：把历史聊天记录、用户偏好、项目约束尽量塞进 system prompt。短期看起来有用，但任务变多后，问题会集中暴露——上下文越来越长，Agent 注意力被稀释；旧偏好覆盖新偏好；每次会话仍要重新解释规则。

原因在于，偏好记忆不是“存储”问题，而是 **抽取—存储—召回—冲突解决** 四个环节。只做其中一段，系统都会不稳定。

## 常见问题

- **全量上下文化**：token 膨胀，推理质量下降，成本同步上升。
- **键值对式记忆**：只能精确匹配，用户换一种问法就召不回。
- **仅有自动抽取**：Agent 把一次临时选择当成长久偏好，后续错误持续复现。
- **记忆不更新**：用户已经改了偏好，Agent 仍按旧规则执行。

## 落地做法：分层记忆 + MCP 接口

建议至少分三层：

1. `profile`：用户显式偏好，例如“代码风格用 ruff format”“默认分支 main”“回复使用中文”。
2. `project`：项目级事实，例如部署环境、目录结构、关键约束。
3. `session`：短期任务状态，会话结束或超时后清理。

轻量场景先用 SQLite 足够，不必一上来就上向量库。可以先用下面这种结构：

```sql
CREATE TABLE memory (
  id TEXT PRIMARY KEY,
  type TEXT NOT NULL,          -- profile / project / session
  key TEXT NOT NULL,
  value TEXT NOT NULL,
  source TEXT NOT NULL,        -- explicit / inferred
  confidence REAL DEFAULT 1.0,
  evidence TEXT,               -- 来源对话或用户原话
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  expires_at TEXT,
  project_id TEXT
);
```

对外暴露成 MCP tool 比较自然：`memory_search`、`memory_save`、`memory_delete`。这样 OpenClaw 或插件调用时不关心底层是 SQLite 还是向量库。`memory_search` 先按 `project_id` 过滤，再做关键词或 embedding 检索，限制返回 top 5，并控制每条 `value` 长度。

写入策略是重点：**只把高置信度偏好自动写入 profile**。临时选择进 `session`，不进入长期记忆。例如用户说“这次先把日志级别调成 debug”，这是 session；用户说“我平时就要详细日志”，才进 profile。`confidence` 低于阈值的推断只保留 evidence，不直接生效。

召回时，先注入显式 profile，再按当前项目检索 project memory，最后才是 session 状态。**显式设置永远优先于推断结果**，避免自动抽取的错误偏好压过用户真实表达。

## 踩坑点

1. **把一次行为当长期偏好**：自动抽取容易把“这次用 pnpm”写成“用户喜欢 pnpm”。解决方式是要求抽取时包含 evidence，首次写入 confidence 设为 0.6 以下，连续出现再提升。
2. **记忆无限增长**：不清理的记忆会变成噪音。session 设 TTL，project 记忆定期 review，profile 只保留高频或用户明确要求的内容。
3. **冲突不处理**：用户先说不喜欢 Docker，后来项目里又说用 Docker。建议保留时间戳和 source，冲突时以最近显式表达为准，同时保留旧记录可回溯。
4. **只用相似度召回**：纯 embedding 可能返回语义相近但时间久远的条目。需要加入时间衰减、项目过滤和 key 匹配，必要时先用全文检索兜底。
5. **隐藏写入失败**：记忆写入失败会静默，下次对话又回到原点。务必记录写入/召回日志，提供 `/memory status` 一类调试入口。

## 可复用建议

- **显式优先**：给用户一个 `/pref` 或 `!memory set` 入口，显式设置直接落 profile，减少猜测。
- **分层且隔离**：项目记忆不要污染全局偏好；不同 `project_id` 之间默认不互相检索。
- **每条记忆都要有 source 和 evidence**：方便排障和回溯。
- **先 SQLite，后向量库**：几百条以内用 SQLite 关键词查询足够，复杂度更低、可维护性更好。
- **做成 MCP server**：可在 OpenClaw 与其它 Agent 之间复用，避免每个插件各存一套。
- **定期导出**：长期记忆要有 JSON/JSONL 导入导出，防止工具链变动导致记忆锁死。

## 总结

让 AI 助手记住偏好，不是把更多内容塞进上下文，而是建立有边界、可追溯、可更新的记忆系统。落到工程上，就是三层存储、显式优先、置信度控制召回。做到这三点，记忆系统才能从“偶尔有用”变成“可以依赖”。
