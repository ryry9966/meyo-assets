# 让 Agent 真正了解你：USER.md 的工程化写法

## 背景

在 OpenClaw 的 Agent 实践里，最容易被忽略的其实不是 MCP 工具配得全不全，也不是插件装了多少，而是“每次新会话，Agent 根本不认识你”。

默认情况下，Agent 只知道自己是通用助手。你的工作目录、默认分支、常用命令、代码风格、哪些事绝对不能做，都不会自动存在。于是你只能在每次任务开始时重复说明环境，浪费 token，还经常因为某次没说全而导致行为漂移。

USER.md 要解决的就是这件事：把高频、非显而易见、可复用的事实和约束，作为常驻上下文注入 Agent。

## 问题

很多人不是没写 USER.md，而是写成了四种东西：

- 流水账：从“我喜欢吃什么”写到“我的猫叫什么”，信息密度极低。
- 太长：超过 150 行以后，模型对中后段规则的遵守率明显下降。
- 和项目级配置打架：项目里的 AGENTS.md 或任务临时指令，经常和 USER.md 互相覆盖。
- 把敏感信息塞进去：token、密码、内网地址，可能被 MCP 工具读取或写进日志。

## 做法 / 步骤

### 1. 放对位置，确认加载顺序

以 OpenClaw 系配置为例，用户级指令通常放在用户配置目录，例如 `~/.openclaw/USER.md`，具体路径以你的安装为准。加载优先级一般建议为：

`会话临时指令 > 项目 AGENTS.md > 全局 USER.md`

这样既能保持全局默认值，又允许项目覆盖。关键是你要自己验证一次：开个新会话，让 Agent 读一段 USER.md 里的规则，看它是否真的被注入。

### 2. 只写“默认值”和“红线”

不要写散文。USER.md 的作用不是让 Agent 了解你的灵魂，而是减少决策成本。可以按四段结构：

```markdown
# USER.md

## Identity
- 用户：后端工程师，主要用 Python 3.12 + PostgreSQL
- 时区：Asia/Shanghai；语言：中文优先，代码/命令用英文

## Environment
- 默认工作目录：~/work
- Python 包管理：uv，不用 pip
- Git 默认分支：main
- 禁止在 ~ 根目录创建测试文件

## Rules
- 修改文件前先读文件；不确定时先问，不要猜
- 优先使用 MCP 工具获取实时数据，不凭记忆
- 不输出超过 200 行的代码块，除非明确要求

## Workflow
- 新任务先确认目标、影响范围、回滚方式
- 涉及数据库操作时，默认加事务并先 SELECT 验证
```

### 3. 写可执行的判断，而不是模糊愿望

“尽量保持代码整洁”基本没用。“默认使用 uv，若项目已有 requirements.txt 则先询问”才是可执行规则。USER.md 里每一条最好都能回答：什么条件下、做什么、遇到冲突怎么办。

### 4. 新会话验证

写完后不要立刻投入使用。开一个干净会话，问 Agent：

- 我的默认工作目录是什么？
- 我的默认分支是什么？
- 如果项目里有 requirements.txt，你会怎么做？

再让 Agent 执行一个小任务，观察它是否自动遵守了“修改前先读文件”“不凭记忆”等约束。

## 踩坑点

- **信息过载**：超过 150 行，模型可能只记住开头和结尾。建议控制在 80-120 行以内。
- **与项目配置冲突**：如果项目 AGENTS.md 覆盖了 USER.md 的某条规则，要在项目文件里显式写“覆盖全局 USER.md 中的 X 条”，否则 Agent 容易两头摇摆。
- **敏感信息泄露**：不要把 API key、数据库密码、内网拓扑写进 USER.md。即使本地运行，MCP server 也可能读取上下文，日志未必安全。用环境变量或密钥管理。
- **过度约束**：每条命令都写死，Agent 遇到新情况反而不会变通。写成“默认”而不是“必须”，给异常留出口。
- **静态不更新**：环境变了，USER.md 没改，Agent 会按旧配置执行。把它当代码一样做版本管理。

## 可复用建议

- **最小模板**：先复制上面的四段结构，不要一上来就写满。
- **纳入 dotfiles**：用 Git 管理 `~/.config/openclaw/USER.md`，每次变更可回溯。
- **定期修剪**：每两周翻一次，删除从未被触发的规则。没用的规则不只是噪音，还会稀释真正重要的约束。
- **冲突规则前置**：在 USER.md 末尾加一句：“如果任务要求与本文冲突，先指出冲突并等待确认，不要静默覆盖。”这条能避免很多自动化事故。

## 总结

USER.md 不是日记，也不是自我表达。它是 Agent 的默认配置文件。写好它，比多装几个 MCP 插件对稳定性的帮助更大。

核心只有三件事：保留默认值、写清红线、用验证代替猜测。
