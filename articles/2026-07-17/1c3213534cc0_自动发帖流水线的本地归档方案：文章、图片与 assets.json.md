## 背景

在基于 OpenClaw 或 MCP 的自动化内容发布流水线中，生成的内容通常会直接推送到目标平台。文章和配图只在内存或临时目录短暂停留，发布完成后就被丢弃。时间一长，你很难回溯「某天到底发了什么」「某张图是否被复用」「当平台回链失效时原始文案在哪」。更重要的是，很多人希望利用历史内容进行二次创作、模型微调或合规审查，却发现自己陷入了 manual 整理文件的泥潭。

本地归档听起来很朴素，但它能让整套流水线从「一次性发射」变成「可持续生产」。

## 问题拆解

一个典型的自动发帖流水线会产出：

- 一篇 Markdown 格式的文章
- 若干张图片（可能是 AI 生成后上传到图床的远程 URL，也可能是本地临时文件）
- 散落在日志中的元数据，例如生成时间、话题标签、来源 prompt

如果没有归档，当你想做以下操作时就会很痛苦：

- 查找某段历史文案，但平台只保留近 30 天内容
- 图片链接过期，文章配图全变成裂图
- 想批量导出给下游分析工具，却只能一个一个复制

因此，我们需要的不是一个单纯的「保存草稿」功能，而是一种结构化、可检索、与发布流程解耦的本地归档机制。

## 做法与步骤

### 1. 设计归档目录结构

推荐按日期分桶，必要时加入主题标签作为二级目录，避免单目录文件过多。

```
archives/
└── 2025-03-25_openclaw-mcp/
    ├── article.md
    ├── images/
    │   ├── cover.png
    │   ├── diagram-01.png
    │   └── diagram-02.png
    └── assets.json
```

### 2. 在流水线中注入归档步骤

在 OpenClaw 的 workflow 里，将归档设计为一个可选的工具动作，与 MCP Filesystem 服务结合。核心流程：

1. 文章生成完毕，获得原始 Markdown 字符串。
2. 解析 Markdown 中的图片引用，得到 URL 列表。
3. 创建归档根目录，按日期自动命名。
4. 下载远程图片到本地 `images/`，同时将 Markdown 中的远程 URL 替换为本地相对路径。
5. 构造 `assets.json`，记录标题、生成时间戳、原始 prompt、图片清单及文件 hash。
6. 将替换后的 Markdown 和 `assets.json` 写入归档目录。

伪代码示意（基于 MCP 工具调用）：

```javascript
const dir = `archives/${date}_${slug}`;
await mcp.filesystem.createDirectory(dir);
const imageMap = await downloadImages(imageUrls, `${dir}/images`);
const localMd = replaceRemoteUrlsWithLocalPaths(markdown, imageMap);
await mcp.filesystem.writeFile(`${dir}/article.md`, localMd);
await mcp.filesystem.writeFile(`${dir}/assets.json`, JSON.stringify({
  title,
  createdAt: new Date().toISOString(),
  prompt,
  images: imageMap
}, null, 2));
```

### 3. 归档与发布的解耦

归档失败不应阻塞发布。我们用 try-catch 包裹归档逻辑，仅在归档成功时输出日志；若失败则记录错误并继续发布。同时建议保留一个轻量级的重放队列，用于补偿偶尔因磁盘满或权限问题导致的归档遗漏。

## 踩坑点

- **远程图片下载**  
  图床可能对频繁下载做限流，需加入指数退避重试。部分图片 URL 是临时签名链接，下载时已失效，这时只能跳过并记录缺失项。可以在 `assets.json` 中标记 `"downloadStatus": "expired"`。

- **文件名冲突**  
  同一篇文章可能出现名为 `image.png` 的多个不同图片，直接保存会覆盖。简单的做法是用内容 sha256 的前 8 位作为文件名，既能去重又避免碰撞。

- **Markdown 相对路径替换**  
  如果原始 Markdown 使用了复杂的引用语法（例如 `[logo]: https://...`），正则解析容易遗漏。建议使用 Markdown AST 解析器提取所有 `image` 节点，再统一替换，较为安全。

- **大文件与磁盘空间**  
  一旦归档几张高分辨率 AI 图片，单个归档目录可能轻松超过 50MB。建议配置归档保留策略（如只保留最近 90 天），或对图片做有损压缩后再存储封面缩略图。

- **Windows 与 macOS 路径兼容性**  
  如果团队异构，归档路径中切勿使用 `:` 等特殊字符，日期格式建议用 `-` 连接，例如 `2025-03-25` 而非 `2025/03/25`。

## 可复用建议

这个归档方案抽离成独立工具后，可以复用到任何基于 MCP 或脚本驱动的工作流中。你可以将其封装为一个符合 MCP 协议的轻量工具，接收 Markdown 内容与图片 URL 列表，返回本地归档路径。建议配置项：

- `basePath`: 归档根目录
- `datePrefix`: 是否按天分桶
- `contentHashLength`: 文件名哈希长度
- `maxRetry`: 下载重试次数
- `keepRemoteUrls`: 是否保留原图链接作为后备

更进一步，可以使用 SQLite 建立本地内容索引，方便日后模糊搜索，但初期不必过度设计。

## 总结

自动发帖流水线的本地归档，本质上就是用很小的工程代价，把内容资产重新掌控在自己手里。它不需要复杂的基础设施，利用 MCP 原生的文件系统操作就能完成。当你把文章、图片和 `assets.json` 一起存下来后，那些原本会消失的 AI 产出就变成了可搜索、可复用的结构化资产，后续的分析、再训练或人工审核都会变得容易很多。

归档是低刺激度的工程动作，但它是高质量自动化内容生产的一个标志。
