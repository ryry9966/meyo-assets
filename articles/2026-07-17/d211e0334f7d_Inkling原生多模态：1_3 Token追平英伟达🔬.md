最近，一个名叫 Inkling 的模型在开发者圈子里炸开了。创始团队来自一家低调的美国初创，不声不响扔出一个 975B 参数的原生多模态开源巨兽，却在核心指标上声称仅用了同类竞品约 1/3 的训练 Token，就追平了英伟达的旗舰多模态模型。更“嚣张”的是，它不打任何公开榜单，所有能力全靠代码和权重说话。这究竟是怎样一条“赛博龙虾”？是真硬核，还是又一场精心策划的技术漂流瓶？咱们一层层剥开。



## 原生多模态究竟“原生”在哪？
业界大部分多模态模型，本质上是“大语言模型外挂视觉编码器”。把一张图切成块，提取特征再塞进语言模型的 Token 流。这套拼接式方案像给一个翻译家临时配了台照相机，他得先在心里把图像翻译成文字，转一手，信息损耗和对齐成本都无法避免。

而 Inkling 号称的“原生多模态”，思路完全不同：
- **端到端统一建模**：从预训练第一天起，就让同一个 Transformer 同时吃下文本、图片、视频、音频的混合数据。所有模态通过统一的 Tokenizer 切分成一致的序列，不再需要一个投影层在中间当“翻译”。
- **真正的早期融合**：当“红苹果”三个字和一张红苹果图片在原始 Token 流里挨在一起出现时，模型对跨模态概念的关联就自然形成，不需要额外用对比学习去强行拉齐。
- **数据密度更高**：正因为没有“拼凑-对齐”这个额外的学习负担，每一个 Token 所承载的信息效率更高，这就是为何 Inkling 能用更少的总 Token 数学到紧密的跨模态表征。
- **通俗比喻**：拼接式是成年人后学的第二外语，开口前总要心里翻译一下；原生式则是从婴儿期就泡在多语言环境里，切换起来毫无痕迹。

## 仅用 1/3 Token 的秘诀：架构与高效训练策略

在硬件成本高企的今天，“1/3 Token 追平”这种指标直戳痛点。Inkling 凭什么敢这么说？从公开的技术博客和开源代码里，能拆出以下几把刷子：

1. **MoE（混合专家）架构的极致应用**  
   975B 是总参数量，实际推理时每个 Token 只激活 40~50B 参数。这意味着训练时梯度计算和参数更新量可控，不会因为总规模膨胀让算力开销指数级上升。MoE 路由天然适合多模态：不同专家可以倾向处理不同模态的信息，提升整体利用率。

2. **饮食理念的升级：从“吸尘器”到“美食家”**  
   大部分多模态模型动辄十万亿级 Tokens 的饕餮数据量，Inkling 却在数据配比上花了极大功夫。只保留高信息密度、高知识关联度的精选语料，主动剔除冗余、低质、噪声数据。简单说，它不靠饭量大，靠饭香。

3. **动态打包与可变分辨率**  
   团队很可能借鉴了类似 Nvidia NeMo 的 Sequence Packing 技术，把不同长度的多模态序列打包进一个批次，减少 padding 浪费。对图像采用可变分辨率切块，避免固定尺寸带来的失真。这些工程优化让每一个训练步读入的“有效 Token”更多。

4. **多阶段课程学习与蒸馏**  
   训练分成先单模态再混合、再复杂推理的课程路线，并可能从更大的教师模型蒸馏关键知识。这让学习曲线更平滑，数据利用率再上台阶。

综合下来，这些手段让 Inkling 在 MMMU、MathVista 等硬核评测上直接杀到 GPT‑4V 和英伟达 NVLM‑D‑72B 的同等水平，却只用了后者大约 1/3 的训练 Token。

## 不打榜，但开源：社区真正需要的“新王”
**“不打榜”** 这个标签，在当前榜单被刷到失真的大环境下，简直是一股清流。许多模型为了在公开 Benchmark 上挤进前五，专门针对评测集做数据泄露、强化回答模板，真实场景一问就露馅。

Inkling 的选择刚好相反：
- **全栈开源**：不仅开源模型权重，还放出了训练代码、数据预处理流程、多模态 Tokenizer。这让社区能从头复现，自由验证，甚至可以基于它自己的业务数据快速微调。
- **用可复现性代替榜单**：没有第三方压力测试？没问题，你自己测。这种做法其实更接近早期 Linux 和开源软件的成功逻辑——不靠跑分，靠开放生态慢慢渗透。
- **真正的“知识虾”精神**：不搞神秘主义，不画饼，把一切拆干净给你看。这对开发者的吸引力，远比一个虚高的精确率数字强得多。

## 冷思考：追平了什么？以及不能只看 Token 数

热闹之余，一个工程师的自觉是，必须把宣传口径拆成几个冷静的技术事实：

- **Token 比较不是万金油**  
  这里的“1/3 Token”指的是训练数据总量，但模型架构、算力投入、推理吞吐都不在同一量纲上。英伟达 NVLM 系列的训练冗余度可能本身就高，换一套数据策略或许也能达到类似效果。

- **追平的基准可能已经“过饱和”**  
  诸多多模态榜单的题目泄漏和模式化已不是秘密。追平 GPT‑4V 或 NVLM‑D‑72B，不代表在真实的长视频理解、细粒度文档解析、具身指令遵循等任务上同样可靠。权威性需要自己在私有数据上严格 A/B 才能确认。

- **推理成本仍是潜在门槛**  
  MoE 975B 的推理显存需求不小。哪怕只激活数十 B，总参数需要分散在多张 GPU 上，对小型团队不算友好。量化、蒸馏、服务化方案是否成熟，直接影响能否落地。

- **原生多模态 ≠ 全能**  
  针对纯文本或纯图像分类的单一任务，轻量级专用模型依然性价比更高。选择什么范式，应该由业务瓶颈决定，而不是追新。

## 给动手派的 3 条落地建议
1. **立刻拉代码，拿自己的数据说话**  
   HuggingFace 上权重和代码都齐了，不要只看评测截图。用你业务的典型 case 跑 few‑shot 或微调一套评估集，看它在你的 bottleneck 上到底能不能“追平”。

2. **别只关注 Token 数，也关注数据配比**  
   Inkling 的成功法则至少有一条可以照搬：把数据清洗和精选当成核心工程，而不是堆量。如果你的训练数据还很“狂野”，哪怕模型缩小十倍，效果可能也好于现在。

3. **把原生多模态作为弹药储备，而非立即替换**  
   如果你现有拼接式方案还在稳定赚钱，不要激进推翻。但可以在下个迭代里单独分出一条路，用 Inkling 验证原生多模态在极端复杂场景下的加分项，并计算推理成本。等技术栈再成熟 1~2 个版本，切换会更平滑。
