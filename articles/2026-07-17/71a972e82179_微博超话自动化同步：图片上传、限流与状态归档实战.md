## 背景

内容创作者常需要将技术长文、动态同步到微博超话，以触达更垂直的读者。手动逐条编辑、配图、发布的过程枯燥且易出错，尤其在维护多个系列文章时。为了把这部分流程交给机器，我们基于 OpenClaw 的 MCP (Model Context Protocol) 能力，搭建了一条从 Markdown 源文件到微博超话的自动化发布管道。

OpenClaw 作为面向智能体的运行时，通过 MCP 工具能安全地访问文件系统、网络与数据库。我们在其中注册了三个自定义工具——图片上传器、限流发布器、状态归档器，由 Agent 按需调用。整个过程不需要人工干预，每日扫描目录即可完成同步。

## 核心问题

实现“微博超话同步”需要解决三个最棘手的工程问题：

1. **图片上传与引用**  
   微博超话帖子中直接使用外链图片往往会被屏蔽或缩略图不显示，可靠方案是先将图片上传至微博图床，获取 `pid`，发帖时通过 `pic_id` 参数引用。这要求处理上传接口、cookie 有效期与图片格式校验。

2. **接口限流与重试**  
   微博开放平台对发帖、上传等接口有频率限制（例如发微博接口 30次/小时，应用级）。如果不加控制，同步任务会迅速触发 10006/10022 等错误码，导致后续所有请求被拒绝。

3. **状态归档与幂等**  
   自动化必须记住哪些内容已同步，避免重复发布。同时需要支持失败重试，而不是每次重新扫描整个目录。需要一套轻量的状态存储和内容指纹机制。

## 做法与步骤

### 1. 管道设计

```
Markdown文件 → 内容解析器 → 图片上传 → 限流队列 → 微博发布 → SQLite归档
```

所有工具以 MCP server 形式注册到 OpenClaw 的 Agent 中。当 Agent 接到“同步本周博客”指令时，它会按需调用这些工具。

- **内容解析器**：用 `markdown` 库提取文本与本地图片路径，自动生成超话文案（标题 + 摘要 + 原文链接），控制正文在 140 字以内。
- **图片上传工具**：基于微博开放平台 `statuses/upload` 接口，使用 `requests` 发送 multipart/form-data 上传本地图片，返回 `pic_id`。如果没有开放平台权限，则降级为模拟网页上传接口——发送至 `picupload.weibo.com`，并从响应中提取 `pid`。
- **限流发布器**：内置基于令牌桶的速率控制。我们选用 `token-bucket` 库，为发帖操作设置 30次/小时的桶。上传图片也有独立桶（120次/小时）。每次调用前尝试获取令牌，若为空则 sleep 等待。
- **状态归档器**：使用本地 SQLite 数据库，表结构如下：

```sql
CREATE TABLE IF NOT EXISTS sync_log (
    id INTEGER PRIMARY KEY,
    file_path TEXT,
    content_md5 TEXT UNIQUE,
    title TEXT,
    posted_at TIMESTAMP,
    weibo_id TEXT,
    status TEXT -- pending, success, failed
);
```

同步前计算文件 MD5 并查询是否存在。成功发布后将微博 ID 写入，失败时标记 `failed` 并记录错误信息，供人工排查。

### 2. MCP 工具调用示例

Agent 会生成类似以下逻辑的调用序列：

1. `get_unposted_files` —— 扫描目录，返回 `pending` 状态的文件列表。
2. 对每个文件：
   - `parse_markdown` 获取文字与图片列表。
   - `upload_images` 批量上传图片，获得 `pic_ids`。
   - `rate_limited_post` 携带 `pic_ids` 发帖。
   - 若成功，`mark_synced` 写入归档；若失败，`mark_failed` 并通知。

### 3. 配置文件

我们将微博 access_token、超话 ID、数据库路径放入 OpenClaw 的 `agent.config.yaml`，不硬编码。超话 ID 可通过搜索接口获取，也可直接在微博超话 URL 中复制数字 ID。

## 踩坑点

- **图片格式与尺寸**：微博要求图片 ≤5MB，且非渐进式 JPEG。部分截图工具生成的 PNG 带 Alpha 通道会触发失败，需预先转换为 RGB 模式。使用 Pillow 统一转换格式可避免。
- **Cookie 保鲜**：若使用网页上传方案，需要周期刷新登录态。我们加入健康检查，每小时用一次简单请求探测 cookie 是否有效，失效则通过 `load_cookies` 重新载入文件。
- **限流粒度**：应用级限流并非绝对均匀，偶尔会出现网络波动导致请求堆积。在令牌桶基础上增加随机退避 (1~5秒) 能显著降低触发风控的概率。
- **文案截断**：微博正文限制 140 字（包括 emoji 和链接），自动截断时不能打断 URL。我们采用“硬截断到 125 字 + … 原文链接”的策略，保证可读性。

## 可复用建议

- **抽象为 MCP 工具集**：上述三个工具可以直接复用到其他需要同步微博的场景，只需调整配置即可。工具本身不依赖特定的 Agent，可以随 OpenClaw 生态被其他智能体调用。
- **使用 SQLite 做轻量状态中心**：不需要 Redis 等外置服务，SQLite 在单机场景下足够稳定，且易于迁移和备份。
- **监控与告警**：我们在 Agent 中加入规则，连续 3 次 `failed` 时自动发送 Webhook 通知，避免长时间静默失败。

## 总结

通过 OpenClaw + MCP 的组合，我们将“同步 Markdown 到微博超话”这个看似简单的需求，拆解为多个可独立测试、可复用的工具。图片上传、限流、状态归档三大难点都得到了工程化的解决，整套流水线已稳定运行数月，每日自动将新内容推送至超话，无需手动干预。对于任何需要批量、定时、安全发布内容的自动化场景，这种“管道式工具集”的思路都值得参考。
