在构建基于 OpenClaw 的自动化 Agent 或 MCP 工具时，一个常见的需求是让 LLM 从长文档中抽取结构化信息，比如生成多段摘要、提取关键段落、输出带章节划分的分析结果。早期几乎所有人都会选择 JSON 作为输出格式——它标准、工具链成熟。但在实际工程中，长文场景下用 JSON 承载结构化数据，经常变成一场“恢复坏 JSON”的折磨。

## 问题：长文场景中 JSON 的脆弱性

当你要求 LLM 输出一个包含上千字内容的 JSON 字段时，模型很容易出现以下错误：

- 字符串内部换行未正确转义，导致 JSON 解析失败。
- 多出一个逗号、少一个引号、花括号不配对。
- 长文本末尾的截断导致整个 JSON 结构不完整。
- 模型在 `"content": "...` 中又出现了 `"` 字符，引发转义混乱。

这些问题在短 JSON 中不常见，可一旦内容超过几百字符，出现概率急剧上升。在生产环境中，一次 JSON 解析失败就意味着整个 Agent 流程中断，需要人工干预或者复杂的重试/修复逻辑，极大地降低了自动化率。

## 做法：用明显边界标签替代 JSON

一个简单有效的思路是：**用自定义标签包裹结构化字段，让解析从“修复损坏的树结构”降级为“用正则提取内容”**。

比如，原来要求输出：

```json
{
  "summary": "这是一段可能很长的摘要...",
  "keywords": ["key1", "key2"],
  "sections": [
    {"title": "第一节", "body": "内容..."}
  ]
}
```

改为标签格式：

```
<summary>
这是一段可能很长的摘要...
</summary>

<keywords>
key1, key2
</keywords>

<section>
<title>第一节</title>
<body>
内容可以任意换行，不用考虑转义。
</body>
</section>
```

在解析时，只需要用简单的正则（如 `<summary>([\s\S]*?)</summary>`）或逐行状态机提取内容，即使模型在某处多输出一些噪声文本，只要标签闭合就不会影响主流程。

### 在 OpenClaw 工作流中的落地步骤

1. **设计标签结构**  
   根据实际需要定义字段名作为 XML 风格标签，保持命名唯一、无歧义。避免使用可能与正文内容冲突的标签名，比如不要用 `<text>` 这种过于通用的词。

2. **改写提示词**  
   明确要求：“请严格按照以下标签格式输出，不要在前后添加任何解释。每个标签内的内容可以包含任意文本、换行、标点，无需转义。示例：……”  
   提供 1-2 个 few-shot 示例能大幅提升格式遵从度。

3. **构建容错解析器**  
   优先使用非贪婪正则逐字段提取，如果某标签缺失，就用空字符串回退，而不是整体失败。可以封装一个 `TagParser` 工具类，便于在多个 Tool/Agent 间复用。

4. **后处理与校验**  
   对提取到的内容做基本的合法性检查（如长度合理性、必填字段是否存在），并在 Agent 中加入一次重试逻辑：若解析失败则让 LLM 重试一次，成本远低于修复 JSON。

## 实际踩坑点

实践中很快就会遇到几个典型问题：

- **模型输出多个同名标签**  
  比如多次输出 `<summary>`，原因往往是提示词不慎让其分步输出。解决方法是只提取第一个匹配项，或在提示词中强调“每个标签只出现一次”。

- **标签内部再次出现相同标签**  
  如果让模型输出代码块，它可能复制出标签自身。需要合理设计命名，如用 `<code_block>` 而非 `<code>`，并在提示词中说明“标签内部不得包含同名标签”。

- **输出截断导致标签不闭合**  
  这是长内容最常见的情况。解析器需要检测缺失闭合标签，并可以尝试用最后一个已知标签的已取内容作为降级结果，同时触发截断告警。

- **模型在标签外输出了一段说明**  
  有些模型惯性会在末尾加“希望以上对你有帮助”。解析器需要忽略标签外的所有内容，并去掉首尾空白。

## 可复用的工程建议

将标签格式推广到项目中时，建议做好以下几件事：

- **封装通用解析器**：写一个接受标签名列表的函数，返回字典。所有 MCP 工具统一调用，避免到处散落正则。
- **标签命名规范**：采用动词或明确名词，如 `<action_plan>`、`<output_summary>`，并在文档中约束。
- **配合流式输出处理**：如果用 `stream=True`，需要自行拼接完整内容后再解析，或者采用增量标签检测。流式场景下也可以设计换行分隔的简化版标签。
- **保留 JSON 作为辅助**：对于高度结构化的数组、嵌套层级较多的数据，可以在标签内部再嵌入小段 JSON，并用检查工具校验——这样把风险控制在局部。
- **监控与告警**：统计标签解析失败率，一旦异常升高就排查提示词退化。

## 总结

在 OpenClaw 这类“Agent 驱动 LLM”的框架中，输出的可靠性远比格式的标准化重要。标签格式牺牲了 JSON 的“理论完美”，换来了工程上极高的容错性和可维护性。在处理长文摘要、多段分析、报告生成等场景时，它已经成为我个人工具链中的默认选择。

当你下一次被坏 JSON 阻断自动化流程时，不妨试试扔开花括号，用一对自定义标签把内容圈起来。也许你会发现，整个链路突然就安静了。
