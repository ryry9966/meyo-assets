最近，Bun 的作者 Jarred Sumner 在社交媒体上扔下一颗数字炸弹：他为重写 Bun 的部分底层组件，向 Claude API 支付了约 16 万美金，生生“生成”了接近 100 万行 Zig 代码。这个数字足够抓眼球，但更值得深挖的是——这 16 万究竟怎么烧掉的？100 万行机器写的代码真能用吗？对普通开发者又意味着什么？



## 事件还原：一场疯狂的 AI 编码实验

*   **起点**：Sumner 从 2024 年初决定用大模型重新实现 Bun 的多个子系统——HTTP 客户端、文件操作、加密模块甚至部分包管理器逻辑。这些模块原本就是手写的，但维护成本高、边缘场景补丁堆积如山。
*   **工具选择**：他先试验了 GPT-4，但很快全面倒向 Claude。核心原因不是“谁更强”，而是 Claude 对长上下文、结构化规范的遵循度明显更高，生成代码的可编译率也更高。
*   **不是“一句话生成”**：关键动作是**spec-driven development**。Sumner 先手写极端详细的规范文档，精确到每个函数的签名、内存分配策略、错误码语义、并发边界条件，然后把整份 spec 作为 prompt 喂给模型，要求输出对应 Zig 源码。
*   **产出规模**：整个项目消耗了数十亿 token，最终被合入主干的代码约 100 万行，覆盖数千个函数。人工审查耗时数周，但生成阶段的速度快到“等一杯咖啡的时间就吐出一个模块”。
*   **落地效果**：这些 AI 生成的代码已在最新版 Bun 中平稳运行，没有因“AI 幻觉”导致系统性崩溃。少数边界 bug 与人类代码的犯错模式并无二致。



## 16 万美金买到了什么？成本拆解

*   **纯 API 账单**：16 万美金几乎全部是调用 Claude API 的费用。按当时 token 计价，相当于输入+输出 数十亿 token。这是一笔纯粹的“算力燃料费”，没有外包团队、没有额外人力工资。
*   **时间换算**：以一个高级系统工程师年包 20 万美金粗略计算，独立重写同样的子系统需要 2–3 年，仅人力成本就远高于 16 万。如果算上团队沟通、代码审查、回归测试的管理开销，AI 这条路径的直接经济回报非常可观。
*   **隐性投入不可忽视**：Sumner 自己耗费数周编写规范、逐段审核 diff、修复 AI 的残留问题。这部分机会成本折算下来也有数万美金。但把这些前期“脑力劳动”和后期“验证工作”相加，仍然比纯手工编码节省一个数量级的时间。
*   **浪费率揭示现实**：16 万美金不是一次生成成功，而是大量试错的累积。为了得到可用的 100 万行，模型可能额外生成了数倍的废弃代码，那些不合格的输出同样消耗 token。这个“浪费率”正是目前 AI 编码必须纳忍的成本。



## 100 万行代码的质量博弈

*   **spec 是命门**：Sumner 反复强调，代码质量几乎完全由规范的严谨度决定。一旦把函数契约、内存模型、错误传播路径写死，Claude 生成的代码逻辑框架很少出错。真正容易犯错的，是那些不在规范里的“暗知识”。
*   **审查重点**：所有 AI 产出代码都经过 diff 审查与完整测试套件。人工主要围剿三类问题：整数溢出与截断、OOM 处理路径的遗漏、并发竞态窗口。这些也是人类程序员最常栽跟头的地方，AI 并没有特别“笨”。
*   **可维护性的隐忧**：100 万行代码的风格虽然因 prompt 强约束而保持统一，但它们不是人类一行行斟酌的结果。当未来需要大规模重构时，工程师对巨量“非己出”代码的掌控感会不会崩塌，目前仍是未知数。好在 Sumner 透露生成的注释质量颇高，这是少有的安慰。
*   **实际表现反直觉**：Bun 的 bug 率并未因 AI 代码而飙升，反而由于快速补全了大量边缘逻辑，一些困扰已久的 corner case 被悄悄修复。这说明——在明确规范下，AI 可以胜任“高级抄写员 + 穷举机器”的角色，而不只是看似正确的代码生成器。



## 给开发者的三条冷思考

*   **冷思考一：AI 是加速器，不是替代品**。整个实验最昂贵、最不可替代的部分，压根不是那 100 万行代码，而是 Sumner 脑中关于 Bun 运行时的全局设计。没有深厚的领域知识，你连一份值得喂给 AI 的 spec 都写不出来。
*   **冷思考二：成本意识必须前置**。16 万美金对个人是巨款，对企业只相当于一个中级工程师一年的总包。如果你的项目天然适合“规范驱动”——功能边界清晰、接口稳定、代码量巨大——AI 生成的 ROI 会极其诱人。但如果是强探索性、高度创造性的模块，AI 带来的修订成本和 token 消耗很可能反噬效率。
*   **冷思考三：代码所有权不要赌**。主流的 API 条款虽然声明输出代码归用户所有，但围绕模型训练数据、生成物相似度的法律风险仍在演进。Bun 基于 MIT 协议，目前未引发纠纷，但企业级应用务必让法务提前介入，评估混入 AI 代码对许可证合规、专利保护的潜在影响。

**立刻上手的实操建议**：别只围观，马上选一个你熟悉的模块，强行给自己写一份不带歧义的规范文档——包含函数签名、所有参数范围、返回值可能性、错误码列表——然后喂给 Claude 或 GPT，看它生成代码的准确度。记录下你的“浪费率”，评估自家项目的切入点。这套 spec-driven 工作流，才是 Bun 实验留给社区最干货的遗产。
