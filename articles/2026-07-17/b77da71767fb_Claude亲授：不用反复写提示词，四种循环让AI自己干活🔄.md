最近，Anthropic 官方发布了一份名为《Equipping agents for the long tail》的工程博客，用四种循环模式把“别再拼命写提示词”这件事讲透了——让 Claude 像自动化流水线上的老师傅一样，自己观察、判断、执行、反思，直到完成任务。这不仅仅是一次文档更新，更像是把 Agent 研发中那些隐秘而好用的工程范式公开摆到了台面上。



## 当“一次问答”不够用时，循环就该上场了

传统的大模型交互很像外卖点单：你扔一句提示词，它回一坨文本，交易结束。可一旦任务变复杂——比如“分析这 300 篇财报 PDF，提取关键数字，做成对比表格，最后给出投资建议”——单轮对话根本兜不住。你会发现自己不断在对话框里追加“不对，再修正一下”“你漏了 X 列”“格式统一成百分数”，活像个监工。

Agent 循环的核心思路，是把这种“重试-纠正-推进”的过程内化成程序逻辑。与其让人类一遍遍喊话，不如让模型自己踩油门和刹车。Anthropic 这次明确列出了四种递进式的循环范式：

- **Chat Loop（对话循环）**：最轻量。Claude 完成一步就停下来，把结果和下一步计划呈给用户，由人类点“继续”或“纠正”后再走下一步。适合高不确定性、需要人类把关的任务。
- **Batch Loop（批处理循环）**：一次给 Claude 一批同类型输入（如 200 封客服邮件），让它逐个处理并自动收集结果，只在出错时暂停。适合大批量、同质化任务，像数据清洗、格式转换。
- **Interactive Loop（交互式循环）**：Claude 在执行过程中可以主动调用工具（搜索、计算器、数据库）并在每轮把中间结果反馈给用户，用户可以实时插话调整方向。适合需要多步推理和外部信息检索的分析型任务。
- **Autonomous Loop（自主循环）**：Claude 全权接管流程，自己规划子目标、调用工具、校验输出、处理异常，直到产出终稿或触发终止条件。适合探索性编程、长文撰写、自动运维等有明确目标但路径开放的任务。

这四种模式并非孤立存在。官方博客里画了一条清晰的“自主性光谱”：从左到右，人类的干预越来越少，模型的决策空间越来越大。而你的任务，就是根据容错率、成本和对结果精确度的要求，给 Claude 装上合适的“方向盘”。

## 这些循环到底是怎么跑起来的？

如果拆解一个典型的 Agent 循环，它的骨架其实来自 2022 年就爆火的 ReAct 范式，以及后来不断堆栈的 Plan-Execute、Self-Reflection 等策略。Claude 把它们产品化之后，做对了三件事：

1. **标准化工具调用协议**  
   API 层面，Claude 支持 `tool_use` 块，模型可以直接输出格式化的函数调用请求，你的代码执行后把结果喂回，形成闭环。这使得循环不再是“模拟”，而是真正可控的、带中断和回调的工作流。

2. **长上下文记忆窗口**  
   Claude 3.5 Sonnet 支持 200K token 上下文，意味着整个循环的历史——包括思考步骤、工具调用结果、错误回溯——都可以塞进 prompt，模型不会“忘记”自己半分钟前在干什么。这是长链条自主循环的生理基础。

3. **内置的思考与校验**  
   Anthropic 用大量合成数据训练模型在每一步输出前进行隐式或显式反思，比如“我刚才提取的销售额是否覆盖了四个季度？如果没有，我需要重新查询一次”。这种模型内部的反思循环大幅降低了过程中的幻觉和跳步。

用一个实际例子解释：你想让 Claude 写一篇技术综述，Autonomous Loop 的运行轨迹大概是——  
- Plan：生成大纲，列出需要查阅的论文关键字。  
- Act：调用搜索工具查论文，读摘要，筛出 10 篇核心文献。  
- Observe：自动对比搜索结果，发现缺失了 2024 年的新研究，再补搜一次。  
- Reflect：把提取出来的论点与自身知识交叉验证，标记不确定的地方。  
- Finalize：生成全文，并把引用来源、不确定部分单独高亮，供你最后审阅。

整个过程你只需要发一句：“用 Autonomous Loop 写一篇关于 LoRA 微调的技术综述，引用至少 10 篇 2023 年后的论文。” 然后去泡咖啡。



## 从 Demo 玩具到生产工具，还有几道坎

虽然在纸上很性感，但在生产环境里让循环 24 小时无人值守，依然是件危险的事。我们不妨看几组数据，帮助大脑冷静一下。根据某智能体基准测试，即使是性能最强的模型，在跨越 50 个步骤以上的自主任务中，任务成功率也会急剧下降到 30% 以下——除非你有精细的错误恢复机制。

商业场景下的三大隐痛：

- **成本失控**：Autonomous Loop 可能反复调用 API、尝试多种方案，一次任务吃掉 100 万 token 很常见。如果没有预算熔断，月底账单会让你血压飙升。
- **目标漂移**：模型在长链条推理中会逐渐偏离原始目标，开始过度优化某个子任务，或者陷入死循环（比如反复修改同一段代码却无法通过测试）。
- **黑箱不可解释**：当最终结果不如预期，你很难快速定位是哪一步的决策出了问题，调试成本反而比手动写提示词更高。

Claude 官方给出的解法是“防御式设计”：强制设置最大步数、在每个关键节点输出结构化日志、以及让 Batch Loop 和 Interactive Loop 承担大多数真实业务——因为完全无人值守并不是他们推荐的默认选项。

## 抛开喧嚣，三条务实建议

大厂一开源，开发者就狂喜，但每次技术放量都需要用工程纪律接住。以下是 RY 哥推荐的三条落地法则：

- **从小循环起步，别一上来就搞 Autonomous**  
  先把你的任务流改成 Chat Loop，让模型每一步都举手问你。跑通 20 个真实 Case 后，你会发现大部分“意料之外”其实可以固化成校验规则。再把校验通过的步骤交给 Batch Loop，逐步放权。一步到胃的 Autonomous 往往是灾难的开始。

- **给每个循环都装上“熔断三件套”**  
  最大步数限制、单次调用 Token 预算、结果置信度校验，这三个开关缺一不可。比如可以在代码里写死：如果模型连续两次返回相同的错误动作，立刻中断并向你发送预警，不要让它默默烧钱。

- **循环不是银弹，把人和 AI 的交接面设计清楚**  
  在设计工作流时，明确标出“人类确认点”。财报分析这种容错率极低的任务，哪怕用 Autonomous Loop 生成初稿，最后也必须嵌入 Interactive 步骤，让你快速检视关键数字并给出口头指令。别用全自动掩盖你对结果的责任——在法律、医疗、金融领域尤其致命。



说到底，“别再写提示词”这句话翻译过来，不是“你可以躺平了”，而是“把你的精力从写提示词转移到设计工作流和验收标准上”。提示词退居二线，系统设计思维走到台前。Claude 这次给出的四种循环，更像是一套开箱即用的脚手架，帮你从对话玩家，升级成 Agent 车间主任。

试着在今天下午，拿一个你重复过五遍以上的小任务，套进 Chat Loop 试一圈。关掉那个手打了八百遍提示词的聊天窗口，或许你会发现，把方向盘交给 Claude 并没有想象中那么可怕。
