36kr抛出“智谱万亿了，DeepSeek还会远吗？”这个问题，本质上不是在问谁更会讲故事，而是在问：大模型公司的价值到底该怎么衡量。估值、模型能力、商业化、算力效率、开源生态，这几件事经常被混在一起讨论，像一锅还没关火的海鲜粥。今天我们把壳剥开，看里面到底有没有肉。

## 一、“万亿叙事”估的不是今天，而是未来入口
先说结论：大模型公司的高估值，通常不是按当前收入简单乘个倍数算出来的，而是市场在押注它未来能不能成为新一代计算入口。

可以拆成四层来看：

1. **模型能力层**  
   也就是基础模型本身：语言、代码、数学、推理、多模态能力是否稳定。模型越接近“通用工具”，未来可服务的行业越多。

2. **平台层**  
   API、Agent 框架、企业私有化部署、模型微调工具，都是平台化能力。只会训模型还不够，还得让别人能低成本调用。

3. **应用层**  
   办公、编程、教育、客服、金融风控、工业质检等场景，能不能跑出真实付费，是估值从“想象”落到“现金流”的关键。

4. **生态层**  
   开发者、企业客户、插件、数据闭环、渠道伙伴，会形成网络效应。生态一旦成型，竞争对手不是只追模型参数就能追上。

所以，“万亿”如果只是一个热议标签，参考意义有限；如果背后有清晰收入、客户留存、算力利用率和生态规模，那才值得认真讨论。否则就像把 GPU 数量当战斗力，听着很硬核，财务同学看完可能只想重启表格。

## 二、DeepSeek为什么总被拿来比较
DeepSeek被频繁放进同一张讨论表，主要因为它代表了另一条路线：用工程效率、开源影响力和推理成本优势，去撬动模型行业的注意力。

几个关键点值得看：

1. **MoE 架构降低推理成本**  
   MoE，也就是 Mixture of Experts，不是每次请求都激活全部参数，而是只调用一部分“专家”。这有点像后厨不是每道菜都让全员上阵，炒青菜就别叫龙虾师傅了。公开技术资料中，DeepSeek 系列模型多次强调“总参数大、激活参数少”的设计思路，核心目标就是把性能和成本做平衡。

2. **开源带来扩散速度**  
   开源模型的价值不只在“免费可用”，更在于开发者会帮它做适配、评测、部署和二次创新。只要许可条件清晰，企业和开发者就能把模型接进自己的工作流，形成草根生态。

3. **技术口碑影响商业预期**  
   大模型行业里，benchmark 不是全部，但也不是没用。代码能力、数学推理、长上下文、工具调用、中文表现，都会影响企业是否愿意试用。

4. **低成本是强叙事**  
   如果模型效果接近，而训练和推理成本显著下降，那它对行业定价体系会有冲击。客户不关心你烧了多少卡，客户关心响应快不快、答案稳不稳、账单贵不贵。

不过，DeepSeek是否“也会远”，不能只看技术热度。开源影响力很强，但商业化路径、企业服务能力、长期算力供给、客户支持体系，都是另一场考试。

## 三、真正决定估值的四个硬指标
大模型公司最终拼的不是单项冠军，而是系统工程。看估值是否站得住，建议盯四个指标。

1. **收入质量：是不是可持续付费**  
   API 调用收入、企业订阅、私有化部署、行业解决方案，性质完全不同。一次性项目收入好看，但可预测性弱；高频 API 和 SaaS 订阅更容易形成估值支撑。

2. **单位经济模型：每个 token 是否赚钱**  
   大模型服务有个朴素公式：收入减去推理成本、带宽、存储、工程运维，剩下才是毛利。关键技术包括 KV cache、量化、蒸馏、Speculative Decoding、批处理调度等。模型越大不一定越赚钱，吞吐、延迟和利用率才是财务报表里的硬菜。

3. **客户迁移成本：能不能留住人**  
   如果客户只是今天调你的 API，明天换另一个 endpoint，那护城河很浅。真正的黏性来自数据适配、业务流程嵌入、权限体系、审计能力、工具链和稳定 SLA。

4. **产品闭环：有没有从模型到场景的链路**  
   模型只是发动机，不是整车。企业需要控制台、监控、权限、知识库、评测、灰度发布、异常回滚。没有这些，模型再强也容易停在 demo 阶段。

所以，估值不是模型排行榜的截屏，而是一份长期压测报告。能跑一次高分不难，难的是高并发、低延迟、可审计、可迭代，还能把账算明白。

## 四、给用户、开发者和观察者的冷思考
大模型行业还在快速变化，今天的领先不等于永久领先，今天的低价也不等于长期低价。与其猜“谁会不会到某个数字”，不如把注意力放在更可验证的地方。

1. **普通用户：别只看模型名，看任务适配**  
   写作、代码、检索、翻译、推理、图片理解，各家模型强项不同。最实用的方法是拿自己的真实任务做小样本测试：准确率、稳定性、响应速度、成本一起看。

2. **开发者：把可替换性设计好**  
   接入大模型时，尽量做模型抽象层，保留多模型切换能力。Prompt、RAG、评测集、日志系统要独立出来，别把业务逻辑焊死在某一家 API 上。工程世界里，最贵的不是调用费，往往是以后改不动。

3. **行业观察者：少看口号，多看三张表**  
   一看客户结构，是否有高频真实付费；二看成本曲线，推理成本是否持续下降；三看生态扩散，开发者和企业伙伴是否自然增长。数字很热闹，但长期价值最终要回到产品、收入和效率。

智谱的热议代表资本市场对大模型入口价值的想象，DeepSeek的热度代表工程效率和开源路线的冲击。两者不一定走同一条路，也不一定用同一把尺子衡量。真正的问题不是“谁离万亿更近”，而是谁能把模型能力变成稳定、便宜、好用、可持续的生产力。这个答案，排行榜给不了，账单和用户留存会慢慢给。
