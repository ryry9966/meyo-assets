最近 36kr 报道了一件事：国内家电巨头海尔向 GitHub 上开源的 Home Assistant 插件作者发了律师函，要求立即停止开发和分发。开发者 Andre Basche 公开通知将在几天内删除 hon 和 pyhOn 两个项目。消息一出，海外社区炸了锅，大量用户 fork 项目保底，亚马逊开源项目办公室首席工程师 Mark Atwood 也公开声援开发者。

这件事本质上是一场标准的「AI 乌龙」——大厂把开放生态当成了威胁，结果搬起石头砸了自己的脚。但如果我们把视角拉远，这场闹剧背后折射出的，恰恰是智能家居行业正在经历的一次深层变局：AI Agent 正在重新定义「控制」的含义。

## 一、海尔到底干了什么？

先梳理一下事件经过：

1. **背景**：德国开发者 Andre Basche 为海尔家电开发了两款 Home Assistant（以下简称 HA）集成插件，让用户可以通过 HA 统一控制海尔设备，甚至桥接到 Apple HomeKit 等生态
2. **导火索**：海尔欧洲公司以「未经授权使用服务、造成重大经济损失」为由，向开发者发送法律通知，要求停止一切开发和分发活动
3. **社区反应**：GitHub 上迅速出现大量 fork，用户表示「有插件才买海尔，没插件换别家」，Mark Atwood 公开为开发者提供免费法律顾问
4. **后续反转**：在舆论压力下，海尔欧洲态度软化，联系开发者表示「可以谈」

这件事的荒谬之处在于：插件开发者并没有破解海尔设备，而是通过公开的 API 接口，用合规方式调用了设备功能。这就像你家的门没锁，邻居帮你开了门，你却告邻居入室盗窃。

## 二、为什么大厂总想关上开放的门？

海尔的操作并非个例。回顾智能家居行业十年发展历程，「封闭生态」几乎是所有巨头的默认策略：

- **小米**：米家生态以米家 App 为唯一入口，设备接入需要走小米认证
- **苹果**：HomeKit 对 MFi 认证要求严格，芯片成本让中小厂商望而却步
- **华为**：HarmonyOS Connect 同样强调「全家桶」体验

这种策略的底层逻辑很清晰：**用户在自己生态里停留的时间越长，数据越多，变现空间越大**。但问题在于，用户的家不是一个 App，而是由几十种不同品牌设备组成的物理空间。

Home Assistant 恰恰击中了这个痛点。作为全球最大的开源智能家居平台（贡献者数量超越 VS Code），它做的事情很简单：

- 支持 Zigbee、Z-Wave、Zigbee 3.0、Thread、蓝牙、WiFi 等几乎所有通信协议
- 通过本地化运行，数据不出家门，隐私由用户掌控
- 让小米开关控制 HomeKit 设备、让海尔空调响应苹果场景成为可能

用一句话总结：**HA 把选择权从厂商手里还给了用户**。这正是大厂们不安的根源。

## 三、AI Agent 是怎么改变游戏规则的？

如果海尔律师函事件只是旧秩序的挣扎，那 2026 年真正的变量是：AI Agent 正在让智能家居从「自动化」进化到「自主化」。

### 传统自动化的局限

过去十年，智能家居的核心逻辑是「如果-那么」（IFTTT）：

- 如果温度 > 28°C，则打开空调
- 如果门锁被打开，则推送通知
- 如果日落，则关窗帘

这种模式的问题是：**规则是僵化的，上下文是缺失的**。你回家晚了，空调照样开着；你出门忘关灯，系统不会主动帮你关。

### AI Agent 带来了什么？

以 OpenClaw + Home Assistant 方案为例，AI Agent 做到了三件传统自动化做不到的事：

1. **自然语言理解**：你不需要说「打开客厅主灯」，只需要说「天黑了，把客厅弄亮点」，Agent 会根据当前时间、传感器状态、你的偏好自动判断该开哪盏灯、调到什么亮度
2. **多步任务编排**：「我准备看电影了」→ Agent 自动关灯、关窗帘、打开投影仪、把音响调到 50% 音量。这在传统方案里需要写 5 条自动化规则，用 Agent 只需要一句话
3. **情境感知决策**：Agent 会综合考虑时间、你在不在家、天气、传感器数据等多维信息，做出动态决策。比如你说「太热了」，它会判断是开空调还是开窗通风，而不是一刀切地开空调

实测数据显示，通过飞书接入 OpenClaw 控制小米设备，平均响应时间 1.2 秒，指令理解准确率超过 92%，远超传统语音助手。

## 四、本地 AI 是隐私的最后一道防线

很多人会觉得：「AI 控制家居」听起来很酷，但把家里的一切交给 AI，隐私怎么办？

这正是 Home Assistant + 本地 LLM 方案的核心价值所在：

| 方案 | 数据流向 | 隐私等级 |
|------|----------|----------|
| 云端 AI（ChatGPT） | 你的指令和家居数据发送到 OpenAI 服务器 | 低 |
| 本地 LLM（Ollama） | 所有推理在本地完成，数据不出家门 | 高 |
| HA 原生 Assist | 本地意图识别，无需 AI 模型 | 极高 |

OpenClaw 的架构设计也遵循了同样的原则：

- 所有对话记录和家居状态存储在本地
- 支持连接 Ollama 部署的本地 LLM（如 Llama 3、Qwen 2.5）
- 通过 MCP（Model Context Protocol）协议与 HA 通信，数据全程不出局域网

Paulus Schoutsen（HA 创始人）在最近的采访中明确表态：「HA 不想去读取你的邮件和私人信息，我们专注于家居设备的物理控制。」这种「各司其职」的解耦设计——设备控制层归 HA，智能决策层归 OpenClaw——才是可持续的本地智能架构。

## 五、智能家居的下一个十年，拼的不是硬件

回到开头的海尔事件。海尔的律师函本质上是在用 2015 年的思维应对 2026 年的战场。当 AI Agent 已经可以通过自然语言控制 34 类设备、自动编排复杂场景、甚至记住你的生活偏好时，靠封闭协议和私有 App 绑住用户的做法，只会越来越无力。

真正的竞争正在转移：

- **从硬件生态到软件智能**：SwitchBot 推出原生 AI Hub，树莓派 5 成为本地智能家居的标配硬件，AI 推理能力正在成为新的「卖点」
- **从封闭协议到开放标准**：Matter 协议自 2022 年上线以来持续推进，虽然进展不如预期，但方向不可逆
- **从「听指令」到「懂意图」**：传统语音助手只能执行精确命令，AI Agent 能理解模糊需求并自主决策

Home Assistant 创始人 Paulus 透露，他预计一年半内会再次来华，推进本土化落地。而 OpenClaw 与 HA 的解耦架构，已经在社区中跑通了从飞书到米家、从 Telegram 到 HomeKit 的全链路控制。

---

### 三条冷思考

1. **AI 不是万能药，安全关键设备别交给模型**：门锁、烟雾报警、安防系统这些涉及人身安全的设备，应该保持确定性规则（if-then），而不是交给 LLM 去「推理」。你不会希望 AI 在判断「要不要开门」这件事上「创造性发挥」
2. **本地 AI 有门槛，先跑通基础再上智能**：本地 LLM 需要一定的硬件算力（至少 8GB 内存的树莓派 5 或迷你 PC），而且配置流程对普通用户仍然不友好。建议先把 HA 基础功能跑稳，再逐步叠加 AI 能力
3. **别被大厂的「生态」绑架，选择权在你手里**：海尔事件告诉我们，厂商随时可能关闭开放接口。但 Matter 协议、Zigbee、Thread 这些开放标准是不可逆的趋势。买设备时优先选择支持开放协议的产品，才是对冲风险的最佳策略
