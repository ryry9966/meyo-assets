最近，AI 圈被两条消息搅动了平静的水面：DeepSeek 大幅上调 API 价格，阿里云则在 Model Studio 上调整了对模型服务商的抽成比例。一边是当红炸子鸡的“变相劝退”，一边是平台方的“坐地收租”，开发者群里立刻炸了锅——有人连夜测算成本，有人开始打包代码准备跑路，也有人淡定围观，觉得这不过是基础设施商品化的必然一步。

涨价、抽成，说到底都是在回答同一个问题：大模型这场盛宴，算力的账单到底谁来付，又该怎么分？先别急着站队，我们不妨把账本拆开，看看这轮价格震荡背后的真实逻辑。



## 一、一张 GPU 账单的解剖：涨价的成本锚点

DeepSeek 从最初的“白菜价”甚至免费额度，突然跳到每百万 token 几块钱的区间，落差确实不小。但要理解这次涨价，必须看清一张 A100/H800 集群的电费单。

1. **推理不是“按需付费”那么简单**
   - 大模型推理消耗的显存带宽远高于传统 SaaS，一个 7B 模型做单次自回归解码，GPU 核心几乎全程在搬运 KV Cache 和权重矩阵。
   - DeepSeek-V2 这种 MoE 架构，虽然激活参数少，但全量参数驻留显存，意味着单卡能同时服务的并发数有硬上限。
   - 算一笔账：按单卡 A100 月租 8000 元、能稳定扛 20 路并发计算，如果每个客户每天消耗 100 万 token，满打满算也覆盖不了多少用户。价格要 cover 硬件折旧+运维+带宽，不可能一直贴钱。

2. **开源≠零成本，生态反噬来得很快**
   - DeepSeek 开源了权重，很多中小开发者选择自己部署，但这部分用户其实本就不是 API 的目标客户。
   - API 服务真正的成本陷阱在“动态长尾”：总有人在深夜跑批量测试，也总有人突发流量把队列打满。为维持 SLA，必须预留大量冗余算力，这部分闲置成本最终会均摊进单价。

3. **免费模式的“断奶期”到了**
   - 去年大厂和独角兽纷纷用免费/低价换开发者心智，本质是融资时代的获客策略。
   - 当外部输血放缓，API 部门就要自证造血能力。DeepSeek 这类独立厂商没有云业务交叉补贴，提价是回归商业本质。

## 二、阿里抽成：模型超市的“包租公”逻辑

如果说 DeepSeek 涨价是上游原料贵了，那阿里云调整 Model Studio 的抽成比例，就是在整理货架出租的价码。



1. **平台抽成的两层结构**
   - **技术服务费**：模型上架、部署、监控、鉴权、计费系统都是阿里云搭好的，这套 PaaS 层本质上和出租商铺一样，收“物业费”在商业上很常见。
   - **流量分成**：阿里系的产品矩阵（通义千问、钉钉、淘宝等）会分发模型能力，这种“渠道费”类似应用商店的 30% 抽成。模型厂商如果想获取阿里生态内的企业客户，就得接受这个体系。

2. **为什么独立开发者觉得“疼”？**
   - 以前 Model Studio 主要面向企业版通义系列，阿里自己左手倒右手，抽成比例只是会计科目。
   - 现在大量第三方模型接入，30%～50% 的抽成直接砍在厂商利润上。对于已经薄利的模型服务商来说，要么跟着涨价，要么压缩运维成本，几乎没有中间地带。

3. **平台与模型商的博弈天平**
   - 阿里手握客户关系、云资源调度、安全合规三大王牌。企业客户不会因为某家模型便宜 20% 就轻易换云，数据已经存在 OSS 上，网络出口成本摆在那里。
   - 但模型厂商也不是全无筹码：如果头部模型集体抵制高抽成，转向自建支付和轻量级部署方案，平台会损失“模型丰富度”这个核心卖点。

## 三、大客户的算盘：跑路 or 买单？

中小开发者抱怨声最大，但真正决定市场走向的，是那些年消费千万级 token 的大客户。他们面对涨价和抽成，心里揣着另一本账。

1. **迁移成本是天然的护城河**
   - 一个深度集成了 DeepSeek API 的企业，代码里可能嵌着针对特定 prompt 模板的微调逻辑，甚至用 LangChain 等框架做了复杂的 Agent 工作流。
   - 换模型不是改个 endpoint 地址那么简单。输出格式的微小差异就能让下游解析器崩溃，重新调试、评估、走合规流程的时间成本，远比省下的 API 费高得多。

2. **大客户看的是“总拥有成本（TCO）”，不是单价**
   - 假设某电商客服系统每天调用 500 万 token，涨价后每月多支出 3000 元。但 DeepSeek 在中文长文本理解上的准确率高 3 个百分点，能减少 15% 的人工转接率——折算成人力成本，多花的那点 API 费几乎可以忽略。
   - 成熟客户会算综合效益：模型稳定性、低延迟、数据不出境的合规保障，每一项都对应着潜在的业务风险金。

3. **“跑路”不一定是投奔竞品，可能是上自部署**
   - 真正触发大客户迁移的，往往不是价格本身，而是服务质量的波动。如果涨价伴随着限流、降优先级，部分有技术能力的客户会直接采购裸金属服务器，自行部署开源模型。
   - 这种“暗度陈仓”才是 API 厂商最该警惕的——短期收入上去了，长期客户却转向了竞品的方案或者自建，护城河在自己涨价那天被悄悄填平。

## 四、行业涟漪：大模型商业化要交卷了

这次涨价和抽成事件，可以说是大模型行业从“秀技术”过渡到“拼利润”的分水岭。

1. **算力成本透明化会倒逼模型轻量化**
   - 量化（INT4/INT8）、投机解码（Speculative Decoding）、KV Cache 压缩等工程优化，将从加分项变成生存技能。谁能在不损失太多精度的情况下把单 token 推理成本打下来，谁就能拿到下一轮定价的主动权。

2. **云厂商正在重新划分“地主”与“佃农”**
   - 阿里云、华为云、AWS 等底层玩家，会继续强化 MaaS（模型即服务）平台的抽佣模式。未来可能看到更精细的阶梯计费：通用对话模型抽成高，垂直行业模型抽成低，以鼓励生态多样性。
   - 模型厂商如果不想沦为纯粹的“算法佃农”，必须建立品牌溢价——要么技术绝对领先，要么私有化部署能力极强。

3. **开源闭源的缠绕会更紧**
   - 开源模型是定价的“鲶鱼”。只要有免费的 Llama3 或者 Qwen2 可以自部署，闭源 API 的涨价天花板就锁死了。
   - 未来的竞争格局很可能是：开源负责技术传播和长尾覆盖，闭源 API 负责高可用企业服务和极端并发场景，两者差价本质上就是“稳定性和便利性”的溢价。



## 冷思考：三条实用判断框架

面对 API 涨价和平台加码抽成，不管是个人开发者还是企业采购，都不必被情绪裹挟。这里给三个实操层面的判断维度：

1. **做一次“关停测试”**
   - 假设你用的 API 明天价格翻倍，你的业务单元能撑多久？如果答案是一天都扛不住，说明耦合太深，需要立刻准备兜底方案（例如自部署开源模型做热备）。
   - 如果影响在 5% 成本以内，且交付质量无明显下滑，那理性选择是继续使用，把省下的工程师时间投到业务优化上。

2. **重新计算“自建 vs 租用”的临界点**
   - 拿一张 A100 的真实租赁价格（别用官网刊例价），加上运维人力、网络带宽、能耗，测算自己业务量级下的单 token 成本。
   - 当 API 单价高于这个成本的 1.5 倍时，自建开始具备吸引力；高于 2 倍时，就值得认真立项评估。反之，就别折腾了。

3. **把“模型可替换性”写进合同**
   - 如果你是企业采购，在和模型厂商签 SLA 时，增加一条“同等效果模型的切换条款”，明确输出格式兼容性标准和灰度迁移方案。
   - 这比单纯砍价有用得多——不锁死技术路线，才是对抗未来涨价的终极底牌。

大模型价格战的下一阶段，不再是“谁更便宜”，而是“谁更不可替代”。能提供确定性、高集成度和持续技术红利的服务，才有资格让客户心甘情愿买单。而那些只靠价格获客、没有差异化壁垒的玩家，涨价通知发出去的那一刻，可能就已经进入了倒计时。
