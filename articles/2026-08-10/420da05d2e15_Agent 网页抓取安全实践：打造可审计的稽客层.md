# Agent 网页抓取安全实践：打造可审计的稽客层

## 背景：Agent 读网页，不止是 `fetch` 那么简单

在 OpenClaw 这类 Agent 编排环境中，我们经常通过 MCP（Model Context Protocol）的 `fetch` 工具或自定义插件，让大模型自动获取某个 URL 的文本内容，用于信息提取、摘要或决策。典型场景包括：

- 监控竞品更新，定期抓取 Release Notes。
- 自动拉取技术文档片段，辅助回答用户问题。
- 汇总多个数据源，生成日报。

然而，直接让 Agent 访问任意 URL，会引入一系列安全和可控性问题。网页内容可能包含恶意脚本、超大体积的二进制数据、诱导性的钓鱼页面，甚至仅仅是意外的大规模抓取就可能触发目标站点的反爬机制或造成法律风险。

解决这个问题的关键在于，在 Agent 与目标网站之间插入一层**可拦截、可审计、可限制**的“稽客”代理。下文基于我们在 OpenClaw + MCP 环境中的实践，给出一个轻量但工程化的稽客方案。

## 问题拆解：Agent 抓取网页的三大风险

1. **内容不可控**  
   Agent 拿到响应后直接注入上下文窗口。如果目标页面返回的不是纯文本 HTML，而是含有巨量 JavaScript、内嵌二进制流（如图片 Base64），很容易撑爆 Token 上限，甚至触发模型幻觉。

2. **行为不可控**  
   自动跟随重定向、抓取内链、请求外部资源，导致爬虫行为扩散。没有白名单时，Agent 可能被诱导去抓取内网地址或敏感路径。

3. **合规不可控**  
   频繁请求同一个域名、忽略 `robots.txt`、无视 `403/429` 状态码，都会使你的出口 IP 被加入黑名单，甚至带来合规麻烦。

## 做法：构建稽客代理中间件

我们基于 OpenClaw 的 MCP 工具扩展机制，实现了一个稽客代理，核心流程如下：

**架构**  
```text
Agent → MCP fetch_wrapper → Auditor Proxy → Target Website
                ↑
        (white list / content check / cache)
```

稽客代理的关键职责：

- **域名白名单/黑名单**：预定义允许抓取的域名模式，如 `*.github.com`、`docs.example.org`，其余一律拒绝。
- **内容类型过滤**：只放行 `text/html`、`application/json` 等白名单 MIME 类型，遇到 `application/octet-stream` 或 `image/png` 直接返回错误摘要。
- **大小与超时限制**：设置最大响应体 2 MB，超时 15 秒，防止阻塞 Agent 流程。
- **重定向策略**：只允许 1 次同域重定向，禁止跨域跳转。
- **缓存与去重**：相同 URL 在 5 分钟内重复请求直接返回缓存，降低外部请求频率。
- **审计日志**：记录每次抓取的 URL、状态码、响应大小、耗时及 Agent 请求方标识。

**具体步骤（以 OpenClaw + 自定义 MCP server 为例）**

1. **编写 MCP 工具 `safe_fetch`**，参数包括 `url`、`max_chars`（返回给 LLM 的最大字符数，比如 8000 字符）。
2. 在工具内部调用上述稽客代理逻辑：
   - 解析 URL，提取 host，匹配白名单。
   - 检查本地缓存。
   - 发起 HTTP GET，严格设置 `Accept: text/html` 等标头。
   - 处理 3xx：检查 `Location` 头，若同域则允许一次，否则返回错误。
   - 读取响应头 `Content-Type`，不合规直接丢弃 body 并返回 `[blocked]`。
   - 流式读取 body，到达 2 MB 截断，返回截断后内容（或摘要）。
   - 将内容截断到 `max_chars`，保证不污染上下文窗口。
3. 在 OpenClaw Skill 或 Workflow 中，要求 Agent 必须使用 `safe_fetch` 工具获取网页，并禁止直接调用原始的 HTTP 库。

## 踩坑实录

1. **重定向到 SSO 登录页**  
   许多内部文档或 SaaS 工具会 302 到身份认证页面。稽客代理因域名白名单通过，但内容却是登录表单。需要额外检测 body 中是否含有 `login` 等模式，或检查返回内容长度小于阈值时触发警告。

2. **页面渲染依赖 JavaScript**  
   纯 HTML 抓取拿不到 SPA 动态渲染的内容。对于这类站点，我们采用预渲染服务（如 headless Chromium）单独生成静态快照，但那是额外的成本。稽客层会返回明确的 `[dynamic-page]` 标记，让 Agent 决定是否降级。

3. **字符编码混乱**  
   部分网站 Content-Type 未声明 charset，或者声明与实际不符。稽客代理必须自动检测编码（如使用 `charset-normalizer`），并转换为 UTF-8 后再截断，否则截断点可能落在多字节字符中间，导致输出乱码。

4. **CDN 或 WAF 针对爬虫**  
   Cloudflare 等防护可能会返回 403。稽客代理此时应直接透传状态码并记录，不做重试，避免触发更严格的封锁。可通过预置固定的 User-Agent 和 Accept-Language 头稍微缓解，但不应伪造身份。

## 可复用建议

- **将稽客层抽象为可配置的中间件**，而不是硬编码在工具里。用 YAML/JSON 配置白名单、超时、最大 body 大小等，方便不同 Agent 场景复用。
- **提供“安全摘要”模式**：解析出网页的主要文本内容（类似 Readability），再截断返回，能显著提升 Agent 的信息密度。
- **注入归属标记**：在 User-Agent 或自定义 Header 中携带 `X-Agent-Id: my-workflow-01`，方便被抓取方联系你排查问题。这是一种负责任的抓取实践。
- **与 OpenClaw 的审计系统集成**：利用 OpenClaw 的日志钩子，将稽客层日志一并写入，方便事后分析 Agent 的抓取行为是否符合预期。

## 总结

Agent 自动抓取网页是强需求，但“能抓到”不等于“应该抓”。通过构建一个轻量的稽客代理层，我们能在不牺牲灵活性的前提下，把内容安全、行为可控与合规性纳入工程化轨道。在 OpenClaw 这类平台上，利用 MCP 工具扩展实现该代理成本很低，收益却非常明显——既保护了 Agent 自身被恶意内容干扰，也保护了外部站点的可用性。

希望以上的实践与踩坑总结，能为同样在构建 Agent 自动化管线的你，提供一些可直接落地的方法。
