老黄又发推了——而且这仅仅是他人生中的第二条推文。就在全行业都在抢购H100、B200的时候，他却用一条简短的动态，点破了AI算力江湖一个容易被忽略的事实：当微软、谷歌、Meta甚至OpenAI都在大举投入自研AI芯片时，只有Anthropic，这家Claude背后的公司，依然在“死扛”英伟达GPU生态，几乎不碰定制化ASIC。

这条推文本身没有指名道姓，但结合公开的投资关系、技术选型文件和云基础设施采购数据，圈内人一看就知道在说谁。那么问题来了——Anthropic到底在坚持什么？自研芯片真能动摇英伟达的护城河吗？今天我们就拆开这枚“硅基洋葱”，一层一层看。



## 谁在逃离英伟达？自研芯片的“集体出走”

先看大势。过去两年，几乎每一家叫得上名的AI公司，都在悄悄把自己的推理乃至训练负载，从英伟达GPU迁移到自研芯片上。

- **Google** 是走得最早的。TPU v5p 已经大规模支撑 Gemini 的训练和推理，内部数据显示在特定矩阵运算上，TPU 的每瓦性能比同时代 GPU 高出 30% 以上。而且 Google Cloud 对外提供 TPU 租赁，本质上是在挖英伟达的墙角。
- **Amazon** 推出 Trainium 和 Inferentia 两条产品线，Anthropic 自己也拿过亚马逊 40 亿美元投资，但有趣的是，Anthropic 的模型训练仍大量使用英伟达 GPU 集群，而不是 Trainium。
- **Microsoft** 与 OpenAI 合作的同时，也在秘密推进 Athena 芯片项目，目标直指降低推理成本。OpenAI 内部同样传出评估自研芯片的消息，Sam Altman 甚至为此在中东和亚洲寻找晶圆厂合作伙伴。
- **Meta** 则发布了 MTIA v2，专为推荐系统和生成式 AI 推理优化，计划在 2025 年将其部署到数百万台服务器上。

这些动作背后的逻辑很清晰：英伟达 GPU 虽然通用性强，但太贵了——一块 H100 的毛利率长期维持在 70% 以上，云厂商的 AI 服务毛利被严重挤压。自研 ASIC，哪怕只比 GPU 在特定模型上节省 20%~30% 的能耗或成本，在万卡集群规模下就是每年数亿美元的真金白银。



## Anthropic 反其道而行：为什么“死扛”GPU？

在这样一个“叛逃”潮流里，Anthropic 却显得格外另类。从它的技术博客、论文以及基础设施团队的公开发言来看，至少有四个原因让这家公司选择继续押注英伟达。

- **1. 训练侧对 CUDA 生态的路径依赖极深**
  Claude 系列模型从第一代开始，就在自研训练框架上深度绑定了 CUDA 底层算子。Anthropic 的工程师曾透露，他们为长上下文注意力机制、宪法式 RLHF 等定制了大量 CUDA kernel，这些算子与 TPU 或 Trainium 的编程模型完全不兼容。迁移意味着至少 6~12 个月的重写和调优，对一家追求模型能力快速迭代的公司来说，时间窗口太宝贵。

- **2. 商业模式决定了“用别人的钱买最好的卡”**
  与 OpenAI 依靠微软 Azure 不同，Anthropic 的云基础设施高度依赖 Amazon Web Services。但注意——Anthropic 拿的是亚马逊的投资，并不是被收购。它保留了对硬件选型的独立决策权。亚马逊当然希望它用 Trainium，但 Anthropic 通过长期合同锁定了数万块英伟达最新 GPU 的供应，等于用投资方的钱，买了市面上最成熟的算力。这种“金主买单、我来点菜”的模式，让它没有强烈的成本自驱力去迁就自研芯片。

- **3. 灵活性比极致的成本更重要**
  Anthropic 以“前沿模型安全研究”为核心定位，这意味着它的模型架构、训练方法仍然在快速演变中。今天可能是密集的 Transformer，明天也许引入 MoE（混合专家模型）或新的注意力变体。ASIC 一旦流片，其硬件架构就固化了，很难跟上算法创新的节奏。英伟达的通用 GPU 虽然“贵”，但它的可编程性让研究人员可以随时调整算子，不用等 18 个月的芯片迭代周期。

- **4. 软件栈的隐性成本被严重低估**
  芯片本身只是冰山一角。编译器、调试工具、性能分析器、分布式通信库……英伟达用十几年的时间构建了一整套 CUDA 软件栈。Google 的 TPU 生态虽然也不错，但仅限于 Google Cloud 内部高度优化的环境；Amazon 的 Neuron SDK 成熟度则明显落后。Anthropic 的工程师坦言，光是解决自定义芯片上的“隐式同步错误”和“内存越界”，就可能花掉一个五人团队两周的时间——这些人力成本换算成 GPU 租金，可能反而更划算。



## 老黄推文的弦外之音：英伟达的“生态霸权”还能撑多久？

黄仁勋这条推文，当然不是只为了夸一句 Anthropic。更深层的信号是：英伟达急需证明“通用 GPU 仍不可替代”。

从财务角度看，英伟达的数据中心业务中，大型云厂商客户的集中度极高。一旦这些客户的自研芯片形成规模替代，英伟达的长期营收结构就会出现裂缝。因此老黄必须不断强调“可编程性”“生态厚度”和“跨模型泛化能力”的价值，而 Anthropic 就成了一个活生生的标杆案例。

然而，产业演进的规律并不会因为一家公司的坚持而改变。历史已经反复证明，当一项技术的市场足够大时，垂直整合就会发生。从大型机到 x86 服务器，从通用 CPU 到手机 SoC——AI 芯片也正在走同一条路。未来三到五年，大概率会形成“训练用最高端 GPU、多数推理用自研 ASIC”的混合格局，而纯 GPU 方案的份额会逐步收窄。



## 从“死扛”中能学到什么？三条冷思考

对于关注这个行业的开发者、创业者和投资者来说，Anthropic 的选择与其说是一个“答案”，不如说是一面“镜子”，折射出几个值得冷静对待的问题。

1. **不要为了自研而自研，算清楚总拥有成本再动手**
  芯片流片动辄上亿美元，加上软件栈开发和后续迭代，总投入可以轻松达到英伟达 GPU 采购费的数倍。只有当你确有时间上的冗余、且未来三年的模型结构相对稳定时，自研 ASIC 的经济账才算得过来。否则，用高昂的短期成本换取工程灵活性，未必是亏本买卖。

2. **CUDA 的壁垒不在技术，而在开发者习惯和工具链**
  很多初创芯片公司以为只要把算力指标堆上去就能抢市场，结果都栽在了软件生态上。对于团队而言，评估新硬件时要先问三个问题：有没有性能分析工具？分布式训练如何启动 debug？遇到奇怪的内存报错时社区里能不能搜到答案？如果这三条都不满足，谨慎跳坑。

3. **关注“混合架构”带来的新机会**
  未来几年，大部分 AI 工作负载会跑在 CPU + GPU + ASIC 的异构集群上。调度器、分布式框架、内存池化这些中间件层的机会远大于芯片本身。与其纠结选哪家芯片，不如把注意力放在跨架构的性能优化和成本治理上——谁能让不同芯片无缝协作，谁就能吃到下一波红利。

说到底，“死扛”这个词本身就是个视角陷阱。在外界看来是固执，在当事人那里，也许只是基于自身节奏的最优解。技术选型从来没有标准答案，只有不断更新的约束条件和权衡。老黄的推文，与其说是在评价一家公司，不如说是给整个行业提了个醒：在算力大起大落的时代，保持一份对自己需求的清醒，比跟风重要得多。
