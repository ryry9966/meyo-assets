## 背景

无论你是在给 MCP 服务写文件读写工具，还是为日常重复任务编写 Shell 脚本，Agent 或自动化流程一旦获得文件系统访问权，就容易踩中两个坑：

1. **误删 / 误改**：一个未转义的路径变量，就可能让 `rm -rf` 跑到不该去的地方。  
2. **数据泄漏**：敏感日志、密钥文件可能被读取后随 LLM 调用外发。

传统的解法是：运行前做好评估、手工确认每条路径。但工程上我们需要的是**可重复、不可绕过的硬限制**——即便代码逻辑犯错，也不允许超出我们设定的安全目录范围。这就是本地目录白名单出现的原因。

## 问题拆解

假设你正在开发一个 MCP 工具，它允许 LLM 读取某个项目目录下的任意文件以便分析代码。工具接口大致像这样：

```python
def read_file(path: str) -> str:
    with open(path) as f:
        return f.read()
```

如果 LLM 尝试读取 `/etc/passwd` 或 `~/.ssh/id_rsa`，没有任何保护。更危险的是写入操作：一个清理临时文件的脚本，可能在路径拼接失误后直接作用到 `/usr`。

你需要的是：**在文件系统操作的入口处，强制检查目标路径是否落在预先声明的白名单目录内，否则直接拒绝**。

## 工程化实现步骤

### 1. 规划白名单目录

在脚本启动时从环境变量或配置文件读取白名单列表，例如：

```bash
export ALLOWED_DIRS="/var/lib/myapp,/tmp/myagent_tasks"
```

### 2. 路径解析与比较

不要信任任何传入的路径字符串。正确的做法是：

- 用 `os.path.realpath()` 展开所有符号链接和 `..`。
- 检查规范化后的路径是否以某白名单目录加上路径分隔符开头。
- 必须加上路径分隔符作后缀匹配，避免目录名称截断绕过（例如白名单 `/var/run/myagent` 不能匹配 `/var/run/myagent_fake`）。

Python 示例：

```python
import os

ALLOWED_DIRS = os.getenv("ALLOWED_DIRS", "").split(",")

def is_path_allowed(path: str) -> bool:
    real_path = os.path.realpath(path)
    for dir_ in ALLOWED_DIRS:
        real_dir = os.path.realpath(dir_.rstrip(os.sep)) + os.sep
        if real_path.startswith(real_dir):
            return True
    return False
```

### 3. 封装为可复用的保护层

#### 装饰器方案（适合 MCP 工具或普通函数）

```python
import functools

def restrict_fs_access(arg_names: list[str]):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            # 查找参数中需要校验路径的字段
            for name in arg_names:
                path = kwargs.get(name)
                if path and not is_path_allowed(path):
                    raise PermissionError(f"Access to {path} denied.")
            return func(*args, **kwargs)
        return wrapper
    return decorator

@restrict_fs_access(["filepath"])
def read_file(filepath: str):
    ...
```

#### 上下文管理器（适合脚本中的批量文件操作）

```python
from contextlib import contextmanager

@contextmanager
def safe_directory(target_dir: str):
    if not is_path_allowed(target_dir):
        raise PermissionError(f"Directory {target_dir} not in whitelist.")
    yield target_dir
```

### 4. 与 MCP 或插件系统集成

在定义 MCP 工具的 handler 中，直接包裹 safety 检查。例如：

```python
@app.tool()
async def read_project_file(ctx, path: str):
    if not is_path_allowed(path):
        return "Access denied."
    return await real_read(path)
```

这比依赖外部沙箱更轻量，也更贴合“工具级访问控制”的粒度。

## 踩坑点

- **符号链接与 bind mount**：`os.path.realpath()` 会跟踪符号链接，但无法感知 bind mount 或 `mount --bind` 创建的隐藏路径。如果你的环境存在 bind mount，建议额外使用 `os.stat` 检查设备号是否变化，或直接采用 Linux 的 `landlock`。
- **通配符与批量操作**：如果你暴露 `glob` 接口（如允许搜索 `*.py`），仍需在每个匹配文件上逐个检查白名单，而非仅在输入参数校验。
- **Windows 兼容**：路径分隔符与多盘符问题，需使用 `os.path.normpath` 后再匹配，且白名单目录也应规范化。
- **文件描述符传递**：如果你在进程间传递文件描述符或使用 `/proc/self/fd/...`，白名单检查可能被绕过。建议在打开文件后不暴露原始 fd。
- **白名单是集合，不是字符串**：避免在配置中直接用逗号分隔的字符串拼接触发 SQL 类似的“路径注入”，务必拆成列表逐一匹配。

## 可复用建议

1. 将 `is_path_allowed()` 和装饰器打包成一个内部 pip 包，在企业内部多个 Agent 项目复用。
2. 对 MCP 插件开发者，可提供 `@require_project_dir` 装饰器，自动从项目上下文获取当前 workspace 目录作为默认白名单。
3. 结合日志审计：记录所有被拒绝的路径访问，帮助发现 Agent 的异常行为模式。
4. 不要只限制写入，读取同样需要白名单——敏感文件泄露同样是高危风险。
5. 对于更复杂的需求（如限制进程而非仅脚本内部），可考虑将脚本运行在 Docker 容器内并用 `-v` 挂载具体目录，或在 systemd 单元里使用 `ProtectSystem=strict` 和 `ReadWritePaths=`。

## 总结

为自动化脚本加上本地目录白名单，是成本极低、收益极高的工程护栏。它不需要引入重量级沙箱，只需在文件操作入口做一次路径规范化与匹配。关键点是：始终解析符号链接，始终用 `os.sep` 结尾比较，始终拒绝未命中白名单的访问。当你的 Agent 开始触碰生产文件系统时，请确保它手上有一张明确的地图，而不是一把万能钥匙。
