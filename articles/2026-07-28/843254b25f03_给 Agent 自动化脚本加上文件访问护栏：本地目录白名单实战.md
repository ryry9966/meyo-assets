## 一、为什么 Agent 需要一个文件护栏

在 OpenClaw、MCP 或任何以“智能体 + 工具调用”为核心的自动化实践中，一旦允许 Agent 读写本地文件系统，就打开了一扇危险的门。无论是误操作还是提示词注入，Agent 都可能：

- 删除配置文件、日志或用户数据
- 覆盖关键脚本，导致下游任务失败
- 读取包含密钥的 `.env` 或 `~/.ssh` 目录
- 通过符号链接逃逸到敏感路径

常见的对策是环境隔离（Docker）或全盘只读，但对很多本机自动化场景并不现实。一个更细粒度的工程方案是：**在 Agent 的工具层实现本地目录白名单，只允许文件操作落在预先声明的合法路径内，形成一个最小权限的文件访问护栏**。

## 二、问题分析：我们要解决什么

Agent 调用文件系统通常通过几个原子操作：读文件、写文件、列目录、删除、重命名。白名单护栏的目标是：

1. 定义一个或多个允许访问的本地目录（例如 `/home/user/agent-workspace/`）
2. 对于每一次文件操作请求，在真正执行前检查目标路径是否属于白名单
3. 拒绝越权操作并记录告警，避免硬阻塞导致的静默失败难以排查
4. 能正确处理符号链接、相对路径、`.` 和 `..`

看似简单，但实际推敲后坑不少。

## 三、实现步骤

以下以 Python 为例，给出一个可直接嵌入 Agent 工具调用的代理层。思路是封装内置的 `open`、`os.remove`、`shutil.move` 等，使之在操作前需通过检查。

### 3.1 定义白名单与路径规范化

```python
import os
from pathlib import Path

WHITELIST_DIRS = []
def set_whitelist(dirs: list[str]):
    global WHITELIST_DIRS
    WHITELIST_DIRS = [Path(d).resolve() for d in dirs]

def _is_allowed(path: str | Path) -> bool:
    target = Path(path).resolve()
    # 防止符号链接指向白名单外
    # 但需要注意：target 可能尚不存在，此时 resolve() 会抛异常
    if target.exists() or target.is_symlink():
        target = target.resolve()
    for wh in WHITELIST_DIRS:
        # 检查 target 是否在 wh 子树内
        try:
            target.relative_to(wh)
            return True
        except ValueError:
            continue
    return False
```

这里使用 `resolve()` 有两个目的：消除 `.`/`..` 和符号链接，使最终物理路径固定。但 **如果目标路径是尚未创建的文件（写入操作）， `resolve()` 会要求路径存在才解析符号链接**，所以需要分支处理。更稳健的做法是先解析父目录，再拼接文件名：

```python
def _resolve_for_nonexistent(path: str):
    p = Path(path)
    parent_resolved = p.parent.resolve()
    return parent_resolved / p.name
```

我们在检查时，对已存在路径用 `resolve()`，对未存在路径用父目录解析，最终都归一化后与白名单比对。

### 3.2 包装文件操作

以只读 `open` 和删除为例：

```python
import builtins

def safe_open(file, mode='r', *args, **kwargs):
    file_path = str(file)
    if not _is_allowed(file_path):
        raise PermissionError(f"Access denied: {file_path} is outside whitelist")
    return builtins.open(file_path, mode, *args, **kwargs)

def safe_remove(file):
    if not _is_allowed(file):
        raise PermissionError(f"Access denied: {file} is outside whitelist")
    os.remove(file)
```

对于写操作（如 `mode='w'`），我们允许创建新文件，此时文件并不存在，要用上面的父目录解析路径。

### 3.3 集成到 Agent 的工具调用中

在 OpenClaw 或 MCP 的自定义工具中，把原本的 `open`/`os` 调用无感替换成 `safe_open`/`safe_remove` 即可：

```python
# 在工具函数内
def read_file(path: str):
    path = os.path.expanduser(path)  # 展开 ~
    with safe_open(path, 'r') as f:
        return f.read()
```

如果是 MCP 服务器端工具，同样可以包装资源访问，确保所有 `uri` 解析后的本地路径在白名单内。

## 四、踩坑点与应对

### 1. 符号链接逃逸
即使用户指定的工作目录在 `/workspace`，如果里面有一个符号链接指向 `/etc`，Agent 仍可能读取 `/etc/passwd`。我们的检查必须解析符号链接。对已存在路径 `Path.resolve()` 能处理；对要创建的文件，需检查上层目录是否已是白名单路径，且不信任任何符号链接组件。注意 `resolve()` 本身不跟随父目录外的符号链接，所以稳妥做法是手动解析每个路径部分，防止通过“未创建的中间目录”绕过。当白名单是 `/workspace`，用户传入 `/workspace/dir/../../etc`，归一化后会留在白名单外，会被拦下。

### 2. 相对路径与 `expanduser`
Agent 可能传入 `~/docs/secret.txt` 或 `subdir/../../etc`，必须统一先展开用户目录，再转为绝对路径后进行归一化。

### 3. Windows 大小写与分隔符
在跨平台场景下，使用 `Path` 对象和 `resolve()` 可自动处理，但注意白名单目录也应使用 `resolve()` 后存储，比较时大小写不敏感（Windows）由 `Path.relative_to` 按系统语义处理。

### 4. 权限拒绝后的错误处理
直接抛异常会导致 Agent 推理链断裂，建议返回带有明确错误码的结构化响应，让 Agent 能够使用备选方案或向用户汇报。例如返回 `{"error": "access_denied", "path": "..."}`。

### 5. 并发与竞争条件
在白名单检查通过后，到实际操作前，文件系统状态可能改变（例如被其他进程替换为符号链接）。这在多数工程环境中风险较低，可酌情决定是否加文件描述符级别的检查（如 `fstat` 后再确认路径）。对高安全场景建议结合操作系统强制访问控制。

## 五、可复用的工程建议

- **封装为可插拔的 `FilesystemGuard` 类**，支持白名单目录动态添加，同时提供 `audit_log` 回调记录越权尝试。
- **将白名单配置化**，通过环境变量 `AGENT_WHITELIST_DIRS` 注入，不硬编码在工具代码中。
- **与权限管理结合**：即使有白名单，仍避免以 root 运行 Agent，并设置文件系统权限（如不可写的只读目录）。
- **测试用例**：准备越权用例，包括符号链接跳转、`..` 路径、绝对路径、非法 Unicode 等，纳入 CI 检查。
- **对 MCP 资源**：如果 Agent 通过 `resource://` 访问，需在其解析逻辑中增加白名单检查，避免直接暴露本地路径。

## 六、总结

Agent 的文件访问护栏并非只为了“防骇客”，更是工程治理的一部分。在自动化脚本中，本地目录白名单能以极低的性能开销，从根本上限制工具暴露面。实现难点集中在路径归一化和符号链接处理，一旦抽象成可靠的 `guard` 层，就可以复用到所有文件类工具上。让 Agent 拥有自由的能力时，也给它一个清晰的安全边界，这样我们才能放心地让它处理更多本机任务。
