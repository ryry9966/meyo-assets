互联网上能爬的公开文本几乎被榨干了，合成数据的质量上限越来越明显，而 AI 的下一个训练数据金矿，其实就藏在你每天打开的电脑屏幕里——你的真实工作流。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-23/53dfb24b97569166.png)

## 从网页文本到屏幕录像：数据范式的根本转向

传统大模型吃的是网页文本、代码仓库、电子书，这些数据教会了模型语言模式和知识推理。但当我们要让 AI 真正“做事”时，需要的远不止语言能力。想象一下，你想让 AI 帮你填一份复杂的报销单、在 Figma 中调整设计稿、或者跨三个内部系统抓取数据生成报表。这些任务需要理解图形界面（GUI）、掌握操作序列、处理动态变化的上下文——静态文本给不了。

- **爬虫数据的尽头**：Common Crawl 这样的数据集已经包含了 PB 级的自然语言，但 90% 以上的页面是低质量、重复的“字符串噪音”。训练数据数量增长带来的性能提升边际递减。
- **合成数据的缺陷**：用 GPT-4 生成多轮对话或指令数据虽然方便，但往往过于“规整”、缺乏真实世界里的模糊与意外，容易造成模型“幻觉闭环”。
- **工作流数据的独特性**：它是一条多模态时间序列，包含了屏幕截图（视觉）、HTML/DOM 结构（语义）、鼠标与键盘事件（动作）、甚至语音记录（音频）。它像一段“带剧本的电影”，每一步都映射着人类的认知决策过程。

目前，像 Adept 的 ACT-1 模型、MultiOn 的 Agent 平台、以及开源的 OS-Copilot 项目，都开始直接消费这种数据。它们不再是“读”文本，而是在“看”和“做”的过程中学习。

## 一帧操作背后：如何从工作流中提炼出可训练的“行为 token”

把人类点鼠标的动作变成能喂给 Transformer 的 token，并不是录屏那么简单。这中间要经过采集、解析、对齐、脱敏四道工序。

1. **采集层**：像 OpenAdapt、ScreenAgent 这样的工具可以挂载在 OS 层面，记录下每个应用的窗口标题、控件 ID 以及对应的屏幕区域。同时捕获的是操作流：点击坐标（x,y）、拖拽路径、键入内容、甚至等待时间。对于复杂流程，还会用一个“任务注解器”自动生成自然语言描述：“用户此时正在从 CRM 导出联系人列表”。
2. **结构化为动作序列**：原始事件被转化为类似“action token”的表示。比如“点击 (120, 340)”对应屏幕上“提交”按钮，模型需要学习屏幕视觉特征与这个按钮语义的映射。Mind2Web 等数据集就利用 HTML 标签属性为动作提供 grounding。
3. **跨应用对齐**：你做一张报销单可能用到邮件、Excel、财务系统三个软件。这就需要一种通用的表示法来连接不同应用的操作，比如微软的 UIA、可访问性树。学术界正在尝试用大型多模态模型（LMM）来统一理解任何界面的 UI 元素，而不依赖于特定框架。
4. **隐私与安全**：屏幕里常出现敏感信息——姓名、金额、内部文档。采集时必须做到实时脱敏或本地化处理。开源社区更倾向于边缘计算方案：数据不出本机，只在本地对脱敏后的行为 token 进行训练或微调。

## 暗涌的生态：从个人 data flywheel 到“行为即服务”

真实工作流数据的价值，正在催生新的协作与商业模式，这里面有开源社区的共创，也有商业公司的圈地。

- **个人工作流开源**：在 GitHub 上已经有人公开自己的操作录屏数据集，用来训练特定任务的 Agent。例如有人录制了几十个小时的“电商选品分析”工作流，其他开发者就可以基于此微调一个选品助理。这很像 Roboflow Universe 之于计算机视觉，但门槛更低——只要你愿意“卖掉”自己的操作习惯。
- **企业行为挖掘**：RPA 厂商如 UiPath、Automation Anywhere，手中握着海量企业内部流程的记录。他们已经开始将匿名的流程图表与操作序列用于预训练“过程理解模型”，用来加速自动化脚本的生成。
- **去中心化数据市场**：一些 Web3 背景的项目（如 Golem 的后续方向）提出用代币激励个人用户贡献脱敏后的工作流数据，形成“做任务即挖矿”的模式。但合规性依然是最大挑战——GDPR 等法规下，操作行为是否属于个人数据仍没有定论。

更有趣的是，微软在 Windows 11 中不断强化 Recall 能力（一种回溯用户操作的功能），虽然因隐私争议而暂缓，但它暗示了操作系统本身正在成为最大的工作流数据生产者。未来你的电脑可能默认“记录一切”，供本地 AI 学习。

## 冷思考与三条建议

当操作屏幕变成数据油田，我们既兴奋又需要冷静。

1. **对于个人开发者**：不妨现在就录制自己重复性的日常工作流，用开源工具（如 OpenAdapt）将其转为结构化数据，尝试微调一个小 GUI Agent。这是一种低成本建立个人数据护城河的方式，前提是严格脱敏。你的专业知识库可能成为最独特的训练集——因为它在网上找不到。
2. **对于技术决策者**：如果考虑在公司内部采集员工操作数据来训练内部工具助手，请务必先建立透明的同意机制和匿名化管道。建议采用“差分隐私 + 联邦学习”的范式，让数据不动，模型动。否则一次数据泄露就可能彻底摧毁信任。
3. **对于行业观察者**：不要把“工作流数据”看成简单的新素材。它背后的隐含假设是：AI 将从“只动嘴”的语言模型，进化成“可动手”的世界模型。当模型学到了你如何操作 Photoshop、如何分析 Excel 表格，就意味着它在掌握一种通用的操作智能——这比再多 10TB 网页文本都更具颠覆性。

最后的工程师式幽默：如果有一天，你的 AI 助手的操作习惯和你一模一样，甚至会像你一样在保存文件前连续按三次 Ctrl+S，请不要惊讶——那是你用自己的工作流数据养出来的“数字分身”。
