## 背景：自动化脚本的“上帝视角”

在 OpenClaw 这类 Agent 平台里，我们通过 MCP 服务器让 LLM 能够调用本地工具——读写文件、执行 shell 命令、操作数据库。这意味着 Agent 眼中的文件系统，和我们打开终端时一模一样：`/etc/passwd`、`~/.ssh/id_rsa`、项目源码、配置密钥，一览无余。

问题在于，绝大多数自动化任务（生成报告、处理数据、导出文档）只需要在一个很小的目录范围内工作。一个“把 CSV 转成 JSON”的任务，根本不应该触碰 `~/.aws` 或者 `/var/run`。然而一旦将文件操作能力交给 Agent，我们就隐式地赋予了它对整个文件系统的读取（甚至写入）权限。这就像给了实习生一个 root shell，还指望他只碰桌面上的一个文件夹。

## 问题定义：我们需要怎样的护栏？

我们需要的不是一套复杂的 MAC/RBAC 体系，而是一个足够简单、工程师愿意实际使用、且能防住 90% 意外越权的机制。具体需求：

- **白名单目录**：显式声明 Agent 只能访问哪些目录（例如 `./workspace`、`/tmp/agent-output`）。
- **防绕过**：符号链接、相对路径、`..` 跳转等花招都应被拦截。
- **低侵入**：以函数装饰器或工具前置检查的方式存在，不影响原有业务逻辑。
- **可复用**：所有涉及文件 I/O 的 MCP 工具都能统一调用。

## 做法：一个极简的路径白名单实现

### 1. 核心检查函数

```python
import os
from typing import List

def is_path_allowed(path: str, allowed_dirs: List[str]) -> bool:
    """检查路径是否在允许的目录列表内（防符号链接绕过）"""
    # 解析符号链接与相对路径，得到规范化的绝对路径
    real_path = os.path.realpath(path)
    for allowed in allowed_dirs:
        # 确保 allowed 目录以分隔符结尾，防止部分匹配
        # 例如 allowed=/var/app 不应匹配 /var/app2/secrets
        if real_path.startswith(allowed.rstrip(os.sep) + os.sep) \
           or real_path == allowed.rstrip(os.sep):
            return True
    return False
```

这里的关键点：
- **使用 `os.path.realpath` 而非 `os.path.abspath`**：`realpath` 会消除路径中的所有符号链接，直接指向真实的 inode。如果项目目录内有一个软链接指向 `/etc`，`abspath` 会留在链接路径上，而 `realpath` 会揭示其真实目标。
- **目录前缀精确匹配**：通过在允许目录后追加 `os.sep`，避免 `/var/app` 意外匹配到 `/var/app-backup/secrets`。同时单独处理路径正好等于允许目录本身的情况。

### 2. 装饰器：自动化参数校验

如果文件路径是作为函数参数传入的（常见于 MCP 工具），我们可以用装饰器自动完成校验：

```python
from functools import wraps
from typing import Callable, Any

def restrict_paths(allowed_dirs: List[str], *path_arg_names: str):
    """装饰器：自动检查指定参数中的文件路径是否在白名单内"""
    def decorator(func: Callable) -> Callable:
        @wraps(func)
        def wrapper(*args, **kwargs) -> Any:
            # 从 kwargs 或按位置参数名查找
            for name in path_arg_names:
                if name in kwargs:
                    path = kwargs[name]
                else:
                    # 简单处理：假设未在 kwargs 中则在 args 的某个位置
                    # 工程中建议统一要求使用关键字参数
                    raise ValueError(f"Path argument '{name}' must be passed as keyword argument")
                if not is_path_allowed(path, allowed_dirs):
                    raise PermissionError(f"Access to '{path}' is not allowed. "
                                          f"Allowed dirs: {allowed_dirs}")
            return func(*args, **kwargs)
        return wrapper
    return decorator
```

使用示例：

```python
ALLOWED_DIRS = ["/home/user/project/workspace", "/tmp/agent-sandbox"]

@restrict_paths(ALLOWED_DIRS, "input_file", "output_dir")
def process_data(input_file: str, output_dir: str):
    with open(input_file) as f:
        # ...
```

### 3. 集成到 MCP 工具

在 MCP 服务器中，只需在每个涉及文件操作的工具函数开头调用 `is_path_allowed` 即可。例如一个“读取文本文件”工具：

```python
@app.tool()
def read_text_file(file_path: str) -> str:
    if not is_path_allowed(file_path, ALLOWED_DIRS):
        raise PermissionError(f"Access denied: {file_path}")
    with open(file_path, 'r') as f:
        return f.read()
```

可以将 `ALLOWED_DIRS` 通过环境变量 `AGENT_ALLOWED_DIRS`（以冒号分隔）注入，便于运维配置。

## 踩坑点：看似简单，仍有暗流

- **符号链接的 TOCTOU 问题**：即便我们在打开文件前做了 `realpath` 检查，攻击者仍然可能在检查通过后、实际打开文件前，将目标替换为指向敏感文件的符号链接。对于本地 Agent 场景，如果 Agent 本身和文件操作在同一台机器且没有恶意内部威胁，这个风险通常可接受；若担忧，可在打开文件后通过文件描述符再次获取路径进行二次验证（Linux 下 `/proc/self/fd/N`）。
- **相对路径的起点**：`realpath` 会将相对路径基于当前工作目录解析。确保 Agent 进程的 `cwd` 是你可控的（例如 Docker 容器的 `/workspace`），或者要求调用方永远传递绝对路径。
- **白名单目录的规范化**：配置文件中的路径可能带有尾部斜杠或多余的点号，在比较前记得都用 `os.path.realpath` 和 `rstrip(os.sep)` 做一次标准化。
- **多目录挂载的边界**：如果允许 `/mnt/data`，而用户通过挂载或软链接让 `/mnt/data/sub` 指向了外部，`realpath` 会跳出白名单。这其实是特性而非 bug：如果想阻止，就不该把挂载点或外部符号链接放入白名单子目录。
- **Windows 兼容性**：如果 Agent 运行在 Windows 上，盘符和分隔符逻辑需要适配，建议统一使用 `pathlib.Path.resolve()`，其行为与 `realpath` 类似且跨平台。

## 可复用建议

1. **封装为独立包或通用模块**：将 `is_path_allowed`、装饰器、环境变量读取等抽离成 `agent_file_guard.py`，所有 MCP 服务统一引用。
2. **与日志/告警联动**：每次拒绝访问时，记录完整的调用上下文（工具名、参数、时间戳），方便回溯是 Agent 幻觉还是路径配置错误。
3. **提供“试运行”模式**：允许通过环境变量将白名单检查置为仅警告不阻断，便于调试时发现误报。
4. **和平台权限模型互补**：OpenClaw 等平台本身的工具权限划分是第一道关，本方案是第二道纵深防御——即便某个工具被意外暴露，它的文件访问范围依然被锁死。

## 总结

给 Agent 的本地文件访问加一个目录白名单，实现成本极低，却能大幅降低“自动化脚本误删系统文件”或“LLM 幻觉导致读取隐私数据”的风险。核心就三件事：用 `realpath` 解析真实路径、严格做前缀匹配、通过装饰器或前置检查无痛集成。工程师花半小时写下这段代码，可能就堵住了未来某个凌晨三点让你从床上跳起来的坑。
