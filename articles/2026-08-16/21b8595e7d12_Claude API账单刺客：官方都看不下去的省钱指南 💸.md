最近海外开发者圈里有个说法：很多人不是被Claude的聪明震撼，而是被账单震撼。Anthropic官方最近更新了成本优化文档，甚至在一些开发者社区直接下场回复，指出大量API费用其实来自“不必要的token消耗”。这不是Claude变贵了，而是我们在给Anthropic白送钱。



## 一、账单刺客：钱到底从哪里漏掉
很多团队复盘API成本时，第一反应是“模型太贵”。但把调用日志拉出来看，贵的往往不是模型，而是使用姿势。

1. **重复发送长前缀**  
   每次请求都带上同一份系统提示、产品文档、历史对话。模型不记得上一轮，每次都要重新逐token读取，这部分按输入token计价。一个5000 token的知识库，每轮对话都重复发，费用直接线性上涨。

2. **max_tokens不设上限**  
   模型默认倾向于把输出写满。很多分类、提取任务只要求几十个token，却给了4096甚至8192的上限。输出token单价通常是输入token的5倍，这里浪费最明显。

3. **实时API干批量的活**  
   离线标注、批量摘要、日志分类等任务，明明可以等几分钟或几小时，却用实时API跑，付了全价。

4. **用大模型做小任务**  
   一个简单的“是/否”判断、关键词抽取、格式转换，也用Sonnet甚至Opus。模型能力溢出，账单也溢出。

5. **无脑重试**  
   网络抖动、超时就重试，同一请求可能被计费2-3次。尤其是输出已经产生一部分、连接断开时，客户端不知道是否需要续传，直接重发。

## 二、提示缓存：官方给的“折扣券”
Prompt Caching 是Anthropic官方主推的省钱机制，但很多开发者没开或没用好。



1. **原理**  
   把请求中的稳定前缀（system prompt、工具定义、知识库、少样本示例）缓存起来。首次写入时按稍高价格计费，后续命中时按约十分之一的价格读取。以Claude 3.5 Sonnet为例，缓存写入约3.75美元/百万token，缓存读取约0.30美元/百万token，而常规输入是3美元/百万token。读缓存比常规输入便宜一个数量级。

2. **适用场景**  
   客服机器人、文档问答、代码库解读、多轮Agent——只要前缀内容足够长（通常超过1024 token）且相对稳定，就能命中缓存。

3. **工程要点**  
   - 把静态内容放前面，动态指令放最后。缓存按前缀匹配，顺序不能乱。  
   - 缓存有生命周期，约5分钟左右。如果系统提示每次都在变，命中率会很低。  
   - 记录`cache_read_input_tokens`和`cache_creation_input_tokens`，用命中率评估效果。

## 三、批量处理：把实时变异步，价格直接腰斩
Batch API 是第二个被低估的省钱开关。

1. **价格**  
   官方Batch API定价约为实时API的50%。这意味着同样100万token的输出，批量跑只花一半钱。

2. **原理**  
   你把一批请求提交到队列，Anthropic在24小时内调度处理，响应延迟从毫秒级变成分钟级或小时级。适合非交互任务。

3. **适用/不适用**  
   - 适合：离线数据分析、测试集评测、批量内容分类、历史日志结构化。  
   - 不适合：聊天机器人、在线客服、任何需要即时响应的场景。

4. **注意**  
   Batch API有并发和文件大小限制，需要把任务拆分成多个批次。提交后可以轮询状态，失败项可以单独重试。

## 四、上下文工程与模型路由：少即是多
成本优化不能只靠缓存，更要在输入源头做减法。

1. **别把整本书塞进上下文**  
   长文档问答用检索增强（RAG），只把最相关的片段拼进prompt。几千token的相关片段，比几万token的全文便宜得多，也更容易命中缓存。

2. **长对话做摘要压缩**  
   多轮Agent在超过10-20轮后，历史消息会占满上下文。每N轮用一个小模型做摘要，把摘要拼回新对话，避免历史线性膨胀。

3. **按难度路由模型**  
   - Haiku：意图识别、关键词抽取、简单分类、格式转换。  
   - Sonnet：复杂推理、代码生成、多步工具调用。  
   - Opus：留给最难的架构设计、高价值决策。  
   很多团队全用Sonnet，不是因为需要，而是因为“懒得切换”。这个懒，很贵。

4. **精简工具描述**  
   如果给模型挂了20个工具，每个工具的schema几百个token，每次请求都带全套工具定义，成本不小。只暴露当前步骤可能用到的工具，或者用更短的参数描述。

## 五、输出控制与重试策略：给模型“闭嘴”的权利
输出端是另一个漏钱大户，因为输出token通常比输入token贵5倍。

1. **合理设置max_tokens**  
   分类任务给200，短摘要给500，长文给2000。不要让模型自己“写到爽”。模型不会因为上限低而变笨，只会更早停。

2. **使用stop_sequences**  
   生成JSON时，设置`}`或`\n`等停止序列，让模型及时收尾。对代码生成，可以用特定注释标记结束。

3. **流式输出与中断处理**  
   streaming不影响计费，但如果用户在流式输出中途关闭页面，服务端可能还在继续生成。需要在客户端中断时主动取消请求，或者设置服务端超时。

4. **重试要聪明**  
   对429（限流）和5xx（服务端错）分别处理：429要等更长时间，5xx可以做有限次重试。用指数退避加随机抖动，避免雪崩。对连接断开但已经有部分输出的请求，先查状态，不要盲目重发。

## 六、实用建议：三条冷思考


1. **先做一次账单审计**  
   把API调用日志按模型、prompt长度、max_tokens、缓存命中情况分组，找出费用最高的前20个请求。你会发现，20%的请求可能贡献了80%的成本。

2. **把“缓存命中率”当KPI**  
   目标不是“用了缓存”，而是命中率。稳定前缀长度超过1024 token的应用，命中率应该做到80%以上。命中率每提高10%，输入成本可能下降一个量级。

3. **从架构层面做成本预算**  
   别只盯着单价。Batch API、Prompt Caching、模型路由、上下文压缩，这些组合拳带来的降幅，远大于充值折扣。成本优化不是一次性项目，而是持续观测和迭代的工程能力。

说到底，Anthropic官方“看不下去”，不是嫌你钱多，而是想告诉你：API成本是可观测、可优化的工程指标。把省钱当KPI，才是对预算最大的尊重。
