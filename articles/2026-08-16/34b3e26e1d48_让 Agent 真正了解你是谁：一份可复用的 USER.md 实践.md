## 背景

很多 OpenClaw/Agent 用户都会遇到同一个问题：每次新开会话，Agent 对你一无所知。它不知道你常用的技术栈、目录习惯、权限边界，也不知道哪些问题你希望它先问、哪些可以直接做。于是前几轮对话经常浪费在“你是谁、你在什么环境、这个目录是干什么的”上。

更隐蔽的问题是：Agent 会猜。猜错时，它可能生成了看似合理但不适用于你环境的命令、路径或工作流。这在自动化、MCP 工具调用、插件开发场景里尤其危险。

USER.md 的思路很简单：把“我是谁、我的环境是什么、我希望你怎么工作”写成一份稳定、可版本管理的文件，让 Agent 在每次会话开始时读取。它不替代系统提示词，但提供了一层可复用、可迭代的用户上下文。

## 问题

没有 USER.md 时，典型痛点包括：

- 重复输入：每次都要说明操作系统、Shell、项目路径、常用命令。
- 上下文漂移：Agent 根据通用经验猜测，产出不符合你实际环境。
- 权限边界模糊：Agent 可能主动执行删除、安装、提交等操作，而你没有提前授权。
- 工作流不连续：你习惯“先跑测试再提交”，Agent 却直接给出提交命令。
- 多项目切换困难：不同项目有不同约束，Agent 无法自动感知。

这些问题的根源不是 Agent 能力不足，而是它缺少稳定、明确的用户侧上下文。

## 做法/步骤

### 1. 确定分层

建议至少分两层：

- **全局 USER.md**：描述你个人长期稳定的信息，例如 `~/.openclaw/USER.md`。
- **项目级 AGENTS.md 或 USER.md**：描述当前项目特定约束，放在项目根目录或 `.openclaw/` 下。

全局文件负责“你是谁”，项目文件负责“这个项目怎么干”。OpenClaw 中可以通过配置将 USER.md 注入 system prompt 或作为启动时自动加载的上下文文件。

### 2. 写什么

一份能用的 USER.md 不需要长篇大论。推荐包含以下块：

```markdown
# USER.md

## 基本身份
- 角色：后端工程师 / 自动化实践者
- 常用语言：Python, TypeScript
- 操作系统：macOS / Linux
- Shell：zsh

## 环境与路径
- 项目根目录：~/work
- 配置文件位置：~/.config/openclaw/
- 包管理：pnpm，禁止使用 npm

## 工作偏好
- 涉及删除、安装、提交前必须先说明
- 命令默认加 --dry-run 或先展示
- 不确定时先问，不要猜

## 常见任务 SOP
- 测试：先跑 pytest，再跑 lint
- 提交：commit message 使用 conventional commits
- 文档：中文为主，代码注释英文

## 已知坑
- 本机 Python 默认是 3.9，不要使用 3.10+ 语法
- 项目依赖有本地缓存，不要轻易 clean
```

### 3. 挂载与引用

在 OpenClaw 配置中，把 USER.md 作为只读上下文加入。可以手动在每次会话开头粘贴，但更推荐自动化加载。若你使用 MCP 或插件扩展，也可以让一个轻量工具读取 USER.md 并注入到会话上下文。

### 4. 迭代维护

每次 Agent 反复问同一个问题、或出现一次因上下文缺失导致的错误，就回写 USER.md。把它当成代码维护，而不是写一次就完事。

## 踩坑点

1. **写太长**：超过 200 行的 USER.md 会被 Agent 忽略或稀释重点。只保留高信号信息。
2. **放敏感信息**：不要在 USER.md 里写 API key、密码、内部 IP。它可能被上传到第三方模型。
3. **写散文不写事实**：避免“我喜欢高效工作”这种空话，改成“优先级：先跑测试，再给建议”。
4. **与项目文档冲突**：如果项目 README 说用 yarn，USER.md 说用 pnpm，Agent 会混乱。保持单一事实来源。
5. **过度约束**：把每一步都写死，Agent 会变得死板。给原则，不给完整脚本。
6. **不更新**：环境换了、工具换了，USER.md 还停留在旧版本，反而误导 Agent。

## 可复用建议

- **使用模板**：固定区块，方便快速填写新项目。
- **控制在 150 行内**：每一条都能回答“Agent 看到这条后会不会少犯错？”
- **只写可验证事实**：路径、命令、版本、工具名。
- **设置兜底规则**：例如“任何不确定的环境差异，先询问再执行”。
- **版本管理**：把 USER.md 放进 dotfiles 或私有仓库，方便多机器同步。
- **与项目文件分工**：全局 USER.md 只写个人稳定信息，项目约束放项目文件，避免全局文件被单项目污染。

## 总结

USER.md 不是魔法，也不该被过度神化。它解决的是一个非常具体的问题：让 Agent 在开始工作前，能稳定地知道你是谁、你在哪、你希望它怎么干。对 OpenClaw/MCP/自动化实践者来说，这比堆更多插件更能减少误操作和不必要来回。

从一份 80 行的 USER.md 开始，持续迭代，会比一次性写 500 行更有效。
