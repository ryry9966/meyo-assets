最近“四代跳Attention”突然上了热搜，评论区一半在问“是不是新模型”，一半在问“是不是营销造词”。其实拆开看就两个关键词：四代，是 Attention 机制的代际演进；跳，是这一代架构里最值得说的跳跃连接思路。这篇不吹热点，只把它拆到公式、复杂度、工程收益三层。



## 1. 先把 Attention 降维成三个张量



- 经典 Scaled Dot-Product Attention 公式：`Attention(Q,K,V)=softmax(QKᵀ/√d_k)V`
- 三个输入 Q、K、V 都来自同一个 token 序列的线性投影：
  1. Query：当前 token 想问“我应该关注谁”
  2. Key：候选 token 的“标签”
  3. Value：候选 token 实际携带的信息
- 先算 Q 和所有 K 的内积，得到相似度分数；除以 √d_k 是为了防止维度大时 softmax 饱和；最后用 softmax 归一化成权重，再对 V 加权求和
- 模型每算一个 token，都要和序列里所有 token 两两打分，所以复杂度是 O(n²)
- 举个具体数：序列长度 1024，注意力矩阵是 1024×1024；到 8192，矩阵变成 8192×8192，约 6.7 千万个得分；再往上，显存和计算都很不友好
- 因此从第一代之后，注意力机制的优化主线就两条：一是降低复杂度，二是提高信息密度

## 2. “四代”不是玄学：注意力机制的四次架构拐点



- 第一代：RNN + Attention。最早在机器翻译里把对齐权重引入序列建模，解决长距离依赖，但 RNN 串行慢
- 第二代：Self-Attention / Transformer。2017 年把序列内部所有 token 互相看，并行训练快，但代价是 O(n²)
- 第三代：稀疏/线性/局部注意力。Longformer、BigBird、Linformer、Performer、FlashAttention 等，分别从拓扑、低秩、核函数、IO 角度降成本
- 第四代：以跳跃/门控/状态空间混合为特征的 Attention。社区把它喊成“四代跳 Attention”，核心不是在 Softmax 上继续堆技巧，而是让注意力模块学会“跳过”不必要的信息
- 注意：这四代不是线性进步，更多是工程取舍。第三代没有淘汰第二代，第四代也不会让 FlashAttention 立刻过时
- 从复杂度和硬件友好度看，四代的大致关系是：
  1. 第一代解决“能建模长距离”，但训练慢
  2. 第二代解决“能并行训练”，但显存大
  3. 第三代解决“长序列可训练”，但信息路由仍偏固定
  4. 第四代尝试解决“动态决定哪些信息值得算”，牺牲一定通用性换效率

## 3. “跳”字从哪来：Skip Connection 老树开新花



- ResNet 的残差连接 `y = F(x) + x`，让梯度能直接穿过深层网络
- DenseNet 更进一步，把前面层的特征反复拼接到后面，形成“密集跳跃”
- 在 Attention 里，“跳”通常有两种含义：
  1. 层间跳跃：让某些 token 或某些层不经过完整注意力计算，直接走残差旁路
  2. 序列跳读：先快速扫全局，再只对部分关键 token 做细粒度 Attention
- 第二类很像人眼跳视（saccade）：不会逐字阅读，而是先定位重点，再集中处理
- 具体到架构里，常见的实现不是“直接丢掉 token”，而是：
  1. 用一个小型门控网络给每个 token 打分
  2. 只把高分 token 送进全注意力分支
  3. 低分 token 走轻量线性投影或残差旁路
  4. 最后把两条路径的输出拼回原序列
- 这样做的好处是：注意力图还是全局的，但参与计算的 key/value 规模变小了
- 所以所谓“四代跳 Attention”，可以理解成把 ResNet 时代就存在的跳跃思想，搬进注意力内部，尤其用在长序列上

## 4. 落地收益、真实代价与三条冷思考



- 收益：长序列下，跳读式注意力通常能把 KV cache 或注意力计算量降低 50%~70%，具体取决于稀疏率和门控质量
- 代入一个例子：32K token 的文档问答，如果门控选出 30% 的关键 token，全注意力的 key/value 规模就从 32K 降到约 9.6K，显存占用和 decode 时延都会明显下降
- 代价：门控网络带来额外参数和延迟，短序列上可能反而更慢；错误跳过关键 token 会造成精度回退
- 适合场景：RAG 长文档问答、代码库检索、视频帧采样、基因序列扫描
- 不适合场景：短文本分类、高精度密集推理、端侧小模型部署
- 如果序列长度不超过 4K，FlashAttention-2/3 通常就够；8K 以上再考虑跳跃/稀疏类方案
- 关注指标别只看精度：显存峰值、prefill/decode 时延、吞吐量的 Pareto frontier 更真实
- 三条冷思考：
  1. 把新代号当作检索线索，不要当成技术信仰；先读原文或复现实验
  2. 在最小 GPT 或 ViT 上先测长序列显存，再决定是否引入跳跃/稀疏
  3. 用 PyTorch Profiler / Triton 看 attention kernel 的瓶颈，避免在非瓶颈处过度优化
