## 背景

在 OpenClaw 里接 MCP 工具或写自动化插件时，最先遇到的通常不是模型能力不够，而是状态不连续。这次会话知道用户习惯用 `uv` 而不是 `pip`，下次会话又反过来问；这次记住了“代码注释用英文”，下次继续生成中文注释。

把偏好写进 system prompt 很快会撑爆上下文，且不可维护；完全不做记忆，Agent 每次都是“新来的”。所以需要给 Agent 加一层独立、可控的记忆系统。

## 问题定义

记忆不等于日志。日志是完整记录，记忆是压缩后能改变后续行为的少量状态。设计时要先分清：

- **用户偏好**：稳定，如语言、代码风格、通知方式。
- **环境事实**：路径、设备名、常用仓库。
- **任务状态**：易过期，如“上次构建失败，正在修复”。
- **推理结论**：过期更快，如“用户最近在调研向量库”。

需要解决四件事：存在哪里、什么时候写、什么时候读、怎么更新。

## 做法/步骤

### 1. 先定 schema，别直接存自然语言

建议用 SQLite 起步，JSON 字段即可，不上向量库。每条记忆固定格式：

```json
{
  "key": "pref.code_style",
  "scope": "user:default",
  "value": "prefer Python type hints",
  "type": "preference",
  "source": "user:2025-01-01",
  "confidence": 0.9,
  "ttl": null,
  "updated_at": "2025-01-01T10:00:00Z"
}
```

在 OpenClaw 中可以把它实现为一个小型 MCP server，暴露 `memory.search`、`memory.upsert`、`memory.delete` 几个工具，插件和 Agent 统一走这套接口。

### 2. 写入策略：宁少勿滥

不要让 Agent 自动把所有对话内容都写入记忆。更稳的做法是：

- 用户明确说“记住……”时，才触发写入。
- 工具调用成功后，只提取关键参数写入，例如用户指定的默认分支、部署目标。
- 新记忆先进入 `candidate`，和已有条目做去重/合并，再落库。

自动推断可以保留，但必须降低 `confidence`，并且不能覆盖用户直接给出的指令。

### 3. 检索注入：按 scope + priority 先过滤

会话开始时，不要把所有记忆都塞进 system prompt。先按 `scope`、`type`、`priority` 规则过滤，再按关键词或 embedding 检索补充。控制预算很关键，例如单次最多注入 10 条或 800 token。

在 OpenClaw 中，这可以做成一个启动钩子：读取当前会话上下文，向 memory server 要一批相关偏好，注入到 system prompt 末尾。不要放在最前面干扰主指令。

### 4. 更新与冲突

同 `key` 更新时记录 `updated_at` 和 `source`。优先级建议：用户显式指令 > Agent 观察推断 > 历史默认值。任务状态类记忆必须带 TTL，否则下次会话还会误读旧状态。

### 5. 可审计与删除

提供 `/memory list` 和 `/memory delete` 这类命令，或者 MCP 工具里直接支持删除。用户能看到 Agent 为什么这么记，才能长期用下去。

## 踩坑点

- **把对话摘要当记忆**：几百字摘要塞进库，检索时噪声多、token 成本高。
- **自动写入过猛**：把临时错误、一次性选择当成长期偏好。
- **用纯 JSON 文件无事务**：多 Agent 或并发写入时文件损坏，SQLite 是更省心的选择。
- **注入记忆过多**：system prompt 变成大杂烩，模型反而忽略关键约束。
- **作用域混乱**：个人偏好被注入到工作项目，或者项目 A 的路径被用到项目 B。
- **隐私泄露**：记忆里存 token、绝对路径、内部域名时，要注意存储位置和日志脱敏。

## 可复用建议

- 从规则过滤起步：`scope + type + priority` 能解决大部分问题，等不够用了再上 embedding。
- 固定 schema，别存自由文本段落。
- 写几条关键测试：写入 → 检索 → 更新 → 删除，保证 MCP server 行为稳定。
- 为每条记忆保留来源和更新时间，方便调试。
- TTL 和 confidence 是必须字段，哪怕一开始用不上。
- 给用户一个“删除记忆”的出口，避免系统替用户做太多决定。

## 总结

Agent 记忆系统不是越像人越好，而是可控、可回滚、低 token 成本。在 OpenClaw/MCP 场景里，比较务实的路线是：先做一个结构化偏好库，配合规则检索和显式写入；等稳定后再考虑向量检索和自动提取。小型 MCP memory server 往往比模型“自动记忆”更可靠，也更适合长期维护。
