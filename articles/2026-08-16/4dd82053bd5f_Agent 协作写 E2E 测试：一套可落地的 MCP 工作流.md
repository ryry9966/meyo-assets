## 背景

E2E 测试是自动化里最容易被“劝退”的一环：选择器脆弱、环境准备繁琐、断言写不到位。Playwright、Cypress 降低了执行门槛，但编写成本依然很高。我们尝试让 Agent 参与后发现，单纯“生成测试代码”价值有限，真正有效的是让 Agent 具备“运行-观察-修复”的闭环。

## 问题

直接让 LLM 写测试，常见问题包括：选择器使用复杂 CSS 或文本定位；断言只检查元素存在，不验证业务状态；测试数据硬编码；生成的代码无法直接运行；甚至修改了不该改的源码。这些问题的根源不是模型能力不足，而是缺少可执行反馈和边界约束。

## 做法 / 步骤

### 1. 工具链准备

在 OpenClaw 中挂载三个 MCP server：

- **Playwright MCP**：提供浏览器操作和页面可访问性树读取
- **Filesystem MCP**：限定测试目录读写权限
- **Shell MCP**：执行 `pnpm test` 等命令

关键是权限隔离。Filesystem 只映射 `tests/` 和 `fixtures/` 目录，避免 Agent 误改源码。

### 2. 任务模板

给 Agent 的指令需要包含以下内容：

- 先读取现有测试示例、页面 ARIA snapshot、项目测试规范
- 生成文件到 `tests/e2e/` 目录
- 运行测试，若失败根据错误信息最多修复 3 次
- 不允许修改 `src/` 目录

### 3. 执行迭代

Agent 会先用 Playwright 打开页面，获取可访问性树，生成初始测试，运行后根据报错（选择器找不到、超时等）调整。我们观察下来，标准流程平均 2-3 轮可以通过。

### 4. 人工审核

通过后必须 review 断言是否验证了关键业务状态，以及是否依赖了易变文案。这一步不能省，Agent 通过不代表测试有价值。

## 踩坑点

- **上下文爆炸**：ARIA snapshot 可能很大，需要截断或只取相关区域。让 Agent 先输出计划，再按需获取 DOM 片段。
- **选择器漂移**：Agent 喜欢 `text=` 定位，文案一改就挂。约束它优先使用 `getByRole` 和 `data-testid`，并在规范中禁止裸 CSS。
- **环境差异**：本地通过 CI 失败，通常是浏览器版本或服务未就绪。让 Agent 生成的测试自带 `beforeAll` 等待逻辑，并在 CI 中复用同一 Playwright 配置。
- **误改代码**：必须通过 Filesystem MCP 限制根目录，否则 Agent 可能“顺手”重构源代码。
- **虚假通过**：测试通过不代表业务正确。要求断言必须包含可观测的状态变化，比如提交后出现成功提示或列表更新。

## 可复用建议

- 把测试规范写成 markdown，作为系统提示的一部分。例如：“所有选择器必须使用 role 或 test-id；每个用例独立准备数据；禁止使用固定 sleep”。
- 采用小步任务：一个 Agent 会话只负责一个用户流程，避免生成巨型文件。
- 保留失败记录：让 Agent 把每次失败原因和修复动作追加到测试注释中，方便人工回溯。
- 如果你没有 OpenClaw，也可以用任意支持 MCP 的 Agent 框架实现，核心是“可执行反馈 + 目录隔离”。

## 总结

Agent 协作写 E2E 测试，真正有价值的部分不是自动补全代码，而是把“写测试”变成“调试测试”。当 Agent 能够运行、观察失败、修正并再次运行，它就从一次性生成器变成了一个可迭代的工程助手。建立好 MCP 工具链和约束，这件事在现有技术栈下已经可以落地。
