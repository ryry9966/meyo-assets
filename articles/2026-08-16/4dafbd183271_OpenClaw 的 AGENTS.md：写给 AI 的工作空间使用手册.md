# OpenClaw 的 AGENTS.md：写给 AI 的工作空间使用手册

在 OpenClaw 里，Agent 能调用 MCP、执行脚本、读写仓库，但它对当前工作空间的了解往往来自泛化的系统提示。AGENTS.md 就是放在项目根目录的一份“工作手册”，告诉 Agent：项目怎么跑、命令是什么、哪里不能碰、失败后怎么办。它不是给模型的情书，而是给 Agent 的操作清单。

## 一、为什么需要它

没有 AGENTS.md 时，Agent 容易做几件事：猜错包管理器、在错误目录执行命令、重复造已经存在的脚本、误改生成文件或敏感配置。每次都要靠人工在对话里重新解释一遍，既不稳定也不可复用。

AGENTS.md 的价值在于把“重复决策”变成“固定约束”。它随仓库走，不依赖聊天记录，换一个会话、换一个 Agent，只要读文件就能获得同样的工作空间上下文。

## 二、怎么写一份能用的 AGENTS.md

### 1. 最小结构

建议至少包含六块：

- **项目一句话**：这是什么，不要写愿景。
- **快速启动**：安装、开发、测试、构建命令，直接复制 scripts。
- **目录地图**：只列关键路径，不写全量树。
- **边界与禁则**：明确不能改、不能删、不能碰的东西。
- **验证方式**：怎么判断任务完成。
- **失败处理**：测试挂了看哪里、日志在哪、常见错误怎么排查。

一个精简示例：

```markdown
# Project: openclaw-quick-notes

## Quick start
- 安装：pnpm install
- 开发：pnpm dev
- 测试：pnpm test
- 构建：pnpm build

## Layout
- src/ 主逻辑
- packages/mcp-*/ MCP 插件
- scripts/ 自动化脚本，仅可显式调用

## Rules
- 所有命令在仓库根目录执行
- 不要修改 packages/mcp-*/dist
- 不要运行 rm -rf 或 git push --force
- 修改 .env.example，不要写入真实密钥

## Verify
- 功能完成 = pnpm test 全绿 + pnpm lint 通过
```

### 2. 给 OpenClaw 的额外说明

如果仓库里挂了 MCP 或插件，AGENTS.md 要写清楚工具边界。例如：

- 哪些 MCP 工具只读，哪些会写文件或调外部服务。
- 插件是否有 side effect，比如会发通知、写日志、触发 webhook。
- 自动化任务的最大步数、超时时间、失败后是否允许重试。

这比泛泛写“谨慎使用工具”有效得多。

## 三、踩坑点

**1. 写成 README 长文。**  
Agent 需要的是命令、路径、限制，不是项目历史和架构愿景。太长的 AGENTS.md 每次都被读入上下文，浪费 token，还会淹没关键信息。建议控制在 300–500 行以内。

**2. 只写“应该做”，不写“禁止做”。**  
“保证代码质量”没有约束力；“不要编辑 lockfile、不要格式化无关文件”才有。

**3. 命令和 package.json 脱节。**  
Agent 会严格照 AGENTS.md 执行。如果文件里写 `npm run build`，但项目实际用 `pnpm build`，它真的会失败。写完最好逐条复制 scripts。

**4. 忽略执行目录。**  
很多 Agent 在子目录里跑命令，相对路径就会错。明确写“以下命令均在仓库根目录执行”能避免大量低级错误。

**5. 把敏感信息写进去。**  
不要放 token、内网地址、数据库密码。只写变量名和获取方式，例如“读取 `.env` 中的 `DATABASE_URL`，不要打印该值”。

**6. monorepo 嵌套混乱。**  
根目录放总纲，子包可以放局部 AGENTS.md。但要注意嵌套覆盖或合并规则，否则 Agent 可能同时读多份文件，产生冲突指令。

## 四、可复用建议

- **用可验证标准代替形容词**：把“确保格式化”改成“提交前运行 `pnpm lint && pnpm format:check`”。
- **先给快速启动，再给细节**：Agent 优先看最前面的命令。把高频命令放在文件顶部。
- **写失败路径，而不只写成功路径**：告诉 Agent 测试挂了去看 `reports/`，或运行 `pnpm test -- --reporter=json`，比只说“排查问题”实用。
- **形成维护闭环**：每次 Agent 重复犯同一个错误，就把规则写成一行回写进 AGENTS.md。下一会话不会再犯。
- **按需索引复杂文档**：如果项目文档很多，不要全塞进 AGENTS.md，用 `docs/agent-*.md` 建索引，让 Agent 按需读取。
- **和代码一起提交**：AGENTS.md 应该进版本库，变更要 review，像改 CI 配置一样严肃。

## 总结

AGENTS.md 不是为了让 AI 更“聪明”，而是为了让它更“可靠”。好的 AGENTS.md 像一份操作手册：短、准确、可验证、有边界。它把每次会话里重复解释的成本，转化为一次维护投入。对 OpenClaw 用户来说，越早把工作空间规则落成文件，越能减少 Agent 的随机行为，真正把自动化跑起来。
