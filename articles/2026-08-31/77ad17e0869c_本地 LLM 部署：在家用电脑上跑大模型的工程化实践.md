## 背景

在 OpenClaw/Agent/MCP/插件这类自动化链路里，LLM 常被当作“可编程的推理核心”。但云端 API 有网络、隐私、调用频率和调试成本问题。家用电脑部署本地模型，收益是数据不出机、接口可离线、调试可复现；代价是显存、推理速度和模型能力都有限。

## 先明确问题

家用电脑通常不是高并发服务器。部署前要确认三件事：

1. **显存能装下模型权重和 KV cache。**
2. **模型是否支持工具调用/函数调用。** OpenClaw、MCP、插件往往不是只聊天，而是要求模型输出稳定的 JSON 或 tool call。
3. **服务是否暴露 OpenAI 兼容 API。** 这样 OpenClaw 只要换 base_url 和 model name，不需要改插件逻辑。

## 部署步骤

### 1. 模型选型

按显存选，不要盲目上大模型。以 Q4_K_M 量化为参考：

- 4–6GB 显存：7B 模型，如 Qwen2.5-7B-Instruct。
- 8–12GB 显存：7B/14B 模型，14B 可用 Qwen2.5-14B-Instruct 或 Mistral-Nemo。
- 无独显：只建议 7B 以下做异步测试，不要接入实时交互。

对自动化链路，优先选 `Instruct` 版本，别用 base 模型。

### 2. 启动本地服务

Ollama 最简单，默认暴露 OpenAI 兼容接口：

```bash
ollama pull qwen2.5:7b-instruct-q4_K_M
ollama serve
```

服务起来后，`http://127.0.0.1:11434/v1` 就是兼容入口。

如果需要更细控制显存卸载和上下文，用 llama.cpp：

```bash
llama-server -m qwen2.5-7b-instruct-q4_k_m.gguf \
  --n-gpu-layers 999 \
  -c 8192 \
  --host 127.0.0.1 --port 8080
```

`--n-gpu-layers 999` 表示尽量把层放 GPU；显存不够就减少。

### 3. 接入 OpenClaw

配置项大致是：

```bash
OPENAI_BASE_URL=http://127.0.0.1:11434/v1
OPENAI_API_KEY=local
MODEL_NAME=qwen2.5:7b-instruct-q4_K_M
```

API key 可以给任意非空字符串。关键是要让 OpenClaw 使用同一个 `model` 名称，且本地服务里确实存在该模型。

### 4. 验证

先发一个简单请求：

```bash
curl http://127.0.0.1:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen2.5:7b-instruct-q4_K_M","messages":[{"role":"user","content":"ping"}]}'
```

再看 tool call：给一个简单函数，如 `get_weather(city)`，检查模型是否返回可解析的函数名和参数。这一步过了，再接入 MCP 或插件；否则后面排错成本更高。

## 踩坑点

1. **以为在 GPU 上跑，实际跑在 CPU。** 用 `ollama ps` 或 `nvidia-smi` 确认。CPU 推理 2–5 tok/s，插件链路会明显卡顿。
2. **上下文开太大导致显存爆掉。** 本地模型 KV cache 是显存杀手。先设 4096–8192，够用就行。
3. **小模型工具调用不稳定。** 可能会输出 Markdown 包裹的 JSON、漏参数、或虚构工具名。解决方案：限制工具数量，写清工具描述，必要时在提示里要求“只输出一个 JSON 对象，不要解释”。
4. **并发访问。** 家用 GPU 一般撑不住多个 OpenClaw 插件同时请求。可以限制 `OLLAMA_NUM_PARALLEL=1`，或把轻量任务和重量任务分流到不同模型。
5. **Windows/WSL2 环境。** 优先原生 Linux；Windows 下确认 GPU 驱动和 CUDA 匹配，避免 WSL2 和 Windows 端同时抢 GPU。

## 可复用建议

- **接口抽象**：所有接入方只依赖 OpenAI 兼容 URL，以后从本地切远程或反过来，不用改业务插件。
- **两层模型**：7B 做抽取、总结、简单路由；14B 做规划或复杂工具选择。不要用一个模型扛所有任务。
- **健康检查**：写一个最小 `/v1/chat/completions` 探活脚本，在 OpenClaw 启动前执行。
- **记录实际指标**：用 `ollama run --verbose` 看 eval rate，量化模型效果和速度，再决定是否继续。
- **明确边界**：本地模型适合隐私、离线、调试、小规模自动化；高并发或复杂环境仍应有远端 API 作为兜底。

## 总结

本地 LLM 部署到家用电脑，可行，但前提是把模型能力、显存和 OpenClaw 的工具调用要求放在同一张表里评估。不要只看模型参数，先跑通一个 tool call，再接入 MCP/插件。这样得到的是一个可调试、可复现、数据可控的本地推理节点，而不是一个容易崩溃的摆设。
