## 背景

在 OpenClaw / Agent / MCP 这类自动化链路里，模型通常是 HTTP API 的一环。云端模型适合快速验证，但不少场景需要本地模型：离线运行、内部数据不出机器、固定 base_url、控制工具调用成本、调试时能直接看进程日志。家用电脑跑大模型不是为了追上旗舰 API，而是用可控的小模型完成结构化提取、指令分发、工具参数生成等窄任务。

## 问题

本地部署的主要矛盾不是“能不能跑”，而是：显存/内存限制了模型尺寸与上下文；小模型在函数调用、JSON 输出上更容易漂移；本地并发差，Agent 并行调工具时会排队超时；模型默认模板和上下文长度经常与项目假设不一致。

## 做法/步骤

### 1. 先按显存选模型

给一个实用基线：

- 8 GB 显存：7B/8B 模型，Q4_K_M，上下文 8192
- 12–16 GB 显存：14B 模型，Q4_K_M/Q5_K_M，上下文 16384
- 24 GB 显存：32B Q4 或 14B Q6 + 更大上下文

不要因为怕慢选 1.5B/3B，它们在工具调用上的稳定性通常不够。

### 2. 运行时优先 Ollama 或 llama.cpp server

个人项目推荐 Ollama，简单稳定，并提供 OpenAI 兼容接口：

```bash
ollama pull qwen2.5:7b-instruct-q4_K_M
ollama serve
```

默认 API 地址是 `http://localhost:11434/v1`。如果已经有 llama.cpp，建议启动 `llama-server` 而不是自己包推理循环，避免重写流式响应和停止条件。

### 3. 选模型看工具调用格式

中文 Agent 场景优先 Qwen2.5-Instruct 系列。7B/14B 的工具调用能力比同体量的旧模型稳。英文链路可以用 Llama 3.1 8B 或 Mistral 7B v0.3，但要在接入前确认 chat template 是否正确。

### 4. 接入 OpenClaw/Agent

把模型供应商的 base_url 指向 `http://localhost:11434/v1`，`api_key` 可填任意非空值，模型名填 `qwen2.5:7b-instruct-q4_K_M`。建议：

- `temperature` 设 0.0–0.2
- 请求超时拉长到 120 秒以上
- 关闭不必要的并行模型加载

如果框架支持 `tools`/function calling，先直接走原生格式；如果不稳定，就退化为 prompt + JSON schema，在系统提示里写死输出结构。

### 5. 先做链路测试

不要一上来接 MCP。先单独发 `/v1/chat/completions`，确认返回 JSON；再测一个简单工具；最后再挂到自动化流程。

## 踩坑点

- **上下文默认太小**：不少本地模型默认 `num_ctx` 是 2048 或 4096。Agent 的系统提示 + 工具列表很容易塞满。Ollama 可在请求参数里带 `options.num_ctx`，或建 Modelfile 固定。
- **显存超分导致速度崩坏**：一旦 KV cache 超过显存，速度会断崖下降。先看 `nvidia-smi`，保留 1–2 GB 余量。
- **小模型 JSON 漂移**：复杂嵌套 schema 是重灾区。把 schema 拆浅，字段控制在 3–5 个，避免 `anyOf` 和多层数组。
- **并发不是越高越好**：本地 GPU 对并发推理不友好。设置 `OLLAMA_NUM_PARALLEL=1`，Agent 工具调用排队执行，比同时发 4 个请求更稳。
- **默认监听地址**：不要直接暴露 `0.0.0.0`。远程访问用 SSH 隧道，或才加反代鉴权。
- **GGUF 模板问题**：如果模型回答里出现特殊 token 或格式混乱，先怀疑 chat template 丢失，换官方 Ollama library 模型或手工补 Modelfile。

## 可复用建议

- 固定“模型 + 量化 + 上下文”作为基线，写进 README，避免每次调整。
- 7B Q4 验链路，14B Q4 做日常，不追新模型。
- 记录 tokens/s 和显存占用，判断慢是显存换页还是模型太小。
- 把本地 LLM 封装成可切换 provider，随时切回云端对比。
- 中文工具调用优先 Qwen；英文优先 Llama/Mistral，但都要用真实 task 回归。

## 总结

在家用电脑上跑本地 LLM，对 OpenClaw/Agent/MCP 用户来说，最实用的不是跑一个“能聊天”的模型，而是跑一个可预测、可复现、可审计的自动化组件。控制好量化、上下文、工具格式和并发，7B/14B 规模已经能承担不少工程化任务。
