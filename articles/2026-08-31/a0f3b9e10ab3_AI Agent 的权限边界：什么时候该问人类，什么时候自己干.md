# AI Agent 的权限边界：什么时候该问人类，什么时候自己干

## 背景：Agent 正在从“对话”走向“执行”

在 OpenClaw、MCP 工具链和插件自动化场景里，Agent 不再只是回答问题，而是能调用文件系统、数据库、浏览器、消息接口甚至付费 API。一个任务可能触发十几步工具调用：读取配置、生成脚本、写入文件、执行命令、发送通知。权限一旦放开，误操作的半径也随之扩大。

我们遇到最多的情况不是 Agent 能力不够，而是权限边界不清：有时 Agent 每一步都停下来问，任务做到一半用户已经不耐烦；有时又过度自主，把生产目录里的文件批量改名，或者给客户发了一封未审核的邮件。

所以这个问题必须被工程化，而不是靠“模型自己判断”。

## 问题：两个失败方向

**过度询问**：所有写操作都弹确认，Agent 退化成聊天机器人。用户确认次数超过三次后，要么直接点“允许”形成习惯，要么放弃自动化。

**过度自主**：该确认的不确认。高风险操作被当成普通步骤执行，比如删除不可恢复的数据、调用付费 API 批量生成、向外部联系人发消息。

真正的难点在于：权限边界不是固定的，它取决于操作的风险、可逆性、成本、上下文以及当前任务的置信度。同一个“写文件”操作，写到临时目录和写到生产配置目录，风险完全不同。

## 做法：把权限边界做成控制面

我们在一组自动化任务里逐步收敛出以下做法。

### 1. 给工具分级，而不是给 Agent 一个总开关

把 MCP/插件工具按副作用分成四类：

- **只读**：查文件、读数据库、搜网页。默认允许，不确认。
- **低风险可逆**：写临时文件、创建草稿、生成报告。自动执行，但记录日志。
- **高风险不可逆**：删除、覆盖生产配置、发送消息/邮件、执行 shell 命令。必须确认。
- **外部成本**：付费 API、批量调用、对外发布。必须确认，并且限流。

这个分级直接写进工具描述里，例如：

```yaml
tool: delete_file
permission: high_risk
requires_confirmation: true
side_effect: irreversible
```

模型在调用前就能读到这些元数据，减少“不知道这是危险操作”的情况。

### 2. 确认策略要区分“计划确认”和“步骤确认”

不要每一步都问。更好的方式是在执行前让 Agent 生成一个**执行计划**，把计划里的高风险步骤标出来，用户只对高风险步骤进行批准，低风险步骤自动放行。

比如任务“清理旧日志并打包上传”，Agent 会先列出：

- [自动] 扫描日志目录
- [自动] 计算文件大小
- [需确认] 删除 30 天前的日志
- [需确认] 上传到外部存储

用户只关注两个确认点，而不是六个步骤。

### 3. 加入 dry-run 和回滚能力

对于高风险工具，先支持 `--dry-run` 或 `preview` 参数。Agent 在真正执行前可以输出将要改动的文件列表、命令内容、影响范围。用户确认后，再执行真实操作。如果工具本身不支持回滚，至少要把操作前后的状态快照保存下来，比如被删除文件的路径和校验和，便于人工恢复。

### 4. 审计日志不只是为了排查，也为了调整边界

每次自动执行或确认通过后，记录：工具名、参数摘要、结果、权限等级、为什么自动/确认。跑两周后就能看到哪些操作被频繁确认，但实际风险很低，可以降级；哪些操作被自动执行但出了错，需要升级。

## 踩坑点

**把确认当作安全网**：如果用户习惯性点“允许”，确认就失效了。需要在确认弹窗里显示具体影响，而不是只显示“是否继续？”要展示将被删除的文件数量、目标目录、不可逆提示。并且避免在批量操作里连续弹几十次确认，而是合并成一个确认清单。

**权限描述模糊**：工具描述写“删除文件”，模型可能删到不该删的路径。必须在描述里限制范围，比如“仅允许删除 /tmp/agent/ 下的文件，禁止递归删除其他目录”。范围限制比模型判断可靠得多。

**所有写操作都加确认**：这会让 Agent 不可用，也会让用户疲劳。正确做法是分级，低风险可逆的放心交给 Agent。

**用人类的高权限凭证跑 Agent**：Agent 拿着管理员 token 或全部目录权限，即使有确认机制，也容易出大事。给 Agent 单独的、最小权限的凭证，限制在它需要的目录、项目、数据库范围内。即使误操作，爆炸半径也有限。

## 可复用建议

1. **先画一张权限分级表**：列出常用工具、副作用、可逆性、确认策略。让团队对齐，不要每个人凭感觉。
2. **在工具元数据里声明权限等级**，而不是写在系统提示词里。模型调用工具时能看到，系统提示词容易被忽略。
3. **高风险操作合并确认**：把同一批危险步骤打包成一个确认卡片，显示影响范围。
4. **保留干运行入口**：任何高风险工具都尽量提供预览模式。
5. **定期复盘自动执行日志**：调整自动/确认边界，让系统逐步收敛到“低风险自主，高风险停下”。

## 总结

Agent 的权限边界不是一个开关，而是一组连续的控制策略。目标不是让 Agent 什么都不问，也不是什么都自己干，而是让它在低风险、可逆、低成本的区间自主行动，在高风险、不可逆、高成本的区间停下来问人类。结合工具分级、计划确认、dry-run、最小权限凭证和审计日志，才能在自动化和安全之间找到可维护的平衡点。
