当大多数人还在把 Perplexity 和 ChatGPT Search、Gemini 放在同一个坐标系里比较引用率、时效性和答案长度时，Perplexity 已经把注下到了另一个层面：搜索只是入口，真正要做的是让 AI 替你完成从“找到答案”到“完成任务”的闭环。最近这波热议背后，不是又一款问答工具，而是一次产品重心的转移。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-08-31/447bf63f56ce0161.png)

## 一、AI 搜索的交付物，仍然是一个半成品

传统搜索给链接，AI 搜索给答案。但用户真正想要的往往不是答案，而是结果：订好的酒店、填完的报销单、比完价并下单的商品、整理好的周报。Perplexity 早期用 RAG 加引用来源建立信任，产品形态却仍然停留在“生成答案”的最后一公里之前。

- 断点在于：它能告诉你“去官网填表，提交后等邮件”，但没有替你打开页面、识别字段、完成提交。
- 对信息型问题，AI 搜索已经很够用；对交易型、执行型问题，答案离结果还隔着好几次点击。
- 换句话说，AI 搜索只是把“找到信息”这件事做得更好，但用户的时间成本并没有因此归零。

## 二、Perplexity 正在做的“下一件事”：从 Answer 到 Act

从公开动作看，Perplexity 已经不再只做一个带引用的问答框。它把产品拆成了三个相互咬合的层：

1. **浏览器层**：推出 Comet 浏览器，把搜索、页面操作、任务自动化放进同一个执行环境。用户输入意图时，系统同时准备可执行的动作，而不只是生成回答。
2. **助手层**：Android 上的 Perplexity Assistant 尝试跨应用操作，例如从邮件中提取时间、地点，再自动在日历里创建事件。
3. **商业层**：Shopping with Perplexity 从“比价摘要”走向“一键下单附近”，Deep Research 也从多轮搜索扩展到多步执行调研任务。

技术本质不再是“检索增强生成”的单次调用，而是一个 agentic loop：

- 意图识别 → 拆解子任务 → 调用搜索、网页操作或支付接口 → 校验结果 → 请求用户确认 → 完成任务
- 与普通聊天机器人的关键区别在于，它需要一个可以操作 DOM、点击按钮、填写表单、跨页面维护状态的执行环境。
- Comet 之所以值得关注，不是因为它叫“浏览器”，而是因为它把 agent 安放在地址栏后面：搜索完成的那一刻，执行流程已经可以启动。

## 三、为什么是现在：三个条件同时成熟

从“能回答”到“能执行”，不是简单的功能叠加，而是依赖三个基础设施在同一时间点变得可用：

1. **模型层**：function calling 和长上下文让模型可以规划多步操作、调用外部工具而不丢失任务状态。
2. **环境层**：Chromium CDP、Playwright 等浏览器自动化协议，让“AI 操作网页”从 demo 变成可以工程化的能力。
3. **商业层**：纯搜索广告增长见顶，任务抽佣、交易闭环和订阅制的长期价值更高，也让用户更容易为“结果”付费。

但条件成熟不等于产品已经可靠。行业里最稀缺的不是演示视频，而是稳定完成率和错误恢复能力。一个能流畅操作网页的 agent，在遇到验证码、登录墙或页面改版时，才是真正接受考验的时刻。

## 四、核心难题不是“搜索不准”，而是“代理不可信”

当 AI 从“给参考”变成“替你执行”，风险模型也发生了变化。错一个答案，用户可能只是多查一次；误操作一次支付，却是真实世界的损失。

- **权限边界**：AI 替你提交订单、发邮件、修改日程，误操作的代价远高于看错一条引用。
- **可审计性**：每一步操作是否留痕、能否回滚、能否看到中间状态，决定了用户敢不敢把真实账户交给它。
- **对抗环境**：登录墙、验证码、反爬机制、网站改版，都会让 agent 失效；这不是模型能力提升就能自动解决，而需要产品设计上的降级策略。
- **责任归属**：AI 给出的答案，用户会自己判断；AI 替你执行的动作如果出错，责任算谁？目前多数产品选择“用户最终确认”来规避，但这也限制了自动化程度。

## 五、冷思考：别急着把搜索全部拨到 agent 模式

围绕 Perplexity 的讨论，容易陷入“下一代搜索已来”的兴奋。更务实的做法是把它当作一个早期信号：answer engine 之后，action engine 是明确方向，但离稳定交付还有距离。

给三条实用建议：

1. **区分任务类型**：信息查询用普通 AI 搜索即可；交易型、执行型任务才值得交给 agent。先在沙盒环境、小金额场景、非关键账户里试，再逐步放开。
2. **优先看“可回滚”和“二次确认”**：如果一个 agent 产品只展示流畅执行，却不提供操作历史、撤销入口和最终确认按钮，要谨慎让它接触真实账户。
3. **把 agent 当实习生而不是秘书**：它擅长草拟、初筛、多步点击，但关键节点仍然需要人来验收。真正的产品成熟标志不是“全自动”，而是“每一步都有清晰的接管点”。
