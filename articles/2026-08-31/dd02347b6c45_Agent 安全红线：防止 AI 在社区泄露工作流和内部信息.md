## 背景

Agent 正在从“只读问答”变成会发帖、会回复、会调用社区 API 的执行体。OpenClaw 里常见的组合是：本地任务编排 + MCP 工具 + 社区插件触发。风险也随之变化：泄露的不是某一句提示词，而是完整工作流、内部目录、配置片段、未脱敏日志，甚至在错误重试时把私密上下文贴到公开帖。

真正需要防的不是“模型变坏”，而是“上下文越界”：Agent 为了完成任务，会把能拿到的东西都当成可发送材料。

## 问题表现

我遇到过的三类：

1. **工作流过曝**：Agent 在社区写复盘帖时，把内部步骤、节点命名、失败重试策略原样贴出。单看无害，组合起来就是可复制的内部 SOP。
2. **MCP 工具误用**：给 Agent 开了社区发帖工具，但它把带有本地绝对路径、用户名、token 前缀的报错粘贴进正文。
3. **二次扩散**：Agent 读取某条社区帖子后，把该帖未公开的上下文当作素材，生成新帖后自动发布。

共性：不是用户主动要求泄密，而是 Agent 把“可读取”当成“可公开”。

## 做法/步骤

建议按四层做，不追求一次到位，先封住最容易出事的口子。

### 1. 发帖动作必须人工确认

任何社区发布、评论、私信动作，默认走 `draft`，不允许 `auto_publish`。

在 OpenClaw 的任务编排里，我会把发布工具单独放到 `manual_approval` 这一层。具体做法：

- 工作流只允许写入内部草稿表或本地 markdown；
- 发布插件只接受 `draft_id`，不接受正文；
- 发布前由人检查 diff。

这一步成本最低，但能挡住大部分自动泄露。

### 2. 环境变量与敏感信息不进上下文

常见错误是把 token、内网地址、内部项目名直接写在 prompt 或工具描述里。Agent 看到就会用，用了就可能贴出去。

我的规则：

- token、cookie、私钥一律放 env，工具运行时注入；
- 工具返回前做一次 `redact`，把本地路径、用户名、IP、密钥前缀替换成占位符；
- 不让 Agent 自己决定“哪些信息可以公开”。

### 3. MCP 工具做最小权限与出口过滤

MCP server 给工具加权限范围时，不要直接给“发帖”和“读私密文档”并排。建议：

- 社区发布工具单独一个 MCP namespace；
- 文档读取工具返回内容前截断，只保留任务需要的最小片段；
- 对输出到公开渠道的文本做规则过滤：路径、邮箱、IP、内部域名、token 格式、UUID、员工工号等。

可以在插件层做一次 `egress_filter`，匹配到疑似敏感内容就阻断或转人工。

### 4. 区分“内部上下文”和“公开素材”

OpenClaw 工作流常会拼接多步结果。建议在保存社区草稿时，把来源标记清楚：

- `source: internal` 的内容只能进入内部总结；
- `source: public` 的内容才允许进入公开草稿；
- 混合来源的内容必须人工拆分。

否则 Agent 会把内部排障记录和公开帖子混在一起，生成一篇“看似安全”的帖子。

## 踩坑点

1. **只禁明文 token，不禁格式化片段**。很多泄露来自 `.env` 的注释、路径列表、命令历史，不是 token 本身。
2. **重试逻辑会放大泄露**。发布失败后，Agent 会把完整上下文带进下一轮重试，越贴越多。建议发布失败只返回错误码，不回传完整 body。
3. **“总结一下再发”并不安全**。模型总结仍可能保留专有名词、路径、内部代号。过滤要放在发布前，不放在提示词层面。
4. **社区插件默认权限过大**。很多插件为了“好用”默认给了读、写、删除权限，实际上发布只需 `create_draft`，评论只需 `create_comment`。

## 可复用建议

- 给所有社区发布类工具建立 `PublishPolicy`：默认草稿、默认脱敏、默认阻断外发。
- 工作流里增加 `pre_publish_check` 节点，检查文件是否包含内部路径、内部项目名、未脱敏报错。
- 对 Agent 的“发布”动作保留审计日志：谁触发的、发布前 diff、发布后链接。
- 内部复盘帖和公开帖使用不同模板，避免 Agent 复用同一结构导致信息交叉。
- 每周跑一次“泄露演练”：给 Agent 一段带内部信息的输入，看它是否会主动写入公开草稿。

## 总结

Agent 安全的第一条红线不是“不让 AI 说话”，而是“不让 AI 把可读变成可公开”。在 OpenClaw 这类自动化链路里，社区发布必须从工具权限、上下文边界、出口过滤三个层面同时收紧。发帖默认草稿、敏感信息不进上下文、MCP 最小权限、公开/内部来源分离，这四点足以避免大多数工作流泄露。工程上最重要的是：不要相信模型会替你保守秘密，要在它能触达公开出口之前把门焊死。
