## 背景

在 OpenClaw/Agent 场景里，很多团队想用 agent 自动写日报。常见做法是把 git log、任务系统导出、监控报警甚至聊天记录一股脑丢给模型。结果经常是：格式每天不一样、漏掉重要阻塞、出现日志里没有的任务。

原因通常不是模型能力不够，而是流水线缺少“采集—清洗—校验”的工程约束。

## 问题

原始日志有三个典型坑：

1. 多源、多时区、非结构化，直接读会互相污染。
2. 上下文窗口有限，原始日志噪音大，关键信息被稀释。
3. 模型输出不稳定，格式漂移，后续难以沉淀。

所以后来我把日报生成拆成固定流水线，而不是只靠一个 prompt。

## 做法/步骤

### 1. 先定义日报字段，不要超过 7 个

例如：今日目标、完成项、阻塞、风险、明日计划、关键指标、需要他人关注。字段先定下来，后面模板和校验都围绕它。

### 2. 采集并统一为 JSONL 事件

用 OpenClaw skill/plugin 或 MCP 工具把不同来源统一成事件流：

```json
{"ts":"2025-01-20T08:12:00+08:00","source":"git","actor":"alice","action":"commit","summary":"fix: retry queue","repo":"core"}
```

命令侧可以用 `git log --since=... --pretty=format:...`，任务系统拉取 API，监控告警拉取触发记录。都写入 `.cache/daily/raw.jsonl`。不要直接把这些原文交给模型。

### 3. 清洗与分组

脚本按 `source/actor/date` 聚合，过滤 bot、merge、revert、重复事件；时间统一到本地时区；同一 ticket id 或 commit message 去重。输出 `normalized.jsonl`。

### 4. 让 Agent 先列事实，再生成草稿

不要直接让它“写日报”。可以分两步：

- 第一步：基于 normalized 事件，列出“完成/未完成/阻塞/风险”的事实清单。
- 第二步：按固定字段生成草稿。

这样可以明显减少幻觉。

### 5. 固定模板与 schema 校验

渲染前先过一层校验，例如 JSON schema：

```json
{
  "required": ["date", "done", "blockers", "tomorrow"],
  "properties": {
    "done": {"type": "array", "items": {"type": "string"}},
    "blockers": {"type": "array", "items": {"type": "string"}}
  }
}
```

校验通过后再渲染 Markdown，避免格式漂移。

### 6. 发布并保留中间产物

最终报告写入本地 markdown，可选发到 IM/邮件。建议保留 `raw.jsonl -> normalized.jsonl -> draft.md -> report.md` 四层文件，方便回放和调试。

## 踩坑点

- **时区**：git commit 通常是 UTC，展示时容易错一天。统一 ISO 带 offset。
- **上下文过大**：不要一次读所有原始日志。先按当日 top N 聚合，保留摘要。
- **模型发明任务**：一定要声明“只依据事件生成，不允许补充未出现内容”。没有阻塞就写“无”。
- **模板漂移**：用 schema 校验后再渲染，不要直接输出最终邮件正文。
- **多源去重**：同一任务可能同时出现在 git 和任务系统，用 ticket id/关键词去重。
- **权限与 token**：MCP 工具 token 过期会导致采集静默失败。建议缓存到本地，由用户刷新，不要硬编码在配置里。

## 可复用建议

- 固定流水线：collect -> normalize -> draft -> validate -> render -> publish。
- 把日报当作“决策摘要”，不是“日志压缩”。只保留需要他人关注的信息。
- 封装成 OpenClaw skill/plugin，输入 `date/repo/channel`，输出报告路径和摘要。
- 加人工确认：先写草稿到本地，用户编辑后发送。全自动直接发容易翻车。
- 每次失败保留中间产物，优先排查输入质量而不是 prompt。

## 总结

自动日报的难点通常不在大模型，而在于原始日志的规范化和输出约束。先统一事件流，再用 agent 做结构化摘要，最后用模板和校验卡住格式，这条流水线就能稳定复用。
