### 背景：Agent 不是缺调用能力，而是缺边界

在 OpenClaw 上做自动化，迟早要把 Agent 接到真实外部服务：工单、CRM、审批、支付回调。很多团队一开始都会选择捷径：把 API 地址、token、请求体塞进 prompt，让 Agent“自己看着调”。Demo 阶段没问题，一旦进测试或生产，问题就集中爆发。

外部 API 不是为 LLM 设计的。超时、非结构化错误、限流、重复副作用、字段爆炸，都会直接传导到 Agent。模型看到一段 HTML 错误页，会开始编造“可能是权限问题”；看到 429 不会退避，只会立刻重试；看到创建接口没有幂等键，重复调用就会产生脏数据。真正要解决的不是模型能力，而是握手层的工程控制。

### 问题：把外部服务直接暴露给 Agent 的五类风险

1. **鉴权与配置泄漏**：token 写进 prompt 或日志，DEV/PROD 混用。
2. **错误不可读**：外部返回非 JSON 错误页，模型开始编原因。
3. **重试放大副作用**：对非幂等 POST 自动重试，产生重复订单或工单。
4. **超时设计不合理**：Agent 等待过久卡死，连环调用时延长不可控。
5. **返回体过大**：全量字段进入上下文，挤占 token，模型丢失关键信息。

这些问题不在模型层，而在于没有给外部服务做一个适配边界。

### 做法：把外部服务封装成 OpenClaw 工具/插件

在 OpenClaw 中，更稳的路径不是让 Agent 直接发 HTTP，而是把每个外部服务封装成一个 tool 或 MCP 适配器。Agent 只调用标准化的工具描述和参数，真正的 HTTP 握手由适配层完成。

步骤大致如下：

1. **定义边界接口**：明确工具入参、出参 schema，只暴露模型需要字段。返回结构要尽量小，大文本可转成摘要或对象存储链接。
2. **实现 client 层**：集中管理 base URL、timeout、retry、auth。不要在 system prompt 里写死地址和 token。
3. **鉴权下沉**：token 从环境变量或密钥管理注入，支持短期凭证刷新。日志和错误信息中脱敏 Authorization。
4. **错误归一化**：把外部响应映射成三类：可重试错误（429、5xx、网络抖动）、不可重试错误（4xx 参数/权限）、业务错误（带业务码）。给模型的 tool_result 只保留必要错误描述，并标记 is_error。
5. **超时与重试策略**：连接超时和总超时分离。外部调用建议总超时 5–10 秒，长任务改异步回调或队列。自动重试只对幂等 GET/查询开放，指数退避加 jitter；对创建/更新类请求，要么引入幂等键，要么禁止自动重试。
6. **分页与限流封装**：不要在工具描述里让模型自己翻页。把分页封装成迭代器或聚合参数，工具内部处理 rate limit 响应头并退避。
7. **可观测性**：每次 tool call 生成 trace_id/request_id 并贯穿日志，记录外部服务状态码、耗时、错误类型。日志要脱敏，不记请求头和敏感 body。
8. **契约测试**：用 stub 或录制回放搭建本地 mock，验证 adapter 在超时、429、非 JSON 错误等场景下的行为，而不是依赖真实 API 反复调试。

### 踩坑点

- **把超时设得太短或太长**：太短，正常查询也会失败；太长，Agent 容易等待、卡住。建议将外部调用视为“快速工具”，超过 8 秒就应考虑异步化，而不是让 Agent 同步等。
- **非 JSON 错误响应**：外部网关、CDN 或 WAF 经常会返回 HTML。解析前先检查 Content-Type，解析失败时返回截断后的原始片段，不要直接把 500 页丢给模型。
- **日志泄漏鉴权信息**：Authorization、Cookie、API key 被打进日志，排查时才发现泄漏。统一在 HTTP client 层做 redact，不要在业务代码里手动拼日志。
- **重试放大写操作**：某团队对创建工单接口做了 3 次自动重试，一次网络抖动产生 3 条重复工单。写操作必须显式幂等，或关闭自动重试。
- **错误信息被当成用户输入**：外部服务报错后，如果不标记 tool_error，模型可能把错误解释成用户回复，继续编造下一步。OpenClaw 工具结果中要明确区分工具失败和正常返回。
- **分页参数写死或乱传**：limit 太大导致外部超时，太小导致几十次调用。根据外部 API 的硬限制选择合理默认值，并设置 max_pages 防止无限翻页。

### 可复用建议

- **用 schema 校验响应，不要相信文档**：外部服务字段经常缺省、改名、类型漂移。对关键字段做校验，失败时进入降级逻辑。
- **只读先行，写操作加确认**：对接新服务先开放只读工具跑一段，再开放创建/更新/删除。写操作可在 OpenClaw 的审批或确认机制中加入人工确认，避免 Agent 误操作。
- **统一错误模型和 client 抽象**：把鉴权、重试、超时、脱敏封装在公共 HTTP client 或 OpenClaw 插件基类里，不要每个工具各写一套。
- **单独监控外部依赖**：对每个外部服务记录成功率、P95 延迟、限流次数，Agent 端出现异常时可快速定位是模型问题还是依赖问题。

### 总结

Agent 与外部 API 的握手，不是一个“填 URL 就能通”的步骤，而是要把外部系统的不确定性关进适配层。OpenClaw 的价值不在于多一种调用方式，而在于让工具调用变得可观测、可约束、可恢复。把鉴权、超时、重试、错误归一化都放在工具层解决，Agent 才能在上下文里做它擅长的事：判断意图、组合工具、处理业务，而不是对着 HTTP 错误页瞎猜。
