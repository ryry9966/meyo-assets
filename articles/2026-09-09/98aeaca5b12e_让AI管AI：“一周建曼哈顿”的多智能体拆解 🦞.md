热搜上那条“他让GPT-6管GPT-6，一周搭出曼哈顿”，配上航拍感十足的城市画面，评论区直接分裂：一半人喊“程序员可以下班了”，另一半人把图放大，说这楼是纸糊的。先别急着站队。这条新闻真正的看点不在"6"这个版本号（先不纠结它是官方命名还是营销叫法），而在架构思路——让一个 AI 当项目经理，指挥一群 AI 当施工队，也就是多智能体（multi-agent）系统。它怎么运转、水分在哪、什么时候真能用，下面一次拆完。

## 一、“AI管AI”，到底是怎么个管法

所谓“让 GPT-6 管 GPT-6”，行话叫 Planner–Executor 分层架构，用建筑业类比很好懂：

- **规划层（Planner）**：顶层大模型把“建一片曼哈顿街区”这种模糊目标拆成任务树——地块划分 → 路网生成 → 单体建筑 → 材质贴图 → 灯光合成。它自己不动手，只出“工单”。
- **执行层（Executor）**：一群小一号的模型各领一个叶子节点，比如“生成第 137 街区的一栋塔楼”，干完把结果回传。
- **通信方式**：不是两个 AI 在聊天，而是靠结构化输出（JSON、场景描述语言）在 agent 之间传递，像微服务之间调 API。
- **工具调用**：执行 agent 通常还要使唤传统工具——用脚本批量生成楼体网格、用程序化规则铺路网。LLM 负责出参数，确定性算法负责出几何，分工明确。

这思路并不新。2023 年 AutoGPT、BabyAGI 就火过一轮；后来 MetaGPT 把软件公司的产品经理、架构师、程序员角色映射到 agent 上；如今 LangGraph、CrewAI 和各家 Agents SDK 已经把编排做成了标准件。“建曼哈顿”本质是同一棵树上的新果子，只是模型更强、推理更便宜。

一句话总结：不是冒出了一个会造城的超级大脑，而是一个会派活的工头，带着一群手速飞快但记性很差的工人。

## 二、“一周建曼哈顿”的真实含金量

先承认：这类任务确实适合 AI。曼哈顿是出了名的规整网格街区，规则性极强，天然适合“模板 + 变量”批量生成。但含金量要掰开看：

- **量大 ≠ 质量高**。远景航拍可能唬人，放大看常是重复纹理、悬空楼板、错乱日照。人类团队做《GTA》级别的城市要几百人干好几年，因为每栋楼都要经得起玩家走到跟前看。
- **成本账**。生成数千栋建筑往往意味着数十万次模型调用，按单次几千 token 算，光推理费用就可能上万美金，还没算失败重试。所谓“一周”是机器挂机时间，不是人效奇迹。
- **精度分层**。这类生成内容一般只有远、中两级细节（LoD），近景经不起推敲。它更像一周 3D 打印出一座假山——体量惊人，但离“能住人”还差验收、加固、装修三座大山。

所以合理的结论是：作为能力演示，接近满分；作为生产力对标，先打对折，再打个八折。



## 三、为什么“AI管AI”这么难：错误会复利

多智能体最大的坑不在“能不能干活”，而在误差管理：

1. **误差沿层级放大**。顶层规划偏一格，中层执行偏一片，底层施工偏一城。人类工程靠层层验收切断误差传播，而 agent 流水线里，下游默认上游是对的，没人喊停。
2. **验证是最贵的一环**。LLM 写一万行代码很快，判断“这代码对不对”往往比写更难。没有自动化 evals 的多智能体系统，等于没有质检的工厂。
3. **上下文丢失**。工头记不住每栋楼的细节，工人也看不见全局。上下文窗口再大也装不下一座城，只能靠外部存储加检索，而每次检索都可能失真。
4. **“最后 10%”问题**。demo 从 0 到 90 分靠模型蛮力，从 90 到 99 分靠工程化、数据和验收流程，后一段的耗时通常是前一段的十倍。“一周搭出来”和“能上线”之间，隔着一条哈德逊河。

## 四、什么时候这套思路真的能打

判断一个任务适不适合丢给“AI 军团”，看三条硬标准：

- ✅ **可分解**：任务能切成弱耦合的块——批量生成游戏素材、批量清洗数据、搭代码脚手架。
- ✅ **可自动验证**：结果能跑测试、能渲染比对、能过 lint。有客观验收标准，AI 才能自己迭代。
- ✅ **失败便宜**：单块错了可以低成本重做，而不是牵一发动全身。

反过来，两类任务先别交出去：一是强事实一致性的活（法律、医疗、财务报表，错一个数字全盘报废）；二是需要长期记忆和风格一致性的活（写一部长篇，agent 一转身就忘了第三章埋的伏笔）。

人的角色也在迁移：从“操作员”变成“规则制定者 + 验收员”。你写的不再是每一行指令，而是验收标准、约束条件和兜底策略。

## 五、冷思考：给想上车的人三条建议

1. **看到“AI 一周干完 X”，先问三个问题**：产出是怎么验收的？总成本多少？换个任务还成立吗？三问之下，大半神话会自动祛魅。
2. **想玩多智能体，别堆 agent 数量**。从两三个节点的小流水线起步，把预算花在自动验证上，而不是多雇几个“工人”——质检环节的投入产出比，远高于扩编施工队。
3. **把 AI 团队当初级工程师用**：不知疲倦、手速飞快、需要明确工单。你的价值在于把模糊需求翻译成可执行规格，并在出口把关。想当甩手掌柜的，最后一般都混成了返工柜。

“曼哈顿”也许一周就能搭出来，但让人放心使用的“曼哈顿”，拼的从来不是手速，是验收。
