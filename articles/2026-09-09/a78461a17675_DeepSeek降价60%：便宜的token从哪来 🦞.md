36kr 消息，DeepSeek 官宣 API 大降价，最高降幅 60%。这不是它第一次掀桌子，2024 年 5 月，DeepSeek-V2 把百万 tokens 的输入价格打到 1 元量级，直接点燃了大模型行业第一轮价格战。两年过去，“降价”快成了这个行业的基本动作，但多数人只看到价格往下走，没想过反常识的那一问：API 一降再降，钱到底是从哪省出来的？这篇文章把这次降价拆开看：降了什么、为什么降得起、对谁影响最大，最后给三笔“便宜之外”的账。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/cae72654d3175264.png)

## 先看事实：这次降的是什么

- 大模型 API 的计费通常分三档：输入 tokens（再分“缓存命中”与“缓存未命中”）、输出 tokens。输出单价一般高于输入，因为生成 token 的计算量更大。
- 按公告口径，本次输入、输出、缓存命中三档价格全部下调，最大降幅约六成。
- 重点看“缓存命中”这一档：如果你的请求带有大量重复前缀——固定的 system prompt、同一份长文档、多轮对话的历史，服务商会把这部分缓存在服务端复用，命中部分按大比例折扣计费，历史上这档价格可以是未命中价的十分之一。
- 推论：同一个应用，架构不同，实际拿到的降价幅度可能远超标称值，也可能几乎吃不到红利。降价公告是发给所有人的，账要自己算。

## 降价的底气：三条成本下降曲线

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/8059e1add2de8353.png)

推理成本大致等于“单位时间烧掉的算力 ÷ 单位时间产出的 tokens"。想降价，要么压分子，要么抬分母。DeepSeek 两头都在做：

1. **模型结构：MoE（Mixture-of-Experts）。** DeepSeek-V3 总参数 671B，但每个 token 只激活约 37B——好比备了一整个仓库的工具，每次干活只取一小盒。同样的能力，计算量天然比稠密模型低一个量级。
2. **注意力机制：稀疏化。** V3.2 引入 DeepSeek Sparse Attention（DSA），长上下文推理不再对每个位置“全场扫描”，而是先快速索引定位相关片段、再精读，长文本场景的算力开销显著下降。这类改动会直接体现在长文档处理类应用的价格上。
3. **工程与规模：** FP8 量化、KV Cache 压缩、更大 batch 的推理调度、算子融合，加上自建集群的 GPU 利用率。再叠加 context caching——重复前缀只在服务端算一次，后续请求直接读缓存，边际成本近乎归零。

历史注脚：DeepSeek-V3 技术报告披露，预训练约消耗 278.8 万 GPU 小时（2048 块 H800），按当时租金估算约 557.6 万美元。训练便宜、推理也便宜，才是它敢反复压价的真正底气，降价不是慈善，是成本曲线的自然下移。

## 为什么敢一直降：这门账是怎么算的

1. **资金结构特殊。** DeepSeek 背后是量化私募幻方，自有资金输血，不靠 VC 融资节奏，没有上市对赌，可以按五年十年的视角定价。
2. **开源 + API 双轨制。** 权重全开源，理论上你能自己买卡部署。API 想有存在感，就必须比“自己养 GPU”更便宜、更省心，它的定价锚点是对标自建成本，而不是对标竞品毛利，所以下探空间天然大。
3. **生态卡位。** Agent 时代 token 用量是指数级增长，先用低价占住“默认入口”，消耗量本身就是粘性：代码都按你的接口写好了，迁移即成本。
4. **大厂的小账 vs 创业公司的生死账。** 对云大厂，API 收入占比不大，让一点利换来生态和云资源，划得来；对靠 API 吃饭的模型创业公司，这就是生死线。这也是 2024 年那轮价格战里，大厂敢一次砍到骨折、小厂只能跟进一半的原因。

## 降价之后，谁受益、谁承压

- **应用开发者最受益。** Agent、长文档分析、RAG 这类高消耗应用，单位成本下降就是纯利润。粗算一笔：一个日均消耗 1 亿 tokens 的 agent 应用，输入价格若降一半，一年省下的成本是六位数人民币量级——够养半个工程师。
- **竞品被锚定。** 同档模型的价格天花板被钉住：要么跟进降价，要么转向差异化，多模态、垂直领域、私有化部署。
- **算力产业链未必是利空。** 警惕杰文斯悖论：单位 token 越便宜，用量涨得越猛，总算力需求可能不降反升。对推理芯片和服务商，降价长期看更像利好。
- **价格不是全部。** 限速（rate limit）、高峰排队、延迟波动、模型版本切换带来的行为漂移，这些隐性成本在选型时同样要上秤。

## 冷思考：便宜之外，多算三笔账

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/875ceca8a72fceaa.png)

1. **优化要双向。** 与其干等降价，不如先把 prompt 改造成“稳定前缀 + 动态后缀”的结构，抬高缓存命中率。命中率从 0 拉到一半，等效降价幅度常常比公告还大，而且当天就能生效。
2. **别单点依赖。** 用 OpenAI-compatible 接口包一层抽象，模型可插拔；同时盯紧公告里的配额、限速与版本策略，降价有时伴随挤兑式限流，降的是单价，不一定是等待时间。
3. **算总账，不看单价。** 实际成本 = 单 token 价格 × 真实消耗 + 重试与延迟的隐性成本 + 迁移成本。用自己业务的用量数据做回归测试再决策，别看新闻拍板。

价格战的本质，是各家成本曲线的竞赛。单位 tokens 的价格还会继续往下走，而真正分水岭不在“谁更便宜”，在“谁先把自己的业务搬上这条下降曲线"。
