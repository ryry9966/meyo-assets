同一场预算评审会上，经常出现两个画风完全不同的 AI 方案：左手边是销售递来的年度合同，25 万打包专属额度、SLA 和全家桶；右手边是工程师的申请单，不签任何长约，让团队按月订阅，月底一合计，每月 1500 美元。36kr 把这个现象概括为“大厂 AI 预算彻底分裂”。这事表面看是采购口味差异，往深挖一层，是 AI 这个物种的成本结构跟传统软件压根不是一回事。这篇拆开讲：钱花在哪了，为什么分裂，普通团队该怎么选。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/85e11926fdd09e2c.png)

## 先看表面：三种花钱姿势，风险分配完全不同

- **按人订阅（per-seat）**：ChatGPT Plus 20 美元/月、Claude Max 200 美元/月、GitHub Copilot 10-39 美元/月。小额、高频、随开随停，财务上按月报销就完事。
- **年度企业合同（enterprise agreement）**：按年谈价，通常打包 SSO、数据合规、专属算力额度和技术支持，量级从十几万到上百万，25 万/年是这种模式的一个典型刻度。
- **API 按量计费**：按 token 付费，用多少算多少，适合接进自家产品或跑批量任务。

三者的本质区别不是折扣，而是**风险的归属**：订阅制把“重度使用”的风险压给厂商，按量计费把“账单失控”的风险压给用户，年度合同则用承诺换折扣，把风险摊给双方。

有意思的是，两条路线还会互相渗透：一个 700 人团队全员上 Microsoft 365 Copilot（30 美元/人/月），一年账单正好是 25 万美元这个量级，订阅堆到规模，也会长成年报里的大单。

## 分裂的根源：AI 的边际成本不是零

传统 SaaS 的账很好算：一套代码复制一万份，边际成本趋近于零，所以“包月无限用”成立。大模型不适用这条公式：

1. 每一次推理都烧真实 GPU 算力，token 是有物理成本的：显卡折旧、电力、机房、带宽，一样都免不了。
2. 用户用量差异极大。同一个 200 美元档套餐，轻度用户一个月可能只消耗几美元算力；重度开发者跑 agent 长任务，烧掉的推理成本能到四位数美元。Sam Altman 就公开承认过，ChatGPT Pro 200 美元/月的订阅是亏钱的。
3. 平价套餐天然吸引重度用户（经典的逆向选择），厂商只能加限速、设用量上限、再拆更高档位。2024-2025 年各家疯狂堆新 tier（Pro / Max / Team / Enterprise），本质上都是在重新切割用量分布曲线。

所以“预算分裂”的因果链是：厂商按成本结构切价位 → 企业按自己的用量画像对号入座 → 预算自然分成两类。

## 推理经济学：一笔 token 的账

- 一张 H100 的市场租金约 2-3 美元/小时起步，顶配模型单卡每秒吐几十个 token；再叠加长上下文（KV cache 越长推理越贵），高质量 token 的单位成本真实存在。
- 好消息是单价降得飞快：OpenAI 的说法是同等能力模型的价格一年降约 10 倍，DeepSeek 和开源模型也把 API 报价打了下来。
- 坏消息是总账单在反向上涨：从“一问一答”走向 agent，一次任务几十上百轮调用、读长文档、试错重试，单任务 token 消耗比聊天高一两个数量级。**单价在降，总账单在涨**，这就是很多团队“模型明明越来越便宜，账单却越来越贵”的原因。
- 于是预算量级也分层了：给团队买“聊天工具”，月付几十美元封顶；把 AI 当“数字劳动力”编进生产流程，就得按年、按量规划，资金量级直接差出几个零。一句话总结：单价跳水，用量起飞，账单原地升天。

## 历史总是押韵：云计费早就演示过一遍

- AWS 把算力拆成 Reserved / On-Demand / Spot 三档：愿承诺就锁折扣，要灵活就付溢价，能容忍中断就捡最低价，和今天的年度合同 / 订阅 / 按量如出一辙。
- 电信行业的“无限流量”套餐也走过同一条路：先无限、后限速、再分层。
- 可以做个预判：AI 定价不会“分裂后收敛成一种”，多档位会长期共存，因为用户用量的长尾永远存在。

## 对企业的启示：不是“哪个便宜”，是“你是什么用户”

- 轻度、广谱使用（写邮件、改文档、搜资料）→ per-seat 订阅最划算，别碰年度大单。
- 重度、确定性生产负载（代码生成、批量内容、agent 流水线）→ 按量或年度合同反而省钱，订阅的 rate limit 会先把你卡死。
- 25 万/年 vs 1500 美元/月，差的不是价格，是**对自己用量画像的认知精度**。

## 三条实用建议 / 冷思考

1. **先画用量分布，再谈采购**：用月度订阅或 API 试点 2-3 个月，记录每人每月 token 消耗与调用次数，找出 P95 重度用户。分布平缓选订阅，长尾陡峭谈按量或年度，用数据砍价比用关系砍价可靠。
2. **把 AI 预算当电费，别当软件费**：软件费按人头恒定，电费随业务量波动。预算模型留 30% 以上弹性，配好用量监控和账单告警，别等月底的“惊喜”。
3. **冷思考**：单价还会继续跌，别用今天的单价锁定明年的用量预期；真正的复利不在省下的订阅费里，而在团队把 AI 嵌进工作流的速度里。价格战年年有，工作流的积累才是你自己的。
