# 背景

用 Agent（OpenClaw 这类常驻助手）时间长了，会发现一个尴尬的事实：它每天陪你写代码、跑任务，却不知道你在哪个时区、主力语言是什么、喜欢什么风格的回复。结果是每开一个新会话都要自我介绍一遍："我用 Arch，Python 3.12，别再给我贴 Ubuntu 的命令了……"

模型的自动记忆能解决一部分问题，但它是模糊的、不可控的。我的做法更朴素：手写一份 `USER.md` 放在 workspace 里，Agent 每次启动读取。它是全局的、版本可控的、随时能 diff 的用户说明书。

# 问题

没有 USER.md 时，常见的三种损耗：

- **重复输入**：环境、偏好、约束反复打字；
- **输出漂移**：同一个问题，今天给 Bash，明天给 PowerShell；
- **风格不稳**：有人要直接给代码，有人要先讲原理，Agent 每次都在猜。

# 做法

**1. 建文件，控制在 50 行以内。** 放在 workspace 根目录，OpenClaw 会随 workspace 记忆一起加载。

**2. 分区写，只写“稳定事实”：**

```markdown
# 用户画像（最后更新：2025-06）
## 环境
- 时区 UTC+8，作息 9:00–24:00
- 本机 Arch Linux + macOS，服务器 Ubuntu 22.04
- 主力 Python / Go，编辑器 Neovim
## 偏好
- 中文回复，代码注释用英文
- 先给结论和代码，解释放后面
- 备选方案最多两个，不要罗列十种
## 禁止
- 不要主动 sudo 覆盖系统文件
- 不要在生产仓库直接 commit
```

**3. 分层管理**：个人稳定事实放 `USER.md`；单仓库的构建/测试约定放项目级 `AGENTS.md`；人设放 `SOUL.md`。冲突时项目级覆盖全局，要显式写明。

**4. 迭代**：让 Agent 在对话中主动问你缺什么；每月 diff 一次，删过时项。

# 踩坑点

- **写成简历**。300 行的 USER.md 每轮都吃 token，还会稀释真正关键的指令。宁可 30 行高密度，不要 300 行大杂烩。
- **写“目标”而不是“事实”**。“正在学 Rust”这类信息很快过期，Agent 却会拿它当现状推理。
- **塞敏感信息**。密钥、密码、真实住址不要放，这份文件大概率被 git 管理，甚至随 workspace 同步。
- **指令打架**。USER.md 写“永远中文”，项目 AGENTS.md 写“文档英文”，Agent 的取舍不可预测。
- **只增不删**。我见过 USER.md 里还留着两年前的服务器 IP。

# 可复用建议

- **冷启动技巧**：先正常聊一周，然后让 Agent “根据我们的对话总结一份 USER.md 初稿”，人工删改后落盘，比从零写快得多。
- **用列表和短句**，不要写长段落。结构化输入的遵守率明显更高。
- **文件头放“最后更新日期”**，强迫自己定期 review。
- **仓库保持私有**。如果 workspace 会被备份共享，宁可把 USER.md 留在本地不同步。

# 总结

USER.md 不是什么新架构，就是一份用户自己维护的纯文本。但“自己维护”这一点恰恰最重要：记忆不该完全交给模型的黑盒，稳定的个人事实用显式文件表达，可控、可审、可迁移。花半小时写第一版，之后每月五分钟修剪，你的 Agent 会从“什么都要重新解释的实习生”变成“真的认识你的同事”。
