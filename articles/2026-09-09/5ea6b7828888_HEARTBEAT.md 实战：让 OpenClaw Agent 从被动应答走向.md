## 背景

OpenClaw 的 Agent 默认是事件驱动的：你发消息，它响应；你不发，它休眠。但真正跑起来一段时间后会发现，很多有价值的事并不需要你先开口——错误日志出现了新条目、磁盘快满了、每天下班前该汇总一次未完成的 todo。

OpenClaw 为此提供了一个很轻的机制：**heartbeat（心跳）**。Agent 每隔固定时间被唤醒一次，读取工作区里的 `HEARTBEAT.md`，自行判断：要不要做事、要不要打扰你。沉默也是一种合法决策。

## 问题

我最初的用法很粗糙：把 HEARTBEAT.md 写成一个大杂烩待办清单，间隔设成 10 分钟。结果是两个极端——要么 Agent 频繁发消息轰炸我（"一切正常！"），要么什么都不说但 token 消耗照涨。

核心认知是：**心跳是"定时唤醒"，不是"定时必做事"**。唤醒后如何决策，完全取决于 HEARTBEAT.md 里怎么写。

## 做法

1. **定位文件**：在工作区根目录创建/编辑 `HEARTBEAT.md`（默认在 `~/.openclaw/workspace/` 下，以你的配置为准）。
2. **每条任务写三要素**：触发条件（什么才算"有事"）、动作（做什么、怎么通知）、沉默条件（什么情况下回复 `NO_REPLY` 保持安静）。
3. **调整间隔**：在 `openclaw.json` 的 heartbeat 配置里设置唤醒间隔（默认约 30 分钟，具体键名以所用版本文档为准）。
4. **先小后大**：调试期把间隔压到 2–5 分钟，看日志确认 Agent 每次醒来读到了什么、判断了什么，稳定后再调回正常值。

一个示例结构：

```markdown
# Heartbeat
- 每次醒来检查 ~/logs/error.log 末尾 50 行
  - 出现新的 ERROR 且与上次不同：摘要后发消息
  - 无异常：回复 NO_REPLY
- 20:00 后首次醒来：汇总今日未完成 todo 并发送
```

## 踩坑点

- **间隔太短纯烧钱**：即使无事可做，每次唤醒也是一次真实的模型调用。先用大间隔验证任务价值，再逐步缩短。
- **沉默条件不明确就会被轰炸**：必须显式写"无事发生时回复 NO_REPLY"，否则模型天然倾向于汇报"一切正常"。
- **上下文污染**：心跳若走主会话，巡检类的大段输出会挤占日常对话的上下文，必要时改用隔离会话配置。
- **别把紧急任务放心跳里**：最坏延迟等于一个间隔。精确时刻的活交给 cron，心跳只管"漂移检测"。
- **工具权限**：依赖 MCP 工具的任务，要确认无人值守时授权能自动通过，否则心跳醒来卡在权限弹窗上。

## 可复用建议

- HEARTBEAT.md 控制在 20 行以内——它每次唤醒都会被完整读一遍，是常驻成本。
- 分工原则：心跳管"有没有异常"，cron 管"几点几分做什么"。
- 让 Agent 把每次心跳的判断追加写入一份 log 文件，事后能回溯它为什么沉默、为什么报警。
- 每月清理一次：删掉不再关心的任务。心跳列表和代码一样会腐化。

## 总结

HEARTBEAT.md 的价值不在于"自动化"本身，而在于把"什么算值得打扰用户"写成明确规则。规则写得越清晰，Agent 的主动行为就越像一个靠谱的同事，而不是一台焦虑的报告机器。建议从监控一个日志文件开始，跑稳了再往上加。
