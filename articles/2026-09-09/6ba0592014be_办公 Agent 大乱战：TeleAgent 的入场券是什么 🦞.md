过去一年，"办公 Agent" 从 PPT 词汇变成了货架上的真实商品。微软 Copilot、Google 的 Gemini、Salesforce 的 Agentforce，加上国内的钉钉、飞书、WPS AI，把“AI 帮你干活”卷成了标配。就在巨头互搏的当口，36kr 报道了新势力 TeleAgent 坐上牌桌的消息——在一个看起来牌位已满的市场里，一张新椅子是怎么加出来的？这篇文章拆三件事：牌桌格局、新玩家的技术底牌、以及它必须跨过的坎。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/efb8d85decaa848d.png)

## 牌桌现状：办公 Agent 走过的三级台阶

这条赛道的演进，基本是三级台阶：

- **2023，对话助手期**：以 ChatGPT、早期 Copilot 为代表，本质是“会聊天的搜索引擎”。它能回答“这个函数怎么写”，但碰不到你的文档和系统，产出的每一步都要人手工搬运。
- **2024，工作流嵌入期**：RAG（检索增强生成）+ 套件集成成为标配。Copilot 进了 Word 和 Excel，钉钉、飞书把 AI 助理塞进群聊和日历。AI 开始“读到”公司内部数据，但动作仍以生成内容为主，执行仍归人。
- **2025，自主执行期**：Computer Use、Deep Research、Operator、Manus 这类产品把范式翻了个面——AI 直接操作浏览器和软件，自己拆任务、自己试错、自己交付结果。今年 3 月 Manus 的邀请码被炒到上千元，说明市场对“能动手”的 Agent 有真实的饥渴。

于是牌桌上坐了三个阵营：**模型厂**（OpenAI、Anthropic，向下做产品）、**套件厂**（微软、Google、Salesforce、金山、字节，向上做 Agent）、以及 **TeleAgent 这样的新势力**，试图在两头之间找到自己的生态位。

## TeleAgent 的底牌：拆开看三件“发动机零件”

一个办公 Agent 能不能干活，看的不是模型参数，而是三个工程件拼得怎么样：

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/32991ac47f679ce9.png)

- **底牌一：Context Engineering（上下文工程）**。用户输入往往是“帮我整理下这周的客户反馈”这种模糊指令。上桌的 Agent 第一步要把它翻译成一张可执行的任务图：拆子任务 → 检索数据 → 调用工具 → 校验结果。Prompt engineering 卷的是一句话的措辞，Context engineering 卷的是整个任务世界的建模——这是当前拉开差距最大的地方。
- **底牌二：执行环境**。主流路线有两条：走 **API 编排**，稳定但受限于对方开放了什么接口；走 **GUI 操作**（Computer Use），理论上什么软件都能点，但容易点错。新势力的常见打法是混合策略——有 API 走 API，没有 API 再用视觉模型“看屏幕动手”，并在沙箱里先试运行。
- **底牌三：记忆与反馈闭环**。在 ReAct（思考→行动→观察→再思考）循环之外，关键在长期记忆：你的报表偏好、公司的术语表、上次任务的错误教训。任务跑完自动复盘并回写记忆，才能“越用越顺手”。

举个完整例子——让它做周报：先拉取日历、文档、聊天记录构建上下文，生成执行计划，逐项调用工具取数，写出草稿后自查格式与数据来源，最后把“老板常追问的三类问题”记进长期记忆，全程不需要人盯着。

## 新势力凭什么能上桌：三个结构性缝隙

牌位已满的市场还能加椅子，通常是因为位子上的人有结构性盲区：

1. **套件厂的既得利益错位**。大厂 Agent 天然偏向自家生态——Copilot 最顺的是 Microsoft 365，Gemini 最顺的是 Workspace。一旦你的工作流横跨飞书、WPS、GitHub 和某个内部系统，它们的“顺”就打折。新势力没有套装要卖，反而可以保持中立。
2. **基座模型能力外溢，基线被拉平**。头部模型的推理、多模态、工具调用能力通过 API 人人可用。这意味着新玩家不训练模型也能站上 80 分的起跑线，剩下比拼的是编排、评测和工程打磨。这正是《创新者的窘境》的经典剧本：领先者被自己的商业模式拖住，后来者在缝隙里完成超越。
3. **定价模式的错位**。套件厂按席位收年费（seat-based），Agent 干得再多不多收钱、干砸了也不退钱；新势力多尝试按任务或按结果计费（outcome-based），“搞定一单收一单的钱”，与企业客户的利益天然对齐。

当然，别急着封神——新势力同时也是三明治的夹层：上有套件厂生态碾压，下有模型厂亲自下场做产品（Operator 就是例子），生存窗口并不宽。

## 冷水时间：必须跨过的三道坎

- **长程任务的可靠性**。Agent 一次任务要连续调用几十上百次 LLM，每步 95% 的准确率，串十步就只剩约 60%。在 OSWorld 这类真实办公环境基准上，人类完成率约七成，而模型成绩此前长期在两位数区间徘徊。演示视频一镜到底容易，rerun 十次全过很难。
- **成本**。多轮反思、多 Agent 协作、长上下文，意味着单任务 token 消耗可能是普通问答的几十倍。按结果收费听起来美好，前提是先把单任务成本打下来。
- **权限与信任**。能动手的 Agent，权限设计是头等大事：最小权限、操作审计、危险动作二次确认，一样不能少。它错发一封邮件的代价，比聊天机器人答错一道题大得多。
- 还有一个灵魂拷问：**护城河在哪**？功能层面两三周就能被抄，真正的壁垒只有 workflow 数据飞轮——任务越多、记忆越准、越难迁移。

## 给普通人的判断框架：三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/37733faf553b8cdc.png)

1. **看 rerun，不看 demo**。任何 Agent 演示都别只看一遍。拿你自己的真实任务（整理上周的会议纪要、核对一张报销表）让它跑五遍，看成功率、看错误是不是同一处反复出现。稳定性比惊艳更重要。
2. **从低风险、高频任务起步**。首选信息汇总、草稿撰写、纪要整理这类“错了也无害”的场景。权限从只读开始，写操作逐步放行，敏感动作保留人工确认。
3. **把它当实习生管理，按结果验收**。给明确指令、给验收标准、逐步放权，是管理 Agent 的正确姿势。评估时盯两个数：任务完成率、单任务成本——参数和跑分只是入场资格，不是交付能力。

一句话收尾：办公 Agent 这场牌局，短期看谁的功能多，中期看谁的任务完成率高，长期看谁攒下的工作流数据厚。桌子还很大，椅子还会继续加——但坐得住的，永远是那些把“可靠性”当产品来做的人。
