## 背景

现在主流的 Agent 框架基本都有一套"记忆文件"约定：项目级的 AGENTS.md、CLAUDE.md，工作区级的各种 MEMORY 目录。大多数人的做法是给项目写说明——架构、命令、注意事项，写得很认真。但很少有人给"自己"写一份。结果就是：Agent 每次会话都在重新认识你。

## 问题

几个高频场景，你可能都遇到过：

- 你在 macOS + zsh，它默认给你 Ubuntu + bash 的命令，装个依赖张口就是 `apt-get`；
- 你全栈用 pnpm，它给你 `npm install`；
- 你说过要简短回答，下个会话它又开始长篇大论；
- 最麻烦的是自动化场景：cron 定时任务、MCP 工具链里无人值守的调用，没有人在旁边纠正它的错误假设。

这些不是模型能力问题，是上下文缺失问题。项目有 AGENTS.md 兜底，"你"没有。

## 做法

核心动作很简单：建一个 USER.md，放到 Agent 每次启动都会读的位置（比如 `~/.openclaw/USER.md` 或 workspace 根目录），以 system prompt 注入或工作区文件形式加载。

内容建议控制在四个块：

1. **角色与环境**：操作系统、shell、包管理器、语言运行时版本、常用工作目录。这是踩坑最多的部分，值得写细。
2. **偏好**：回答语言、默认长度、代码风格（如"不用分号""注释只写为什么"）。要写成可判断的规则。
3. **边界**：明确不做的事，例如"删除文件前必须确认""新增依赖需要我批准"。
4. **当前关注**：最近两三周在做什么。这块最容易过期，也最影响回答的相关性。

两条维护规则：

- **重复纠正即入库**：同一件事纠正到第二遍，就写进 USER.md；
- **用 git 管**：放 dotfiles 仓库，多机同步，改动可追溯。

长度控制在 50–150 行。它是每次都进上下文的内容，写长了就是持续付费的噪音。

## 踩坑点

- **写成简历**。角色背景写三十行，有效信息三行。模型不缺恭维素材，缺事实。
- **信息过期比没有更糟**。换了技术栈没更新，Agent 会拿着旧信息自信输出。文件头加"最后更新"日期，换环境、换项目时强制 review。
- **敏感信息别放**。公司内部代号、密钥、住址这类内容，这个文件会被发往云端模型，要当它是公开的来写。
- **和项目级文件冲突**。USER.md 说 A、AGENTS.md 说 B 时行为不可预期。明确优先级——我选"项目覆盖全局"，因为项目约束更具体。
- **写愿望不写约束**。"回答简洁一点"没有执行价值，"默认 ≤ 10 行，除非我追问"才有。

## 可复用建议

- 只写事实和可判定规则，别写人设式 prompt（"你是资深专家"这类没有信息量）；
- 分层管理：USER.md（可移植的全局层）+ 机器本地覆盖 + 项目 AGENTS.md；
- 自动化场景把 USER.md 当"用户偏好 API"：它是无人值守任务里唯一能代表你的东西；
- 定期砍：每季度检查一遍，删掉一半行数后如果 Agent 行为没变差，就说明该删。

## 总结

USER.md 是我目前用过成本最低、杠杆最高的 Agent 配置之一：一个纯文本文件，把"你是谁"从每次口述变成持久配置。它不会让模型变聪明，但能显著减少摩擦——少重复、少踩环境坑、自动化任务更可信。如果你已经在给项目写 AGENTS.md，花二十分钟给自己也写一份，收益很直接。
