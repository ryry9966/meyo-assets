DeepSeek 又把价格打下来了——官方公告，API 定价最高降 60%。热搜评论区两极分化：有人喊“开发者福利”，有人担心“价格战又要开打”。但降价从来不是一个孤立事件，它更像一份公开的**成本体检报告**：只有推理成本真的降下来了，价格才敢降得这么理直气壮。这篇文章就把它拆开看——钱花在哪、为什么能降、谁在博弈、你该怎么用。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/39427f6c3571786a.png)

## 先看懂账单：一次 API 调用的钱花在哪

要看懂降价，先要看懂计价。大模型 API 的账单有几个关键变量：

- **token 是最小计费单位**：1 个 token 大致对应 0.5~1.5 个汉字（取决于各家 tokenizer 的切分效率）。你发的每条 prompt、模型回的每句话，都会被切成 token 计费。
- **输入和输出分开计价**：输出单价通常是输入的 2~4 倍。原因很硬核——生成的每个输出 token 都要对模型做一遍完整前向计算，而输入主要是一次性读完。
- **缓存命中与未命中**：主流 API 都支持 prefix caching。相同的系统提示词、相同的长文档前缀，第二次调用时不用重算，直接复用缓存里的 KV Cache。公开定价里，命中价与未命中价的差距从几分之一到一个数量级都有。
- **错峰折扣**：凌晨的 GPU 闲着也是闲着，深夜时段调用打折，逻辑和峰谷电价完全一样。

举个直观的例子：一个日均 10 万次调用的客服机器人，系统提示词固定 2000 token。缓存命中率每提升一档，仅输入费用就能差出数倍——所以老手看到“降价”新闻的第一反应，永远是先查自己的缓存命中率，而不是急着转发。

## 为什么敢降 60%：推理成本的三条下降曲线

价格能降，前提是成本曲线先降。大模型推理成本的下降，主要走三条路径：

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/aafacceb11747dd7.png)

1. **架构层：少算一点。** MoE（Mixture of Experts）让模型“按需激活”——总参数很大，但每个 token 只激活一小部分专家网络。以公开资料中的 DeepSeek-V3 为例，总参数 671B，每个 token 实际激活约 37B，计算量直接砍掉一个数量级。MLA（Multi-head Latent Attention）则压缩 KV Cache 的显存占用，同一张卡能塞进更多并发请求。
2. **工程层：算得更快更满。** 自研推理框架、算子融合、更激进的 batch 调度，把 GPU 利用率往上顶。成本与利用率成反比——利用率从 30% 提到 50%，等于给每个 token 变相打了六折。
3. **算法层：长文本不算两遍。** 稀疏注意力这类技术，让模型只对相关片段做精细计算，长上下文的注意力开销大幅下降。这轮降价中长文本场景降幅最大，不是巧合，是架构红利直接传导到了价格标签上。

一句话总结：**模型架构省下来的算力，最终都会变成价格表上的数字。**降价和发版一样，都是工程能力的副产品。

## 降价不是慈善：价格战背后的商业逻辑

技术解释了“能不能降”，商业逻辑解释了“为什么要降”：



1. **成本结构决定打法。** 训练是一次性固定成本，推理是边际成本。模型训完之后，卖出的每一亿 token 都在摊薄固定成本，“降价换规模”在财务上完全说得通。
2. **历史剧本在重演。** 2024 年 5 月 DeepSeek-V2 以超低定价入场，随即引发全行业跟进降价，国内大模型 API 价格在当年夏天普遍腰斩，甚至把百万 token 定价打进了个位数。这一轮的剧本类似：有人先降，其他人不得不跟。
3. **Jevons 悖论在起作用。** 单价降 60%，用量可能涨 300%。便宜的 token 会催生原本算不过账的场景——长文档分析、多轮 Agent、批量数据处理。用户的总支出未必下降，但对厂商来说，token 总消耗量涨了就是赢。
4. **生态卡位才是长期目标。** 主流 API 都兼容同一套接口格式，切换成本其实很低。锁定开发者的从来不是合同，而是“便宜 + 够用 + 稳定”的组合拳。低价期抢下的开发者习惯，就是未来的护城河。

## 开发者怎么接住这波降价

降价是好事，但“看起来便宜”和“你用起来便宜”是两回事。给一套自查路径：

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/dcf22f0c6a43961a.png)

1. **用自己的真实流量压测，别信榜单。** 评测跑的是标准数据集，而你的业务可能是长文本、多轮对话、高并发——不同负载下，各家的实际成本差异能到数倍。拿一周真实日志回放一遍，比看任何评测都准。
2. **先吃透计价规则，再谈迁移。** 缓存命中率、错峰时段、输入输出配比，这三个变量对账单的影响往往大于单价本身。把系统提示词做成稳定前缀提高命中率，把离线批处理排到深夜时段，都是零改造的省钱动作。
3. **留一层模型抽象。** 龙虾断钳还能再生，你的预算烧掉了可不会——在业务层加一个路由中间层，保留随时切换模型的能力。价格战的最大受益者，永远是手里有选择权的那一方。
4. **盯总成本，不盯单价。** 总成本 = 单价 × 用量 × 失败重试率。一个输出质量不稳、需要反复重试的模型，单价再便宜也可能是净亏。

## 三条冷思考

1. **单价还会继续降，但你的总账单未必。** token 单价的长期趋势是逼近成本线，而用量会随 Agent 和多模态场景持续膨胀。预算要按“单位任务成本”来管理，而不是“每百万 token 多少钱”。
2. **价格战筛的是工程能力。** 敢降价的厂商，背后是架构创新和推理优化在撑腰；没有成本结构支撑的降价，撑不过两个季度。观察谁在降价后还能持续迭代，比观察谁降得狠更有信息量。
3. **对应用层是明确利好。** 推理成本每降一个数量级，就有一批原本算不过账的场景变得可行。上一轮降价催生了长文本应用爆发，这一轮大概率轮到 Agent 和批量数据处理。

技术降本 → 价格下降 → 场景解锁 → 用量上涨 → 再摊薄成本，这个飞轮转起来的时候，红利永远属于提前把架构准备好的人。至于钱包，建议让你们的工程师和财务一起看这份新账单。🦞
