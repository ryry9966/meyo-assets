## 背景

Agent 会话本质上是无状态的。你上周解释过的技术栈、时区、代码风格偏好，这个新会话里一概不知。OpenClaw 的做法是在 workspace 里放几个固定文件，会话启动时注入系统上下文：`SOUL.md` 定性格，`AGENTS.md` 定行为规则，而 `USER.md` 负责回答"和我协作的这个人是谁”。

多数人装完环境后这三个文件要么空着，要么只有模板默认内容。等于让 Agent 每次都从零开始猜你——猜错了，你就得花一轮对话纠正，然后下一个会话继续猜错。

## 问题

没有 USER.md 时的典型摩擦，我自己全踩过：

- 时区和语言习惯靠猜，深夜排障时它还在按"工作时间"的节奏给我排计划；
- 每个新会话重复交代一遍目录约定、主力语言、部署方式；
- 依赖记忆系统零散地攒事实，结果是噪声多、互相矛盾，检索还不稳定；
- 换机器或重建 workspace 后，所有隐性上下文归零。

## 做法

半小时能搞定，步骤如下：

1. 在 workspace 根目录创建 `USER.md`，按"配置"而非"作文"的思路写；
2. 控制篇幅在 1–2KB，只写会改变 Agent 行为的事实；
3. 纳入 git 管理，和 workspace 一起同步到多台设备；
4. 让 Agent 帮你做首次访谈，基于你的回答生成草稿，再手工删减；
5. 每月固定 review 一次。

一份实际在用的骨架：

```markdown
# 用户画像

## 环境
- 时区 Asia/Shanghai，沟通用中文，技术名词保留英文
- 主力机 macOS，服务器 Ubuntu 24.04，Python 3.12 / Node 22

## 偏好
- 回答先给结论再给依据，不确定就明说，不要硬编
- 代码示例必须可直接运行，不要伪代码

## 禁区
- 未经我确认不执行 git push、不删除文件
- 回复里不要堆 emoji

## 协作
- 深夜消息大概率在排障，优先给最小复现路径
```

## 踩坑点

- **写太长**：这份文件每个会话都会注入，超两屏后 Agent 开始忽略后半部分，注意力被稀释，关键约束反而失灵；
- **放敏感信息**：密钥、token、住址一概不要写，它会被所有会话无差别读取，还可能被 Agent 复述进日志；
- **与记忆冲突**：记忆系统里的旧事实会覆盖 USER.md 的当前设定。出现"它坚持我已经不用的技术栈"时，直接让它列出所有冲突记忆并清理，别硬掰；
- **写成自我介绍**：Agent 需要可执行的约束。"我喜欢简洁"没用，"先结论后依据"才有用；
- **忘记更新**：换栈三个月后，它还在按旧习惯输出，比不写更误导。

## 可复用建议

- **分层维护**：全局 `USER.md` 放跨项目事实，项目级约定放到各自仓库的 agent 配置里，避免单文件膨胀；
- **当配置管**：有 diff、有 commit message、有 review，改了什么一目了然；
- **定期自审**：跑一句 "对照 USER.md 和你的记忆，列出所有矛盾点和过期条目"，比自己翻高效；
- **红线意识**：超过 2KB 就拆分或删减，删不动的说明写得不够抽象；
- 团队场景可以衍生一份 `TEAM.md`，记录协作约定，思路完全一样。

## 总结

USER.md 的价值不在"让 AI 更懂你"这类玄学表述，而在把每次会话都要重复支付的上下文成本，变成一份一次性的、版本化的配置资产。半小时写好，每月十分钟维护，换来的是所有会话的默认行为对齐。这是目前投入产出比最高的 Agent 配置动作之一，没有理由空着。
