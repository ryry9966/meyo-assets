2025 年常被称作 Agent 元年，但真正热闹的不是技术突破本身，而是"谁能把 Agent 塞进办公桌"这场混战。微软、Google、OpenAI 占据着头条，36kr 却把镜头对准了新势力 TeleAgent——一个模型不是最大、算力不是最多的团队，凭什么坐上牌桌？这篇文章不聊情怀，只拆三件事：牌桌格局、技术门槛、新势力的差异化打法。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-09/8f9ae79b2bb9ef30.png)

## 一、牌桌上都有谁：办公 Agent 的三层格局

先看清对手。目前桌上的玩家大致分三层：

- **巨头生态系**：Microsoft 365 Copilot、Google Workspace 里的 Gemini，以及国内的钉钉 AI、飞书智能伙伴。它们的优势不在模型，而在入口——办公软件本来就是每天八小时的天然入口。
- **模型原生系**：OpenAI 的 Operator 与 Deep Research、Anthropic 的 computer use，直接让模型操作浏览器和电脑。它们证明了一件事：Agent 的能力上限由模型决定，"AI 替人用电脑"已经从科幻变成了可跑通的演示。
- **创业新势力**：Manus、Devin，以及 TeleAgent 这一档公司。没有存量业务要保护，聚焦垂直场景，迭代以周为单位。

这三层不是简单的替代关系，更像"入口—引擎—工作流"的分工：巨头握入口，模型厂握引擎，新势力抢的是中间最难啃的一层——把能力编排成可信的工作流。

## 二、从 Chatbot 到 Agent：难的不是聊天，是把事办成

很多人低估了 Agent 和聊天机器人之间的距离。一个真能办事的办公 Agent，至少要过四关：

1. **任务规划（planning）**：把"帮我准备下周复盘会"拆解成查日历、拉数据、写初稿、发邀请，每一步都可执行、可回溯。
2. **工具调用（tool use）**：调 API、查数据库、发邮件。工具一多，选错参数、调错顺序的概率是指数级上升的——这是当前 Agent 失败率的最大来源之一。
3. **长程记忆**：办公任务常跨越数天甚至数周，上下文窗口再大也装不下全部历史，必须依赖外部记忆和状态管理。
4. **结果校验**：聊天说错可以重说，办公任务错了是真把错误邮件发出去了。可靠性不是加分项，是生死线。

所以业内评估 Agent 用的是任务完成率（task success rate），而不是对话流畅度。这也解释了为什么不少演示惊艳的产品一进企业流程就水土不服：demo 是单步的，真实工作是长链路的。

## 三、TeleAgent 的入场逻辑：新势力的典型打法

从公开报道和行业通行路径看，TeleAgent 这类新势力能上桌，靠的通常不是"更大的模型"，而是四件事：

- **场景闭环优先**：不做万能助手，先吃透一两条办公流水线，比如"会议纪要 → 待办生成 → 任务分派 → 周报汇总"，把整条链路的完成率做到真正可用，而不是每一步都停在 80 分。
- **人机协同设计**：多 Agent 分工之外，在关键动作前设置人工确认点（human-in-the-loop），用流程设计换可靠性——这是当下工程上最现实的取舍。
- **借力开放协议**：MCP（Model Context Protocol）这类开放标准，让新玩家不必自研全部连接器，就能接上日历、文档、IM。生态红利第一次把新势力与巨头的工具差距拉平。
- **部署与数据边界灵活**：中小企业未必买得起整套巨头套件，也未必愿意把数据放进公有云。轻量部署、权限可控，是真实存在的需求缝隙。

一句话总结：巨头卖的是"席位"，新势力卖的是"办成的事"。按结果交付的模式，天然适合从巨头看不上的长尾市场切入。



## 四、范式切换期，为什么新势力还有机会

历史经验是，平台范式切换的窗口期，往往就是后来者的机会：

- **交互范式未定**：GUI 时代的入口是图标，移动时代是 App，Agent 时代的入口是对话与委托。旧入口的价值正在被重估，巨头的分发优势不会自动延续到新范式。
- **存量包袱**：巨头按席位收费，Agent 却倾向"按任务交付"，两者存在左右手互搏。转型慢不是态度问题，是商业模式的结构性问题。
- **迭代速度差**：创业公司两周一个版本；大厂一个功能从评审到上线，可能就要两周——这还是流程顺畅的情况。

当然要泼一盆冷水：基础模型每半年上一个台阶，今天应用层辛苦挖的护城河，可能明天就被下一代模型的原生能力直接覆盖。应用层必须跑得比模型层快，才有生存空间——这是所有 Agent 创业公司头顶共同的达摩克利斯之剑。

## 五、写在最后：三条实在的建议

给正在观望或已经上桌的团队三条冷思考：

1. **评估看完成率，不看演示**。给候选 Agent 一组真实任务（比如 20 封邮件处理、3 次会议纪要），统计一次通过率和返工次数，比看十场发布会都有用。
2. **数据边界先于功能**。接入前先想清楚它能看到什么、能替你发出什么，把"发送""删除""对外承诺"这类不可逆操作一律设为人工确认。
3. **小步试点，先建基线**。从周报、纪要、日程这类低风险流程开始，先记录人工耗时基线，再看 Agent 带来的真实提效——别为了用 AI 而用 AI。

牌桌上的位置从来不是终身制。对 TeleAgent 们来说，上桌只是拿到了继续打牌的资格；对巨头来说，牌局也远没到收场的时刻。对我们普通用户，最划算的策略是：保持关注，小步使用，让工具自己证明自己。
