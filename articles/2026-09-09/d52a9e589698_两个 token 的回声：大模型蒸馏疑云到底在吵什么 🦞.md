最近 AI 圈有个小实验刷了屏：一位前 Google DeepMind 研究员在测试月之暗面开源的新模型 Kimi K2 时发现，只要在输入里补上两枚与 Claude 身份相关的 token，模型的语气、排版甚至"自我介绍"就整体偏向 Claude 的风格，像被"附体"了。截图传开，"中国大模型蒸馏 Claude"的猜测迅速发酵。热闹之外，这其实是一堂难得的公开课：蒸馏到底是什么，"像"能不能当证据，全行业心照不宣的数据配方又是怎么回事。这篇就把这层窗户纸捅开看看。

## 一、事件回放：两枚 token 做了什么

- 据公开报道与社区讨论，这位研究员在做模型行为测试时注意到，Kimi K2 在部分提示下会产出高度"Claude 风格"的内容：markdown 排版习惯、拒答的措辞结构、长文的分节方式都似曾相识。社区流传的复现方式更戏剧化：在上下文里追加两枚指代 Claude 的 token，模型便顺势切换进"Claude 模式"。截至目前，相关猜测未获官方证实，模型所属团队也未认可"用 Claude 数据训练"的说法。
- 先解释一个细节："两个 token"是分词器视角的计数。同一段文本在不同模型的 tokenizer 里切法不同，同一个名字在有的词表里是两枚，在有的词表里是四枚。关键从来不在数量，而在语义——这是一句"暗号"。
- 一个贴切的类比：一个人说话带某地口音，不能证明他户籍在那儿，但能说明他在那个语言环境里泡了很久。两枚 token 做的事，就是把模型推回它曾经"泡过"的那个条件分布区域。

## 二、蒸馏的两种含义：从 Hinton 讲到大模型时代

- 经典定义（Hinton 等，2015）：让小模型（student）去拟合大模型（teacher）输出的"软标签"——带温度缩放的概率分布，用 KL 散度算损失。初衷是模型压缩：把集成网络的知识塞进一个小网络。这条路需要拿到 teacher 的 logits，跨公司基本走不通——商业 API 不会把概率分布端给你。
- LLM 时代新闻标题里的"蒸馏"，几乎都指**黑盒输出蒸馏**：用 teacher 生成数据，再拿这些数据做监督微调（SFT）。案例一抓一把：
  1. 斯坦福 Alpaca：5.2 万条指令数据由 text-davinci-003 生成；
  2. Vicuna：直接用 ShareGPT 上抓取的 ChatGPT 对话微调；
  3. 微软 Orca：学习 GPT-4 的推理轨迹（explanation tuning）；
  4. DeepSeek-R1 论文：官方把 R1 的输出蒸馏进 Qwen、Llama 系列小模型，配方全公开。注意，用自家模型蒸馏自家小模型，是完全合规的常规操作。
- 还有第三种灰色但普遍的做法：RLAIF / LLM-as-judge，用另一个强模型当裁判给奖励信号，本质是把 teacher 的"价值观"也蒸了进来。
- 一条关键分界线：Anthropic、OpenAI 的服务条款都明文禁止用其输出训练竞争模型。所以"输出蒸馏"在技术上平平无奇，争议全在合同与商业伦理层面——这与窃取模型权重的"偷"，是性质完全不同的两回事。

## 三、"像"不等于"抄"：证据链要分三级看

1. **风格层（最弱证据）**：排版、语气、拒答话术。2024 年以来，各家模型都在相似的 RLHF + AI 反馈配方下训练，文风集体趋同，圈内甚至有 "style collapse" 的说法——大家都礼貌、爱用列表、爱加粗小标题，人类审稿都头疼。风格像，更可能说明是同一个时代、同一套方法论的产物。
2. **行为指纹层（中等证据）**：特定触发词下的自我认知、对特殊 token 的响应。有趣，但有一个常被忽略的污染源：网上大量被粘贴转发的 Claude 对话——论坛帖、技术博客、公开数据集——本身就是"Claude 这个词附近长什么样"的第一手教材。模型不需要被官方"喂"过数据，也可能从公开语料学会这口音。
3. **数据溯源层（最硬证据）**：训练数据清单、水印统计检测、成员推断攻击。目前没有任何一方公开拿得出这一级别的证据。
- 所以现状是：观察有趣，指控不足。它更像一条值得跟进的线索，而不是可以结案的卷宗。

## 四、行业底色：所有人都在喝合成数据这杯奶茶

- 高质量人类标注又贵又慢，用强模型批量生成再过滤，早已是行业标配。自 Alpaca 之后，开源模型数据配方里合成数据的占比只增不减。
- 开源模型更容易被观察到"Claude 口音"，有个朴素的技术解释：Claude 的对话输出在公开语料（ShareGPT 类站点、GitHub、博客）中浓度极高，爬虫一抓一个准。
- 这并非某一家独有：据当时媒体报道，2025 年初 OpenAI 也曾公开表示掌握了对手蒸馏其模型的证据，随后收紧 API 侧防护。攻防两端都在场。
- 还有个观测偏差：开源权重人人可下，行为实验随便做，什么口音都藏不住；闭源模型就算有同样的口音，外人也摸不到它的输入输出细节。可见性的差异，放大了印象的差异。



## 五、能不能"验 DNA"：检测思路与它的天花板

- **水印/金丝雀**：teacher 在输出里埋统计模式（如对特定 token 集合的偏好偏置），student 大量吸收后可做统计检验。但改写、混洗、多源混合都会稀释信号，工程上很难对抗刻意规避。
- **行为指纹统计**：构造探测 prompt 集，比对响应分布（embedding 距离、格式偏好），而且必须有同期基线模型做对照，否则分不清"像 Claude"还是"像 2024 年的所有模型"。
- **成员推断与记忆提取**：只能证明模型"背过某段文本"，无法证明"用了谁的数据集训练"。
- 结论：目前没有法庭级的验伪手段。这类争议停在"疑云"，不是没人想验，是工具还不够硬。

## 六、三条冷思考

1. **先拆概念再讨论**：logit 蒸馏、输出蒸馏、权重窃取是三件性质不同的事。对齐术语，能省掉八成无效争论。
2. **给选型的工程师**：把"像谁"当段子听，把可复现评测、许可证条款、model card 当决策依据。开源模型可自测、可复现，这是它相对闭源 API 的真实优势。
3. **给造数据、训模型的团队**：用别家 API 造数据，就把 ToS 里"禁止训练竞品"条款当供应链风险来管理；训自己的模型，就学 DeepSeek 公开数据配方——争议来临时，透明是最好的防御。

两枚 token 撬不开真相，但撬开了公众对"模型知识从哪来"的好奇。这个问题的答案，最终要靠水印、审计和更硬的检测工具，而不是热搜。
