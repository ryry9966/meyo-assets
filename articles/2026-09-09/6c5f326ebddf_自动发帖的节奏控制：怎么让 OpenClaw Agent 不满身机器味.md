## 背景

用 OpenClaw 挂上 MCP 工具做社区自动发帖，是很多团队上自动化后的第一步：每日摘要、版本速递、精华整理。跑起来不难，难的是跑一个月之后——帖子准时得像秒表，格式像复印，成员一眼认出"机器人又来了"，轻则无视，重则被管理员当 spam 处理。

## 问题：机器味从哪来

拆下来，"机器感"主要来自四个指纹：

1. **时间指纹**：固定整点、固定间隔，凌晨三点照发。
2. **结构指纹**：标题模板、emoji、footer 签名每次一模一样。
3. **上下文指纹**：人类正在激烈讨论时插进来一条公告，答非所问。
4. **行为指纹**：失败重试导致连发；多个 agent 各发各的，同一频道十分钟三连。

平台的反垃圾规则和人类的直觉，抓的都是这些模式。

## 做法

**1. 时间建模：从 cron 到分布采样**

不要用 `0 */2 * * *` 这种整点表达式。先统计目标社区人类的真实发帖时间分布（大部分平台 API 能拉到历史消息时间戳），把发帖槽位从这个经验分布里采样，再叠加 ±15% 抖动。夜间和周末自然就稀疏了。

**2. 事件驱动 + 配额**

发帖的动机应该是"有值得发的内容"，而不是"定时器到了"。调度器只产出候选槽位，内容管线填充，最后一道闸门检查：距上帖是否超过最小间隔、今日/本周配额是否用完。token bucket + 每日硬上限，上限写在配置里，别写死在代码里。

**3. 打散内容指纹**

准备 3-5 套结构模板轮换，标题句式、篇幅、是否带摘要块都做变化。特别注意：**结构比措辞更指纹化**——同一个 footer、同一种分割线样式，比用词重复更容易被识别。

**4. 发帖前的上下文门控**

投递前拉取频道最近 10-20 条消息：如果正在讨论事故或热点，推迟并重入队列；如果上一条就是自己的帖子，跳过本轮。这个 gate 只要 20 行代码，能挡掉大部分尴尬场面。

**5. 反馈回路**

记录每帖的回复与反应数据，互动持续走低或帖子被撤回时，按指数退避降频。低置信度内容先进人工审核队列，而不是直接发出去。

## 踩坑点

- **均匀随机 ≠ 像人**。`random.uniform` 出来的间隔在统计上依然均匀，而人类是"簇状"的（下班后扎堆）。用经验分布，别用均匀分布。
- **重试风暴**：发送失败后立即重试是连发的最大来源，重试必须退避并重新排队。
- **多 agent 抢频道**：两个 agent 没有共享锁，单机节流做得再好也白搭，频道级互斥队列是必须的。
- **过度随机会毁掉有用的仪式感**。"周一晨报"本身是个 feature，别把锚点也随机掉——保留固定锚点，打散的是周边细节。
- **别走另一个极端**：把 bot 硬伪装成真人反而更糟。该标注自动化来源就标注，我们要的是"有礼貌的自动化"，不是欺骗。

## 可复用建议

把节奏控制做成独立的一层：**调度器产槽位 → 内容管线填充 → 上下文门控 → 配额闸门 → 发送**，每层独立可测试。所有帖子落库（时间、触发源、模板版本、互动数据），每周复盘一次。最后，永远留一个 kill switch。

## 总结

自动发帖的目标不是把机器人伪装成人，而是让自动化尊重人类的节奏：跟着社区活跃度走、对上下文敏感、结构上留变化、对反馈有反应。做到这四点，即使所有人都知道它是 bot，也不会觉得被骚扰。好的自动化，是安静且有分寸的。
