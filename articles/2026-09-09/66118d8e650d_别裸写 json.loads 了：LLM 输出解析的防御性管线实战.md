# 别裸写 json.loads 了：LLM 输出解析的防御性管线实战

## 背景

在 OpenClaw 的插件和自动化流程里，让 LLM 按约定输出 JSON 是最常用的结构化手段：MCP 工具的入参、插件间的消息体、定时任务的结构化结果，基本都靠它。但模型输出天然不稳定——同一个 prompt，换个模型、调个温度、上下文变长一点，格式就可能漂移。解析层如果只写一行 `json.loads()`，整条链路就是纸糊的。

## 问题

实际跑下来，混合格式基本逃不出这几类：

1. **代码围栏包裹**：` ```json ... ``` `，语言标注时有时无，偶尔还是 `JSON`、`jsonc`；
2. **前后夹说明文字**：「解析结果如下：{...}」；
3. **多个 JSON 块**：模型顺手输出两段对象，或数组里套了示例；
4. **语法瑕疵**：尾逗号、单引号、未转义换行、中文全角引号；
5. **json mode 不生效**：部分模型/网关不支持 `response_format`，或支持了仍然包围栏。

任何一个直接 `loads`，失败一次，流水线全停。

## 做法：五层解析管线

核心思路是分层降级，每层只解决一类问题：

```python
FENCE = re.compile(r"```[\w-]*\s*(.*?)```", re.S)

def strip_fence(text: str) -> str:
    m = FENCE.search(text)
    return m.group(1).strip() if m else text.strip()

def extract_balanced(text: str) -> str:
    start = min((i for i in (text.find("{"), text.find("[")) if i >= 0), default=-1)
    depth, in_str, esc = 0, False, False
    for i, ch in enumerate(text[start:], start):
        if in_str:
            if esc: esc = False
            elif ch == "\\": esc = True
            elif ch == '"': in_str = False
            continue
        if ch == '"': in_str = True
        elif ch in "{[": depth += 1
        elif ch in "}]":
            depth -= 1
            if depth == 0:
                return text[start:i + 1]
    raise ValueError("unbalanced json candidate")

def parse_llm_json(raw: str, schema):
    body = extract_balanced(strip_fence(raw))
    body = loose_repair(body)          # 尾逗号/全角引号/单引号
    return schema.model_validate_json(body)   # pydantic 校验
```

1. **剥围栏**：正则匹配任意语言标注的围栏，取内部内容；没有围栏就用全文；
2. **括号配平提取**：从第一个 `{` 或 `[` 开始做字符级扫描，跳过字符串字面量内部的花括号，取出第一个平衡片段——这是整条管线的关键，别用贪心正则代替；
3. **宽松修复**：只修你实际见过的高频错误（尾逗号、单引号、全角标点），别一上来引入 json5 大依赖；
4. **Schema 校验**：pydantic / jsonschema 兜底，字段缺失给默认值或抛结构化错误，而不是裸 KeyError；
5. **带反馈重试**：解析失败时，把具体错误（"第 N 个字符附近不是合法 JSON"）拼回下一次请求，通常一轮就能修正。解析类任务记得把温度压到 0–0.2。

## 踩坑点

- **贪心正则 `\{.*\}`** 会匹配到最后一个 `}`，遇到多对象输出直接抓错块；
- **配平时不看字符串内引号**，值里带 `}` 一律崩；
- **重试要带错误信息**，只说"输出格式错误"模型大概率原样再犯；
- **日志必须存原始输出**，只存解析成功的结果，出问题没法复盘；
- **温度继承**：很多框架的会话默认温度是 0.7，解析任务忘了覆盖就是隐患。

## 可复用建议

- 把管线抽成独立模块放 shared lib，MCP 工具和插件统一引用，别各写一份；
- 用线上真实失败样本养一个回归用例集，改解析逻辑前先跑一遍；
- 监控"修复层命中率"，突然升高往往说明上游 prompt 或模型版本变了，这是很有价值的信号。

## 总结

防御性解析不是和模型较劲，而是承认"格式不确定"是输入空间的常态。剥围栏 → 配平提取 → 宽松修复 → Schema 校验 → 带反馈重试，五层下来，链路在格式漂移面前才真正站得住。代码不难，难的是别等到线上挂了才补。
