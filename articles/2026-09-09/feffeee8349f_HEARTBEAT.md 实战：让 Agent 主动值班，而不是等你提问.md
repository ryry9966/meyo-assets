## 背景

OpenClaw 的 Agent 默认是被动模式：你问一句，它答一句，没人说话它就闲着。但框架里有个容易被忽略的机制——heartbeat（心跳）。Agent 会按固定间隔（默认 30 分钟）被唤醒一次，读取工作区里的 `HEARTBEAT.md`，按文件内容决定是干活还是保持沉默。

这个文件本质上是一份交给 Agent 自己执行的常驻任务清单，也是把 Agent 从"工具"升级成"值班员"的最小改动路径。

## 问题

多数人的用法停留在：想起来才让 Agent 查一下服务器、拉一次摘要。痛点很明显：

- 人不在终端前，Agent 完全闲置；
- 定时类需求（早报、巡检、提醒）全靠人发起；
- 外部 cron + 脚本能覆盖一部分，但 Agent 自带工具调用和上下文，很多事它自己做得更顺。

## 做法

1. **找到文件**：`~/.openclaw/workspace/HEARTBEAT.md`，默认是空的占位说明。
2. **写任务**，关键是把"何时做、做什么、何时沉默"写清楚：

```markdown
# Heartbeat

## 每次心跳
- 无异常时不发消息，回复 HEARTBEAT_ACKED 即可

## 每天 08:00（UTC+8）
- 拉取 RSS 待读列表，挑 3 条发摘要

## 异常才上报
- 运行 check-server.sh，连续失败 2 次才通知我
```

3. **调间隔**：配置里 `agents.defaults.heartbeat.every` 可改为如 `45m`；单个 Agent 不需要心跳就设 `HEARTBEAT_DISABLED=1`。
4. **固定回报渠道**：把 heartbeat 的 target 指到指定会话，避免消息打进"最近用过"的频道里。

## 踩坑点

- **静默不等于免费**：即使无事可做，每次心跳仍会调用一次模型。任务少就拉长间隔，或给心跳单独指定便宜的小模型。
- **指令模糊 = 消息轰炸**："帮我盯着服务器"这种写法，Agent 会频繁打扰你。必须写清触发条件和静默策略。
- **长任务拖垮节奏**：心跳里塞爬虫式长任务，下一轮触发时上一轮可能没跑完。心跳任务保持幂等、短平快，重活交给独立脚本。
- **时区歧义**："早上 8 点"取决于 Agent 拿到的当前时间，明确标注时区，或者干脆用 crontab 触发消息代替文件内的自然语言定时。
- **别写密钥**：它就是个普通文件，建议连同工作区纳入 git 管理，但注意 `.gitignore`。

## 可复用建议

- 用**三段式结构**维护：每次检查 / 定时任务 / 异常上报，职责清晰，改一条不动其他。
- 每条任务写成**可判定**的形式：有明确的成功/失败条件，Agent 才能执行到位。
- 与 MCP、技能脚本组合：心跳负责"何时"，工具负责"怎么做"，职责分离后清单会非常稳定。
- 从一条低频任务起步（比如每日摘要），观察一周的 token 消耗和消息噪音，再逐步加码。

## 总结

HEARTBEAT.md 没有黑科技，就是一份 Agent 每半小时会认真读一遍的 markdown。但配上明确的静默策略和触发条件，它把 Agent 的价值从"随叫随到"推进到"自己值班"。建议先写一条真正能省你时间的任务进去试跑一周——比看十篇教程都有用。
