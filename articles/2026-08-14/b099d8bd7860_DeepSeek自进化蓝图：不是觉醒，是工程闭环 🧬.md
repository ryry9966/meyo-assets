最近36氪曝出DeepSeek的“自进化”蓝图，社区讨论像炸了锅：一波人觉得AGI门缝已经透光，另一波人觉得又是概念套壳。我的判断是：先别急着讨论“数字生命”，把“自进化”拆成可回滚的工程流水线，反而更能看清这件事的价值。它没那么神秘，也没那么廉价。



## 一、自进化不是“模型自己变强”，而是一条可回滚的流水线


很多人一听“自进化”，脑子里浮现的是模型半夜偷偷给自己升版本，第二天智商翻倍。真实情况要朴素得多。

- 传统 LLM 的权重训练完成后基本冻结，线上模型不会因为用户反馈自动改变；所谓“进化”只是厂商隔几个月重训一次。
- 自进化指的是部署后的系统自动完成一个闭环：生成新样本 → 自动验证 → 筛选高质量数据 → 参数更新 → 评估 → 通过后合并，失败则回滚。
- 每一步都有明确职责：Generate 根据种子任务生成新解法；Verify 用代码执行、数学验算或规则检查打分；Select 按难度、正确率和多样性过滤噪声；Fine-tune 只拿通过筛选的数据做小步微调；Eval 在固定 benchmark 和隐藏测试集上做回归；最后 Rollback 或 Merge 决定是否进入主分支。
- 类比一下：不是一只龙虾自己学会了敲键盘，而是一套自动养殖系统每天根据肉质、水温、饲料转化率微调配方。不浪漫，但能落地。
- 历史参照并不少。AlphaGo Zero 通过 self-play 摆脱人类棋谱，40 天超越此前所有版本；Meta 2024 年的 Self-Rewarding Language Models 尝试让模型自评自训；DeepSeek-R1 用 GRPO 省掉独立的 critic model，让强化学习更轻量。
- 工程上的关键是：每一步都要可验证、可回滚、有 regression test。没有刹车和倒挡的进化，只能叫随机漂移。

## 二、为什么现在才谈自进化：三个前提刚好凑齐


自进化不是新词，但过去更像口号。最近两年有三个条件陆续成熟，才让它从 PPT 变成可执行方案。

1. **长链推理能力**：模型不再只吐一个最终答案，而是能输出中间步骤。思维链像代码 diff 一样可以被检查，错误能定位到具体 step，反馈粒度从“对/错”变成了“哪一步错、为什么错”。GPT-3 时代反馈信号太稀疏，自进化只能瞎猜；现在 reasoning model 提供了稠密梯度。
2. **可验证场景变多**：代码可以跑单测，数学可以验算，形式化证明可以过 Lean 或 Isabelle 等 checker，部分科学计算有客观结果。合成数据成本下降，让系统不再完全依赖昂贵的人类标注。
3. **训练与推理架构优化**：MoE、MLA、FP8 等技术把单次迭代成本打下来。以 DeepSeek 系模型为例，公开论文中反复强调的核心就是“用更低算力做更多有效训练”。这一前提下，频繁小步更新才具备现实可行性。

DeepSeek-R1 的 GRPO 尤其值得一提：它不训练单独的 value network，而是对一组采样结果做相对优势估计。这个设计直接降低 RL 门槛，等于给“自进化”补上一块便宜的发动机。不是某个天才突然发明了进化，而是零件终于凑齐了。

## 三、可能的技术路径：不是重训大模型，而是局部闭环


不要把自进化理解成每轮都全量重训大模型。那种成本没人扛得住，也不安全。更可能出现的是围绕主干模型的局部闭环。

- 路径 A：自动课程生成。模型根据自身薄弱点生成练习题，按难度分层，再用 rejection sampling 淘汰劣质样本，只保留高置信度、可验证的数据进入训练池。比如数学题库可以由模型出题，配合形式化验证器批量判分。
- 路径 B：self-play / 对抗自博弈。一个生成器负责出题，一个验证器负责判分，两者交替更新。生成器越来越刁钻，验证器越来越严格，能力对偶上升。这在围棋、代码生成和数学推理里已有相似验证。
- 路径 C：模型裁判。代码执行结果、数学证明检查器、多模型一致性投票，部分替代人类偏好标注。但要注意“裁判被模型贿赂”的问题——评估污染会让闭环自欺欺人。
- 路径 D：参数高效更新。LoRA、QLoRA 或 router 微调，每轮只动一小部分参数，便于版本管理、灰度发布和安全回滚。

最可能落地的形态不是单路径，而是一个 DAG 工作流：数据生成 → 清洗 → 微调 → 评测 → 灰度 → 回滚，再加一层“模型议会”投票决定是否合并到主分支。对，看起来更像 CI/CD，而不是科幻现场。

## 四、商业与冷思考：这是一把双刃剑，先看飞轮再看刹车


自进化的商业诱惑很直接：迭代越快，数据反馈越密，模型与场景贴合越深。竞争会从“单次模型能力”转向“系统闭环效率”。

- 机会在于垂直场景。谁拥有专有反馈和可验证任务，谁就能用小模型打过大模型。代码、数学、表单抽取、规则校验等天然有客观判据，最适合冷启动。
- 风险一：fitness function 错了，进化越快越偏。如果只优化答题正确率，可能牺牲指令跟随、安全、多轮一致性。
- 风险二：benchmark hacking。自动优化非常容易过拟合评测集，甚至出现“模型给自己出题、自己表扬自己”的闭环。
- 风险三：对齐漂移。没有人类反馈校准的自进化，可能在开放域任务里慢慢跑偏，尤其在“有用、无害、诚实”三者之间失衡。

所以我会把自进化看作自动驾驶里的影子模式：先在后台跑，和主模型对比，通过严格 regression gate 再上线。飞轮要转得快，刹车必须更灵。

**三条实用建议：**

1. 开发者：先把可验证评测体系和回滚机制建起来，再谈自进化。没有 regression gate，不要自动合并权重。
2. 创业者：优先选有客观判据的场景做数据飞轮，别一开始就赌开放域对话自进化，那是最难对齐的方向。
3. 普通用户：别被“自进化”三个字带节奏，看模型更新是否透明、可复现。模型说自己进步了，不如让它跑一遍你手头的固定测试集。
