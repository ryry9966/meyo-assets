DeepSeek Harness 来了，它不想做下一个 Codex。这句话在开发者圈子里刷了屏。很多人的第一反应是：DeepSeek 也要出一个代码生成 Agent 了？但如果仔细看 Harness 这个词，会发现事情可能反过来：它不是在和 Codex 抢同一个产品形态，而是在补模型落到真实任务里最缺的那一层——连接、调度与可观测的工程骨架。



## 一、Harness 在“牵”什么：名字里藏着定位

Harness 在工程英语里至少有三种常见含义：马具、线束、测试固定装置。共同点是：它本身不产生动力，但决定力量往哪里传导、动作是否受控。放到 AI 语境，Harness 指的是把模型能力套到实际任务上的那层胶水。

- 如果大模型是发动机，Harness 就是传动轴、刹车和仪表盘。
- 如果 Codex 更像一台已经装好导航的整车，Harness 更像给你一套可以改装的方向机。
- 这也解释了“不想做下一个 Codex”：Codex 的核心叙事是“模型+产品”的一体化体验；Harness 更像“框架+协议”，让不同模型、不同工具、不同环境都能被组织起来。

这种定位没有高下之分，但商业路径完全不同。Codex 路线押注的是越用越顺的托管产品；Harness 路线押注的是开发者可以自己搭、自己拆、自己审计的工程基础件。



## 二、为什么“不做下一个 Codex”是更聪明的技术判断

2021 年 OpenAI Codex 发布时，大家还在为“自然语言直接生成代码”兴奋。到了 2023、2024 年，Code Interpreter、Advanced Data Analysis、各类 Agent SDK 已经把“模型直接出结果”的故事讲过很多轮。此时再做一个高度相似的闭源 Codex，边际收益很低。

DeepSeek 的既有优势不在“重新发明一个助手”，而在三件事：

1. 推理成本低，适合被高频调用；
2. 开源权重，开发者可以本地部署、私有化改造；
3. 代码、数学、长上下文能力足够支撑复杂执行链。

Harness 如果只是 DeepSeek 模型的专属外壳，路会越走越窄；只有把工具调用、执行轨迹、权限边界开放出来，才能把上述能力变成生态粘性。换句话说，它不想做下一个 Codex，不是清高，而是因为 Codex 那个位置已经太挤了。

更值得注意的一点是：Harness 的竞争对象未必是 OpenAI，而是 LangChain、AutoGen、MCP 这类框架协议。这个维度上，模型厂商做框架本身就是一个信号——模型能力开始从单点智能，转向对执行过程的控制。



## 三、拆开 Harness 的工程骨架：它可能长什么样

具体实现还没有官方完全公开，但从 Harness 一词的工程传统和现有开源趋势，可以推演五个关键层：

1. **任务定义层**：定义目标、输入输出 schema、成功标准。开发者不再只写 prompt，而是写一个可验证的任务对象。
2. **执行循环层**：负责 step-by-step 地调用模型、观察结果、决定下一步。类似 Agent 的 runtime，但更强调可中断、可恢复、可回放。
3. **工具适配层**：把文件系统、数据库、浏览器、API、代码解释器统一成标准化接口。模型看到的不再是零散函数说明，而是带权限和返回格式的工具协议。
4. **策略与安全层**：哪些动作可以自动执行，哪些需要人工确认，哪些必须只读。这个层在金融、医疗、制造业场景里，往往比模型能力更重要。
5. **评估与回放层**：记录每一次工具调用、模型推理片段、环境变化，形成可复现的执行轨迹。这解决了一个长期痛点：Agent 做错了，不是只给一个错误答案，而是可以回放看它在第几步走偏。

举一个具体例子：让 Harness 处理“分析近三个月销售数据并生成异常预警”。

- 任务定义层要求输出：异常门店列表、归因假设、建议动作。
- 执行循环先读数据目录，发现两个 CSV 格式不一致，调用清洗工具。
- 工具适配层给模型两个选择：用 Pandas 本地处理，或调用 BI 系统 API。
- 策略层规定 API 只读，删除/覆盖操作必须人工确认。
- 评估层把整个执行过程记下来，下一次可以直接对比轨迹质量，而不只看最终报告好不好看。

这比输入一句话，等一个魔法结果要慢，但对生产环境友好得多。



## 四、开发者真正该关注的三件事

不要只盯着“DeepSeek 又发了个东西”的热闹，Harness 真正改变的是工程边界。

1. **从 prompt 工程转向任务编排**  
   未来更值钱的不是写出更长的提示词，而是把任务拆成可执行、可验证、可回滚的步骤。谁能定义清楚“什么叫完成”，谁就能更好驾驭模型。

2. **评估从离线分数走向在线轨迹可观测**  
   以前评测只看最终准确率；Harness 这类框架会让过程数据变得重要。哪个工具调用是冗余的、哪一步模型开始幻觉、哪次重试是无效的，这些都能被记录和量化。

3. **开源框架可能进一步压低 Agent 开发门槛**  
   过去小团队做 Agent 要自己搭调度、做权限、接工具。如果 Harness 真的把这些做成可复用骨架，那么一个三五个人的团队也可能做出稳定跑在私有环境里的业务 Agent。

与此同时，也要避免过度神话。Harness 不能解决领域知识缺失，也不能替你梳理混乱的业务流程。它更像是把你的执行逻辑放大，而不是帮你发明执行逻辑。



最后给三条冷思考：

- **先把它当执行记录仪，而不是自动赚钱机**：第一阶段的收益往往来自可观测性，而不是自动决策。
- **从结构化任务切入，别一上来做开放世界 Agent**：报表、数据清洗、工单分类、代码审查这些边界清晰的任务更容易见效。
- **关注工具调用协议，而不是单一模型能力**：将来生态的分水岭可能不是谁的模型更聪明，而是谁定义的工具接口被更多系统接受。

这大概就是 DeepSeek Harness 最值得被讨论的地方：它不想做下一个 Codex，但有可能成为很多人手里第一把真正能上生产线的 AI 工具钳。
