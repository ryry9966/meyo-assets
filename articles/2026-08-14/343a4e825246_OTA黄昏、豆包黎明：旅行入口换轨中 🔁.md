最近36氪那条《OTA的黄昏，豆包的黎明》在几个产品群里被转得不少。标题把在线旅游平台（Online Travel Agency，OTA）和字节的豆包放在新旧世界的两端，很符合互联网喜欢“换代叙事”的胃口。但如果把技术链路、交易闭环和用户真实行为拆开看，OTA 还没进ICU，豆包也还没拿到预订的钥匙。今天不吹不黑，把这条热搜背后的机制讲透。



## 一、OTA 为什么被推到“黄昏”位置

OTA 的焦虑不是今天才有的，只是这次被 AI 话题放大了。

- **信息差红利变薄**：早年间 OTA 的核心价值是把分散的机票、酒店、门票供给集中到一张屏上，用户不用挨个打航空公司电话。如今价格越来越透明，用户可以直接跳转到航司官网、酒店官方小程序，OTA 的“比价中间商”角色被削弱。
- **推荐逻辑广告化**：很多 OTA 的默认排序不是“最适合你”，而是“出价更高者靠前”。广告位、套餐打包、会员返佣交织在一起，用户做决策的成本反而变高。
- **入口被内容平台分流**：用户先在短视频和图文社区被“种草”，再打开 OTA 下单。OTA 从一个“发现目的地”的入口，退化为“结算工具”。
- **增长见顶**：移动互联网用户规模见顶，OTA 买量成本持续上升，但佣金率受供给方直连和同业竞争影响，很难大幅提升。

所以“黄昏”不是说旅游需求没了，而是 OTA 的旧入口形态确实在老化。用户要的不是一个更长的列表，而是一个能直接回答“我该订哪个”的东西。

## 二、豆包们的“黎明”在技术上成立吗？



如果只说“AI 帮你查攻略”，那不算什么新东西。这一轮真正的变化是：大模型从“聊天”走向“任务执行”。

- **自然语言变成可执行指令**：传统搜索引擎只能理解关键词，比如“杭州 三天 父母 行程”。但豆包可以理解“下周三上海出发，带父母，预算4000，不想爬太累的山”这种含约束条件的自然语言。
- **关键在 function calling 和工具链**：模型本身没有实时票价和酒店库存，但可以调用地图、天气、票务、酒店等外部 API。一次请求会被拆成多步：查天气 → 筛车次 → 圈定酒店区域 → 生成三日路线 → 给出比价链接。
- **从“给链接”到“给方案”**：传统 OTA 给的是列表，AI 助手给的是带顺序、带预算分配、带体力评估的行程草稿。这让用户感觉不是在“搜索”，而是在“被理解”。
- **成本下降让 Agent 成为可能**：多轮工具调用意味着多次模型推理，过去 token 成本高、延迟大，难以规模化。现在上下文窗口扩大、推理成本下降，AI 规划从 demo 变成了可落地的产品能力。
- **协议标准化在加速**：MCP（Model Context Protocol）这类协议正在把工具调用标准化，OTA、航司、酒店可以把查询和下单能力包成一个个工具，让不同 AI Agent 接入。这会慢慢改变流量分配方式，但距离真正替代交易还有距离。

但注意，这些优势集中在“意图理解”和“方案生成”，并不自动等于“敢下单”。那是另一道更难的关。

## 三、真正的关口：不是“会不会搜”，而是“敢不敢订”

搜索和规划只是旅行决策的前半段，交易和履约才是后半段。豆包们目前更多停在前半段。

- **信任成本**：用户可以让 AI 推荐餐厅，但支付环节跳转到陌生页面时会犹豫。OTA 品牌、发票、客服、退改入口是长期积累的信任资产。
- **责任归属不清**：AI 说“这家酒店离西湖步行500米”，实际 1.5 公里，谁来负责？模型厂商、应用开发者还是供应商？目前没有清晰的规则。
- **退改与售后复杂**：一张机票可能涉及航司规则、舱位限制、联程中转、保险理赔。AI 生成方案如果没和订单系统打通，用户仍需回到人工核对。
- **商业闭环缺失**：目前用户通过豆包等助手订酒店，多数仍会跳到 OTA 或官方小程序完成支付。豆包如果只做前端推荐，不变现；如果接入交易，就要和酒店、航司、OTA 谈直连，等于从轻应用变成重平台。
- **数据飞轮不在手上**：推荐效果依赖真实入住、消费、投诉数据，这些数据目前主要在 OTA 和酒店会员体系里，AI 助手拿不到闭环反馈。

换句话说，豆包的“黎明”更像天亮了，但还没完全照进交易大厅。

## 四、更可能的格局：不是替代，而是入口迁移与供应链重排

如果非要说谁取代谁，很可能是一种更无聊但更常见的结果：分工变了。

- **前端入口层**：AI 助手、内容平台、地图、语音助手都可能成为新的“意图入口”。用户第一个打开的可能不再是 OTA App。
- **中间调度层**：OTA 有可能从直接面向消费者的预订工具，变成 AI Agent 背后的库存与履约服务商，向各家助手提供查询、比价、售后接口。
- **后端供给层**：酒店集团和航司加速直连，把会员价、退改政策、库存状态做成标准化 API，减少对单一渠道的依赖。
- **历史类比**：搜索引擎没有杀死航司官网，只是把入口从官网首页移到了搜索结果页；短视频没有杀死 OTA，只是把“种草”前置。AI 大概率也会这样，改变的是用户最先打开谁。

所以“OTA的黄昏”更准确的说法是：传统 OTA 作为第一入口的黄昏；“豆包的黎明”是 AI 助手作为意图入口的黎明。真正被重构的是旅行交易链路，而不是某一类公司突然消失。

## 五、冷思考与实用建议



- **对普通用户**
  1. 把 AI 行程当“初稿”，不要当“订单”。付款前回到官方渠道或 OTA 核对退改政策、实际地址和差评。
  2. 比较价格时别只看标价，要把税、行李额、退改成本一起算进去。
  3. 复杂行程，比如多程中转、签证、团队出行，仍建议保留人工客服作为兜底。
- **对从业者**
  1. OTA 与其防守，不如把库存、客服、核价能力 API 化，做 AI 时代的水电煤。
  2. 酒店和航司要重视会员直连与数据主权，避免被新的流量入口锁死。
  3. 内容平台如果只做推荐不做履约，用户跳失率会越来越高，需要补后端能力。
- **对创业者**
  1. 机会不在再做一个通用大模型，而在垂直场景的 Agent 编排、异常处理、可信评价。
  2. “AI 推荐错误谁来赔”目前是空白，保险、担保、审核机制可能是真正的缺口。

最后说一句：商业世界里，黄昏和黎明通常不是同一天发生的。OTA 不会因为豆包的黎明就立刻关灯，豆包也需要跨过交易闭环才能把黎明变成正午。真正受益的，可能是那些愿意为“可信决策”和“交付确定性”买单的用户。
