过去一年，大模型圈的竞争节奏被压到以“周”为单位。一个新模型刚发布，几周甚至几天内，就常有一批小模型宣称在部分 benchmark 上逼近它。这类快速追赶背后，经常藏着一个关键词：蒸馏（distillation）。如果把大模型比作一位经验丰富的老师，蒸馏就是把老师脑子里的判断力压缩进一个小得多的学生模型。但当越来越多平台收紧对模型输出使用的限制，一些公司也开始公开强调“没有用任何第三方模型输出训练”，一个问题随之浮出水面：如果一家大模型公司真的选择不蒸馏，它会付出什么代价？



## 蒸馏到底在“蒸”什么：从 Hinton 的一篇论文说起


蒸馏并不是因为大模型火了才出现的技术。2015 年，Geoffrey Hinton 等人发表论文《Distilling the Knowledge in a Neural Network》，正式提出“教师-学生”框架。它的核心逻辑不是让学生背答案，而是让学生学习老师的“判断分布”。

- 教师模型不只是输出一个硬标签。比如识别手写数字“7”，教师可能给出“7”的概率 0.8，“1”的概率 0.08，“9”的概率 0.05。这些微弱概率揭示了类别之间的相似性：7 和 1 有点像，7 和 9 也有点像。
- 温度参数 T 会进一步软化这个分布。T 越大，概率越平滑，原本被 softmax 压缩掉的信息会重新显露出来，学生模型就能学到更多关于“错在哪、错得多接近”的细节。
- 训练时，学生模型通常会同时使用教师的软标签和真实硬标签，用 KL 散度等损失函数平衡泛化与精度。
- 因此，蒸馏不是套壳，也不是简单复制权重。它更像一种能力迁移机制：把大模型已经编码好的知识、偏好和推理倾向，压缩到更小的网络结构中。

## 不蒸馏的第一张账单：训练数据与算力成本被抬高


如果一家公司决定完全不依赖第三方模型输出，也就是不走“外部蒸馏”路线，那么第一笔代价会直接落在数据与算力上。

- 从零训练大模型需要高质量、多样、去重后的数据集。没有教师模型提供软信号，就要更依赖人工标注、人工反馈和精细化数据清洗。
- 以一个数十亿参数模型为例，预训练通常需要数十亿到数万亿 tokens，训练周期从几周到几个月。即便使用数千张 H100 级别的 GPU，总成本也轻松达到数百万美元级别。
- 高质量人工标注并不便宜。一条涉及多轮推理、代码调试或安全判断的数据，平台报价可能在数美元到数十美元之间。百万条规模的数据集，仅标注成本就可能与训练成本相当。
- 如果无法复用外部模型输出的高质量问答、推理链和人类偏好，企业就必须自己建设数据飞轮，投入更多时间与工程人力。
- 换句话说，不蒸馏意味着同样的能力目标，需要更厚的钱包、更长的周期和更重的数据工程负担。

## 不蒸馏的第二张账单：迭代速度与对齐成本同步上涨


大模型竞争不仅是参数规模的竞争，更是反馈闭环速度的竞争。蒸馏在这个闭环里扮演了加速器角色。

- 一个能力较强的教师模型，可以快速生成大量高质量指令、代码、摘要和偏好数据，用来蒸馏小模型。企业能在一两周内完成一个版本迭代。
- 如果不蒸馏，就必须走更慢的路径：自己设计 RLHF 或 RLAIF，建立奖励模型，组织红队测试，持续收集在线反馈。
- 人工反馈的延迟非常高。评估一个复杂 prompt 的多轮回答，人类需要几分钟，而机器生成可能只要几秒。几百条样本的差异积累起来，就会把版本周期从几天拖到几周。
- 还有“对齐税”问题。为了让模型安全、礼貌、懂得拒绝有害请求，需要额外训练。没有教师模型，企业就需要自己烧更多算力做对齐实验。
- 合成数据常被看作替代方案，但它也有代价：如果只用自家模型生成数据，错误可能被循环放大，多样性也会下降；如果使用外部模型生成，又可能触及合规红线。于是迭代速度不得不降下来。

## 不蒸馏的第三张账单：推理部署和产品毛利承压


即使模型训出来了，不蒸馏的影响还会延续到推理阶段。很多人只关注训练贵，但推理成本才是产品上线后的“长期账单”。

- 大语言模型推理的单位 token 成本与参数量强相关。千亿级模型在 GPU 上的延迟、显存占用和能耗，很难支撑高并发、低延迟的产品体验。
- 蒸馏后的小模型，通常能保留常见任务 70%–90% 的能力，同时把参数量缩小 10 倍以上。推理成本降低一个数量级并不罕见。
- 如果坚持不蒸馏，就需要在手机端、浏览器插件、车载助手、客服系统等场景中部署更大的模型，或者大量堆 GPU 提高并发，毛利会被持续侵蚀。
- 很多场景本来就是“小模型友好”的：意图识别、函数调用、SQL 生成、简单摘要、格式转换等。用千亿模型处理这些任务，好比用卡车送一杯咖啡。
- 因此，不蒸馏不仅是研究路线问题，更会直接影响产品能否跑到盈亏平衡线附近。

**冷思考：不蒸馏并不全是坏事**

如果只看表面，蒸馏像一条捷径；但把时间拉长，它的意义更像一种工程杠杆。对行业来说，正确的问题也许不是“要不要蒸馏”，而是“在什么边界内蒸馏”。

- 冷思考一：蒸馏不是万能解药。小模型在复杂多步推理、长程一致性、开放域创意等“深水区”能力上，仍可能表现出明显的天花板。底座模型不能因此被忽视。
- 冷思考二：合规边界会越来越清晰。利用第三方 API 输出做训练，可能违反平台服务条款；开源权重则有各自的许可证限制。企业需要把蒸馏纳入数据治理和模型合规评估。
- 冷思考三：不蒸馏的代价最终会转移到用户体验上。响应变慢、价格变贵、离线不可用，用户会用脚投票。所以即使有合规压力，行业也会继续探索“合法蒸馏”，比如自生成数据、使用明确授权的开源模型，或者通过多方授权数据完成能力迁移。

实用建议：
1. 对模型公司：把资源优先投向自有数据飞轮与评估体系，不要把蒸馏当成核心壁垒。
2. 对应用团队：先跑通产品闭环，用中等模型加蒸馏满足 80% 场景，再对长尾需求上大模型。
3. 对观察者：关注许可证、服务条款与合成数据边界，这些规则会重新定义“谁能用谁的智能”。
