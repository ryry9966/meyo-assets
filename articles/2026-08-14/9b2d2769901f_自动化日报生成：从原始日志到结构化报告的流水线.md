## 背景

团队日报往往要汇总多个来源：GitHub 提交与 PR、CI 失败、线上错误、任务系统状态。人工拼贴不仅耗时，还容易漏掉关键变更。引入 Agent + MCP 之后，确实可以把“复制粘贴”交给自动化，但直接把原始日志丢给模型生成日报，效果通常不稳定：上下文爆炸、幻觉链接、格式漂移、时区混乱都很常见。

这篇文章记录一条可落地的流水线：采集 → 清洗 → 结构化 → 聚合 → 推送。核心思路不是“让模型写得好”，而是先把原始日志变成可验证的结构化事件。

## 问题

原始日志有三个典型特征：

1. 噪音大：调试日志、机器人提交、重复告警混在一起。
2. 格式不一：每个源的字段、时间格式、严重级别都不同。
3. 时间边界模糊：“昨天”“最近一次”在跨时区时容易产生歧义。

如果让 Agent 直接读这些内容，模型需要同时做提取、去重、归类、总结，任何一步出错都会传导到最终日报。

## 做法 / 步骤

### 1. 数据源接入

每个数据源封装成薄适配器，通过 MCP 工具暴露，例如：

- `get_commits(since, until)`
- `get_ci_failures(since, until)`
- `get_sentry_errors(since, until)`
- `get_task_status(since, until)`

不要在 Agent 内部做重度转换，工具层只负责取数并返回稳定结构。

### 2. 显式时间窗口

日报通常按自然日或工作时段生成。在 OpenClaw 的编排层确定 `since` / `until`，以 ISO8601 传入所有工具，避免“昨天”这种自然语言描述。所有数据源统一返回 UTC，展示层再转本地时区。

### 3. 清洗与去重

规则先行：

- 过滤调试日志、机器人提交、已经关闭的告警。
- 用 `commit SHA`、`issue key`、错误指纹去重。
- 对同一事件在不同源出现的情况，保留来源字段，但按 `source + id` 聚合。

### 4. 结构化中间层

不直接生成日报，先让 Agent 把原始事件转成统一 JSONL，例如：

```json
{
  "source": "github",
  "id": "pr-123",
  "summary": "修复登录超时问题",
  "severity": "info",
  "owner": "@alice",
  "link": "https://github.com/org/repo/pull/123",
  "ts": "2025-06-10T08:30:00Z"
}
```

这一步是关键。后续生成、审计、去重、推送都基于这个 Schema，而不是依赖模型自由发挥。

### 5. 聚合与生成报告

把结构化事件按类别聚合，再套用固定模板生成 Markdown：

- 今日概览
- 代码变更
- CI / 发布
- 线上问题
- 待办 / 风险

模型在这一步只负责摘要、归类和语言润色，不负责创造事实。事实字段必须来自中间 JSONL。

### 6. 推送与留档

推送到企业微信、邮件或仓库。同时保存原始 JSONL 和最终报告，方便后续排查“为什么日报里出现了这条”。

## 踩坑点

- **直接喂原始日志**：模型容易编造 commit 或 issue 链接。应先提取 `sha`、`id`、`link` 等可验证字段。
- **时区不一致**：所有工具必须接收显式时间参数，不要依赖“昨天”。统一 UTC 存储，展示层再转换。
- **重复事件**：错误告警可能在多个源重复出现。用 `source + id` 或事件指纹去重。
- **格式漂移**：让模型自由写日报，格式会越来越不稳定。用 JSON Schema 约束中间层，最后一步再渲染 Markdown。
- **工具失败静默**：MCP 工具调用失败要显式记录为 `unknown/failed`，不能悄悄跳过，否则报告看似完整，实际缺数据。
- **缺少人工兜底**：全自动日报适合内部同步，对外或管理汇报要保留人工确认链接。

## 可复用建议

1. **先结构化，后生成**。中间 JSONL 是稳定契约，日报只是它的视图。
2. **每个数据源一个薄适配器**，输出统一事件，不在 Agent 里做复杂转换。
3. **时间参数显式传递**，工具返回 UTC，展示层转本地。
4. **保留原始输入与最终报告的映射**，排障时能追溯每一条结论来自哪里。
5. **小步上线**：先跑一个源，稳定后再加下一个源。

## 总结

自动化日报的工程重点不是模型能力，而是管道设计。采集、清洗、去重、时区处理、失败可见性这些基础工作决定了系统能不能长期稳定运行。先把原始日志变成结构化事件，再让模型做摘要和归类，这条流水线才会真正可复现、可维护。
