## 背景

在 OpenClaw/Agent 工作流里，越来越多人把 system prompt 从聊天框里抽出来，放进项目目录里的 `SOUL.md`。这样做的好处很直接：可版本化、可评审、可团队共享。但常见的问题是，很多人只把它写成“你是一个乐于助人的 AI 助手”，结果该约束的行为没约束住，反而消耗了大量上下文。

对能接 MCP、插件和自动化工具的 Agent 来说，`SOUL.md` 不只是人格设定文件，更应该是一份行为边界文件。

## 问题

实际使用中，两类问题最典型：

1. **人格漂移**：长任务跑了几十轮之后，Agent 的语言风格、决策目标开始偏离初始设定。比如一开始说“回复简洁”，后面开始大量输出不必要解释。
2. **边界失效**：面对 MCP 工具、文件系统插件或 shell 能力时，Agent 可能读取仓库外文件、写系统目录、执行高风险命令，甚至在日志里打印密钥。

仅靠自然语言说“不要这么做”并不够。必须把提示词约束和工具权限叠加使用。

## 做法：把 SOUL.md 当作可版本化配置

### 1. 确定加载位置

建议放在项目根目录的 `.claw/SOUL.md`，项目级配置可以覆盖全局 `~/.claw/SOUL.md`。团队协作时，项目级配置随仓库走，评审和回滚都方便。

### 2. 内容结构要够工程化

一个最小可用的 `SOUL.md` 模板如下：

```markdown
# SOUL.md

## 身份
你是在本仓库工作的 OpenClaw 工程助手。默认语言中文，回复简洁，不寒暄。

## 边界（高优先级）
- 只能读写当前仓库目录，不访问 ../、/etc、~/.ssh。
- 禁止执行破坏性命令：rm -rf、git push --force、sudo、shutdown。
- 除非用户明确要求，不修改 .env、Makefile、CI 规则。
- 不在聊天或日志中打印 secret/token/密码。
- 对删除文件、覆盖文件、执行 shell 命令，先给出计划并等待确认。

## 工具策略
- 只读查询优先使用 MCP 只读接口。
- 写文件使用 apply_patch/diff 方式，不直接覆盖。
- 插件能力只使用白名单：filesystem.read、filesystem.write、git.status、git.diff。

## 失败处理
- 工具调用失败最多重试 2 次，然后停下来说明原因。
- 对不确定的路径或命令，先问，不要猜。
```

这个模板的重点不是“人格”，而是边界、工具策略和失败处理。人格部分可以控制语气和回复风格，边界部分控制安全底线。

### 3. 让 SOUL.md 与工具权限配合

`SOUL.md` 负责“行为约束”，MCP/tool whitelist 负责“能力约束”。例如：

- 在 `SOUL.md` 里写“禁止访问 `/etc`”；
- 同时在文件系统插件里把 roots 限制到 workspace。

只写提示词约束而没有真实权限限制，Agent 仍可能在特定条件下越界；只做权限限制而没有提示词约束，Agent 遇到拒绝后会不断换姿势尝试。两者缺一不可。

### 4. 做小型回归测试

每次修改 `SOUL.md` 后，可以跑一组固定用例：

- 让 Agent 尝试读取仓库外文件；
- 让 Agent 尝试执行危险命令；
- 让 Agent 输出环境变量或密钥；
- 检查它是否按预期拒绝并解释原因。

这样能把“提示词改了但行为没生效”这类问题尽早暴露出来。

## 踩坑点

- **写太长**：几百行的人格故事会稀释关键规则。控制在 80–120 行比较合适。
- **只写性格不写边界**：结果就是“温柔地越界”。
- **改了不生效**：全局 `SOUL.md` 改了，但当前会话还缓存着旧版本。需要新开会话或显式 reload。
- **多份规则互相冲突**：项目里同时存在 `SOUL.md`、`AGENTS.md`、`CLAUDE.md`，规则覆盖关系不清晰，行为不稳定。建议只保留一份主配置，其他文件引用它。
- **把密钥写进 SOUL.md**：可能通过日志、会话导出、版本控制泄露。

## 可复用建议

1. `SOUL.md` 纳入 git 版本控制，任何边界变更都走评审。
2. 用“允许/拒绝”列表代替长段落，拒绝项放在高优先级。
3. 高危操作增加二次确认，不要只靠一句“不要执行危险命令”。
4. 边界规则和 MCP/插件权限保持一致，实施最小权限。
5. 用固定测试集做行为回归，避免只凭感觉判断“它应该不会这么干”。

## 总结

`SOUL.md` 不是给 Agent 写人设小作文，而是一份可评审、可测试、可版本化的行为边界文件。人格设定负责协作风格，边界负责安全底线。对 OpenClaw 这类可以接 MCP、插件和自动化工具的 Agent 来说，提示词约束必须和工具权限叠加使用，才能既保持行为稳定，又不越界。
