玩了一夜 DeepSeek Harness，最直接的感受不是“又一个套壳工具”，而是像在《我的世界》里开了一张新图：没有固定主线，方块散落一地，但你能用很低的成本搭出自动化产线。把这种体验放到 AI 编程智能体上，事情就变得有意思了。



## 一、DeepSeek Harness 到底是什么

在软件工程里，harness 通常指测试、装配或评估框架。它不负责生产模型，而是给模型装上方向盘、刹车和仪表盘。DeepSeek Harness 并不是某一个官方产品的严格名称，更合理的理解是：围绕 DeepSeek 开源模型形成的编程代理与评估框架。它把 DeepSeek 模型接进类似 Claude Code 的终端代理模式：读取仓库、执行命令、修改文件、生成 commit。

它和 Claude Code 的定位差异很明显。

- Claude Code 是 Anthropic 官方发布的垂直产品，模型与工具链绑定更深，体验更接近“精装修的旗舰店”。
- DeepSeek Harness 更像开源世界的“工作台”，模型权重开放、接口透明、可本地部署，用户可以自己决定怎样组合工具。
- 从工程角度看，harness 层负责调度模型、管理上下文、执行工具调用、记录状态和恢复现场，这些正是 AI 编程智能体能否落地的关键。

## 二、为什么说它像《我的世界》



把 DeepSeek Harness 类比为《我的世界》，并不是说它变成了游戏，而是产品逻辑和生态逻辑非常相似。

- 开放世界，而不是线性关卡。Claude Code 更像精心设计的主题乐园，入口、路线、安全护栏都比较清晰；DeepSeek Harness 更接近开放沙盒，给你基础方块和红石，怎么建取决于你。没有唯一通关路线，也没有强制任务顺序。
- 方块化模块。Minecraft 里复杂装置由活塞、红石、漏斗组合而成。DeepSeek Harness 把模型调用、工具执行、上下文管理、检查点恢复拆成可替换模块，开发者可以像搭积木一样组装自己的编程流程。
- 低成本试错。在 Minecraft 里炸掉一座房子，损失的是几分钟；DeepSeek 的 API 价格相比 Anthropic 高端模型有明显数量级优势，本地部署甚至只消耗算力。这让大量笨拙、失败的尝试变得可承受，而试错恰恰是复杂系统涌现的前提。
- 社区 Mod 生态。Minecraft 的长期生命力很大程度来自 mod。DeepSeek 开源权重、采用 MIT 协议，开发者可以做量化、接私有工具、改模型行为，形成类似 mod 的扩展生态。
- 涌现式用法。红石电路不是官方设计的核心玩法，但玩家用它造出了计算器。类比过来，开发者用低成本 DeepSeek 模型堆出复杂 agent 流程，也会出现官方文档里没有写过的用法。

## 三、Claude Code 的护城河还在

如果只看价格和开源，很容易得出“Claude Code 药丸”的结论。但实际工程使用中，Claude Code 仍有几个不容易被替代的优势。

- 上下文管理更成熟。代码库索引、长对话压缩、工具输出截断，这些细节决定了长链路任务能否稳定跑完。Claude Code 在这方面的工程积累更深。
- 工具调用与安全边界更完整。权限控制、沙盒执行、敏感操作确认、审计追踪，对企业合规更友好。很多大型团队不敢把核心仓库交给一个没有清晰安全边界的代理。
- 模型生成质量仍然能打。在跨文件重构、复杂业务逻辑追踪等场景，Claude 高端模型的代码生成稳定性和长上下文理解依然是第一梯队。
- 但它的软肋也很明显：闭源、API 定价较高、定制空间有限。对于预算敏感或数据不能出域的场景，限制会越来越突出。

## 四、DeepSeek 的沙盒竞争逻辑

DeepSeek Harness 能形成讨论热度，底层还是模型能力、成本结构和开源生态的共同作用。

- 训练成本被大幅压缩。DeepSeek-V3 论文披露的训练成本约为 557.6 万美元，虽然这并不包括全部前期研究成本，但相比同代头部模型常见的训练开销，已经低了一个数量级。
- 推理定价更便宜。DeepSeek 的 API 价格与 Anthropic 高端模型相比有数量级优势，尤其适合大规模、重复性的代码生成和测试任务。
- 开源与本地部署。模型权重开放，企业可以在自己的 GPU 集群上跑，数据不出域。这对金融、医疗、政务等敏感场景有天然吸引力。
- 生态兼容性强。DeepSeek 模型可以跑在 vLLM、llama.cpp 等推理框架上，也能配合各种开源 agent 框架，像 Minecraft 里的不同 mod 加载器一样灵活。
- 但工程补课仍然必要。DeepSeek 模型在工具调用格式、指令跟随、长上下文稳定性等方面，还需要 harness 层做大量适配。开源只是把可能性打开，不等于开箱即用。

## 五、判断框架：别急着喊“干掉”



“干掉 Claude Code”这个说法更多是社区里的情绪表达。从技术演进看，两者并不是简单的替代关系，而是在不同约束条件下各占生态位。

- 任务剖面决定选型。高频小任务、预算敏感、私有化要求高的场景，DeepSeek Harness 的性价比优势明显；企业级合规、长链路重构、审计追踪要求高的场景，Claude Code 更稳。
- 公开 benchmark 只做参考。真实代码库的依赖复杂度、历史包袱和团队习惯，远比榜单分数重要。建立自己的回归评测集，才能判断一个工具是否适合。
- 沙盒验证再进生产。先在隔离环境跑通，重点监控 token 消耗、工具调用失败率、上下文遗忘和权限风险。不要因为“看起来能跑”就一步接入核心流水线。

三条冷思考：

1. 开源低价会拉低试错成本，但不会自动提高工程质量。便宜可以让你多试，但“试得多”不等于“试得对”。
2. Harness 的本质是“把模型变成工具”，真正的壁垒在工具链、反馈闭环和可恢复性，而不是单个模型的分数。
3. 未来更可能是多模型混合编排。Claude Code 负责高风险长链路，DeepSeek Harness 负责高频、低成本、可并行的“苦力活”，这比单打独斗更现实。
