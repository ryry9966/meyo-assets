过去一周，大模型圈几乎同时放出三张牌：DeepSeek V4 Pro 正式版、Grok 4.6、Claude Fable 5。三款模型发布时间高度重叠，让不少团队被迫在预算会里重新算一笔账：到底看总分，还是看单位智能成本？36kr 的消息把 DeepSeek 推到了前台。与前代相比，V4 Pro 更强调“生产可用性”，而不是单纯在一个公开榜单上刷新数字。这也是它敢直接对上 Grok 4.6、并逼近 Claude Fable 5 的原因。



## 1. 这场对撞，比的不是“谁分高”

先拆清楚三款模型的路线差异。

- DeepSeek V4 Pro：开源权重、MoE 架构、低推理成本，主攻私有化部署和 Agent 工作流。
- Grok 4.6：闭源、强绑定 X 平台实时数据，长于联网搜索和多模态输入。
- Claude Fable 5：闭源、注重长程任务与工具调用，企业级 Agent 场景表现稳定。

从目前流出的评测看，V4 Pro 在 MMLU-Pro 上约 82.7，GPQA Diamond 约 69.4，分别略高于 Grok 4.6 的 81.9 和 68.7，仅比 Claude Fable 5 的 83.1 和 70.2 低一个身位。这个差距在真实业务中，往往不如延迟和成本影响大。

如果只看总分，很容易得出“差一点就追上”的结论。但更有信息量的是三个模型在不同任务上的方差：V4 Pro 在代码补全、数学推理上更强，Fable 5 在浏览器操作和多步工具调用上更稳，Grok 4.6 在实时信息检索上占优。



## 2. DeepSeek V4 Pro 的技术底牌：不是更大，而是更薄

V4 Pro 没有走“参数膨胀换分数”的老路，而是把效率压得更薄。

- MoE 架构：外界推测总参数约 685B，每次推理激活约 37B。这样既保留了大规模知识容量，又降低了单次计算量。
- 稀疏注意力：在长上下文场景中，V4 Pro 对历史 token 做分层压缩，减少了 KV cache 占用，128K 上下文下显存压力明显下降。
- 混合精度与批处理：FP8 权重、动态 batching 和分页注意力配合，使高并发推理更稳定。
- 训练侧优化：据公开技术报告摘要，团队强化了代码、数学和 Agent 轨迹数据占比，并引入课程学习，减少早期训练中的低质量 token。

最直接的结果是价格。V4 Pro 每百万输入 tokens 约 0.15 美元，输出约 0.45 美元；对比同窗口的闭源模型，性价比优势明显。对一个每天跑 2000 万 tokens 的客服 Agent 系统来说，模型单价差一截，月底账单可能是数倍差别。



## 3. 正面对撞 Grok 4.6：实时数据与私有化部署的路线之争

Grok 4.6 和 DeepSeek V4 Pro 其实代表了两种相反的产品哲学。

- Grok 4.6 强在“外部信息入口”。它直接绑定 X 平台的数据流，对突发事件、社区讨论、实时检索有天然优势，适合舆情分析、快速信息抽取。
- V4 Pro 强在“内部可控系统”。开源权重意味着企业可以在自己的 VPC 或本地集群部署，数据不出域，模型也可以微调。

速度方面，Grok 4.6 在短查询场景下首 token 延迟更低，但长输出和高并发时波动较大。V4 Pro 在 batch 推理和长上下文任务中表现更稳，适合流水线式 Agent 调用。

一个典型例子：某团队需要每天对 50 万条用户反馈做结构化抽取。用 Grok 4.6，需要把数据发到第三方 API；用 V4 Pro，可以在自有 GPU 集群跑完，且成本更低。合规与成本，常常比跑分更早进入决策清单。



## 4. 逼近 Claude Fable 5：Agent 能力不只是“会调用工具”

Claude Fable 5 这代把 Agent 能力抬到了新高度，尤其是在多步推理、浏览器操作和失败恢复上。V4 Pro 的策略不是复制，而是选择高频场景做深。

- 轨迹强化学习：训练时大量使用真实 Agent 轨迹，不只奖励“最终答案正确”，还奖励“中间步骤可验证”，因此重试和纠错能力提升。
- 结构化输出：function calling 的 schema 遵循度更高，延迟抖动降低，适合需要稳定 JSON 输出的生产系统。
- 长任务完成率：在模拟 GitHub issue 修复任务中，V4 Pro 完成率约 68%，低于 Claude Fable 5 的 74%，但高于 Grok 4.6 的 61%。

需要注意的是，Agent 评测还没有统一标准。同一模型在不同评测集、不同环境下，完成率可能差 10 个点以上。公开数字可以作为筛选依据，不适合直接当作生产承诺。



最后，三款模型同台，很多团队第一反应是“赶紧切到最新”。但模型切换本身有成本，建议先做三件事。

1. 建立内部 eval 集：不要只看公开榜单。至少覆盖你业务中的 20 类真实任务，并记录准确率、拒答率、延迟和成本。
2. 算清单位智能成本：把缓存命中、重试次数、上下文增长、微调成本都摊进单次调用，再比较“每有效 token 成本”。
3. 验证合规与可替代性：V4 Pro 开源权重很有吸引力，但要确认商业使用条款、数据保密要求，以及未来版本是否可持续维护。

模型竞赛已经进入“系统能力”阶段。与其追最新版本，不如先把自己内部的评测和成本口径建好。毕竟，在一个月一更的节奏里，稳定性比单点领先更稀缺。
