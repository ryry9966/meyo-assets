## 背景

OpenClaw 作为 Agent 运行时，真正干活的边界很大程度取决于它能调用什么。内置工具能覆盖消息、文件、命令执行，但一旦需要查工单、发告警、操作数据库、调用内部系统，就必然要对接外部 API。

很多团队的第一反应是让 Agent 直接拼 HTTP 请求，比如在提示词里给一个 endpoint，让模型自己生成 URL 和参数。这条路在 demo 里能跑通，但上了真实环境很快就会撞上认证、Schema、错误处理、超时、权限边界等问题。

对接外部服务的核心不是“能通”，而是让外部 API 成为 Agent 可以安全、可观测、可降级使用的工具。

## 问题

直接让 Agent 拼 HTTP 请求有三个典型问题：

1. **模型生成 URL/参数不稳定**：query 编码、路径参数、分页参数容易出错，Agent 会反复试错。
2. **API 错误信息不经过翻译**：外部服务返回的 `401`、`429`、`500` 或网络超时，模型很难理解并修正。
3. **密钥和权限边界不清晰**：如果 key 或 token 出现在 prompt 或工具描述里，很容易泄露；同时模型可能误调用写操作，造成事故。

所以在 OpenClaw 里做对接，应该把“不可靠的自然语言动作”收敛成“可靠的函数调用”。

## 做法 / 步骤

### 1. 先定义边界

列清楚外部服务哪些端点需要暴露。只读优先，写操作单独拆开。不要为了通用性把整个 API 开放给 Agent。比如 GitLab 对接，先只开放 `GET /issues` 查 issue，不开放创建、关闭、修改。

### 2. 优先复用 MCP

如果 OpenClaw 已支持 MCP，先找现成的 MCP server。没有就写一个薄封装。MCP 的好处是 schema 明确，模型知道工具有哪些参数、参数类型是什么，不需要去猜 endpoint 结构。

### 3. 自己封装 Tool

如果走插件或自定义工具，按 JSON Schema 定义入参，输出固定结构。推荐统一返回：

```json
{
  "ok": true,
  "data": {},
  "error": null,
  "request_id": "req_01H..."
}
```

不要让模型接触原始 header、签名逻辑或完整 API 响应。工具层负责处理认证、超时、重试和分页。

例如对接 GitLab 查 issue，可以封装成 `get_open_issues`，入参是 `project_id`、`state`、`per_page`，输出只保留前 20 条，每条剪裁成 `iid`、`title`、`labels`、`author`、`url`，避免上下文爆炸。

### 4. 错误翻译

工具层要把 HTTP 状态码、超时、网络错误转成语义错误。例如：

- `401` → “API 凭证无效，请检查 GITLAB_TOKEN 环境变量”
- `429` → “请求被限流，稍后重试”
- `404` → “项目不存在或 token 无权限”

错误信息要给模型可操作的下一步，而不是只返回 `request failed`。

### 5. 超时与并发

设置合理超时。只读操作建议 5 秒左右，写操作可以放宽到 10 秒。限制单个 Agent 会话的并发调用数，避免一个慢 API 拖垮整个执行链路。

### 6. 先跑通再接入

先用 curl 或 Python 脚本验证外部 API 的认证、参数、返回结构，再接入 OpenClaw 做小范围调用测试。记录每次调用的 `request_id`、耗时、状态码和错误信息，方便排障。

## 踩坑点

- **大 JSON 直接塞给模型**：外部 API 返回上千条记录，模型上下文很快耗尽。工具层要限制返回条数或做摘要。
- **分页处理不当**：很多 API 默认只返回第一页，Agent 可能只看到部分数据。工具层要处理分页参数，或一次性拉取合并。
- **认证信息进 prompt**：key 写在提示词或工具描述里，很容易在日志、分享、截图里泄露。统一走环境变量或 secret store。
- **错误信息太粗**：只返回 `request failed`，模型无法修正，会重复犯同样的错误。
- **读写操作混在一起**：模型可能误触发删除、关闭、修改等危险操作。拆分工具并加确认步骤。

## 可复用建议

- 对接新 API 前，先写一个“工具契约”：输入、输出、错误码、超时、副作用。评审通过再开发。
- 用命名规范区分读写，例如 `get_*` 只读、`create_*` / `update_*` 写操作。
- 统一返回结构，并在 Agent 提示词里说明工具返回字段的含义。
- 用 mock server 或录制响应做回归测试，外部 API 变更时能快速发现。
- 监控调用耗时、失败率、限流情况，不要等用户说“Agent 坏了”才排查。

## 总结

Agent 对接外部 API 的本质，是把模型的自然语言动作收敛成可靠的函数调用。在 OpenClaw 里做得好的对接，不是把 endpoint 裸奔给模型，而是通过 MCP 或插件封装成有 schema、有错误语义、有边界的小工具。

先把接口约束在前，Agent 才能稳定执行。外部 API 不是给模型“自由发挥”的，而是给它一套经过工程化处理的工具接口。
