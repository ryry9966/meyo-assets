玩了一夜 DeepSeek Harness，最明显的感受不是“又一个终端 AI 助手”，而是它把编程智能体的搭建逻辑从「精装公寓」变成了《我的世界》式的开放沙盒。Claude Code 更像给你一套装修好的房间，冰箱、灶台、桌子位置都定好了；DeepSeek Harness 则像把红石、活塞、箱子和按钮丢在面前，让你自己拼出一条自动化产线。这种思路并非简单的界面变化，而是在重新划分 AI 编程工具的竞争维度。



## 一、为什么它像《我的世界》，而不是又一条 CLI



传统 CLI 式 AI 编程助手的工作模式接近线性：用户下达一句任务，模型生成计划，调用内置工具，返回结果。这个流程的效率很高，但扩展方式相对有限。DeepSeek Harness 的不同之处在于，它把「模型调用」「文件读写」「终端命令」「搜索服务」「MCP 工具」都抽象成一个个独立方块。每个方块只做一件事，暴露统一的输入、输出和权限接口。方块之间通过结构化的数据流连接，而不是依赖模型一次性生成整段脚本。

- 在 Minecraft 里，玩家不会按下一个“造房子”按钮，而是用方块合成墙、门、台阶。Harness 也一样，给你的是工具件，不是成品。
- 同一批方块可以拼出「读取 diff → 生成 review → 写回 PR 评论」，也可以拼出「生成代码 → 运行测试 → 自动修复」。
- 你可以自己注册 pytest runner 作为方块，接到代码生成后面，形成一个最小修复闭环；官方没支持某个框架时，不必等版本更新。
- 代价是上手门槛更高：需要理解每个方块的输入输出格式、失败模式和重试策略。

这个“开放沙盒”类比不是营销话术，而是对可组合性（composability）的直觉化表达。可组合性越高，基础能力不变的情况下，能搭出的工作流种类越多。

## 二、技术拆解：方块之间的“红石信号”如何流转



从内部看，Harness 的核心并不是神秘反射，而是一条可观测的事件循环：input → planner → tool router → executor → memory → next iteration。每一步都可以被日志、回放和重试。与 Minecraft 红石电路类似，方块之间传递的不是抽象承诺，而是结构化的执行结果；短路、延迟、信号丢失都能被定位。

- 工具注册：每个工具通过 JSON Schema 或 typed function 描述自己的能力，模型只负责输出 tool call，例如选择 run_terminal 或 read_file；Harness 负责真正执行，并把 observation 回填给模型。
- 状态管理：任务图（task graph）比简单的 TODO 列表更细粒度，能表示依赖、并行和条件分支。
- 上下文压缩：一些实现把 context compaction 和 memory 拆成独立方块。你可以在进入下一轮之前选择摘要策略、保留哪些文件、丢弃哪些历史。
- 可观测性：事件流像红石信号灯。一个失败任务可以快速判断是「模型选错工具」「工具返回超长」还是「终止条件写错」。

假设你要搭「本地 CI 修复回路」。流程是：代码生成方块输出 diff；测试方块运行 pytest；如果失败，错误信息作为 observation 返回模型；模型再次尝试，最多循环 5 次。这个回路在 Claude Code 里也可以做，但 Harness 把循环次数、失败回传格式、终止条件都暴露给用户，不用去猜内部 retry 逻辑。

## 三、Claude Code 与 Harness：封闭公寓与开放服务器的竞争



把两者摆在一起比较，并不是为了论证谁绝对更好，而是看清两种产品哲学。

- 任务建模：Claude Code 以会话和 TODO 列表为核心，适合连续对话式开发；Harness 以可组合 task graph 为核心，适合可复用、可编排的工程流程。
- 工具生态：Claude Code 官方工具链稳定，第三方扩展主要走 MCP；Harness 更像 mod 加载器，任何 Python/TypeScript function 包装成方块即可接入。
- 控制粒度：Claude Code 为降低门槛，隐藏了循环次数、上下文压缩和重试策略；Harness 把这些暴露出来，好处是能调，坏处是必须调。
- 商业模式：Harness 开源、本地可跑、模型可替换，天然对闭源订阅形成价格压力。

“干掉 Claude Code”这个说法有夸张成分，但逻辑链条不复杂：当工具链被拆成可替换积木，产品粘性会从某个封闭实现转移到生态和模型能力上。过去用户因为 Claude Code 好用而付费，未来用户可能因为 Harness 里已经积累了十几个顺手方块而留下。Claude Code 仍然在长程任务、错误恢复、安全边界上做得更稳，但开源模块化路线会持续压缩闭源集成方案的溢价空间。

## 四、冷思考：这块“乐高”并不适合所有人



可组合性从来不是免费的。《我的世界》里红石大触能造出计算器，普通玩家可能被一个活塞门卡到天亮。Harness 的复杂度同样值得警惕。

- 调试成本：方块越多，信号路径越长。一个失败可能由模型、工具、权限、循环条件共同造成，没有日志几乎无法排查。
- Token 成本：每个方块调用都消耗上下文窗口。把任务拆得过细，等于把预算烧在无效往返上。模块化不等于节省 token，有时候反而更贵。
- 生产稳定性：Claude Code 的封闭设计在错误恢复、安全确认、长任务记忆上经过大量打磨。Harness 适合愿意折腾的工程团队，而不是开箱即用的个人开发者。

实用建议：

1. 从最小闭环开始：先搭「生成 → 测试 → 修复」三步，只用一个测试框架，跑满 50 次再考虑扩展。
2. 把可观测性当默认项：记录每个方块的输入、输出、耗时和 token 消耗，否则复杂回路会迅速变成黑盒。
3. 混合使用而非站队：DeepSeek 做 planner，Claude 或 GPT 做 code reviewer，Harness 做调度器，这是当前性价比和稳定性都较高的组合。

AI 编程工具竞争的下半场，未必是比谁的模型参数更大，而是比谁能让开发者像搭积木一样，把模型能力、工具生态、执行环境自由组合。Harness 至少给了一条不同于 Claude Code 的路线。
