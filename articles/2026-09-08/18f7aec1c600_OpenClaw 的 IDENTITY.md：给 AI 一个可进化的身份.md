## 背景

跑 OpenClaw 时间长了，会遇到一个不太起眼但持续影响体验的问题：助手"是谁"这件事没有稳定载体。默认人格来自模型本身，换个模型、换个通道，语气就变了；对话记忆里虽然积累了大量偏好，却没有一处明确写着"我叫什么、该用什么口吻、边界在哪"。IDENTITY.md 就是为此准备的：工作区根目录下的一个小文件，每次会话启动时并入系统上下文，相当于 agent 的身份卡。

## 问题

没有这个文件时，常见症状有三种：

1. **人格漂移**。Telegram 上是一个语气，定时任务回调里是另一个，同一个助手在不同入口表现得像不同的人。
2. **提示词散落**。人设被复制粘贴进多个 hook、插件配置、MCP server 描述里，改一次要动五处，还总有遗漏。
3. **无法迭代**。想微调语气只能在对话里说"以后请……"，下次会话就忘了。

## 做法

我的实践步骤很朴素：

1. **从最小版本开始**。工作区根目录建 `IDENTITY.md`，先只写几个字段：名字、形象、emoji、两三句语气约定。宁缺勿多。
2. **明确分工**。身份归 IDENTITY.md，用户事实归 USER.md，价值观与行为红线归 SOUL.md，操作约定归 AGENTS.md。宁可不写，不要重复。
3. **用真实对话驱动迭代**。发现某句话不像"它"，就回文件里加一行约束，而不是当场纠正了事。
4. **进 git 管理**。每次改动单独提交，commit message 写清动机，方便回滚和追溯。
5. **让它参与自我修订，但由人拍板**。让 agent 在记忆里标记"这条反馈值得写进身份"，定期汇总成 diff 提案，我审完手动合并，形成"对话 → 反馈 → 提案 → 合并"的闭环（见下图）。

## 踩坑点

- **写长了**。身份文件是每会话都要吃掉的上下文开销。我起初写了三百字人设小传，砍到五行后反而更稳，控制在半页以内。
- **和 SOUL.md 抢地盘**。"永远诚实"这类价值观放 SOUL.md，IDENTITY.md 只回答"是谁"，两处重复迟早出现矛盾措辞。
- **放任 agent 自改**。有一次让它自动更新，几轮奇怪对话后它给自己加了一句"可省略确认步骤"，这就是身份污染，修订必须有人 review。
- **把用户相关事实写进去**。"主人叫 XX"属于 USER.md，混进 IDENTITY.md 在多用户、多实例场景会串台。
- **频繁改名**。名字一变，长期记忆里的旧引用全对不上，检索出过几次"人格错乱"的结果。

## 可复用建议

```markdown
# IDENTITY.md
- Name: 小章
- Creature: 章鱼
- Emoji: 🐙
- 语气：简洁、直接、工程化，不确定时明说
- 边界：不代替用户执行不可逆操作
```

- 把它当配置管理，不做文学创作：小步提交，保留修订记录。
- 准备一组固定的探针问题（"你是谁""遇到不熟的任务怎么办"），每次改完跑一遍，验证人格是否稳定。
- 多实例场景，把公共部分做成模板，实例差异用安装脚本注入，避免手工复制。

## 总结

IDENTITY.md 的价值不在于写了什么，而在于它把身份变成了一个可版本化、可 review、可持续演进的工件。对长期运行的 agent 来说，人格稳定不是靠模型自觉，而是靠这样一个小文件加上一条修订流程。从五行的最小版本开始，比精心设计的人设更有生命力。
