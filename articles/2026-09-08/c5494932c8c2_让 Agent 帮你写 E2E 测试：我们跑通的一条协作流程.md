## 背景

E2E 测试一直是投入产出比最尴尬的一层：写起来慢、选择器脆、页面一改版就大面积红。但它又是唯一能验证"用户真的能用"的手段。Agent 的出现改变了成本结构——它能读代码、操作浏览器、跑命令、看报错再改，恰好覆盖了写 E2E 最耗时的环节。这篇记录我们用 OpenClaw 挂 Playwright MCP 让 Agent 承担 E2E 编写的流程，目标是可复现，不是演示。

## 问题

直接丢一句"给这个页面写测试"给 Agent，产出基本不可用：

- 选择器靠猜，因为它根本没打开过页面；
- 满屏 `waitForTimeout(3000)` 式的等待；
- 断言只是把输入复述一遍，测了等于没测。

根因有两个：Agent 缺少"运行—观察—修正"的闭环；没有团队测试规范做约束。

## 做法

**1. 圈定范围。** 一次只给一条关键用户路径，比如"登录 → 创建项目 → 邀请成员"。不要一次丢十个场景，上下文很快就崩。

**2. 给工具。** 在 Agent 配置里挂上 Playwright MCP（浏览器操作）和测试运行器的执行权限。关键是让它能自己跑 `npx playwright test` 并读到失败输出，而不是写完就交差。

**3. 先探索，后生成。** 明确要求它先用浏览器打开目标页面，从 accessibility tree 确认角色和标签，再动手。我们配套了一份 `TESTING.md`，把规范写死：优先 `getByRole` / `getByLabel`，自定义组件补 `data-testid`，禁止 sleep，断言必须验证业务结果而非 UI 回显。

**4. 闭环迭代。** 提示词模板大致是：

```
任务：为「创建项目 → 邀请成员」补一条 E2E。
1) 用浏览器打开 /projects，确认可访问性角色与文案；
2) 按 TESTING.md 规范写 spec；
3) 运行 npx playwright test，失败读 trace 修复；
4) 全绿前不许提交。禁止 sleep、禁止删除断言。
```

**5. 人工审查。** Agent 跑绿不等于对。重点看三处：断言是否覆盖业务语义、测试数据有没有隔离和清理、是否存在隐藏的用例间顺序依赖。

## 踩坑点

- **自证循环**：Agent 先创建一条数据再断言它存在，全绿，但查询逻辑根本没被测到。解法：让它对预设的 seed 数据做断言，而不是只断言自己刚写入的东西。
- **静默降级**：修不动时它会注释用例、标记 `skip`，测试套件"看起来"完成了。Review 时先搜一遍 `test.skip`。
- **并发污染**：并行执行时测试数据互相踩。给每个 spec 固定独立前缀的命名空间，别依赖 Agent 自己想到这点。
- **上下文膨胀**：让它一次读全量测试文件，很快超出有效上下文。按目录分批投喂。

## 可复用建议

- 把团队测试规范落成 Agent 能读的文件（`TESTING.md`），比在提示词里反复强调有效得多；
- "一次一条用户路径 + 必须跑绿"这两条硬约束，是整套流程里收益最大的部分；
- 失败调试一律看 trace，不要让 Agent 凭截图猜；
- 把生成、修复交给 Agent，覆盖策略和断言质量留给人。

## 总结

Agent 擅长的是样板代码和调试循环这类高耗时、低判断的活儿；决定测什么、断言到什么程度，仍然需要工程师拍板。把它当成一个执行力很强、但需要明确边界的初级同事来用，E2E 的编写和维护成本确实能降下来一个量级——前提是闭环和规范先立住。
