## 背景

LLM 本身无状态。基于 OpenClaw 搭的 Agent，每次会话都从零开始：你得反复解释“我用 pnpm 不用 npm”“提交信息用中文”“时区 UTC+8"。上下文窗口再大也装不下全部历史，全文注入既贵又稀释注意力。记忆系统的目标不是“记住一切”，而是把**稳定的用户偏好**变成 Agent 每次启动就能读到的结构化上下文。

## 问题

三种常见做法，各有坑：

1. **全塞 system prompt**：偏好一多，注入 token 暴涨，一次性指令和长期偏好混在一起。
2. **只靠聊天历史检索**：近因偏差明显，三个月前的话基本检索不到，“记了但不用”。
3. **让模型自己决定记什么**：不稳定，同样对话有时记有时不记，行为不可复现。

## 做法

我们的方案是一个轻量 MCP memory server，核心四层：

1. **分层存储**
   - 工作记忆：当前会话上下文，不落盘；
   - 偏好库（语义记忆）：结构化条目，如 `commit_style: 中文, conventional-commits`；
   - 事件日志（情景记忆）：只追加的原始记录，用于事后挖掘重复模式。
2. **写入门槛**。满足其一才写入：用户显式声明（“以后都……”）；同一行为重复出现三次以上；用户纠正过模型行为。推断型记忆一律打低置信度标签。
3. **注入策略**。会话初始化时读取偏好库，只注入高置信、与当前任务相关的子集，预算控制在 500 token 以内。偏好是有限可枚举的，不必上向量检索，全量读 + 过滤反而更稳。
4. **更新与遗忘**。新偏好覆盖旧偏好，保留 version 字段；低置信且 30 天未命中的条目自动降级；提供 `memory_forget` 工具支持显式删除。

存储层用一个人可读的 `MEMORY.md`，每条记忆带 source / confidence / scope / updated_at / hits 元数据。

## 踩坑点

- **一次性指令污染**：“这次用 Python 写”被存成“用户偏好 Python"。必须区分 scope（global / project / once），once 类型不进长期库。
- **写入了但从不注入**：忘了在 session 初始化时读取。建议加观测，记录每次实际注入了哪些条目，否则记忆系统等于摆设。
- **冲突不处理导致行为抖动**：新旧偏好并存时模型随机听哪个。覆盖逻辑必须显式，不能指望模型自己权衡。
- **记忆文件进了公共仓库**：偏好常带个人信息，memory 文件要 gitignore，或放本地配置目录。

## 可复用建议

- **人可读可编辑是第一优先级**：`MEMORY.md` 让用户直接改，是最快的 debug 手段。
- **写入前先查重和冲突检测**，别无脑 append。
- **注入预算设死**：超了就按 confidence × recency 排序截断，宁缺毋滥。
- **规则兜底 + LLM 分工**：“要不要记”用规则判断，“记成什么”才交给模型总结，确定性场景别交给概率。

## 总结

记忆系统的核心不是存得多，而是**存得准、取得对、改得动**。分层存储解决“记什么”，写入门槛解决“何时记”，注入预算解决“怎么用”，版本化与遗忘机制解决“怎么改”。建议先用几十行代码的 MCP server 加一个 Markdown 文件跑起来，观察两周命中率，再决定是否引入向量库——大多数个人助理场景，根本用不到那么重。
