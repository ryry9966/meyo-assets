## 背景

用 Agent 做日常开发和自动化的频率上来之后，最耗时间的不是写指令，而是反复交代背景：主力语言是什么、回复要中文还是英文、哪些目录不许动。每个新会话都得来一遍。

OpenClaw 的记忆机制能记住一部分，但记忆是概率性的——它可能某次想得起你用 pnpm，下次就想不起来。而 workspace 文件注入是确定性的，每个会话必然生效。USER.md 做的事，就是把“我是谁”从概率性记忆挪到确定性配置里。

在 OpenClaw 的 workspace 约定里，AGENTS.md 告诉 Agent 怎么干活，USER.md 告诉它在为谁干活。两者分工不同，别混着写。

## 问题

没有用户档案时，Agent 的默认行为是“面向所有人”：

- 输出风格跑偏：要结论的人收到三段客套；
- 环境假设错误：默认 Python，实际是 Go/TS；
- 越界操作：在明确不想被碰的路径里动手；
- 重复烧 token：同样的自我介绍写了几十遍。

MEMORY.md 记录的是 Agent 积累的二手观察，零散且可能过期。USER.md 是你主动声明的一手事实，优先级应该更高。

## 做法

**1. 建文件。** workspace 目录（默认 `~/.openclaw/workspace`）下创建 USER.md，会话启动时自动注入上下文。

**2. 按固定分区写，控制在 300 字以内。** 我的版本：

```markdown
# 关于我
- 角色：后端为主，少量前端；主语言 Go / TypeScript
- 环境：macOS + Linux 服务器；包管理 pnpm；shell 是 zsh
- 偏好：回复用中文，先给结论再展开；代码不写无谓注释
- 红线：不自动执行删除类命令；不修改 ~/.ssh 下任何文件
- 沟通：直接指出方案问题，不要铺垫和恭维
```

**3. 进版本管理。** 放进 dotfiles 仓库，多机之间 symlink，改动能追溯。

**4. 建立迭代规则。** 我的标准是“同样的错犯两次就写进去”：Agent 第二次犯同一个错，当场把纠正落成 USER.md 里的一行，而不是只在会话里抱怨一句。

## 踩坑点

- **写成简历。** Agent 不关心你的履历，关心怎么和你协作。写行为约束，别写生平。
- **太长。** USER.md 每个会话都占上下文，超过一屏就开始稀释有效信息，还会挤压其他注入文件。
- **稳定信息和易变信息混放。** “本周在赶的版本”两周就过期，过期档案比没有更糟——它会变成持久化的错误先验。易变状态我单独放 STATE.md，按需更新。
- **塞敏感信息。** 它会进入每一次会话，密钥、内网地址、客户数据一概不放。
- **所有 Agent 共用一份。** 编排类和编码类 Agent 需要的“你”不一样，按场景拆成片段再拼接注入更干净。

## 可复用建议

- 把 USER.md 当配置而不是文档：有分区结构、有 review、进 git；
- 分层：全局档案放通用偏好，项目级上下文放各仓库自己的 AGENTS.md，两者不重复；
- 每月回顾一次，删掉不再成立的条目——过期条目的危害大于缺失；
- 多客户端场景可以把同一份档案通过 MCP resource 挂载复用，避免多处维护；
- 团队场景：仓库里放“团队约定”，个人 USER.md 只放“个人偏好”，避免把个人习惯强加给协作者。

## 总结

USER.md 便宜、确定性、可版本管理，解决的不是“Agent 聪不聪明”，而是“Agent 是否在正确的默认值上工作”。半小时写第一版，之后每次被惹烦就补一行，两三周后新会话里的铺垫会明显变少——这份文件本身，就是你和 Agent 协作风格的沉淀。
