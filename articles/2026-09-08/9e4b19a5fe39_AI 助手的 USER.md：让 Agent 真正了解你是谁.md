## 背景

用 OpenClaw 这类长期运行的 Agent，有一个明显的体验断层：system prompt 是通用的，每个会话开始时，它其实并不认识你。于是同样的偏好要反复声明——"用 pnpm 不是 npm"、"回复别堆 emoji"、"我的服务器是 Ubuntu 22.04"。

OpenClaw 的 workspace 里有一个专门解决这个问题的文件：`USER.md`。它在每次会话启动时被注入上下文，职责很单一——持久化地描述"你是谁"。它和另外两个文件分工明确：`SOUL.md` 定义 Agent 的人格与语气，`AGENTS.md` 定义工程协作约定，`USER.md` 是唯一站在你这一侧的配置。

## 问题

没有它，代价不是"不够智能"，而是低效和不可靠：

- 每个新会话都是冷启动，偏好靠运气；
- 口头交代过的上下文，换个设备、重置会话就丢；
- 临时写进对话的约定，无法被后续会话引用。

## 做法

**1. 建文件。** 在 workspace 根目录创建 `USER.md`（路径以你的部署为准）。

**2. 分节写，每节只放"能改变 Agent 行为"的事实。** 推荐骨架：

```markdown
# 关于我
- 称呼：老周；时区 UTC+8；技术交流默认中文

# 技术环境
- 主语言 TypeScript / Python；包管理器 pnpm / uv
- 部署：自托管 Docker，Ubuntu 22.04

# 协作偏好
- 先给结论再给推理；代码示例优先可运行
- 不确定的 API 版本直接问我，不要猜

# 红线
- 不要自动 git commit；不要引入我未使用的框架
```

**3. 控制长度。** 建议压在 40 行以内。它是每次会话的固定开销，也是指令源——越长越容易自相矛盾。

**4. 建立维护机制。** 两件事：
- 对话中直接说"把这一点记进 USER.md"，让 Agent 自己追加；
- 每隔几周 `git diff` 一次，删掉过期条目。

## 踩坑点

- **写成简历。** "热爱技术、追求卓越"没有信息量；"只用 pnpm"才有。写可操作的事实，不写自我评价。
- **敏感信息明文。** USER.md 会随每次请求送出，密钥、住址、真实身份信息一律不要放。
- **越写越长。** 150 行的 USER.md 等于给每次会话上 token 税，且旧指令会和新增指令打架。要定期删。
- **全局一份走天下。** 个人偏好放全局 USER.md，项目差异（框架版本、分支规范）写项目级 `AGENTS.md` 覆盖。
- **过期信息比没有更糟。** 我删过一条"测试用 Jest"，在那之前 Agent 一直拒绝帮我迁移到 Vitest。

## 可复用建议

- 检验标准：这一条删掉后，Agent 的行为会变差吗？不会就删。
- 身份与状态分离：稳定事实进 USER.md，任务进度交给 memory，不要混写。
- 用 git 管理 workspace，变更可回溯，也方便多设备同步。
- 新环境从模板 fork 起步，不要每次从零回忆。

## 总结

USER.md 的本质，是把"让 Agent 了解你"从重复劳动变成一次性资产。它不神秘：十几行可操作的事实，加上一条维护纪律，就能把每次会话的冷启动成本降到接近零。写它花掉的时间，会在之后的每一次对话里还给你。
