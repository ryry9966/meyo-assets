# HEARTBEAT.md 实践：让 Agent 主动干活，而不是等你提问

## 背景

大多数人对 Agent 的使用模型是"拉"式的：你想起来，去问一句，它答一次。但真正有价值的很多事不是你提问时才发生的——磁盘快满了、证书快过期、每日汇总还没人做。OpenClaw 跑在常驻机器上，天然具备"守着事情"的条件。它内置的 heartbeat 机制就是为此设计的：守护进程按固定间隔唤醒 Agent，Agent 先读工作区里的 HEARTBEAT.md，有活干活，没活保持沉默。

## 问题

把主动权交给 Agent，有三个前提缺一不可：**触发器**（定时唤醒）、**任务源**（事情写在哪）、**静默纪律**（没事别说话）。前两条好解决，第三条最容易被忽略——如果没有"默认安静"的约定，每次心跳都往群里推消息，你会在三天内亲手关掉这个功能。

## 做法

1. **配置间隔**。在 OpenClaw 配置里设置 heartbeat 间隔，建议从 30 分钟起步，跑一周看日志再调。
2. **写 HEARTBEAT.md**。放在 workspace 根目录（默认 `~/.openclaw/workspace/`），内容就是一份人能读懂的清单。关键是每条任务写成"可判定条件 + 越限动作"：

```markdown
- 检查磁盘：根分区使用率超过 80% 才通知我，附 df 输出
- 每天上午 9 点后的第一次心跳，汇总昨日 GitHub 通知，发到私聊
- 同一问题已提醒且未处理过，不要重复提醒
```

3. **利用 HEARTBEAT_OK 约定**。没有可做的事时，Agent 内部返回 HEARTBEAT_OK，网关不向任何频道推消息。这条是整个机制能长期开着的生命线。
4. **心跳里只做"检查 + 派发"**。重量级任务（跑测试、爬数据、长报告）不要同步做在心跳会话里，心跳判断条件满足后交给后台任务或子会话执行。

## 踩坑点

- **任务写得太模糊**。"帮我看看有什么新鲜的"会导致每次心跳产生随机动作，噪音比故障还烦。
- **不幂等**。同一告警每 30 分钟推一次。解法：让 Agent 把"已提醒"状态写进一个状态文件，心跳时先读再判断。
- **夜间轰炸**。凌晨三点照样推消息。在 HEARTBEAT.md 里显式写时间窗，比如"23:00–08:00 只记录不通知"。
- **频率与成本**。心跳本质是周期性调用 LLM，间隔越密 token 消耗越高，低价值任务不值得 5 分钟一跳。
- **明文文件的安全边界**。HEARTBEAT.md 是工作区明文，别把密钥写进去；建议纳入 git，改了什么任务有据可查。

## 可复用建议

把 HEARTBEAT.md 理解成"声明式的 cron + 判断逻辑"。crontab 只会按时执行，做不了"超过阈值才说话""处理过就别再说"这类判断，而这恰好是 LLM 擅长的。任务建议分三类固定写法：

- **巡检类**：越限才报，平时安静；
- **汇总类**：每日/每周固定一次，绑定时间窗；
- **watch 类**：出现特定事件才说话，且记录去重状态。

每类套同一个模板，动作尽量落到已有 skills 或 MCP 工具上，不让 Agent 每次自由发挥，行为就可控了。

## 总结

HEARTBEAT.md 是个很小的文件，但它把交互模型从"你拉 Agent"变成"Agent 值班"。让它能长期运转的工程要点其实只有三条：**条件可判定、默认静默、动作幂等**。做到这三条，它是一个安静的值班员；做不到，它就是一个每小时骚扰你的群成员。
