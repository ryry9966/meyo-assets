过去十年，企业协作工具上演着一场看似无解的“入口战争”：钉钉要做企业级操作系统的超级 App，飞书要成为承载所有工作流的“All in One”平台，甚至连浏览器、邮件客户端、即时通讯都曾试图把一切功能揽入自己的界面。不管用户愿不愿意，谁的客户端被打开的次数多、停留时间长，谁就握着分发能力的权杖。然而，随着 WorkBuddy 这类以任务为中心的跨平台智能体跑出来，钉钉和飞书突然不再强调首页的 DAU 了，反而主动把功能拆成 API，让智能体在背后调度。这背后不是一句简单的“格局大了”能解释的，而是一次协作范式的底层重构。



## 从“入口霸权”到“工具平权”：办公协作的七年之痒

2015 年钉钉诞生时，To B 赛道的共识是用一个超级 App 吃掉所有企业服务。这种逻辑来自消费互联网的路径依赖：谁的日活高，谁就是生态链的顶端。于是钉钉塞进了审批、考勤、日志、视频会议、应用中心，飞书也在文档、多维表格、妙记里追求无缝闭环。入口即权力，界面即生意。

- **超级 App 的代价**：随着功能膨胀，用户体验逐渐走向“千层饼”。在钉钉或飞书里完成一项简单任务（比如发起一次跨部门周会）可能需要在 5 个模块间跳转，学习成本陡升。
- **员工的反抗**：终端用户开始偷偷用第三方轻量工具组合，比如用 Notion 写会议纪要，再用 Slack 提醒，最后手动同步到日历。这种“影子 IT”现象说明，员工要的不是一个万能入口，而是以自己任务为中心的顺畅路径。
- **产业逻辑的转向**：2023 年后，大模型让 AI Agent 的商业化成为可能。如果一个智能体可以在后台理解意图、拆解步骤、调用任何一家软件的 API，那么用户根本不需要打开哪个固定的 App——他只需要一个对话窗口或一个悬浮球。入口的定义从“人找功能”变成了“任务找人”。

这时，WorkBuddy 这一类产品出现了。它不像一个传统软件，而像一层横跨在钉钉、飞书、邮件、网盘之上的任务编排层。入口执念，第一次被技术釜底抽薪。



## WorkBuddy 解构：不是又一个 AI 助手，而是跨平台任务编排器

如果只看宣传语，很容易把 WorkBuddy 当成 ChatGPT 的办公套壳，或者高级 RPA。但实际上它的定位更接近一个以自然语言驱动的“工作伴侣”。

- **核心架构**：WorkBuddy 底层通常由一个 LLM（大语言模型）作为推理引擎，搭配一个任务分解中间件和一个 API 网关。用户输入“帮我在飞书约个下周三下午的全员评审会，把时间空出来，并在钉钉群发通知”，它不会简单回复一句话，而是执行一系列操作：
  1. 意图识别：找到“飞书日历”“钉钉群消息”两个执行对象。
  2. 任务拆解：查询所有参会者日历空闲时间 → 预定会议 → 生成会议详情 → 调用钉钉机器人发送群消息。
  3. 异常处理：如果某位同事日历冲突，自动发起一次协商，而不是粗暴占用。
- **与传统自动化工具的差异**：RPA 靠录屏和 UI 抓取，脆弱且维护成本高；低代码平台需要人工定义规则。WorkBuddy 利用了 LLM 的理解能力和 Plugin/Function Call 机制，只要有 API 文档，它就能动态对接。这意味着它不需要钉钉或飞书改变任何界面，只需要提供标准化接口。
- **入口的溶解**：用户交互场所回归到操作系统级——一个快捷键、一声唤醒词、一个悬浮图标，甚至直接利用 Apple Intelligence 或 Copilot 的系统级接入。这时，谁再强调自家的 App 首页有多少按钮已经毫无意义，因为用户根本不会点开它。

这种架构本质上把协作软件“后台化”了。钉钉飞书的短信通知、日程同步、文档权限等功能变成了可被调用的微服务，而 WorkBuddy 成了前台的唯一接触点。这正是入口执念瓦解的底层技术原因。



## 钉钉与飞书的“放下”：开放 API 与 Agent 插件策略

如果你留意钉钉和飞书近半年的产品迭代，会发现一个微妙的变化：开放平台的权重被提到了历史最高，而客户端功能的堆砌明显降速。

- **钉钉的“魔法棒”与连接器**：2024 年钉钉全面拥抱 AI Agent，推出了“AI 助理市场”，并允许开发者调用钉钉内部的考勤、文档、审批等原子能力。其宣传口径不再是“所有事在钉钉完成”，而是“一切服务皆可被 AI 调用，无论在不在钉钉内”。
- **飞书的“连接”战略**：飞书开放了大量 Webhook 和 API，比如通过飞书机器人对外暴露消息通道，允许 WorkBuddy 这样的外部智能体直接操控飞书的群聊、日历、云文档。飞书甚至提供了一种“飞书之外的任务卡片”格式，让用户在第三方工具里也能获得与飞书内一致的交互体验。
- **商业逻辑的重构**：过去软件靠日活收广告或卖应用分成，现在它们意识到，企业愿意为 AI 调用的算力和服务买单。钉钉和飞书不再争做用户的“第一屏”，而是争做“被调用最多的能力后台”。这有点像亚马逊 AWS 的策略：让第三方软件在自己之上生长，自己收取计算和存储费用。入口让位于能力，反而打开了更大的收入天花板。

“放下”并不是情怀，而是一笔更精明的算账。当 WorkBuddy 每调度一次钉钉的审批，钉钉就能收取一次 API 调用费用或沉淀流程数据，这才是更具黏性的商业模式。



## 入口消亡后，协作的下一步是什么？

既然入口不再是竞争焦点，从业者和团队管理者应该警惕哪些新坑，又该如何利用这个转折？

- **新的异构挑战**：没有统一入口后，员工会在 WorkBuddy、钉钉弹窗、飞书通知、邮件里交叉处理任务。如果缺乏统一的意图记录与状态同步，可能出现“AI 帮你约了一个会，但你却找不到会议入口”的尴尬。于是，团队需要建立一套围绕任务 ID 的跨平台追踪规范，例如在飞书多维表格或专业项目管理工具中维护一张唯一的任务主表。
- **安全与权限的隐忧**：当 WorkBuddy 可以跨平台替你审批报销、发送文件时，它的权限边界必须在管理员层面清晰定义。否则一次提示注入攻击可能导致批量发送错误信息。钉钉和飞书正在引入更细粒度的 Scope 控制，但集成还是需要团队自行深度配置。
- **组织技能的迁移**：超级 App 时代，能力考核的是“会不会用钉钉的审批控件”；AI 编排时代，能力变成“能否设计一条清晰的任务分解逻辑让 WorkBuddy 执行”。管理者需要培养团队用自然语言描述业务流程，并验证智能体输出质量，这是一种新型数字素养。

总之，入口执念的消散，不是巨头的退让，而是整个行业从界面层的竞争转向了智能层的竞争。WorkBuddy 只是这波浪潮中的一个信号——未来的办公协作，将不再是“我在钉钉里做完了所有事”，而是“我一件事都没打开钉钉，但所有事都做完了”。



### 给团队的三条冷思考

1. **别再纠结日活，去关心任务闭环率**：衡量工具好坏的标准，应该从“多少人每天打开 App”变为“从任务发起到完成，平均经历几次界面切换”。WorkBuddy 能大幅降低这个切换次数，但需要团队提前整理好业务 API 的可用性。
2. **为你的公司建一个“能力目录”**：把审批、通知、文件权限等能力抽象成可被 AI 调用的服务清单，并配上清晰的权限说明。这会让 WorkBuddy 这类智能体的接入更顺畅，而不是每次都让 AI 去猜测哪个接口能干什么。
3. **保留人类决策的仲裁权**：智能体编排带来效率，但完全自动化的审批或沟通可能引发信任危机。关键节点（如合同签署、敏感群发）必须留存人工确认步骤，形成“AI 编排 + 人类校对”的双环机制。
