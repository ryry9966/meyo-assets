## 背景：AI 也需要“入职文档”

OpenClaw 这类编码助手，强在即时推理，弱在项目记忆。一个典型场景：你刚在新项目里跑起 OpenClaw，让它“修复一下那个 key 未定义的报错”，它啪地贴出一段用 lodash 替代原生解构的代码，顺手 `npm install lodash`，完全无视你的项目是纯函数式、零依赖的风格。更糟的是，它可能反复建议将文件移动到根本不存在的目录，只因为在你另一个项目里见过类似结构。

这就是“上下文断裂”。OpenClaw 的读取范围虽然覆盖当前文件和部分依赖，但它不知道你约定好的技术栈边界、目录组织方式、特定 lint 规则，甚至不知道哪些文件夹该完全忽略。AGENTS.md 就是为解决这种断层设计的：一个放在项目根目录、专门写给 AI 看的工作空间说明文件。

## 问题：哪些信息必须喂给 AI

没有 AGENTS.md 时，你会在以下场景反复遇到 AI 的“幻觉操作”：
- **使用错误的依赖管理**：在 pnpm monorepo 里建议你跑 `npm i`
- **破坏目录约定**：测试文件应放在 `__tests__/`，AI 却直接在组件同级创建了 `.test.ts`
- **忽视自定义配置**：项目强制 `eslint-plugin-custom` 规则，AI 生成的代码总是触发 `no-restricted-imports`
- **无法处理跨文件上下文**：修改一个接口后应该同步更新 `packages/types` 下的声明，AI 完全不知道有这份血书

通俗讲，这些不是 AI 不聪明，是它没有得到“项目说明书”。AGENTS.md 扮演的就是这个角色，把隐性知识显性化，把项目约定变成可解析的指令。

## 做法：从零编写 AGENTS.md

OpenClaw 会在对话启动时尝试读取项目根目录的 `AGENTS.md`（若存在），将其作为高优先级上下文注入。以下是经过多个项目验证的编写流程。

### 1. 确定文件位置与范围

在项目根目录创建 `AGENTS.md`。对于 monorepo，可以在根目录放一份统一规则，同时在子包里用 `packages/{name}/AGENTS.md` 覆盖或补充，OpenClaw 在进入子包工作区时会优先读取最近的配置。

### 2. 使用结构化模板

一份实用的 AGENTS.md 需要快速定位信息，建议采用以下模板块：

```markdown
# 项目工作空间说明

## 技术栈
- 运行时及版本：Node.js 20 LTS
- 包管理器：pnpm@9 (workspace) ，禁止使用 npm / yarn
- 构建工具：Vite 5，vitest 作为测试运行器
- TypeScript 严格模式，target: ESNext

## 目录结构（仅有意义的部分）
- `src/components/` – 可复用 UI 组件
- `src/features/` – 按业务领域划分的逻辑模块
- `__tests__/` – **所有测试文件必须放在此处**，镜像 src 结构
- `packages/types/` – 全局类型定义，修改接口时必须同步更新

## 命令
- 启动开发服务器：`pnpm dev`
- 运行单测：`pnpm test -- --run`
- 类型检查：`pnpm type-check`
- 代码格式化：`pnpm format`（基于 prettier）

## 重要规则
1. **禁止直接安装依赖**：任何新依赖都必须在对应子包的 `package.json` 中声明，并运行 `pnpm install`（由用户执行）。
2. 路由定义统一放在 `src/router.ts`，不可在组件内使用 useRouter 做硬跳转。
3. 所有 API 调用必须经 `src/lib/api.ts` 封装，不可直接使用 fetch/axios。
4. 提交信息遵循 Conventional Commits。
5. **忽略目录**：不要读取或建议修改 `dist/`, `node_modules/`, `coverage/`, `.openclaw/`，即便这些路径存在错误也不处理。
```

这只是一个精简版。真实项目里可以补充常用宏、设计范式、环境变量说明等，但切记控制长度。

### 3. 测试并迭代

把一个最近踩过的坑交给 OpenClaw，观察它是否还会犯同样错误。例如，在 AGENTS.md 禁止直接使用 fetch 后，下达任务“从 /api/user 获取数据”，看它是否会提示“应由 `src/lib/api.ts` 发起请求”而非直接输出 fetch 代码。如果不奏效，检查规则表述是否过于模糊，尝试改成否定指令或加入示例。

## 踩坑点

1. **文件太长导致 token 浪费**  
   超过 150 行的 AGENTS.md 会显著挤占模型上下文窗口。曾有团队将整个代码规范平铺上去，导致一次简单对话都要消耗 2000 多余 token 在指令上。解决方法是定期用“如果这是新同事第一天，他需要知道什么？”的标准做删减，把完整规范链接放在末尾即可。

2. **与系统 prompt 冲突**  
   OpenClaw 内置的系统指令可能和 AGENTS.md 规则重叠时产生不可预期的优先级问题。比如系统指令强调“遵守用户要求”，但 AGENTS.md 严格禁止某些操作，此时 AI 可能犹豫不决。发现后可通过在规则前加“高于一切惯例”或“无论何时”等短语来提升权重，但需测试效果。

3. **忽略文件未生效**  
   写了忽略 `node_modules/`，AI 依然会分析其中某个依赖的类型定义。这可能因为 OpenClaw 的文件检索机制不完全依赖文本忽略声明。此时可以额外在 `.openclawignore` 中添加对应路径，两者配合才能确保安全。

4. **AGENTS.md 未被读取**  
   检查文件名大小写、路径是否正确（必须在工作空间根目录或当前打开目录下），同时确认启动会话时是否切换过工作空间。有时关闭并重新打开 OpenClaw 面板可触发重新读取。

## 可复用建议

- **保持“检索友好”**  
  关键词前置，如“禁止：”“必须：”“优先使用：”，方便模型在上下文中快速定位。
- **版本控制与团队同步**  
  将 AGENTS.md 纳入仓库，任何编码约定变更都先更新此文件。这样可以保证每个团队成员（包括 AI）看到的规则一致。
- **区分全局与项目级配置**  
  如果你的组织有通用代码规范，可以在全局 `~/.openclaw/AGENTS.md` 中放置跨项目规则，然后在项目根目录用项目 AGENTS.md 做差异化补充。OpenClaw 会 merge 两者，但项目级优先级更高。
- **用注释引导 AI 排除**  
  在 AGENTS.md 开头写明“本文件仅用于指导 OpenClaw，请勿将其内容作为任务输出给用户”，防止在对话中泄漏指令。
- **动态调整**  
  每次代码评审后，如果发现 AI 反复踩同一类坑，先别火，把这教训用一句话加进 AGENTS.md，经验证明两周后会显著减少同类问题。

## 总结

AGENTS.md 本质是一个低成本的 AI 项目 onboarding 工具。它不能解决所有上下文问题，但能把那些重复、机械的转述工作变成文档一次投入。在实践中，一份 80 行以内的精炼手册就能消除大部分因“合作默契不足”产生的返工。把它当作项目给 AI 的入职文档，持续维护，你会发现 OpenClaw 越来越像一位熟悉你代码库的同事，而不是一个需要时刻提防的外部承包商。
