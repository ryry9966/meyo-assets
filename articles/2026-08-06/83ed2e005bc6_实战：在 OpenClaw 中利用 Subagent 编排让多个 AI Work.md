## 背景：为什么需要 Subagent 并行

在自动化任务里，单个 Agent 的串行执行是明显的瓶颈。比如你需要分析一份长文档、同时爬取几个网站信息、再汇总成报告，如果由主 Agent 一步步做，时间线性累加，且每一步的等待都会放大 LLM 延迟。更重要是，许多子任务之间没有依赖关系，天然适合并行。

OpenClaw 作为 MCP 亲和型 Agent 框架，提供了工具调用（Tool Calling）与外部进程交互的能力。我们可以利用这些基础能力，构建一个主 Agent + 多个 Subagent 的编排模式，将任务拆解成一批 Worker，并行执行，最后汇总结果。这种模式在小规模自动化（如数据抓取、多源对比、批量文件处理）中非常实用，工程成本可控。

## 问题拆解

假设这样一个真实需求：对五个竞品官网进行结构化信息提取，包括产品名、价格、核心特性，并输出对比表格。单一 Agent 只能逐个网站调用爬虫工具，等待每次 LLM 生成爬取策略，耗时可能超过 3 分钟。而并行方案可以将五个网站分析任务同时分发给 5 个 Subagent，每个只负责一个站点，最后合并。

技术挑战在于：
1. **如何拆分任务并分发给 Subagent**  
2. **Subagent 如何感知自己的职责并独立执行工具调用**  
3. **如何管理并发与结果收集**  
4. **如何保证工具资源不冲突（如浏览器实例、MCP 连接数）**

## 实现方案（基于 OpenClaw）

我们使用 OpenClaw 的 `create_subagent` 工具（实际可能是对底层 Agent 类的一次封装，传入独立会话与工具集），并在 Python 异步环境中并行调用。

### 步骤

**1. 定义子任务模板**  
主 Agent 首先分析输入，生成子任务列表，每个子任务包含明确的 prompt 和允许使用的工具集（如 `web_fetch`、`dom_extract`）。子任务声明使用统一的 Schema，便于 Subagent 解析。  
```json
{
  "id": "competitor_1",
  "goal": "提取 https://example.com 的产品名、价格、特性",
  "tools": ["web_fetch", "html_to_text"]
}
```

**2. 实现 Subagent 工厂**  
创建一个异步函数 `run_subagent(task)`，内部初始化一个新的 Agent 会话，注入任务目标和工具。注意避免复用主 Agent 的对话历史，保持上下文隔离。使用 OpenClaw 的 `Agent.run()` 方法，监听工具调用事件并记录日志。

**3. 并发调度**  
主 Agent 利用 `asyncio.gather` 并发启动所有 Subagent，并设置超时（如单个子任务 45 秒）。同时维护一个任务状态字典，用于追踪完成/失败/超时。  
```python
tasks = [run_subagent(t) for t in subtasks]
results = await asyncio.gather(*tasks, return_exceptions=True)
```

**4. 结果汇聚与再处理**  
收集结果后，主 Agent 对每个子任务输出做格式校验（如是否返回合法 JSON），丢弃失败或超时的部分，然后调用一次汇总 LLM 生成最终对比表格。汇总阶段只处理摘要信息，避免二次长上下文。

### 关键踩坑点

**踩坑 1：工具状态冲突**  
如果 Subagent 共用同一个浏览器实例或 MCP 连接，很容易出现 Cookie 污染、页面跳转冲突。解决方式是每个 Subagent 使用隔离的工具实例（如单独的无头浏览器上下文），或者对共享工具加分布式锁。我们在实践中为 `web_fetch` 工具实现了一个连接池，限制最大并发为 3，超出时排队，避免目标站点反爬。

**踩坑 2：MCP 连接数爆炸**  
每个 Subagent 可能开启自己的 MCP Client 连接远程服务。并发 10 个 Subagent 时，远程 MCP Server 可能拒绝连接。解决方案：一是限制并发数（信号量控制）；二是在主 Agent 层面预取共享上下文，将必要数据通过参数传入 Subagent 而不是让它们自己调 MCP。

**踩坑 3：结果非结构化**  
Subagent 返回的自然语言文本难以直接用于下一步处理。需要强制要求 Subagent 以特定结构（如 JSON 代码块）输出，并在汇聚时做解析重试。我们设计了 `final_report` 工具，它只接受一个 JSON 对象作为参数，从而迫使 Subagent 按规定格式输出。

**踩坑 4：超时与无限等待**  
个别子任务可能因为网络或 LLM 幻觉而长时间挂起，拖累整体。必须设置严格的超时（如 `asyncio.wait_for`），超出后主动抛出异常并标记失败，主流程不应卡死。

## 可复用建议

- **任务拆分尽量细粒度且无依赖**：高内聚的子任务能让 Subagent 专注，减少内部对话轮次。  
- **统一数据交换协议**：定义输入/输出的 JSON Schema，主 Agent 和 Subagent 都遵守。可在 tool description 中明确要求输出格式。  
- **限制并发，设计降级**：信号量限制同时运行 Subagent 数，当全部失败时降级为串行模式，保证基本可用。  
- **充分打日志**：每个 Subagent 分配唯一 run_id，记录工具调用链、耗时与出错信息，便于排障。  
- **复用 LLM 能力**：Subagent 应使用轻量模型（如 GPT-4o-mini）降低成本与延迟，重推理留到汇总阶段用强模型。

## 总结

Subagent 并行编排是在现有 Agent 框架上实现任务加速的务实方案，不需要复杂的 DAG 引擎，只需合理运用异步并发和上下文隔离。在 OpenClaw 生态中，结合 MCP 工具和轻量 Agent 实例，能够快速落地类似多源信息聚合、批量文件处理等场景。踩坑过后，你会发现并行不仅节省时间，还能提升容错性——单个子任务失败不会拖垮整个流程。

最终，你得到的不是一个全知全能的超级 Agent，而是一队职责清晰、能同时干活的小型 Worker，这恰恰是工程上最可靠的形态。
