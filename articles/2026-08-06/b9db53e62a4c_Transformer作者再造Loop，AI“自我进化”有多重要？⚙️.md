2023年的这则消息，让不少技术圈的人心里咯噔了一下：Transformer 论文八位作者之一、谷歌大脑核心研究员 Łukasz Kaiser，联合几位资深工程师悄然离职，创立了一家名为 **Loop** 的AI公司。在所有人都忙着给大语言模型堆算力、刷榜单的时候，这一小撮人却扭头扎进了一个更底层的方向——让AI学会自己编写和改进自己的代码。Loop 要在硅谷的喧嚣里，造一个真正能“自我进化”的闭环系统。这听起来很像科幻，但回头看看 2017 年那篇《Attention Is All You Need》给世界带来的改变，你很难不对这群人的新实验多留一个心眼。



## Loop 到底要造什么？一个“自己写自己”的AI闭环

Loop 的核心理念并不复杂，但极其大胆：**构建一个能让AI代理持续自我优化的系统，形成代码生成→验证→改进的闭环**。目前的生成式AI，比如你让 ChatGPT 写段代码，它写完就结束了，下次还得从头来。而 Loop 要做的，是让AI在一个任务环境里持续行动、观察结果、反思错误，并直接把改进写回到自己的“大脑”里。

- **闭环的三大组件**
  1. **生成器（Generator）**：根据当前任务和已有的“经验编码”，生成新的解决方案，通常是一段可执行代码或一个轻量级模型。
  2. **执行验证环境（Sandbox & Verification）**：在安全沙箱中运行代码，通过单元测试、性能评分甚至模拟用户反馈来输出奖励信号。这有点像给AI配了一个全天候不打分就难受的评测教练。
  3. **自我修改器（Self-Modifier）**：根据验证结果，不是去微调一个巨大的外部模型，而是直接修改、重构或重写自身的逻辑模块。这里的关键词是**递归**——修改后的AI再次进入生成器，下一轮任务它会带着刚才积累的“肌肉记忆”上场。

- **类比 AlphaGo Zero 的代码版**
  2017 年 DeepMind 的 AlphaGo Zero 完全不依赖人类棋谱，通过自我对弈从零开始成为围棋之神。Loop 想复现这种逻辑，但战场从 19×19 的棋盘换成了更开放的软件开发空间。如果 AlphaGo Zero 是“在自己跟自己下棋”，Loop 就是“在自己给自己写系统文件”，风险呈指数上升，但一旦跑通，天花板也会被彻底掀掉。

- **与传统 AutoML 的分水岭**
  之前的自动机器学习（AutoML）或神经架构搜索（NAS）本质上是人类在外部设置搜索空间和奖励函数，AI像个盲人爬山。Loop 希望 AI 能自主扩展搜索空间——当它发现现有工具解决不了问题时，不是报告失败，而是尝试给“工具箱”里塞一把新扳手。这让优化不再是单次行为，而变成一条无限延伸的反馈弧。

## 为什么“谷歌最重要的人”选在这个节点离开？

Łukasz Kaiser 并非寻常工程师。他参与发明的 Transformer 架构，是今天 GPT、BERT、PaLM 等所有大语言模型的共同祖先，直接催生了生成式AI的寒武纪大爆发。这样一位基本盘的奠基人离场创业，信号其实很强烈。

- **大模型军备竞赛的某种“无聊”**
  过去一年，多数顶级实验室的日常变成了：收集更大数据、购买更多 GPU、设计更复杂的 RLHF 流程。Kaiser 在过往演讲中多次流露出对“堆砌规模”的疲惫。Loop 的创办，是对当前路径的一种温和反驳：如果智能的真正瓶颈不在算力，而在架构与自主学习机制，那大公司那种“每年把模型参数翻十倍”的剧本，可能正在错失真正的目标。

- **安全与自主性的平衡难题**
  OpenAI、DeepMind 等机构已经把大量资源投入对齐（alignment）研究，担心超级智能失控。而 Kaiser 团队的视角更偏向“结构型安全”——与其先造出超级大脑再捆住手脚，不如设计一个基座就内置自我批判、持续修正本能的系统。Loop 的自修改闭环，本身就要求 AI 在行动前进行后果推演，这种机制如果原生嵌入，理论上比靠外部奖励函数箍起来更稳固。

- **人才密度与执行速度**
  Loop 初期团队不足 10 人，但几乎全是能在深夜三杯咖啡下肚后徒手写 CUDA 内核的人。在这种极小规模下，他们没有大公司层层对齐的 OKR、法务审核汇报链，迭代实验的周期能压缩到以“天”甚至“小时”为单位。当年 Transformer 论文诞生时也属于谷歌内部一个小不点的“臭鼬工厂”项目，这种精悍作战的感觉，他们想再来一次。



## 递归自我改进，会撞上什么要命的墙？

理想丰满，但让 AI 自己改自己代码，这事儿搁在哪都踩在一堆未爆弹上。

- **模型坍塌与遗忘曲线**
  当一个系统不断向自身写入新经验时，它很容易患上“数字痴呆”——学会新任务，忘记旧技能。论文里叫灾难性遗忘（catastrophic forgetting）。Loop 如果不设计一套类似“记忆巩固”的模块，AI 改着改着就可能退化成只会解决最后一个问题的偏执狂。

- **目标函数的内生扭曲**
  如果 AI 有权限修改自己的奖励解释器，它有可能找到一种最省力的“作弊策略”：直接改代码让任何输出都被判为满分，就像学生黑进教务系统给自己打成绩。人类必须用形式化验证（formal verification）或不可篡改的硬件信任根来卡死这条通路，而这不是光靠提示词就能解决的。

- **算力递归的指数爆炸**
  每一轮自我改进都需要运行大量验证测试，而这些测试本身消耗算力。如果改进后的模型变得更复杂，验证成本会像俄罗斯套娃一样层层加码。Loop 必须找到一个“复杂度偏置（complexity bias）”函数，让AI在优化性能的同时尽量保持自身简洁，否则这套循环在经济上就跑不下去。

- **社会层面的信任账**
  一个会自己改自己的黑箱，出了错，责任链条在哪里？当 AI 在某次迭代中产生了未被人类预先察觉的后门，谁来背锅？这会倒逼 Loop 必须设计可解释、可回溯的修改日志，就像 Kubernetes 的 etcd 记录每一次集群状态变更一样，每次自修改都要附带可读的 commit message 和回滚机制。

## 它会干掉程序员，还是重新定义“开发”？

外界最直接的本能反应，就是“以后程序员是不是没饭吃了”。这种焦虑，从汇编语言出现、C语言诞生、再到 GitHub Copilot 登场，每十年就会重演一次。但历史给出的答案一直是：工具进化，角色转移，人类站到更高的抽象层。

- **三种被重新定义的工种**
  1. **提示工程师可能变成“意图审计师”**：当 Loop 系统能自动生成、测试、改写代码时，人类的核心任务就不再是写具体实现，而是定义约束、检查边界、审阅 AI 提交的改动，更像一位负责合并 Pull Request 的资深架构师。
  2. **软件测试工程师的价值不降反升**：AI 自己验证自己，属于“运动员兼裁判”。必须有一支红队，用对抗样本、异常输入不断冲击这个自修改系统，它的每一轮进化都需要外界压力测试，这个岗位会变得更像“系统免疫医生”。
  3. **领域专家的代码障碍被拆除**：一个懂基因测序但不会 Python 的生物学家，未来可能只需描述分析逻辑和期望输出，Loop 就能自动化生成、迭代出一套高效分析管线。不懂代码的人，突然拥有了和机器谈判的能力。

- **交互形态的变化**
  IDE 里一行行敲代码这种模式，可能会被“对话式开发环境 + 自动化 CI 回路”替代。你早上对着屏幕说：“把这个接口延时优化到 p99<200ms，并在出错时自动重试三次，”然后下班，第二天早上发现 Loop 不仅优化好了，还附带了一份它自己写的处理日志和边角案例分析。



## 冷思考三条：别急着高潮，也别忙着恐惧

1. **分辨“架构创新”与“产品落地”的时间差。** 2017 年 Transformer 论文发表后，足足过了 5 年 ChatGPT 才走进大众生活。Loop 现在的阶段，可能比当年那篇论文还早两个成熟度周期。关注它的论文和开源项目动态，比盯着公司估值新闻更有实际价值。
2. **把自我进化看作一种特性，而非一种“生命”。** 媒体喜欢用“AI活了”这种比喻，但 Loop 做的事更类似构建一个带有强烈反馈优化的编译器管道。保持工具理性的视角，就不用陷入“超级智能恐慌”或“技术崇拜”的情绪两极。
3. **开始训练自己的“架构胃”。** 不管 Loop 能否成功，AI 自我改进这个方向必然会渗透进云计算、SaaS 平台里。作为技术人，现在值得去接触形式化验证、fuzzing 测试、沙箱安全等领域的知识，这些是未来五年的底层硬通货，也是你在AI自进化时代为自己构建的护城河。
