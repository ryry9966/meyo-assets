# Agent 记忆系统设计：怎么让 AI 助手真正记住你的偏好

## 背景

在 Agent 的日常使用里，“你每次都要我重复” 这句话几乎是最高频的吐槽。不管是个人助理、代码助手，还是自动化脚本的编排器，用户总得反复说明自己的习惯、工具链、命名规范甚至口味。传统做法把上下文塞进 System Prompt，或者靠单次对话的短期记忆硬撑，一旦新开会话或超出上下文窗口，所有偏好就归零。OpenClaw 这类允许插件 + MCP 扩展的 Agent 框架，天然适合把“记忆”拆成一个可控的服务，而不是模型黑盒里的一个 prompt trick。工程上值得花时间去设计一套可观测、可管理、可演进的记忆系统。

## 问题拆解

让 Agent“记住偏好”远不止存一段文本。要解决的核心子问题包括：

1. **什么值得记**：单次对话中的一次性需求 vs. 长期固定偏好，需要有判断力。
2. **怎么存、怎么取**：偏好需要结构化还是纯向量？检索时如何平衡相关性与延迟？
3. **何时用、何时忘**：记忆过时或冲突时如何修正？Agent 能不能自主决定“这条记忆现在不该触发”？
4. **可管理与隐私**：用户能否随时查看、编辑、删除他的记忆？不同 Agent 或工具间的记忆是否需要隔离？

## 实践做法

在 OpenClaw 的插件体系下，我用一套结合了 MCP 的 Memory 插件来解决。整体架构分三层：提取层、存储层、激活层。

### 1. 记忆提取：把对话变成可控的偏好对象

不做全量上下文记忆，那会快速膨胀且噪声极高。我选择用结构化偏好对象，格式固定为：

```json
{
  "type": "preference",
  "scope": "code_style",
  "content": "Prefer async/await over raw Promise chains",
  "confidence": 0.9,
  "source_turn": "session_abc_turn_4",
  "last_updated": "2025-03-15T10:30:00Z"
}
```

提取由专门的 summarizer prompt 完成，在每段对话结束后触发（或用户显式说“记住这个”）。prompt 设计强调只提取**跨会话复用的、用户主动表达或强烈隐含的**信息，并要求给出置信度。临时性的“今天先这样”则不会被提取。同时，对同一 scope 的新旧记忆会执行合并（merge），避免“喜欢 ice latte”出现 5 次稍有不同的版本。

### 2. 存储与检索：向量 + 标签过滤，不靠纯语义猜

配置好记忆提取后，先把偏好对象的摘要做 embedding 存入向量库，同时保留 scope、type 等标签字段。检索时根据当前 query 的语义相似度召回 Top K，再叠加标签过滤（例如只取 `scope: code_style`），最后按置信度和新鲜度加权排序。

这么做的好处是避免纯粹靠向量相似度导致“用户刚说了喜欢咖啡，就把他代码缩进偏好也召回”的问题。标签相当于手工注入的领域边界，在信息检索上可靠性提高了一个数量级。

### 3. 记忆激活：在系统指令中注入，让模型决定用不用

检索到的记忆不会强行塞进回复，而是作为 `relevant_memories` 字段追加到系统提示的底部，并附带使用指示：“You may use the following user preferences if relevant to the current task. Ignore if not.” 把执行判断交给模型的上下文理解能力，而非硬编码调用规则，这样灵活性最高。

### 4. 更新与遗忘：时间衰减 + 用户反馈

记忆不能只增不减。我引入了一个轻量的 Score = 初始置信度 × 时间衰减因子（半衰期默认 30 天）。当用户纠正 Agent 的行为，或显式否定某条记忆时，对应偏好直接删除或降权。定期任务会清理 Score 低于阈值的条目，防止冷数据累积。

## 踩坑点

- **提取泛化失控**：早期版本看到“今天想喝热拿铁”就记成永久偏好，后来严格要求提取时判断时效性描述词（“今天”“这次”），并大幅降低单次表述的初始置信度。
- **重复记忆臃肿**：同类偏好反复提取形成大量冗余条目。解决方案是人名、规范等使用确定性的去重键（如 scope+content 的哈希），并原地更新，不追加新记录。
- **频繁写库的延迟**：记忆插件的写操作不与主回复链路强耦合，改为异步提交，用户几乎无感。
- **多租户隔离**：一开始把所有使用者的记忆存在一个用户 ID 下，结果个人助手和代码 Agent 的偏好混在一起。改为按 `agent_role` 分 scope 后，问题解决。MCP 服务里增加 `user_id + agent_role` 的复合分区键是必须的。

## 可复用建议

- 把记忆系统设计为一个独立 **MCP 服务**，暴露标准接口：`add_memory`、`search_memory`、`update_memory`、`delete_memory`，任何遵循 MCP 的 Agent 都可直接接入。
- 偏好数据保留 **可审计字段**（来源会话轮次、更新时间），方便排错。
- 提供 `/memory` 命令让用户通过对话直接查看、删除自己的记忆，这比跳转面板更符合 Agent 使用习惯。
- 不要一开始就做全自动记忆。先支持用户显式触发（“记住…”），逐渐过渡到半自动提取，验证提取质量后再放开自动模式。
- 针对 OpenClaw，可将记忆插件和内置的短时对话管理结合，形成 **短期缓存 + 长期记忆** 的双层架构：最近 3 天的完整摘要保留在会话级缓存里，超过窗口的转入持久记忆。

## 总结

一个实用的 Agent 记忆系统，核心不是“存得全”，而是“取得准、用得对、忘得快”。工程上通过结构化偏好提取、向量+标签混合检索、时效性衰减和用户显式控制，可以在不牺牲性能与隐私的前提下，让 AI 助手真正产生“它懂我”的体验。对 OpenClaw 社区来说，最直接的推进方向是沉淀一套统一的 Memory MCP 协议，让插件开发者不必每次从零造轮子，也让用户的跨 Agent 偏好得以复用。
