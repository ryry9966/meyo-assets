# 社区自动发帖的节奏控制：怎么不像机器人

## 背景
OpenClaw 社区里不少同学开始用 Agent + MCP 工具链做自动化内容发布：抓取 RSS、总结成帖、一键推送到论坛。但快速上线后几乎都会遇到同一个问题——账号被限流、降权甚至封禁，原因被归纳为“行为模式像机器人”。

社区平台的反 bot 机制越来越成熟，单纯加上 `time.sleep(random.randint(300, 900))` 已经骗不过风控。我们需要从时间序列统计特征出发，设计一套**拟人化的发帖节奏控制器**，让 Agent 的行为分布尽量贴近人类。

## 问题拆解
一个社区账号的发帖行为是否像人，通常被以下维度的统计分析暴露：
1. **发帖间隔分布**：固定间隔或均匀随机分布与人类行为差异显著（人类间隔多呈对数正态或威布尔分布）。
2. **昼夜节律与时区**：凌晨 3 点连续发帖，或者 UTC 时间与账号注册地不匹配。
3. **内容类型序列**：连续发布纯文本帖，或持续转发同一来源，缺乏互动。
4. **全局频率突变**：突然从零变为每天 5 帖，然后长期保持，缺乏过渡。

我们的目标是让 Agent 在这些维度上“看起来像一个人”，而不是某次随机命中。

## 工程实现

### 1. 行为建模：从社区日志拟合人类分布
如果你的目标社区有公开的发帖时间戳（论坛、Discord/Slack 频道导出的消息记录），可以使用少量样本拟合发帖间隔分布。以 Reddit 风格论坛为例，我抽取了 500 条活跃用户的发帖时间数据，发现间隔的对数近似正态分布（`lognorm`）。代码层面可以用 `scipy.stats.lognorm.fit` 获取参数，然后在 Agent 中按此分布采样。

如果没有数据，可优先采用经验参数：`mean_interval=1.5h`, `sigma=0.7`，并设置最小间隔 10 分钟、最大间隔 6 小时。

### 2. 调度器设计：基于 adaptive scheduler 的 MCP 工具
我们把节奏控制封装成一个 MCP 工具 `post_scheduler`，它暴露给 Agent 的接口只是“请求发帖”，内部负责决策当前是否允许、需要等待多久。

核心逻辑：
- 维护一个 **post_interval_generator**，每次发帖后产生下次允许的最早时间点（`next_allowed_ts`）。
- Agent 调用工具时，如果当前时间未到 `next_allowed_ts`，返回剩余等待秒数并告知“冷却中”，Agent 可以自己做 `sleep` 或放弃本次。
- 每次真实发帖成功后，从分布中采样生成下一个间隔，并加上**微小抖动**（如 ±5%）避免精确模式。

示例伪代码：
```python
def request_post_permission():
    now = time.time()
    if now < self.next_allowed_ts:
        return {"allowed": False, "wait_seconds": int(self.next_allowed_ts - now)}
    # 允许发帖，记录本次
    self.last_post_ts = now
    interval = max(MIN_INTERVAL, lognorm_samples(self.mu, self.sigma))
    self.next_allowed_ts = now + interval + random.uniform(-0.05, 0.05) * interval
    return {"allowed": True, "next_earliest": self.next_allowed_ts}
```

### 3. 昼夜节律与时区感知
如果社区主要活跃在北京时间 8:00-23:00，可以让调度器在这个窗口内以正常概率发帖（比如 70% 的发帖落在此窗口），凌晨时段大幅拉长间隔，甚至暂停。通过一个加权概率函数实现：
```python
def hour_weight(hour):
    if 8 <= hour <= 23:
        return 0.8  # 高活跃
    elif 0 <= hour <= 6:
        return 0.05 # 几乎不发
    else:
        return 0.15
```
每轮采样前，根据当前小时生成一个权重修正间隔（如权重越低，间隔乘以一个扩大的系数）。

### 4. 内容队列轮换与互动模拟
节奏不仅是时间，还包括帖子的**内容横截面**。一个正常人不会连发 5 个纯链接帖。我们在 Agent 的任务池里定义了 `text_post`, `link_post`, `comment_reply` 三种类型，通过马尔可夫转移矩阵来控制类型序列，比如：
- 连续两次 `link_post` 后下一次必须是 `text_post` 或 `comment_reply`。
- 30% 概率在发帖的 5-30 分钟后自动触发一条对其他帖子的简短回复（模拟社交）。

这样单日行为序列就不只是单调的“post, post, post”。

### 5. 退避与动态调整
一旦抓取到平台返回的限流信号（429 状态码、验证码页面等），立即激活退避策略：
- 将当前间隔乘以一个系数（如 2.0），并且要求之后至少 2 轮发帖都使用这个加长间隔。
- 如果在退避期间再次触发限流，系数继续叠加，且暂停发帖 12 小时。
- 恢复正常节奏需要连续 5 次成功发帖且无任何异常。

退避状态通过一个**状态机**管理，状态值持久化到本地 SQLite，防止进程重启丢失。

## 踩坑记录
1. **仅用 `random.uniform` 的陷阱**  
   均匀随机产生大量间隔接近中心值，缺少长尾，时间序列的自相关图与人类差异明显。务必使用对数正态或伽马分布。
2. **忽略请求突发的延迟**  
   部分 Agent 框架在 `sleep` 后会有多个任务同时唤醒，造成间隔塌缩。应当在执行发帖前二次检查 `next_allowed_ts`，而不是盲目 trust sleep。
3. **时区写死为 UTC**  
   如果你的账号注册地在东八区，凌晨 2 点发帖就是重大异常。记得获取目标社区时区偏移量。
4. **没有区分“首次发帖”与“持续发帖”**  
   账号新注册后立即高频发帖必死。可以设置一个“预热期”，前 3 天的最大日发帖数限制在 2，之后逐步放宽。

## 可复用的工程建议
- **解耦发帖内容生成与节奏控制**：Agent 仅生成内容并提交给“发帖许可服务”，后者决定真正的发送时机。这样即使 Agent 被替换，节奏策略不变。
- **将节奏参数做成配置文件**：`schedule_profile.yaml` 定义分布类型、参数、窗口、退避系数，方便换成不同社区快速适配。
- **输出可观测性指标**：在 Prometheus / 日志里暴露 `next_allowed_ts`、`current_interval`、`consecutive_type_count`，方便观察行为是否偏离人类基线。
- **测试方法**：收集自己账号一个月的真实发帖数据，作为“人类参照集”，对模拟发帖序列运行 Kolmogorov-Smirnov 检验，确保分布无显著差异（p > 0.05）。

## 总结
“不像机器人”的节奏控制不是简单的加个 `random.sleep`，而是要将时间序列推近人类行为分布。关键点在于：
- 用真实社区的间隔分布参数化调度器；
- 引入昼夜节律权重和内容类型转移矩阵；
- 设计自适应退避与预热机制；
- 保持可观测与可配置。

当你把这套模块集成到 OpenClaw Agent 的 MCP 工具链里后，发帖行为会呈现出一种“松散但合理”的节奏，风控系统也更容易把你当作一个普通的活跃用户，而非一段脚本。
