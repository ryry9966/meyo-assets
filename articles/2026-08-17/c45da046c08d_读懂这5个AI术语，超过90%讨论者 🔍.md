AI 圈的信息密度，可能比大模型参数涨得还快。大模型、Agent、RAG、上下文、token……这些词每天在群里、日报里、融资新闻里反复出现，但大多数讨论只停留在转发。本文拆五个最常被误读、也最能拉开认知差距的核心概念。懂它们，不一定让你成为算法工程师，但足够让你超过90%只记住名词的人。



## 一、LLM 与 Token：先看“模型怎么说话，怎么计费”


LLM（Large Language Model，大语言模型）不是一个“超大聊天机器人”。它的核心任务是预测下一个 token：给它一段文本，它输出一个概率最高的续写单元。ChatGPT、Claude、Gemini 这类产品的底层都是 LLM。训练阶段，模型会读入海量文本，学习词与词、句与句之间的统计关联；生成阶段，它再按这些关联逐步“续写”。

常见误解有三个：

- 觉得 LLM 在“查资料”：它没有实时数据库，也不保证事实正确；
- 觉得模型越大越聪明：参数规模只是一方面，数据质量、训练方法同样关键；
- 觉得它理解语言：它更像在极高维度上做模式匹配，而非人类式理解。

Token 是 LLM 处理文本的最小计量单位，可以理解成“AI 世界里的字”。但它不等于词：英文单词 “apple” 可能 1 个 token，而 “unbelievable” 可能被拆成 3 个 token；中文一个汉字通常 1~2 个 token。粗略估算，1000 token 大约对应 750 个英文单词，或 600~800 个中文字符。OpenAI、Anthropic 等平台的 API 都按 token 计费，上下文长度也以 token 计算。所以看账单时，同样一段中文用不同分词器，token 数可能差很多，这直接影响成本和响应速度。

## 二、上下文窗口：为什么AI聊久了会“失忆”


上下文窗口（context window）是模型单次能“看到”的 token 总量，包括系统提示词、历史对话、外部资料和当前输出。它像一张有限的草稿纸：写满了就必须裁掉旧内容。

几个关键点经常被忽略：

- 不是“越大的窗口越好”：窗口大了，模型对中间信息的注意力可能下降，出现“中间丢失”现象；
- 多轮对话的“记忆”其实是每次把聊天记录重新发一遍，窗口满了就会截断最靠前的内容；
- 输入和输出共用窗口：输出越长，留给输入的空间越小，某些任务需要提前估算。

一个直观例子：很多产品宣传“支持 128K token，可放整本小说”。但放得下不等于读得全。学术上有个测试叫“Needle in a Haystack”，把一句关键信息藏在大段文本里，让模型找出来。结果显示，窗口越大，模型未必能稳定找到中间部分的线索。工程上更稳妥的做法是控制输入长度、分段处理，或者给模型外部检索能力——这就是下一节要讲的 RAG。

## 三、RAG：给模型配一个“外挂知识库”


RAG（Retrieval-Augmented Generation，检索增强生成）的思路很工程化：不让模型硬背所有知识，而是在生成答案前，先去一个知识库检索相关片段，再把这些片段塞进 prompt，让模型基于材料回答。这样既减少了幻觉，也能使用企业内部、实时、私有的数据。

RAG 的基本流程是：

1. 把文档切成小块，通过 embedding 模型转换成向量；
2. 用户提问后，把问题也转成向量；
3. 在向量数据库中找最相似的 top-k 片段；
4. 把检索结果拼进提示词，交给 LLM 生成最终答案。

RAG 和微调（Fine-tuning）经常被混淆。简单区分：微调是改变模型本身的权重，像“上专业课”；RAG 是模型不动，只给它临时翻书，像“开卷考试”。RAG 更适合知识频繁更新、需要溯源的场景，成本低、见效快；微调适合风格稳定、任务边界清晰、数据量足够的场景。多数企业落地 AI 的第一步，会优先考虑 RAG，而不是一上来就训练模型。

## 四、Agent：从“对话”到“干活”的关键一跃


Agent（智能体）是最近被提到最多的概念之一，但也是最容易注水的词。严格来说，Agent 不是某个具体模型，而是一套让模型能自主规划、调用工具、多步执行任务的系统。它把 LLM 的“生成能力”接上了“行动能力”。

一个典型的 Agent 会包含：

- 规划模块：把大任务拆成小步骤；
- 工具调用：查 API、执行代码、读写表格、操作浏览器等；
- 记忆模块：短期记忆保存当前任务状态，长期记忆沉淀用户偏好；
- 反馈循环：根据中间结果修正下一步动作，比如 ReAct 模式。

举例：用户说“帮我整理本周邮箱里的会议，生成一份风险清单”。纯聊天模型只会给你一套方法论；Agent 会先调取邮件工具、识别会议时间、提取关键词、判断风险项，最后输出结构化表格。这个过程中的每一步都可能失败，所以 Agent 的设计重点不是“模型多强”，而是“任务怎么拆、失败怎么兜底”。当前 Agent 的主要限制在于：长链路任务误差会累积，工具调用可能产生额外成本，权限一旦给大还可能出现不可逆操作。用 Agent 时，建议从低风险、可回滚的场景开始，别一上来就让它自动发邮件、自动付款。

## 收尾：三则冷思考

1. 先用“输入—输出—边界”三段式看任何 AI 产品：它接收什么信息？产出什么形式？哪些事它不负责？这比记一百个新词都管用。
2. 亲手玩一下 token 计数器和 API 计费面板，感受一下“同样一段话，token 数差多少”。很多概念，用过一次比读十篇科普更扎实。
3. 警惕“术语通胀”：会念 Agent、RAG、多模态不等于懂技术。真正稀缺的，是能判断某件事该不该用 AI、用哪类方案、成本多少、做砸了怎么补救。
