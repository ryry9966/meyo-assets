近期，一个与 Claude 输出水印相关的开源项目在 GitHub 上迅速涨到约 11k Star，但同名或同功能的浏览器扩展却被 Chrome Web Store 拒绝上架。这个组合看起来像“用户需要、开发者追捧、平台刹车”，但在 AI 内容溯源尚未定型的背景下，它其实是一个很典型的工程与合规交叉问题：技术能做出来，不代表分发渠道会接受。



## 一、11k Star 背后，用户真正需要的是什么

GitHub Star 不是安全认证，也不代表“官方认可”。它更接近开发者的收藏夹。一个移除 Claude 输出水印的工具能拿到 11k Star，至少说明三个现实：

- 复制文本确实会带入异常字符。很多用户把 Claude 网页版的回答贴进代码编辑器、JSON 配置或博客后，会碰到不可见字符导致的解析错误、代码报错或搜索结果不一致。
- 官方没有提供足够细粒度的导出选项。用户要么接受带标记的文本，要么自己手动清理，于是第三方工具自然出现。
- Star 数放大了传播，却没有改变合规性质。一个仓库在 GitHub 上受欢迎，不等于浏览器商店就必须受理同功能扩展。

因此，高 Star 与“被拒绝安装”同时发生，并不矛盾。一个服务的是开源代码交流场景，另一个面向的是普通消费者分发场景，两者的审核尺度完全不同。



## 二、不可见水印是怎么藏进文本的

这里说的水印，大多不是图像水印，而是文本级水印。屏幕上看起来只有普通字母和标点，但复制后可能夹带肉眼不可见的信息。常见形态有：

- 零宽字符编码：在字符之间插入 U+200B、U+200C、U+200D 或 U+2060 等不可见 Unicode 字符。它们在多数文本框中不占宽度，却会影响字符串长度、哈希值、解析和比较。不同组合可以对应不同二进制序列。
- 同形异义字替换：把某些拉丁字母替换为西里尔字母、希腊字母或其它几乎长得一样的 Unicode 码位。例如拉丁小写 a 和西里尔文 а 在屏幕上是两个不同字符，视觉上却很难区分。
- 空白与标点微扰：在空格、缩进、换行、连字符处做轻微变化，普通用户不会注意，但程序可以通过统计或精确比对识别。
- 模型层统计水印：在生成 token 时，服务方用密钥对候选词做伪随机偏置，使整段文本在概率分布上带有可验证签名。这种水印不依赖客户端复制，也不在 DOM 或粘贴内容里直接可见。

Claude 网页输出被社区讨论较多的，以前两类为主。所谓“破解”工具，本质也不是逆向加密算法，而是批量识别并清理这些可疑字符：删除零宽字符、统一混合脚本码位、标准化空白、过滤控制字符。它提高的是清理效率，技术门槛并没有标题里“破解”二字听起来那么高。



## 三、商店拒绝安装，与文本水印的“不可能三角”

Chrome Web Store 拒绝这类扩展上架，与其说是针对某个项目，不如说是平台在规避四类风险：

- 反滥用政策：商店明确禁止扩展用于规避安全机制、干扰访问控制或反滥用系统。移除水印会被归入“规避”类别，即使作者称自己只是清洁文本。
- 法律与 DMCA 风险：在部分司法辖区，删除或改变用于内容溯源的技术信息，可能触碰类似 DMCA 第 1201 条“禁止规避技术保护措施”的争议。商店作为分发方，不愿成为连带责任方。
- 权限与隐私风险：这类扩展必须读取并修改网页内容。如果被仿冒或植入恶意代码，聊天记录、cookie、剪贴板内容都可能暴露给第三方。商店很难逐个审计，拒绝是成本最低的风控。
- 责任不对称：允许上架一个“移除水印”的扩展，平台几乎没有收益；一旦出现纠纷，则可能面临法律、舆情和用户信任三重成本。

所以，GitHub 允许仓库存在，Chrome Web Store 却不允许扩展上架，背后是不同平台对“自由分发”和“消费级安全”的边界理解不同。开源社区看重代码可审计，商店则更看重默认安全。

文本水印也很难同时做到三点：足够隐蔽、足够鲁棒、不影响生成质量。

- 如果藏得太浅，客户端插件、编辑器清理或复制后的规范化处理都能轻松洗掉。
- 如果追求鲁棒，往往需要改变用词、语序或输出分布，这会牺牲可读性或准确性。
- 如果只依赖客户端水印，截图、拍照、翻译、重写、摘要等操作都能让它失效。

在这个前提下，有三条比较务实的建议：

1. 如果目的是清洁文本，优先使用支持显示不可见字符的编辑器或自建脚本，不要因为图方便就安装来路不明的浏览器扩展。
2. 如果企业真正关心敏感内容泄露，不应高估客户端水印。更可靠的是服务端审计、访问控制、API 调用日志和内容签名。
3. 如果开发者计划发布类似工具，需要在开源之外提前考虑分发渠道的合规边界，避免先积累高 Star，再被平台事后拒绝或下架。

水印被破解并不可怕，它只是说明单点隐藏的效力有限。更值得关注的，是 AI 内容溯源正在从“厂商单方面控制”走向“用户知情、可控、可审计”的阶段。最终能留下来的方案，很可能不是把水印藏得更深，而是让用户在导出、复制和分享时，能够清楚知道发生了什么，并且有得选。
