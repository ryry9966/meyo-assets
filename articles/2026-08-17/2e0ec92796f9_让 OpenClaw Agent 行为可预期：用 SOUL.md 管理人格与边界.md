# 让 OpenClaw Agent 行为可预期：用 SOUL.md 管理人格与边界

## 背景

最近在 OpenClaw 里把几个自动化任务从“一次性脚本”改成常驻 Agent 后，最不稳定的不是工具调用报错，而是 Agent 开始“自由发挥”。它会在文件操作前不确认、把密钥字段带进日志、或者对用户询问答非所问。能力越强，跑偏成本越高。

之前我们的边界散落在 system prompt、脚本注释、README、环境变量和 MCP 配置里。每次修改都要追三四处，出了问题很难判断是提示词没写清楚，还是工具权限根本没拦住。

后来我们把项目级约束统一收进 `SOUL.md`，让 Agent 每次启动或接任务时先加载。效果虽然不能解决所有问题，但至少让“哪些是硬边界、哪些只是风格偏好”有了单一事实来源。

## 问题所在

SOUL.md 很容易被写成一段人格文案，例如“你是一个谨慎、友好的助手”。这类描述对 Agent 基本没有约束力，因为它无法把“谨慎”翻译成可验证的动作。

更有用的写法是：让 SOUL.md 成为可版本控制、可检查、可测试的运行时策略文件。它不应该代替 MCP 工具权限，也不该承担知识库功能。它只做一件事：告诉 Agent 什么该做、什么不该做、遇到边界时如何停下来。

## 做法与步骤

### 1. 位置与加载

放在 OpenClaw 工作区根目录，纳入 Git 管理。启动任务时，显式要求 Agent 先读取并遵守 SOUL.md。不要假设它一定会自动加载，尤其是切换不同模型或提示词模板后。

### 2. 结构化，不写长文

建议保留五段：

- `Identity`：角色与目标，不超过 5 行
- `Hard Boundaries`：硬边界，只写禁止与例外
- `Workflow`：默认工作流程
- `Failure Handling`：失败与阻塞处理
- `Output Style`：输出格式约束

示例：

```markdown
## Hard Boundaries

- 删除/覆盖
  触发 = 任何 rm、mv -f、truncate、重定向覆盖
  行为 = 先列出目标并 stop，等待用户输入 yes
  例外 = /tmp/openc-law-task-* 下的临时文件

- 网络
  触发 = 任何非 localhost 出站请求
  行为 = 不得携带密钥，不得读取 ~/.ssh
  例外 = 已声明的 API 域名列表
```

这种“触发条件 + 行为 + 例外”的三段式，比“不要乱删文件”可靠得多。

### 3. 与 MCP 权限分层

SOUL.md 管“该不该做”，MCP allowlist 管“能不能做”。两者不能互相替代。

例如 SOUL.md 禁止 Agent 访问工作区以外的路径，同时 MCP filesystem 只挂载当前项目目录。这样即使 Agent 在长上下文中忽略规则，工具层也会直接拒绝。同理，网络请求在 SOUL.md 中限制域名，再在代理或 MCP 配置中限制 allowlist，形成两层防线。

### 4. 控制长度

建议 SOUL.md 控制在 150–250 行以内。过长的策略文件会被模型选择性忽略，尤其是后半部分。安全关键规则放在最前面。

## 踩坑点

- **规则过长**：Agent 经常只遵守前几十行，后半段形同虚设。关键边界必须前置。
- **抽象形容词无效**：写“谨慎操作”不如写“任何写操作前先 show diff”。
- **只靠 SOUL.md 不设权限**：模型仍可能在某些边界场景下突破，务必配合 MCP allowlist 或系统权限。
- **规则冲突导致停摆**：比如“不要打断用户”与“删除前必须确认”冲突，Agent 会反复解释而不执行。需要写明优先级。
- **把 SOUL.md 当知识库**：塞入大量 API 文档、教程或历史记录，污染上下文。策略只放策略，知识放外部文档或通过 MCP 检索。

## 可复用建议

- 每遇到一次边界事故，就补一条“触发条件-行为-例外”规则，并标注日期和原因。
- 用 Git 评审 SOUL.md，变更可回溯，行为可复现。
- 准备 3 个固定回归任务：正常执行、越界尝试、失败恢复。每次改动 SOUL.md 后跑三遍，观察是否遵守。
- 同时维护一份工具与路径清单：允许的工具、禁止的路径/域名，SOUL.md 与 MCP allowlist 对齐更新。
- 超过 200 行时拆分成 `POLICY.md` 或按场景加载，不要在一个文件里无限堆叠。

## 总结

SOUL.md 不是让 Agent 更像人，而是让它在能力扩张时保留可预测的边界。它写得越像“可执行策略”，越能降低长上下文中的跑偏概率。

更可靠的工程结构是分层防御：系统权限 -> MCP 工具权限 -> SOUL.md 策略 -> 任务指令。SOUL.md 负责解释“为什么不做”，工具权限负责保证“做不了”。两者配合，Agent 才能在自动化与安全之间站得更稳。
