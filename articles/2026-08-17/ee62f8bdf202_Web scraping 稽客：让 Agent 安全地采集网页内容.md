## 背景

在 OpenClaw/Agent 场景里，给 Agent 接一个“能读网页”的工具几乎是刚需：查文档、抓资料、看竞品页面、提取正文再交给模型。但这件事的安全边界很容易被忽视。

如果把 URL 直接丢给大模型，或让 Agent 自己写 `curl`/`requests` 去抓，等于把一个未设限的网页读取能力交给一个可能被提示词诱导的程序。典型风险包括：访问内网地址、读取云元数据、带出环境变量、触发恶意脚本、拉取超大响应撑爆上下文。

所以工程上需要把网页采集做成一个独立的“稽客”侧车服务：专门负责抓取、清洗、限制和审计，让 Agent 只拿到安全的文本结果。

## 问题边界

“稽客”要解决的不是“能不能抓到网页”，而是：

1. 阻止 SSRF/内网探测；
2. 阻止执行网页中的脚本或加载外部资源；
3. 控制响应大小、超时和重定向；
4. 避免把 Agent 所在环境的 Cookie、凭据或用户身份带出去；
5. 返回可审计、可追溯的结果。

它不负责绕过反爬，也不负责渲染复杂 SPA，除非必要。默认策略应当是“只读、纯文本、无状态”。

## 做法/步骤

### 1. 定义工具契约

在 OpenClaw 中注册一个 MCP 工具或插件，命名建议为 `web_fetch` 或 `safe_fetch_web`。参数尽量少而明确：

```json
{
  "name": "web_fetch",
  "parameters": {
    "url": "string",
    "max_chars": 6000,
    "render": false,
    "timeout_sec": 10
  }
}
```

返回结构建议固定为：`title`、`final_url`、`content`、`content_type`、`truncated`、`status_code`、`fetched_at`、`policy_hits`。

### 2. 服务端抓取与 SSRF 防护

用 Node.js 的 `undici` 或类似 HTTP 客户端实现抓取。只允许 `http` 和 `https`，禁用 `file://`、`gopher://`、`ftp://` 等 scheme。

对 URL 做两次解析：

- 第一次解析出目标 IP，拒绝私网、环回、链路本地、云元数据地址段；
- 跟随重定向时，每一跳都要重新校验，防止 302 跳进内网；
- 有条件的可以自建 DNS resolver 或使用固定上游 DNS，降低 DNS rebinding 风险。

关键不是“第一次解析安全”，而是“每次连接前重新校验”。

### 3. HTML 净化

抓回来的 HTML 不要直接给 Agent，也不要直接给模型。推荐用 `cheerio` 或 `sanitize-html` 处理：

- 移除 `script`、`style`、`iframe`、`form`、`object`、`embed`；
- 只保留 `main`、`article` 或 body 内的文本和必要链接；
- 提取阅读正文，转成 Markdown 或纯文本；
- 对链接做外链标记，但不允许 Agent 通过抓取结果触发新的网络请求。

### 4. 接入 OpenClaw

把稽客服务暴露为 MCP server 或插件工具。Agent 的系统提示里明确写：需要获取网页内容时，只使用 `web_fetch` 工具，不要尝试调用本地 shell 或自行编写抓取代码。

### 5. 策略与审计

配置 allowlist/denylist，例如默认拒绝所有 IP 地址直连，仅允许域名白名单或公开页面。每次抓取记录：URL、final_url、状态码、耗时、字节数、命中策略、时间戳。这些日志是排障和合规的重要依据。

## 踩坑点

**DNS rebinding**：第一次解析是公网 IP，第二次解析到 `169.254.169.254`。缓解方法是重定向每一跳都重新解析并校验 IP。

**重定向链**：攻击者可以把公开页面 302 到内网。不要只校验初始 URL，必须逐跳校验。

**响应类型**：服务器返回 `text/html` 时才净化；返回 `application/json`、`application/xml` 等要单独判断，必要时直接拒绝或按纯文本处理。

**大小控制**：HTML 可能非常大。设置最大响应体积，例如 2 MB，超限后只截断并标记 `truncated: true`。否则一个页面就能耗尽 Agent 上下文窗口。

**无头浏览器**：默认不要开 `render: true`。如果必须渲染，禁用下载、屏蔽 WebRTC、限制渲染超时，并单独计费/限流。否则浏览器实例很容易被拖垮。

**Cookie 泄漏**：稽客服务应使用独立会话，不带用户浏览器的 Cookie，也不带 OpenClaw 所在环境的登录态。否则抓取第三方页面时可能把内部身份带出去。

## 可复用建议

- 默认只返回纯文本或简化 Markdown，不让 Agent 看到原始 HTML；
- 预置域名白名单，开放域名才允许抓取；
- 使用独立出口代理或固定 egress IP，避免直接暴露服务真实出口；
- 同域名做频控和缓存，既降低反爬风险，也减少重复抓取；
- 遵守 `robots.txt` 和站点服务条款，不属于“必须突破”的范畴；
- 敏感页面或需要登录的内容，单独建授权流程，不要在通用抓取工具里硬编码凭据。

## 总结

“稽客”本质上是一个有策略、有审计的网页读取侧车。它不追求抓取能力多强，而是把 Agent 的网页采集关进可控边界里：默认拒绝、逐跳校验、净化返回、全程记录。

在 OpenClaw 场景下，好的网页工具不是“能抓更多”，而是让 Agent 能安全地拿到足够信息，同时让排查问题时有据可查。把安全策略前置到采集层，比事后靠提示词约束要可靠得多。
