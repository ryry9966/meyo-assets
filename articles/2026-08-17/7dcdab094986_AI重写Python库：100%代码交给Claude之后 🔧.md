最近，一名 OpenAI 研究员的发言在开发者圈子里被反复引用：他已经把 100% 的代码交给 AI 写，Claude 还顺手重写了一个 Python 库。很多人第一反应是“程序员完了”，但这句话真正值得拆开看的地方，不在于那个百分比，而在于“代码”的定义正在改变。当生成代码的成本趋近于零，写代码这个动作正在从手工劳动变成一项工程治理问题。



## 一、真正值得注意的不是“100%”



- “100% 代码由 AI 生成”不等于“100% 技术决策由 AI 做出”。多数场景里，AI 生成的是样板代码、测试、迁移、文档和重写；架构取舍、API 设计、边界条件、安全策略仍由人给出。
- 以 Python 库重写为例，通常不是让 AI 自由发挥，而是：保留原 API 签名、兼容现有测试、升级依赖、清理历史包袱、补充类型标注。AI 在“约束内”很快，人在“约束外”很慢。
- 代码行数不等于产出。一个 AI 重写 PR 可能删掉 2000 行旧代码、新增 1500 行更清晰的实现，diff 统计上看着像“减少”，却可能带来可维护性提升。
- 这个数字听起来很唬人，但细看 diff 就会发现，大量工作正是我们之前最想外包的部分。真正值得关注的是工作流变成了 prompt → generate → diff → review → test → merge 的闭环。
- 可以类比自动驾驶：现在更像封闭园区接驳，路线固定、护栏清晰，而不是随便开上陌生公路。

## 二、Claude 重写 Python 库，发生了什么？



- 现代 agentic coding 工具不是单次补全，而是能读取仓库、列出文件、规划修改、运行命令、观察报错、继续修复。Claude 的长上下文和工具调用能力，让它能“看到”整个库的结构。
- 典型流程：输入任务 → 读取 pyproject.toml 与源码树 → 设计迁移计划 → 逐文件重写 → 运行 pytest 和 mypy → 根据失败修正 → 输出 PR 描述。
- Python 库适合这种任务：模块边界清晰、测试文化成熟、动态类型可通过类型标注补强、打包规范统一。重写旧库往往是体力活，正好是 LLM 的舒适区。
- 比如把一个从 Python 2 时代遗留的库迁到 Python 3.11+，需要处理 print 函数、异常语法、内置类型、路径处理等。模型可以批量处理这些机械迁移，而人重点验证行为差异。
- 但要清醒：模型不是一次成功，大量时间花在“让测试通过”和“消除回归”上。Claude 能重写，不等于重写结果一定优雅；它可能通过测试，却引入隐藏的复杂度。

## 三、100% 代码由 AI 写，不等于工程师失业



- 历史上的参照：编译器没有消灭程序员，而是创造了系统软件与语言设计；IDE 没有消灭开发者，而是把注意力从记忆 API 转向设计；Stack Overflow 也没有让软件工程师消失。
- 角色正在从“编写实现”迁移到“定义验收”。具体工作变成：拆需求、写规格、设计测试矩阵、审查 diff、维护上下文、处理模糊性。
- 新技能点：
  1. 需求工程：把模糊产品语言转成可验证约束；
  2. 测试设计：property-based test、模糊测试、边界用例；
  3. 代码审查：识别“看起来对但不合理”的实现；
  4. 工具编排：选择模型、控制上下文、设置沙盒权限与 CI 门槛。
- 一个常见问题是：需求只说“支持昨天和明天的订单统计”，AI 生成的代码在测试数据上通过，但把时区全部按 UTC 写死，导致跨时区用户账单日偏移。这类问题不会出现在 happy path，只有人追问边界时才会暴露。
- 风险同样存在：如果只把 AI 当“更快的打字机”，会制造大量需要维护的代码；如果没有 review 文化，AI 的引入会放大技术债。

## 四、生成越快，验证越重要：CI 成为新硬通货



- 当代码生成量上升，单点人工 review 会失效。原先一个 PR 200 行，人工可以逐行看；现在可能 3000 行，必须靠自动化护栏。
- Python 生态的工具链正好匹配：ruff 做 lint，mypy/pyright 做类型检查，pytest 与 coverage 做测试，bandit/pip-audit 做安全扫描。AI 可以在这些 gate 下快速迭代。
- 关键原则：让 AI 在“护栏内”快速失败。生成 10 个候选实现，用测试和类型检查筛掉 8 个，比让人逐行挑错更高效。
- 除了测试，还要评估非功能指标：导入时间、依赖数量、包体积、内存占用。AI 重写可能让一个轻量库变成依赖树怪物。
- 还要关注供应链与许可证问题：AI 重写可能引入新依赖、复制代码片段。Python 库尤其要注意依赖膨胀，建议跑 license 扫描和 SBOM。

## 结语：先别急着把键盘收起来

1. 把“AI 能写”和“应该由 AI 写”分开。样板代码、迁移、格式化、测试脚手架可大量外包；核心算法和安全边界仍要人审。
2. 先建验证闭环，再放开生成。测试、类型检查、CI、review 之外，还要有可回滚的版本管理。AI 生成快，回滚也要快。
3. 关注维护成本与所有权。代码生成只是生命周期起点，文档、依赖、重构、退役才是大头。AI 不替你承担 on-call，也不会替你背锅。
