“中介”在互联网语境里常被当成轻资产、不性感的角色。但当 36kr 报道全球最大大模型中介 OpenRouter 被 Snowflake 以约 63 亿美元、折合人民币约 471 亿元收购时，很多人开始重新理解这门生意的厚度。OpenRouter 不训练大模型，也不囤 GPU，它做的是模型 API 的统一入口、计费、路由和分发。成立不过三年，它从开发者小工具长成“全球最大模型中介”，最终被数据云巨头收入囊中。这个价格买的不只是一个通道，而是一个正在形成的 AI 工作流入口。



## 1. 不是模型厂，而是模型“路由器”

OpenRouter 的模式，简单说就是“模型聚合层”。

- 用户只需在 OpenRouter 注册一个 key，就能调用数百个模型：GPT、Claude、Llama、Mistral、DeepSeek 等都在同一个接口下。
- 平台提供统一 API 格式，屏蔽不同模型厂商的输入输出差异，开发者改一个 `model` 字段就能切换。
- 计费、退款、发票、预付费、按量付费全部由平台统一处理，模型调用按 token 结算。
- 平台还会做自动路由、缓存、重试、故障转移，开发者不用为每个模型维护一套 SDK 和错误处理。

可以把它理解成支付聚合商：银行和卡组织很多，但商户只对接一家聚合商。OpenRouter 把模型供给和开发者需求之间的复杂度“吃掉”，让自己成为标准层。

## 2. 越“中立”越值钱：聚合长尾的飞轮

OpenRouter 能长成全球最大，核心不是技术多难，而是它站在了一个双边网络效应的位置上。



- **供给端越丰富**：开源模型、中小模型厂商、大模型厂商都愿意接入。对中小模型团队来说，OpenRouter 帮他们省掉支付、税务、合规、客户支持、SDK 维护，几乎是零成本获得分发渠道。
- **需求端越集中**：独立开发者、创业公司、甚至企业团队不需要同时维护多个模型账户，也不需要每接一个模型就改一次架构。
- **中立性稀缺**：单一模型厂商自己推 API 有排他性，OpenRouter 不属于任何一家模型厂，这种中立让它成为多模型评估、切换、降级的天然场所。
- **数据飞轮**：平台沉淀大量真实调用数据——哪个模型在哪类任务上质量更好、延迟更低、失败率更高。这些数据反过来优化路由策略，让平台推荐的模型组合越来越贴近开发者真实需求。

模型越多，开发者越愿意来；开发者越多，新模型越愿意接入。这个飞轮一旦转起来，后来者很难靠单纯的“更低抽成”打破。

## 3. 471亿不是按利润算的，是按入口与数据算的

很多人看到 471 亿元人民币，第一反应是：“一个中介抽佣，凭什么这么贵？”

- OpenRouter 本质上是抽佣或加价生意，毛利并不像软件订阅那么高。但基础设施估值看的是 ARR、增速、开发者习惯和入口稀缺性。
- 公开报道显示，其年化收入已经跨过 1 亿美元级别。如果按 63 亿美元收购价倒推，估值倍数相当高，市场买的是远期收益和生态位。
- 真正值钱的资产，不是“中介”这个身份，而是开发者 token 消费数据、多模型性能反馈、计费结算系统、模型兼容层。
- 这类入口一旦形成习惯，迁移成本很高。开发者把 key、预算、日志、缓存都放在平台上，切换就意味着重写调用层。

类比来看，数据库时代 Snowflake 是数据仓库入口；AI 时代，模型路由可能成为工作流入口。入口不一定有最高毛利，但往往有最强控制力。

## 4. Snowflake在买什么：数据云与模型流量的合流

Snowflake 是云数据仓库龙头，2020 年上市，这些年一直想从“存数据”延伸到“跑 AI”。

- Snowflake 之前已经推出 Cortex AI、ML 功能，但缺少一个开放的模型分发层。客户在数据平台里想调用多个模型，仍然要自己解决 API 碎片化问题。
- 收购 OpenRouter 后，企业可以在数据治理边界内选择模型、管理预算、审计调用，数据不必离开 Snowflake 的权限体系。
- 对 Snowflake 客户而言，多模型选择意味着不被单一模型厂商绑定；对 OpenRouter 而言，获得企业渠道和云资源，从小开发者群体进入大客户市场。
- 更长的路线是：Snowflake 把数据权限、查询引擎、模型路由合成一条“从数据到模型调用”的安全工作流。这是 AWS Bedrock、Azure AI Foundry、Google Vertex AI 都在抢的方向。

不过整合挑战也明显。OpenRouter 是极简、开发者友好的工具，Snowflake 是复杂企业平台，两者产品节奏、定价逻辑、企业文化之间仍有不少要磨合的地方。

## 5. 三点冷思考：别只看见“中介”，要看见“标准层”



这次收购至少留下三个判断框架：

1. **做 AI 应用时，别把模型调用写死在业务逻辑里。**  
   至少在架构上保留统一网关、fallback 和模型切换能力。今天最强的模型不一定明天最划算，绑定单一模型会让成本与能力都失去弹性。

2. **控成本不是只盯着 token 单价，而是看“任务-模型匹配”。**  
   简单任务用便宜小模型，复杂推理再上大模型；同时关注平台缓存命中率、批处理折扣、失败重试策略。省下的往往不是单价，而是不必要的“大模型杀鸡”。

3. **判断一个基础设施平台有没有价值，看三个控制点。**  
   是否沉淀可复用的数据或标准；是否形成双边网络效应；是否真正掌握计费、结算、权限等关键环节。三者缺一，再热闹的“中介”也可能只是套壳。下次再看到“AI 中间层”被高价收购，先问它卡住了哪一条。
