在 Agent 驱动本地脚本或 MCP 插件的场景中，我们经常让 Agent 生成并执行一段 Python/Shell 来自动整理文件、处理数据、写临时结果。如果没有任何限制，Agent 生成的代码有可能读取、改写甚至删除关键目录下的文件。仅靠 Prompt 提示“不要碰 /etc 或 ~/.ssh”是不可靠的，我们需要用工程手段把文件访问限定在一个白名单目录内——给 Agent 装上一个可执行的护栏。

## 问题：为什么 Prompt 级限制靠不住

典型场景：你通过 OpenClaw 让 Agent 统计一个 project 目录下的 Python 文件数量，Agent 会写类似以下代码：

```python
from pathlib import Path
for py in Path("/home/user/project").rglob("*.py"):
    print(py)
```

但如果你没有限制，Agent 完全可能写出：

```python
for py in Path("/home/user").rglob("*.py"):
    # 顺便读一下 ../.env 或 ~/.ssh/id_rsa
```

模型不知道宿主环境的安全边界，它会根据上下文“自由发挥”。一旦你给 Agent 配了 MCP filesystem 工具或 code-interpreter 插件，这种越界就会变成事实上的数据泄露或文件损坏。

所以，必须从执行层面加护栏：**让 Agent 生成的代码只能访问指定目录，超出就抛异常并阻断操作。**

## 设计思路：运行时路径校验 + 规范化

目标：定义一个安全根目录 `SAFE_ROOT`，Agent 执行过程中任何文件读/写/删除的路径，必须落在该目录下。我们需要处理几种典型绕过方式：

- 绝对路径穿越：`/etc/passwd` 直接不在白名单内
- 相对路径：依赖当前工作目录，需先解析为绝对路径再判断
- 符号链接：链接指向白名单外，需解析真实路径
- `..` 穿越：`/home/user/project/../../etc/passwd` 规范化后变成 `/home/etc/passwd`

统一策略：**在每次文件操作前，用 `os.path.realpath()` 解析出文件的真实绝对路径，然后检查是否以 `SAFE_ROOT` 为前缀**（需处理尾部路径分隔符，防止 `/home/user/project_bak` 被误判为在 `/home/user/project` 下）。

## 实现：一个可复用的 Python 上下文管理器

下面给出一个可直接植入 Agent 执行环境的 `FileGuard` 类，采用上下文管理器包裹批量操作，或者单独暴露 `guard_path()` 供拦截使用。

```python
import os
from pathlib import Path
from contextlib import contextmanager

class FileGuard:
    def __init__(self, root: str):
        # 确保根目录不存在歧义，统一用 realpath 并加分隔符
        self.root = os.path.realpath(root) + os.sep

    def guard_path(self, given_path: str) -> Path:
        """返回合格的 Path 对象，否则抛出异常"""
        target = Path(given_path).expanduser().absolute()
        real = Path(os.path.realpath(target))
        if not str(real).startswith(self.root):
            raise PermissionError(
                f"Access denied: {real} is outside allowed root {self.root}"
            )
        return real

    @contextmanager
    def safe_roots(self):
        """上下文管理器，暂时未限制全局，仅做示范"""
        yield self
```

如果 Agent 执行环境是独立 Python 进程，可以把 `FileGuard` 注入 `builtins.open`、`os.remove`、`shutil` 等，用猴子补丁全局拦截。例如：

```python
import builtins

_original_open = builtins.open

def guarded_open(file, mode='r', *args, **kwargs):
    safe_root = os.environ.get("AGENT_SAFE_ROOT", "/tmp/agent_sandbox")
    guard = FileGuard(safe_root)
    # 只写/创建操作需要检查，只读也可按需放行
    if 'w' in mode or 'a' in mode or 'x' in mode:
        guarded_path = guard.guard_path(file)
        return _original_open(guarded_path, mode, *args, **kwargs)
    else:
        # 读操作也需要检查，防止读敏感文件
        guarded_path = guard.guard_path(file)
        return _original_open(guarded_path, mode, *args, **kwargs)

builtins.open = guarded_open
```

启动 Agent 代码前设置环境变量 `AGENT_SAFE_ROOT` 即可，比如指向 `/home/user/agent_workspace`。这种方法会让所有依赖 `open` 的第三方库也受到限制，需注意兼容性。

## 踩坑记录

1. **符号链接戏法**  
   用户在 `/home/user/project/data` 下建了个软链接 `secret` -> `/etc/passwd`。Agent 通过 `project/data/secret` 路径访问，如果用 `os.path.abspath` 而不调用 `realpath`，前缀匹配可能通过。必须用 `realpath` 解析最终目标。

2. **分隔符尾部缺失**  
   假设 `root = "/home/user/project"`，攻击者构造 `/home/user/project_bak/secret`。如果用 `path.startswith(root)` 会误判为安全。解决：统一加 `os.sep` 后缀（`"/home/user/project/"`），再判断。

3. **相对路径与 os.getcwd()**  
   如果 Agent 代码内部调用了 `os.chdir()`，可能改变后续相对路径的解析结果。在 `guard_path` 中强制用 `expanduser().absolute()`，先锚定到绝对路径再做解析。

4. **与 MCP filesystem 工具的冲突**  
   如果你在 OpenClaw 中通过 MCP 提供了 `read_file` 工具，该工具后端也需要应用同样的 `FileGuard`，否则 Agent 可能绕过 Python 脚本直接用工具读越界文件。需要在插件服务端实现统一校验逻辑。

5. **临时文件目录**  
   许多库会使用 `/tmp`，如果白名单未包含 `/tmp`，相关操作将失败。需要把 `/tmp` 或其子目录加入安全白名单，或单独映射一个临时目录到沙箱内。最简单的：直接让 `SAFE_ROOT` 指向一个完整的项目工作区，Agent 只在该目录下读/写/执行。

## 可复用建议

- **把 FileGuard 作为一个独立模块部署到 Agent 镜像或执行环境**，所有自定义 executor 都导入它，并全局替换 `open`。避免每次写 Prompt 时叮嘱“只写到工作目录”。
- **将白名单根目录作为环境变量注入**，方便容器化和多租户隔离。例如 `AGENT_WORKSPACE=/srv/agent-tasks/{task_id}`。
- **和代码审查结合**：在执行前对 Agent 生成的代码做静态扫描，检查是否有 `eval`、`exec`、`subprocess` 等潜在逃逸手段。FileGuard 主要挡文件访问，但进程执行需要额外限制（可用 `seccomp` 或 `nsjail`）。
- **应用在插件侧**：若你自研 MCP 插件（如自定义 file_ops.py），务必在工具函数入口调用 `guard.guard_path()`，然后返回结果。这是最后一道防线。
- **记录被拒绝的访问**：将异常日志输出到监控系统，可以发现 Agent 是否有异常行为或被提示注入。

## 总结

给 Agent 加目录白名单不复杂，核心就是“真实路径解析 + 前缀匹配”，再配合全局钩子或工具层拦截。工程实践中的细节主要在于符号链接、路径分隔符和第三方库兼容。一旦落成，Agent 就能在限定区域内安全地操作文件，自动整理、生成报告、转换格式都不再需要担心越界读取你的 SSH 密钥或环境变量文件。

护栏的价值不是装饰，而是让自动化脚本在生产环境真正可放行。
