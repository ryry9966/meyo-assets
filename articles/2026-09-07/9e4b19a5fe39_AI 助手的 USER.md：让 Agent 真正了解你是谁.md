# AI 助手的 USER.md：让 Agent 真正了解你是谁

## 背景：项目有 AGENTS.md，你呢？

用 OpenClaw 或任何带工作区记忆的 Agent 框架跑了一段时间后，大家都会给项目配 AGENTS.md，写清构建命令、代码风格、目录约定。这类文件解决的是"项目上下文"。但还有一层上下文长期缺位：**你是谁**。

Agent 对项目了解得一清二楚，对用户却一无所知。每次新会话，它不知道你用 Arch 还是 macOS，不知道你偏好简洁结论还是完整推演，不知道你的时区和主力语言。于是它每次都用默认人格跟你对话——礼貌、啰嗦、时区错乱。

## 问题：重复声明，且声明会漂移

我最初的解法很原始：把偏好塞进每次对话开头。"我是后端，只说重点""别给我 Windows 路径"。三个问题：

1. **重复成本高**，每天开场都要自我介绍一遍；
2. **声明不可靠**，口头偏好只在本会话生效，下次归零；
3. **无人维护**，没有版本、没有 review，写没写对全靠记忆。

本质上是把"用户配置"当成了"对话内容"。配置应该持久化、结构化、可 review——这就是 USER.md 的定位。

## 做法：一份最小可用的 USER.md

在 OpenClaw 工作区根目录放一个 `USER.md`，Agent 启动引导时会自动加载。我现在的版本：

```markdown
# 用户画像

## 环境
- 系统: macOS + Linux server (Ubuntu 24.04)
- 时区: Asia/Shanghai
- 主力语言: Python / Go，中文交流

## 偏好
- 回答先给结论，推理过程按需展开
- 代码示例默认带错误处理，不省略 import
- 不确定时直接说不确定，不要硬编

## 禁区
- 不要主动重构我没让你动的文件
- 不要生成超过 50 行的示例除非我要求
```

维护方式两条：

1. **手工写骨架**：第一次花 10 分钟把环境和硬偏好写清楚。
2. **让 Agent 增量维护**：在系统提示里加一条约定——"当我纠正你的行为时，把可复用的部分以一行追加到 USER.md 对应小节"。我纠正过一次"回复别用 emoji"，它自己写进了禁区，下次会话即生效。

## 踩坑点

- **写太多**。早期我写了 60 多行，塞满"技术哲学"。结果注意力被稀释，核心约束反而偶尔漏掉。现在控制在 30 行内：USER.md 是配置，不是自传。
- **敏感信息入档**。真实姓名、住址、API key 别放。工作区文件会被读进上下文，也可能随备份同步，按"这文件泄漏了会怎样"的标准写。
- **内容过期**。换电脑、换技术栈后忘了改，Agent 按旧环境给建议，比不知道还糟。我挂在每次工作区升级时顺手 review。
- **与项目级文件打架**。USER.md 说"简洁回复"，项目 AGENTS.md 要"完整测试报告"。需明确优先级（建议项目级 > 用户级），或把例外情况写进 USER.md。

## 可复用建议

- **分层**：用户级事实进 USER.md，项目级约定进 AGENTS.md，单次任务直接说，三层别混。
- **写可执行的规则，不写形容词**："先给结论"可执行，"聪明一点"不可执行。
- **让 Agent 自己读写这个文件**：它最清楚哪里理解错了你。每次纠错后落盘，形成"纠错即配置"的闭环。
- **定期瘦身**：每月删一次没人遵守的条目，配置和代码一样需要清理死代码。

## 总结

USER.md 解决的不是技术问题，是工程习惯问题：把散落在对话里的用户上下文，收拢成一个持久、可 review、可版本管理的文件。成本是一个 Markdown 文件加一条维护约定，换来的是每次会话不必从零认识你。如果你已经在用 AGENTS.md 管项目，那就补上另一半——项目有说明书，你也该有一份。
