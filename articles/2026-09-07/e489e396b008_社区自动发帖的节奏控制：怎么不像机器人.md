# 背景

用 OpenClaw + MCP 工具做社区自动发帖，已经是很常见的玩法：Agent 定期生成内容，通过论坛或 IM 的 API 推出去。链路跑通只要一个晚上，但要跑得"像个人"，花的时间多得多。这篇只讲一件事：**节奏（pacing）**。

# 问题

被识别成机器人，通常不是内容本身的问题，而是时间特征太整齐：

- cron 固定在整点/半点触发，时间戳精确到秒
- 每天发帖数量恒定，周末照常
- 发完就走，从不回复评论
- 多个社区零延迟同步发布同一篇内容

人和机器的差别，大部分不在"发什么"，而在"什么时候发、发了之后干嘛"。

# 做法

**1. 调度层加抖动。** 不要用裸 cron。在触发层加随机延迟：基准间隔 ±30%~80% 抖动，并避开整点：

```python
delay = base * (0.2 + random() * 1.6)
```

每个频道单独配令牌桶限速和日上限；失败重试用指数退避 + 抖动，避免重试风暴。

**2. 对齐社区的真实活跃曲线。** 采样目标社区一周的流量分布，把发帖时段概率往高峰区靠，深夜和节假日降权。注意：均匀随机本身就是机器特征，要用真实分布做采样底座。

**3. 内容节奏错开。** 长文、短评、链接分享、答疑按比例混排，别让 Agent 每次都输出"标题 + 三段论 + emoji"的固定结构。可以在 prompt 里注入风格种子（口语度、段落长度、是否带图），连续输出相似度超阈值就换模板。

**4. 发帖后要有"后动作"。** 这是人味最重要的一环。评论来了不要秒回：在 5~40 分钟内随机挑一个时间点回复，回复频率低于发帖频率。嫌复杂的话，至少让 Agent 发帖 30 分钟后读一遍评论区，标记需要人工接手的问题。

**5. 高风险动作走人工审批。** 用 OpenClaw 的审批模式或往审核频道推 webhook：跨社区同步、首次接触新社区的内容，全部人工过一遍。

# 踩坑点

- **均匀随机 ≠ 自然**：分布要对齐真实流量，而不是 `random()` 一把梭。
- **重试风暴**：网络恢复瞬间把积压帖子一次性发出，比固定节奏更显眼。队列必须有冷却窗口。
- **LLM 输出太干净**：结构完美、零口语、emoji 习惯恒定，本身就是签名。风格注入要做，但别做成"每次换个花哨开头"——那也是一种规律。
- **跨频道内容重复**：同一篇内容多社区同时发是最容易暴露的行为。至少错开 2~6 小时，并做本地化改写。
- **别碰平台红线**：有的社区明确禁止自动化发帖。遵守官方 API 限频、必要时亮明身份，比任何伪装都可持续。

# 可复用建议

把节奏参数收敛成一份配置：`jitter_ratio`、`daily_cap`、`active_hours`、`reply_delay_range`、`cooldown`。审计日志单独落盘，记录计划时间、实际时间、拦截原因。调整节奏参数后跑满一周，再对比互动指标（评论率、举报次数）下结论。最后，**留一个 kill switch**——一条命令停掉所有自动发帖，这比任何优化都重要。

# 总结

节奏控制不是伪装术，是邻里礼仪。Agent 发得像人，本质是尊重社区的带宽：按大家的作息说话、发完负责到底、不占公共资源。链路一晚跑通，节奏值得调一个月。
