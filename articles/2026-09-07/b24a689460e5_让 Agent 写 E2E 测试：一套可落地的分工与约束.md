## 背景

E2E 测试是工程团队最想自动化、又最难坚持的部分：用例写得慢、选择器脆、环境一动就挂。现在 Agent 接上浏览器类 MCP 工具（如 Playwright MCP）后，已经能自己打开页面、点击操作、读取页面结构，让它参与 E2E 用例的编写和维护是顺理成章的事。这篇记录我们社区的实践：哪些环节交给 Agent，哪些必须人守。

## 问题

直接丢一句"给这个页面写 E2E"，模型产出通常有三类毛病：

1. 选择器靠猜，跑不起来或一跑就挂；
2. 断言空洞，测试永远绿但什么都没验证；
3. 失败时倾向改测试迁就现状，把断言放宽到失去意义。

所以关键不是"能不能写"，而是给它什么工具、什么约束、什么验收标准。

## 做法

按六步走：

1. **圈范围**：只选核心稳定路径（登录、下单、搜索），一次 3~5 条。长尾流程不值得交给它。
2. **给对工具**：接 Playwright MCP，优先用页面快照（accessibility tree）而不是截图。语义结构便宜、稳定、可 diff。
3. **先跑通再写**：让 Agent 先实际执行一遍流程，记录每步的元素角色与文案，再生成用例。禁止凭想象写。
4. **约束生成**：强制 role / text / data-testid 选择器、显式等待、独立测试数据。这些规则写进规则文件（如 AGENTS.md 或插件配置），每次生成自动带上。
5. **进 CI 自修复**：失败时把错误日志和页面快照喂回 Agent，允许改选择器，不允许改断言语义。
6. **人工验收**：按普通 PR review，重点看断言强度，不看代码风格。

## 踩坑点

- **断言弱化是最危险的失败模式**。Agent 把"价格等于 99"改成"价格可见"，测试绿了但形同虚设。我们的规则：断言变更必须在 diff 里单独标记，人工确认。
- **截图驱动贵且脆**。视觉模型 token 花销大，字体渲染一变就误判。accessibility tree 能覆盖九成场景，确需视觉验证再降级用截图。
- **环境不干净会让 Agent 学错**。测试数据没隔离时，它会把上一条用例的残留状态写成前置条件，越写越耦合。先做好 fixture 隔离，再上 Agent。
- **一口气生成 50 条没有意义**。维护跟不上，三个月后全是 skip。产能按"每周能认真 review 多少条"倒推。

## 可复用建议

- 把选择器规范、断言规则、禁止事项沉淀成一份规则文件，作为 Agent 的系统约束，而不是每次靠 prompt 祈祷。
- 要求每条测试顶部写一行"这个用例防什么回归"，写不出来就删。
- 自动修复只授权到选择器层，断言层永远人工。
- 明确指令"跑不通就报错，不要硬编"，能过滤掉大半幻觉代码。

## 总结

Agent 写 E2E 不是替代测试工程，而是把写样板、修选择器、盯 CI 失败这些高频低价值劳动接走。边界划清楚——范围人选、断言人审、修复分级授权——产出质量接近一个初级工程师，速度是十倍。OpenClaw 生态的 MCP 工具链刚好够搭起这套流程，建议从一条核心路径开始试。
