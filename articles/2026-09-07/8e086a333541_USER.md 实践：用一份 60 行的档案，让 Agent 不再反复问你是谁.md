## 背景

OpenClaw 的工作区里有一个常被忽略的文件：`USER.md`。它在每次会话启动时被注入上下文，作用是把"你是谁"确定性地告诉 Agent。它和 MEMORY.md 的分工是：记忆是检索式的、概率性的，而 USER.md 是每轮必达的。很多人装完就把它留成模板，或者随手贴一段自我介绍——这其实是整个 Agent 配置里性价比最高的文件。

## 问题

没有一份像样的 USER.md 时，典型症状是：

- 每次都要重申环境："我在 macOS 上，用 zsh，Node 22"；
- Agent 给的方案默认 Windows 路径、错的时区、你不用的语言；
- 沟通风格反复横跳，今天极简明天啰嗦；
- 同一个偏好（比如"注释用中文"）在记忆里丢了就失效。

根因：这些信息属于**稳定事实**，却被当成了要靠记忆检索的**事件**。

## 做法

编辑 `~/.openclaw/workspace/USER.md`，按五段组织：

```markdown
# 基本情况
- 时区 Asia/Shanghai，主要用中文交流

# 环境
- macOS + zsh，编辑器 Neovim
- 主力语言 TypeScript / Python，Node 22，pnpm
- 服务器：两台 Ubuntu 22.04，SSH 直连

# 偏好
- 回答先结论后解释，先代码后说明
- 注释和 commit message 用中文
- 不加 emoji 和客套话

# 边界
- 改配置文件前先展示 diff
- 删除操作必须二次确认

# 当前
- 2025-06 起：在做 xx 自动化项目（细节见 MEMORY.md）
```

要点：只写"会改变 Agent 输出"的事实，用条目不用段落，控制在 60 行以内。写完放进 dotfiles 仓库用 git 管理，多机同步。

## 踩坑点

1. **写成简历。** 三页自我介绍只会稀释信号、浪费 token。判断标准：这一行删掉后，Agent 的输出会变差吗？不会就删。
2. **塞敏感信息。** USER.md 每轮都进 prompt，真实姓名、手机号、密钥、公司内部信息一律别放。
3. **和记忆打架。** 记忆里残留的旧事实（换了工作、换了机器）会和 USER.md 冲突，Agent 可能两边都信。原则：USER.md 管稳定事实，MEMORY.md 管事件，定期清理记忆里的过期项。
4. **时间敏感内容写成永久事实。** "正在做 X 项目"三个月后就是错的——要么带日期，要么挪到记忆。
5. **一次写完不再维护。** 最有效的用法是增量式：Agent 哪次假设错了，就往 USER.md 加一行。这是成本最低的纠偏手段。

## 可复用建议

- **环境段落收益最大**：一次写清 OS/shell/运行时版本，能省掉无数次重复问答。
- 偏好要写具体行为（"先结论后解释"），比"简洁一点"这种形容词有效。
- 换工作、换设备、开新项目，是自然的复查节点。
- 多 agent 场景下，确认子代理是否继承工作区上下文，必要时在 AGENTS.md 里显式引用。

## 总结

USER.md 本质上是"给自己的 prompt engineering"：十分钟的投入，换来 Agent 不再反复问你是谁、不再猜错你的环境。它不玄学，就是一个每轮必读的配置文件——按配置文件的纪律去维护它，就够好了。
