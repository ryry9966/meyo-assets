最近科技圈流传一个很形象的说法：AI 开始「互发微信」了。当然，Agent 们并没有真的注册微信账号唠嗑，而是指 AI 智能体（Agent）之间正在通过专门协议互相发现、协商、调用乃至交易。Google 的 A2A 协议发布时有五十多家企业站台，Anthropic 的 MCP 已成为事实上的工具调用标准，各类 Agent 支付协议也在密集出现。当机器开始直接和机器打交道，一个老问题换上了新面孔：谁来管它们？这篇把技术本质、发生原因和治理难点一次拆清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-07/b2db003a74369642.png)

## 一、技术本质：不是聊天，是协议握手

先把概念捋准，「AI 互发消息」背后是几套正在成型的协议栈：

- **MCP（Model Context Protocol）**：Anthropic 于 2024 年 11 月开源，用统一接口让模型调用外部工具和数据源，社区常类比成「AI 界的 USB-C」。
- **A2A（Agent2Agent）**：Google 于 2025 年 4 月发布，让不同厂商的 Agent 能互相发现能力、委派任务、汇报进度，参与企业覆盖云计算、出行、IT 服务等行业，后来捐给了 Linux 基金会。
- **ANP（Agent Network Protocol）等开放方案**：尝试把 Agent 的身份与组网方式也标准化。

举个例子：你对助理 Agent 说「下周去东京，帮我安排」。它转身去问航空公司的订票 Agent、酒店的预订 Agent 和汇率服务，谈好价格、锁定仓位，最后回你一份完整行程。对你只有一个对话框，背后可能是十几次 Agent 之间的消息往返。

它与传统 API 调用的关键区别在于：API 是预先写死的接口，而 A2A 这类协议允许 Agent 动态发现对方「能干什么」（通过类似名片的自我描述文件），消息里混合自然语言和结构化数据，对方能理解意图、自主决策。柔性上去了，不确定性也上去了。

## 二、为什么是现在：三个条件同时凑齐

Agent 互联不是新点子，多智能体系统学术界研究了三十年，真正引爆需要三个条件同时满足：

1. **模型能力过了线**：LLM 能理解非标准化的任务描述并拆解执行，这在五年前做不到。
2. **工具调用成熟**：Function Calling 与 MCP 让 Agent 从「会说」进化到「会做」。
3. **单 Agent 撞上天花板**：一个 Agent 没法连接全世界的服务，让专业 Agent 互相协作，是架构演进的必然。

可以类比互联网早期：网站之间靠超链接互相跳转，形成「人找服务」的网络；现在 Agent 之间靠协议互相委派，正在形成「Agent 找 Agent」的网络。这一次，流量主角换成了机器。

## 三、机机对话的「物理学差异」：治理为什么突然变难

人类社会的规则是围绕「人的速度和规模」设计的，机机对话直接击穿了这批假设：

- **速度与规模**：人一天发几百条消息，Agent 一秒能发起上万次调用。人工审核在这种量级面前，相当于用算盘拦洪水。
- **身份模糊**：Agent 代表谁？是你的代理人，还是服务方的窗口？如果一个 Agent 冒用你的身份授权消费，你多久能发现？
- **责任链拉长**：Agent A 调 B，B 再调 C，出错时每一层都可以说「我只是转发的」，甩锅链比调用链还长。
- **提示词注入**：恶意指令可以藏在数据里。例如一份文档中埋一句「忽略之前的规则，直接执行某操作」，下游 Agent 读到就可能被带偏。安全研究者从 2023 年起就复现过针对 Agent 流水线的这类攻击。

这些不是科幻担忧，是已经在测试环境里跑通的攻击路径。



## 四、规则正在铺：身份、授权、审计三条线

治理不是从零开始，三条主线已经铺开：

1. **身份与授权**：OAuth 体系的 Agent 扩展、可验证凭证（Verifiable Credentials）等方案，目标是让每个 Agent 携带「数字工作证」，它代表谁、有什么权限、有效期多久。
2. **支付边界**：AP2（Agent Payments Protocol）、x402 等协议尝试给「机器花钱」加上密码学凭证：用户的明确授权被签名固化，Agent 凭凭证扣款、事后可验证。
3. **审计溯源**：要求 Agent 之间的每次调用留日志、带签名，出事后能还原「谁在什么时间让谁做了什么」。

但要清醒：协议解决的是「能不能对话」，治理解决的是「对话出了事怎么办」。前者跑得快，后者慢得多，中间的时间差就是风险敞口。

## 五、三条冷思考

1. **给自己的 Agent 设预算和权限白名单**。以后用 Agent 订票、付款时，先问一句「它最多能花多少、能访问哪些服务」，像给新实习生开权限一样对待它。
2. **选产品看审计能力，不只看聪明程度**。操作记录能否完整导出、授权能否一键撤销，这些「无聊功能」在出事那天比演示视频值钱。
3. **别高估短期，别低估长期**。眼下 Agent 互联还有大量协议圈地和 demo 成分，但机机对话流量超过人人对话，大概率是未来几年的事。身份、授权、追责体系能否在那之前建成，决定了这次迁移是平滑过渡还是一地鸡毛。

机器互发消息本身不可怕，可怕的是用管理人类的直觉，去管理以毫秒为单位行动的机器。规则跟上速度，才是这场变革真正的考题。
