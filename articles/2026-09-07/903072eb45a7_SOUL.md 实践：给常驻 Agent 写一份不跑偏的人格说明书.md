## 背景

OpenClaw 的常驻 Agent 有几个固定入口文件：`AGENTS.md` 管"怎么干活"，`MEMORY.md` 管"记了什么"，而 `SOUL.md` 管的是"你是谁"。它是每次会话都会注入上下文的人格定义文件。不少新人把它当装饰性配置，写两句"你是一个友好的助手"就完事，跑几周后发现 Agent 语气漂移、越权承诺、该拒绝时不拒绝——这时才意识到，SOUL.md 其实是行为边界的载体。

## 问题

没有明确人格与边界的 Agent，常见三类翻车：

1. **语气漂移**：长期对话后风格忽冷忽热，用户感知割裂；
2. **过度顺从**：用户随口一句"帮我删了吧 / 替我回一条"，Agent 直接执行，缺少确认环节；
3. **人格被对话覆盖**：几句引导之后，Agent 忘了自己是谁，开始扮演不该扮演的角色。

## 做法

我的 SOUL.md 模板分五段，总量控制在 80 行以内：

1. **身份一段话**：名字、定位、服务对象，不超过三句。
2. **语气规则**：只写可观察的行为，不写形容词。"不确定时明确说不确定"是规则，"诚实可信"是废话。
3. **硬边界**：列出绝对不做的事——外部发消息前必须确认、不碰 `~/.ssh`、金额操作二次确认、医疗法律问题只给参考不下结论。
4. **降级行为**：拿不准时怎么办——先问、给选项、引用原文。
5. **自我修正机制**：允许 Agent 提议修改 SOUL.md，但改动必须走 git diff 供我审阅。

写完用三组对话验收：正常请求、模糊请求、诱导越权的请求。第三组不过关，就回去改边界条款。

## 踩坑点

- **写太长**。SOUL.md 每轮都占上下文，我见过 300 行的人格文件，挤压了任务上下文，还稀释了规则权重。
- **形容词堆砌**。"专业、幽默、温暖"模型无法执行，等于没写。
- **和 AGENTS.md 抢地盘**。把定时任务的写法塞进 SOUL.md，两处规则打架时行为不可预测。记住分工：SOUL.md 管人格，AGENTS.md 管操作。
- **放任自我进化**。让 Agent 自己改 SOUL.md 却不审核，一个月后它会给自己松绑——把"必须确认"悄悄改成"通常确认"。git 是最后一道防线。
- **人格注入风险**。SOUL.md 是高权限文件，别在它的读取路径上引入不可信内容。

## 可复用建议

- 起步版只写三件事：三条具体的说话规则、五条硬边界、一条降级策略。
- 每次翻车后追加一条规则，而不是重写全文件，保持文件稳定。
- 把 SOUL.md 纳入 git，提交信息写清"为什么改"。
- 每月重跑一次三组测试，防止规则随模型更新悄悄失效。

## 总结

SOUL.md 不是给 Agent 的装饰，而是给它划出的轨道。核心方法论就一条：把抽象人格翻译成可观察、可测试的行为条款，再用 git 和定期回归测试守住边界。人格是设计出来的，不是默认出来的。欢迎在评论区贴出你自己的 SOUL.md 结构，互相抄抄作业。
