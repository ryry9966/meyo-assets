## 背景

OpenClaw 的 agent 有一个固定的工作空间（默认 `~/.openclaw/workspace`），里面有 `AGENTS.md`、`MEMORY.md`、`memory/` 等文件。其中 `AGENTS.md` 最特殊：每次会话启动时，它会被整份注入 agent 的上下文。换句话说，这是你唯一能保证"每次都生效"的指令位。

和 MEMORY.md 的分工要分清：MEMORY.md 记录事实，AGENTS.md 定义规则。前者是日记，后者是员工手册。

## 问题：没有手册的 agent 每天都在"重新入职"

没有手册的 agent，表现是可预测的不稳定：

- 同一件事反复纠正：语气、输出格式、哪些目录能动、哪些命令要先确认；
- 频道串味：私聊里克制得体，一到 Telegram 群里开始刷表情；
- 工具滥用：本地文件能解决的事偏要开浏览器，shell 操作一通才想起来先问一句；
- 边界模糊：把临时对话里的一句"帮我装个依赖"理解成长期授权。

这些都不是模型能力问题，而是规则没有持久化。你在聊天里说的每句话，会话结束就丢了。

## 做法：把它当成新人入职文档写

我的 AGENTS.md 目前 120 行左右，分六块：

1. **身份与语气**：两三行。服务谁、默认中文、代码注释语言、emoji 只在对方先用的频道使用。
2. **环境事实**：操作系统、用户目录、时区、常用项目路径、本机关键工具版本。agent 每次都在猜环境，不如直接告诉它。
3. **工具与 MCP 策略**：什么场景用什么工具，什么场景禁止。比如"读本地文件不开浏览器""shell 命令先展示再执行""有对应 MCP 工具时不手写脚本"。
4. **安全边界**：安装依赖、删除文件、向他人发消息、涉及凭据的操作，一律先确认；密钥只从环境变量读，不落盘、不复述。
5. **频道行为**：按 WhatsApp / Telegram / Discord 分别写，显式限定 scope，避免串味。
6. **记忆协议**：什么算"值得写进 MEMORY.md 的事实"、每日 reset 后该做什么。

写法遵循一个模板：**触发条件 + 动作 + 例外**。例如："用户要求安装 npm 包 → 列出包名和用途等待确认 → 例外：workspace 内已有项目的 package.json 更新。"

## 踩坑点

- **写成散文**。模型对短句、祈使句、带边界的规则的遵循度，远好于一大段理念描述。删掉所有"你应该具备……的意识"这类话。
- **规则互相冲突**。"任何命令都要确认"和"别拿琐事烦我"放一起，模型只能随机站队。冲突时用优先级语句显式裁决。
- **把密钥写进去**。AGENTS.md 每个会话都进上下文，等于每次都把钥匙递过去。密钥放环境变量，手册里只写"从哪读"。
- **膨胀**。这是按 token 计费的常驻上下文。超过两三百行就该做减法，参考性内容挪到 memory 文件按需检索。
- **改完不重开会话**。AGENTS.md 在会话启动时读取，改完记得 `/new` 或重启 gateway 再验证，否则你以为生效了其实没有。
- **跨频道规则不写 scope**。"不要刷表情"如果不限定群聊，私聊里它会变得过度拘谨。

## 可复用建议

- **当代码管理**：workspace 放进 git，每次改 AGENTS.md 走 diff 和 commit，回滚和审计有据可查。
- **让 agent 自己维护**：发现自己在聊天里第二次纠正同一件事，直接说"把这条写进 AGENTS.md"，然后 review 它提交的改动。人定方向，AI 做初稿。
- **换机迁移先拷它**：新机器装完 OpenClaw，第一个恢复的文件应该是 AGENTS.md，它比插件列表更能复现你的使用习惯。
- **多 agent 场景**：每个 workspace 各有一份，通用策略抽出来保持同步，别让两份手册悄悄分叉。

## 总结

AGENTS.md 是 OpenClaw 工作空间里杠杆最高的文件：几百行、零代码、每个会话都生效。把它当作"给一个每天失忆的聪明同事写的入职手册"来维护——短、具体、可验证，冲突显式裁决，内容随踩坑迭代。手册写得好，你在聊天里说"不"的次数会肉眼可见地减少。
