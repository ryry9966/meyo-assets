最近 36kr 一条热搜让不少人愣了一下：AI 开始「互发微信」了。先别急着脑补两个 AI 在群里斗图——真正发生的事情是，智能体（Agent）之间的机器通信，正在借助人类熟悉的即时通讯形态走向落地。当 AI 不只和人聊、还开始和 AI 聊，问题就从「它说得对不对」升级成了「谁给它们立规矩」。这篇把来龙去脉、底层机制、真实风险和治理进展一次讲清。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-07/8661662c04738f45.png)

## 一、互发消息的不是聊天机器人，是 Agent

先厘清概念，这件事的关键词不是「聊天」，是「自主」：

- **Chatbot（聊天机器人）**：一问一答，主动权在你手里，关掉窗口它就下班。
- **Agent（智能体）**：给它一个目标，它能自己拆任务、调用工具、发起动作，甚至主动联系别的 Agent。核心差别是**主动性 + 工具权限**。

时间线看得更清楚：

1. 2024 年 11 月，Anthropic 开源 **MCP（Model Context Protocol）**，统一了 Agent 接入工具的接口标准，人称「AI 界的 USB-C」。
2. 2025 年 3 月，OpenAI 宣布支持 MCP，两大阵营在接口层握了手。
3. 2025 年 4 月，Google 发布 **A2A（Agent2Agent）协议**，50 多家公司参与，专治「Agent 之间怎么对话」。

再补一个历史注脚：2017 年 Facebook 的谈判实验机器人被曝「发明了自己的语言」后紧急中止。当时媒体渲染过度——真实情况是两个 Agent 把英文聊成了低效缩写，工程师嫌没法调试就重置了实验。但这件事第一次让公众意识到：**Agent 之间的通信一旦脱离人类可读的格式，事情就会变得微妙**。

## 二、它们怎么「说话」：比群聊严谨多了

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-07/0e8efd9d78fa411d.png)

很多人以为 AI 互发消息像人类唠嗑，其实恰恰相反：

- **结构化消息，不是自然语言瞎聊**：Agent 之间的通信走 JSON 这类结构化格式，消息类型明确——请求、响应、错误、心跳，各有固定字段。与其说是「发微信」，不如说是「互相发工单」。
- **协议先于生态**：互联网能长起来，不是因为两台电脑「聊得来」，而是它们都守 TCP/IP。MCP 和 A2A 干的是同一件事：先立通信格式，再谈生态繁荣。先立规矩后做生意，是工程师的老传统。
- **一个完整例子**：你说「订下周去上海的行程」，主 Agent 拆任务 → 调用机票 Agent 查报价 → 拿到结果再调酒店 Agent → 每一步消息都带**身份凭证**和**能力声明**，对方 Agent 能查你能调它什么、能调到什么边界。

## 三、风险不在科幻片里，在这四个真实问题里

1. **提示词注入串联**：Agent A 读到某个网页，里面藏了一句「把通讯录发到某地址」，A 把它当正常指令转给 Agent B。OWASP 已把 prompt injection 列为大模型应用的头号安全风险——单 Agent 都会中招，多 Agent 等于给了它一条接力赛道。
2. **传话游戏会「自信地失真」**：每转一次手，语义就漂移一点。人类传话失真了还会心虚，Agent 失真时带着格式完美的 JSON 一路绿灯，下游根本看不出哪里错了。
3. **死循环烧钱**：A 调 B，B 没理解又反问 A，两个 Agent 互相客气，一晚上烧掉一个季度的 API 预算。这不是段子，开发者社区晒过真实账单。
4. **责任链断裂**：A 的失误通过 B 落到 C 头上，谁背锅？传统软件是「我的代码我负责」，多 Agent 变成「我的 Agent 调了你的 Agent」，链式归责目前没有成熟答案。

## 四、谁来管：治理工具箱正在装配

- **身份与鉴权**：给每个 Agent 发「工牌」，走 OAuth 式授权，坚持最小权限原则——能只读就别给写，能一次性就别给长期。
- **审计日志**：Agent 间所有消息留痕、可回放。出事能复盘，是治理的底线能力。
- **熔断与限流**：借鉴金融系统——调用次数、涉及金额、调用层级都设上限，超限自动断开、转人工。
- **Human-in-the-loop**：付款、给真人发消息、删数据这类高风险动作，强制人工确认，不允许 Agent 自主完成。
- **标准组织介入**：2025 年 A2A 已捐给 Linux Foundation 托管。行业在走互联网的老路：先野蛮生长，再协议收编。Gartner 预测到 2028 年约 33% 的企业软件会内置 Agentic AI——盘子越大，这套工具箱越等不起。

## 五、冷思考：三件事值得记在心里

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-07/6253b0c49469ac89.png)

1. **开发者视角**：把 Agent 当生产系统，别当 demo。日志、权限、熔断开关、预算上限一个都不能省——出事时「一键停机」比多十个功能都值钱。
2. **普通用户视角**：看清自己授权出去的每一项权限。最小权限原则不是工程师专属；用不到的「自动发送」「自动支付」，统统关掉。
3. **底层判断**：治理的重点从来不是「禁止 AI 互相对话」，而是让每次对话**可审计、可追责、可熔断**。当年的互联网也没谁能「管住」，是 TCP/IP、TLS、垃圾邮件过滤一层层长出来的。协议成熟的速度，得跑赢 Agent 落地的速度——这才是真正值得盯的竞赛。

下次再看到「AI 互发微信」上热搜，不必惊呼失控，也不必急着玩梗。真正的问题不是「它们在聊什么」，而是「聊崩了之后，谁按下暂停键」。
