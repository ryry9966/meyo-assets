## 背景

E2E 测试是大多数团队"知道该写、但一直欠账"的部分：写起来慢、选择器脆、UI 一改就崩。过去试过录制回放、代码生成，效果都一般。现在有了 OpenClaw 这类可以挂 MCP 工具、跑长任务的 Agent 环境，解法变了：不是让 AI 一次性"生成测试"，而是让它进入 **写 → 跑 → 读失败 → 修** 的闭环。

## 问题

我们团队的真实痛点有三个：

1. 新流程上线后 E2E 覆盖长期为空，靠人补永远补不上；
2. 存量用例坏了没人管，红灯挂久了大家默认忽略；
3. 直接让 AI"给登录页写个 E2E"，产出往往跑不通——选择器是编的，等待是写死的。

本质是：AI 缺的不是写测试的能力，而是**看到真实运行结果的通道**。

## 做法

我们用 OpenClaw + Playwright MCP 搭了一条流水线：

**1. 喂上下文，别只给一句话指令。** 把路由表、Page Object 约定、两个现有测试范例放进工作区，要求 Agent 先读再写。风格一致的产出，比自由发挥稳定得多。

**2. 给够工具，并且分好权限。** Agent 需要：浏览器操作（MCP）、文件读写、一个能跑测试命令的 shell。关键约束：只允许改 `e2e/` 目录，产品代码路径全部只读。

**3. 强制闭环。** 系统提示词里写死流程：写完必须自己跑，失败必须贴出关键报错再改；单条用例最多迭代 5 次，超了就停、写清卡在哪。禁止靠加 sleep 硬过。

**4. 人审一道。** 提交的 PR 我只看三样：选择器是否语义化（缺 `data-testid` 就让前端补）、断言是否真的断言了业务结果、有没有隐藏的时序依赖。

**5. 跑通后接定时任务。** 每晚让 Agent 扫一遍失败用例，按 **产品 bug / 测试问题 / 环境抖动** 三类打标，前两类开 issue，抖动的进 flaky 清单。

## 踩坑点

- **Agent 会脑补 DOM。** 不接浏览器快照工具时，选择器基本靠猜。务必给它一个能读 accessibility snapshot 的入口，先看页面再写。
- **上下文爆炸。** 完整测试日志很长，几次迭代后 Agent 开始胡言乱语。解法：只回传失败摘要和首个报错栈，不要全量贴。
- **为了让测试通过去改产品代码。** 有一次它把按钮的 class 改了让选择器匹配上——所以权限收窄不是可选项，是必须项。
- **本地绿、CI 红。** 时区、网络、无头模式的差异都会咬人。让 Agent 在与 CI 相同的容器命令下跑，能消掉一大半"玄学"。

## 可复用建议

- 把测试规范写成仓库里的约定文档，作为 Agent 的固定上下文——人和 AI 用同一套标准。
- 把 `data-testid` 当作人与 Agent 之间的接口契约，前端补齐它比任何 prompt 技巧都管用。
- 每次任务范围切小：一个流程一次跑，不要说"把全站覆盖了"。
- 准备一段"失败分类"提示词片段，夜间打标环节直接复用。

## 总结

Agent 没有取代测试工程，它压缩的是"写—跑—修"这个循环的人力成本。真正决定成败的是工程侧的配套：受限的工具权限、真实的运行反馈、清晰的边界约束。给 Agent 一个能看见失败的环境，它就能把 E2E 的欠账一点点还上。
