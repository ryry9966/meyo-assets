## 背景

用 AI 助手（尤其是 OpenClaw 这类 Agent 框架）越久，越会发现一个反复出现的痛点：每次新开一个会话，你都要重新交代自己的技术栈、项目结构、代码风格、工具偏好，甚至当前正在做的事情。这些话术不仅重复，稍不留神还会遗漏关键信息，导致 Agent 回答跑偏。

对于个人用户这是体力活，对于自动化流水线或 MCP 插件场景则更致命——你可能在一个自动化 Pipeline 里调用 Agent，它根本等不到你“手动补充上下文”。

理想的方案是：有一个持久化、结构化、可版本控制的「个人使用说明书」，Agent 启动时自动读取，把“你是谁、你想要什么、你的环境长什么样”这类信息作为隐式的 system knowledge 注入。

这就是 USER.md 的动机。

## 问题拆解

我们需要解决三个子问题：

1. **信息采集**：哪些信息对 Agent 是真正有用的，哪些只是噪音。
2. **注入方式**：怎么把这个文件稳定地喂给 OpenClaw 或其他 Agent 框架，且不浪费过多 token。
3. **维护策略**：如何让这份文件随着你的实际工作同步演进，而不是沦为一次性文档。

下面我会围绕这三个点，给出已经在生产环境（个人 & 小团队自动化）实际跑通的方案。

## 做法 / 步骤

### 1. 设计 USER.md 的结构

一份对 Agent 友好的 USER.md 应该是**高度结构化的 Key-Value + 简短叙述**，避免大段散文。我的推荐模板：

```markdown
# User Profile

## Basics
- Role: backend engineer / open-source maintainer
- Preferred language: TypeScript, Go
- OS & Shell: macOS, zsh

## Current Focus
- Project: OpenClaw CN docs (openclaw.cn)
- Active branches: feature/mcp-auth
- Deadline context: personal project, weekends only

## Preferences
- Code style: Prettier defaults, no semicolons
- Commit style: conventional commits (feat:, fix:, chore:)
- PR template: link to .github/pull_request_template.md
- Test framework: vitest
- Linting: biome

## Repo Map
- openclaw/docs: documentation site
- openclaw/core: agent engine
- openclaw/mcp-server: MCP tool implementations

## Constraints
- No npm packages that bring heavy native deps (avoid node-gyp)
- All generated code must be in TypeScript strict mode
- Never change package.json scripts without asking
```

关键原则：
- 每个一级标题代表一个“上下文域”，方便 Agent 按需提取。
- 避免长篇叙述，用列表、键值对。
- 包含**当前焦点**和**约束条件**，这比“我会 Python”更有即时价值。

### 2. 注入到 OpenClaw 会话

OpenClaw 从设计上支持通过 MCP 或内置插件（如 `user-profile`）加载这类文件。如果你的环境尚未提供自动化，最朴素的方式是：在每次对话开始时，将 USER.md 整个追加到 system prompt 中。

示例（伪代码）：

```python
user_md = Path("~/.openclaw/USER.md").read_text()
system_prompt = f"{base_system_prompt}\n\n[User Profile]\n{user_md}"
```

但这种全量插入对长文件不友好（成本高、降低注意力）。更好的做法是：

**结合 MCP 工具，让 Agent 主动查询**。将 USER.md 注册为一个 MCP 资源（resource），Agent 在需要时通过 `mcp://user-profile` 获取全部或部分内容。OpenClaw 的资源体系正好支持这种“按需拉取”的模式，避免一开始就把一大堆 token 泼过去。

具体步骤：
1. 定义 MCP server，暴露 `resource://user-profile`，背后实际上就是读取 `~/.openclaw/USER.md` 并可以按 section 过滤。
2. 在 OpenClaw 的配置中启用该 MCP server。
3. Agent 在回答问题时，可以自主调用 `readResource`，根据问题选择性地获取 `Current Focus` 或 `Preferences` 部分。

这样做的好处是，USER.md 膨胀到上千行时，Agent 不会因为无关上下文而分心。

### 3. 版本化与团队复用

USER.md 属于极度私人的配置，但其中与项目相关的部分（如 Repo Map、Constraints）完全可以提取为项目级的 `PROJECT.md`，保存在仓库根目录，供整个团队使用。个人私有的开发偏好（如代码风格）保留在个人配置中。

建议：
- 个人文件路径：`~/.openclaw/USER.md`
- 项目级文件：`./.openclaw/PROJECT.md`
- 在 Agent 查询时，将两份文件内容做**分层合并**：项目底层 + 个人上层，项目信息优先级更高。

## 踩坑点

1. **信息过载导致 Agent 关注力稀释**  
   一开始我塞了 200 行，包含所有技术栈细节、过往项目经验。结果 Agent 经常“记不住”当前焦点，反而会用到三个月前的信息。后来严格按照“与本周工作相关”做裁剪，效果立竿见影。

2. **隐私泄露**  
   USER.md 会出现在 LLM 的上下文里，如果你用第三方 API（如 OpenAI），那么这些信息会离开本地。务必只写**可公开的工程信息**，不要把密钥、内部系统地址、私人日程写进去。敏感配置走环境变量或独立的 secrets 管理。

3. **文件编码与路径问题**  
   在 Windows 环境下，直接使用 `~/.openclaw/` 可能被解析到意料外的目录。建议通过环境变量 `$OPENCLAW_HOME` 显式指定，跨平台一致性更好。

4. **热更新与缓存**  
   在长时间的 Agent 任务中，你可能修改了 USER.md，但 MCP server 可能缓存了旧内容。记得在 MCP 实现中加入文件变动监听（如 `fs.watch`），或在每次资源读取时检查 mtime。

## 可复用建议

- **用 Git 管理 USER.md**  
  放在 dotfiles 仓库里，和你的 `.zshrc`、`.gitconfig` 一同维护。更新后 push，多台机器同步。
- **添加一个 `last_updated` 字段**  
  方便 Agent 判断信息新鲜度。若发现某部分信息过于陈旧，Agent 可以提示你更新，甚至自动帮你生成新版草稿。
- **与 OpenClaw 的“记忆插件”结合**  
  短期偏好（比如“今天的任务”或“刚修了一个 bug 还需要回归”）更适合用 Memory/Memo 插件，而 USER.md 适合长期稳定的“元信息”。
- **写一个简单的 linter**  
  检查 USER.md 中是否包含疑似敏感词（如 `password`, `secret`, `http://internal`），集成到你的 editor 或 pre-commit hook。

## 总结

USER.md 本质上是将“人”抽象为一种可被 Agent 消费的 profile，使得每次交互的初始上下文损耗降到最低。它在工程上的价值不止于省去重复自我介绍，更在于把个人工程方法论和约束**固化成可执行的上下文**，让 Agent 输出更贴近你的现实需求。

对于 OpenClaw 社区用户，结合 MCP 资源按需拉取、项目级 PROJECT.md 分层、Git 版本化这几招，几乎可以在不引入新依赖的情况下，显著提升 Agent 的“长期理解能力”。但务必记住：精简 > 详尽，安全 > 便利。
