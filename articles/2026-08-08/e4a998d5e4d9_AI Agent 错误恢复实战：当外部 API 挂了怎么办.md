## 背景

AI Agent 通常不是孤岛，它需要调用外部 API 来获取实时天气、查询数据库、搜索网页或触发下游系统。在 OpenClaw、MCP 工具链或自动化插件中，一个任务往往由多次外部调用串联而成。当某个 API 出现问题——超时、返回 503、限流或网络闪断——如果 Agent 没有妥善处理，整个自动化流程就会中断，轻则丢失上下文，重则需要人工重置整个任务，这在生产环境中代价很高。

## 问题

多数 Agent 实现中，工具函数直接发起 HTTP 请求，捕获异常就把错误堆栈扔回 LLM 或直接终止。面对瞬时故障，这种方式毫无自愈能力。我们需要一套工程化的错误恢复机制，让 Agent 在外部依赖不可用时，能够尽可能继续工作、降级处理，并在恢复后自动重试，减少人工介入。

## 做法 / 步骤

### 1. 为 API 调用套上带退避的重试

对可重试的错误（5xx、429、连接超时），使用指数退避 + 随机抖动，避免惊群效应。例如：

- 首次失败等待 1s，第二次 2s，第三次 4s，上限 30s。
- 可重试次数一般设为 3 次，结合合理超时（总耗时 < 60s），防止阻塞过久。

在 OpenClaw 的工具定义中，可以用装饰器包装每一个 MCP 工具调用，统一实现重试逻辑。

### 2. 引入熔断器（Circuit Breaker）

当某个 API 连续失败达到阈值（例如 5 次），直接快速失败，不再发起真实请求，保护下游免受无效压力，也让 Agent 快速得到失败反馈而不是长时间等待。熔断器一段时间后进入“半开”状态，允许一次探测调用，如果成功则关闭熔断，否则继续保持打开。分布式场景下，多个 Agent 实例应共享熔断状态（基于 Redis 或 etcd），否则每个实例独立熔断无法有效保护后端。

### 3. 设计降级与缓存策略

对于读操作为主的 API（天气、汇率、新闻），可以在成功时缓存响应并记录时间戳。一旦调用失败且熔断器打开或重试耗尽，使用最近一份缓存数据作为降级返回值，并在响应中标记数据陈旧度（如 `stale_seconds: 600`），让 LLM 知晓当前信息可能滞后，决策时更加保守。

写操作（发送通知、创建工单）的降级更需谨慎。通常是暂存失败的操作到持久化队列，待 API 恢复后异步补发，同时告知 Agent 操作已“延迟执行”。

### 4. 持久化检查点，支持断点续传

Agent 执行长任务时，每完成一个重要步骤（如搜索、分析、写初稿），可以将状态和中间结果序列化到文件或数据库。这样，即使后续 API 调用失败导致 Agent 崩溃，重启任务时可以从最近的检查点恢复，避免重新执行已成功的昂贵步骤。在 OpenClaw 中可以利用插件生命周期或自定义工具钩子，在步骤间隙保存状态。

### 5. 超时控制与告警

为每个外部调用设置连接超时（如 5s）和读取超时（如 30s），防止资源被长时间挂起。同时，记录 API 成功率、熔断开启次数、降级使用量，接入监控（Prometheus + Grafana），并设置告警。当某 API 持续降级超过 1 小时或失败率飙升时，通知运维介入。

## 踩坑点

- **重试风暴**：多个 Agent 同时重试可能加剧 API 故障。必须限制单实例的重试并发，最好在全局队列中控制对同一 API 的并发请求数。
- **无差别的降级导致决策错误**：若把昨天天气当今天返回，Agent 可能做出错误判断。降级数据必须带上时间戳，让 LLM 知道数据陈旧，并在提示词中引导 Agent 在数据不可靠时询问用户或跳过该步骤。
- **检查点状态不一致**：保存检查点时，要确保与当前执行步骤原子化。部分成功的副作用（如已发送一封邮件）再恢复时可能导致重复执行。需要设计幂等操作或状态标记。
- **熔断恢复探测时机**：若“半开”探测请求恰好遇到 API 短暂恢复又失败，会使熔断时间延长。可以配置探测间隔和成功率要求，例如连续 2 次成功才关闭熔断。

## 可复用建议

- 封装一个 `ResilientAPIClient` 工具类，内置重试、熔断、缓存降级，所有 MCP 工具上层调用时统一复用，避免散落各处的错误处理代码。
- 使用成熟库：Python 中 `tenacity` 处理重试、`pybreaker` 实现熔断、`diskcache` 做本地持久缓存，减少造轮子。
- 策略参数化：每个 API 的配置（超时、重试次数、熔断阈值、缓存有效期）通过配置文件或环境变量管理，便于针对不同 SLA 调整。
- 提供手动旁路开关：在运维面板中为关键 API 设置“强制降级”或“跳过”开关，紧急情况下可绕过异常链路。
- 编写集成测试模拟 API 故障，验证 Agent 在降级、重试、熔断下的行为是否符合预期。

## 总结

让 AI Agent 稳定运行在生产环境，不能假设外部 API 永远可靠。通过组合重试退避、熔断保护、降级缓存、检查点状态与监控告警，Agent 可以从被动崩溃变为主动恢复。工程上没有银弹，但先从关键业务路径开始，逐步加固外部依赖的韧性，是投入产出比最高的务实做法。
