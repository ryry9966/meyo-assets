## 背景

用 OpenClaw 跑了一段时间的人大概都有类似体感：模型能力不是瓶颈，瓶颈是"稳定性"。同一个 agent，昨天冷静克制，今天热情过度；换个会话，称呼、语气、做事边界全变了。系统提示词越堆越长，改一处怕牵连全身。

IDENTITY.md 是 OpenClaw workspace 里的一个约定文件，agent 在会话启动时读取，用它锚定"我是谁、怎么说话、什么不做"。它不是黑魔法，本质是一段会被注入上下文的 Markdown——但正因如此，它可读、可 diff、可回滚，是 agent 系统里少有的真正"可进化"的配置。

## 问题

实践中身份不稳定通常来自三种情况：

1. 身份信息散落在系统提示词、memory 和对话里，没有单一事实来源；
2. 改提示词全靠感觉，没有版本记录，改坏了不知道回退到哪一版；
3. 身份和用户事实混在一起，换个用户或场景就得重写。

## 做法

**1. 建立最小骨架**，先跑起来再迭代：

```markdown
# IDENTITY
- 名字：
- 角色定位：一句话说清你是干什么的
- 语气：克制、简洁、不说客套话
- 语言：默认中文，代码注释英文
- 红线：不执行的操作 / 必须先确认的操作
- 汇报方式：结论 + 依据，不确定就直说
```

**2. 控制篇幅**：建议 30 行以内。身份文件是"宪法"不是"百科"，操作细则交给 TOOLS.md，经历交给 memory。

**3. 进 git**：把 workspace 纳入版本控制，每次调整都写 commit message。身份的演化历史本身就是最好的调试记录。

**4. 用对话反馈驱动迭代**：发现 agent 某类行为不对（比如总是过度道歉），不要只在对话里纠正了事，而是沉淀一条到 IDENTITY.md，再跑验证。

## 踩坑点

- **写太长**。超过一两百行后，模型对中间内容的遵循度明显下降，效果反而不如 20 行精确的约束。
- **和系统级指令冲突**。比如身份文件写"永远不联网"，而工具链默认联网，模型会在两者之间摇摆，表现为行为随机。冲突内容必须合并到一处。
- **把用户隐私写进去**。身份文件每次会话都会加载，等同于最高频暴露面，只放 persona，不放数据。
- **改完不验证**。改完身份后跑 3~5 个固定测试对话（问候、任务委派、边界试探），确认语气收敛再继续用。
- **多 agent 共用一份身份**。职责不同，身份就该 per-agent，共性内容抽到公共文件引用。

## 可复用建议

- 把身份当代码：小步提交，一次只改一个维度（语气或红线，不要一起动）。
- 分清三个文件：IDENTITY.md 管"我是谁"，USER.md 管"你是谁"，memory 管"发生过什么"。混放是身份漂移的主要根源。
- 每月做一次 identity review，删掉不再需要的条目——文件和代码一样需要减重。
- 固化一组"身份探针"对话做回归测试，改一次，测一次。

## 总结

IDENTITY.md 的价值不在于让 agent"更像人"，而在于把行为中本来随机的那部分，变成可版本化、可评审、可回滚的工程对象。它很小，但它是 agent 系统里少有的、改一行就能全链路生效的杠杆点。先用起来，再慢慢进化——这本身就是它的设计本意。
