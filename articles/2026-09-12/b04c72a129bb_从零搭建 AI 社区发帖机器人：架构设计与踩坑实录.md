## 背景

社区每周要发一期资源汇总：GitHub Release、论坛精华帖、值得关注的讨论。手工做了三期之后，问题暴露得很典型——拖稿、格式不统一、链接贴错。于是我基于 OpenClaw 搭了一个发帖机器人：cron 定时触发，Agent 负责收集和起草，人审后发布。目前稳定跑了五周，本文记录架构取舍和踩过的坑。

## 目标与约束

这件事的难点不在"让 LLM 写一篇帖子"，而在工程约束：

- 定时从固定信源抓素材，按社区口吻起草
- 前期必须人工审核，不能直接自动发布
- 不重复发、不漏发、不发模型编造出来的链接

## 架构

拆成三层：

1. **触发层**：OpenClaw cron 任务，每周一 09:17 触发（故意避开整点）。
2. **Agent 层**：一个专职 agent，系统提示词只写职责边界；素材获取走 MCP——fetch server 拉 RSS，另写了一个小 MCP server 包装 GitHub API。
3. **动作层**：只暴露两个工具 `draft_post`（写草稿目录）和 `publish_post`（人审通过后调社区 API）。

目录结构：

```
sources.yaml   # 信源与抓取规则
style.md       # 口吻、禁词、格式模板
drafts/        # 待审草稿
state.db       # 内容 hash 幂等键 + 发布记录
```

## 踩坑实录

**1. 幻觉链接。** 第一版让模型"整理本周动态"，它写出了一条不存在的版本号和配套链接。修复方式不是加一句"请不要编造"，而是硬约束：prompt 明确只允许引用工具返回条目，draft 工具校验每条链接必须出现在素材清单里。

**2. 重复发帖。** cron 误触发一次，叠加失败重试，同一篇发了两遍。解决：发布前查内容 hash，publish 动作加文件锁。幂等键用 hash，不用时间戳。

**3. 定时太规律被反垃圾盯上。** 整点触发连续两周后，社区 API 开始返回 429。加 ±10 分钟随机抖动后消失。

**4. Token 失控。** 早期把所有 RSS 全文塞进上下文。改成两段式：先抓标题+摘要，Agent 挑选后再拉选中条目的全文，单次成本降了约 70%。

**5. 格式转义。** 论坛 API 吃的是受限 Markdown，草稿里嵌套反引号直接把排版打爆。在 publish 工具里加了一层白名单渲染，超范围就拒绝发布。

**6. 提示词漂移。** 口吻规则最初堆在系统提示词里，改一次风格等于全量重调。拆出独立的 style.md 后，风格变更可以走 git 单独 review。

## 可复用建议

- **采集、起草、发布三段拆开**，任何一段可单独重跑，失败不污染全局
- **事实与风格分离**：事实必须来自工具返回，风格收进独立文件
- **前两周强制人审**，稳定后再对低风险类别（如纯链接汇总）放开自动发布
- **失败要可见**：发布失败推一条 IM 消息，禁止静默重试

## 总结

发帖机器人本身不难，难的是把"偶尔聪明"做成"持续可靠"。幻觉靠工具层约束，不靠提示词哀求；重复靠状态表，不靠运气；风格靠文件版本管理，不靠模型记忆。这套三段式结构后来被我复用到周报和 changelog 翻译两个场景，改动基本只有信源配置和 style.md——这也说明它是对的抽象层级。
