最近有条新闻在技术圈刷了屏：一位 00 后安全员对市面上一批“中转站”做了实测，发现这类服务把用户请求原样落盘，累计数据量达到 6TB；其中泄漏的凭证与密钥，经匹配足以进入 26 家知名校企系统。听起来像电影桥段，但把链路拆开看，每一环都是工程世界里再普通不过的“设计选择”叠加出来的结果。这篇文章不渲染情绪，只回答三个问题：中转站为什么会漏？6TB 是怎么堆出来的？我们该怎么防？

## 中转站：一门架在“必经之路”上的生意

先厘清概念。所谓中转站（API relay / proxy），典型形态是：你的请求不直接发给上游服务，而是发给一个第三方，由它转发并回传结果。

- 它存在的理由很朴素：价格差、合规差、网络可达性差。有人拿不到上游额度，有人图便宜图省事，中间商应运而生。
- 技术上，它是“合法的中间人”：为了改写请求头、计费、限流，中转站必须终结 TLS（TLS termination），看得见你发出的每一个字节——prompt 全文、随身携带的 API key、甚至内部接口地址。
- 这意味着此类架构的安全上限，等于运营者的自觉性，协议层不提供任何兜底。

用工程师的话说：把机密文件交给陌生复印店，然后祈祷店主不做副业。中间人问题并不新鲜，从邮件中继到短信验证码平台，“二道贩子”架构的信任危机一直在重演，只是这轮被 AI 调用量成倍放大了。

## 6TB 是怎么“滚”出来的：数据雪球模型

单条请求只有几 KB，6TB 显然不是一天攒下的，它靠三件事相乘：

1. **全量落盘**。不少中转站以“排查问题”为由，把 request/response 完整存储：不脱敏、不过期、不加密。
2. **长期聚合**。做个算术：平均单次全量日志 10KB，两万日活、人均每天 30 次调用，一天就是约 6GB；日志三年不清理，6TB 就“自然生长”出来了。
3. **内容密度极高**。用户发给模型的 prompt 里什么都有：测试环境的数据库密码、内网域名、客户名单，甚至整段业务代码。“向模型提问”这个动作，天然会把敏感信息带出组织边界。

雪球滚大时只是资产，进入黑市就变成弹药。灰产渠道里，一条有效的 API key、一组能登录的账号密码，都是明码标价的硬通货。

## 从一条 Key 到 26 家系统：攻击链拆解

“6TB 攻入 26 家校企系统”是报道里最扎眼的一句，但拆开看是一条经典杀伤链，全程不需要 0day：

- **采集 → 清洗**：从日志里筛出高价值字段——密钥格式串、邮箱密码对、内网地址段。
- **撞库（credential stuffing）**：利用的是密码复用这个老毛病。某员工用来注册中转站的密码，往往和公司邮箱、VPN、内部 OA 是同一个，自动化工具拿着凭证组合批量尝试即可。
- **校企系统为何先破**：边界系统普遍“三多”——历史遗留系统多、弱口令多、临时账号多，且缺少异常登录审计。门多、锁旧、没监控，攻击者自然优先挑软柿子。
- **横向移动**：进入一个边缘系统后，顺着内网信任关系一路摸向核心数据。

这条链的材料成本几乎为零：配置疏忽、密码复用、日志裸奔，三者叠加，就够搭出最贵的灾难。

## “揭底”与“攻击”之间：合规测试的分界线

这位安全员的做法本身也值得展开。安全研究与黑产用的是同一套技术，分界线只有三条：

1. **授权与最小化**：只采集证明问题所需的最小数据量，不扩大战果，不触碰无关系统。
2. **脱敏与不牟利**：报告里隐去所有可复用的凭证细节，数据不留存、不交易。
3. **负责任披露（responsible disclosure）**：先私下通知受影响方，给出修复窗口，再决定公开时机。

任何一步为了流量或利益“顺手”了，性质就变了。白帽子的职业价值正在于此：在坏人敲门之前，先由自己人把门锁检查一遍。

## 防御清单：把“信任”换成“机制”

个人与企业面对的其实是同一道题：不要假设任何中间环节是善意的。

如果你是普通用户：

- 不用来源不明的中转服务；非用不可，就默认自己在公共场合打电话，敏感信息一律不进 prompt。
- API key 存进环境变量或密钥管理工具，不进代码仓库、不进聊天记录；一旦怀疑泄漏，立即轮换。
- 不同系统不同密码，交给密码管理器托管——这一条能挡掉绝大多数撞库。

如果你管企业或学校系统：

- 上 secret scanning（gitleaks 这类开源工具即可）：仓库、日志、工单里出现密钥格式就告警。
- 凭证短时效 + 最小权限：即便泄漏，可利用窗口也只剩几分钟。
- 审计出站流量：海量数据流向陌生域名，往往比入站攻击更早暴露问题。
- 给边缘系统加 MFA 和异常登录检测，别让十年前的老 OA 成为整个内网的地板。

## 收尾：三条冷思考

1. 便利是有汇率的：中间环节每多一层，你支付的安全溢价就高一截，省下的钱迟早换一种方式付出去。
2. 数据的威胁不在单条多敏感，而在聚合之后是什么。6TB 的可怕之处，是把一万次无意的泄漏，锻成了一把有组织的钥匙。
3. 安全做得越好，越像什么都没发生。愿意在出事之前“敲门”的安全员，值得被认真对待，而不是被当成麻烦。
