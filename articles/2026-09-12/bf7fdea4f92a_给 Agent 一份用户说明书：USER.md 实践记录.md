## 背景

LLM 会话天然无状态。每次开新会话，Agent 对你的了解归零：技术栈、部署方式、代码风格、回复语言、命名习惯，全都要重新交代一遍。平台自带的记忆功能能缓解一部分，但记忆是碎片式、黑盒的——它记了什么、为什么这么记，你不可控。

USER.md 是一个更朴素的方案：用一个纯 Markdown 文件，显式、可版本化地描述"你是谁、你怎么工作"，在每次会话组装上下文时注入给 Agent。

## 问题

没有用户画像时，典型症状是：

- Agent 默认假设你用 Docker，而你实际是 systemd + 裸机部署；
- 它反复生成 pnpm 命令，但你仓库统一用 npm；
- 它用英文回复，而你的交付物全中文；
- 你纠正过的同一个问题，下周它又犯。

本质就一句话：Agent 缺一份持久的、由你主导的用户上下文。

## 做法

**1. 建文件。** 在全局配置目录放一份 USER.md，骨架参考：

```markdown
# 用户画像
## 身份与环境
- 角色：后端工程师，主要维护 Go / Python 服务
- 机器：macOS 开发 + Linux 服务器，无 Docker 桌面版
## 技术约定
- 包管理：npm（不是 pnpm / yarn）
- 提交：Conventional Commits，中文 subject
## 偏好
- 回复用中文，代码注释用英文
- 先给方案对比，再给推荐
## 禁区
- 不要自动执行删除类命令、不要碰生产环境
```

**2. 注入。** 三条常见路径：启动脚本读取后拼进 system prompt；通过 MCP 暴露为 resource 按需读取；插件 / hook 在会话初始化时自动挂载。在 OpenClaw 里建议走 MCP resource 或 hook，按需加载比全量塞 prompt 更省 token。

**3. 分层。** 全局 USER.md 只放跨项目通用信息；每个仓库再放一份 PROJECT.md，写构建命令、目录结构、部署流程。会话时按"全局 + 项目"合并注入。

## 踩坑点

- **写太长。** 超过一页纸，关键条目会被稀释。控制在 30 行以内，优先写"不改必出错"的内容。
- **写空话。** "我喜欢简洁的代码"没有约束力；"函数不超过 50 行，错误必须显式处理"Agent 才能执行。
- **信息过期。** 换技术栈不更新文件，Agent 会拿着旧地图导航。用 git 管它，改栈时顺手改。
- **与系统提示冲突。** 平台级 system prompt 规定英文回复、你的文件又要求中文，行为会不稳定。冲突条目要显式声明优先级。

## 可复用建议

- **让 Agent 自己维护。** 纠正它之后补一句"把这条写进 USER.md"，文档变成活的。
- **每季度审一次。** 像清理 dotfiles 一样清理用户画像，删掉不再成立的条目。
- **敏感信息不进文件。** 密钥、内网地址走环境变量或密钥管理器，USER.md 只写"密钥通过 1Password CLI 获取"这类指引。
- **文件即接口。** 换 Agent 框架、换工具链时这份文件可以带走——它声明的是你的工作方式，不绑定任何产品。

## 总结

USER.md 的价值不在"高级"，在于可控：内容你写的，变更是 git 记的，注入路径你选的。它把"Agent 懂我"从玄学变成工程问题。花二十分钟写第一版，之后每次纠正 Agent 时顺手沉淀一两条，两三周后你会发现，新会话不再需要从头自我介绍。
