## 背景

用 OpenClaw 接 MCP 工具做社区自动化是社区里聊得很多的话题：每周摘要、公告同步、新帖的首次回复，这些重复劳动交给 agent 很自然。我们频道跑了三个月，链路本身没出过大事，但第二周开始陆续有人问"发帖的是不是机器人"。复盘下来，问题不在内容质量，而在节奏——发帖的时间模式太干净，一眼就是 cron。

## 问题：机器味从哪来

对照发布日志，典型痕迹有四类：

1. 触发时间恒定，每周一 09:00:00 整，误差为零
2. 服务器跑 UTC、社区在 CST，摘要总在深夜发出
3. API 超时重试没做去重，短时间连发两条相同内容
4. 文案模板固定，开场白每次一样

这些都是工程问题，不是玄学，可以逐条修。

## 做法

**1. 把"发什么"和"什么时候发"拆开。** 内容 agent 只产出草稿和类型标签（announce / digest / reply），调度器独占发布权。解耦后调节奏不用动内容，改内容也不会破坏节奏。

**2. 两层调度。** 粗层按受众活跃时段定义窗口：工作日 9:30–11:30、14:00–17:00、20:00–22:00，全部换算成社区本地时间。细层在窗口内加非均匀抖动——我用对数正态偏移而不是 uniform，因为真人发帖间隔是长尾分布，均匀随机画出来的间隔直方图依然一眼假。

**3. 发帖前读一次频道状态。** 通过 MCP 的 read 工具看最近 30 分钟有无消息：频道安静就顺延到下一个窗口；上一条是自己发的且无新回复，直接跳过。这一条对"像人"贡献最大。

**4. 状态机 + 分档冷却。** 流程是 DRAFT → WAIT_WINDOW → POST → COOLDOWN，cooldown 按类型分档：公告 6 小时、摘要 24 小时、回复 45 分钟。失败走指数退避，最多 3 次，带 dedup key，重试绝不重复发布。

**5. 文案防同质化。** 每类内容准备 3–5 个 prompt 变体，禁止固定开场白；再加一层 embedding 相似度检测，和历史帖超过阈值就打回重写——agent 换个说法重发同一条公告，比定时任务更像机器人。

**6. 低置信度进人工队列。** agent 起草并附判断理由，人确认后才进窗口排队。因为起草和发布时间解耦，审核不会打乱节奏。

## 踩坑点

- **均匀随机不够。** 换加权窗口之前，间隔直方图规整得像打印出来的。
- **摘要类不能重度抖动。** 受众对"每周大概什么时候出"有预期，摘要锚定在窗口头部，只有公告才大范围抖动。
- **时区。** 第一次配置就栽在 UTC/CST 上，凌晨三点的帖被群友截图。
- **内容去重别省。** 节奏调好之后，重复内容成了最大的暴露源。

## 可复用建议

- 节奏全部配置化：窗口列表、分类型 cooldown、抖动参数，别写死在 cron 里
- 发布日志记全：时间、类型、决策原因，出问题能回放"为什么发了两条"
- 频率先砍半上线，两周无负反馈再逐步加
- 观测三个指标：发帖间隔直方图、单频道日发帖数、被问"是机器人吗"的次数——最后这条最诚实

## 总结

不像机器人的关键不是加随机，而是"有反应"：对频道冷热有反应，对失败有反应，对受众预期有反应。把调度和内容生成拆成两个模块之后，剩下的都是参数和日志的活儿，没有魔法。
