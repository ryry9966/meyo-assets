## 背景：我们给项目写了说明书，却没给自己写

跑 OpenClaw / Agent 的人大多会给项目配 `AGENTS.md` 或类似的 bootstrap 文件：测试怎么跑、目录结构是什么、哪些文件别碰。但很少有人反过来写一份“关于我”的说明。结果就是每次新会话都要重复交代：我用 pnpm 不用 npm，中文回答先给结论，commit 遵循 conventional commits，不要主动重构我没问的代码。

## 问题：偏好散落在对话历史里

这类信息有两个特点：高度稳定（几年不变），却只存在于历史会话中。Agent 每次冷启动都从零猜你的默认值，猜错一次你就得纠正一次。同时维护多个工作区时，同样的解释要重复 N 遍。这不是模型能力问题，是上下文工程问题。

## 做法：一份 100 行以内的 USER.md

**1. 位置与加载。** 全局放 `~/.openclaw/USER.md`，启动阶段读入系统提示；项目级 AGENTS.md 只放项目事实。优先级明确：项目覆盖全局，全局覆盖模型默认。

**2. 内容结构，只写事实：**

```markdown
# 环境
- macOS + Homebrew，Node 22 LTS
- 包管理器：pnpm，禁止用 npm 装依赖

# 代码习惯
- 格式化交给 Biome，不要手动调格式
- 未被要求时不重构、不加注释

# 沟通
- 中文回答，先结论后细节，不要寒暄
- 给方案先列权衡，再给推荐

# 红线
- 不要动 infra/ 目录
- 不引入新的状态管理库
```

**3. 写法原则：** 每条一行、祈使句、可执行。“不要用 npm” 是规则，“希望代码优雅” 是愿望——愿望模型没法执行，只会稀释注意力。

## 踩坑点

- **写成简历。** 把工作经历、技术叙事全塞进去，两三百行，关键规则反而被淹没。注意力是稀缺资源，超 100 行就该删。
- **全局与项目打架。** 全局说 pnpm，某个老项目强制 npm，agent 会犹豫。解法是在项目级文件里显式声明覆盖，别指望模型自己猜优先级。
- **敏感信息。** 真实姓名、公司名、内网地址、任何密钥都不要写。这份文件会进入上下文，随请求发出去。
- **过期不维护。** 换了包管理器、换了格式化工具，文件不改，agent 就一直按旧规则干活。当代码维护，季度 review 一次。

## 可复用建议

- **冷启动让 agent 代笔。** 直接说：“回顾我们最近的对话，总结我的技术偏好和工作习惯，输出一份 USER.md 草稿。” 然后人工删掉一半——它倾向于写多，你负责删。
- **进版本管理。** 放 dotfiles 仓库，改动走 diff，换机器直接同步。
- **分层，不堆大文件。** 稳定的个人事实放全局，项目相关放项目级，会话内的临时约定别写进来。

## 总结

USER.md 做的事情很朴素：把只存在于你脑子里的隐性偏好，显性化成一个模型每次都能读到的文件。半小时的写作成本，换来每次新会话省掉几分钟的重复交代，以及更一致的输出风格。它不会让 agent 变聪明，但会让它少犯那些“其实你早就说过”的错。对长期跑自动化任务的人来说，这份投入很划算。
