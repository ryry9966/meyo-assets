## 背景

Agent 跑起来之后，最高频的需求之一就是“帮我盯着这个页面”：文档更新、价格变动、公告发布。在 OpenClaw 里接一个 fetch/browse 类 MCP 工具并不难，几行配置 Agent 就“能上网”了。但从“能抓一次”到“安全、稳定、长期地抓”，中间差着一整层工程。这篇帖子记录我给 Agent 做网页采集时的做法与教训——把 Agent 当成一位“稽客”：可以登门查访、抄录，但得守规矩。

## 问题分三类

1. **合规与礼仪**：robots.txt、访问频率、UA 标识，这些决定你能不能一直抓下去。
2. **稳定性**：反爬机制、动态渲染、站点改版导致选择器失效。
3. **安全**：网页内容本质上是不可信输入。页面里可以藏指令（prompt injection），Agent 也可能在任务中“顺手”去抓没授权的域名，或者把整页 HTML 塞进上下文，token 爆炸还引入注入面。

## 我的做法：六步

1. **能不爬就不爬**。先找官方 API、RSS/Atom、sitemap，这些比抓 HTML 稳一个量级。
2. **明身份、守规矩**。自定义 UA 附上联系方式；遵守 robots.txt；限速用固定间隔加随机 jitter，比如 2–5 秒一请求。
3. **缓存与条件请求**。利用 ETag / Last-Modified，本地再存一层内容哈希，页面没变就不往下走。
4. **抽取而非搬运**。用 readability 式正文抽取，剥掉导航、脚本、广告，截断到上下文预算内再交给模型。
5. **把内容当不可信输入**。工具返回结构化结果（title、url、发布时间、正文摘要），不把原始 HTML 直接注入对话；维护域名白名单；禁止 Agent 自主展开页面里的链接。
6. **可观测**。每次抓取记录 URL、状态码、耗时、是否命中缓存；失败退避，连续失败熔断并告警。

## 踩过的坑

- 一开始没限速，并发抓一个站，几分钟后 IP 被封，还殃及同出口 IP 上的其他任务。
- requests 拿到的 SPA 页面是空壳。先看数据是不是走 JSON 接口，再考虑 headless 浏览器——后者资源开销大，还有指纹检测问题。
- 精确到 class 的 CSS 选择器活不过一次改版。改用语义化抽取，抽取失败立即告警，而不是返回空字符串装作成功。
- 最隐蔽的一次：Agent 在完成任务途中，根据页面里的一句话自行决定“再去抓这个链接”，形成了计划外的爬虫。之后我收紧了工具权限，抓取目标只允许来自显式配置。

## 可复用的建议

- 把采集封装成一个独立的 MCP 工具：入参只有 `url`、`mode`（fresh/cache）、`max_chars`，出参固定 schema，Agent 侧不需要理解爬虫细节。
- 目标站点配置化：每个站一份 YAML，写清允许路径、频率、抽取策略，新增监控项不改代码。
- 变更驱动：哈希不变不进下游，模型只看增量，省 token 也降低注入风险。
- 抓取日志落盘，出问题时能回放“当时到底抓到了什么”。

## 总结

Agent 的网页采集能力 = 一个克制的爬虫 + 一层不信任输入的安全边界。先做好礼貌与限速，再加内容净化与白名单，最后让每次抓取可观测、可回放。工具越小、契约越稳，Agent 在开放的网页里就越不容易跑偏。欢迎在评论区交流你们的采集管线设计。
