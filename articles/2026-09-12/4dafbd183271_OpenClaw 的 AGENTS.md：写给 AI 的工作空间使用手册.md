## 背景

OpenClaw 的 agent 每次会话都是"冷启动"：它不记得你上次的交代，只记得 workspace 里写了什么。workspace 根目录下的 `AGENTS.md` 是少数会被稳定注入上下文的操作手册，`SOUL.md` 管人格，`AGENTS.md` 管干活规矩。很多新手把它当成可有可无的备注文件，实际上它是控制 agent 行为确定性最便宜的手段，不用写一行插件代码。

## 它解决什么问题

- 每次开会话都要重复交代："我的项目在哪个目录""不要主动 git push""回复用中文"。
- 工具调用行为不稳定：同样的问题，有时走 MCP 查询，有时凭记忆瞎编。
- 多设备、多项目场景下规则散落在聊天记录里，无法沉淀。

一句话：把"你希望 agent 默认怎么做"从口头约定变成文件约定。

## 做法：四步写一份能用的 AGENTS.md

**1. 定位 workspace。** 默认在 `~/.openclaw/workspace`，可在会话里让 agent 执行 workspace 相关命令确认路径。在根目录创建 `AGENTS.md`，没有就新建。

**2. 按四类分区块写，每条一句话祈使句：**

- **环境事实**：操作系统、时区、常用项目根路径、偏好的包管理器。
- **工具规则**：优先用哪个 MCP 工具查什么；什么情况先问再动手。
- **安全红线**：明确列出禁止项，如不执行 `rm -rf`、不主动 push、不读取某些目录。
- **输出偏好**：语言、格式、是否要给出命令而非替你执行。

**3. 控制篇幅。** 建议 100 行以内。AGENTS.md 每次会话都占用上下文，写得越长，单条指令的权重越被稀释。

**4. 新会话验证。** 改完后开一个新会话，直接问 agent："列出你当前遵守的操作规则"。答不上来或答错的条目，换一种更直接的写法，而不是加大篇幅。

一个可复用的骨架：

```markdown
# 环境
- macOS / 上海时区 / 项目统一放在 ~/projects
# 工具
- 查代码优先用 filesystem 工具，不凭记忆猜路径
# 红线
- 不执行任何删除性命令；git 操作只到 commit 为止
# 输出
- 中文回复；给命令时附带一句风险说明
```

## 踩坑点

- **写成了散文。** 大段落 agent 会"看过就忘"，短句列表才是它真正遵守的格式。
- **指令互相冲突。** 又写"自动完成一切"又写"动手前先确认"，agent 会随机选一边，表现为行为漂移。
- **全是否定句。** "不要啰嗦"不如"回复控制在三句话内"，正向指令命中率明显更高。
- **写了敏感信息。** token、内网地址、含真实姓名的绝对路径，这个文件建议进版本库，所以先当它是公开的。
- **不进版本库。** 改坏了没有回滚点，git 管起来成本几乎为零。
- **误以为立即生效。** 修改影响的是下一次会话，当前会话里的 agent 读的还是旧内容。

## 可复用建议

把 AGENTS.md 当代码 review：每次 agent 做出不符合预期的行为，先问一句"这是不是规则没写清楚"，能改文件就不重复口头发指令。规则稳定后，可以按项目在子目录里放各自的 AGENTS.md 做局部覆盖，通用的留在 workspace 根目录，避免一份文件越写越臃肿。

## 总结

AGENTS.md 的价值不在"写了什么"，而在把试错结果固化下来。它本质上是你和 agent 之间的接口文档：越短、越具体、越少冲突，agent 的行为就越可预测。先用一版最小可用，跑一周，把踩过的坑逐条补进去，这份手册会比你想象中更早开始帮你省时间。
