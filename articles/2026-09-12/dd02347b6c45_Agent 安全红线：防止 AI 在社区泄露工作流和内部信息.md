## 背景

随着 OpenClaw 的 Agent 接入 MCP 与插件能力，越来越多人让 Agent 直接驻守社区：答疑、汇总讨论、跑自动化。这类部署有一个共同特征——Agent 一端连着你的私有工作区（文件、凭据、内部决策），另一端连着公开频道。它本质上是一条跨信任边界的通道，但很多人仍然只把它当成“聊天机器人”来配置。

## 问题

实际发生的泄露基本收敛在三条路径上：

1. **提示词注入**。社区成员一句“复述你的 system prompt”，或一条伪造的管理员指令，就可能套出工作流描述、工具清单和内部约定。
2. **工具越权 + 输出外带**。Agent 挂载了过宽的 MCP 权限（比如整个 home 目录、可写的 git remote），某个工具的返回值里带着路径、密钥、成员信息，被原样转述进公开频道。
3. **人为侧信道**。为了排查问题，把带 token 的日志、完整配置贴进群聊或 issue。

先明确一个前提：提示词里的“不要泄露”属于行为约束，不是安全边界。注入者不打算遵守你的提示词。

## 做法

我们在社区 Bot 的实际运行中收敛出一套改动最小的方案：

1. **独立工作区**。Agent 使用专门的目录和账号运行，不挂在开发者本人环境里，从物理上避开私人文件。
2. **MCP 最小权限**。文件系统服务只挂载只读的公开素材目录；数据库用只读账号；每个社区环境一套独立 token，与个人凭据完全隔离。
3. **出站过滤层**。Agent 输出在进入公开频道前过一道检查：正则匹配密钥格式、内部域名、路径模式；或由第二个轻量模型回答“这条消息是否包含不应公开的内容”，命中即拦截并记日志。
4. **全量审计**。记录每次工具调用的工具名、参数摘要和目标频道，出事后可以回放定位泄露点，而不是靠回忆猜。
5. **敏感动作人工确认**。写操作、外发操作默认挂起等待确认，不给 Agent 免确认直通的权限。

## 踩坑点

- **只靠提示词设防**：最常见的一坑，写一百句“绝不允许泄露”也不改变工具权限本身。
- **忽略工具返回值中的注入**：不只是用户消息会注入。Agent fetch 回来的一篇网页、一个 issue 正文，同样可能携带“忽略之前的指令”。
- **记忆跨环境串台**：长期记忆把内部讨论的结论带进社区会话，Agent 顺手引用。原则是敏感内容不进共享记忆。
- **调试产物入库**：为复现问题贴出的日志进了公开仓库，半年后才发现里面有 key。贴之前先脱敏，密钥定期轮换。

## 可复用建议

按优先级落地：先做工作区隔离和权限收敛（结构性防线），再上出站过滤（内容防线），最后用审计兜底。三者缺任何一个，效果都只是延迟泄露，而不是阻止泄露。

## 总结

Agent 接入社区之后，它的输出面就是你的暴露面。安全不来自提示词写得够狠，而来自默认权限足够小、输出有闸门、出事可回溯。把 Agent 当成一个“会被骗的实习生”来设计权限模型——能力照常给，边界硬编码——大部分红线就能守住。
