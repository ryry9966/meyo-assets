## 背景

玩 OpenClaw 一段时间后，大多数人会把精力花在接 MCP、写 skill、配自动化上，却很少回头处理一个更基础的问题：Agent 对"你"一无所知。每次新会话，它都要重新猜你是谁——时区、技术栈、说话习惯、手头的项目。SOUL.md 定义了 Agent 自己的人格，但那个人格里没有你。

## 问题

具体症状大家都遇到过：

- 你主力写 Go，它反复给 Python 方案；
- 它不知道你在 UTC+8，排任务用它的默认假设；
- 同一段自我介绍，你在十次会话里粘贴了十遍；
- 语气忽冷忽热，因为它每次都在重新校准你的偏好。

这些指向同一件事：关于你的**稳定信息**不应该每次靠对话重建，而应该持久化成文件。这就是 USER.md 的位置。

## 做法

步骤不复杂，重点在内容结构：

1. 在 workspace 根目录（与 SOUL.md、MEMORY.md 同级）建 `USER.md`；
2. 只写事实，一条一行，不写散文。我的骨架大致是：

```markdown
# USER
- 时区：UTC+8，工作时间 9:30–19:00
- 主力语言：Go / TypeScript，Python 仅读
- 偏好：先给结论，代码带注释，不要客套
- 禁止：主动推荐新框架
- 当前项目：openclaw 插件 X（截至 2025-06）
- 最后更新：2025-06-14
```

3. 在 AGENTS.md 或 SOUL.md 里加一行引用，明确"会话开始先读 USER.md"；
4. 纳入 git。以后想让它记住什么，直接说"写进 USER.md"，由它起草 diff，你 review 后提交。

## 踩坑点

- **写成小作文**。三段自我介绍只会稀释注意力，Agent 检索的是条目不是语感，控制在 100 行以内。
- **和 MEMORY.md 边界不清**。我的分工：USER.md 存稳定身份（半年一变），MEMORY.md 存事件性记忆（昨天干了什么）。混写会出现两个版本的你。
- **塞敏感信息**。这个文件会被频繁读取、随上下文发给模型。API key、住址、证件号一律不进。
- **免 review 自动写入**。Agent 会慢慢"脑补"出你从未说过的事实，且条目之间互相矛盾。必须走 git diff 审查。
- **信息过期**。三个月前的"当前项目"会把它定向带偏，所以模板里强制保留"最后更新"字段。

## 可复用建议

- 把**默认行为**和**临时覆盖**分开：USER.md 里写"默认中文回复"，具体任务里仍可临时要求英文，Agent 能理解优先级；
- 每季度或项目切换时手动过一遍，删失效条目比新增更重要；
- 验证方法：开一个全新会话，问它"你了解我哪些信息"，比对它的复述和文件内容是否一致——这一步能暴露引用链是否真的生效。

## 总结

USER.md 不是 prompt 黑魔法，它就是一份配置：把"我是谁"从每次对话的临时输入，变成一次维护、长期生效的静态资产。投入半小时，之后每次会话的冷启动成本都会降下来。对跑长期自动化任务的人来说，了解你的 Agent，才是可托付的 Agent。
