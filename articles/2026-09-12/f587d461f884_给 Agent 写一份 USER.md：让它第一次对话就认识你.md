## 背景

大模型是无状态的。每次新会话，Agent 对你的了解归零：时区、技术栈、命名习惯、回复语言……这些要么每次重说，要么只靠 system prompt 里一句泛泛的"你是一个乐于助人的助手"。OpenClaw 这类常驻 Agent 的价值恰恰在长期协作，缺的只是一份结构化的用户档案。

## 问题

没有用户档案时的典型症状：

- 每个会话都要重新交代"用中文回复""我用 macOS""部署在 home lab"；
- Agent 的建议不符合你的环境，比如推荐 Kubernetes 而你只用 Docker Compose；
- 输出风格漂移，今天简洁明天啰嗦。

本质问题：关于"你是谁"的信息没有持久化，也没有被 Agent 可靠地读到。

## 做法

1. 在 Agent 工作区根目录建 `USER.md`，OpenClaw 的 workspace 会把它注入上下文；
2. 只写**可执行的客观事实**，分四段：环境（系统、语言、时区）、技术偏好（工具链、明确不用的东西）、协作风格（详略、注释习惯）、边界（不许自作主张的事，如自动 push、动生产配置）；
3. 每条一行，整份文件控制在 30 行以内；
4. 纳入 git 管理，环境变化时顺手更新；
5. 需要时在系统提示里补一句"回答前先对照 USER.md"，确保它真的参与推理。

精简模板：

```markdown
# User
## 环境
- macOS + NixOS server，时区 UTC+8
## 偏好
- 中文交流；先结论后细节
- 部署用 Docker Compose，不用 K8s
## 边界
- 不要自动 git push；不修改 .env
```

## 踩坑点

- **写成简历**：背景故事和自我介绍不产生行为差异，只烧 token，删掉；
- **放敏感信息**：密钥路径、内网域名、手机号——这个文件每次都会进模型上下文，按"会被第三方看到"的标准来写；
- **和 MEMORY.md 混淆**：USER.md 是"我是什么样的人"，MEMORY.md 是"我们做过什么事"，混写后两边都会失焦；
- **信息过期**：换了机器、换了工具链不更新，Agent 会拿半年前的事实给你建议；
- **指令冲突**：这里写"回复极简"，任务里又要求详细报告，冲突时模型行为不可预测。长期边界放 USER.md，任务级要求放会话里。

## 可复用建议

- 把 USER.md 当配置文件对待：有版本、有变更、有理由；
- 让 Agent 参与维护：会话里直接说"把这条偏好记进 USER.md"，比手动编辑更容易坚持；
- 团队场景可另建共享档案，但个人事实和团队约定分开，避免互相污染；
- 每月花两分钟通读一遍，删掉不再成立的条目。

## 总结

USER.md 的价值不在"文件"而在"契约"：你用最小成本声明环境、偏好和边界，Agent 用它替换掉每一次重复的自我介绍。三十行以内，进 git，月度回顾——在所有 Agent 调优手段里，这个投入产出比大概是最高的一个。
