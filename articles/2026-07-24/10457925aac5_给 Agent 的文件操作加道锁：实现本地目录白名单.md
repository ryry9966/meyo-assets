## 背景：为什么 Agent 的文件访问需要护栏

在 OpenClaw、插件或 MCP 工具链里，Agent 经常需要接触本地文件系统——读配置、写日志、保存处理结果、抓取文本片段，甚至是批量重命名和数据处理。无论哪种场景，本质上都是赋予了 Agent 某种“本地执行能力”。

问题在于，很多自动化脚本或自定义工具在实现文件读写时，是直接暴露了 `os.open`、`open`、`shutil` 这类系统调用，Agent 看到的就是一个几乎可以访问任何路径的文件工具。一旦 prompt 注入、任务理解偏差或交互流程失控，就可能误删 `.ssh`、覆盖系统配置，甚至读走隐私文件。

一个低成本且工程上可控的缓解措施是：**为文件访问工具建立一个本地目录白名单（允许访问的目录列表），所有读写操作必须限定在这些目录内，否则直接拒绝。**

本文将给出一个具体的实现思路，适配 OpenClaw 的工具函数 / MCP Server 场景，并梳理其中容易踩坑的边界情况。

## 问题拆解

目标很明确：当我们写一个让 Agent 使用的文件操作函数（例如 `read_file`、`write_file`、`list_dir`）时，必须在执行前校验参数中的**最终真实路径**是否落在预设的白名单目录集合内。

这里有几个关键点：

- 必须是**最终真实路径**，而不是用户传入的原始字符串，避免符号链接、`..` 穿越、相对路径等绕过手法。
- 白名单应该以**目录**为单位，比如 `[“/home/user/project/data”, “/home/user/project/output”]`，而不是文件级别的列表，否则维护成本过高。
- 校验逻辑要轻量、无外部依赖，方便嵌入到工具函数或 MCP Server 中。

## 做法与步骤

### 1. 定义白名单配置

建议将白名单集中在一个配置对象中，方便后续扩展。例如使用 Python dataclass：

```python
from dataclasses import dataclass
from typing import List, Set

@dataclass
class FileAccessConfig:
    allowed_dirs: Set[str]   # 已经解析过的真实路径
    allow_hidden: bool = False
```

初始化时将允许的目录路径统一用 `os.path.realpath` 展开，并转换成集合：

```python
import os

def init_config(dirs: List[str]) -> FileAccessConfig:
    real_dirs = set()
    for d in dirs:
        real = os.path.realpath(os.path.abspath(d))
        real_dirs.add(real)
    return FileAccessConfig(allowed_dirs=real_dirs)
```

### 2. 编写路径校验函数

核心逻辑：对传入的文件路径，先解析为绝对路径，再取 `realpath`，然后检查它是否以任意一个白名单目录为前缀。注意不能简单用字符串前缀匹配，需要加上路径分隔符，防止 `/data/app` 错误匹配 `/data/app-store` 这种情形。

```python
def validate_path(file_path: str, config: FileAccessConfig) -> str:
    # 先转为绝对路径，保留 .. 等，再 realpath 解析符号链接和 .. 穿越
    abs_path = os.path.abspath(file_path)
    real_path = os.path.realpath(abs_path)
    
    # 检查是否在允许的目录下
    for allowed in config.allowed_dirs:
        # 确保是真正的子路径：要么相等，要么以 allowed + separator 开头
        if real_path == allowed or real_path.startswith(allowed + os.sep):
            # 可选：禁止访问隐藏文件
            if not config.allow_hidden and _has_hidden_component(real_path):
                raise PermissionError("access to hidden files is not allowed")
            return real_path
    raise PermissionError(f"access denied: {file_path} -> {real_path}")
```

一个辅助函数检测路径中是否包含以 `.` 开头的组件（排除 `.` 和 `..`）：

```python
def _has_hidden_component(path: str) -> bool:
    parts = path.split(os.sep)
    for p in parts:
        if p not in (".", "..") and p.startswith("."):
            return True
    return False
```

### 3. 在工具函数中集成

假设我们有一个 `read_file` 工具要暴露给 OpenClaw，典型写法：

```python
def safe_read_file(path: str, config: FileAccessConfig) -> str:
    safe_path = validate_path(path, config)
    with open(safe_path, "r", encoding="utf-8") as f:
        return f.read()
```

对于写入操作，同样校验后才会实际执行。目录列举（`list_dir`）也可以复用相同的 `validate_path`，避免枚举白名单之外的目录结构。

### 4. 接入 OpenClaw 或 MCP Server

- **作为普通工具函数**：在 OpenClaw 的 `tool.py` 或自定义插件中，使用上述 `safe_read_file` 替换原来的 `read_file`，并在工具初始化时注入 `config`。
- **作为 MCP Server 资源/工具**：可以在 MCP Server 内持有 `FileAccessConfig`，每个工具调用都先进行校验。这样即便客户端换成了其他 Agent 框架，白名单策略仍然生效。

## 踩坑记录

- **符号链接穿透**：白名单目录内如果存在指向白名单外路径的符号链接，`realpath` 会解析到真实位置，校验会拒绝。这通常是期望的行为，但如果你的确需要访问链接指向的文件，可以增加一个选项把符号链接视为允许（直接使用 `abspath` 而不调用 `realpath`），但安全性会降低，需要权衡。
- **相对路径依赖工作目录**：`os.path.abspath` 依赖于当前工作目录。如果 Agent 可能改变 `os.chdir`，必须在每次工具调用时基于稳定变量（最好不要依赖全局 cwd），或者禁止在工具内改变工作目录。另一个方案是在初始化白名单和工作目录的基路径，然后使用 `os.path.join` 来解析相对路径，但这会增加复杂度。通常建议要求所有文件参数必须是绝对路径，或者相对路径统一基于某个固定的 `base_dir`。
- **Windows 上的盘符和路径分隔符**：如果跨平台部署，记得在比较时统一使用 `os.path.abspath` 得到的格式，并用 `os.sep` 拼接。白名单目录最好也用 `os.path.realpath` 处理，保证格式一致。
- **硬链接**：硬链接不会被 `realpath` 变换，因为它指向同一个 inode。这意味着如果白名单目录内有一个到 `/etc/passwd` 的硬链接（需要 root 权限），可能被访问。在可信环境下一般不存在这个问题，如果担心，可以暂时不考虑，因为硬链接多数情况需要高权限创建；更彻底的方案是使用 `os.lstat` 检查文件 inode 并与白名单目录挂载点比对，但对大多数脚本来说过于重量。

## 可复用建议

- **封装成可复用的 `SafeFileTools` 类**：将 `read_file`、`write_file`、`list_dir` 等方法统一在一个类中，构造函数传入 `allowed_dirs`，内部自动初始化 `FileAccessConfig`。这样可以快速在不同项目里复用。
- **提供 MCP Server 示例**：如果社区常用本地文件 MCP Server，可以基于上述思路发布一个“安全文件访问 MCP Server”，仅允许配置的目录集合，避免直接使用无限制的文件系统 MCP。
- **与 OpenClaw 工具白名单配合**：除了文件目录白名单，还应该通过 OpenClaw 的工具白名单（允许调用的工具列表）控制 Agent 只能调用你包装后的安全工具，从根本上禁止它调用原始危险函数。
- **增加审计日志**：在校验失败时记录详细日志（请求路径、解析后路径、时间、Agent 任务上下文），便于发现潜在越权尝试或配置错误。

## 总结

给 Agent 加文件访问护栏并不需要引入复杂的沙盒或容器技术。工程上，一个轻量的路径校验函数加上清晰的目录白名单配置，就能防止绝大多数非预期的文件读写操作。实现的核心是**解析真实路径后再进行前缀检查**，并小心处理符号链接、相对路径等边界情况。

对于正在将 Agent 接入本地文件系统的工程师来说，这一步是投入产出比极高的安全实践。它不仅降低了误操作风险，也让你在工具开放更多能力时更有底气。

最后，永远假设 Agent 会被诱导去访问你没想到的路径——然后提前在工具层说“不”。
