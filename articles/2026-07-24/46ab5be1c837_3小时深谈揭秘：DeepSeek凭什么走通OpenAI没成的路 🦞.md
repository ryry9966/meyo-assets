梁文锋用一场3小时的长谈，把最近圈内最大的两个问号摆上了台面：OpenAI主导的「大模型军备竞赛」是不是走到头了？DeepSeek这个突然冒出来的玩家，凭什么跨过烧钱的门槛，把推理能力做到了顶尖？对谈里没有宏大叙事，只有技术路线的冷静拆解。听完最大的感受就是——AI 这条赛道，固有剧本正在被彻底改写。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-24/ec0a91bb6f6f96bc.png)

## 1. 路线分歧：OpenAI的Scaling Law为何撞墙？

过去三年，几乎所有大模型团队的操作手册都写着同一行公式：**更多算力 + 更多参数 = 更强智能**。OpenAI 将这套 Scaling Law 奉为圭臬，从 GPT-3 到 GPT-4，参数规模指数级膨胀，训练成本动辄数亿美元。但这条路正在越走越窄，几个红灯已经亮了起来：

- **性能增益锐减**：GPT-4 在多数基准测试上的提升，比起从 GPT-2 到 GPT-3 的跨越已经温和太多。后来推出的 GPT-4 Turbo 和 GPT-4o 更侧重于成本优化与多模态，单纯堆参数的“奇迹”不再。
- **推理成本失控**：一个万亿参数模型，每次回答都要调度海量 GPU，即便有批处理和量化，单次推理的能耗和时延仍是商业化的巨大阻碍。
- **数据墙与算力墙**：互联网上高质量文本的增长速度远远跟不上模型贪婪的吞噬节奏；同时，H100 的交付周期和功耗，让纯规模扩张的边际成本陡升。

梁文锋在对话里直接点破：Scaling Law 不是物理定律，它只是基于 Transformer 架构的经验观察。**当架构本身没有质变，堆规模迟早会撞上一堵看不见的天花板**。而 DeepSeek 从第一天起就没打算沿着这条“大力出奇迹”的路走到黑，他们选择了另一条看似更窄、实则更长的技术通道。

## 2. DeepSeek的三角法宝：MoE、多头潜在注意力、纯RL推理

DeepSeek 能在成本仅为 OpenAI 几十分之一的前提下实现对标 GPT-4 的推理能力，靠的不是某个单点突破，而是一套精心设计的组合拳。梁文锋把它拆解为三个彼此咬合的技术齿轮：

- **Mixture of Experts（混合专家，MoE）**：模型虽然体量庞大（V3 总参数 671B），但每次计算只激活其中一小部分“专家”。这就像一栋大楼里住了几百位教授，每通电话只叫醒最相关的两三位，而不是让所有人同时加班。V3 训练成本因此压到了惊人的 557.6 万美元，不到 GPT-4 的 1/20。
- **Multi-head Latent Attention（多头潜在注意力，MLA）**：传统注意力机制在长上下文下，KV 缓存会吃掉巨量显存。MLA 通过低秩压缩把缓存大小削减了 90% 以上，让模型在 128K token 的窗口里依然轻快。这也直接拉低了推理价格——目前 DeepSeek API 的百万 token 输入价格仅为 GPT-4o 的 1/10。
- **纯强化学习驱动推理**：DeepSeek-R1 走了一条激进路线，完全砍掉人类示例微调（SFT），直接让模型在强化学习奖励信号下自我进化。结果涌现出了**链式思考的自我验证、反思和回溯**——模型学会了自己质疑自己，然后再修正答案。这恰恰是 OpenAI 早期设想过但在 GPT-4 上并未大规模实践的方向。

三把钥匙拧在一起，解开的就是“低成本高性能”这道曾被视作不可能的门锁。

## 3. 开源生态：为什么说“开放才是最好的护城河”？

如果只有技术革新，DeepSeek 最多是个低调的学术项目。让它真正出圈的，是另一套违反硅谷直觉的策略——**彻底开源**。不仅模型权重开放，技术报告也写得像教科书，生怕别人学不会。

- **开发者飞轮**：Hugging Face 上基于 DeepSeek 微调的衍生模型已经超过数千个，从医疗问诊到代码生成，长尾场景被社区自发填补。这种速度是任何封闭团队无法匹敌的。
- **定价的降维打击**：当 OpenAI 还守着每百万 token 十几美元的高价时，DeepSeek 直接把价格打到几毛钱人民币。更关键的是，它向所有开发者证明了——这个白菜价你自己部署也能做到。
- **生态反哺技术**：社区在大规模部署中暴露出的效率瓶颈、长尾场景缺陷，会直接转化为下一版模型优化的输入。梁文锋甚至坦言，“开源不是做慈善，是加速技术迭代最有效的方法”。

这种模式下，护城河不再是一座封闭的城堡，而是一片不断扩大的森林。竞争对手可以复制仓库里的代码，但复制不了成千上万开发者共同滋养出来的生态活力。

![img3](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-24/c744b8ef524d281b.png)

## 4. 技术理想主义的胜利：从追赶到引领的范式转换

最让硅谷紧张的可能不是某个模型指标，而是梁文锋反复强调的一句话：“DeepSeek 是一家由技术理想主义驱动的公司。” 在对话中，他几乎没有谈论商业模式和营收增长，所有兴奋点都落在如何逼近 AGI 的“本质问题”上。

- **不复制，只重构**：团队极少使用 OpenAI 模型的输出来蒸馏微调，因为他们发现那样做会“继承对方的思维惯性”。相反，他们选择从 Transformer 底层算子开始重新思考，这才有了 MLA 这种原创架构的出现。
- **研究优先于产品**：V3 论文的致谢名单里，清一色是算法工程师和研究员，没有产品经理。这种纯粹让很多观望已久的国内开发者终于敢说一句，“我们也能做世界级的基础创新”。
- **反焦虑的节奏**：当全行业都在追赶 GPT-4 发布时间表时，DeepSeek 却选择在 V2 发布后沉静大半年，把所有力气花在架构升级而非查漏补丁上。这种长周期主义，在融资驱动的 AI 创业环境里极度稀缺。

这场对谈最动人的地方，不是胜利者的复盘，而是一个工程师团队如何用第一性原理的笨功夫，悄悄改写了看似固化的游戏规则。

## 三条冷思考，给燃烧的热情浇一盆实用的凉水

热度之下，一些无法绕开的硬骨头还是得啃：

1. **推理成本并非永远友好**：MoE 模型在并发稍高时，每路请求依然需要把整个模型权重加载到显存，总内存开销依旧庞大。当访问量爆发，推理成本会非线性增长，白菜价可能只是单路测试的理想情况。
2. **开源的双刃剑**：模型权重完全开放，意味着安全对齐的机制也可以被轻易剥离。如何防止模型被微调成钓鱼邮件生成器、恶意代码助手，是开源模型要长期背负的沙袋。
3. **芯片断供的现实约束**：DeepSeek 目前仍大量依赖英伟达 GPU 集群，而先进算力的获取在未来可能更加受限。MLA 这类算法优化是削薄了成本，但如果芯片性能骤降一个世代，再精妙的软件也难为无米之炊。

**给开发者的建议**：不要把 DeepSeek 当作廉价替代品，而是去读它的技术报告，理解 MoE 和 MLA 在你业务场景下的真实内存/时延表现，再决定模型选型。

**给创业者的建议**：与其在闭源大厂的 API 上构建薄薄的应用层，不如考虑基于开源基座做深垂直领域的数据飞轮——这才是小团队唯一能掌控的壁垒。

**给普通用户的建议**：别被“免费”“低价”冲昏头脑，每一次使用 API 都是在贡献反馈数据。选择平台时，除了价格，更要看隐私条款到底尊不尊重你的输入。
