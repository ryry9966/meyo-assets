## 背景

在 OpenClaw 这类本地工具链里，Agent 常常需要借由插件或 MCP 服务器在文件系统上做一些事情——读取配置文件、导出报告、清理临时文件。只要你的编排脚本里出现了 `open()`、`shutil.rmtree()` 或是某个子进程的 `rm -rf`，理论上它就能摸到当前用户可及的任何路径。

如果不加限制，一个 prompt 生成的路径、一个拼接错误的变量、甚至插件里的一个 bug，都可能让自动化流程误伤 $HOME 下的重要目录。轻则丢数据，重则需要从备份恢复。而且很多时候，Agent 其实只需要访问一个或多个“项目目录”，完全没有理由拥有全局文件访问权。

## 问题定义

**需求**：让 Agent 只能读写指定白名单目录（以及它们的递归子目录），任何白名单外的路径访问都应被拦截并报错。

表面看只要比一下前缀就行，实际上即使仅在标准文件系统层面，绕过手段也不少：

- **符号链接**：白名单目录里可以有一个指向 `/etc` 的 symlink，直接 `readlink` 不过滤就会越权。
- **路径遍历**：`a/../../b` 这样的相对路径在规范化前可以逃逸出去。
- **不存在的文件**：`os.path.realpath()` 要求路径对应的实体存在，否则抛异常，但我们恰恰需要在文件被创建前就检查其合法性。
- **大小写与跨平台**：macOS 默认文件系统不区分大小写，但字符串前缀比较是区分的；Windows 的盘符和短路径名更是特殊。

因此需要一个工程上可靠的检查函数，而不是随手写一个 `startswith()`。

## 做法：一个精简但有效的路径护栏

我们采用 Python 标准库函数，避免引入额外依赖。目标是对“已存在”和“尚未创建”的路径都能做出正确判断。

### 核心函数设计

```python
import os
from pathlib import Path

class FileAccessGuard:
    def __init__(self, allowed_dirs: list[str]):
        # 将允许目录全部解析成规范化的绝对路径
        self.allowed = [os.path.realpath(d) for d in allowed_dirs]

    def is_allowed(self, target: str) -> bool:
        # 1. 将目标转成绝对路径，但不跟随符号链接（解析 .. 和 .）
        abs_target = os.path.abspath(target)

        # 2. 如果目标路径已经存在，解析符号链接得到真实路径
        try:
            real_target = os.path.realpath(abs_target)
        except OSError:
            # 路径不存在时，直接使用 abs_target 继续检查
            real_target = abs_target

        # 3. 检查是否位于任一允许目录内
        for allowed in self.allowed:
            # 保证 /allowed 作为前缀匹配 /allowed/...，而不是 /allowed-fake
            if real_target == allowed or \
               real_target.startswith(allowed + os.sep):
                return True
        return False
```

#### 集成到 Agent 的文件操作

假设你的工具函数原本是：

```python
def read_file(path: str) -> str:
    with open(path) as f:
        return f.read()
```

现在变成：

```python
guard = FileAccessGuard(allowed_dirs=["/home/user/projects", "/var/tmp/agent-sandbox"])

def safe_read_file(path: str) -> str:
    if not guard.is_allowed(path):
        raise PermissionError(f"Access to '{path}' is not allowed by file guard.")
    real_path = os.path.realpath(path) if os.path.exists(path) else os.path.abspath(path)
    with open(real_path) as f:
        return f.read()
```

其他写入、删除、遍历目录的操作同理。在插件或 MCP 工具的入口统一包裹，就可以形成一个可复用的访问控制层。

### 与容器化隔离的配合

目录白名单是一种应用层防护，可以补强容器边界。例如，你可以将整个 Agent 放到 Docker 容器里，只挂载白名单目录，但那样就失去了对宿主机部分路径的灵活访问。护栏方案允许你在一台开发机上同时运行多个 Agent，每个只授予它们各自需要的目录访问权，无需启动多个容器。

## 踩坑记录

1. **符号链接的竞态条件**  
   在检查 `is_allowed()` 之后、实际 `open()` 之前，符号链接的目标可能已被替换。对于高安全要求的场景，需在打开后用 `os.fstat` + `os.lstat` 比对 inode，确保没有发生 symlink 替换。工程中如果只是防止误操作，竞态条件通常可以接受。

2. **路径不存在的处理**  
   写入新文件 `allowed_dir/new_file` 时，`os.path.realpath` 会失败。这里我们用 `abspath` 兜底，并仍然检查父目录是否在允许范围内。更严谨的做法是逐级解析父目录的 `realpath`，直到存在的部分，再拼接剩余部分，防止通过“不存在的符号链接链”绕过。简单场景下可以先认可 `abspath` 的检查。

3. **挂载点与不同文件系统**  
   如果白名单目录 `/mnt/data` 是一个挂载点，`realpath` 会返回挂载源路径，可能与白名单不符。需要确保 `allowed_dirs` 本身就用挂载后的路径配置，并且所有检查发生在同一 mount namespace 下。

4. **大小写不敏感文件系统**  
   在 macOS 上，如果白名单是 `/Users/alice/Documents`，而请求 `/users/alice/documents/secret.txt`，`startswith` 无法匹配。可以在检查前将比较双方都做 `str.lower()`，但这会牺牲精确性。更合理的做法是通过 `os.path.realpath` 获取系统实际的规范形式。

5. **相对路径与工作目录**  
   如果 Agent 脚本改变了工作目录，传递给 `is_allowed` 的可能是相对路径。`abspath` 依赖于当前工作目录，因此必须在检查前明确设定一个基准（比如项目根），或者一律要求传入绝对路径。

## 可复用建议

- **抽成独立模块**  
  将 `FileAccessGuard` 封装为你的 MCP 工具或插件系统的中间件，文件操作全部经过它检查，不依赖开发者自觉。
- **通过环境变量配置白名单**  
  例如 `AGENT_ALLOWED_DIRS=/path/a,/path/b`，启动时解析，让同一个 Agent 包在不同项目间可配置。
- **记录拒绝日志**  
  每次拦截都要记录时间、被拒绝的路径、调用栈片段，便于排查合法的误杀。
- **提供审计模式**  
  增加一个 `audit` 选项：不实际拒绝，只发出警告。上线前先跑一段时间收集数据，微调白名单。
- **结合最小权限原则**  
  即使有护栏，也不要让 Agent 以具有 sudo 权限的用户运行；目录白名单是纵深防御的一层，不是银弹。

## 总结

给 Agent 加一个本地目录白名单，代码量可能只有几十行，但它能把一次脚本事故的概率降低一个数量级。核心要点是：不要只做简单前缀匹配；始终解析真实路径以对抗符号链接和路径遍历；处理好不存在路径的检查；并且把检查逻辑与实际的 I/O 操作放在同一上下文里，避免竞态被利用。

在 OpenClaw 或类似工具链中，你可以把这个功能做成一个可插拔的“文件安全网关”，让自动化的灵活性不会以数据安全为代价。
