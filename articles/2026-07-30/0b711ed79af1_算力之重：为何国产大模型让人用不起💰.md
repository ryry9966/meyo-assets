这两天开发者圈子里最扎心的一句话，恐怕是：“国产大模型，贵到用不起。”从年初各家纷纷下调 API 价格、放出超大免费额度，到如今悄然提价、缩减体验包，许多早期尝鲜的用户发现，自己的 API 账单正以肉眼可见的速度增长。一块钱聊几句，十块钱写篇报告，看似单价不高的“分/千 tokens”，一旦跑起业务量，瞬间就成了烧钱利器。

这背后的逻辑远比“厂商想多赚钱”复杂得多。大模型的昂贵，写在每一片 GPU 的晶体管里，藏在每一次矩阵乘法的功耗中，也刻在市场博弈的深层规则上。



## 烧钱的硬件：GPU才是真正的吞金兽

大模型训练和推理的核心硬件是 GPU。一个能稳定运营的国产大模型，背后至少是成百上千张高性能加速卡组成的计算集群，而这张硬件账单，从一开始就极其沉重。

- **天价的单卡成本**：目前主流的训练方案依然依赖英伟达 A100/A800 或更先进的 H100。尽管受出口管制影响，国内企业转向昇腾 910 等国产替代，但性能差距与软件生态适配成本使得单卡有效算力大打折扣。一张 A100 在禁运前单价已超 10 万元人民币，而要靠多张国产卡拼出同等算力，硬件投入不降反升。
- **千卡集群的规模效应与烧钱效应**：训练一个千亿参数模型通常需要 512~1024 张卡持续运行数周甚至数月。仅算力租赁一项，以市场价 30 元/卡/小时计算，一个千卡集群一个月的开销就在 220 万元左右。这还没算上 InfiniBand 网络、高速存储、机房散热等杂项开支。
- **推理同样不便宜**：很多人误以为只有训练在烧钱，实际上推理的成本被严重低估。一个 70B 参数模型若采用 FP16 精度，全量推理需要约 140GB 显存，意味着至少 3~4 张 80GB 显存的 GPU 才能服务少量并发请求。想要保持毫秒级响应，就必须留出显存冗余，导致硬件利用率不高，折算到单次问答的成本绝不便宜。

所以，用户每调一次 API，背后都有一排风扇狂转的显卡在吞噬电力，而这张物理账单最终一定会传导到价格端。



## 训练的大出血：数据、时间与精英团队

硬件之外，训练过程本身消耗的“软成本”同样令人咋舌。大模型的打造是一场精密的马拉松，任何环节的闪失都可能让千万级预算打水漂。

- **数据获取与清洗**：高质量的中文语料本就是稀缺资源。TB 级数据的版权采购、脱敏过滤、去重标注，涉及大量人工与算法投入。某些模型为了规避合规风险，需要建立包含数亿条数据的审核流水线，光是数据治理就可能耗时半年、耗资数百万。
- **疯狂的电力与时间消耗**：训练一次千亿模型，整体算力需求可达数万 PFlop/s-day。以 GPT-3 训练为例，业界估计其用电量约 1,287 MWh，相当于 120 个美国家庭的年用电量。国内模型由于芯片算力密度和互联带宽偏低，需要更多的卡、更长的时间，电费开销动辄百万元级。更可怕的是，一次训练失败、超参数调优失败导致重头再来，周期和成本直接翻倍。
- **顶尖人才的天价薪酬**：能驾驭千卡集群、进行大规模分布式训练的人才在国内凤毛麟角。这类工程师的年薪通常超百万，团队动辄上百人，人力成本每年就要吃掉数千万。而且训练结束后，仍需持续投入进行对齐、安全加固，才能上线。

所有这一切，最终都被压缩成了 API 文档中那个“￥0.012/千 tokens”的数字。它看似微小，但乘上训练摊销和推理并发，就成了用户账单上难以忽视的分量。



## 按 token 收费的算术题：为什么对话越聊越贵

现在的国产大模型几乎清一色按 token 计费。这看起来公平透明，但一算细账，很多人才发现“免费时代”一去不返。

- **token 并非文字数**：中文下的 token 通常按字或词切分，一条 prompt 可能包含系统提示、历史对话、用户查询，轻易达到数千 tokens。如果应用需要长上下文（如分析整本书、处理长文档），一次请求消耗数十万 tokens 并不罕见。以某主流国产模型 0.008 元/千 tokens 输出价计算，生成长篇报告 5 万 tokens 就要 4 元。若是高频调用，日积月累相当可观。
- **推理的服务质量税**：为了保证低延迟，服务端需要预留足够的 GPU 并发槽位，意味着哪怕请求少，算力也在空转。云厂商按部署小时收费或按并发计费的模式，会将闲置成本摊入定价。部分模型对低延迟、高并发需求的用户还会提供差异化的“加速”套餐，价格进一步上浮。
- **隐性成本：Context 越长越吃亏**：随着上下文窗口不断扩展（从 4K 到 100K 甚至百万 tokens），注意力的计算复杂度以平方级增长。即使采用 FlashAttention、KV-cache 量化等优化，超长 context 请求仍然会瞬间占满显存，迫使厂商采用动态批处理策略，但成本增量最终还是落在定价阶梯上。很多模型对超过一定长度的输入直接按高端定价，或者限制批次速率。

对个人开发者来说，可能的账单幻觉是“聊一句才几分钱”，但跑起一个每日几千次调用的 AI 助手，月费轻松破万。这才是用不起的真实困境。



## 市场博弈：为何厂商不敢轻易降价

面对用户“贵到用不起”的吐槽，模型厂商并非不想降价，而是身不由己。定价策略背后是一场关乎存活的资本游戏。

- **烧钱换市场的终局来临**：2023 年各家的免费额度、白菜价 API 本质上是 VC 补贴下的获客工具。随着资本寒冬加剧，投资人对盈利的耐心越来越短，厂商不得不从“拉新”转向“造血”。低价策略不可持续，回调是必然。
- **硬件成本受制于人**：由于高端 GPU 禁运，国产模型只能依赖性能、良率、产能均存在瓶颈的替代方案。训练和推理单位成本难以像国外那样随着时间平滑下降。NVIDIA 每代产品性能翻倍，而国内算力进步更像是爬缓坡，降价空间被严重挤压。
- **开源模型的冲击与差异化压力**：Qwen、Baichuan 等开源模型性能日益强劲，部分企业选择本地部署以避开持续付费。这虽然省了 API 开销，却需要自己承担硬件投资和运维，总拥有成本并不低。商业 API 若想留住用户，就必须在性价比上明显优于开源自建方案，进一步拉伸成本线。
- **看不见的安全与合规投入**：国内大模型部署需满足内容过滤、数据安全等多种合规要求，输出侧需配备敏感词检测、人工审核兜底等机制，这些都是实打实的运维成本。

因此，当前的定价与其说是“暴利”，不如说是行业在为整个技术栈的“基础建设”买单。用得起用不起，取决于业务能否消化这些被物化的算力成本。



## 冷静下来，三条接地气的思考

面对国产大模型的高昂成本，情绪宣泄解决不了问题。下面几条思路或许能帮你把钱花在刀刃上。

1. **个人开发者的“降本捷径”**：日常使用不必死磕千亿大模型，可以优先尝试量化版开源模型（如 Qwen2.5-7B-INT4），在消费级显卡甚至 Mac 上就能跑出可接受的效果。对于代码辅助、短文案生成等任务，轻量模型性价比极高，云端调用只留给真正需要强推理的长难任务。
2. **企业客户的精细化算账**：在采购 API 前，必须做全链路成本仿真——基于真实业务量测算每日 token 消耗，再与自建推理集群的成本做对比。很多场景下，用 7B~13B 参数模型进行领域微调，效果不输通用大模型，但推理成本降低一个数量级。同时，善用缓存、提示压缩、多级路由等技术手段，能显著削减重复调用开销。
3. **站在行业高度的耐心期待**：国产大模型的价格症结，根源在于上游算力瓶颈。未来几年，若国产 AI 芯片能在制程、生态和产能上实现突破，配合 MoE、稀疏激活、深空压缩等模型架构创新，单位智能成本有望大幅下降。在那一天到来之前，我们需要既理性看待账单，又要给技术和产业多一点时间。
