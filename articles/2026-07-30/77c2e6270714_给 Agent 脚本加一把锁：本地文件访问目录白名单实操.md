## 背景：Agent 的“手脚”为什么需要被约束

在 OpenClaw、MCP 工具链或自建 Agent 的日常使用中，我们经常让脚本代表我们操作本地文件：读取配置、生成报告、整理下载目录。一个典型的场景是：Agent 接收自然语言指令，后端通过函数调用去读写文件系统。如果不加任何限制，一条错误的指令（或一次 prompt 注入）就可能读取 ~/.ssh、覆盖关键配置，甚至递归删除主目录。

沙箱化当然是最彻底的办法——容器、虚拟机、OS 级隔离——但对很多自动化脚本、本地工具链来说，这类方案太重。更轻量的做法是：**给文件访问加一个目录白名单**，只允许 Agent 碰指定的目录，其余路径一律拒绝。这就是本文要实现的“文件访问护栏”。

## 问题拆解：从一段不安全代码说起

假设我们有一段 Agent 里常见的文件读取逻辑：

```python
def read_file(path):
    with open(path, 'r') as f:
        return f.read()
```

攻击路径很直观：如果 Agent 收到 `{"file_path": "../../.ssh/id_rsa"}`，`open()` 会顺着相对路径跳出预期目录。常见的“修复”是用字符串前缀检查：

```python
if not path.startswith('/safe/dir'):
    raise PermissionError
```

这有两个经典绕过：`/safe/dir/../etc/passwd` 和 `/safe/dir_but_not_really`。前缀匹配连路径穿越和目录名近似都拦不住。所以真正的护栏需要**解析规范化路径**。

## 实现：一个可复用的白名单访问层

我们基于 Python 内建库 `pathlib` 和 `os.path.realpath` 做一个最小实现。核心逻辑只有两步：解析符号链接和相对路径，得到真实的绝对路径；然后检查该路径是否在白名单内（以白名单路径 *加目录分隔符* 开头）。

### 1. 核心类 `SafeAccess`

```python
import os
from pathlib import Path

class SafeAccess:
    def __init__(self, allowed_dirs: list[str]):
        # 预解析白名单，统一为绝对路径
        self.allowed = [
            os.path.realpath(d) for d in allowed_dirs
        ]
        # 确保白名单路径以分隔符结尾，防止前缀欺骗
        self.allowed = [
            d + os.sep if not d.endswith(os.sep) else d
            for d in self.allowed
        ]

    def _resolve(self, path: str) -> str:
        real = os.path.realpath(path)
        # 关键：realpath 会跟随符号链接，我们需要对链接目标也做检查
        if not any(real.startswith(allowed) for allowed in self.allowed):
            raise PermissionError(
                f"Access denied: {path} (resolved: {real})"
            )
        return real

    def safe_open(self, path: str, mode='r', **kwargs):
        safe_path = self._resolve(path)
        # 额外检查：如果是写模式，禁止创建符号链接？
        # 可按需扩展
        return open(safe_path, mode, **kwargs)

    def safe_listdir(self, path: str):
        safe_path = self._resolve(path)
        return os.listdir(safe_path)
```

用法示例：

```python
sa = SafeAccess(allowed_dirs=['/home/user/agent_workspace'])
content = sa.safe_open('reports/daily.txt').read()
```

### 2. 集成到 MCP 工具或 OpenClaw 插件

在 MCP 服务器中，可以将 `SafeAccess` 实例化后注入到工具处理函数中：

```python
@server.tool()
def read_local_file(file_path: str) -> str:
    with sa.safe_open(file_path, 'r') as f:
        return f.read()
```

对 OpenClaw 的插件开发者，同样可以在执行操作前统一调用 `_resolve` 做权限校验。更进一步，可以将 `SafeAccess` 替换掉全局的 `open`（通过 `builtins.open`），但建议只替换 Agent 执行上下文内的，免得影响插件自身的正常 I/O。

## 踩坑与工程化细节

下面是我在几个项目里实际踩过的坑和对应的解决办法。

### ① 符号链接的“绕白名单”问题
`os.path.realpath` 会跟随符号链接，解析后可能指向白名单外的真实路径。例如用户在白名单内创建了一个指向 `/etc` 的软链接 `workspace/link_to_etc`，`realpath` 会将其解析为 `/etc`，此时 `_resolve` 可以正确拦截。**但反过来呢？** 如果攻击者在白名单外创建指向白名单内的软链接，访问该软链接实际上是在白名单内操作，风险相对可控。重点是要保持 `realpath` 逻辑，并且禁止 Agent 自行创建符号链接（可以通过 `safe_open` 写模式时不支持 `O_SYMLINK` 或增加检测）。

### ② 目录分隔符与前缀欺骗
如前所述，必须保证 `allowed` 路径以 `/`（或 Windows 上的 `\`）结尾。更健壮的做法是使用 `os.path.commonpath`：

```python
def _resolve(path):
    real = os.path.realpath(path)
    common = os.path.commonpath([real, allowed_dir])
    if os.path.normpath(common) != os.path.normpath(allowed_dir):
        raise PermissionError
```

但需要处理 Windows 盘符不一致的情况。如果你追求跨平台，`pathlib.Path` 的 `is_relative_to`（Python 3.9+）更干净：

```python
real_path = Path(real).resolve()
if not any(real_path.is_relative_to(allowed) for allowed in self.allowed):
    raise PermissionError
```

不过 `is_relative_to` 在新版本才稳定，老环境仍需手动处理。

### ③ 相对路径与初始工作目录
Agent 运行时的 cwd 可能不是白名单目录。务必确保传入 `_resolve` 的路径先被解析成绝对路径。`os.path.realpath` 本身会基于 cwd 转换相对路径，因此直接传给它就可以。但如果你在代码里先做了 `os.path.abspath`，要注意 `abspath` 不解析符号链接，仍有可能被绕过，**始终在最后使用 `realpath` 或 `resolve()`**。

### ④ 性能与审计
每次文件操作都调用 `realpath` 和字符串匹配，对高频读写有点浪费。可以加一层简单的缓存，按已解析路径缓存判断结果，因为白名单很少变化。

另外，强烈建议在 `_resolve` 拒绝时记录完整的原始路径、解析后路径、时间戳，存到审计日志。这在事后排查“为什么 Agent 没读到文件”时极其有用。

## 可复用建议

1. **配置化白名单**：不要在代码里硬编码，通过配置文件或环境变量传入，方便运维切换 Agent 的工作区。
2. **只读与读写分离**：如果某个 Agent 任务只需要读数据，可以将白名单目录挂载为只读，并在 `safe_open` 里限制 `mode` 只能是 `r`。
3. **最小权限原则**：为每个 Agent 实例分配最小白名单集合，不要一下子把整个家目录扔进去。
4. **与现有机制互补**：这个护栏属于应用层控制，不能防御内核漏洞或权限提升攻击。生产环境还是建议配合容器用户映射、SELinux/AppArmor 等一起使用。

## 总结

给自动化脚本加目录白名单不是万灵药，但它是工程上成本极低、收益明显的一步。通过强制路径规范化和前缀匹配，你可以用几十行代码大幅降低文件访问失控的风险。把它封装成 MCP 工具的基础设施，或者 OpenClaw 插件的一个中间件，能让你在享受 Agent 带来的自动化便利时，少一些被“删库跑路”的恐惧。

最后的提醒：任何文件护栏的实现，都**务必将日志和拒绝策略放在一起测试**——我见过太多因为忘记打印错误原因而让调试变成猜谜的现场。
