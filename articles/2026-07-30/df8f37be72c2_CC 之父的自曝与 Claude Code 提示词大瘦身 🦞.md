Anthropic 的 CEO Dario Amodei 被许多人称为“CC 之父”（Claude Code 的缔造者）。最近他在一次访谈里轻描淡写地提到：自己当年学编程，动机单纯得离谱——为了考试作弊。更让技术圈炸锅的，是他透露 Claude Code 内部已经将系统提示词（system prompt）砍掉了超过 80%。一个以安全谨慎著称的团队，居然会主动对自家模型的“护栏”下手？这背后不是黑客偷袭，也不是临时工删库，而是一场关于效率、幻觉与能力边界的精密手术。这也恰好戳中当下不少开发者隐隐的痛点：模型越来越啰嗦，总在回答前先上一堂思想品德课，让人怀念那个更“听话”的助手。

## 系统提示词到底是什么？不是魔法，是贴在模型脑门上的便利贴

很多初上手调 API 的人容易把系统提示词与用户消息混为一谈。其实可以把大语言模型想象成一个非常聪明但极度中立、没有预设身份的超级雇员。系统提示词就是你递给它的那份《入职手册》——定义角色、设定边界、给出行为准则。

- 典型内容：你是一位专业的代码助手，始终输出正确、安全、无害的内容；遇到不确定时请说明；不要生成违法信息。
- 技术实现：在模型输入的最前端拼接一段固定的文本，优先级高于用户输入，通常对模型输出有全局约束力。
- 实际案例：Claude 旧版系统提示词可能长达数千 token，包含大量安全指令、拒绝规则、格式要求、伦理条款。

这些提示词就像汽车的安全带加防滚架再加限速器。一开始大家觉得越多越安心，但很快发现：每多加一条规则，都可能挤占模型宝贵的注意力（context window），也让响应变慢、迂回，甚至在简单任务上出现“拒绝服务”式的安全过敏。

## Claude Code 砍掉 80% 提示词，到底发生了什么？

外部研究者与开发者发现，近期 Claude Code（Anthropic 专为编程场景优化的模型版本）的系统提示词已经大幅瘦身，从原本洋洋洒洒几千字缩减到不足原先的 20%。根据一些可靠社区的逆向工程与 API 行为对比，剩余的部分几乎只包含：

- 基础身份声明
- 极简的输出格式约定
- 少量关于代码安全的关键规则（如不生成恶意代码）

而大量曾被塞进去的“你应当友善”“确保不歧视”“回应要体现包容性”等价值教导类指令，以及繁琐的角色扮演设定，被悄然移除。这对老用户来说感知非常强烈——Claude Code 回答代码问题更直接、少说教，拒绝率明显下降。

这让很多人猜测 Anthropic 是不是在“去安全化”。但从动机看，更合理的解释是把控制权更多交还给开发者，把“软约束”迁移到模型基座的训练阶段，而不是只依靠表面的文本命令。

## 为什么必须删？顶层指令在跟能力打架

系统提示词的过度膨胀，不只是浪费 token 那么简单。它会给模型带来三类实打实的伤害。

1. 上下文挤占效应
   - Claude Code 主要用于长序列代码生成，输入常包含大量源代码、日志、测试用例。
   - 系统提示词每占用 1k token，用户能用到的上下文就少 1k。对于需要喂入整个项目架构的场景，省下的几千 token 可能就是能跑通与跑不通的距离。

2. “道德说教”引发幻觉与错误拒答
   - 大量安全规则会让模型形成一种“先审查再回答”的惯性。有些指令彼此冲突，比如“永远诚实”与“避免冒犯用户”，在微妙场景下会让模型陷入内部矛盾，反而生成更保守甚至扭曲的回答。
   - 曾有用户发现，在纯技术问题中包含敏感变量名（如 bomb、hack）时，旧提示词下的 Claude 会直接拒绝，哪怕那只是游戏逻辑。

3. 训练与提示的不对齐
   - 如果模型通过 RLHF（人类反馈强化学习）已经在骨子里学会了无害化，那么额外在提示词里重复强调就是画蛇添足。过多的“行为处方”反而会抑制模型真实能力的发挥，让它变得像被太多规矩束缚而不敢迈步的员工。

因此，Claude Code 删掉大量提示词，不是放松安全，而是把这些约束下沉到模型权重本身——让一个真正懂得界限的模型，不必每天被耳提面命。

## 对开发者意味着什么？四个立即可感的变化

- API 成本下降：减少的前缀 token 会直接在每次 API 调用中省掉输入费用，对高频调用的企业是实打实的节省。
- 首字延迟更低：prompt 处理环节的指令简化，缩短了预填充时间，IDE 里的代码补全反应更快。
- 拒绝率骤降：对于 SQL 注入测试、安全渗透脚本等灰区场景，Claude Code 更倾向于直接给出技术实现，同时由开发者自行负责合规性。
- 可控性增强：现在你可以通过用户消息或助理首轮消息更自由地塑造行为，而不会被系统级指令搞得“人格分裂”。

当然，这也带来新的责任。瘦身后的模型更依赖开发者的合理使用，你需要在应用层做好输入过滤和输出审核，而不是指望模型自带万能护身符。

## 跟 CC 之父的自曝有什么关系？从作弊到务实主义

Dario Amodei 说自己初学编程是为了在考试中做手脚，这听起来像个玩笑，但对照这次提示词删减事件，隐约能看出一条一以贯之的工程逻辑：解决问题优先，框架和仪式感往后放。当年用程序生成小抄，是为了突破无聊记忆的局限；如今砍掉冗余指令，是为了突破模型啰嗦与能力受限的困局。

这种务实主义，恰恰是开发者在选择工具时需要反复咀嚼的。我们太容易迷恋“万能的安全咒语”，以为加几条 prompt 就能让模型变好。但真正的好用，往往来自底层训练、数据清洗与精心的架构取舍，而不是给每个请求套上厚厚的话术马甲。

### 三点冷思考

- **别让系统提示词成为你的安全幻觉**。如果你依赖一段文本就认定模型无害，那么当文本被移除或攻击者通过 prompt injection 绕过时，整个应用就会裸奔。真正的安全防线必须落实到输出过滤和沙箱执行。
- **时常审视你的“入职手册”**。定期检查你给模型设定的系统指令，删除那些已经内化到模型行为的冗余要求。实验表明，精简后的提示词往往能同时提升响应质量和速率。
- **拥抱“瘦身”趋势，但别丢了自己的护栏**。Claude Code 的示范可能很快被其他模型跟进。你的产品应该设计成“轻提示词+重后处理”的架构，这样无论底层模型如何调整系统策略，你都能保持稳健的用户体验。

说到底，CC 之父拿作弊开玩笑，与删掉 80% 提示词，都是在用最少的必要约束换取最大的效果。下次看到某个模型突然变聪明又少废话，不妨先看一眼它的系统提示词——说不定它刚刚做完一场健康的职场瘦身。
