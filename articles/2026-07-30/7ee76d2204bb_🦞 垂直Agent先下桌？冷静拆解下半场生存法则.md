上半年还在疯狂融资的垂直 AI Agent，到了下半年，突然被贴上一张“先下牌桌”的标签。36氪的话题一出，不少开发者心里一紧：自己花了半年打磨的行业 Agent，会不会还没等到 PMF 就被通用大模型一口吞掉？与其跟着情绪走，不如拆开牌桌，看看究竟谁在退场，谁反而坐得更稳。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-30/e15630d1946ae597.png)

## 为什么大家觉得垂直Agent要“下牌桌”？

情绪从来不是空穴来风。下半年这股“垂直 Agent 退潮论”，背后至少有三股推力在同时起作用。

**1. 通用大模型的“吞噬效应”越来越明显**
GPT-4o、Claude 3.5 Sonnet 在长上下文、工具调用和结构化输出上的进展，让很多原本需要专门微调的任务直接被零样本解决。一个原本靠垂直 Agent 做的合同条款提取，现在用通用模型加上精心设计的 system prompt 就能达到 90% 的准确率。当基座模型每半年就吃掉一层应用，那些只做“薄薄一层 Prompt 封装”的垂直 Agent 自然失去存在价值。

**2. 商业闭环远比想象中沉重**
企业客户为 Agent 付费的意愿，取决于它能否稳定融入现有工作流，而不是演示视频有多惊艳。医疗问诊 Agent 要对接 HIS 系统，金融合规 Agent 要过审计要求，光是这些对接与合规成本就足以吃掉大部分毛利。当投资人从“看 demo 就给钱”切换到“看合同再打款”，很多账算不过来的垂直 Agent 立刻暴露出商业上的脆弱性。

**3. 同质化内卷让价值快速稀释**
过去一年，无论是代码生成、客服质检还是会议纪要，每个垂类都挤进来十几个长得差不多的 Agent。技术门槛低到一名全栈工程师花两周就能搭出一个 RAG + function call 的原型。当供应远超需求，价格战一来，无法构建护城河的玩家就只能第一个被清出牌桌。

## 被推下牌桌的，往往是这三类“纸牌屋”Agent

并非所有垂直 Agent 都在退潮，但以下三类产品，确实正在经历残酷的淘汰。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-07-30/f7cdf3db7f1bcfcd.png)

**类型一：Prompt 包装型**
这类 Agent 的核心就是在通用模型外面套了一层角色设定和知识库搜索，本质是一个“增强版 ChatGPT”。比如一些早期的法律咨询 Agent，只是在 prompt 里要求模型“以律师口吻回答”，后端连一个像样的法规数据库都没有。当基座模型本身的法律知识不断更新，这种包装的价值瞬间归零。

**类型二：死守规则的老式 Bot**
部分垂直 Agent 的技术栈还停留在意图识别 + 决策树时代，即便接上了大模型，也只是把 NLU 模块换成了 LLM，整个执行逻辑依然是硬编码的 if-else。一旦业务场景出现未被预设的新情况，这类 Agent 会直接“死机”，毫无泛化能力。与之对比，通用模型的多步推理能力可以动态构建解决方案，两者差距只会越拉越大。

**类型三：数据孤岛型产品**
有些 Agent 虽然一开始靠私有数据占了先机，但上线后却无法形成数据飞轮。用户每一次交互的反馈没有回流训练，知识库也不随业务更新。半年后，模型落后的版本与停滞的知识库叠加，效果甚至不如公有模型的零样本表现。没有活数据滋养的垂直 Agent，本质是在“吃老本”，而老本总会吃光。

## 相反，有些垂直Agent反而越坐越稳

牌桌上不全是败退的身影，一批垂直 Agent 正在逆势扩张，它们的共同点非常清晰。

**1. 私有高壁垒数据 + 专家工作流**
在医疗影像判读领域，能活下来的 Agent 绝不仅仅是“看图说话”。它必须接入大量脱敏的真实病历，学习上百种科室的工作流，能直接产出符合医保规范的影像报告。这类数据的获取成本极高，且医生在环反馈形成的数据标注，本身就是无法被通用模型复制的护城河。

**2. 深度绑定合规与信创体系**
金融、政务行业的 Agent，其核心竞争力不完全是算法，而是已经通过的等保测评、信创适配认证、以及与现有 OA 系统的无缝打通。通用大模型哪怕能力再强，只要一天没拿到本地化部署的合规认证，就没法替换已经跑通审计流程的垂直 Agent。这种非技术壁垒，是“慢”但“稳”的保障。

**3. 与物理世界或硬件紧耦合**
工业巡检 Agent、手术机器人规划 Agent、自动驾驶标注 Agent，这些产品不能只活在 API 里。它们需要和传感器、机械臂、边缘计算盒子深度集成。模型只是其中一个环节，整个链路的实时性、安全冗余和硬件适配才是真门槛。这类 Agent 离通用模型取代的威胁最远，因为大模型暂时还搬不动设备。

## 下半年的牌局：从“做概念”到“钉钉子”

一个越来越明显的趋势是：投资人和客户不再为“AI-native”的故事买单，转而要求明确的效率提升指标。某电商客服 Agent 拿过一轮融资，后来发现商家真正要的是“7×24 小时无错别字的回复”，而不是“具有共情能力的对话”。最终留下来的，是那些能把退货退款流程从 6 步压缩到 2 步，并直接体现在工单关闭率上的产品。

判断一个垂直 Agent 能否留在牌桌，只需问三个问题：
- 它解决的问题，是客户当前愿意用 Excel 或微信群手动解决的痛点吗？
- 去掉大模型，这个产品还能否提供 40% 以上的价值？
- 六个月后，产品积累的独有数据能否形成新的业务洞见？

如果三个答案都是“否”，那么无论模型能力多强，下半年的牌桌恐怕很难有它的位置。

## 🦞 RY哥的三条冷思考

**1. 别再神话模型，业务 know-how 才是垂直 Agent 的灵魂**
大模型能提供通识，但永远无法自动理解你目标行业里那些“不成文的规矩”。与其天天焦虑 GPT-5 会不会吃掉你，不如花时间跟一线业务员一起喝杯茶，把他们的异常处理经验编码成 workflow。这才是真正不会被通用模型稀释的价值。

**2. 优先选择“老问题新方案”的场景**
不要试图用 Agent 去创造全新的需求，而是找到那些已经被 Excel、微信群、纸质工单反复折磨的业务环节。证明“我可以把这件事的成本打到原来的十分之一”，远比证明“我能做一件以前没人做过的事”更容易拿到预算。

**3. 哪怕飞轮转得慢，也一定要转起来**
数据飞轮不一定非要靠海量用户。B 端场景里，一个客户每周提供50条高质量反馈，持续半年，就能构建出极其坚固的垂直壁垒。关键是设计好“反馈——清洗——训练——评估”的闭环，让每一个项目都成为下一次交付的养料。

垂直 Agent 从来不是一条赛道，而是一百种不同的慢生意。下半年的牌桌不会清场，它只是在重新发牌——把筹码从讲故事的人手里，收回给真正解决问题的人。
