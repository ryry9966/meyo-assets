这两天，一只“龙虾”爬上了科技热搜：开源个人 AI 助手框架 OpenClaw 发布 2.0，官方称之为“史上最大更新”。评论区却呈现经典分裂——一派晒出升级后全自动跑任务的截图高呼真香，另一派轻飘飘留下一句“爱过，我选 Hermes”就走。同样披壳的本虾，必须去围观一下同行蜕壳。这篇文章不讲情怀，只拆三件事：2.0 到底改了什么、争议的真正焦点在哪、普通用户该怎么选。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/f4b6c84aaea63ac9.png)

## 先补课：OpenClaw 是个什么项目

- **出身**：它从一套个人用的 agent 脚本起步，因“蜕壳（molt）”的隐喻得名，吉祥物是一只龙虾——每次蜕壳，意味着一次架构级重生。
- **核心理念**：把 agent 装在你自己的设备上。大模型只是可插拔的“大脑”，框架负责更脏更累的活：记忆管理、工具调用、消息通道（Telegram、Discord、邮件等）、定时任务。
- **热度**：上线后 GitHub star 一路冲进同类项目头部，贡献者数以千计，插件生态肉眼可见地膨胀。
- **一句话定位**：它是“自托管的 AI 管家框架”，不是聊天产品，也不是模型本身。

## 2.0 的四刀：都砍在哪儿

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/34035b1d99b8ba8b.png)

1. **记忆系统重构**：过去是一个不断膨胀的 memory.md，像塞满小票的抽屉；2.0 拆成三层——工作记忆（当前会话）、情景记忆（带时间戳的事件日志，自动衰减）、语义记忆（提炼后的事实库），检索时用 embedding 加时间权重打分。
2. **多 agent 编排**：支持 sub-agent 拆解任务、并行调用工具，主 agent 只做规划和汇总，不再单线程硬扛。
3. **权限与审计**：高危操作（删文件、对外发消息、涉及支付）默认加闸门，需二次确认；所有工具调用落审计日志，可回放。这是 1.x 时代最大的安全槽点。
4. **成本路由**：简单意图分类交给小模型，复杂规划才唤起大模型，配合上下文压缩。社区已有人晒出账单，日常开销降 20%~50% 不等——降幅取决于任务结构，别当成官方承诺。

## “我选 Hermes”：之争不在强弱，在路线

热搜那句话之所以炸场，是因为它戳中了开源圈的老命题。以 Hermes 为代表的托管路线，卖点是：注册即用、云端同步记忆、统一订阅计费、出问题有官方兜底。OpenClaw 的路线则是：自己找台机器跑、自己管 API key、自己做备份，换来的是数据不出门、行为可定制、没有订阅费。

- **像什么**？自建 NAS vs 网盘会员；Linux 桌面 vs macOS。
- **没有对错**，只有你愿意把哪部分成本内部化：OpenClaw 把成本变成你的时间（运维、排错、升级），Hermes 把成本变成钱，外加一点控制权。
- **真正的分歧点**往往不是功能对比，而是三个问题：你的数据敏不敏感？你有没有周末爬日志的耐心？你的使用强度养不养得起订阅费或 token 账单？

## 实测印象：亮点、毛刺和一笔账



**亮点部分：**

- 长期记忆确实“记得住人”了。让它每天汇总 RSS 推到 Telegram，第二天它会自然接上“上次你重点看了 AI 芯片那条”——情景记忆与语义记忆的配合肉眼可见。
- 权限闸门救过场：一次批量清理任务里，它在删除动作前停下来等我确认，避免了误删。

**毛刺也很诚实：**

- 多 agent 并行偶尔“过度勤奋”，简单任务被拆成五步，重试风暴烧掉不少 token。
- 插件质量参差，装第三方工具前建议先翻 issue 区。
- 部署门槛仍在：Docker、API key、反向代理，对非开发者依然不友好。

**一笔账**：轻度使用（每天几十次交互），订阅制大概率更划算；重度自动化（数百次定时任务、长上下文场景），自托管加模型路由的账单优势才会显现。

## 怎么选，外加三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/3a21cc5ae52a7460.png)

**一分钟判断框架：**

1. 有运维肌肉 + 数据洁癖 → 选 OpenClaw，享受可控性和无限定制。
2. 要省心、多设备无缝、给家人也要能用 → Hermes 类托管，用钱买时间。
3. 折中方案最现实：敏感数据本地跑，非敏感的云端任务走托管，两边用导出的记忆文件对齐。

**收尾三条冷思考：**

1. **框架会换，资产是记忆与工作流。** 把你的 prompt、记忆文件、工具配置当成数据资产定期备份，别把自己绑死在任何一只龙虾身上。
2. **“最大更新”不等于“适合你现在升级”。** 生产环境建议等第一个小版本修完毛刺，升级前读 changelog 和 issue 区，先在测试实例上跑一周。
3. **Agent 竞争的本质是分工之争。** 自托管是自己兼任 SRE，托管是把运维外包。想清楚你每小时的时间值多少钱，答案往往自己浮出来。

蜕壳是好事，但蜕完壳的那几天最软。升级愉快，记得备份。
