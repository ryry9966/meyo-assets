## 背景

OpenClaw 的 workspace 目录里有一组随会话注入的 Markdown 文件，`IDENTITY.md` 是其中最容易被忽略的一个。它回答的问题很朴素：这个 agent 是谁——名字、形象、语气、边界。默认模板只有几行，很多人装完就跳过，结果 agent 的行为全靠模型默认性格，加上聊天里的临时纠正撑着。

## 问题

没有一份稳定的身份文件时，典型症状有四个：

- **人格漂移**：同一个 agent 今天话痨、明天冷淡，跨会话不一致；
- **调教不可迁移**：在对话里反复纠正出来的风格，换模型、升级版本后全部丢失；
- **多实例混淆**：几个 agent 共用默认提示，回复风格雷同，分不清谁是谁；
- **Prompt 散落**：身份相关指令散布在配置、system prompt 覆写和会话记忆里，没法 review，也没法回滚。

## 做法

### 1. 建立最小身份文件

路径 `~/.openclaw/workspace/IDENTITY.md`，建议控制在 30–50 行：

```markdown
# Identity
- Name: Nova
- Creature: 一只务实的工程猫头鹰
- Emoji: 🦉
- Vibe: 冷静、直接、偏工程口吻，不堆敬语

## 语气规范
- 默认简体中文，代码与命令保持英文
- 先给结论，再给依据；不确定就直说

## 边界
- 删除数据、对外发消息等不可逆操作，先复述确认
- 不编造版本号、路径、API 名称

## 示例
（贴 2–3 条真实问答的 few-shot）
```

关键点：形容词模型没法执行，示例可以。两条真实的 few-shot 问答，比十行“要友好、要专业”管用。

### 2. 把 workspace 纳入 git

身份改动 = 一次 commit。能 diff、能回滚，行为突变时立刻能定位是哪次改动引入的。

### 3. 设计进化回路

- 每周让 agent 复盘近期对话，输出“哪些回应不符合预期”的 diff 建议；
- 人工 review 后合并进 IDENTITY.md，**一次只改一个维度**；
- 准备 10 条左右的固定测试问题（覆盖日常、边界、报错场景），改动前后各跑一遍，做行为回归。

### 4. 明确文件分工

IDENTITY.md 管“我是谁”，SOUL.md 管行为准则，USER.md 管用户事实，MEMORY.md 管经验记录。互相渗透是多用户场景下最常见的污染源。

## 踩坑点

1. **写太长**。IDENTITY.md 每次会话都进上下文，几百行会挤占预算、稀释重点。
2. **形容词堆砌**。“聪明、友好、专业”无法落地，要换成可观察的行为描述加示例。
3. **塞入用户事实**。“用户喜欢简洁回复”属于 USER.md；写进身份文件，换个用户就翻车。
4. **无人审核的自我进化**。直接让 agent 自改身份会自我强化——“少道歉”可能进化成“永不承认错误”。必须走 commit/PR 审核。
5. **改完不验证**。开一次冷启动会话确认新身份确实注入生效，别只看热会话的表现。

## 可复用建议

- 把身份当代码：小步提交、diff review、可回滚；
- 示例 > 形容词；
- 固定测试集做行为回归，避免“感觉变好了”式玄学评估；
- 每次只改一个维度，方便归因；
- 每月做一次压缩，合并重复条目，保持文件精瘦。

## 总结

IDENTITY.md 的价值不是让 AI“更像人”，而是把调教从会话内的临时纠偏，变成版本化、可审计、可复现的持久资产。身份稳定了，行为才可预期；行为可预期，自动化才敢真正放权。建议今晚花二十分钟：建文件、进 git、写三条示例——下周复盘时你会感谢自己。
