## 背景

在 OpenClaw/Agent 生态里，社区发帖很适合自动化：内容有固定结构、发布有 API、审核边界清晰。但直接让大模型输出一段 Markdown 再 curl 发出去，基本会在第一晚被限流、格式错误或标签失败教做人。

我做这个机器人的目标不是“全自动灌水”，而是把重复劳动压缩为：定时采集 -> 生成草稿 -> 人工确认 -> 发布记录。核心思路是：Agent 负责组装内容，MCP 工具负责隔离社区 API，生产环境只允许写草稿。

## 问题定义

真正的问题不是“能不能生成”，而是发布链路是否可回滚、可审计。直接让模型拼 Markdown 后 POST，会出现三类事故：标签不在平台枚举内、代码块被平台二次改写、同一内容重复发布。所以先把边界定清楚：模型不直接拿发布权限。

## 做法与步骤

架构分三层：

1. **采集层**：从 RSS、issue、CHANGELOG 拉取条目，做去重和摘要，写入 SQLite。
2. **生成层**：OpenClaw agent 按模板生成 Markdown，必须输出 title / tags / status 三个字段，默认 status=draft。
3. **执行层**：MCP server 暴露社区 API，提供 create_draft、publish_post、list_categories、list_my_posts 四个工具。

Agent 的工具调用链路如下：

```text
list_categories -> 选择合法分类
create_draft -> 获得 post_id
写入审计日志 -> human_review
publish_post -> 记录 content_hash
```

关键点：publish_post 不放在默认工具集，只有人工确认后由另一个会话或带审批参数调用。所有工具返回统一规范化为：

```json
{"ok": true, "data": {"post_id": "123"}, "retryable": false}
```

错误也分 retryable / non_retryable，避免 Agent 对“业务 code 非零但 HTTP 200”误判成功。

## 踩坑点

- **API 返回 200 但业务失败**：很多社区接口总是 HTTP 200，真正状态在 body 的 code 字段。工具层必须统一解包，否则 Agent 会认为发布成功。
- **Markdown 被平台二次处理**：表格、代码块语言标注、外链会被过滤。Prompt 里要明确：不用复杂表格，代码块只保留必要语言，图片最多 1 张。
- **标签/分类自由发挥必翻车**：让 Agent 从 list_categories 返回中选，而不是生成新分类。
- **重复发布**：同一内容源可能被多次采集。发布前用标题+正文前 200 字符做 sha256，查本地表。
- **时区问题**：容器默认 UTC，cron 按本地时间写会差 8 小时。统一存 UTC，展示层再转换。
- **凭证泄漏**：不要把社区 cookie/token 写进 prompt 或模型上下文，只在 MCP server 环境变量注入。

## 可复用建议

1. 权限边界放在工具层，不要放在提示词里。Agent 只能调用 create_draft，不能碰 publish。
2. 发布必须经过草稿状态。即使以后做全自动，也保留草稿快照和回滚入口。
3. 审计日志至少保留 30 天，记录 prompt 版本、模型版本、工具调用参数和返回。
4. 先跑个人草稿箱或低风险板块，观察两周再考虑开放公共频道。
5. MCP 工具的错误翻译比优化 prompt 更重要，很多重试和幻觉来自模糊的工具返回。

## 总结

社区发帖机器人的难点不在内容生成，而在发布链路的边界与可回滚。用 OpenClaw 把生成和工具执行分离，再用 MCP 包装社区 API，可以让系统从“能发”变成“发得稳、能追责”。先跑通草稿闭环，再谈自动化，是成本最低的路径。
