最近开发者圈刷屏的消息：开源项目 OpenClaw 在断更 7 周后回归，一个版本一口气处理了 1.6 万个 PR。表面看是"项目大爆发"，实际更像一次审核系统过载后的"泄洪"。当 AI 把写代码的成本压到接近零，而人类审代码的速度还停留在每分钟几百行，生产力与审核力之间的剪刀差，第一次大到能把一个成熟开源社区逼停。这件事，值得每个写代码的人都看懂。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/3e7e9e86ff6a7e34.png)

## 一、发生了什么：一场审核堰塞湖

- 按报道口径，OpenClaw 的节奏大致是：PR 涌入速度远超审核速度 → 队列积压 → 正常发版被卡住 → 被迫停更 7 周集中消化 → 一个版本合并 1.6 万个 PR。
- 算一笔时间账：哪怕每个 PR 只花 15 分钟（看 diff、跑测试、读提交说明、回复评论），1.6 万个 PR 就是 4000 个工时，相当于一个人全职审核约 100 周。所谓"断更 7 周"，其实是维护团队在用自己的时间，给整个生态的"生成过剩"买单。
- 涌入的 PR 大致三类：真人提的功能需求、AI 辅助的正常贡献、低质量的批量提交（业内戏称 AI slop）。真正消耗审核精力的，恰恰是后两者的混合——你无法从外观上区分一个精心打磨的 PR 和一个 LLM 批量产出的 PR。

## 二、不对称的根源：生成是并行的，审核是串行的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/fc9978e968ab5806.png)

- **生成端的速率**：现代 LLM 每秒可输出上百个 token，一个 agent 一晚上能"写完"一个中型功能；更关键的是并行性——一个人可以同时开十几个 agent 会话，边际成本约等于 API 费和电费。
- **审核端的物理约束**：人类读代码大约每分钟 200~400 行，而且不能理解错；还要加载上下文、权衡设计、评估安全影响。审核天然是串行的，同一份代码不能被两个人各审一半。
- 于是数学上出现剪刀差：一个熟练的 prompt 使用者一天能产出的 PR 数量，可能超过一个维护者一年的审核量。就算 90% 是垃圾，剩下 10% 也要靠人眼筛——垃圾多不多不是重点，重点是"甄别成本"由接收方全额承担。
- 这和垃圾邮件的逻辑一模一样：当发送成本趋近于零，接收方必须自建过滤设施，否则收件箱直接瘫痪。生成快如闪电，审核慢如蜗牛，中间没有任何缓冲层。

## 三、"扫一眼"为什么不行：AI 代码的可读性陷阱

- AI 代码的平均质量并不低：风格规整、命名规范、注释齐全、"看起来都对"。但 review 的本质不是找"像错的"，而是找"不像 bug 的 bug"——边缘条件、隐式依赖、并发时序、安全边界。
- 典型风险点至少有三个：
  1. **幻觉 API**：引用不存在的库函数或包名，甚至衍生出 slopsquatting 攻击面（有人抢注被幻觉出来的包名投毒）；
  2. **许可证污染**：训练数据里混入的受限代码片段被模型原样"复述"进 PR；
  3. **测试迎合**：AI 生成的测试常只覆盖 happy path，绿灯不代表安全。
- 信任被稀释之后没有捷径：维护者无法跳过任何一个 PR，因为不知道第几个是"真的"。2024 年 curl 就因收到大量看似专业、实则空洞的 AI 生成安全报告，公开宣布不再接受此类报告，甚至专门设了悬赏来抓 AI slop。审核成本不会消失，只会转移。

## 四、社区的应对：给审核环节造基础设施

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/556ac497a8ccd26f.png)

- **硬化 CI**：强制测试、覆盖率门槛、静态扫描、fuzzing，让机器先挡一轮，人类只看机器标记出来的疑点。
- **用 AI 审 AI**：预审 bot 做重复检测、diff 粒度检查、幻觉 API 检测，自动归类、自动关闭不合格提交。审核的第一道闸门必须是自动化的，否则毫无胜算。
- **流程门槛**：issue-first（先讨论设计再写码）、贡献模板、要求声明 AI 生成内容——把"讨论成本"前置，过滤掉随手一投的提交。
- **速率与信誉**：限制单个账号或组织的并发 PR 数，像反垃圾邮件一样给贡献者建信誉分。
- **人力与资金**：培养更多 reviewer、降低 bus factor；部分项目开始探索给"审核"这件事找钱，比如赞助维护者、为复杂功能 PR 设置付费优先审核通道。

## 五、冷思考：稀缺资源换位了

开源经济学过去默认：写代码的人是稀缺资源，所以有 bug bounty、捐赠和赞助。现在发生了反转——代码无限供给，稀缺的是维护者的注意力和判断力。

这不意味着开源要完，而是协作规则要重写：从"人人可以随手提 PR"走向"人人可以先提 issue，PR 是讨论的产物"。就像邮箱时代的 spam 逼出了过滤基础设施，AI 时代正在逼开源社区建设"审核基础设施"。谁能把审核带宽做成可持续的工程系统，谁就能在下一波 AI 洪峰里活下来。

## 三条带走的建议

1. **给维护者：把审核带宽当核心资产运营。** 写清贡献规则（issue-first、PR 粒度、AI 声明），用 bot 和硬 CI 外包重复劳动，把人类 reviewer 的宝贵时间留给真正需要判断的设计问题。
2. **给用 AI 的贡献者：PR 不是免费彩票。** 先开 issue 对齐设计，diff 拆小，本地跑全量测试再提交。一条被认真回应的 issue，比十个无人问津的 PR 更接近"成为 contributor"。
3. **给评估项目的人：看审核基础设施，别只看 star 数。** CI 深度、PR 平均响应时间、积压健康度，比 star 数更能说明这个项目扛不扛得住 AI 洪峰。

代码可以无限生成，判断力不行。这大概是 AI 时代最早被写进运维手册的常识。
