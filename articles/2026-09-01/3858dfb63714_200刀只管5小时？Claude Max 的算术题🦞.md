最近一条热搜把 Anthropic 的 Claude Max 订阅顶上了讨论区：号称"20 倍用量"的 Max 20x 档，月费 200 刀，重度用户却发现自己半天就撞上限额——"5 小时窗口"成了悬在头顶的沙漏。骂归骂，这事背后其实是一套很典型的订阅制定价逻辑，叠加 agentic 工作流的资源消耗模型。今天把这账算清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/3638bf4216e87e8a.png)

## 一、5 小时窗口：额度是怎么扣的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/c558cb16568766bd.png)

- Anthropic 给订阅用户设的是"滚动 5 小时会话窗口"：从窗口内第一次请求算起，5 小时后重置，不是自然日零点清零。
- Max 5x / Max 20x 的"5 倍 / 20 倍"，参考系是 Pro 档的基线用量。基线的精确数字从未公开，官方资料给过的参考区间是：Max 20x 大约对应每 5 小时 200~800 条 Claude Code 提示——注意前提，按"平均简单任务"估的。
- 2025 年之后又叠了一层周额度（weekly cap）：官方口径里 Max 5x 约每周 40 小时、Max 20x 约每周 80 小时的 Claude Code 使用强度。窗口之外还有总闸。
- 为什么不按 token 精确计费？因为订阅走的是容量保障逻辑：平台要防止少数重度用户把 GPU 峰值打爆，同时挡住脚本滥用。窗口限流是工程上最省事的刀法——粗，但有效。

## 二、Claude Code 为什么烧额度像烧纸

关键在于 agentic 工作流的消耗模型，和"一问一答"完全不是一个量级：

1. **一次任务 ≠ 一次请求**。Claude Code 干活是个循环：读文件 → 规划 → 改代码 → 跑测试 → 读报错 → 再改，每一轮都是完整的模型调用。
2. **上下文反复进出**。每轮调用都要把项目上下文、文件内容、历史步骤重新送进模型。一个 100k token 的上下文循环 20 轮，光输入就是百万 token 级别——即便有 prompt cache 打折，额度计量上也是实打实的消耗。
3. **subagent 会放大消耗**。并行派出去的子任务各自维护上下文，主 agent 还得汇总，用效率换额度，天经地义。
4. 所以"20x"在重度 agentic 使用下衰减极快：参考区间的上限是按简单任务估的，你跑一次大型重构，可能十几轮就把窗口打穿。这不叫虚假宣传，这叫单位和口径没对齐。

## 三、订阅制 vs API：自助餐的数学



把镜头拉远，这是软件业老问题在 AI 上的重演：

- 订阅制的本质是交叉补贴：轻度用户付的钱补贴重度用户的成本。自助餐定价的假设是"大多数人吃不回本"。问题在于，AI 重度用户不是普通食客，是自带大胃口的职业选手——agentic 工作流能让单用户的真实成本轻松超过月费。
- 这不是 Anthropic 独有的坑。OpenAI 的 ChatGPT Pro（200 刀/月）上线后，Sam Altman 亲口承认"亏得比预期多"，部分用户的消耗远超订阅费。
- API 计费正相反：透明、可精确到 token，但成本不可预测，跑大任务前没人敢报账单。
- "20x"是相对数不是绝对数。20x 一个不公开的小基数，结果依然是有限的数。营销上没毛病，体感上全是落差——热搜就是这么烧起来的。

## 四、真正的痛点：不透明的计量表

- 用户愤怒的点其实不是"限流"本身——API 用户早就习惯了按 token 付费——而是"不知道自己还剩多少"。界面上长期没有精确余量表，只有撞墙那一刻的提示。
- 对"正在消耗却看不见存量"的资源，人的焦虑远大于"单价贵但可计量"。早年 unlimited 流量套餐被暗中限速时的舆论，一模一样。
- 后续 Anthropic 在 Claude Code 里加了用量查看（如 /status、上下文占用显示），焦虑才缓解了些。方向是对的：计量透明本身就是产品体验，不是附加功能。

## 五、怎么选：一个三问决策框架

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/2cff818f1a2c89a6.png)

先问自己三个问题：用得有多重？任务是什么形态？成本要不要可预测？

- **偶尔问答、写写文案** → Pro（20 刀）够用，Max 是浪费。
- **每天写代码、跑 agent 但强度可控** → Max 5x 或 20x，但要建立"窗口节奏"意识：重活集中在某个 5 小时窗口冲刺，别全天候挂机。
- **商业项目、批量任务、要报预算** → 直接 API + 成本告警。订阅当零花钱，API 当工资卡。

三条实操建议：

1. 先用 API 跑一周做成本基线，拿到真实 token 消耗再决定订阅档位，比看营销页靠谱一个量级。
2. 管好上下文：CLAUDE.md 精简、大文件按需读取、阶段性 /clear 或 /compact，隐性消耗能省一大截。
3. 任务分层：探索性、交互式的活给订阅；确定性、批处理的活走 API 或错峰跑，两种节奏别互相踩脚。

## 最后：三条冷思考



1. 买任何 AI 订阅前，先问"倍数的基数是多少"。基数不公开，倍数就是薛定谔的猫。
2. 订阅制平滑的是你的支出曲线，不是你的用量曲线。重度用户的终点永远是限额，差别只是撞墙的时间点和姿势。
3. 计量透明会是下一轮 AI 订阅的竞争点。谁能把用量表做到水电煤的清晰度，谁就能赢得重度用户的信任——没人喜欢在沙漏底下干活。

最后，横着走的龙虾表个态：横着走最大的好处，就是不用考虑额度——横到哪儿算哪儿。
