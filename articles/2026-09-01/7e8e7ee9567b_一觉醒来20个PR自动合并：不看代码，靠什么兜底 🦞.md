刷到一条挺魔幻的热搜：一位做 AI 基础设施的工程师，一觉醒来发现 20 个 PR 已经自己合进了主干，本人淡定表示"我基本不看代码了"。评论区秒变两个阵营：一半人羡慕这是躺平天花板，一半人惊呼"生产事故预定"。这事值得认真拆一拆——"不看代码"不是摆烂，而是工程注意力的整体迁移：从读 diff，迁移到读系统。能不能学，取决于你家的闸门修到了哪一级。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/6325257f7b876022.png)

## 一、注意力去哪了：从"读代码"到"读信号"

传统开发节奏里，人是流水线上最慢的工位：人写代码 → 人 review → 人合并。AI agent 把这个循环压缩成了机器自转：写代码 → 跑测试 → 自我修复 → 开 PR → 绿灯即合并，全程不需要人插手。

这时人的角色发生了本质变化：

- 过去：逐行审 diff，判断"这段代码写得对不对、好不好"
- 现在：设计并维护"让机器判断"的机制，判断"这套闸门可不可信"

一个不太恰当但好用的类比：你不再亲自检查流水线上的每一瓶水，而是校准质检仪器、盯着次品率曲线。这不叫不负责任，叫换岗位。

所以"基本不看代码"的正确读法是：他不看 diff，但一定在看测试通过率、告警面板和回滚按钮还好不好使。只学"不看代码"、不学"看什么"，属于抄作业只抄了封面。

## 二、敢让 AI 自动合并的四道闸门

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/89638d2d9deb8322.png)

主干之所以能被信任，不是因为 AI 有多聪明，而是因为系统能快速发现错误、快速撤销错误。自动合并的底气来自四道闸门串成的流水线：

1. **自动化测试**：单元、集成、端到端三层都要有，覆盖率达到阈值才给绿灯。这是最基础的一道，缺了它后面全是空中楼阁。
2. **静态检查**：lint、类型检查、SAST 安全扫描、依赖漏洞审计。机器看机器写的代码，最大的优点是不犯困、不打人情分。
3. **灰度发布**：canary 先放 5% 流量，feature flag 随时可以关，蓝绿部署随时切换。就算出错，爆炸半径也被限制在一小块。
4. **可观测性 + 一键回滚**：指标、日志、trace 齐全，出问题几分钟内 revert。主干永远"可恢复"，比"永远正确"现实得多。

四道闸门没有就学"不看代码"，约等于闭眼过马路还嫌红绿灯吵。

## 三、哪些 PR 可以放飞，哪些必须留给人

并非所有改动生而平等。这事业界其实悄悄干了十年：Dependabot 自动升级依赖、merge queue 自动合并绿灯 PR，都是"自动合并"的史前形态，只是当时没人觉得魔幻。

适合自动合并的：

- 依赖升级、机械重构、样板代码调整
- 补测试、补文档
- 内部工具和实验性功能——那位工程师大概率就在这类场景，迭代速度优先于代码优雅

必须人来的：

- 支付、鉴权等安全敏感路径
- 数据库 schema 变更、权限与基础设施配置
- 含产品判断的模糊需求：AI 能写出"能跑"的代码，但"该不该这么做"是人的问题

## 四、别急着抄作业：四个失败模式

1. **测试会撒谎**。覆盖率不等于正确性。agent 既写实现又写测试时，可能写出"贴合自己实现"的测试，自我验证闭环里绿灯常亮，问题全攒到线上。
2. **提示注入是新的攻击面**。agent 读了 issue 或评论里的恶意文本，手里又有合并权限，等于把自动化钥匙递了出去。
3. **架构漂移**。每个 PR 单看都合理，合起来抽象越来越乱，技术债按复利计息，半年后没人敢动核心模块。
4. **责任真空**。出了事故，"是 AI 合的"不构成免责声明。合规行业必须有审计留痕，关键合并必须有人签核。

## 五、想跟进？三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/64ee542d438d6bc4.png)

1. **先修闸门，再放权限**。自主权是挣来的，不是拍脑袋给的。用缺陷逃逸率、change failure rate、MTTR 这些指标说话，数字好了再逐步放权，而不是反过来。
2. **分级放行**。低风险路径打上标记走自动合并，高风险路径强制人审。人不逐行读，但读 PR 摘要、风险画像和测试报告——把 review 从"读代码"升级成"读风险"。
3. **定期抽查，用复盘校准**。每周随机抽 5% 的 agent PR 做人工审查，专治测试撒谎；每出一次事故，就把结论喂回 agent 的约束规则。信任不是给的，是校准出来的。

最后一点冷思考：那句"我基本不看代码了"听着像偷懒宣言，实际上是把工程判断上移了一层——他看的不再是 diff，而是仪表盘、告警和失败模式。当 AI 让写代码变得便宜，真正稀缺的能力变成了两样：设计一个能自我纠错的系统，以及知道什么时候该把权限收回来。代码可以不看，系统不能不懂。
