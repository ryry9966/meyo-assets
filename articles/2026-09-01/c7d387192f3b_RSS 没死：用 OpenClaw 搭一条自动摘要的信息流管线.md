## 背景

信息源越加越多，但真正每天会打开的没几个。RSS 依然是控制信源最干净的方式——没有算法推荐，全部自己选。问题是 RSS 阅读器只解决"聚合"，不解决"消化"。订阅 40+ 个源之后，未读数常年四位数，最后变成心理负担。

我的思路是：让 OpenClaw 定时跑一个 Agent 任务，把每天的 RSS 条目做去重、打分、摘要，生成一份日报推给我。只看日报，原始条目按需回查。

## 做法

整条管线分五步，全部跑在一台小主机上：

1. **采集**：用 FreshRSS 自托管聚合订阅源，API 干净，也抹平了各源更新频率的差异。
2. **抓正文**：不少源只有摘要甚至只有标题，用 readability 类工具抓原文，转纯文本。
3. **去重与打分**：这步交给 Agent。把最近 7 天处理过的标题存进 SQLite，新条目先做相似度比对，再按自定义规则打分（关键词命中、来源权重、时效）。
4. **摘要**：只对过分数线（比如 6 分以上）的条目生成两三句摘要，强制保留原文链接。
5. **投递**：汇总成一篇 Markdown 日报，由 OpenClaw 的 cron 推到 IM，同时归档到笔记目录。

每天早上 7 点触发一次，全流程 10 分钟内结束。prompt 和打分规则放配置文件里，跟代码一起做版本管理。

## 踩坑点

- **别把 50 条塞进一个 prompt**：一开始我让模型一次输出全部摘要，后面条目明显敷衍，还会互相串。改成每条单独摘要、日报环节只做排序和写导语，质量立刻稳定。
- **去重必须跨天**：只对"今天"去重基本没用，同一事件会被不同源连报一周。按标题做 7 天滑动窗口比对，重复率才降下来。
- **正文抓取要兜底**：约 15% 的链接抓不到正文（反爬或纯 JS 页面）。失败就降级用 RSS 自带摘要，并标记"未验证"，不要硬编。
- **摘要必须带原文链接**：模型偶尔会"脑补"细节，保留链接让每条结论可回溯，这是底线。
- **定时任务防重入**：某次抓取卡住，下一轮 cron 又起一个进程，导致重复推送。加个简单的锁文件解决。

## 可复用的建议

- **管线分层**：采集、清洗、筛选、生成、投递各自独立，中间结果落盘。哪一步坏了单独重跑，不用从头来。
- **打分规则先简单后复杂**：关键词 + 来源权重已经能过滤七成噪音，别一上来就堆复杂模型。
- **prompt 里明确"不确定就写不确定"**：宁可短，也不要编。
- **日报之外保留全量归档**：纯 Markdown，随时可以 grep，这是这套系统最值钱的副产品。

## 总结

这套东西没有用到什么高深技术，本质是"定时任务 + 一点 Agent 判断 + 纯文本存储"。但它把每天一小时的阅读压到十分钟，而且因为信源完全自己控制，日报质量是可持续的。RSS 的价值从来不在阅读器，而在于你可以把整条信息流当成数据管道来编程——这才是 Agent 时代它依然值得维护的原因。
