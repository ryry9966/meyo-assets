## 背景

大模型没有跨会话记忆。每次新会话，Agent 对你的认知都是零：你的操作系统、常用包管理器、“先给结论别铺垫”的沟通习惯，要么每轮手动贴一遍，要么靠模型在对话里慢慢猜。OpenClaw 的 workspace 机制提供了一类常驻文件，`USER.md` 会在会话启动时随上下文一起注入。把“你是谁”写成一份结构化文档，是目前成本最低、收益最确定的个性化手段。

## 问题

实际用下来，痛点集中在三处：

1. **重复自我介绍**。每次都要交代“我用 pnpm 不用 npm”，说漏一次就收获一条错误的安装命令。
2. **风格不对付**。模型默认输出偏百科式，而你可能只要结论加关键代码。
3. **记忆不可控**。依赖对话内记忆，模型记住什么、忘掉什么全凭概率，无法审计、无法迁移。

## 做法

在 workspace 根目录建 `USER.md`，建议分四区：

```markdown
# Identity
- 全栈开发，主写 TypeScript / Python
- macOS + zsh，编辑器 Neovim

# Environment
- 包管理器：pnpm（不要用 npm / yarn）
- Python 统一用 uv 管理
- 时区 UTC+8

# Preferences
- 回答先给结论，解释放后面
- 代码示例直接可运行，不要伪代码
- 中文交流，技术名词保留英文

# Do-not
- 不要主动重构我未要求的代码
- 不要在回复里加表情符号
```

三条写法原则：

- **只写事实和稳定偏好**，不写一次性任务——那是 `MEMORY.md` 和任务列表的职责，混在一起两边都失效。
- **控制在 60 行以内**。这份文件每轮会话都要付 token，长文件还会稀释模型注意力。
- **定期沉淀**：对话里纠正过两次以上的事，就写进去。

## 踩坑点

- **写成日记**。项目进展、临时待办全塞进来，几周后膨胀到几百行，Agent 开始答非所问。
- **敏感信息裸奔**。API key、真实住址写进去，等于给所有会话常驻一个泄漏源。该写的是“密钥走环境变量”这类规则，不是密钥本身。
- **内容过时**。换了工具链没更新，Agent 会理直气壮地坚持旧偏好，比不写还糟。
- **文件间冲突**。SOUL.md 或系统提示要求简洁，USER.md 又要求详细展开，模型只能随机站队。改动前先全局搜一遍相关文件。
- **期望过高**。USER.md 是上下文注入，不是微调。它能矫正偏好，不能让模型突然会写它本来不会的东西。

## 可复用建议

- **进版本管理**：把 USER.md 放进 dotfiles 仓库，多机同步，改动有迹可循。
- **分层放置**：全局 USER.md 只放稳定偏好，技术栈细节下沉到项目级 AGENTS.md，避免重复和漂移。
- **让 Agent 参与维护**：会话结束前问一句“这轮有没有值得沉淀进 USER.md 的偏好”，让它提议 diff，你人工确认后合入。
- **每月删一次**：删掉没再被验证过的条目，维持信噪比。画像文件和代码一样需要 refactoring。

## 总结

USER.md 的本质是把“人肉上下文”工程化：一份你拥有完整所有权、可审计、可版本管理的用户画像。它不炫技，但每一轮会话都在省掉重复沟通的成本。写第一版只要十分钟，之后按“纠正两次就沉淀”的节奏维护即可。建议从 Environment 和 Do-not 两区起步——这两区误伤率最低，收益最快。
