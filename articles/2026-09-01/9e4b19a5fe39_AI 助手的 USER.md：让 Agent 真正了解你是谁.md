## 背景

OpenClaw 的工作区（默认 `~/.openclaw/workspace`）里有一组约定文件：`AGENTS.md` 管行为规范，`SOUL.md` 管人格，`USER.md` 管"你是谁"。多数人装完只填了个名字和时区，剩下的全是模板注释。这其实浪费了整套机制里性价比最高的一个文件。

## 问题

Agent 的上下文是易失的。会话压缩、重启、换设备之后，它对你的一切认知都会清零。结果就是反复出现的场景：

- 每次都要解释"我用的是 Debian 12，别给我 brew 命令"；
- 它算错你的时区，提醒任务全偏几个小时；
- 上周明确说过的偏好，这周又被问一遍；
- 它给你推荐你早就放弃的技术栈。

聊天记录解决不了这个问题——历史会被压缩、截断，模型对"翻旧账"的召回并不可靠。稳的做法是把"关于你的稳定事实"落成一个每次会话都会加载的静态文件，这就是 `USER.md` 的定位。

## 做法

我的 `USER.md` 分六段，总共 40 行左右：

1. **基础信息**：称呼、时区、工作时段、语言偏好。时区尤其重要，cron 和提醒类任务全靠它。
2. **技术画像**：主力栈、操作系统、关键工具版本、部署环境。一行一条，写给模型看，不用修辞。
3. **协作偏好**："先给结论再给代码""不确定时直接问，不要猜"这类。
4. **边界**：哪些目录、仓库、话题不要碰（原因见踩坑）。
5. **当前项目**：每个项目一行，说清它是什么、目前卡在哪。这是最常过期的段落。
6. **历史决策**：重要的"不要再说"清单，比如"已决定不迁移到 X，别再建议"。

写法上两个原则：**一行一个事实**，便于模型定位和后续 diff；**控制长度**，这个文件每次会话都会进上下文，超过一两千 token 就是在烧预算。

## 踩坑点

- **写成日记**。`USER.md` 是身份，不是记忆。会话产生的临时事实应进 `MEMORY.md` 或每日笔记，静态身份才进 `USER.md`。混着写，文件会迅速膨胀。
- **塞敏感信息**。token、密码、真实住址不要放。上下文不是保险箱。
- **只写不改**。三个月前的"当前项目"比不写更糟，模型会基于过期信息做出自信的错误假设。我用 git 管工作区，每周 review 一次 diff。
- **职责混淆**。`AGENTS.md` 是"你应该怎么做事"，`USER.md` 是"我是谁"。但涉及硬性禁止的行为（比如"不许动 `~/prod`"），我会两边都写——`USER.md` 是提示，不是约束执行的保证。

## 可复用建议

- **让 Agent 参与维护**：隔段时间说一句"根据最近的对话，更新 USER.md 的项目段落，输出 diff 给我确认"。它比你更清楚哪些信息重复出现过，但合并必须人工把关。
- **当配置代码对待**：进 git、写 commit message、定期 review。
- **新机器冷启动**：装完 OpenClaw 第一件事把这个文件拷过去，十分钟换回全部个性化上下文。

## 总结

`USER.md` 是整套 Agent 配置里成本最低、杠杆最高的一环：十分钟的书写量，换来每次会话省掉的开场解释和错误假设。把它当成"你自己的 README"来维护，Agent 的输出质量会有肉眼可见的改善。
