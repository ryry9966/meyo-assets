据36氪报道，Kimi（月之暗面）正与微软、亚马逊、谷歌谈判，希望后者在云平台上提供 Kimi 模型托管服务时，分出约30%收入。消息出来后，很多人第一反应是：开源模型不是免费吗？怎么开始“收租”了？

其实，这里收的不是下载费，也不是开源代码授权费，而是模型生态里最容易被忽略的一层——云厂商的托管推理收入。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/beae53917856c49c.png)

## 一、先拆概念：开源代码、开放权重、托管服务不是一回事

“开源模型”并不是一个单一概念，至少可以拆成三层：

1. **开源代码**：训练框架、推理引擎、数据处理脚本可以开放，比如 PyTorch、vLLM，但这里不包含模型参数。  
2. **开放权重**：模型训练完成后的参数文件开放下载，开发者可以在自有 GPU 上加载、微调、本地推理。  
3. **托管推理**：云厂商把权重部署在数据中心，按 token、并发、小时数向用户收费。

Kimi 本次瞄准的是第三层。个人开发者下载权重、在自己服务器上跑，大概率不触发分成；真正触发的是微软 Azure、AWS Bedrock、Google Vertex AI 这类“模型托管货架”。

这有点像 MySQL 开源免费，但 AWS RDS 把 MySQL 包装成云数据库服务后持续收费，开源项目方却一分钱拿不到。Kimi 想改的，正是这个分配结构。

## 二、30%从哪来？本质是云市场抽成

把收入链路拆开看：

1. 企业或开发者调用云平台上的 Kimi API；  
2. 云厂商按 token、小时或月费收取推理服务费；  
3. 传统模式下，模型方可能只拿到一笔固定授权费，或者完全免费；  
4. Kimi 要求从云厂商的 Kimi 模型相关收入中抽 30%。

这个逻辑很像苹果 App Store 的抽成机制：开发者用苹果平台获客，苹果抽成 30%；现在模型方认为，云厂商靠我的模型获客，也应该抽成 30%。差别在于，苹果抽的是开发者的收入，Kimi 抽的是云厂商的收入。

需要强调的是，这不是“向开发者加价 30%”，也不是“下载权重收费”。如果企业不走云托管，而是在自有 VPC 或本地 GPU 上部署，通常不会按这个比例被抽成。当然，具体条款要看许可证和合同。

## 三、为什么现在敢要？开源模型也需要现金流

训练一个大规模开源模型并不便宜。以千亿参数模型为例，单次训练可能需要数千张 H100 GPU 跑数周，成本动辄数千万美元。开放权重可以换生态、换口碑、换数据反馈，但换不来持续的训练经费。

云厂商恰恰是这波开源模型的最大间接受益者：

- 不用承担模型训练成本；  
- 利用开源权重的热度快速上架新模型；  
- 赚取推理服务的高毛利经常性收入。

过去软件行业有很多类似博弈。MongoDB 因为不满 AWS 等云厂商“只托管不贡献”，推出 SSPL 许可证；Red Hat 把开源 Linux 变成订阅和支持生意；Android 开源但 Google 通过 GMS、应用商店抽成获利。

Kimi 的 30% 诉求不是凭空发明，而是把云托管时代的老问题，搬到了大模型领域。当然，30% 是否能谈成，还要看谁更需要谁。如果云厂商认为 Kimi 模型带来的增量收入足够覆盖分成，就可能接受；如果市场上同水平开源模型很多，叫价权就会弱化。

## 四、谁最紧张？开发者、企业、云厂商的三笔账

1. **开发者**：如果云平台 API 因分成涨价，短期成本可能上浮；但开源权重给出另一条路：自部署。开发者要开始把“API 依赖”和“许可证风险”放进技术选型清单。  
2. **企业**：采购云上模型服务时，多了商业合规变量。需要确认云厂商与模型方是否达成正式协议，否则可能遇到服务下架、许可证变更、价格调整等波动。  
3. **云厂商**：接受 30%，模型服务的毛利会明显收窄；不接受，可能失去一款热门模型，让竞争对手抢先。云厂商还会加快自研或扶持其他愿意免费、低成本开放权重的模型。

这种博弈会强化一个趋势：模型方不再只是云厂商的“零配件供应商”，而是有议价权的上游 IP 持有者。

## 五、冷思考：收租能持续吗？

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/58bb8f1fb8ff3ed5.png)

判断这轮收租能否持续，有三个关键点：

1. **许可证会越来越细**。开源模型将出现个人、研究、商用、云托管等不同条款。开发者不能只看 GitHub 首页上的“open weights”标签。  
2. **开源生态可能分裂**。太苛刻的分成许可证会引发“假开源”争议，影响社区贡献和模型传播。  
3. **替代性决定定价权**。如果其他模型方以更宽松的开放权重策略换生态，Kimi 的 30% 可能被迫调整；反之，如果模型能力拉开代差，云厂商也可能选择接受。

实用建议：

- **商用前把许可证逐条读完**，特别关注 cloud hosting、revenue share、subprocessors 等条款，不要只看“开放权重”四个字。  
- **评估 API 与自部署的长期总成本**，包括 GPU、运维、延迟、人才，而不是只比较每百万 token 单价。  
- **在推理层做抽象和适配**，避免把业务绑死在单一模型或许可协议上，保证必要时可以替换。
