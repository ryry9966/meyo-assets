## 背景

OpenClaw 的主会话是长期存在的：工具输出、网页抓取、日志分析、多轮排障，全堆在同一个上下文里。跑得越久越明显——上下文被撑满触发 compaction 后，被压掉的往往不是垃圾，而是你前面定下的约束和决策。我们把这类问题统称「会话污染」。

## 问题

污染有三个典型来源：

1. **噪声型**：子任务产生大量中间输出（长日志、搜索结果），只有最后一行有用，但全程占着主会话上下文。
2. **串台型**：并行跑两个任务，A 的中间状态被 B 读到，或 session key 复用导致历史混在一起。
3. **软污染**：session 本身隔离了，但子 Agent 直接改了共享的 memory / 工作区文件，主会话下次加载记忆时被悄悄打了补丁。

## 做法

核心原则：**主会话只保留决策和状态，一切高噪声执行下放到子 Agent。**

1. 用 `sessions_spawn` 起子 Agent，任务描述写清三点：目标、边界（允许动哪些文件/工具）、回报格式（「只回结论，150 字以内」）。
2. 结果需要挂在当前对话线程时用 `thread: true`；需要彻底隔离（比如跑不可信的批处理）就给独立 agentId + 独立 workspace。
3. 子 Agent 与主会话之间只走 `sessions_send` 点对点传消息，不要广播。
4. 跑完用 `sessions_list` 审计，确认没有僵尸 session；有价值的结论由主会话显式写入 memory，别指望子 Agent 自己留痕。

一个可直接复用的任务描述模板：

```text
任务：分析 /var/log/app.log 中最近一次报错的根因
边界：只读该日志，不修改任何文件，不调用部署类工具
回报：结论 + 证据行号 + 建议动作，150 字以内
完成后结束 session，不留守
```

## 踩坑点

- **把主会话上下文整段复制进任务描述**——等于手动污染，隔离白做。只给完成任务所需的最小事实。
- **子 Agent 默认继承系统提示和工具集**，权限没收紧时它会「顺手」改共享文件。隔离 session ≠ 隔离工作区，敏感任务必须配 workspace 隔离。
- **子 Agent 自己也会触发 compaction**。长日志分析建议在任务描述里就要求分段处理、只保留摘要。
- **手工指定 session key 时复用了旧 key**，新任务读到旧历史，表现为「子 Agent 一上来就知道不该知道的事」。

## 可复用建议

- 把高频子任务（日志分析、网页抓取、批量转换）固化成带固定模板的技能，spawn 时只填参数。
- 主会话定期「减负」：翻一遍 `sessions_list`，清掉不再需要的 session。
- 团队内约定回报格式（结论 / 证据 / 建议三段式），子 Agent 的产出才能直接进主会话。

## 总结

session 隔离不是 OpenClaw 自动的魔法：spawn 只给了你隔离的容器，污染往往从任务描述和共享工作区漏进去。守住三条线——**最小上下文进、结构化摘要出、共享资源显式声明权限**——主会话就能长期保持干净。
