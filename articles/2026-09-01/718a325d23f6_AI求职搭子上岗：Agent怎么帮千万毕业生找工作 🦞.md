36kr 最近报道了一个"水下项目"——还没正式官宣、低调打磨中的创业产品：一款定位为千万应届毕业生"求职搭子"的 Agent。从筛岗位、改简历、模拟面试，到批量投递、跟进进度，试图用一条对话流水线全包。听起来像是把"求职辅导 + 猎头助理 + 简历工具"塞进了一个对话框里。这篇文章不吹不黑，拆三件事：创业者为什么盯上这个场景、这类 Agent 技术上大概怎么干活、这门生意真要跑通还差哪几块板。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/5c3b350b709192b8.png)

## 为什么偏偏是"求职"这个场景

AI 应用创业选赛道，本质是在找"需求密度 × 痛感 × 可自动化程度"的乘积最大点，求职恰好三项都拉满：

- **需求体量大**：教育部数据，2024 届高校毕业生 1179 万，2025 届预计约 1222 万，再叠加考研考公失利后回流就业市场的人群，每年活跃求职人次以千万计；
- **流程又长又碎**：从信息搜集、简历定制、批量投递、笔试面试到谈薪，动辄持续 3~6 个月，环节之间信息差极大，"哪个岗位值得投""简历要不要为这家公司改一版"全靠人肉判断；
- **现有工具的空档**：招聘平台本质是"货架 + IM"，匹配质量靠用户自己刷；线下求职咨询动辄几千到几万元，服务非标、依赖顾问个人经验，几乎无法规模化；
- **Agent 的甜点区**：多步骤、跨平台、目标函数明确（拿到面试/offer）、有天然反馈循环（投递 → 回复 → 面试结果），正是 LLM Agent 相比传统软件最有增量价值的任务形态。

换句话说，不是求职场景突然变好了，是 Agent 技术终于够到了这个场景的门槛。

## 这个 Agent 大概怎么干活：技术拆解

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/32ab4c5fe1d931d7.png)

市面上同类产品形态各异，但技术骨架大同小异，可以分四层看：

1. **感知层**：用户上传简历 PDF，LLM 做结构化抽取（教育经历、实习、技能标签）；同时聚合各渠道 JD，用 embedding 向量计算"人岗语义匹配度"，这一步决定推荐是不是比关键词搜索聪明；
2. **规划层**：把"帮我拿到面试"拆成子任务——圈定目标岗位池 → 为不同公司生成差异化简历版本 → 排期投递 → 设置跟进提醒。这是典型的 LLM 做 planner、传统代码做 executor 的混合架构；
3. **执行层**：两条路线，一是调用平台开放接口或合作协议；二是用 browser use 类技术模拟浏览器操作自动填表投递。模拟面试则靠语音 Agent（ASR + LLM + TTS）做实时问答对抗；
4. **记忆层**：记录投递历史与面试反馈，动态修正用户画像——投了 20 个岗位只回 3 个，说明定位偏高，Agent 应该主动提示调整目标区间。

现实约束也得摆在台面上：LLM 有幻觉，简历"润色"过度会在背调和面试环节翻车；模拟浏览器操作会撞上平台风控与反爬机制；代投带来的账号安全与责任归属至今没有清晰的商业与法律答案。"Demo 能跑通"和"能规模化商用"之间，隔着很长的工程地带。

## 生意经：谁付钱，护城河在哪



技术上能实现只是入场券，这门生意真正的难点在商业模型：

- **C 端订阅最直接**：求职季付费意愿强。参照线下求职咨询 5000~30000 元的"陪跑"服务价格锚点，AI 版定价百元到千元/月，用户感知是"便宜"，转化空间存在；
- **硬伤是频次**：普通人一生求职次数屈指可数，LTV 天花板低，且需求高度集中在春招、秋招两个窗口，现金流季节性剧烈，团队要在淡季活下来；
- **更深的坎在供给侧**：招聘是双边市场，岗位数据才是真正的护城河。创业公司手里没有独家岗位，要么爬取（合规风险），要么与平台合作（议价权弱）。这也是为什么 LinkedIn、BOSS 直聘们自己叠加 AI 功能时，入口优势接近碾压——它们不缺 Agent 能力，缺的只是把它装上去；
- **可能的解法**：往服务纵深走（面试陪练、offer 决策咨询这类高价值单点），或往 B 端走（帮企业批量初筛、生成 JD、做校招流程自动化），避开和平台正面抢入口。

## 冷水与判断框架：怎么用，怎么挑

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/22fb6c0ddfa34fd6.png)

给求职者一个快速过滤框架，遇到这类产品可以照着过一遍：

1. **匹配逻辑可解释吗**？只说"AI 智能匹配"却给不出推荐理由的，多半是关键词匹配套壳；
2. **岗位数据从哪来**？来源和更新频率是否透明——过期 JD 是求职工具最大的负资产；
3. **谁在操作我的账号**？凡是要求提供平台账号密码、代点投递的服务，先评估封号与隐私风险，身份证、成绩单等敏感材料尤其谨慎；
4. **收费模型合不合理**？按月订阅可以理解，"保 offer"在逻辑上就不成立——offer 是企业发的，不是工具发的；
5. **效果可归因吗**？做一个简单的 A/B：自己投一半岗位，Agent 投另一半，两周后对比回复率，数据说话。

## 写在最后：三条实用建议



1. **把 Agent 当副驾驶，别当代驾**：信息筛选、简历初稿、模拟面试这类高频重复劳动可以放心外包；但投哪些公司、薪资底线、关键轮次怎么沟通，决策权留给自己——求职是你职业生涯第一次重大谈判，全托管了可惜；
2. **隐私默认最小化**：给工具的授权只开必需项，定期检查授权记录，任何工具都不要上传身份证原件照片；账号密码永远不给第三方；
3. **给从业者的冷思考**：这个赛道最终拼的不是对话体验，而是岗位供给侧资源与合规的自动化通道。做 C 端，把"陪练与决策辅助"做深，比"全托管代投"更稳；做 B 端，先想清楚与招聘平台的竞合关系，别在别人的主场打仗。

工具在变快，判断力依然是你的。这大概就是 AI 时代求职的第一课。
