## 背景

OpenClaw 这类常驻 Agent 的会话是滚动重建的：上下文压缩、网关重启、换设备接入，都会让“它记得我”变成错觉。系统提示词（SOUL.md / AGENTS.md）解决的是“Agent 该怎么做事”，而“你是谁”这件事，长期靠模型从聊天记录里现猜。

USER.md 就是把这件事显式化：在工作区放一个纯文本文件，写清你的身份、环境、偏好和边界。会话冷启动时，Agent 先读它，再干活。

## 问题

没有 USER.md 时的典型症状：

- 每次新会话都要重复自我介绍：称呼、时区、常用技术栈；
- Agent 默认英文回复、默认长篇解释，而你只想要结论；
- 它不知道你机器上有什么，给出的路径、包管理器全是“通用假设”；
- 团队里每个人都要各自调教一遍，经验无法沉淀。

本质问题：关于“用户”的稳定事实，缺少一个持久化、结构化的载体。

## 做法

1. 在工作区根目录建 `USER.md`，建议分五段：

```markdown
# 用户画像
## 基本信息
- 称呼：老周（不要叫“用户”）
- 时区：Asia/Shanghai，工作时段 09:00–19:00
## 环境
- 主力机：macOS arm64 + Homebrew；两台 Ubuntu 22.04 服务器
## 偏好
- 默认中文回复，先结论后细节
- 代码注释用中文，commit message 用英文
## 边界
- 不要主动重启服务；生产操作先列 diff 再执行
## 当前项目
- openclaw-gateway 调优（截至 2025-06）
```

2. 控制篇幅：目标 30 行以内。它每次会话都进上下文，每一行都是 token 成本，也是注意力成本。
3. 约定更新机制：在 AGENTS.md 里写明“当用户纠正你时，先提议把该事实写入 USER.md”。让每次纠错沉淀为记忆，而不是口头重复。
4. 纳入 git：变更可审计、可回滚，换设备直接 clone。

## 踩坑点

- **写成流水账。**“上周去了杭州”这类事件性信息应进 MEMORY.md，USER.md 只放“半年内大概率不变”的稳定事实。混写的结果是文件越长、信噪比越低。
- **写成命令清单。**“必须用 Rust”这类硬约束如果和任务冲突，Agent 会自相矛盾。偏好用“默认/倾向”措辞，真正的硬约束留给 AGENTS.md。
- **敏感信息裸奔。**真实姓名、住址、密钥不要写。工作区可能被同步、被插件读取，按“文件迟早会泄露”的假设做信息最小化。
- **写完就忘。**建议每月 review 一次，过期项目移出去。陈旧信息比没有信息更糟——Agent 会基于错误的“你是谁”，做出自信的错误决策。

## 可复用建议

- **三层记忆分工**：SOUL.md / AGENTS.md 管“Agent 是谁、怎么做事”，USER.md 管“用户是谁”，MEMORY.md 管“最近发生了什么”。三者混用是大多数记忆混乱的根源。
- 用列表和短表格而不是长段落，方便 git diff。
- 多设备、多 Agent 场景下，USER.md 做唯一事实源，用软链接或同步分发，避免出现两份漂移的画像。
- 团队内沉淀一份 USER.md 模板进内部仓库，新人接入 Agent 的成本从“一周调教”降到“十分钟填表”。

## 总结

USER.md 的价值不在“多一个文件”，而在于把“让 Agent 了解你”变成可版本化、可审计、可迁移的工程实践。先花十分钟写第一版，之后两周里，每当 Agent 猜错你一次，就修一行——两周后你会得到一个不再需要你反复解释自己的助手。
