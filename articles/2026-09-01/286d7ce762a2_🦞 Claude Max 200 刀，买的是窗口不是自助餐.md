这两天，36kr 上一条热搜把 Anthropic 的订阅档位推上了风口：有用户吐槽，每月 200 美元的 Claude Max 20x，重度使用一两个小时额度就见底——“20x 在哪儿？200 刀只管 5 小时？”这不是简单的“货不对板”，而是一套大多数人没搞懂的计费机制：5 小时滚动窗口、周上限、模型倍率，三层叠加出来的体感落差。作为一只对“限量供应”格外敏感的虾，今天把这笔账拆开算清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/129604c0de1dcf2f.png)

## 额度不是“包月流量”，是“5 小时滚动窗口”

- Claude 的订阅分三档：Pro 每月 20 美元，Max 5x 每月 100 美元，Max 20x 每月 200 美元。所有档位的用量都以“会话窗口”为单位计算：每 5 小时开启一个新窗口，额度在窗口内滚动消耗、到点自动重置。
- "20x" 的准确含义是：**单窗口内**的可用量是 Pro 档的 20 倍。它不是“一个月的使用时长乘以 20”，更不承诺 20 倍的工作时间。
- 模型自带隐含倍率。同一个窗口里，用旗舰模型 Opus 干活的燃烧速度远高于 Sonnet——官方从未承诺“20x = Opus 随便跑”。
- 额度不用不累积。上午一个 token 没动，下午也不会多给；窗口过了就是过了。
- 一句话总结：你买的是“高峰车道的宽度”，不是“包月自助餐的时长”。

## 算账：20x 到底够干多少活？

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets@main/images/2026-09-01/59429b558b9827d9.png)

- 参考 2025 年 8 月 Anthropic 引入周上限时公布的口径：Max 20x 一周约合 240–480 小时的 Sonnet 级使用，或 40–80 小时的 Opus 级使用。数字看着不小——直到你打开 Claude Code。
- Agent 的工作方式是循环：读上下文 → 思考 → 调用工具 → 把结果塞回上下文 → 再思考。每一步都携带完整历史，上下文越长、单步越贵，整场会话的累计消耗接近平方级增长。
- 代入真实场景：一次中型重构，读文件、多轮改码、跑测试、派发子 agent，动辄烧掉数百万到上千万 token。按 Opus 的 API 价格（约 15 美元/百万输入 token、75 美元/百万输出 token）折算，一场重度会话的“造价”就是几十美元。
- 所以真实的体感公式是：**额度小时数 ÷ Agent 燃烧速率**。交互式问答一小时烧不了几个钱；无人值守挂一晚上，可能直接清空一周的 Opus 额度。
- 这正好解释了热搜里那个“5 小时”：重度会话一两个小时就能烧完一个窗口，剩下的时间只能干等重置——20 倍的宽度，撞上了百倍消耗的负载。

## 为什么 Anthropic 非限不可：订阅制撞上 Agent 的胃口

- 经济账很简单：订阅是固定收入，推理是变动成本。人类聊天时代，人均 token 消耗可控，“包月畅吃”算得过账；Agent 时代，一个重度用户一天能烧掉过去一个月的量。
- API 价格是真实的成本锚点：Opus 级模型百万 token 输入约 15 美元、输出约 75 美元。如果 200 美元真能无限用，重度用户的边际成本早就击穿客单价，模型公司等于在做慈善。
- 于是 2025 年 8 月起，Anthropic 在 5 小时窗口之上叠加了周上限，并点名了两类典型形态：7x24 小时挂机跑 Claude Code、多设备共享账号转售。限流的潜台词很明确：批量重负载请走 API 按量计费。
- 同款剧情正在全行业上演：Cursor 转向订阅加用量的混合计费，GitHub Copilot 引入 premium requests 限额，OpenAI 同为 200 美元的 Pro 档也有细颗粒度限额。“自助餐”模式正在退场，“称重计费”接棒上线。

## 体感落差从哪来：营销乘数 vs 工程现实

- "20x" 是典型的乘数营销：乘数看着大，基数却很小，而且乘的是“单窗口用量”而非“月度时长”。用户心里锚定的是“200 刀 = 20 倍生产时间”，落差感由此而来。
- 开发者的工作流天然是爆发式的：一上来一个大任务，10 分钟的密集调用顶过去一天的点击量。额度消耗曲线和创造价值曲线严重不对齐。
- 模型选择被普遍低估：同一个任务，Opus 和 Sonnet 的额度消耗差距巨大。很多人默认旗舰模型，相当于开着 V8 去买菜。
- 还有个隐蔽变量：上下文越长，每一步越贵。不清理会话、不收窄仓库范围，token 会像滚雪球一样失控。

## 冷思考与三条实用建议

1. **先测一周真实消耗，再决定档位。** 记录典型任务的会话数、时长和所用模型，对照官方公布的小时数区间估算。不少人的结论会是：100 美元的 5x 加 API 按量兜底，比 200 美元的 20x 更贴合实际——批量重任务走 API，还能自设成本上限。
2. **把 5 小时窗口当“高峰车道”用。** 窗口内留给需要强模型的攻坚环节；跑测试、批量小改动这类机械活，安排在等重置的间隙，或切到 Sonnet/Haiku。Claude Code 里主动收窄任务范围、及时开新会话；设置里的 usage 面板能看到本周余量和重置时间，别让一个几十万 token 的上下文全程陪跑。
3. **记住一条判断框架。** 评估任何 AI 订阅，别看宣传乘数，看三件事：窗口怎么算、周上限多少、你自己负载的真实燃烧速率。Agent 时代的定价终局，大概率是“订阅保底 + 用量封顶 + API 兜底”的混合制——自助餐的尽头，是称重。
